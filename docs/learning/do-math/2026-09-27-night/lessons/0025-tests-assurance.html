25. 시험이 확인한 것과 아직 확인하지 않은 것

구조 검사·회귀 시험·실호출·연구 효능의 증거 범위를 구별합니다.

설치 구조 검사가 통과했다는 보고를 받았다고 합시다. 필요한 역할 문서와 스키마가 갖춰졌다는 증거는 되지만, 모델이 실제 연구를 잘하거나 Lean·Windows·외부 서비스의 모든 경로가 작동한다는 증거는 아닙니다. 검증 결과는 언제나 판본·사례·실행 범위와 함께 읽습니다.

확인하려는 성질에 맞는 검사를 고른다

probe_cli.py --skill-only는 스킬 폴더의 역할별 필수 문서와 출력 스키마 구조를 읽는 검사입니다. 모델을 호출하지 않습니다. 실제 provider probe는 모델과 사례, 새 증거 경로를 명시해 호출하며 실제 모델 예산을 씁니다. 설치된 문서의 정확성·모델 품질·연구 효능은 각각 다른 평가가 필요합니다.

회귀 시험의 진입점은 scripts/run_tests.py 하나입니다. 지정한 시험 ID·클래스·모듈, --shard 영역, 또는 전체를 실행합니다. --list는 실행하지 않고 선택을 보여 줍니다. 시험 결과 캐시는 없으므로 선택한 시험은 실제로 돌아갑니다. 시작 상태 템플릿 재사용은 결과 재사용과 다릅니다. scripts/tests/시험-지침.md

python .agents/skills/do-math/scripts/probe_cli.py --skill-only
python .agents/skills/do-math/scripts/run_tests.py --list
python .agents/skills/do-math/scripts/run_tests.py test_task_scope

이 명령들은 검사의 사용 예입니다. 교재를 읽는 것만으로 해당 검사가 실행되지는 않습니다. 새 수업 제작의 확인은 링크·본문·문항·렌더링 검사이며 제품 전체 회귀 시험을 대신하지 않습니다.

조각과 실제 자원 시험

시험 조각은 foundation·host·lifecycle·research·review·academic이며 정확한 모듈 목록은 test_categories.SHARDS가 소유합니다. 등록되지 않은 시험 모듈이 있으면 실행기는 오류를 냅니다. 선택된 시험이 0개여도 통과로 표시하지 않습니다.

실제 Lean·프로세스 자원을 다루는 lean·resource 표시 시험은 Windows Job 안의 별도 프로세스에서 클래스 단위로 수행합니다. 시험·준비·종료 단계에는 기본 300초 상한이 있고 넘으면 자손을 종료해 미완료를 기록합니다. 이 시험 운용 상한이 제품 Lean의 계산 계약을 바꾸지는 않습니다.

보고서는 시험별 통과·실패·오류·건너뜀·미실행, 시간, 코드 판본과 실행 중 변경 여부를 남깁니다. 건너뛴 실제 Lean 시험을 통과한 형식 검사로 세지 않습니다. 단독 조각 120초, 전체 순차 300초는 시간 목표이며, 앞 조각이 만든 템플릿을 재사용한 뒤 조각의 시간과 단독 시간을 같은 조건의 측정으로 비교하지 않습니다.

변경할 때의 검증 순서

편집 중에는 바꾼 성질의 가장 작은 시험을 돌리고, 넘기기 전 관련 영역을 확인하며, 통합 뒤 전체를 확인합니다. 시험 중인 작업 트리는 편집하지 않습니다. 실패하면 먼저 traceback과 코드를 읽어 가설을 세우고 필요한 가장 작은 재현을 고릅니다.

새 시험은 성질 하나를 가장 싼 시작 상태에서 확인합니다. 순수 검사로 되면 전체 초기화를 돌리지 않고, 활성화 과정 자체를 검사해야 하면 공개 경로를 사용합니다. 필요한 값이 확정된 첫 상태에서 멈춥니다. 도우미는 다른 시험 파일에 기대지 않고 적합한 fixture 모듈을 공유합니다. 결함 수리는 그 결함을 재현하는 시험의 실패를 먼저 확인합니다.

이렇게 검사를 통과해도 연구 효능은 별도입니다. 대표 문제군에서 후보·지식 회수·오류 발견·미해결·비용을 정한 방법으로 비교해야 성능을 말할 수 있습니다. 작은 예시 성공과 넓은 수학 문제군의 해결 능력을 같은 보증으로 쓰지 않습니다.
