21. 정지·HOLD·정비와 독립 운영의 관계

연구와 자동 운영을 멈추거나 이어갈 때 각 제어의 효과를 읽습니다.

사람이 연구를 잠시 멈추려는 상황과, 설치 파일을 교체하려는 상황은 다릅니다. 전자는 사용자 정지의 뜻을 보존해야 하고, 후자는 새 배정을 막은 채 기존 실행과 자원을 정산해야 합니다. do-math는 이 책임을 별도 제어로 기록합니다.

제어 접수와 실제 효과부터 구별한다

공개 제어 명령은 먼저 workspace의 inbox, 즉 요청 전달함에 바뀌지 않는 요청을 남깁니다. 이것이 접수입니다. 저장 상태를 쓰는 담당이 동시에 둘이 되지 않게 하는 잠금이 writer lock입니다. 명령을 처리하는 쪽이 이 잠금을 얻으면 요청을 즉시 적용하고 적용 뒤의 snapshot을 반환할 수 있습니다.

이미 연구 실행기가 잠금을 보유했다면 요청은 pending engine processing으로 남습니다. 실행 중인 엔진이 제어 요청을 읽거나 다음에 엔진이 시작될 때 적용을 시도합니다. 따라서 읽는 순서는 접수 여부 → effect가 applied·rejected·대기 중 어느 것인지 → reason과 해당 snapshot입니다. 예를 들어 pause가 접수돼도 대기 응답이면 아직 사용자 정지가 적용됐다고 보고하지 않습니다. accepted=true와 종료 코드 0은 이 뒤 단계를 대신하지 않습니다.

같은 내용을 재전송하면 최초 영수증을 재생해 효과를 반복하지 않습니다. 재개한 뒤 같은 이유로 새 정지를 요청하려면 새 --idempotency-key를 사용합니다. replay 응답의 상태는 최초 처리 시점의 값이므로 현재 상태는 다시 조회합니다. README.md · 정지, 재개와 종결

제어바꾸는 것이어서 확인할 것
pause / resume일반 연구 배정의 사용자 정지와 재개실제 실행 종료·현재 권한·남은 대기
operator hold / release고유 HOLD와 그 HOLD가 만든 사용자 정지다른 사용자 정지를 함께 풀지 않는가
quiesce / release-quiesce설치 정비를 위한 새 배정 차단 fencequiescent·예약 정산·실제 엔진 종료
closequeue를 비우고 인스턴스 종결남은 실행의 회수와 미완료 의무

resume은 completed·closed를 다시 열지 않습니다. 입력 초과나 기술 실패, 사용자 질문·권한 부족을 모두 해결하는 만능 명령도 아닙니다. 각각의 원인을 해소하고 적합한 후속 요청을 이어야 합니다.

정상 감독과 설치 복구 AI는 다르다

정상 예약 감독은 모델 없는 기계 작업입니다. HOLD·정지·상태·대화 소실 정책·예약·공급자 wake와 시작 조건을 대조하고, 가능하면 연구 엔진 작업을 요청한 뒤 반환합니다. 연구 의미를 판단하거나 grant를 새로 만들지 않습니다. 기본 감독 주기는 7200초이며 주기가 있는 감독과 지속 연구 엔진의 수명은 별도입니다.

실행기가 시작하지 못한 실제 실패나 수락된 설치 결함 진단이 있을 때 설치 복구 AI를 엽니다. 단순 대기·미해결 수학·공급자 한도·writer lock 경합은 설치 결함이 아닙니다. 복구 전에는 선행 로컬 종료, writer lock과 별도 설치 유지보수 lock, 정확한 recovery 프로필과 능력·공급자·호스트 자원을 확인합니다. 같은 실패와 같은 설치 판본의 자동 수리는 한 번만 시도합니다. 계약/독립-운영.md

예약 진입점은 설치 파일 manifest에 고정한 bootstrap 사본입니다. live 설치가 import조차 실패해도 감독의 출발점을 남기려는 구조입니다. 복구 AI는 고정 사본이 아니라 허용된 live 설치를 최소 수리하며 연구 기록·목표·예산·grant·사용자 설정·예약 작업은 바꾸지 않습니다. 관련 검사와 설치 구조 검사, 로컬 종료 뒤 lock을 놓고 launcher가 재시작을 요청합니다. 수리 보고·검사 통과·재시작 요청·실제 연구 시작은 별도 사실입니다.

정비는 종료 확인 후 교체한다

quiesce의 applied는 새 배정을 막는 fence가 적용됐다는 뜻입니다. 기존 계산은 정상 정산하며 오래 걸린다는 이유만으로 강제 종료하지 않습니다. maintenance_fence.state=quiescent와 실제 엔진 종료·lock 반환을 확인한 뒤 교체합니다. release는 지정한 fence만 풀며 pause·HOLD는 유지합니다. 저장 계약을 바꾼 프리알파 설치는 새 인스턴스로 검증하고 과거 상태를 임의 변환하지 않습니다.
