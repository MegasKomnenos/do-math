05. 사용자의 말이 내부 결정이 되기까지

원문 보존·의미 해석·독립 검사·승인·적용을 구별합니다.

사용자가 “이 문제를 계속 연구하되 외부 발표 전에는 내 결정을 받아 달라”고 말했다고 합시다. 목표와 지속 운전의 뜻, 외부 행동의 경계가 한 문장에 함께 들어 있습니다. 이를 짧게 요약한 “연구를 계속한다”만 저장하면 발표 조건이 사라집니다. do-math는 원문을 먼저 보존하고 각 의미를 맡을 내부 소유자에 연결합니다.

무엇을 정하는 문장인지 나눈다

연구 헌장은 이유·정확한 목표·성공과 부분 성과 기준·범위·우선순위·학술 요구를 보존합니다. 정책은 적용 범위와 규범을, 연구 맥락은 인스턴스 고유 용어와 경계를 맡습니다. 설정은 이 틀 안의 운용값입니다. 동시 세션 수를 바꾸는 일과 목표를 바꾸는 일은 서로 다른 변경입니다. 허가인 grant는 누구에게 어떤 행동·대상·기간·한계를 허용하는지 정합니다.

의도 해석은 원문을 import_units라는 단위들로 나눕니다. 각 단위에는 원문의 어느 부분인지, 그 부분을 어떻게 해석했는지, 어떤 내부 기록에 무엇을 적용하자는지를 적습니다. 이 제안을 받아 자기 기록을 검사·적용하는 절차가 소비자입니다. 목표 문장이 헌장 소비자로, 동시 실행 수가 설정 소비자로 가는 식입니다.

원문 구간은 처음부터 끝까지 빈틈·겹침 없이 정확히 한 번 덮어야 합니다. 공백과 구두점도 버리지 않습니다. 구간의 위치는 Unicode 코드 포인트, 곧 문자열을 이루는 문자 코드의 순서로 셉니다. 겉보기 같은 글자도 코드 구성이 다를 수 있으므로, 문자열을 같은 모양으로 정규화해 바꾸지 않습니다. 그래야 해석자·검사자·승인자가 정확히 같은 원문을 대조할 수 있습니다. 계약/의도-해석.md

전건 피복과 올바른 뜻은 따로 검사한다

구간이 원문 전체를 덮었다고 의미까지 옳은 것은 아닙니다. 별도 의도 해석 실행의 stage=check가 누락·왜곡·창작된 선호, 소유자와 질문의 연결을 대조합니다. 승인된 해석 묶음도 적용 후보일 뿐입니다. 사용자에게 속한 새로운 결정은 실제 승인 범위가 필요하며, 이미 승인된 정확한 범위는 그 근거를 재사용합니다.

기계 적용기는 수입 묶음·독립 검사·단위별 의미 해시가 승인 대상과 맞는지 확인합니다. 이 해시들은 무엇을 승인했는지 고정하는 수단입니다. 해시를 계산하는 행위가 승인을 만들지는 않습니다. 내부 기록을 직접 고쳐 원문 해석이나 승인 절차를 건너뛰지 않습니다.

소비자맡는 내용의 예
charter, policy, research_context, additional_audit목표·규범·용어·추가 감사
grant, revoke, delegation행동 허가·철회·정해진 미래 사례 위임
configuration승인 범위 안의 운용값
question_answer, task_scope질문의 답·과제 의무의 범위 처분
research_record, evidence연구 자료를 그 증거 수준대로 보존

사용 가능한 소비자는 실제 입력의 import_consumers가 정합니다. 이 표는 역할을 이해하는 안내이고, 등록되지 않은 소비자를 새로 만들 권한은 아닙니다. 정확한 payload는 references/입력-소비자.md에서 확인합니다.

질문은 영향을 받는 대상에 연결한다

사용자만 정할 정보가 빠졌다면 질문 원문·소유자·대상·차단 여부·선택 효과를 기록합니다. 한 과제만 답을 기다리면 그 과제만 대기하고 독립 작업은 계속할 수 있습니다. input --responds-to나 구조화 결정의 resolves_questions로 실제 답변을 연결하며 무관한 새 입력이 옛 질문을 지우지 않습니다.

사례 기반 위임은 명시된 종류의 미래 결정을 한정된 범위에서 재사용하는 허가입니다. 유사해 보인다는 이유만으로 적용하지 않습니다. 의미 대조가 필요한 경로에서는 같은 원문을 받은 두 독립 실행이 범위 안·밖·미해결을 판단합니다. 일치한 자동 적용도 새로운 위임의 원천이 되지는 않습니다.
