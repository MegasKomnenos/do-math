06. 새 연구를 실제로 시작할 조건 갖추기

init 성공에서 독립 연구 인계까지 남는 단계를 찾습니다.

새 연구를 만든 직후 화면에 인스턴스 ID가 보이더라도, 연구가 시작된 것은 아닙니다. 생성은 원입력과 저장할 자리를 마련하는 단계입니다. 연구자가 어떤 목표와 권한으로, 어떤 실행 능력과 신뢰 환경을 사용해 일할지 연결해야 활성화할 수 있습니다.

생성 시 확정하는 두 장소

--repository는 권위 있는 상태와 산출을 저장할 Git 저장소이고, --workspace는 실행별 입력 사본·작업 파일·제어 전달과 복구 자료를 둘 로컬 공간입니다. 목표는 --goal 또는 --goal-file, 목표보다 넓은 전체 요청은 --request-text 또는 --request-text-file로 보존합니다. 첫 상태에는 실행 grant나 연구 queue가 없습니다.

설치 경로도 확인합니다. 이 과정의 원문 기준은 .claude/skills/do-math이고, 저장소 문서는 Codex 운전에 .agents/skills/do-math를 사용하도록 안내합니다. 실제 운전에서는 선택한 설치 폴더의 문서와 코드를 함께 사용해야 합니다. 예시 속 ID·경로·기간은 실제 승인값으로 바꿉니다. README.md · 새 연구를 시작하고 인계하기

활성화는 한 가지 표시로 판정하지 않는다

  1. 원입력과 설정을 읽고 실제 승인된 목표·제약을 확인합니다.
  2. 초기 헌장과 정책 등 통치 기록을 승인 근거에 연결합니다.
  3. 초기화용 허가와 연구용 허가를 나누어 등록합니다.
  4. 현재 프로필의 정확한 ID·revision·sha256을 조회하고 실제 CLI 능력을 관측합니다.
  5. 설정·프로필·검토 방침·대화 소실 정책과 권한을 채택합니다.
  6. 기록된 툴체인에 연결한 신뢰 환경을 등록하고 전환·활성화 검사를 거칩니다.
  7. 최초 원문 해석과 독립 검사, 승인된 단위의 실제 적용을 확인합니다.
  8. 복구를 포함한 활성화 관문 전부를 확인합니다.

도구가 응답하지 않을 때 언제 점검할지 정하는 값이 tool_review_window_seconds이고, 작업자가 자기 점검 요청에 응답할 시간을 정하는 값이 self_check_response_window_seconds입니다. 두 값에는 제품 기본값이 없습니다. 이 시간이 없으면 점검과 응답 의무의 경계를 정할 수 없으므로 필요한 관찰 프로필을 채택할 수 없습니다. 실제 사용할 값을 확정한 뒤 새 프로필 참조를 다시 읽습니다.

프로필은 이번 실행에 허용할 모델·도구·관찰 방식을 고정한 계약입니다. 능력 증거는 그 계약과 실제 컴퓨터·CLI·어댑터의 정확한 판본을 함께 식별합니다. 예를 들어 CLI나 어댑터 코드가 바뀌었다면, 이름이 같아도 옛 관측을 현재 능력의 증거로 바로 사용할 수 없습니다. 아직 생성되지 않은 과제의 세부 관찰 규칙을 이 초기화 단계에서 요구하는 것은 아닙니다. references/초기화-운전.md

초기화의 run --until-active는 활성화 직후 연구 역할을 배정하기 전에 반환합니다. 활성화 시 지식 기록군에 기록이 하나라도 있으면 최초 연구 계획을, 비어 있으면 최초 후보 준비를 엽니다. 이 분기는 인증된 K의 유무만 세는 조건이 아닙니다. 최초 역할은 활성화까지의 미소비 초기화 사건도 읽고 수락된 결과로 소비합니다.

별도 프로세스에 인계됐는지 확인한다

대화가 끝나도 계속하려면 continue_authorized 대화 소실 정책과 현재 허가, 실제 예약·실행 경로가 필요합니다. pause 정책으로도 초기화는 가능하므로 활성화만으로 지속 운전을 단정하지 않습니다. operator status와 status --json을 읽고 시작 조건이 맞으면 operator start로 별도 연구 작업을 요청합니다.

반환 코드 0이나 예약 상태 Running 하나만으로 인계를 끝내지 않습니다. 예약의 Running에는 bootstrap도 포함될 수 있습니다. 문서가 정한 30초 시작 관측 구간 안에서 대상 저장소·인스턴스 ID의 실제 연구 명령과 현재 상태를 대조합니다. 이 30초는 연구의 종료 제한이 아닙니다. 이미 끝났다면 이번 시작의 종료 기록과 남은 의무를 읽습니다.

인계 보고에는 ID·저장소·workspace, 적용한 모델 제한, 관측 시각과 프로세스 근거, 감독 상태·주기, 지속 정책·허가와 남은 담당을 적습니다. 오류에 next_owner가 적혔다는 사실만으로 그 담당에게 실제 요청이 배정된 것은 아닙니다. 이 대화 이후에도 누가 어떤 입력과 조건으로 이어갈 수 있는지 확인해야 합니다.
