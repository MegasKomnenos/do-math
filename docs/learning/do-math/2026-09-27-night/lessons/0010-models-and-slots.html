10. 모델·프로필·작업 슬롯을 따로 이해하기

모델 요구를 먼저 정하고, 그 실행이 무엇 때문에 기다리는지 읽습니다.

어려운 과제에 필요한 모델이 바쁜 상황을 생각해 봅시다. 빈자리가 있다는 이유만으로 더 낮은 등급의 모델을 쓰면 원래 판단한 요구가 달라집니다. do-math는 과제의 요구로 모델을 정하고, 그 모델의 자리가 없으면 기다립니다. 연구 우선순위와 모델 등급도 다른 판단입니다.

난이도·중요도·역할 하한 중 높은 요구

후보 준비는 과제마다 난이도와 중요도, 구체적인 이유를 씁니다. 난이도는 새로운 전략이나 복잡한 조건 대조가 필요한 정도이고, 중요도는 잘못된 판단이 연구와 후속에 미치는 영향입니다. 둘 중 높은 등급과 역할별 최소 등급을 비교해 실제 등급을 정합니다. 짧은 일이라도 핵심 의미를 판정하면 중요도가 높을 수 있습니다.

현재 기본 대응은 상 gpt-6-astra, 중 gpt-5.6-sol, 하 gpt-5.6-terra이고 모델별 작업 슬롯은 3개입니다. 이는 이 설치본의 기본 운용 설정이며 모델의 실험적 성능 우위를 증명하는 표가 아닙니다. 인스턴스마다 tier_models, role_tiers, session_limits.work로 바꿀 수 있습니다. 같은 모델을 여러 등급에 배정하면 모델 이름 하나의 용량을 공유합니다. references/모델과-실행예산.md · 인스턴스별 기본 구성

작업 슬롯은 로컬 실행의 동시 점유다

작업 슬롯을 쓰는 역할은 연구 수행·보충 조사·작업 계약 검토·동일성 검토·목표 감사입니다. 시작을 예약한 뒤 starting·running·stopping 동안 점유하며 로컬 종료 확인 뒤 반환합니다. 누적 호출 횟수나 토큰·금액 한도가 아닙니다. 대기 과제가 살아 있는 프로세스를 계속 유지할 이유도 아닙니다.

후보 준비·연구 계획·의도 해석·운영 점검·유지보수와 설치 복구 AI는 운영 역할로서 작업 슬롯을 쓰지 않습니다. 작업이 꽉 차도 계획과 복구를 배정할 수 있게 한 구조입니다. 그러나 공급자 한도나 설정한 호스트 자원 한도는 운영 역할에도 적용됩니다. 정상 예약 감독은 모델을 호출하지 않습니다.

한 인스턴스에서 후보 준비와 연구 계획은 각각 하나, 진행 중 실행의 운영 점검은 대상 실행마다 하나, 같은 과제의 연구 수행도 한 번에 하나만 진행합니다. 서로 다른 과제와 독립 검토 자리는 해당 자원 조건 안에서 병렬 실행할 수 있습니다. 운영 역할에 모델 슬롯이 없다는 사실을 무제한 병렬 운전으로 읽지 않습니다.

프로필은 이름보다 많은 것을 고정한다

실행 프로필은 모델·어댑터·도구·입출력 한도·관찰 규칙·호스트 요구·구현 판본을 묶은 불변 능력 계약입니다. 참조는 {id, revision, sha256} 전부를 사용합니다. 프로필이 선언된 것과 실제 호스트 능력이 검증된 것은 다릅니다. 과제에 이미 고정된 프로필을 설정 변경으로 조용히 교체하지 않습니다.

작업 AI와 중앙 Lean에는 경과 시간만으로 끝내는 실행 기한이 없습니다. 운영 AI에는 call_timeout_seconds, 설치 복구에는 operator_timeout_seconds가 적용됩니다. 정지·권한 회수·필수 전제 변경과 수락된 처분은 시간 제한과 별개로 실행을 끝낼 수 있습니다. 중앙 형식 검사와 신뢰 환경 전환의 Lean 검사는 합쳐 인스턴스당 한 건만 진행합니다.

모델 이름이 claude: 또는 claude-로 시작하면 Claude 경로, 그 밖은 Codex 경로를 사용합니다. 모델 표기의 별칭과 전체 ID를 섞으면 슬롯이 별개 문자열로 계산될 수 있으므로 한 인스턴스에서는 통일합니다. 공급자가 실제로 보고한 모델과 사용량의 관측 범위도 따로 남깁니다.
