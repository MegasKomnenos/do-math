23. 외부 행동에서 성공·실패·불명을 구별하기

결과를 모르는 외부 요청을 안전한 후속 판단으로 넘깁니다.

원고 전송 요청을 보낸 뒤 네트워크가 끊겼다고 합시다. 상대가 받았는지 모르는 상태에서 다시 보내면 중복 제출이 될 수 있습니다. 로컬 오류가 외부 효과의 부재를 증명하지 않기 때문에 외부 행동에는 별도의 원장과 결과 대조가 필요합니다.

요청의 정확한 내용과 허가를 함께 고정한다

현재 구현의 외부 행동 경로는 허가된 HTTP 요청을 준비·전송·대조합니다. 요청자는 같은 논리 요청 ID, method·URL·body, 실제 grant와 목적을 제안합니다. 허가에는 허용 origin·method·path prefix·기간·크리덴셜 참조 등이 있을 수 있습니다. 비밀 값 대신 허용된 환경변수 이름을 기록합니다.

지원 method는 GET·POST·PUT·DELETE이고 GET·DELETE에는 비어 있지 않은 본문을 보내지 않습니다. URL의 사용자 정보·fragment·점 경로 조각은 허용하지 않으며 자동 리디렉션을 따르지 않습니다. 이 필드 검사가 외부 효과의 사용자 승인을 새로 만들지는 않습니다. 준비 때와 실제 전송 직전에 현재 허가를 대조합니다. references/공통-실행.md · 외부 행동을 제안하고 결과를 이어받는다

허가가 없으면 실행기는 요청과 필요한 질문을 보존하고 효과를 만들지 않습니다. 크리덴셜 부재도 해당 행동의 대기 사유이지 수학 입력의 결함이나 다른 계정을 사용할 허가는 아닙니다. 외부 요청을 적었다는 사실과 실제 전송은 별개입니다.

외부 원장이 기억해야 할 불확실성

상태읽는 뜻
prepared정확한 요청과 허가를 준비했다
running외부 실행이 진행 중인 상태다
confirmed결과를 확인한 기록이며 succeeded도 확인한다
failed알려진 실패이며 재시도 근거를 별도로 본다
unknown효과를 확정할 수 없다
cancelled취소 근거가 있는 상태다

전송 직전에는 전송 기록을 먼저 보존합니다. 그 뒤 timeout·통신 오류가 나면 효과가 없었다고 단정하지 않고 unknown으로 남깁니다. 현재 전송 코드는 2xx를 confirmed·succeeded=true로 기록합니다. 비성공 HTTP 응답도 효과 부재의 증거가 없다면 자동으로 안전한 실패가 되지 않습니다. scripts/do_math/external.py

unknown의 대조는 정확한 operation ID·요청 해시·멱등 키에 결박된 증거를 요구합니다. 재시도에는 효과가 없다는 확인 또는 유효기간 안의 검증된 멱등성 근거가 필요합니다. 멱등성은 같은 논리 요청을 반복해도 외부 효과가 중복되지 않는다는 성질입니다. 단순히 키를 붙였다는 사실만으로 상대 시스템의 그 성질이 증명되지는 않습니다.

모델 공급자 대기는 다른 문제다

공급자 한도에 걸린 모델 요청은 queue에 남고 dispatch_wait.kind=provider_limit과 재관찰 시각을 갖습니다. 같은 공급자의 작업·운영 역할 새 호출을 기다리게 하며, 허용 시각 뒤 실제 승인된 action 하나로 재관찰합니다. 별도 ping 모델을 반복 호출하지 않습니다. 모델 없는 wake 예약이 진입점을 깨워도 HOLD·사용자 정지·권한 검사가 먼저 적용됩니다.

공급자 한도가 풀렸다는 사실은 외부 HTTP unknown을 재전송할 근거가 아닙니다. 원장의 소유 대상과 불확실성이 다르기 때문입니다. 후속 보고에서도 준비한 요청, 실제 전송, 확인한 효과, 아직 모르는 효과를 나누어 남겨야 합니다.

전송 기록 뒤 timeout이 났고 상대의 수신 여부는 모른다. 다음 판단은?

정답과 해설

unknown으로 대조 — 통신 오류는 효과 부재를 증명하지 않는다. 정확한 요청에 대한 결과 대조와 재생 안전성 근거 없이 다시 보내지 않는다.
