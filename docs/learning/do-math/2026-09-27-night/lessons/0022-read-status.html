22. 상태·기록·시간을 같은 근거에서 읽기

한 snapshot의 저장 상태와 조회 순간의 현장 관측을 구별합니다.

“과제가 active인데 프로세스가 보이지 않는다”는 보고는 두 관측이 어느 시점과 대상을 말하는지부터 확인해야 합니다. active는 선택됐거나 수행 중인 과제 상태이고 실제 실행 여부는 실행 기록에서 봅니다. 저장된 snapshot과 조회 순간의 호스트 프로세스 관측도 정확히 같은 시각의 원자적 사진은 아닙니다.

status에서 다음 행동의 이유를 찾는다

status --json의 snapshot을 먼저 기록하고, operating_summary·status·goal_status를 함께 봅니다. 이어 tasks, questions·question_links, waiting_actions, dispatch_waits, budget, 활성 신뢰 환경과 academic_validation을 읽습니다. 기록 수를 성공 판정 수로 해석하지 않습니다. K 수, 형식 결과 수, 해설 수, 동일성 판정 수는 같은 값이 아닙니다.

capacity_waiting은 현재 미처리 요청들이 슬롯이나 호스트 용량을 기다리는 상태입니다. waiting은 공급자·입력·권한 등 다른 이유일 수 있습니다. 정확한 다음 행동은 대기 행의 종류·이유·소유자에서 읽습니다. 특정 요청의 고정 프로필과 현재 설정의 예산 요약이 다를 수 있으므로 설정 화면 하나로 요청의 조건을 덮지 않습니다. README.md · 현재 상태를 읽는다

query로 찾고 read로 정확한 기록을 읽는다

query는 여러 기록 가족을 하나의 목록으로 검색합니다. --related-to와 방향으로 관계의 이웃을 찾을 수 있습니다. 응답의 total·loaded·truncated·next_cursor를 함께 보고, 다음 페이지는 같은 조건과 cursor로 이어갑니다. 파일을 찾으려면 query --files를 사용합니다.

read --id는 복원된 논리 기록과 그 해시를 반환합니다. read --path는 실제 파일 바이트입니다. 큰 값은 내용 주소형 artifact에 저장되고 물리 기록에는 payload 참조가 있을 수 있으므로 둘의 표현과 해시는 다릅니다. null 자리와 payload 포인터를 보고 원문이 없다고 단정하지 않습니다. 레코드 조회는 정확한 artifact를 읽어 논리 값을 복원합니다.

$dmCli = '.agents/skills/do-math/scripts/do_math.py'
python $dmCli status --repository '<실제 저장소>' --instance '<실제 RI-ID>' --json
python $dmCli query --repository '<실제 저장소>' --instance '<실제 RI-ID>' --kind knowledge
python $dmCli read --repository '<실제 저장소>' --instance '<실제 RI-ID>' --snapshot '<조회 OID>' --id '<조회 ID>'

이 예시는 조회 명령의 모양이며 꺾쇠 안은 실제 값으로 바꿉니다. export는 기본적으로 research만 새 경로나 빈 디렉터리에 복사하고 --all일 때 runtime도 포함합니다. 내보낸 파일은 조회 사본이며 새 정본이 아닙니다.

시간은 관측 단위를 지킨다

과거 status --snapshot에서는 현재 호스트에만 관측 가능한 budget·pending_controls·provider_waits·operation_progress 등의 값이 null입니다. 과거에 관측하지 않은 값을 지금의 값으로 채우지 않습니다. timeline은 고정 snapshot의 실행 이력을 UTC와 지정 시간대로 내보냅니다. 기록하지 않은 과거 시각도 빈칸으로 남깁니다.

--include-operations는 workspace의 운영 단계 로그를 별도 단위로 포함합니다. 이 로그에는 원 파일 해시와 관측 시각이 붙지만 해당 연구 snapshot 안의 기록이 된다는 뜻은 아닙니다. 병렬 실행 2개의 시간이 각각 10분이라고 실제 경과 시간이 20분인 것은 아닙니다. 겹친 구간을 합계 경과 시간으로 사용하지 않습니다.

check는 저장·참조·상태 불변식과 artifact 해시를 검사합니다. 자연어의 올바른 뜻이나 새 수학적 타당성을 판정하지는 않습니다. 어떤 종류의 검사로 무엇을 확인했는지 범위를 붙여 결과를 읽습니다.

판단 연습

과거 snapshot의 budget 값이 null이다. 올바른 해석은?

정답과 해설

해당 관측을 제공하지 않는다. — 조회 순간의 호스트 관련 필드는 과거 snapshot에서 관측값을 제공하지 않는다. null을 0이나 당시의 정상 상태로 해석하지 않는다.
