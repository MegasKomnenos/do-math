12. 문헌을 검색 결과에서 연구 근거로 바꾸기

원문 회수·전사·가정 대조·계산을 각각 확인합니다.

논문에서 읽은 식을 계산해 반례를 얻었다고 합시다. 계산 코드가 맞더라도 분수의 분모나 첨자를 잘못 옮겼다면 그 결과는 논문의 오류를 입증하지 못합니다. 문헌을 근거로 쓰려면 “찾았다”, “읽었다”, “정확히 옮겼다”, “같은 가정에서 확인했다”를 차례로 구별해야 합니다.

현재 자료원의 지원 범위에서 시작한다

필요한 문헌 조사가 생기면 실제 세션에 scholarly 도구가 있는지 확인합니다. list_sources로 자료원과 구현 상태를 보고, describe_source에서 검색 문법·지원 기능·페이지 한도를 읽습니다. 도구가 허가됐다는 사실, 실행 설정에 연결됐다는 사실, 이번 세션에 실제 노출됐다는 사실은 다릅니다.

자료원을 정한 뒤 search로 찾고, 큰 결과는 extract로 후보를 읽고, 정확한 대상을 골라 fetch합니다. 이미 정확한 DOI나 식별자가 있으면 이를 지원하는 자료원에서 바로 fetch할 수 있습니다. 검색은 의식처럼 반복할 절차가 아니라 필요한 원자료를 찾는 수단입니다. 제목의 유사성만으로 판본과 대상을 확정하지 않습니다. references/학술자료-활용.md

실패 상태를 문헌의 부재로 바꾸지 않는다

검색 창의 0건, 접근 제한, 미구현 기능, 자료원 오류, 일부 component만 확보한 상태는 다릅니다. 429 응답은 문헌이 없다는 뜻이 아닙니다. 같은 입력으로 결과를 바꿀 근거 없이 즉시 반복하지 않고, 확보한 자료와 다음 재조회 조건을 남깁니다. 다른 자료원을 사용할 필요가 있으면 연구자가 다음 호출에서 명시적으로 선택합니다.

모델 공급자 한도와 scholarly 자료원의 한도도 서로 다른 대기입니다. 자료원 요청 실패를 모델 공급자 전체의 호출 금지로 해석하지 않습니다. scholarly가 구성돼야 하는데 도구 자체가 없으면 승인된 사용 의사를 다시 묻기보다 실행 구성·프로필·허가의 기술적 부족을 실제 근거와 함께 수리 대상으로 넘깁니다.

수식과 표는 실제 페이지를 읽는다

정의·가정·정리·수식 배치·표·각주가 결론을 바꾸면 짧은 검색 결과만 읽지 않습니다. 회수한 PDF·DjVu에서 배치가 중요하면 render=true로 페이지 이미지 참조를 만들고, 그 이미지 참조를 extract해 직접 봅니다. 이미지 파일이 생성됐다는 사실과 판독했다는 사실도 다릅니다.

첫째, 기호·분수·지수·행과 열을 원문과 대조합니다. 둘째, 반례나 계산이 원문의 변수 영역·순서·방향·가정을 만족하는지 확인합니다. 셋째, 정확히 전사한 정의로 독립 계산을 합니다. 전사가 잘못됐으면 원문 비판을 철회하고 실제 남는 문제만 구별합니다.

다음 실행에서도 읽을 수 있게 보존한다

보고에는 자료원, 실제 query 또는 target, 판본·범위, 응답 상태, 확보 component, 파일 경로·해시, 읽은 쪽·식, 미확인 범위와 재조회 조건을 적습니다. 실행별 scholarly-data/의 파일은 산출 회수를 거쳐 다음 역할의 입력으로 복원될 수 있습니다. scholarly://artifact/... 참조 하나가 다른 서버나 실행에서도 같은 바이트를 보장하지는 않습니다.

같은 원문을 다시 읽어 기존 주장의 오류를 발견했다면 원본 바이트를 고치는 대신 허용된 지식 개정 경로로 판단을 바로잡습니다. 실제로 그 주장에 기대었던 결과의 재검토도 연결합니다. 원자료의 동일성과 해석의 정확성은 다른 문제이기 때문입니다.
