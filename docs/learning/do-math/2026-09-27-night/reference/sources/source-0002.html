1# 개발 원칙
2
3do-math는 프리알파 프로토타입이다. 이 디렉토리는 현재 구현과 계약 하나만 지원한다.
4
5- 설계를 바꾸면 구현·호출부·스키마·테스트·예시·문서를 같은 변경에서 새 계약으로 교체한다. 구판 호환을 위한 이전 구현·이름 별칭·래퍼·구형 인자·무시되는 설정·버전별 분기·마이그레이션 경로를 남기지 않는다.
6- 과거 실험 인스턴스·저장 기록·산출물은 호환성 요구가 아니다. 새 계약으로 다시 초기화해 검증한다. 예전 자료를 읽기 위한 기본값 보충이나 자동 변환을 추가하지 않는다. 실제 실험 자료의 삭제는 해당 작업의 범위에 따라 처리한다.
7- 테스트도 현행 계약을 직접 구성한다. 구형 fixture나 인터페이스를 살리려고 제품 코드에 예외를 넣지 않는다. 폐기한 기능만 검사하는 테스트는 제거하고, 유지하는 기능의 검사는 새 계약에 맞춘다.
8- 현재 입력의 구조·참조·권한·증거·현재성 검사는 유지한다. 같은 연구 안에서 달라지는 과제·정책·프로필 판본과 실행 이력은 연구 의미의 일부이며, 소프트웨어 구판 호환성과 구별한다. 형식 검사는 저장·입력 경계에 모으고 내부 로직에서 제품 버전을 반복 확인하지 않는다.
9- 사용자가 구체적인 대상과 기간을 지정해 호환성을 명시적으로 요구한 경우에만 예외를 둔다. 미래 사용자나 이전 기록의 존재를 추측해서 호환 계층을 만들지 않는다.
10- 두 모듈 이상이 같은 규칙을 쓰면 정본 하나를 참조하고, 같은 규칙을 모듈 안에서 다시 구현하지 않는다. 검사 함수는 하나를 두고 생산자와 수신자 양쪽에서 실행한다. 정본의 목록, 쓰는 방법, 새 정본을 둘 곳은 `scripts/이음새-정본.md`가 정한다.
11
12시험을 언제 무엇으로 돌리고 새 시험을 어떻게 쓰는지는 `scripts/tests/시험-지침.md`를 따른다. 실행 도구는 `python scripts/run_tests.py`다. 구조 검사는 `python scripts/probe_cli.py --skill-only`를 사용한다. graphify 그래프 갱신은 상위 AGENTS.md에 따라 명시적인 갱신 요청이 있을 때만 수행한다.
