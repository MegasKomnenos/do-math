1# 초기화에서 연구 활성화까지
2
3현행 검사·저장·정비 경계는 [초기화 효율과 정비](초기화-효율과-정비.md)에 정의한다. 등록은 머신이 공유하는 툴체인 기록을 인스턴스에 결박하고, 전환 뒤 `trust_activate`가 현재 판본 식별과 지문을 그 기록과 대조해 활성화한다. 이 차이를 등록 성공과 환경 활성화 성공의 보고에 반영한다. 큰 payload의 원문을 읽을 때에는 물리 파일의 `payloads` 참조와 논리 레코드를 구별한다.
4
5이 문서는 사람 운영자가 인스턴스의 원입력·승인·프로필·신뢰 환경을 공개 CLI로 연결하는 절차다. `init` 성공은 입력을 보존한 상태이며 연구 시작의 승인이 아니다. 아래 JSON은 요청 형식을 보여 주는 예시다. 목표·정책·허가 범위·만료 시각·환경과 증거는 실제 사용자가 정하거나 실제 측정에서 얻어야 한다. 예시를 문서에서 읽었다는 사실은 승인이 아니다.
6
7이 절차는 README의 [초기화 완료 단계](../README.md#activate-instance)에서 이어진다. 선행 읽기는 SKILL.md의 [사용자 대화 진입 절차](../SKILL.md#이-문서를-읽는-실행의-역할)를 따른다.
8
9아래 명령은 저장소 루트에서 실행한다. `$dmRepository`와 `$dmInstance`를 실제 값으로 정하고 현재 디렉터리는 바꾸지 않는다. `--file`은 UTF-8 JSON 객체 하나를 읽는다. 요청마다 반환의 `effect`를 확인한다. `accepted=true`만 있고 처리가 대기 중이면 해당 요청이 적용될 때까지 다음 의존 단계를 진행하지 않는다.
10
11```powershell
12$dmCli = '.agents/skills/do-math/scripts/do_math.py'
13$dmRepository = '.skill-workspace/my-math/repo'
14$dmInstance = 'RI-실제-init-응답-ID'
15python $dmCli status --repository $dmRepository --instance $dmInstance --json
16```

18## 1. 보존된 입력과 설정을 확인한다
19
20README의 `init`으로 생성한 ID와 첫 snapshot을 사용한다. `query --files`로 등록된 경로를 찾고 `read --path`로 정확한 snapshot을 읽을 수 있다. 연구 저장 파일은 직접 고치지 않는다.
21
22```powershell
23python $dmCli query --repository $dmRepository --instance $dmInstance --files --prefix research/ --limit 1000
24python $dmCli query --repository $dmRepository --instance $dmInstance --files --prefix runtime/ --limit 1000
25```
26
27CLI의 JSON 조회 결과는 최상위 `result` 안에 있다. 그 안의 `next_cursor`가 있으면 같은 조건에 `--cursor`를 추가해 다음 쪽도 읽는다. 각 조회의 `result.snapshot`을 후속 `--snapshot`에 지정하면 같은 판본을 대조할 수 있다. 경로 조회의 실제 `result.items[].path`를 복사해 다음처럼 읽는다.
28
29```powershell
30python $dmCli read --repository $dmRepository --instance $dmInstance --snapshot '<조회 snapshot>' --path '<조회한 lifecycle 또는 config 파일 경로>'
31```
32
33원입력은 `lifecycle.immutable_input`의 `text`, `sha256`, `bytes`에 하나의 정확한 표현으로 보존된다. 모델 상한·새 연구·절차 요구도 원문의 일부다. 목표 문장보다 요청이 넓으면 생성 때 `--request-text-file`로 전체 원문을 별도로 넣는다. `text`는 사용자가 준 문자열의 코드 포인트열이고, 해시와 크기는 그 문자열의 UTF-8 바이트에 대해 계산한다. 이름과 원문을 NFC로 바꾸거나 Base64 원문을 별도로 만들지 않는다. 이 세 필드는 바이트 보존을 증명하지만, 해석·검토·승인이 그 원문을 실제로 사용했다는 뜻은 아니므로 뒤 단계의 `user_request.text`와 소비 근거를 별도로 대조한다.
34
35설정 변경이 실제로 필요하면 승인된 변경만 `configure --config-file`로 적용한다. 그대로 쓸 기본값은 뒤의 채택 요청에서 현행 설정으로 결박한다. 이미 사용자에게 채택받은 값을 다시 새로운 의미 승인 대상으로 만들 필요는 없다. 위임 범위에서 운영자가 선택한 초 단위 관찰값과 허가 기간은 원요청의 근거와 선택 이유를 운영 기록에 남긴다. 그 선택을 사용자가 직접 지정한 값이라고 표현하지 않는다. 예시의 만료일이나 수치를 승인 근거 없이 그대로 복사하지 않는다. 모델·effort·용량·관찰 window가 바뀌면 그 변경으로 생성된 프로필 판본을 새로 조회해야 한다.
36
37프로필 조회·채택 전에 `tool_review_window_seconds`와 `self_check_response_window_seconds`가 설정에 있는지 확인한다. 두 값에는 제품 기본값이 없다. 빠져 있으면 해당 연구에서 사용할 양의 초 값을 확정하고, 두 키와 확정한 값을 담은 JSON 객체를 `observation-settings.json`으로 저장한다. 이미 승인된 값이 있으면 그 값을 재사용한다. 주기·사건 관찰의 `observation_interval_seconds`도 유효해야 한다. 이 단계는 프로필의 관찰 설정을 준비하는 단계이며, 아직 생성되지 않은 과제의 개별 관찰 규칙을 요구하지 않는다.
38
39```powershell
40python $dmCli configure --repository $dmRepository --instance $dmInstance --config-file observation-settings.json
41```
42
43적용 응답을 확인한 뒤 4단계에서 새 프로필을 조회하고 `operation=probe`로 능력을 관측한다. 같은 4단계의 채택 요청으로 해당 프로필과 현행 설정을 채택한다. 누락된 관찰 설정은 역할·프로필 ID·필드로 표시되며 채택 또는 활성화를 막는다. 이 경우 같은 인스턴스에서 설정을 보충하고 프로필 조회부터 다시 진행한다. 원입력과 과거 프로필은 보존되며 이미 유효한 사용자 승인·권한을 새로 만들지 않는다.

114## 3. 초기화 권한과 연구 권한을 나눈다
115
116초기화 grant는 `intent_interpretation`·`maintenance` 안의 역할 범위, 명시적 만료와 `reuse="reusable"`을 요구한다. 두 역할은 운영 역할이므로 작업 슬롯을 예약하지 않으며, grant에 예산 종류를 적는 필드는 없다. 연구 grant는 다른 ID를 사용한다. 초기화 grant의 ID를 연구 grant로 다시 채택하지 않는다.
117
118다음 만료 시각은 형식 예시다. 실제 허가 기간으로 바꾸고, 역할 목록과 재사용 범위를 사용자가 승인한 대로 정한다. `task_ids=[]`는 열거한 역할의 모든 과제를 허용하므로 특정 과제로 제한할 때에는 실제 과제 ID를 넣는다. HTTP 등 외부 효과는 별도 grant가 필요하다.

160초기화 중 grant를 등록하는 일은 연구 계획이나 연구 과제를 열지 않는다. 이 단계에서는 이후 활성화에 사용할 서로 다른 초기화·연구 허가를 보존하고 채택할 뿐이다. 최초 후보 준비 또는 연구 계획은 원입력 해석·독립 검사·신뢰 환경·프로필 능력·복구를 포함한 활성화 관문 전건이 통과해 lifecycle이 `active`가 될 때 열린다. 활성화 뒤 grant가 추가·교체되면 그 사용자 결정의 `decision_id`가 재계획 사유가 된다. 새 `grant_id`는 이후 실행을 허가할 수 있는 권한 참조이지 계획을 연 근거 ID가 아니다.

162## 4. 실제 프로필을 조회하고 능력을 관측한다
163
164프로필 참조는 등록된 기록 본문의 `id`, `revision`, `sha256` 세 값을 그대로 묶은 객체다. 조회 항목 바깥의 `sha256`은 조회 표현의 해시이므로 참조의 해시로 복사하지 않는다. 아래 조회는 현재 설치·설정에서 생성된 실제 프로필을 얻는다.
165
166등록부에는 설정 변경 전의 프로필도 남는다. 1단계의 연구 기록 조회에서 `research/role_profile_refs/state.json`의 `record`를 읽는다. 그 객체의 역할 이름별 배열에는 사용할 수 있는 프로필의 `id`, `revision`, `sha256` 참조가 들어 있다. 프로필 ID는 본문 해시에서 생성되므로 같은 ID로 다른 판본을 등록할 수 없다. `revision`도 해당 불변 기록의 값과 대조하는 참조 요소이며, 설정 변경 때 같은 ID의 revision만 올리는 갱신 번호로 사용하지 않는다. 허용 목록이 가리키는 현행 판본 중 사용할 프로필을 고르고, 보관된 프로필 전건을 채택 목록에 넣지 않는다. 과제에 이미 고정된 프로필은 설정 변경만으로 교체되지 않으며, 새 프로필을 쓰려면 해당 과제를 재준비하고 독립 계약 검토를 받아야 한다.
167
168```powershell
169$dmPage = (python $dmCli query --repository $dmRepository --instance $dmInstance --kind execution-profile --limit 1000 | ConvertFrom-Json).result
170if ($LASTEXITCODE -ne 0 -or $null -eq $dmPage -or $null -eq $dmPage.items) { throw '프로필 조회 실패: CLI 종료 상태와 반환 본문을 확인한다.' }
171$dmProfileRecords = @($dmPage.items.record)
172$dmCursor = $dmPage.next_cursor
173while ($dmCursor) {
174 $dmPage = (python $dmCli query --repository $dmRepository --instance $dmInstance --kind execution-profile --limit 1000 --cursor $dmCursor | ConvertFrom-Json).result
175 if ($LASTEXITCODE -ne 0 -or $null -eq $dmPage -or $null -eq $dmPage.items) { throw '프로필 다음 쪽 조회 실패: CLI 종료 상태와 반환 본문을 확인한다.' }
176 $dmProfileRecords += @($dmPage.items.record)
177 $dmCursor = $dmPage.next_cursor
178}
179$dmProfileRecords | Select-Object id, revision, sha256, role, actor_kind, ai
180$dmProfileRecords | ConvertTo-Json -Depth 20
181```
182
183쪽이 나뉘면 전건을 회수한다. 조회 cursor는 첫 쪽의 snapshot에 결박되어 다음 쪽도 같은 판본을 읽는다. 사용할 역할·모델·effort·도구·관찰 모드·용량을 본문에서 확인한 뒤 채택할 프로필을 고른다. 같은 역할에 여러 모델 판본이 있으므로 첫 행을 임의 선택하지 않는다. 초기 해석용 프로필은 현행 설정의 역할 등급·모델 선택과 일치하는 `intent_interpretation` 프로필이다. 아래 `$dmChosenIds`는 그 검토를 마친 실제 ID 목록으로 바꾼다.
184
185최초 의도 해석 프로필은 다음 공개 조회의 `result.selection.profile_ref`로 얻는다. 역할 하한·과제 평가를 실제 배정과 같은 규칙으로 계산한다. 과제에 사용할 프로필은 `--task TK-...`도 지정한다. 조회는 실행이나 채택을 수행하지 않는다.
186
187```powershell
188python $dmCli select-profile --repository $dmRepository --instance $dmInstance --role intent_interpretation
189```
190
191선택한 ID의 기록이 역할별 허용 참조와 `id`·`revision`·`sha256` 모두 일치하는지도 이번 프로필 조회의 snapshot에서 다시 검사한다. 누락되거나 다른 판본이면 probe와 채택으로 진행하지 않는다.
192
193```powershell
194$dmChosenIds = @('EP-실제로-채택한-ID')
195$dmSelectedProfiles = @($dmProfileRecords | Where-Object { $_.id -in $dmChosenIds })

238## 5. 툴체인 기록을 등록한다
239
240`setup_lean.py --verify-only --trust-file <새 경로>`는 설치된 환경의 툴체인 기록을 만들거나 확인하고, 그 기록의 현재 기준으로 등록 요청을 새 파일에 쓴다. Lean이 없으면 먼저 인자 없는 `setup_lean.py`로 설치한다. 설치에도 `--trust-file`을 줄 수 있다. 준비 표지나 `--inspect-only`의 판본 식별만으로 등록 요청을 만들지 않는다.
241
242```powershell
243$dmTrustFile = '.skill-workspace/my-math/06-trust-register.json'
244$dmRecorded = python .agents/skills/do-math/scripts/setup_lean.py --verify-only --trust-file $dmTrustFile | ConvertFrom-Json
245if ($LASTEXITCODE -ne 0 -or $dmRecorded.status -ne 'recorded') { throw '툴체인 기록 실패: 출력의 status와 reason을 확인한다.' }
246python $dmCli trust --repository $dmRepository --instance $dmInstance --file $dmTrustFile
247```
248
249같은 판본의 기록이 이미 있고 현재 지문이 그 기록의 현재 기준과 같으면, `setup_lean.py`는 새로 컴파일하지 않고 그 기록을 다시 사용한다. 기록이 없으면 판정 파일 전건의 지문과 내용 해시를 계산한다. 그다음 구성된 명령으로 `import Mathlib`, 자연수 덧셈의 항등원, 실수 `norm_num` 예제를 소유된 Windows Job에서 컴파일한다. 임의의 시간 상한으로 컴파일을 자르지 않으며, 진행은 증거 디렉터리의 `operations/live/`에서 볼 수 있다. 컴파일이 실패하면 기록을 만들지 않고 `status=failed`, 종료 코드 1로 끝난다. `--command-file`로 프로젝트 없는 Lean 명령을 지정하면 자연수 항등원과 `True`의 core 예제를 검사한다.
250
251`status=rerecord_required`는 판정 파일 전건의 내용 해시가 같은 판본의 기존 기록과 같은데도 그 기록을 다시 사용할 수 없는 상태다. 원인은 둘 중 하나다. 파일 메타데이터가 그 기록의 마지막 기준 항목(현재 기준)과 달라졌거나, 현재 기준에 대한 전수 점검이 `mismatch`를 남긴 뒤 파일을 복구해 내용이 다시 같아졌다. 설치 명령은 기존 기록에 기준을 덧붙이지 않는다. 사용자나 운전자가 [초기화 효율과 정비](초기화-효율과-정비.md)의 `지문 불일치와 재기록`에 따라 `--rerecord` 여부를 정한다.
252
253등록 요청은 `operation`, `toolchain`, `allowed_axioms`, `toolchain_record`, `binding` 다섯 필드만 갖는다. `toolchain`은 툴체인 기록의 판본 식별과 같은 객체다. `toolchain_record`는 기록 파일의 절대 경로와 기록 ID이고, `binding`은 결박할 기준 항목의 번호와 그 항목의 지문 다이제스트, 내용 해시 다이제스트, 대표 검사 요약 해시다. `allowed_axioms`는 `propext`, `Classical.choice`, `Quot.sound`다. 생성 경로는 새 파일이어야 하며 요청을 손으로 조립하지 않는다.
254
255등록은 툴체인 기록 파일을 읽는다. 기록의 ID와 판본 식별이 요청과 같고, 요청이 결박한 기준 항목의 다이제스트가 기록의 해당 항목과 같으며, 현재 기준의 대표 검사가 성공했고 현재 기준에 대해 `mismatch`로 끝난 전수 점검 결과가 없을 때만 등록한다. 설치 파일은 읽지 않는다. Lake가 구성한 검색 경로 `toolchain.project.search_paths`가 Lean 설치와 Lake 프로젝트 밖에 있으면 등록을 거부한다. Lean 관련 검색 경로 환경 변수는 호스트에서 상속하지 않는다.
256
257대표 검사의 source·명령·출력·종료 코드·시각은 툴체인 기록에 있고, 인스턴스는 그 요약 해시를 결박한다. 인스턴스의 환경 기록과 등록 요청에는 설치 파일 목록이 들어가지 않는다. 한 머신의 여러 인스턴스는 같은 툴체인 기록을 함께 등록할 수 있으며, 등록할 때 지문이나 내용 해시를 다시 계산하지 않는다.
258

281## 6. 최초 해석·독립 검사·실제 적용을 확인한다
282
283초기 원입력의 해석·독립 검사가 기술적 실행 실패, 제출 처리 실패 또는 실행기 소실로 끝나면 실패 실행과 원입력을 보존하고 유지보수 진단을 요청한다. 진단은 현재 초기화 권한이 허용할 때만 실행된다. `retry` 판정을 낸 유지보수 실행이 종료되고 그 판정이 수락되면 중앙은 같은 원입력·활동의 후속을 한 번 처리한다. 필요한 권한이나 자료가 없으면 그 부족과 다음 담당자를 남기고 기다린다.
284
285운전자가 원인을 해소한 뒤에는 보류된 action ID를 `request --retry-action AC-... --request-id UC-...`에 지정해 명시적으로 재시도할 수도 있다. 실행기는 자동 진단 후속과 공개 재시도 모두에서 전 실행의 로컬 종료·예약 회수, 원입력·활동 계보, 현재 초기 운영 권한·채택 프로필을 확인한다. 일반 `resume`은 이 실패를 재시도하지 않는다. 정상 종료한 native 최종 응답이 정확한 원문·실행 근거와 함께 보존돼 있으면 그 응답을 중앙 접수·편입에 재사용한다. 이 경우 새 모델 실행을 만들지 않으며 원 실행의 종료 시각·원 결과 참조·실패 이력을 보존한다. 재사용 조건을 충족하는 정상 응답이 없으면 같은 활동을 잇는 새 실행을 배정한다. 기존 봉인 후보를 다른 final로 대체하거나 오류·중단 응답을 정상 응답으로 취급하지 않는다. 새 입력으로 원문을 대체하거나 인스턴스를 다시 만들 필요는 없다.
286
287초기 프로필과 운영 grant가 채택되고 능력 관문을 통과하면 초기 원입력의 `intent_interpretation`이 열린다. `run`이 해석과 별도 검사 실행을 처리한다. 의도 해석 AI는 원문 범위를 `import_units`에 전건 배정하며 각 단위의 payload를 해당 종류의 저장·적용 영역에 연결한다. 이 영역을 payload의 소유자라고 부르며, 헌장·권한·설정 등 각 종류의 적용을 담당한다. 질문이 남아 있어도 확인 가능한 범위의 독립 검사는 생략하지 않는다.
288
289차단 질문이 남은 해석은 그 질문의 답변을 기다리며 같은 원문으로 반복 실행하지 않는다. 답변이 검사·승인·적용되어 해당 차단 질문이 모두 해소되면, 원문과 해석 계보를 유지한 재해석에서 답변을 반영한다.
290
291정상 종료한 최종 응답의 JSON·출력 형식 오류는 원문과 중앙 검사 결과를 보존해 같은 의도 해석 역할의 제한된 수리로 연결한다. 수리가 한도에 이르면 초기화 권한이 허용하는 유지보수가 원 실패를 진단한다. 유지보수의 `retry` 판정은 같은 의무에 한 번의 후속 수리를 열고, `wait` 또는 후속 수리의 재실패는 원인과 소유자를 보존해 기다린다. 새 권한을 만들거나 초기화에서 허용하지 않는 운영 점검 역할을 실행하지 않는다. 응답을 정상 접수한 사실만으로 사용자 승인·답변 대기를 해소하지 않는다.
292
293질문에는 `input --text` 또는 `input --file`과 실제 `--responds-to QU-ID`로 답한다. 해당 답의 수입·독립 검사 뒤 해소된 질문만 닫힌다. 답변은 별도의 grant를 자동 생성하지 않는다.
294
295```powershell
296python $dmCli input --repository $dmRepository --instance $dmInstance --file actual-answer.txt --responds-to QU-실제-질문-ID
297python $dmCli run --repository $dmRepository --instance $dmInstance --until-active
298```
299
300독립 검사가 승인해도 사용자 권한이 필요한 payload의 적용은 별도다. 검사된 수입 기록에서 `id`, `sha256`, `check.sha256`, 비어 있지 않은 payload 전건의 `unit_id`와 정규 의미 해시를 확인한다. 이미 승인된 기록과 동일한 의미·권한이면 그 승인 근거를 재사용한다. 새로운 목표·허가를 예시나 모델의 추천으로 승인하지 않는다.
301
302현행 공개 CLI는 승인 JSON을 한 번 읽은 payload와 같은 정확한 원문으로 control에 전달한다. `decision`의 `kind=import_approval`은 이 경로에서 `apply_import_control`로 간다. 먼저 같은 snapshot에서 검사된 수입을 조회하고 정확한 record를 읽는다.

304```powershell
305python $dmCli query --repository $dmRepository --instance $dmInstance --kind intent_imports --limit 1000
306python $dmCli read --repository $dmRepository --instance $dmInstance --snapshot OID-위-조회-응답의-snapshot --id IM-실제-조회-ID

336적용기는 사용자 출처, 승인 종류, 수입 묶음·검사·unit 해시의 정확한 일치와 비어 있지 않은 승인 원문을 확인한 뒤 그 봉인 묶음만 적용한다. 적용 뒤 수입 record와 그 안의 검사·적용 결과를 위 조회로 읽는다. 이를 위해 초기 원문 해석이나 독립 검사를 다시 열지 않는다. 반대로 하나라도 달라지거나 원문이 없으면 적용되지 않는다. 해시를 계산하거나 기록에서 회수하는 행위는 사용자 결정이 아니다. 내부 함수를 직접 호출하거나 저장 JSON을 편집해 관문을 우회하지 않는다.
337
338정확한 원문 의미에도 같은 확인이 필요하다. 초기 입력은 `immutable_input.text`의 코드 포인트열과 그 UTF-8 바이트의 해시·크기로 하나만 보존하며 NFC 사본이나 Base64 중복 원문을 만들지 않는다. 이 보존만으로 초기 해석·원문 피복·독립 검사·승인이 그 원문을 실제로 읽었다고 보증할 수는 없다. `user_request.text`로 제공된 값과 각 소비자가 사용한 원문을 대조해, 코드 포인트 차이가 뜻을 바꾸는 입력도 같은 원문에 결박됐는지 확인한다.
339
340완료는 `active_trust_environment`의 존재 하나가 아니라 초기화 관문 전건과 실제 수입 적용 기록으로 판단한다. 미완료 항목은 lifecycle 기록·가용성·대기 요청에서 확인한다. 전건을 통과한 활성화가 lifecycle을 `active`, 실행 상태를 `ready`로 바꾸며, `knowledge` 기록군에 보존된 기록이 하나라도 있으면 최초 연구 계획을, 비어 있으면 최초 후보 준비를 연다. 이 분기는 사용 가능한 K만 세는 조건이 아니다. 기록의 존재는 `query --kind knowledge`로 확인한다. 이 분기는 기록의 검증 통과를 뜻하지 않으며, 수학적 사용 가능성은 해당 기록의 형식 결과·동일성 판정·현재성으로 따로 판단한다. 초기화 중 앞서 등록한 grant 자체는 이 작업을 열지 않는다.
341
342활성화 때까지 보존된 미소비 초기화 사건은 이 최초 역할의 `event_refs`에 함께 배정한다. 후보 준비가 진행 중이라는 이유만으로 같은 초기화 사건을 다시 계획에 배정하지 않는다. 사건은 그 고정 입력을 읽은 응답이 수락될 때만 소비한다. 이후 새 사용자 결정이나 전제 상실은 별도의 사건으로 처리하며 이미 시작한 입력에 덧붙이지 않는다.
