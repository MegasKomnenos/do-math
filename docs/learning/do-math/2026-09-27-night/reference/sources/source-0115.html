1"""Shared test fixtures: synthetic inputs, process helpers and shared starting states.
2
3All authority and persistence still pass through the engine. The adapter and
4Lean facts here are synthetic test evidence. They do not establish host
5capabilities, a real compiler result, or approval by the actual user.
6
7Fixture modules
8===============
9A test module takes its fixtures from these modules, never from another test
10module. Each module's docstring lists what it holds.
11
12- ``research_fixtures`` (this module): inputs every area uses (task
13 candidates, review outputs, charters and their approval, trust environments,
14 observation rules, clocks and batches), the in-process ``git_init``,
15 ``run_cli`` and ``cli_result``, public activation (``activate``) and the
16 shared starting states below.
17- ``state_fixtures``: the validated synthetic active state (``active_instance``,
18 ``active_repository``, ``start_active_copy``) and the owner-loop helpers
19 (``owner_calls``, ``start_model_call``).
20- ``engine_fixtures``: engine doubles over in-memory state (``FakeEngine``,
21 ``routing_engine``, ``context_engine``) and Git-backed engine start states
22 (``start_submission_history``, ``start_query_repository``).
23- ``runner_fixtures``: ``ScriptedRunner`` and the role outputs it writes.
24- ``purpose_fixtures``: the purpose scenario (``PurposeRunner``), its harnesses
25 and the builds that drive it.
26- ``record_fixtures``: records for pure domain functions (governance, task
27 contracts, submissions).
28- ``knowledge_fixtures``: knowledge candidates and their synthetic formal evidence.
29- ``review_fixtures``: identity review doubles, cycles and harnesses.
30- ``provider_fixtures``: provider adapters, host resources and external services.
31
32A fixture that one test module uses stays in that module as a module function.
33Before a second module uses it, it moves to the fixture module of its area.
34
35Shared starting states
36======================
37
38Building an active instance through the public path (``activate``: several
39controls plus two interpretation executions) costs tens of seconds, and a Git
40or CLI child process costs a noticeable fraction of a second. A test whose
41subject comes after that path starts from a copy of a state built once per
42process instead.
43
44What to use
45-----------
46``restore_template(build, **parameters)`` returns ``(root, value)``. The first
47call in a process runs ``build(root, shared, **parameters)`` once. Every call,
48the first included, then gives a fresh copy of exactly the bytes that build
49left under ``root``: Git objects and refs, the workspace with its ``runs/``
50outputs and the control inbox, as the product published them. ``value`` is a
51deep copy of what the build returned. Every build puts the repository at
52``root / 'repository'`` and the workspace at ``root / 'work-0'``. These builds
53are shared (keywords in parentheses):
54
55- ``state_fixtures.active_instance`` (``config``, ``external_policy``,
56 ``review_policy``): the validated synthetic active state assembled with
57 ``engine_fixtures.FakeEngine``, without interpretation executions;
58 returns the instance ID.
59- ``activated_instance`` (``goal``, ``config``, ``external_policy``,
60 ``review_policy``): public ``initialize`` plus ``activate``, the published
61 state before the first research step; returns the instance ID.
62- ``engine_fixtures.initialized_instance`` (``goal``, ``config``): the public
63 ``initialize`` alone; returns the instance ID.
64- ``purpose_fixtures.solved_instance`` (``criteria``): public activation driven
65 by the purpose scenario to the mathematical solution, with academic
66 requirement ``writeup`` approved first when ``criteria`` is a list; returns
67 ``{'instance_id', 'head', 'work_order'}``.
68- ``purpose_fixtures.purpose_state`` (``config``, ``until``,
69 ``review_policy``, ``external_policy``, ``signed``): the synthetic active
70 state driven until task ``A``'s work is queued (``until='prepared'``) or its
71 identity review opens (``'review'``); returns the instance ID.
72- ``purpose_fixtures.assessment_preparation_instance`` (``config``): two
73 academic tasks of requirement ``r`` awaiting model assessment; returns the
74 instance ID.
75
76The other builds serve one test module each and stay there, each with its
77state in its docstring: ``requirement_change_instance`` (``test_academic_engine``),
78``cli_instance`` (``test_cli``), ``created_instance`` (``test_cli_advanced``),
79``plan_ready_instance`` (``test_currentness``), ``efficiency_instance``
80(``test_engine``), ``overflowed_maintenance`` (``test_input_recovery``),
81``rejected_assessment_instance`` (``test_model_assessment_flow``),
82``reviewed_task``, ``parked_failed_plan`` and ``paused_limited_recovery``
83(``test_research_recovery``), ``ready_work`` (``test_session_scheduler``),
84``waiting_action`` (``test_stop_flags``) and ``prepared_tasks``
85(``test_submission_boundaries``).
86
87Then ``ResearchEngine(root / 'repository', instance_id, runner=..., formal_verifier=...)``
88with a new runner. ``purpose_fixtures.ActivatedPurposeHarness`` wraps the first
89two as ``make_active`` and ``make``. ``test_engine.EngineTests.active`` is the
90plain form.
91
92Two process helpers replace a child process where the process is not examined:
93``git_init(path)`` for ``git init -q <path>`` and ``run_cli(*arguments, cwd=...)``
94for ``python do_math.py *arguments`` (a ``CompletedProcess`` with text output).
95
96Rules of a copy
97---------------
98- ``root`` is the same path for every copy of one template; that keeps the
99 absolute paths in the state, and the hashes over them, true. A call replaces
100 the previous copy, so a test finishes with one engine before asking for the
101 next. A test may add instances to the copied repository itself.
102- Parameters are JSON values, and every value that shapes the built state is
103 one: goal, config, policies. Set configuration here rather than with a later
104 ``configure`` control, which makes new profile editions that need new
105 capability evidence. Defaults count, so omitting one names the same template.
106- Process-local engine state is not in a copy; set it on the new engine:
107 ``_task_readiness`` is empty until ``run`` (call ``_refresh_readiness()`` to
108 read it before), and clock or method patches (``lifecycle_clock``,
109 ``_solution_basis``) apply to the object they were set on.
110- A template lives in one process and is never reused from disk: it carries
111 the installed edition, grant expiries (one day after the build) and the
112 clock high-water. A test whose rule depends on time elapsed since the build
113 uses the public path.
114- The build runs inside the first test that asks for it, and a failed build
115 fails every later test that asks for the same template.
116
117Writing a build
118---------------
119``build(root, shared, **parameters)`` creates everything the state names under
120``root``, except files whose stat fingerprint the state records, such as
121``trust_fixture`` toolchains and records: a copy gets a new creation time, so
122those go under ``shared``, which is never copied or cleared and must only be
123read afterwards. A deeper state is a build that starts from a ready build on
124its own ``root`` (for example ``activated_instance(root, shared, ...)``) and
125then drives an engine with a scripted runner; it returns whatever the tests
126need (instance IDs, a task's copy before a change, an execution ID). End the
127build where no execution is unfinished and nothing is reserved: an executor
128started on the copy recovers every unfinished execution. A test that needs a
129running call copies the state before it and starts the call itself. Formal
130checks on the synthetic state need ``lean_command=list(state_fixtures.ACTIVE_LEAN_COMMAND)``
131in its config; public activation registers the configured command itself.
132
133When to keep the public path or the child process
134--------------------------------------------------
135Keep the public path when the test's subject is that path: initialization,
136activation gates, the interpretation check, probes or trust registration
137during initialization, or the end-to-end connection the dedicated tests keep
138(``test_engine.EngineTests.test_public_initialization_reaches_active_with_distinct_interpretation``,
139``test_engine.PublicGitFlow.test_public_activation_work_receipt_assessment_and_next_plan``, and
140the ``purpose_fixtures.solved_instance`` build, which ``test_purpose_engine.SolvedPurposeTests``
141reads).
142Keep it too when the test patches or counts something during activation, or
143reads process-local engine state activation leaves behind. The check: if
144activation broke while still publishing the same final state, should this
145test fail? If yes, it examines the path.
146
147Keep the child process when the process is the subject: exit codes as the
148shell sees them, stdout/stderr encoding, ``pythonw``, Windows Jobs, owner
149identity of another process, background or detached processes, and the
150interpreter's start-up (imports, ``sys.path``, installation freezing). A lock
151held by another descriptor in the same process conflicts as across processes
152(``file_io.os_lock``), so lock contention alone does not need a child.
153
154When a scenario may stop early
155------------------------------
156A ``drive``/``run`` loop may stop at the first state in which every asserted
157value is final: its predicate is what the assertions read. Before stopping
158early, confirm that nothing after that point adds to an asserted count
159("exactly N reviews") and that no fixture check that only runs later is lost
160(a scripted role that raises on a wrong input is a check). Drive to the goal
161when the goal judgment is asserted, is the test's stated claim (its name or
162docstring), or feeds such a fixture check.
163"""

255class StateStore:
256 """The persisted head of an in-memory engine double.
257
258 It implements the repository calls an in-memory engine reaches: ``load``
259 reads the engine's current state as that head's published state,
260 ``published_state`` holds no cached state (so ``_save`` always publishes),
261 and ``save_with_state`` publishes a candidate as the next head and keeps a
262 copy in ``published``. It has no Git directory (``git_dir`` is None), so no
263 process cache records its reads. Any other repository use fails as it would
264 without a store.
265 """
266 git_dir = None

270 self.published = []

273 return None

301def read_fixture_context(prompt, workspace):

303 from do_math.context_store import read_source
304 value = json.loads(prompt.split('--- CANONICAL INPUT CONTEXT ---\n', 1)[1].split('\n--- OUTPUT JSON SCHEMA ---', 1)[0])
305 def read(reference):
306 result = read_source(workspace, reference, limit=max(1, reference['bytes']))
307 if result['status'] != 'ok' or result['truncated']:
308 raise AssertionError('Supplied context source could not be read exactly: ' + repr(result))
309 contents = json.loads(result['bytes'])
310 for token in reference.get('json_pointer', '').strip('/').split('/') if reference.get('json_pointer') else []:
311 contents = contents[int(token)] if isinstance(contents, list) else contents[token]
312 return contents
313 for key, entry in list(value.items()):
314 if isinstance(entry, dict) and isinstance(entry.get('source_ref'), dict) and entry['source_ref'].get('path'):
315 value[key] = read(entry['source_ref'])
316 for index, task in enumerate(value.get('tasks', []) if isinstance(value.get('tasks'), list) else []):
317 if isinstance(task.get('source_ref'), dict):
318 task = value['tasks'][index] = {**task, **read(task['source_ref'])}
319 for field in ('results', 'reviews', 'revision_history', 'assessment_history'):
320 if task.get(field + '_source'):
321 task[field] = read(task[field + '_source'])

581def local_job_runner(method):
582 """Give scripted model calls a real, bounded local process lifetime."""
583 @wraps(method)
584 def run(self, **arguments):
585 callback = arguments["on_started"]

932def run_cli(*arguments, cwd=None):
933 """Run the CLI's ``main`` in this process, as ``python do_math.py *arguments`` would.
934
935 Returns a ``subprocess.CompletedProcess`` with ``returncode`` and text
936 ``stdout``/``stderr``. ``cwd`` is the working directory during the call.
937 Nothing about the process is exercised: stream encoding, interpreter
938 start-up and process-wide state stay those of the test process.
939 """
940 import io
941 import subprocess
942 from contextlib import redirect_stderr, redirect_stdout
943 from do_math.cli import main
944 arguments = [os.fspath(argument) for argument in arguments]
945 stdout, stderr = io.StringIO(), io.StringIO()
946 previous = os.getcwd()
947 try:
948 if cwd is not None:
949 os.chdir(cwd)
950 with redirect_stdout(stdout), redirect_stderr(stderr):
951 try:
952 code = main(arguments)
953 except SystemExit as exit:
954 # As the interpreter does: None is success, other non-integers print and fail.
955 code = 0 if exit.code is None else exit.code if isinstance(exit.code, int) else 1
956 if not isinstance(exit.code, (int, type(None))):
957 print(exit.code, file=sys.stderr)
958 finally:
959 os.chdir(previous)
960 return subprocess.CompletedProcess(['do_math.py', *arguments], code, stdout.getvalue(), stderr.getvalue())

965 completed = run_cli(*arguments, cwd=root)

967 raise AssertionError(completed.stdout + completed.stderr)

1012def restore_template(build, **parameters):
1013 """Return ``(root, value)``: a fresh copy of what ``build`` made once in this process.
1014
1015 ``build(root, shared, **parameters)`` runs on the first call for its
1016 parameters. It creates the state under ``root`` and returns ``value``
1017 (usually the instance ID). Every call, including the first,
1018 then hands out ``root`` holding the exact bytes ``build`` left there, so
1019 the Git state, workspace and control inbox are those the product published.
1020
1021 ``root`` is the same path on every call: that is what keeps the absolute
1022 paths inside the state true. A call therefore replaces the previous copy;
1023 finish with an engine before asking for the next one. ``shared`` is never
1024 copied or cleared. Put there only files the product reads and never writes
1025 whose stat fingerprint the state records, such as ``trust_fixture``
1026 toolchains: a copy would change their creation time. Parameters must be
1027 JSON values; together with ``build``'s name they select the template.
1028 """
1029 import inspect
1030 # Defaults are part of the key, so omitting one names the same template.
1031 bound = inspect.signature(build).bind(None, None, **parameters)
1032 bound.apply_defaults()
1033 parameters = dict(list(bound.arguments.items())[2:])
1034 key = (build.__module__, build.__qualname__, json.dumps(parameters, sort_keys=True))
1035 template = _TEMPLATES.get(key)
1036 if template is None:
1037 # A failed build is not retried: each later test would repeat its cost.
1038 _TEMPLATES[key] = 'failed'
1039 template = _TEMPLATES[key] = _Template(build, parameters)
1040 elif template == 'failed':
1041 raise AssertionError('This template failed to build earlier in this process: ' + repr(key))
1042 return template.restore()
