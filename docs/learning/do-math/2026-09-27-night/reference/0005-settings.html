기본값이 없는 것과 무기한인 것

tool_review_window_seconds와 self_check_response_window_seconds는 사용에 필요한 값을 확정해야 합니다. no_progress_limit과 계보별 반복 한도는 적용 설정의 의미를 따릅니다. 계보별 한도를 설정하지 않은 경우 해당 횟수 한도를 두지 않는다는 명시 계약이며, 모든 빈칸을 일반적으로 무제한이라고 읽는 규칙은 아닙니다.

작업 AI·중앙 Lean에는 경과 시간만으로 취소하는 기한이 없습니다. 운영 AI에는 call_timeout_seconds가, 설치 복구 AI에는 operator_timeout_seconds가 적용됩니다. 연구 예약의 ExecutionTimeLimit은 PT0S, 운영 예약에는 복구 기한에 종료 여유 300초를 더한 유한 제한이 적용됩니다. finish_notice는 마무리 예고이며 그 자체가 실제 정지는 아닙니다.

역할 하한과 프로필 변경

기본 상 등급은 후보 준비·연구 계획·의도 해석·동일성 검토·목표 감사·설치 복구입니다. 중 등급은 계약 검토·운영 점검·유지보수, 하 등급은 연구 수행·보충 조사입니다. 과제의 난이도·중요도가 더 높으면 상향합니다.

configure에서 생략한 최상위 필드는 유지하지만 tier_models와 session_limits를 바꿀 때는 해당 맵 전체를 제공합니다. 슬롯 한도를 현재 점유보다 낮추면 새 배정을 기다리게 하며 이미 시작한 실행을 강제 종료하지 않습니다. 새 프로필의 도입과 과제에 고정된 프로필 변경은 구별합니다. 후자는 재준비·독립 계약 검토가 필요할 수 있습니다.

host_resources를 쓸 때에는 jobs·memory_bytes·cpu_rate_basis_points와 제어용 reserve, 역할별 요구량을 정확한 제약 ID에 결박합니다. CPU는 10000을 전체로 한 단위입니다. Lean 기계 역할의 현행 무상한 계약은 유지합니다. 설정된 호스트 자원의 변경·해제에는 CLI 계약이 정한 정지·미종료 실행·예약 조건이 필요하므로 슬롯 수 조정과 같은 것으로 다루지 않습니다.

Claude는 minimal을 지원하지 않고 operator_effort의 ultra도 전달할 수 없습니다. 실제 모델·노력 수준 접근은 CLI 응답으로 확인하며 실패를 다른 모델로 조용히 우회하지 않습니다. claude_only_assigned_model은 내부 보조·fallback 모델 제한이고 모든 역할을 Claude로 바꾸는 옵션은 아닙니다.
