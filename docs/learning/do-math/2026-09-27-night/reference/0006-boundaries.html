저장·제출·개정과 보증의 경계

같은 원문이 여러 단계에서 읽혀도 각 단계의 책임은 다릅니다. 원문 보존은 과거 바이트를, 현재성은 지금 적용할 수 있는 전제를, 판정은 해당 의미를 소유합니다. 다음 표는 무엇을 혼동하면 안 되는지 찾는 참조입니다.

평가·관찰 보충 전용 준비는 배정된 보충 가족만 다룹니다. 검토 자리의 고정 질문을 맡은 보충 조사에는 비어 있지 않은 확장을 허용하지 않습니다. 같은 역할 이름이라도 이 단계 차이를 확인하고 실행별 확장 스키마를 사용합니다.

수학 관계를 제출하는 두 단계

일반 주 응답의 relations 항목은 kind·source·target·evidence만 가집니다. 형식 근거까지 필요한 관계는 다음 두 단계로 제출합니다. 아래는 필드의 위치를 읽기 위한 조각 예시이며 완전한 실행 응답이 아닙니다. 실제 활성 종류·ID·범위와 현재 출력 스키마를 사용해야 합니다. references/지식-저작과-재사용.md · 새 결과를 저작하고 후속에 연결한다

첫 단계는 관계를 입증할 형식 결과를 제안하면서 같은 응답의 확장 knowledge_metadata에 관계 주장을 붙이는 것입니다. 이때는 아직 관계 승인이나 K 편입이 없습니다.

{"knowledge_metadata":[{
  "title":"같은 주 응답의 새 형식 결과 제목",
  "relation_claim":{
    "kind":"활성 관계 종류",
    "source":"기존 KN 출발 ID",
    "target":"기존 KN 도착 ID",
    "confirmed_scope":"이 증명이 닫는 정확한 범위"
  }
}]}

둘째 단계는 그 형식 결과가 중앙 형식 검사·동일성 검토를 통과해 현재 사용할 수 있게 된 뒤입니다. 새 제출의 확장 relations에 해당 FR과 IA를 붙입니다.

{"relations":[{
  "kind":"같은 활성 관계 종류",
  "source":"같은 KN 출발 ID",
  "target":"같은 KN 도착 ID",
  "evidence":"그 방향의 관계가 성립하는 근거",
  "confirmed_scope":"검증된 같은 범위",
  "formal_result_refs":["실제 FR 형식 결과 ID"],
  "assessment_refs":["실제 IA 동일성 판정 ID"]
}]}

실행기는 검증된 relation_claim과 이 제출의 종류·양끝·범위가 같은지, 형식 결과와 판정의 사용 효력이 현재 유효한지 검사합니다. 첫 단계의 주장을 둘째 단계의 확정 관계로 미리 올리지 않습니다.

보존과 로컬 정리

연구 저장소의 불변 artifact는 추가 전용입니다. 큰 값은 내용 주소형 payload로 한 번 보존하고 정확한 참조로 복원합니다. 같은 프로세스에서 이미 대조한 불변 artifact는 반복 해시를 생략할 수 있지만, 이 가정은 저장된 불변 바이트와 같은 사용자 권한의 위협 범위에 상대적입니다.

로컬 실행 공간 정리는 retention의 명시적 승인·보관·보호 참조 폐쇄 규칙을 따릅니다. 먼저 종료와 보관 근거, 활성 참조가 보호하는 경로를 확인합니다. 정리했다고 연구 정본의 근거를 지우거나 아직 실행 중인 공간을 제거하는 것은 아닙니다. scripts/do_math/retention.py

저장 검사는 직전 상태인 부모와 같은 기록의 개별 검사를 반복하지 않고, 상태 전체의 관계·식별·의미 조건은 다시 확인합니다. 값의 같음을 비교하는 방식에는 구현상 한계가 있습니다. 개념 예로 이전 값이 {"count": 1}이고 메모리 후보가 {"count": true}라면, Python의 일반 동등 비교는 1과 True를 같게 볼 수 있습니다. 실제 저장 레코드는 각 가족의 전체 스키마를 따르지만 이 예는 비교가 자료형까지 엄격하게 구별하지 않는다는 점을 보여 줍니다.

이 경우 현재 코드는 바뀌지 않은 기록으로 취급해 개별 스키마 검사를 생략하고 부모의 원래 바이트를 유지할 수 있습니다. 즉 잘못된 true를 새로 저장한다는 설명이 아니라, 요청한 자료형 변경을 독립적으로 검출·반영하지 않을 수 있다는 한계입니다. 이 비용 절충은 state_contract의 주석에 명시되어 있으므로 모든 메모리 후보의 자료형 차이를 매번 재검증한다고 설명하지 않습니다. scripts/do_math/state_contract.py

이 판본의 지문 기반 확인은 우발적 변경을 대상으로 합니다. 크기·시각이 보존된 내용 변조, 계산 중 환경 변경, 같은 OS 사용자 권한의 의도적 접근까지 막는 보안 격리는 아닙니다. 세부 확인 경계는 references/초기화-효율과-정비.md에서 읽습니다.
