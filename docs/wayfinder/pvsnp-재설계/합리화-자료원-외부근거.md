# P vs NP 사전 문헌조사 자료원 합리화 — 외부 근거

조사일: **2026-09-04 (KST)**

이 문서는 KUDOS와 공개 자료원의 운영기관 문서·제공 목록·API·서비스 화면을 근거로, P vs NP 사전 문헌조사에 사용할 자료원과 그 역할을 판정한다. 서비스의 존재나 규모는 문헌의 수학적 진위·P vs NP 관련성·기준 핵심층 편입을 뜻하지 않는다. 이 문서의 권고는 조사 우주를 현대 수학·이론 컴퓨터과학 전 분야로 유지하면서 검색·식별·원문·판본·관계 증거를 가장 적은 중복으로 확보하는 데 맞춘다.

## 1. 기존 정본과의 대조

직접 대조한 문서:

- [`research/pvsnp/문헌-체계-명세.md`](../../../research/pvsnp/문헌-체계-명세.md): 현대 수학·이론 컴퓨터과학 전 분야를 가변 해상도로 조사한다. KUDOS와 공개 자료원은 한 번 실사한 뒤 실제 기능에 따라 분야별로 배정한다. 정확한 판본·정정·철회·접근 상태·원문 재진입 좌표를 기록하며, 자료원은 기준 핵심층이나 수학적 타당성을 자동 판정하지 않는다.
- [`research/pvsnp/연구-주제-선호.md`](../../../research/pvsnp/연구-주제-선호.md): P vs NP의 주제·결과·범위 소유 문서다. 자료원 선택이 특정 연구 방향이나 결론을 선호하는 것으로 읽히지 않도록 한다.
- [`docs/do-math/통합-설계.md`](../../do-math/통합-설계.md): 외부 자료는 초기 입력·자료·근거로 수입될 수 있으나, 연구 인스턴스의 F·작업·관계·Lean 정본을 자료원이 직접 생성하지 않는다. 원문 판독, 검토, 인증은 별도 단계다.

따라서 아래의 `주자료원`은 그 자료원이 가장 잘 보존하는 기록 종류에 대한 의미이고, 전 분야의 유일한 색인이라는 뜻이 아니다. `보완자료원`은 검색 누락·식별자·인용망·형식화·코드/데이터를 보충한다. `접근전용`은 원문 또는 페이지를 재진입하는 데 쓰며, 그 자체로 문헌 목록의 완전성을 주장하지 않는다. `제외`는 이번 닫힌 집합의 필수 채널로 채택하지 않는다는 뜻이지 자료가 무가치하다는 뜻은 아니다.

## 2. 판정 요약

### 2.1 KUDOS 전수 목록과 선정

[경북대학교 도서관의 공식 Databases 목록](https://kudos.knu.ac.kr/eng/sub.htm?nav_code=eng1643175350)은 2026-09-04 조회 시 128개 항목을 공개했다. 목록에는 서지·인용 DB, 출판사 원문 플랫폼, 학위논문 DB뿐 아니라 EndNote·Mendeley·RefWorks·Grammarly·Turnitin 같은 도구와 법률·의학·신문·기업정보 서비스도 함께 있다. 따라서 목록 항목 전건을 문헌 발견 DB로 취급하면 실제 역할이 다른 서비스를 같은 검색 교차곱에 넣게 된다.

인증이 필요한 1차 후보 발견에는 다음 여섯 인터페이스를 채택한다. Web of Science Core Collection과 CPCI는 KUDOS 목록에서는 두 항목이지만 한 인터페이스의 독립 색인으로 운용한다.

|---|---|---|
| MathSciNet | MSC별 수학 문헌·책·학위논문·리뷰와 인용 검색 | 전 수학 분야의 인증 주자료원 |

KUDOS가 공개한 제공 목록의 실물도 대조했다. [ACM Open 2026 목록](https://kudos.knu.ac.kr/download/db/ACM%20Open%20TitleList%282026%29.xlsx)에는 *Journal of the ACM*, *ACM Transactions on Computation Theory*, *ACM Transactions on Algorithms*, *ACM Transactions on Computational Logic*이 있다. [IEL 2026 목록](https://kudos.knu.ac.kr/download/db/IEL%20Title%20List%282026%29.xlsx)에는 1960년대 이후 FOCS 전신과 FOCS, 과거 IEEE CCC 학회록이 있다. [Springer 2026 목록](https://kudos.knu.ac.kr/download/db/Springer%20eJournal%20TitleList%282026%29.xlsx)에는 *Computational Complexity*와 *Foundations of Computational Mathematics*가 있고, [ScienceDirect 2025 목록](https://kudos.knu.ac.kr/download/db/lists/ScienceDirect%20TitleList%282025%29.xlsx)에는 *Journal of Computer and System Sciences*, *Information and Computation*, *Theoretical Computer Science*, *Journal of Complexity*가 있다.

AMS·CUP·De Gruyter·JSTOR·OUP·ScienceDirect·Springer·Taylor & Francis·Wiley와 KNU FRIC·개별 구독은 선정된 원문의 판본 확보에 사용한다. AIP·APS·IOP와 다학제 Nature·Science·PNAS도 해당 분야에서 선별 문헌이 나왔을 때 원문 경로로 사용한다. 같은 검색을 이 출판사 플랫폼 전건에서 반복하지 않는다.

공식 목록은 로그인 없이 전건과 제공 목록을 보여 주었으므로 이번 목록 실사에는 `.credentials/kudos.md`를 읽거나 로그인할 필요가 없었다. 인증 검색은 사용자가 브라우저로 수행한다. 같은 공식 페이지의 전자자원 이용수칙은 특정 전자자원에서 30건 이상의 논문·저널, 책·저널 전건, 프로그램·서지관리도구를 통한 자동 대량 원문 다운로드를 금지한다. 따라서 UI가 제공하는 서지정보 export와 원문 다운로드를 구별하고, 1차 조사에서는 원문을 대량 확보하지 않는다.

## 3. 자료원별 근거와 운용 판정

### 3.1 수학 서지·분류: zbMATH Open

zbMATH Open의 운영자 설명은 FIZ Karlsruhe, EMS, Heidelberg Academy가 편집하며 2021년부터 공개 접근 서비스라고 밝힌다. 순수·응용수학 전 영역과 컴퓨터과학·경제·공학 등 응용을 다루고, MSC2020 분류·키워드·리뷰·초록을 제공한다. 2024년에는 수학 관련 arXiv가 통합되었고, 참고문헌·소프트웨어·연구데이터·원문 플랫폼 연결도 제공한다고 설명한다. 문헌·저자·serial·MSC 검색 화면에는 DOI/ISBN/arXiv ID와 `db:Zbl`, `db:JFM`, `db:arxiv` 같은 데이터베이스 필터가 실제로 보인다. [About zbMATH Open](https://zbmath.org/about/), [문서 검색 화면](https://zbmath.org/)

그러므로 `field_refs`, MSC 기반 분야 씨앗, 수학 문헌의 review/abstract 후보, 관련 참고문헌을 만드는 주자료원으로 채택한다. 다만 운영자 자신이 리뷰를 peer review의 대체물이 아니며 리뷰어가 원 논문의 correctness/novelty를 원칙적으로 책임지지 않는다고 명시한다. 리뷰는 기준 핵심층의 학술적 채택 신호이지 증명 검증으로 쓰지 않는다. `zbMATH ID`와 exact version의 DOI/arXiv/출판 URL을 모두 보존한다.

공개 REST API는 search/display/download/analysis를 지원하지만, API 조건은 FIZ·출판사 권리와 트래픽 제어를 요구하고 데이터 사용을 CC-BY-SA 4.0 조건에 둔다. citation matcher는 여러 citation 문자열을 zbMATH entry에 매칭하는 보완 도구다. [zbMATH API terms](https://api.zbmath.org/), [API 이용조건 원문](https://static.zbmath.org/legal/api-terms-and-conditions.html), [Citation matching API](https://zbmath.org/static/citation-matching-api.pdf)

### 3.2 프리프린트·판본: arXiv

arXiv 운영 문서는 공개 API가 개방성과 상호운용성을 위한 것이라고 명시하고, metadata API·bulk pipeline·RSS·OAI를 연결한다. OAI-PMH는 `https://oaipmh.arxiv.org/oai`를 base URL로 하며, article item마다 최신 버전만 노출한다. `arXivRaw`에는 이전 버전 이력이 있고, OAI set으로 archive/category/group을 선택할 수 있다. datestamp는 마지막 메타데이터 수정일이며 오래된 대량 업데이트 때문에 제출·교체 시각과 다를 수 있고, 제출 날짜 범위만으로 선택 수확할 수 없다. [arXiv API Access](https://info.arxiv.org/help/api/index.html), [arXiv OAI-PMH 안내](https://info.arxiv.org/help/oa/index.html)

각 후보는 `arXiv:<id>vN`, 조회 시각, PDF/소스, history를 exact version으로 기록한다. 출판 DOI·journal reference가 arXiv record에 추가되어도 두 record를 자동 병합하지 말고, Crossref/DBLP/출판본과 `version/update_relation`을 명시한다. arXiv posting은 peer review가 아니므로 current frontier과 미출판 주장에 유용하지만, 확정된 문헌 유래 주장과 기준 핵심층 판정은 원문·독립 자료로 다시 한다.

### 3.3 이론CS 서지: DBLP

DBLP 공식 FAQ는 publication, person, venue의 세 검색 API를 제공하고 `/search/publ/api`, `/search/author/api`, `/search/venue/api`를 base URL로 제시한다. 응답은 XML·JSON·JSONP, `h`/`f` 페이지네이션, 최대 1,000 hit 상한을 갖는다. 전체 bibliographic records는 DTD와 함께 `dblp.xml.gz`로 공개되며, venue 페이지에서 개별 record를 BibTeX·RIS·RDF·XML 등으로 export할 수 있다. [DBLP search API FAQ](https://dblp.org/faq/13501473.html), [DBLP XML dump](https://dblp.org/xml/)

DBLP는 이론CS venue/저자/연도 누락 검사의 핵심 보완선으로 사용한다. 그러나 DBLP의 데이터는 bibliographic metadata이지 증명·초록·원문이 아니다. `first/last hit`와 API query를 보존하고, 1,000건 상한에 걸리면 venue/year/author/category로 쪼개어 결과 수가 안정되는지 검산한다. DBLP venue 화면 스스로 OA 정보가 아직 불완전할 수 있음을 고지하므로 OA 여부는 원 출판처에서 재확인한다.

### 3.4 전 분야 연결 그래프: OpenAlex

OpenAlex는 works, authors, sources, institutions, publishers, funders, topics를 연결하는 전 세계 연구 지도라고 설명하며 DOI/ORCID/ROR/ISSN 등의 외부 ID를 저장한다. API는 `/works` 등 entity endpoint에서 filter/search/sort/group/select와 JSON 응답을 제공하고, 무키 기본 사용·무료 key·cursor paging·snapshot을 구분한다. `page×per_page` 10,000건 제한을 넘는 검색은 cursor가 필요하고, 대량 전수 취득은 서버 부하 때문에 snapshot을 쓰라고 안내한다. [OpenAlex API reference](https://help.openalex.org/api/), [OpenAlex data reference](https://help.openalex.org/data/), [paging](https://help.openalex.org/api/paging/), [authentication/rate limits](https://help.openalex.org/api/authentication/)

OpenAlex의 native entity ID는 OpenAlex의 동일성 판단이 들어간 결과이며, 운영자 문서도 잘못될 수 있고 merge가 정상적인 ongoing 과정이라고 명시한다. 따라서 `openalex_id`는 고정된 외부 정본이 아니라 검색 당시의 연결 키로 기록하고 DOI·arXiv·DBLP·zbMATH ID를 함께 저장한다. API의 citation count/topic은 후보 확장과 누락 탐지에만 쓴다.

### 3.5 DOI·정정·철회: Crossref와 Crossmark

Crossref REST API는 회원과 trusted source가 기탁한 scholarly metadata를 JSON으로 제공하며, funding, license, ORCID/ROR, abstracts, post-publication updates를 포함할 수 있다. `/works`, DOI 단건, journal/member/funder/type endpoint 및 filter/facet/sample을 제공하고 sign-up 없이 쓸 수 있다. 다만 metadata가 회원의 직접 deposit이라는 점과 일부 abstract의 저작권 가능성을 운영자가 명시한다. [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)

Crossmark은 독자가 correction, retraction, update 등 현재 상태를 보고, 회원이 제공한 editorial metadata를 확인하게 하는 표시·API 계층이다. 운영자 문서는 회원이 업데이트를 정확히 등록할 의무를 지지만 Crossmark 버튼의 존재가 보증은 아니라고 명시한다. 따라서 각 판본에서 Crossref `/works/{doi}`와 Crossmark 상태를 조회하되, Crossmark 부재를 “정정 없음”으로 기록하지 않는다. 출판사 landing page와 원문 PDF의 correction/retraction link도 함께 검사한다. [Crossmark](https://www.crossref.org/services/crossmark/)

### 3.6 인용 그래프: Semantic Scholar와 OpenCitations

Semantic Scholar Academic Graph API는 papers, authors, citations, venues를 찾고 recommendations/datasets API와 JSON 조회를 제공한다. 공식 tutorial은 paper search가 title/abstract 단어를 대상으로 하고 pagination·filter·citation/reference field를 지원하며, datasets API가 release별 JSON dataset을 제공한다고 설명한다. 공개 endpoint는 key 없이도 가능하지만 rate limit이 있고, dataset download 등 일부 endpoint는 key가 필요하다. [Semantic Scholar API](https://www.semanticscholar.org/product/api), [API tutorial](https://webflow.semanticscholar.org/product/api/tutorial), [API terms](https://api.semanticscholar.org/license/)

Semantic Scholar는 AI가 중요 논문을 추출하는 graph라는 점과 PDF/abstract 등 보조 metadata를 제공한다. 그 결과는 적대 검색과 후보 확장에 유용하나 complete corpus나 peer review 판정으로 승격하지 않는다. API query, returned paper IDs, retrieval time과 `paperId`/DOI/arXiv mapping을 저장한다.

OpenCitations는 bibliographic/citation data를 공개 인프라로 제공하고, Index API는 특정 PID의 incoming/outgoing citation, count와 OCI를 JSON/CSV로 돌려준다. API 문서는 180 requests/min/IP rate limit과 대량 retrieval에는 dumps를 쓰라는 경계를 명시하며, `filter`, `sort`, `format` 파라미터를 제공한다. [OpenCitations](https://opencitations.net/), [Index REST API v2](https://api.opencitations.net/index/v2)

따라서 OpenCitations는 “A가 B를 인용한다”는 문헌 유래 관계의 독립 교차검산으로 쓰고, 원문 내용·정정·출판 상태는 Crossref/출판처에서 확인한다. OpenCitations의 citation count와 Semantic Scholar의 count가 다르면 어느 쪽을 참값으로 택하지 말고 수확 시각·인덱스 범위·identifier matching 차이를 기록한다.

### 3.7 공식 informatics proceedings와 계산복잡도 보고서

DROPS 운영 문서는 LIPIcs가 informatics 전 분야의 high-quality conference proceedings series라고 밝히며, 실제 series 화면에는 CCC, ICALP, ITCS, RANDOM, SAT, STACS, ITP 등이 표시된다. 모든 DROPS publication은 OA, DataCite DOI, DBLP indexing을 갖고, 기본 OAI와 extended metadata를 공개한다. metadata export는 Dagstuhl XML, ACM-XML, DOAJ-XML, Schema.org를 지원하며 2024년부터 software/dataset artifact를 supplementary material로 다룬다. [DROPS About](https://drops.dagstuhl.de/docs/about), [LIPIcs series 화면](https://drops.dagstuhl.de/entities/series/LIPIcs)

conference paper는 P vs NP 직접·인접 분야의 primary_core/current_frontier 후보가 될 수 있으나, preliminary proceedings, arXiv full version, 최종 LIPIcs paper, journal version을 별도 version으로 기록한다. LIPIcs 원문 페이지와 DOI를 기준으로 하고 DBLP는 서지·누락 보완에만 쓴다.

ECCC는 1994년부터 계산복잡도 아이디어·기술의 신속한 교환을 위한 forum/repository로 운영되며, central topics에 computation models, lower bounds, coding, combinatorics, cryptography, logic, optimization, quantum 등을 명시한다. 게시물의 지위는 technical report이고, 관련성·명확한 수학적 profile·strictly mathematical format을 요구한다. [ECCC About](https://eccc.weizmann.ac.il/), [ECCC report/keyword 화면 예](https://eccc.weizmann.ac.il/keyword/18771/)

ECCC는 P vs NP의 current frontier와 장벽·하계·완화 문제를 빠르게 포착하는 직접 주자료원이다. 다만 technical report를 journal peer review와 동일시하지 않는다. ECCC report number와 revision을 고정하고, 이후 journal/venue 출판과 arXiv 버전의 relation을 추적한다. 운영자 과거 설명도 ECCC가 usual peer-refereed journal이 아니며 proofs를 전면 검사하지 않는다고 명시하므로, 모든 핵심 주장에는 원문 판독과 별도 검토가 필요하다. [ECCC 운영 취지의 공식 설명](https://eccc.weizmann.ac.il/static/impressions/eatcs/)

### 3.8 동료심사 OA 원문: Theory of Computing

Theory of Computing의 공식 소개는 2004년 설립된 diamond OA 이론CS 저널로, 독자·저자 모두 무료이고 CC 라이선스와 rigorous single-blind peer review, ACM SIGACT endorsement를 설명한다. 공식 P/NP policy는 P/NP 투고를 허용하되 같은 저자의 submission/review history 공개와 36개월당 1편 제한을 둔다. [Theory of Computing 소개](https://www.theoryofcomputing.org/introduction.html), [P/NP policy](https://www.theoryofcomputing.org/submit/pnp.html)

이 저널의 article archive와 PDF/HTML/DOI는 해당 저널의 peer-reviewed primary publication으로 우선한다. 그러나 저널 자체가 전 분야 색인이나 최신 프리프린트 저장소는 아니므로 arXiv·DBLP·Crossref와 대조한다. P/NP policy는 “이 분야에서 오류를 식별하는 심사 부담이 실제 운영 문제”라는 공식 맥락을 보여주지만 특정 투고의 진위를 대신 판정하지 않는다.

### 3.9 수학 디지털 도서관: Project Euclid·EuDML·Numdam

Project Euclid는 Cornell/Duke의 비영리 대학 기반 수학·통계 출판 플랫폼으로 확인된다. 운영 파트너 설명은 theoretical/applied mathematics와 statistics journal hosting, 독립·학회 출판사와의 협력, 광범위한 접근을 그 사명으로 둔다. 실제 플랫폼의 title/browse/search와 개별 원문 접근은 확인되지만, 2026-09-04 조사에서는 안정적인 공개 REST 검색 API 문서를 운영자 사이트에서 확인하지 못했다. 따라서 플랫폼에 실제 호스팅된 논문의 접근전용 및 해당 논문의 원출판 페이지로만 사용하고, 전 분야 수확·완전성 근거로 쓰지 않는다. [Duke University Press의 Project Euclid 파트너 설명](https://dukeupress.edu/information-for/mathematics-authors-editors/partnerships), [Project Euclid](https://projecteuclid.org/)

EuDML의 공식 검색 화면은 제목·저자·키워드·인용·날짜 및 수식 기반 advanced search를 제공하고, 통계 화면은 문서·full-text indexed 수와 article/monograph/volume 유형을 제시한다. EuDML service-interface 문서는 OAI-PMH 2.0과 CQL OpenSearch API(`/api/search?q=...&startIndex=...&count=...&format=...`)를 설명한다. 그러나 이 API 문서는 2013년 프로젝트 deliverable이므로 실행 시 endpoint 상태와 응답 schema를 반드시 재검증한다. [EuDML 검색](https://eudml.org/search), [EuDML 통계](https://eudml.org/statistics), [EuDML service-interface 문서](https://wiki.eudml.org/mediawiki/eudml/images/D6.4.pdf)

Numdam의 운영 문서는 OAI-PMH 2.0 base URL, `oai_dc`/`eudml-article2`, `ListSets`, `GetRecord` 예와 KBART export를 공개한다. 이용조건은 bibliographic metadata가 CC0이고 OAI로 체계적 다운로드가 가능하다고 하면서도 full text의 대량 재구성은 금지한다. 따라서 Numdam collection에 속한 역사 수학 논문은 원문·메타데이터 주자료원으로 채택하고, 대량 PDF 수집은 하지 않는다. [Numdam metadata & interoperability](https://www.numdam.org/metadata/), [Numdam 이용조건](https://www.numdam.org/conditions/)

### 3.10 공개 원문 탐색: Unpaywall·CORE

Unpaywall의 공식 API는 DOI별 공개 접근 상태와 공개 판본 위치를 반환하고, 제목 검색도 제공한다. CORE는 기관·분야 저장소와 공개·hybrid 저널에서 메타데이터와 공개 원문을 모아 검색·API로 제공한다. 두 서비스는 출판사에서 원문을 확보하지 못한 선별 후보의 공개 저자본·기관 저장본을 찾는 보완선으로 사용한다. 공개 링크가 있다는 사실만으로 출판본과 같은 판본이라고 보지 않고 제목·저자·버전 문면을 대조한다. [Unpaywall REST API](https://data.unpaywall.org/products/api), [CORE](https://core.ac.uk/), [CORE API](https://core.ac.uk/services/api)

### 3.11 형식 증명·코드·데이터

#### Lean mathlib

mathlib4 공식 repository는 Lean 4 수학 라이브러리와 자동 생성 문서, covered theories 개요, contribution guide를 제공한다. 정확한 formal evidence는 사람에게 읽히는 문서가 아니라 `.lean` source, commit SHA, `lean-toolchain`, `lake-manifest`와 성공한 build를 함께 보존할 때 성립한다. [mathlib4 repository](https://github.com/leanprover-community/mathlib4), [mathlib contribution guide](https://leanprover-community.github.io/contribute/how-to-contribute.html)

#### Archive of Formal Proofs

AFP 공식 페이지는 Isabelle에서 mechanically checked 된 proof library·scientific development를 모으고, scientific journal처럼 운영하며 refereed submission, DBLP indexing, ISSN을 제공한다고 설명한다. 검색 결과의 entry release, Isabelle version과 source를 고정한다. formal theorem의 존재는 비형식 P vs NP 주장과 동일하지 않으므로 `formalizes`, `reproduces`, `proves` 관계를 원문과 실제 build 결과에 따라 분리한다. [Archive of Formal Proofs](https://isa-afp.org/)

#### Mathematical Components

MathComp 공식 사이트는 Rocq prover용 formalized mathematics library, version별 HTML/coqdoc와 source 다운로드, changelog를 제공한다. 유한 구조·대수·조합 등 P vs NP의 경계 수학과 연결될 수 있으나, Lean/Isabelle 객체와 자동 동일시하지 않는다. [Mathematical Components](https://math-comp.github.io/), [MathComp GitHub](https://github.com/math-comp/math-comp)

#### GitHub, Zenodo, Software Heritage

GitHub는 코드·formalization·데이터의 저자/기관 원 저장소가 될 수 있지만 branch는 mutable하다. 공식 REST API의 search/repository/release와 raw commit을 사용해 exact commit SHA, tag, release asset, license, workflow/build 증거를 기록한다. [GitHub REST API search](https://docs.github.com/en/rest/search/search?apiVersion=2022-11-28), [GitHub REST API](https://docs.github.com/en/rest)

Zenodo는 record에 version DOI와 전체 버전을 가리키는 concept DOI를 발급하고, 후속 upload마다 version DOI를 발급한다고 안내한다. 연구 코드·데이터의 버전 고정에는 적합하지만 파일의 권리·실행환경·검사 결과를 대신하지 않는다. [Zenodo DOI versioning](https://zenodo.org/help/versioning), [Zenodo developers/API](https://developers.zenodo.org/)

Software Heritage는 공개 소스코드를 보존하고 content/directory/commit/release 그래프와 origin visits를 API로 조회하며, SWHID를 제공한다. 공식 문서는 인기 낮은 출처가 underrepresented될 수 있고 REST API는 non-bulk 접근이라는 한계를 명시한다. 따라서 삭제·이동된 코드의 재진입과 provenance를 보완하되, GitHub/Zenodo 원본·license·build와 함께 사용한다. [Software Heritage](https://www.softwareheritage.org/), [Using Software Heritage data](https://docs.softwareheritage.org/user/using_data/index.html)

## 4. 닫힌 문헌 집합을 만드는 권고 절차

자료원 목록을 무제한으로 늘리지 않고도 전 분야와 누락을 다루려면 역할을 다음처럼 나눈다.

1. **자료원 우주를 한 번 실사한다.** KUDOS와 공개 자료원의 실제 범위·검색 기능·원문 기능을 확인한다. 도구·평가 서비스와 문헌 DB를 구별한다.
2. **분야별로 가장 적은 주자료원을 배정한다.** 수학은 MathSciNet과 zbMATH Open, 이론 컴퓨터과학은 ACM·IEEE·DBLP, 최신 프리프린트는 arXiv, 계산복잡도 기술보고는 ECCC, 주요 공개 학회록은 DROPS/LIPIcs를 중심으로 한다. Web of Science와 Scopus는 독립 누락 검사에 사용한다.
3. **인증 검색과 공개 검색을 분업한다.** 인증 검색은 사용자가 직접 수행하거나 사용자가 승인한 범위에서 로컬 브라우저 프로그램이 수행하고, AI는 공개 자료원 조사와 수집물 검증을 맡는다. 모든 자료원을 모든 분야에 적용하지 않는다.
4. **메타데이터를 먼저 모은다.** 첫 회차에 원문을 대량 다운로드하지 않는다. 후보를 정규화·중복 제거·선별한 뒤 필요한 원문만 후속 묶음에서 확보한다.
5. **정확한 판본을 결박한다.** DOI·arXiv·MR/Zbl·DBLP·venue/report ID, URL, 조회 시각, 출판·접근 상태, 로컬 SHA-256과 update/retraction relation을 필요한 범위에서 기록한다. arXiv 판본, ECCC revision, 학회판, 저널판과 repository commit/release를 자동 병합하지 않는다.
6. **원문과 메타데이터를 구별한다.** API·색인의 title/abstract/citation은 발견·식별 증거다. 수학 주장·정의·반례·장벽은 정확한 원문을 다시 읽은 판독 증거다.
7. **새 후보가 나오는 부분만 반복한다.** 표준 종합 자료의 참고문헌, 핵심 작업의 전후방 인용, 독립 색인, 반론·정정·철회, 형식 증명·코드·데이터를 대조한다. 완전한 누락 검사에서 새 핵심 후보가 나오지 않을 때 문헌 집합을 동결 대상으로 올린다.
8. **형식·코드에는 별도 증거를 요구한다.** mathlib·AFP·MathComp·GitHub·Zenodo·Software Heritage 자료는 실제 build·toolchain·commit·license·artifact SHA를 확인한 범위만 기록한다.

## 5. 최종 권고 집합

이번 사전 조사에서 자료원은 다음처럼 닫는다.

- **인증 발견 자료원**: `MathSciNet`, `Web of Science Core Collection + CPCI`, `Scopus`, `ACM Digital Library / Guide`, `IEEE Xplore / IEL`, `PQDT Global`.
- **AI 공개 주자료원**: `zbMATH Open`, `arXiv`, `DBLP`, `ECCC`, `DROPS/LIPIcs`, `Theory of Computing`.
- **후보별 판본·인용 보완자료원**: `Crossref/Crossmark`, `OpenAlex`, `Semantic Scholar`, `OpenCitations`.
- **후보별 원문·역사 자료원**: 실제 원출판사·학회, `Unpaywall`, `CORE`, `Project Euclid`, `EuDML`, `Numdam`과 저자·기관 공개본.
- **관련 결과가 있을 때만 여는 형식·코드·데이터 자료원**: `Lean mathlib`, `AFP`, `MathComp`, `GitHub`, `Zenodo`, `Software Heritage`.
- **핵심 근거에서 제외**: 상업 비교글·블로그·비공식 집계·검색 결과의 2차 요약, mutable branch만 있는 코드, 추천 순위나 citation count만 있는 페이지.

이 자료원 집합은 분야를 축소하지 않는다. 자료원마다 잘하는 기록 종류를 나누고, 전 분야 분류 검색·독립 인용 색인·전문 저장소·정확한 판본 재진입을 결합해 “검색 결과가 많다”와 “기준 핵심층이 닫혔다”를 구별한다.
