# P vs NP 문헌 체계: 외부 근거

조사일: 2026-08-31

이 노트는 승인된 문헌 체계 명세를 뒷받침할 수 있는 외부 사실만 기록한다. 여기의 “시사점”은 사실에서 바로 따라오는 기록·검증상의 제약이며, 자료 범위·완료 기준·도구 선택 같은 사용자 결정을 정하지 않는다. 링크는 모두 해당 제도·서비스 운영자의 공식 문서다.

## 1. 분야 분류의 공인 입력

### 수학: MSC2020

[Mathematics Subject Classification 2020(MSC2020)](https://msc2020.org/)은 Mathematical Reviews와 zbMATH가 공동 유지하고 수학 문헌을 분류하는 분류체계다. 현재 판본은 63개의 두 자리, 529개의 세 자리, 6,022개의 다섯 자리 분류를 제공한다. 따라서 같은 분류체계 안에서도 상위 분야와 세부 주제를 서로 다른 해상도로 표기할 수 있다. MSC2020에는 컴퓨터 과학(68)도 포함된다. [MSC2020 공식 개요](https://msc2020.org/), [공식 분류 탐색](https://zbmath.org/classification/)

zbMATH Open의 공식 검색 문서는 MSC 코드가 여러 개일 수 있음을 전제하며, `cc` 검색에서 `*`를 붙이면 주 분류(primary MSC)만으로 한정한다고 설명한다. arXiv의 수학 제출 메타데이터도 `Primary`와 복수 `Secondary` MSC 분류를 지원한다. 이는 하나의 자료가 주제 분류를 하나만 가질 필요가 없다는 서비스 수준의 사실이다. [zbMATH 검색 도움말](https://zbmath.org/general-help/), [arXiv 메타데이터 필드](https://info.arxiv.org/help/prep.html)

### 이론 컴퓨터과학: ACM CCS와 arXiv 범주

[ACM Computing Classification System 2012(CCS)](https://www.acm.org/publications/class-2012)은 ACM Digital Library의 검색·주제 표시에 통합된 컴퓨팅 온톨로지다. ACM의 저자 안내는 논문에 CCS 개념을 하나 이상 선택할 수 있고, 각 선택에 개념 ID·개념 설명·유의도를 담는 메타데이터를 생성한다고 명시한다. 이론 컴퓨터과학을 MSC의 68·03 계열만으로 축소하지 않고 별도 컴퓨팅 분류 축으로도 표기할 수 있는 공식 근거다. [ACM CCS 설명](https://ccecc.acm.org/guidance), [ACM 저자 안내 PDF](https://www.acm.org/binaries/content/assets/publications/article-templates/sig-alternate-guide.pdf)

arXiv는 논문마다 주 범주 하나와 0개 이상의 cross-list 범주를 둔다. 범주는 검색의 부분집합 제한과 공지 메일링을 제어한다. arXiv의 식별자에는 2007년부터 분류 정보가 들어 있지 않으므로, 식별자와 범주를 서로 다른 필드로 다뤄야 한다. [arXiv 메타데이터 필드](https://info.arxiv.org/help/prep.html), [arXiv 식별자](https://info.arxiv.org/help/arxiv_identifier.html)

## 2. 문헌·사람·기관·소프트웨어를 다시 찾는 식별자

- Crossref REST API는 DOI별 서지 메타데이터, 라이선스, 초록, ORCID·ROR 식별자, 사후 업데이트를 JSON으로 공개한다. `/works/{doi}`는 한 DOI 레코드를, `/journals/{issn}/works`는 ISSN의 저널 수록물을 반환한다. [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)
- DOI 콘텐츠 협상은 DOI 등록기관을 미리 알지 않아도 한 DOI의 메타데이터를 지정 형식으로 요청하는 공식 경로다. 단일 DOI 메타데이터 회수와 목록 검색·필터링은 서로 다른 인터페이스다. [Crossref 콘텐츠 협상](https://www.crossref.org/documentation/retrieve-metadata/content-negotiation/)
- zbMATH Open은 문헌 레코드에 `Zbl` 문헌 ID를 부여하고, DOI·ISBN·arXiv ID를 검색 필드로 제공한다. 이 ID들은 색인 레코드를 재진입하는 좌표이지 원문 판본 자체의 식별자는 아니다. [zbMATH 문헌 검색](https://zbmath.org/), [zbMATH 일반 도움말](https://zbmath.org/general-help/)
- arXiv의 완전한 판본 인용은 `arXiv:YYMM.numbervV`다. 판본 접미사가 없는 ID는 최신 판본을 가리킨다. arXiv는 특정 판본·분류·날짜를 함께 인용할 것을 권한다. [arXiv 식별자](https://info.arxiv.org/help/arxiv_identifier.html)
- ORCID iD는 연구자·기여자를 구별하는 영속 식별자이며, ROR은 연구·지원 기관의 공개 영속 식별자다. 두 식별자는 저자명·소속명 동음이의 해소에 쓸 수 있지만, 공개된 ORCID 레코드 범위는 당사자 프라이버시 설정에 좌우된다. [ORCID 소개](https://info.orcid.org/what-is-orcid/), [ORCID Registry](https://info.orcid.org/what-is-orcid/services/orcid-registry/), [ROR 소개](https://ror.org/about/)
- GitHub Releases API는 release의 `tag_name`, `target_commitish`, asset 정보와 asset digest를, Commits API는 특정 commit SHA를 제공한다. release 태그와 실제 대상 commit, 배포 asset은 서로 다른 판본 좌표일 수 있다. [GitHub Releases API](https://docs.github.com/en/rest/releases/releases), [GitHub Commits API](https://docs.github.com/en/rest/commits/commits)

## 3. 인용·관계·정정·철회 상태

Crossref는 인용(reference linking/cited-by), 자료·소프트웨어 등 연구 객체의 형식 관계, 그리고 material effect가 있는 업데이트 관계를 분리해 표현한다. 일반 관계 메타데이터에는 `isPreprintOf`·`hasPreprint`, `isVersionOf`·`hasVersion`처럼 판본·프리프린트 연결에 쓰이는 관계가 있고, REST API는 `has-update`, `is-update`, `update-type`, `relation.type` 등의 필터를 제공한다. [Crossref 관계 메타데이터](https://www.crossref.org/documentation/schema-library/markup-guide-metadata-segments/relationships/), [Crossref REST API 필터](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/)

Crossmark의 업데이트 어휘에는 `correction`, `corrigendum`, `erratum`, `expression_of_concern`, `partial_retraction`, `retraction`, `withdrawal`, `new_version` 등이 있다. 편집상 중요한 변경은 보통 별도 DOI 레코드의 업데이트로 등록하며, 원 자료 DOI를 함께 기탁한다. 반대로 사소한 표기·서식 변경은 Crossref 통지 없이 직접 고칠 수 있다. [Crossmark 참여·업데이트 등록](https://www.crossref.org/documentation/crossmark/participating-in-crossmark/)

arXiv는 공개된 각 판본을 과학 기록의 영구 부분으로 보며, 교체나 철회는 새 판본 번호를 만든다. 철회 판본은 사유를 표시하고 해당 판본의 원문 다운로드를 제공하지 않지만, 이전 판본은 이력에서 계속 접근 가능하다. [arXiv 판본 가용성](https://info.arxiv.org/help/versions.html), [arXiv 철회 정책](https://info.arxiv.org/help/withdraw.html)

## 4. 공식 검색·회수 경로와 한계

| 경로 | 공식적으로 확인한 범위 | 재현성에 관련된 사실 |
| --- | --- | --- |
| MSC2020 / zbMATH Open | MSC는 PDF·TeX·CSV로 배포되고, zbMATH는 문헌·저자·연속간행물·소프트웨어·분류 검색을 제공한다. | 검색 결과의 zbMATH ID와 사용한 MSC 판본을 구별할 수 있다. [MSC2020](https://msc2020.org/), [zbMATH 도움말](https://zbmath.org/frequently-asked-questions/) |
| Crossref | REST API는 가입·등록 없이 사용 가능하며, `mailto` 또는 `agent`를 넣는 polite 접근을 권장한다. | 결과는 기탁 회원과 신뢰 출처의 메타데이터이므로 조회 시점에 따라 변경될 수 있다. [Crossref 접근·인증](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/) |
| arXiv | 공개 API와 bulk 경로가 있으며 API 이용자는 약관·기초·사용자 설명서를 검토해야 한다. | API는 식별자·메타데이터 회수 경로이고, 특정 원문은 판본 접미사와 실제 회수본으로 구별된다. [arXiv API 접근](https://info.arxiv.org/help/api/index.html), [API 기초](https://info.arxiv.org/help/api/basics.html) |
| GitHub | 공개 저장소의 release·commit API는 코드와 배포물의 좌표를 제공한다. | tag, commit, release asset은 별도 객체다. [GitHub Releases API](https://docs.github.com/en/rest/releases/releases) |

이미 승인된 기관·학술 DB 경로의 실제 인증 절차와 이용 조건은 이 공개 조사로 일반화하지 않았다. 그 경로는 해당 기관이 제공하는 현재 이용 화면·약관과 승인 범위에서만 판정할 수 있다.

## 5. 사실에서 나오는 보존상의 주의

다음은 위 서비스 사실에서 나오는 비설계적 주의다.

- Crossref의 관계·업데이트와 Crossmark 상태는 기탁·보강 데이터다. 따라서 Crossmark 또는 update 관계가 없다는 사실만으로 정정·철회가 없다고 결론내릴 수는 없다. 이는 업데이트 등록이 출판자 기탁에 의존하고 사소한 변경은 별도 통지가 아닐 수 있다는 문서에서의 추론이다.
- arXiv 기본 ID는 최신 판본으로 해석되므로, 특정 판본을 읽었다는 주장은 버전 접미사 또는 회수한 파일의 식별 정보 없이는 고정되지 않는다.
- 검색·색인 응답과 원문 파일은 다른 대상이다. 외부 레코드의 식별자·조회 시각·응답 또는 파일 해시를 함께 남기면, 후속 판독자가 같은 외부 좌표와 실제 사용 판본을 구별해 다시 확인할 수 있다. 이는 Crossref·arXiv·GitHub가 각각 갱신 가능한 메타데이터·판본·배포 객체를 노출한다는 사실에서의 재현성 추론이다.
