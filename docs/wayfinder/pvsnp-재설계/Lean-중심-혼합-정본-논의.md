# Lean 중심 정본의 역사적 검토

## 1. 문서의 지위

이 문서는 Lean을 사후 보강 도구가 아니라 수학 내용의 정본으로 사용하는 방안을 검토한 역사 기록이다. 최초 문서는 `확실·불확실` 연구 지도와 Lean을 결합한 혼합안을 제안했다. 후속 결정은 그 연구 지도 구조를 대체했다.

현행 결정은 `docs/wayfinder/pvsnp-재설계/컨텍스트.md`가 요약한다. 보편 연구 방법의 상세는 [「보편 수학 연구 스킬 do-math의 통합 설계를 확정한다」](https://github.com/MegasKomnenos/math/issues/18)가 소유한다. P와 NP의 정확한 Lean 정의는 [「P vs NP 핵심 Lean 정의를 완성하고 검증한다」](https://github.com/MegasKomnenos/math/issues/20)가 소유한다.

## 2. 현행 결정으로 채택된 부분

후속 결정은 다음 원칙을 채택했다.

- 수학 정의, 명제, 관계와 증명은 Lean 정본에 둔다.
- 연구 아이디어, 문헌, 실패와 계획은 연구 작업공간에 둔다.
- 편입 전 Lean 후보와 검사 자료는 Lean 형식화 작업공간에 둔다.
- 미해결 명제는 Lean 정본의 공리로 선언하지 않는다.
- 의도 인증과 Lean 검사를 모두 통과한 내용만 Lean 정본에 편입한다.
- 공리 의존, 도구체인과 Mathlib 판본을 기초 프로필로 관리한다.

이 구성을 현재 문서에서는 `Lean 중심 혼합 정본`이라고 부르지 않는다. 현행 용어는 연구 작업공간, Lean 형식화 작업공간과 Lean 정본이다.

## 3. 대체된 부분

최초 제안은 별도 연구 지도 스키마가 다음 정보를 정본으로 소유한다고 보았다.

- `확실·불확실` 상태
- 노드·간선, 뭉텅이와 연결 가설
- 검토단 판정과 이의
- 비활성 이력과 상태 전이.

현행 체계는 이 스키마를 실행 정본으로 채택하지 않는다. Lean 정본이 형식 수학 내용을 소유한다. 단일 작업 DAG와 연구 작업공간이 연구 과정과 실행 상태를 소유한다. 좁은 부정 결과는 실제 범위의 독립 Lean 정리 후보로 다룬다.

## 4. 유지할 기술적 경계

### 4.1 불확실 명제와 공리

Lean에서 명제의 내용만 정의하면 그 명제의 참을 가정하지 않는다.

```lean
def p_ne_np : Prop := P ≠ NP
```

다음 선언은 증명 없이 `P ≠ NP`를 사용할 수 있게 한다.

```lean
axiom p_ne_np_proof : P ≠ NP
```

미해결 명제를 둘째 형식으로 선언하면 미입증 내용이 다른 정리의 의존 경로에 들어간다. 현행 Lean 정본은 이 방식을 금지한다.

### 4.2 Lean이 직접 보장하지 않는 정보

Lean 커널은 형식 명제와 증명 항을 검사한다. Lean 커널은 다음 정보를 자동으로 판정하지 않는다.

- 자연어 의도와 Lean 형식문의 의미 일치
- 문헌을 정확히 이해했는지 여부
- 연구 아이디어의 유망성
- 작업 우선순위와 실패 환류
- 검토 기록의 독립성.

이 정보는 연구 작업공간, 인증 기록과 작업 DAG가 관리한다.

### 4.3 기초와 외부 라이브러리

정리 이름이 같아도 계산 모형, 부호화, 환원과 기초가 다를 수 있다. 외부 Lean 결과를 사용할 때는 정의와 가정의 대응을 확인한다.

현행 Lean 정본은 Mathlib 밖의 전문 라이브러리를 직접 의존하지 않는다. 필요한 수학 내용은 우리 Lean 언어로 다시 작성한다. 두 모형 사이의 부호화, 시뮬레이션과 등가는 우리 Lean 정리로 입증한다.

## 5. 현재 열린 구현 문제

다음 사항은 이 역사 문서가 결정하지 않는다.

- 세 작업 영역의 물리 저장 구조
- 정본 편입 단위와 판본 전이
- 인증 역할, 검토 기수와 이의 처리
- Lean 도구체인과 Mathlib의 정확한 판본
- 격리 빌드, 목표 형식문 비교와 외부 검사기 사용 절차
- 핵심 P·NP 정의의 정확한 Lean 자료구조.

`do-math` 통합 설계와 핵심 Lean 정의 티켓이 각 소유 범위에서 이 문제를 닫는다.

## 6. 사용 경계

후속 세션은 이 문서를 Lean 정본 결정을 만든 근거와 기술적 위험을 이해하는 데만 사용한다. 후속 세션은 최초 연구 지도 스키마와 대안 기초 프로필 제안을 현행 요구로 사용하지 않는다.
