# 입증 검토와 `verify-rounds`의 역사적 검토

## 1. 문서의 지위

이 문서는 2026-08-28 당시 `verify-rounds`를 수학 입증 검토에 활용할 수 있는지 조사한 기록이다. 이 문서는 현행 인증 절차가 아니다.

초기 조사는 [「연구 운용 루프를 설계한다」](https://github.com/MegasKomnenos/math/issues/14)의 입력이었다. 그 티켓은 해결 결정 없이 통합 대체됐다. 현재 [「보편 수학 연구 스킬 do-math의 통합 설계를 확정한다」](https://github.com/MegasKomnenos/math/issues/18)가 보편 인증, 검토와 실패 처리 절차를 소유한다.

이 문서의 `verify-rounds` 설명은 조사일의 계약에 상대적이다. 현행 도구를 재사용하려는 세션은 현재 스킬과 계약을 다시 읽어야 한다.

## 2. 조사한 질문

조사는 다음 두 판정을 구별했다.

1. 완성된 산출물에서 결함과 수정안을 찾아 적용하는 판정
2. 수학 입증이 논증 의무 전건을 충족하는지 승인하는 판정.

2026-08-28 당시 `verify-rounds`는 첫째 판정을 수행했다. 수리자는 결함 주장과 수정안을 함께 냈다. 심사자는 입증 전체가 아니라 제안된 결함과 수정안을 판정했다.

`verify-rounds` 종료는 지정한 계약 아래에서 승인된 수정안이 더 나오지 않았다는 뜻이었다. 종료는 수학 명제가 입증됐다는 뜻이 아니었다. 모든 수리자가 같은 결함을 놓치면 심사자는 그 결함을 판정하지 못했다.

## 3. 재사용 후보였던 구성

초기 조사는 다음 구성을 재사용 후보로 기록했다.

- 목적, 불변식, 산출물과 기준 원문을 고정하는 동결문
- 서로 결과를 보지 않는 수리자와 심사자의 독립 파견
- 결함의 위치, 기준, 영향과 수정안을 보존하는 서식
- 여러 수정안의 충돌을 병합하는 절차
- 수정안별 독립 심사와 집계
- 수정 뒤 산출물 전건을 다시 검사하는 반복
- 발견, 판정, 적용과 잔여 문제를 보존하는 장부
- 라운드별 사본, 원문 대조와 커밋 경계.

이 목록은 현행 `do-math`가 채택해야 하는 닫힌 요구가 아니다. 통합 설계는 각 구성이 현재 인증 목적에 필요한지 다시 판정한다.

## 4. 수학 입증 승인에 부족했던 기능

초기 `verify-rounds` 계약에는 다음 보장이 없었다.

- 전체 검토자가 논증 의무 전건을 판정하는 보장
- 결함을 제안하지 않은 검토도 명시적 판정을 남기는 보장
- 자연어 의도와 Lean 형식문의 의미 대응 판정
- Lean 커널 수락과 공리 의존 감사
- 신뢰한 목표 형식문과 제출 형식문의 동일성 검사
- 미해결 이의나 판정 불능이 있으면 편입을 막는 관문
- 판본을 바꾸면 이전 검토 승인을 무효화하는 규칙.

후속 논의에서는 전체 검토자, 부분 전문 검토자, 이의 심사자와 고정 집계 규칙을 제안했다. 사용자는 이 세부를 독립 결정으로 확정하지 않았다. 해당 제안은 현행 실행 계약이 아니다.

## 5. 현행 결정과의 관계

현행 연구 체계는 의도 인증과 Lean 검사를 서로 다른 관문으로 둔다. `do-math`는 판정자를 배정하고 결과를 기록하지만 판정을 바꾸지 못한다.

Lean 공식 검증 지침은 커널 수락, 공리 감사, 목표 형식문 비교, 격리 빌드와 외부 검사기를 구별한다. 정확한 검토자 역할, 기수, 판본 전이, `verify-rounds` 재사용 여부와 종료 조건은 `do-math` 통합 설계가 결정한다.

수학 판단 역할에는 `gpt-5.6-sol max`를 사용한다. 기계적으로 완전 판정할 수 있는 검사만 스크립트나 충분한 경량 모델에 맡길 수 있다.

## 6. 사용 경계

후속 세션은 이 문서를 다음 목적으로만 사용한다.

- 수정안 중심 검증과 입증 승인 사이의 차이를 이해한다.
- 기존 검증 하네스에서 재사용할 수 있는 장치를 찾는다.
- 초기 제안이 놓친 승인 보장을 확인한다.

후속 세션은 이 문서의 검토단 구성, 집계와 종료 제안을 현행 결정으로 사용하지 않는다. 후속 세션은 `verify-rounds`의 현행 스킬과 계약을 다시 읽고, 통합 설계의 목적에서 절차를 결정한다.
