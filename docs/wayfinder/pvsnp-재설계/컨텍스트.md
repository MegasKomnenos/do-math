# 컨텍스트 정본 — wayfinder 지도 「P vs NP 연구 체계 재설계」

## 0. 지위와 읽기 계약

이 문서는 wayfinder 지도 [「P vs NP 연구 체계 재설계」](https://github.com/MegasKomnenos/math/issues/6)의 현행 컨텍스트 정본이다. 지도 아래의 티켓을 수행하는 세션은 착수 전에 이 문서 전문을 읽는다.

문서별 소유권은 다음과 같다.

- 루트 `CONTEXT.md`는 구현 세부를 제외한 보편 수학 연구 용어를 정의한다.
- `docs/do-math/통합-설계.md`는 `do-math`의 상태·권한·저장·실행·검증·복구를 구현할 규범 계약을 소유한다.
- P vs NP 프로젝트 입력은 `research/pvsnp/연구-주제-선호.md`, `research/pvsnp/핵심-정의-명세.md`, `research/pvsnp/문헌-체계-명세.md`와 승인·동결 문헌 지도다.
- 이 문서는 지도 목적, 티켓 사이의 소유권, P vs NP 프로젝트 계약과 과거 자료의 참고 경계를 소유한다.
- 열린 작업과 선행 관계의 정본은 GitHub 하위 이슈와 차단 관계다.

보편 용어의 정의나 `do-math`의 구현 세부를 이 문서에 다시 쓰지 않는다. 이 문서와 다른 정본이 충돌하면 먼저 위 소유권으로 실제 소유자를 판정한다. 중요한 판단은 요약이 아니라 소유 원문을 다시 읽어 대조한다.

같은 티켓을 이어가는 세션은 결정마다 이 문서와 루트 `CONTEXT.md`를 증분 수정하지 않는다. handoff, 티켓 종료나 그 밖의 세션 종결 시 그 세션의 확정 결정을 원자료와 대조해 한 번에 반영한다. 새 결정이 대체한 문면과 중복도 함께 제거한다. 티켓을 닫는 세션은 이 일괄 갱신을 커밋하고, 바꿀 것이 없으면 해결 댓글에 `정본 갱신: 영향없음`을 명시한다.

## 1. 목적과 범위

이 지도의 종착은 P vs NP 연구 체계를 재설계하고 보편 수학 연구 스킬 `do-math`를 구현·검증해 실제 연구를 시작할 수 있는 상태다.

이 지도는 다음 산출을 포함한다.

1. P vs NP 연구 주제·성공·범위·방향의 프로젝트 입력
2. P와 NP의 정확한 핵심 Lean 정의와 연결 정리 명세
3. 연구 시작 전 승인·동결할 문헌 기준선과 그 구축 계약
4. 보편 `do-math`의 자기충족적 통합 설계
5. `do-math` 구현과 격리된 검증

실제 P vs NP 문헌의 후속 재판독, Lean 연구 정본 구축과 증명·반증 시도는 이 지도의 범위 밖이다. 기준선 문헌 조사와 `do-math` 구현 검증은 실제 연구를 시작하기 위한 선행 산출이므로 범위 안이다.

## 2. 보편 설계와 티켓 소유권

`K`, `F`, `U`, 연구 진전, 형식 타당성, 해설–형식 동일성과 신뢰 시대의 뜻은 루트 `CONTEXT.md`가 소유한다. 해당 개념의 운용·직렬화·상태 전이는 `docs/do-math/통합-설계.md`가 소유한다.

`do-math` 통합 설계는 다음 원리를 구현 계약으로 닫는다.

- 수학적 사실의 형식 정본은 유효한 신뢰 시대의 Lean 정본이다.
- 수학 해설은 사람이 읽는 주 산출물이며, Lean 표현과 같은 의미인지 독립 인증한다.
- 연구 작업공간, Lean 형식화 작업공간과 Lean 정본을 분리한다.
- F 객체·F 종류 정의·관계·관계 종류 정의·자료·근거·공용 연구 기억·연구 맥락은 엄격한 frontmatter와 Markdown 본문을 가진 지식 개념 문서로 저장한다. 컨테이너 관례는 해시로 고정한 OKF v0.2 부분집합을 쓰되 의미는 `do-math`의 닫힌 프로필이 소유한다. 정체성은 의미 경로와 분리된 ID가 소유하고, 항해 색인은 공용 편입마다 다시 만든다.
- 작업 씨앗과 연구 작업은 같은 `task_id`를 쓰고, 실행만 별도 `execution_id`를 가진다.
- 작업 DAG를 두지 않는다. 실행 껍질은 특정 공용 커밋에서 착수 가능한 작업만 담는 깊이 1 파생 보기다.
- 포트폴리오 선택 packet은 작은 통치·이력·용량 자료는 전문으로, 규모와 함께 자라는 후보·지식·K는 목차로 제공한다. 선택자는 기준 공용 커밋의 읽기 전용 checkout에서 원자료를 재량으로 열람하고, 실제 결과를 다음 선택에 환류한다.
- 작업 씨앗은 주기 도래 또는 실행 껍질 고갈로 여는 생성 회차가 계속 공급한다. 생성자는 탐색과 집중 활용, 폭넓은 렌즈의 씨앗을 함께 고려하되 생성량·배합·렌즈 산출에는 쿼터가 없고, 씨앗의 추구는 포트폴리오의 재량이다.
- 결정론적 도구는 입력·무결성·권한·동시성·형식 조건을 검사하며 수학 판단을 대신하지 않는다.
- 작업별 격리, 외부 감시, 운영 점검, Git 조건부 ref 갱신과 원자적 종결 편입은 통합 설계가 정한 단일 계약을 따른다.
- 스킬 구현은 `.agents/skills/do-math/`의 `SKILL.md`, 자기충족 `GLOSSARY.md`, 역할별 `계약/`, 공통 `references/`, `schemas/`, `scripts/`로 나눈다. `SKILL.md`의 단일 역할 읽기 대응표가 각 AI 역할의 진입 문서와 참조 문서를 정하고, 인스턴스 계약은 스킬 문서 묶음의 경로와 해시를 고정한다.

위 목록은 구현 세부의 제2 정본이 아니다. 정확한 상태값, JSON 스키마, ref, 전이, 실패 처분과 테스트는 통합 설계에서만 읽는다.

`do-math` 통합 설계는 프로젝트 중립의 보편 계약이며 P vs NP 유래 내용을 담지 않는다. `do-math` 구현, P vs NP 프로젝트 입력 패키지와 P vs NP 문헌 조사는 서로 분리되며, 문헌 조사는 별도 세션에서 수행하고 `do-math` 문면과 계약으로 결합하지 않는다. P vs NP의 검증 기준과 수학 소재는 3절의 프로젝트 입력이 소유하고, 초기화의 일회성 수입과 연구 헌장·정책·종류 정의·감사 계약이라는 일반 기구로만 연구 인스턴스에 들어간다.

`do-math` 구현 완료는 보편 테스트 벡터와 대표 연구 워크스루로 검증한다. P vs NP 인스턴스 초기화나 해답 fixture는 구현 완료 조건이 아니며, 이를 대신하는 가상 프로젝트 fixture도 현행 계약에 두지 않는다.

## 3. P vs NP 프로젝트 입력

정적 프로젝트 입력은 다음 세 문서다.

1. `research/pvsnp/연구-주제-선호.md`: 전체 연구 주제, 원하는 결과, 성공·부분 성과, 범위·방향, 문헌·학술 검증 선호
2. `research/pvsnp/핵심-정의-명세.md`: P와 NP의 정확한 수학 정의, 부호화·기계 모형과 연결 정리 의무
3. `research/pvsnp/문헌-체계-명세.md`: 연구 시작 전 문헌 기준선의 주제·깊이·수렴·동결 계약

문헌 명세에 따라 구축하고 승인·동결한 문헌 지도와 완료 증거는 세 정적 문서와 구별되는 네 번째 입력 묶음이다. 네 입력의 주제와 소유 관계가 일치하고 문헌 기준선의 완료 증거가 유효할 때만 P vs NP 연구 인스턴스를 초기화한다.

초기화는 입력 의미 전건을 연구 헌장·정책·맥락·설정, 초기 `F`, 자료·근거, 사용자 결정과 그 밖의 정확한 내부 소유자에 한 번 수입한다. 평시 재개는 외부 입력을 다시 읽지 않는다. 입력 하나를 임의로 우선해 충돌이나 누락을 숨기지 않는다.

## 4. 핵심 수학 목표와 기초

핵심 P와 NP 정의는 이진 문자열 언어, 결정론적 단일 테이프 Turing 기계의 최악 경우 `n^k+k` 시간과 다항 길이 증명서를 검사하는 결정론적 다항시간 검증자를 뼈대로 사용한다. 다른 표준 정의·기계·부호화는 우리 Lean 언어로 작성한 연결 정리로 핵심 정의에 연결한다. 실제로 입증한 관계가 등가보다 약하면 등가라고 부르지 않는다.

수학적 해결은 핵심 정의의 `P = NP` 또는 `P ≠ NP` 증명 항이 해설–형식 동일성, 커널 검사, 공리 감사, 범위 차분 감사와 프로젝트별 추가 관문을 통과해 Lean 정본에 편입된 상태다. 두 결론 중 미리 선호하는 답은 없다.

조건부 정리, 제한 모형 분리, 장벽 결과와 부분 성과는 정확한 연구 결과일 수 있지만 P vs NP 해결이 아니다. 시간·토큰·비용 한도나 새 접근 부재도 해결이 아니다. 미해결 상태와 재개 좌표를 보존한다.

범위 차분 감사의 P vs NP 판정 어휘는 `동일`, `등가 입증`, `충분성 입증`, `범위 축소`, `범위 확장`, `조건부`, `미해결`이다. 앞의 셋만 목표 해결과 양립한다. 나머지 결과도 수학적으로 타당하고 엄밀하면 실제 범위로 Lean 정본에 편입할 수 있다. 이 어휘와 효과의 프로젝트 권한 원천은 `research/pvsnp/연구-주제-선호.md`다.

활성 기초 프로필은 Lean의 표준 고전 기초 하나다. 공리 허용 목록은 `{propext, Quot.sound, Classical.choice}`다. 다른 기초의 결과는 비활성 대안 프로필에 구분해 보존하며 검증된 번역·해석·보존 정리 없이 활성 `K`에 옮기지 않는다.

ZFC는 Lean 정본과 경쟁하는 제2 정본이 아니라 학계의 통상적 기초와 비교하는 P vs NP 전용 검증 기준이다. `P = NP` 또는 `P ≠ NP`를 최종 해결로 인정하려면 같은 결과를 ZFC나 더 약한 명시적 기초에서 증명하거나, Lean 결과를 그 기초로 옮기는 검증된 번역·해석·보존 정리를 제시해야 한다. 이 기초 이동은 목표 해결 감사의 필수 관문이다.

수학적 해결 뒤에는 사람이 읽는 증명, 자연어–Lean 대응, 재현 환경, 외부 독립 검토, 결함 제보·수정, 적격 출판과 공동체 검토를 수행한다. 외부 공개·출판은 사용자 권한 경계를 따른다.

## 5. 문헌 기준선 계약

P vs NP 문헌 기준선의 조사 우주는 현대 수학과 이론 컴퓨터과학 전 분야다. P vs NP와 가까울수록 분야 해상도를 세밀하게 하고 멀수록 거칠게 한다. 분야는 여러 부모를 허용하는 중첩 계층이며, 깊이는 기초 지식·표준 종합·핵심 원 성과·후속 논쟁과 개선·현행 연구 전선을 구별한다. 출처 유형은 깊이와 다른 축이다.

각 `분야 × 깊이` 칸의 기준 핵심층은 그 칸을 정확히 구별·설명·검증하는 데 필요한 정본·대표 문헌뿐 아니라 대안, 반론, 반례, 경계, 주변 개념과 의존 지식을 포함한다. 고정 문헌 수나 인용 수를 완료 기준으로 쓰지 않는다.

문헌 지도는 원문을 대신하지 않는다. 정확한 판본·재진입 좌표·내용 윤곽·한계·관계를 제공하고 문헌 유래 관계와 AI 유래 미검증 관계를 구분한다. 후속 연구가 수학 내용을 사용하려면 원문을 다시 읽고 현행 검증을 적용한다.

칸 검토는 새 AI 세션들이 이전 판본·이의·답변·피드백 전건을 읽는 회차 교체형 수렴으로 수행한다. 같은 칸 판본을 모든 검토자가 승인하고 미해결 이의가 없어야 충족이다. 고정 회차 상한과 다수결을 두지 않는다. 학계 논쟁·현재 판정 불가, 실제 자료 부재와 허용 경로를 소진한 접근 불가는 그 범위와 근거에 전원이 합의하면 완료를 막지 않는다. 확보 가능한 자료를 놓친 상태는 미충족이다.

공개 웹과 이미 허가된 접근 경로를 사용한다. KUDOS 현행 목록과 사용자 제공 목록의 학술 DB 검색은 승인된 headless 브라우저 경로를 사용한다. 크리덴셜은 로그인에만 쓰고 프롬프트·로그·산출물에 복제하지 않는다. 능동 문의·원문복사·상호대차·유료 구매는 하지 않는다.

적법하게 로컬 보존할 수 있는 원문·코드·데이터는 Git에서 무시하는 `research/pvsnp/literature-baseline/originals/`에 두고 추적 manifest에 판본·해시·접근·권리 정보를 기록한다. 기준선 승인 뒤 문헌 지도는 동결한다. 새 문헌과 새 접근 가능성은 기준선을 다시 열지 않고 연구 인스턴스의 일반 자료·근거로 처리한다.

문헌 체계의 외부 근거와 현재 접근 한계는 `docs/wayfinder/pvsnp-재설계/문헌-체계-외부근거.md`가 설명하고, 전체 규범 계약은 `research/pvsnp/문헌-체계-명세.md`가 소유한다.

## 6. 모델과 사용자 권한

메인 세션·포트폴리오 선택자·작업 씨앗 생성자·연구 작업자, 운영 점검자·운영 처분 심사자, 검토 계획자·동일성 검토자·이의 심사자·부분 전문 검토자와 목표·추가 감사자는 `gpt-5.6-sol max`를 사용한다. 착수 명세 검토자와 전례 적용 1·2차 판정자는 별도의 `gpt-5.6-sol high` 세션을 사용한다. 이 역할에는 `gpt-5.6-terra`를 사용하지 않는다. 기계적으로 완전 판정할 수 있는 파일·해시·스키마·빌드·상태 작업은 판본화된 스크립트나 충분한 경량 모델을 사용할 수 있다.

`do-math`가 병렬화를 직접 운전한다. 연구 작업과 판정 세션 안에서 Codex `ultra`의 내부 다중 에이전트 운전을 사용하지 않는다. 정확한 역할 배정과 동시 용량은 통합 설계의 단일 역할표가 소유한다.

`do-math`는 연구 헌장과 정책 안에서 자율적으로 운전한다. 연구 목적·신뢰 경계, 외부·비가역·재생 불가능한 효과 또는 사용자 절충을 바꾸는 행위는 사용자 결정이나 현재 사례에 적용 가능한 사용자 유래 전례를 요구한다. 내부 상태만 바꾸고 자료·이력을 보존하는 실행 복구는 통합 설계가 정한 독립 심사와 재생 안전 조건을 통과하면 자동 적용할 수 있다.

## 7. 과거 자료와 현재 소유권

새 연구 체계는 종결한 `pvsnp-탐사-1`의 상태, 작업 부채, 완료 판정, 자료구조와 규칙을 승계하지 않는다. 과거 문헌 판독, 출처 원장, 기각 지도, 검증 기록과 보존 산출은 필요한 사실·근거·실패 경위와 원자료 좌표를 확인할 때만 읽는 참고 자료다.

과거 자료의 완료·검증 판정은 새 체계에 전이되지 않는다. 같은 문헌이나 내용을 선택하면 현행 절차로 다시 처리한다. 과거 자료는 원래 좌표에 보존하고 현재 정본에 중복 복사하지 않는다.

주요 원자료 좌표는 다음과 같다.

- P vs NP 문제 정본과 선행연구: `research/p-vs-np-statement-and-prior-work.md`
- P vs NP 주제 선호: `research/pvsnp/연구-주제-선호.md`
- 도구 실사: `docs/wayfinder/pvsnp-재설계/도구-지형-실사.md`
- Lean 표현력 대조: `docs/wayfinder/pvsnp-재설계/Lean-증명-표현력-심층검토.md`
- 기초와 Lean 대조: `docs/wayfinder/pvsnp-재설계/현대수학-기초와-Lean-대조.md`
- 트래커 규약: `docs/agents/issue-tracker.md`

과거 입증 검토 문서의 수리자·심사자 구조를 현행 해설–형식 동일성 인증 사슬과 혼합하지 않는다. 현행 인증 절차는 `docs/do-math/통합-설계.md`만 소유한다.
