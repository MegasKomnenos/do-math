# P vs NP 연구 체계 재설계 컨텍스트

## 0. 지위와 읽기 계약

이 문서는 wayfinder 지도 [「P vs NP 연구 체계 재설계」](https://github.com/MegasKomnenos/math/issues/6)의 현행 컨텍스트 정본이다. 지도 아래의 티켓을 수행하는 세션은 착수 전에 이 문서 전문을 읽는다. 보편 설계와의 대조 기준은 [do-math 통합 설계](../../do-math/통합-설계.md)의 9차 판본, 2026-09-12 본문 개정이다. 아래의 설계 요지는 구현 완료나 P vs NP 연구 인스턴스의 활성화 사실을 뜻하지 않는다.

문서별 소유권은 다음과 같다.

- 루트 [CONTEXT.md](../../../CONTEXT.md)는 보편 수학 연구 개념의 정의 원천이며 구현 GLOSSARY.md의 저작 입력이다.
- `docs/do-math/통합-설계.md`의 소유 절은 `do-math`의 상태·권한·저장·실행·검증·복구 의미를 정한다. 자료 형식·명령 계약은 그 본문과 일치한다고 검증한 정확한 규범 묶음이 소유한다.
- P vs NP 프로젝트 입력은 `research/pvsnp/연구-주제-선호.md`, `research/pvsnp/핵심-정의-명세.md`, `research/pvsnp/문헌-체계-명세.md`와 승인·동결 문헌 지도·완료 증거다.
- 이 문서는 지도 목적, 티켓 사이의 소유권, P vs NP 프로젝트 계약과 과거 자료의 참고 경계를 소유한다.
- 열린 작업과 선행 관계의 정본은 GitHub 하위 이슈와 차단 관계다.

보편 용어의 정의나 `do-math`의 구현 세부를 이 문서에 다시 쓰지 않는다. 이 문서와 다른 정본이 충돌하면 먼저 위 소유권으로 실제 소유자를 판정한다. 중요한 판단은 요약이 아니라 소유 원문을 다시 읽어 대조한다.

설계·정의·프로젝트 결정의 변경은 해당 의미의 소유 원문에 먼저 반영한다. 같은 티켓을 이어가는 세션은 결정마다 이 문서와 루트 `CONTEXT.md`를 증분 수정하지 않는다. handoff, 티켓 종료나 그 밖의 세션 종결 시 그 세션의 확정 결정을 원자료와 대조해 한 번에 반영한다. 새 결정이 대체한 문면과 중복도 함께 제거한다. 티켓을 닫는 세션은 이 일괄 갱신을 커밋하고, 바꿀 것이 없으면 해결 댓글에 `정본 갱신: 영향없음`을 명시한다. 후속 구현에 계약을 넘기기 전에는 통합 설계 16.5절의 원천·소비자 대조를 마치고, 남은 동기화 범위를 완료와 구별해 기록한다.

## 1. 목적과 범위

이 지도의 종착은 P vs NP 연구 체계를 재설계하고 보편 수학 연구 스킬 `do-math`를 구현·검증해 실제 연구를 시작할 수 있는 상태다.

이 지도는 다음 산출을 포함한다.

1. P vs NP 연구 주제·성공·범위·방향의 프로젝트 입력
2. P와 NP의 정확한 핵심 Lean 정의와 연결 정리 명세
3. 연구 시작 전 승인·동결할 문헌 기준선과 그 구축 계약
4. 보편 `do-math`의 자기충족적 통합 설계
5. `do-math` 구현과 격리된 검증

실제 P vs NP 문헌의 후속 재판독, Lean 연구 정본 구축과 증명·반증 시도는 이 지도의 범위 밖이다. 기준선 문헌 조사와 `do-math` 구현 검증은 실제 연구를 시작하기 위한 선행 산출이므로 범위 안이다.

## 2. 보편 설계와 티켓 소유권

보편 개념의 뜻은 루트 `CONTEXT.md`에서, 실행할 정확한 절차는 통합 설계의 소유 절에서 읽는다. P vs NP 프로젝트 입력은 그 보편 기구 안에서 연구 목표·정책·설정값을 제공하며 보편 계약을 재정의하지 않는다.

`do-math`의 채택된 연구 방식은 다음과 같다.

- 온톨로지와 시맨틱 레이어를 통해 K·F·자료·근거·관계·맥락·기억을 축적하고, 현재 질문에 적용할 내용·조건·효력을 대조해 새 결과와 다음 선택에 반영한다. 지식과 메타데이터는 기존 생산자·검토자·생성기의 저작·검사에서 함께 보존한다. 탐색의 깊이는 질문과 근거에 따라 정하며 기존 관계 밖의 통찰도 제안할 수 있다.
- 수학적 사실의 형식 정본은 유효한 활성 신뢰 환경의 Lean 표현이고, 사람이 읽는 해설이 주 산출물이다. 해설의 요약도 함께 작성·검토하며 K 목차는 그 검증된 요약을 회수한다. 형식 타당성·해설 동일성·목표 충족·행동 허가·실행 상태는 서로 대신하지 않는다.
- 인스턴스마다 기계 실행기 하나가 실행 권한·예산·정본 갱신을 소유한다. 연구 정본과 실행 원장은 상태 커밋 하나로 공개하며, 모든 AI 실행과 기계 작업은 공통 실행·격리·권한 회수·종료·복구 계약을 따른다. 과제·활동의 대기, 실행 종료와 원격 자원 정산은 구별한다.
- 작업 예산과 운영 예산은 실제 제약마다 분리한다. 후보 준비·최종 선택·계약 검토는 각자의 역할과 독립성을 유지하며, 준비·검토가 남아 있어도 유효한 기존 후보의 선택은 진행한다. 계약의 공통 전제와 허용 프로필별 전제를 검사하고 연구 수행 요청마다 허용 목록에서 하나를 선택한다. 선택한 요청 수와 실제 동시 점유는 구별한다.
- 준비와 선택에는 통치 전문, 서로 다른 모집단의 후보 목차, K 목차와 필요한 이력을 제공한다. 목차의 상세 원자료는 재량으로 조회하되 실제 사용한 내용과 적용 범위를 남긴다. 입력 초과는 실측과 정해진 분기로 처리하며 필수 내용을 조용히 생략하지 않는다. 반복 교정 문턱은 연구 책임자에게 남겨진 계속 결정이다.
- 수학 검토는 세 기본 관점과 필요한 조건부 전문 검토, 각 검토자의 전건 대조와 독립성을 유지한다. 검토 자리의 자기 메시지는 전건 복원하고 새 제안 판본은 의미 전건을 다시 검토한다. 같은 판본의 복구, 미해결, 성립한 불일치와 실행 미완료는 구별한다. 부분 결과는 정확한 범위로 K에 편입할 수 있다.
- 관찰은 연구 수행의 자기 점검과 사건 기반 운영 점검을 결합한다. 복구 전제가 기계 검사로 모두 확인되면 그 검사로 처리하고, 남은 의미 판단만 독립 복구 확인에 보낸다. 정지 직전 기록과 정지 중 승인된 변환·복구는 각각 한정된 허가를 따르며 일반 연구 재개와 구별한다.
- 입력 원문은 내부 불변 사본으로 보존하고, 의미 수입은 해석·독립 대조·필요한 승인을 거쳐 실제 내부 소유자에 편입한다. 평시 재개는 외부 원본을 다시 읽지 않는다. 판정의 봉인된 내용과 현재 사용 효력은 분리하고 영향은 실제 의존에만 적용한다.

보편 구현, P vs NP 입력 패키지와 P vs NP 문헌 조사는 서로 다른 작업이다. 문헌 조사는 별도 세션에서 수행하며 보편 설계에 프로젝트 고유 검증 기준·수학 소재·모델 배정을 넣지 않는다. 이 내용은 초기화 수입과 연구 헌장·정책·맥락·설정·종류 정의·추가 감사라는 일반 기구로 인스턴스에 전달한다.

2026-09-12 기준, 통합 설계 본문은 채택된 상태지만 그 본문에 맞춘 규범 묶음과 실제 역할 입력의 동기화·재검증은 D08에 남아 있다. `.agents/skills/do-math/`의 스킬 파일은 구현할 대상이며 현재 이 경로에 구현은 없다. 이전 명세 검사 보고나 같은 9차라는 이름은 개정된 동작의 지원 근거가 아니다. 이 문서와 루트 정의의 정리는 D08의 원천 대조 일부이며 전체 완료가 아니다.

구현 완료는 실제 어댑터 능력, 현행 상태·시간선 벡터와 연구 워크스루, 정의·규범 묶음·역할 입력·도구의 일치를 통합 설계 17.4절에 따라 확인한다. 연구 성능 우위와 검토 보증의 실효성은 별도의 실제 평가다. 남은 관문의 담당·시점은 18절이 소유한다. 특히 D01·D02는 실운전·예산 활성화 전에, D04는 검토 방침 채택 전에, D07은 해당 역할 입력 확정 전에 확인한다. D09의 연구 효능은 성능 우위·지원 범위의 주장 전에 평가하며 미평가 프로필은 미평가로 표시한 채 다른 활성화 조건 안에서 운전할 수 있다. D10의 확정 식별자 결정은 규범 묶음의 설치·해시 고정 전에 필요하다.

P vs NP 인스턴스 초기화나 해답 fixture는 보편 구현 완료 조건이 아니다. 통합 설계 17.3절의 가상 수학 사례는 보편 연구 흐름을 검증하며 P vs NP 프로젝트 입력을 모사하지 않는다.

## 3. P vs NP 프로젝트 입력

정적 프로젝트 입력은 다음 세 문서다.

1. `research/pvsnp/연구-주제-선호.md`: 전체 연구 주제, 원하는 결과, 성공·부분 성과, 범위·방향, 문헌·학술 검증 선호
2. `research/pvsnp/핵심-정의-명세.md`: P와 NP의 정확한 수학 정의, 부호화·기계 모형과 연결 정리 의무
3. `research/pvsnp/문헌-체계-명세.md`: 연구 시작 전 문헌 기준선의 주제·깊이·수렴·동결 계약

`research/pvsnp/핵심-정의-명세.md`는 [「P vs NP 핵심 Lean 정의를 완성하고 검증한다」](https://github.com/MegasKomnenos/math/issues/20)의 산출이며 아직 작성되지 않았다. 문헌 명세에 따라 구축하고 승인·동결한 문헌 지도와 완료 증거는 세 정적 문서와 구별되는 네 번째 입력 묶음이다. 네 입력의 주제와 소유 관계가 일치하고 문헌 기준선의 완료 증거가 유효할 때만 P vs NP 연구 인스턴스를 초기화한다.

초기화는 입력 의미 전건을 연구 헌장·정책·맥락·설정, 초기 `F`, 자료·근거, 사용자 결정과 그 밖의 정확한 내부 소유자에 한 번 수입한다. 수입 결과 가운데 연구 헌장·정책·맥락·설정은 연구 책임자가 전건을 읽고 승인해야 활성화된다. 초기 운영 프로필·예산·허가와 대화 소실 정책은 초기화 입력에서 연구 책임자가 준다. 평시 재개는 외부 입력을 다시 읽지 않는다. 입력 하나를 임의로 우선해 충돌이나 누락을 숨기지 않는다.

## 4. 핵심 수학 목표와 기초

핵심 P와 NP 정의는 이진 문자열 언어, 결정론적 단일 테이프 Turing 기계의 최악 경우 `n^k+k` 시간과 다항 길이 증명서를 검사하는 결정론적 다항시간 검증자를 뼈대로 사용한다. 다른 표준 정의·기계·부호화는 우리 Lean 언어로 작성한 연결 정리로 핵심 정의에 연결한다. 실제로 입증한 관계가 등가보다 약하면 등가라고 부르지 않는다.

수학적 해결은 핵심 정의의 `P = NP` 또는 `P ≠ NP` 형식 결과가 커널 검사·공리 감사와 동일성 판정을 통과해 `K`에 편입되고, 목표 감사와 연구 정책이 정의하는 추가 감사인 범위 차분 감사가 충족을 확인해 수학적 해결로 기록된 상태다. 두 결론 중 미리 선호하는 답은 없다.

조건부 정리, 제한 모형 분리, 장벽 결과와 부분 성과는 정확한 연구 결과일 수 있지만 P vs NP 해결이 아니다. 시간·토큰·비용 한도나 새 접근 부재도 해결이 아니다. 미해결 상태와 재개 좌표를 보존한다.

범위 차분 감사의 P vs NP 판정 어휘는 `동일`, `등가 입증`, `충분성 입증`, `범위 축소`, `범위 확장`, `조건부`, `미해결`이다. 앞의 셋만 목표 해결과 양립한다. 이 어휘가 목표 감사의 충족·미충족·미해결 가운데 어디에 대응하는지는 연구 정책의 추가 감사 계약이 적용 전에 고정한다. 나머지 결과도 수학적으로 타당하고 엄밀하면 실제 범위로 `K`에 편입할 수 있다. 이 어휘와 효과의 프로젝트 권한 원천은 `research/pvsnp/연구-주제-선호.md`다.

활성 기초 프로필은 Lean의 표준 고전 기초 하나이며, 이 선택의 프로젝트 권한 원천은 `research/pvsnp/연구-주제-선호.md`다. 그 프로필의 공리 허용 목록, 신뢰 환경의 전환·무효화 절차와 비활성 대안 프로필의 격리 규율은 통합 설계가 소유한다.

ZFC는 Lean 정본과 경쟁하는 제2 정본이 아니라 학계의 통상적 기초와 비교하는 P vs NP 전용 검증 기준이다. `P = NP` 또는 `P ≠ NP`를 최종 해결로 인정하려면 같은 결과를 ZFC나 더 약한 명시적 기초에서 증명하거나, Lean 결과를 그 기초로 옮기는 검증된 번역·해석·보존 정리를 제시해야 한다. 이 기초 이동은 목표 해결 감사의 필수 관문이다.

수학적 해결 뒤에는 학술 검증으로 사람이 읽는 증명, 자연어–Lean 대응, 재현 환경, 외부 독립 검토, 결함 제보·수정, 적격 출판과 공동체 검토를 수행한다. 요구의 정확한 판본은 연구 헌장의 학술 요구가 소유하고, 외부 공개·출판은 연구 책임자의 권한 경계를 따른다.

## 5. 문헌 기준선 계약

P vs NP 문헌 기준선의 조사 우주는 현대 수학과 이론 컴퓨터과학 전 분야다. P vs NP와 가까울수록 분야 해상도를 세밀하게 하고 멀수록 거칠게 한다. 분야는 여러 부모를 허용하는 중첩 계층이며, 깊이는 기초 정의·표기·입문 전거, 표준 종합과 공통 관점, 핵심 원 성과와 논증, 후속 개선·대안·비판·반례·경계, 조사 시점의 연구 전선과 열린 문제, 관련 형식 증명·코드·데이터의 여섯 층위를 구별한다.

각 분야를 여러 깊이에서 살필 때의 기준 핵심층은 그 분야를 정확히 구별·설명·검증하는 데 필요한 정본·대표 문헌뿐 아니라 대안, 반론, 반례, 경계, 주변 개념과 의존 지식을 포함할 수 있다. 고정 문헌 수나 인용 수를 완료 기준으로 쓰지 않는다.

문헌 지도는 원문을 대신하지 않는다. 정확한 판본·재진입 좌표·내용 윤곽·한계·관계를 제공하고 문헌 유래 관계와 AI 유래 미검증 관계를 구분한다. 후속 연구가 수학 내용을 사용하려면 원문을 다시 읽고 현행 검증을 적용한다.

`분야 × 깊이`는 조사 관점이지 모든 조합에 같은 DB 검색·파일·투표를 강제하는 작업 격자가 아니다. 조사 시작 때 KUDOS와 공개 자료원을 한 번 실사하고, 실제 수록 범위와 누락 검출 능력을 확인해 분야별 자료원을 배정한다. 같은 문헌을 찾는 광역 검색을 모든 출판사 플랫폼에서 반복하지 않는다.

공개 웹 탐색, 자료원 선별, 문헌 판단, 정규화, 판본 연결과 누락 검사는 AI가 맡는다. 연구 책임자가 특정 조사 묶음의 자동화를 승인하면 AI가 크리덴셜을 출력하지 않는 로컬 브라우저 프로그램으로 인증 DB 검색과 서지 export도 수행한다. 연구 책임자는 자동화할 인증 검색의 승인이나 프로그램이 처리하지 못한 인증 자료원 검색, 프로그램이 처리하지 못한 DB의 원시 export 저장, AI가 선별한 원문·코드·데이터의 허용 범위 내 확보, 접근 실패나 부분 완료를 보여 주는 최소 증거 저장만 맡는다. AI는 수집 실물을 직접 검사한 뒤 필요한 보충 묶음을 하나씩 연다. 대화가 아니라 `research/pvsnp/literature-baseline/STATUS.md`와 현재 묶음이 협업의 재개 좌표다.

동결의 완료 조건 전건은 `research/pvsnp/문헌-체계-명세.md` 7.4절이 소유한다. 모든 분야의 정한 해상도 포괄, 선정 자료원 검색, 선별한 핵심 작업의 정확한 판본과 재진입 좌표, 핵심 참고문헌과 전후방 인용망 처리, 접근 가능한 핵심 원문의 확보, 판본·정정·철회 기록, 독립 누락 검사의 포화, 로컬 실물 manifest와 추적 산출물의 참조·해시 유효성, `do-math` 최초 수입에 전달할 입력 패키지와 완료 보고의 일치를 모두 확인한 뒤 문헌 집합을 동결한다. 고정 문헌 수·검색 횟수·AI 투표 수는 완료를 대신하지 않는다.

원시 export와 적법하게 로컬 보존할 수 있는 원문·코드·데이터는 Git에서 무시하는 `research/pvsnp/literature-baseline/intake/`와 `originals/`에 두고, 추적 manifest에 판본·해시·접근·권리 정보를 기록한다. 크리덴셜 값은 AI 프롬프트·대화·로그·산출물에 넣지 않으며 승인된 로컬 프로그램만 실행 직전에 읽어 로그인 입력란에 사용한다. 능동 문의·원문복사·상호대차·유료 구매는 하지 않는다.

문헌 체계의 외부 근거와 현재 접근 한계는 `docs/wayfinder/pvsnp-재설계/문헌-체계-외부근거.md`와 `docs/wayfinder/pvsnp-재설계/합리화-자료원-외부근거.md`가 설명하고, 전체 규범 계약은 `research/pvsnp/문헌-체계-명세.md`가 소유한다.

## 6. 모델과 연구 책임자의 권한

모델·노력·실행 어댑터·도구·자원 한도는 통합 설계가 정한 실행 프로필로 정확히 고정하며, 실제 입력 주입·격리·종료 확인의 능력 검사를 통과한 프로필만 실운전에 사용한다. 프로필과 용량의 실제 값은 인스턴스 생성 때 연구 설정으로 승인하고, 초기화 국면의 초기 운영 프로필·예산은 초기화 입력에서 연구 책임자가 준다.

P vs NP 프로젝트가 확정한 모델 배정은 다음과 같다. 배정의 프로젝트 권한 원천은 이 문서이며, 3절의 정적 입력에는 없으므로 초기화 입력의 실행 프로필 값으로 연구 책임자가 준다. 이 배정은 프로젝트 요구다. 보편 계약이 허용 프로필 목록을 지원한다는 이유로 다른 모델·노력을 자동 허용하지 않는다.

- 후보 준비, 연구 계획, 연구 수행, 수입의 의도 해석, 운영 점검, 동일성 검토의 범위 계획자·초기 검토자·쟁점 정리자·이의 답변자·쟁점 판정자, 보충 조사와 목표·추가 감사는 `gpt-5.6-sol max`를 사용한다.
- 작업 계약 검토와 사례 기반 위임 적용의 해석·대조 실행은 별도의 `gpt-5.6-sol high` 실행 프로필을 사용한다.
- 유지보수의 AI 판단에 사용할 모델·노력은 미결정이며 초기화 입력에서 정한다.
- 이 역할에는 `gpt-5.6-terra`를 사용하지 않는다.
- 기계적으로 완전 판정할 수 있는 파일·해시·스키마·빌드·상태 작업은 판본화된 스크립트로 수행한다. 이 범위에 검증된 경량 모델을 사용할 수 있다는 프로젝트 허용은 유지하되, 모델을 사용하면 기계 작업이 아닌 AI 실행으로 분류하고 해당 활동의 예산·허가·검증된 프로필을 적용한다.

`do-math`가 병렬화를 직접 운전한다. 연구 활동과 판정 활동 안에서 Codex `ultra`의 내부 다중 에이전트 운전을 사용하지 않는다.

후보 회수와 의미 탐색, 지식·작업 계약 검토의 재사용, 후보 준비와 연구 계획의 분리·환류, 관찰 적응, 정지 직전 기록, 검토 자리의 연속성과 전면 재검토의 연구 효과와 비용은 통합 설계가 정한 대로 대표 과제에서 비교한다. 역할·문제군별 실제 평가를 실행 프로필과 검토 방침의 근거로 삼으며, 설계 문면이나 fixture 검사의 통과를 연구 성능 향상의 증거로 사용하지 않는다.

`do-math`는 연구 헌장·정책과 연구 책임자의 허가 범위 안에서 자율적으로 운전한다. 연구 목적·신뢰 경계, 외부·비가역·재생 불가능한 효과 또는 연구 책임자의 절충을 바꾸는 행위는 사용자 결정이나 현재 사례에 적용 가능한 사례 기반 위임을 요구한다. 내부 상태만 바꾸고 자료·이력을 보존하는 실행 복구는 통합 설계 12.4절의 결정론 검사와 필요한 독립 의미 확인, 현재성·재생 안전 조건을 충족하면 적용할 수 있다. 연구 수행의 재개에는 계약 검토·최종 선택·착수 조건도 적용하며, 정지 중 변환·복구는 13.5.1절의 정확한 승인 범위에 한정한다. 기계 실행기의 단독 쓰기 권한은 의미 판정을 대신하지 않는다.

## 7. 과거 자료와 현재 소유권

새 연구 체계는 종결한 `pvsnp-탐사-1`의 상태, 작업 부채, 완료 판정, 자료구조와 규칙을 승계하지 않는다. 과거 문헌 판독, 출처 원장, 기각 지도, 검증 기록과 보존 산출은 필요한 사실·근거·실패 경위와 원자료 좌표를 확인할 때만 읽는 참고 자료다.

과거 자료의 완료·검증 판정은 새 체계에 전이되지 않는다. 같은 문헌이나 내용을 선택하면 현행 절차로 다시 처리한다. 과거 자료는 원래 좌표에 보존하고 현재 정본에 중복 복사하지 않는다.
