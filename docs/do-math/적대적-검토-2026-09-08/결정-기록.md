# 9차 초안 결정 기록

작성일: 2026-09-08. 대상: `docs/do-math/통합-설계-초안.md` 9차와 `docs/do-math/통합-설계-명세-v9/`.

이 문서는 8차 초안의 입력 한도 대응을 검토한 뒤 사용자가 확정한 결정과, 그 결정을 초안에 적용한 변경 단위, 제거한 갈래의 복원 조건, 적대 검토의 반영을 기록한다. 이 기록의 문장은 초안의 규정을 대신하지 않는다.

## 1. 출발점

검토 전제는 둘이었다. 실행 프로필이 1M 토큰급 문맥 창을 쓴다. 불필요한 문맥의 적재는 배제하되 필요한 문맥은 들어가는 한 적재한다. 검토는 8차 초안의 한도 대응 규정을 실측 규모와 대조해 여덟 발견을 냈고, 사용자는 그 위에 다음 원칙을 세웠다.

문맥이 넘칠 때의 처분은 원인으로 나눈다. AI 자신의 실수이거나 해결책이 뻔한 원인이면 직접 수리한다. 그 밖의 원인이면 지금 정책을 정하지 않고 사용자에게 상신하고 대기한다. 상신은 해당 활동만 멈추고 다른 활동은 계속하며, 사용자의 답은 기존 기제로 적용하고 재발은 일반 허가로 기계 적용한다.

## 2. 확정된 결정

| ID | 결정 | 근거 |
|---|---|---|
| A | 검토 자리의 복원은 자기 메시지 전건을 보존하고 도구 결과 본문과 이전 판본 제안 전문을 정확한 참조 항목으로 대체한다. 참조 대체는 관련성과 무관하게 종류 전체에 균일하게 적용하며 요약이 아니다. 참조 대체 뒤에도 넘으면 상신한다. 기록 기반 대체 실행은 사용자의 결정 또는 13.2절의 일반 허가로만 열며 검토자가 스스로 열 수 없다 | 봉인은 전건이어야 하고 복원은 봉인에서 재구성 가능하면 된다. 참조는 보존·유일 참조·접근의 세 조건 아래 무손실이며 초안이 셋을 이미 제공한다. 도구 결과 본문이 transcript의 대부분이라 대화로 인한 초과가 사실상 사라진다 |
| A-1 | 이전 판본의 제안 전문도 참조 대체의 대상이다 | 봉인된 artifact이고 수정 대응표가 필수 입력으로 제공되며 검토 의무는 이번 판본 전문이다 |
| B | 한도를 넘는 제안의 재구성은 계획의 판단이다. 실행기가 검토 계획을 만들지 않고 실측을 담은 활동 결과와 함께 활동을 unresolved로 닫으며, 다음 계획이 작성자 과제의 재구성을 개정 준비 요청으로 반환할 수 있고 더 큰 프로필이 필요하면 사용자 결정 요청을 낸다. 결론 폐쇄 분할 갈래는 제거한다 | 제안을 나누는 일은 헌장이 AI에 위임한 연구 방법이고 비용을 수반하는 프로필만 사용자 소유다. 최소 묶음 규칙 아래 주 결론의 폐쇄는 제안 대부분과 겹쳐 분할의 실익이 좁다 |
| C | 목차가 이력을 0으로 줄여도 들어가지 않으면 목차를 자르지 않고 상신한다. 잘림은 사용자 허가가 닫힌 값으로 지정한 목록·순서·활동 종류로만 수행한다. 8차의 partial 갈래와 최소 조합 탐색은 제거한다 | 해법이 후보 정리, 프로필 변경, 잘림 허가이며 전부 사용자 소유다. partial 갈래는 K 객체 수천 개 규모에서만 열리고 목차 항목의 크기가 균일해 조합 탐색이 막는 상황이 목차 형식상 생기지 않는다 |
| D | 선택 출력이 최대 출력에서 잘리면 수신 검사 실패로 같은 입력을 재시도하지 않고 상신하며 선택 실패 횟수에 넣지 않는다. 후보당 출력 몫 상수는 두지 않는다 | 결정론적 실패라 6.6절이 무변경 재시도를 이미 금지한다. 상수 없이 첫 회에 올리는 편이 단순하다 |
| E | 공통 문서·역할 문서·통치 전문이 한도에 맞지 않으면 상신한다 | 그 문서들은 AI가 줄일 수 없는 사용자 문서다 |

| G | 목차 항목의 모델 표현과 정확한 참조를 분리한다. 후보 항목의 모델 표현에 question·scope·excluded_scope·expected_research_change를 기본으로 싣는다. 모델은 ID·revision으로 지목하고 실행기가 manifest의 정확한 참조로 결박해 활동 결과 기록에 남기며 제출된 plan 바이트를 고치지 않는다 | 해시·커밋 문자열은 모델이 판단에 쓰지 않는 바이트다. 계약 전문은 후보 수백 개까지 들어가며 목차만 보고 판단할 위험을 줄인다 |
| H | 수입에서 효력 있는 결정 전문과 이번 수입이 참조하는 과거 원문은 들어가면 목차와 함께 직접 제공하고, 아니면 목차와 회수로 한다. 수입 구간 크기 설정은 두지 않는다 | 8.5절·11.3절의 전문 우선 패턴과 통일한다. 큰 수입은 13.1절의 읽지 못한 범위 반환과 import_rework_limit이 이미 다룬다 |
| I | 계수 수단의 문면. 폐쇄 모델의 계수 수단은 어댑터의 계수 기능이며 execution-profile의 tokenizer 필드가 그 식별자를 가진다. 항목별 계수의 합으로 포장하고 최종 입력을 한 번 더 계수하며, 차이가 여유를 넘으면 최종 계수로 재포장한다 | 폐쇄 모델은 토크나이저 파일이 아니라 계수 API를 제공한다 |
| J | manifest의 순서는 회차 사이에 안정된 부분을 앞에, 회차마다 바뀌는 부분을 뒤에 둔다. 검토 자리의 복원 대화는 공통·역할 문서 뒤, 이번 판본 입력 앞이다 | 프롬프트 캐시가 접두부의 동일성에 의존한다 |
| K | 실행 중 조회·도구 결과 누적으로 한도에 닿으면 어댑터는 요약 없이 호출을 실패로 반환하고 실행기는 execution_incomplete와 원인 context_overflow로 끝낸다. 압축을 끌 수 없거나 보고하지 못하는 어댑터는 대화 복원이 필요한 활동에 쓰지 않는다 | 8차의 무요약 보장이 어댑터 층의 자동 압축으로 조용히 깨질 수 있었다 |
| L | 누적 초과의 자기 수리는 한 번이다. 검토 자리는 참조 대체 복원으로, 연구 수행은 체크포인트로, 그 밖의 AI 활동은 실패 실측을 입력에 더해 다시 시작한다. 같은 자리·활동의 두 번째 누적 초과와 참조 대체 뒤의 잔여 초과는 상신한다 | 사용자의 원칙 A와 같고, 끝내는 사람이 총한도뿐인 되풀이를 막는다 |

## 5. 명세 묶음 v9

`통합-설계-명세-v9/`는 v8을 복사한 뒤 `apply_bundle_v9.py`와 `apply_bundle_review.py`의 치환으로 만들었다. 바뀐 선언은 다음과 같다.

- execution-profile의 ai에 `compaction`의 disabled·evidence_ref·overflow_behavior·overflow_evidence_ref. execution의 종료 기록에 `stop_reasons`와 원인 context_overflow일 때 필수인 `overflow`.
- input-manifest에 `reference_read_refs`, `continuity_break_cause`, 대화 항목의 `restore_form`과 `reference`의 call·arguments_ref·size_bytes, 목록의 `order`, planning_input의 `truncation_permission_ref`, 닫힌 구성 이름의 `provided_order`. canon_exposure·full_canon_tokens·partial_reason 제거. 후보·K 항목의 `view`와 `refs` 분리.
- governance permission에 `truncation`의 lists·order·activity_kinds. runtime의 threshold_holds kind에 context_overflow·output_truncation.
- review-plan에서 scope_allocations·full_proposal_fits·scope_reconstruction_ref 제거, `input_measurement_ref` 추가. issue-state에 `continuity_break_cause`. plan에 `user_decision_requests`. activity-result에 research_plan과 identity_review 결과 종류.
- 규칙 R15·R16·R17·R20·R23·R33·R39 개정, R45 신설. 역할 계약의 검토 단계 입력·권한 문면 개정.
- spec_checks에 pack_listings 재작성과 overflow_disposition·restore_forms·check_plan_binding·plan_receipt_disposition·check_restoration_profile·check_truncation_permission 추가. verify_spec의 review-plan·input-manifest 검사와 시험 개정.

검증 결과는 `validation-report.json`이 기록한다. 실제 어댑터의 압축 제어, 멈춘 이유 반환, 결과별 artifact 수집은 검증하지 않았고 D01의 몫이다.

## 6. 바꾸지 않은 것

- 8.3절의 무요약 원칙, 실측·출력 예약·환경 여유, 초과 시 자동 반복 금지.
- 8.1절의 전문 제공과 발췌 금지, 정확히 한 번 규칙.
- 8.5절의 이력 축소 우선과 후보 난수 순서, history_window 초기값.
- 16.5절의 설계도면 비상주, 17.5절의 컨텍스트 크기를 품질 대체값으로 쓰지 않는 원칙.

## 7. 적대 검토의 반영

`통합-설계-명세-v9/review/adversarial-review.md`가 발견 20건을 냈고 `author-assessment.md`가 지적별 판단을 기록한다. 기각은 없다. 중 발견 여섯은 다음과 같이 닫혔다. 제안 초과의 처분을 8.3절의 별도 항목으로 두어 11.3절과 맞췄다. 상신하는 활동은 미종료 실행이 남아 있으면 working을 유지하고 전건 ended 뒤 waiting으로 간다. 대화를 복원하지 않는 AI 활동의 누적 초과는 실패 실측을 입력에 더해 한 번 재시작하고 재발은 상신한다. 보류는 활동을 현재 결과로 닫는 답이다. 잘림 허가는 permission의 닫힌 truncation 항목이며 검사기가 manifest와 대조한다. 제안 초과의 종료는 실행기의 identity_review 활동 결과로 기록하고 재구성·프로필 요청은 다음 계획의 산출인 사용자 결정 요청과 준비 요청으로 실린다.
