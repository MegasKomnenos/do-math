# 통합 설계 전문 재독

사용자의 전문 재독 지시에 따라 `docs/do-math/통합-설계.md`의 0~20절을 순서대로 다시 읽었다. 17.2절의 접힌 벡터 전건, 19절의 규범 묶음 계약과 20절의 판본 이력도 포함했다. 문서는 2,634행이며 재독 전후 SHA-256은 `98b0f7bf64cd97a4871917a7a93102d7dcaba6fac0537e289284a3230f732ef6`로 같았다.

읽기 범위는 1–120, 121–250, 251–380, 381–510, 511–640, 641–770, 771–900, 901–1030, 1031–1160, 1161–1290, 1291–1420, 1421–1550, 1551–1680, 1681–1810, 1811–1940, 1941–2035, 2036–2140, 2141–2245, 2246–2355, 2356–2470, 2471–2570, 2571–2634였다. 각 범위의 도구 출력을 실제로 읽었으며 잘린 출력은 없었다.

## 재독 후 적용할 판단

정의의 저작 원천은 루트 CONTEXT.md다. 0.3절은 공통 용어와 소유 절을 연결하고, 소유 절이 0.3인 용어는 그 표가 정의한다. 16.5절에 따라 GLOSSARY는 이 원천과 선택한 실행 구조에서 공통 정의를 작성한다. 같은 개념을 역할마다 다시 정의하지 않는다.

SKILL.md는 목적·전체 흐름·역할 읽기 대응표만 단독 소유한다. GLOSSARY는 공통 개념·판정, 역할 계약은 입력·판단·산출·실패 행동, references는 여러 역할의 긴 절차를 소유한다. 긴 정의를 분리할 수 있지만 사용하는 역할에 전문을 배정해야 한다. 파일 하나의 완성도와 실제 독자가 받는 입력의 완전성을 함께 확인한다.

0절의 위임은 구현 수단의 강도를 일률적으로 결정하라는 뜻이 아니다. 목적 기여, 위반 영향, 대안 효과와 개발·운영·복구 비용을 실제 상황에서 비교한다. 기능 목적을 현행 CLI의 한계로 줄이는 것은 명시적으로 금지된다. 따라서 '현재 CLI에서는 다름'은 차이에 대한 사실 설명일 뿐 대체의 적합성을 입증하지 않는다. 목적을 보존한 대체와 실제 미완료를 구별한다.

1.5·7.3.1·8.4절의 지식 저작·탐색·재사용·환류는 연구 수행만의 책임이 아니다. 준비·계획·검토·수입·인계에서 실제 사용한 내용과 조건, 남은 차이와 다음 판단의 변화를 확인한다. 이 내용을 ID나 관계의 목록으로 대체하지 않는다. 일반적인 '정보 상태'의 사용과 연구 기억의 information_status 같은 전용 필드도 문맥에 맞게 구별한다.

5.3절의 종결 처분 이력과 11.8절의 완료 판정 사용 효력은 다르다. 입력이 바뀌면 실제 의존 판단의 현재성을 다시 확인하지만 completed 과제를 planned로 바꾸어 과거 완료를 지우는 것은 별도 문제다. 현재 코드의 source 변경 처리를 재현하여 고친다.

11.5절의 개별 unresolved는 실제 검토 뒤 판단 미확정이다. 활동의 unresolved는 필수 실행·범위 미완료도 포함한다. 실행 미완료에 작성하지 않은 의미 판정값을 끼워 넣지 않는다. 새 판본 전면 검토, 같은 판본의 빠진 자리 복구, 자기 메시지와 참조 대체, 원 이의 답변과 최종 집계를 구별한다.

17.4·17.5절에 따라 문서·전달·실제 동작의 일치와 넓은 문제군에서의 연구 효능은 별도로 검증한다. 정의 제목 수, 코드 테스트 통과, 작은 수학 사례의 성공을 문장 이해의 충분성이나 연구 성능으로 대신하지 않는다.
