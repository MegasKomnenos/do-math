# do-math 문서와 입력 전달 검증

이 기록은 do-math의 공통 정의, 스킬 진입 문서, 역할 계약과 운영 안내를 다시 작성한 뒤, 실제 독자가 뜻을 이해할 수 있는지와 필요한 문서·원자료가 실행에 전달되는지를 확인한 결과다. 문서의 이해 가능성, 코드 동작, 일반적인 수학 연구 성능을 서로 다른 검증 대상으로 다룬다.

기준 원문은 `docs/do-math/통합-설계.md`의 0~20절과 루트 `CONTEXT.md`, `docs/형식과-절차.md`다. 구현자는 통합 설계의 접힌 검증 벡터와 판본 이력까지 포함한 2,634행을 순서대로 다시 읽었다. 재독 전후 통합 설계의 SHA-256은 `98b0f7bf64cd97a4871917a7a93102d7dcaba6fac0537e289284a3230f732ef6`로 같았다. [전문 재독 기록](review/전문-재독.md)은 읽은 범위와 재독 뒤 적용한 판단을 보존한다.

## 무엇을 고쳤는가

사용자는 기존 문서가 필요한 개념을 충분히 정의하지 않고, 내부 구조가 불분명하며, 의미 전달보다 축약을 앞세웠다고 지적했다. 이어 용어를 한 번 정의한 뒤 같은 뜻으로 사용하고, 정의의 위치는 통합 설계에서 확인하라고 요구했다. 이번 개정은 그 요구를 다음과 같이 반영했다.

- GLOSSARY는 루트 CONTEXT와 통합 설계의 소유 절에서 공통 개념·판정의 뜻과 경계를 회수한다. K·F·U, 탐색·집중 활용·연구 진전, 온톨로지·시맨틱 레이어, 과제·활동·실행, 기록과 판정의 효력을 구별한다.
- SKILL은 목적, 전체 연구 흐름과 역할 읽기 대응표를 소유한다. 역할 계약은 공통 정의를 다시 만들지 않고 자기 입력·판단·산출·실패와 다음 소유자를 설명한다.
- 「공통 실행」과 「지식 저작과 재사용」은 여러 역할이 사용하는 긴 절차를 설명한다. 읽기 대응표는 이 문서들도 실제 역할 입력에 연결한다.
- 역할 계약과 운영 안내는 필드 이름을 열거하는 데 그치지 않고, 무엇을 확인하는지와 그 이유, 원자료를 찾는 방법, 결과의 효과와 한계를 설명한다.

원천과 구현의 표현이 다른 경우에는 기능 목적이 실제로 보존되는지를 판단했다. 별도 필드가 없다는 사실만으로 기능 미완료를 확정하지 않았으며, 반대로 필수 자료가 다음 역할에 전달되지 않는 문제를 문장상의 주의로만 처리하지 않았다.

참고한 스킬의 지식과 적용 경계는 [스킬 참고 기록](review/skill-reference-notes.md)에 있다. 독자를 위한 충분한 설명, 정의와 절차의 소유 구분, 실제 수신자를 기준으로 하는 프롬프트 작성, 원천에 근거한 독립 검토를 적용했다. 짧은 문장이나 문서 길이 자체를 품질 기준으로 삼지는 않았다.

## 실제 CLI 독해 비교

같은 세 질문을 개정 전 문서와 개정 중 문서에 각각 적용했다. 두 실행 모두 기존 Codex CLI 로그인과 `gpt-5.6-sol`, `medium`을 사용했다. 독자는 제공된 스킬 문서만 읽고, 코드·통합 설계·외부 검색에서 빠진 내용을 보충하지 않도록 했다. 질문은 개념과 연구 방식, H → P의 부분 결과와 후속 조사, 이의·보충 조사·외부 허가 대기를 다룬다.

| 입력 판본 | 관찰한 결과 | 원자료 |
|---|---|---|
| 개정 전 | U·온톨로지·시맨틱 레이어를 정의에서 찾지 못했다. K를 현재 사용할 수 있는 검증 지식으로 설명했고, H → P의 확보를 연구 진전으로 인정하는 설명도 나왔다. | [질문](readers/before/questions.json), [답변](readers/before/answers.json), [실제 입력](readers/before/evidence/input.txt) |
| 개정 중 | 세 개념과 기존 기록에서 새 질문을 만드는 과정을 설명했다. H → P의 과제 완료·K 편입·목표 해결과 목표 상대적 진전을 구별했다. 다만 기록 기반 대체 실행의 허가 조건을 답변에서 빠뜨렸다. | [질문](readers/after-v1/questions.json), [답변](readers/after-v1/answers.json), [실제 입력](readers/after-v1/evidence/input.txt) |

개정 전 실행은 입력 30,642토큰·출력 4,476토큰, 개정 중 실행은 입력 97,824토큰·출력 4,821토큰을 보고했다. 이는 비교를 위해 모든 역할 문서와 CLI 참조까지 제공한 독해 과제의 비용이다. 실제 연구 역할은 읽기 대응표에 배정된 공통 문서와 자기 계약을 받으므로, 이 수치를 모든 역할 실행의 비용으로 사용하지 않는다.

한 번씩 수행한 독해 표본이며 문서 길이만의 효과를 분리한 실험은 아니다. 답변의 개선은 이 질문에서 확인한 결과다. 수학 연구 성능이나 모든 독자에게 같은 이해가 생긴다는 보증으로 확대하지 않는다.

## 독립 검토와 교정 후 독해

별도 검토 실행이 원천과 문서를 대조해 [독립 독자 검토](review/independent-reader-review.md)를 작성했다. 초기에는 GLOSSARY에서 두 결함을 확인했고, 구현자가 원천과 다시 대조한 뒤 고쳤다.

1. 기록 기반 대체 실행에 필요한 사용자 결정 또는 일반 허가를 명시했다. 대화 복원 실패는 그 자체로 개설 권한이 아니다.
2. 일반적인 결함 제보의 접수와 판정 사용 정지의 발동 근거를 구별했다. 정지는 결정론 검사에서 확인한 결함이나 정식 독립 검토의 구체적인 의미 이의를 근거로 한다.

구현자의 추가 독해에서는 일반 연구 기록의 보존에 형식·동일성 관문을 일괄 요구하는 문장과, 최초 관찰 규칙이 자기 점검을 여는 것처럼 설명한 문장도 고쳤다. 일반 기록 보존과 K 편입을 구별하고, 현행 CLI에서 관찰 조건이 운영 점검을 직접 요청한다는 실제 동작을 설명했다. 운영 점검의 계속 처분에도 현재 진전의 확인을 일괄 선행조건으로 두지 않았다.

최종 문서의 관련 여덟 파일로 새 독해 실행을 수행했다. [교정 확인 질문](readers/corrections-final/questions.json)과 [답변](readers/corrections-final/answers.json)은 다음 핵심 판단을 모두 구별했다.

- 유한 계산 결과를 일반 연구 기록으로 보존하는 일과 형식 결과를 K에 편입하는 일.
- 관찰 조건의 도래, 작업자의 체크포인트, 운영 점검과 근거 있는 계속 처분.
- 대화 복원 실패와 대체 실행 허가, 일반 제보와 판정 사용 정지·재심사·복원·철회의 근거.

이 실행은 입력 63,537토큰·출력 2,444토큰을 보고했다. 독립 검토자도 두 원래 결함의 교정과 일반 연구 기록 보존 문장을 다시 대조하여 통과로 판정했다. 초기 지적과 최초 판본의 좌표는 보고서에 그대로 보존했다. 모든 답변의 표현이 완벽하다는 판정은 아니며, 지정한 조건과 후속 판단을 전달하는지 확인한 결과다.

## 문서와 원자료의 실제 전달

문서 개정과 함께 다음 코드 경로를 보완했다. 각각 입력 누락이나 잘못된 상태 변화를 먼저 재현한 뒤 수정했다.

- 파견 문서 목록을 코드에 따로 유지하지 않고 SKILL의 읽기 대응표에서 읽는다. 모든 역할에 필요한 원문을 순서대로 전달하고 작업 공간 사본, 입력 산출 묶음, 경로·해시·크기와 설치 판본 검사에 연결한다.
- 후보 준비와 연구 계획에 현행 설정 전체를 제공한다. 이전 준비·선택의 원문과 실제 수신 상태를 회수할 수 있게 하여, 반려·미완료 결과가 뒤의 무관한 사건 때문에 사라지지 않게 한다.
- 후보 준비가 제안한 최초 관찰 규칙을 과제의 계약 해시·검토·실행에 연결한다. 새 계약 판본에서는 이전 계약의 실행 중 관찰 변경이 새 최초 규칙을 덮지 않게 한다.
- 원자료가 바뀌어도 완료 과제의 처분 이력을 보존한다. 완료 판정의 현재성을 별도로 정지하고 실제로 그 판정을 사용하는 의존 과제의 착수를 검사한다.
- 종료 뒤 운영 점검에 대상 실행의 결과·체크포인트·부분 파일을 제공한다. 실행기 소실로 최종 결과가 생산되지 않은 경우와, 있어야 할 결과를 읽지 못한 경우를 구별한다.

10개 역할의 문서 배정을 대조했다. 각 역할은 공통 문서 네 개와 자기 계약 하나를 받으며, 고유 구현 문서는 14개다. 읽기 순서와 정확한 바이트, 작업 공간 사본과 영속 자료, 누락·중복·잘못된 배정의 거부를 확인했다. 이 검사는 문서가 전달됐다는 사실을 확인하며 수학적 판단의 정확성을 대신하지 않는다.

## 자동 검증의 판본과 결과

[최초 전체 회귀](regression/initial-full/result.json)는 272건을 실행하여 255건을 통과했고, 2건 실패·14건 오류·1건 미실행을 기록했다. [로그](regression/initial-full/tests.txt)와 [고정 소스](regression/initial-full/source/SKILL.md), [소스 manifest](regression/initial-full/manifest.json)를 보존했다. 명세 자료의 참조 경로와 Lean 사용 불가, 로컬 HTTP 시험의 실패를 통과로 처리하지 않았다.

[최종 문서의 관련 회귀](regression/final-targeted/result.json)는 53건을 통과했다. 문서 배정·원문 전달·설정과 이력·최초 관찰·완료 판정의 현재성·운영 복구 입력·계획과 상태 검사를 포함한다. 전체 회귀에서 이미 통과한 범위를 이 53건만으로 대체하지 않는다.

실패 범위의 [보완 검증 기록](regression/repairs/README.md)은 원인과 후속 결과를 보존한다. 명세 자료 14건과 Lean 검사 1건은 최초 고정 소스를 그대로 두고 필요한 지원 자료와 Lean 경로를 제공하자 [15건 모두 통과](regression/repairs/runs/preflight-formal-v1/result.json)했다. 제품 코드의 결함으로 판정하지 않는다.

HTTP 시험은 요청 본문을 모두 소비하고 성공 응답의 길이를 명시하도록 시험 서버를 고쳤다. 의도적인 응답 소실은 유지했으며 외부 행동 제품 코드는 바꾸지 않았다. [관련 11건](regression/repairs/runs/http-fixtures-current/result.json)과 알려진 실패 뒤 재시도의 독립 반복 5회가 통과했다.

최종 코드 대조에서 운영 점검의 별도 활동 결과와 체크포인트가 같은 복원 경로를 사용해 서로 덮는 경우도 재현했다. 두 경로를 구별한 뒤 [최종 입력 회귀 20건](regression/final-inputs/result.json)을 통과했다. 이 소스의 [manifest](regression/final-inputs/manifest.json)와 수정한 [실행기](regression/final-inputs/source/scripts/do_math/engine.py), [재현 검사](regression/final-inputs/source/scripts/tests/test_currentness_recovery.py)를 함께 보존한다.

최초 전체 검사와 실패 범위의 재검증을 합쳐 보면 272개 검사 가운데 271개의 통과를 확인했고, Windows 토큰에 symlink 생성 권한이 필요한 1개는 미실행으로 남았다. 이는 단일한 최종 전체 실행이 모두 통과했다는 뜻이 아니다. 최초 실행의 실패·오류는 원 기록에 그대로 있으며, 최종 변경은 위의 대상 회귀로 확인했다.

스킬 형식 검사는 정본과 생성 사본 모두 통과했다. 사본 생성 뒤 `build_skill_mirrors.py --check`도 드리프트 없음으로 통과했다. 현재 구현 문서의 정확한 판본은 각 검증 manifest와 실제 CLI 입력에서 확인한다.

[최종 참조 검사](final-checks.json)는 현행 스킬이 마지막 입력 회귀의 소스 manifest와 같고, 진입 문서 19개의 로컬 참조 62개가 존재함을 확인했다. 캡처 자료는 원래 행 끝과 바이트를 보존하며, 복사한 소스 내부의 속성 파일이 이를 다시 정규화하지 않게 했다. [Git에 올릴 바이트의 대조](staged-evidence-check.json)에서는 대상 증거 파일 305개에 원본과 다른 바이트가 없었고 이 작업 밖의 스테이징 경로도 없었다.

## 재현 명령

사용한 [독해 스크립트](scripts/reader_probe.py)와 [고정 사본 검사 스크립트](scripts/verify_snapshot.py)를 보존했다. 경로와 도구 환경은 이번 Windows 작업 공간 `C:\math`를 기준으로 한다. 아래 출력 디렉터리는 아직 존재하지 않는 새 경로를 사용해야 한다.

```powershell
python docs/do-math/문서-검증-2026-09-15/scripts/reader_probe.py --skill .claude/skills/do-math --output .skill-workspace/do-math-doc-recheck/reader --case-set corrections
python docs/do-math/문서-검증-2026-09-15/scripts/verify_snapshot.py --destination .skill-workspace/do-math-doc-recheck/runs/all --repository-support C:/math --lean-bin C:/math/.skill-workspace/do-math-toolchains/lean-4.32.0/lean-4.32.0-windows/bin
```

새 실행은 그 시점의 설치 소스와 모델 응답을 사용한다. 보존된 과거 실행을 그대로 재현했다고 주장하려면 소스·입력·지원 자료와 실제 환경을 해당 manifest에 대조해야 한다.

## 적용 범위

이 기록은 개정한 문서와 연결 코드의 검증이다. 2026-09-14에 수행한 실제 수학 연구·Lean·이의 왕복·학술 후속의 증거를 새 문서 판본의 실행으로 바꾸어 기록하지 않았다. 일반적인 수학 연구 효능과 전문 분야별 검토 강도의 동등성은 별도 평가 대상이다.

현행 구현은 `codex exec`을 사용하며 별도의 OpenAI API 키를 요구하지 않는다. 파일 접근을 모두 기술적으로 차단하는 격리, 공급자 내부 호출별 자원 예약이나 원격 종료의 완전한 관찰을 이 문서 개정으로 제공하게 된 것은 아니다. 실제 구현 방식과 보증 범위는 [CLI 실행 계약](../../../.claude/skills/do-math/references/CLI-실행-계약.md)에서 확인한다.
