# do-math 구현 진행

이 문서는 현행 `통합-설계.md`를 구현하는 작업의 상태와 완료 기준을 기록한다. 구현 정본은 [통합 설계](통합-설계.md)이며, 이 문서는 그 의미·권한·상태 전이를 바꾸지 않는다.

## 현재 상태

초기 실행 경로는 사용자 지시에 따라 `codex exec` CLI로 확정했다. 기존 Codex 로그인으로 실행하며 별도 API 인증을 요구하지 않는다. 구현과 실행법은 [Codex용 README](../../.agents/skills/do-math/README.md)에 있다.

현재 구현한 범위는 다음과 같다.

| 구현 | 실제 기능 |
|---|---|
| `codex_adapter.py`, `codex_worker.py` | 입력·출력 스키마의 실행별 사본, 명시적 CLI 설정과 환경, 정지 생성·재개·중단·JSONL·최종 응답 수집 |
| `windows_job.py` | 생성 시 Job 편입, 허가 전 suspended 상태, 자식 포함 종료, 상속 가능 주변 handle 차단, PID·생성 시각·종료 장벽 |
| `git_store.py` | 단일 상태 ref의 부모 없는 초기 커밋과 단일 부모 후속 커밋, 이전 머리 비교 갱신, 불변 산출 묶음·과거 판본 회수 |
| `budget.py` | 고정한 예약 원자료로 계산하는 work·operations 분리, 공유·호스트 제약의 전건 예약, 미정산 보존과 정산 재전송 |
| `preflight.py` | 명세 원문·벡터·스키마 가족과 바이트·검사 보고의 현재성 검사 |
| `probe_codex.py` | 실제 CLI의 일반 응답·구조화 응답·도구 실행·중도 취소 및 원문·해시 보고 |

[실제 CLI 보고](구현-검증-2026-09-14/cli/report.json)는 선택한 네 사례의 결과를 기록한다. 사용량은 CLI turn의 관찰값이다. 공급자 호출별 ID·사용량·원격 종료와 모델에 전달한 전체 내부 입력, 자동 압축 통제는 별도 미확인으로 남긴다. CLI의 모델 목록과 설정 이름이 존재한다는 사실을 해당 능력의 실증으로 사용하지 않는다.

[Windows 격리 보고](구현-검증-2026-09-14/native-isolation/report.json)에서는 명시한 입력만 읽도록 제한한 프로필이 `Restricted read-only access requires the elevated Windows sandbox backend`로 거부됐다. 현재 구성한 `unelevated` backend에서는 이 프로필을 실행하지 못했다. 검사 프로그램 자체가 실행되지 않았으므로 파일·소켓 접근이 차단됐다는 결과로 세지 않는다. D01을 닫으려면 지원하는 Windows backend에서 전체 접근 경계를 실제로 검증해야 한다. 이 작업에서는 로컬 계정·방화벽·전역 정책을 변경하지 않았다.

Git 저장과 예산 계산은 실행기에 사용할 원시 기능이다. 기록의 의미·실행 허가와 실제 연구 역할을 판정하거나 활성화하지 않는다. 시간창 예산은 호출자가 결박한 예약 모집단을 합산하며, 그 모집단의 완전성과 시간창 효력을 검증하는 원자료 유도 경로는 남아 있다. 통합 운전·복구 상태 기계, 연구 역할 문서, Lean, 현행 시간선 벡터와 연구 워크스루의 실제 실행은 미완료다.

v9 규범 묶음에는 허용 프로필 목록·선택, queued 취소 표현·후보 처분 전개, 해설 요약·K 목차 참조, 검토의 새 쟁점·답변 담당, 수치 관찰의 반복 필드와 현행 V·Q 원천 대응을 추가했다. [현행 명세 보고](통합-설계-명세-v9/validation-report.json)는 갱신한 본문·생성 산출의 해시와 오프라인 검사 범위를 고정한다. 과거 보고는 `review/validation-report-baseline-2026-09-09.json`에 보존했다.

paused maintenance·recovery 승인 범위, machine-check 생성기 결속, knowledge·relation의 전체 원자료·효력·후속 연결, repeat_interval의 단위별 재발동은 아직 형식·관계 검사와 실운전에서 완결하지 않았다. R50·R52 같은 규칙 문장은 이 미완료를 대신하지 않는다. 따라서 D08 전체 완료와 연구 지원을 선언하지 않는다.

## 검토와 수리

독립 검토에서 스키마 JSON을 깨뜨리거나 registry의 가족별 경로를 바꾸고 해시만 맞추어도 현재성 검사가 통과하는 반례를 발견했다. JSON 파싱과 가족·경로·스키마 ID·계약 ID의 대응을 검사하도록 수리하고 두 반례를 회귀 검사에 넣었다.

CLI 검토에서는 원본 입력을 실행 사이에 바꾸었다가 복원하는 경우, 불완전한 사건열, 주변 handle 상속, 임의 CLI 인자 삽입과 진단 실패 시 보고 소실을 확인했다. 고정 사본과 실제 worker 입력 해시, 사건 순서·유일성, handle 비상속, 단일 실행파일 경로와 실패 보고를 검사한다. 스냅샷 파일의 완전한 OS 접근 격리는 위 D01의 남은 사항과 구별한다.

## D01: 첫 실행 어댑터 관문

다음은 실제 연구 역할을 만들거나 활성화하기 전에 닫아야 한다. 소유 절은 [16.1](통합-설계.md#d16)·16.1.1절과 17.1절이다.

- [ ] `describe`가 실제 지원 모델·노력·한도·계수·대화 압축·도구·격리·취소·조회·외부 효과 멱등성 정보를 반환한다.
- [ ] `start`가 실행 ID에 결박한 로컬 프로세스와 CLI thread·turn 또는 이에 준하는 호출 ID, 실제 입력 manifest, 마무리 예약을 반환한다.
- [ ] `inspect`, `stop`, `collect`가 로컬·원격 상태, 사용량·진행 중 도구, 효과 통로 차단, 종료와 결과별 artifact·멈춘 이유를 구별해 반환한다.
- [ ] `verify_isolation`이 중앙 정본·다른 실행·공간 밖 쓰기·직접 네트워크·비밀·IPC·자식 권한 접근의 실제 거부를 검증한다.
- [ ] 대화 복원이 필요한 활동에서 자동 압축을 끄거나 그 사건을 관찰할 수 있음을 확인한다.
- [ ] Windows에서 이름 없는 Job, `KILL_ON_JOB_CLOSE`, breakaway 비허용, `CREATE_SUSPENDED`와 생성 시 Job 편입, Resume 전 상태 공개, PID와 생성 FILETIME, Job의 빈 프로세스 목록과 종료 handle의 대조를 실제 호스트에서 검증한다.
- [ ] 실패 단계, 실행기 소실, PID 재사용, 자식 이탈 시도, 중첩 Job, 호스트 부하를 재현하고 관찰·환경·결과를 보존한다.

D01이 실패하거나 미확인이면 원인을 해소하기 전까지 연구 역할 전체를 만들지 않는다. fixture 상태 기계와 Windows Job 단위 검사는 이 관문을 대신하지 않는다.

## D08: 현행 본문과 v9 규범 묶음의 동기화

이전 보고가 고정한 설계 SHA-256은 `737812…`였다. 현행 보고는 갱신한 본문과 검사 파일을 입력으로 고정한다. 그 통과 범위는 오프라인 명세 검사이며, 아래 D08 항목 전부의 구현·실증 완료를 뜻하지 않는다.

다음 항목은 이미 본문이 선택한 계약이다. 구현자는 새 의미를 정하지 않고 `build_spec.py`의 선언, 관계 검사, fixture, 역할 계약과 생성 산출을 함께 동기화한다.

- [ ] 과제 계약의 비어 있지 않은 `execution_profile_refs`와 실행 요청의 단일 `execution_profile_ref`를 분리한다. 목록 안 프로필 선택·프로필별 현재성·목록 변경의 revision 검사를 구현한다. 근거: 5.2·5.4~5.6, 6.1, 19.5.
- [ ] 해설의 `summary_item_id`·anchor, K 목차의 검증된 요약·정확한 summary ref·요약 부재 표시를 구현하고 동일성 검토에 포함한다. 근거: 8.5, 11.1, 19.5~19.6.
- [ ] 계획의 요청별 프로필 지목, 순서·병행 관계, queued 요청 취소 ID·근거, 명시한 나머지 후보 처분의 후보별 전개와 누락·중복·목록 밖 거부를 구현한다. 근거: 9.2~9.3, 16.3, 19.5.
- [ ] `review-result.new_findings`, `issue-state`의 원 발견 ref와 `answer_role_slot_id`, phase별 필수·금지 필드와 실제 할당 결속을 구현한다. 근거: 11.3.2, 11.4.1, 19.6.
- [ ] 수치 관찰 규칙의 조건부 양의 `repeat_interval`, 발동 경계·범위와 중복 소비 검사를 구현한다. 근거: 12.1.1, 19.4.
- [ ] 정지 중 승인된 변환·복구의 절차·대상·범위·허가, 재정지·최신 원장 보존, `checking_recovery`의 결정론 검사와 의미 판단 분기를 구현한다. 근거: 12.4, 13.5.1, 14.5, 19.4.
- [ ] 생성기가 기계 메타데이터만 결합하고, 모호한 지목을 거부하며, 생성 입력·전개 결과·규칙·해시를 `machine-check`에 결박하게 한다. 근거: 16.3.
- [ ] `.agents/skills/do-math/`의 SKILL.md, GLOSSARY.md, 역할 계약, references, schemas, scripts를 16.5절 역할별 입력·판단·산출·실패 행동에 맞춰 저작한다. 현재 이 경로에는 do-math 스킬이 없다.
- [ ] 지식·관계·원자료·확인 범위·현재 효력·후속 연결을 닫힌 기존 가족과 관계 검사에 둔다. 자유 `activity-result.payload`로 D08의 의미를 우회하지 않는다. 근거: 1.5, 7.3.1, 8.4, 10.1·10.4, 19.3·19.5.
- [ ] 과제 완료·닫힘의 지정 판정, 범위 처분, 소유 research execution 전건 ended 조건과 activity unresolved/finished, execution ended의 별도 보고를 관계 검사와 상태 벡터로 구현한다. 근거: 3.2.1, 5.3~5.5, 11.5, 16.6, 19.4~19.5.
- [x] `source-vector-map.json`을 V01~V254, Q01~Q25, 철회 V159·V162·V189에 맞춘다. 철회 V162를 semantic rule의 source vector로 참조하지 않는다. README와 validation report도 같은 본문·생성 산출 해시를 고정한다. 근거: 17.2, 17.6, 19.8.

생성 단계는 저장소 루트에서 `build_spec.py`, `verify_spec.py --refresh-examples`, 마지막 읽기 검사 `verify_spec.py` 순서로 수행한다. 마지막 검사는 저장된 산출물을 읽어야 하며, 검사 직전의 자동 수리로 결함을 숨기면 안 된다. 새 report는 이전 report를 현행 통과로 가장하지 않고, 검사한 입력 해시·범위·통과·실행하지 않은 영역을 고정한다.

## 17.4 구현 완료 기준

다음 전건이 충족될 때만 구현 완료다.

- [ ] 현행 본문, 루트 `CONTEXT.md`, GLOSSARY, 역할 계약, 규범 묶음, 실제 역할 입력, 도구가 일치하며 가족 표·registry·소유 절·벡터 대응을 양방향으로 확인했다.
- [ ] 실제 실행 어댑터의 필수 능력을 해당 호스트에서 검증했다.
- [ ] 17.2절의 현행 시간선 벡터 전건과 17.3절의 연구 워크스루 전건을 수행해 기대 결과를 확인했다.
- [ ] 권한·형식 타당성·동일성·목표·실행 상태, 원자료 회수·실제 수행 범위, 미완료·미해결·실패·무결과를 실제 동작에서 구별했다.
- [ ] 지식 저작·조회·적용 판단·후속 연결이 실제 역할 입력, 산출, 편입, 재개에서 근거와 효력을 잃지 않고 이어진다.
- [ ] 17.6절의 보존·대체·제거 근거가 실제 역할 입력, 스키마, 도구, 검증 위치와 연결되고 제거한 전제의 잔재가 없다.
- [ ] 구현 중 새 의미를 선택했다면 설계 개정과 승인 범위에 반영했다.
- [ ] 검사 판본, 실행 환경, 실제 범위, 결과, 남은 제한을 불변 보고로 보존했다.

연구 효능·비용과 검토 강도의 실효성은 이 완료 기준과 별도다. 17.5절의 대표 과제 비교와 D09의 근거가 있어야 역할·문제군의 연구 성능이나 지원 범위를 주장할 수 있다.

## 후행 결정과 활성화 경계

D02의 실제 공급자 공유 한도, D03의 대화 소실 정책, D04·D05·D07·D09의 검토·연구 검증 사실, D10의 확정 계약 식별자는 각 소유자가 정한다. 구현 코드나 CLI 어댑터가 이 값을 추측해 채우지 않는다.

D08이 닫히기 전에는 기존 v9 묶음으로 현행 개정 동작을 활성화하지 않는다. D01과 D02가 닫히기 전에는 실제 연구 역할을 활성화하지 않는다.
