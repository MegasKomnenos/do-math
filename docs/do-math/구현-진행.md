기준 시점은 2026-09-15이다. 현재 구현 계약은 `do-math-cli/1`, 기능 판본 2다. 이 문서는 구현·검증 상태를 찾는 진입점이며 do-math의 목적과 전체 연구 흐름을 다시 정의하지 않는다. 목적과 역할별 읽기 순서는 [SKILL.md](../../.claude/skills/do-math/SKILL.md), 공통 개념은 [GLOSSARY.md](../../.claude/skills/do-math/GLOSSARY.md), 운영 방법은 [README.md](../../.claude/skills/do-math/README.md), 구체 CLI 인터페이스와 지원 범위는 [CLI 실행 계약](../../.claude/skills/do-math/references/CLI-실행-계약.md)을 따른다.

후속 독립 검토를 위한 [구현자의 결정과 변명](구현자-결정과-변명.md)은 변경·생략의 맥락, 당시 근거와 사후 설명, 실제 지원 범위와 검증의 한계를 공개한다. 이 기록은 새 구현 계약이나 완료 판정이 아니다. 구체적으로 기재하지 않은 사항은 구현자가 고려하지 않은 것으로 간주하며, 검토자는 추가 변명을 기다리지 않고 평가할 수 있다.

## 현재 연결된 구현

현재 CLI는 인스턴스별 Git ref와 작성자 잠금(writer lock)을 사용하고, 기존 Codex 로그인으로 역할별 AI 실행을 순차 운전한다. 연구 정본과 실행 원장의 의미를 두 JSON 상태 루트와 불변 산출 묶음에 투영한다. 실제 필드·경로·상태값은 CLI 실행 계약이 소유한다.

연구 흐름에서는 후보 준비, 작업 계약 검토, 배정 후보 계산, 별도 연구 계획의 최종 선택, 연구 수행과 완료 판정을 구별한다. 형식 결과가 있으면 중앙 Lean·공리 검사와 동일성 검토를 연결하고, 사용할 수 있는 K와 현재 연구 헌장을 독립 목표 감사가 대조한다. 학술 검증 요구가 있으면 수학적 해결 뒤 별도 과제·판정·외부 행동 영수증으로 이어진다.

지식 기록은 `source` 원문, 지식 후보, 종류 정의와 관계를 구별한다. 지식 재사용은 내용·확인 범위·근거·효력을 현재 질문에 대조하고, 실제 사용한 판본과 남은 차이를 다음 준비·계획·수행에 전달한다. 연구 관계의 존재를 수학적 함의로 바꾸지 않으며, 수학 관계는 정확한 양끝·범위를 입증하는 형식 결과와 동일성 판정을 요구한다.

운전 중에는 입력 manifest와 실행별 작업 공간, 결과 스키마, 체크포인트와 부분 파일을 보존한다. 정지·실패·실행기 소실 때 완료되지 않은 실행을 성공으로 바꾸지 않고, 실제 회수한 결과와 다음 소유자를 새 실행의 복구 근거로 연결한다. 외부 HTTP 행동은 허가와 요청 정체성을 먼저 기록하고, 결과를 확정할 수 없으면 `unknown`으로 남긴다.

## 2026-09-15에 보완한 전달과 후속

이번 문서 개정과 함께 다음 연결을 코드와 스킬 문서에 반영했다. 각 항목의 현재 판본 검증 결과는 문서 검증 기록에서 확인한다.

### 역할 문서 전달

SKILL의 역할 읽기 대응표가 문서 배정의 단독 원천이다. 입력 생성기는 그 표를 해석해 모든 역할에 SKILL·GLOSSARY·공통 실행·지식 저작과 재사용 문서를, 각 역할에는 자기 계약을 순서대로 제공한다. 제공 문서의 경로·바이트·해시는 입력 manifest와 불변 산출 묶음에 고정한다. 필수 문서가 없거나 읽기표가 모호하면 조용히 생략하지 않고 실행 준비를 실패시킨다.

### 준비·계획 입력

후보 준비와 연구 계획은 현재 연구 설정 전문을 받는다. `recent_history`는 이전에 종료한 연구 계획 실행을, 후보 준비의 `preparation_history`는 이전에 종료한 후보 준비 실행을 전건 회수한다. 각 이력 행은 실행 ID, 역할, `outcome`, 오류, `action`과 보존 결과의 정확한 참조·로컬 사본·해시·크기를 가진다. 반려·미완료·무산출도 다음 회차에서 읽을 수 있고, 큰 목록은 원문 catalog의 정확한 참조로 회수한다.

### 최초 관찰 규칙

후보 준비는 새로 만들거나 개정하는 과제에 발생 조건·의존과 함께 최초 관찰 규칙을 제안할 수 있다. 실행기는 그 규칙을 정확한 과제에 결박하고 작업 계약 해시·독립 계약 검토·실제 연구 수행의 관찰기까지 전달한다. 관찰 규칙의 도래는 운영 점검을 열 뿐 연구 진전이나 자동 중단의 판정이 아니다.

### 완료 이력과 원자료 변경

같은 이름의 `source`가 바뀌어도 완료한 과제의 `completed` 상태와 완료 이력은 보존한다. 그 과제의 완료 판정은 `current=false`와 변경 이유로 현재 사용을 정지한다. 과거에 완료됐다는 이력 질의와 그 완료 판정을 새 과제의 실제 의존으로 사용하는 일을 구별하며, 착수 검사는 현재가 아닌 완료 판정에 기대는 의존 조건을 차단한다. 재검증 의무는 완료 과제를 다시 여는 대신 후속 과제로 연결한다.

### 운영 점검과 복구 입력

운영 점검은 대상 실행의 정확한 기록, 관찰 스냅샷, 오류·종료 결과, 체크포인트와 부분 산출 참조, 이전 복구 근거를 입력으로 받는다. 실행 중 점검과 종료 뒤 실패 진단의 처분 어휘를 구별한다. 복구는 이전 실행을 되살리는 일이 아니라 보존한 원자료와 남은 범위를 새 실행에 연결하는 일이다.

## 역사적 검증 근거

아래 수치는 모두 2026-09-14에 보존한 정확한 소스 manifest와 실행 환경에 상대적이다. 현재 문서·코드 판본의 검증 수로 사용하지 않는다.

### 실제 전체 실행 흐름

[기능 판본 2 실행 흐름 보고서](구현-검증-2026-09-14/feature2/workflow/report.json)는 실제 Codex CLI 18회와 실제 Lean 1회를 사용했다. 당시 기록은 작업 실행 8회, 운영 실행 10회, 자연수 오른쪽 영 덧셈의 K 1개, `mathematically_solved`, 학술 검증 `completed`, CLI 인스턴스 `completed`와 대기 실행 요청 0건을 보존한다. 이는 그 작은 사례에서 입력부터 학술 후속까지 연결됐음을 입증하며 일반 수학 연구 성능을 입증하지 않는다.

### 의미 검토

[이의 심사 왕복](구현-검증-2026-09-14/feature2/semantic/dispute/README.md)은 이의 경로를 여는 initial 판단 2건이 합성 fixture였음을 표시한다. 그 뒤 쟁점 정리, 세 판정자, 원 검토 자리의 답변과 같은 판정자의 재심은 실제 CLI 8회로 수행했다.

[부정 의미 사례](구현-검증-2026-09-14/feature2/semantic/negative/README.md)는 실제 Lean을 통과한 `∀n∃m`을 해설이 `∃m∀n`으로 바꾼 입력에 실제 initial 검토자 2명을 실행해 두 `mismatch`와 K 차단을 확인했다. 쟁점 정리 전에 멈췄으므로 최종 쟁점 경로 전체의 mismatch 판정으로 확대하지 않는다.

### 관찰·신뢰·실행 프로필

[실행 중 관찰 증거](구현-검증-2026-09-14/feature2/observation/README.md)는 구버전 쓰기 실패, 실제 체크포인트·부분 산출 회수, 당시 발견한 pause 지속성 결함과 수정 뒤 결과를 판본별로 나눈다. [신뢰 환경 증거](구현-검증-2026-09-14/feature2/trust/report.json)는 실제 Lean 4.32 환경 전환과 허용 밖 공리 거부를 대조하며, 기존 동일성 판정 fixture가 합성이었다는 범위를 보존한다.

[CLI 프로필 증거](구현-검증-2026-09-14/feature2/cli-profile/)는 제한 모드의 실제 쓰기 실패와 선택한 로컬 권한 모드의 파일 쓰기·읽기를 따로 기록한다. 현재 Windows Job의 로컬 수명 보증을 모든 호스트 파일·네트워크·크리덴셜 격리로 확대하지 않는다.

### 회귀

[전체 동결 회귀](구현-검증-2026-09-14/feature2/regression/full/result.json)는 당시 소스에서 261건 중 260건 통과와 Windows symlink 권한 때문에 실행하지 못한 1건을 기록한다. 이어진 계획 변경의 [첫 진단](구현-검증-2026-09-14/feature2/regression/first-targeted-diagnosis/result.json)은 45건 중 1건의 실패 원인을 당시 기록만으로 확정하지 않았고, 시험 HTTP fixture를 보강한 [최종 대상 회귀](구현-검증-2026-09-14/feature2/regression/planning-final/result.json)는 당시 대상 45건의 통과를 기록한다. 이 수치는 현재 문서 판본의 검증 결과가 아니다.

## 현재 검증 상태와 남은 판단

2026-09-15 문서·입력 전달 판본의 독립 검토와 교정 후 CLI 독해를 마쳤다. 최초 전체 회귀와 실패 범위의 보완 검증은 272개 검사 중 271개 통과와 환경상 미실행 1개를 확인했고, 최종 변경은 관련 회귀 53건과 입력 회귀 20건으로 확인했다. 최초 전체 실행의 실패·오류를 지우거나 단일 최종 전체 실행의 통과로 바꾸어 기록하지 않았다. 정확한 판본·범위·원문은 [문서 검증 기록](문서-검증-2026-09-15/README.md)에 있다.

현재 동일성 검토는 동적 범위 계획 대신 모든 initial 검토자와 세 쟁점 판정자에게 제안 전문을 제공하고, 각 검토자가 논증 재구성·범위 반박·의미 동일성의 세 관점을 모두 적용하는 고정 전면 배정을 사용한다. 전문 분야의 독립 자리 자동 선정은 없고 동적 범위 계획과의 검토 강도·비용 동등성은 평가하지 않았다. 필요한 전문성을 확보하지 못하면 미해결과 고정 질문 보충 조사·후속 질문으로 반환한다.

연구 계획의 현재 주 JSON에는 `not_assessable` 전용 필드가 없다. 판정 불가 원인은 보류 이유·질문·준비 요청에 보존하지만 전략적 보류와 기계적으로 분리되지 않는다. 작업 계약 검토도 항목별 판단을 findings에 서술하고 정확한 계약·목표·정책 basis는 실행기가 결합하지만, 항목별 `validity_basis`를 별도 구조 필드로 저장하지 않는다. 이 표현 차이가 실제 의미 보존과 후속 판단에 미치는 영향은 현재 판본의 검증에서 확인한다.

현재 작업·운영 예산은 관찰 가능한 AI 실행 시도 수를 센다. Codex CLI의 turn usage는 보존하지만 공급자 내부 호출별 ID·예약·실시간 사용량과 원격 종료를 완전히 관찰하지 않는다. 현재 기본 Windows 프로필은 기존 사용자 권한을 사용하므로 강한 host 파일·network·credential 격리를 제공하지 않는다. 이 한계는 실제 연구 결과의 의미와 별도로 보고한다.
