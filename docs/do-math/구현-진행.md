# do-math 구현 진행

`do-math` feature 2의 필수 기능 목적은 현재 코드에 연결돼 있다. Windows 실행기는 기존 Codex 로그인의 `codex exec`과 실제 Lean을 사용해 후보 준비, 계약 검토, 계획, 연구 수행, 형식 검사, 독립 동일성 검토, 목표 감사, 학술 후속을 한 Git 정본에서 운전한다. 별도 OpenAI API 키는 요구하지 않는다. 실행법은 [README](../../.agents/skills/do-math/README.md), 영속·제어 계약은 [CLI 실행 계약](../../.agents/skills/do-math/references/CLI-실행-계약.md)에 있다.

[통합 설계 0절의 사용자 위임](통합-설계.md#implementation-judgment)에 따라 목적에 필수인 효과는 구현하고, OS 격리 방식·wire 이름·동시성 같은 수단은 실제 효용에 맞게 선택했다. 현재 계약은 `do-math-cli/1`, 기능 판본은 2다. 과거 `do-math-draft/*/9` 기록과 혼합하지 않는다.

## 구현한 동작

| 영역 | 현재 동작 |
|---|---|
| 공개 명령 | `init`, `run`, `status`, `pause`, `resume`, `close`, `input`, `configure`, `request`, `decision`, `source`, `knowledge`, `trust`, `external`, `conversation`, `query`, `read`, `export`, `check`, `profile` |
| 연구 흐름 | 후보 준비, revision에 결박된 계약 검토, ready 전건 처분, 수행·평가, 사건·조건 기반 후속 계획을 구별한다. 목표·정책·scope 변경 때 기존 의무를 합쳐 다시 검토한다. |
| 수학·의미 | Lean 실행파일·판본·해시·선언 시그니처·공리 의존을 기록한다. Initial 검토, 이의 정리, 원 자리 답변, 독립 판정자 재심과 round 상한을 거쳐 전건 동의한 결과만 K로 편입한다. |
| 목표·학술 | 현재 usable K에 결박한 별도 목표 감사 뒤 수학적 해결을 판정한다. 사용자가 설정한 학술 요구와 필요한 외부 효과는 독립 후속 과제·평가를 통과해야 인스턴스가 `completed`가 된다. |
| 지식·관계 | Raw source와 structured candidate를 구별하고 provenance, 같은 ID revision, 실제 의존 전파, 현재성 hash를 보존한다. 확장 가능한 kind 정의와 research relation을 지원하며, mathematical relation은 정확한 edge·scope에 결박된 proof metadata를 요구한다. |
| 입력·산출 | 역할 문서와 고정 snapshot의 목표·정책·과제·원자료·지식을 제공한다. 큰 입력은 원문 catalog로 보존하고 필수 항목·ready universe를 유지한다. 모델 작업공간의 source·실험 데이터·checkpoint·부분 산출은 누락 이유와 함께 회수한다. |
| 관찰·복구 | JSONL 사건, 도구 실행, idle, checkpoint와 작업자 규칙을 관찰해 inline 운영 검토를 열 수 있다. pause·close·권한 및 입력 변경은 checkpoint 유예 뒤 Windows Job 자손 종료 장벽을 확인하고 부분 산출을 보존한다. 실행기 소실과 외부 효과 `unknown`도 성공으로 바꾸지 않는다. |
| 허가·외부 효과 | 사용자 결정, grant, conversation generation·lease를 단일 writer의 inbox로 처리한다. 외부 요청은 grant와 논리 요청 identity에 결박하고 `prepared/running/confirmed/failed/unknown` 원장을 남긴다. `unknown`은 reconcile 전 재시도하지 않는다. |
| 저장·조회 | GitStateStore의 단일 ref CAS, canonical JSON, 불변 artifact, snapshot-bound cursor, 정확한 `query/read/export`를 제공한다. 적용 실패는 상태와 artifact를 함께 보존한다. |
| 자원·검사 | 작업·운영 CLI 실행 횟수, 실행·run 시간, 검토 회차, 입력·artifact 크기를 제한한다. 역할별 JSON Schema와 참조·현재성·완료 기준을 검사하며 실패도 사용량에 포함한다. |

정본은 `.claude/skills/do-math/`이며 `.agents/skills/do-math/`는 최종 생성하는 Codex 사본이다.

## 영구 실제 증거

[Feature 2 전체 workflow](구현-검증-2026-09-14/feature2/workflow/report.json)는 새 인스턴스에서 실제 Codex CLI 18회와 실제 Lean 1회를 수행했다. 작업 실행 8회와 운영 실행 10회 뒤 `n + 0 = n`의 K 1개, `mathematically_solved`, 학술 요구 `completed`, 인스턴스 `completed`, 대기 action 0을 기록했다. 실행별 입력·schema·출력·사용량, Lean 결과, 최종 상태, source manifest와 복원 가능한 Git bundle이 함께 보존돼 있다.

의미 검토는 두 범위를 따로 검증했다.

- [실제 이의 심사 왕복](구현-검증-2026-09-14/feature2/semantic/dispute/README.md)은 이의 경로를 열기 위한 initial 판단 2건을 합성 fixture로 표시하고, organize 1회·판정자 3회·원 자리 answer 1회·같은 판정자 재심 3회의 실제 CLI 8회를 수행했다. 최종 `match`와 유효한 identity assessment를 기록했다.
- [실제 부정 의미 사례](구현-검증-2026-09-14/feature2/semantic/negative/README.md)는 실제 Lean을 통과한 `∀n∃m`을 해설이 `∃m∀n`으로 바꾼 입력에 실제 initial 검토자 2명을 실행했다. 둘 다 `mismatch`를 찾았고 K는 생성되지 않았다. 이 사례는 organize 이전에 멈췄으므로 최종 이의 심사 전체의 mismatch 판정으로 확대하지 않는다.

[실행 중 관찰 증거](구현-검증-2026-09-14/feature2/observation/README.md)는 세 프로필·판본을 분리한다. 구버전 elevated 쓰기 실패, 실제 checkpoint 기반 inline 운영 검토와 부분 artifact·Job 종료의 성공 및 당시 pause 지속성 결함, 수정 뒤 실제 pause의 최종 `paused`와 바이트 보존을 각각 기록한다. [신뢰 환경 증거](구현-검증-2026-09-14/feature2/trust/report.json)는 실제 Lean 4.32 환경 전환의 성공과 허용 밖 공리의 거부를 대조한다. 신뢰 시험의 기존 identity assessment fixture만 합성이며 컴파일·서명·공리·전환 처리는 실제다.

로컬 외부 효과는 전체 회귀에서 실제 loopback HTTP 원장과 reconcile을 검사했다. [CLI 프로필 양성 사례](구현-검증-2026-09-14/feature2/cli-profile/local-access-pass/report.json)는 Windows Job과 명시 작업경로에서 선택한 `danger-full-access` 프로필의 실제 파일 쓰기·읽기를 확인한다. unelevated `workspace-write`의 상대·절대 쓰기 실패도 같은 `cli-profile/`에 보존한다.

## 회귀와 전달 상태

[전체 동결 회귀](구현-검증-2026-09-14/feature2/regression/full/result.json)는 총 261건 중 260건을 통과했고 1건을 건너뛰었다. Skip은 현재 Windows 토큰에 symlink 생성 권한이 없어 실행할 수 없었던 외부 symlink 검사이며, 누락을 성공 수에 포함하지 않는다. 이 회귀는 순수 상태 의미, model-double 엔진 시간선, 임시 Git, 실제 Windows process·loopback을 함께 검사한다. 모든 순수 상태 벡터를 실제 모델 호출로 반복하는 것은 완료 조건이 아니다.

그 뒤 planning 변경의 [첫 targeted 진단](구현-검증-2026-09-14/feature2/regression/first-targeted-diagnosis/result.json)은 45건 중 44건 통과·1건 실패였다. 학술 요구의 필수 외부 효과 fixture가 loopback 실행을 `unknown`으로 받았지만 당시 예외 원문이 저장되지 않아 원인을 확정하지 않았다. Fixture가 HTTP 요청 본문을 끝까지 소비하고 Content-Length가 있는 응답을 보내며 실행 오류를 기록하도록 보강한 뒤 좁은 반복 검사와 학술 검사들이 통과했고, [최종 targeted 회귀](구현-검증-2026-09-14/feature2/regression/planning-final/result.json)는 같은 대상 45건을 모두 통과했다. 실패 원문과 한계도 별도 보존했다.

필수 기능 구현과 기능 검증은 완료됐다. 정본, 생성한 `.agents` 미러, 검증 자료와 작업 기억을 같은 작업 커밋으로 관리한다.

## 보증 범위

실제 증거는 위 사례와 실행 당시 source manifest에 한정한다. 작은 자연수 항등식과 지정한 의미 반례의 성공은 일반적인 수학 연구 성능이나 의미 판정의 무오류성을 보증하지 않는다.

일반 역할은 명시 지시·선별 입력·별도 세션과 작업공간을 사용하지만, 모든 호스트 경로의 비공개 자료 접근 차단을 보증하지 않는다. 실행은 순차로 배정하고 예산은 관찰 가능한 CLI 실행 단위로 집행한다. 공급자 내부 호출 ID·실시간 사용량 상한·원격 종료·CLI 내부 압축은 완전히 관찰하지 못하며, 로컬 Windows Job 종료와 CLI가 보고한 사용량만 그 범위대로 기록한다. 실제 외부 공용 서비스에 효과를 가하는 호출도 이번 증거에 포함하지 않았다.

`통합-설계-명세-v9/`는 오프라인 명세 자료다. 그 wire·상태 벡터의 모든 형식을 현재 CLI에서 반복 구현하거나 실제 CLI로 전건 재생한 것으로 해석하지 않는다. 현재 완료 판정은 통합 설계의 필수 기능 목적, feature 2 코드, 위의 실제·결정적 검증 증거를 함께 기준으로 한다.
