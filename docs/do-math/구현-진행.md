# do-math 구현 진행

현재 Windows 실행기는 `codex exec`으로 연구 인스턴스를 초기화하고 후보 준비·계약 검토·선택·수행·Lean 검사·독립 검토·목표 감사·후속 연구를 진행한다. 기존 Codex 로그인을 사용하며 별도 OpenAI API 키를 요구하지 않는다. 실행법은 [README](../../.agents/skills/do-math/README.md)에 있다.

구현자는 [통합 설계 0절의 사용자 위임](통합-설계.md#implementation-judgment)에 따라 강한 격리·제약·선행조건도 실제 상황의 실익으로 판단한다. 현재 운전·기록의 정본은 [CLI 실행 계약](../../.agents/skills/do-math/references/CLI-실행-계약.md)이다. 이 선택을 개별 작업마다 다시 승인받지 않는다.

## 구현한 동작

| 영역 | 실제 동작 |
|---|---|
| 운전 명령 | init, run, status, pause, resume, close, input, configure, request, query, read, export, check, profile |
| 역할 입력 | SKILL·GLOSSARY·역할 계약 전문, 고정 snapshot의 목표·정책·과제·원자료·지식과 출력 JSON Schema |
| 연구 흐름 | 후보 준비와 계약 검토·선택의 분리, 전건 ready 후보 처분, 수행 결과의 보존, 독립 완료 판정과 다음 준비·선택 |
| 수학 결과 | 실제 Lean 컴파일·공리 검사, 서로의 이번 결과를 받지 않은 검토 슬롯들의 전면 검토, 전건 동의 뒤 K 편입 |
| 목표 | 별도 목표 감사 전건 동의. 비형식 연구 목표 충족과 mathematically_solved를 구별 |
| 보충·운영·유지보수 | request로 명시적 활동 개설. 실행 실패는 운영 점검으로 진단하고 근거를 추가한 한정 재시도·수정·대기·정지로 연결 |
| 저장 | GitStateStore의 단일 ref·원자 갱신·이전 머리 비교, 불변 artifact, 정확한 과거 snapshot 회수 |
| 제어 | 단일 writer와 control inbox, 실제 Job 정지, 프로세스·활동·과제 상태의 분리, 실행기 소실 뒤 미완료 보존과 재개 |
| 자원 | 작업·운영 CLI 실행 횟수 분리, 호출·run 시간·회차·입력 크기 한도, CLI 보고 사용량 보존 |
| 지식 탐색 | 지식·과제·활동·실행·관계 검색, 관계 방향·종류, snapshot에 고정한 cursor, 정확한 기록·파일 읽기와 export |
| 검사·수리 | 역할별 출력 schema, 참조·범위·완료 기준 검사, 원인과 이전 출력에 근거한 한정 수리, 영속 상태의 판정·실행 결속 검사 |

구현 정본은 `.claude/skills/do-math/`이며 `.agents/skills/do-math/`는 생성한 Codex 사본이다. CLI 상태의 계약 식별자는 `do-math-cli/1`이다. 과거 `do-math-draft/*/9` 스키마와 기록을 혼합하지 않는다.

## 실제 검증

[새 인스턴스의 CLI 전체 흐름](구현-검증-2026-09-14/cli-workflow/report.json)은 init와 run 명령으로 자연수의 `n + 0 = n`을 검증했다. 사용자 개입이나 중간 상태 수리 없이 CLI AI 실행 9회와 기계 형식 검사 1회를 수행했다. 작업·운영 예산은 각각 6회·3회였고, 두 동일성 검토와 두 목표 감사 뒤 K 1개·과제 completed·목표 mathematically_solved·대기 작업 0으로 종료했다. [Lean 소스](구현-검증-2026-09-14/cli-workflow/proof.lean), [해설](구현-검증-2026-09-14/cli-workflow/explanation.md), 입력·출력·판정·상태와 복원 가능한 Git bundle을 함께 보존했다.

[형식 반례](구현-검증-2026-09-14/cli-workflow/formal-cases/report.json)는 실제 Lean 4.32.0에서 정상 정리의 통과, sorryAx·허용 밖 공리의 거부, 없는 선언·잘못된 증명의 실패를 확인한다. [의미 반례](구현-검증-2026-09-14/cli-workflow/semantic-counterexample/report.json)는 Lean이 통과한 ∀n∃m 명제를 해설이 ∃m∀n으로 바꾼 사례다. 별도 CLI 검토자 둘 모두 scope_complete=true와 mismatch를 반환했다. 이 결과는 해당 반례의 탐지를 확인하며 일반적인 연구 성능이나 의미 판정의 무오류성을 보증하지 않는다.

CLI runner는 실제 구조화 응답과 사용량 수집, 실행 중 정지와 재개 전 정지의 종료 장벽을 검증했다. [정지 원자료](구현-검증-2026-09-14/cli-workflow/prestart-stop/)를 보존한다. Git·상태 기계·예산·수리·조회·CLI 명령의 회귀 검사는 모델 응답을 모의한 검사와 실제 Windows 프로세스 검사를 구별해 기록한다.

최종 제어 경계 수리 뒤 [회귀 97건](구현-검증-2026-09-14/cli-workflow/regression/result.json)이 통과했다. 보고에는 실제 검사 파일 15개, 검사 시점의 Python 소스 전건 해시, 실패·오류·traceback을 기록했다. 완료 상태의 재개 방지, 접수 뒤 전제가 바뀐 요청의 거부와 후속 처리, 실행기 소실 시 활동 상태 정리도 포함한다. 별도 v9 오프라인 명세 80건과 스킬 미러·기억 색인 검사도 통과했다.

초기 실제 흐름에서는 작업 ID 배열에 설명문이 섞인 출력과, 목표 감사에 완료된 이전 단계의 근거를 충분히 전달하지 않은 문제가 있었다. 필드의 대상·의미를 명시하고, 이번 동료 판정의 비노출과 완료된 이전 단계의 근거 제공을 구별하도록 수리했다. 위의 새 인스턴스 검증은 그 수리 뒤 처음부터 수행한 사례다.

## 채택한 범위와 보증

일반 역할은 명확한 지시·선별 입력·별도 세션과 작업 공간을 사용한다. Codex의 공유 ACL이 순차·동시 프로필 사이에 간섭한다는 [이전 접근 시험](구현-검증-2026-09-14/elevated-reproducible/report.json)은 여전히 관찰 사실이다. 전용 OS 격리 backend를 전체 구현의 선행조건으로 추가하지 않았으며, 모든 호스트 경로의 비공개 입력 접근이 불가능하다고 보증하지 않는다.

실행은 순차로 배정한다. 예산의 예약 단위는 관찰 가능한 CLI 실행이다. 공급자 내부 호출별 ID·실시간 사용량 상한·원격 종료, CLI 내부 압축의 완전한 통제는 제공하지 않는다. 실제 CLI 사용량과 로컬 Job의 종료는 그 범위대로 보고한다. Lean 소스의 임의 호스트 효과를 완전히 격리하는 기능도 제공하지 않는다.

현재 동일성 검토는 고정 슬롯의 전면 검토와 전건 동의, 수정·추가 조사의 환류를 사용한다. v9의 별도 쟁점 정리·답변·세 심사자 왕복과 검토 자리의 대화 전건 복원은 현재 운전 경로에 추가하지 않았다. 새 세션에 명시적인 입력과 보존된 결과를 제공한다. 이 차이는 CLI 실행 계약과 역할 문서가 정의하며, 원래의 강한 보증과 동등하다고 표현하지 않는다.

## 과거 v9 명세 묶음

`통합-설계-명세-v9/`는 별도 오프라인 명세 자료다. 현재 본문 좌표·해시와 대응을 유지하지만 그 검사 통과를 CLI 실행기의 검증 완료로 사용하지 않는다. D08에 남았던 원래 v9 가족·관계·전건 시간선의 동기화와 실증을 완료했다고 표시하지 않는다. 현재 실행기의 코드·역할 입력·동작·검증은 위 CLI 계약과 실제 보고를 기준으로 읽는다.

실제 연구 목표·기간·모델·작업과 운영 예산·외부 행동의 허용 범위는 인스턴스를 생성하는 사용자가 정한다. 구현 검증에 사용한 작은 정리의 성공을 P vs NP 같은 다른 연구 목표의 해결이나 성능 보장으로 확대하지 않는다.
