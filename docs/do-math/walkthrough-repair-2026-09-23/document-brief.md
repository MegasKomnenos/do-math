독자는 승인된 수리안의 2~8 구현을 확인하는 사용자와 do-math 유지보수 개발자다. 원고는 변경 계약 절의 전문과 필요한 공통 정의, 수리 결과 보고의 전문이다. 변경하지 않은 다른 문서의 전체 독해를 뜻하지 않는다.
확정 구현: 횟수 한도 보류 repetition_hold의 실제 생성자는 record_repetition 하나이고 기술 보류를 별도로 생성하는 경로가 없다. 따라서 제안의 AI 전용 반복 허용·소비 원장은 폐기했다. 사용자 repetition_continue로 현행 계보·보류·정확한 요청 범위를 승인한다. 일반 기술 복구는 기존 운영 처분과 continuation_action_id의 멱등성을 사용한다. 과거 owner=ai 표시는 원문을 바꾸지 않고 사용자 소유 한도 보류로 해석한다. 기존 허가·현재성·외부 효과의 경계는 유지한다.
재저작은 같은 원입력의 새 interpret 실행 등록을 세고 검사와 검사 응답 수리는 제외한다. 선택 실패는 실제 정상 최종 응답의 파싱·스키마·계약 수신 실패를 세며 전제·자원·공급자·공개 대기와 구별한다. 일반 준비만 고정 observed_at 이후 timezone 포함 regenerate_after를 작성한다. 실제 계약 보존 0건일 때만 자동 고갈 시각에 사용하며, 보충은 무산출 집계·보류에서 제외하고 실제 관찰 규칙의 계약 개정은 유지한다. 일괄 수락 지식과 부수 통찰은 한 계획으로 모으고 수락 참조를 남긴다.
수리안과 다른 선택을 결과 보고에 명시하고, 과거 제안은 역사 기록으로 둔다. 원자료 변경에서 실행·활동에 소비하지 않는 필드를 추가하던 영향 전파 오류도 수정했다. 실제 모델·Lean 연구 실행은 하지 않았고, 고정 사본 검사들의 중복 건수는 합산하지 않는다. 선행 미커밋 작업을 이번 변경으로 취급하지 않는다. 코드·검사 원장·원문 근거와 모순하면 원고를 수정한다.
압축 진술: 수리안의 7개 문제를 실제 생산·수신·후속 경로에서 고쳤고, 존재하지 않는 기술 보류를 위한 허용 원장은 추가하지 않았다. 사용자 한도 계속 승인과 기존 기술 복구의 경계를 보존하며 검증 범위를 명확히 기록한다.
경중 선언: 무거운 것은 반복 승인과 기술 복구의 실제 연결, 생성·보충·재저작·수신 실패의 구별 및 검증 범위다. 가벼운 것은 명령·필드·파일 좌표와 기존 배경이다. 뺄 것은 조사 순서와 원고만으로 확인할 수 없는 실제 연구 효과다.
