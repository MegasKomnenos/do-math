### D-06 [유형: 절차문·응답 기한 해석 분기] [심각도: 상] (S-1620, S-1621, S-1622)

### D-07 [유형: 절차문·상태와 종료 종류 혼합] [심각도: 중] (S-1811)
- 원문: "`queued` 요청은 예약·프로세스 없이 `ended/cancelled`로 닫고, `starting`은 stopping/terminating으로, `running`인 AI는 6.4.1절의 허가·원인에 따라 stopping/checkpointing 또는 stopping/terminating으로 옮긴다."
- 지적: 상태(`ended`, `stopping`)와 별도 필드인 종료 종류(`cancelled`)·정지 단계(`checkpointing`, `terminating`)를 슬래시 표기 하나로 결합하고, 세 출발 상태의 처분을 한 문장에 넣었다. 앞서 6.2절에서 세 축을 따로 정의했기 때문에 여기서 `ended/cancelled`를 하나의 복합 상태처럼 읽을 가능성이 생긴다.
- 수정안: `현재 실행 상태 / 다음 실행 상태 / stop_phase / 종료 종류 / 추가 조건` 표로 바꾼다. 예를 들어 queued 행은 다음 상태 `ended`, 종료 종류 `cancelled`, stop_phase `부재`를 각각의 열에 적는다.

K 전건/부분 노출의 이유, 전면 재검토와 같은 판본 복구, 대화 연속 단절, 정지 직전 체크포인트의 수신·미수신과 비용을 표시한다. 검색·입력 초과는 실측 범위와 초과량을, 되풀이되는 수리·실패는 규칙과 원인을 표시한다."
- 지적: 상태 검사의 기계 범위와 사람 보고의 정보 구조가 각각 긴 가운뎃점 목록으로만 제시된다. 항목이 어느 앞 절의 계약을 검증하는지, 어떤 실패가 `degraded`·`blocked`·`incomplete` 중 무엇으로 이어지는지, 사람 보고에서 어떤 제목 아래 보여야 하는지 표면에 드러나지 않는다. 특히 사람 보고는 사람이 읽는 산출물인데도 우선순위 없이 수십 항목을 같은 문장 수준에 놓는다.
- 수정안: 상태 검사는 `검사 영역 / 소유 절 / 입력 / 판정 또는 실패 등급`의 요구 매트릭스로 바꾼다. 사람 보고는 `현재 결론과 보증`, `막힌 일과 다음 행동`, `실행·자원`, `검토·입력 범위`, `근거 링크`처럼 독자의 판단 순서로 절을 나누고, 각 항목이 어느 절에서 파생되는지 연결한다.

### D-09 [유형: 표현·조사 결합] [심각도: 하] (S-673, S-1369, S-1969)
- 원문:
  - S-673: "로컬 실행 슬롯은 기존 실행의 것을 유지하며, 추가 공급자 호출 슬롯은 4절대로 별도 검사한다."
  - S-1369: "검토 실행 몫은 11.3.1절의 단계별 배정으로 계산하며, 실제 실행·원격 호출·사용량의 자원 예약은 4절대로 별도로 집행한다."
  - S-1969: "원격 추론·원격 효과의 종료 및 예약 정산도 4.2절대로 별도 대조한다."
- 지적: `4절대로`·`4.2절대로`는 절 번호와 조사 `대로`가 붙어 "4절에 규정된 그대로"인지 "4절에 따라"인지 되읽게 한다. 같은 표현이 세 번 반복된다.
- 수정안: 각각 `4절에 따라`, `4.2절에 따라`로 고친다.

## 총체 소견

- 수신자성·가독: 문장 단위로는 D-01~D-09가 있다. 형식적이고 절제된 어조는 구현자·후속 검토자에게 적합하며, 비유나 감정적 강조로 규범을 흐리는 문제는 없다.
- 흐름: D-10·D-11. 2절의 정상 흐름과 각 절의 국소 표는 유용하지만, 문서 전체를 어떤 순서와 깊이로 읽어야 하는지 안내가 없고 대규모 검증 벡터가 본문 전개를 오래 끊는다.
- 목적 적합성: 구현 계약에 필요한 의미·상태·예외를 폭넓게 제공한다. 다만 D-08처럼 사람 보고의 정보 구조까지 구현용 필드 열거 방식으로 적은 부분은 사람 수신자의 판단 순서에 맞지 않는다.

### D-10 [유형: 흐름·전체 항해 부재] [심각도: 중]
- 원문: 문서는 0절부터 19절까지 20개 최상위 절과 다수의 하위 절로 이루어진 1,995행 문서이지만, 목차나 수신자별 읽기 경로가 없다.
- 지적: 구현자는 개념·권한·상태 기계·스키마·시험 중 현재 판단에 필요한 층을 찾아야 하고, 후속 설계 검토자는 같은 의미가 본문과 19절에서 어떻게 연결되는지 추적해야 한다. 현재는 0절의 짧은 채택 목록과 반복 상호참조만 있어 전체 구조를 먼저 파악하기 어렵다.
- 수정안: 0절 뒤에 링크 가능한 목차와 두 읽기 경로를 둔다. 구현 경로는 `목적·신뢰 경계 → 전체 흐름 → 상태·권한 → 인터페이스·스키마 → 검증`, 후속 검토 경로는 `권위·소유 절 → 미결 관문 → 규범 묶음 → 검증 범위`처럼 기존 절을 가리키면 된다. 각 경로가 규범 우선순위를 새로 만들지 않는다는 점을 함께 명시한다.

### D-11 [유형: 흐름·검증 부록의 본문 점유] [심각도: 중]
- 원문: 17.2절 `필수 상태·시간선 벡터`는 V01~V197을 한 표에 연속 배치하며 원문 1,495~1,699행, 205행을 차지한다.
- 지적: 벡터 자체는 구현 검증에 필요하지만, 197행의 단일 표가 `구현 순서`와 `연구 워크스루` 사이를 끊는다. 구현자가 특정 계약의 시험을 찾을 때도 의미 영역별 묶음이나 본문 절별 색인이 없어 V 번호를 순차 검색해야 한다. 19.8절이 이미 `source-vector-map`으로 원문·기대·소유 연결을 대조한다고 밝히므로, 본문 표와 기계 대응 자료의 역할도 한눈에 구별되지 않는다.
- 수정안: 본문에는 의미 영역별 벡터 묶음과 필수 보장만 요약하고, V01~V197 전문은 링크된 검증 부록 또는 생성 자료로 분리한다. 부록에는 `벡터 ID / 본문 소유 절 / 상태 기계 영역 / 실패 종류` 색인을 추가하고, 본문의 17.6절 Q 대응표에서 해당 묶음으로 바로 이동하게 한다.
