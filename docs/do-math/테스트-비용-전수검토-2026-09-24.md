# do-math 테스트 비용 전수검토 (2026-09-24)

## 범위와 근거

현재 `.claude/skills/do-math/scripts/tests/`의 `test_*.py` 121개에서 정적으로 선언된 테스트 메서드 1,648개를 열거했다. [개별 원장](test-cost-inventory-2026-09-24.csv)은 각 메서드의 원문 위치, 본문 행수와 해시, 직접 단언의 대상, 실행·반복·대기 호출, 보존된 과거 실행시간과 결과를 한 행씩 기록한다. 단언이 없는 32개도 본문을 확인했다. 대부분은 단언이 있는 공통 시나리오 헬퍼를 호출하거나, 유효한 입력을 예외 없이 받아야 하는 검증기 검사다. 이름만으로 중복을 판정하지 않았고, 동일한 AST 본문은 없었다.

과거 완료 통합 배치의 1,242개 테스트는 개별 실행시간 합계가 41,844초였다. 이 중 30초 이상인 134개가 39,682초(94.8%)를 차지한다. 다른 단위·Lean·자원·이전 통합 보고서를 합쳐 현재 메서드 1,604개의 과거 시간이 남아 있고, 44개는 이전 실행이 중단되어 숫자 시간이 없다. 원장의 빈 시간은 **미측정**이며 0초가 아니다. 기록은 두 모듈이 동시에 실행되던 Windows 환경 등을 포함하므로, 개별 시간 합계나 이전·이후 차이를 단독 실행 성능으로 해석하지 않는다. 이번 검토에서는 테스트를 다시 실행하지 않았다.

graphify는 구조 조회에 사용했다. 그래프는 2026-09-23 구축판으로 현재 원문보다 오래된 `stale` 상태였으므로, 연결은 위치 탐색에만 쓰고 아래 판단은 현행 테스트와 구현 원문으로 확인했다. 사용자가 갱신을 지시하지 않았으므로 그래프를 갱신하지 않았다.

고비용이라도 다음 경계는 보존했다.

- `test_engine.test_nonformal_mathematical_goal_is_not_solved`는 반환 직후에 멈추면 이후 독립 평가·목표 판정의 오승인을 놓칠 수 있다. 20단계 전체 표본을 유지했다.
- `test_purpose_engine`의 지식 현재성 회복, 이의 제기·판정, 선행 과제 완료 및 실제 임시 Git 목표 흐름은 각각 다른 상태 전이를 통과해야 단언이 성립한다. 공통 준비가 길지만 삭제하지 않았다.
- `test_academic_engine`의 성공 HTTP 영수증과 거부·결과 불명 HTTP는 상반된 실제 전송 결과를 검사한다. 거부·결과 불명 사례는 수학적 해결 전제만 합성하되 외부 작업과 영수증 게이트는 실제 경로로 남겼다. 활성 fixture로 바꾸려던 안은 외부 정책이 같지 않아 적용하지 않았다.
- `test_review_research`의 초기 동료 질문 비공개와 조사자에게 동료 요약 비공개는 각각 일반 제출과 보충 조사 제출을 거친다. 한 경로로 합치면 첫 경계가 달라져 병합안을 되돌렸다.
- `test_submission_boundaries`의 대용량 보고서 수정 후 보존과 `test_submission_tools`의 긴 자체 리뷰 이력은 보존해야 할 바이트와 입력 초과 처리가 다르다. 입력 크기를 임의로 줄이지 않았다.
- 실제 Lean 컴파일, Windows Job 자원 상한, 외부 HTTP, 봉인된 제출, Git CAS·원문 바이트 보존, 독립 리뷰의 단위·통합 사례는 같은 이름의 순수 함수 검사만으로 대체되지 않는다. 해당 경계의 정밀 검사는 유지했다.
- `test_session_scheduler`의 과거 통합 배치에는 실패 8건과 긴 대기가 있었다. 동시 호출·일시정지·슬롯 해제는 고유 경계다. 미통과를 비용 절감 명목으로 삭제하거나 빠른 실행군에서 숨기지 않았다. 시간 조건과 fixture 사건을 고친 뒤 실행으로 판정해야 한다.
- `test_run_feedback`의 준비 직후 계획 세 사례는 새 계약만 대기, 이미 준비된 과제 존재, 보류된 검토 없음이라는 다른 모집단을 검사한다. `test_engine`의 비형식 목표 두 사례도 연구 목표와 수학 목표가 다르다. 비슷한 본문을 한 이름 아래 묶어도 독립 엔진 준비 횟수가 줄지 않으므로 삭제하지 않았다.

고비용 후보 이외의 테스트도 원장에 모두 남겼다. 단언이 짧더라도 입력 형식의 다른 분기, 저장 경계, 거부 조건, 호환 판본을 확인하는 경우에는 합쳐도 실행 비용이 거의 줄지 않고 실패 위치만 흐려진다. `test_redesign_*`, 순수 계약·지식·계획·관찰 검사, CLI·운영·자원 검사에서 동일한 본문이나 단순 이름만 다른 중복은 찾지 못했다. 공통 시나리오 헬퍼를 호출하는 짧은 래퍼는 서로 다른 상태·매개변수를 시험하는지 본문에서 확인하고 유지했다.

## 확인의 한계

이 검토는 과거 기록과 현행 코드를 읽은 **정적 판단**이다. 변경 후 통과 여부와 실제 절감량은 새 실행으로 확인하지 않았으며, 실패 8건의 원인도 이번 자료만으로 확정하지 않는다. 원장의 시간은 현재 코드 판본의 벤치마크가 아니라 실행 당시 보고서의 수치다. 특정 테스트를 삭제하거나 fixture를 바꾸는 판단에서는 비용만으로 보증을 대체하지 않았다.
