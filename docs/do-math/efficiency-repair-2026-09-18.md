# do-math 효율 검토에 따른 수리

초기 계획의 실행 시점, 요청 병합, Git 입출력, 대기 저장, 입력 준비 중 정지와 Lean 사전 검사를 수리했다. `.claude/skills/do-math`를 정본으로 수정하고 `.agents/skills/do-math`는 생성기로 갱신했다. 연구 준비·독립 계약 검토·선택·수학 검토의 판단 책임은 유지한다.

연구 정보는 `research/instance.json`, 실행 상태는 `runtime/state.json`에 보존한다. 이 문서에서 두 상태 루트는 이 두 JSON 객체를 뜻한다.

이 작업의 기준은 [재검토 보고서](../../.skill-workspace/do-math-efficiency-review/report.md)다. 그 보고서는 관찰한 비용 전부를 낭비라고 단정하던 이전 판단을 철회하고, 절차가 지키는 의무와 대체 후의 실패를 함께 판단했다. 따라서 이번 수리도 호출을 줄이는 것과 판단 범위를 줄이는 것을 구별한다. 재검토 보고서와 상세 작업 로그는 Git 제외 대상인 로컬 보관 자료이며, 보존되는 수리 근거는 이 문서, [검증 집계](efficiency-repair-2026-09-18.json), 스킬 코드와 회귀 검사다.

## 전체 절차를 대조한 범위

SKILL, GLOSSARY, README, references 문서 5개와 역할 계약 11개를 모두 읽고, 역할 입력을 만드는 코드와 결과를 받는 코드에 연결해 확인했다. 초기 등록과 스케줄링뿐 아니라 계약 승인·과제 선택·결과 완료 판정, 형식 검사·동일성·목표 감사·학술 후속, 사용자 제어·정지·복구·독립 운영의 경계를 함께 대조했다. 저장과 프로세스 실행 경로는 별도 읽기 전용 조사로 교차 확인했다.

후보 준비가 계약을 쓰고, 다른 실행이 계약을 검토하며, 연구 계획이 실제 수행 대상을 선택한다. 계획은 후보 선택 외에도 반환 결과의 완료 판정과 다음 준비의 필요성을 판단한다. 중앙 Lean 검사는 형식 타당성을, 동일성 검토는 형식 표현과 해설의 대응을, 목표 감사는 연구 목표 충족을 판정한다. 이 경계를 합치면 호출 수뿐 아니라 오류를 찾아내는 방식도 달라지므로 단순한 구현 최적화로 처리하지 않았다.

## 보고서 열 항목의 처리

| 항목 | 처리와 근거 |
|---|---|
| 1. 큰 공통 입력 | 공통 문서와 역할별 소비 경로를 대조했다. 필수 의미를 잃지 않는 문서 제외를 확정하지 못해 전문 제공을 유지했다. 이미 역할별 계약과 운영자 전용 문서는 분리되어 있다. 자료를 줄였다는 이유만으로 동일한 연구 품질을 주장하지 않는다. |
| 2. 준비·계획 왕복 | 세션 모드에서 시작 전 학술 요구 등록이 만든 계획만 최초 준비와 첫 착수 가능 과제를 기다린다. 진행 중 준비의 공개 업무 정보를 계획에 제공한다. 요청을 합칠 때 이유·사건·사용자 요청 참조를 보존하고, 정지 중인 실행에도 새 요청을 병합하지 않는다. |
| 3. 정지와 저장의 결합 | 입력 준비 중 새 제어와 실행 기한을 확인하고 모델 시작 직전에 제어를 다시 적용한다. 정지 또는 사용자 제어로 입력 판본이 바뀌면 미공개 입력 폴더를 정리하고 실행을 시작하지 않는다. 준비·입력 공개·정지 관찰·종료 시각을 구분해 기록한다. 모델을 시작하기 전 최초 정지 확인에서는 유예 없이 중단하고, 수행 중인 모델에는 체크포인트 유예를 유지한다. 중앙의 순차 상태 적용은 유지한다. |
| 4. 자료 복원과 파일별 Git | 같은 snapshot의 원자료·과제 산출·재개 파일·계획 이력을 묶어서 읽고, 저장할 blob을 한 `hash-object` 호출로 기록한다. 자료 선택 범위, 정확한 바이트, 불변 산출, 단일 부모와 ref의 CAS 공개를 유지한다. |
| 5. 무변경 저장과 설치 검사 | 두 상태 루트의 내용이 같고 새 산출이 없으면 저장을 생략한다. 재시작한 실행기에도 적용한다. 준비 상태의 내용·근거가 같으면 평가 시각을 유지한다. 설치 전체 해시는 반복 순회에서 최대 초당 한 번, 실행 준비·입력 확정·결과 수신에서는 간격과 관계없이 검사한다. |
| 6. 작은 작업의 단계 우회 | 채택하지 않았다. 계약 결함을 연구 착수 전에 찾고 제안자의 자기 선택을 견제하는 역할이 다르다. 검토 묶음화도 입력 누락·판정 간 영향·부분 재시도까지 비교해야 한다. |
| 7. 동일성 검토 범위·인원 축소 | 채택하지 않았다. 새 판본 전면 검토는 이전에 놓친 불변 부분의 오류도 다시 찾으며, 쟁점의 기각과 제안 전체의 승인을 구별한다. 고정 배정은 별도 범위 계획 비용을 없애는 효과도 있다. |
| 8. 지속 운영과 정기 점검 | 지속 연구와 작업·운영 슬롯 분리를 유지했다. 상태 불변만으로 의미적 정체 진단을 생략하지 않았다. 동시 세션 한도를 누적 비용 상한으로 바꾸거나 사용자가 정하지 않은 상한을 추가하지 않았다. |
| 9. Lean 사전 검사 | 작업 공간에 같은 지급 검증 코드와 구성 명령을 사용하는 사전 검사 도구를 추가했다. 정확한 소스 해시와 실제 도구체인·공리 검사 결과를 반환한다. 작성 중 피드백이며 중앙은 제출 소스를 다시 검사한다. |
| 10. 창 숨김 검증 | 기존 Python 대역 검사에 더해 실제 Git 응답과 프로세스 계보를 관찰하고, 콘솔 연결·가시 창을 검사했다. 숨긴 실제 Git 콘솔을 양성 대조로 사용했다. 실제 연구의 재개 검사는 수행하지 않았다. |

## 초기 계획이 기다리는 조건

초기 학술 요구를 등록해 생긴 계획 요청과 사건은 없애지 않는다. 최초 준비가 그 요구를 읽고 계약 후보를 만든 뒤, 첫 과제가 계약 검토를 통과해 착수 가능해지면 독립 계획을 시작한다. 다른 계약의 검토가 늦어진다고 첫 착수 가능 과제를 선택할 계획의 시작을 막지 않는다.

준비가 실패하거나 빈 결과로 끝났을 때, 계약이 반려됐을 때, 이미 판정할 결과가 있을 때, 새로운 사용자 판단이나 요구 판본 변경이 있을 때에는 기다리지 않는다. 모든 계약 검토가 끝났는데도 착수할 과제가 없으면 계획이 원인을 판단한다. 일반 계획은 준비와 병렬로 진행하며 선택 후보가 없어도 실행할 수 있다. 사건은 계획이 실제 입력으로 받아 판단한 결과가 수락된 뒤에만 소비한다.

`ongoing_preparation`은 배정 이유·대상·상태·입력 판본을 보여 준다. 다른 준비의 미공개 초안이나 잠정 결론은 제공하지 않는다. 이미 맡겨졌다는 사실은 완료 근거가 아니므로, 계획자는 기다림과 별도 추가 의무를 구별해야 한다. 설명이 길어지면 해시와 경로로 원문을 회수하는 기존 입력 축소 절차를 사용한다.

## 저장 비용의 관찰

중단된 연구의 원자료 38개, 8,396,697바이트를 읽기 전용으로 회수해 같은 바이트로 비교했다. 쓰기는 별도 임시 저장소에서 원자료 38개와 상태 파일 2개를 저장했다.

| 측정 대상 | 수정 전 | 수정 후 |
|---|---:|---:|
| 원자료 읽기의 Git 프로세스 | 38 | 1 |
| 한 저장 전체의 Git 프로세스 | 50 | 11 |
| 그 저장의 `hash-object` 호출 | 40 | 1 |
| 복원 바이트 일치 | 일치 | 일치 |

배치 읽기는 [Git의 크기 기반 batch 출력](https://git-scm.com/docs/git-cat-file)을 사용하고, 쓰기는 [필터 없는 다중 파일 해시](https://git-scm.com/docs/git-hash-object)를 사용한다. 입력 파일을 선별하거나 문헌을 생략해서 얻은 감소가 아니다. 경과 시간도 기록했지만 다른 로컬 검증이 진행되던 단일 관찰이므로 통제된 성능 비교나 연구 전체의 비용 절감률로 해석하지 않는다.

## 검증과 한계

새 수리는 실패 재현 후 수정하는 순서로 검사했다. 검증 중 추가로 확인한 경계 문제는 새 고정 사본에서 해당 변경의 영향 범위를 검사했다. 결과는 다음과 같다.

| 고정 사본 | 포함한 추가 변경과 검사 범위 | 완료 결과 |
|---|---|---|
| 전체 회귀판 | 초기 계획·요청 보존·Git·저장·입력 준비 중 정지·Lean 사전 검사·창 숨김의 전체 회귀 | 440개 중 439개 통과, 1개 미실행 |
| 입력 크기 보완판 | 긴 `ongoing_preparation`의 원문 참조 전환. 입력 보존·스케줄링·문서 지급·제출 경계·모델 평가 흐름 | 67개 중 66개 통과, 같은 심볼릭 링크 검사 1개 미실행 |
| 최종 정지 보완판 | 모델 재개 전 최초 정지의 유예 제거. 실행기·병렬 정지·권한 회수·시간 제한·수행 중 유예 유지 | 13개 모두 통과 |

미실행은 Windows 계정에 심볼릭 링크 생성 권한이 없어 발생했다. 영향 범위 검사에는 앞서 실행한 검사가 포함되므로 위 건수를 서로 다른 검사 수로 합산하지 않는다. 각 사본과 최종 설치본의 정확한 파일 차이·해시·결과는 검증 집계에 보존한다. 첫 전체 회귀의 시험 실행기 오류, 시험용 저장소 인터페이스 누락, 마지막 검사 목록의 클래스명 오기는 원 기록에 남기고 수리 또는 정정 후 다시 검사했다.

모델 응답을 대역으로 둔 통합 검사는 요청 보존, 첫 계획의 승인 후보 수신, 사건 소비, 병렬 진행과 중단·복구를 확인한다. 실제 Git 검사는 바이너리 바이트, 과거 snapshot, 기본 index 비변경, 산출 불변성, SHA-256 저장소와 동시 CAS 충돌을 확인한다. 실제 Lean 검사는 올바른 증명, `sorry`, 거짓 증명, 정지 및 CRLF 소스의 정확한 해시를 구별한다. 문서 독해는 이 실행 검증과 별도로 수행했다.

Lean 4.32.0의 [공식 배포본](https://github.com/leanprover/lean4/releases/tag/v4.32.0)을 로컬 작업 폴더에 준비하고 배포 원본의 SHA-256을 대조했다. 호스트 PATH나 연구 설정을 영구 변경하지 않았다. 사전 검사는 공유 라이브러리·Lake 프로젝트·빌드 캐시의 격리를 보증하지 않으며, 그 성공이 중앙 인증·동일성 판정이나 인증된 형식 결과 집합으로의 편입을 만들지 않는다.

실제 모델을 이용한 장기 연구의 품질과 총비용, 과거 정지에 걸린 약 35초의 원인별 비중은 이번 검사로 입증하지 않았다. 초기 계획을 늦춘 효과를 모든 연구 상황의 생산성 향상으로 확대하지 않는다. Git 임시 쓰기 파일은 정상 반환과 예외에서 정리되지만 프로세스의 비정상 종료까지 자동 청소한다고 보증하지 않는다.

## 연구 중단 상태

주차 함수의 단봉성을 다루는 연구 `RI-01M2PZY54SEB1B0P140FTCPQQT`는 수리 대상 스킬과 별개로 중단 상태를 유지했다. 저장 snapshot은 `fc178e3ed7f2ab3a84835ee8b516620d04f4effd`이며, HOLD `ddb615629ad343849c21133969d7f08a`와 사용자 pause를 해제하지 않았다. 현행 예약 작업 `DoMath-Engine-a1745b27f2bd`, `DoMath-Operator-a1745b27f2bd`는 비활성으로 유지한다. 이번 수리가 연구 재개를 승인하지 않는다.
