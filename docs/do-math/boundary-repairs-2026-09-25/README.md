# do-math 경계 결함 수리

대상은 [수리 전 감사의 D1–D7](../similar-defects-2026-09-25/README.md)이다. 기준 커밋은 `c44dd7b7f34813d525ef4b79758dea7369984296`이며, 수리 전 재현 자료는 그대로 보존했다. 이 문서는 수리의 범위·판단·검증 결과를 기록한다.

## 변경한 동작과 영향 범위

핵심 구현은 `scripts/do_math/repository.py`, `observations.py`, `relation_refs.py`, `control_contracts.py`와 그 소비자다. 문서는 공통 실행·CLI 실행 계약·초기화 효율과 정비를 갱신했다. `.agents` 생성본도 정본에서 다시 만들었다. graphify는 갱신하지 않았다.

## 구현을 구체화하며 바꾼 판단

- **체크포인트 참조만 복사하는 수리는 부족했다.** 기존 두 helper는 원문을 버린 뒤 일반 수집 파일에서 해시가 같은 항목을 찾았다. 봉인 제출물에서 빠진 checkpoint나 `input/` 근거에는 이 방법이 충분하지 않다. 원문과 명시 근거를 직접 포착·보존하는 함수 하나로 교체했고 이전 helper는 제거했다.
- **모든 의존 순회를 하나로 합치는 안은 채택하지 않았다.** 개정 충돌, 완료 판정, 영향 분석, 제출 인용은 질문이 다르다. 직계 관계 참조만 공유하고 순회 정책은 각 소유자에 남겼다. 영향 분석에서는 파일 경로가 레코드 의존이 되지 않도록 기존 필터를 유지한다.
- **`AttributeError`를 광범위하게 잡는 안은 채택하지 않았다.** 자료 구조가 확인되기 전에 타입 의존 연산을 하던 경계를 고쳤다. 내부 구현 오류를 정상 반려처럼 숨기지 않는다.
- **입력 검사가 의미 판단을 앞질러서는 안 된다.** configure patch에 기본 설정을 합쳐 검사하는 초기 안은 사용자 인스턴스의 유효한 부분 변경을 잘못 거절할 수 있어 순수 형식 검사로 바꿨다. 실제 설정·자원 검사는 현재 인스턴스와 합성한 기존 경계에서 수행한다.
- **기존 유효 표현을 새 검사로 좁히지 않았다.** 관계 주장·형식 참조의 명시적 null과 대상 없는 연구 계획의 `target=None`을 유지했다. 재제출 action의 타입은 저장 queue의 같은 좌표 정의를 재사용한다.
- **범위를 확장해 확인한 두 가지도 처리했다.** checked import 승인 목록의 값이 배열이면 후속에서 같은 타입 예외가 남았다. 접수와 도메인 적용 경계에서 같은 승인 값 검사를 사용한다. 지나치게 큰 정수형 대화 lease도 날짜 범위 초과로 거절하여 뒤 제어를 막지 않게 했다.

수리의 실익은 정상 자료의 재사용·회수·후속 처리 복원이며, 새 호환 계층이나 연구 권한을 추가하지 않는다. 실제 연구 기록의 자동 변환·삭제·재시작은 수행하지 않았다.

## 검증 기록

수정 전에 기존 반례를 정상 결과를 요구하는 회귀 검사로 바꿔 실패를 확인했다. 독립 영향 검토에서 나온 추가 문제도 실패 검사를 만든 뒤 고쳤다. 새 검사는 다음 파일에 있다.

- `test_boundary_repairs.py`: 문자열·manifest 재사용, 합성 충돌과 head 보존.
- `test_checkpoint_persistence.py`: 실제 실행기 종료·재시작·검토 입력, 독립 본문·근거 포착과 한도.
- `test_relation_dependencies.py`: 개정·질문 대기, 명시 판정 효력, 내용 근거와 후속 bookkeeping의 구별, locator 음성 대조.
- `test_trust_continuation.py`: 실제 Git 저장과 trust activation 취소·재시도 계보.
- `test_control_shapes.py`: 모든 공개 action의 잘못된 config, 중첩 입력·승인, CLI 오류, 수신 정산·재시작·후속 처리, 유효한 부분 설정·null 입력.

중간 회귀 실행 일부는 실행 도중 소스 변경 감시가 작동해 정지했다. 해당 결과는 최종 통과로 세지 않는다. 독립 점검 결과 반영을 위해 중단한 실행도 제외한다. 최종 검증은 소스를 고정한 상태로 실행하며 그 결과와 파일 해시를 별도 보존한다.

**고유 테스트 ID별 최신 결과 587개가 모두 통과했다.** 단위 검사 358개와 관련 통합 검사 229개다. [검증 집계](validation-summary.json)에 테스트별 마지막 실행, 원 보고서와 해시를 보존했다. 여러 고정 판본 실행 묶음의 최신 결과를 합친 수치이며, 전체 테스트 스위트를 한 번에 돌린 수치가 아니다.

통합 묶음 215개에서는 214개가 통과하고, 잘못된 trust 입력을 예전처럼 접수 후 거절할 것으로 기대한 검사 하나가 실패했다. 새 계약은 이 입력을 접수 전 `input_error`로 거절한다. 기대값을 갱신한 해당 검사와 영향받는 제어 8개를 다시 실행해 통과했다. 마지막 입력 형식 대조에서 확인한 기존 알림 객체와 실제 초기화 채택 플래그도 현재 정의에 맞췄고 관련 구조 검사·실제 Git 채택 검사를 통과했다. 실패 기록은 덮어쓰지 않았다.

정본·생성본의 `probe_cli.py --skill-only`, 미러 드리프트 검사, `git diff --check`도 통과했다. [최종 정본 해시](source-snapshot.json), [구조·미러 검사](structure-and-mirror.json)를 함께 보존했다. 검증은 Windows의 폐기 가능한 Git 저장소·CLI·로컬 실행 수명을 사용하며, 모델 응답은 테스트 대역이다. 실제 모델 서비스, 기존 연구 인스턴스, 전체 Lean 검사 그룹은 실행 범위에 포함하지 않는다.

기존 감사 폴더의 재현 스크립트는 수리 전 오동작을 확인하는 자료다. 수리 후 검증에는 위 현행 회귀 검사와 `scripts/run_tests.py`를 사용한다.
