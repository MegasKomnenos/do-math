# do-math의 계약 개정·학술자료·독립 운영 개선

`do-math`의 계약 개정, 계획과 실패 복구, scholarly 도구 전달, 주기적 독립 운영을 함께 개선했다. 분석에서 확인한 실행 결함은 재현해 고쳤고, 수학적 접근의 실패와 원문 판독의 오류는 각각의 의미에 맞는 연구·검증 절차로 연결했다. 정본은 `.claude/skills/do-math`이며 `.agents/skills/do-math`는 생성 사본이다.

사용자는 기존 주차 함수 연구를 나중에 처음부터 시작하겠다고 정했다. 따라서 이번 작업은 기존 연구의 기록 정정·상태 복구·재개를 포함하지 않는다. 그 인스턴스와 HOLD·예약 작업을 변경하지 않았으며, 실제 실행 검사는 별도의 새 연구 인스턴스에서 수행했다.

## 확정된 동작

독립 운영은 연구별로 설정할 수 있고 기본값은 활성화·2시간 주기다. 작업·운영 AI 실행 횟수의 기본값은 모두 `null`, 즉 제한 없음이다. 실제 사용량은 계속 기록하며 시간 제한·반복 실패 처리·사용자 정지는 별도로 적용한다. 외부의 독립 운영 담당 호출은 내부 `operations_calls`와 구분해 보고한다.

사용자의 최종 목표·필수조건을 유지하면서 AI가 만든 개별 과제의 범위 변경과 철회는 자율이다. 개정한 완료 기준은 현행 목록으로 교체하고 과거 계약은 이력으로 보존한다. 새 계약은 독립 계약 검토를 다시 받는다. 부분 결과가 있는 미완료 과제도 철회할 수 있지만, 철회를 완료나 수학적 실패로 표시하지 않는다. `academic_requirement_id`로 사용자 학술 요구를 가리키는 과제는 이 자율 변경 경로에서 보호한다.

기계 실행기의 내부 관찰·운영 점검은 유지한다. 별도로 예약되는 운영 담당은 실행기 소실, 반복 오류, 입력·도구 부족과 구현 수리를 살피며, 사용자 대화는 요청·결정·정지와 조회 창구가 된다. 사용자 정지는 `user_pause`로 보존하고 자동 운영의 재개 요청으로 해제하지 못하게 했다.

HOLD에는 고유 ID가 있고 그 ID를 정지 사유에 넣는다. 해제 요청은 실행기가 실제 적용할 때 현행 사용자 정지 사유와 정확히 대조한다. 이로써 HOLD 접수 직후 해제해도 대기열에서 순서대로 처리할 수 있고, 그사이에 생긴 다른 사용자 정지를 해제하지 않는다.

제어 요청은 파일 ID의 무작위 부분이 아닌 기록된 접수 시각 순으로 처리한다. 같은 밀리초의 pause·resume이 뒤집히는 사례를 재현해 고쳤다. 사용자가 대화 소실 시 정지하도록 명시한 정책도 자동 운영의 재개가 덮지 못하게 했다.

scholarly는 인스턴스에 보존된 서버 설정을 하위 Codex 실행에 명시적으로 전달한다. 다른 사용자 설정과 MCP를 통째로 상속하지 않는다. 확보한 원문과 manifest는 실행 작업 공간의 `scholarly-data/`에 두어 산출 묶음에 수집하고 다음 역할에 복원한다. 검색 결과, 원문 확보, 이미지의 실제 판독과 수학적 타당성을 구별하도록 공통 문서와 역할의 읽기 경로를 연결했다.

## 분석 항목과 조치의 대응

분석 원문은 `임시/parking-unimodality-analysis-20260916/분석.md`다. 아래의 절 번호는 그 문서를 가리킨다.

| 분석 범위 | 조치와 검증 근거 |
|---|---|
| §2 완료 기준 누적 | 기존 기준과 개정 기준의 합집합을 제거했다. 새 목록의 정확한 저장, 이전 이력 보존, 검토 초기화와 재검토를 `test_research_recovery.py`에서 검사한다. |
| §2 최초 계약의 논리 문제 | 후보 준비와 계약 검토에 조사 범위, 성공·실패·부분 성공, 양화, 최소성, 앞 단계 실패 뒤의 정의, 충분조건의 실제 적용을 대조하는 절차를 반영했다. 전체 문서 독해와 실제 계약 검토 실행을 함께 확인했다. 모든 미래 수학 판단의 무오류성을 보증하는 것은 아니다. |
| §3.1 완료 과제의 readiness | 이미 수리된 제거 동작을 유지했다. `test_lifecycle_engine.py`와 새 계획 입력 시험에서 완료 과제가 현행 모집단에 들어가지 않음을 확인한다. |
| §3.2~3.3 계획 오류와 과거 판단 반복 | 생산자와 수신자가 같은 `ready_task_ids`를 사용한다. 모집단 오류는 누락·과잉·중복 ID를 구별한다. 과거 거부 출력은 정확한 참조로 보존하며 현재 상태와 분리해 읽게 했다. |
| §4 실패 계획의 재개 | 출력 수리 소진 행동을 별도로 보존해 진단한다. 일반 resume은 이를 무조건 복원하지 않는다. 진단된 계획 재시도는 새 action과 현재 입력을 받고, 성공한 후속은 원 실패를 삭제하지 않고 해결 이력을 남긴다. 독립적으로 가능한 다른 작업은 계속한다. |
| §5 scholarly 제공과 자료원 실패 | 설정 회수, worker 전달, 실제 MCP 호출, 원문·이미지 수집과 후속 판정을 연결했다. 접근 제한·오류·부분 확보·검색 무결과는 별개로 보고한다. 외부 서비스 실패를 없애거나 문헌 부재로 바꾸지는 않는다. |
| §6 수학적 장애물 | 특정 충분조건의 반례를 원 명제 전체의 반례로 확대하지 않는 기존 원칙을 유지했다. 개정된 계약 절차는 이런 부분 실패를 후속 연구로 넘길 수 있게 한다. 원래 단봉성 문제를 이번 작업에서 풀었다고 주장하지 않는다. |
| §7 명령·검색·조회·시험·관찰 | 검색 무일치와 자료 부재, 셸·보조 조회 오류와 연구 실패, 마지막 셸 종료와 개별 검사 결과를 구별하도록 했다. 예약 작업의 trigger·다음 시각 부재는 실제 시험에서 재현해 처리했다. 자료 묶음은 record ID 조회와 구별한 경로로 안내한다. |
| §8 비용과 수리 책임 | 반복 실패를 문안 수정으로만 돌리지 않고 운영 진단·구현 수리에 연결한다. 계획 이력에서는 과거 수리 응답 전문을 참조 파일로 옮기고, 최신 운영 보고에는 실행별 원 영수증의 경로를 남긴다. 이전 응답 전문을 계속 중복 전달하지 않으면서도 실제 바이트를 다시 읽을 수 있게 한다. |
| §9 사용자 HOLD와 남은 연구 | 기존 연구를 제외한다는 사용자 결정에 따라 그대로 보존했다. 새로운 임시 인스턴스에서 HOLD·release·재시작·종결을 검증했다. |
| §10 원문 오독과 잘못된 검증 | 원본 이미지의 전사, 정의·가정 충족, 독립 계산을 각각 대조하는 절차를 추가했다. 같은 원문 바이트의 판독 정정은 기존 지식 개정과 실제 의존 재검토로 이어짐을 회귀로 확인했다. 원래 연구 기록 자체의 정정은 이번 범위가 아니다. |

첫 전체 검사 사본에는 병렬 수정 중인 Python·PowerShell 판본이 섞였고, 일부 시험용 실행기가 새 scholarly 인자를 받지 못했다. 그 실행은 316건 중 10건 실패·1건 미실행이었다. 실패 자료를 `.skill-workspace/do-math-improvement-20260916/core-regression.txt`에 보존했고, 수정과 재확인 뒤 위의 일치하는 고정 사본에서 전체 회귀를 다시 수행했다.

전체 회귀 이후의 설명 문단 재구성은 전체 문서 독해로 확인했다. 운영 보고·반환의 축소는 `test_operator.py`가, HOLD 해제·제어 순서·대화 소실 정책은 `test_research_recovery.py`의 `RecoveryRoutingTests`가 확인한다. 보고 축소 후에는 같은 임시 인스턴스에서 실제 읽기 전용 probe도 다시 통과했고 원 영수증과 4,406바이트의 CLI 반환을 구별해 보존했다. 모든 검사가 최종 파일의 한 번의 실행에서 끝났다고 합치지 않는다.

## 실제 실행의 한계와 재현 위치

문헌 검사는 저자 공개 PDF 하나와 첫 쪽을 대상으로 했다. 공개된 49개 자료원 전체의 가용성이나 일반 수학 연구 성능을 평가한 것은 아니다. 이 사례는 목표 감사자 1명으로 설정했으며, 기본값인 두 독립 감사자의 동작은 별도 회귀가 확인한다. 일반 수학 명제의 증명이나 반증을 완료했다고 보고하지 않는다.

Windows 작업의 2시간 반복 설정과 실제 수동 예약 호출을 확인했다. 자연적인 예약 시각 도래를 장기간 관찰한 시험은 아니다. HOLD·재시작 시험에서는 완전한 작업자 체크포인트가 작성되기 전에 정지했으며, 실행 미완료와 관찰된 부분 상태를 보존했다. 프로세스 종료를 체크포인트 완성으로 확대하지 않는다. 시험에 만든 예약 작업은 제거됐다.

정상 연구 실행의 도구 로그는 결과 JSON의 `execution.collect.stdout.raw.base64`에 원바이트로 들어 있다. 별도 `adapter-evidence/stdout.jsonl` 파일이 없다는 이유로 로그 소실 가능성을 제기한 검토는 잘못이었다. 실제 JSONL 371,805바이트를 복원해 해시와 바이트가 같음을 확인했고 지적을 철회했다.

세 시험 인스턴스와 원 로그는 `.skill-workspace/do-math-improvement-20260916/`의 `live-research`, `operator-live`, `operator-controls-live`에 보존한다. 현재 문서는 각 시험이 입증한 범위를 설명하며, 미래 실행의 성공이나 외부 서비스의 현재 가용성을 대신하지 않는다.
