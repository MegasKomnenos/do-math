# do-math 정적 워크스루 수리 결과

사용자가 승인한 [후속 수리안](정적-워크스루-후속-수리안-2026-09-23.md)의 2~8번을 정본 작업 트리에 반영했다. 앞서 승인받아 제거한 run 전체 기한도 유지한다. 이 기록은 구현의 변경 범위와 검증 근거를 설명하며, 실제 연구 인스턴스를 실행한 결과는 아니다.

## 계속 승인과 복구의 연결

채택된 횟수 한도를 넘는 계속은 사용자 결정이다. `repetition_hold`를 만드는 실제 경로는 이 횟수 문턱뿐이므로, 과거 원문에 `owner=ai`가 남아 있어도 현재 효력은 사용자 소유로 계산한다. 과거 기록 자체는 다시 쓰지 않는다. 사용자 결정은 현재 계보·보류 사건·정확한 후속 범위를 대조하며, 평가 대상과 관찰 규칙 대상도 범위에 포함한다.

준비 결과는 정상 수신됐지만 새 계약·개정 계약을 한 건도 보존하지 못해 한도에 도달할 수 있다. 그 계보에 다음 큐·대기 요청이 없다면 사용자가 계속 결정의 `allowed_action`으로 새 일반 준비 요청을 지정한다. 실행기는 승인한 요청을 결정과 함께 저장한다. 제출이 실패한 경우에는 현재 큐·대기에 보존된 수리 요청의 범위를 승인한다.

수리안에서 제안했던 별도의 AI 기술 보류 허용·소비 장치는 구현의 생산 경로를 확인한 뒤 폐기했다. 그런 보류를 만드는 경로가 없는데 허용 원장을 더하면 쓰이지 않는 상태 관리가 남기 때문이다. 호출되지 않던 `authorize_repetition_repair()`도 제거했다. 기술적 복구는 기존 운영 처분과 수리 요청으로 처리한다. `retry`·`resume`의 후속은 원 action ID를 재사용하고 배정 시 새 execution ID를 받는다. 처분의 `continuation_action_id`에는 재사용한 action ID를 기록하여 후속의 중복 생성을 막는다. 수락된 처분과 후속 요청은 같은 저장 갱신으로 공개한다.

기술 수리를 이유로 선택 실패나 무산출 횟수를 초기화하지 않는다. 계획의 정상 수신은 연속 선택 실패 구간을 끝내고, 실제 계약을 보존한 일반 준비는 무산출 구간을 끝낸다. 제안·계약 판본과 의도 재저작은 각각의 기록으로 계속 집계한다. 반복 한도 보류는 이 집계와 구별되며 공개 사용자 계속 결정으로 해소한다.

재개용 체크포인트는 수집한 원문 바이트의 해시가 맞을 때 저장 참조를 연결한다. `resume`은 그 참조와 바이트를 다시 대조한다. 재시도 계보에 결과가 `unknown`인 외부 행동이 있으면 공개 외부 행동의 `reconcile` 절차로 전송 결과를 먼저 확인해야 한다. 같은 operation ID·요청 해시·멱등 키에 묶인 관찰 근거로 성공·효과 부재·미전송 중 해당 사실을 확정한다. 실제 외부 재전송은 그 뒤에도 별도의 기존 재시도 허가를 검사한다. 사용자 정지·grant·현재성·이미 수락된 편입 묶음의 보존 조건도 계속 적용한다.

공개 결정의 입력 형식은 [CLI 실행 계약의 반복 보류 절](../../.claude/skills/do-math/references/CLI-실행-계약.md)에 기록했다. 생산자의 변경 의무는 GLOSSARY와 후보 준비·의도 해석·운영 점검 계약에 함께 반영했다.

## 검증 근거와 한계

검사는 편집 중인 정본과 분리한 고정 사본에서 수행했다. [검증 원장](walkthrough-repair-2026-09-23/verification.json)에 각 실행의 대상·판본·실제 결과와 원보고서 위치를 보존한다. 여러 실행에 같은 검사가 포함되므로 실행별 건수를 합산해 독립 검사 수로 쓰지 않는다. 최초 실패도 후속 통과로 덮어쓰지 않는다.

수정 전 사본에서는 검토 입력 복원 실패 뒤 `activities.wait_for()`가 미종료 실행을 이유로 예외를 냈다. 같은 사본에서 비형식 지식 3건을 받은 연구 결과는 계획 요청 4건을 만들었다. 수정 사본에서는 복구 대기 저장·재개와 계획 요청 한 건을 각각 확인했다. 관련 회귀에는 공개 사용자 계속 결정, 정상 최종 응답의 원문 포착부터 수신 실패 집계까지, 운영 처분의 수락부터 중복 없는 후속 생성과 사용자 한도 검사까지, 보충의 집계 제외, 재생성 시각 도래와 중복 방지가 포함된다.

결과 참조를 연결하면서 드러난 영향 전파 오류도 고쳤다. 기존 전파기가 실행·활동에 저장 계약에 없는 `input_current`·`use_history`를 추가하여 원자료 변경의 저장을 거부했다. 이 두 기록은 기존 입력 현재성 검사와 영향 전파 이력으로 다루므로, 소비하지 않는 필드를 새로 저장하도록 스키마를 넓히지 않았다. 실행·활동의 원래 결과를 보존하고 영향받은 기록 목록을 이력에 남긴다. 해당 원자료 변경 검사의 최초 오류와 재검증 결과도 검증 원장에 구별한다.

모델 응답과 수학 검사 결과는 명시적인 대역을 사용했다. Git·파일·등록·수신·활동 전이·후속 요청은 검사에 따라 실제 구현을 통과했다. 문서 독해는 변경한 절의 전문과 필요한 공통 규정을 대상으로 했으며, 변경하지 않은 문서 전체의 의미 검증이나 실제 연구 모델·Lean·연구 성과의 검증을 뜻하지 않는다. 전체 저장소의 모든 회귀를 통과했다는 주장도 하지 않는다.

## 변경의 보존 범위

정본은 `.claude/skills/do-math`이며 `.agents/skills/do-math`를 생성기로 갱신하고 드리프트 검사를 통과시켰다. 이번 수리 전부터 같은 파일들에 선행 구현의 미커밋 변경이 있었다. [수리 패치](walkthrough-repair-2026-09-23/source-changes.patch)는 그 작업 시작 상태와 이번 결과 사이의 차이를 보존한다. 패치와 검증 원장은 선행 구현 전체를 이번 작업의 산출로 취급하지 않는다. 기존 변경을 함께 포함하는 소스 커밋·푸시는 수행하지 않았다.
