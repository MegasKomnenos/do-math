# `do-math` 통합 설계 재심사 최종 반영 보고서

## 1. 결론

닫혔던 [「보편 수학 연구 스킬 do-math의 통합 설계를 확정한다」](https://github.com/MegasKomnenos/math/issues/18)를 다시 심사한 결과, 기존 설계의 연구 철학과 신뢰 경계는 유지할 가치가 있지만 구현 정본으로 바로 넘길 수 없는 결함이 남아 있었다. 결함은 문서가 길다는 사실이 아니라 같은 상태의 다중 소유, 결정론 계약과 실시간 입력의 충돌, 종료되지 않는 감시기, 저장 위치가 없는 프로세스 원장, 스키마·도구·테스트 사이의 결선 누락과 확정 사용자 요구의 유실이었다.

최종 결정은 다음과 같다.

- Lean 정본, 세 작업 영역, 작업과 실행의 분리, 3+3 동일성 검토·심사, 원자적 Git 편입과 불변 이력은 유지한다.
- 비작업 역할 요청, 스키마 레지스트리, 현재성, 프로세스 원장과 외부 입력 제거 시험은 단일 기계 계약으로 수렴한다.
- P vs NP 최종 결론의 ZFC 또는 더 약한 기초 이동 요구, 비활성 대안 기초의 보존, 동일성 인증 철회와 `gpt-5.6-terra` 금지 범위를 복구한다.
- 검토 계획 세션 제거, 이의 루프 전용 무진전 상태, 국소 수정만의 재인증과 전문 외부 Lean 라이브러리 직접 의존은 기능·신뢰를 줄이므로 채택하지 않는다.

수정된 통합 설계는 규범 스키마 투영 71개와 테스트 벡터 128개를 가진다. 수치는 구현 정본의 양을 목표로 늘린 결과가 아니다. 수동 목록과 중복 상태를 제거한 뒤, 실제로 빠져 있던 계약 검사·감시 종료·ZFC 이동·인증 철회 벡터를 추가한 결과다.

## 2. 읽고 검증한 범위

다음 원문을 전수 읽었다.

- 복잡성 세부 검토 `복잡성-O1.md`~`복잡성-O4.md`
- 복잡성 검증 `검증-복잡성-O1.md`~`검증-복잡성-O4.md`
- 충실성 종합과 `충실성-F1.md`~`충실성-F7.md`
- 충실성 종합 검증과 `검증-충실성-F1.md`~`검증-충실성-F7.md`
- 현행 `CONTEXT.md`, 지도 컨텍스트, `docs/do-math/통합-설계.md`, 이슈 18 본문과 P vs NP 주제 선호

검토·검증 보고의 기술은 액면가로 채택하지 않았다. 각 복잡성 지적을 현행 통합 설계 전문에서 다시 재현했고, 검증 보고가 부분 타당 또는 기각으로 내린 반론을 함께 판정했다.

사용자 지시에 따라 `기억/`은 읽지 않았다. 세션 대화 전문도 다시 읽지 않았다. 추가 확인이 결과를 바꾼 네 좌표만 발췌했다.

1. ZFC 비교 기준과 최종 결론의 기초 이동 승인
2. 기본 기초 하나와 대안 기초 여러 개의 보존 승인
3. 인증 부여·철회 원칙과 철회 권한 세부의 보류
4. 연구 실작업자에게 `gpt-5.6-terra`를 쓰지 않는 기존 결정

발췌 대조 결과는 충실성 검토의 원 진술과 일치했다.

## 3. 복잡성 검토의 최종 처분

표의 `채택`은 지적과 대안을 그대로 적용했다는 뜻이다. `교정 채택`은 결함은 인정하되 검증 보고의 반론을 반영해 대안의 범위나 구현을 바꿨다는 뜻이다. `기각`은 현행 기능을 줄이거나 지적의 전제가 원문과 맞지 않아 적용하지 않았다는 뜻이다.

## 4. 충실성 검토의 최종 처분

충실성 종합의 `왜곡 0`과 주된 계보 복원은 대체로 맞았다. 다만 검증이 지적했듯 “잔존 결함은 ZFC 하나”라는 결론은 강했다. 다음 네 항목을 원 대화 발췌로 다시 확인하고 현행 계약에 명시했다.

1. **ZFC 이동**: `P = NP` 또는 `P ≠ NP` 최종 결론은 ZFC 또는 명시한 더 약한 기초의 별도 증명, 검증된 번역이나 해석·보존 정리를 요구한다.
2. **대안 기초**: 활성 기초는 하나지만 다른 기초의 결과를 별도 프로필·신뢰 시대에 보존한다. 검증된 이동 없이 활성 `K`에 섞지 않는다.
3. **인증 철회**: 기계 결함은 즉시 정지하고, 의미 결함은 정확한 인증 판본의 독립 이의 심사를 거쳐 철회한다. 영향은 실제 인증 의존 관계에만 전파한다.
4. **모델 범위**: 연구 내용이나 수학 판단을 생산·평가하는 역할에는 `gpt-5.6-terra`를 사용하지 않는다. 역할별 모델은 통합 설계의 단일 표가 소유한다.

세션 G의 단순화 목적은 “무조건 짧은 명세”가 아니라 AI 재량을 살리고 불필요한 기제를 제거하라는 방향으로 해석했다. 따라서 안전·수학 신뢰를 담당하는 구조는 유지하고 중복 소유·무소비 상태·수동 동기화 표면을 제거했다.

충실성 F4가 지적한 이슈 18 댓글의 사용자 발화 오귀속도 수정했다. 재구성 문장을 사용자 인용처럼 보이게 한 블록을 실제 사용자 발화로 교체하고, 공용 작업대에 관한 전제는 채택 근거였음을 분리했다.

## 7. 검증 결과와 남은 경계

수정한 네 로컬 정본에 대해 다음을 확인했다.

- UTF-8 BOM 없음
- Markdown code fence 짝 일치
- 통합 설계 JSON 예시 7개 구문 통과
- 최상위 절 `0`~`29` 연속
- 테스트 ID 128개 전건 고유
- 스키마 ID 71개 전건 고유
- `git diff --check` 통과
- 제거한 옛 ref·요청 배열·역할별 미완료 토큰·수동 정책 root·`canon_entry_exists`가 현행 계약에 남지 않음
- ZFC 이동, 대안 기초, 인증 철회, request/supervisor ref, `monitor_stopped`, transcript와 크리덴셜 점유 경계가 실제 소비 절·테스트까지 연결됨

이 검증은 설계 문서의 구조·정합성 검사다. `do-math` 구현, JSON Schema 파일, Windows Job Object fault injection과 Lean 빌드는 아직 존재하지 않으므로 실행하지 않았다. 그 실행 검증은 [「보편 수학 연구 스킬 do-math를 구현하고 검증한다」](https://github.com/MegasKomnenos/math/issues/19)의 완료 조건이다.

사용자가 `기억/` 열람을 금지했으므로 기억 그래프와 커밋 메모리 노드의 읽기·갱신·검사는 수행하지 않았고 기억 파일도 변경하지 않았다. 이 제한은 문서 재심사와 위 검증 결과에는 영향을 주지 않지만, 이번 커밋에는 `commit-harness`의 메모리 노드 결합 단계를 적용하지 않는 사용자 지시상 예외가 생긴다.
