## 구간 서사 (10문장 이내)

H 리셋 뒤 백지에서 재개한 세션 I는 assistant가 단일 조정자·병렬 작업자 동시성부터 물었다가 사용자의 「근본 층위 먼저」 교정을 받았다. 사용자가 known mathematics/frontier/unknown 목적 진술을 제시했고, 이로부터 `K`의 정의, `U → F → K` 모형, 형식 타당성·의도 대응·신뢰 시대의 이중 축, 적응형 연구 포트폴리오, 프런티어 확장과 연구 진전의 구분이 차례로 확정됐다. 이어 사용자가 자기완결 연구 프로그램·공용 작업공간·점유 구조와 작업대의 원 의도를 제안·설명했고, Git 판본 제안까지 나온 상태에서 실행 조정층 승격을 지적받은 assistant가 이를 철회한 뒤 handoff(댓글 1)로 종료했다. 세션 J는 그 미결정에서 재개해 Git 판본 계약, 연구 작업대의 의미, 핵심 기록·파생 보기·공용 편입 골격, 안정 ID+Git 판본, 공통 외피+역할별 내용을 확정했다. 그 직후 사용자가 「애시당초 별도의 연구 프로그램을 두는 대신 작업 단위로 분할」을 다시 열어 프로그램 구조를 폐기하고 작업 중심 구조로 전환했다. 이어 작업 DAG 폐기와 깊이 1 실행 껍질 고정, 예상하지 못한 `U → F` 발견 후보, 순차 절차의 작업 경계, 작업당 종결 공용 편입 한 번, 씨앗의 네 생성 근거, 씨앗·작업 동일 ID, 네 작업 인터페이스, 선언형 발생 조건식, JSON 물리 형식, Git 실행 ref 점유가 확정됐다. 작업자 중단 처리에서 assistant의 lease·heartbeat·fencing 자동 회수안을 사용자가 진단 우선 운영 점검으로 교체했다. 운영 점검 처분 권한 분리 추천을 사용자가 답하기 전에 세션을 멈췄고, 그 미결정을 담은 handoff(댓글 2)로 종료했다. 세션 J는 이슈 18 본문의 「단일 작업 DAG」 문면도 실행 껍질 구조로 직접 갱신했다.

### F4-36 공용 머리·Git 실행 ref·작업 브랜치의 분리

- 판정: 후속 구간 확인 필요

### F4-38 진단 우선 운영 점검(자동 lease 회수 폐기)
- 원 진술: J — 「대신, 프로세스가 사라졌거나 아니면 살아 있지만 N 시간이 지났을 경우 별도의 점검 작업을 그에 대해 실행해서 직접 관련 코드, 내용, 로그 및 상태 정보 등을 읽고 … 그에 대한 처분을 결정하게 하는 것은 어때?」 → 「확정」
- 종류: 사용자 결정 + 확정 계약
- 판정: 반영
- 이슈 18 좌표와 근거: 댓글 2 §17(자동 lease 회수안 불채택 명기, 발동 조건, 작업별 `N`, ref 고정·낡은 관찰 처리, 승인 시에만 fencing), 본문 범위 7항(「운영 점검 실행, 운영 처분 실행, … 진단 우선 실패 회수」)과 불변 결정(「외부 안전 발동 조건과 작업 진전 계약의 점검 발동 조건은 자동 점유 상실이 아니라 운영 점검 실행을 발동한다」). 발동 조건의 세부 표현(heartbeat 부재, 시간·진전 한계 `N`)은 뒤 구간의 관찰 조건·관찰 의무 체계로 정련됐으나(댓글 3 미결정 → 댓글 4 §1~§2) 진단 우선 원칙 자체는 본문에 존속하므로 모순이 아니다.

### F4-40 handoff 작성 지시와 재구성 요구
- 원 진술: J — 「관련 자료들에 결정화 되지 않은 이 세션의 대화 진행 전체의 고유 맥락 등을 다음 세션이 읽어 전달받을 수 있도록 정리해 보존하자」, 「이미 결정되어 정본에 기록된 대상들에 대해서도 보다 세부적이고 디테일한 전후 맥락을 포함해 담아줘. 그리고 … 정해진 절차를 통해 어차피 이미 제공되는 정보들은 제거해줘」, 「적용」
