### F1-26: 타당

- 근거: 세션 C 2710~2799행은 Cook의 결정적 Turing 기계와 검증 관계에 직접 필요한 정의만 초기 범위로 삼도록 승인한다. 이슈 18 본문 14행은 핵심 정의 소유자를 프로젝트 입력 문서로 분리하고 댓글 5의 1144행은 후속 이슈 20을 가리키므로, 이 구체 정의가 보존됐는지는 담당 구간만으로 확인할 수 없다.

### F1-27: 타당

- 근거: 세션 C 2805~2905행은 `P = NP`, `P ≠ NP`를 별도 Lean 명제로 두고 문제 객체에는 해결·미해결을 적용하며 동시 승인 시 모순으로 처리하도록 승인한다. 이 프로젝트 특화 구조는 이슈 18 본문에 없고 범위 19(36행)는 프로젝트별 하드코딩을 금지한다. 후속 프로젝트 입력·이슈 20 대조가 필요하다는 판정이 타당하다.

### F1-28: 부분 타당

- 근거: 세션 C 3042~3224행에서 승인된 계약은 단순 개명뿐 아니라 표현 인증과 증명 인증의 분리, 명제·관계의 이중 요건, `미인증`은 거짓이나 의심이 아니라는 의미, 활성·비활성의 독립을 포함한다. 이슈 18은 본문 28~29, 42~43행 등에서 인증 어휘와 절차를 쓰지만 이 세부 의미를 정의하지 않는다. 용어 전환은 반영됐어도 의미 전환 전건이 반영됐다고 볼 수 없으므로 보고서의 `반영`은 `부분 반영`으로 낮춰야 한다.

### F1-29: 타당

- 근거: 세션 C 3397~3534행과 3653~3656행은 검토 성공 뒤 인증을 부여하고 실제 인증 의존 관계에 한해 박탈 영향을 갱신한다는 큰 원칙을 확정한다. 이슈 18 본문은 인증 절차의 존재만 범위 12에 두며 부여·박탈·전파 규칙을 명시하지 않는다. 후속 재설계 또는 설계 문서 이관 확인이 필요하다.

### F1-30: 타당

- 근거: 세션 C 3637~3656행에서 사용자는 방금 승인한 인증 박탈 권한·절차를 즉시 취소하고 전체 작업 흐름을 먼저 정한 뒤 다루도록 보류했다. 이슈 18 댓글 2의 협업 방식 629~638행은 제1원리와 전체 구조를 먼저 확정하는 순서를 보존하지만, 박탈 권한의 최종 규칙은 이 구간에 없다. 보고서가 보류와 순서 원칙을 분리해 판정한 것은 맞다.

### F1-31: 타당

- 근거: 세션 C 4138~4351행은 상세성·누락 방지·백지 세션 가독성, 표면 연대기보다 본질·목적·구조의 보존, 함축 금지, 검색이 아닌 적재 맥락의 직접 검토를 반복해 요구한다. 이슈 18 댓글 4의 851~870행은 간단성·명확성·충분성·충실성과 독자 관점의 퇴고 기준으로 이를 정식화한다.

## 누락 관찰

- 세션 A 1194~1224행에서 사용자는 전체 검토자도 논증 의무마다 `승인·기각·예외`를 쓰고 전건 판정을 기계 집계하는 규칙을 별도로 승인했다. F1-11은 이의 심사 어휘만 다뤄 이 전체 검토 계약을 포함하지 않았다. 이슈 18에는 해당 세부가 없으므로 독립 항목으로 추출했다면 `후속 구간 확인 필요`가 적절하다.
- 세션 A 195~294행의 문헌 객체 반입 제안은 문헌에서 객체를 발견·등록하는 단계와 그 객체의 입증을 검토해 상태를 바꾸는 단계를 분리하고, 미정 절차를 명시적으로 비워 둔다. 사용자는 298행에서 이 제안을 포함한 추천들을 승인했지만 F1-03의 요약에는 이 반입/판정 분리 계약이 빠졌다. 이슈 18에서의 보존 여부를 별도로 확인할 필요가 있다.
- 세션 C 1330행은 `사실 뿌리 선언` 같은 자의적·모호한 새 고유명사를 만들지 말라는 명시적 작문·용어 제약이다. 이 제약은 4259행에서 handoff 초안의 보존 대상으로 다시 확인됐지만 F1-31의 원 진술군에는 포함되지 않았다. 이슈 18 댓글 4의 일반 명확성 기준과 관련되지만, 새 고유명사 금지라는 구체 경계는 별도로 추출했어야 한다.
