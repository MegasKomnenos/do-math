## 항목 판정

### F5-01: 타당

- 근거: K·L 첫 사용자 메시지의 기억 미열람·문서 크기 우선 확인 지시가 실재한다(K·L 각 12행). 이슈 18 댓글 3 「이번 연속 작업에만 추가된 읽기 지시」는 기억 미열람, 크기별 읽기와 원자료 재대조를 모두 보존한다(이슈 18 671~675행).

### F5-02: 타당

- 근거: 사용자는 점검자의 저영향 직접 확정과 별도 운영 처분 심사라는 추천을 명시적으로 확정했다(K 68~75, 127행). 댓글 3은 직접 처분과 심사 대상, 원자료 재대조 책임을 같은 경계로 기록한다(이슈 18 694~700행).

### F5-03: 타당

- 근거: 사용자는 점검 기록, 별도 심사 기록, 재점검·재심사의 새 기록 원칙을 승인했다(K 151~163행). 댓글 3은 네 기록 경계를 전건 보존한다(이슈 18 702~711행).

### F5-04: 타당

- 근거: 사용자가 심사 판정을 `승인·기각`으로 두고 사용자 결정 사례만 전례를 만드는 구조를 직접 제안했다(K 192행). 댓글 3은 승인만으로 적용 권한이 생기지 않는 점과 자동 적용 사례의 연쇄 전례화를 막는 점까지 보존한다(이슈 18 713~723행).

### F5-05: 타당

- 근거: 사용자는 `재처분`이 후속 행위를 지나치게 좁힌다고 교정하고, 정의를 확인한 뒤 `대응`으로 확정했다(K 226~291행). 댓글 3은 시작 조건, 열린 예시, 실행 계약과 실제 `대응 실행`의 구별을 정확히 기록한다(이슈 18 725~731행).

### F5-06: 타당

- 근거: 사용자는 적용 가능한 전례가 있으면 기존 필수 상신도 생략하고 기존 자율 적용 규칙도 전례 관문으로 교체하라고 확정했다(K 303~348행). 댓글 3은 전례를 범위 한정 위임으로 설명하며 네 사용자 개입 범주도 위임 범위 안에서 넘을 수 있다고 기록한다(이슈 18 721~723행).

### F5-07: 타당

- 근거: 형식 검사를 의미 판단 없이 확실히 부적합한 후보만 제거하는 필터로 두라는 사용자 결정이 실재한다(K 515행). 댓글 3은 통과가 적용 가능을 뜻하지 않고 평가 오류도 적용 불가로 바꾸지 않는다는 경계까지 보존한다(이슈 18 751~759행).

### F5-08: 타당

- 근거: 사용자는 상신 뒤 새 결정을 전례로 만들고 사용자가 명시적으로 배제한 기존 후보에 비적용 정보를 붙이는 방식을 승인했다(K 566~598행). 댓글 3은 별도 불변 `전례 비적용 관계`, 현재 사례 기본 범위와 AI의 일반화 금지를 기록한다(이슈 18 733~741행).

### F5-09: 타당

- 근거: 사용자는 전례를 추상 규칙이 아니라 실제 사용자 결정 사례로 보존하고 일반 조건은 사용자만 추가하는 추천을 승인했다(K 612~624행). 댓글 3의 사례 기반 위임 설명이 이 결정과 일치한다(이슈 18 743~749행).

### F5-10: 타당

- 근거: 사용자는 별도 재인증 없이 전례를 보관할 방법을 요구하고 원자료 봉인형 자동 활성화를 승인했다(K 653~687행). 댓글 3은 질문·답변 문맥, 기계적 생성, 모호한 원 결정의 재확인과 파생 보기의 비권위성을 보존한다(이슈 18 771~779행).

### F5-11: 타당

- 근거: 세 판정값은 K 529~539행, 역할 독립은 701~713행, 비대칭 2차와 불일치의 `판정 불가` 정규화는 727~741행에서 각각 승인됐다. 댓글 3은 세 결정을 빠짐없이 결합한다(이슈 18 761~769행).

### F5-12: 타당

- 근거: 사용자가 `gpt-5.6-sol max` 대신 `gpt-5.6-sol high`를 제안하고 확정했다(K 759~791행). 댓글 3은 전례 적용 판정 1·2차를 별도 `high` 실행으로 기록하며, 본문의 수학 판단 `max` 규칙과 대상 역할도 구별된다(이슈 18 769행, 본문 71행).

### F5-13: 타당

- 근거: 사용자가 전례의 제자리 수정 금지, 대체·폐기, 비소급, 적용 직전 판본 재검사안을 승인했다(K 809~823행). 댓글 3은 이력 보존과 새 판본 재판정까지 같은 의미로 기록한다(이슈 18 781~787행).

### F5-14: 타당

- 근거: 사용자는 근거 부족을 `승인·기각`과 구별되는 `심사 미완료` 실행 상태로 두는 추천을 승인했다(K 837~852행). 댓글 3은 미완료가 세 번째 판정이나 기각이 아니며 적용·대응·전례 관문을 열지 않는다고 기록한다(이슈 18 702~711행).

### F5-15: 타당

- 근거: 사용자는 일반 Wayfinder 절차의 중복을 제거하되 결정 경위를 지나치게 압축하지 말라고 교정한 뒤 확장본을 승인했다(K 1144~1280, 1461행). 세션은 게시본과 승인 초안의 문자 단위 일치를 확인했고(K 1463~1477행), 이슈 18 댓글 3의 구조와 내용도 확장본과 일치한다.

### F5-16: 타당

- 근거: 완료 예상의 예측 곤란성과 진전 신호를 작업 내부 운전에 사용해야 한다는 사용자 원문이 실재한다(L 158행). 댓글 4는 원문을 직접 인용하고 완료 예상의 선택성 및 작업 진전 계약의 내부 운전 의무를 보존한다(이슈 18 874~889행).

### F5-17: 타당

- 근거: 사용자는 수정된 작업 진전 계약을 승인했다(L 230~240행). 이슈 본문은 목적 기여 상태 변화, 진전 신호, 내부 절차와 다음 관찰 조건을 불변 입력으로 두고(54행), 댓글 4는 heartbeat·분량의 배제와 근거 있는 실패의 진전 가능성까지 기록한다(876~889행).

### F5-18: 타당

- 근거: 사용자는 `진전·무진전·계약 부적합` 자기 점검과 제한된 내부 적응안을 승인했다(L 258~285행). 이슈 본문 55행과 댓글 4 891~903행은 세 값, 내부 적응 한 번, 형식 검사와 의미 판단의 분담을 보존한다.

### F5-19: 타당

- 근거: 사용자는 최초 관찰 조건 모형을 `확정`한 직후 명시적으로 철회했다(L 315~323행). 그 뒤 비대칭 원칙을 반영한 재승인이 같은 구간에서 이루어졌으므로, 최초 확정을 `구간 내 대체`로 판정하고 최종안만 이슈에 남은 것을 정상으로 본 보고가 옳다.

### F5-20: 타당

- 근거: 작업자가 알 수 있는 모든 관찰 계기는 감시기도 재현하고 외부 안전 조건만 감시기에 추가할 수 있다는 사용자 정리와 승인이 실재한다(L 349행). 이슈 본문 56행과 댓글 4 905~915행이 공동 관찰 조건과 비대칭 예외를 보존한다.

### F5-21: 타당

- 근거: 사용자는 외부 감시기의 구현 주체를 질문했고, 결정론적 스크립트와 운영 점검 AI의 분리를 포함한 관찰 평가 모형을 뒤이어 승인했다(L 381~412, 416~569행). 이슈 본문 58행과 댓글 4 917~923행이 역할 경계를 그대로 기록한다.

### F5-22: 타당

- 근거: 사용자는 조건 평가 방식을 질문한 뒤 3값 평가, 평가 오류 우선과 관찰 의무 분리 모형을 승인했다(L 416~569행). 이슈 본문 56~57행과 댓글 4 911~915행은 전건 평가, 의무 ID·상태, 새 조건 세대와 낡은 관찰 재평가를 보존한다.

### F5-23: 타당

- 근거: 사용자는 첫 안전 제어 경계와 최대 응답 시각 중 먼저 도래하는 응답 조건을 확정했다(L 579~600행). 이슈 본문 57행과 댓글 4 913~915행은 최대 시각이 완료 마감이 아니며 자동 중단하지 않는다는 경계까지 일치한다.

### F5-24: 타당

- 근거: 사용자는 감시 기록을 작업자가 읽을 필요가 없다는 단방향 교정을 제시하고 승인했다(L 783~872행). 이슈 본문 58~59행과 댓글 4 925~939행은 작업자 공개 상태에서 감시·점검으로 가는 단방향 흐름과 확정 운영 처분만의 역방향 제어를 보존한다.

### F5-25: 타당

- 근거: 사용자는 실행 ref가 가리키는 완결·검증 상태만 정상 관찰 입력으로 인정하고 미커밋 상태는 이상 진단에만 쓰는 경계를 승인했다(L 882~913행). 이슈 본문 51행과 댓글 4 937행이 같은 경계를 명시한다.

### F5-26: 타당

- 근거: 최초 지시는 남은 결정을 모두 닫은 뒤 한 번에 수정하자는 것이었다(L 921~927행). 같은 세션에서 사용자는 즉시 일괄 적용한 뒤 향후에는 handoff·티켓 종료 등 세션 종결 시 갱신하라고 범위와 시점을 다시 정했다(L 1866행). 후자가 전자를 구체적으로 바꿨으므로 `구간 내 대체`가 맞으며 댓글 4에는 최종 절차만 남았다(이슈 18 1035~1043행).

### F5-27: 타당

- 근거: 사용자가 외부 세션의 Git-native 안을 검토 대상으로 제시했고(L 990~1071행), assistant가 OID의 fencing 한계, JSON OID 문자열의 객체 비보존성과 공통 ref 데이터베이스 전제를 실측한 뒤 사용자가 수정안을 확정했다(L 1091~1194행). 이슈 본문 49·51행과 댓글 4 941~987행이 수정된 구조와 검증 결과를 보존한다.

### F5-28: 타당

- 근거: 사용자는 설명을 들은 뒤 실행 상태와 원 작업 이력의 영구 보존을 승인했고(L 1252~1385행), 임시 편입 이력 보존도 다음 편입 방식 승인에 포함했다(L 1553~1567행). 이슈 본문 52행과 댓글 4 1010~1033행은 실행·작업·임시 편입 보관 ref와 비자동 만료를 보존한다.

### F5-29: 타당

- 근거: 사용자가 작업 B에 최신 공용 변경을 적용하는 방안을 물었고, 원 브랜치 동결·임시 편입 브랜치 merge·재검증·단일 직접 후속 편입 커밋이라는 수정안을 승인했다(L 1455~1567행). 이슈 본문 53행과 댓글 4 989~1008행이 같은 절차를 기록한다.

### F5-30: 타당

- 근거: 사용자는 추가 지시 절 삭제, 현재 일괄 적용과 향후 세션 종결 시 컨텍스트 정본 일괄 갱신을 명시적으로 지시했다(L 1866행). 댓글 4는 원문과 지도 Notes 반영, root 용어집과 구현 계약의 재분리까지 보존한다(이슈 18 1035~1043행).

### F5-31: 타당

- 근거: 사용자는 원문을 실익 있는 정도로만 남기고(L 2183행), 간단성을 짧음과 구별하며 명확성·충분성·충실성을 함께 보존하라고 반복 교정한 뒤 최종 재작성과 작문 기준 추가를 승인했다(L 2209~2385행). 댓글 4 「이 티켓의 작문 기준」은 이 기준과 인과 점검, 산문·목록 사용 조건을 충실히 기록한다(이슈 18 851~870행).

### F5-32: 타당

- 근거: 두 축과 네 종결 처분은 assistant의 추천 뒤 사용자 답 없이 handoff로 넘어간 미승인 제안이다(L 1573~1622행). 댓글 4는 이를 「현재 미결정과 첫 질문」으로 명시하고 사용자 답 전 수정 금지를 기록한다(이슈 18 1045~1073행). 이후 본문에 반영된 최종 상태는 후속 구간에서 생겼으므로 F5가 승인으로 소급하지 않은 것도 옳다.

### F5-33: 타당

- 근거: K의 작업별 점검 발동 계약 제안에는 사용자가 답하지 않고 handoff를 요청했다(K 866~880행). 댓글 3은 제안을 미승인으로 보존했고(이슈 18 789~795행), L에서 사용자의 교정을 거쳐 작업 진전 계약으로 확정됐으므로 보고의 구간 내 시간순 설명이 맞다.

### F5-34: 타당

- 근거: K에서 확정한 전례 관문·대응·비적용·원자료 봉인·이중 판정은 댓글 3에 상세히 남아 있다(이슈 18 713~787행). 그러나 덤프 시점의 최종 본문 불변 입력과 댓글 5 요약에는 전례 체계가 없고, K·L만으로는 후속 세션에서 유지·단순화·폐기됐는지 판정할 근거가 없다(이슈 18 본문 40~75행, 댓글 5 1123~1147행). 따라서 즉시 누락이나 폐기로 단정하지 않고 `후속 구간 확인 필요`로 둔 보고가 계약의 구간 밖 의존 규칙에 맞다.
