## 구조 정리와 보존

입력 초과의 조건·처분은 8.3절이, 제안 재구성의 후속 연구 절차는 11.3절이 소유한다. 19.5절에서 되풀이하던 후보·K 목차 필드 목록은 8.5절을 참조하고 실제 view·refs 직렬화의 구별만 남겼다. 7.3절은 OKF의 채용 범위를 닫힌 목록으로 유지하면서 채용하지 않은 계산 체계의 설명을 덜었다. D06의 최초 동기화 이력은 20절로 모으고 18절에는 후속 의무의 참조를 남겼다.

과제·활동·실행, 실행 종료·원격 정산, 형식·동일성·목표 판정의 구별은 유지했다. 같은 판본의 실패 자리 복구, 새 판본의 전면 의미 검토, 초기 전건 match의 직접 집계, 개별 이의·반박의 보존과 구체 수학 사례도 유지했다. K 목차 전건·대화 연속성·전면 재검토의 연구 효과를 측정 없이 부정하지 않았다.

## 검증 범위

다음 명령으로 묶음을 재생성하고 예제 저작 뒤 저장된 산출물을 검사했다.

```text
python docs/do-math/통합-설계-명세-v9/build_spec.py
python docs/do-math/통합-설계-명세-v9/verify_spec.py --refresh-examples
python docs/do-math/통합-설계-명세-v9/verify_spec.py
```

명세 검사는 기존 70개에 경계 검사 5개를 더한 75개다. 새 검사들은 수정 전 검사기의 미지원 입력 또는 한 회차 방침 거부를 검출했다. 수정 후에는 공급자 상태 무시, 하위 실행 합산 생략, 두 회차분 고정, 공통 문면의 초과 우선순위 제거를 각각 메모리 안에서 주입하여 네 변경 모두 새 검사에 검출됨을 확인했다. 이 프로브는 파일을 바꾸지 않았다.

V01–V222는 본문 대응 사례이며 V159·V189는 철회 번호다. Q01–Q22와 스키마·레지스트리·검사기·생성 표를 대조한다. V 전건의 실제 런타임 실행 상태는 여전히 not_run이다. 정확한 검사 입력의 해시와 통과 결과는 명세 묶음의 validation-report.json·validation-output.txt에 있다.

실제 모델·Windows 프로세스 생성과 격리·공급자 종료·Lean 실행·연구 효능 시험은 수행하지 않았다. 이번 수리는 본문과 오프라인 명세를 대상으로 하며 별도 에이전트의 독립 검토를 수행한 기록은 아니다. 외부 정의는 이번에 영향받은 문면만 동기화했으며 문서 전체의 재검토를 주장하지 않는다.
