# do-math 기능 완료 대응

이 표는 [통합 설계](통합-설계.md)의 기능 목적을 feature 2 구현과 검증 근거에 연결한다. 새 승인 양식이 아니며, 특정 v9 wire·OS 수단을 그대로 반복하는지를 완료 기준으로 삼지 않는다. 소비자에게 필요한 기능 효과는 모두 구현해야 하고, 같은 목적을 충족하는 부수 수단은 현재 실행 환경에 맞게 바꿀 수 있다.

증거는 성격에 따라 구별한다.

- **실제 전체 workflow**: [영구 보고서](구현-검증-2026-09-14/feature2/workflow/report.json)의 실제 Codex CLI 18회와 실제 Lean 1회. 작업 8회·운영 10회 뒤 수학 목표와 설정된 학술 요구를 모두 완료했다.
- **실제 경계 사례**: [의미 이의·부정 사례](구현-검증-2026-09-14/feature2/semantic/), [실행 중 관찰](구현-검증-2026-09-14/feature2/observation/README.md), [신뢰 환경 전환](구현-검증-2026-09-14/feature2/trust/report.json), [CLI 프로필](구현-검증-2026-09-14/feature2/cli-profile/)처럼 해당 경계만 실제 모델·Lean·프로세스로 검사한 증거다.
- **결정적 검증**: 순수 상태 의미, model-double 엔진 시간선, 임시 Git, 실제 Windows process와 loopback HTTP 검사다. 모델의 판단 품질이 대상이 아닌 상태 전이는 이 검사가 직접적인 완료 증거다.
- **과거 증거**: 초기 CLI1의 9 AI·1 formal 흐름과 당시 97개 회귀는 그 source manifest에 한정한 역사적 근거이며 현재 완료 수치로 사용하지 않는다.

## 현재 완료 판정

통합 설계의 필수 기능 목적은 feature 2 코드에 구현됐고 기능 검증도 완료됐다. 실제 전체 workflow·의미 검토·관찰·신뢰 전환과 결정적 회귀가 목적별 근거를 제공한다. 이 판정은 실제 모델의 일반 수학 능력, 모든 외부 서비스, 공급자 내부 호출, 모든 호스트 경로의 강제 격리를 보증하지 않는다.

Planning 변경의 [첫 targeted 진단](구현-검증-2026-09-14/feature2/regression/first-targeted-diagnosis/result.json)은 45건 중 1건이 실패했다. 학술 요구의 필수 외부 효과 fixture가 loopback 결과를 `unknown`으로 받았지만 당시 예외 원문은 저장되지 않아 원인을 확정하지 않았다. HTTP fixture의 완전한 요청 본문 소비·Content-Length 응답·오류 기록을 보강하고 좁은 반복 검사와 학술 검사를 통과한 뒤, 최종 동결본의 45건도 모두 통과했다. 첫 실패는 삭제하거나 사후에 다른 원인으로 단정하지 않고 영구 보존한다.

정본, 생성한 `.agents` 미러, 검증 자료와 작업 기억을 같은 작업 커밋으로 관리한다. 이 대응에서 확인한 필수 기능 간극과 기능 검증 항목은 모두 닫혔다.
