# 통합-설계 상시 생성·목차 열람 개편 수정안

## 0. 이 문서의 지위와 읽기 계약

이 문서는 `docs/do-math/통합-설계.md`(이하 "통합-설계")를 개편하는 확정 결정과 구체 규격의 정본이다. 연구 책임자가 2026-09-01 검토 대화에서 개편의 골격을 승인했고, 골격이 정하지 않은 세부는 연구 책임자의 지시에 따라 AI가 그 대화의 전체 맥락에서 가장 타당한 값으로 채웠다. 어느 부분이 어느 쪽인지는 5절이 구분한다. 이 문서 전체가 연구 책임자의 검토 대상이다.

수신자는 개편을 수행할 신규 AI 세션이다. 우선순위 계약은 다음과 같다.

- 이 수정안의 기준 문면은 `docs/do-math/지식층-OKF-수정안.md`(이하 "지식층 수정안")의 반영이 완료된 통합-설계다. 그 반영이 완료되기 전에는 이 수정안을 적용하지 않는다.
- 개편 작업 중에는 이 문서의 3절(확정 결정과 구체 규격)이 통합-설계의 현행 문면보다 우선한다.
- 이 문서가 다루지 않는 사항은 통합-설계의 현행 내용을 유지한다.
- 이 문서 안에서 3절과 다른 절이 어긋나면 3절이 우선한다.
- 이 문서의 결정·규격과 다른 선택이 필요하다고 판단되면 임의로 바꾸지 않고 사용자에게 상신한다.

개편이 완료되면 통합-설계가 유일한 구현 정본이고 이 문서는 경위 기록으로 남는다. 이 문서를 통합-설계와 병행하는 제2 정본으로 유지하지 않는다.

### 0.1 착수 전 필독

수행 세션은 다음을 전문으로 읽은 뒤 착수한다.

1. 이 문서 전문
2. `docs/do-math/통합-설계.md` 전문 (지식층 수정안 반영 완료본)
3. 루트 `CONTEXT.md` 전문 (보편 용어 정본)
4. `docs/wayfinder/pvsnp-재설계/컨텍스트.md` 전문 (티켓 계약과 정본 소유권)

이 문서가 인용하는 통합-설계 절 번호는 지식층 수정안 반영 전 문면 기준이다. 지식층 수정안의 수행 세션은 절 번호 재배치 재량을 가지므로, 이 수정안의 수행 세션은 완료본에서 대응 절을 절 이름과 내용으로 찾는다.

## 1. 개편의 본질

### 1.1 무엇을 만드는가

세 변경을 만든다.

1. **생성 회차 규칙**: 빈 실행 껍질에서만 열리던 씨앗 생성 세션(§7.7 생존 절차)을, 실행 껍질이 바쁘게 돌아가는 평시에도 주기적으로 열리는 **생성 회차**로 확장한다. 생성 세션은 공용 작업대의 현재 상태 전반을 재량으로 열람하고 다양한 새 작업 씨앗과 기존 씨앗 정련·대체안을 제안한다.
2. **렌즈 지시**: 생성 세션이 받는 씨앗 계약에, 의도적으로 폭넓고 서로 다른 관점(렌즈)을 지정한 탐색 씨앗을 포함하도록 고려하는 지시를 넣는다. 이 탐색 씨앗은 서로 다른, 때로는 거리가 먼 개념들을 연결·고찰해 새로운 통찰·방향·후보를 생산하는 작업이다.
3. **목차 packet**: 포트폴리오 선택 packet(§10.2)을 후보·연구 상태의 전문 동봉에서 **목차 제공 + 고정 커밋 재량 열람**으로 바꾼다. 선택자는 목차를 훑고, 관심 가는 후보와 원자료를 스스로 골라 깊이 읽는다.

부수 변경 하나가 따른다: 착수 명세 검토자의 모델을 sol max에서 sol high로 내린다(3.6).

### 1.2 왜 만드는가 (사용자 확정 목적)

1. **씨앗 생성을 생명주기 사건에서 해방한다.** 현행 설계에서 새 아이디어가 공용 상태에 들어가는 AI 유래 경로는 작업 종결 묶음과 빈 껍질 생존 절차뿐이다. 종결 제안자는 자기 계약의 시야를 갖고, 생존 생성자는 풀이 고갈된 뒤에야 깨어난다. 전판을 신선한 컨텍스트로 훑으며 후보 사이의 패턴을 보고, 엉뚱한 연결을 포함한 다양한 씨앗을 계속 공급하는 자리가 없다. 생성 회차가 그 자리를 만든다.
2. **소관은 생성 보장까지다.** 이 개편은 다양한 씨앗이 풀에 계속 존재하게 만든다. 그 씨앗의 추구는 현행 그대로 포트폴리오의 순수 재량이다. 씨앗 기아(생성됐으나 계속 선택되지 않는 상태)에 대한 대책 여부는 포트폴리오의 실제 작동을 관찰한 뒤 연구 책임자가 판단한다. 관찰 원자료는 현행 기록으로 충분하다: 후보별 처분과 보류 이유(§10.4), 대기 이력·기아 위험 고려 의무(§10.3), 과거 선택의 기대·실제 환류(§10.2).
3. **packet을 규모에서 해방한다.** 현행 packet은 미점유 후보 전부와 후보별 연결 자료 전문을 1M 한도에 담고, 초과하면 요약 없이 선택을 차단한다(§10.2, 테스트 P03). 후보와 연구 이력이 자라는 장수 인스턴스는 이 절벽에 부딪친다. 목차 packet은 절벽을 "풀이 클수록 선택적으로 읽는" 경사로 바꾸고, 지식층 수정안이 만든 지식 트리·`index.md`·`description`을 항해 표면으로 그대로 쓴다.

- 선택자에 대한 원자료 열람 의무, 기아 위험 후보의 지정과 그에 결부된 의무, 열람 이행의 transcript 검증

## 2. 배경: 현행 설계에서 알아야 할 최소 사실

수행 세션은 통합-설계 전문을 읽으므로 여기서는 개편 결정을 이해하는 데 필요한 연결 사실만 짚는다.

- 씨앗 생성 근거는 넷으로 닫혀 있다: 초기화, 작업 종결 공용 편입, 승인된 외부 변화, 빈 실행 껍질의 생존 규칙(§7.1 `generation_basis`, 루트 CONTEXT.md 「작업 씨앗 생성 근거」).
- 생존 절차(§7.7)는 "목표 unsolved + 활성 연구 작업 없음 + 빈 실행 껍질"에서만 씨앗 생성 세션을 열고, 7단계 절차(기존 씨앗 전수 검사 → 외부 대기 보고 → 세션 개설 → 제안 작성 → output ref 봉인 → 기계 검사·독립 착수 검토 → `survival_generation` 원자 편입)를 수행한다.
- 선택 packet(§10.2)은 헌장·정책·맥락·설정 전문, K manifest와 인증 해설, F 전건, 미점유 후보 전부와 후보별 연결 자료 전문, 진행 중 작업, 과거 선택, 용량, 선택 계약을 담고, 후보 블록을 HMAC seed로 섞으며, 토큰 초과 시 `context_overflow`로 차단한다.
- 역할별 모델·노력은 §9.1의 단일 역할표가 소유하고, 표의 변경은 연구 설정 변경이 아니라 `do-math` 계약 변경이다.
- 공용 변경 종류(§18.0)는 여섯으로 닫혀 있고 생존 생성은 `survival_generation`이다.
- 지식층 수정안 반영 후 F·관계·근거·기억·맥락은 `knowledge/` 트리의 개념 문서이고, 디렉터리별 `index.md`(상대 경로 링크 + `description` 요지 + 기록 ID)와 `id-index.json`이 공용 편입마다 결정론 재생성된다.

## 3. 확정 결정과 구체 규격

이 절이 개편의 규범 전건이다.

### 3.1 생성 회차 규칙 (트리거)

씨앗 생성 세션이 열리는 조건을 다음 두 갈래의 OR로 확장한다. 두 갈래는 같은 역할(씨앗 생성자), 같은 절차(3.2), 같은 생성 근거 값과 같은 공용 변경 종류를 사용한다.

- **주기 갈래**: 인스턴스가 `active`이고 목표가 `unsolved`이며, 마지막 생성 회차의 개설 UTC 시각부터 연구 설정 `seed_generation_interval` 이상 경과했으면 메인 heartbeat가 생성 회차를 연다. 실행 껍질의 상태와 무관하게 발동하며, 외부 대기 가드를 적용하지 않는다.
- **고갈 갈래**: 현행 생존 조건 그대로다. 목표가 `unsolved`이고 활성 연구 작업이 없으며 실행 껍질이 비면 주기 경과와 무관하게 발동한다. 현행 §7.7 1~2단계의 기존 씨앗 전수 검사와 외부 대기 가드(외부 사건만 기다리는 씨앗이 있으면 사건·재관찰 조건을 보고하고 새 씨앗을 만들지 않는다)를 유지한다.

세부 규격:

- `seed_generation_interval`은 연구 설정의 양수 ISO 8601 기간이며 기본값은 `PT24H`다. 주기 판정은 `wall_time_reached`(§14.2)와 같은 UTC 벽시계 방식이다. 단조 시계는 프로세스 재시작을 넘는 일 단위 주기에 쓸 수 없다.
- controller 상태(§9.0)에 마지막 생성 회차의 request ID와 개설 UTC 시각을 기록한다. 인스턴스에 생성 회차 기록이 아직 없으면 인스턴스 생성 시각을 앵커로 쓴다.
- 생성 회차는 동시에 하나만 연다. heartbeat 직렬성(§9.2)이 이를 보장하며, 주기 도래와 고갈이 같은 heartbeat에서 겹치면 회차 하나만 연다.
- heartbeat 절차(§9.3)에 생성 회차 도래 검사와 회차 개설 단계를 추가한다. 자리는 완료 실행 처리 뒤, 포트폴리오 선택 요청 전이다.
- 생성 근거 값과 공용 변경 종류의 명칭을 개정한다: 넷째 생성 근거 "빈 실행 껍질의 생존 규칙" → **"생성 회차 규칙"**, §18.0 `survival_generation` → **`seed_generation`**. 다섯째 값을 신설하지 않는다. 루트 CONTEXT.md 「작업 씨앗 생성 근거」의 넷째 항을 같은 뜻으로 개정한다(6절 3단계).
- 씨앗 생성자를 모델 용량 사용량 집계(§9.1)에 명시로 포함한다.

### 3.2 생성 회차의 절차와 산출

현행 §7.7 3~7단계의 기계를 그대로 사용한다: 9.1절 역할표의 씨앗 생성 세션 개설(§4.3 request 사슬) → 제안 작성 → 자기 output ref 봉인 → 메인 세션의 스키마·참조·생성 근거 좌표 기계 검사 → 통과 씨앗별 독립 착수 명세 검토 → `seed_generation` 공용 변경으로 원자 편입.

생성 세션의 입력은 현행 생존 생성과 같다: 연구 헌장, 현재 K·F, 기존 씨앗 전건, 실패·선택 이력(후보별 처분·보류 이유 포함), `do-math` 씨앗 계약 전문. 지식층 수정안 반영 후 K·F·근거·기억의 열람은 지식 트리와 그 색인으로 한다.

산출과 재량:

- 산출은 새 작업 씨앗과 기존 씨앗 정련안이며, 정련안에는 대체(supersede) 제안을 포함할 수 있다. 씨앗 생명주기 변경은 현행 §7.2 규율대로 명시적 근거를 가진 공용 변경으로만 적용된다.
- 회차당 생성량, 렌즈 선택, 탐색·집중 활용 배합, 정련·대체 제안 여부는 생성 세션의 재량이다. 상한과 의무를 두지 않는다.
- 실행 가능한 씨앗을 만들지 못한 회차는 현행 문면대로 부족한 입력, 남은 F, 시도한 생성 방향과 다시 생성할 사건을 기록한다.

씨앗 계약은 선택 계약과 대칭으로 계약 수준에 잠근다: `do_math_contract`(§6.1)의 구성에 씨앗 계약 판본·해시를 추가한다. 지식층 수정안이 다섯으로 늘린 구성이 여섯이 된다. §6.1의 표·수량 표현과 §3.2의 구성 문장을 같은 값으로 함께 고친다.

### 3.3 씨앗 계약 문면: 렌즈 지시

씨앗 계약에 다음 골자의 지시를 넣는다. 정확한 문면은 수행 세션이 작성하되 골자의 의미를 보존한다.

- 회차마다 탐색과 집중 활용 양쪽의 씨앗을 함께 고려한다. 그 일부로, 의도적으로 폭넓고 서로 다른 관점(렌즈)을 지정한 탐색 씨앗을 포함하는 것을 고려한다.
- 렌즈 지정 씨앗의 기본형: 질문은 "지정한 렌즈에서 현재 K·F·자료·기억과 문헌 기준선 유래 자료를 통독·재해석해, 기존 F 후보와 구별되는 새로운 통찰·방향·정의 후보를 생산·기록하라"의 꼴이다. `exploration_intent`에 렌즈, 방법, 기존 후보와의 구별 기준을 명시한다. 완료 기준은 판정 가능하게 닫는다. 예: "기존 F와 구별되는 신규 발견 후보 N개 이상, 각각 근거 좌표와 구별 서술 포함". 진전 신호는 관찰 가능한 상태 변화(예: 신규 발견 후보의 작업대 기록)로 둔다.
- 거리가 먼 개념의 연결을 피하지 않는다. F 객체의 `selection_relevance`는 추측적 관련이어도 그 추측을 명시하면 충분하다.
- 씨앗 제안의 근거는 확인된 근거, 추론, 가설, 직감을 구분해 기록한다.

이 지시는 고려 의무이지 회차별 강제 산출이 아니다. 렌즈 씨앗이 없는 회차도 유효하다.

### 3.4 포트폴리오 packet의 목차 개편

§10.2의 packet 구성을 다음 이분 원칙으로 개정한다.

**전문 유지** (작고 필수적인 통치·이력·용량): 연구 헌장·정책·설정 전문, `do-math` 선택 계약과 도구 사용법, 과거 포트폴리오 선택의 기대·실제 결과, 실행 중·인계 대기·인증 중 작업 목록, 모델 용량과 현재 세션.

**목차 + 재량 열람** (규모와 함께 자라는 연구 상태):

- **후보 목차**: 실행 껍질의 미점유 후보 전부. 항목은 task ID, 제목, 한 줄 요지(`description`, 있으면), `work_class`, 관련 F ID다. 항목 순서는 현행 HMAC shuffle을 유지하되, 섞는 대상이 후보 블록 전문에서 목차 항목으로 바뀐다.
- **지식 목차**: 지식 트리의 `index.md` 전건과 `id-index.json`. 별도 생성물을 신설하지 않고 지식층 수정안의 파생 보기를 재사용한다.
- **K 목차**: 현행 K manifest(정본 객체 목록)는 유지하되 인증된 수학 해설의 전문 동봉을 제외한다.
- **열람**: `portfolio-pack`이 기준 공용 커밋의 읽기 전용 checkout(임시 worktree)을 준비하고 그 경로를 packet에 기록한다. 선택자는 그 경로 아래의 파일 읽기로 후보 상세(작업 기록·연결 자료), 지식 트리, 수학 해설 등 원자료를 재량으로 열람한다. 쓰기는 현행 §10.5 검사("허용 범위 밖 파일·ref를 쓰지 않음") 그대로 금지된다. 회차 종료 후 checkout을 정리하고, 정리 실패는 청소 결함(`degraded`)이다.

동반 개정:

- 작업 기록 `data`에 선택 필드 `description`(사람과 AI가 훑는 한 줄 요지)을 추가한다(§7.1). 씨앗 작성·정련 시 저작하며, 부재는 요지 없음이고 그 목차 항목은 제목만 싣는다. 목차 방식에서 요지 품질이 선택자의 주의 배분을 좌우하므로, 씨앗 계약의 저작 지침과 착수 명세 검토의 기존 항목(질문·범위 명세의 충분성) 서술이 요지 저작을 다루게 한다. 검토 항목을 신설하지 않는다.
- §10.3의 "선택자는 후보 전건을 읽고"를 "선택자는 후보 목차 전건을 훑고 필요한 원자료를 재량으로 열람해"로 고친다.
- 토큰 한도 검사와 `context_overflow` 처분(§10.2)은 목차 packet에 그대로 적용한다.
- 입력 manifest는 전문 유지 재료와 목차·checkout 좌표(기준 공용 커밋 OID 포함)를 덮는다. 열람 가능 우주는 기준 공용 커밋 OID가 봉인한다.

### 3.5 선택 계약 문면: 열람 지시

선택 계약에 다음 골자의 지시를 넣는다. 정확한 문면은 수행 세션이 작성하되 골자의 의미를 보존한다.

- 후보 목차 전건을 훑는다. 어떤 후보와 원자료를 얼마나 깊이 열람할지는 실제 판단에 따른 재량이다.
- 판단 근거의 구분 기록 규율(§10.3)은 열람 깊이에 그대로 적용된다. 목차만 보고 내린 처분은 그렇게 기록한다.
- 후보별 처분 완결성(§10.4~10.5)은 유지된다.

열람 의무, 기아 위험 후보의 지정, 열람 이행의 transcript 검증을 도입하지 않는다(1.3절의 기각 목록).

### 3.6 착수 명세 검토자의 모델

§9.1 역할표에서 착수 명세 검토자를 sol max 행에서 분리해 전례 적용 판정자와 같은 `gpt-5.6-sol high`로 배정한다. 근거: 검토 항목(§7.4)은 명세 품질의 메타 판단이며, 의미 비교 메타 판단인 전례 적용 판정과 같은 급이다. terra 금지와 "연구 내용·수학 판단을 생산하는 역할은 sol max" 원칙은 불변이다. 검토 결함의 하류 방벽(포트폴리오 재량, 작업자의 실제 수행)이 존재하고 검토는 씨앗 판본마다 반복 가능하므로 하향의 실패 비용이 낮다. 운용 증거가 부족을 보이면 역할표 개정(계약 변경)으로 재론한다.

- 주기 갈래: 주기 도래 시 실행 껍질이 바빠도 생성 회차 개설. 주기 미도래 시 미개설. `mathematically_solved`·`paused`에서 미개설
- 고갈 갈래: 현행 S09의 의미 유지(명칭 개정 반영). 외부 대기 가드는 고갈 갈래에만 적용하고, 주기 갈래는 외부 대기 씨앗이 있어도 생성 가능(S10 개정)
- 주기·고갈 동시 도래 시 회차 하나만 개설
- 목차 packet: P01~P03의 목차 기준 개정, 목차 shuffle 결정론(P04 상당), `description` 부재 항목의 형식
- 선택자 checkout: 파일 읽기 허용, 쓰기 시도는 검사 실패, 회차 후 정리, 정리 실패는 `degraded`
- 후보별 처분 완결성이 목차 방식에서도 검사됨
- `seed_generation` 명칭의 스키마·검사 정합

**무변경 확인 목록**: §0~§2, §3.1, §3.3~3.4, §4, §5, §6.2, §6.4~6.10, §7.2~7.3, §7.5~7.6, §8, §9.2, §10.4, §11~§17, §18.1~18.7, §19~§23, §24.1, §24.3~24.4, §25.1, §25.3~25.7, §27, §28. 위 표의 행과 이 목록이 통합-설계의 절 전건을 나눠 덮는다. 개편 뒤 전문 통독(6절 2단계)에서 이 목록의 절에 파급이 발견되면 이 지도의 결함이므로 최소 반영하고 보고에 기록한다.

## 5. 결정의 유래 구분: 연구 책임자 검토용

**대화에서 명시 승인된 골격**: 상시 씨앗 생성자(생존 절차를 주기 기반 생성 회차로 확장하고 재량으로 다양한 씨앗을 생성); 소관은 생성 보장까지이고 추구는 포트폴리오 순수 재량 유지, 기아 대책 여부는 운용 관찰 후 연구 책임자 판단; 의도적으로 폭넓은 렌즈를 지정한 통찰 씨앗; packet의 목차 + 자율 열람 전환(열람 의무·기아 위험 후보 지정·transcript 검증의 배제, 열람 방식 지시만 부여, 목차 shuffle 유지); `description` 비중 증가 인식; 착수 명세 검토자 sol high 하향; 큐레이션·생성량 재량(상한·의무 없음); 빈도 노브에 의한 비용 통제; 별도 수정안 문서 + 기준 문면은 지식층 수정안 완료본 + verify-rounds는 별도 세션.

**AI가 채운 세부** (사용자 지시에 따라 채움. 검토 시 이 목록을 우선 훑으면 된다):

1. 넷째 생성 근거의 의미 확장(다섯째 값 신설 대신)과 명칭 개정: "생성 회차 규칙", `survival_generation` → `seed_generation` (3.1)
2. 주기 갈래의 정확한 조건(인스턴스 `active`·목표 `unsolved`·UTC 경과), 앵커(controller 상태의 마지막 회차 request ID·개설 UTC, 최초 앵커는 인스턴스 생성 시각), 벽시계 방식, 회차 동시 1개, heartbeat 내 위치 (3.1)
3. `seed_generation_interval` 노브와 기본값 `PT24H` (3.1)
4. 외부 대기 가드의 갈래 한정(고갈 갈래에만 적용) (3.1)
5. 씨앗 계약의 `do_math_contract` 잠금(구성 5→6) (3.2)
6. 렌즈 지시·열람 지시의 골자 문면과 "고려 의무이지 강제 산출 아님" 경계 (3.3, 3.5)
7. packet 이분 원칙(통치·이력·용량은 전문, 연구 상태는 목차+열람)과 목차 실체: 후보 목차 항목 구성, 지식 트리 `index.md`·`id-index.json` 재사용, K manifest 유지·해설 전문 제외 (3.4)
8. 작업 기록 `description` 선택 필드와 그 저작·검토 취급 (3.4)
9. 읽기 전용 checkout 방식(신규 CLI 없이 `portfolio-pack` 확장), 정리 규칙 (3.4)
10. 씨앗 생성자의 용량 사용량 목록 명시 (3.1)
11. 문서 이름·절 구성, 개편 지도·무변경 목록·테스트 벡터 목록, 수행 절차와 완료 기준 (4, 6, 7)

**수행 세션에 남는 재량**: 개편된 문면의 절 번호·배치·서술, §26 테스트 벡터의 정확한 ID·문면, 씨앗 계약·선택 계약의 완성 문면(3.3·3.5 골자의 의미 보존), 스키마 파일·판본 상승의 필드 상세(3절 규격의 의미 보존). 이 재량 밖의 변경 필요는 상신한다.

**이탈 등급** (이 절차에서 쓰는 닫힌 두 값):

- `중단`: 시작 조건이 미충족이거나, 필독 자료를 읽을 수 없거나, 개편의 정합을 보장할 수 없으면 수행을 멈추고 원인과 재개 좌표(끝낸 단계와 다음 단계)를 보고한다. 그대로 진행하면 정본에 검증되지 않은 규범이 들어간다.
- `상신`: 이 문서의 결정·규격과 다른 선택이 필요하거나 5절의 잔여 재량 안에서 답을 정할 수 없으면 물음과 재개 좌표를 함께 적어 사용자에게 묻는다. 임의 결정으로 진행하면 사용자 승인 범위를 벗어난다.

**단계**:

1. **개편 반영**. 3절의 규범 전건을 4절 지도의 위치에 반영한다. 서술 밀도·문체는 현행 통합-설계와 같은 수준을 유지한다. 새 연구 방법·상태·권한을 이 문서에 없는 범위에서 만들지 않는다.
2. **전문 정합 통독**. 개편본 전문을 통독하며 4절 지도 밖의 파급을 찾는다. 최소한 다음 문자열을 전수 검색해 잔존 구절을 색출한다: `survival_generation`, `생존 절차`·`생존 규칙`(씨앗 생성 문맥), `빈 실행 껍질`(트리거 문맥), `후보 전건을 읽고`, `1M`, `후보별 연결 자료`, 착수 명세 검토자의 모델 언급. 발견한 파급은 최소 반영하고 보고에 기록한다.
3. **하류 정본 동기화**. 루트 `CONTEXT.md`의 「작업 씨앗 생성 근거」 넷째 항을 3.1의 뜻("생성 회차 규칙")으로 개정하고, 다른 용어와의 충돌을 검사한다. `docs/wayfinder/pvsnp-재설계/컨텍스트.md`는 그 문서의 읽기 계약(일괄 갱신, 바꿀 것이 없으면 `정본 갱신: 영향없음` 명시)을 따른다.
4. **이슈 처리**. `docs/agents/issue-tracker.md`의 규약에 따라 이슈 18에 이 개편을 반영한다.
5. **검증 확인**. 개편본의 재검증 여부와 규모를 사용자에게 확인한다(`상신`). 답을 받기 전에는 완료로 처리하지 않고, 재검증 지시가 있으면 그 재검증이 끝나야 완료다.
6. **완료 보고**. 7절의 완료 기준 각 항에 증거를 붙여 보고한다.

중단·상신 뒤 재개하는 세션은 이미 끝난 단계를 반복하지 않도록 보고된 재개 좌표에서 잇는다.

## 7. 완료 기준

전건 충족 시 완료다.

1. 4절 지도의 모든 행이 개편본에 반영됐다.
2. 6절 2단계의 검색어가 그 단계가 붙인 한정(문맥) 아래에서 0건이다.
3. 3절의 각 규격이 개편본 문면에 존재한다: 이원 트리거와 세부(앵커·주기 노브·가드 한정·동시 1개·heartbeat 단계), 명칭 개정 전건, 씨앗 계약 잠금, 렌즈 지시 골자, packet 이분 원칙과 목차·checkout 규격, `description` 필드, 열람 지시 골자, 착수 명세 검토자 모델 하향.
4. 1.3절 유지 표의 계약이 모두 개편본에서 여전히 규정되어 있고, 기각 목록의 요소가 도입되지 않았으며, 무변경 확인 목록의 절이 수정되지 않았다(2단계 통독에서 확인한 최소 파급 제외).
5. 4절의 「신규·개정 테스트 벡터가 덮어야 할 사실」 각 항을 덮는 벡터가 §26에 있다.
6. 하류 정본 동기화가 완료됐거나 `정본 갱신: 영향없음`이 명시됐다.
7. 이슈 처리와 검증 확인(6절 4~5단계)이 끝났고 완료 보고가 제출됐다.

## 8. 경위와 근거 좌표

- 결정 경위: 2026-09-01 연구 책임자와의 grilling 검토 대화. "현행 설계가 AI의 자율적·독립 연구자적 탐구를 지원하는가"라는 화두의 진단(상시 생성 장치의 부재, 비작업자 통찰의 경로 부재, 후보 풀 다양성의 수호자 부재)에서 출발해, 연구 책임자의 아이디어(주기적 자율 씨앗 생성 역할 + 열린 관점 통찰 씨앗)를 계약 언어로 변환하고, packet 목차 전환(연구 책임자 제안), 착수 명세 검토 모델 하향, 소관과 산출 형태를 차례로 확정했다. 골격은 사용자 승인 사항이고 세부는 사용자 지시로 AI가 채웠으며(5절 구분), 이 문서 전체가 사용자 검토 대상이다.
- 대화 로그: 그 대화의 표시 텍스트 전문이 `docs/do-math/상시생성-목차열람-수정안-대화로그.md`에 보존돼 있다. 보존 범위는 대화 시작부터 verify-rounds 검증 지시까지다. 수행 세션의 필독은 0.1절 목록이며 이 로그는 거기 들지 않는다.
- 이 문서의 한계: 인용한 통합-설계 절 번호는 지식층 수정안 반영 전 기준이다(0.1절의 대응 규칙). `PT24H` 기본값은 운용 실측 전의 초기값이며 연구 설정으로 조정한다.
