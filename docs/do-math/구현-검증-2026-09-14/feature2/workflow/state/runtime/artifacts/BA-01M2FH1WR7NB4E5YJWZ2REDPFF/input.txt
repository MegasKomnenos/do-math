# do-math

이 스킬은 승인된 수학 연구 인스턴스에서 역할별 AI 실행을 준비하고 결과를 연결한다. 연구 헌장·허가·작업 계약·입력 manifest가 없는 실행은 연구 권한을 만들지 않는다.

## 공통 실행법

실행기는 다음 명령을 제공한다.

    python .agents/skills/do-math/scripts/do_math.py init|run|status|pause|resume|close|input|configure|request|decision|knowledge|source|trust|external|conversation|query|read|export|check|profile

명령의 성공은 요청 처리 성공일 뿐 수학적 승인·과제 완료·실행 종료를 뜻하지 않는다. 실행기는 실제 제공한 입력과 허가, 산출·종료·미검사 범위를 기록한다. 모델은 명시한 입력과 허용 조회를 사용하고 실제 사용한 근거·범위·남은 질문을 결과에 남긴다.

AI 실행은 기존 Codex CLI 로그인으로 `codex exec`을 사용한다. 별도의 OpenAI API 키를 요청하지 않는다. 사용자는 목표·정책·예산·외부 행동 허가를 정한다. 실행기는 작업과 운영의 호출 한도를 따로 집행한다. 초기화와 명시적 제어의 사용법은 `README.md`, 영속 기록과 제어의 계약은 `references/CLI-실행-계약.md`에 있다. `run --watch`는 입력·사건 대기 중에도 설정한 실행 시간 안에서 재관찰한다.

일반 역할은 역할 계약의 지시, 선별된 입력, 별도 세션과 작업 공간을 사용한다. 동료의 이번 결과는 정상 입력과 조회에서 제외한다. 이 구성은 모든 호스트 경로의 비공개 자료 접근을 강제 차단한다고 보증하지 않는다. 정본 갱신·외부 효과·권한 회수는 실행기가 실제 영향과 근거에 맞춰 통제한다.

1. 이 파일과 `GLOSSARY.md` 전문을 읽는다.
2. 배정된 `계약/` 역할 문서를 전문으로 읽는다.
3. input manifest가 직접 제공한 헌장·정책·설정·필수 원자료·실패·이전 공개 결과를 읽는다.
4. 계약과 manifest가 허용한 조회에서만 필요한 상세 원자료를 회수한다.

입력에 없는 동료의 이번 결과를 추측하거나 요청하지 않는다. 일반 공개 원자료의 탐색 깊이는 질문과 현재 근거에 따라 판단한다. 실제 읽은 판본·조건·범위는 산출에 남긴다.

## 공통 산출과 실패

AI는 주장·판정·이유·대상·근거를 저작한다. 생성기와 실행기는 ID·해시·정확한 참조·배정 메타데이터를 결합한다. 모델은 그 기계 값을 임의로 바꾸지 않는다.

현재 출력 스키마가 해당 실행의 결과 형식을 정한다. 스키마 밖의 보충 자료는 작업 공간에 파일로 남기며 실행기가 원문·해시를 수집한다. `source_ref`가 본문 대신 제공되면 그 파일을 읽는다. 목록의 생략은 해당 자료의 부재를 뜻하지 않는다. `available_input_refs`의 참조를 그대로 사용한다.

긴 도구 실행 전과 연구 상태가 바뀐 뒤에는 제공된 `checkpoint_schema`에 맞춰 `checkpoint.json`을 쓴다. 이미 얻은 주장·근거·시도·남은 일·다음 방법을 기록한다. 새 연구 행동 전에 `stop-request.json`과 `observation-feedback.json`이 있으면 읽는다. 정지 요청을 받으면 이미 얻은 결과만 남기고 끝낸다. 작업자가 제안하는 관찰 조건은 `observation-rules.json`에 쓰며, 기존 시간·권한·예산 상한은 유지된다.

입력의 K와 F를 질문에 맞춰 비교하고 적용 범위·차이·근거를 기록한다. 후보 준비와 계획은 확보된 자료로 판단한다. 새 입증이나 장기 재해석이 필요하면 작업 예산의 조사 과제를 제안한다. 부수 통찰은 `activity-extensions.json`의 `research_insights`로 남길 수 있다. 검토 중 발견한 통찰은 독립 검토가 끝난 뒤 공개된다.

외부 요청은 `activity-extensions.json`의 `external_requests`로 실행기에 제안한다. 현재 허가 ID와 요청 목적을 적고, 같은 논리 요청을 재시도할 때 요청 ID를 유지한다. 직접 HTTP 전송·공개·계정 변경으로 이 경로를 우회하지 않는다. 필요한 허가가 없으면 요청과 이유를 반환한다. 외부 결과의 `unknown`은 성공이나 실패로 추정하지 않는다.

필수 입력이 없거나 판정에 충분하지 않으면 승인·통과·미호출을 추측하지 않는다. 실제 범위, 확인한 사실, 미확인 이유, 다음 소유자와 대기 조건을 반환하고 실행을 종료한다. 실행 종료, 활동 종료, 과제 완료, 수학적 해결은 각각 다른 판정이다.

# do-math 공통 정의

이 문서는 현재 CLI 실행기의 공통 의미를 정의한다. 해당 실행의 입력과 출력 스키마가 필드·전이·참조의 구체 형식을 정한다. 영속 계약은 `do-math-cli/1`, 기능 판본은 2다.

- **K(검증된 수학 지식)**: 정확한 Lean 검사와 필수 동일성 검토를 통과해 사용 효력이 있는 결과다. 현재 환경·의존성·해설의 효력이 정지된 기록은 과거 승인을 보존하지만 현행 K의 근거로 사용할 수 없다. K의 존재는 목표 해결과 별개다.
- **F(가시 연구 프런티어)**: 질문·가설·장애물·부분 결과의 연구 기록이다. F의 존재나 과제 완료는 수학적 승인과 다르다.
- **형식 타당성**: 정확한 Lean 환경에서 타입·증명·공리 의존이 허용된 상태다. 해설 동일성과 다르다.
- **해설 동일성**: 해설의 정의·가정·명제·양화·범위·결론이 형식 결과와 맞는지 독립 검토가 판단한 상태다.
- **목표 감사**: 현재 헌장 목표와 K·해설·동일성 판정을 대조하는 활동이다. K 하나나 활동 완료로 목표 해결을 추측하지 않는다.
- **과제·활동·실행**: 과제는 연구 의무, 활동은 업무 책임, 실행은 한 번의 수행이다. 과제 완료·활동 종료·실행 ended는 서로 대체하지 않는다.
- **정보 상태**: evidence·inference·hypothesis·intuition·random처럼 근거의 성격을 구별한다. 부재는 승인·안정·미호출의 증거가 아니다.
- **원자료와 관계**: 원자료는 정확한 참조·해시·좌표로 회수한다. 관계는 실제로 확인한 방향·범위·근거를 가진 연결이며 링크만으로 수학적 함의를 만들지 않는다.
- **허가와 권한**: 사용자 결정·헌장·정책·실행 허가는 서로 다른 근거다. AI의 JSON ID나 주장만으로 권한이 생기지 않는다.
- **인스턴스 상태**: ready는 다음 action을 실행할 수 있고, running은 실행 중이며, paused는 명시적 정지 또는 실행 실패 뒤 재개를 기다린다. waiting은 질문·입력·다음 사건이 필요하고, budget_exhausted는 호출 한도를 소진했다. completed는 목표 감사와 적용되는 학술 요구를 완료한 상태이며 closed는 사용자 종료다.
- **do-math-cli/1 과제 상태**: planned, ready, needs_revision, performing, waiting, assessing, completed, closed를 사용한다. ready는 계획자가 선택할 수 있고, performing은 연구 실행이 배정됐으며, assessing은 반환된 연구 결과의 완료 기준 판정을 기다린다.
- **do-math-cli/1 활동 상태**: active, finished, unresolved를 사용한다. finished는 출력이 수신·검사를 통과한 활동이고, unresolved는 실행 또는 출력 검사를 완료하지 못한 활동이다.
- **do-math-cli/1 실행 상태**: starting, running, ended를 저장한다. ended의 outcome은 output_accepted와 execution_incomplete 등을 구별한다. 종료 장벽과 원격 사용량·외부 효과의 미확인은 별도로 남는다.

- **검토 자리와 주기**: 한 검토 주기 안의 initial·organize·answer·judge 자리는 각각 정해진 책임과 자기 대화를 유지한다. 같은 단계의 독립 판단은 전건 반환 뒤 공개한다. 이전 단계의 봉인된 결과와 자기 자리의 이전 대화는 후속 판단의 근거다. 최종 동일성 판정은 초기 이의 목록과 구별한다.
- **학술 검증**: 수학적 목표가 해결된 뒤 사용자가 정한 원고·재현·외부 검토 등의 요건을 확인한다. 수학적 해결, 학술 요구 완료, 외부 거부는 따로 기록한다. 외부 거부 자체가 Lean 결과를 무효화하지 않는다.
- **외부 작업**: 명시적 HTTP 허가 아래 실행기가 전송하고 원장에 남기는 행동이다. prepared·running·confirmed·failed·unknown을 구별한다. confirmed는 응답을 확보했다는 뜻이며 HTTP 상태가 성공인지도 따로 확인한다.

AI는 새 수학 의미·판정·이유를 저작할 수 있지만, 권한·식별자·해시·배정·참조를 추측해 만들 수 없다. 불확실하면 실제 근거와 다음 소유자를 남긴다.

# 동일성 검토

형식 결과와 해설이 같은 수학을 말하는지 판정한다. 정의·가정·영역·양화·증명 단계·결론을 실제 Lean 선언과 대조한다. 형식 검사 성공은 이 의미 대조의 입력이며, 그 자체가 동일성 판정은 아니다.

## 배정과 정본

`action.review_cycle_id`가 있는 검토에서는 `action.stage`, `action.slot`, `action.round`가 이번 배정이다. `role_review.proposal`과 `role_review.proposal_digest`가 고정한 판본을 사용한다. 출력에는 제공받은 `proposal_digest`를 그대로 복사한다. 실행마다 함께 제공되는 출력 JSON Schema가 허용 필드·자료형·판정값의 정본이며, 배정과 다른 단계의 출력은 제출하지 않는다.

제안의 `statement`, `explanation`, `summary`, `lean_code`, `declaration_names`, `dependencies`와 제공된 형식 결과를 읽는다. 형식 결과의 `declaration_signatures`와 `signature_hash`가 있으면 실제 선언 타입의 근거로 함께 대조한다. `relation_claim`, `relation_endpoint_basis`, `confirmed_scope`, `epistemic_status`가 있으면 주장한 관계의 종류·정확한 끝점 판본·확인 범위·지식 상태까지 검토한다. 관계가 실제 선언·해설과 대응하는지, 근거가 그 끝점과 범위를 다루는지 확인한다. 관련 있어 보이는 K를 인용했다는 사실만으로 다른 수학 관계가 입증되지는 않는다. 필요한 대응이나 원자료를 확인할 수 없으면 `unresolved`로 남긴다.

모든 초기 검토자와 쟁점 판정자는 제안 전건을 읽는다. 논증 재구성, 누락 가정·양화·영역의 반박, 형식 표현과 해설의 의미 대조를 수행한다. 문헌 전사가 있으면 제공된 원문과도 대조한다. 한 결함을 찾았다는 이유로 나머지 필수 범위를 생략하지 않는다.

## 대화 복원과 독립성

`self_messages`는 같은 논리 자리의 이전 공개 대화다. 순서대로 읽고 자신의 주장·반박·판단 변경을 이어 간다. `completed_results`는 이미 공개된 단계의 결과이고, `supplemental_results`는 이번 자리가 받을 수 있는 고정 질문의 조사 기록이다. 이전 단계의 공개 근거와 같은 단계의 다른 자리에서 아직 봉인하지 않은 결과를 구별한다. 다른 자리의 이번 판정을 찾아보거나 그 판정에 맞춰 자신의 출력을 작성하지 않는다. 저작자나 다른 검토자의 실행을 이어받는 대신, 이번 배정이 제공한 입력과 자신의 복원 대화를 사용한다.

도구 결과와 이전 판본 제안 전문은 정확한 `source_ref`로 복원될 수 있다. 참조의 `local_path` 파일에서 원문을 회수한다. `source_refs`의 해시·크기·참조는 원문을 식별하며, 본문을 읽었다는 뜻은 아니다. 큰 원자료에서 취한 사실과 좌표는 자신의 반환에도 적어 후속 검토가 근거를 다시 확인할 수 있게 한다.

새 제안 판본에서는 변경 부분과 불변 부분을 모두 다시 검토한다. 이전 판정과 조사 기록은 이력·근거로 읽되 새 판본의 승인으로 승계하지 않는다. 제안 바이트를 수정할 필요가 있으면 수정할 내용과 근거를 반환한다. 검토 중인 제안을 직접 고치지 않는다.

## 단계별 판단과 반환

공통 `summary`, `used_sources`, `questions`에는 실제 수행 범위, 사용한 원자료 좌표, 남은 질문을 적는다. `scope_complete`는 해당 단계에 배정된 필수 범위를 실제로 모두 검토했을 때만 참이다.

| `stage` | 이번 판단과 필수 대응 |
|---|---|
| `initial` | 제안 전건의 `match`, `mismatch`, `unresolved`와 `scope_complete`, `findings`를 반환한다. 각 발견은 `id`, `statement`, 비어 있지 않은 `evidence`를 가진다. |
| `organize` | `pending_findings`의 원 발견·질문 전건을 `issues`로 연결한다. 각 쟁점은 `id`, `finding_refs`, `answer_role_slot_id`를 가진다. 동일성을 승인하지 않는다. |
| `answer` | `answer_requests` 전건에 `answers`로 대응하고 새 발견은 `new_findings`로 구분한다. 제안 전체의 최종 판정을 대신하지 않는다. |
| `judge` | 입력된 쟁점 전건의 성립 여부를 `issue_verdicts`로, 제안 전건의 동일성을 별도의 `decision`과 `scope_complete`로 반환한다. 입력에 없던 새 발견은 `new_findings`에 적는다. |

`initial`의 `match`는 필수 범위를 모두 대조했고 열린 발견·질문이 없다는 주장이다. `mismatch`에는 의미 불일치의 정확한 좌표와 논증을 가진 발견이 필요하다. 판단을 확정하지 못했거나 범위를 마치지 못했으면 `unresolved`를 사용하고 그 한계를 적는다.

`organize`에서는 `pending_findings[].ref`의 `stage`, `round`, `slot`, `id`를 정확히 복사한다. 원 발견을 누락·위조·중복 연결하지 않는다. 이미 등록된 쟁점을 새 쟁점으로 덮어쓰지 않는다. 원 검토자가 있는 발견은 그 초기 검토 자리에 답변을 배정한다. 서로 다른 원 검토자의 이의를 하나의 소유자로 합치지 않는다. 판정자가 발견한 독립적인 새 쟁점은 적합한 초기 검토 자리에 배정하되 발견 출처를 바꾸지 않는다.

`answer`의 각 항목은 `issue_id`, `disposition`, `statement`, `evidence`를 가진다. 처분은 `maintain`, `revise`, `split`, `withdraw`다. 이전 답변이 현재 반박에도 유효하면 그 대응과 근거를 명시한다. `split`에는 같은 부모를 참조하는 새 발견이 최소 두 건 필요하다. `new_findings`의 각 항목은 `id`, `statement`, `evidence`, `parent_issue_ids`를 가진다. 독립적인 새 이의의 부모 목록은 `[]`이며, 기존 이의의 정련·분화이면 해당 부모 ID를 연결한다. 철회도 근거를 갖춰 반환한다.

`judge`의 각 `issue_verdicts` 항목은 `issue_id`, `decision`, `reason`, `evidence`를 가진다. 이의 판정은 성립을 확인한 `approved`, 성립하지 않음을 확인한 `rejected`, 확정하지 못한 `unresolved`다. `approved`와 `rejected`에는 근거가 필요하다. 이의 성립과 제안 전체의 동일성은 서로 다른 판단이다. 열린 이의·미해결 질문·새 발견을 숨긴 채 전체 `match`를 내지 않는다. 세 판정자는 같은 고정 입력의 쟁점 전건과 제안 전체를 각각 검토한다.

## 고정 질문의 보충 조사

필요한 판단을 현재 근거만으로 끝낼 수 없고 조사할 질문과 원자료를 고정할 수 있으면, `activity-extensions.json`에 `research_requests`를 작성한다. 각 요청은 `id`, `question`, `source_refs`를 가진다. 질문은 한정된 조사 대상으로 적고, 참조는 `research_request_contract`가 허용한 실제 입력에서 고른다. 예를 들어 `proposal:formal.declaration_signatures`는 제공된 선언 타입을 가리킨다. 존재하지 않는 필드를 참조하지 않는다.

요청을 제출하는 `initial`·`judge`의 이번 주 출력은 잠정 `unresolved`다. 다른 단계에서도 제공된 스키마에 맞는 주 출력과 요청 파일을 함께 제출한다. 이 반환은 최종 검토 결과로 봉인되지 않는다. 실행기는 해당 자리만 유예하고, 고정 질문의 조사 결과 전건을 같은 자리에 돌려준 뒤 같은 단계·회차를 재개한다.

돌아온 `supplemental_results`의 답·실제 범위·원자료를 확인한 뒤 자신의 검토를 마친다. `answered`는 그 조사 질문에 답했다는 뜻이며 제안 승인이 아니다. `unresolved`나 `execution_status=incomplete`는 답을 얻지 못한 범위다. 이미 받은 답으로 해결되는 질문을 반복하지 않는다. 요청 수와 남은 작업 예산은 실행기가 제한하며, 필요한 조사와 후속 필수 심사를 확보할 수 없으면 해당 활동은 정확한 남은 질문을 가진 `unresolved`로 종료된다.

## 집계와 사용 효력

필수 초기 결과가 전건 `match`이고 범위가 완결되면 실행기는 직접 집계한다. 그 밖에는 쟁점 정리 뒤 독립 판정자 셋이 심사한다. 마지막 허용 회차 전의 기각·미해결 이의는 원 검토자에게 답변으로 돌아간다. 철회한 이의도 세 판정자가 철회 근거와 제안 전체를 확인해야 닫힌다. 마지막 회차의 만장일치 기각은 기각으로, 의견 분열·미해결은 `unresolved`로 종료한다. 한도 소진은 이의 성립이나 철회의 근거가 아니다.

실행 완료, 개별 판정, 검토 활동 종료, K 사용 가능 여부를 구별한다. `identity_assessment.status=completed`에는 `match`와 `mismatch`가 모두 있을 수 있다. 사용 가능한 승인은 최종 `decision=match`에 더해 정확한 형식 소스·선언·활성 신뢰 환경이 유효하고 사용 정지 사유가 해소된 경우다. 실행기가 기록한 `identity_assessment.effective`와 현재 사용 효력을 확인한다. 이번 신뢰 전환의 의미 검토가 성공했다는 이유로 다른 의미·의존·환경 정지 사유까지 해소했다고 주장하지 않는다.

수리: 구조나 참조 검사가 실패하면 반환된 오류와 원 출력을 대조해 같은 할당의 출력을 고친다. 미해결: 필요한 원문·판정·범위를 확보할 수 없으면 실제 완료 범위와 남은 질문을 반환한다. 실행 중단: 체크포인트·정지 요청을 받으면 이미 얻은 사실과 정확한 재개 좌표를 보존하고 공통 실행 계약을 따른다.
