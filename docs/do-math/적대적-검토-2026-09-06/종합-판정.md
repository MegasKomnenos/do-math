# 일곱 렌즈 적대적 검토의 종합 판정

작성일: 2026-09-06

## 1. 판정 범위와 결과

사용자가 지정한 일곱 렌즈를 각각 gpt-5.6-sol xhigh에 맡겼다. 동시 슬롯 안에서 나누어 파견했고, 다른 렌즈의 결과를 보지 않은 최초 보고서 일곱 개를 받았다. 여섯 보고서는 지적·제안을 냈고 충실성 렌즈는 PASS를 냈다.

주 에이전트는 보고서 전부를 읽고 각 지적의 근거를 기준 초안·기존 설계·대화와 대조했다. 기술 사실은 로컬 명령과 공식 문서를 별도로 확인했다. 반환의 수나 일치율을 사실의 증거로 사용하지 않았다.

기준 초안은 99,166바이트, 1,032행, SHA-256 `98de2c15e1e17a4b3422d01a22a5be6da0b1a7bbf2663605f5639eda7cc7a2f8`이다. [기준 사본](기준-초안.md)은 원본과 같은 바이트·해시로 보존했다. 최초 렌즈 보고서의 행 번호와 아래 표의 원문 근거는 이 사본을 가리킨다. 개정된 [현재 초안](재검토-기준-초안.md)의 행 번호로 소급해서 읽지 않는다.

최초 발견 ID는 51개다. 같은 원인을 여러 렌즈가 지적한 경우를 포함하므로 서로 다른 결함 51개라는 뜻은 아니다. 최초 판정은 채택 29개, 부분 채택 19개, 반박 2개, 보류 1개다. 추가 대조의 11개까지 합치면 총 62개 주장에 채택 38개, 부분 채택 21개, 반박 2개, 보류 1개로 판정했다. 추가 근거와 마지막 수정은 6절에 정리한다.

- 채택: 원문으로 지적·구조 제안의 타당성을 확인해 초안에 반영했다. 실제 구현을 시험했다는 뜻은 아니다.
- 부분 채택: 성립 범위만 반영하거나 제안과 다른 해결책을 택했다. 경험 가설은 검증 과제로만 반영한다.
- 반박: 핵심 논증의 전제가 성립하지 않는다. 관련 설명 개선과 그 지적의 채택은 구분한다.
- 보류: 관찰한 절충은 인정하지만 현재 목적·근거로 제안한 변경을 적용하지 않는다.

## 2. 무엇을 바꾸고 무엇을 유지했는가

연구 상태와 실행 상태는 유지하되 권위 있는 Git 머리를 하나로 합쳤다. 단일 작성자와 broker 조회라는 범위에서 별도 가변 머리의 동기화가 주는 필수 이익을 찾지 못했다. 두 subtree의 구분은 보존하고 한 상태 커밋으로 공개하므로 교차-ref 불일치라는 실패 조합이 사라진다.

모든 실행의 소유 activity, 조건부 요청 필드, 종료·후속의 원자 단위, 계약 개정 권한, 외부 행동의 호출 전 취소와 미확인 복구를 명시했다. 누적 허가와 시간창·호스트 제약을 동시 슬롯과 구분하고, 통상 운영 큐는 먼저 기다린 계획을 새 점검이 계속 추월하지 못하게 했다.

보충 조사 깊이를 1로 고정하는 규칙은 전체 활동 예산 안의 적응적 조사로 바꿨다. 정확한 범위·의존이 봉인된 검토는 불변 부분에 한해 승계할 수 있게 했다. 미조사·미해결을 승인으로 바꾸지는 않는다.

운영·작업 예산의 자동 차용 금지, Lean 형식 타당성·해설 동일성·목표 감사의 구분, 개별 검토 결과를 주장으로 읽는 원칙은 유지했다. 실제 어댑터와 규범 스키마가 아직 검증·작성되지 않았다는 한계도 유지했다.

## 4. 그대로 적용하지 않은 중요한 논증

### 불일치 주장과 입증된 반례

L6-04와 L7-02의 예시는 한 판정자의 반례가 옳고 다른 판정자가 놓쳤다는 전제를 넣는다. 그 전제가 실제로 확인됐다면 반례 하나로 충분하다. 그러나 시스템이 가진 입력이 서로 충돌하는 검토 주장이라면 그 유효성을 먼저 확인해야 한다. 개별 mismatch 정의는 판정자가 어떤 주장을 내는지 정하며, 그 판정자를 무오류로 만들지 않는다.

따라서 mixed 판정의 unresolved는 논리 모순이 아니다. 단독 표를 사실로 승격하는 집계 변경은 하지 않았다. 다만 구체적인 불일치와 반박이 일반적 불확실성 속에서 사라지지 않게 기록·후속 입력을 명시했고, 총예산 안의 추가 조사로 다룰 수 있게 했다.

### 운영 용량 차용

L7-06의 유휴 용량 손실은 실제 절충이다. 그러나 burst 종류·대여 조건·취소 보장·회수 시점을 더하는 것은 사용자가 선택한 간단한 예산 분리와 다른 구조다. 현행 초안에서는 비차용을 유지한다. 실제 이득과 필수 운영 응답이 입증되지 않은 최적화를 먼저 넣지 않는다.

### 모든 트리 참조에 해시 추가

L1-05는 판정 입력의 재결박 위험을 정확히 짚었다. 제안된 전역 해시 추가는 순환 구조의 해시 고정점과 무관한 연결 갱신을 만들 수 있다. 구조 참조와 봉인된 판정 입력의 소비자가 다르므로, 후자에만 정확한 immutable 참조를 요구하는 안을 택했다.

### 비형식 최종 보증과 효능 승인 관문

L6-03·L7-01의 더 넓은 제품 방향은 선택할 수 있는 확장이다. 현재의 Lean 기반 수학적 해결을 의도에서 벗어난 결함으로 판정하지 않았다. 비형식 과제의 계약 완료는 보존하며 최상위 보증 경로를 새로 열지는 않았다. 연구 효능 비교는 구체화했지만 모든 연구 시작에 새 사용자 승인 관문을 추가하지 않았다.

## 5. 기술 사실의 직접 확인

주 에이전트가 직접 확인한 로컬 결과는 Codex CLI 0.153.4, Git 2.50.0.windows.2와 App Server help의 존재다. 현재 PATH에서 lean·lake·do-math는 발견되지 않았다. 이를 호스트 어디에도 설치돼 있지 않다는 주장으로 확대하지 않는다.

공식 원천은 2026-09-06에 다시 대조했다.

- [Background mode](https://developers.openai.com/api/docs/guides/background)와 [Data controls](https://developers.openai.com/api/docs/guides/your-data)는 저장 모드에 따른 유한 보존 기간을 설명한다. 조회·취소 API의 존재만으로 임의의 복구 공백에서 종료 증거를 다시 얻는다고 보장할 수 없다.
- [Codex App Server](https://learn.chatgpt.com/docs/app-server)는 turn 시작·중단·최종 상태를 구분한다. 저장 thread의 재개와 소실한 공급자 요청의 재부착은 같은 보장이 아니다. 구독 해제 뒤 무활동 만료도 사용자 대화 소실과 다르다.
- [Rate limits](https://developers.openai.com/api/docs/guides/rate-limits)는 요청·토큰의 시간창 한도와 공유 한도를 설명한다. 로컬 슬롯 수를 실제 공급자 동시성으로 표기하지 않는다.
- [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)와 [Restricted Tokens](https://learn.microsoft.com/en-us/windows/win32/secauthz/restricted-tokens)는 프로세스 수명 관리와 접근 제한의 역할을 구분한다. Job 편입만으로 네트워크·파일·비밀이 격리된다고 결론 내리지 않는다.
- [Reparse Points](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-points)와 [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)를 대조해 논리 경로와 실제 파일·잠금의 정체성을 구분했다.
- [git-update-ref](https://git-scm.com/docs/git-update-ref.html)의 조건부 ref 갱신은 사용할 수 있는 기반이다. 여러 ref의 갱신이 가능하다는 사실이 현재 설계에 여러 가변 권위 ref가 필요하다는 이유는 아니다.

로컬 모델 실행·sandbox 설정·실제 원격 취소·Lean 빌드는 수행하지 않았다. 플랫폼 지원 여부와 성능은 초안의 명시된 능력 검사·실험 과제로 남는다.

### 추가 수정의 핵심 판단

동시 편입의 문제는 Git 부모가 최신인지와 실제 파일 내용이 최신인지가 다르다는 데 있다. A가 오래 검사하는 동안 B가 먼저 편입되면, A는 최신 research에 자기 변경분만 적용해야 한다. 그 결과 달라지는 참조·파생 보기·검사 입력을 다시 확인한다. 긴 검사 내내 다른 연구 공개를 막는 전역 잠금은 택하지 않았다.

원격 조회 불능은 확인되지 않은 자원을 돌려줄 이유가 아니다. 그러나 로컬 프로세스와 새 행동 통로가 이미 닫혔는데도 과제 철회·이전까지 영구히 막을 이유도 아니다. 그래서 실행 종료 기록은 연구 행동의 종료를, 별도 공급자 호출·예약 기록은 남아 있는 자원 사실을 소유하게 했다. 초기 원격 모델은 추론만 하고 도구·외부 행동은 로컬의 권한 검사 경로를 거친다. 원격 도구가 독립적으로 새 효과를 낼 수 있는 배치에는 이 논리를 적용하지 않고 실제 종료 장벽을 요구한다.

이 분리는 운영 용량의 차용이나 미확인 예약의 탕감이 아니다. 각 공급자 호출은 여전히 원래 작업·운영 예산을 소비하고, 알 수 없는 종료·사용량은 그대로 남는다. 불확실성이 차단해야 하는 대상을 해당 자원으로 좁힌 것이다.

프로필도 비슷한 방식으로 정리했다. 과제 요구, 모델 프로필, 도구 프로필 사이의 별도 적합성 절차를 더하지 않고 정확한 실행 프로필 참조 하나로 통일했다. 남은 범위는 불변 계약에서 진행 상태로 옮겼으며, 순차 검토 때문에 실행마다 새 활동을 만드는 대신 기존 활동의 실행 집합을 사용했다. simplify의 문제 발생 구조를 줄이는 원칙과 write-for-reader의 소비자가 추측하지 않아도 되는 계약 표현을 적용한 결과다.

추가 충실성 PASS는 2차 초안에 대한 해당 렌즈의 판정이다. 마지막 3차 수정까지 외부 검토자가 통과시켰다는 뜻으로 확대하지 않는다. 주 에이전트는 마지막 변경에서도 예산 비차용, 정확한 권한·판정 입력, 부분 결과 보존과 형식·동일성·목표의 구분이 유지되는지 직접 대조했다.

### 문서 검증

최종 초안은 141,354바이트·1,258행이고 SHA-256은 `850d2f62d42f4111eeb2f5df23c3bd381ccd01a11a28f3bfdeb159b2fd992168`이다. 다음은 문서에 수행한 검사다.

- 초안의 0~18절과 명시 anchor 19개는 중복·누락이 없다. 최종 초안과 이 판정문의 표 열 수·코드 울타리·제목 및 목록 앞뒤의 빈 줄·후행 공백 검사에서 오류가 없었다.
- 검증 시나리오 V01~V77의 번호가 연속이고 중복이 없다. 이는 기대값을 작성·대조했다는 뜻이지 런타임에서 77개를 실행해 통과했다는 뜻이 아니다.
- 최종 초안과 판정문이 연결하는 로컬 파일 대상 15개가 모두 존재하며, 두 문서의 명시 anchor 링크가 정확한 대상 판본에 연결된다.
- 최초 51개·추가 11개의 발견 ID 62개가 판정표에 한 번씩 있다. 렌즈 2의 두 PASS는 결함 개수에 섞지 않았다.
- 동시 A/B 편입, 활동의 순차 실행, unknown 뒤 미호출 취소, 분기별 시작 예약, 원격 미정산 뒤 논리적 종료의 시간선을 본문의 전이·소유권·검증 기대값과 대조했다. 실운전 시험으로 간주하지 않았다.
- 기존 `통합-설계.md`는 339,911바이트와 SHA-256 `782b2c8338372e45a61a2a5192fee6869a3874ab44a8ff9be0b1aee09abee872`가 그대로다. 두 검토 기준 사본도 위에서 명시한 원본 해시와 일치한다. 정본을 교체하거나 커밋하지 않았다.

판정 원문은 수정된 초안에 맞춰 소급 고치지 않았다. 최초 보고서는 최초 사본을, 추가 보고서는 2차 사본을 근거로 읽는다. 이후의 반박·한정·적용은 이 판정문이 소유한다.

## 7. 남은 한계

원격 실행의 보존·종료·사용량과 격리는 실제 어댑터 시험 전에는 확정할 수 없다. 규범 JSON Schema·wire 계약·codec vectors도 아직 실제 파일로 완성되지 않았다. 큰 수학 제안의 경계 검토, 검토 구성의 실효성, 기록 중심 맥락 승계와 검색 품질은 대표 문제로 검증해야 한다.

이번 산출물은 일곱 렌즈의 주장, 원문에 대한 재판정, 수정된 구조·행동 계약이다. 이 과정을 실제 런타임·수학적 연구 효능의 검증 완료로 표현하지 않는다.
