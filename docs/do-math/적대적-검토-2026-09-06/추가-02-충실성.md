# 추가 렌즈 02 — 개정판 충실성 재검증

## 처분

개정된 초안을 이전 보고서의 결론과 독립적으로 전문 대조했다. 지정된 변경은 대화에서 제시된 재설계 목적이나 기존 자산에서 보존하려 한 권한·신뢰·기능을 약화하지 않는다. 단일 상태 ref와 공통 activity는 상태 종류를 합친 것이 아니라 공개·소유권 구조를 단순화했다. 적응형 보충과 판정 범위 승계는 유한한 총예산, 정확한 입력 결박, 독립성, 미해결 처분을 유지한다. 비차용 예산과 Lean 기반 목표 경계도 명시적으로 남아 있다.

발췌의 사용자 발언과 조력자 제안을 구분했다. 사용자의 오버뷰 긍정(`대화-근거-발췌.md` 95–97행)을 모든 세부 수단의 명시적 승인으로 확대하지 않았고, 발췌 밖의 합의를 창작하지 않았다.

## 중요 변경의 충실성

### 단일 상태 ref

기존 자산은 공용 연구 머리와 controller·supervisor·run 등 실행 ref를 분리했다(`통합-설계.md` 76–99행). 이 수단의 보존 목적은 연구 의미와 실행 상태를 섞지 않으면서 동시성·복구·원자성을 지키는 것이었다. 개정판은 하나의 가변 ref가 research와 runtime 하위 트리를 함께 공개하고, 두 트리의 소유 내용은 계속 분리한다(`통합-설계-초안.md` 402–439행). runtime만 바뀌면 research 하위 트리 OID가 유지되고, 한 상태 커밋이 같은 변경의 기록을 함께 보이게 한다(410–412행).

판정·허가·검토 입력은 상태 커밋과 파일 해시 또는 불변 artifact에 결박하며 `tree_record_ref`를 금지한다(441–455행). 편입은 최신 runtime을 보존한 후보 상태 커밋 하나와 단일 조건부 ref 갱신으로 공개한다(613–626행). 따라서 연구 판단과 실행 판단의 의미를 합치지 않고, 두 가변 머리 사이의 부분 조합 가능성만 제거했다. 기존 수단 변경은 충실성 결함이 아니다.

### 공통 activity

개정판은 과제와 실행 사이에 모든 업무의 영속 소유자인 `activity`를 둔다. 모든 실행은 `owner_activity_id` 하나를 갖고, 활동은 입력·단계·실행·결과·미결 사항·후속을 소유한다(`통합-설계-초안.md` 143–163행). 결과·후속·실행 종료·예약 반환도 한 상태 공개로 기록한다(163행). 공통 실행 요청은 AI 작업, AI 운영, 기계 작업의 필수·금지 필드를 분기하고 같은 실행 생명주기를 유지한다(305–346행).

이는 조력자가 제안한 “수학적 판정은 역할별 산출물이, 실행 생명주기는 공통 계약이 소유”한다는 구분(`대화-근거-발췌.md` 53–55행)을 직접 구현한다. `activity_kind`별 결과 어휘가 남아 있으므로 동일성·목표·운영 판정을 하나의 일반 결과값으로 평탄화하지 않는다. 과제 완료도 실행 종료와 계속 분리돼 있다(`통합-설계-초안.md` 270–302행).

### 총예산 안의 적응형 보충

조력자의 인증 제안은 동일성 확인, 구체적 불일치, 미해결을 구분하고, 미해결이면 남은 연구를 환류하며, 구조 단순화를 이유로 독립 검토 강도를 낮추지 않는 것이었다(`대화-근거-발췌.md` 65–75행). 개정판 검토 방침의 `execution_limit`은 범위 계획·초기 검토·보충·최종 판정·재시도를 합친 활동 전체 상한이다(`통합-설계-초안.md` 672–685행). 필수 관점과 최종 판정자는 양수이고, 전체 상한은 필수 단계를 수행할 수 있어야 한다.

보충 질문은 앞 답에 적응해 이어질 수 있지만 최종 필수 판정의 몫을 먼저 남긴다. 조사·질문 정리·재시도와 자식 activity도 같은 한도에서 차감한다(695–712행). 예산이 부족하면 `unresolved`로 끝내고 실제 완료 범위와 쟁점을 반환한다. 이 구조는 기존 설계의 판본·이의 회차 상한과 피드백 루프(`통합-설계.md` 2,082–2,110행)를 그대로 복제하지 않지만, 유한성과 후속 질문의 정보 가치를 함께 보존한다. 한도 도달을 승인이나 불일치로 바꾸지 않으므로 신뢰 강도를 낮추지 않는다(`통합-설계-초안.md` 714–734행).

### 보존할 검토 결과의 범위 승계

기존 자산은 새 제안 판본마다 새 판정을 받고 이전 판정은 경위 입력으로만 쓰게 했다(`통합-설계.md` 2,104–2,110행). 개정판은 이 수단을 부분 승계로 바꿨지만, 승계 대상을 “이전 검토 결과” 전체로 열지 않았다. 판정이 읽은 수학 항목·정의·가정·의존·검토 방침을 `scope_manifest`에 해시로 고정한 경우만 후보가 된다(`통합-설계-초안.md` 706–708행). 새 범위 계획은 변경 항목, 역의존과 전체 연결 할당을 다시 검토하고, 입력·전제가 같은 불변 할당만 정확한 이전 판정 참조로 승계한다. 전체 해설 해시 하나만 가진 판정은 국소 승계할 수 없고, 새 제안의 전체 연결 판정은 다시 수행한다.

반복 쟁점도 현재 주장·살아 있는 반박·처분·원자료를 `issue_state`에 보존하며, 새 요약은 독립 대조가 범위·가정 보존을 확인해야 한다(`통합-설계-초안.md` 537–547행). 이 변경은 “실행이 끊겨도 원자료와 성과를 잃지 않고 이어간다”는 보존 목적(`대화-근거-발췌.md` 21–28행)을 강화하면서, 바뀐 의미에 낡은 판정을 적용하는 길을 닫는다. V48·V54·V62가 누락, 가변 입력과 잘못된 국소 승계를 별도로 시험한다(`통합-설계-초안.md` 1,142행, 1,148행, 1,156행).

### 비차용 예산

사용자는 복잡한 사후 운영 예산 확보보다 작업 예산과 운영 예산의 구조적 분리를 제안했다(`대화-근거-발췌.md` 5–15행). 개정판은 실제 공유 공급 제약마다 작업·운영·총 슬롯을 함께 기록하고 전건에서 원자 예약한다(`통합-설계-초안.md` 184–200행). 작업 실행은 작업 예산만, 운영 실행은 운영 예산만 쓰고 자동 차용과 유휴 운영 용량의 작업 사용을 금지한다(201–202행). 예산 재배치는 별도 승인 변경이다.

누적 허가량·시간창·호스트 한계는 동시성 슬롯과 섞지 않고 별도 예약으로 다루며, 미정산 사용량을 실행 종료로 없애지 않는다(228–238행). 이는 비차용 보장을 약화하지 않고 실제 공급 제약의 범위를 더 정확히 한정한다.

### Lean 기반 목표 경계

조력자가 회수한 목적은 Lean 형식 타당성, 해설 의미와 연구 목표 충족을 각각 확인하는 것이다(`대화-근거-발췌.md` 21–28행). 개정판은 `mathematically_solved`를 Lean 형식 결과·동일성·목표 감사가 모두 갖춰진 해결로 명시하고, 비형식 연구 과제의 계약상 완료가 그 상태를 대신하지 못하게 한다(`통합-설계-초안.md` 54–72행). 동일성 `match` 뒤에도 최종 형식 검사와 공용 편입을 요구하고(736–742행), 목표 감사 전건이 현재 판본에서 `satisfied`일 때만 해결 상태를 바꾼다(744–750행).

정확한 조건부·부분 결과는 목표 미해결이어도 K에 남고, 신뢰 환경 결함은 실제 의존 범위의 사용을 정지한다(736–766행, 936–960행). 이는 기존 자산의 Lean 정본·동일성·목표 감사 분리 목적(`통합-설계.md` 56–68행, 1,946–1,950행, 2,136–2,150행)을 유지한다.

## 함께 다시 확인한 권한·복구 보장

- 단일 실행기는 유일한 상태 작성자이지만 수학 판정이나 AI 산출 문면을 대신 저작하지 않는다(`통합-설계-초안.md` 109–124행).
- 대화 소실 정책은 사용자 승인값이고, 연결 어댑터가 실제 사건을 제공하지 못하면 `pause`를 지원한다고 선언하지 않는다(165–173행).
- 연구·운영 예산의 활동은 역할 책임에 따라 분리되고, 운영 추가 수학 조사는 작업 예산 활동으로 넘긴 뒤 운영 실행을 끝낸다(126–141행, 771–802행).
- 정확히 승인된 변경과 새 의미 해석을 구분하고, 유사 사례는 새 권한을 만들지 않는다(823–841행).
- 사용자 결정이나 다른 AI를 기다리는 동안 실행·예산을 붙잡지 않는다(83–104행, 204–214행).
- 복구는 단일 상태 사슬, 실제 로컬·원격 실행, 예약·외부 행동·불변 묶음을 대조하고 확인 불가능한 사실을 추측하지 않는다(877–934행).

## 검증을 통과한 중요한 부분

- 단일 ref는 research와 runtime의 의미 경계를 유지하면서 원자 공개 단위를 하나로 줄였다.
- 공통 activity는 모든 실행의 결과·대기·후속 소유자를 닫고 역할별 판정 어휘를 보존했다.
- 적응형 보충은 하나의 총실행 상한을 우회하지 않으며 필수 최종 판정 몫과 미해결 출구를 남긴다.
- 판정 승계는 해시로 고정한 불변 범위에 한정되고 변경·역의존·전체 연결은 다시 검토한다.
- 작업·운영 예산 사이 자동 차용 금지는 그대로다.
- 비형식 과제 완료는 Lean 기반 `mathematically_solved`를 대신하지 않는다.

## 남은 불확실성과 읽지 않은 범위

- 발췌 밖 전체 대화는 읽지 않았다. 그 범위의 추가 합의는 미확인이고 주 에이전트가 전체 대화에서 대조해야 한다.
- 다른 렌즈 보고서, 종합 판정, 최초 초안 검토 기록, 기억과 루트 `CONTEXT.md`는 읽지 않았다.
- 초안 D04·D05·D07·D08의 실제 검토 총예산 효능, 큰 제안 분할, 판정 승계의 실효성, 규범 스키마·wire 계약 완결성은 아직 실증되지 않았다(`통합-설계-초안.md` 1,188–1,204행). 문서는 이를 방침 채택·지원 선언·구현 전의 관문으로 남기므로, 이번 문면 충실성 검토에서는 구현 완료 사실로 취급하지 않았다.
- 보편 도메인 정본과 K·F·U 의미의 일치는 D06으로 남아 있고 이번 읽기 권한 밖이다. 따라서 그 일치를 검증했다고 주장하지 않는다.
