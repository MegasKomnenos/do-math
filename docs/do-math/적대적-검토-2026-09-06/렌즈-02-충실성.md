# 렌즈 02 — 충실성 검토

## 처분

지정된 세 원천을 전문 대조한 범위에서는 새 초안이 대화에서 확정된 재설계 방향과 기존 설계에서 보존하려 한 목적·신뢰 보장을 벗어났다고 입증할 지점이 없다. 새 초안은 기존의 씨앗 생성 세션, 다중 runtime ref, 관찰 조건 세대, 이의 피드백 루프 같은 수단을 그대로 보존하지 않았다. 대신 예산 분리, 단일 실행기, 불변 산출 묶음, 판본화된 검토 방침과 유한한 검토 활동으로 같은 목적을 다시 닫았다. 이 수단 변경 자체를 불충실로 판정하지 않았다.

이 처분은 발췌 밖의 대화에 합의가 없었다는 뜻이 아니다. 사용자 발언과 조력자 제안을 구분해 대조했고, 사용자의 오버뷰 긍정(`대화-근거-발췌.md` 95–97행)을 조력자 제안의 모든 세부 선택에 대한 명시적 승인으로 확대하지 않았다.

## 충실성 대조

### 목적과 서로 대신하지 않는 판단

조력자가 회수한 목적은 충분한 자료·도구를 이용한 연구, 탐색과 집중 활용의 환류, 정보 상태의 구별, Lean 형식 타당성·해설 의미·목표 충족의 분리, 중단 뒤 재개, 사용자 권한 안의 자율 운전이다(`대화-근거-발췌.md` 19–30행). 기존 설계도 이를 문서 목적과 연구 철학으로 명시했다(`통합-설계.md` 5–9행, 56–68행).

새 초안은 탐색·집중 활용과 결과 환류, 실패·무결과의 기록을 규정하고(`통합-설계-초안.md` 44–50행), 형식 타당성·해설 동일성·목표 충족·행동 허가·실행 상태를 서로 대신하지 못하는 다섯 판단으로 분리한다(52–68행). 사용자 결정과 연구 기록이 새 허가를 만들지 못하게 한 권위 경계도 유지한다(70–74행). 목적을 기존 역할·상태 이름에 묶지 않고 더 직접적인 판정 계약으로 옮겼다.

### 운영 예산과 작업 예산

사용자는 운영 예산 부족을 사후 보충하는 다단계 장치보다 운영 예산과 작업 예산을 처음부터 분리하는 구조를 제안했고(`대화-근거-발췌.md` 5–15행), 조력자는 수학 생산·검증을 작업 예산, 배정·점검·복구를 운영 예산으로 분류했다(46–53행). 새 초안은 수학 검토와 작업 계약 검토를 작업 예산에, 계획·운영 점검·의도 해석을 운영 예산에 둔다(`통합-설계-초안.md` 120–135행). 공유 공급 제약에서도 두 몫을 원자 예약하고 자동 차용을 금지한다(150–188행). 기존의 단일 모델 용량 원장에 운영 역할을 함께 세던 수단(`통합-설계.md` 1,138–1,164행)을 보존하지 않은 것은 의도한 구조 변경이며, 보존하려 한 운영 가능성을 더 직접적으로 보장한다.

### 단일 실행기와 공통 실행 생명주기

조력자 제안은 한 기계 실행기가 허가·예산·프로세스·종료·산출 후속의 권위 있는 소유자가 되고, AI 판단은 실행기에 제안하는 구조였다(`대화-근거-발췌.md` 32–42행). 새 초안은 인스턴스별 단일 실행기와 독점 잠금, 연구 정본·실행 원장의 단일 작성자를 명시한다(`통합-설계-초안.md` 103–118행). 모든 AI와 긴 기계 작업에 `queued → starting → running → stopping → ended` 생명주기, 실행별 Job Object, 권한 회수, 수신 검사와 종료 장벽을 적용한다(245–310행). 기존 설계의 여러 역할별 ref와 별도 상태 기계를 그대로 복제하지 않으면서 실행 생명주기의 신뢰 목적을 보존했다.

### 대기, 후보, 과제 완료와 편입 단위

조력자는 대기 중 AI 실행을 끝내고, 풍부한 후보는 연구 기록에 남기며, 선택한 일에만 작업 계약을 만들고, 작업 계약의 완료 기준을 보존하며, 함께 성립해야 하는 결과만 묶어 편입하자고 제안했다(`대화-근거-발췌.md` 53–63행). 새 초안은 AI가 다른 응답을 기다리지 않고 종료하게 하고(77–100행), 후보와 확정 과제를 구분한 뒤 실행할 일이 정해졌을 때만 작업 계약을 만든다(191–216행). 과제 상태·대기 조건·범위별 완료 처분을 실행 종료와 분리한다(218–242행). 편입도 의미가 함께 성립하는 최소 단위로 제한하고 독립 기록의 별도 편입을 허용한다(493–520행). 이 부분은 제안의 목적과 효과를 직접 반영한다.

### 인증의 세 결과와 독립 검토 강도

조력자는 동일성 확인, 특정 불일치 확인, 판단 미완료·쟁점 미해결을 구별해 인증을 끝내고 남은 연구를 환류하며, 구조 단순화를 이유로 독립 검토의 강도를 낮추지 않겠다고 했다(`대화-근거-발췌.md` 65–75행). 새 초안의 최종 판정은 `match`, `mismatch`, `unresolved`이고, 갈림·미완료를 승인이나 확정 불일치로 만들지 않는다(`통합-설계-초안.md` 603–619행). 검토 활동도 종료해 예산을 반환하고 남은 질문을 계획으로 보낸다.

기존 설계의 고정된 기본 역할 셋과 심사자 셋(`통합-설계.md` 2,019–2,031행, 2,068–2,096행)은 새 초안에서 판본화된 검토 방침으로 바뀌었다. 새 초안은 관점별 독립 실행 수와 양수의 최종 판정자 수를 요구하고, 기존 셋과 같은 출발 구성을 권고하며, 단순화에서 구성 축소를 자동 도출하지 말라고 명시한다(`통합-설계-초안.md` 568–586행). 실제 구성은 인스턴스 생성 때 승인할 값으로 남긴다(26–41행). 이는 “수와 배치는 별도로 판단한다”는 제안에 맞는 수단 변경이다. 발췌만으로 특정 수가 영구 하한으로 합의됐다고 확대하지 않았다.

### 운영 관찰, 사용자 권한과 원자료

조력자는 예정 시각을 자동 중단 판정이 아니라 점검 계기로 쓰고 작업자가 체크포인트와 상태를 공개하게 하자고 했다(`대화-근거-발췌.md` 77–79행). 새 초안은 예정 시각·실제 상태·작업자 요청으로 운영 점검을 열고, 시간이나 무진전 횟수만으로 계속 여부를 정하지 않는다(`통합-설계-초안.md` 654–687행). 적용 직전에는 실제 실행과 전제를 다시 검사한다(689–695행).

정확히 승인된 변경, 새 해석의 확인, 권한 밖 행동의 사전 승인과 전례의 비권위성(`대화-근거-발췌.md` 81–87행)은 새 초안 700–724행에 반영됐다. 사용자는 제시된 선택지 밖으로 답할 수 있고, 유사 사례 자체는 권한이 되지 않는다. 중요한 판단에서 요약의 원자료를 회수하자는 제안(89–91행)도 연구 기억의 정확한 `source_refs`, 원자료 없는 권한·수학 사실 확정 금지, 입력 manifest의 원자료 스냅샷, 검토자의 직접 대조로 이어진다(`통합-설계-초안.md` 377–445행, 588–619행). 저장소 전체 목록을 매번 넣지 않고 고정 스냅샷의 조회·페이지 범위를 드러내는 방식은 확장성과 원자료 회수를 함께 보존한다.

### 중단 뒤 보존과 복구

대화에서 회수한 목적은 실행이 끊겨도 원자료와 성과를 잃지 않고 이어가는 것이다(`대화-근거-발췌.md` 21–28행). 새 초안은 두 단일 부모 사슬, 추가 전용 불변 산출 묶음, 불변 체크포인트와 보존 후 청소를 규정한다(`통합-설계-초안.md` 321–413행). 새 실행은 이전 실패·외부 행동·체크포인트·남은 범위를 필수 입력으로 받고(312–318행), 새 실행기는 로컬·원격 실제 상태, 예약, 공간과 후속 소유권을 대조한다(741–791행). 기존의 다수 보관 ref와 논리 세션 transcript를 그대로 유지하지 않고 판본화된 쟁점·답변·판정·재개 기록을 승계하는 방식(439–445행)으로 바꿨지만, 검증 벡터가 기존 쟁점의 반박·답변 누락을 입력 불완전으로 판정하게 한다(940–991행).

## 반박 검토를 통과한 의심 지점

- 새 초안이 `solution_invalidated`를 별도 목표 상태로 유지하지 않는 것은 곧바로 사용자 권한 상실을 뜻하지 않는다. 새 초안은 형식·동일성 판정의 사용 효력을 `suspended`·`withdrawn`으로 따로 보존하고 실제 의존에만 전파한다(`통합-설계-초안.md` 637–651행). 또한 수학적 사실 상태를 사용자의 승인으로 대신하지 않으면서, 연구 재개는 남은 허가를 따르게 한다(486–490행). 기존 상태 이름의 삭제만으로 목적 불충실을 입증할 수 없다.
- 검토자·심사자 수를 스키마 상수로 고정하지 않은 것은 검토 강도의 자동 하향이 아니다. 실제 방침은 승인 대상이고, 관점·독립 실행 수·최종 판정자와 범위 경계를 양수로 닫으며, 구성 축소를 단순화에서 도출하지 말라고 명시한다(26–41행, 568–586행).
- 전체 transcript 복원을 필수로 하지 않은 것은 연속성 포기가 아니다. 새 초안은 후속 입력에 판본화된 쟁점·답변·판정·필요 원자료를 요구하고, 누락을 검증 벡터로 둔다(439–445행, 940–991행). 아래 미확인 능력의 실제 시험은 남아 있지만, 문면상 목적을 제거하지 않았다.

## 검증을 통과한 중요한 부분

- 운영 예산은 작업 예산과 분리되고 자동 차용되지 않는다.
- 실행 종료, 과제 대기·완료, 산출 공개, 동일성 인증과 목표 해결이 서로 다른 상태와 판정으로 유지된다.
- 단일 기계 실행기가 권한·예산·프로세스·정본 적용을 직렬화하되 수학 의미를 판정하지 않는다.
- 동일성 검토는 확인·불일치·미해결을 구분하고 미해결 상태에서 실행과 예산을 붙잡지 않는다.
- 사용자 승인 범위, 새 의미 확인, 외부 효과 원장과 전례의 비권위성이 보존된다.
- 원자료·실패·부분 산출·체크포인트와 실제 실행 상태를 복구 입력으로 남긴다.

## 남은 불확실성과 읽지 않은 범위

- 발췌 밖의 전체 대화는 읽지 않았다. 발췌에 없는 합의의 존재 여부는 미확인이고 주 에이전트가 전체 대화와 다시 대조해야 한다.
