# 결함 기록 서식

do-math 시험 재편을 위한 결함 유출 분석(defect escape analysis)의 공통 서식이다. 발굴 담당마다 맡은 기간의 결함을 이 서식으로 기록하고, 집계자가 기간별 기록을 합쳐 결함 범주를 만든다. 목적은 개별 결함의 재발 방지가 아니라, 어떤 종류의 시험이 없어서 어떤 범주의 결함이 실제 운전까지 새어 나갔는지를 밝히는 것이다.

## 1. 기록 대상

다음 둘 중 하나에 해당하는 결함을 모두 기록한다.

- **실제 운전 결함**: 실제 모델(Codex·Claude)로 do-math 연구 인스턴스를 초기화하거나 운전하는 과정에서 드러난 결함. 발견한 주체(사용자, 독립 운영 AI, 기록 분석)는 가리지 않는다.
- **정지급 결함**: 발견 경위(검증런, 시험 실행, 정적 검토)와 무관하게, 영향 등급(3절)이 `정지`인 결함.

위 둘에 들지 않는 결함, 예컨대 검증런이 찾은 문서 표현 결함이나 비용 결함은 개별 기록을 쓰지 않는다. 출처별 건수만 요약 표(6절)에 센다.

## 2. 기록 항목

결함마다 아래 블록 하나를 쓴다. 값을 확인할 수 없는 항목에는 `미확인`과 그 이유를 적고, 빈칸으로 두지 않는다.

```text
### <담당 접두>-<두 자리 번호> <한 줄 제목>

- 출처: <원자료 경로:행 또는 절>, <관련 커밋 해시(있으면)>
- 발견 경위: 실제 운전 | 검증런 | 시험 실행 | 정적 검토 | 사용자 지적 | 기타(<설명>)
- 영향 등급: 정지 | 저하 | 잠재   (3절)
- 증상: <운전에서 무엇이 관찰되었는가. 관찰되지 않았으면 '운전 미발현'>
- 근본 원인: <코드·계약 수준의 원인. 원문 근거 좌표를 붙인다>
- 수정: <커밋, 고친 파일·함수, 함께 추가된 회귀 시험의 이름. 수정되지 않았으면 '미수정'>
- 결함 유형: <4절의 값 하나>
- 트리거: <결함을 활성화한 조건. 4절의 트리거 값 하나 이상과 구체 설명>
- 결함 위치 층: <5절의 값 하나>
- 시험 유출 원인: <그 시점의 시험이 이 결함을 잡지 못한 이유. 4절의 유출 원인 값 하나 이상과 구체 설명>
- 검증런 유출: <검증런이 이 결함을 찾았는지, 찾지 못했다면 확인 가능한 이유. 해당 없으면 '해당 없음'>
- 가장 싼 포착 시험: <이 결함을 잡을 수 있었던 가장 저렴한 시험의 형태. 무엇을 입력으로 주고 무엇을 단언해야 했는가>
- 범주 후보: <같은 기제의 결함을 묶을 짧은 이름>
```

## 3. 영향 등급

- **정지**: 연구 인스턴스가 더 진행하지 못한다. 실행기 비정상 종료, 영구 `blocked`·`paused`, 끝나지 않는 대기나 재시도 반복, 저장 거부로 상태 전진 불가, 초기화 미완료, 필수 역할 출력의 전건 거부가 여기에 든다. 사람의 개입 없이 풀리지 않으면 정지다.
- **저하**: 인스턴스는 진행하지만 결과가 틀리거나(잘못된 판정·승인, 자료 누락) 비용·시간이 크게 는다.
- **잠재**: 운전에서 발현되지 않았고, 발현 조건이 드물거나 아직 도달하지 않았다.

## 4. 분류 값

**결함 유형**(직교 결함 분류 ODC의 결함 유형에 do-math 경계 두 값을 더함): `기능`, `대입·초기화`, `인터페이스`, `검사`(검증 조건의 누락·과잉), `타이밍·직렬화`, `알고리즘`, `빌드·패키지`, `문서·계약`, `스키마·계약 불일치`(생산자·수신자·스키마·대역 사이의 모양 어긋남), `외부 경계`(공급자 CLI·OS·Git·Lean의 실제 동작에 대한 잘못된 가정).

**트리거**: `실제 모델 출력 형태`, `실제 외부 도구 동작`(CLI 판본, Windows API, 파일 시스템, Git, Lean), `시간 경과·기한`, `동시성·경합`, `재시작·복구·재개`, `장시간 누적`(입력 크기, 기록 수), `특정 전이 순서`, `사용자·운영 제어`, `설정·환경`, `기타`(설명).

**시험 유출 원인**:
- `시험 없음`: 해당 코드 경로를 실행하는 시험이 없었다.
- `대역이 가림`: 결함 지점을 시험 대역(저장소 대역, 엔진 대역, 러너 대역, 합성 증거)이 대신해 실제 코드가 돌지 않았다. 어느 대역인지 적는다.
- `합성 입력이 실제와 다름`: 대역이 만든 입력(모델 답, 도구 출력)의 모양·크기·순서가 실제와 달랐다.
- `출발 상태가 경로를 건너뜀`: 템플릿이나 합성 상태에서 출발해 결함이 있는 경로를 지나지 않았다.
- `단언 약함`: 경로는 실행됐지만 단언이 결함을 판별하지 못했다(거부 사유 미고정, 존재만 확인 등).
- `조합·순서 미탐색`: 개별 단계는 시험됐지만 결함을 활성화하는 전이 순서나 조합이 시험되지 않았다.
- `환경 차이`: 시험 환경(OS, 판본, 권한, 경로)이 실제 운전과 달랐다.
- `시간·규모 미재현`: 장시간, 큰 입력, 동시성을 시험이 재현하지 않았다.
- `확인 불가`: 원자료로 판정할 수 없다. 이유를 적는다.

## 5. 결함 위치 층

이 층은 재편 설계를 위한 **분류용 가설**이며, 현재 코드가 이렇게 나뉘어 있다는 뜻이 아니다. 결함이 난 코드가 어떤 성격인지로 고른다.

- `L1 원시`: 부작용 없는 함수와 헬퍼. 직렬화, 해시, 스키마 검사, 경로 계산, 단일 값 검증기.
- `L2 인터페이스 요소`: L1을 조합한 기능 단위. 상태 전이 규칙, 제출 검사, 역할 입력 구성, 저장소 게시, 제어 요청 해석. 외부 프로세스를 직접 띄우지 않는다.
- `L3 배선`: L2 요소를 실제 프로세스·스레드·시간·OS 사건으로 엮는 코드. 엔진 실행 루프, 작업자 기동과 회수, 제어 수송의 대기, 예약 운영자, CLI 진입.
- `경계 어댑터`: 외부 프로그램·OS와 직접 대화하는 코드. 공급자 CLI 호출과 출력 해석, Windows Job API, Git 자식 프로세스, Lean 실행, PowerShell 예약.
- `계약·스키마`: 역할 계약 문서, 출력 스키마, references 문서처럼 코드가 아닌 규범.

## 6. 산출 파일의 구성

1. **읽은 범위**: 실제로 읽은 원자료의 경로 목록과, 목록마다 전문을 읽었는지 일부만 읽었는지. 읽으려 했으나 못 읽은 자료와 이유.
2. **요약 표**: 개별 기록마다 한 행(번호, 제목, 영향 등급, 결함 유형, 결함 위치 층, 시험 유출 원인, 범주 후보). 이어서 개별 기록을 쓰지 않은 결함의 출처별 건수.
3. **개별 기록**: 2절의 블록.
4. **관찰**: 기록 전체에서 보인 반복 기제, 서식의 분류 값으로 담기지 않은 사항. 사실과 추론을 구분한다.
