## 종결된 native 시도의 실제 접수 영수증

별도 docs 트리의 native_scene에서 기존 실제 엔진·저장소·게시 입력·의사결정 전제를 사용했다. native_result는 명시된 제공자 증거 대역이며 실제 Windows Job 수집이라고 하지 않는다. 정상 final bytes를 만든 뒤 실제 전이 함수로 stopping→ended/execution_incomplete를 만들고 실제 저장했다. 실제 `_capture_native_submission`의 recovery_request 경로가 봉인·수락 영수증·execution authority revocation을 생산하고 실제 저장·재적재하도록 했다. 기존 execution 전체에 접수 관련 세 필드만 추가되고 status/outcome/transitions/ended_at/result_disposition이 전부 그대로임을 단언한다. 공개 retry 요청부터 복구 완료까지의 전건 여정을 대신하지 않는다.
