## 목적과 역할

G1/G2와 최종 관문의 선행 관계를 현재 증거로 정리한다. 109개 항목을 다시 조사하거나 다시 구현하는 작업이 아니다. 기존 판정이 어느 원문 성질을 입증하고 무엇을 아직 결정하지 못하는지 구분해 manager가 전체 종료 경로를 선택할 수 있게 한다. 문서 검사기의 코드 검토와 관문 실행기 분석은 같은 phase의 다른 task 책임이며 그 결과를 기다리거나 읽지 않는다.

## 완료 조건

### A1 원문 모집단의 전건 대응

sources/requirements-index.json과 원래 표를 대조해 19/11/61/12의 모든 원래 ID를 자기 evidence/requirement-state.json에 빠짐없이 한 번씩 대응시킨다. 서로 다른 모집단을 단순 합산한 완료율은 내지 않는다. 현재 출처와 원문 의미가 다른 항목은 최신 사용자 정정·현재 계약·역사 수단을 구별한다.

### A2 재사용할 증거와 끝나는 질문

각 항목에 검토된 성질, 근거 파일/판본, 적용 한계, 남김, 다음 행동을 기록한다. 분류는 최종 판본 연결만 필요/확정된 수리 필요/판정 질문 필요/현재 근거 부족 중 하나로 설명한다. 코드 의미를 확인하지 못했다면 '검토됨'으로 승격하지 않는다. 막연한 추가 감사 대신 해당 생산자/소비자/입력/성질 중 무엇을 확인하면 판정되는지 명시한다. 109개 기존 추적 항목도 원문 및 이 분류에 연결해 고립 항목·중복을 표시한다.

### A3 기존 작업 재검토의 실적과 남김

기존 prior_review의 25영역 매핑과 실제 완료 판정을 구별한다. 이미 끝난 PR23/B107~B109 검토와 B115 문서 검사기 검토 등 유효한 원증거를 재사용하고, 나머지는 필요한 실제 diff/소비자/원보고의 범위를 정한다. 이 task에서 B01~B134 전체 코드 재감사를 시작하지 않는다. 기존 구현 작업과 같은 파일을 읽게 되는 재검토는 함께 배정할 수 있는 관계를 제시한다.

### A4 다음 선택과 완결성 검사

근거로 결정할 수 있는 가까운 우선순위와 선행 관계, 다시 구현할 필요 없는 성질, 최종 관문에 남길 사항을 보고한다. 원래 ID 누락/중복·잘못된 파일 참조를 기계적으로 확인한 출력과 절차를 evidence에 남긴다. 확인 불능한 성질을 분명히 남겼다면 이 분류 작업은 완료될 수 있지만 G1/G2 충족을 선언하지 않는다.

## 판단과 경계

프로젝트 writes=[]다. 제품·시험·기존 작업판·공용 문서·Git을 바꾸지 않는다. source의 수 MB JSON은 Python으로 키별 조회하고 원문의 original_requirement/original_rule, current_work의 실제 증거와 판정을 구분한다. source 목록 전체를 출력하지 않는다. 과거 raw report를 전부 다시 실행하지 않고 필요한 판정 근거만 읽는다. 단순 파일 존재·해시 일치만으로 의미를 검토했다고 쓰지 않는다.

이 task의 제안은 manager가 검수할 근거다. 같은 phase 다른 task와 같은 문제를 독립적으로 판단해 상충하면 report finding으로 남긴다. 미래 수십 phase를 확정하거나 기존 요구를 '허용 잔여사항'으로 바꾸지 않는다. 한 문맥에 들어오지 않는 실제 재검토는 정확한 다음 질문과 원자료를 반환한다.

## 검증 방법

cwd는 repo다. 원래 JSON의 obligations, preservation, stage2.eleven_obligations, stage2.p2_bindings 및 current_work.p2.original_ids를 선택 조회한다. sources의 해시와 현재 원자료를 비교하고 달라졌다면 의미와 판본 차이를 기록한다. 자신의 매핑 JSON에서 ID 집합 동등·중복 없음·참조 존재를 확인하는 작은 read-only 명령을 실행하고 실제 출력/exit를 evidence에 저장한다. 제품 시험·T3·변이·공급자 호출은 하지 않는다.

report에는 A1~A4의 판정과 근거, 판단을 바꾸는 findings 및 후속 조치를 넣는다. 제출 직전에 bootstrap의 Python으로 services/continuous-development/check.py report <repo> <run> 001 closure-map을 실행한다. 형식 통과를 원문 의무의 의미 충족으로 표현하지 않는다.
