## 목적과 역할

G4~G8을 나중의 막연한 '전체 검사'로 남기지 않고, 현재 도구와 실제 모집단·정상 기준·환경에 연결한 실행 준비를 만든다. 이 task는 무거운 검사를 실제로 실행하는 단계가 아니다. 첫 manager가 최종 관문을 막는 조건과 앞서 해결할 일을 판단하도록 한다.

## 완료 조건

### A1 관문별 실제 실행 계약

공식 run_tests.py와 직접 coverage/mutation/port/corpus 코드를 읽고 일반 전체·fresh T3·변이·T4/T5 각각의 실제 선택 방식, cwd, 명령, 선행 입력, 출력 경로·중요 필드, 실패/미완결 판단을 자기 evidence/gate-readiness.json에 정리한다. 존재하지 않는 옵션이나 새 실행기를 만들지 않는다. 전체 선택을 폴더 수동 목록으로 축소하지 않는다.

### A2 변이 모집단과 정상 기준의 준비

기존 17개 파일 분할·T3 선택 색인/함수 진입 자료를 현재 소스와 연결할 방법을 확인한다. 과거 함수 수를 현재 분모로 확정하지 않고 fresh T3 뒤 확정할 값과 지금 확인 가능한 파일 범위를 구별한다. 정상 기준 실패, 미선택·미도달, 변이 생존, 환경 실패를 구분하는 실제 보고 필드와 후속 수리 책임을 설명한다.

### A3 실환경 가용성과 부족 조건

현재 설치된 실행 파일·지원 자료·말뭉치 manifest를 읽고 필요한 경우 안전한 --version 등 읽기 명령만 실행한다. 인증 비밀을 읽거나 로그에 남기지 않는다. 공급자 모델 호출, Lean 설치/다운로드/대형 컴파일, Windows 예약 등록/발화, 네트워크 비용 발생 스모크는 이번에 하지 않는다. 존재/버전과 실제 사용 가능·호출 성공을 구별하고, G7에 필요한 아직 미확인 접근·권한·환경 조건을 구체적으로 남긴다.

### A4 판본·재사용·대기 운용

B129 원보고와 이후 부분 결과를 대조하여 현재 입증 범위와 최종 재실행 이유를 정리한다. 소스 고정, worker 합계 3 이하, 실제 종료와 관찰 만료 구별, 공유 읽기, 환경 건너뜀, 판본 변경 시 무효화되는 증거, 실제 공급자 녹화 재사용 조건을 실행 절차로 제시한다. 비용은 확인한 값과 미측정을 구별하고 근거 없는 완료 시간을 약속하지 않는다.

## 판단과 경계

writes=[]다. run_tests를 import/실행해 수집 부수 효과나 .timings/선택 색인을 갱신하지 않는다. 필요한 모집단 조회는 코드·등록 파일과 기존 보고의 집합 대조로 하고, 실제 --list/fresh 측정은 적절한 후속 phase에 남긴다. 제품/검사기/서비스를 수정하지 않는다. timeout이나 최대 phase 수를 새 실패 조건으로 만들지 않는다. 실행 기록에 없는 exit나 프로세스 종료 원인을 추측하지 않는다.

기능 의무의 전체 상태는 closure-map, 문서 검사기 설계는 document-closeout 책임이다. 외부 도구 부재를 synthetic 성공으로 대체하지 않는다. 환경 문제를 발견해도 나머지 준비를 완료할 수 있으면 그 사실을 별도 finding으로 남긴다.

## 검증 방법

cwd는 repo다. 지정한 파일의 실제 옵션/경로/필드와 제시한 명령을 대조한다. 버전 명령을 실행하면 실제 executable 경로·argv·exit·stdout을 evidence에 기록한다. 명령이 오래 걸리면 경과 시간만으로 종료하지 말고 실제 상태를 확인한다. 실행하지 않은 T3·변이·스모크는 report checks에서 not_run/null과 이유를 명시한다.

run:sources/baseline.json, 기존 일반 원보고·말뭉치·변이 분할 정보를 활용한다. proposal의 경로·옵션·필수 입력이 실제로 존재하는지 확인하고 불확실성은 표시한다. report와 A1~A4를 작성해 check.py report <repo> <run> 001 gate-readiness를 통과하고 반환한다.
