# 독해 대조의 합의

압축 진술: phase 006의 Codex 대표 실호출은 원 역할 의미를 보존해 성공했지만 직접 소비 시험 11건과 성공 표본 공백이 남아 partial이다. phase 007은 제품 실행 경로를 고정하고 외부 CLI fixture와 실제 분기 단언을 수리한다. 과거 실패를 유지하며 관련 회귀와 미러 인도 근거가 충족된 뒤 공급자 단위의 제품 커밋을 판단한다.

무거운 것: 실호출 성공과 관련 회귀 미완료의 구별; 전송 schema와 원 역할 schema의 구별; 저장 가능한 실패가 성공 표본을 대신하지 못하도록 실제 분기를 검증하는 완료 조건.

가벼운 것: 쓰기 범위, 공식 실행 명령, 기존 실호출 재사용의 판본 조건, 근거 경로, 검사·Git 권한과 후속 전체 관문.

뺄 것: 이번 관리 조사 순서, 무관한 G의 구현 설계, 과거 작업 목록 전체의 재해설, 필수 자료에 이미 있는 서비스 형식의 반복.

독해 원고에는 다음 작업자가 실제로 먼저 읽는 protocol, 공용 context/plan/seams, phase 007 배정과 objective를 원문 그대로 함께 제공한다. manager 검수 보고와 이번 기억 노드도 인계 판단 근거로 포함한다. 코드·원실행 자료의 진실성은 manager의 별도 검산으로 판정하며 독해자에게 합격 판정을 요구하지 않는다. 새 요구나 사용자 결정을 만드는 작업이 아니다.

원천은 sources/user-decisions.md, services/continuous-development/protocol.md, phase 006 task report 및 manager-evidence/verification.json과 현재 원코드다. 사용자 목표 G1~G8은 유지한다. F1/F4는 한정 resolve, F2/F3는 새 objective로 carry한다. manager가 직접 제품을 고치거나 다음 task를 실행하지 않는다.
