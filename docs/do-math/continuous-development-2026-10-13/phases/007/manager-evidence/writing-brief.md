# 독해 대조의 합의

압축 진술: phase 007은 제품 실행 경로를 고정한 채 공급자 직접 소비 11실패와 성공 pair의 검출 공백을 해소했다. manager는 지정된 관련 회귀와 원자료 인도를 검수해 공급자 변경 단위를 커밋하고, 다음 단일 task에 운영·복구 문서의 실제 반환 결속과 설치 경로의 낡은 설명 교정을 배정한다. 전체 G1~G8의 다른 남김과 최종 관문은 유지한다.

경중 선언의 무거운 것: 지정 A 완료와 프로젝트 전체 완료의 구별, 실제 성공·반려 사유를 입증한 근거, 다음 task가 동명 필드를 실제 생산 객체와 연결해야 하는 이유와 관찰 가능한 완료 조건.

가벼운 것: 모델 지정, 정확한 쓰기 범위와 원자료 좌표, 검사·미러·Git 마감 절차, 기존 실호출 재사용의 한계.

뺄 것: 이번 검수 명령의 실행 순서, 과거 전 phase의 반복 설명, 다음 범위 밖 제품 수리 설계.

독해 원고는 protocol, 공용 context/plan/seams, phase 008 배정과 objective, manager review, 기억 노드를 각각 원문으로 묶는다. 실제 독자가 절차상 먼저 얻는 자료다. 코드와 원실행의 참 여부는 별도 manager 검산이 맡는다. 독해자가 합격을 선언하도록 요구하지 않는다.

원천은 사용자 요구 sources/user-decisions.md와 sources/model-policy-2026-10-14.md, 현 protocol, phase 007 report와 manager verification, phase 001 P01 packet 및 현재 doc_code/core_engine/operator_bootstrap이다. C8의 task gpt-6.1-sol/high, manager gpt-6-astra/xhigh를 유지한다. 작문 독해도 도구의 새 기본값을 사용한다. 운영자 변경 네 파일은 task 변경으로 귀속하지 않는다. manager는 제품을 수정하지 않고 다음 task 실행은 서비스에 맡긴다.
