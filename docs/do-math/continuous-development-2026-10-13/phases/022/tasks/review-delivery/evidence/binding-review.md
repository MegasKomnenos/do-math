022는 work이며 제품 합격을 선언하는 최종 review가 아니다. 시작 skills/diff 2675파일은 021 manager source-inspected의 SHA256과 전건 같다. 초기 대조 도우미의 hash 문자열/객체 형식 차이는 도우미에서 바로잡았고 start-comparison.json은 동일 SHA 표현으로 대조한 결과다. Git 시작 상태의 canonical/repository/planning·이전 021 제품 변경을 보존했으며 이번 변경은 start/final 바이트 차이만 보고한다.

## 021 F1의 수리

CLI-실행-계약의 현재 「입력 크기 조정」은 같은 제안 전문을 role_review.proposal에 한 번만 제공한다. 기존 실제 단계 시험에 최종 prepare_role_input 반환 전체를 재귀 비교하는 독립 기대값 1을 추가했다. 수리 전 공식 red의 한 row는 failed/exit1이고 실제 실패는 2 != 1이다. 최상위 proposal 부재나 context_for를 기대값으로 다시 부르는 비교만으로 대신하지 않았다. 021 원관찰과 원보고는 고치지 않는다.

review_cycle.context_for가 kind=proposal의 현재/이전 판본 원메시지를 모두 기존 source_ref 형식으로 지급하도록 수리했다. role_review.proposal의 현재 전문은 그대로 한 번 남는다. 원 turns·transcript_manifest·input_bindings·delivered_prompt의 봉인 형식과 원바이트·순서·담당·판본은 바꾸지 않았다. review_engine._build_review_context는 이미 검증된 원메시지를 compact_json_bytes로 물질화하고 local_path를 self_messages와 source_refs에 함께 연결한다. 이 기존 구현을 사용하므로 review_engine 자체를 바꿀 필요가 없었다. context_store.prepare_role_input의 공유 authorized seat view는 context_for를 직접 사용하므로 새 참조 표현과 실제 포장이 일치한다. 별도 형식 정의나 호환 분기를 만들지 않는다.

실제 scope/initial/organize/judge/answer의 최종 자리 입력에서 독립 count를 검사하고, 각 참조 파일은 원 cycle의 message·manifest와 ref/SHA/bytes/proposal_digest를 대조한다. 현재 원문 파일 사본의 부재는 검증된 봉인 원문으로 다시 물질화하고, 잘못된 파일은 slot/index/path와 기대·실제 SHA를 갖춘 restoration_error가 된다. 원 transcript/manifest의 부재·내용 변조는 기존 validate_transcript의 정확 좌표 반려를 유지한다. 제안 판본 변경의 기존 실제 엔진 시험에 이전 전문 파일의 정확 바이트/판본 복원을 추가했다. 같은 자리의 입력 봉인·profile 일치, 봉인전 동료 비노출, organizer의 전건 정확ref/원 담당, 고정 질문·원자료·private supplemental·재개/재실행 성질은 기존 선택을 그대로 유지한다.

## P07

packet의 현재 소유자는 submission.check_submission과 RepairExecutionMixin.route_submission_return이다. doc_code의 result/retry AST 두 결속을 실제 반환 경계로 바꿨다. 반환값을 추정하는 범용 AST·전역 담당 등록부를 새로 만들지 않았다. DELIVERY_INPUT_BOUNDARIES의 두 sentinel은 실제 값 없는 검사를 반려하고, 일반 순회는 정확한 담당 시험에만 위임한다. 담당 확인 AST는 함수 안의 실제 assert_delivery_documents(owner=...) 호출을 확인하며 반환 추론이 아니다. 담당/owner/method 누락·오기와 문서 검사 없는 method를 실패시킨다. 다른 owner의 기존 deferred 검사·별칭·callable·저장/입력 소유 단언은 유지한다.

red-doc은 실제 값 없이 submission_check.passed와 repair.previous_output을 통과시키던 두 subTest가 ValueError not raised로 실패했다. 최종 helper는 실제 check의 passed, issue 유무, not_checked의 수학/Lean 한계, 실행·모드·도구·check ID, 현재 후보/확장/schema/context의 정규 해시를 연결한다. passed 삭제·반전·다른 후보/실행/모드/check·import_check.sha256 차용을 반려한다. passed·capture_eligible·delivery.state=accepted·편입은 서로 다른 의미이며 unit.test_submission_check_invariants와 기존 수신/부분 접수/preview/최종 수락 선택을 유지한다.

실제 route가 만든 queue repair와 재반려 뒤 waiting action에서 정확한 previous_output·execution_id·retry bundle/issue 범위를 읽는다. 원 출력 삭제·다른 후보/실행·다른 수리 범위의 사본은 반려한다. 공개 활성화된 실제 엔진 장면에서 실제 반려 후보의 원 UTF-8 바이트를 저장하고, 현재 ended execution의 같은 역할/활동을 잇는 후속을 포장했다. 실제 _context와 prepare_role_input의 action.repair가 정확한 후보를 유지하고, continuation_history의 raw_output_ref가 정확한 rejected-response 파일/SHA/bytes를 회수한다. 그 경로에 저장하거나 포장하는 제품 함수는 대역으로 교체하지 않는다. Git/모델/시계 대역은 기존 외부 포트 경계에만 둔다.

## 네 문서 절

current-sections.json은 역사 행번호 대신 현재 제목을 기준으로 구간을 고정한다. section-name-decisions.json에는 N01-237의 24, N01-260의 45, N02-002의 99, N02-014의 79개 절별 고유 inline 이름과 실제 문장·소유자·판정·재사용/미검사 한계가 있다. 숫자는 검토 목록 크기이고 의미 완료율이 아니다. 도우미의 AST 검사는 지정한 함수 좌표가 존재하는지 확인할 뿐 문장을 참으로 채점하지 않는다.

입력 크기 조정의 현재 제안 단일 지급은 새 동작 검증으로 닫는다. 제출/최종응답의 검사·후보 포착·접수·편입과 이전 원문 수리는 실제 경계에 연결했다. 시작 입력의 P01~P05 및 B130~B134의 문서/manifest·catalog·원자료·도구·profile 성질은 승인된 기존 검사와 현재 불변 코드로 유지한다. logical path, placeholder, 출력 heading, JSON Schema required 및 외부 셸 login=false 표기는 각각의 의미로 분류하며 파일명이나 비코드 표현을 필드 존재의 증거로 세지 않는다. 현재 문서 본문 수정은 필요하지 않았다.

네 절에서 인용한 별도 소유자의 **전체 의미 인증은 남는다**. N01-237의 input_overflow_retry_resolved/failed·question_links 및 N02-002의 input_overflow_requests/input_overflow_resolutions는 input_recovery와 CoreEngineMixin._resume_input_overflow_action/_apply_input_overflow_resolutions가 소유한다. 검토 제안 overflow의 기존 flow는 이번 선택에 있지만 일반 계획의 프로필 선택/현재성/사용자 retry 전이는 이 work에서 새로 실행하지 않았다. N01-260의 scope/replay_safety/repair_target은 contracts.disposition_schema와 운영 처분/설치수리 경계에 속한다. N02-014의 calculated impact/currentness/권한과 revision_requests/revision_resolutions는 integration·submission·거버넌스 적용이 소유하며 P06/P10의 전체 의미를 이 P07 검사로 닫지 않는다. 기존 packet의 해당 종료 질문에 정확한 이름과 문장 좌표를 연결해 후속 판단에 반환한다. 네 절 밖 N 모집단이나 L01 읽기/준수 인증도 수행하지 않았다.
