## 목적과 역할

문서 후보 L01과 원문13-C의 미정인 실제 운전 읽기 한도를 닫을 판단 자료를 확보한다. 현재 Codex/Claude의 어떤 host/tool/version/read-call에 어느 단위·절단 규칙이 적용되는지 확인한다. 역할 문서를 stdin으로 전달하는 제품 경로와 운전 AI가 도구로 문서를 읽는 경로를 분리한다. 한도 미상을 통과로 바꾸거나 token을 근거 없이 byte로 환산하지 않는다.

이 task는 work 조사이며 제품 수정 없는 최종 review가 아니다. 같은 phase의 host-smoke는 새 host 시험·시험 지침·비용 캐시·미러만 쓴다. 이 task는 그 파일이나 결과에 의존하지 않고 고정된 SKILL/운전 계약·CLI 입력 코드와 설치 호스트 자료를 읽는다. 공식 시험·공급자 실호출·생성기·공유 cache를 실행하지 않으므로 독립적으로 진행한다.

## 완료 조건

### A1 실제 운전 읽기 모집단과 단위를 특정

followup-packets의 L01, binding-inventory의 읽기 경계, 원문13-C/B-20, 현 SKILL의 구간 읽기, contracts.reading_map/render_prompt와 context_store.prepare_role_input, cli_worker의 stdin 경계를 필요한 원문 구간에서 확인한다. 이전 역할10개 검증은 그대로 재사용하고 역할 입력 총합을 단일 shell 출력으로 취급하지 않는다.

현재 실제 운전 경로를 Codex와 Claude별로 host/CLI·버전·도구명·읽기 호출 옵션·집계/개별 출력 제한·문서/구간·단위·절단 위치/표시·근거로 정리한다. 개발 manager가 사용하는 도구와 제품 운영자가 사용하는 도구가 같다는 가정은 검증 없이 두지 않는다. SKILL 진입·후속 필수 문서의 실제 읽기 단위를 현재 원문으로 특정하고 역사 버전을 현재로 재인증하지 않는다.

### A2 권위 있는 한도와 온전한 회수 근거를 대조

설치 CLI의 공개 help/schema/코드·활성 도구 정의·관련 비밀 아닌 설정을 우선 확인하고 필요한 경우 해당 제공자의 공식 문서를 확인한다. 로컬 설치/도구 계약과 공개 최신 문서의 판본 차이를 표시한다. 인증 토큰·사용자 전체 설정/개인 대화·무관 연구자료를 출력하거나 증거로 복사하지 않는다. 필요한 설정 키만 읽고 값이 비밀이면 가린다.

현재 세션의 실제 읽기 도구를 관측할 수 있으면 자기 evidence에 만든 비밀 없는 유한 fixture로 호출 인자·출력·truncation 표기·전체 구간 대응을 기록한다. 한 번에 거대한 출력을 쏟지 않는다. ASCII·다중바이트 문자·구간 경계의 차이가 판정에 중요하면 구별한다. 원 파일의 byte 해시와 도구 출력/전문 회수는 다른 근거다. 로컬 파일을 해시했다는 사실만으로 모델에 도달한 전문을 증명하지 않는다. 끝표지 하나만으로 누락 없는 수신을 주장하지 않는다.

현재 host에서 확인한 token 한도는 그 단위로 남긴다. 권위 있는 byte 상한이 없거나 Claude의 실제 read-call을 유료 호출 없이 관측할 수 없다면 무엇이 확인됐고 어떤 조건/결정이 더 필요한지 구체적으로 적는다. 실험만으로 보편 상한을 만들어내지 않는다. 새로운 모델 세션을 기동하지 않으며 이미 보존된 비밀 없는 공급자 원출력은 증언 가능한 범위에서만 재사용한다.

### A3 구현 또는 외부 결정으로 바로 이어질 유한 인계

evidence에 `reading-boundaries.json`과 `review.md`를 작성한다. 각 경계는 원문 요구·실제 읽기 단위·현재 관측/설정·판정/한계·근거 경로를 갖고, 결론은 충족/검사 추가 필요/외부 결정 필요를 구별한다. 모두 확인됐다면 추가 검사 위치와 정상/절단 반례·기존 검사 재사용을 특정한다. 확인할 수 없는 부분은 정확히 어떤 host/도구/한도 단위나 요구 해석을 누가 결정해야 하는지, 영향13-C/G1/G3 및 L01을 적는다. 막연한 추가 감사나 전체 의무의 재작성은 하지 않는다.

조사 자체는 미정의 정확한 상신을 포함해 완료할 수 있으나 13-C/L01의 충족으로 읽히지 않게 보고한다. status/acceptance는 이 조사 A의 완료 여부이고 실제 제품 요구의 판정은 narrative/findings에 따로 둔다. 다른 문서 패킷·host-smoke 결과·전체 G7의 완료로 확대하지 않는다.
