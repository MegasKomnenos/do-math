# do-math 통합 설계 초안의 검토 기록

작성일: 2026-09-06

이 기록은 [첫 초안의 보존 판본](적대적-검토-2026-09-06/기준-초안.md)에 대한 저작 당시 검토다. 일곱 렌즈 검토 이후의 수정과 판정은 [종합 판정](적대적-검토-2026-09-06/종합-판정.md), 현재 규칙은 [현행 통합 설계](통합-설계.md)를 참조한다.

## 1. 결과와 범위

[새 통합 설계 초안](적대적-검토-2026-09-06/기준-초안.md)을 작성했다. 합의한 오버뷰를 예산·실행 상태·과제 대기·산출물·검증·권한·저장·복구의 구체 계약으로 옮겼다. 현행 통합 설계 파일과 기존 구현·인스턴스는 변경하지 않았다.

현재 결과는 후속 구현과 검토의 출발점이 되는 초안이다. 실제 모델 실행 어댑터의 능력, 검토 방침의 실효성과 외부 정의 정본의 일치까지 확인한 최종 구현 정본은 아니다.

이번에는 기존 설계와 기억·다른 원자료를 다시 읽지 않았다. 앞서 읽은 문서, 사용자와 확정한 방향, 이미 읽은 write-for-reader·simplify 지침을 사용했다. 새로 작성한 초안 자체는 전문을 읽고 상태 전이와 정상·실패 시간선을 대조했다. 독립 세션 검증, 실제 어댑터 시험, Lean 빌드와 연구 실행은 수행하지 않았다.

## 2. 오버뷰를 구체화한 주요 결정

| 오버뷰의 방향 | 초안의 구현 계약 |
|---|---|
| 운영·작업 예산 분리 | 실제 공급 제약마다 두 예약 한도를 두고 전건에서 원자 예약. 수학 검토는 작업 예산을 사용 |
| 기계 실행기가 지속 상태 소유 | 한 작성자와 연구 정본·실행 원장 두 ref. 긴 검사는 별도 기계 작업이며 상태 적용만 직렬화 |
| 모든 AI에 공통 실행 계약 | queued·starting·running·stopping·ended. 권한 회수와 종료 확인을 연구자·검토자 모두에 적용 |
| 대기 과제와 모델 실행 분리 | 사용자·자료·검증을 기다리는 과제는 보존하고 해당 AI 실행은 종료 |
| 산출물과 인증 분리 | 불변 산출 묶음을 먼저 보존하고 공개·동일성·목표 감사를 후속 처리 |
| 인증의 정직한 종료 | match·mismatch·unresolved 구분. 새 질문 ID로 보충 활동 상한을 우회하지 못함 |
| 입력 규모에 맞는 원자료 회수 | 고정 스냅샷의 페이지 조회, 이번 판단의 필수 범위와 저장소 탐색의 완전성 구분 |
| 사용자 권한의 정확한 적용 | 정확한 변경의 직접 승인을 기록하고, 해석에 새 선택이 생길 때 확인. 유사성만으로 권한 확대 금지 |

두 Git ref, 원장의 불변 산출 묶음, 구체 상태 이름과 초기 검토 구성은 이번 저작자가 선택한 초안의 구체안이다. 사용자가 이 세부까지 별도로 확정한 것으로 기록하지 않는다.

## 3. 작성 중 발견해 수정한 문제

다음은 남겨 둔 결함이 아니라 초안에 수정을 반영한 항목이다. 문면과 시간선 대조에서 해당 문제 경로가 해소됐음을 확인했다. 실제 실행 테스트를 통과했다는 뜻은 아니다.

### C01. 모델별 장부만 나누면 공통 공급 한도를 중복 예약할 수 있었다

모델 A와 B가 같은 계정 상한을 쓰는데 각각 독립 상한인 것처럼 예약하면 운영 예약이 남아 있어도 공급자 전체 한도를 작업이 차지할 수 있다. [4.1절](적대적-검토-2026-09-06/기준-초안.md#d04)은 공급 제약을 별도 식별하고, 실행이 소비하는 제약 전건에서 같은 원장 변경으로 예약하게 수정했다. 상한의 실제 공유 관계는 D02에서 환경으로 확인해야 한다.

### C02. 운영 실행의 점검이 다시 운영 예산을 기다릴 수 있었다

모든 실행에 똑같이 AI 운영 점검을 붙이면 운영 점검자 자체를 점검할 다른 운영 실행을 기다리는 경로가 생긴다. [12.1절](적대적-검토-2026-09-06/기준-초안.md#d12)은 작업 예산의 실행에 AI 운영 점검을 적용하고, 운영 AI·기계 작업에는 정해진 실행 기한과 기계적 실패 처리를 적용하도록 수정했다. 필요한 후속 운영 판단은 현재 실행의 종료·반환 뒤에 한다.

이 수정은 운영 예산 부족을 해결하려고 연구 작업을 정지하는 절차를 추가한 것이 아니다. 유한한 운영 요청의 종료 계약으로 재귀 대기를 막는다.

### C03. 임시 참조를 공용 편입 뒤 어떻게 해석할지가 비어 있었다

새 기록의 참조를 임시로만 허용하고 편입 뒤에는 자기 공용 커밋 OID를 요구하면, 그 OID를 파일 안에 넣어 커밋을 만드는 순환이 생긴다. [7.2절](적대적-검토-2026-09-06/기준-초안.md#d07)은 같은 트리의 ID 참조를 정식 참조형으로 두었다. 후보와 편입된 기록 모두 자신이 속한 트리에서 해석하므로 재작성과 자기 OID가 필요 없다. 다른 판본을 가리킬 때는 정확한 커밋 참조를 사용한다.

### C04. 정지 규칙이 예약 전 요청의 전이와 충돌했다

실행 전건을 stopping으로 옮기는 문장은 queued 상태의 허용 전이와 맞지 않았다. [13.5절](적대적-검토-2026-09-06/기준-초안.md#d13)은 queued를 직접 ended/cancelled로 닫고 준비·실행 중인 경우만 stopping으로 옮기게 수정했다. 초기화 중 정지는 원래 단계로 돌아가도록 복귀 상태도 보존한다.

### C05. 단일 작성자가 긴 검사를 수행하며 정지·상태 처리를 막을 수 있었다

Lean 빌드 전체를 원장 쓰기 구간에 넣으면 별도 운영 예산이 있어도 기계 실행기가 응답하지 못할 수 있다. [10.3절](적대적-검토-2026-09-06/기준-초안.md#d10)은 긴 검사를 고정 입력의 기계 작업으로 분리하고 실제 상태 적용만 직렬화했다. 편입 때는 최신 원장에 결과를 합쳐 다른 실행의 사건을 잃지 않는다.

### C06. 최종 제출과 프로세스 종료의 순서가 불명확했다

제출한 프로세스가 먼저 사라지면 정상 제출을 늦은 통지로 거부할 수 있었다. [6.5절](적대적-검토-2026-09-06/기준-초안.md#d06)은 제출 의도·manifest·권한 회수를 같은 원장 변경으로 기록한 수신 확인을 정의했다. 이 확인과 최종 출력 검사 통과는 구분한다. 로컬 파일의 최종 회수는 종료 장벽 뒤에 한다.

### C07. 집단 시작을 넣으며 불필요한 OS 원자성 문제를 만들고 있었다

여러 프로세스의 실제 행동 시작을 하나의 원자적 배정으로 취급하면 부분 시작 실패를 위한 별도 제어가 필요하다. [9.3절](적대적-검토-2026-09-06/기준-초안.md#d09)은 실행별 배정을 사용하고, 함께 성립해야 하는 일은 작업 내부 단계나 선행 결과 의존으로 표현하게 수정했다.

### C08. 판정자 수와 과제 실행의 기본 불변식이 빠져 있었다

판정자 0명이 공허한 만장일치로 통과하지 않도록 [11.3절](적대적-검토-2026-09-06/기준-초안.md#d11)에 양수 조건을 넣었다. [5.3절](적대적-검토-2026-09-06/기준-초안.md#d05)은 과제별 미종료 연구 수행 실행 하나, 과제 완료·닫힘 전 그 실행의 종료를 명시했다. 별도 검토 활동은 자기 실행으로 관리한다.

## 4. 아직 남은 문제와 확인 사항

### D01. 실제 실행 어댑터가 요구한 경계를 보장하는지 확인하지 않았다

[16.1절](적대적-검토-2026-09-06/기준-초안.md#d16)은 실제 모델·노력·입력 주입, 실행별 권한, 비공개 검토 자료의 격리, 로컬·원격 종료 조회를 요구한다. 현재 환경에서 그 기능을 제공하는 구체 어댑터를 조사하거나 구현하지 않았다.

특히 로컬 래퍼 종료가 원격 모델 실행의 종료를 뜻하지 않는 경우에는 예약을 정직하게 반환할 방법이 필요하다. 도구·파일 격리가 지침문에만 존재하면 정본의 단일 작성자와 검토 독립성도 실행상 보장되지 않는다.

다음 단계의 첫 구현은 연구 역할 전체가 아니라 이 어댑터의 작은 실행·중단·복구 시험이어야 한다. 능력이 부족하면 지원 경계를 바꾸거나 실행 방식을 다시 선택해야 한다. 문서상의 선언으로 통과시킬 수 없다.

### D02. 공급자의 실제 자원 제약을 확인하지 않았다

[4절](적대적-검토-2026-09-06/기준-초안.md#d04)은 공유 동시성 제약을 함께 예약하는 논리를 정의했다. 어떤 모델·계정이 상한을 공유하는지, 속도·사용량 제한이 따로 있는지, 다른 프로그램의 같은 계정 소비를 어떻게 다룰지는 실제 공급자 자료와 어댑터로 확인해야 한다.

이 값들은 임의의 안전 숫자로 채우지 않았다. 예산 분리의 적용 범위와 실제 보장 범위를 일치시키는 검증이 필요하다.

### D03. 대화 소실 정책은 사용자 선택으로 남아 있다

[3.3절](적대적-검토-2026-09-06/기준-초안.md#d03)은 continue_authorized와 pause의 동작을 정의했다. 어느 값을 사용할지는 이 초안 작성에서 대신 결정하지 않았다. 이 선택은 초안의 상태 구조를 막지는 않지만 실제 인스턴스의 초기 허가에는 필요하다.

### D04. 새 검토 구조의 강도와 중복 비용을 평가해야 한다

[11절](적대적-검토-2026-09-06/기준-초안.md#d11)은 초기 독립 검토, 한 번의 보충 단계, 최종 독립 판정으로 닫았다. 출발 구성으로 초기 세 관점과 최종 판정자 셋을 제안했으나, 그 구성이 실제로 필요한 신뢰를 제공한다는 실험 결과는 없다.

분쟁 없는 제안에도 최종 판정 전건을 다시 수행하게 하는 이익이 충분한지, 초기 판정이 완결된 경우 어떤 단계를 합칠 수 있는지를 비교해야 한다. 기존 숫자와 익숙한 심사 형태가 새 설계의 최적 구성으로 자동 승계된다고 보지 않는다. 검증 강도를 낮추는 것과 불필요한 중복을 없애는 것을 구별해 평가할 필요가 있다.

### D05. 큰 제안의 범위 분할이 의미를 보존하는지 실제로 시험해야 한다

[8.3절](적대적-검토-2026-09-06/기준-초안.md#d08)과 [11.3절](적대적-검토-2026-09-06/기준-초안.md#d11)은 분할 뒤 정의·가정·양화·결론 연결을 확인하게 한다. 부분의 항목 ID가 전건 덮였다는 사실만으로 전체 의미를 보증하지 않는다.

공유 가정이 빠졌거나 양화 순서가 뒤바뀐 대표 제안으로 경계 검토가 실제 오류를 잡는지 확인해야 한다. 분해할 수 없는 필수 입력이 한도를 넘는 경우에는 그 규모를 지원한다고 선언하지 않는다.

### D06. 보편 도메인 정의 정본과 새 의미를 대조하지 않았다

이번 작업의 원자료 범위를 지켜 해당 정본을 새로 읽지 않았다. [1절](적대적-검토-2026-09-06/기준-초안.md#d01)의 K·F·U와 과제·판정의 표현은 앞서 읽은 설계와 합의한 오버뷰를 기준으로 작성했다.

새 초안을 정본으로 채택하기 전에는 보편 정의를 다시 대조해, 구현상의 단순화가 도메인의 의미를 바꾸지 않았는지 확인해야 한다. 이는 확인하지 않은 범위이며 현재 불일치가 발견됐다는 주장이 아니다.

### D07. 판정 기록 중심의 맥락 승계가 실제로 충분한지 시험해야 한다

[8.3절](적대적-검토-2026-09-06/기준-초안.md#d08)은 전체 transcript 대신 쟁점·답변·판정과 원자료를 다음 실행에 준다. 입력 규모를 제한할 수 있지만, 기록이 중요한 반박이나 불확실성을 빠뜨리면 같은 오독을 반복할 수 있다.

기각된 이의, 수정된 범위, 서로 다른 해석이 실제로 이어지는 검토 사례를 재생해야 한다. 필요한 맥락이 빠지면 기록·입력 계약을 고쳐야 한다. 전체 대화를 생략해도 언제나 같은 판단을 얻는다고 보장한 것은 아니다.

## 5. 검증 수준과 후속 순서

이번 확인은 새 초안의 전문 대조, 상태·참조·권한·실패 시간선의 자체 검토, 문서 내부 링크·절 번호·표의 기계 점검이다. 초안의 V01 이후 벡터는 구현이 수행해야 할 테스트 명세이며 실행한 테스트 결과가 아니다.

문서 기계 점검은 통과했다. 초안의 0~18절과 V01~V48이 빠짐없이 한 번씩 나오고, 두 문서의 파일·anchor 링크가 해석되며, 코드 블록 닫힘·표의 열 수·줄 끝 공백 검사에 오류가 없었다. 이 결과는 실제 실행 어댑터나 수학적 검증의 통과 판정으로 사용하지 않는다.

후속 순서는 실제 어댑터의 실행·중단·격리·복구, 공통 실행과 두 예산의 최소 운전, 산출물·두 ref 편입, 작은 수학 제안의 검토, 큰 제안과 맥락 승계의 검증이다. 사용자에게 속하는 인스턴스 선택과 검토 방침의 채택은 그 결과를 보고 정확한 적용 대상으로 확정한다.
