## 연결 자료와 정리 범위

과제·활동·실행, 종료·자원 정산, 형식 결과·해설·판정의 구분은 보존했다. 새 상태·활동 종류·원장·실행별 점검 모드 사본은 추가하지 않았다. 다음 시각의 의무는 이미 존재하는 대상 execution의 모드에서 판단한다.

루트 CONTEXT의 운영 처분 정의를 동기화했다. P vs NP 컨텍스트는 세부 운영 처분을 재정의하지 않고 사건 기반 점검과 통합 설계의 초과 분류를 따르므로 변경하지 않았다. 기존 검토 보고는 원래 판본의 이력으로 유지한다.

명세 묶음은 저작 선언에서 재생성했다. 스키마·레지스트리·예제·의미 규칙과 V01~V225·Q01~Q22의 본문 행·해시 대응을 함께 갱신했다. V159·V189의 철회 상태는 유지한다.

## 검증

저장소 루트에서 다음 순서로 수행한다.

```text
python docs/do-math/통합-설계-명세-v9/build_spec.py
python docs/do-math/통합-설계-명세-v9/verify_spec.py --refresh-examples
python docs/do-math/통합-설계-명세-v9/verify_spec.py
python 기억/scripts/validate_memory_index.py
```

새 회귀 검사 두 개는 수정 전 스키마의 next_review_at 필수 조건에서 실패했고, 수리 뒤 전체 명세 검사 77개가 통과했다. 재점검의 모드·불확실성·대상 실행 결속 검사를 무력화한 변이 결과는 `의미-변이-검증.txt`에 기록한다. 최종 저장 산출의 검사 결과는 명세 묶음의 validation-report.json과 validation-output.txt가 고정한다.

이 검증은 오프라인 구조·관계 검사와 문서의 조건·효과 대조다. V223~V225의 실제 런타임 실행, Windows·공급자·Lean·모델의 동작과 연구 효능은 수행한 것으로 표시하지 않는다. 별도 실행의 변경 검토 결과와 작성자의 처분은 `독립-검토.md`에 기록한다.
