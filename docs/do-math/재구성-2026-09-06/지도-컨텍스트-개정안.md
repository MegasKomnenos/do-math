# 컨텍스트 정본: wayfinder 지도 「P vs NP 연구 체계 재설계」

> 정본 전환용 수정안이다. 적용 대상은 `docs/wayfinder/pvsnp-재설계/컨텍스트.md`이며, 통합 설계·루트 정의의 전환과 함께 적용한다. 프로젝트 고유 계약과 외부 티켓의 상태를 이 수정안이 새로 승인하지 않는다.

## 0. 지위와 읽기 계약

이 문서는 wayfinder 지도 [「P vs NP 연구 체계 재설계」](https://github.com/MegasKomnenos/math/issues/6)의 현행 컨텍스트 정본이다. 지도 아래의 티켓을 수행하는 세션은 착수 전에 이 문서 전문을 읽는다.

문서별 소유권은 다음과 같다.

- 루트 `CONTEXT.md`는 구현 세부를 제외한 보편 수학 연구 용어를 정의한다.
- `docs/do-math/통합-설계.md`는 `do-math`의 상태·권한·저장·실행·검증·복구를 구현할 규범 계약을 소유한다.
- P vs NP 프로젝트 입력은 `research/pvsnp/연구-주제-선호.md`, `research/pvsnp/핵심-정의-명세.md`, `research/pvsnp/문헌-체계-명세.md`와 승인·동결 문헌 지도·완료 증거다.
- 이 문서는 지도 목적, 티켓 사이의 소유권, P vs NP 프로젝트 계약과 과거 자료의 참고 경계를 소유한다.
- 열린 작업과 선행 관계의 정본은 GitHub 하위 이슈와 차단 관계다.

보편 용어의 정의나 `do-math`의 구현 세부를 이 문서에 다시 쓰지 않는다. 이 문서와 다른 정본이 충돌하면 먼저 위 소유권으로 실제 소유자를 판정한다. 중요한 판단은 요약이 아니라 소유 원문을 다시 읽어 대조한다.

같은 티켓을 이어가는 세션은 결정마다 이 문서와 루트 `CONTEXT.md`를 증분 수정하지 않는다. handoff, 티켓 종료나 그 밖의 세션 종결 시 그 세션의 확정 결정을 원자료와 대조해 한 번에 반영한다. 새 결정이 대체한 문면과 중복도 함께 제거한다. 티켓을 닫는 세션은 이 일괄 갱신을 커밋하고, 바꿀 것이 없으면 해결 댓글에 `정본 갱신: 영향없음`을 명시한다.

## 1. 목적과 범위

이 지도의 종착은 P vs NP 연구 체계를 재설계하고 보편 수학 연구 스킬 `do-math`를 구현·검증해 실제 연구를 시작할 수 있는 상태다.

이 지도는 다음 산출을 포함한다.

1. P vs NP 연구 주제·성공·범위·방향의 프로젝트 입력
2. P와 NP의 정확한 핵심 Lean 정의와 연결 정리 명세
3. 연구 시작 전 승인·동결할 문헌 기준선과 그 구축 계약
4. 보편 `do-math`의 자기충족적 통합 설계
5. `do-math` 구현과 격리된 검증

실제 P vs NP 문헌의 후속 재판독, Lean 연구 정본 구축과 증명·반증 시도는 이 지도의 범위 밖이다. 기준선 문헌 조사와 `do-math` 구현 검증은 실제 연구를 시작하기 위한 선행 산출이므로 범위 안이다.

## 2. 보편 설계와 티켓 소유권

`K`, `F`, `U`, 연구 진전, 형식 타당성, 해설–형식 동일성과 신뢰 시대의 뜻은 루트 `CONTEXT.md`가 소유한다. 해당 개념의 운용·직렬화·상태 전이는 `docs/do-math/통합-설계.md`가 소유한다.

`do-math` 통합 설계는 다음 원리를 구현 계약으로 닫는다.

- 유효한 신뢰 환경의 Lean 표현이 형식 정본이고 사람이 읽는 수학 해설이 주 산출물이다. 형식 타당성·해설 동일성·목표·학술 검증의 판정을 구별한다.
- K·F·U, 실제 연구 진전, 근거의 정보 상태와 부분 결과를 구별하며 원자료에서 판단을 재검증한다.
- 기계 실행기 하나가 연구·실행 상태를 단일 커밋으로 공개하고 모든 AI·기계 실행은 같은 격리·권한 회수·종료·복구 계약을 따른다.
- 거친 후보는 F와 연구 기록으로 보존하고, 독립 검토에 올릴 만큼 정련된 제안에 작업 계약을 만든다. 유효한 사전 AI 검토는 재사용하고 기계가 현재 착수 조건을 확인한다.
- 후보 준비와 최종 배정 선택은 서로 다른 AI 실행이 맡으며 기존 공통 활동·실행 체계를 따른다. 준비·검토 중인 후보가 있어도 이미 준비된 후보의 선택은 계속할 수 있다.
- 후보 준비는 사건과 개설 시각 기준의 주기에 따라 탐색·집중 활용·다양한 렌즈·실제 성과와 실패를 재고한다. 생성량·발견 수·배합에 보편 쿼터를 두지 않는다.
- 작업 계약은 기대 변화·진전 증거·사건별 자기 점검·완료 기준·권한을 소유한다. 반복 무진전 등은 조기 점검을 열며 발동 자체로 연구를 중단시키지 않는다.
- 작업·운영 자원을 분리하고 실제 공유 제약을 함께 예약한다. 과제·활동의 대기, 실행 종료와 원격 자원 정산은 별도로 기록한다.
- F·근거·관계·맥락·기억과 종류 정의는 고정 OKF 부분집합의 개념 문서로 보존한다. 안정 ID·출처·확인 범위·효력·항해 색인과 정확한 판정 참조를 구별한다.
- 준비·선택 입력은 후보·K 목차와 최근 선택의 기대·실제 결과를 기본 제공한다. 큰 목차의 포함 범위를 표시하고 상세 원자료 열람은 재량으로 유지한다. 제공 후보의 처분 완결성과 원문 전수 열람은 구별한다.
- 수입은 원문·의미 단위·내부 소유자·질문·영향을 독립 대조하고 통치 기록의 필요한 승인을 받는다. 명확한 직접 승인과 새로운 의미 해석을 구별한다.
- 수학 검토는 기본 관점·조건부 전문성·전체 연결을 확인한다. 중요한 반박에는 제기자의 답변과 필요한 맥락 회수를 연결하고 미응답·미해결을 해소나 승인으로 바꾸지 않는다. 판정 승계의 범위가 불명확하거나 전체 논증 해석이 바뀌면 전체 재검토한다.
- 산출물은 함께 의미가 성립하는 단위로 편입한다. 사용자 결정 대기는 같은 과제의 남은 의무와 재관찰 조건으로 보존할 수 있다.
- 스킬의 진입·정의·역할·공통 절차·스키마·도구는 각각 소유 문서를 가지며 실제 역할 입력의 전달·판본·의미 일치를 검증한다.

위 목록은 구현 세부의 제2 정본이 아니다. 정확한 상태값·판정·권한·실행·실패 처리·검증은 통합 설계에서 읽는다.

`do-math` 통합 설계는 프로젝트 중립의 보편 계약이며 P vs NP 유래 내용을 담지 않는다. `do-math` 구현, P vs NP 프로젝트 입력 패키지와 P vs NP 문헌 조사는 서로 분리되며, 문헌 조사는 별도 세션에서 수행하고 `do-math` 문면과 계약으로 결합하지 않는다. P vs NP의 검증 기준과 수학 소재는 3절의 프로젝트 입력이 소유하고, 초기화의 일회성 수입과 연구 헌장·정책·종류 정의·감사 계약이라는 일반 기구로만 연구 인스턴스에 들어간다.

`do-math` 구현 완료는 보편 테스트 벡터, 대표 연구 워크스루와 초기화 워크스루로 검증한다. P vs NP 인스턴스 초기화나 해답 fixture는 구현 완료 조건이 아니며, 이를 대신하는 가상 프로젝트 fixture도 현행 계약에 두지 않는다.

## 3. P vs NP 프로젝트 입력

정적 프로젝트 입력은 다음 세 문서다.

1. `research/pvsnp/연구-주제-선호.md`: 전체 연구 주제, 원하는 결과, 성공·부분 성과, 범위·방향, 문헌·학술 검증 선호
2. `research/pvsnp/핵심-정의-명세.md`: P와 NP의 정확한 수학 정의, 부호화·기계 모형과 연결 정리 의무
3. `research/pvsnp/문헌-체계-명세.md`: 연구 시작 전 문헌 기준선의 주제·깊이·수렴·동결 계약

문헌 명세에 따라 구축하고 승인·동결한 문헌 지도와 완료 증거는 세 정적 문서와 구별되는 네 번째 입력 묶음이다. 네 입력의 주제와 소유 관계가 일치하고 문헌 기준선의 완료 증거가 유효할 때만 P vs NP 연구 인스턴스를 초기화한다.

초기화는 입력 의미 전건을 연구 헌장·정책·맥락·설정, 초기 `F`, 자료·근거, 사용자 결정과 그 밖의 정확한 내부 소유자에 한 번 수입한다. 수입 결과 가운데 연구 헌장·정책·맥락·설정은 연구 책임자가 전건을 읽고 승인해야 활성화된다. 평시 재개는 외부 입력을 다시 읽지 않는다. 입력 하나를 임의로 우선해 충돌이나 누락을 숨기지 않는다.

## 4. 핵심 수학 목표와 기초

핵심 P와 NP 정의는 이진 문자열 언어, 결정론적 단일 테이프 Turing 기계의 최악 경우 `n^k+k` 시간과 다항 길이 증명서를 검사하는 결정론적 다항시간 검증자를 뼈대로 사용한다. 다른 표준 정의·기계·부호화는 우리 Lean 언어로 작성한 연결 정리로 핵심 정의에 연결한다. 실제로 입증한 관계가 등가보다 약하면 등가라고 부르지 않는다.

수학적 해결은 핵심 정의의 `P = NP` 또는 `P ≠ NP` 증명 항이 해설–형식 동일성, 커널 검사, 공리 감사, 범위 차분 감사와 프로젝트별 추가 관문을 통과해 Lean 정본에 편입된 상태다. 두 결론 중 미리 선호하는 답은 없다.

조건부 정리, 제한 모형 분리, 장벽 결과와 부분 성과는 정확한 연구 결과일 수 있지만 P vs NP 해결이 아니다. 시간·토큰·비용 한도나 새 접근 부재도 해결이 아니다. 미해결 상태와 재개 좌표를 보존한다.

범위 차분 감사의 P vs NP 판정 어휘는 `동일`, `등가 입증`, `충분성 입증`, `범위 축소`, `범위 확장`, `조건부`, `미해결`이다. 앞의 셋만 목표 해결과 양립한다. 나머지 결과도 수학적으로 타당하고 엄밀하면 실제 범위로 Lean 정본에 편입할 수 있다. 이 어휘와 효과의 프로젝트 권한 원천은 `research/pvsnp/연구-주제-선호.md`다.

활성 기초 프로필은 Lean의 표준 고전 기초 하나이며, 이 선택의 프로젝트 권한 원천은 `research/pvsnp/연구-주제-선호.md`다. 그 프로필의 공리 허용 목록, 목록 변경 절차와 비활성 대안 프로필의 격리 규율은 통합 설계가 소유한다.

ZFC는 Lean 정본과 경쟁하는 제2 정본이 아니라 학계의 통상적 기초와 비교하는 P vs NP 전용 검증 기준이다. `P = NP` 또는 `P ≠ NP`를 최종 해결로 인정하려면 같은 결과를 ZFC나 더 약한 명시적 기초에서 증명하거나, Lean 결과를 그 기초로 옮기는 검증된 번역·해석·보존 정리를 제시해야 한다. 이 기초 이동은 목표 해결 감사의 필수 관문이다.

수학적 해결 뒤에는 사람이 읽는 증명, 자연어–Lean 대응, 재현 환경, 외부 독립 검토, 결함 제보·수정, 적격 출판과 공동체 검토를 수행한다. 외부 공개·출판은 사용자 권한 경계를 따른다.

## 5. 문헌 기준선 계약

P vs NP 문헌 기준선의 조사 우주는 현대 수학과 이론 컴퓨터과학 전 분야다. P vs NP와 가까울수록 분야 해상도를 세밀하게 하고 멀수록 거칠게 한다. 분야는 여러 부모를 허용하는 중첩 계층이며, 깊이는 기초 지식·표준 종합·핵심 원 성과·후속 논쟁과 개선·현행 연구 전선을 구별한다. 출처 유형은 깊이와 다른 축이다.

각 분야를 여러 깊이에서 살필 때의 기준 핵심층은 그 분야를 정확히 구별·설명·검증하는 데 필요한 정본·대표 문헌뿐 아니라 대안, 반론, 반례, 경계, 주변 개념과 의존 지식을 포함한다. 고정 문헌 수나 인용 수를 완료 기준으로 쓰지 않는다.

문헌 지도는 원문을 대신하지 않는다. 정확한 판본·재진입 좌표·내용 윤곽·한계·관계를 제공하고 문헌 유래 관계와 AI 유래 미검증 관계를 구분한다. 후속 연구가 수학 내용을 사용하려면 원문을 다시 읽고 현행 검증을 적용한다.

`분야 × 깊이`는 조사 관점이지 모든 조합에 같은 DB 검색·파일·투표를 강제하는 작업 격자가 아니다. 조사 시작 때 KUDOS와 공개 자료원을 한 번 실사하고, 실제 수록 범위와 누락 검출 능력을 확인해 분야별 자료원을 배정한다. 같은 문헌을 찾는 광역 검색을 모든 출판사 플랫폼에서 반복하지 않는다.

공개 웹 탐색, 자료원 선별, 문헌 판단, 정규화, 판본 연결과 누락 검사는 AI가 맡는다. 사용자가 특정 조사 묶음의 자동화를 승인하면 AI가 크리덴셜을 출력하지 않는 로컬 브라우저 프로그램으로 인증 DB 검색과 서지 export도 수행한다. 프로그램이 처리하지 못한 인증 검색과 선별 후 원문 확보만 사용자가 맡는다. AI는 수집 실물을 직접 검사한 뒤 필요한 보충 묶음을 하나씩 연다. 대화가 아니라 `research/pvsnp/literature-baseline/STATUS.md`와 현재 묶음이 협업의 재개 좌표다.

모든 분야의 정한 해상도 포괄, 선정 자료원 검색, 핵심 참고문헌과 전후방 인용망 처리, 접근 가능한 핵심 원문의 확보, 판본·정정·철회 기록과 독립 누락 검사의 포화를 모두 확인한 뒤 문헌 집합을 동결한다. 고정 문헌 수·검색 횟수·AI 투표 수는 완료를 대신하지 않는다.

원시 export와 적법하게 로컬 보존할 수 있는 원문·코드·데이터는 Git에서 무시하는 `research/pvsnp/literature-baseline/intake/`와 `originals/`에 두고, 추적 manifest에 판본·해시·접근·권리 정보를 기록한다. 크리덴셜 값은 AI 프롬프트·대화·로그·산출물에 넣지 않으며 승인된 로컬 프로그램만 실행 직전에 읽어 로그인 입력란에 사용한다. 능동 문의·원문복사·상호대차·유료 구매는 하지 않는다.

문헌 체계의 외부 근거와 현재 접근 한계는 `docs/wayfinder/pvsnp-재설계/문헌-체계-외부근거.md`와 `docs/wayfinder/pvsnp-재설계/합리화-자료원-외부근거.md`가 설명하고, 전체 규범 계약은 `research/pvsnp/문헌-체계-명세.md`가 소유한다.

## 6. 모델과 사용자 권한

모델·노력·실행 어댑터·도구·자원 한도는 통합 설계가 정한 실행 프로필로 정확히 고정한다. 이 문서에 별도 역할별 모델 표를 두지 않는다. 실제 입력·권한·격리·종료·복구의 능력 검사를 통과한 프로필만 실운전에 사용한다.

후보 회수·검토 재사용·환류·점검·맥락 및 판정 승계의 연구 효과와 비용은 대표 과제에서 비교한다. 역할·문제군별 실제 평가를 모델·검토 방침의 근거로 삼으며 설계 문면이나 fixture 검사의 통과를 연구 성능 향상의 증거로 사용하지 않는다.

`do-math`는 헌장·정책과 사용자의 위임 범위 안에서 자율적으로 운전한다. 실행기의 단독 쓰기 권한은 의미 판정을 대신하지 않는다. 사용자 위임의 재사용, 외부 효과, 재개·재시작의 독립 안전 확인과 계약 변경 권한은 통합 설계의 현행 계약을 따른다.

## 7. 과거 자료와 현재 소유권

새 연구 체계는 종결한 `pvsnp-탐사-1`의 상태, 작업 부채, 완료 판정, 자료구조와 규칙을 승계하지 않는다. 과거 문헌 판독, 출처 원장, 기각 지도, 검증 기록과 보존 산출은 필요한 사실·근거·실패 경위와 원자료 좌표를 확인할 때만 읽는 참고 자료다.

과거 자료의 완료·검증 판정은 새 체계에 전이되지 않는다. 같은 문헌이나 내용을 선택하면 현행 절차로 다시 처리한다. 과거 자료는 원래 좌표에 보존하고 현재 정본에 중복 복사하지 않는다.

주요 원자료 좌표는 다음과 같다.

- 도구 실사: `docs/wayfinder/pvsnp-재설계/도구-지형-실사.md`
- Lean 표현력 대조: `docs/wayfinder/pvsnp-재설계/Lean-증명-표현력-심층검토.md`
- 기초와 Lean 대조: `docs/wayfinder/pvsnp-재설계/현대수학-기초와-Lean-대조.md`
- 트래커 규약: `docs/agents/issue-tracker.md`

과거 입증 검토 문서의 수리자·심사자 구조를 현행 해설–형식 동일성 검토 활동과 혼합하지 않는다. 현행 인증 절차는 `docs/do-math/통합-설계.md`만 소유한다.
