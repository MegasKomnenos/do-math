# 통합 설계 재구성 검토

[기존 설계](../통합-설계.md)의 연구상 비교우위에 대한 검토와 사용자가 승인한 반영 계획을 [5차 초안](../통합-설계-초안.md)에 적용했다. 단일 실행기·공통 실행 구조에서 후보 노출, 사전 검토 재사용, 생성과 선택의 분리, 결과 환류, 탐색 주기, 사건별 점검과 검토 연속성을 연결한다. 이 기록은 항목별 처분과 실제 검증 범위를 소유하며, 설계 변경을 실운전 성능 향상의 증거로 사용하지 않는다.

## 주요 선택

| 내용 | 반영한 계약 |
|---|---|
| 실행과 저장 | 단일 기계 실행기·상태 머리와 공통 실행 생명주기로 권한·예약·종료·후속을 연결한다. |
| 후보와 과제 | 정련된 계약을 배정 전에 독립 검토한다. 유효한 AI 승인은 재사용하고 현재 착수 조건은 기계가 확인한다. 준비·검토 중인 다른 후보가 현재 배정을 막지 않는다. |
| 탐색과 진전 | 준비와 선택을 서로 다른 실행에 배정한다. 주기는 회차 개설 시각에서 계산하고 연구 사건의 자기 점검·반복 무진전을 운영 점검으로 연결한다. |
| 지식과 입력 | 후보·K 목차와 최근 기대·실제 결과를 기본 제공한다. 큰 목록의 실제 범위를 표시하고 상세 열람은 재량으로 유지한다. |
| 수학 검토 | 기본 세 관점·조건부 전문성·전체 연결과 무쟁점 직접 집계를 유지한다. 중요한 반박에는 답변·맥락 회수를 연결하고 승계 경계가 불명확하면 전체 재검토한다. |
| 산출물과 목표 | 사람이 읽는 수학 해설을 주 산출물로 삼고, 형식 타당성·해설 동일성·목표·추가 감사를 구별한다. 정확한 부분 결과는 보존한다. |
| 학술 검증 | 현재 해답과 요구 판본별로 완료·외부 거부·해소를 기록하고, 해답 개정에 옛 완료를 자동 승계하지 않는다. |
| 위임 | 명시한 일반 조건과 사용자가 승인한 사례 기반 위임을 같은 허가 계약으로 표현한다. 유사성 판단이 새 권한을 만들지 않는다. |
| 역할 문서 | 공통 정의의 소유를 유지하고 필요한 계약·정의·도구·원자료를 해당 판단 전에 전달한다. |

사례 기반 위임의 실제 범위·제외·자원·외부 효과는 인스턴스 생성 때 사용자가 정한다. 두 위임 형태 중 하나를 보편 설계의 전역 기본값으로 골라야 한다고 보고 제시했던 질문은 이 구조로 해소했다. 사용자 회신이나 승인을 받은 것으로 처리하지 않았다.

사전 검토의 비용은 최초 AI 검토·변경에 따른 AI 재검토·매회 기계 확인·선택 후 재계획으로 나눈다. 현행이 매번 후보 전부를 AI로 재검토한다고 가정하지 않았다. 또한 후보 상세 열람 강제·특정 기아 후보 지정·transcript 열람 이행 검사, 고정 발견 수·탐색 비율은 추가하지 않았다.

양화·가정·주요 증명 단계의 대응, 세 기본 검토 관점·조건부 전문성, 정확한 부분 결과와 유용한 실패, 목표·학술 검증의 구별은 4차에 이미 존재하며 유지했다. 이 항목들은 누락 지적 없이 검증을 통과한 보존 대상이다. 의견 분열을 확정 결함으로 만드는 규칙은 복원하지 않고 unresolved를 유지한다.

## 검토와 검증 범위

4차 재구성은 기존안 192개 절 구간·3차 초안 100개 구간·기존 테스트 목적 246개를 대조한 작업이었다. 이번 5차에는 V118~V141의 24개 시나리오를 추가하고 V18·V78·V79 및 워크스루·역할·스키마 소유 표를 갱신했다. 현재 V01~V141은 구현이 수행할 검증 명세이며 실운전 시험의 통과 수가 아니다.

변경 후 대조에서 사전 검토 결과의 다음 소유자, 초기화의 준비·선택 개설, 수학 검토 결과의 계획 발동, 실행별 스냅샷의 독립성을 확인해 문면을 맞췄다. K 목차가 유효한 해설 연결을 필수로 요구하면 형식적으로 유효한 K를 누락할 수 있어 연결의 효력 표시와 V141을 추가했다. 자기 점검의 응답 행동 자체가 다음 실질 행동 금지에 걸리지 않게 하고, 첫 안전 경계 전 응답 불가능과 경계 이후 기한을 구별했다.

이번 변경은 수정 문면 전건과 연결된 활동·입력·검사·후속·정의의 의미 대조를 통과했다. 기계 검사는 네 Markdown 문서의 UTF-8·BOM·LF·NFC·끝 개행, 코드 펜스·표 열수·로컬 링크, 초안의 절 참조·19개 명시 anchor·141개 고유 시나리오 ID·판본 5, 10개 활동과 역할 읽기 계약의 대응을 확인했다. `git diff --check`와 `git apply --check`가 통과했고, 동기화 패치를 메모리에서 적용한 두 대상의 결과가 전환 안내를 제외한 두 개정안의 바이트와 정확히 일치했다. 이 검사는 구현할 스키마나 실제 역할 입력의 시험을 대신하지 않는다.

실제 do-math 역할·실행기·Lean을 구동한 시험과 별도 독립 AI 검증은 수행하지 않았다. 현재 작업 공간에 do-math 스킬 구현이 없어 17.5절의 실제 효능 비교는 수행할 수 없으며, D07·D09가 해당 역할 입력·지원 범위의 후속 확인을 소유한다. 이번 작업은 설계 반영의 완료이며 연구 효능 검증의 완료가 아니다.
