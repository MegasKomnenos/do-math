# 통합 설계 재구성 검토

이 기록은 [기존 설계 기준판](기준-기존안.md)과 [3차 초안 기준판](기준-3차-초안.md)을 내용별로 대조해 [4차 초안](../통합-설계-초안.md)을 작성한 근거다. 기존 설계의 실행 기구를 그대로 유지해야 한다고 가정하지 않고, 유효한 연구·판정 계약의 행방을 전수 확인한다. 새 초안의 선택도 같은 검토를 받는다.

현재 산출은 설계 후보와 정본 동기화 수정안이다. 실제 모델·프로세스 격리·Lean·복구·수학 연구 효능의 실운전 검증 결과는 아니다. 사용자 위임의 Q1은 [결정 기록](결정.json)에 상태를 보존한다. 미회신 동안 13.2절은 3차 초안의 후보 규칙이며 새로 승인된 위임으로 사용하지 않는다.

## 1. 기준과 산출물

사용자는 두 문서의 복잡성과 내용 성숙도를 비교한 뒤, 기존안 전체를 보존 검토의 기준으로 삼고 타당한 새 구조에 맞춰 초안을 재구성하는 작업을 지시했다. 앞선 검토에서 지적한 부분만 수정하는 것이 아니라 원문 전체의 유지·재표현·대체·제거와 새 선택의 근거를 확인하는 범위다.

기준 네 문서의 실제 바이트·행 수·SHA-256은 [기준.json](기준.json)에 고정했다. 기준 사본의 본문과 링크는 원래 바이트를 보존한 감사 자료이며, 사본 안의 옛 지시·판정·상태를 현재 계약으로 적용하지 않는다.

| 산출물 | 역할 |
|---|---|
| [4차 초안](../통합-설계-초안.md) | 선택한 구조와 보존한 연구·판정·실행 계약 |
| [원문 대응표](원문대응.md), [기계 자료](원문대응.json) | 기존안 192개 절 구간과 3차 초안 100개 절 구간의 처분·목적·새 소유 절 |
| [벡터 대응표](벡터대응.md), [기계 자료](벡터대응.json) | 기존 246개 테스트 목적과 새 계약·벡터의 대응 |
| [정의 수정안](CONTEXT-개정안.md), [정의 대응](정의대응.json) | 루트 CONTEXT의 유지·개정·제거·추가 |
| [지도 컨텍스트 수정안](지도-컨텍스트-개정안.md) | 보편 실행 구조와 모델·권한 설명의 동기화 |

| [문서 검증 결과](검증.json) | 기준 무결성·구간 덮개·참조·표·벡터·패치 적용 가능성의 실제 검사 |

단계별로 별도 승인을 요구하는 절차를 만들지 않는다. 기술적 설계 선택은 원문의 목적·전제·효과로 판단했고, 사용자 위임처럼 실제 선호가 필요한 선택은 따로 남겼다. 기존 문면이 길거나 여러 검토를 거쳤다는 이유, 초안에 먼저 적혔다는 이유는 타당성의 근거로 쓰지 않았다.

## 2. 구조 선택과 실익

다음은 이번 저작에서 채택한 설계안이다. 개별 구현 값까지 과거 사용자가 확정했다고 주장하지 않는다.

| 선택 | 근거·효과 | 버리거나 바꾼 수단 |
|---|---|---|
| 기계 실행기·상태 머리 하나 | 단일 호스트에서 연구와 실행의 같은 공개 시점을 제공한다. OS·서비스 효과는 별도 대조한다. | controller·supervisor·run·monitor 등 여러 가변 머리의 동기화와 AI 메인 handoff |
| 공통 활동·실행 | 의미 판정 책임은 활동에, 실행권한·자원·종료는 공통 계약에 둔다. | worker와 비worker의 서로 다른 요청/종료 프로토콜 |
| 과제 대기·실행 종료·자원 정산 구별 | 사용자·자료 대기 동안 의무는 남고 프로세스는 끝난다. 원격 미정산은 독립 자원에만 영향을 준다. | 결정 대기를 위한 강제 분할 종결과 후속 씨앗 |
| 후보와 실행 계약 구별 | 미성숙 아이디어를 풍부하게 남기고 실행할 일에 충분한 계약 검토를 수행한다. | 전 후보의 발생 AST·실행 껍질·미리 수행하는 착수 검토 |
| 작업·운영 예산 분리 | 작업이 동시성 용량을 사용해도 운영 몫을 유지한다. 실제 공유·누적·시간창·호스트 제약은 각각 집행한다. | 운영 용량이 부족해진 뒤 연구를 회수하는 추가 프로토콜 |
| 주기적 탐색 재고 | 실행 중인 접근과 별개로 후보 밖의 렌즈·원자료 재해석을 고려한다. 깊은 탐색은 작업 예산에 배정한다. | 별도 씨앗 생성자·전용 packet·생성 전용 카운터 |
| 작업별 진전 계약 | 작업자와 점검자가 기대 변화·증거·계약 적합성의 같은 기준을 읽는다. | 관찰 의무·세대·사본 거부 연쇄·고정 적응 횟수 |
| 조회와 정확한 근거 승계 | 필수 검토 범위는 완결하고 저장소 탐색은 실제 조회 범위를 남긴다. 쟁점의 살아 있는 반박은 독립 대조로 보존한다. | 매번 넣는 전체 K/후보 목차·전체 transcript |
| 지식 문서의 OKF 부분집합 | type·제목·요지·저작·출처·항해와 안정 ID를 보존한다. 실제 자료형과 구체 종류를 명확히 읽는다. | 모든 YAML scalar의 문자열화, type의 @ 합성, 종료 시 신규 ID 승격 |
| 무쟁점 직접 집계와 유한 쟁점 검토 | 기본 세 관점·조건부 분야·전체 연결이 모두 match이면 중복 최종 AI 없이 기계 관문으로 간다. 쟁점은 셋의 독립 최종 판단을 받는다. | 정상 경로의 보편 중복 판정, 상한 분열을 승인 이의로 표시하는 의미 혼합 |
| 사람용 해설·부분 K·목표/추가 감사 | 수학자가 정의·가정·핵심 논증을 읽을 수 있어야 한다. 정확한 부분 성과는 목표 미해결이어도 보존한다. | 해설을 해시·대응표의 부속물처럼 읽히게 하는 축약 |
| 판본별 학술 검증 | 현재 해답과 요구별 완료·외부 거부·해소를 연결한다. 외부 거부와 내부 수학적 결함을 구별한다. | 과거 원고/검토 완료의 묵시적 승계 |
| 실제 역할 읽기 계약 | 공통 정의의 소유를 유지하고 필요한 정의·도구·원자료를 해당 판단 전에 전달한다. | 전 역할의 전체 용어집 상주와 수기 기계 목록의 중복 |

예산·접근 경계·원격 정산의 구체화는 비용 없는 단순화가 아니다. 그 보장을 요구하는 만큼 실제 어댑터가 입증할 것이 늘어난다. 이 문서 재구성으로 D01·D02의 능력 검증을 통과했다고 하지 않는다. 역할별 모델은 검증된 프로필로 선택하며 특정 모델 명칭만으로 연구 품질을 보증하지 않는다.

## 3. 사용자 결정 Q1

기존 17절은 사용자 결정을 유사한 미래 사례에 적용하는 전례 위임을 둔다. 3차 초안 13.2절은 사용자가 명시한 일반 적용 범위의 허가를 직접 참조한다. 두 규칙의 차이는 검사기 교체만이 아니라 자동 위임의 범위다.

사용자에게 제시한 선택은 명시한 재사용 범위 안에서 자동 적용하는 안과, 개별 결정을 전례로 삼아 유사 사례에 재사용하는 안이다. 추천은 전자다. 허가 범위와 재생 안전성을 직접 대조할 수 있고, 유사성 판단만으로 범위를 확대하는 경로가 작기 때문이다. 후자는 개별 사례 결정만으로 미래 개입을 줄이는 이익이 있다.

회신 전에는 전자를 새 사용자 결정으로 봉인하지 않는다. 초안은 기존 3차의 후보 문면을 유지하고, 원문·벡터 대응의 전례 항목은 결정 상태로 표시한다. 선택에 따라 13.2절, 관련 질문·위임 벡터, 정의 수정안과 이 기록을 함께 갱신한다. 전체 정본 전환의 적용 권한으로 이 검토기록을 사용하지 않는다.

## 4. 원문 대조의 범위와 판단

원문 대응표는 코드 울타리 안의 예시 제목을 절로 세지 않는다. 실제 절 경계마다 원문 행 구간을 보존하고 표제만 있는 상위 절은 구성으로 구별한다. 내용이 있는 구간에는 실제 처분과 새 소유 절을 적었다. 새로 분리한 1.4절은 기존 통치 계약을, 7.3.1절은 기존 항해·저작 계약을 맡는다.

행 수의 완전성은 의미 보존의 증명이 아니다. 핵심 검토는 각 처분의 전제와 소비자를 따라 수행했다. 예를 들어 관찰 세대를 제거한 뒤에도 실행기의 다음 점검이 유지되는지, 진전 기준은 작업자가 읽을 수 있는지, 결정 대기에서 남은 의무와 후속 소유자가 남는지, 해답 개정 뒤 옛 학술 완료가 사용되지 않는지를 대조했다.

기존 246개 벡터는 새 계약의 112개 시나리오와 소유 절에 대응했다. 여러 옛 벡터가 하나의 공통 계약을 검사할 수 있고, 없어진 기구의 전이를 시험하던 벡터는 원래 기대값을 폐기한다. 모든 옛 상황을 새 런타임에서 실행해 통과했다는 뜻은 아니다. 기존 또는 초안의 벡터 수를 검증 강도의 대리값으로 사용하지 않는다.

다음 보존 여부는 문서 대조를 통과했다: K·F의 별도 정체성, 형식 타당성·해설 동일성·목표 충족의 구별, 정확한 부분 결과, 금지 공리·고정 환경, 미완료/미해결/무결과의 구별, 원자료와 실제 의존을 따르는 철회, 새 실행의 실패 근거 승계, 권한 회수와 실제 종료의 구별. 보존되지 않은 옛 수단과 새 권한 선택은 위 구조표 및 Q1에서 별도로 설명한다.

## 5. 집필 후 대조에서 수정한 사항

| 항목 | 확인한 문제와 교정 | 개정안의 소유 절 |
|---|---|---|
| 착수 승인 결속 | 계약 검토가 있다는 일반 지시만으로 실제 시작 전제의 연결이 충분하지 않았다. 현행 revision의 전건 승인과 시작 직전 재검사를 명시했다. | 5.4·6.3 |
| 과제 정체성 | 모든 질문 의미 변경에 새 ID를 요구하는 문면과 같은 과제의 계약 개정이 겹쳤다. 같은 의무의 구체화와 다른 연구 의무로의 대체를 구별했다. | 5.5·7.2 |
| 대기 중 미종료 요청 | 활성 프로세스가 없다는 읽기로 queued 연구 요청이 남은 과제를 waiting으로 옮길 수 있었다. 소유 연구 요청 전건의 ended를 요구했다. | 5.3 |
| 외부 ID의 생성 시점 | 공급자가 호출 뒤 부여하는 ID를 호출 전에 요구하는 문면이 있었다. 내부 action_id·멱등 키를 먼저 보존하고 외부 ID는 확인 뒤 연결한다. | 6.1·13.3 |
| YAML 정규 바이트 | JSON의 정규화만 명시한 채 지식 문서 전체의 인코딩·개행·NFC 충돌 조건이 약해졌다. YAML과 본문의 바이트 경계를 함께 복원했다. | 7.3 |
| 초기 미완료 검토 | 직접 집계의 나머지 경우라는 분기가 초기 실행 미완료에도 최종 판정을 열 수 있었다. 초기 필수 실행 미완료는 복구 또는 unresolved로 처리한다. | 11.4 |
| 학술 검증의 기계 입력 | 외부 거부의 본문 서사만으로 파생 상태를 계산할 수 없었다. external_rejection·정확한 해결 근거·해소 참조를 지식 스키마에 결선했다. | 7.3·9.4·16.4 |
| 일반 과제 완료의 주체 | 완료 기준에 판정자 이름만 두고 실제 활동과의 연결이 부족했다. 기계 검사·research_plan·identity_review·goal_audit·사용자 결정을 각각 지정했다. | 3.2.1·5.4·9.2 |
| 초기 프로필 검사 | 초기 의도 해석을 실행한 뒤 어댑터를 검사하는 것으로 읽힐 수 있었다. 초기 운영에는 이미 능력을 검증한 정확한 프로필을 요구했다. | 14.1·16.1 |
| 판정 효력의 최초 생성 | 판정 사용 상태의 초기값·작성자·근거가 필요했다. 판정의 편입 조건을 통과할 때 실행기가 active와 근거를 함께 공개하고, 결과값과 효력을 구별해 소비하도록 명시했다. 복원은 같은 대상·범위·입력에 한정한다. | 11.8 |
| 옛 해시 변경 벡터 | 기존 L11의 ‘해시 변화→새 제안’은 기존 19.11절의 예기치 않은 훼손 처리와도 맞지 않았다. 훼손과 의도적 수정은 V24·V25로 구별했다. | 11.6·벡터 대응 |

교정은 문제를 발견했다는 이유만으로 통과시킨 것이 아니다. 바뀐 소유 필드·활동·전이와 시나리오를 다시 대조했다. 별도 독립 AI 세션을 실행한 검증이라고 표현하지 않는다.

## 6. 시간선과 실패 반경 대조

| 흐름 | 대조한 경로와 판정 |
|---|---|
| 활성 작업 중 탐색 재고 | 설정 시각 도래→사건 하나→운영 계획→탐색 고려→선택/보류→다음 시각. 작업 유무가 주기 발동을 생략하지 않는다. |
| 초기화 중 정지·재개 | 검증된 초기 프로필→initializing→pause와 복귀 단계→종료→복구→남은 초기화. 미생성 신뢰 환경을 재개 선행조건으로 강요하지 않는다. |
| 사용자 답변 대기 | 수행/잔여 범위·질문 봉인→실행 종료→과제 waiting→답변/현재 권한 대조→같은 의무의 새 실행 또는 개정. 대기용 프로세스와 후속 씨앗 강제가 없다. |
| 슬롯 하나의 검토 | 범위 계획→초기 독립 할당을 순차 배정→각 결과 봉인→전건 match 직접 집계 또는 쟁점 경로. 이미 봉인한 결과를 다시 수행하지 않는다. |
| 검토 입력 누락 | 해당 실행 미완료→완료된 결과 보존→원인 수정 시 빠진 실행만 재시도 또는 unresolved. 필수 미완료에서 승인·최종 판정으로 건너뛰지 않는다. |
| 쟁점 분열·한도 도달 | 원 주장·반박→남은 한도 안 보충→최종 판정→unresolved와 실제 범위. 상한을 증명된 불일치로 만들지 않는다. |
| 조건부 성과 | H→P의 해설·형식 동일성→K 편입→목표 P 불충족→H 관련 또는 다른 접근. 부분 K를 삭제하거나 P를 해결로 표시하지 않는다. |
| 동시 편입 | A의 고정 검사 중 B 편입→최신 research에 A 변경분 재적용→바뀐 전제 재검사→최신 runtime과 원자 공개. B를 옛 트리로 덮어쓰지 않는다. |
| 로컬 종료·원격 미정산 | 권한 회수→효과 통로 차단·로컬 종료→실제 결과에 맞게 ended→원격 예약 별도 대조. 독립 자원과 과제 처분까지 영구 점유하지 않는다. |
| 외부 행동 중 소실 | prepared→호출 여부/결과 불명→unknown→외부 대조. 부재한 외부 ID나 사용자 취소를 미호출 증거로 쓰지 않는다. |
| 해답 개정·외부 거부 | 현행 solution_basis·요구별 결과→거부 접수/내부 검토→근거 정지 시 새 외부 행동 차단→새 해설·감사→요구 재대조. 옛 완료의 자동 승계가 없다. |
| 청소·저장 결함 | 종료·원자료 보존 뒤 정확한 공간 청소. 청소 실패는 degraded, 권위 참조·중앙 상태 손상은 실제 영향 범위의 blocked 또는 검사 incomplete다. |

이 표는 본문의 상태·소유자·입력·후속을 따라 수행한 문면 검토다. 실제 프로세스나 모델을 실행한 로그가 아니다. 외부 검증과 구별해 자체 대조의 한계를 남긴다.

## 7. 검증과 정본 전환의 경계

문서 검증기는 기준 사본의 해시, 원문 구간·벡터 대응의 전건성, 새 소유 절의 실재, 표와 명시 anchor·로컬 링크, 벡터 번호, 정의 대응과 패치의 적용 가능성을 확인한다. 그 실행 결과는 검증.json이 소유한다. 행·링크·구문 검사로 의미 보존이나 연구 효능을 자동 입증하지 않는다.

문서 검사는 오류 없이 통과했다. 검사 대상은 기준 사본 4개, 원문 대응 292개 구간, 기존 벡터 246개와 새 벡터 112개, 원 정의 108개와 개정 정의 103개다. 로컬 참조와 표·명시 anchor·동기화 패치도 검사했다. 첫 실행에서 나온 생성 파일의 Windows 개행 차이는 생성기를 LF로 고쳐 해결했다. 검사기의 자체 출력 링크는 이번 실행이 생성하는 파일로 처리하며 출력 쓰기가 실패하면 성공을 반환하지 않는다.

Git의 core.autocrlf 설정이 새 체크아웃에서 기준 해시를 바꾸지 않도록 관련 현행 문서 넷에는 LF를 지정하고, 이 감사 디렉터리의 사본·산출물은 바이트를 그대로 보존한다. 패치의 빈 문맥 행에 있는 공백은 unified diff 문법이므로 그 파일에만 whitespace 검사를 제외하고 git apply --check로 형식을 검사한다.

동기화.patch는 기준 CONTEXT.md와 지도 컨텍스트에 적용 가능한 수정안이다. 현재의 통합-설계.md, 루트 CONTEXT.md와 지도 컨텍스트를 작업 도중 교체하지 않았다. 정본 전환 때는 확정한 위임과 계약 식별자, 정의·지도 동기화를 함께 적용해야 한다. GitHub 이슈와 외부 앱에는 이번 작업으로 메시지나 변경을 보내지 않는다.

실제 어댑터·공급 제약·검토 강도·큰 제안의 분할·맥락 승계·규범 schema/codec/wire는 초안 18절의 후속 검증 범위다. 이 작업의 문서 완결성과 그 능력의 실증을 혼합하지 않는다. Q1의 회신과 문서 검사 결과가 남으면 그 상태를 그대로 보고한다.
