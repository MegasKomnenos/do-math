# 통합 설계 재구성 검토

[기존 설계](../통합-설계.md)의 내용을 전수 대조해 [4차 초안](../통합-설계-초안.md)을 작성했다. 기존의 유효한 연구·판정 기준을 보존하면서 실행 구조는 타당한 새 방식으로 재구성했다. 이 기록은 최종 판단과 검증 범위를 요약한다.

## 주요 선택

| 내용 | 반영한 계약 |
|---|---|
| 실행과 저장 | 단일 기계 실행기·상태 머리와 공통 실행 생명주기로 권한·예약·종료·후속을 연결한다. |
| 후보와 과제 | 후보는 풍부하게 보존하고 실행할 일에 작업 계약을 만든다. 사용자 결정 대기는 같은 과제의 남은 의무로 유지할 수 있다. |
| 탐색과 진전 | 진행 작업과 별개로 탐색을 주기적으로 재고하고, 작업자와 점검자가 기대 변화·진전 신호·필수 증거를 공유한다. |
| 지식과 입력 | OKF의 기본 필드·항해와 안정 ID를 유지한다. 원자료 조회·검증된 쟁점 승계로 입력을 구성하며 의미와 실제 확인 범위를 구별한다. |
| 수학 검토 | 기본 세 관점·조건부 전문성·전체 연결을 확인한다. 전건 match·무쟁점은 직접 집계하고, 쟁점은 총한도 안 보충·독립 최종 판정으로 처리한다. |
| 산출물과 목표 | 사람이 읽는 수학 해설을 주 산출물로 삼고, 형식 타당성·해설 동일성·목표·추가 감사를 구별한다. 정확한 부분 결과는 보존한다. |
| 학술 검증 | 현재 해답과 요구 판본별로 완료·외부 거부·해소를 기록하고, 해답 개정에 옛 완료를 자동 승계하지 않는다. |
| 위임 | 명시한 일반 조건과 사용자가 승인한 사례 기반 위임을 같은 허가 계약으로 표현한다. 유사성 판단이 새 권한을 만들지 않는다. |
| 역할 문서 | 공통 정의의 소유를 유지하고 필요한 계약·정의·도구·원자료를 해당 판단 전에 전달한다. |

사례 기반 위임의 실제 범위·제외·자원·외부 효과는 인스턴스 생성 때 사용자가 정한다. 두 위임 형태 중 하나를 보편 설계의 전역 기본값으로 골라야 한다고 보고 제시했던 질문은 이 구조로 해소했다. 사용자 회신이나 승인을 받은 것으로 처리하지 않았다.

## 검토와 검증 범위

기존안 192개 절 구간과 3차 초안 100개 절 구간, 기존 테스트 목적 246개를 대조했다. 최종 초안에는 117개 검증 시나리오를 두었다. 이 숫자는 자료의 대조 범위이며 수학적 보증이나 실운전 시험의 통과 수가 아니다.

문면 검토에서는 착수 승인과 실제 시작의 결속, 과제의 계약 개정과 새 연구 의무, 대기 중 미종료 요청, 외부 ID의 생성 시점, YAML 정규 바이트, 초기 검토 미완료의 처리, 학술 거부의 기계 입력, 완료 판정의 소유자, 초기 프로필의 사전 검사와 판정 효력의 최초 생성을 보강했다. 정상·대기·실패·재개·동시 편입·해답 개정의 시간선도 대조했다.

작성 당시 문서·참조·표·원문 대응·벡터·정의 대응·동기화 패치 검사는 통과했다. Git 색인에서 꺼낸 관련 자료 22개의 바이트도 당시 검사한 파일과 일치했다. 실제 모델·격리·Lean·복구·연구 효능의 실운전 시험과 별도 독립 AI 검증은 수행하지 않았다. 해당 능력과 규범 스키마의 실물 검증은 초안 18절의 후속 범위다.
