## 수리 설계

수리 단위 `U1`은 기존 상태 구조를 바꾸지 않는다. `runtime.local_package_managers`, 후보별 조회 구조, `environment-changes.json`의 필드도 새로 늘리지 않는다. `U1`은 설치 시도 조건과 검증 범위를 아래 다섯 요구로 닫는다.

1. SAT 후보 집합은 `minisat`·`cadical`·`kissat`·`cryptominisat`과 탐색 중 발견한 추가 후보 전건이다.
2. 후보별 조회 구조는 후보 전건의 확보 가능성을 도출한다.
3. 확보 가능 후보 전건은 확보 가능성 판정에 사용한 기존 로컬 패키지 관리자와 패키지 ID로 설치를 시도한다.
4. 설치를 시도한 후보마다 설치 사건을 기록한다. 설치 시도 뒤에는 실행 파일 탐색과 SAT·UNSAT DIMACS 스모크 테스트를 다시 실행한다.
5. 설치 실패는 오류·대체 수단·갱신 트리거로 `FAIL`을 완결한다. 확보 불가 후보는 후보별 조회 근거를 남기고 설치하지 않는다.

행 `2.6.9.2`의 완료 기준 (2)·(3)·(5)·(6)·(8)과 임무 5~7이 다섯 요구를 실행한다. 행 `2.6.9.3`의 완료 기준과 「불변식 재료」가 다섯 요구를 독립 검증한다. 후속 충족성 렌즈 `2.6.9.4.1`은 요구마다 두 행의 완료 기준을 다시 지목한다.

## 실측 근거

현재 작업 디렉토리의 `toolchain_smoke.py`는 SAT 후보 4종을 고정 사전에 둔다. `collect_report()`는 각 후보를 `_solver_row()`로 보낸다. 그러나 후보별 패키지 관리자 조회와 설치 시도는 아직 구현하지 않았다.

```text

winget search cadical -> 일치 항목 없음
winget search kissat -> 일치 항목 없음
winget search cryptominisat -> 일치 항목 없음
```

현재 환경에서는 `minisat`만 확보 가능하다. 따라서 기존 기준을 실행하면 우연히 현재 확보 가능 후보를 덮을 수 있다. 그러나 기준은 실행 환경이 달라지거나 추가 후보를 발견해도 후보 전건을 덮어야 한다. 특정 후보 이름으로 설치 대상을 제한한 기존 기준은 이 요구를 보장하지 않는다.
