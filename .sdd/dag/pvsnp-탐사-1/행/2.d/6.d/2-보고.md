## 이월 사슬

행 2.6.3·2.6.4·2.6.6은 기준선의 설치 명령, exit code, 버전, 스모크, `PASS|FAIL`, 대체 수단, 갱신 트리거를 소비한다. 행 2.11은 S1의 PASS 도구만 직접 호출한다. FAIL 도구에는 기준선의 대체 수단만 쓴다.

## 잔여·처분

`pip check`는 기존 KFP 계열 3종과 OR-Tools가 요구한 `protobuf 6.33.6` 사이의 제약 충돌로 exit code 1이다. 승인 패키지 4종의 최소 스모크는 통과했다. MiniSat·CaDiCaL·Kissat 실행 파일은 FAIL이며 기준선의 갱신 트리거 전까지 대체 수단을 쓴다.

## 반증 의무

초기 기준선은 승인 Python 패키지와 solver 실행 파일이 없다고 적었다. 재실측과 승인 범위 설치 뒤 Python 패키지 4종, Z3, CryptoMiniSat가 PASS로 바뀌었다. 그 밖의 파견문·입력과 어긋난 지점은 없음.

# 증거 부록

## E1. TDD 5단계

1. virtual interface로 `collect_report()`와 CLI를 만들었다.
2. Python 패키지 4종, Z3 분리 판정, SAT 후보 4종, 실제 명령 필드, 로그 생성을 검사하는 테스트를 만들었다.
3. RED에서 `Ran 3 tests` 뒤 `FAILED (failures=1, errors=2)`와 exit code 1을 관찰했다. 원인은 `NotImplementedError: TDD virtual interface`였다.
4. 실제 import, subprocess, DIMACS·SMT-LIB 입력, JSON 로그 생성을 구현했다. 설치 자체의 RED는 구조상 불가능하므로 미관찰이다.
5. 최종 GREEN에서 `Ran 4 tests in 17.857s`, `OK`, exit code 0을 관찰했다.

## E2. 최종 스모크 출력

명령은 `python experiments/pvsnp/smoke/test_toolchain_smoke.py`와 `python experiments/pvsnp/smoke/toolchain_smoke.py --evidence-dir experiments/pvsnp/smoke/evidence`다. Python 패키지 4종, Z3, CryptoMiniSat는 PASS다. MiniSat·CaDiCaL·Kissat는 FAIL이다. 원시 stdout·stderr·exit code는 겨냥의 증거 파일 3건에 있다.

## E3. 공식 배포 조사

공식 PyPI와 프로젝트 문서를 Python 패키지 4종에 사용했다. 공식 GitHub 릴리스를 실행 파일 후보 5종에 사용했다. Windows x64 사전 빌드가 있던 Z3 5.1.0과 CryptoMiniSat 5.14.7만 확보 가능으로 판정했다. 조사 중 추가 Windows x64 SAT 실행 파일 후보는 없었다.

## E4. 환경 변경 명령

환경 변경 명령은 I-PY, I-Z3, I-CMS 3건이다. 세 명령의 exit code는 모두 0이다. `pip check`는 별도 환경 정합성 검사이며 exit code 1이다. 기준선 2절과 원시 로그의 `environment_change` 필드가 명령·대상·exit code를 연결한다.

## E5. 안전 기준 전수 검사

검사 범위는 Git diff의 추가·변경 파일 7건, 원시 로그 3건, 환경 변경 명령 3건이다. P5′ 밖 설치, 형식 증명 도구 설치, WSL, 컨테이너, 새 패키지 관리자, 소스 빌드, 크리덴셜 값, 개인 식별 정보, 유한 스모크의 복잡도 계급 주장은 각각 0건이다. 로컬 경로는 `%LOCALAPPDATA%`와 `%TEMP%` 표기로 정규화했다.
