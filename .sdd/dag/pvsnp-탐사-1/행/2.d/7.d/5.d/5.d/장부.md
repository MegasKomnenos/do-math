## 운영 기록

- **§2.1 재량 — 0단계 git 상태 전제의 do-dag 판독.** 0단계 착수 시 `git diff --cached --quiet`(색인 비었음, exit 0)와 산출물 7개 경로의 `git status --short`는 전건 `??`(미추적, 신규)를 냈다. 이는 앞선 파견(행 `2.7.5.4`)이 아직 커밋되지 않은 정당한 산출이다. `계약/검증런.md` 「실행 규율」은 검증런이 라운드 커밋을 수행하지 않으며 커밋은 노드 싱크가 진다고 정한다. 이 do-dag 적용에서 산출물은 구조적으로 라운드 1 착수 전까지 항상 미추적 상태이므로, SKILL.md §7 0단계 7·8항의 "변경이 있으면 시작하지 않는다"는 전제(커밋 기준선 존재)를 그대로 적용하면 do-dag 검증런이 원천적으로 착수 불가능해진다. §3의 "어긋나는 자리는 커밋 하나"라는 문언을 이 전제의 조정까지 포함하는 것으로 읽어, 미추적이되 이번 산출물 목록과 정확히 일치하는 신규 파일 상태를 착수 저지 사유로 보지 않고 라운드 1을 시작했다.
- **작업 격리 — 수리자 3기 파견의 불필요한 worktree 격리.** 수리자 3기를 `Agent` 도구로 파견할 때 `isolation: worktree`를 실수로 지정해, `C:\math` 저장소에 새 git worktree 셋(`.claude/worktrees/agent-*`)이 만들어졌다. 세 수리자 모두 동결문·사본·기준 원문·산출 파일 경로를 절대 경로로 받아 그 경로들이 실제로는 이 격리 worktree 밖(주 저장소 `C:\math`와 노드 worktree)을 가리켰으므로 내용에는 영향이 없었으나, 두 기(`aa369d9a8c73fde86`·`ab9de06ec7d775e20`)는 격리 worktree의 `Write`·`Edit`·heredoc이 그 밖 경로 쓰기를 거부해 단일행 `printf` 추가로 우회했다. 3기 완료 뒤 `git worktree remove`를 시도했으나 이미 자동 정리되어 있었다(빈 worktree는 정리됨). 병합자 4기와 심사자 파견부터는 `isolation`을 지정하지 않았다.
- **§8 신호 7 — 심사 기 1·2·배치 1의 3회 결손.** 두 심사자(codex `gpt-5.6-terra` medium)가 같은 서식 결손을 3회 연속 냈다 — 승인 처분이 「사용자에게 올린다」인 항목(R1-07/R1-19)에 `### 상신안` 칸을, 「호출자에게 전달」인 항목(R1-13)에 `### 검토전개 실익` 칸을 두지 않았다(`계약/심사.md` 「산출 서식」). 1·2회차는 같은 파견문으로 그대로 재파견했다(§5.3 7항). 3회차도 같은 결손이 나 §8 신호 7 문턱(같은 기·배치 3회 결손)에 닿았다. 자체 판단(오판 비용 낮음 — 서식 보정이지 판정 내용 변경이 아님 / 되돌리기 비용 낮음 / 판단 가능성 있음 — 두 독립 모델이 동일 패턴으로 반복해 원인이 지시문 강조 부족임이 명백함)으로 상신하지 않고, 4회차 파견문에 `계약/심사.md`의 해당 요구를 축자 재인용한 서식 재확인 문단을 추가해 재파견했다. 4회차는 두 기 모두 exit 0으로 통과했다. 결손 3회분 산출·반환·로그는 `라운드1/_결손[2/3]_*` 접두로 보존했다.
