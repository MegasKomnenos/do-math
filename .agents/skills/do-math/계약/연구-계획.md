# 연구 계획

## 목적

고정 snapshot의 제공 후보를 비교해 수행할 작업·순서·보류·준비 요청을 선택한다.

## 판단

현재 상태가 ready인 후보 전건을 선택 또는 보류한다. selections에는 선택한 작업의 정확한 ID만 실행 순서대로 넣고, deferred에는 나머지 ready 작업의 ID와 보류 이유를 넣는다. 같은 작업을 양쪽에 넣거나 설명문을 ID 배열에 넣지 않는다. 계약이 승인된 작업의 증명이 아직 없다는 사실은 선택을 막는 이유가 아니다. 그 증명을 만드는 일이 수행자의 과제다.

이미 연구 결과를 반환한 assessing·waiting 과제에만 task_assessments를 작성한다. 완료 기준의 원문을 criteria_results에 정확히 복사하고 각 기준의 충족 여부와 실제 근거를 판단한다. 수행 전 과제의 완료를 미리 판정하지 않는다. 계약 저작자와 다른 관점에서 실제 결과가 기대와 어떻게 달랐는지와 재사용할 지식·남은 차이를 대조한다.

파일 산출을 요구한 기준은 `tasks[].results[].output_files`의 local_path 원문을 읽고 판정한다. 수행자의 보고만으로 파일 내용이 기준을 충족한다고 간주하지 않는다. criteria_results의 evidence에는 확인한 파일·결과 좌표와 기준을 충족하는 이유를 적는다.

진전은 현재 결과가 목표 해결에 어떻게 도움이 됐는지로 평가한다. 결과 없음·실패한 방법도 계약의 조사 범위를 실제로 끝냈으면 완료할 수 있다. 미완료 기준이 남으면 incomplete로 준비에 돌린다. closed는 명시적 의무 이전·철회가 있는 과제에만 사용한다. 보류한 과제의 이유와 다시 볼 조건을 적는다.

수학적 목표가 해결됐으면 현재 academic_requirements에 연결된 과제만 수행한다. 각 과제의 solution_basis와 요구 판본을 확인하고 완료 기준별 증거를 평가한다. external_rejections의 원문은 K의 형식 타당성과 따로 검토한다. 확보된 근거로 거부를 해소할 수 있으면 `activity-extensions.json`에 academic_resolutions=[{id,decision:"resolved",evidence}]를 적는다. 판단할 수 없으면 unresolved와 필요한 조사를 반환한다. 실제 결함을 확인했으면 어느 지식·해설·목표 판정이 영향을 받는지 준비 요청에 명시한다.

## 산출과 실패

선택 ID, 보류 이유, 준비 요청, 목표 감사 요청과 수행한 과제의 완료 판정을 제공된 출력 스키마에 맞춰 반환한다. 목차 밖 후보를 직접 배정하지 않는다. 입력이 부족하거나 선택 근거가 불명확하면 그 범위와 다음 준비 요청을 반환한다. 목표가 충족됐을 가능성은 목표 감사 요청으로 넘기며, 계획자가 목표 해결을 확정하지 않는다.
