# 모델 배정과 동시실행 예산

연구 계획은 현재 목표와 근거를 비교해 수행할 작업과 순서, 병행 관계를 정한다. 각 실행에는 그 작업의 난이도와 중요도에 맞는 모델을 배정한다. 기계 실행기는 배정된 모델의 슬롯과 착수 조건이 갖춰진 요청을 시작하며, 여러 독립 실행의 결과를 한 연구 정본에 차례로 반영한다.

## 인스턴스별 기본 구성

새 인스턴스는 다음 구성을 사용한다. 모델 대응은 `tier_models`, 모델별 동시 세션 수는 `session_limits`로 바꾼다. 설정의 모델 이름은 아래 세 이름으로 제한하지 않는다.

| 배정 등급 | 기본 모델 | 운영 세션 | 작업 세션 |
|---|---|---:|---:|
| 상 `high` | `gpt-6-astra` | 3 | 3 |
| 중 `medium` | `gpt-5.6-sol` | 3 | 3 |
| 하 `low` | `gpt-5.6-terra` | 3 | 3 |

기본값은 인스턴스 하나에서 운영 9개와 작업 9개의 동시 세션을 허용한다. 여러 인스턴스가 한 용량을 공유하는 설정은 아니다. 각 값은 0 이상의 정수이며 0은 그 모델·예산의 새 실행을 대기시킨다. 같은 모델을 여러 등급에 연결해도 용량은 모델 이름 하나에 설정된 값으로 센다.

한 세션은 한 번 시작해 종료하는 로컬 AI 실행이다. 준비 중인 요청은 슬롯을 사용하지 않는다. 시작을 예약한 실행은 `starting`, `running`, `stopping` 동안 같은 슬롯을 점유하고 로컬 종료를 확인한 뒤 반환한다. 제출·실패·취소 뒤 반환된 슬롯은 다음 실행이 재사용한다. 외부 입력을 기다리기 위해 결과를 반환한 과제는 실행을 종료하고, 과제의 대기와 다음 의무는 기록으로 유지한다.

운영과 작업은 모델이 같아도 별도 용량이다. 작업에 남은 운영 슬롯을 자동으로 빌려 주거나 그 반대로 처리하지 않는다. 독립 운영 담당도 이 인스턴스의 운영 슬롯을 사용한다. 이는 로컬 실행의 동시성 한도다. 누적 실행횟수·토큰·금액이나 공급자 내부 호출의 동시성 한도를 뜻하지 않는다.

## 난이도와 중요도에서 모델을 정한다

후보 준비는 과제의 질문·범위·필요한 판단을 바탕으로 난이도와 중요도를 각각 평가하고, 작업 계약 검토는 그 근거가 과제와 맞는지 함께 검토한다. 연구 계획은 현재 근거로 선택한 과제의 평가를 유지하거나 갱신한다. 두 축 가운데 높은 등급을 사용하며, 해당 역할에 설정된 최소 등급이 더 높으면 그 등급을 사용한다.

| 등급 | 난이도를 판단할 근거 | 중요도를 판단할 근거 |
|---|---|---|
| 상 | 새로운 증명 전략이나 표현을 찾아야 함. 여러 가정·정의·분야를 연결하며 접근의 성립 자체가 불확실함. 복잡한 의미 충돌을 해결해야 함 | 연구 방향이나 공용 판단을 좌우함. 잘못된 판단이 여러 후속 과제에 퍼짐. 목표 충족이나 핵심 수학적 동일성을 판정함 |
| 중 | 알려진 접근을 제한된 문제에 적용하되 여러 조건·예외를 비교하고 판단해야 함 | 한 과제 또는 제한된 후속 흐름에 영향을 주며, 오류를 확인하고 다시 수행할 경로가 분명함 |
| 하 | 입력과 처리 방법이 명확하고 국소적인 추출·정리·단순 대조가 중심임 | 영향이 국소적이며 원자료와 결과를 직접 대조해 수정할 수 있음 |

위 설명은 판단 기준이며 작업 이름만 보고 등급을 고정하는 목록이 아니다. 짧은 과제라도 핵심 가정이나 연구 전체의 선택을 바꾸면 중요도가 높다. 파일 수, 실행시간, 현재 빈 슬롯 수를 난이도나 중요도의 대용으로 쓰지 않는다. 모델의 자리가 없다는 이유로 평가를 낮추지 않는다.

평가는 `difficulty`, `importance`, 구체적인 `reason`으로 보존한다. 과제에 평가가 없으면 미평가 상태임을 드러내고 상 등급을 사용한다. 후속 계획은 실제 과제와 근거를 읽어 평가를 작성할 수 있다. 이 기본 배정 등급은 운용 정책이며, 모델 이름만으로 수학 성능의 우위가 실험적으로 검증됐다고 주장하는 근거는 아니다.

최초 계획을 열기 전에도 운영 판단이 필요하므로 역할별 최소 등급을 `role_tiers`에 둔다. 기본 상 등급은 후보 준비·연구 계획·의도 해석·동일성 검토·목표 감사·독립 운영 담당이다. 기본 중 등급은 작업 계약 검토·운영 점검·유지보수다. 연구 수행·보충 조사의 역할 하한은 하 등급이며 과제 평가가 실제 등급을 정한다. 과제나 점검 대상 실행의 요구가 역할 하한보다 높으면 그 요구를 적용한다. 역할별 설정은 인스턴스에서 바꿀 수 있다.

## 평가를 제출하고 전달한다

후보 준비와 연구 계획은 작업 공간의 `activity-extensions.json`에 `model_assessments` 배열을 적는다. 후보 준비는 같은 응답의 후보를 `task_title`로, 연구 계획은 이번 `selections`의 과제를 `task_id`로 지목한다. 같은 대상을 중복해서 쓰지 않는다. 각 항목에는 대상 필드와 아래 세 평가 필드만 사용한다.

```json
{
  "model_assessments": [
    {
      "task_id": "TK-현재-입력의-정확한-ID",
      "difficulty": "high",
      "importance": "medium",
      "reason": "기존 점화식의 항별 비교가 성립하지 않아 새로운 대응을 찾아야 한다."
    }
  ]
}
```

후보 준비에서는 위 `task_id` 대신 실제 후보 제목인 `task_title`을 쓴다. 실행기는 후보의 평가를 과제 계약에 결합하고, 연구 계획의 평가는 선택된 다음 실행 요청에 결합한다. 원 평가와 선택한 모델·등급·근거는 실행 기록에 남긴다. 요청이 대기하는 동안 같은 배정을 유지한다. 승인된 모델 대응 설정을 변경하면 미시작 요청은 현재 평가와 새 대응으로 다시 결합하며, 이미 시작한 실행의 모델은 그대로 유지한다.

## 우선순위와 실제 배정

연구 계획은 목표 기여, 기대 정보와 불확실성, 탐색과 집중 활용, 기존 결과의 재사용, 과거 성과·실패, 후보 사이의 중복·보완·독립·의존, 오래 기다린 작업, 현재 병행 작업과 자원을 함께 비교한다. 제공된 배정 후보 전건에 선택 또는 보류와 이유를 남기고, 선택한 과제를 실행 순서대로 반환한다. 용량을 모두 채울 의무는 없다. 높은 모델 등급이 곧 높은 연구 우선순위를 뜻하지 않는다.

선택할 작업 수는 동시 슬롯 수를 넘을 수 있다. 기계 실행기는 계획 순서대로 착수 조건과 해당 모델 슬롯을 검사한다. 앞 요청의 모델이 가득 차 있으면 그 요청을 원래 순서에 남기고, 독립된 자원으로 진행할 수 있는 뒤 요청을 검사한다. 같은 자원을 기다리는 앞 요청이 착수할 수 있게 되면 뒤 요청을 먼저 시작하지 않는다. 슬롯 부족 때문에 다른 모델로 우회하지 않는다.

실행기 내부의 운영 요청은 운영 요청끼리의 큐 진입 순서로 처리한다. 독립 운영 담당은 별도 예약 시점에 같은 운영 슬롯의 가용성을 검사한다. 현재 필요한 자원을 확보할 수 있는 가장 오래된 요청부터 시작한다. 자원이 막힌 요청을 건너뛰어 다른 운영 모델의 슬롯을 사용할 수 있다. 정지와 권한 회수는 운영 AI의 차례를 기다리지 않는 기계 제어다. 한 인스턴스에서 후보 준비와 연구 계획은 각각 하나만 진행하고, 같은 과제의 연구 수행도 한 번에 하나만 진행한다. 서로 다른 과제와 독립 검토 자리는 각자의 슬롯 안에서 병렬로 수행할 수 있다.

새 결과나 사용자 결정으로 기존 순서를 바꾸어야 하면 연구 계획은 `queued_work`에서 아직 시작하지 않은 요청을 읽는다. `activity-extensions.json`의 `queued_requests` 배열에 `request_id`, `decision`과 `reason`을 반환한다. `decision`은 `keep` 또는 `cancel`이며, 유지할 요청의 배열 순서가 그 요청들 사이의 새 순서다. 취소 요청을 제거한 뒤, 유지할 요청들이 원래 차지하던 위치에서 그 요청들만 새 순서로 교환한다. 언급하지 않은 요청은 이 교환에 참여하지 않는다. 이미 시작했거나 종료된 요청에는 이 처분을 적용하지 않고 미적용 이유를 남긴다. 취소는 요청의 수행을 철회하는 것이며 과제 완료나 과제 의무의 삭제가 아니다.

## 병렬 실행과 결과의 반영

실행마다 별도 `runs/<실행 ID>/workspace`에서 고정 입력과 자기 산출을 다룬다. 입력 스냅샷과 계약·지식·원자료·허가의 적용 전제를 기록하고, 결과의 원문과 파일은 실행별 산출 묶음으로 보존한다. 모델 호출은 병렬로 진행하지만 실행 상태의 변경과 연구 정본의 갱신은 실행기 하나가 수행한다.

돌아온 결과에는 스키마와 참조·권한·의존 전제의 현재성을 검사한다. 관련 없는 결과가 먼저 도착했다는 이유로 폐기하지 않는다. 계획은 자기 입력에 있던 후보를 전건 처분하고, 새로 준비된 후보는 후속 계획으로 연결한다. 실제로 바뀐 계약이나 효력에 의존한 결과는 현재 근거로 다시 판단할 담당에게 돌린다. 과제 완료·수학적 동일성·목표 충족은 각 지정 AI가 판단하고, 실행기는 그 판정을 정해진 상태 전이로 반영한다.

작업 공간은 경로와 입력의 분리다. 현재 로컬 권한 모드가 다른 호스트 경로의 접근을 기술적으로 차단한다는 뜻은 아니다. 같은 단계의 독립 검토자에게 동료의 중간 결과를 제공하지 않는 기존 입력 경계는 병렬 실행에서도 유지한다.

## 설정 변경과 기존 인스턴스

한도를 현재 점유보다 낮추면 해당 모델의 새 배정을 기다리게 한다. 이미 실행 중인 세션을 강제로 종료하는 지시로 해석하지 않는다. 실행 종료까지 원하면 별도의 정지 제어를 사용한다. 슬롯 반환 또는 허용된 설정 변경 뒤 대기 요청을 다시 검사한다. `capacity_waiting`은 자원 대기이며 연구 완료나 오류가 아니다.

기존 실행횟수 예산 인스턴스는 그 계약을 유지한다. 새 세션 예산을 명시한 `configure`로 전환하며, 기록된 실행횟수와 산출 이력을 보존한다. 호환 운전에서는 `session_limits=null`, `work_calls`·`operations_calls`와 구 모델 설정을 사용한다. 새 설정 예시, 전환 명령과 상태 필드는 [CLI 실행 계약](CLI-실행-계약.md)의 설정 계약을 따른다.
