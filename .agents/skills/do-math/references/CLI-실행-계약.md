# do-math CLI 실행 계약

이 문서는 `do-math-cli/1` 실행기의 구체적인 운전·기록 계약이다. 통합 설계 0절에서 위임한 실익 판단에 따라 채택했다. 통합 설계의 연구 목적, 형식 타당성·해설 동일성·목표·허가·실행 상태의 구별, 원자료 보존과 연구 결과의 환류를 실제 CLI 흐름으로 구현한다. 과거 `do-math-draft/*/9`의 전체 wire 형식과 상태 벡터를 구현했다는 의미는 아니다.

현재 실행기는 한 Windows 호스트에서 인스턴스별 단일 writer lock을 가진다. 각 AI 실행은 새 Codex 세션과 작업 공간을 사용한다. 실행은 순차로 배정하며 독립 검토도 서로의 이번 결과를 받지 않는 별도 세션에서 순차로 수행한다. 이 구조는 동시 실행의 공유 ACL 문제를 해결하기 위한 별도 backend 없이 역할의 분리와 결과 전달을 구현한다. 파일시스템 전체의 읽기 불가능성이나 모델 오류의 통계적 독립성을 보증하지 않는다.

영속 상태는 한 Git ref `refs/heads/do-math/<instance_id>`에 있다. `research/instance.json`은 목표·정책·설정·지식·관계·목표 판정을, `runtime/state.json`은 과제·활동·실행·대기 요청·다음 작업·사용자 입력을 보존한다. 두 JSON은 하나의 커밋으로 갱신한다. 입력·모델 출력·실행 증거·Lean 소스와 검사 결과는 `runtime/artifacts/<bundle_id>/`에 불변 바이트로 저장한다. 초기 커밋은 부모가 없고 후속 커밋은 직전 상태 하나를 부모로 가진다. 작업 저장소의 체크아웃이나 일반 브랜치를 연구 상태로 사용하지 않는다.

외부 CLI의 pause·resume·input·configure·request는 작업 공간의 control inbox에 요청을 기록한다. 이 파일은 요청을 전달하는 통로이며 정본 상태가 아니다. 실행기만 요청을 적용해 Git 상태를 갱신한다. 실행기가 없을 때 CLI는 같은 writer lock을 얻어 제어 요청만 적용하며 모델을 호출하지 않는다. 실행 중인 작업은 pause·close 요청을 관찰하고 Job 전체를 정지시킨다.

요청을 접수한 뒤 대상 과제가 이미 배정됐거나 인스턴스가 종료되는 등 전제가 바뀌면 그 요청을 이유와 함께 거부한 것으로 기록하고 다음 요청을 처리한다. 낡은 요청 하나가 inbox를 영구히 막지 않는다. 완료·종결 상태는 pause·resume으로 다시 열지 않는다.

| 단계 | 실제 소비자와 전제 |
|---|---|
| 후보 준비 | 목표·정책·이전 결과에서 질문·범위·완료 기준을 가진 작업을 제안한다 |
| 계약 검토 | 작성 실행과 다른 실행이 approved·revision_required·unresolved를 반환한다 |
| 작업 선택 | ready 과제 전건을 선택 또는 보류하고, 이미 반환한 과제의 완료 기준을 평가한다 |
| 수행·보충 조사 | 실제 보고·부분 결과·Lean 제안·관계·남은 질문을 제출한다. 제출은 인증이 아니다 |
| 형식 검사 | 정확한 Lean 소스를 실제 컴파일하고 지정 선언의 공리 의존을 검사한다 |
| 동일성 검토 | 제안 생성 시 고정한 수의 별도 실행이 명제·해설·요약·가정·형식의 대응을 전건 검토한다 |
| K 편입 | 형식 소스 해시와 검토 대상이 일치하고 필수 검토가 모두 scope_complete·match일 때 편입한다 |
| 목표 감사 | 별도 감사들이 현재 목표와 결과를 판단한다. 수학 목표는 K 없이 해결됐다고 기록하지 않는다 |
| 다음 연구 | 미완료·수정 필요·남은 질문을 준비와 계획에 제공한다. 같은 계약의 완료와 목표 해결을 구별한다 |

현재 동일성 검토는 고정한 검토 슬롯의 전면 검토와 전건 동의를 사용한다. 불일치·미해결은 근거를 보존하고 다음 계획의 수정·조사로 돌려준다. v9의 별도 쟁점 정리·답변·세 심사자 왕복과 검토 자리의 전체 대화 복원을 추가로 운전하지 않는다. 새 실행은 보존한 명시적 입력·판정·근거를 받는다. CLI 내부 압축과 비공개 추론의 복원을 보증하지 않는다.

각 역할 입력은 SKILL·GLOSSARY·역할 계약 전문, 고정 snapshot의 목표·정책·과제·원자료 좌표·지식 목차와 필요한 대상 원문, 출력 JSON Schema를 포함한다. 상세 지식과 원자료는 자기 작업 공간의 input 사본에서 읽는다. 이번 독립 검토 묶음의 동료 판정은 숨기되, 이전 단계에서 완료된 검토는 후속 계획과 목표 감사의 근거로 제공한다. 과거 수행 보고의 예정 상태와 이후 검사의 실제 결과를 구별한다.

작업과 운영의 예산은 누적 CLI 실행 시도 횟수로 분리한다. 실패·중단된 시도도 횟수에 포함한다. 계약 검토·연구 수행·보충 조사·동일성 검토·목표 감사는 작업 예산을, 준비·선택·의도 해석·운영 점검·AI 유지보수는 운영 예산을 사용한다. Lean은 기계 실행이며 AI 횟수를 사용하지 않는다. 호출 시간·한 번의 run 시간·연구 회차·입력 바이트 상한을 별도로 집행한다. CLI가 반환한 토큰 사용량은 종료 뒤 실제 관찰값으로 저장하며 공급자 내부 호출별 예약, 실시간 토큰 상한, 원격 처리 종료로 표현하지 않는다.

구조·참조 오류가 있는 모델 출력은 기본 한 번까지 오류와 이전 출력을 제공하여 수리하게 한다. `max_output_repairs`로 그 횟수를 바꿀 수 있고 모든 수리 실행은 해당 예산을 사용한다. 실행 실패는 원자료를 보존해 운영 점검에 넘기며, 진단에 따른 retry는 진단 근거를 새 입력으로 추가한 한 번의 재시도다. 사용자 정지는 자동 재시도하지 않는다. 입력 부족·예산 소진·정지·실행기 소실은 수학적 불일치로 바꾸지 않는다. 소실된 실행은 미완료로 기록하고 명시적 재개 뒤에 진행한다.

Lean의 허용 공리는 `propext`, `Classical.choice`, `Quot.sound`다. `sorryAx`와 그 밖의 공리에 의존하면 K에 넣지 않는다. 검증한 실행파일·판본과 소스 해시를 결과에 보존한다. Lean 소스는 실행 가능한 프로그램이며 이 검사는 악성 소스의 모든 호스트 효과를 격리하는 장치가 아니다. 컴파일러와 자식의 시간 초과 회수는 Windows Job으로 수행한다. 외부 공개·메시지 전송·결제 같은 효과는 이 연구 흐름의 자동 단계에 포함하지 않는다.

`query`·`read`는 정확한 snapshot과 내용 해시를 반환한다. 페이지 cursor는 snapshot과 질의·방향·마지막 기록에 결박되며 현재 머리가 바뀌어도 같은 판본을 이어 읽는다. 빈 결과, 존재하지 않는 기록, 읽기 오류를 구별한다. 관계는 방향과 근거를 가진 연구 연결이며, 연결 경로만으로 수학적 함의나 동일성을 부여하지 않는다.

`check`는 저장한 상태·참조·완료 기준·검토 실행과 판정의 결속을 검사한다. 이 명령은 Lean 재검증이나 새로운 의미 판정을 수행하지 않는다. 구조 검사 통과, 모델 실행 종료, 과제 완료, K 편입, 목표 해결은 상태와 보고에서 서로 다른 값으로 유지한다. 기본 한도나 검토 수를 바꾸면 새 동작의 비용과 실제 보증에 맞게 해석한다.
