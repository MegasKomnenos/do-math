# 개발 원칙

do-math는 프리알파 프로토타입이다. 이 디렉토리는 현재 구현과 계약 하나만 지원한다.

- 설계를 바꾸면 구현·호출부·스키마·테스트·예시·문서를 같은 변경에서 새 계약으로 교체한다. 구판 호환을 위한 이전 구현·이름 별칭·래퍼·구형 인자·무시되는 설정·버전별 분기·마이그레이션 경로를 남기지 않는다.
- 과거 실험 인스턴스·저장 기록·산출물은 호환성 요구가 아니다. 새 계약으로 다시 초기화해 검증한다. 예전 자료를 읽기 위한 기본값 보충이나 자동 변환을 추가하지 않는다. 실제 실험 자료의 삭제는 해당 작업의 범위에 따라 처리한다.
- 테스트도 현행 계약을 직접 구성한다. 구형 fixture나 인터페이스를 살리려고 제품 코드에 예외를 넣지 않는다. 폐기한 기능만 검사하는 테스트는 제거하고, 유지하는 기능의 검사는 새 계약에 맞춘다.
- 현재 입력의 구조·참조·권한·증거·현재성 검사는 유지한다. 같은 연구 안에서 달라지는 과제·정책·프로필 판본과 실행 이력은 연구 의미의 일부이며, 소프트웨어 구판 호환성과 구별한다. 형식 검사는 저장·입력 경계에 모으고 내부 로직에서 제품 버전을 반복 확인하지 않는다.
- 사용자가 구체적인 대상과 기간을 지정해 호환성을 명시적으로 요구한 경우에만 예외를 둔다. 미래 사용자나 이전 기록의 존재를 추측해서 호환 계층을 만들지 않는다.

검증은 `python scripts/run_tests.py`의 관련 그룹부터 수행한다. 같은 입력에서 이미 통과한 unit·integration 시험은 다시 실행하지 않고 캐시된 통과로 보고된다. 입력은 두 부분이다. 하나는 시험 모듈을 뺀 스킬 트리, 저장소의 `docs/do-math`, Python·git 판본이다. 다른 하나는 그 시험 모듈과 그 모듈이 import하는 시험 모듈이다. 그래서 시험 파일만 고치면 그 파일을 읽는 시험만 다시 돈다. 따라서 기준선이나 변경 없는 재확인을 위해 같은 시험을 다시 돌리지 않는다. 강제로 다시 실행하려면 `--no-cache`를 준다. 구조 검사는 `python scripts/probe_cli.py --skill-only`를 사용한다. graphify 그래프 갱신은 상위 AGENTS.md에 따라 명시적인 갱신 요청이 있을 때만 수행한다.
