# 계약: 싱크

싱크가 적재한다.

범위의 수렴점이다. 할 일이 없으면 파견표의 **파견문·완료 신호·모델 세 열을 함께** `—`로 두고 파일을 만들지 않는다.

공통 최종 반환 계약을 그대로 따른다. 싱크도 첫 줄에 `DONE`·`DONE-비준`·`상신`·
`예외` 중 하나만 쓴다. `예외`의 코드는 `싱크비완결`이다. 공통 필드를 모두 쓴 뒤
`결산: <절대 경로>`를 추가한다. 상세 결과는 결산 frontmatter `상태:`에만 기록한다.
완결 상태의 싱크는 결산 `단계: 종결`까지 마친다.

싱크 파견문에도 `명령:` 슬롯이 있다. 아래 절차의 `dag_marker.py`는 그 슬롯에 실린 마커 명령이고, 싱크는 그것을 축자로 받아 돌린다 — scripts 경로를 재도출하지 않는다.

**싱크는 둘로 갈린다.**

```전거 종결싱크판별식
요지: 행 번호에 마디가 없는 싱크 행이 국면 종결 싱크다

마디 없는 `싱크` 행(`z`)이 국면 종결 싱크이고, 마디가 있는 것(`X.z`)이 노드 싱크다.
노드 싱크는 노드 하나를 저장소에 들이고, 국면 종결 싱크는 국면을 닫는다.

**국면 종결 싱크는 정확히 하나일 때만 최상위 수렴이 선다.** 둘 이상이면 검산이
발견을 낸다.
```

## 노드 싱크 (결산)

노드의 싱크는 **결산**이다. 원칙 하나가 순서를 정한다: **되돌릴 수 없는 행위 앞에 그것을 막을 판정이 온다.** 판정 둘(귀속 대조·완료 기준)이 맨 앞에 오고, 공유 자원을 쥐는 임계구역은 병합에서 커밋까지로 최소화한다.

0. 검증런 전원 종료와 기각 보관 검토 완료를 확인한다. 기각 보관 파일의 항목 ID 전건이 기각 보관 검토전개 보고의 읽은 항목에 있음을 대조한다. 빠진 항목이 있으면 결산을 `상태: 완료미충족`·`단계: 판정완료`로 쓰고 첫 줄 `예외`, 둘째 줄 `코드: 싱크비완결`로 반환한다. worktree와 브랜치는 보존한다. worktree 좌표는 재도출한다 — 전사받지 않는다. 브랜치는 `dag/<국면>/<행번호>`이고, 경로는 메인 체크아웃에서 `git worktree list --porcelain`을 돌려 그 브랜치가 붙은 항목의 경로를 읽는다.
1. **귀속 대조** — worktree의 `git status --porcelain`·diff를 보고의 편집 귀속 표와 대조한다(실측기 `attrib`). 결과와 미귀속 편집을 붙잡아 둔다.
2. **노드 완료 기준의 전건 판정** — 각 항이 지명한 증거 실물을 연다. worktree가 살아 있으므로 그 안의 증거도 여기서 열린다. 결과와 미충족 항을 붙잡아 둔다.
3. **결산 파일을 만들고 `단계: 판정완료`를 기입한다**(아래 「단계 원장」). **원장이 첫 비가역 행위보다 앞선다.** 미귀속 편집이 있으면 `상태: 귀속불일치`로 쓰고 첫 줄 `예외`로 반환한다. 미귀속 편집이 없고 완료 기준이 미충족이면 `상태: 완료미충족`으로 쓰고 첫 줄 `예외`로 반환한다. 둘 다 통과하면 파견문이 허용한 완결 낱말을 `상태:`에 쓰고 계속한다. 앞의 두 반환에서는 병합하지 않고 worktree와 브랜치를 지우지 않는다.
4. **worktree 커밋** — `git -C <worktree> add -A && git -C <worktree> commit -m "<노드> 작업"`. 격리 안의 커밋은 grant 없이 선다. 커밋이 서면 곧바로 `단계: 격리커밋완료 <SHA>`.
5. **병합 자리 확보** — 셋을 순서대로 한다.
   - `<마커 명령> lease --acquire --owner <행번호> --minutes 30`. exit 1이면 다른 싱크가 병합 중이다. 결산을 `상태: 대기`로 바꾸고 첫 줄 `예외`로 반환한다. **메인 체크아웃에 손대지 않는다.**
   - lease를 쥔 뒤 메인 체크아웃의 인덱스를 실측한다: `git diff --cached --name-only`(스테이징)와 `git ls-files --unmerged`. 어느 쪽이든 비어 있지 않으면 결산을 `상태: 대기`로 바꾸고 lease를 반납한다. 첫 줄 `예외`로 반환한다. **미추적·비스테이징 변경은 판정에서 제외한다.**
   - `<마커 명령> allow --minutes 30 --reason "<노드> 병합"`으로 grant를 받고 출력된 ID를 붙잡아 둔다.
6. 메인 체크아웃에서 `git merge --squash dag/<국면>/<행번호>`. 마치면 결산 `단계: 병합완료`. **충돌은 봉합하지 않는다.** `git reset --merge`로 되돌리고 결산을 `상태: 병합충돌`로 바꾼다. lease를 반납한 뒤 첫 줄 `예외`로 반환한다.
7. 그 위에 M 노드·색인을 얹어 **하나의 커밋**으로 종결한다(`commit-harness` 정본 — 이 파견문이 절차를 복제하지 않는다). 커밋이 서면 곧바로 결산 `단계: 커밋완료 <SHA>`.
   - **commit-harness 위임의 범위** — 그 문서와 이 계약이 어긋나면 이 계약이 이긴다. 어긋나는 자리는 둘이다. 첫째, 4항의 worktree 커밋은 commit-harness 「결합 불변식」의 「작업 커밋」이 아니다 — 6항의 `git merge --squash`가 그 커밋을 부모로 달지 않고 8항이 브랜치를 지우므로, 그 커밋은 저장소 이력에 서지 않는다. M 노드는 이 7항의 커밋 하나가 진다. 둘째, do-dag의 노드 격리는 commit-harness 절차 1항의 「커밋·푸시를 위해 별도 브랜치를 만들지 않는다」 밖이다.
   - 스테이징 반경: 병합 인덱스 + M 노드·색인 + 이 노드가 편입하기로 확정한 파일 전건.
   - **이 커밋에 함께 서는 것 — 편입 집합.** 판별 술어: **이 커밋만 놓고 볼 때** 그 파일이 없으면 이 커밋의 변경이 왜 그렇게 됐는지 설명되지 않는 결정·규율 산출. 보존은 이 술어의 몫이 아니다 — 국면이 닫힐 때 메인의 이관이 런 디렉토리 전부를 저장소에 들인다(`SKILL.md` 「3. 종결 보고」). 여기서 미리 편입하는 이유는 **근거가 그것에 근거해 선 커밋과 같은 커밋에 있어야 하기 때문**이고, 국면 끝까지 미루면 중간 커밋들이 근거 없이 선다. 추적 집합은 착수 시 `git ls-files .sdd/`로 재도출한다. 편입 집합 중 추적 집합에 없는 것은 `git add -f`로 편입하고(`.sdd/.gitignore`의 `*`가 평범한 `add`를 막는다), 이미 있으면 확인만 하고 지나간다. 계수도 파일명도 문면에 박지 않는다.
   - 멈춤 조건: 편입 집합에도 추적 집합에도 없는 `.sdd/` 경로가 스테이징에 들면 커밋하지 않는다. 결산 상태를 `상신`으로 쓰고 공통 첫 줄 `상신` 뒤에 사유와 좌표를 추가한다. 두 집합 안 파일의 수정은 멈출 사유가 아니다.
8. `git worktree remove <worktree>` · `git branch -D dag/<국면>/<행번호>`. 결산 `단계: 회수완료`.
9. **이음새 전기 · 계약 이동 확인 · 잔여 경미 처분**. 계약 이동이 있으면 결산을 `상태: 계약이동`으로 바꾸고 첫 줄 `예외`로 반환한다. 파견표 상태 열은 오케가 쓴다.
10. **결산 본문을 채운다** — 아래 서식. 이 행의 완료 신호다. 단계 값은 아직 `회수완료`다.
11. `<마커 명령> clear-token --grant <발급받은 ID>`
12. `<마커 명령> lease --release --owner <행번호>`
13. **마지막 편집으로 `단계: 종결`** — grant 해제·lease 반납 뒤에 오른다. 11·12는 재실행이 무해하므로 `회수완료`에서 재개하면 그대로 다시 돌린다.

**9항의 잔여** — 작업자 보고 「잔여·처분」 기재분, 기각 보관 검토전개가 최종 기각한 항목, 산출물에 남은 미검증·미확인·유보 표지 전건은 그 노드의 싱크가 결산에서 선별한다: 이월(소유자 명시) / 기각(근거 기록). 검증런의 기각·무처분 항목은 이 자리 전에 기각 보관 검토전개가 전건 판정한다. 싱크는 산출물에서 표지(`[미검증 …]`·`[미확인 …]`·「열림」 류의 유보 표기)를 검색해 결과 계수를 결산에 적는다. 표지 잔여의 이월에는 해소 소유자를 명시한다 — 해소 행은 원자료 접근과 문안 수정 권한을 함께 받는다. 싱크는 수리하지 않는다. 수리가 필요하면 결산을 `상태: 완료미충족`으로 바꾸고 첫 줄 `예외`로 반환한다. 예외가 수리 행을 형제로 추가한다. 침묵 이월은 하지 않는다.

## 국면 종결 싱크

국면 하나를 닫는다. 자기 노드가 없으므로 병합도 회수도 자기 트리에 대해 하지 않는다.

**이 싱크의 원장은 노드 싱크와 순서가 다르다** — 회수가 커밋보다 앞선다. 회수의 결과(채록·잔재 처분)가 그 커밋에 실린다. 값의 정본은 【단계원장-국면 · 판정완료 · 회수완료 · 커밋완료 · 종결】이고 노드 싱크의 원장과 섞지 않는다.

1. **이음새 원장의 전 행 종결 확인.** 잔여는 간극 처분하고, 소비자가 후속 국면에 있으면 「노출됨 + 인계」로 종결한다.
2. **결산 파일을 만들고 `단계: 판정완료`를 기입한다.** 첫 비가역 행위는 다음 항의 sweep(트리·브랜치 삭제)이고, **원장이 그보다 앞선다.**
3. **격리 회수** — `<마커 명령> sweep --phase <국면>`을 exit 0(잔존 0)이 될 때까지 돌린다. 확인이 아니라 처분이다: 잔존으로 보고된 트리·브랜치는 미커밋 산출을 `행/<번호>.d/`에 채록한 뒤 삭제하고 다시 돌린다. 파킹된 노드의 트리가 여기까지 남아 오고, worktree 루트는 저장소 밖이라 `git status`에 보이지 않는다. 닫히면 결산 `단계: 회수완료`.
4. **커밋할 것이 있으면** 노드 싱크와 같은 순서로 자리를 잡는다 — lease 획득 → 인덱스 실측 → grant → 커밋 → grant 해제 → lease 반납. 커밋이 서면 곧바로 결산 `단계: 커밋완료 <SHA>`. 커밋할 것이 없으면 이 항을 건너뛰고 값은 `회수완료`에 머문다.
5. **최종 push.**
6. `<마커 명령> close --phase <국면>`.
7. **결산 본문을 쓴다.** 「병합·회수」 절에 sweep 결과·최종 push·`close --phase`를 적는다. **마지막 편집으로 `단계: 종결`** — grant 해제·lease 반납·push·`close --phase`가 모두 끝난 뒤에 오른다.

국면 종결 싱크도 재개 규약을 그대로 따른다. 다시 쏘아지면 자기 결산의 `단계:`를 읽고 아래 표의 「재개가 시작할 자리」부터 잇는다.

```전거 단계원장-국면
요지: 판정완료 · 회수완료 · 커밋완료 · 종결

| 단계 값 (국면 종결 싱크) | 이 값이 서면 끝난 것 | 재개가 시작할 자리 |
|---|---|---|
| `판정완료` | 이음새 원장 종결 확인 (아직 비가역 없음) | 격리 회수(sweep) |
| `회수완료` | sweep이 잔존 0으로 닫혔다 | 커밋 자리 확보 |
| `커밋완료 <SHA>` | 국면의 최종 커밋 | 최종 push |
| `종결` | 전부 | 없음 — 다시 쏘아지면 아무것도 하지 않는다 |
```

기록 전 중단의 복구도 실측이다. sweep과 push는 재실행이 무해하므로 그대로 다시 돌린다. `회수완료`에서 재개할 때는 `git log`로 그 커밋이 이미 섰는지 보고, 섰으면 `커밋완료 <SHA>`로 올린 뒤 push부터 잇는다. `close --phase`가 이미 돌았으면 마커에 그 국면이 없다 — 그때는 결산의 마지막 편집만 남았다.

## worktree 처분

```전거 격리생명주기
요지: 다시 쓸 가능성이 있으면 보존하고, 쓰지 않기로 처분한 뒤에만 채록하고 삭제한다

| 상태 | 처분 |
|---|---|
| 작업자 소멸 · 테스트 실패 · 미귀속 편집 · 검증 실패 | worktree 보존. 수리·재시도가 같은 트리를 다시 연다 |
| 병합 충돌 | 메인 체크아웃만 `git reset --merge`(하는 주체는 `병합lease`가 진다). worktree 보존 |
| 정상 완료 | 병합·최종 커밋 뒤 worktree와 브랜치 삭제 |
| 파킹 · 국면 포기 | diff·미추적 실물·HEAD를 `행/<번호>.d/`에 채록한 뒤 삭제 |

**재시도는 `worktree-open`이 같은 좌표를 다시 열어 이전 시도의 부분 산출 위에서
잇는다.** 기계는 지우지 않고 처분을 넘긴다.
```

경계 사례의 처분:

- **병합 뒤에 드러난 미충족은 되돌리지 않는다.** 병합은 그대로 둔다. 미충족 항과 증거를 결산에 적고 `상태: 완료미충족`으로 바꾼다. 첫 줄 `예외`로 반환한다.
- **grant가 만료되면 강행하지 않는다.** `allow`로 다시 받고, 그 사이 트리가 움직였을 수 있으므로 시간에 의존하는 판정을 다시 돌린 뒤 커밋한다. 어느 판정이 그에 해당하는지는 이 노드가 정하고 결산에 적는다. lease가 만료됐으면 다시 획득한다 — 그 사이 남이 쥐었으면 exit 1이 온다.
- **`git reset --merge`는 lease 소유자만 한다.** lease 없이 더러운 메인 인덱스를 본 싱크는 결산을 `상태: 대기`로 바꾼다. 손대지 않고 첫 줄 `예외`로 반환한다.
- **병합 후 커밋 전에 멈출 때는 `git reset --merge`로 메인 체크아웃을 되돌리고** 그 사실과 명령을 결산에 적는다. lease는 되돌린 뒤에 반납한다.
- **계약 이동**: 갱신이 아직 파견되지 않은 노드의 계약을 움직였으면 병합은 마친다. 결산을 `상태: 계약이동`으로 바꾸고 첫 줄 `예외`로 반환한다. 그 행 파일의 폐기·재저작은 상위 전개의 몫이다.

이음새 전기의 「결합됨」 전이는 증거 좌표 없이 기입하지 않는다. 병합 자리의 직렬화는 【병합lease · 메인 체크아웃에 들어가는 싱크를 하나로 줄인다 · 실패하면 결산 상태 대기와 반환 예외로 닫는다】가 한다.

## 결산 (싱크의 산출)

결산은 【산출이름 · <번호>는 행 번호의 마지막 마디이고, 파일은 그 행이 속한 .d/ 아래에 놓인다】가 정한 자리에 쓴다 — 행 `2.z`면 `행/2.d/z-결산.md`이고 최상위 행 `z`면 `행/z-결산.md`다. 이 행의 완료 신호다. 커밋 반경 밖이므로 스테이징하지 않는다. `상신`·`예외`로 반환할 때도 쓴다.

**싱크가 스테이징하지 않을 뿐 저장소에 안 남는 것은 아니다.** 국면이 닫힌 뒤 메인이 런 디렉토리를 통째로 저장소로 이관하며 결산도 함께 간다(`SKILL.md` 「3. 종결 보고」). 그때 이 파일은 이미 종착까지 쓰인 뒤라 뒤이을 편집이 없다 — 자기를 싣는 커밋의 SHA를 담아야 하는 순환이 서지 않는 것이 이관을 싱크가 아니라 메인이 하는 이유 하나다.

**단계 원장.** 이 파일은 **첫 비가역 행위보다 먼저** 만들고 비가역 행위마다 그 직후에 갱신한다. `단계:`가 어디까지 갔는지가 재개의 유일한 근거다(【결산frontmatter · 유형 · 행 · 상태 · 단계】). 값의 정본은 싱크 종류별로 【단계원장-노드 · 판정완료 · 격리커밋완료 · 병합완료 · 커밋완료 · 회수완료 · 종결】·【단계원장-국면 · 판정완료 · 회수완료 · 커밋완료 · 종결】이다.

```전거 단계원장-노드
요지: 판정완료 · 격리커밋완료 · 병합완료 · 커밋완료 · 회수완료 · 종결

각 값은 **완료된 마지막 비가역 행위**를 가리키고, 재개는 그 다음 행위부터 잇는다.
순서가 계약이다. 두 커밋 값은 뒤에 SHA를 달고 선다.

| 단계 값 (노드 싱크) | 이 값이 서면 끝난 것 | 재개가 시작할 자리 |
|---|---|---|
| `판정완료` | 귀속 대조·완료 기준 판정 (아직 비가역 없음) | worktree 커밋 |
| `격리커밋완료 <SHA>` | worktree 커밋 | 병합 자리 확보(lease) |
| `병합완료` | 메인 체크아웃 squash 병합 | 메인 커밋 |
| `커밋완료 <SHA>` | 메인 커밋 | 회수 |
| `회수완료` | 트리·브랜치 삭제 | 이음새 전기 · 결산 본문 · grant 해제 · lease 반납 |
| `종결` | 전부. **grant 해제와 lease 반납 뒤에 오른다** | 없음 — 다시 쏘아지면 아무것도 하지 않는다 |
```

```markdown

유형: 결산
행: {번호}
상태: {DONE | DONE-비준 | 상신 | 귀속불일치 | 완료미충족 | 병합충돌 | 계약이동 | 대기}
단계: {그 싱크 종류의 단계 원장 값 하나 — 위 「단계 원장」. 두 커밋 값은 뒤에 SHA를 단다}
---

## 판정 (병합 앞)
{귀속 대조 — 실측기 attrib 블록.
 완료 기준 전건 판정 — 기준 | 판정 | 증거 좌표}

## 병합·회수
{실행한 명령과 결과: worktree 커밋 · lease 취득·반납 · 인덱스 실측 · squash 병합 ·
 트리 처분(보존이면 사유) · grant ID 취득·해제.
 grant·lease 만료로 다시 돌린 판정이 있으면 어느 판정인지 명시.
 국면 싱크는 여기에 sweep 결과 · 최종 push · `close --phase`를 적는다}

{ID | 전이 | 증거 좌표. 「결합됨」은 실결합 실행 산출물 좌표 없이 오르지 않는다. 없으면 "없음"}

## 경미 처분
{항목 | 이월(소유자 명시) | 기각(근거). 기각 보관 파일 수·항목 수·검토전개 보고 좌표를 함께 적는다. 없으면 "없음"}

## 잔여·처분
{미충족 항과 증거, 계약 이동, 되돌린 병합. 없으면 "없음"}
```

**재개 규약.** 싱크가 다시 쏘아지면 첫 행동은 자기 결산 파일을 읽는 것이다. 파일이 없으면 처음부터 돌고, `단계:`가 있으면 자기 종류의 표에서 「재개가 시작할 자리」를 찾아 잇는다. 이미 선 커밋을 되돌리지 않는다.

**기록 전 중단은 실측으로 복구한다.** 값을 믿기 전에 그 값이 가리키는 다음 행위가 이미 섰는지 실측한다 — 판정은 원장이 아니라 실물이 낸다. 아래는 **노드 싱크**의 표이고, 국면 종결 싱크의 실측은 그 절이 담는다.

| 읽은 값 (노드 싱크) | 실측 | 이미 섰으면 |
|---|---|---|
| 파일 없음 | `git -C <worktree> log -1 --format=%H`와 브랜치 실재 | 노드 커밋이 base 위에 서 있으면 `격리커밋완료 <SHA>`로 원장을 세우고 잇는다 |
| `판정완료` | `git -C <worktree> status --porcelain`이 비었고 브랜치 HEAD ≠ base | 같다 — 커밋을 다시 시도하지 않는다 |
| `격리커밋완료 <SHA>` | 메인 체크아웃 `git diff --cached --name-only` | 스테이징에 그 병합이 보이면 `병합완료`로 올리고 커밋부터 한다 |
| `병합완료` | `git log -1 --format=%H`와 그 커밋의 내용 | 그 병합이 이미 커밋됐으면 `커밋완료 <SHA>`로 올리고 회수부터 한다 |
| `커밋완료 <SHA>` | worktree 경로·브랜치 실재 | 둘 다 없으면 `회수완료`로 올린다 |
| `회수완료` | 실측하지 않는다 | 남은 넷(이음새 전기 · 결산 본문 · grant 해제 · lease 반납)은 재실행이 무해하다 — 그대로 다시 돌린다 |

worktree 커밋 재시도 자체는 무해하다. 실측이 막는 것은 **빈 커밋 강행과 중복 병합**이다.

완결 상태(【완결상태 · 완 · 비준】)인 싱크 행의 결산 `단계`가 `종결`인지는 검산 ⑦이 본다.
