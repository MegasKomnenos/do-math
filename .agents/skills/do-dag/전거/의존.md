# 전거 — 의존

**정본이 이 스킬 밖에 있는 사실이 산다.** 전거 항목은 ID로 인용되므로 정본을 고치는
사람이 `grep ID`로 영향 범위를 안다. 밖이 정본인 사실에는 그 장치가 없다 — 고치는
사람이 이 저장소를 보지 않거나, 그 파일이 주석을 받지 못한다. 그래서 방향을 뒤집어,
딛는 자리를 여기에 등재한다.

각 항목은 셋을 더 든다.

- **정본** — 그 사실이 실제로 사는 곳. 저장소 안이면 좌표를 백틱에 담고 뒤에
  `(저장소 안, …)`을 달며, 검사 E가 그 좌표도 파일로 서는지 본다
- **딛는 자리** — 이 스킬 안에서 그 사실을 딛는 파일. 검사 E가 파일로 서는지 보고,
  항목이 이 줄을 싣지 않으면 그것도 낸다
- **증상** — 정본이 바뀌었을 때 어떻게 보이는가

**「증상」이 이 대장의 값이다.** 깨진 자리를 만난 사람이 원인을 밖에서 찾게 하는 것이
그 줄의 일이다. 어떤 항목은 크게 깨지고(오류 문면과 exit 1) 어떤 항목은 조용히
깨지는데(낮은 값, 사라진 도구, 서지 않는 게이트), 그 차이를 각 증상 줄이 적는다.

- _경계_ 심을 역포인터 주석이 항목 밖에 하나 더 있다 — `decision-briefing/SKILL.md`다.
  `references/분해_원리.md`가 그 스킬의 절 이름 둘을 축자로 딛는데, 그 사실은 이
  대장의 어느 항목도 지지 않아 항목의 `- _경계_`에 설 자리가 없다. 아직 심지
  않았으므로 그 스킬을 고치는 사람은 do-dag가 그 절 이름을 딛는다는 것을 알지
  못한다. `.agents/config.toml` 몫은 `의존:MCP등재`의 경계가 진다.

## 【의존:하네스-트랜스크립트】 서브에이전트 트랜스크립트의 배치
요지: ~/.claude/projects/<munge된 저장소 경로>/<세션 UUID>/subagents/ 아래에 산다

정본: Claude Code 하네스 (저장소 밖)
딛는 자리: scripts/agent_usage.py · scripts/tests/test_agent_usage.py
증상: 배치가 바뀌면 열쇠에 걸리는 meta가 0건이 되어 `[agent_usage] <열쇠 이름> '<열쇠 값>' 을 <루트> 아래에서 찾지 못했다 (하한 <하한> 이후)`를 내고 exit 1로 끝난다. 열쇠 이름은 `description` 또는 `toolUseId`이고, 꼬리는 `--phase`나 `--since`를 실은 호출에만 붙는다 — `SKILL.md`가 규정한 오케 판독 호출 둘은 `--phase`를 실으므로 늘 붙는다. 부재이지 적재 0이 아니므로, 이 문면을 「아직 안 쌓였다」로 읽으면 교대 임계를 놓친다.

## 【의존:하네스-파일명명】 트랜스크립트 파일의 짝 명명
요지: agent-<id>.meta.json과 agent-<id>.jsonl이 짝을 이룬다

정본: Claude Code 하네스 (저장소 밖)
딛는 자리: scripts/agent_usage.py · scripts/tests/test_agent_usage.py
증상: 열쇠는 `.meta.json`에서 찾고 적재는 짝 `.jsonl`에서 읽는다. 명명이 갈리면 짝을 못 찾아 `의존:하네스-트랜스크립트`와 같은 「찾지 못했다」 문면과 exit 1이 온다. 그 문면이 싣는 루트는 munge 구간까지이므로 루트 실재만으로는 이 원인과 배치 변화를 가르지 못한다. 루트 아래에 `<세션 UUID>/subagents/`가 실재하는지 먼저 보고, 실재하면 원인을 이쪽으로 좁힌다.

## 【의존:하네스-트랜스크립트키】 트랜스크립트가 담는 키
요지: meta.json은 description과 toolUseId로 조회하고, jsonl은 message.usage의 세 키를 더해 적재를 낸다

정본: Claude Code 하네스 (저장소 밖)
딛는 자리: scripts/agent_usage.py · scripts/tests/test_agent_usage.py
증상: 적재는 `message.usage`가 담은 `input_tokens` + `cache_creation_input_tokens` + `cache_read_input_tokens`의 합이다. 파괴 문면은 셋이다. 조회 열쇠가 갈리면 「찾지 못했다」로 크게 깨진다. 행 유형 `assistant`나 `message` 키가 갈리면 `[agent_usage] usage 실린 assistant 행이 없다: <경로>`와 exit 1로 크게 깨진다. **합의 키 하나가 사라지면 조용히 깨진다** — 오류 없이 값만 작게 나와 교대 임계에 늦게 닿는다. 하네스가 보여 주는 적재와 이 값이 어긋나면 그쪽을 의심한다.

## 【의존:하네스-munge】 프로젝트 디렉토리의 munge 규칙
요지: 경로의 비영숫자를 전부 하이픈으로 치환한다

정본: Claude Code 하네스 (저장소 밖)
딛는 자리: scripts/agent_usage.py · scripts/tests/test_agent_usage.py
증상: 규칙이 바뀌면 트랜스크립트 루트가 실재하지 않는 디렉토리를 가리켜, `의존:하네스-트랜스크립트`와 같은 「찾지 못했다」 문면과 exit 1이 온다. **그 문면이 싣는 루트 경로가 갈린 규칙을 그대로 보여 준다.** 루트가 실재하지 않으면 이 원인이다. 루트가 실재하면 같은 문면을 내는 원인이 여럿이므로 순서를 두고 좁힌다. 저장소 안에서 고치는 둘을 먼저 본다 — `--description` 축자가 meta의 값과 어긋남 · `--phase`가 무는 mtime 하한이 meta보다 늦음. 그 둘이 아니면 배치(`의존:하네스-트랜스크립트`)와 명명(`의존:하네스-파일명명`)을 본다. 그래도 아니면 `find_agent_matches`가 히트를 0건으로 내는 나머지 경로(meta 판독 예외 · 짝 jsonl 부재)를 본다.

## 【의존:MCP-프로토콜버전】 MCP 프로토콜 버전 문자열
요지: 클라이언트가 주지 않으면 2024-11-05로 답한다

정본: MCP 명세 (저장소 밖)
딛는 자리: scripts/dag_measure_mcp.py
증상: 클라이언트가 `protocolVersion`을 실어 보내면 서버가 그 값을 되돌려 주므로 이 기본값이 쓰이지 않는다. 클라이언트가 주지 않는 경로에서 명세가 이 형식을 버리면 초기화 응답이 거부되어 **실측기 일곱이 통째로 도구 목록에서 사라진다.** 조용히 깨진다 — 에이전트는 오류를 받지 않고 도구가 없는 것으로 읽어 실측 주장을 산문으로 쓴다.

## 【의존:git-훅공유】 링크된 worktree의 훅 디렉토리
요지: 링크된 worktree들이 $GIT_COMMON_DIR/hooks를 공유한다

정본: git의 동작 (저장소 밖)
딛는 자리: scripts/dag_marker.py · scripts/tests/test_dag_marker.py
증상: 이 사실 때문에 `install-hook` 1회로 전 트리가 덮인다. git이 이것을 바꾸면 **노드 worktree에서 커밋 관문이 서지 않는다** — 차단이 아니라 무방비다. 조용히 깨지고, 드러나는 것은 관문이 서 있었다면 막혔을 커밋이 노드 worktree에서 선 자리다 — 닫힌 국면의 잔재 트리, 분리 HEAD, `dag/<활성 국면>/<행>`이 아닌 이름의 브랜치. 활성 국면의 노드 브랜치에서 grant 없이 서는 커밋은 관문이 서 있어도 통과하므로 이 신호가 아니다.

## 【의존:훅등록】 세션 훅의 등록 자리
요지: .agents/settings.json의 SessionStart와 UserPromptSubmit에 등록된다

정본: `.agents/hooks.json` (저장소 안, 주석을 못 받는 형식)
딛는 자리: scripts/hooks/dag_session_note.py
증상: 등록이 빠지면 활성 국면 재정박과 격리 잔재 고지가 **아무 말 없이 멈춘다.** 훅은 항상 exit 0이라 실패도 조용하다. 세션 머리에 국면 고지가 안 보이면 이 자리를 본다.

## 【의존:SendMessage】 중단된 에이전트의 재개 도구
요지: Claude Code는 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1에서 SendMessage를 노출한다

정본: Claude Code 하네스 (저장소 밖)
딛는 자리: SKILL.md · 대응표.md
증상: 환경 키가 없으면 게이트·상신·교대 뒤에 반환한 오케와 행 에이전트를 재개할 `SendMessage`가 도구 목록에 없다. 새 에이전트를 같은 역할로 쏘면 기존 에이전트의 문맥을 잃고, 새 오케의 고아 점검이 아직 도는 행을 예외로 바꿀 수 있다.

## 【의존:MCP등재】 실측기의 MCP 등재 자리
요지: 루트 .mcp.json과 .agents/config.toml에 등재된다

정본: `.mcp.json` (저장소 안, 주석을 못 받는 형식) · `.agents/config.toml` (저장소 안, 주석을 받는 형식)
딛는 자리: SKILL.md · scripts/dag_measure_mcp.py
증상: 등재가 빠지면 실측기가 도구로 노출되지 않는다. `의존:MCP-프로토콜버전`이 깨졌을 때와 세션에서 보이는 것이 같으므로, 도구가 안 보이면 등재를 먼저 보고 그다음 프로토콜 버전을 본다.

- _경계_ 두 파일이 한 항목인 것은 등재 자리가 하나이기 때문이다. `.mcp.json`은 JSON이라
  주석을 못 싣고 `.agents/config.toml`은 TOML이라 싣는다.
- _경계_ `.agents/config.toml`에는 「딛는 자리」를 적은 주석을 직접 심는다. 아직 심지
  않았으므로, 그 파일을 고치는 사람은 do-dag가 그 등재를 딛는다는 것을 알지 못한다.

## 【의존:verify-rounds-종료보고】 verify-rounds 종료보고의 「발견」 절
요지: 종료보고의 `## 발견` 절 제목과 0건 표기 「없음」을 verify-rounds SKILL.md §7이 정한다

정본: `.agents/skills/verify-rounds/SKILL.md` §7 종료 보고 10항 (저장소 안)
딛는 자리: scripts/dag_check.py · 계약/검증런.md · 검토전개.md
증상: 절 제목이나 0건 표기가 바뀌면 dag_check ⑦의 발견 검사가 그 절을 찾지 못해 0건으로 읽는다 — 발견이 있는데 검토전개 행이 없어도 무발견을 낸다. 조용히 꺼진다. 검증런 종료보고에 발견 항목이 보이는데 같은 층에 검토전개 행이 없으면 이 자리를 본다.
