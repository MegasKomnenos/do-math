# 커밋-기억 하네스

이 저장소의 **커밋·푸시 정본**이자, 커밋 단위 작업 기억의 결정화 절차다. 기본 동작에 우선한다.

이 스킬은 `memory-harness`에서 커밋 절차만 분리한 것이다. 기억 그래프의 구조 — 3층 그래프(layer-1 메모리 / layer-2 dream / layer-3 현행), 헌법/세칙 2층, 핵심층 계약(결합 불변식·노드 frontmatter 골격·색인·읽기 경로), dream 종합 절차 — 의 **정본은 `memory-harness`**다. 이 문서는 그 구조를 참조하며 그 위에서 도는 커밋 절차만 담는다.

## 결합 불변식 (핵심층)

모든 작업 커밋은 정확히 하나의 layer-1 메모리 노드를 **같은 커밋에** 포함한다. 아래 절차를 따르면 이를 보장한다. 예외는 dream 커밋뿐이다. 이 불변식과 노드 frontmatter 골격의 정본은 `memory-harness` 핵심층 1·2이며, 여기서는 그 이행 절차를 제공한다.

## 절차: 커밋-기억 (커밋 시 적용)

1. **작업 단위 식별**: 분리 가능한 단위로 변경을 나눈다. working tree에 서로 독립적인 변경이 섞여 있으면 적절한 선에서 별개 커밋으로 나누고, 더 잘게 나눌 실익이 없으면 묶어 하나로 커밋한다. 이 저장소는 현재 브랜치(`main` 포함)에서 직접 작업하며 커밋·푸시를 위해 별도 브랜치를 만들지 않는다.
   - **검증-커밋 선후**: 그 작업 단위에 적대 검증(국면 경계 검증 등)이 예정되어 있으면 **검증 통과와 교정 반영 후에 커밋**한다(교정이 같은 커밋에 흡수되어 커밋 이력이 검증 통과 상태와 일치한다). 미커밋 대기가 길어지는 위험은 검증 파견 전 작업기록·계장 로그의 결정화로 상쇄한다. 미커밋 대기의 위험은 리밋 사망만이 아니라, 세션이 정상 종료한 뒤 세션 밖 행위자(사용자·병행 세션·동기화 클라이언트)에 의한 워킹트리 소실을 포함한다(실측 1건의 진상은 사용자의 의도적 삭제였고, 교훈은 원인과 무관하게 성립한다: M-0256·M-0260, D-0044). 커밋 가치가 있는 산출물은 세션 종료 전에 커밋한다.
2. **변경 영역별 검증 게이트**:
   - **스킬 미러 게이트**: 스킬 정본 트리 또는 타깃 diff 디렉토리에 닿은 변경이면 생성기 `build_skill_mirrors.py`(writing-skills `scripts/`)로 런타임 사본을 재생성하고 `--check` exit 0을 확인한다(오버레이 낡음 경고는 해당 오버레이 재검토·개정 후 `--bless`). 정본 변경·diff 변경·재생성 사본을 같은 커밋에 담는다(경로·절차 정본: writing-skills `references/멀티런타임_동기화.md`).
   - **테스트 게이트**: 검증·생성 스크립트 코드(`.agents/skills/writing-skills/scripts/`·`.agents/skills/do-dag/scripts/`·`기억/scripts/`)에 닿은 변경이면 해당 디렉토리의 `test_*.py`를 **각 파일 직접 실행**으로 돌려 전부 exit 0을 확인한다(일부 테스트는 unittest 미기반이라 `unittest discover`가 조용히 건너뛴다 — 직접 실행이 정본). `do-dag`는 트리거 경로와 실행 대상 경로가 다르다: 트리거는 `scripts/` 아래 어디든(`hooks/**` 단독 변경 포함) 닿은 것이고, 실행 대상은 `scripts/tests/`의 `test_*.py` 각 파일이다.
   - **기억 색인 게이트**: `기억/`의 노드·색인에 닿은 변경이면 `python 기억/scripts/validate_memory_index.py` exit 0을 확인한다.
   - **프로젝트 전용 게이트**: 변경 영역의 정본 문서가 추가 검증 게이트를 정하면 해당 게이트를 모두 실행해 exit 0을 확인한다. 정본 문서가 없는 영역에는 이 항목을 적용하지 않는다.
3. **메모리 노드 작성**: `기억/세칙.md`(커밋-기억 관례부)를 읽고(dream 전용 관례부 `기억/세칙_dream.md`는 커밋 시에는 읽지 않는다), 이 커밋에 대응하는 `기억/layer1/M-####.md`를 `memory-harness` 핵심층 frontmatter 골격 + 세칙 본문 형식으로 작성한다. **이 시점의 컨텍스트 윈도우에 살아있는, 이 커밋 작업과 연관된 곧 휘발될 맥락을 결정화한다**(사후 회고가 아니라 지금 살아있는 맥락의 보존이며, 작업 자체에 국한되지 않는다). 무엇을 결정화할지의 선별은 세칙의 현행 관례를 따른다. 사소한 커밋이면 짧아도 되지만 생략하지는 않는다. 중간 결정화 커밋(리밋 사망 대비 등 진행 중 임시 커밋)도 작업 커밋이므로 노드를 동반한다. 급하면 노드를 짧게 쓰는 것이지 생략하는 것이 아니다(첫 이탈 실측: 2a1bcff, M-0103). 작성한 M 노드가 layer-3의 특정 항목을 명백히 뒤집음을 이미 알면(읽기 경로로 그 항목을 읽었던 경우가 대표적이다), 해당 L 항목 앞에 정정 대기 한 줄만 남긴다(형식은 세칙). 통합 개정은 하지 않는다(다음 dream의 몫). 그 커밋 단위 세션에서 task-intake 협의 블록의 실전 발화가 있었으면 그 블록 원문을 M 노드에 부기한다(형해화 감사의 표본 원장화: D-0045. 교정된 블록만 부기하면 표본이 사용자 적발 사례로 편향되므로 부기 대상은 실전 발화 전수이며, 블록은 3~6줄이라 비용이 작다).
4. **색인 갱신**: `기억/색인.md`의 layer-1 절에 한 줄을 추가한다.
5. **동일 커밋으로 커밋**: 작업 변경 + 메모리 노드 + 색인 갱신을 **하나의 커밋**으로 stage·commit한다. 메시지는 변경의 목적을 한국어 한 줄로 요약하고, `Co-Authored-By` 등 트레일러는 붙이지 않는다.
6. **종료 시 푸시**: 사용자가 요청한 전체 작업이 끝나면 그때까지의 모든 커밋을 push한다.

## 세칙 참조

커밋-기억 절차의 구체 형식(메모리 노드 본문 형식·결정화 선별 관례)은 `기억/세칙.md`(커밋-기억 관례부)에 있다. 커밋 시에는 이 파일만 읽고 `기억/세칙_dream.md`(dream 전용 관례부)는 읽지 않는다. 세칙은 dream이 진화시키므로 시점마다 다를 수 있다.
