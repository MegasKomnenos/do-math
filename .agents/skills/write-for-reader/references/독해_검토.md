# 원고 독해와 합의 대조

작성자가 알고 있는 내용을 독자가 원고만 읽고도 이해하는지 확인한다. 메인은 원자료와 합의를 유지하고, 별도 독해자는 작성 대화를 보지 않은 상태에서 원고를 읽는다. 두 역할의 입력을 구별해 작성자의 해설이 원고의 설명을 대신하지 않게 한다.

## 입력과 적용 범위

메인은 세 파일을 준비한다.

- **합의**: 독자가 읽은 뒤 이해하거나 판단할 내용, 확정된 사실·조건, 원자료 위치와 우선순위. 작성 전에 확보하며 독해자에게 전달하지 않는다.
- **독자 정보**: 독자의 배경지식, 문서 종류, 사용 상황. 의도한 답이나 평가자의 선호를 유도하는 설명은 넣지 않는다.
- **원고**: 독자가 실제로 받는 본문 전체. 현재 실행기는 UTF-8 `.md`와 `.txt`를 받는다. HWP·PDF 등은 해당 문서 추출 절차로 본문과 표를 확보하고 실제 문서와 대조한다. 그림이 전달하는 정보가 핵심이면 텍스트 독해만으로 시각적 이해까지 통과했다고 판단하지 않는다.

스킬·절차처럼 독자가 참조 문서를 읽어야 하는 글은 실제 독자가 그 시점에 얻는 필수 참조도 원고 입력에 함께 제공한다. 작성자가 원래 전달하지 않는 설명을 추가해 빈틈을 메우지 않는다. 제공 범위는 합의에 기록한다.

합의와 독자 정보는 등록 시점에 고정한다. 사용자의 새 결정으로 바뀌면 기존 작업을 변경 이유와 함께 취소하고 새 입력으로 등록한다. 독해 결과에 맞추어 평가 기준을 바꾸지 않는다.

## 명령 사용

아래 명령은 저장소 루트에서 실행한다. Codex용 생성 사본에서는 경로가 `.agents/skills/`로 바뀐다. 세 파일의 이름은 예시이며 기존 작업 폴더를 사용한다.

```powershell
python .agents/skills/write-for-reader/scripts/writing_flow.py begin --draft 임시/작문/원고.md --brief 임시/작문/합의.md --audience 임시/작문/독자.md
python .agents/skills/write-for-reader/scripts/writing_flow.py read --scope whole
python .agents/skills/write-for-reader/scripts/writing_flow.py decide --decision 임시/작문/대조.json
python .agents/skills/write-for-reader/scripts/writing_flow.py status
```

일반 명령의 세션은 루트 세션을 나타내는 `CODEX_SESSION_ID`, 없으면 `CODEX_THREAD_ID`에서 얻는다. 하위 에이전트의 thread ID와 루트의 Stop 세션을 혼동하지 않는다. 작업 등록과 종료 판단은 메인이 담당한다. 환경변수가 없는 런타임은 `--session <현재 작업의 고유 ID>`를 하위 명령 앞에 명시한다. 다른 작업의 세션 ID를 재사용하지 않는다. `--root`는 상태를 보관할 저장소를 지정하며 기본값은 이 스킬을 설치한 저장소다. 각 명령의 `--help`에서 인자를 확인할 수 있다.

긴 문서의 중심 절을 먼저 검사할 때에는 `read --scope sample`을 사용한다. 같은 원고 파일을 전체 원고로 발전시킨 뒤 `read --scope whole`로 전체를 검사한다. 짧은 독립 문서는 처음부터 전체를 작성해 검사한다.

독해 모델의 기본값은 `gpt-5.6-sol`, 추론 수준은 `high`다. `--model`, `--effort`로 변경할 수 있다. 이 기본값은 모든 분야의 독해 품질을 보장하지 않는다. 해당 과제에서 더 적합한 모델은 실제 독해 결과로 선택한다. `--timeout`은 한 독해 호출의 제한 시간이며 기본 600초다. 시간 초과는 검토 미완료로 기록한다.

## 독해 실행

`read`는 원고·합의·독자 정보의 사본과 해시를 보존하고, 원고와 독자 정보만으로 독해 입력을 만든다. 저장소 밖의 임시 작업 폴더에서 새 `codex exec`를 실행한다. 부모 대화를 재개하거나 분기하지 않는다. 사용자 설정, 훅, 추가 에이전트, 셸 도구, 앱과 플러그인을 비활성화하고 읽기 전용 모드로 실행한다. 웹 검색도 사용하지 않는다.

독해자는 다음 내용을 JSON으로 반환한다.

- `status`: 전문을 읽었으면 `complete`, 읽지 못했으면 `incomplete`.
- `understanding`: 실제로 이해한 중심 내용과 설명의 연결. 각 항목에 `statement`와 본문 근거인 `evidence`를 담는다. 근거는 `line`과 해당 행의 정확한 `quote`다.
- `difficulties`: 다시 읽거나 관계를 보충해야 하는 대목. 각 항목에 `line`, 정확한 `quote`, 어려운 이유인 `reason`을 담는다. 발견하지 못하면 빈 배열을 반환한다.
- `uncertainties`: 원고만으로 확정하지 못한 내용이나 외부 지식에 의존한 해석. 없으면 빈 배열을 반환한다.

실행기는 원래 응답, CLI 이벤트, 오류 출력, 실행 구성과 사용량을 보존한다. 인용과 행 번호가 실제 원고에 있는지도 확인한다. 인용이 존재한다는 사실은 그 인용이 설명을 뒷받침한다는 의미가 아니므로 메인이 직접 대조한다. 독해자의 자기 보고만으로 전수 이해가 증명되지는 않는다.

현재 모듈은 독해자의 역할을 수행한다. 원고 수정은 메인 또는 별도 작성자가 한다. 독해 결과를 받기 전에 원고를 계속 수정하지 않는다. 다른 작업으로 원고가 바뀌었으면 새 판본을 독해한다.

## 대조와 수정

메인은 원고, 독해 원문, 합의를 함께 읽는다. 독자가 설명한 내용이 합의의 사실과 관계를 전달하는지 확인한다. 원고가 빠뜨린 설명을 독해자가 추론으로 보충한 경우에는 원고의 전달 성과로 세지 않는다. 독해자가 글의 중심으로 재구성한 내용이 합의의 경중 선언과 일치하는지도 `경중_배분.md`의 `독해와 맞댄다`에 따라 판정한다. 문법과 수식 관계, 문장·문단의 연결에 관한 지적도 해당 문맥에서 검토한다.

다음 형식으로 대조 결과를 작성한다. `difficulties`의 첫 항목을 1번으로 하여 모든 항목에 처분을 붙인다. 지적이 없으면 `findings`는 빈 배열이다.

```json
{
  "verdict": "revise",
  "alignment": "독해자는 개념 비교 기능은 설명했지만, 그 비교가 작성자의 어떤 판단을 돕는지는 원고에서 찾지 못했다. 합의에서 요구한 필요성 설명이 부족하다.",
  "findings": [
    {
      "index": 1,
      "action": "revise",
      "reason": "필요성 문단에서 비교 결과를 통해 기존 개념과의 관계를 검토한다는 연결을 설명해야 한다."
    }
  ]
}
```

`verdict`는 `accept` 또는 `revise`다. `alignment`에는 합의와 실제 독해의 일치 여부를 근거와 함께 설명한다. `action`은 `keep` 또는 `revise`다. 지적을 기각하거나 현재 표현을 유지할 때에는 `keep`과 원문에 근거한 이유를 적는다. 수정할 지적이 남아 있으면 `accept`할 수 없다.

원고를 고치면 이전 독해와 대조는 현재 판본에 적용되지 않는다. 새 독해를 실행하고 새 결과를 대조한다. 동일한 결함이 다시 나타나면 원고의 주장·근거·배치를 원자료에서 다시 구성한다. 새 작성자에게는 확정된 합의, 원자료, 통과한 예문을 제공하고 실패한 초안이나 그에 대한 변명은 전달하지 않는다. 새 문맥이나 다른 모델의 효과는 해당 부분의 실제 원고로 판단한다.

전체 원고의 독해와 대조가 끝난 뒤 서식을 적용한다. 서식 적용으로 본문이 바뀌면 최종 본문을 원고 파일에 반영하고 다시 독해한다. 표본 판정, 이전 판본의 판정, 저장 성공을 전체 원고의 완료 근거로 사용하지 않는다.

## 대기·실패·취소

진행할 수 없는 원인은 명령으로 기록한다.

```powershell
python .agents/skills/write-for-reader/scripts/writing_flow.py pause --reason "결과를 바꾸는 사용자 결정의 답변을 기다림"
python .agents/skills/write-for-reader/scripts/writing_flow.py block --reason "독해 호출을 사용할 수 없어 검토 미완료"
python .agents/skills/write-for-reader/scripts/writing_flow.py resume
python .agents/skills/write-for-reader/scripts/writing_flow.py cancel --reason "사용자가 이 작문 작업을 중단함"
```

`pause`는 사용자 입력 대기, `block`은 외부 실행·자료 문제, `cancel`은 사용자 중단이나 명시적으로 대체된 작업에 사용한다. 글이 잘 써지지 않는다는 이유로 이 상태를 완료 대신 사용하지 않는다. 대기와 외부 실패의 원인이 해소되면 `resume`으로 이어간다. 취소된 작업은 새로 등록한다.

독해 호출이 실패하면 원래 실행 자료를 보존하고 `blocked`로 남긴다. 실패한 호출을 성공한 독해로 보완 기록하지 않는다. 실행 중인 호출을 취소한 경우 그 결과가 늦게 도착해도 취소 상태를 되돌리지 않는다. 이 상태 변경은 외부 서버의 연산 취소를 증명하지 않는다.

## 종료 검사와 적용 한계

상태와 실행 자료는 `<저장소>/.codex/writing-flow/<세션 ID>/`에 보존한다. `Stop` 훅은 stdin으로 받은 현재 세션 ID의 등록 작업만 검사한다. 전체 독해와 합의 대조가 현재 입력에 대응하면 완료로 기록한다. 기록이 없거나 입력이 바뀌었으면 미완료 이유를 전달해 작업을 재개시킨다.

같은 문제가 자동 재개 뒤에도 그대로 남으면 반복 재개를 멈추고 미완료를 고지한다. 대기·외부 차단 상태는 원인을 고지하며 자동 재시도를 강제하지 않는다. 사용자 취소와 등록되지 않은 세션은 종료를 방해하지 않는다. 일반 질문·짧은 답변은 작문 작업으로 등록하지 않는다.

Codex용 훅은 활성 설정의 `.codex/hooks.json`에 등록한다. 새 훅이나 수정한 훅은 `/hooks`에서 신뢰 상태를 확인해야 실행된다. 스킬 사본인 `.agents/hooks.json`의 존재만으로 등록을 판정하지 않는다. `Stop`은 이미 전달된 메시지를 회수하지 않고 후속 지시로 작업을 이어간다.

다른 런타임이나 훅이 실행되지 않는 환경은 `status`의 `completion_problem`이 비었는지 직접 확인한다. 이 경우 자동 종료 감사가 작동했다고 보고하지 않는다. 문서 자체의 사실 검증, 그림·배치의 판독, 모든 작문 요청의 자동 분류는 이 스크립트의 검증 범위에 포함되지 않는다.

스킬 호출과 작업 등록의 누락은 이 훅이 전부 발견하지 못한다. 상태와 증거는 같은 사용자 권한으로 수정할 수 있으므로 악의적인 조작을 막는 보안 장치로 취급하지 않는다. 판정의 품질은 원고·독해·합의를 실제로 대조한 근거로 확인한다.
