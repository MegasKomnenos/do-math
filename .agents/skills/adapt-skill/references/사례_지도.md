# 알려진 충돌 사례 지도

이 문서는 범용 스킬을 로컬 규범과 대조할 때 자주 놓치는 충돌 유형을 보여 준다. 목록은 예시다. 설치된 원본과 현재 저장소의 실측 결과가 판정의 정본이다.

## 먼저 확인할 로컬 규범

- 기계 강제층: 훅, 권한, 설정 파일
- 절차 정본층: 로컬 스킬과 실행 계약
- advisory층: `AGENTS.md`와 `AGENTS.md`
- 참조 문서층: 스킬이 가리키는 references와 정본 문서
- 기억층: 판단의 이유와 적용 경계를 담은 현행 노드

## 충돌 후보

1. **실패 테스트 강제**: 산문이나 데이터 작업에는 실행 가능한 테스트가 없을 수 있다. 실패 조건을 먼저 정한다는 의도는 보존하고, 산출물에 맞는 검증으로 바꾼다.
2. **강제 호출 규범**: 넓은 자동 호출 조건은 더 구체적인 로컬 절차를 가로챌 수 있다. description과 호출 경계를 함께 대조한다.
3. **브랜치 격리 강제**: 로컬 저장소가 현재 브랜치 직접 작업을 규정하면 worktree와 새 브랜치 강제는 충돌한다.
4. **서브에이전트 대량 사용**: 로컬 규범이 위임 범위나 모델을 제한할 수 있다. 독립 검증의 의도와 작업자 대량 파견을 구별한다.
5. **테스트 스위트 통과 게이트**: 테스트 러너가 없는 저장소에서는 명령 자체가 성립하지 않는다. 실물 재현, 정적 검사, 렌더 판독 같은 실제 검증 수단을 찾는다.
6. **검증 명령 전제**: 산출물에 대응하는 명령이 없을 수 있다. 신선한 증거 없이 완료를 주장하지 않는다는 의도는 유지한다.
7. **하드코딩 경로와 커밋 형식**: 원본이 고정한 산출 경로와 커밋 접두사가 로컬 정본과 충돌할 수 있다.
8. **영어권 톤 규범**: 영어 특정 표현은 한국어 작문 규칙과 맞지 않을 수 있다. 표현을 바꾸되 검증 강도와 금지 의도는 보존한다.
9. **운영체제와 도구 전제**: `/tmp`, `open`, `nohup`, POSIX 셸 문법은 Windows 환경에서 작동하지 않을 수 있다.
10. **수정 요구 자체의 편향**: 사용자가 각색을 요청했다는 사실은 충돌이 존재한다는 증거가 아니다. 모든 지시가 무충돌이면 원본 사용을 권고한다.

## 사용법

4단계 대조를 마친 뒤 이 목록을 누락 검사에 사용한다. 목록에 있는 유형도 실측 근거가 없으면 충돌로 판정하지 않는다.
