# 작업 격리(git worktree)의 로컬 처리

격리 워크스페이스가 필요해 보이는 작업 착수 국면에서 이 프로젝트가 따르는 규범과 예외 경로를 정한다. 기본 답은 격리를 만들지 않는 것이다.

## 기본 규범: 격리를 만들지 않는다

이 저장소는 현재 브랜치(`main` 포함)에서 직접 작업하며 커밋·푸시를 위해 별도 브랜치를 만들지 않는다(정본: commit-harness, `.agents/AGENTS.md` 커밋·푸시 절차). worktree 격리는 새 브랜치의 생성과 그 브랜치에서의 작업을 필연적으로 수반하므로(같은 브랜치는 두 worktree에 동시 체크아웃할 수 없다) 이 규범과 정면으로 충돌한다.

원본의 핵심 원리 "Never fight the harness"(플랫폼이 제공하는 체계와 싸우지 않는다)는 이 프로젝트에서 격리 생성이 아니라 격리 불사용으로 실현된다. 이 프로젝트의 하네스는 격리 대신 다음 수단으로 원본의 의도(진행 중 변경으로부터 작업 상태 보호)를 담당한다.

- 분리 단위 커밋(commit-harness): 독립적인 변경이 섞이지 않도록 작업 단위로 커밋한다.
- 프로젝트 밖 스크래치패드: 임시 산출물·실험 파일은 저장소 밖에 둔다.
- PostToolUse hook 검증 게이트(`.agents/hooks.json`): 사건 문서·그래프 쓰기를 자동 검증한다.

격리 선호를 사용자에게 묻지 않는다. 원본 자신이 "선언된 선호가 있으면 묻지 말고 존중하라"고 지시하는데, 이 프로젝트는 그 선호가 규범으로 명문 선언되어 있다(위 정본). 묻지 않고 현재 브랜치에서 직접 작업하는 것이 원본 원리의 관철이다.

## 예외 경로: 사용자가 명시로 격리를 요청한 경우

사용자의 명시 요청으로만 열린다. 이때도 다음 수칙을 지킨다.

1. **감지 먼저**: 만들기 전에 이미 격리된 환경 안인지 먼저 감지한다. 기존 격리 위에 중복 격리(중첩 worktree)를 만들지 않는다.
2. **네이티브 도구 우선**: EnterWorktree 등 플랫폼 네이티브 worktree 도구가 있으면 그것을 쓴다. 수동 `git worktree add`는 네이티브 도구가 없을 때의 최후 수단이다. 수동 생성은 플랫폼이 보지도 관리하지도 못하는 유령 상태를 만든다.
3. **수동 폴백 수칙**: 수동 폴백으로 프로젝트 내부에 worktree를 두게 되면 그 디렉토리가 git ignore 대상인지 먼저 확인한다(worktree 내용물이 저장소에 실수로 커밋되는 오염 방지). 이때 필요한 커밋은 commit-harness를 따른다.
4. **격리는 규범의 우회 수단이 아니다**: 격리본 안에도 저장소 전체가 복제되므로 이 프로젝트의 전 규범(불변 자산 보호, 커밋 정본, 검증 게이트)이 그대로 적용된다.
5. **마무리**: 예외 국면의 통합·정리는 그 국면을 연 사용자 요청의 맥락에서 사용자와 정한다.

## 착수 시점 상태 확인

원본의 베이스라인 테스트(작업 시작점이 깨끗함을 확인해, 이후 발견되는 결함이 새 것인지 기존 것인지 구별)는 테스트 러너가 없는 이 프로젝트에서 다음이 담당한다.

- 코드 수정: test-driven-development 로컬판의 재현·회귀 절차. 수정 전 실패 관찰과 기존 정상 사례 재실행이 시작점 상태 확인을 겸한다.
- 기억 그래프(노드·색인) 변경: `python 기억/scripts/validate_memory_index.py` exit 0.

## 빠른 대조

| 상황 | 행동 |
|---|---|
| 일반 작업 착수(격리가 필요해 보임) | 격리를 만들지 않는다. 현재 브랜치에서 직접 작업한다 |
| 사용자가 명시로 격리를 요청 | 예외 경로: 감지 먼저, 네이티브 도구 우선, 수동 폴백 수칙 |
| 격리본 안에서 작업 중 | 이 프로젝트의 전 규범이 그대로 적용된다 |
| 착수 시점 상태 확인 | 코드는 TDD 로컬판 재현·회귀, 하네스 데이터·문서는 self-test |

## 차단선

하지 않는다.

- 격리 요청이 없는데 브랜치·worktree를 만드는 것
- 규범이 이미 답한 격리 선호를 사용자에게 재질의하는 것
- 격리본을 규범 밖 공간으로 취급하는 것(불변 자산 수정, 검증 게이트 우회)
- (예외 경로에서) 기존 격리 감지 없이 새 격리를 만드는 것, 네이티브 도구가 있는데 수동 `git worktree add`를 쓰는 것, ignore 미확인 상태로 프로젝트 내부에 worktree를 만드는 것
