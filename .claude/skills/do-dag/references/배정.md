# 배정

메인과 오케는 자기 절차에 필요한 배정표와 Codex 일반 파견을 이 문서에서 읽는다. 전개는 행을 저작할 때 파견표 모델 열을 배정표로 채운다. 행 파일·결정·이음새·기준선 서식은 `references/서식.md`에 있다.

## 배정표 (모델·노력)

```전거 배정표
요지: claude-full · mixed · codex-full

전개가 행을 저작할 때 파견표 모델 열에 `모델 노력` 두 낱말로 기입한다. 두 축은
독립이다. `모델_프리셋`은 `claude-full`·`mixed`·`codex-full` 중 하나이다.
근거 없이 서는 조합은 아래 배정표가 전부다. 표에 없는 조합은 이탈이므로 행별
근거가 든다.

**모델**은 문맥 예산과 계열을 정한다.

| 모델 | 자리 |
|---|---|
| sonnet | 국면 내내 사는 저부하 운전 — 오케 |
| opus | 기본. 판정과 절차 집행 |
| fable | 한 컨텍스트에 담아야 판단의 질이 서는 행. 쪼갤 수 있어도 쪼개면 그 판단이 얕아진다 |
| gpt-5.6-sol | codex CLI로 독립 컨텍스트를 여는 일반 파견 단위 |
| gpt-5.6-terra | codex CLI로 독립 컨텍스트를 여는 일반 파견 단위 |
| gpt-5.6-luna | codex CLI로 독립 컨텍스트를 여는 일반 파견 단위 |

**Claude와 Codex의 모델 대비**는 역할 체급을 기준으로 한다.

| Claude | Codex |
|---|---|
| fable | gpt-5.6-sol |
| opus | gpt-5.6-terra |
| sonnet | gpt-5.6-luna |

**노력**은 그 행이 쓸 추론 깊이를 정한다.

| 노력 | 자리 |
|---|---|
| low | 잣대가 이미 주어져 있고 집행만 하는 행 — 싱크 |
| med | 문면을 설계·저작하되 판정의 잣대는 밖에서 오는 행 — 작업자, 전개, 검증런 |
| high | 실측과 처분을 한 컨텍스트에서 함께 내는 행 — 예외 |
| xhigh | 사용자 확정 또는 행별 이탈 도출이 최상급 추론을 요구하는 행 |

| 역할 | `claude-full` | `mixed` | `codex-full` | 도출 |
|---|---|---|---|---|
| 오케 | sonnet med | sonnet med | sonnet med | 국면 내내 살며 파견만 한다 · 세 프리셋에서 Claude로 고정한다 |
| 작업자 · 조사 · 브리핑 | fable low | fable low | gpt-5.6-terra med | 잣대는 파견문이 주고 산출을 직접 저작한다 |
| 싱크 | opus low | opus low | gpt-5.6-terra low | 잣대가 단계 원장으로 고정돼 밖에서 온다 |
| 검증런 {경량} | sonnet med | sonnet med | sonnet med | 절차와 잣대는 verify-rounds와 체급 프리셋이 닫고, 동결문·파견문을 저작한다 · sonnet은 「모델」 표의 자리 설명과 갈린다 — 이 행은 한 검증런을 완주하고 죽는다 |
| 검증런 {표준} | sonnet med | sonnet med | sonnet med | 도출은 {경량}과 같되 산출물 부피와 판정 종합의 난도가 높다 |
| 전개 | fable med | fable med | gpt-5.6-sol med | 한 서브트리의 분해를 한 컨텍스트에서 저작한다 |
| 예외 에이전트 | fable high | fable high | gpt-5.6-sol high | 실측과 처분을 한 컨텍스트에서 함께 낸다 |

검증런 내부의 수리·병합·심사 배정은 `검증런_모델_프리셋`이 정한다.

**파견표의 모든 모델 값은 도출을 갖는다.** 선택한 프리셋의 배정표를 따르면 그 행의
「도출」 열이 도출이고, 벗어나면 그 행에서 새로 도출한다. **「배정표에 있다」는 그 자체로 도출이
아니다.**

**배정 이탈은 행마다 새로 도출하고 근거 한 줄을 `모델 배정 근거:` 슬롯에 적는다.**
앞선 행의 이탈은 선례가 되지 못하고, 임계값 대입은 도출이 아니다.

**사용자가 산출물을 반려하면 그 재생성 행의 배정은 기본값 대입이 아니라 새로
도출한다.** 반려 사유가 도출의 입력이고, 도출 결과(유지 또는 변경)와 근거를
`모델 배정 근거:` 슬롯에 적는다.

**`claude-full`·`mixed`에서 fable 한도 소진으로 난 예외만 `opus high`로 쏜다.** 그
고장은 fable 계열을 통째로 들고 있어 같은 계열의 복구 경로가 고장과 함께 죽는다. 그
밖의 예외는 배정표의 예외 에이전트 값을 쓴다.
```

```전거 예산
요지: sonnet 200k · opus 250k · fable 250k · gpt-5.6-sol 250k · gpt-5.6-terra 250k · gpt-5.6-luna 250k

한 파견 단위가 완주해야 하는 문맥 상한이다.

**예산을 넘는 단위는 쪼갠다.** 양적 초과에서 모델을 올리지 않는다 — 모델을 올리는
근거는 질적 난이도 하나다.

행 에이전트에는 도중 중단·이어달리기 기제를 두지 않는다 — 완주하거나 예외로
돌아온다.
```

노력 인자를 하네스가 지원하지 않으면 모델만 적용된다(`대응표.md` 사이클 2).

**체급·기수의 고정은 파견 단위의 분할을 막지 않는다.** 고정된 것은 검증 축의 수이고, 한 축의 읽기를 여러 행으로 나누는 것은 축을 늘리지 않는다.

검산 ⑦이 `모델 배정 근거:` 슬롯이 채워졌는지를 본다.

**크레딧·차단 시 하위 티어로 대체하지 않고 그 행을 멈춘다.**

**배정을 바꾸면 파견표 모델 열과 그 행 파일의 `모델 배정 근거:` 슬롯을 같은 편집에서 함께 고친다.** 둘이 갈리면 파견표가 이긴다.

### Codex 일반 파견

`gpt-5.6-sol`·`gpt-5.6-terra`·`gpt-5.6-luna`는 심사자에 한정하지 않는 일반 행 모델이다.
파견표 모델 열에 이 값 하나와 노력 하나를 적으면 오케는 Agent 호출 대신 codex CLI를 쓴다.

- 노력 값은 CLI 값으로 바꾼다. `low`는 `low`, `med`는 `medium`, `high`는 `high`, `xhigh`는 `xhigh`다.
- Codex 행은 격리 노드 worktree를 작업 디렉토리로 쓴다. 격리 없는 행에 Codex를 배정하지 않는다.
- Codex 행은 파견문이 정한 완료 신호 파일을 직접 쓴다. Codex의 마지막 메시지 전체가
  최종 반환이다. 첫 줄은 공통 반환어휘 하나만 쓴다. 둘째 줄부터 역할 계약이 요구하는
  확장 필드만 쓴다. 그 밖의 설명은 쓰지 않는다.
- 반환 파일은 `행/<행번호>-codex.md`다. 로그 파일은 `행/_로그_<행번호>.txt`다. 반환 파일은 반환어휘를 읽는 제어 파일이며 완료 신호가 아니다.
- 셸이 Codex보다 먼저 리다이렉션 경로를 해석한다. 파견문·반환·로그·재개 지시문·재개 반환·재개 로그와 대기 인자는 모두 런 디렉토리 절대 경로로 넣는다.

오케는 파견문 파일을 표준 입력으로 넘긴다. 전달은 아래 명령의 파일 리다이렉션(`- <
파견문`)만 쓴다 — 바이트가 보존된다. 텍스트를 셸 파이프에 태우지 않는다.
`<모델>`·`<노력>`은 파견표 모델 열에서 읽는다.

```
PATH="$(printf '%s' "$PATH" | tr ':' '\n' | grep -vi windowsapps | paste -sd:)" \
  codex -a never exec -s danger-full-access -m <모델> \
  -c model_reasoning_effort=<CLI 노력> -c mcp_servers={} \
  - < <파견문 절대 경로> > <반환 절대 경로> 2> <로그 절대 경로>
```

오케는 시작 전에 반환 파일과 로그 파일이 없는지 확인한다. 둘 중 하나가 있으면
예외 에이전트에게 넘긴다. 병행 행은 명령 하나씩을 백그라운드로 함께 시작한다.
시작 직후부터 아래 대기 호출을 포그라운드로 반복한다. 완료 통지를 기다리며 턴을
마치지 않는다.

```
python .claude/skills/do-dag/scripts/wait_outputs.py <반환 절대 경로 ...>
```

호출 하나가 30초 간격 검사 스무 번(약 570초)이므로 Bash 도구 인자에 `timeout: 600000`을
준다. 기본 timeout 120초로 부르면 대기가 매번 중도에 끊긴다.

exit 0은 인자 경로 전건이 비어 있지 않은 파일로 섰다는 완료 판정이다. 디렉토리는
항목 유무와 관계없이 완료로 보지 않는다. exit 3이면 같은 호출을 다시
낸다. 완료 뒤 오케는 반환 파일의 첫 낱말만 읽어 `반환어휘`의 같은 처분을 한다.

Codex 행이 `상신`으로 반환하면 오케는 메인의 결정 파일 경로를 담은 재개 지시문을
`행/<행번호>-codex-재개<R>.md`로 쓴다. `<R>`은 그 행의 재개 회차이고 1부터 센다.
오케는 처음 로그의 `session id:` 줄에서 세션 ID를 읽고 아래 명령으로 같은 컨텍스트를
재개한다. 재개 반환은 `행/<행번호>-codex-재개<R>-반환.md`에 저장하고, 재개 로그는
`행/_로그_<행번호>-재개<R>.txt`에 저장한다. 재개 반환도 첫 낱말만 읽는다.

```
codex -a never exec resume <세션 ID> -m <모델> -c model_reasoning_effort=<CLI 노력> \
  -c sandbox_mode="danger-full-access" -c mcp_servers={} \
  - < <재개 지시문 절대 경로> > <재개 반환 절대 경로> 2> <재개 로그 절대 경로>
```

`codex exec resume`에는 `-s`를 넣지 않는다. PATH 문제로 실행이 시작되지 않으면
결번으로 처리하지 않고 PATH를 정비한 뒤 같은 파견을 다시 시작한다. `mcp_servers={}`와
명시적 노력 값은 생략하지 않는다. 새 파견과 재개 모두 `danger-full-access`와
`-a never`를 생략하지 않는다. Codex 행이 격리 worktree와 런 디렉토리를
함께 다루므로 권한 요청이나 샌드박스 경계에서 비대화식 실행이 멈추지 않아야 한다.
