# 사용자 의도 발굴

사용자가 자신의 목표와 선호를 일상 언어로 말하게 한다. AI는 프롬프트 설계에 필요한 결정을 찾고, 질문하고, 실행 계약으로 변환한다.

## 질문을 시작하는 조건

새로운 답에 따라 목표, 범위, 평가, 권한, 위험, 되돌리기 어려운 행동, 하류 사용처가 달라지면 `결과를 바꾸는 결정`이다. 결과를 바꾸는 사용자 결정이 비어 있으면 질문한다.

모든 빈칸을 질문하지 않는다. 영향이 작고 되돌릴 수 있는 세부사항은 AI가 정할 수 있다. AI는 그 세부사항을 사용자 의도로 표현하지 않는다.

## 의도 지도

다음 차원은 누락을 찾는 지도다. 고정 질문지가 아니다. 이미 분명하거나 결과에 영향이 없는 차원은 묻지 않는다.

1. **목적**: 왜 이 작업이 필요한가?
2. **산출물**: 무엇을 만들거나 결정하는가?
3. **사용 맥락**: 누가 어디에서 어떻게 사용하는가?
4. **입력과 근거**: 무엇을 사실의 원천으로 삼는가?
5. **범위와 제약**: 무엇을 포함·제외하고 어떤 한계를 지키는가?
6. **평가 기준**: 무엇을 좋은 결과로 판정하는가?
7. **우선순위**: 기준이 충돌하면 무엇을 먼저 지키는가?
8. **결정 권한**: AI가 정할 사항과 사용자가 정할 사항은 무엇인가?
9. **불확실성 처리**: 조사, 질문, 가정, 보류 중 무엇을 택하는가?
10. **출력과 완료**: 어떤 형태로 내고 무엇을 검증해야 끝나는가?
11. **경계 예시**: 말로만 경계를 닫기 어려울 때 원하는 예와 원하지 않는 예는 무엇인가?

## 발굴 절차

1. 사용자 요청, 대화, 현재 자료에서 이미 확정된 내용을 회수한다.
2. 확인 가능한 사실과 사용자만 정할 수 있는 결정을 분리한다.
3. 파일, 도구, 원자료에서 확인할 수 있는 사실을 먼저 조사한다.
4. 남은 결정이 결과를 바꾸는지 검사한다.
5. 선행 결정이 후속 선택지를 바꾸는 순서로 결정 트리를 정렬한다.
6. 질문하고 답을 실행 계약으로 변환한다.
7. 새 답이 이전 답과 충돌하는지 검사한다. 충돌하면 다음 질문으로 해소한다.
8. 종료 검사를 통과할 때까지 남은 중요한 결정을 질문한다.

## 질문 단위와 정박 방지

결과 방향을 바꾸거나 다음 질문에 영향을 주는 결정은 한 번에 하나씩 묻는다. 서로 독립적인 단순 사실은 함께 물을 수 있다. `grilling`과 `wayfinder`의 의도 발굴은 항상 한 번에 하나씩 묻는다.

첫 질문 전에 의도 발굴의 전체 지도를 짧게 설명한다. 사용자는 어떤 결정 영역을 어떤 순서로 닫을지 알 수 있어야 한다. 지도는 현재 요청에 필요한 가지만 보이고, 답에 따라 순서가 바뀌 수 있음을 밝힌다.

각 질문 전에 세 가지를 알린다.

1. 현재 묻는 결정 영역
2. 그 결정을 지금 먼저 닫는 이유
3. 사용자의 답이 실행 계약의 어느 항목과 후속 질문을 바꾸는지

이 설명은 여러 결정을 한꺼번에 묻는 우회로가 아니다. 설명 뒤에는 현재 결정에 대한 질문 하나만 제시한다.

사용자의 취향, 가치, 위험 허용도처럼 사용자 안에 답이 있는 질문은 먼저 중립적으로 묻는다. 사용자가 답하기 어려워하면 구별되는 예시와 선택지를 제시한다.

확정된 목표와 근거에서 도출할 수 있는 기술적 선택은 AI가 추천할 수 있다. 추천에는 전제, 이유, 다른 선택이 바꾸는 결과를 함께 준다. 사용자가 승인하기 전에는 AI 추천을 사용자 결정으로 기록하지 않는다.

사용자에게 프롬프트 양식이나 전문 용어를 채우라고 요구하지 않는다. AI가 사용자의 일상 언어를 목적, 범위, 기준, 권한, 완료 조건으로 변환한다. 변환 과정에서 새 의미가 생기면 사용자에게 확인받는다.

## 판정 가능한 평가 기준

평가 기준은 지정된 판정자가 산출물과 사용 가능한 근거를 보고 판정할 수 있어야 한다. 판정자는 판정 과정에서 새 평가 기준을 임의로 만들지 않는다.

다음 세 방법을 쓸 수 있다.

1. **직접 검사**: 포함 요소, 금지 요소, 수치 한계, 테스트 결과를 산출물에서 확인한다.
2. **기준점 비교**: 원하는 예, 원하지 않는 예, 등급별 기준점과 산출물을 비교한다.
3. **명시된 판단 절차**: 지정 판정자가 사전에 정한 질문과 비교 방법으로 합격·불합격 또는 후보 순위를 정한다.

### 구체화가 어려운 경우

| 상태 | 어려운 이유 | 판정 가능하게 만드는 방법 |
|---|---|---|
| 선호 미형성 | 사용자가 결과를 보기 전에 원하는 방향을 모른다. | 서로 다른 후보를 탐색하고 선택에서 기준을 형성한다. |
| 암묵적 선호 | 사용자는 보면 구별하지만 원리를 말로 설명하지 못한다. | 기준점 비교와 반복 선택으로 경계를 찾는다. |
| 전체적 품질 | 부분 조건의 합이 전체 품질을 설명하지 못한다. | 지정 판정자가 전체 후보를 기준점과 비교한다. |
| 새로운 해법 | 사전 기준이 예상 밖의 우수한 해법을 제거할 수 있다. | 최소 목적과 금지 조건만 고정하고 다양하게 탐색한다. |
| 결과 의존 | 후보를 보아야 비교 축이 드러난다. | 1차 탐색에서 비교 축을 추출하고 2차 수렴 전에 확정한다. |
| 장기·외부 성과 | 실제 성공이 나중에 외부 환경에서 드러난다. | 현재 대리 기준과 미래 성과 기준을 분리하고 판정 시점을 정한다. |
| 확률적 성과 | 같은 품질도 우연과 환경에 따라 다른 결과를 낸다. | 표본, 반복, 분포, 불확실성을 포함한 판정 절차를 정한다. |
| 맥락 의존 | 환경이 확정되기 전에는 좋은 결과의 조건이 달라진다. | 조건별 기준과 적용 분기를 정한다. |
| 다수 판정자 | 판정자별 기준이 충돌한다. | 판정 권한, 거부권, 집계 방법, 충돌 우선순위를 정한다. |
| 측정 왜곡 | 측정 가능한 대리 지표가 실제 목적을 대표하지 못한다. | 여러 증거를 쓰고 대리 지표의 한계를 명시한다. |
| 지식 부족 | 좋은 결과를 결정하는 원리를 아직 모른다. | 조사와 기준 설계를 선행 작업으로 둔다. |

직접 기준과 판정 절차 모두를 만들 수 없으면 중요한 평가 기준은 아직 미결정이다. 최종 산출물을 만들지 않고 기준 발굴 단계를 계속한다.

## 시점별 판정 가능성

최초 요청에서 최종 평가 기준을 모두 확정할 필요는 없다. 대신 현재 수행할 단계의 기준은 항상 판정 가능해야 한다.

- **탐색 단계**: 후보 방향의 차이, 필요한 다양성, 사용자의 비교 선택, 잠정 기준 형성을 판정한다.
- **수렴 단계**: 확정한 산출물 기준을 완료 조건과 검증 절차로 바꾼다.
- **장기 성과**: 현재 산출물의 대리 기준과 나중에 관찰할 실제 성과를 같은 것으로 표현하지 않는다.

## 종료 검사

다음 조건을 모두 만족할 때 의도 발굴을 끝낸다.

1. 현재 단계의 목적과 산출물이 확정됐다.
2. 결과를 바꾸는 사용자 결정이 모두 확정됐다.
3. 현재 단계의 평가 기준과 판정 절차를 적용할 수 있다.
4. 범위, 제외 범위, 자원, 권한, 완료 조건이 수행에 충분하다.
5. 사실, 사용자 결정, AI 추천, 가정이 구분됐다.
6. 충돌하는 답과 지시가 해소됐다.
7. 미결정 사항을 남기면 결정할 주체, 시점, 다음 행동이 정해졌다.
8. 수신 AI가 사용자 의도를 새로 만들어야만 수행할 부분이 없다.
9. 같은 자료를 받은 수신 AI 둘이 누락된 사용자 결정 때문에 다른 목표를 수행할 가능성이 없다.
10. 의도 발굴 세션에서는 AI가 전체 실행 계약을 다시 설명했고 사용자가 승인했다.

일반 작업에서는 1~9를 통과하면 별도 승인 절차 없이 수행한다. 의도 발굴이 작업 자체인 `grilling`과 `wayfinder`에서는 10을 함께 적용한다.

## 실행 계약 요약 골격

필요한 항목만 남기고 빈 절을 만들지 않는다.

```text
현재 단계의 목적:
산출물:
하류 사용처:
확정된 사용자 결정:
AI가 정할 사항:
입력과 정본:
범위와 제약:
평가 기준과 우선순위:
불확실성과 가정:
출력과 완료 조건:
미결정 사항:
```
