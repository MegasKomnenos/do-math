# 절차문

스킬의 절차, 계약 파일, 점검 목록, 운영 절차서처럼 단계로 수행을 지시하는 글에 적용한다. 절차문의 수신자는 문장을 실제 행동으로 바꾼다. 모호함은 질문이 아니라 갈라진 수행으로 드러난다.

## 시작과 종료

절차 시작 전에 세 가지를 정한다.

- 시작할 조건과 필요한 입력
- 절차가 변경할 수 있는 대상과 권한
- 완료를 판정할 상태와 증거

시작 조건이 없으면 언제 절차를 실행해야 하는지 판정할 수 없다. 종료 조건이 없으면 단계를 모두 수행하고도 완료를 판정할 수 없다.

## 단계

- 한 단계에 하나의 주요 행위를 둔다. 두 행위의 필수 여부나 성공 여부를 각각 판정해야 하면 단계를 나눈다.
- 선행 관계가 있는 단계에 번호를 붙인다. 동시 수행이 가능하면 병렬 가능한 범위를 적는다.
- 각 단계에 사용할 입력, 행위, 산출물, 성공 조건을 필요한 범위에서 명시한다.
- 조건을 행위보다 먼저 쓴다. `필요하면`처럼 수행자에게 판정 기준을 넘기는 말 대신 관찰 가능한 조건을 쓴다.
- 실패나 예외 다음에 정상 흐름으로 복귀할 위치를 정한다. 중단된 절차는 이미 끝난 비가역 행위를 반복하지 않게 재개 좌표를 남긴다.

단계의 주석, 괄호, 여담에 지시·요구·한계를 숨기지 않는다. 주석을 제거한 본문만으로 올바르게 수행할 수 있어야 한다.

## 분기와 예외

분기는 관찰 가능한 조건과 각 조건의 다음 행동을 연결한다. `문제가 있으면 고친다`처럼 판정 기준과 행동이 빈 분기를 쓰지 않는다.

예상 가능한 이탈에는 처리 방법을 적는다. 수행자가 임의로 무시해도 되는 이탈과 중단해야 하는 이탈을 구분한다.

### 이탈 등급 (S27)

절차 문서는 사용할 이탈 등급을 닫힌 낱말로 정의한다. 이탈 조항은 등급을 첫 자리에 두고, 조건, 행동, 이탈을 무시하면 생길 결과를 함께 적는다.

예:

```text
중단: 원자료를 읽을 수 없으면 수행을 중단한다. 원자료 없이 진행하면 결론의 정확성을 판정할 수 없다.
```

## 용어와 상태

같은 작업, 상태, 처분은 절차 전체에서 같은 낱말로 부른다. 현재 상태와 행동을 구분해야 하면 이름으로 드러낸다.

상태 전이를 기계가 읽거나 여러 에이전트가 집계하면 허용 상태 값을 닫힌 목록으로 정한다. 상태를 확정할 수 없을 때 쓸 값도 정한다.

모든 용어에 복잡한 사전을 강제하지 않는다. 실제로 재해석된 용어나 두 가지 전문적 읽기가 모두 성립하는 용어만 경계와 예를 추가한다.

## 절차문 점검

- 시작 조건, 입력, 권한, 완료 조건이 있는가?
- 한 단계의 성공과 실패를 따로 판정할 수 있는가?
- 조건이 행동보다 먼저 있는가?
- 열린 표현을 수행자가 임의로 판정해야 하는가?
- 모든 분기에 다음 행동과 복귀 좌표가 있는가?
- 주석을 제거해도 올바르게 수행할 수 있는가?
- 상태와 처분 낱말이 절차 전체에서 같은 뜻인가?
