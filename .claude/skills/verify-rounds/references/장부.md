# 장부 서식

장부는 세션이 쓰는 상태의 정본이다. 기재의 기계 작업은 공식 스크립트(`장부머리`·`장부갱신`·`종료집계`)가 맡고, 이 문서는 서식과 상태 어휘를 닫는다.

## 상태와 전이

항목의 상태는 아홉이다:

| 상태 | 뜻 |
|---|---|
| 제기 | 수리판독이 항목을 세웠다 |
| 병합 | 묶음에 들어 병합 항목이 이 항목을 대신한다. 이후 상태는 그 묶음의 확정이 전파한다 |
| 기각 | 심사에서 정족에 미달했다 |
| 무처분 | 승인되었으나 고치지 않는다 |
| 상신 | 사용자에게 올렸다 |
| 전달 | 승인된 발견 — 호출자에게 전달했다 |
| 수리확정 | 「수리한다」로 확정되어 적용을 기다린다 |
| 적용 | 산출물에 반영되었다 |
| 결번 | 병합 결번으로 이번 라운드에서 빠졌다 |

전이는 넷이다:

- 제기 → 병합 | 기각 | 무처분 | 상신 | 전달 | 수리확정
- 병합 → 기각 | 무처분 | 상신 | 수리확정 | 결번 (묶음의 확정 전파)
- 상신 → 수리확정 | 무처분 (§8 승계 전환·회신·자체 처리)
- 수리확정 → 적용.

**금지** — 장부 행을 다음 라운드 수리자에게 주는 것. 어기면 수리자가 앞 항목을 되풀이해, 결함의 재발과 새 발견을 가르지 못한다.

## 절 목록

절 유형은 아래 일곱으로 닫는다. 1~5는 라운드마다 `## 라운드 <N> — <유형 이름>`으로 두고, 6·7은 런에 한 벌만 두고 라운드 표지를 붙이지 않는다. 유형 이름은 목록의 축자를 그대로 쓴다. 다른 절이나 줄인 제목은 공식 스크립트가 읽지 못한다.

1. 라운드 머리
2. 본표
3. 묶음 구성표
4. 사유 절
5. 결산
6. 신호 처리 절
7. 운영 기록

## 1. 라운드 머리

세션이 쓰는 재료 파일(`라운드N/_라운드머리.md`)의 절은 다섯으로 닫는다. 앞 셋은 필수이고 뒤 둘은 있을 때만 둔다. 서식과 기계 작업은 `장부머리 --help`가 정한다:

- `## 파라미터 전건`
- `## 상한 측정값 대조` — 심사 분할 발동 여부와 배치 수
- `## 영역 검산 결과` — 재정박 행 번호와 결번 기의 「검토되지 않음」을 포함한다
- `## 모델 배정 변경`
- `## 파라미터·배정의 도중 변경` — 변경 내용과 시점

배정·파라미터 변경은 라운드 머리에만 적는다. 밖에 적은 변경은 적용하지 않는다.

## 2. 본표

항목마다 ID / 위치 / 요지 / 심사 / 처분 / 상태 한 행을 쓴다. `장부갱신 --모드 제기`가 세우고 묶음·심사·적용 모드가 갱신한다. 위치는 첫 조각의 좌표 표기(상신 제안 항목은 「상신 제안」, 발견 항목은 「발견」), 요지는 항목 제목의 축자, 심사는 「승인 수/기수」다. 묶음 ID는 본표에 행을 두지 않는다 — 묶음의 확정·적용은 구성 항목 행에 전파된다.

칸 안의 파이프 문자는 `\|`로 적는다. 칸을 가르는 것은 앞에 역빗금이 없는 `|` 하나다. 이 규약은 본표와 묶음 구성표에 함께 걸린다.

## 3. 묶음 구성표

묶음 ID(`R<라운드>-M<순번>`)와 구성 항목 ID 목록과 조각 수를 적는다. `장부갱신 --모드 묶음`이 세운다.

## 4. 사유 절

기각 항목의 심사자 기각 사유(다음 라운드의 재발 신호)와 결번의 사유를 적는다. `장부갱신 --모드 심사`가 기각 사유를 덧붙이고, 결번은 세션이 적는다. 기재 전에 절을 미리 세우면 본문을 `(해당 시 기재)` 한 줄로 둔다 — `장부갱신`이 그 축자 줄만 지우고 기재를 잇는다.

호출자가 기각 보관 경로를 주면 `심사집계`가 기각 항목과 무처분 항목의 원문·심사
판정·근거를 별도 파일에 보존한다. 사유 절은 장부 안의 상태 기록이고, 기각 보관 파일은
호출자가 worktree 종료 전에 다시 검토할 지급물이다. 둘 가운데 하나가 다른 하나를
대체하지 않는다.

## 5. 결산

`종료집계`가 라운드 판정을 낼 때 이 절을 함께 기재한다 — 본표에서 센 상태별 건수를 「<상태> <수>」 축자로, 판정과 근거 수치를 그 아래에 적는다. 세션이 수기로 쓰지 않는다. 상태 건수의 「적용 <수>」가 이 절에서 그 서식의 첫 출현이어야 한다 — `종료집계`가 앞 라운드의 적용 건수를 그 첫 출현에서 회수한다(「미적용」처럼 앞에 글자가 붙은 출현은 세지 않는다).

## 6. 신호 처리 절

SKILL.md §8 신호의 처리를 적는다. 기재는 셋이다:

- 상신 — 신호 1로 올린 항목은 올린 내용과 사용자의 답과 처분 변경을 적는다. 신호 2~7로 올린 것은 신호 번호와 올린 내용과 답과 그 답이 낳은 세션의 행동을 적는다.
- 승계 — 승계가 선 항목마다 항목 ID / 인용 좌표(사용자 확정 기록의 경로와 자리) / 성립 자리를 적는다. 성립 자리는 「심사」·「전환」 둘이다 — 심사자 자리에서 선 승계는 「심사」, 세션의 승계 전환은 「전환」이다. 전환이면 원 처분을 함께 적는다.
- 자체 처리 — 신호 번호와 상황과 판단과 물음 셋의 답을 적는다. 사용자 확정 기록을 뒤집었으면 그 기록의 좌표와 뒤집는 근거를 함께 적는다.

## 7. 운영 기록

SKILL.md가 운영 기록을 지정한 자리를 전건 적는다:

- §2의 재량 행사와 예상 밖 판단
- §5.3 4항의 스크립트·시험 수정
- §5.6의 대기 60분 초과 실행의 원인
- §5.7의 `_` 보조 스크립트 셋 — 이름 / 맡은 작업 / 공식 스크립트가 그 작업을 덮지 않는다는 판단의 근거
- §7 4단계의 불변식 재실측 명령과 결과
- §7의 런 도중 사용자 지시 반영

설계 근거: `references/근거.md`의 「references/장부.md」 절.
