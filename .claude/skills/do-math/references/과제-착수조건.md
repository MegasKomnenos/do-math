# 과제의 착수 조건

후보 준비는 이 문법으로 착수 조건을 저작하고, 작업 계약 검토는 조건이 실제 질문의 선행관계와 맞는지 대조한다. 문법·참조 검사는 생산자 검사와 실행기가 수행하며, 조건의 의미와 연구 의무의 적합성은 해당 AI 역할이 판단한다.

조건 객체는 `op`와 다음 표의 필드로 작성한다. 조건의 기록 ID와 비교값은 실제 입력에서 확인하며, 현재 구현에는 별도 `space` 필드를 쓰지 않는다.

| `op` | 함께 쓸 필드와 뜻 |
|---|---|
| `always` | 추가 필드 없이 참인 조건이다. |
| `all`, `any` | 비어 있지 않은 조건 배열 `args`를 둔다. 각각 전건 참, 하나 이상 참을 요구한다. |
| `not` | 부정할 조건 객체 하나를 `arg`에 둔다. |
| `record_exists` | `record_id`와 기록 가족 `family`를 둔다. 지정 ID의 기록이 그 가족에 속하는지 확인한다. |
| `record_lifecycle_is` | `record_id`, 비교할 `value`를 둔다. 기록의 `lifecycle`을 읽고 그 필드가 없으면 `status`를 읽는다. |
| `record_field_equals` | `record_id`, 아래에서 허용한 `pointer`, 스칼라 `value`를 둔다. 실제 필드값과 자료형까지 같아야 한다. |
| `relation_exists` | 관계 종류 `subkind`, 출발 ID `from_id`, 도착 ID `to_id`를 둔다. 관계 출력의 `source`·`target`을 여기의 필드명으로 쓰지 않는다. |
| `task_disposition_is` | `task_id`, 요구하는 종결 처분 `value`를 둔다. `value`는 착수 의도에 맞는 `completed` 또는 `closed`다. |

`family`는 기록의 구체적인 지식 종류와 구별한다. 현재 기록 가족은 `knowledge`, `governance`, `grant`, `task`, `activity`, `execution`, `decision`, `external-operation`, `source`, `trust-environment`, `review-cycle`, `instance`다. 조건에서 참조한 대상이 실제로 제공되지 않았다면 존재하는 ID처럼 만들어 넣지 않는다.

`record_field_equals`의 `pointer`는 `/`로 시작하며 아래의 기계 필드만 가리킬 수 있다. 해당 기록에 그 필드가 실제로 존재하고 스칼라값을 가져야 한다. 자유 산문이나 객체·배열 전체를 비교하지 않는다.

| 기록 가족 | 허용 포인터 |
|---|---|
| `knowledge` | `/status`, `/lifecycle`, `/kind`, `/value`, `/use_suspended` |
| `task` | `/status`, `/revision` |
| `activity` | `/status`, `/role` |
| `execution` | `/status`, `/role`, `/outcome`, `/http_status`, `/succeeded` |
| `governance`, `grant` | `/status`, `/lifecycle` |
| `decision` | `/kind` |
| `external-operation` | `/status`, `/http_status`, `/succeeded` |
| `source` | `/status`, `/revision`, `/sha256` |
| `trust-environment` | `/status` |
| `review-cycle` | `/status`, `/decision`, `/phase` |
| `instance` | `/goal_status`, `/goal_revision`, `/policy_revision` |

예를 들어 같은 응답에서 만든 과제 `가정 H 조사`의 완료 뒤 과제 `H를 사용한 증명`을 시작하려면 다음처럼 선행관계를 제출한다. 두 제목은 실제 주 산출의 제목과 같아야 한다.

```json
{"task_conditions":[{"task_title":"H를 사용한 증명","dependencies":["가정 H 조사"],"occurrence_condition":{"op":"always"}}]}
```

실행기는 선행 과제의 완료 조건을 결합하고, 조건 안의 `record_id`, `task_id`, `from_id`, `to_id`에 같은 준비 결과의 유일한 제목이 있으면 새 ID로 결박한다. `not`은 평가 오류를 참으로 바꾸지 않으며 `all`·`any`도 하위 조건의 오류를 숨기지 않는다. 현재 실행기가 지원하지 않는 연산자를 만들지 않는다. 실행기가 이름 결박과 조건 검사를 끝내기 전에는 착수 가능하다고 주장하지 않는다.
