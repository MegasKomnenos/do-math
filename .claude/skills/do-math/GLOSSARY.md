# do-math 공통 정의

이 문서는 루트 `CONTEXT.md`의 보편 정의와 `통합-설계.md`의 실행 구조를 역할 입력에 옮긴다. 필드·전이·권한의 정확한 형식은 input manifest와 규범 묶음이 소유한다.

- **K(형식 정본)**: 활성 신뢰 환경에서 편입된 Lean 결과의 집합이다. K 편입은 자연어 의도·목표 해결을 보증하지 않는다.
- **F(가시 연구 프런티어)**: 질문·가설·장애물·부분 결과의 연구 기록이다. F의 존재나 과제 완료는 수학적 승인과 다르다.
- **형식 타당성**: 정확한 Lean 환경에서 타입·증명·공리 의존이 허용된 상태다. 해설 동일성과 다르다.
- **해설 동일성**: 해설의 정의·가정·명제·양화·범위·결론이 형식 결과와 맞는지 독립 검토가 판단한 상태다.
- **목표 감사**: 현재 헌장 목표와 K·해설·동일성 판정을 대조하는 활동이다. K 하나나 활동 완료로 목표 해결을 추측하지 않는다.
- **과제·활동·실행**: 과제는 연구 의무, 활동은 업무 책임, 실행은 한 번의 수행이다. 과제 완료·활동 종료·실행 ended는 서로 대체하지 않는다.
- **정보 상태**: evidence·inference·hypothesis·intuition·random처럼 근거의 성격을 구별한다. 부재는 승인·안정·미호출의 증거가 아니다.
- **원자료와 관계**: 원자료는 정확한 참조·해시·좌표로 회수한다. 관계는 실제로 확인한 방향·범위·근거를 가진 연결이며 링크만으로 수학적 함의를 만들지 않는다.
- **허가와 권한**: 사용자 결정·헌장·정책·실행 허가는 서로 다른 근거다. AI의 JSON ID나 주장만으로 권한이 생기지 않는다.
- **do-math-cli/1 인스턴스 상태**: ready는 다음 action을 실행할 수 있고, running은 실행 중이며, paused는 명시적 정지 또는 실행 실패 뒤 재개를 기다린다. waiting은 질문·입력·다음 결정이 필요하고, budget_exhausted는 명시된 호출 한도를 소진했으며, completed와 closed는 각각 목표 판정 완료와 사용자 종료다.
- **do-math-cli/1 과제 상태**: planned, ready, needs_revision, performing, waiting, assessing, completed, closed를 사용한다. ready는 계획자가 선택할 수 있고, performing은 연구 실행이 배정됐으며, assessing은 반환된 연구 결과의 완료 기준 판정을 기다린다.
- **do-math-cli/1 활동 상태**: active, finished, unresolved를 사용한다. finished는 출력이 수신·검사를 통과한 활동이고, unresolved는 실행 또는 출력 검사를 완료하지 못한 활동이다.
- **do-math-cli/1 실행 상태**: starting, running, ended를 저장한다. ended의 outcome은 output_accepted와 execution_incomplete 등을 구별한다. 종료 장벽과 원격 사용량·외부 효과의 미확인은 별도로 남는다.

이 상태 집합은 현재 `do-math-cli/1` 저장·조회 계약이다. 통합 설계의 더 넓은 상태 기계 전건이 구현됐다는 뜻이 아니며, 대상이 다른 상태를 서로 대신하지 않는다.

AI는 새 수학 의미·판정·이유를 저작할 수 있지만, 권한·식별자·해시·배정·참조를 추측해 만들 수 없다. 불확실하면 실제 근거와 다음 소유자를 남긴다.
