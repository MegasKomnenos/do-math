# 실제 Codex·Claude 혼합 연구의 작은 목표 완주

## 맡은 결과

수용된 새 do-math를 실제 사용자 진입 경로에서 사용해, Codex와 Claude가 함께 참여하는 연구 인스턴스 하나가 사람의 개입 없이 작은 수학 목표를 처음부터 목표 검토의 달성 판정까지 완주하게 한다. 사용을 막는 구현·문서 결함을 발견하면 이 task의 workspace에서 수정하고 필요한 최소 확인까지 함께 마친다. 파일과 스크립트 존재만으로 완료하지 않는다.

먼저 inputs/context.md, inputs/plan.md, inputs/seams.md와 task.json을 읽는다. 실제 제품 진입점은 자기 workspace의 `.claude/skills/do-math/SKILL.md`다. 이어 RUNTIME.md, protocol.md, common.md와 범주 문서, runner.py/cli_adapter.py/check.py의 해당 부분을 읽는다. 확정 요구 원문은 `C:/math/.async/do-math-rebuild-20261021/user-messages.md`다. 이전 do-math나 Git 이력을 설계 자료로 사용하지 않는다. runner task의 보고는 무엇을 이미 확인했고 무엇이 미확인인지 구분하는 근거이며 혼합 완주를 대신하지 않는다.

## 실제 수행

1. SKILL.md가 안내하는 준비→init→start→기동 확인을 사용한다. 목표는 모든 자연수 n(0 포함)에 대해 n + 0 = n임을 Lean으로 증명하고 그 증명에 충실한 사람이 읽을 해설을 쓰는 정도로 작게 둔다. 이 목표와 필요한 조건만 전달하고 계획·연구·검토의 산출을 개발 task가 대신 작성하지 않는다.
2. 새 인스턴스는 자기 task 기록 아래 `evidence/instance-<고유이름>/`처럼 제품 변경과 구분되는 위치에 둔다. 자체 Git을 가지며 저장소 본체와 섞이지 않아야 한다. 목표·설정 원문과 실제 기동 명령, 로그 경로를 `evidence.md`에서 찾을 수 있게 한다. 자기 workspace 스킬의 runner를 사용하며 공용 소스와 다른 task는 수정하지 않는다.
3. 실제 설치와 로그인 환경을 사용한다. context 7절의 Codex·Claude·Lean 경로는 시작점이며 필요한 작은 파일/명령 확인만 한다. 범주 기본 모델 일부를 Codex, 일부를 Claude로 설정한다. 예를 들어 plan/research는 `codex/gpt-6.1-sol`, review는 `claude/sonnet`, 노력은 각 CLI가 지원하는 값을 쓴다. 공급자 접두는 설정에만 있고 실제 argv에는 모델 나머지가 전달된다. max_sessions는 작은 값으로 충분하다. core Lean으로 충분한 목표이므로 Mathlib이 필수인 것처럼 만들지 않는다. 실제 사용한 lean --version 문자열이 공개 결과에 기록되어야 한다.
4. 독립 start 호출의 PID와 새 로그를 확인한다. 개발 검증을 위해 이후 status와 공개 결과를 관찰하되, 연구의 계획·지시·산출·검토에 사용자 입력이나 수동 파일 편집으로 개입하지 않는다. 실제 세션이 공식 검사를 사용하고 실행기가 재검사·Git 반영하여 연구→독립 검토→다음 계획→목표 검토를 잇는 근거를 남긴다. 두 CLI의 참여는 설정만으로 판단하지 말고 실제 세션과 기록으로 확인한다.
5. 구현 때문에 진행할 수 없으면 원인과 영향, 작은 수정 범위를 판단한다. 제품의 직접 관련된 코드·문서와 필요한 시험을 workspace에서 고치고, 수정 뒤 처음부터 완주할 새 인스턴스를 사용해 무인 완료 근거를 만든다. 이미 충분한 가짜 시험 전체를 반복하거나 새 방어 체계를 추가하지 않는다. 수학 판단은 세션에 맡기고 검사 범위를 넓히지 않는다. 실패 인스턴스는 근거로 남기되 새 파견이 불필요하게 계속되지 않도록 운영 명령으로 정리하고 상태를 기록한다.
6. 실제 공급자 한도가 생기면 정상 대기 경로를 관찰하고 따른다. 한도 발생을 일부러 유도하지 않는다. 인증·계정 접근 또는 외부 입력 때문에 완료할 수 없으면 정확한 오류·인스턴스 상태·필요 입력을 보고한다. 자동으로 끝난 세션을 재실행하거나 사용자가 정한 세션 시간 상한 없음 원칙을 바꾸지 않는다. 단순히 오래 걸린다는 이유로 정상 연구 세션을 실패로 취급하지 않는다.

## 완료 판단과 최소 확인

실제 공개 연구 해설과 Lean 원문, 해당 연구를 공개 자료만으로 판단한 독립 검토, 목표 검토의 achieved 판정, 실행기의 complete 상태와 기존 세션 반영 종료, 인스턴스 Git 기록을 확인한다. 해설의 자연수 범위·정리·증명이 목표를 충족하는지 내용도 읽는다. 검토가 Lean 재컴파일과 해설 일치를 어떻게 확인했는지 공개 근거로 대조한다. 작성자 작업 로그로 수학 검토를 대신하지 않는다. 개발 기록에서는 실제 모델 참여·공식 검사 호출·프로세스 흐름 확인에 필요한 세션 로그의 최소 부분을 사용할 수 있다.

report와 evidence.md에는 인스턴스 절대 경로, 각 세션 ID·범주·공급자·모델·노력, 공개 기록 ID와 검토 연결, 목표 달성 기록, Git 근거, 실제 Lean 판본, 발견한 결함과 수정·재확인 범위를 남긴다. 직접 확인하지 않은 Linux·실제 한도·장기 어려운 연구까지 결론을 확대하지 않는다. 실제 완주에 필요한 확인을 마치면 종료하며 최종 독립 개발 review는 후속 task가 맡는다.

제품 쓰기 범위는 자기 workspace의 `.claude/skills/do-math/`다. 그래프 갱신, `.agents/skills/do-math/` 복사, 다른 저장소 범위 변경은 포함하지 않는다. 제품 변경 없이 완주하면 changes는 빈 목록이다. 제출 전 `python C:/math/services/async-development/check.py report C:/math/.async/do-math-rebuild-20261021 mixed-completion`을 실행한다.
