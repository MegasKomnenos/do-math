# Codex·Claude 기동과 공급자 한도 어댑터

## 맡은 결과와 입력

후속 실행기가 두 CLI로 새 세션을 띄우고, 끝난 로그의 공급자 한도를 보고 파견 대기 시각을 정할 수 있도록 작은 Python 어댑터를 만든다. 이 기능은 연구 산출 프로토콜과 독립적이다. 먼저 `inputs/context.md`, `inputs/plan.md`, `inputs/seams.md`, `task.json`을 읽는다. 수용된 조사 진입점은 `C:/math/.async/do-math-rebuild-20261021/tasks/cli-discovery/cli-evidence.md`이며 필요한 help·소스·설치 구현 발췌는 같은 디렉터리에 있다. 확정 요구 원문은 `C:/math/.async/do-math-rebuild-20261021/user-messages.md`다. 과거 do-math 구현이나 다른 task의 미수용 산출을 참고하지 않는다.

사용자는 두 CLI, 범주별 기본 모델·노력과 계획의 선택적 개별 지정, 공급자 한도 때 파견 대기를 요구했다. 기본값과 개별 지정을 합치는 것은 실행기의 책임이고, 어댑터는 최종 선택된 모델·노력과 필요한 명시적 값을 받는다. 인스턴스 설정, 세션 산출, 실행기 상태와 흐름을 새로 정할 필요가 없다.

## 구현

1. 모델 이름에서 공급자를 정하는 단순한 규칙과 두 CLI의 argv 생성 함수를 제공한다. 지원 범위와 모르는 이름의 오류 의미를 설명한다. 선택한 CLI 경로, 모델, 노력, 작업 디렉터리를 명시적 입력으로 받는다. stdin 프롬프트·로그 파일을 연결하는 호출 예를 제공하되 프로세스 수명·PID 저장·독립 실행기 기동은 후속 실행기의 책임으로 둔다. 새 대화, 무인 승인, 설치된 구독 인증과 맞는 옵션을 사용한다. 권한 옵션이 OS 수준의 폴더 격리라는 설명은 하지 않는다.
2. 끝난 stdout/stderr에서 공급자 사용 한도와 대기 만료 시각을 얻는 함수를 제공한다. 한도 없음과 한도 있음(확인된 해제 시각 또는 설정 간격에 따른 대기)을 호출자가 구분할 수 있어야 한다. 반환 시각의 단위·시간대, 현재 시각·설정 대기 간격 등 필요한 입력, 입출력 오류의 의미를 문서화한다. 함수 이름·정확한 시그니처는 구현자가 정하고 `CLI.md`에 실제 심볼로 연결한다. 불필요한 범용 플러그인 구조 대신 표준 라이브러리와 작은 함수를 우선한다.
3. Codex는 조사에서 확인한 오류 이벤트의 한도 메시지와 retry 시각을 읽는다. 정상 답변·도구 출력의 인용은 한도 신호가 아니다. 로컬 시간만 있는 경우 메시지 날짜를 확인할 수 있는 입력 정보가 충분할 때만 해석하고, 자정 경계 등으로 불명확하면 설정 간격을 쓴다. 실제 출력에 없는 숫자 reset 필드를 가정하지 않는다.
4. Claude는 조사에서 확인한 계정 한도 거절 표식과 Unix 초 정보를 우선한다. 일반 429, rate_limit, allowed/allowed_warning만으로 한도를 판정하지 않는다. `rate_limit_event` 보조 경로를 쓰면 paid overage가 계속 가능한 경우를 차단하지 않도록 근거를 따른다. 여러 reset의 선택은 의미가 확인된 분기만 처리하고 알 수 없으면 설정 간격을 사용한다. 조사의 구현 제안은 확정 요구가 아니므로 가장 단순하고 근거 있는 선택을 문서화한다.
5. 전체 CLI 출력 적합성은 세션 승인 조건이 아니다. JSON이 아닌 줄·알 수 없는 필드·중복 키·의미 없는 값 때문에 산출 처리를 실패시키지 않는다. 한도 탐지와 공식 산출 검사는 별개이며 어댑터는 산출을 승인·거절하거나 세션을 재시작하지 않는다. 프로세스 종료 코드나 성공 이벤트를 산출 승인 조건으로 추가하지 않는다.

## 쓰기 경계

제품 변경은 자기 workspace의 다음 세 파일에 한정한다.

- `.claude/skills/do-math/cli_adapter.py`
- `.claude/skills/do-math/CLI.md`
- `.claude/skills/do-math/tests/test_cli_adapter.py`

진행 중인 `protocol-checker`의 objective는 CLI 어댑터를 제외하고 있다. 그 작업의 범위나 산출을 바꾸지 않는다. CLI.md는 실행기 작성자가 함수 입력·출력·오류 및 Windows 호출 방법을 바로 사용할 수 있는 진입점이다. 조사 근거의 중요한 내용과 한계는 제품 본문에 설명하고, 필요하면 공식 출처와 연결한다. RECORDS의 조사 파일만 읽어야 함수 의미를 알 수 있게 만들지 않는다. 제품 문서에서 개발 과정 설명은 줄이고 그 과정은 task 기록에 둔다.

## 완료와 최소 확인

두 argv 생성 결과를 help와 대조한다. 한도 탐지는 조사 근거에서 만든 작은 합성 입력으로 두 공급자의 한도·미래 해제 시각, 시간 미확인 시 간격 대기, 정상 인용·경고 및 섞인 불완전 로그를 구분하는지 확인한다. 시각을 입력으로 주어 긴 실제 대기 없이 확인한다. 검증은 실제 불확실성을 해소하는 대표 사례만 사용한다. 실제 계정 한도를 유도하거나 실제 모델 OK 호출을 반복하지 않는다. 두 모델의 실제 산출 작성은 후속 혼합 완주가 담당한다.

`report.json`에 실제 확인 범위와 한계, 파일·함수 계약, 후속 실행기가 할 일과 선택 이유를 기록한다. 사용한 로그 예가 합성임을 명시한다. `python C:/math/services/async-development/check.py report C:/math/.async/do-math-rebuild-20261021 cli-adapter`로 보고 형식과 변경 범위를 확인한다.
