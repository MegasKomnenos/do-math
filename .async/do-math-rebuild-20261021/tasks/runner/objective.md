# 연구를 이어 가는 실행기와 사용자 명령

## 맡은 결과와 입력

사용자가 목표와 설정을 넣은 인스턴스를 독립 프로세스로 기동하면, 사람의 대화 없이 계획→연구→검토→다음 계획을 이어 가고 목표 검토의 달성 판정으로 완료할 수 있게 만든다. 구현과 필요한 작은 가짜 세션 흐름 확인을 이 task에서 함께 마친다. 실제 모델로 하는 혼합 완주와 사용자 진입 문서 SKILL.md는 이후 작업이다.

먼저 inputs/context.md, inputs/plan.md, inputs/seams.md, task.json을 읽는다. 자기 workspace의 `.claude/skills/do-math/protocol.md`, `check.py`, `cli_adapter.py`, `CLI.md`가 수용된 제품이다. 추가 근거는 `C:/math/.async/do-math-rebuild-20261021/tasks/cli-discovery/cli-evidence.md`와 그 문서가 연결한 help·소스 발췌다. 확정 요구 원문은 `C:/math/.async/do-math-rebuild-20261021/user-messages.md`다. 예전 do-math 구현은 참고하지 않는다. async-development는 원리만 참고하며 엔진을 가져오지 않는다.

진행 중인 session-contexts는 common.md, plan.md, research.md, review.md를 작성한다. 그 배정과 미수용 산출에 의존하지 않는다. 이 네 파일의 예정 경로는 seams 2절에 확정되어 있으므로 실행기는 그 경로를 input.json에 연결한다. 작은 흐름 시험에는 시험용 임시 맥락 파일을 사용해도 된다. 후속 manager가 실제 문서와 연결한다.

## 첫 연결 보완: 모델 표기

protocol.md 1절과 check.py의 요청은 `codex/<CLI 모델>`·`claude/<CLI 모델>`을 사용하지만 현재 어댑터 provider_for_model/build_command는 bare 모델 이름을 추정한다. 프로토콜의 명시적 공급자 접두를 유지한다. 어댑터를 앞부분으로 공급자를 고르고 첫 `/` 뒤 전체를 실제 CLI 모델로 전달하도록 수정하고 CLI.md와 기존 argv 시험을 함께 맞춘다. 알려진 bare 모델 목록을 새 제약으로 두거나 호환 분기를 만들 필요가 없다. 최소한 codex/gpt-6.1-sol, claude/sonnet 및 `/`를 포함한 모델 나머지가 올바르게 전달됨을 확인한다. 모델 존재와 계정 접근 권한은 실제 CLI가 판단한다.

## 구현할 동작

1. 인스턴스의 goal.md/settings.json과 protocol.md의 디렉터리 계약을 사용한다. 실행기는 Python 표준 라이브러리와 Git, 수용된 검사기·어댑터를 우선 사용한다. 상태·사건·미완료 요청·프로세스 정보의 내부 형식은 이 task가 최소한으로 정한다. 자기 인스턴스의 Git을 초기화하고 저장소 본체의 Git과 분리한다. 환경 고정·파일 해시 봉인·설치 비교·수학적 내용 판정은 추가하지 않는다.
2. context.md 4절의 흐름과 불변식 열 가지를 구현한다. 시작 사건으로 계획 하나를 띄운다. 계획의 연구·추가 검토·목표 검토 요청을 게시하고 요청별로 새 세션을 한 번 파견한다. 연구 반영 뒤 자동 검토 하나를 붙인다. 검토 반영·세션 실패·사용자 입력은 아직 어느 계획에도 주지 않은 사건들과 함께 다음 계획에 준다. 실행 중 계획이 받지 않은 사건은 이후 계획에 남긴다. 정상 연구 반영 자체를 계획 사건으로 만들지 않는다. 모든 범주의 합계가 max_sessions를 넘지 않으며 계획은 동시에 하나다. 빈 새 계획이 앞선 미완료 요청을 취소하지 않는다.
3. 기동 프롬프트는 자기 세션 폴더·input.json·공식 검사 명령을 알려 준다. common 목록에 common.md, protocol.md, 인스턴스 goal.md, category에 해당 범주 문서를 연결한다. 계획은 이미 게시한 미완료 과제와 대체 의도를 읽어 중복 배정을 피할 수 있어야 한다. 그 실행 상태의 읽기 경로·필드 의미를 RUNTIME.md에 설명하고 계획 기동 맥락에서 발견할 수 있게 한다. 검토에는 대상 공개 지식과 자기 입력만 전달하며 작성자 세션 폴더·로그 경로를 추가하지 않는다. 쓰기는 자기 세션 폴더로 지시하며 실행 감시 장치를 만들지 않는다.
4. 요청의 model/effort는 지정한 필드만 범주 기본값을 덮어쓴다. 계획 자신과 자동 검토는 기본값을 쓴다. 어댑터의 Command.argv/cwd를 shell=False, UTF-8 stdin 파일, 별도 stdout/stderr 파일에 연결한다. 두 CLI 모두 새 대화를 띄우며 세션 시간 상한은 두지 않는다. CLI 핸들로 종료를 확인하고 PID와 시작 시각을 남긴다.
5. 끝난 방식·종료 코드와 무관하게 공식 check.py로 재검사한다. 통과한 output/ 전체를 새 knowledge/<ID>/에 복사하고 인스턴스 Git에 커밋한다. 입력·중간 작업·로그는 공개 지식으로 복사하지 않는다. 기존 기록은 덮어쓰지 않는다. 검사 실패·산출 부재는 이유를 가진 session_failed 사건으로 다음 계획에 보낸다. 기동 실패도 다음 판단이 가능하게 기록한다. 재검사·반영된 목표 검토의 achieved만 완료로 만들고, 완료 뒤 새 파견은 전부 막되 이미 돌던 세션의 종료·반영은 계속 처리한다.
6. 종료 로그의 공급자 한도는 detect_usage_limit로 읽어 전체 새 파견을 retry_at까지 대기시킨다. 이미 돌던 세션과 산출 재검사는 계속 처리한다. 로그 읽기 OSError는 기록하고 산출 재검사를 계속한다. 한도 만료가 STOP·외부 입력 대기·완료를 해제하지 않는다. 끝난 세션을 자동으로 그대로 다시 띄우지 않는다.
7. STOP 존재 시 새 파견만 막는다. 계획의 wait 선언도 새 파견을 막고 사용자 입력으로 해제한다. control/inputs/ 원문을 보존하면서 각 입력을 다음 계획에 전달한다. 대기 중 실행기가 살아 있을지 종료할지는 구현자가 정하되, 사용자가 입력 후 해야 할 동작을 명확히 문서화한다.
8. 같은 인스턴스 실행기는 하나만 돌도록 최소한의 프로세스 잠금을 둔다. 실행기 사망·재부팅 후 사람의 재기동으로 기록상 실행 중인 세션을 확인한다. 실제 살아 있으면 그대로 기다리고, 죽었으면 남은 산출을 같은 검사·반영/실패 절차로 처리한다. 세션 재파견·중복 지식 반영을 피할 만큼의 상태 저장과 복구를 구현한다. 자동 감시/재기동 서비스는 만들지 않는다. PID만으로 잘못된 프로세스를 종료하지 않도록 필요한 식별 정보를 보존하고, 사용자가 세션 하나를 끝내는 실제 방법을 제공한다.

## 사용자 명령과 제품 문서

진입 스크립트는 `.claude/skills/do-math/runner.py`, 소비자 안내는 `RUNTIME.md`로 둔다. 세부 하위명령과 상태 형식은 구현자가 정한다. 최소한 아래 일을 실제 명령 또는 문서화된 파일 조작으로 할 수 있어야 한다.

- goal·settings 파일로 새 인스턴스를 준비한다.
- 실행기를 대화와 수명이 분리된 프로세스로 기동/재기동하고 PID와 새 시작 로그로 확인한 뒤 호출자가 끝날 수 있다. Windows의 무창 기동을 포함한다.
- 상태, 진행 중 세션, 미완료 요청, 대기 이유, 완료와 공개 지식 위치를 조회한다.
- STOP을 놓고 거두며 사용자 입력을 전달한다.
- 끝나지 않는 세션 하나를 식별해 프로세스를 종료하고, 남은 산출은 실행기의 일반 종료 처리로 넘긴다.

RUNTIME.md는 SKILL 작성자와 후속 실제 완주 작업자가 읽을 제품 진입점이다. 목적·기본 흐름과 명령의 입력, 출력, 오류/종료 상태, 파일 책임, 재기동·대기·완료 의미를 본문에서 이해할 수 있어야 한다. 주요 필드·동작은 실제 함수/심볼로 연결한다. 개발 기록을 읽어야 명령을 쓸 수 있게 만들지 않는다. 권한 옵션이 OS 수준의 세션 폴더 격리라는 설명은 하지 않는다.

실행기 구현과 직접 관련된 보완·확인을 이 task에서 끝낸다. 프로토콜·공식 검사기·진행 중인 작업맥락 문서의 변경이 필요하면 이유와 최소 변경을 보고한다. 임시 인스턴스와 실행 근거는 자기 task 기록 또는 임시 디렉터리에 두고 제품 변경에 섞지 않는다.

가짜 세션은 정해진 산출을 쓰고 끝나는 작은 프로세스로 충분하다. 실제 검사기와 Git을 사용해 계획→연구→검토→계획→목표 검토→완료까지 한 번 이어지는지 확인한다. 남는 불확실성에 맞춰 실패가 다음 계획으로 전달됨, STOP, 사용자 입력으로 외부 입력 대기 해제, 합성 한도 신호로 파견 대기를 확인한다. 긴 시간 기다리는 시험 대신 짧은 시각/간격을 사용한다. 단일 실행기·재기동 후 죽은 세션의 잔여 산출 처리·완료 후 기존 세션 반영은 코드로 충분하면 정적으로 판단하고 실행이 필요한 부분만 작은 확인을 한다. 독립 기동은 호출 프로세스 종료 뒤 자식이 기록을 남기는 최소 확인으로 충분하다. 실제 CLI 모델 호출과 실제 계정 한도 유도는 이 task의 검증에 필요하지 않다.
