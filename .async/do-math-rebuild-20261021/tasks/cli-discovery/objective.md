# 두 CLI의 실행기 연결을 위한 사실 확인

## 목표와 읽을 자료

후속 실행기 작성자가 Windows에서 Codex와 Claude의 새 세션을 기동하고 공급자 사용 한도에 따라 파견을 멈출 수 있도록, 설치된 CLI의 실제 인터페이스를 조사한다. 산출 프로토콜과 독립적인 외부 도구 사실 조사이며 제품 변경은 없다.

`inputs/context.md`, `inputs/plan.md`, `inputs/seams.md`, `task.json`을 먼저 읽는다. 추가 요구 원문은 `C:/math/.async/do-math-rebuild-20261021/user-messages.md`다. 도구 위치는 context 7절을 출발점으로 실제 존재와 help를 확인한다. 이전 do-math 구현이나 Git 이력은 참고하지 않는다. 다른 task의 미수용 결과를 전제로 삼지 않는다.

## 필요한 조사

- Codex와 Claude 각각의 비대화 실행 명령, 프롬프트 전달 방식, 작업 디렉터리, 모델·추론 노력 지정, 권한·승인 설정을 확인한다. 이전 대화를 이어받지 않는 새 세션이어야 하며, 세션 쓰기 범위는 자기 폴더라는 지시와 모순되지 않아야 한다. 실행기가 사용할 만한 실제 argv와 입력 예를 남긴다.
- 끝난 프로세스의 출력에서 공급자 사용 한도 신호와 해제 시각을 어떻게 찾을지 확인한다. 설치 CLI의 help·공개된 로컬 구현 또는 공식 자료의 실제 문면과 필드를 근거로 남긴다. 신호의 출처, 관찰한 사실, 구현을 위해 제안하는 해석, 확인하지 못한 점을 구분한다. 실제 한도를 소진하려고 호출하지 않는다. 사용 가능한 근거가 없으면 추정 신호를 확인된 사실로 쓰지 않는다.
- 한도 신호 이외의 CLI 출력은 결과 프로토콜이 아니다. 전체 출력에 엄격한 JSON 구조를 요구하지 않고 해당 신호만 읽는 최소 방식을 제안한다. 해제 시각이 없을 때는 설정된 간격으로 기다린다는 요구를 적용한다. 모델 이름에서 공급자를 정하는 간단한 방법은 제안할 수 있으나 제품 계약으로 확정하지 않는다.
- Windows에서 CLI 프로세스의 종료 판정과 로그 파일 수집, 호출 대화와 수명이 분리되는 실행기 기동에 영향을 주는 확인된 제약이 있으면 함께 적는다. 감시 서비스나 자동 재기동 장치를 설계하는 작업은 아니다.

먼저 로컬 help와 설치 파일 등으로 충분한 사실을 얻는다. 실행 여부가 불명확해 작은 실제 호출이 꼭 필요하면 최소한으로 하며 비용을 유발하는 반복 호출은 하지 않는다. 웹 자료가 필요하면 공식 자료를 사용하고 정확한 출처와 확인 날짜를 남긴다. 인증 토큰·쿠키·비밀 설정은 보고서나 로그에 복사하지 않는다.
