# 산출 계약과 공식 검사기

## 이 작업이 만드는 결과

빈 `.claude/skills/do-math/`에 새 do-math의 인스턴스·산출 계약과 공식 검사기를 만든다. 다음 실행기 작성자와 계획·연구·검토 문서 작성자가 이 결과만 읽고 같은 의미의 입력과 산출을 만들 수 있어야 한다. 사용자의 목적은 사람이 대화에 붙어 있지 않아도 연구가 이어지고, 독립 검토를 거친 수학 해설과 축적 지식으로 목표를 달성하는 것이다. 이 task는 그 전달에 필요한 최소 형식을 마련한다.

시작할 때 `inputs/context.md`, `inputs/plan.md`, `inputs/seams.md`, `task.json`을 읽는다. 추가 원자료는 `C:/math/.async/do-math-rebuild-20261021/user-messages.md`다. 공용 context의 확정 요구와 이 원문의 사용자 발언을 구분해 읽는다. 기존 do-math나 Git 이력에서 설계를 가져오지 않는다.

## 구현할 범위

1. 연구 인스턴스의 폴더 구조와 파일 책임을 정한다. 목표·조건, 설정, 축적 지식, 세션별 폴더, 실행기 상태, 정지 표시와 사용자 입력의 위치가 설명돼야 한다. 설정은 동시 상한, 범주별 모델·노력, CLI·Lean 경로, 한도 대기 간격을 표현할 수 있어야 한다. 실행기 내부 상태의 세부 구현은 후속 실행기 task가 정할 수 있도록 필요한 경계만 설명한다.
2. 계획·연구·검토의 산출을 정한다. 계획은 연구 과제, 추가 검토, 목표 검토, 외부 입력 대기와 판단 이유를 표현한다. 계획이 게시한 연구·검토에는 선택적인 모델·노력 지정과 이유를 표현한다. 연구는 사람이 읽는 해설, 실제 확인 범위, 실패한 접근, 남은 질문, 사용한 지식 참조를 표현하며, Lean을 쓴 결과에는 원문과 `lean --version` 문자열을 남긴다. 검토는 대상 산출 안의 결과별 판단·근거 또는 인스턴스 전체의 목표 달성 판정·근거를 표현한다. Lean의 수용, 해설과 Lean의 일치, 목표 달성은 서로 다른 판단으로 전달돼야 한다.
3. 축적 지식의 참조와 새 기록이 기존 기록을 대신하는 방식을 정한다. 기존 파일을 덮어쓰지 않고 연구와 검토를 연결하며, 독자가 현재 내용과 그 근거를 찾을 수 있어야 한다. 검토 전 결과는 작성자의 주장이고 상충하는 검토가 붙은 결과는 인정된 것으로 쓰지 않는다는 의미를 설명한다. 같은 기록을 대신할 과제 둘을 피하는 일은 계획의 책임이다.
4. 세션 폴더 하나를 입력으로 받는 공식 검사 스크립트를 구현한다. 세션과 실행기가 같은 명령·검사를 사용한다. 통과/실패 종료 상태와 고칠 위치·이유를 제공한다. 스크립트의 경로, 인자, 출력 의미, 사용 가능한 Python 함수가 있다면 그 입력·반환·오류 의미를 제품 문서에 명시한다. 검사에 필요한 인스턴스·지식 위치를 세션 입력에서 어떻게 찾는지도 계약의 일부다.
5. 제품 폴더에 프로토콜 문서를 둔다. 코드의 실제 파일·심볼, 세 범주의 작은 유효 산출 예시, 세션 폴더에서 새 지식 기록으로 복사할 대상과 참조의 해석을 설명한다. 실행기 작성자는 이 문서로 세션 입력을 만들고 산출을 반영할 수 있어야 한다. 예시는 전달 이해를 위한 최소 크기로 둔다.

공식 검사의 범위는 구조와 참조 실재뿐이다. Lean 컴파일, 수학적 정확성, 목표 충족, 계획의 연구 가치, 기존 기록의 현재성은 세션의 판단이다. 일반적인 전달 형식에 필요하지 않은 승인 필드나 봉인·해시 대조·환경 고정·실행 감시를 추가하지 않는다. 검토자는 축적 지식을 읽으며 작성자 세션의 중간 파일과 로그를 받지 않으므로, 공개 산출이 작성자 작업 폴더에 의존하지 않도록 참조 의미를 정한다.

## 수정 권한과 후속 경계

제품 수정은 자기 workspace의 `.claude/skills/do-math/` 안에서만 한다. 파일 배치는 위 기능에 맞게 정할 수 있다. 실행기·CLI 어댑터·SKILL.md·범주별 작업맥락 본문은 후속 task의 범위다. 이번에는 그들이 소비할 계약과 검사기, 필요한 작은 검증만 완성한다. 공용 context·plan·seams와 queue는 수정하지 않는다. 이 task와 병렬인 `cli-discovery`의 결과에 의존하지 않는다.
