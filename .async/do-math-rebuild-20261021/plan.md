# do-math 재구축: 계획

이 문서는 새 do-math를 완성하기까지 남은 결과물과 그 사이의 선행 관계를 정리한다. 무엇을 왜 만드는지는 `context.md`에, 구성 요소 사이의 인터페이스는 `seams.md`에 있다. 결과물을 어떤 task로 나누고 묶을지는 manager가 정한다. 아래 순서는 결과물 사이의 실제 의존에서 나온 것이다.

## 현재 상태

개발을 막 시작했다. `.claude/skills/do-math/`는 비어 있고, 구현된 것은 없다. `seams.md`의 인터페이스도 아직 의미만 정해져 있고 구체적인 형식은 정해지지 않았다.

## 남은 결과물

### 1. 산출 프로토콜과 공식 검사 스크립트

다른 결과물이 모두 이 계약 위에 서므로 가장 먼저 만든다. 정할 것은 다섯 가지다.

- 연구 인스턴스 폴더의 구조
- 축적 지식의 저장 구조, 그리고 기존 기록을 대신하는 새 기록이 있을 때 무엇을 현재 내용으로 읽는지의 규칙(`context.md` 3절)
- 계획·연구·검토 범주마다 세션이 낼 산출의 분류 형식
- 계획이 과제·검토 요청·목표 검토 요청·외부 입력 대기를 게시하는 형식
- 그 형식들의 준수를 확인하는 공식 검사 스크립트

검사 스크립트의 범위는 `context.md` 3절이 정한 대로 구조와 참조 실재다. 세션과 실행기가 같은 스크립트를 같은 방식으로 실행할 수 있어야 한다. 이 결과물이 수용되면 manager는 정해진 형식을 `seams.md`에 기록한다.

### 2. 실행기

1번에 의존한다. 이 결과물이 갖춰야 할 기능은 다음과 같다.
- `context.md` 4절의 정해진 흐름을 따른다.
- `context.md` 4절의 불변식 열 가지를 지킨다.
- Codex CLI와 Claude CLI로 세션을 띄운다.
- 끝난 세션의 공급자 한도 신호를 감지하면 새 세션을 띄우지 않고 기다린다. CLI가 해제 시각을 알려 주면 그 시각까지, 알려 주지 않으면 설정한 간격만큼 기다린 뒤 흐름을 재개한다(`context.md` 4절). 각 CLI의 한도 신호는 실제 CLI의 문서, 출력, 동작에서 확인해 정한다.
- 대화와 수명이 분리된 독립 프로세스로 기동된다. Windows에서 쓸 기동 방법을 포함한다.
- 사용자의 정지 표시와 입력을 받는다.

### 3. 작업맥락 문서와 SKILL.md

1번에 의존한다. 2번과 병렬로 만들 수 있다. 다만 `SKILL.md`에 들어갈 명령 안내는 2번이 정한 명령 체계를 따르므로, 그 부분은 2번이 수용된 뒤에 맞춘다.

- **공통요소 문서**: do-math의 목적과 판단 원리, 산출 프로토콜, 공식 검사 스크립트 사용법. 모든 세션이 받는다.
- **작업공통요소 문서 셋**: 계획, 연구, 검토 범주마다 하나씩이다. 각 범주의 세션이 무엇을 판단하고, 축적 지식을 어떻게 읽고, 무엇을 어떤 형식으로 내는지 설명한다. 계획 문서에는 같은 기존 기록을 대신하는 과제 둘을 동시에 배정하지 않는다는 지시가 들어간다(`context.md` 3절).
- **SKILL.md**: 사용자 대화가 이 스킬을 부를 때 읽는 진입 문서다. 담을 내용은 다음과 같다.
  - 새 연구의 시작: 목표 받기, 인스턴스 폴더 만들기, 실행기의 독립 기동과 확인
  - 진행 상황 조회
  - 정지 표시를 놓고 거두는 방법
  - 입력 넣기와, 외부 입력 대기를 풀 때 사용자가 할 일
  - 끝나지 않고 멈춰 버린 세션 하나의 프로세스를 끝내는 방법(정지 표시와는 별개)
  - 실행기를 다시 띄우는 방법

이 문서들은 세션이 판단하고 행동하는 데 쓰는 글이다. 이 개발의 대화를 모르는 세션이 그 문서와 자기 작업특정요소(`context.md` 4절, 그 세션 하나에만 해당하는 지시나 대상)만으로 작성자가 뜻한 대로 읽을 수 있게 쓴다.

### 4. 가짜 세션 흐름 시험

2번과 3번에 의존한다. 실제 모델 대신, 정해진 산출을 내고 끝나는 가짜 세션으로 실행기를 돌린다. 확인할 것은 다음과 같다.
- 시작부터 완료까지 흐름이 이어진다. 계획에서 연구, 검토, 다시 계획으로 가고, 목표 검토를 거쳐 완료된다.
- 세션 실패가 다음 계획에 넘어간다.
- 정지 표시가 새 세션을 막는다.
- 사용자 입력이 외부 입력 대기를 푼다.
- 공급자 한도 신호가 파견을 멈춘다.

시험은 각 성질을 확인하는 가장 작은 형태로 둔다.

### 5. 실제 세션 완주

4번에 의존한다. 실제 Codex 세션과 Claude 세션이 함께 참여하는 연구 인스턴스를 하나 만들고, 사람의 개입 없이 처음부터 완료까지 돌린다. 범주별 기본 모델의 일부를 Codex로, 일부를 Claude로 두면 둘이 함께 참여한다. 목표는 `context.md` 6절의 작은 목표다. 증거는 그 인스턴스의 축적 지식(결과, 검토, 목표 검토 판정)과 실행 기록이다. 보고에는 인스턴스 폴더의 위치, 참여한 세션과 각 세션의 CLI·모델을 적는다.

### 6. 최종 review

1~5번이 수용된 뒤 연다. `context.md`의 확정 결정과 6절 완료 기준을, 수용된 실제 결과와 대조한다.
