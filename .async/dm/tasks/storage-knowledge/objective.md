## 유한 모집단과 종료 질문

families.json의 root/family 키를 유지한다.

- trust 4: research.active_trust_environment, research.trust_environments, runtime.trust_bindings, runtime.trust_transitions.
- knowledge 5: research.assessment_uses, research.expositions, research.formal_results, research.identity_assessments, research.knowledge.

1. 각 가족의 현재 shape·정본 checker·실제 producer와 저장 caller를 기존 표에서 확인한다. 스칼라/metadata/map/list를 record와 혼동하거나 최상위 fields가 빈 가족을 무의미한 빈 pair로 통과시키지 않는다. 오래된 표의 AST 불일치는 결함 수가 아니며 현재 정의로 판정한다.
2. 현재 필수/선택 필드마다 실제 producer의 쓰기와 해당 검증 receiver를 통과하는 기존 시험/정확 단언을 연결한다. 기존 직접 시험과 수용된 실행 근거로 충분한 항목은 재실행 없이 유지한다. 이름 사용/reader의 문자열·schema fixture·시험에서 사후 보충한 값만으로 실제 생산을 증명하지 않는다. 원래 유한 입력축(해당 선택지·관계 0/1/여럿·선택 필드 있음/없음)을 필요한 실제 분기와 연결한다.
3. 실제 빠진 표본/단언이 있으면 기존 direct producer와 Repository/StateContract 시험에 최소 보완한다. 일반 Pair/assert_pair 또는 기존 저장 helper를 재사용할 수 있고 표본 전건을 새 registry로 옮길 의무는 없다. 적용 가능한 경우 정본에 미생산 optional 필드를 추가한 음성 입력이 같은 역방향 검사에서 드러나도록 한다. runtime의 미생산/잘못된 값·불필요한 schema 필드를 실제로 발견하면 배정된 provider/schema와 해당 consumer를 함께 고친다. 단언을 통과시키려고 fixture에 필드를 사후 주입하거나 검증을 끄지 않는다.
4. actual 저장·reload/read_record/read와 관계·봉인·원 bytes/독립 기대값을 유지한다. 순수 review fixture와 Sim의 입장/수송을 구별한다. state/10의 구조 공유와 공개 위임·승인·현재성/정산을 되돌리지 않는다. keep-storage의 SOURCE/restart·review decision·게시 후 stop 보완은 보존한다.
5. 계약 대응의 현행 충족/수리와 쓰기 지점의 최종 분기 도달을 분리해 남긴다. 모든 쓰기 분기 미도달0은 G5 fresh T3에서 실제 source 위치/분기 자료와 대조해야 한다. 이번에는 그 대조에 필요한 해당 13가족의 정확 producer/쓰기 지점과 이미 있는 증거만 남기고 전체 T3를 실행하지 않는다. 나머지 71가족과 관찰4가족을 새로 종결하지 않는다.
