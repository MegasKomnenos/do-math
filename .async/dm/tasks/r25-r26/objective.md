## 끝낼 유한 질문

1. 초기화의 init→status/query/read→operator configure→user governance/grants→probe/adopt/select-profile→공개 setup/trust→run --until-active를 실제 정의/시험에서 대응한다. 원문 코드포인트·UTF-8 길이/SHA, 실제 주체와 승인 원문, 응답에서 받은 snapshot/ID/config hash의 다음 명령 전달, 활성화 직후 연구 실행0을 확인한다. JOURNEY_STEPS의 문자열이나 implemented 표시만으로 통과를 세지 않는다. CLI에 주는 사용자 요청 문서와 내부 저장 JSON·승인 해시를 수작업으로 조립해 우회하는 행위를 구별한다. 새 범용 문서 단계 registry는 만들지 않는다.
2. 조건부 질문답변·검사된 import 승인초안→정확 승인·HOLD/해제·pause/resume/close·부족/만료/회수 권한의 현재 절차를 실제 공개 명령과 연결한다. 초기 상태 fixture가 도메인 생산자인 사실과 그 조건을 만드는 CLI 절차 인증은 구별한다. 문서의 한 단계가 여러 공개 명령이면 각 명령의 역할과 반환을 그대로 설명하며, 무관한 모든 여정을 매번 init부터 재실행하지 않는다. 이미 충분한 관련 단언은 유지한다.
3. 명시된 남은 초기화 실패 절차를 같은 여정에 묶는다. 기술 실패 뒤 request --retry-action, 정상 종료 native 최종 응답의 새 모델 없는 재수신, 형식 실패의 제한 수리→maintenance retry/wait, 지문 불일치·재기록의 공개 도구/신뢰 입력을 현행 caller와 직접 시험에 대응한다. 원실행/원결과/종료/예약·권한·활동 계보, 실제 새 모델 수, 정확 후속1회/대기 이유·소유자·재시작 보존 중 부족한 성질만 작은 공개 입력으로 보완한다. 역사 KD-0804 실패를 성공한 재시도로 세지 않고 현재 구현에서 처분한다. 실설치 변경 없이 자기 임시 설치와 기존 외부 대역을 사용한다.
4. 예약 handoff의 인프로세스 공개 CLI 연쇄와 OS 실제 발화를 구별한다. 이미 확인한 실제 연구 CLI/worker 경로를 LeanDouble의 임의 성공으로 대체하지 않는다. 과거013의 held OS 발화는 연구 모델 운전 성공이 아니다. 새 실예약/실모델/Lean 설치는 이 배정이 아니다. 단순히 partial 표기를 없애려고 경계를 합치지 않는다.
5. PR16 B60과 PR24 B64 중 이 CLI 절차에 직접 해당하는 실제 hunk→현재 소비자→정확 단언/원보고의 처분만 함께 남긴다. 다른 cross slice는 r12-r13의 판정을 재사용한다. 원Temp 보고가 없으면 counts를 성공으로 합산하지 않는다. 수정하는 가까운 unpinned_rejection은 함께 고치되 구조44건 전체나 모든 PR/G의 감사를 추가하지 않는다.
