# 제출의 현재성과 실제 적용 계약

manager0084는 g5-core-tail의 명시적/native 캡처 재조회 실패 수리를 통합·부분 수용했다. 남은 원56arc/60행을 같은 core 파일의 세 유한 묶음으로 나눴다. 이 작업은 7함수의 원24arc/24행에 해당하는 아래 계약 판단을 맡는다. 좌표는 이전 전체T3에서 나온 질문의 범위이며 시험quota가 아니다. 수리와 필요한 확인을 함께 끝낼 크기로 줄인 배정이다.

실제 선행은 g5-core-edge 하나다. 같은 core_engine.py·직접 helper·설명/미러의 통합판을 소비하기 위한 순서이며 다른 독립 작업의 완료를 기다리는 장벽이 아니다. 앞 결과가 partial이면 그 보고의 남김을 완료로 간주하지 않는다.

## 이번에 해결할 결과

1. _validate_bundle_current의 source_basis·academic hash·추가 authority/decision은 앞 guard의 책임과 실제 생산 집합을 먼저 연결한다. decision_basis와 source_basis가 같다고 가정하지 않는다. currentness 거절은 원 요청/출력 보존과 정확 owner에 연결한다.
2. mixed impact 결과의 held bundle만 요청으로 만드는 필터, 손상된 원생산자의 대기 처리에서 관계없는 pending action 보존, 무영향 mutation의 실제 적용을 같은 integration/helper 소비 경계에서 묶는다. 수용된 assignment 계산 회귀를 다시 돌리거나 공개 owner 전체 증거로 부풀리지 않는다.
3. _apply_extensions의 private insight는 원 source_execution/input_snapshot·basis/source와 실제 suspension/재거절을 판단한다. 구조 schema·공통 codec 보장은 재사용하고 출처의 업무 의미만 남긴다.
4. _apply의 preparation/revision/formal environment/condition 이름·평가·순환·후속 kind와 닫힌 role dispatch, _apply_plan의 fixed planning population을 실제 producer→currentness→적용 순서에서 판단한다. 이미 수리한 nested condition 이름 결박은 반복하지 않는다. 지원되지 않는 role이나 불가능한 내부 누락을 시험에 주입하지 않는다. 외부 artifact 오류와 내부 불변식을 구분한다.

## 실제 범위와 판단 방식

SESSION_JSON, task.json, inputs/context.md·plan.md·seams.md, 자기 workspace의 do-math AGENTS.md와 시험-지침.md를 읽는다. 절대경로 원자료는 읽기 전용이다. 자기 gap-scope.json은 manager0084 수용판의 좌표/심볼과 원 g5-full 좌표를 함께 보존한다. 앞 task 통합으로 줄번호가 바뀌면 자기 base의 실제 함수로 다시 연결한다. 앞 작업의 완료되지 않은 범위까지 자동으로 인수하지 않는다. 이전 worker의 제안 시나리오는 확정 요구가 아니다.

이 묶음의 현재 계약 판단·필요 구현·최소 확인·설명/미러를 한 task에서 마친다. 공통 입력/저장 검증과 실제 생산/호출 불변식부터 읽고, 충분하면 정적 근거로 종료한다. 행마다 새 시험을 만들지 않는다. 불필요한 방어는 실제 전제에 따라 줄일 수 있다. 현재 구조·권한·참조·증거·현재성 검사는 유지하고, 외부 오류를 불가능한 내부 상태로 바꾸지 않는다. 제외가 필요하면 원설계5.5의 같은 행 사유와 실제 caller/불변식으로 판단한다. 자동제외·blanket no-cover·새 skip·층/분모/임계값 완화는 하지 않는다. 수치 감소 자체가 완료가 아니다.

제품 쓰기는 task.json의 경로에 한정한다. 목록은 수정·시험 의무가 아니다. core와 해당 직접 소비 시험/helper·설명을 같은 소유자가 맡는다. integration/submission은 허용된 경우에도 맡은 core 계약의 직접 결함 수리에만 수정한다. 다른 제공자 수리가 필요하면 원인/영향/최소 범위를 보고한다. 실행 중 g23-handoff의 고정 배정이나 기록을 바꾸지 않는다. g23 인계·전체 관문을 이 작업의 선행으로 삼지 않는다.

## 최소 확인과 제출
