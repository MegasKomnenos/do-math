# 권한·위임·개정과 계획 발동의 역사 변경을 실제 변경과 현행 소비로 판정한다

g23-handoff는 K61/P2 12와 PR25의 연결을 마쳤지만 이 배정의 역사 hunk 검토는 소비한 수용 근거에서 확인하지 못했다. 이번 결과는 또 다른 매핑이 아니라 **지정 변경의 유지·교정·제거 또는 정확한 자료 부재 판정**이다. 기존 의미 검토는 재사용하고 실제로 남은 질문을 끝낸다. 제품 수정 없는 유한 review이며 최종 G8 review는 아니다.

## 입력과 범위

SESSION_JSON, task.json, 고정 inputs/context.md·plan.md·seams.md, objective.md와 scope.json을 읽는다. 실제 선행은 g23-handoff 하나다. 현재 수용판은 manager0085이고 이전 인계의 고정판은 manager0082다. managers/0085/handoff-delta.json을 함께 읽어 0083 예약과 0084 capture 수용을 보충한다. 진행 중 g5-core-edge와 준비된 apply/recover의 workspace·미완성 보고를 읽거나 기다리지 않는다. 자신이 시작할 때의 base를 검토판으로 쓴다.

원 B ID는 B24, B25, B45, B26, B41, B43 (6개)다. scope.json.rows는 원 PR slice를 그대로 옮긴 읽기 입력이며 question·board_selector·commit·원보고 locator·현재 정의를 제공한다. 같은 이름의 P2 ID와 혼동하지 않는다. 해당 unit_context의 전체 foundation/migration 목록은 길찾기 자료이고 이번 검토 할당량이 아니다.

등록/철회·위임의 실제 소유자, 개정 보류, 자기점검 계수/준비·계획 발동의 hunk를 현재 생산자·직접 소비·정확 단언에 연결한다. r12-r13-fix/r39-r42/r41과 이미 수용한 발동 의미를 재사용한다. A-31의 자동 판단대상 생산과 정확 지급 action 재접수를 구분하고 target=None 전면 거부를 새 요구로 삼지 않는다. A-42는 현행 동시성/독립 운영배정 성질로 판단하며 폐기된 누적 work_calls를 복원하지 않는다. 진행 중 core의 위임/정산/처분은 실제 수용 뒤 필요한 diff만 남긴다.

원자료 root는 C:/math/docs/do-math/continuous-development-2026-10-13, 원 board/설계는 C:/math/docs/do-math/시험-재편-2026-09-29다. run:은 전자, repo:는 검토판 workspace의 상대경로다. 과거 Git 조회만 git -C C:/math로 읽기 전용 수행한다. commit이 주어지면 그 hunk부터, 없으면 board의 해당 key를 도입한 git log -S/관련 경로의 유한 이력으로 찾는다. 원보고 Temp 경로가 없으면 같은 수용 task/manager의 보존 근거만 사용하고 원자료 부재를 숨기지 않는다. 무관한 전체 Git 이력·보고·SHA 재수집은 하지 않는다.

## 수행과 완료 판단

1. 각 지정 ID에서 실제 제품/시험/설명 hunk의 변경 심볼과 보호하려던 성질을 확인한다. 변경이 없는 실행/보고 기록이면 그 사실을 구분하고 실제 선택·종료·판본·실패 분류의 원근거를 확인한다. commit이 존재하거나 시험이 통과했다는 사실만으로 유지 판정하지 않는다.
2. 현재 직접 caller/생산·수신 경계와 관련 정확 단언을 읽어 현재 계약에서 유지·이미 교정·정당하게 제거·추가 수리 필요를 결정한다. 기존 수용 결과가 같은 질문을 실제로 해소했으면 그 정확 근거를 연결해 마친다. 최신 계약이 폐기한 timeout/옛 예산·호환 경로·결함 기대를 복원하지 않는다.
3. evidence/judgment.md와 evidence/history-decisions.json에 ID별 실제 commit/path/symbol·검토한 hunk, 근거/판본, 현재 처분과 이유, 새 구체 결함 또는 정확 미확인만 기록한다. 기존 의미 판단 충분/최종판 실행 대기와 실제 미검토를 구분한다. 원자료가 없더라도 현재 코드로 판단 가능한 범위는 판정하고, 나머지는 필요한 자료·영향을 특정한다. '다음 검토자가 다시 조사'라는 일반 인계만 반복하지 않는다.
4. 새 제품 결함이 확인되면 정확 원인·현재 사용자 영향·최소 수정 파일/심볼·필요한 확인을 findings에 묶어 manager에게 반환한다. 진행 중 core와 겹치면 해당 수용 diff에서 다시 볼 성질만 지정한다. 쓰기범위가 없는 review이므로 제품을 고치지 않는다. manager가 실제 결함의 수정·관련 최소 확인을 한 work에 함께 배정한다.
5. 원설계3.3/A20/A22와 사용자 storage-scope-direction을 적용한다. 공통codec·검증게시·이미 수용한 업무 보장을 재사용하고 전가족/전필드/새reader/옛head 재입증이나 장기감사를 만들지 않는다. 기존 72개의 한정 역사검토·P01~P11·K61/P2 의미 판단은 새 반례 없이 재개방하지 않는다. 전체 migration 단언강도·비B 기반의 다른 미결과 최종 관문은 이번 지정 ID의 판정으로 자동 해소되지 않는다.
