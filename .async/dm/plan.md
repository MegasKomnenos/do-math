# 현재 계획: 이관 검수에서 실제 잔여 해결로

0001은 029의 지정 문서/검사 수리를 현재 소스와 원자료에 대조해 이관 성과로 수용했다. 여덟028 finding과029 F1은 종결했다. 판본 한계인 F2와 G4~G8, L01, symlink 미검사는 유지한다. 이관 성과는 새 queue의 accepted task가 아니다. 근거는 managers/0001/inheritance-review.json·review.md이며 새 제품 시험은0이다.

모델은 세 task 모두 gpt-6.1-sol/high이며 실행기 max_workers=3이다. 시작 inputs/base/workspace가 각자 고정되므로 다른 task 결과를 기다리거나 중간 변경을 소비하지 않는다. 순수 정적 파싱·해시·기존 원자료 대조로 종료 질문에 답한다. 새 공식 검사·실호출·공유 캐시 변경은 이번 배정에 필요하지 않다. 자료와 결론은 자기 task/evidence와 async report.json에 남긴다.

한 결과가 도착하면 manager가 실제 파일/단언/원보고를 검수하고 무변경 조사도 integrate한 뒤 accepted에 넣는다. 충분한 기존 증거, 최종 실행 대기, 확인된 수리, 정확 미결을 구별한다. 구현이 필요하면 정확 반례·파일·검증을 한 task에 묶고, 공유 helper 수정은 한 담당자로 모은다. 독립 후속은 다른 조사 종료를 기다리지 않고 준비하며 실행 중 배정은 바꾸지 않는다.

## 이후의 진행 방식

결과가 하나라도 끝나면 manager가 검수·통합·수용하고 그 결과가 필요한 후속 수리를 준비한다. 다른 독립 worker가 남아 있어도 기다리지 않는다. 명확한 구현 공백과 그 관련 과거 변경 검토를 같은 한정된 task에서 처리한다. 공유 helper를 다루는 수리는 묶고 독립 파일·질문은 병렬화한다. 작업을 한 문맥에서 원문 확인부터 필요한 검사·보고까지 끝낼 수 있는 크기로 유지한다.

원래 요구30·보존61·P2 12와 기존 재검토25영역의 미결 질문은 legacy requirement-state/prior-review-state와 현재 판단을 연결한다. phase 수나 AST 제거 수를 전체 완료율로 보고하지 않는다. 수용 결과마다 관련 요구 ID의 증거·해결·남김을 현재 plan에 갱신해 반복 배정을 막는다. 전체103항목에 대해 미해결과 최종 증거 대기를 구분하는 집계가 필요하며, 새 대형 계획 프레임워크를 만들지 않고 기존 ID를 쓴다.

현재 문서 P01~P11, 정책·이름 작업의 지정 성과는 legacy 원report/manager의 범위대로 유지한다. 029의 지정 여덟 발견은0001에서 이관 검수를 마쳤다. L01의 실제 운전 프로필·출력 단위 결정, Windows1314 symlink 실제 반려 미검사, 원래 남은 의미 질문은 열린 상태다. 독립 작업을 진행할 수 있는 동안 전체를 blocked로 만들지 않는다. 외부 결정 없이는 더 진행할 수 없을 때만 정확한 질문과 이유를 남기고 queue를 blocked로 게시한다.

## 최종 판본과 종료

필요한 수리 뒤 제품을 고정해 G4 전체 일반, G5 fresh T3, G6 현재 함수 모집단 전체 극단 변이와 정상 기준, G7 실제 경계의 최종 판본 연결을 확보한다. 과거 T4 각295passed·실호출 성과는 판본/성질이 유효한 범위만 재사용한다. 작은 부분 검사의 합으로 전체 성공을 만들지 않는다. 최소 검증 원칙은 불필요한 반복을 없애는 원칙이며 사용자가 명시한 최종 관문을 생략하는 근거가 아니다.

마지막에는 수용된 모든 새 work를 선행으로 포함하는 제품 수정 없는 review task를 배정한다. 상속된 기존 작업과 원래 G1~G8도 함께 검토한다. 새 queue의 work만 완료됐다는 이유로 원래 목표를 축소하지 않는다. 실제 충족 증거와 모든 잔여 처분이 있어야 queue complete를 게시한다. 최종 검증 중 공유 소스를 바꾸지 않도록 구현 배정을 비우고 최종 integration 판본에 증거를 결속한다.
