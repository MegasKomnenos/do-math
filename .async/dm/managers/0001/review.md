# 0001 이관 판정과 첫 배정

029/doc-names A1~A5와 F1의 지정 여덟 발견을 이관된 시작판의 완료 성과로 수용한다. 이 task는 새 async 실행에서 수행되지 않았으므로 integrate/accepted 기록을 만들지 않는다. inbox completed/running과 state.tasks는 비어 있었다.

현재 변경 파일을 읽었다. setup_lean/probe_cli의 build_parser와 parse_arguments를 main과 문서 helper가 함께 소비하며, 입력 반려가 host 접근보다 먼저 수행된다. helper는 지정 문서 좌표에서 실제 config/control/candidate/stage/checkpoint 검사와 adapter 속성을 사용한다. 기존 시험에 추가된 정상/오류/부재 단언과 문구 변경을 원보고·legacy manager 검수에 대조했다. 문구 검사가 모델의 독해·권한 승인·실제 외부 효과를 보증하지 않는 한계도 유지한다.

새 검산은 제품 시험 재실행이 아니라 현재 파일과 원결과의 결속 확인이다. reconcile.py는2675 스킬 소스와029 종료/manager 판본, 이관 snapshot2681파일, 원task129파일의 SHA 일치를 확인했다. 보고된22변경은 writes 안의 정본10·미러10·비용캐시2이며, 최종 c2/m2 각각183선택·고유row·passed·exit0와875Python SHA를 원JSON에서 확인했다. 기존38문서ID 및 여덟 finding의 연결ID도 최종 결과에 포함된다. 같은 바이트의 기존 공식 미러 생성·--check와 양쪽 skill-only exit0를 재사용한다. 새 제품 시험/외부 호출은0이다.

중단된 manager의 verification/review는 유효한 검수 자료였지만 manager.json 게시·archive·commit은 완료되지 않았다. 기존 draft와 공용문서 및 M-0579의 예정 표현을 사실로 승격하지 않았다. 원task129파일,20제품 원바이트, 중단 manager 자료·로그·030 후보·M-0579를 legacy-029-raw.zip에 보존하고 내용별 SHA를 다시 확인했다. 원경로는 수정하지 않았다. 과거 비용캐시와 기존 dirty/untracked 제품·운영자 변경은 커밋 범위에서 제외한다. 이번 커밋의 진입점은 이 문서와 inheritance-review.json·preservation.json·공용 context/plan/seams다.

029 F1은 지정 범위 종결, F2는 carry다. 설치/prompt hash가 달라졌으므로 과거 전체 설치/실호출 판본이나 모델 독해를 재인증하지 않는다. L01 Q1/Q2와 UTF-8 byte 요구, Windows1314 symlink 실반려 미검사, 나머지 의미 질문과 G4~G8은 남는다. 전체 개발은 active다.

r02/r07/r18은 기존030의 서로 독립적인 종료 질문을 그대로 이어 받는다. ModelRunner 요청의 필수+선택 역방향, 반환 소유권의 남은 모집단, 현재 외부 경계 호출과 등록 대응만 조사한다. 원문·관련 PR slice·직접 K/P2 연결, 표와 구체적 후속 입력/기대/파일 요구를 유지하면서 새 workspace 경로와 async report/check 명령으로 바꿨다. 모두 work, writes=[], depends_on=[], gpt-6.1-sol/high이며 max_workers=3이다. 제품 변경이 없으므로 서로 기다릴 이유가 없고 다음 결과가 도착하면 해당 결과부터 통합·수용한다.

공용 문서와 objective를 먼저 준비한 뒤 별도 queue.pending.json을 check.py queue로 검사한다. 검사한 바이트를 queue.json으로 마지막에 원자 교체한다. 진행 중 배정 변경은 없고 새 task 성과를 선행 수용으로 꾸미지 않는다. 관리 커밋 후 수신 파일 commit.json과 실행기 state/log는 로컬 운영 기록이며 이 문서의 검수 근거를 대체하지 않는다.
