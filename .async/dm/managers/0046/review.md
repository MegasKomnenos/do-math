keep-rejections는 F2의 required validator·루트 path·정확 누락필드, F3의 같은 outside/repository 입력을 보존한 relative_to 진단, F4의 같은 REF에 대한 fake/real 고유 사유를 결박했다. 실제 Git 쪽 작은 문자열 상수는 rev-parse --verify --quiet 실패와 broken-ref 경고이며 fake의 broken reference 진단과 구별한다. 양측 SHA1/SHA256 네 소비자, 두 malformed raw, absent ref/없는 object·정상 no-repository·정상 schema 대조가 유지된다. 기존 winerror/원값 보존 메서드는 변경하지 않았다.
