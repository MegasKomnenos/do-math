# 반환 소유권·native 경계 수리 수용과 독립 후속

r07-fix와 r18-fix를 수용한다. 두 보고의 실제 base/workspace 차이를 확인하고 workspaces.py integrate로 정본4·미러4의8파일을 충돌 없이 통합했다. 비용 캐시는 각각 자기 base로 복원돼 변경에 없고 기존 공용 캐시를 덮지 않았다. report 검사는 PASS이며 source-review.json과 각 integration.json이 경로·판본 근거다.

## 반환 소유권 수리

output_contract의 Claude 분기는 기존 values.json_copy를 사용하여 공유 leaf를 결과 안에서 분리한다. Codex 봉투와 원 schema description, 미지원 provider 반려는 유지됐다. _composition_calls가 두 공급자를 기존 반복 격리 검사에 연결하며 새 직접 단언은 값 보존과 한 필드 변경 뒤 형제·입력·다른 반환 불변을 확인한다. 기존 schema-name 탐색·다른 builder·transformer·borrowed lookup의 계약을 바꾸지 않았다. 현재 ModelRunner는 이 함수를 Codex에서만 호출하므로 Claude 실전송 실패 수리로 보고하지 않는다.

원 red 보고의1failed는 Claude index1의 repeat0/1에서 동일 가변 노드가 한 결과에 두 번 나타난다는 정확 반례다. parent exit는 task가 회수하지 못했으므로 미확인으로 보존한다. green은 선택12·고유 실제12passed, complete/successful=true, exit0이다. 하위 result row가 부모 보고와 같고 fixture 오류·실행 중 소스 변경이 없으며 Python875해시가 제출판과 전부 같다. 세 미러 쌍도 원바이트가 일치한다. R07 F1/F2는 해결됐고 R07/1-E는 최종 판본 증거 대기로 옮긴다.

## 파일 교체 검사 수리

_replacement_sites는 현재 SetFileInformationByHandle binding과 tuple 반환·unpack으로 연결된 실제 호출을 발견한다. _sites의 실제 제품/메모리 AST 입력을 공유하며 발견값은 경로·함수·종류·노드다. 기존 os.replace/shutil.move 검사도 유지한다. 실제 _windows_files의 binding과 _replace_once의 호출을 정확히 단언하고, 실제 native 함수 AST의 전체 이동·소비만 이동을 같은 소유 판정으로 반려한다. reader가 네 번째 값을 받기만 하는 경우나 관계없는 rename 이름을 호출로 세지 않는다.

탐색은 현재 직접 binding/tuple/absolute from-import 형태에 한정된다. 범용 별칭 분석이나 임의 동적 우회 완전성을 요구하지 않는다. 수리 전 공식1failed·exit1은 native 발견 목록이 비어서 발생했고 준비 오류가 아니다. green은 기존6+추가1의7선택·7고유 passed, complete/successful=true, exit0이다. 하위 row·Python875해시와 미러1쌍을 확인했고 fixture 오류·소스 변경은 없다. runtime은 불변이다. R18 F1은 해결돼 R18/9-A를 최종 판본 증거 대기로 옮기지만 이 AST 수리를 새 Windows 실교체 증거로 세지 않는다.

## 통합판과 근거의 범위

manager는 제품 시험을 새로 실행하지 않았다. 두 수정의 의미 있는 파일이 독립적이고 r07의 provider_final 변경은 r18의 프로세스/파일 교체 경계 모집단을 바꾸지 않는다. 단언과 원보고·제출판 대조로 수용 판단에 충분하다. 통합판 미러 --check는1336파일 드리프트0·exit0이다. 각 사본의 관련 통과를 통합판 전체 검사 성공으로 합산하지 않는다.

PR06 B22/K-51의 기존 지정 성질과 PR02 B13/B14/B62/B85 지정 slice만 유지한다. 전체 K/P2나 다른 의미 질문, 과거 Temp 원보고 부재, 029의 설치/prompt 판본 한계, G4~G8, L01 Q1/Q2·UTF-8 byte, Windows1314 symlink 실반려 미검사는 남긴다.

## 배정 판단

inbox의 진행 중 task는 r04다. 정의·입력·쓰기 범위를 변경하지 않는다. 완료된 두 자리는 원래 미결 R05의 외부 값 경계와 R11의 공개 run 조기 반환으로 잇는다. 이 작업들은 r04의 중간 결과나 두 수리의 출력에 실제 선행 관계가 없으므로 depends_on=[]이다. 현재 수용된 소스가 시작 사본에 포함되는 것은 별개다.

r05는 네 값 경계의 실수/큰 정수/bytes/문자열/null/빈 컨테이너 축과 실제 저장·해시·직렬화 의미를 다룬다. 같은 경계의 null 확인을 묶되 제품 전체 R06 모집단은 남긴다. r04의 pairs와 기존 결과8표본 단언을 다시 구현하지 않는다. r11은 현행 종료 위치표·세 직접 소비 시험을 묶고 until_active/live-future의 실제 도달 전제를 해결한다. 표 존재나 이미 active인 시험만으로 그 분기의 실행을 주장하지 않는다. 시작 전 무착수와 실행 후 종료 전제 뒤 추가 착수 없음을 구별한다.

두 새 task는 해당 시험과 좁은 helper·미러만 수정하며 runtime 결함은 정확 입력/위치/필요 쓰기를 보고한다. 현재 확인된 runtime 결함이 없어 광범위한 runtime 쓰기를 열지 않는다. 각 task는 충분한 정적 확인을 재사용하고 실제 보완에 필요한 공식 ID만 jobs1로 확인한다. 비용 캐시는 evidence 보존 뒤 자기 base로 복원한다. 이 분담은 r04와 쓰기 충돌 없이 최대3 worker가 진행하도록 한다.

context·plan·seams와 두 objective를 먼저 완성했다. 제출 후보는 queue.pending.json이며 기존7개 정의를 보존하고 accepted에 r07-fix/r18-fix, task에 r05/r11만 추가했다. check.py queue를 통과한 후보를 마지막으로 queue.json에 원자 교체한다. 상태는 active이며 이 inbox 이후 도착한 완료 사건은 다음 manager가 판단한다.
