## 변경과 계약 판단

정본6개 base→workspace diff는 reviewed.diff에 보존했다. formal._job_run의 한 줄 if/return을 두 행으로 나눈 것은 try/finally 실행과 측정 좌표를 맞춘 표기 변경이다. task의 독립 비교 원자료에서 반환값/두 stream/finally 1회는 같고, inline의 정적 missing exit와 split의 실제 arc를 구분했다. manager가 이 실험을 재실행하지는 않았다.

formal_engine._trust_control(register)는 register_request_errors, 실제 toolchain record/선택 baseline, environment_errors를 계속 검사한다. transition/check의 중복 lexical 검사를 제거해도 공개 등록과 저장 경계, 실제 check_environment의 신원/내용 검사가 남는다. 비활성 환경의 모든 의미를 저장 schema 하나가 보장한다고 확대하지 않는다. 공개 등록의 의미 검사와 후속 상태 전이가 근거다.

core_engine._register_execution의 None 경로, review_engine._admit_review_execution의 AI 전용 입장, execution_profiles.build_profiles의 세 machine 역할, SessionSlots의 빈 provider/model/host 예약을 대조했다. 새 활동/자기 continuation을 쓰는 formal/trust action에 review restoration 활동을 임의 결속한 내부 상태를 정상 입력으로 세지 않는다. 세 machine caller의 불가능한 None guard만 제거했고 공유 등록기/프로필은 바꾸지 않았다.

knowledge_io.import_candidate와 knowledge.replace_knowledge는 기존 KN을 덮는 공개 개정이 아니라 새 KN을 만들고 원문 변경에는 새 FR을 쓴다. 변하지 않은 사용 가능한 FR을 재사용하는 현행 경로도 유지된다. formal_engine.FormalEngineMixin._formal_steps의 stop은 원 decision basis/환경/권한을 검사한다. 같은 KN 원문 덮어쓰기 방어와 stop 뒤 중복 환경 비교를 줄이되 _require_action_clock 및 record_formal_result의 활성 환경·새 transition·정확 증거·기봉인 검사를 유지했다. stop과 정산/게시 사이에 control을 적용하는 yield가 없는 순서도 확인했다.

새 직접시험은 검사 전 공개 invalidate의 무기동/정확 실패/이전 권위 보존, compiler verified 반환 뒤 새 transition의 봉인 거절과 원결과/정산/후속계획, stopped의 원 두 stream/Job 닫힘을 확인한다. 외부 compiler/Jobs 포트만 대역이며 내부 verifier/수신자를 대역으로 바꾸지 않았다. transition.ready는 모든 target 반환이며 전체 verified의 뜻이 아니다. 실제 Lean/Mathlib·native Job 성공은 이 확인 범위 밖이다.
