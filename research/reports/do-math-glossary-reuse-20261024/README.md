# 용어 정본의 재사용 기준과 현재 자료 수리

기존 계약에는 같은 대상의 이름을 재사용하라는 규칙이 있었다. 이번 변경은 그 규칙을 반복하는 대신, 모든 보조 표기를 제안하도록 하던 범위와 새 정의이면 채택하던 기준을 고쳤다. 작업자는 먼저 기존 정의를 사용하고, 원고 안의 국소 약칭과 연구 전체에서 공유할 이름을 구별한다. 계획은 제안됐다는 이유만으로 새 항목을 등록하지 않는다.

현재 용어집도 일괄 수리했다. 338개 공유 항목 중 38개를 공통 정의의 식이나 원 논증의 국소 표기로 옮겨 300개를 유지한다. 같은 항목에 누적된 상태 설명은 현재형으로 다시 쓰고 과거 설명은 이력으로 옮겼다. 서로 다른 전역 함수나 필요한 증명 의무는 통합하지 않았다. 구형 형식을 허용하는 검사 분기와 현행 별칭 항목은 두지 않는다.

이 폴더는 검토 가능한 완료 증거의 저장소 사본이다. *.snapshot.md와 glossary.before.md는 해당 시점의 기록이며 현행 정본이 아니다. 문서 안의 상대 링크는 원 공개 폴더를 기준으로 작성되어 있으므로 원문을 따라갈 때에는 아래 위치를 사용한다.

- 원 인스턴스: C:/math/.skill-workspace/do-math/parking-unimodality-fresh-20261023-014524
- 수리 전 계획: k8e795159fffe4295b1da2d8205bfa010
- 공개한 운영 계획: k3a9e2b2d0e5e4113bd6f6838037fccb8
- 이 인스턴스는 루트 Git에서 제외되고 자체 Git으로 공개 기록을 관리한다. 이 폴더의 스냅샷과 검증 자료는 루트 Git에 보존한다.

consolidation-evidence.json에 제외한 항목·이유·전후 정의가 있다. verify_relations.py는 Python 표준 라이브러리로 작은 순열·숲과 원 주차 과정을 직접 열거하여 식을 대조한다. 유한 비교이며 새 일반 정리나 Lean 인증을 뜻하지 않는다. validation.json은 구조·참조·57개 회귀 검사 범위를 기록한다. reader-final.json과 reader-decision.json은 전체 독해에서 실제로 이해한 내용과 작성자의 대조다.

운영 계획은 기존 대기 요청과 미처리 사건을 소비하지 않고 공식 검사·공개 경로로 반영했다. publication-receipt.json에 그 확인이 있다. 사용자의 마지막 지시 “재개는 하지 마”에 따라 STOP을 유지하며 실행 세션 0개, 대기 동료 요청 5개를 보존했다.

저장소 사본은 줄 끝 공백과 파일 끝 빈 줄을 정리했다. 변경한 사본의 정리 전후 해시는 snapshot-normalization.json에 있으며 원 공개 파일의 바이트는 바꾸지 않았다. validation.json의 원 파일 해시는 원 공개 폴더 기준이다.
