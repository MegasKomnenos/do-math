# P vs NP 초기 문헌 체계 명세

## 0. 문서 계약

이 문서는 P vs NP 연구 인스턴스를 만들기 전에 한 번 수행할 기준 문헌 조사의 계약이다. 조사는 현대 수학과 이론 컴퓨터과학 전 분야의 현행 문헌을 가변 해상도로 지도화한다. 실제 P vs NP 연구는 이 조사가 완료된 뒤에만 시작한다.

이 문서는 문헌을 실제로 수집하거나 판독한 결과가 아니다. 실제 조사는 `do-math` 연구 인스턴스를 만들기 전의 별도 사전 조사 절차가 수행한다. 사전 조사 도구는 `do-math` 구현이 제공하지만 연구 인스턴스의 F·작업·관계 상태를 사용하거나 만들지 않는다. 조사 결과인 승인·동결 문헌 지도는 이 명세와 함께 문헌 입력 패키지를 이루며, `research/pvsnp/연구-주제-선호.md`, `research/pvsnp/핵심-정의-명세.md`와 별도로 `do-math` 초기화에 전달된다.

승인 문헌 지도는 연구 인스턴스의 F 객체, 작업 씨앗, 관계나 Lean 정본을 직접 만들지 않는다. `do-math` 초기화는 명세와 동결 지도를 별도 입력자료로 받아 최초 수입 대응표에 따라 자료·근거, 연구 맥락, 초기 F 객체, 작업 씨앗, 관계와 그 밖의 실제 소유자에 나누어 수입한다. 동결 지도가 없거나 완료 증거가 유효하지 않으면 연구 인스턴스를 만들지 않는다.

이 문서와 다음 정본이 충돌하면 다음 순서를 적용한다.

1. 보편 연구 방법과 내부 상태는 `docs/do-math/통합-설계.md`가 소유한다.
2. P vs NP의 주제·결과·범위는 `research/pvsnp/연구-주제-선호.md`가 소유한다.
3. 핵심 P와 NP의 수학 문면은 `research/pvsnp/핵심-정의-명세.md`가 소유한다.
4. 초기 문헌 조사의 분야·깊이·검색·판독·검토·완료·출력은 이 문서가 소유한다.

종결한 `pvsnp-탐사-1`의 `research/pvsnp/literature/` 자료는 과거 참고 자료다. 그 문헌 목록, 접근·판독 상태와 완료 판정은 새 조사에 전이되지 않는다. 새 조사가 같은 자료를 선택하면 이 계약으로 다시 처리한다.

## 1. 목적, 산출물과 제외 범위

### 1.1 목적

초기 문헌 조사는 후속 AI가 다음 판단을 정확히 할 수 있는 문헌 지도를 만든다.

- 어떤 분야와 지식 층위를 다시 읽어야 하는가.
- 각 문헌의 정확한 판본과 재진입 좌표는 무엇인가.
- 어떤 정의·주장·방법·논쟁·반례·장벽과 구조가 문헌에 있는가.
- 문헌끼리 어떤 관계가 있고 그 관계를 누가 주장했는가.
- 무엇이 학계의 핵심층이며 무엇이 미해결·논쟁 중·접근 불가인가.
- 어떤 미검증 연구 후보를 `do-math`가 수입 단계에서 검토할 수 있는가.

문헌 지도는 수학 지식의 정본이나 원문의 대체물이 아니다. 후속 AI가 문헌의 수학적 내용을 연구 논증, 확정 관계, Lean 후보나 정본 편입 제안에 사용하려면 지도에 결박된 정확한 원문 판본을 다시 읽고 현행 `do-math` 검증을 적용한다.

### 1.2 완료 산출물

실제 조사는 `research/pvsnp/literature-baseline/`에 다음 추적 산출물을 만든다.

```text
survey.json
fields/<field_id>.json
cells/<cell_id>.json
works/<work_id>.json
versions/<version_id>.json
readings/<reading_id>.json
readings/<reading_id>.md
relations/<relation_id>.json
search/<cell_id>/<search_run_id>.json
gaps/<cell_id>.json
reviews/<cell_id>/<cell_version>/<round_id>/...
manifests/artifacts.json
reports/coverage.md
reports/completion.md
originals/                         # Git 비추적
```

JSON은 기계 정본이다. Markdown 판독 지도와 보고는 JSON이 파일 참조와 SHA-256으로 결박한다. `originals/`의 실물은 Git에 넣지 않고 `manifests/artifacts.json`만 추적한다.

`survey.json`은 `schema_version`, 조사 ID, 명세·정적 입력의 파일 참조, 생명주기 `planning|running|reviewing|converging|frozen`, 분야 계층 판본, 칸 집합 manifest, artifact manifest, 전체 완료 검사와 동결 Git OID를 가진다. `frozen`은 흡수 상태이며 같은 조사 ID의 내용을 다시 열지 않는다.

### 1.3 제외 범위

초기 문헌 조사는 다음을 수행하지 않는다.

- P vs NP 증명·반증과 실제 수학 연구
- 문헌의 모든 수학적 주장을 독립적으로 재증명
- 수학 해설–Lean 동일성 인증이나 Lean 정본 편입
- 초기 F 객체·작업 씨앗·관계의 직접 생성과 포트폴리오 선택
- 문헌 지도의 장기 갱신·재개정·폐기 운용
- 저자·출판사·도서관에 대한 문의, 원문복사·상호대차 신청과 유료 구매

조사 완료 뒤 지도는 동결한다. 뒤에 발견되거나 발행된 문헌과 새 접근 가능성은 지도를 다시 열지 않고 연구 인스턴스 안의 일반 자료·근거와 외부 변화 절차로 처리한다.

## 2. 도메인 모형

### 2.1 기준 핵심층

**기준 핵심층**은 한 `분야 × 깊이` 칸을 정확히 구별·설명·검증하는 데 필요한 학계의 핵심 문헌과 지식이다. 교과서적·정본적·총괄적·대표적이라고 일반적으로 평가되는 자료뿐 아니라, 그 내용을 판별하는 데 필요한 주요 대안·반론·반례·경계 사례·주변 개념·외부 의존 지식과 관계를 포함한다.

관계 폐쇄는 새로 만난 주변 개념의 전 영역을 재귀적으로 조사하지 않는다. 최초 칸의 내용을 정확히 구별·설명·검증하는 데 필요한 범위에서 멈춘다. 중단 근거는 포함한 관계와 제외한 후속 관계를 함께 제시해야 한다.

기준 핵심층은 고정 편수, 인용 횟수나 검색 결과 수로 정의하지 않는다. 학계의 일반적 지위는 서로 독립적인 전거의 채택·종합·비판·교육·후속 사용을 대조해 판정한다. 이 문장의 신호들은 열린 예시다.

### 2.2 문헌 지도

**문헌 지도**는 원문을 대신하지 않고 후속 판독을 안내하는 승인된 조사 산출물이다. 문헌 지도는 자료의 존재, 판본, 정보 상태, 내용 윤곽, 한계, 관계, 접근 상태와 원문 재진입 좌표를 보존한다.

### 2.3 지적 작업과 판본

**지적 작업**은 판본이 바뀌어도 같은 연구 산출로 식별되는 논문·책·데이터셋·소프트웨어 프로젝트 등의 논리적 작업이다. **판본**은 실제로 접근·판독한 출판본, 프리프린트 판본, 개정본, 정오표, 철회문, 데이터 릴리스나 코드 커밋이다.

주장과 인용은 지적 작업의 대표 제목이 아니라 정확한 판본에 결박한다. 정정·철회·대체는 과거 판본과 판독 기록을 삭제하지 않고 현행 지위와 사용 가능성을 바꾼다.

### 2.4 문헌 유래 관계와 AI 유래 관계

**문헌 유래 관계**는 정확한 판본이 명시하거나 입증한 관계다. **AI 유래 관계**는 조사 AI가 여러 자료를 대조해 제안한 미검증 관계다.

AI 유래 구조적 유사성은 단순한 비유나 같은 낱말의 사용만으로 만들지 않는다. 대응 객체·관계·가정, 보존되거나 깨지는 성질, 근거 좌표, 반례 가능성, 검증 과제와 그 밖에 타당성을 바꾸는 정보를 제시한다. 이 항목들은 열린 예시다. AI 유래 관계는 문헌의 주장이나 인증 수학으로 표시하지 않는다.

## 3. 분야 계층과 깊이

### 3.1 조사 우주

조사 우주는 현대 수학과 이론 컴퓨터과학 전 분야다. 다른 학문을 독립 분야로 확장하지 않는다. 다만 최초 칸을 이해·검증하는 데 필요한 다른 학문의 자료는 기준 핵심층의 관계 폐쇄 안에 포함할 수 있다.

분야는 단일 트리가 아니라 여러 부모를 허용하는 중첩 계층이다. 한 문헌과 한 지식 항목은 여러 분야와 칸에 연결할 수 있다. 기록은 한 번만 만들고 칸에서 참조한다.

### 3.2 가변 해상도

분야 해상도는 조사 시점에 학계가 일반적으로 평가하는 P vs NP 근접도에 따라 정한다.

- 직접 영역은 개별 문제군·방법군·장벽·표현 체계까지 세분한다.
- 인접 영역은 관련 하위 분야까지 세분한다.
- 맥락 영역은 표준 학문 하위 분야 수준으로 둔다.
- 먼 영역은 현대 수학 또는 이론 컴퓨터과학의 공인 대분류 수준으로 둔다.

근접도는 현재 연구 접근의 유망성이나 포트폴리오 우선순위가 아니다. 근접도는 문헌 지도의 분류 해상도만 정한다. 실제 연구 가치는 `do-math`가 연구 헌장과 현행 근거로 판단한다.

초기 계층은 공인 수학·컴퓨터과학 분류의 현행 구조를 모두 씨앗으로 가져온다. 수학은 [MSC2020 공식 분류](https://msc2020.org/)의 계층을, 이론 컴퓨터과학은 [ACM Computing Classification System](https://www.acm.org/publications/class-2012)과 [arXiv 범주](https://info.arxiv.org/help/prep.html)를 독립 분류 축으로 사용한다. 이 분류들은 같은 자료에 여러 분류를 허용하므로 하나의 부모만 강제하지 않는다. 분류 원전의 식별자, 실제 가져온 판본과 해시를 `scheme_refs`에 보존한다. 외부 근거와 판본 주의는 `docs/wayfinder/pvsnp-재설계/문헌-체계-외부근거.md`에 있다.

P vs NP 직접 영역에는 적어도 다음 구분을 제공하되 이 목록으로 하위 분야를 닫지 않는다.

- 계산 모형, 계산 가능성과 시간·공간 복잡도
- P, NP, coNP와 관련 계급, 환원과 완전성
- 구조 복잡도와 복잡도 계층
- 회로 복잡도와 하계
- 증명 복잡도
- 무작위성, 의사난수성과 derandomization
- 기술 복잡도, 유한모형이론과 논리적 특성화
- 알고리즘, SAT·CSP와 정확·매개변수·지수시간 복잡도
- 대수적·기하적·표현론적 복잡도
- 통신·질의·정보 복잡도와 데이터 구조 하계
- 양자·무작위·비균일·평균 경우 계산과 핵심 목표의 경계
- relativization, natural proofs, algebrization와 그 밖의 방법론적 장벽
- 형식 증명, 계산복잡도 라이브러리와 공개 계산 자료

`field` 기록은 다음 필드를 가진다.

| 필드 | 의미 |
|---|---|
| `field_id` | 위치와 무관한 안정 ID |
| `title` | 사람이 읽는 분야 이름 |
| `definition_ref` | 포함·제외 경계를 정한 산문과 해시 |
| `parent_ids` | 비어 있을 수 있는 여러 부모 |
| `scheme_refs` | 외부 공인 분류 식별자와 판본 |
| `proximity_basis` | 일반적 근접도 판정 근거 |
| `resolution` | 이 분야에서 사용한 세분 수준 |
| `child_ids` | 같은 판본의 직접 자식 |

### 3.3 깊이 축

깊이는 출처 유형이 아니라 지식의 학습·발전 층위다. 값은 다음 다섯 가지로 닫는다.

| 값 | 의미 |
|---|---|
| `foundations` | 기본 대상·정의·표기·선행 기초와 입문적 표준 결과 |
| `standard_synthesis` | 분야가 표준으로 종합한 이론, 교과서적 관계와 공통 관점 |
| `primary_core` | 분야의 핵심 원 성과와 그 원 논증·구성 |
| `development_and_critique` | 후속 개선·대안·반례·정정·논쟁·적용 경계 |
| `current_frontier` | 조사 시점의 열린 문제·최신 결과·활성 방법과 불확실성 |

교재·조사 논문·원 논문·프리프린트·형식 증명·데이터·코드는 출처 유형이다. 한 출처는 여러 깊이를 뒷받침할 수 있다.

특정 분야에 한 깊이가 개념적으로 적용되지 않으면 `applicability=not_applicable`로 판정한다. 깊이는 적용되지만 해당 층위의 자료가 실제로 없으면 `material_status=no_material`로 판정한다. 둘은 다른 축이며, 모두 근거와 전원 합의를 요구하고 승인된 칸 완료 뒤 전체 착수 관문을 통과한다.

## 4. 출처 자격, 권위와 정보 상태

### 4.1 출처 자격

정식 출판과 동료평가는 기준 핵심층의 필수 자격이 아니다. 학계가 중심 자료로 실제 취급하면 프리프린트, 미출판 원고, 형식 증명 저장소, 공개 데이터와 코드도 포함한다. 자료 언어에는 제한을 두지 않는다.

번역은 판독 보조물이다. 번역문을 원문 인용 좌표나 권위 있는 주장으로 사용하지 않는다. 원문과 번역이 다르면 원문을 다시 판독하고 차이를 기록한다.

공인 문헌은 높은 사전 신뢰를 가진다. 높은 사전 신뢰는 핵심 후보의 우선 탐색과 결함 주장에 대한 주의 깊은 재검사를 뜻한다. 문헌에 실렸다는 사실은 수학적 타당성, Lean 정본 편입이나 P vs NP 관련성을 자동 확정하지 않는다.

### 4.2 출처 유형과 지위

출처 유형은 열린 분류다. 각 판본은 적어도 다음 지위를 별도 필드로 기록한다.

- 출판·동료평가·편집 상태
- 기관·학회·저자·저장소의 권위와 소유 관계
- 정정·철회·대체 상태
- 형식 검사·빌드·데이터 검증의 실제 범위
- 원문 확보와 판독 범위
- 학계 채택·비판·교육·후속 사용의 근거

`work` 기록은 다음 필드를 가진다.

| 필드 | 의미 |
|---|---|
| `work_id` | 지적 작업의 안정 ID |
| `title`, `contributors` | 판본을 아우르는 식별 정보와 저자·기관 식별자 |
| `work_kind` | 논문·책·데이터·소프트웨어 등을 표현하는 열린 유형 ID |
| `identifier_refs` | DOI·ISBN·arXiv·zbMATH·저장소 등 외부 식별자 |
| `version_ids` | 확인한 판본 전건 |
| `field_refs`, `cell_refs` | 이 작업이 관련된 분야와 칸 |
| `core_status_refs` | 기준 핵심층 후보·채택·제외 판정과 근거 |
| `relation_refs` | 인용·대체·비판·정정과 내용 관계 |

`version` 기록은 다음 필드를 가진다.

| 필드 | 의미 |
|---|---|
| `version_id`, `work_id` | 정확한 판본과 지적 작업 |
| `version_label`, `date` | 원천이 제공한 판본 표지와 날짜 |
| `publication_status` | 출판·동료평가·프리프린트·철회 등 실제 상태 |
| `identifier_refs` | 이 판본에 결박된 외부 식별자 |
| `source_coordinates` | 원 URL·저장소·페이지와 조회 시각 |
| `access_status` | 원문 확보·접근 불가·판독 불가 상태와 근거 |
| `artifact_ref` | 로컬 실물 manifest 항목 또는 `null` |
| `rights` | 로컬 저장·재배포 가능성의 확인 상태 |
| `update_relation_refs` | 정정·철회·대체·새 판본 관계 |
| `citation` | 이 판본을 다시 식별하는 완전한 인용 |

### 4.3 정보 상태

문헌 지도는 다음을 구별한다.

- 원문이 명시한 사실·주장·추측·질문
- 조사 AI가 원문에서 직접 추출한 관찰
- 여러 자료를 대조해 만든 AI 추론
- 아직 검증하지 않은 구조적 유사성과 연구 가설
- 접근 불가·판독 불가·학계 논쟁·자료 부재

원문이 주장한 사실과 그 주장의 수학적 타당성을 같은 필드에 넣지 않는다. 학계가 논쟁 중이거나 조사 자료로 진위를 확정할 수 없으면 그 상태를 정확히 기록한다. AI 전원이 이 판정과 범위에 합의하면 칸 완료를 막지 않는다.

## 5. 검색과 원문 확보

### 5.1 허용 접근 경로

조사는 공개 웹과 조사 시점에 이미 허가된 계정·학술 DB를 사용한다. 공개 웹 검색과 학술 DB 검색은 서로의 실패 때만 여는 대체 경로가 아니라 모든 칸에서 독립적으로 수행하는 필수 검색 채널이다.

경북대학교 학술 DB(KUDOS)의 로그인 크리덴셜 좌표는 `.credentials/kudos.md`다. 조사 대상은 KUDOS가 제공하는 현행 학술 DB 목록과 사용자가 제공한 학술 DB 목록을 합친 뒤 중복 제거한 전건이다. 실제 학술 DB 검색은 Claude headless CLI의 비대화형 실행이 Playwright를 호출해 KUDOS 로그인, 학술 DB 선택, 검색, 결과 판독과 원문 연결 확인을 브라우저에서 직접 수행한다. 단순 HTTP 요청이나 공개 검색 결과로 이 학술 DB 검색을 대신하지 않는다.

Claude 실행에는 크리덴셜 값이 아니라 크리덴셜 파일의 절대 경로만 전달한다. Claude 실행만 이 파일을 직접 읽어 브라우저 입력란에 값을 넣을 수 있다. 크리덴셜 값은 Claude 프롬프트·표준 출력·디버그 로그·Playwright 증거·조사 산출물·manifest·Git 변경에 복제하지 않는다. 검색·로그인 증거는 계정 식별값과 세션 토큰을 제거한 뒤 기록한다.

Claude headless CLI는 로컬에서 확인한 비대화형 `claude -p` 인터페이스를 사용한다. 구현은 정확한 Claude Code 판본, 모델·노력, `--mcp-config`, 허용 Playwright 도구, 조사·세션·실행 ID와 출력 스키마를 실행 manifest에 고정한다. 사전 조사 runner의 프로세스 감독기는 이 Claude CLI와 Playwright 브라우저 프로세스를 같은 하위 AI 실행의 Windows Job Object 안에서 운전한다. 이 감독 상태는 아직 생성되지 않은 연구 인스턴스의 controller나 공용 상태가 아니다.

Claude 브라우저 실행은 로그인·검색·원문 연결·접근 증거 수집을 담당하고 수학적 타당성, 기준 핵심층이나 칸 완료를 판정하지 않는다. 수학 내용을 판독하거나 분야·관계·결함·완료를 판단하는 AI 세션은 `docs/do-math/통합-설계.md`의 수학 판단 모델 계약에 따라 `gpt-5.6-sol max`를 사용한다.

허용 경로에는 다음이 포함될 수 있다. 이 목록은 열린 예시다.

- 공인 학술 DB와 도서관 검색
- 출판사·학회·연구기관의 현행 페이지
- 저자·기관 공개 원고와 프리프린트 서버
- 공식 서지·인용 색인과 전후방 인용망
- 형식 증명 아카이브, 공개 코드 저장소와 데이터 저장소
- 교재·핸드북·조사 문헌의 참고문헌과 강의·분야 안내의 표준 전거

조사는 저자·출판사·도서관에 메시지를 보내지 않는다. 원문복사·상호대차를 신청하거나 유료 자료를 구매하지 않는다.

### 5.2 검색 절차

각 칸은 다음 순서로 검색하되, 결과가 새 핵심 후보나 관계를 드러내면 필요한 앞 단계로 돌아간다.

1. 분야 정의와 깊이에 맞는 공인 분류어·동의어·표준 전거를 찾는다.
2. 공개 검색·공식 색인·공개 원문 경로에서 후보와 원문을 찾는다.
3. Claude headless CLI와 Playwright로 KUDOS 현행 목록과 사용자 제공 목록의 실제 학술 DB 전건을 검색한다.
4. 교재·핸드북·조사 문헌에서 핵심 개념, 원 성과, 대안과 논쟁을 전개한다.
5. 핵심 작업의 정확한 식별자와 판본을 고정한다.
6. 전후방 인용망, 정정·철회·후속 비판과 개선을 추적한다.
7. 형식화·데이터·코드와 다른 언어의 핵심 자료를 대조한다.
8. 반대 관점과 누락을 찾는 별도 적대 검색을 수행한다.
9. 새 후보가 기준 핵심층, 관계 폐쇄, 보조 자료 또는 제외 자료인지 판정한다.
10. 공개 검색과 각 학술 DB의 검색어·필터·결과·원문 연결·결과 없음까지 불변 기록으로 남긴다.

검색 순서는 완료 증명이 아니다. 칸의 전체 판본과 검색 증거를 검토한 AI 전원 합의만 완료를 확정한다.

### 5.3 접근 판정

`retrievable`은 허용 경로에서 원문이나 필요한 공식 내용을 실제로 확보할 수 있는 상태다. `unavailable_after_exhaustion`은 허용 경로 전건을 시도하고도 확보하지 못한 상태다.

충분히 확보할 수 있는 자료를 놓치면 `retrievable_missing`이며 사용자가 정의한 `미충족`이다. 조사 세션은 이 상태를 남긴 채 칸 승인을 요청하지 않고, 새 검색·접근 세션으로 확보를 계속한다.

모든 허용 경로를 소진해도 확보하지 못한 자료는 미충족이 아니다. 작업 식별, 중요성, 시도한 경로·시각·결과, 남은 미검증 주장과 대체 근거의 유무를 기록한다. 동등한 대체 근거가 없어도 이 접근 한계에 AI 전원이 합의하면 칸을 충족으로 닫을 수 있다.

HTTP 성공, 서지 페이지 확보와 원문 확보를 구별한다. 원문이 실제로 열리고 의도한 자료와 일치할 때만 원문 확보로 판정한다.

## 6. 판독 지도와 관계 추출

### 6.1 판독 완료의 기준

전문 완독, 페이지 수나 요약 길이는 판독 완료 기준이 아니다. 판독자는 칸의 완료 판단과 후속 재판독에 필요한 산출물을 정확히 만들어야 한다. 필요한 판독 범위는 산출물에서 역으로 정한다.

각 `reading`은 다음 내용을 가진다.

- 정확한 지적 작업·판본·실물 해시와 접근 좌표
- 실제 판독 범위와 읽지 않은 범위
- 자료가 담당하는 분야·깊이와 핵심층 지위
- 정의·가정·주장·추측·질문·논증 구조·외부 의존 결과
- 관례적 생략, 숨은 전제 후보, 적용 범위와 결론의 한계
- 원문이 제시한 반례·장벽·기법·데이터·코드·형식화
- 다른 문헌·핵심 P·NP 정의와의 명시 관계
- AI가 제안한 미검증 관계와 구조적 유사성
- 정정·철회·후속 비판과 남은 불확실성
- 후속 AI가 원문을 다시 읽을 정확한 페이지·절·정리·파일·선언·커밋 좌표

이 목록은 산출물의 최소 의미를 설명한다. 자료 유형과 실제 판단에 필요한 추가 항목을 막는 닫힌 열거가 아니다.

`reading` JSON은 `reading_id`, `version_id`, 작성 AI·모델·노력·세션·실행 ID, 입력 manifest, Markdown 파일 참조·해시, 판독 범위, 정보 상태, 관련 칸·관계·결함 후보, 검사 결과와 대체 판독 참조를 가진다. Markdown은 위 내용의 사람이 읽는 표현이며 JSON 필드를 별도 정본으로 복제하지 않는다.

### 6.2 논증 전사

문헌 지도는 후속 판독을 가능하게 할 정도로 논증을 구조화한다. 원 증명을 대신하는 자기충족적 재증명은 요구하지 않는다.

전사는 다음을 구분한다.

- 원문이 정의한 대상과 표기
- 명시 가정과 복원한 암묵 가정
- 결론과 양화·범위
- 논증의 주요 단계와 사용한 외부 결과
- 계산·실험·형식 검사에 의존한 부분
- 원문이 생략한 관례적 단계와 실제 논리 공백 후보
- 후속 검증이 다시 열어야 할 정확한 좌표

### 6.3 결함 판정

결함 후보는 정확한 판본·주장·좌표, 기대한 논증, 관찰한 차이, 가능한 영향과 정보 상태를 가진다. 검토는 적어도 실제 결함, 허용 가능한 관례적 생략, 검토자 오독과 현재 판정할 수 없는 논쟁을 구별한다. 이 구별은 원문 권위나 다수 견해만으로 확정하지 않는다.

결함 후보는 칸 전체 판본의 이의로 들어간다. 회차 교체형 수렴이 결함 후보를 승인·철회·수정하거나 `현재 판정 불가`로 합의할 때까지 칸을 승인하지 않는다.

### 6.4 관계

관계 기록은 관계의 양 끝, 방향, 의미, 근거 판본·좌표, 생성 주체, 정보 상태, 한계와 후속 검증 요구를 가진다. 이름이 같거나 인용했다는 사실만으로 수학적 관계를 만들지 않는다.

핵심 P·NP 정의가 아직 완성되지 않았으면 관계를 그 정의의 특정 판본에 가장하지 않는다. 관계 후보가 요구하는 정의·부호화·계산 모형·환원·자원 측정의 의무를 기록하고 `research/pvsnp/핵심-정의-명세.md`의 완성 판본을 수입할 때 대조한다.

## 7. 칸 상태와 전원 합의

### 7.1 칸 기록

`cell`은 `field_id + depth`로 식별한다. 같은 문헌과 관계를 여러 칸에서 참조할 수 있다. 칸 기록은 다음 필드를 가진다.

| 필드 | 의미 |
|---|---|
| `cell_id` | 안정 ID |
| `field_id`, `depth` | 칸의 좌표 |
| `applicability` | `applicable`, `not_applicable` |
| `material_status` | `material_present`, `no_material`, 또는 `not_applicable`일 때만 `null` |
| `cell_state` | `open`, `in_review`, `converging`, `satisfied` |
| `core_claim_ref` | 이 칸의 기준 핵심층과 경계 |
| `work_refs`, `reading_refs` | 문헌과 판독 지도 |
| `relation_refs` | 칸 안팎의 관계 |
| `search_manifest_ref` | 검색어·경로·결과·접근 상태 전건 |
| `gap_register_ref` | 누락 후보·접근 불가·논쟁·제외 근거 |
| `cell_version` | 검토한 불변 판본 |
| `review_plan_ref` | 검토 역할과 입력 manifest |
| `approval_ref` | 전원 승인 기록, 없으면 `null` |

`미충족`은 `cell_state`의 값이 아니다. `retrievable_missing` 자료가 있다는 획득 결함이다. 결함이 존재하면 칸은 `satisfied`가 될 수 없다.

### 7.2 검토 계획

칸 판본마다 서로 결과를 보지 않는 새 `gpt-5.6-sol max` 세션을 최소 세 개 배정한다. 전원은 칸 판본, 연결 원자료, 검색·접근 증거, 앞선 회차의 산출물·이의·답변·피드백 전건을 직접 읽는다. 역할은 전체를 검토하되 다음 관점을 나누어 사각을 줄인다.

- 핵심층·분야·깊이·누락 검토
- 출처·판본·접근·인용 좌표 검토
- 주장·논증·결함·관계·정보 상태 검토

자료 유형이나 전문 분야가 추가 관점을 요구하면 검토자를 더 배정한다. 세 역할은 최소 구성이지 닫힌 역할 목록이 아니다.

필수 입력을 읽지 못했거나 컨텍스트 한계 때문에 전건을 검사하지 못한 세션은 승인·이의를 만들지 않고 `incomplete`로 끝난다. 요약이나 이전 결론으로 원자료와 피드백 전문을 대체하지 않는다.

### 7.3 회차 교체형 합의 수렴

한 회차의 검토자들은 서로의 출력을 보기 전에 `approved` 또는 이의 전건을 봉인한다. 하나라도 이의가 있으면 칸은 `converging`으로 남는다.

다음 회차는 기존 세션을 재개하지 않는다. 새 작성·검토 세션들이 이전 판본, 이의, 답변, 피드백과 근거 전건을 읽는다. 새 작성 세션은 이의를 반영하거나 근거를 들어 답하고 새 칸 판본을 만든다. 새 검토 세션들은 새 판본 전체를 다시 검토한다.

고정 회차 상한, 다수결, 최종 단독 판정자와 미해결 이의의 묵시적 기각을 두지 않는다. 모든 현행 검토자가 같은 칸 판본을 승인하고 미해결 이의가 없을 때만 전원 승인 기록을 만들 수 있다.

전원 합의는 타협한 공통 문구가 아니라 근거로 방어되는 공통 판정이어야 한다. `접근 불가`, `자료 부재`, `학계 논쟁 중`이나 `현재 판정 불가`도 그 범위와 근거에 전원이 합의하면 타당한 공통 판정이다.

### 7.4 칸 완료

다음 조건을 모두 만족할 때만 `applicable` 칸을 `satisfied`로 바꾼다.

```text
field_and_depth_valid
AND core_boundary_explicit
AND search_manifest_complete
AND no_retrievable_missing
AND every_included_work_has_pinned_version
AND every_required_reading_and_relation_valid
AND every_access_limit_and_uncertainty_recorded
AND current_cell_version_unanimously_approved
```

`applicability=not_applicable`인 칸과 `material_status=no_material`인 칸도 같은 검색 증거와 전원 승인을 요구한다. 자료를 찾지 못했다는 사실만으로 자료 부재를 판정하지 않는다.

### 7.5 전체 조사 완료

분야 계층과 칸 집합 자체를 별도 전체 검토에 보낸다. 전체 검토는 현대 수학·이론 컴퓨터과학 전 분야 포함, 가변 해상도, 중첩 관계, 깊이 적용성과 미생성 칸을 검사한다.

다음 조건을 모두 만족할 때만 조사를 `frozen`으로 닫는다.

```text
taxonomy_unanimously_approved
AND every_applicable_cell_satisfied
AND every_not_applicable_or_no_material_cell_satisfied
AND no_open_or_converging_cell
AND no_retrievable_missing
AND cross_cell_references_valid
AND artifact_manifest_valid
AND do_math_input_package_valid
```

조사 완료량, 문헌 수와 파일 수는 이 완료 판정을 대신하지 않는다.

## 8. 저장, 무결성과 민감 정보

### 8.1 원문 보관

적법하게 확보했고 로컬 저장이 허용된 원문·코드·데이터는 다음 Git 비추적 경로에 둔다.

```text
research/pvsnp/literature-baseline/originals/
```

파일 이름은 안정 ID와 원래 확장자를 포함한다. 자료가 디렉터리나 저장소이면 판본 식별자와 파일별 manifest를 함께 만든다. 원문을 수정하지 않는다. 추출 텍스트·렌더 이미지·빌드 산출물은 원문과 다른 파생 자료로 식별한다.

`manifests/artifacts.json`은 각 실물의 상대 경로, SHA-256, 바이트 크기, 미디어 형식, 원본 좌표, 접근 시각, 판본 식별자, 로컬 저장·재배포 권리 상태와 파생 관계를 가진다. manifest에 크리덴셜이나 세션 토큰을 넣지 않는다.

### 8.2 판본과 중복

DOI, ISBN, arXiv ID, zbMATH ID, 저장소 URL·commit OID, 데이터 DOI, ORCID·ROR와 출판사 식별자는 출처가 소유한 의미대로 기록한다. 하나의 식별자만으로 지적 작업 동일성을 추정하지 않는다. DOI 메타데이터·관계·업데이트는 [Crossref 공식 REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/), arXiv 판본은 [특정 판본 식별자](https://info.arxiv.org/help/arxiv_identifier.html), 코드·릴리스는 GitHub의 정확한 release·asset·commit 좌표를 우선 사용한다.

바이트가 같은 파일은 같은 실물로 중복 제거할 수 있다. 내용이 같은지 판정하려면 제목·저자·판본 문면·출판 이력과 실제 차이를 대조한다. 프리프린트와 출판본, 학회판과 저널판, 번역과 원문은 자동 병합하지 않는다.

### 8.3 기계 형식

추적 JSON은 UTF-8, LF, 고정 들여쓰기, 결정론적 키 순서와 파일 끝 개행을 사용한다. 알 수 없는 필드, 깨진 참조, 해시 불일치와 누락 파일을 조용히 무시하지 않는다. 파일 참조는 `docs/do-math/통합-설계.md`의 파일 참조 계약과 호환돼야 한다.

## 9. 측정과 보고

수집, 이해와 연구 활용을 하나의 점수로 합치지 않는다.

### 9.1 수집 측정

수집 측정은 분야·깊이별 후보·핵심 작업·판본·원문 확보·접근 불가·자료 부재·중복과 검색 경로를 설명한다. 수량은 누락 탐지와 감사에 사용하지만 완료 임계값이 아니다.

### 9.2 이해 측정

이해 측정은 판독 지도 필드의 완전성, 정확한 재진입 좌표, 전제·한계·논쟁·결함의 처리와 전원 검토 상태를 설명한다. 페이지 수나 요약 길이를 이해의 대리값으로 쓰지 않는다.

### 9.3 활용 측정

활용 측정은 문헌 유래 관계, AI 유래 미검증 관계, 핵심 정의 연결 의무와 `do-math`가 검토할 후보를 설명한다. 후보 수나 관계 수가 연구 가치 또는 P vs NP 진전이라는 뜻은 아니다.

### 9.4 보고

`reports/coverage.md`는 사람이 분야 계층과 모든 칸의 상태·근거를 따라갈 수 있게 한다. `reports/completion.md`는 전체 완료 식의 각 항목, 검사 명령, 결과와 실패 의미를 기록한다. 보고는 기계 정본을 복제하지 않고 정확한 기록을 링크한다.

## 10. 문헌 활용 전략

### 10.1 분야 독립 전략

문헌 지도는 이미 알려진 결론의 목록이 아니라 후속 문제풀이가 정확한 원문과 구조에 재진입하는 장치다. `do-math`가 문헌을 활용할 때는 다음 순환을 적용한다.

1. 연구 질문과 현재 F 객체에서 필요한 정의·가정·관계·방법·반례의 형태를 정한다.
2. 문헌 지도에서 같은 형태와 대비되는 형태를 찾고 정확한 판본을 다시 읽는다.
3. 원문의 논증이 어떤 구조를 사용하고 어느 가정·표현·범위에서 성립하는지 재구성한다.
4. 현재 질문과 원문 사이의 대응과 차이를 명시한다. 차이를 이름·직관·분야 명성으로 메우지 않는다.
5. 그대로 재사용할 수 있는 결과, 변환·일반화가 필요한 기법, 적용을 막는 반례·장벽과 새 미검증 후보를 분리한다.
6. 필요한 후속 검증을 F 객체·관계·작업 씨앗 제안으로 만들되 `do-math`의 실제 수입·착수 검토를 거친다.
7. 작업 결과가 문헌 해석이나 구조 대응을 바꾸면 연구 인스턴스의 자료·근거와 기억에 반영한다. 동결 문헌 지도 자체는 수정하지 않는다.

이 순환은 정의 정렬, 사례·반례 전이, 증명 패턴 차용, 장벽의 전제 회피, 다른 분야의 성공 구조 변환과 계산·형식 자료 재사용을 포함할 수 있다. 이 항목들은 열린 예시다.

### 10.2 P vs NP 전용 전략

P vs NP에 문헌을 적용할 때는 모든 후보를 핵심 정의와 직접 대조한다.

- 계산 모형, 입력 부호화, 최악·평균 경우, 균일성, 결정성, 자원 측정과 환원 종류의 차이를 기록한다.
- 제한 회로·증명 체계·oracle·양자·무작위·비균일·조건부 결과를 핵심 목표와 같은 명제로 바꾸어 쓰지 않는다.
- 장벽 결과는 이름을 확인하는 데 그치지 않고 후보 방법에 장벽 전제가 실제로 성립하는지 검사한다.
- 알고리즘·하계·완전성·구조 정리·형식화·계산 자료는 실제 결론 범위와 핵심 목표로 가는 추가 의무를 분리한다.
- 먼 분야의 방법은 구조 대응과 깨지는 성질을 먼저 기록하고, 입증되지 않은 전이는 AI 유래 가설로 둔다.
- 문헌의 다수 견해, 권위, 발행 시점과 인용 수는 `P = NP` 또는 `P ≠ NP`의 증거가 아니다.

이 전략은 연구 방향을 고정하거나 포트폴리오 우선순위를 선결정하지 않는다. `do-math` 선택 세션은 동결 지도를 포함한 전체 현행 맥락과 실제 연구 결과로 탐색·집중 활용을 판단한다.

## 11. `do-math` 입력 인터페이스

승인 지도는 다음 의미 묶음을 제공한다.

- 분야·깊이와 기준 핵심층 경계
- 지적 작업·판본·판독·접근·권리·무결성 기록
- 문헌 유래 주장과 관계
- AI 유래 추론·구조적 유사성·연구 후보
- 논쟁·결함·접근 불가·자료 부재와 남은 불확실성
- 핵심 P·NP 정의와 대조할 연결 의무
- 검색·검토·전원 합의의 증거

입력 패키지는 각 의미를 정보 상태와 함께 전달한다. `do-math`는 문헌 유래 `source`, 조사 관찰 `observation`, AI 논증 `argument`, 미검증 유사성 `hypothesis`와 실패 기록 `failure_record`를 자기 자료·근거 어휘에 맞게 수입한다.

지도 안의 F 후보·작업 씨앗 후보·관계 후보는 제안이다. `do-math` 최초 수입은 후보를 전건 보존하되, 내부 F 객체·작업 기록·관계로 만들지 여부와 실제 소유자를 자기 계약으로 판정한다. 문헌 지도의 `satisfied`는 Lean 형식 타당성, 수학적 진리, 연구 가치나 작업 착수 가능성을 뜻하지 않는다.

## 12. 전체 워크스루

### 12.1 표준 교재와 핵심 원 논문

1. 조사 AI가 한 분야의 공인 분류어와 표준 종합 자료를 찾는다.
2. 종합 자료가 핵심으로 다루는 정의·정리·방법과 원 출처를 전개한다.
3. 지적 작업과 정확한 판본을 분리하고 원문·정정·후속 비판을 확보한다.
4. 판독 지도는 핵심 내용과 한계, 원 논증 재진입 좌표를 기록한다.
5. 칸 검토자들은 표준 종합과 원 성과가 서로 일치하는지, 빠진 대안과 반례가 없는지 검사한다.
6. 이의가 있으면 새 회차가 자료를 보강하고 칸 전체를 다시 검토한다.

### 12.2 접근 불가 원문

1. 핵심 후보의 서지 페이지는 찾았지만 원문을 확보하지 못한다.
2. 공개 웹, 허가된 학술 DB, 저자·기관 공개본과 공인 저장소를 전건 검사한다.
3. 능동 문의·상호대차·구매는 수행하지 않는다.
4. 모든 허용 경로가 실패하면 `unavailable_after_exhaustion`과 증거를 기록한다.
5. 동등한 대체 근거가 없어도 검토자 전원이 접근 한계와 남은 불확실성에 합의하면 칸을 승인할 수 있다.

### 12.3 프리프린트·형식화·코드·데이터

1. 학계의 후속 사용과 분야 지위를 근거로 핵심 후보 자격을 판정한다.
2. 프리프린트 판본, 출판본, 저장소 commit, 데이터 릴리스와 정정 관계를 분리한다.
3. 실제로 실행한 빌드·검사만 검증 상태에 기록한다. 저자의 성공 진술을 독립 재현으로 바꾸어 쓰지 않는다.
4. 결과의 수학적 의미, 계산 자료의 유한 범위와 핵심 P vs NP 목표의 차이를 기록한다.

### 12.4 먼 분야의 구조적 유사성

1. 먼 분야는 공인 대분류 수준에서 기준 핵심층을 조사한다.
2. 문헌이 P vs NP와의 관계를 명시하면 문헌 유래 관계로 기록한다.
3. AI가 새 유사성을 발견하면 대응 구조, 근거와 실패 조건을 갖춘 AI 유래 관계로 기록한다.
4. 검토자들은 단순 비유인지 검증 가능한 후보인지 판정한다.
5. 승인된 관계도 미검증 후보로 남고 `do-math` 상태를 직접 바꾸지 않는다.

### 12.5 전체 동결

1. 모든 칸의 `cell_state`가 `satisfied`에 도달한다. 적용되지 않는 칸은 `applicability=not_applicable`, 자료가 실제로 없는 칸은 `material_status=no_material` 근거를 함께 가진다.
2. 전체 분류 검토가 분야 누락, 부적절한 해상도와 깨진 중첩 관계를 검사한다.
3. 기계 검사가 JSON·참조·해시·manifest와 완료 식을 전수 검사한다.
4. 새 AI 검토단이 전체 입력 패키지와 완료 보고를 승인한다.
5. 조사 상태를 `frozen`으로 바꾸고 정확한 Git 커밋과 로컬 원문 manifest를 고정한다.
6. `do-math`는 동결 패키지를 별도 프로젝트 입력자료로 수입한다.

## 13. 구현 요구와 완료 조건

`do-math` 구현은 다음 기능을 제공해야 한다.

- 공인 분야 분류를 가져와 중첩·가변 해상도 분야 계층으로 만드는 도구
- 분야·칸·지적 작업·판본·판독·관계·검토·artifact manifest 스키마와 검사기
- 허용 접근 경로의 검색·접근 증거를 불변 기록으로 만드는 어댑터
- Claude headless CLI와 Playwright로 KUDOS 로그인 및 제공 학술 DB 전건을 검색하는 전용 어댑터
- URL·서지 페이지·원문 확보, 접근 불가와 `retrievable_missing`을 구별하는 검사
- 정확한 판본·식별자·해시·정정·철회 관계 처리
- 칸 판본 생성, 회차별 입력 manifest와 새 AI 세션 파견
- 전원 승인과 완료 식의 기계 검사
- 연구 인스턴스 밖에서 전체 조사를 운전하고 동결 지도 패키지를 `do-math` 최초 수입에 전달하는 사전 조사 runner와 exporter
- 연구 인스턴스와 분리된 조사 ID·실행 ID·Windows Job Object·체크포인트·재개 상태를 관리하는 사전 조사 프로세스 감독기
- Git 비추적 원문 디렉터리와 추적 manifest의 무결성 검사

문헌 체계 구현은 다음 시험을 통과해야 한다.

1. 한 자료를 여러 칸에서 참조해도 지적 작업과 판본 기록을 중복 생성하지 않는다.
2. 접근 가능한 원문을 놓치면 칸 완료를 차단한다.
3. 허용 경로를 소진한 접근 불가는 근거와 함께 완료를 허용한다.
4. `not_applicable`, `no_material`, 검색 실패와 접근 불가를 서로 바꾸어 쓰지 않는다.
5. 미해결 이의 하나라도 있으면 전원 승인과 전체 동결을 차단한다.
6. 모든 검토자가 승인한 같은 칸 판본만 `satisfied`가 된다.
7. 정정·철회 뒤에도 과거 판본과 판독 이력을 보존하고 현행 지위를 바꾼다.
8. 문헌 유래 관계와 AI 유래 관계를 기계적으로 구별한다.
9. 문헌 지도 후보가 `do-math` 내부 F·작업·관계를 직접 만들지 못한다.
10. Git에 원문 실물이 추가되면 검사에 실패한다.
11. 크리덴셜 값이 추적 파일·로그·프롬프트에 나타나면 검사에 실패한다.
12. 전체 분야 계층과 모든 칸의 승인 없이는 P vs NP 연구 인스턴스의 실행 껍질을 열지 않는다.
13. 공개 검색만 수행했거나 KUDOS·제공 학술 DB 검색 증거가 빠진 칸은 승인을 차단한다.
14. Claude headless CLI 실행, Playwright 브라우저와 그 자식 프로세스가 지정된 Job Object 밖에서 실행되면 검사에 실패한다.

명세 구현이 위 의미를 보존하면서 더 간단한 기계 구조를 제공할 수 있으면 그 구조를 선택할 수 있다. 사용자 결정, 신뢰 경계, 상태 구별, 전원 합의와 전체 착수 관문은 구현 편의를 이유로 약화하지 않는다.
