# P vs NP 초기 문헌조사 명세

## 0. 문서 계약

이 문서는 P vs NP 연구 인스턴스를 만들기 전에 한 번 수행할 문헌조사의 규범 계약이다. 조사는 현대 수학과 이론 컴퓨터과학 전 분야를 다루며, P vs NP에서 먼 분야도 제외하지 않는다. 실제 자료 수집은 여러 조사 묶음으로 나누어 반복할 수 있지만, 조사를 끝낼 때는 정확한 판본과 출처가 결박된 하나의 닫힌 문헌 집합을 만든다.

이 문서는 검색 결과가 아니다. 실제 자료원 목록, 분야 검색표, 사용자 조사 지침, 수집 상태와 완료 보고는 `research/pvsnp/literature-baseline/`에 둔다.

연결 문서의 소유권은 다음과 같다.

1. `docs/do-math/통합-설계.md`는 보편 연구 방법, 최초 수입, 자료·근거, 파일 참조와 크리덴셜 경계를 소유한다.
2. `research/pvsnp/연구-주제-선호.md`는 P vs NP의 목표·범위·연구 방향을 소유한다.
3. 이 문서는 초기 문헌조사의 범위, 협업, 검색, 수집, 누락 검사와 완료를 소유한다.

문헌조사는 `do-math` 연구 인스턴스 밖에서 수행한다. 동결한 조사 패키지는 프로젝트 입력 원문이며, `do-math`가 최초 수입 절차에서 의미 단위별 실제 내부 소유자를 판정한다. 조사 패키지가 초기 F 객체·작업·관계나 Lean 정본을 직접 만들지는 않는다.

종결한 `research/pvsnp/literature/`의 자료는 과거 참고 자료다. 그 목록이나 완료 판정은 새 조사에 전이하지 않는다. 같은 자료를 다시 채택하면 이 명세에 따라 판본과 출처를 다시 확인한다.

## 1. 목적과 산출물

### 1.1 목적

초기 문헌조사는 후속 연구가 현대 수학과 이론 컴퓨터과학의 핵심 지식과 P vs NP의 선행연구에 정확히 재진입할 수 있는 문헌 집합을 만든다. 문헌 집합은 다음 판단을 지원한다.

- 어느 분야의 어떤 자료를 다시 읽어야 하는가.
- 정확히 어느 판본과 위치를 읽어야 하는가.
- 어떤 정의·주장·방법·반례·장벽·논쟁·형식화·코드·데이터가 있는가.
- 문헌끼리 어떤 관계가 있으며 그 관계가 원문 주장인지 조사자의 추론인지 구별되는가.
- 어느 자료가 확보됐고, 어느 자료가 아직 확보 가능하며, 어느 자료가 허용 경로를 소진한 뒤에도 접근 불가인가.

문헌 집합은 원문을 대신하지 않고 문헌의 수학적 진위를 자동 확정하지 않는다. 후속 연구가 한 주장을 사용하려면 결박된 원문 판본을 다시 읽고 `do-math`의 현행 검증을 적용한다.

### 1.2 완료 산출물

조사는 다음 산출물을 만든다.

```text
research/pvsnp/literature-baseline/
├─ README.md
├─ STATUS.md
├─ 자료원-목록.md
├─ 분야-검색표.md
├─ batches/
│  └─ <batch_id>.md
├─ intake/                         # Git 비추적 사용자 투입함
├─ originals/                      # Git 비추적 원문·코드·데이터
├─ catalog/                        # 선별한 작업·판본·관계 기록
├─ manifests/
│  └─ artifacts.json
└─ reports/
   ├─ coverage.md
   └─ completion.md
```

`STATUS.md`는 현재 열린 조사 묶음, 사용자가 할 일과 다음 AI 행동을 알려 주는 재개 지점이다. 사용자는 이 파일과 현재 조사 묶음만 읽으면 된다.

`intake/`에는 사용자가 받은 원시 검색 export와 접근 실패 증거를 그대로 둔다. `originals/`에는 적법하게 로컬 보존할 수 있는 원문·코드·데이터를 둔다. 두 경로의 실물은 Git에 넣지 않는다. AI는 파일명 정리, 정규화, 중복 제거와 해시 계산을 맡는다.

`catalog/`와 보고서는 사람이 판단할 내용을 담고, `manifests/artifacts.json`은 로컬 실물의 상대 경로·SHA-256·크기·형식·출처·조회 시각·판본·권리 상태를 결박한다. 소비자가 없는 필드는 만들지 않는다.

### 1.3 제외 범위

초기 문헌조사는 다음을 수행하지 않는다.

- P vs NP의 증명·반증과 실제 수학 연구
- 문헌의 모든 수학적 주장을 독립적으로 재증명하는 일
- Lean 정본 편입이나 수학 해설–Lean 동일성 인증
- `do-math` 내부 F 객체·작업·관계를 직접 생성하는 일
- 저자·출판사·도서관에 연락하거나 원문복사·상호대차·유료 구매를 신청하는 일

## 2. 조사 범위

### 2.1 분야 우주

조사 우주는 현대 수학과 이론 컴퓨터과학 전 분야다. 수학은 MSC2020의 현행 두 자리 분야 전건을 씨앗으로 사용한다. 이론 컴퓨터과학은 ACM Computing Classification System과 arXiv 컴퓨터과학 범주를 독립 씨앗으로 사용한다. 한 자료와 한 분야는 여러 분류에 속할 수 있다.

분야 해상도는 고정하지 않는다.

- P vs NP 직접 영역은 문제군·방법군·장벽·표현 체계까지 세분한다.
- 인접 영역은 실제 내용에 필요한 하위 분야까지 세분한다.
- 먼 영역은 공인 대분류 수준에서 핵심 지식과 계산·구조 연결을 조사한다.

먼 분야라는 이유로 제외하지 않는다. 반대로 먼 분야 전체를 세부 분류까지 재귀적으로 확장하지 않는다. 새 세부 분야가 문헌 집합의 이해·검증·누락 판정에 실제로 필요할 때만 해상도를 높인다.

### 2.2 깊이

조사는 분야마다 다음 지식 층위를 살핀다.

- 기초 정의·표기·입문 전거
- 표준 종합과 공통 관점
- 핵심 원 성과와 논증
- 후속 개선·대안·비판·반례·경계
- 조사 시점의 연구 전선과 열린 문제
- 관련 형식 증명·코드·데이터

이 층위는 검색과 누락 검사의 관점이다. 모든 `분야 × 깊이` 조합에 별도 파일·투표·DB 검색을 강제하는 작업 격자가 아니다. 하나의 자료가 여러 층위와 분야를 담당할 수 있다.

### 2.3 기준 핵심층

**기준 핵심층**은 한 분야를 정확히 구별하고 후속 연구가 재진입하는 데 필요한 학계의 핵심 문헌과 지식이다. 표준 교재·종합 자료·핵심 원 성과뿐 아니라 주요 대안·비판·반례·경계·외부 의존 지식을 포함할 수 있다.

AI는 미리 만든 점수표, 저널 등급이나 인용 수 문턱으로 핵심성을 결정하지 않는다. 자료원과 문헌의 실제 내용, 분야에서 맡는 역할, 후속 채택·비판, 다른 자료와의 중복·보완 관계를 직접 조사해 판단한다. 인용 수와 출판 지위는 판단의 근거가 될 수 있지만 결론을 대신하지 않는다.

출처 유형은 닫지 않는다. 논문·학회록·책·학위논문·프리프린트·형식 증명·코드·데이터와 공식 웹 자료를 실제 역할에 따라 포함할 수 있다.

## 3. 자료원 합리화

### 3.1 역할

자료원은 실제 기능에 따라 다음 역할 중 하나 이상을 맡는다.

- **발견 자료원**: 분야별 후보 문헌과 핵심 전거를 찾는다.
- **누락 검사 자료원**: 독립 색인·인용망·검색 방식으로 빠진 후보를 찾는다.
- **원문 자료원**: 정확한 출판본·프리프린트·책·코드·데이터를 제공한다.
- **판본 자료원**: DOI, 정정, 철회, 대체, 릴리스와 커밋을 확인한다.

KUDOS의 현행 목록과 공개 자료원 우주는 조사 시작 시 한 번 실사한다. AI는 실제 수록 범위와 기능을 확인해 분야별 자료원을 배정한다. 모든 자료원을 모든 분야에 반복 적용하지 않는다. 한 자료원이 특정 분야에 실질적인 발견 또는 누락 검사 능력을 제공하지 않으면 그 분야 검색에서 제외한다.

출판사 플랫폼은 대체로 선정된 원문을 확보하는 데 사용한다. 같은 후보를 광역 색인에서 찾은 뒤 모든 출판사 플랫폼에서 같은 검색을 반복하지 않는다. 독립 색인이나 전문 저장소가 실제로 다른 문헌 집합을 제공할 때만 별도 발견 자료원으로 사용한다.

### 3.2 KUDOS와 인증 자료원

KUDOS 목록 확인에는 공개 공식 목록을 우선 사용한다. 공개 목록이 현재 항목과 제공 범위를 충분히 보여 주면 로그인하지 않는다. 인증이 필요한 검색은 사용자가 직접 수행하거나, 사용자가 특정 조사 묶음에 명시적으로 승인한 로컬 브라우저 프로그램이 수행한다.

AI는 실제 실사를 바탕으로 인증 자료원별 조사 지침을 작성한다. 지침에는 검색 목적, 검색식, 필터, 기간, 결과 분할법, export 형식, 저장 위치와 완료 증거를 적는다. 브라우저 프로그램은 승인된 검색표, 순차 실행, 자료원별 건수 상한, 기존 유효 산출물 건너뛰기, 결과 검증 뒤 원자 저장과 중단 뒤 재개를 구현한다. 원문 다운로드는 별도 사용자 지시 없이는 자동화하지 않는다.

자료원 UI가 제공하는 서지정보 export 상한은 허용된 기능으로 사용한다. 결과가 한 번의 export 상한을 넘으면 연도·문서 유형·분야 등 서로 겹치지 않는 조건으로 나눈다. 분할한 결과 수의 합과 원 검색 결과 수가 맞는지 확인한다. UI가 허용하더라도 현재 이용약관이나 도서관 이용수칙이 금지하는 수집은 하지 않는다.

### 3.3 공개 자료원

AI는 공개 웹, 공인 분류, 공개 서지·인용 색인, 프리프린트·학회·저널 아카이브, 형식 증명·코드·데이터 저장소를 직접 조사한다. 검색엔진 요약은 후보 발견에만 쓰고, 판정은 운영기관의 공식 페이지·원문·공식 API와 저장소를 다시 확인한다.

공개 자료원과 인증 자료원은 역할이 겹칠 수 있다. 중복 검색은 서로 다른 검색 범위나 누락 검출 능력이 있을 때만 유지한다.

## 4. 협업과 조사 묶음

### 4.1 역할 분담

AI는 다음 일을 맡는다.

- KUDOS와 공개 자료원 실사·선별
- 분야 지도와 검색어 설계
- 공개 웹 조사
- 자료원별 조사 묶음과 승인된 브라우저 프로그램 작성·실행
- 수집물의 형식 확인·정규화·중복 제거·판본 연결
- 문헌 선별·판독·인용망 전개·누락 검사
- 다음 보충 묶음 결정과 최종 완료 판정

사용자는 다음 일만 맡는다.

- 자동화할 인증 검색의 범위와 위험을 승인하거나, 프로그램이 처리하지 못한 인증 자료원 검색
- 프로그램이 처리하지 못한 DB의 원시 export 저장
- AI가 후속 선별한 원문·코드·데이터의 허용 범위 내 확보
- 접근 실패나 부분 완료를 보여 주는 최소 증거 저장

사용자는 문헌을 요약하거나 분류하거나 파일명을 정규화하거나 manifest를 작성하지 않는다.

### 4.2 한 묶음의 순환

1. AI는 하나의 조사 묶음을 `batches/<batch_id>.md`에 작성하고 `STATUS.md`에서 그 묶음을 현재 행동으로 지정한다.
2. 승인된 브라우저 프로그램 또는 사용자가 지침대로 검색하고 원시 결과를 `intake/<batch_id>/<source_id>/`에 둔다.
3. 사용자가 실행한 경우 완료, 부분 완료 또는 접근 실패를 알린다. 프로그램 실행이면 프로그램이 항목별 상태와 재개 좌표를 남긴다.
4. AI는 실제 파일과 검색 증거를 직접 열어 결과 수, 검색 범위, export 완전성, 파일 손상과 누락을 검사한다.
5. 의미를 바꾸지 않는 형식 정리와 중복 제거는 AI가 처리한다. 검색 자체가 빠졌거나 결과 일부가 없는 경우에만 보충 묶음을 만든다.
6. AI는 새 자료가 드러낸 참고문헌·인용·반론·판본·분야를 조사하고, 새 핵심 후보가 있으면 다음 묶음을 연다.
7. 완료 조건이 충족되면 새 묶음을 열지 않고 문헌 집합을 동결한다.

동시에 여러 사용자 묶음을 열지 않는다. 앞 묶음의 실제 결과가 다음 검색을 바꾸므로 한 묶음을 검사한 뒤 다음 묶음을 정한다.

### 4.3 상태와 재개

대화는 상태의 정본이 아니다. `STATUS.md`에는 다음만 유지한다.

- 현재 단계와 열린 묶음
- 사용자에게 남은 행동
- AI가 마지막으로 확인한 실물과 결과
- 완료된 묶음
- 다음 판단을 막는 실제 결손

대화가 끊기면 AI와 사용자는 `STATUS.md`와 현재 묶음에서 재개한다. 과거 대화 요약만으로 완료를 판정하지 않는다.

## 5. 검색과 수집

### 5.1 검색 순서

1. 공인 분류에서 전 분야 씨앗과 분야별 기준 전거 유형을 정한다.
2. 공개 주자료원과 선별한 인증 발견 자료원에서 후보를 찾는다.
3. 표준 종합 자료에서 핵심 정의·원 성과·대안·비판·반례·열린 문제를 전개한다.
4. 핵심 작업의 후방 참고문헌과 전방 인용을 추적한다.
5. 정확한 지적 작업과 접근한 판본을 구별한다.
6. 정정·철회·대체·프리프린트·출판본·코드 릴리스 관계를 확인한다.
7. 형식 증명·코드·데이터와 다른 언어의 핵심 자료를 찾는다.
8. 다른 색인과 다른 검색어를 사용한 적대 누락 검사를 수행한다.
9. 새 후보가 나오면 필요한 앞 단계로 돌아간다.

이 순서는 한 번만 도는 체크리스트가 아니다. 새 핵심 후보가 더는 나오지 않을 때까지 필요한 부분만 반복한다.

### 5.2 검색 증거

각 검색은 다음을 다시 실행할 수 있을 정도로 기록한다.

- 자료원과 실제 검색 화면 또는 API
- 검색어, 필드, 필터, 기간과 정렬
- 실행 시각과 결과 수
- export 파일 또는 결과 없음·부분 완료·실패 증거
- 분할 검색이면 각 분할과 합계

`결과 없음`, `검색하지 않음`, `검색 실패`, `일부만 export`, `접근 실패`를 서로 바꾸어 쓰지 않는다. 결과가 0건이면 알려진 양성 표본으로 같은 검색 기능이 작동하는지 확인한다.

### 5.3 원문 확보와 접근 상태

첫 조사 묶음은 서지정보와 검색 증거를 수집하고 원문을 대량 다운로드하지 않는다. AI가 후보를 선별한 뒤 필요한 원문만 다음 묶음에서 확보한다.

접근 상태는 다음 의미를 구별한다.

- `retrievable`: 허용 경로에서 의도한 판본을 실제로 확보할 수 있다.
- `retrievable_missing`: 확보할 수 있으나 아직 로컬 자료가 없다.
- `unavailable_after_exhaustion`: 허용한 공개·기관 경로를 모두 확인했으나 확보하지 못했다.

HTTP 성공, 서지 페이지, 초록과 원문 확보는 서로 다른 상태다. 원문이 실제로 열리고 의도한 판본과 일치할 때만 원문 확보로 판정한다.

`retrievable_missing`인 핵심 자료를 남긴 채 조사를 닫지 않는다. `unavailable_after_exhaustion`은 작업 식별자, 시도한 경로, 시각, 남은 불확실성을 기록하면 완료와 양립할 수 있다.

## 6. 문헌 기록

### 6.1 작업과 판본

지적 작업은 논문·책·데이터셋·소프트웨어 프로젝트 같은 논리적 연구 산출이다. 판본은 실제로 접근한 출판본·프리프린트 판본·개정본·정오표·철회문·데이터 릴리스·코드 커밋이다.

한 작업을 여러 분야에서 사용해도 작업 기록을 복제하지 않는다. DOI·ISBN·arXiv ID·MR/Zbl 번호·DBLP 키·저장소 URL 같은 식별자를 실제 의미대로 함께 기록한다. 한 식별자만으로 작업 동일성을 추정하지 않는다.

프리프린트와 출판본, 학회판과 저널판, 번역과 원문, 태그와 커밋은 자동 병합하지 않는다. 정정·철회·대체 뒤에도 과거 판본과 판독 이력을 보존한다.

### 6.2 정보 상태

문헌 기록은 다음을 구별한다.

- 원문이 실제로 한 주장과 질문
- 조사자가 원문 또는 검색 결과에서 직접 관찰한 사실
- 여러 자료를 대조해 만든 논증과 추론
- 아직 검증하지 않은 가설과 구조적 유사성
- 검색·접근·판독 실패와 남은 불확실성

이는 `docs/do-math/통합-설계.md`의 `source@evidence`, `observation@evidence`, `argument@evidence`, `hypothesis@evidence`, `failure_record@evidence`로 수입할 수 있게 구별하는 것이며, 조사 단계에서 내부 자료·근거 ID를 미리 만들라는 뜻은 아니다.

문헌 유래 관계는 정확한 원문 판본과 좌표를 가진다. AI 유래 관계는 생성 주체, 대응 구조, 근거, 한계와 후속 검증 요구를 가진 미검증 후보로 남긴다. 같은 이름이나 단순한 비유만으로 관계를 만들지 않는다.

### 6.3 판독 지도

선별한 핵심 문헌의 판독 지도에는 다음 중 실제 재사용에 필요한 내용을 기록한다.

- 판독한 판본과 범위, 읽지 않은 범위
- 정의·가정·주장·논증의 주요 단계와 외부 의존 결과
- 적용 범위, 관례적 생략, 반례·장벽·논쟁과 불확실성
- 다른 문헌과의 명시 관계와 AI가 제안한 미검증 관계
- 페이지·절·정리·파일·선언·커밋 같은 재진입 좌표

고정 요약 길이와 전문 완독 여부는 판독 완료 기준이 아니다. 후속 판단과 재진입에 필요한 정보를 정확히 제공하는지가 기준이다.

## 7. 누락 검사와 완료

### 7.1 분야 포괄

`reports/coverage.md`는 MSC2020 두 자리 분야 전건과 이론 컴퓨터과학 분류 씨앗 전건을 포함한다. 직접·인접 영역은 실제 조사에 필요한 세부 분야를 추가하고, 먼 분야는 공인 대분류 수준에서 기준 핵심층과 계산·모형·자료 연결을 기록한다.

각 분야는 다음 중 하나의 현재 상태를 가진다.

- `open`: 검색이나 판정이 남았다.
- `covered`: 필요한 기준 핵심층과 검색 증거가 있다.
- `not_applicable`: 특정 깊이나 자료 유형이 그 분야에 개념적으로 적용되지 않는다.
- `no_material_after_search`: 적용되는 대상을 찾았으나 허용 검색을 마친 뒤 자료가 실제로 확인되지 않았다.

`not_applicable`과 `no_material_after_search`는 근거가 있어야 한다. 검색 실패나 결과 0건만으로 두 상태를 만들지 않는다.

### 7.2 포화 검사

AI는 다음 경로를 서로 대체하지 않고 누락 검사에 사용한다.

- 공인 분류어·동의어·다른 언어 표현
- 표준 종합 자료의 참고문헌
- 핵심 작업의 전후방 인용망
- 독립 서지 색인과 전문 저장소
- 반론·정정·철회·대체 판본 검색
- 형식 증명·코드·데이터 검색

한 완전한 누락 검사에서 새로 포함할 자료원, 핵심 작업, 필수 판본 또는 관계 폐쇄 의무가 나오면 조사로 돌아간다. 새 후보가 나오지 않고 모든 보류 항목의 처분 근거가 있으면 포화 검사를 통과한다. 고정 검색 횟수나 문헌 편수는 포화를 대신하지 않는다.

### 7.3 완료 조건

다음 조건을 모두 만족할 때 AI가 조사를 완료로 판정한다.

1. 현대 수학과 이론 컴퓨터과학의 전 분야가 정한 해상도로 `covered`, `not_applicable` 또는 `no_material_after_search`에 있다.
2. 선정 자료원별 지침에 따른 검색이 완료됐고, export 상한·부분 결과·결과 없음·실패가 구별돼 있다.
3. 선별한 모든 핵심 작업은 정확한 판본과 재진입 좌표를 가진다.
4. 핵심 종합 자료의 참고문헌과 핵심 작업의 전후방 인용망을 처리했다.
5. `retrievable_missing`인 핵심 자료가 없다.
6. 정정·철회·대체와 남은 접근·판독 불확실성을 기록했다.
7. 독립 누락 검사가 포화됐다.
8. 로컬 실물 manifest와 추적 산출물의 참조·해시가 유효하다.
9. `do-math` 최초 수입에 전달할 입력 패키지와 완료 보고가 서로 일치한다.

`reports/completion.md`는 각 조건의 근거와 실패 의미를 기록한다. 완료량, 검색 횟수, 문헌 수와 파일 수는 완료를 대신하지 않는다.

완료 뒤 조사 집합을 `frozen`으로 표시하고 추적 산출물의 정확한 Git OID와 로컬 실물 manifest를 고정한다. 같은 조사 ID의 집합은 다시 열지 않는다.

## 8. 저장·권리·민감 정보

원시 export와 원문을 수정하지 않는다. 추출 텍스트·렌더 이미지·정규화 메타데이터는 원자료와 다른 파생물로 기록한다.

자료원의 이용약관과 저작권을 확인하고, 자동화를 실행할지에 관한 사용자의 명시적 결정과 함께 적용한다. 브라우저 자동화는 승인된 검색표와 서지 export 상한 안에서 수동 절차와 같은 화면 동작만 수행한다. 특정 저널·책·전자자원의 전체 원문과 자동화된 대량 원문 다운로드는 수행하지 않는다.

크리덴셜 값은 AI 프롬프트·대화·로그·검색 증거·산출물·manifest·Git에 넣지 않는다. `docs/do-math/통합-설계.md`의 비밀 경계를 적용한다. 승인된 로컬 브라우저 프로그램만 실행 직전에 크리덴셜 파일을 읽어 로그인 입력란에 넣고, 브라우저 컨텍스트 종료와 함께 세션 상태를 폐기한다.

추적 파일 참조는 POSIX 상대 경로와 실제 파일 바이트의 SHA-256을 사용한다. 알 수 없는 필드, 깨진 참조와 해시 불일치를 조용히 무시하지 않는다.

## 9. `do-math` 입력 경계

동결 패키지는 분야·깊이와 기준 핵심층, 작업·판본·판독, 검색·접근·권리, 문헌 유래 주장과 관계, AI 유래 추론·가설, 실패·불확실성과 artifact manifest를 제공한다.

`do-math` 최초 수입자는 `docs/do-math/통합-설계.md` 5.2절에 따라 입력 원문을 보존하고 의미 단위마다 내부 소유자를 하나 배정한다. 조사 패키지의 선정·완료 표지는 수학적 진리, Lean 타당성, 연구 가치나 작업 착수 가능성을 뜻하지 않는다.

Git에 넣을 수 없는 원시 export와 원문은 입력 패키지의 추적 manifest로 식별한다. `do-math`가 실제 파일을 내부 활성 참조로 사용하려면 권리와 파일 참조 계약을 충족하는 별도 수입 처리가 필요하다. 외부 URL만을 내부 파일 참조로 가장하지 않는다.

## 10. 수용 시험

이 명세의 구현과 실제 조사는 다음 시험을 통과해야 한다.

1. KUDOS와 공개 자료원은 한 번 실사하고, 각 분야에는 실제 기능이 있는 자료원만 배정한다.
2. 모든 KUDOS DB를 모든 분야에 반복 검색하지 않아도 전 분야 포괄과 독립 누락 검사를 입증할 수 있다.
3. 인증 검색을 브라우저 프로그램으로 수행할 수 있으면 AI가 실행하고, 수동 개입이 필요한 부분에서만 사용자가 원시 export·선별 후 원문·접근 실패를 제공한다. 분류·정규화·중복 제거·manifest 작성은 AI가 맡는다.
4. 검색 결과 없음, 미실행, 실패와 부분 완료를 구별한다.
5. 한 자료를 여러 분야에서 참조해도 작업과 판본 기록을 중복 생성하지 않는다.
6. 접근 가능한 핵심 원문을 놓치면 완료를 차단하고, 허용 경로를 소진한 접근 불가는 근거와 함께 완료를 허용한다.
7. 프리프린트·학회판·저널판·정정·철회 이력을 자동 병합하거나 삭제하지 않는다.
8. 원문 주장, 조사 관찰, AI 추론·가설과 실패를 구별한다.
9. 원문·원시 export가 Git에 추가되거나 크리덴셜 값이 산출물에 나타나면 검사에 실패한다.
10. 모든 분야의 포괄과 누락 검사 포화 없이는 조사 집합을 동결하지 않는다.
11. 조사 패키지가 `do-math` 내부 F·작업·관계를 직접 만들지 않는다.
12. 대화가 없어도 `STATUS.md`, 현재 조사 묶음과 실제 수집물에서 협업을 재개할 수 있다.

더 간단한 구조가 같은 목적과 하류 전제를 충족하면 더 간단한 구조를 선택한다. 형식이나 절차는 실제 소비자가 기대는 전제를 지킬 때만 추가한다.
