# Version 선별 절차 최종 결정

결정일: 2026-09-05. 상태: **개정 절차 확정, 도구 구현·기존 기록 전환 전.**

이 문서는 version 선별의 전체 운영 절차와 기존 70개 결과를 이어 쓰는 방법을 확정한다. 사용자 요청의 범위 안에서 총괄이 내린 설계 결정이며, 구현 완료 보고가 아니다. 개정 구현의 기준은 이 문서다. 기존 `catalog/version-review-contract.md`와 판정·manifest는 v1 실행의 해석과 재현을 위해 보존한다. v2 구현과 전환 검사를 통과하기 전에는 묶음 002를 시작하지 않는다.

조사 목적·분야 우주·최종 문헌조사 종료는 [문헌 체계 명세](../../문헌-체계-명세.md)가 소유한다. 이번 결정은 그 범위를 좁히거나 P vs NP의 증명·반증, 새 분야 검색, 단행본 구성요소 전개와 참고문헌 추출을 시작하지 않는다.

## 1. 목적에서 정한 구조

이 단계의 결과는 후속 판독자가 **어느 version을 어떤 역할 때문에, 어느 원천에서 다시 읽을지** 결정하게 해야 한다. 소비자가 필요한 보장은 다음 네 가지다.

| 소비자 | 필요한 보장 | 그것을 만드는 절차 |
|---|---|---|
| 선별자·독립 검증자 | 정확한 version의 실제 자료를 다시 볼 수 있다. | 자료 회수·표시와 자동 근거 기록 |
| 핵심층 확정자 | 확인한 기여와 재진입 역할의 판단을 구분할 수 있다. | 한 version의 선별 판정 |
| 총괄 | 독립 판단의 차이와 합의된 오류를 찾고 해소할 수 있다. | 독립 검증·위험 표본 감사·resolution |
| 재개 실행 | 유효한 결과를 보존하고 남은 일만 이어 갈 수 있다. | 행별 검사·집계·재개 좌표 |

상설 운영은 **자료 회수·판독 → 선별 판정 → 독립 검증·총괄 감사 → 집계·재개**의 네 부분으로 둔다. 배정은 이 흐름의 입력을 정하는 일이고, 차이 해소는 검증의 일부다. 각 부분마다 별도 위원회·보고서·승인 절차를 만들지 않는다.

유지할 것은 `version_id`, `work_id`, source/prior 추적, 한 version의 생산 소유자 하나, 다섯 처분, 독립 판정의 분리, 비교한 행 SHA에 결박한 resolution이다. 같은 work의 다른 version에 처분을 복사하지 않는다. work 집계는 저작 중복과 미완료 판본을 찾는 데 사용한다.

완료 표시는 **version 선별 완료**다. 자료 회수, 선별, 정밀 판독, 논증 검증과 최종 핵심층 확정은 서로 다른 성과다. core_candidate가 곧 최종 핵심 문헌이 되거나 선별 완료가 문헌의 수학적 타당성을 보증하지 않는다.

## 2. 배정: 비교하기 쉬운 묶음, 단일 생산 소유자

기존 source의 MSC·분야 분류·문서 유형을 우선 활용해 가까운 분야와 비교 가능한 자료를 묶는다. 분류가 부족하면 원 source의 keyword·검색 provenance를 읽어 잠정 표지를 붙인다. 제목도 배정의 단서로는 쓸 수 있지만 내용 처분에는 충분하지 않다. 분야 배정을 위해 초록을 실제로 읽었다면 그 판독 근거를 보존해 후속 선별에서 재사용한다.

분야 표지는 복수일 수 있고 미분류도 허용한다. 배정용 역할은 서지에서 확인되는 교재·survey·원 논문 등 잠정 비교 표지이며, 핵심성의 선판정이 아니다. 잠정 분류와 배정 근거는 배정 기록에 둔다. 이를 queue의 내용 해시에 섞어 재분류만으로 기존 판정을 stale하게 만들지 않는다.

총괄은 열린 분야 묶음을 순환해 배정한다. 다분야·미분류 후보도 같은 순환에 포함하며 어려운 후보를 계속 뒤로 미루지 않는다. 한 묶음 안의 동률을 정할 때 ID 정렬을 쓴다. 미완료 소유 범위가 있으면 그 범위의 남은 ID부터 이어 간다. 일부 미완료가 있어도 다른 작업자에게 겹치지 않는 새 범위를 줄 수 있다.

생산자 두 기와 독립 검증자 한 기, 총괄을 포함해 동시 최대 네 기를 유지한다. 배정은 정확한 ID·현재 version 행 SHA·작업자·출력 파일을 고정한다. 모델에는 현재 배정과 필요한 기준·비교 자료의 위치를 주며, 전체 queue·과거 판정·실물을 모두 프롬프트에 넣지 않는다. 더 큰 묶음 크기는 자료의 길이와 검증 처리량에 따라 조절하되, 묶음 크기를 조사 종료 조건으로 사용하지 않는다.

## 3. 자료 회수와 판독: 공용 도구 하나

자료마다 생산자·검증자가 별도의 수집 코드를 만드는 일을 없앤다. 하나의 공용 회수·보기 기능이 기존 로컬 export, 공개 HTML·API 응답, 필요한 PDF·페이지 이미지를 취급한다. 로컬 export는 기존 `build_b001_catalog.py`의 파서와 `load_review_material`을 확장해 사용한다. 해시·원자 저장·원자료와 인덱스의 분리는 기존 생성기와 Crossref 수집기의 실제 패턴을 재사용한다. Crossref 전용 수집기가 일반 HTML/PDF 회수까지 지원한다고 가정하지 않는다.

공용 도구는 다음 사실을 자동으로 남긴다. 작업자는 회수 사실을 증명하는 기록을 손으로 작성하지 않는다.

- 요청한 version과 그 입력 SHA, 요청 위치·최종 위치·회수 시각
- 응답 상태, 감지한 파일 형식, 바이트 수와 실제 보존한 자료의 SHA
- 로컬 원자료의 기존 경로·SHA·record ID·rank 또는 웹에서 확인할 수 있는 서지 식별 정보
- 표시하거나 추출한 자료의 경로·SHA와 쪽·절·HTML 항목·JSON 위치 등 원천으로 돌아갈 좌표
- 회수 실패, JS/접근 차단 화면, 비어 있는 응답, 텍스트 추출 실패, 이미지 판독이 필요한 스캔의 구분

HTTP 200·URL의 `.pdf` 접미사·페이지 수만으로 본문을 확보했다고 판정하지 않는다. 스캔의 텍스트 추출값 0은 빈 문서와 다르다. 스캔은 실제 페이지 이미지를 표시한 근거에 연결한다. 알려진 오류 화면은 걸러 내되, 기계가 문서의 내용 종류나 의미를 완벽히 알아본다고 주장하지 않는다.

새 회수 실물은 기존 비추적 `originals/` 아래에 보존하고, 자동 회수 근거 기록은 `catalog/version-review-evidence/`에 로컬 보존하고 Git에서 제외한다(2026-09-06 사용자 결정). 이 기록은 실물의 경로와 해시를 가리킨다. 판정·감사·manifest는 계속 Git 추적 대상으로 유지한다. 이미 있는 `intake/` 파일은 복제하거나 고치지 않고 기존 실물을 참조한다. 같은 실물은 여러 작업자가 공유할 수 있다. 자동 만료·자동 폐기는 두지 않는다. 활성 선별, 후속 정밀 판독, 동결 패키지나 후속 수입의 재진입 참조가 있는 동안 실물을 유지한다. 폐기는 사용자가 정확한 범위를 명시적으로 승인한 경우에만 수행하고, 근거 부재가 되는 참조와 회복 가능성을 기록한다.

Git만으로는 자동 회수 근거 기록과 비추적 실물을 복구할 수 없으므로 별도 백업에 둘 다 포함한다. 작업공간을 이관할 때도 참조 중인 자동 회수 근거 기록과 비추적 실물을 함께 전달하고 목적지의 경로·SHA를 확인한다. Git 파일만 전달한 것을 실물까지 이관한 것으로 표시하지 않는다. 실제 파일이 사라졌거나 목적지에서 읽을 수 없으면 해당 version의 근거 보완 의무를 열고, 역사적 선별 결과는 보존하되 현재 재현 가능하다고 표시하지 않는다. 회복·대체 원천 확인은 그 의존 범위만 대상으로 한다.

보존 범위는 허용된 원문 또는 실제 사용한 발췌·추출물·렌더 중 충분한 최소 실물이다. 추출·정제한 자료를 원시 응답이라고 부르지 않는다. 원응답 전체를 보존하지 않았으면 그 사실을 명시한다. 인증 헤더·Cookie 값·크리덴셜은 기록하지 않는다. 이 도구는 필요한 개별 자료를 처리하며 PDF 전수 다운로드를 시작하지 않는다. 허용된 실물 기록을 만들 수 없는 경우에는 자료·도구·권한 중 무엇이 부족한지 남기고 그 의존 작업만 보완 대기로 둔다.

생산자와 검증자는 같은 회수 실물을 각자 읽을 수 있다. 검증자는 실물의 제목·식별자·판본·선택 위치도 독립적으로 대조한다. 의심이 있으면 다른 허용 원천을 추가 확인한다. 같은 바이트를 공유한다는 사실은 판정의 독립성을 없애지 않지만, 같은 추출 오류를 함께 믿을 위험은 감사해야 한다.

회수 기록은 **무엇을 확보·추출·표시했는지**를 뒷받침한다. 독자에게 반환한 범위와 독자가 읽었다고 선언한 범위는 구분한다. 이해·판본 동일성·내용 해석의 정확성은 기계 로그만으로 증명하지 않는다.

## 4. 판독 범위와 판정 행

기존 판정 행의 ID·version SHA·reviewer·disposition·basis·role_in_field·evidence·limitations를 유지한다. 개정 형식에서는 정책의 의미 판본, 자동 회수 기록 참조, 읽은 위치, 대상 version과 회수 자료의 관계를 추가로 결박한다. 새 필드는 아래 소비자 판단을 위해서만 둔다. 정확한 JSON 스키마와 실제 CLI는 구현·실패 테스트와 함께 버전 올려 공개하며, 현행 v1 검사기에 새 필드를 넣어 실행하지 않는다.

### 실제로 읽은 자료의 구분

다음은 **개정 read_scope의 확정된 구분**이다. 현행 코드가 이미 받는 목록이 아니다.

| 값 | 의미 |
|---|---|
| `bibliographic` | 서지·식별 정보 |
| `abstract` | 해당 자료의 초록 |
| `publisher_description` | 출판사·공개 책 페이지의 내용 소개 |
| `table_of_contents` | 목차 |
| `front_matter` | 저자·편집자의 서문 등 내용이 있는 전면부. 제목면·판권면만 읽었으면 bibliographic |
| `selected_body` | 실제 본문의 일부. 서론·주요 결과·특정 절 등을 위치로 특정 |
| `full_text` | 해당 판본의 전문을 실제로 읽음. 수학적 타당성 검증과 별개 |
| `access_attempt` | 접근 시도. 내용을 읽었다는 증거로 세지 않음 |

목차와 서문을 함께 읽었으면 같은 실물을 참조하는 두 범위로 적는다. 전문을 확보했어도 목차만 읽었으면 table_of_contents다. 여러 종류를 함께 담던 selected_full_text는 신규 판정에서 사용하지 않는다.

모든 내용 근거는 회수 실물과 실제 읽은 위치를 연결한다. HTML에서는 DOI·ISBN이 있는 자료 항목과 읽은 section/selector를, PDF에서는 판본과 쪽·절을, 로컬 export에서는 candidate/record ID와 rank·필드를 특정한다. 근거가 요청 version 자체의 내용·소개인지, 같은 work의 다른 판본인지, 후속 연구·비판처럼 독립된 다른 저작인지, 아직 귀속 미확정인지 구분한다. 다른 판본이나 다른 저작을 읽었으면 대상 판본의 본문 판독량에 넣지 않는다. 관련 판본의 내용을 판정 근거로 쓰려면 그 내용이 요청 version에도 적용된다는 별도의 출처·관계 근거가 있어야 한다. 독립된 후속 연구는 대상의 채택·비판·역할을 뒷받침하는 근거이며 대상 본문의 대체물이 아니다.

### 두 판단을 나누어 쓴다

`basis`는 실제 관찰한 기여를 쓴다. **어떤 대상·가정에서 어떤 정의·결과·방법·종합·반론을 제공하는가?** 서지나 source의 주장, 검토자가 만든 해석을 구별하고 근거 위치를 연결한다.

`role_in_field`는 후속 사용자의 재진입 이유를 쓴다. **어느 분야의 무엇을 이해하거나 시작하기 위해 이 version을 다시 읽어야 하는가?** 핵심 정의·기준 종합·대표적인 원 성과·방법이나 경계·필수 연결 중 구체적인 역할과 그 근거를 밝힌다. 역할은 닫힌 점수표가 아니며 여러 분야에 걸칠 수 있다.

“새 알고리즘/정리가 있다”, “관련 분야다”, “유명하다”만으로 두 번째 답을 대신하지 않는다. 반대로 새로운 자료에 후속 인용 실적이나 이미 확정된 표준성을 필수로 요구하지 않는다. core_candidate에 필요한 것은 정확한 원문 판독을 정당화하는 구체적인 역할의 가능성이다. 최종 핵심층 채택은 다음 단계의 판단이다.

다섯 처분은 그대로 유지한다.

- **core_candidate**: 위 두 답과 근거가 핵심 역할의 구체적인 가능성을 지지한다.
- **context_material**: 실제로 관련 배경·사례·응용을 제공하지만 그 핵심 역할은 맡지 않는다. 새 범용 이론이 없다는 사실을 곧 무관함으로 바꾸지 않는다.
- **search_noise**: 실제 내용이 조사 우주와 무관하다. MSC 97을 포함한 먼 분야나 다른 계산모형이라는 이유만으로 제외하지 않는다.
- **relationship_only**: 독립 내용 역할 없이 정오표·철회·구성요소·식별자 관계 설명을 위해 보존한다. 다른 판본이나 중복 source의 존재만으로 이 값을 주지 않는다.
- **defer**: 실제 자료·허용 경로를 확인했지만 처분을 가르는 내용이 부족하다. 부족한 정보와 다시 열 조건을 적는다. 미실행·시간 부족·도구 고장·검토자의 낯섦을 defer로 바꾸지 않는다.

초록·소개·목차만으로 대상과 역할이 충분히 드러나면 선별할 수 있다. 역할의 중요성, 계산모형·가정, 판본 귀속 또는 처분 경계가 불분명하면 필요한 서론·주요 결과·관련 전거를 추가로 읽는다. 해당 version의 역할을 확인하는 범위에서 기존 자료와 필요한 공개 원천을 대조하며, 이를 새 분야 전수 검색으로 확장하지 않는다. 추가 판독은 그 불확실성을 해소했을 때 끝낸다.

## 5. 독립 검증·총괄 감사와 종료 소유자

core_candidate·search_noise·defer는 독립 검증자가 전건 다시 읽는다. 생산 판정 뒤 필수 검증 대상을 골라 ID·자료·정책만 검증자에게 전달하고 처분·이유는 감춘다. 별도 표본이나 이미 배정한 독립 검증이 먼저 끝나는 순서도 허용한다. 생산자와 검증자는 각자의 최초 판정 봉인 전 상대 판정과 총괄의 새 결론을 보지 않는다. 공개 자료의 위치는 공유할 수 있다. 실행자는 실제 작업자·허용 입력·봉인 순서를 기록하되, reviewer 문자열이나 자기보고만으로 독립성이 기계적으로 증명됐다고 표시하지 않는다. 원시 대화 전체를 새 의무 산출물로 만들지 않는다.

context_material과 relationship_only는 기계 참조 검사와 총괄 표본 감사를 받는다. 첫 묶음처럼 전건 독립 검증한 결과는 재사용하되, 이를 모든 후속 묶음의 추가 의무로 확대하지 않는다.

총괄 감사에는 **생산 판정, 필요한 독립 검증, 근거·형식 검사와 차이 해소까지 끝난 현재 판정**을 넘긴다. 이는 아직 감사가 남아 pending인 행이며 complete를 선행 조건으로 삼지 않는다. 각 점검 시점에 해당 배정에서 이렇게 준비됐고 아직 유효한 감사에 포함되지 않은 행 전부를 `(version_id, 현재 판정 SHA, 정책 판본)`의 **감사 입력 집합**으로 먼저 고정한다. 표본을 고른 뒤 불편한 행을 그 집합에서 빼지 않는다. 과거 표본의 실물·회수 기록·판독 결과는 재사용할 수 있지만, 이전에 닫힌 집합의 표본으로 새 집합의 최소 표본 수를 대신하지 않는다.

고정한 감사 입력 집합에서 다음 존재하는 범주를 최소 한 건씩 포함한다.

1. 생산·독립 검증이 합의한 core_candidate
2. 생산·독립 검증이 합의한 search_noise
3. 현재 정책 아래에서 역할 감사가 아직 없었던 분야, 다분야 또는 미분류 후보
4. 내용 근거가 소개·목차·전면부에만 의존한 후보
5. context_material
6. relationship_only

한 표본이 여러 범주를 충족하면 함께 인정한다. 범주가 없으면 대상 0을 기록한다. 동률은 ID로 정하되 총괄은 근거의 취약점이 드러난 행을 추가하거나 우선할 수 있고 선택 이유를 남긴다. 이는 최소 위험 범주를 덮는 감사이며 오류율 추정용 통계 표본이 아니다. 판정 불일치 수, 표본 발견 수, 전체 오류율을 서로 바꾸어 쓰지 않는다.

표본의 범위·선정 근거·현재 최종 판정 SHA·사용한 근거·총괄 결론은 기계 판독 가능한 감사 기록에 묶는다. 기존 감사 보고서는 이 기록의 설명으로 사용하고, 같은 사실을 여러 수작업 보고서에 반복하지 않는다. 감사에서 결함이 나오면 같은 자료 추출기·판독 범위·잘못된 경계 적용 등 **공통 원인이 입증된 범위**로 재검토를 확대한다. 한 발견으로 전수 재시작하지 않는다.

처분뿐 아니라 기여·역할·판독 범위가 실질적으로 갈리면 총괄이 원자료에서 해소한다. 동의한 처분에도 오류가 있으면 같은 방식으로 연다. 총괄은 현재 비교한 판정 SHA를 결박한 resolution으로 끝낸다. 다수결이나 모든 검토자의 재동의를 종료 조건으로 두지 않는다. 자료가 부족하면 실제 결손을 근거로 defer로 끝낼 수 있다. 정책의 의미가 부족했으면 영향받은 기준과 테스트를 고친 뒤 해당 범위만 다시 판단한다. 확정된 사용자 목적·권한을 바꿔야 할 때만 사용자에게 상신한다.

감사 입력 집합에 대한 표본 대조와 필요한 결함 해소가 끝나면 그 집합의 감사 의무를 닫는다. 새 행은 다음 감사 입력 집합에 들어가며 그 안에서 존재 범주별 표본을 새로 고른다. 이미 닫힌 집합은 새 행을 감사하기 위해 다시 열지 않는다. 같은 행을 구 보고서에서 개정 감사 기록으로 이행하거나 보완 후 다시 열 때는 입력·정책에 여전히 적용되는 기존 판독 결과를 재사용할 수 있다. 감사 도중 행이 바뀌면 그 행의 새 SHA와 영향을 확인하고, 바뀌지 않은 유효 표본을 다시 읽지 않는다. 아직 끝나지 않은 다른 version 때문에 완료된 범위를 다시 읽거나 폐기하지 않는다.

## 6. 집계·재개: 행의 유효성과 전체 입력 무결성을 분리

전체 source/version/work 참조와 입력 manifest는 queue를 만들거나 새 입력을 수입할 때, 그리고 전수 선별을 닫을 때 검사한다. 검증되지 않았거나 무결성이 깨진 활성 입력에서 새 배정을 만들지 않는다. 입력 변경을 발견하면 유효한 queue를 다시 구성하고 바뀐 version을 식별한다. 전역 manifest를 무시하거나 불일치를 통과로 바꾸는 방식으로 간소화하지 않는다.

일상 제출·검증·재개는 **배정 ID와 version 행 SHA, 적용 정책의 의미 판본, 해당 근거 실물·회수 기록, 필요한 판정·resolution·감사 기록**을 검사한다. 무관한 다른 source, 보고서 문구, 배정용 표지와 코드의 단순 수정 때문에 유효한 내용 판정을 재생산하지 않는다. 코드 해시는 생성·검사 재현 이력에 남긴다. 정책 의미나 도구 결함이 판정의 전제를 바꾸면 총괄이 영향 범위와 재검사 종류를 기록한다.

한 명령이 모든 과거 실물을 반복 해시하는 것을 필수로 만들지 않는다. 같은 실행에서 동일 실물은 한 번 해시해 재사용하며, 읽기 전용 입력 세대와 파일 참조가 달라졌으면 다시 확인한다. 새 실행·입력 변경을 넘어 검증하지 않은 캐시를 신뢰하지 않는다.

검사기는 유효 행과 결함 행을 함께 반환한다. JSON 문법·필드·receipt·범위 오류는 해당 행만 격리하고, 같은 version의 상충·중복 제출은 그 version을 보완 대상으로 둔다. ID를 읽을 수 없으면 파일·줄·실물 해시를 남기고 배정 범위 안에서 영향을 가린다. 영향을 가릴 수 없는 동안에는 그 배정 범위의 완료만 보류하며 무관한 범위는 진행한다. 오류 행이나 이전 유효 행을 조용히 삭제하지 않는다.

검증자가 먼저 봉인한 행도 수락한다. 생산이 없는 동안 그 version만 생산 대기이고, 다른 유효한 version의 집계는 진행한다. 기계 형식 수리는 작성자나 도구가 처리하고, 의미 변경은 해당 판정 책임자 또는 총괄 resolution이 처리한다. 재개 입력은 원인·좌표·담당 역할과 남은 ID이며, 단순히 같은 작업 전체를 다시 실행하라는 요청이 아니다.

개정 집계 상태는 다음 세 가지로 단순화한다. 이는 v1 state 스키마를 바꾸는 신규 결정이다.

| 상태 | 의미 |
|---|---|
| `pending` | 생산·검증·근거·감사·수리 중 필요한 일이 남음 |
| `conflict` | 현재 유효한 판정 또는 총괄의 내용 이의가 해소되지 않음 |
| `complete` | 현재 정책의 요건을 통과한 version 선별 완료 |

대기 이유는 `production`, `verification`, `evidence`, `audit`, `repair` 중 필요한 항목의 집합으로 기록한다. 미해소 차이가 있으면 conflict를 우선 표시하고 남은 대기 이유도 보존한다. 여러 대기를 위해 별도 상태를 계속 추가하지 않는다. complete일 때만 현행 최종 처분을 노출한다. 이전 유효 결과와 역사적 완료량은 별도로 보존하며, 현재 보완 의무가 있으면 이를 숨기지 않는다.

묶음의 일부만 끝났을 때도 그 완성 범위의 검증·감사를 닫아 선별 완료로 집계할 수 있다. 묶음은 작업 포장 단위이지 결과 전체를 통과·폐기하는 단위가 아니다. 최종 전수 선별 종료에는 현재 version 전건의 처분 하나, 미완료·필수 검증·미해소 이의·미해결 검사 결함 0, work 집계·참조 폐쇄·manifest·재현성·전체 테스트가 필요하다. 이는 최종 문헌 집합 동결이나 정밀 판독 완료와 다르다.

## 7. 기존 70개와 새 절차의 전환

현재 실물은 구계약 아래 선별 완료 70개, core 40/context 19/noise 10/defer 1이다. 원 생산·독립 판정과 17개 resolution, queue와 기존 manifest는 보존한다. 개정 도구·출력은 기존 재현에 필요한 계약·builder·파일 참조를 보전한 뒤 별도로 검증하고, 통과 후 활성 재개 좌표를 바꾼다. manifest만 보관한 채 그것이 참조하는 구 파일·코드를 덮어써 재현을 깨지 않는다. 기존 입력 해시를 새 숫자로 덮어쓰거나 과거에 없던 회수 기록을 당시 기록처럼 만들지 않는다.

전환은 다음 순서로 한 번 수행한다.

1. 공용 회수·보기, 판독 범위, 행별 검사·집계와 감사 기록을 실패 테스트부터 구현한다. 개정 정책·스키마와 실제 생성·검사 명령을 함께 제공한다.
2. 70개의 현재 효력 판정과 그 근거를 전건 분류한다. 관찰 내용에서 분명한 판독 종류·범위는 정리하고, 로컬 근거는 기존 실물 SHA·selector와 현재 추출 결과를 대조한다. 이는 전건 내용 재판정이 아니다.
3. 회수 실물 부재·범위 불명확·다른 판본 귀속·재진입 역할 근거 부족이 있는 부분만 보완한다. 웹 재회수는 현재 시각의 재확인으로 기록한다. 과거 해시를 복원했다고 주장하지 않는다. 부족한 것은 처분의 defer와 별개인 증거·절차 보완 의무일 수 있다.
4. 보완은 원 판정 SHA를 가리키는 추가 기록으로 남긴다. 의미가 유지되는 행은 원 판정과 독립 검증을 재사용한다. 새로운 자료가 기여·역할·처분을 바꾸는 version만 재판정·resolution 대상으로 연다.
5. 구 70개의 실제 감사 기록도 현재 판정 SHA·정책에 결박해 이행한다. 기존 보고서에서 대상·근거·결론을 확인할 수 있는 감사는 재사용한다. 새 최소 표본 범주가 빠졌거나 감사 범위를 확인할 수 없는 부분만 추가 감사한다. receipt를 채웠다는 이유만으로 감사까지 완료했다고 표시하지 않는다.
6. 정상·실패·재개 경로의 수용 시험을 통과하고 남은 보완 의무의 ID·원인·담당이 빠짐없이 추적되면 묶음 002부터 개정 절차로 진행한다. 구 70개 중 보완이 남은 행을 v2 완료로 세지 않으며, 독립적인 신규 후보 선별은 계속할 수 있다.

과거 공통 20-version pilot의 성과와 발견은 보존한다. 새 도구·의미 경계는 그중 영향받는 사례와 실제 실패 사례로 확인한다. 같은 20개를 전부 다시 생산·투표하는 것을 매 개정의 의무로 만들지 않는다. 새 정책이 없었던 위험을 드러내면 그 위험을 검사할 사례만 추가한다.

## 8. 구현 수용 시험

새 대량 배정을 열기 전에 다음을 실제 자료와 축소 실패 사례로 확인한다. 이 표는 아직 실행하지 않은 구현 수용 기준이다.

| 경로 | 통과 조건 |
|---|---|
| 로컬 초록 | 기존 파일·SHA·record/rank와 실제 초록 추출물이 연결되고 원자료가 바뀌지 않음 |
| 웹 자료 | 실물·회수 기록·읽은 위치가 함께 존재하며 요청하지 않은 URL을 붙인 판정은 거부됨 |
| 잘못된 응답 | HTTP 200의 JS 화면·빈 응답은 내용 근거가 되지 않고, 스캔은 이미지 경로로 처리됨 |
| 범위·판본 | 소개·목차·서문·본문이 구분되고, 다른 판본을 대상 판본 본문 판독으로 집계하지 않음 |
| 기여·역할 | 새 결과의 존재만 쓴 core 근거와 범용성이 없다는 이유만으로 내린 noise 근거를 내용 감사가 발견함 |
| 독립 검증 | 필수 세 처분에 독립 판독이 필요하며, 검증자가 먼저 끝나도 유효 행이 보존됨 |
| 실패 반경 | 같은 파일의 한 잘못된 행을 격리하고 다른 유효 행은 집계·재개할 수 있음 |
| 합의 감사 | 합의 core/noise·낯선 분야·얕은 자료 의존·context/relationship의 존재하는 표본 범주가 감사 기록에 결박됨 |
| 변경 시간선 | 보고서 문구·무관한 source·배정 표지 변경은 유효 판정을 폐기하지 않고, 실제 의존 자료·정책 변경은 영향 행에 반영됨 |
| 부분 완료 | 완료된 범위와 미완료·보완 ID가 구분되고, 새 감사 집합은 자체 최소 표본을 갖추되 과거 집합을 다시 감사하지 않음 |
| 과거 보존 | 구 70개의 원행·resolution·해시를 보존하고 현재 재회수를 과거 증거로 소급하지 않으며, 실제 구 감사와 빠진 새 표본 범주도 구분해 이행함 |
| 실물 이관 | 참조 실물을 옮긴 목적지에서 해시를 확인하며, Git만 전달한 경우 해당 근거의 부재와 영향 ID를 검출함 |
| 전체 집계 | version/work 폐쇄·중복 배정 방지·미완료 이유·manifest·동일 입력 재현성과 전체 테스트/compileall 통과 |

후속 정밀 판독자는 이 단계에서 남긴 핵심 후보를 정확한 판본·정의·가정·논증·의존 결과에서 다시 읽고 최종 핵심층을 정한다. 그 뒤의 구성요소·참고문헌·누락 검사와 문헌조사 동결은 문헌 체계 명세와 사용자가 정한 후속 범위를 따른다.

## 9. 결정의 근거와 단순화한 지점

[simplify](../../../../.agents/skills/simplify/SKILL.md)의 네 질문과 [형식과 절차](../../../../docs/형식과-절차.md) 2.2·2.3·2.5·3.4절을 적용했다. [독립 반박 감사](version-review-procedure-independent-review.md)는 기존 코드·계약·실물 177판정행을 대조했다. 총괄은 그 권고를 다음처럼 채택하거나 좁혔다.

- ID·원장·기존 파서·resolution은 재사용한다. 일반 웹/PDF receipt와 행별 격리·감사 기록은 아직 없는 기능이라고 명시한다.
- 더 많은 동의 절차 대신 실제 자료 근거와 두 판단 질문을 보강한다. 총괄이 전원 재동의 없이 근거로 종료한다.
- 검증자가 먼저 끝나는 경우를 위해 여러 새 대기 상태를 추가하는 대신 pending과 대기 이유를 쓴다.
- 분야 표지는 배정에만 사용하고 본문 판단이나 version 해시와 섞지 않는다. 전수 분야 분류를 새 선행 과제로 만들지 않는다.
- 전역 무결성은 처음·입력 변경·최종 종료에서 지키고, 일상 판정의 현재성은 실제 의존 범위로 좁힌다. 입력 무결성을 종료 때까지 미루라는 권고로 해석하지 않는다.
- 원격 실물은 보존해 다시 볼 수 있게 하되, 회수/보기 로그가 이해·독립성·수학적 진위를 증명한다고 주장하지 않는다.
- 기존 70개를 다시 시작하지 않는다. 기록 보완과 실제 내용 재판정을 구분하고 필요한 것만 수행한다.
