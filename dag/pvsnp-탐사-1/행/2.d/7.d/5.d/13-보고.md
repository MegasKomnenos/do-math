## 결론

검증런 `2.7.5.5`의 발견 `R1-13`은 타당하다. L14 기록은 ECCC PDF를 판독 원문으로 사용한다. 공개 접근표 L14 행은 CMU PostScript만 기록하고 ECCC PDF를 기록하지 않는다.

발견의 구조 설명은 일부 틀렸다. 공개 접근표의 `대체 공개본 탐색 결과` 열은 대체본을 여러 건 기록할 수 있다. 따라서 22행 구조를 바꿀 필요가 없다. 결함 원인은 후행 판독 작업자가 새 판독 원문의 접근 증거를 기존 열에 되돌려 쓰도록 책임을 받지 못한 점이다.

상신과 기각 발견은 없다. 사용자 확정 문면을 바꾸지 않고 기존 표의 접근 증거를 보완할 수 있다.

## 실측·입증

`public-web.md` L14 행은 DOI 접근과 CMU PostScript URL을 기록한다. `L14.md`는 ECCC Technical Report TR94-010 PDF를 판독 원문으로 지목한다. `_로그_4.txt`는 `https://eccc.weizmann.ac.il/report/1994/010/download/`에서 380,659바이트 PDF를 받은 명령과 SHA-256을 기록한다.

`public-web.md` L20 행은 프로젝트 페이지의 직접 GET만 기록한다. `L20.md`는 GitHub 공개 저장소, 판독 커밋과 `CookLevin.v`의 정리 좌표를 판독 근거로 쓴다. `_로그_6.txt`는 같은 GitHub URL의 얕은 clone과 커밋 확인 명령을 기록한다.

기존 `대체 공개본 탐색 결과` 열은 L04·L05·L06·L12·L13 행에서 URL, 시각, HTTP 상태, 콘텐츠 유형과 바이트 수를 함께 담는다. 이 실물이 22행 구조 안에 L14·L20 증거를 적을 수 있음을 반증한다.

## 수리 설계

수리 단위 `U1`은 기존 필드 값을 보완한다. 새 원장, 필드, 공개 함수와 JSON 키를 만들지 않는다. `2.7.5.13.2`는 과거 시각을 추정하지 않고 현재 접근을 재측정한다. 수리자는 L14 ECCC PDF와 L20 공개 저장소의 URL, 시각과 접근 결과를 표와 판독 기록에 함께 적는다.

수리자는 L09~L22 실제 판독 URL을 다시 대조한다. 수리자는 공개 접근표의 L14·L20 겨냥 셀과 판독 기록의 접근 절만 고친다. `2.7.5.13.3`은 세 파일을 함께 동결하고 하류 소비자 세 행을 검사한다.
