## 결론

검증런 `2.7.5.5`의 발견 `R1-13`은 타당하다. 행 `2.7.5.12.5.11`은 발견 뒤 공개 접근표 L14 행에 ECCC PDF URL과 판독 사실을 추가했다. 그러나 현행 L14 행에는 ECCC PDF의 접근 시각, 최종 URL, HTTP 상태, 콘텐츠 유형, 바이트 수와 리디렉션 수가 없다. L14 판독 기록도 공개 접근표의 증거 좌표를 연결하지 않는다.

같은 책임 누락이 L20과 L21에도 있다. L20 판독 기록은 공개 저장소와 판독 커밋을 근거로 쓴다. 공개 접근표 L20 행은 프로젝트 페이지의 직접 GET만 기록한다. L21 판독 기록은 공식 proof document PDF의 해시, 바이트 수와 물리 페이지 수를 근거로 쓴다. 공개 접근표 L21 행은 AFP 항목 페이지의 직접 GET만 기록한다.

발견의 구조 설명은 일부 틀렸다. 공개 접근표의 `대체 공개본 탐색 결과` 열은 대체본을 여러 건 기록할 수 있다. 따라서 22행 구조를 바꿀 필요가 없다. 결함 원인은 후행 판독 작업자가 새 판독 원문의 접근 증거를 기존 열에 되돌려 쓰도록 책임을 받지 못한 점이다.

상신과 기각 발견은 없다. 사용자 확정 문면을 바꾸지 않고 기존 열의 접근 증거를 보완할 수 있다.

## 실측·입증

`public-web.md` L14 행은 DOI 접근, CMU PostScript URL, ECCC PDF URL과 판독 사실을 기록한다. ECCC PDF에 대해서는 접근 시각, 최종 URL, HTTP 상태, 콘텐츠 유형, 바이트 수와 리디렉션 수를 기록하지 않는다. `L14.md`는 ECCC Technical Report TR94-010 PDF를 판독 원문으로 지목한다. `_로그_4.txt`는 같은 URL에서 380,659바이트 PDF를 받은 명령과 SHA-256을 기록한다.

`public-web.md` L20 행은 프로젝트 페이지의 직접 GET만 기록한다. `L20.md`는 GitHub 공개 저장소, 판독 커밋과 `CookLevin.v`의 정리 좌표를 판독 근거로 쓴다. `_로그_6.txt`는 같은 GitHub URL의 얕은 clone과 커밋 확인 명령을 기록한다.

`public-web.md` L21 행은 AFP 항목 페이지의 직접 GET만 기록한다. `L21.md`는 공식 proof document PDF의 URL, SHA-256, 4,411,247바이트와 물리 875쪽을 기록한다. `2.7.5.12.5.26-보고.md`는 같은 URL에서 받은 PDF의 보관과 재측정을 기록한다.

기존 `대체 공개본 탐색 결과` 열은 L04·L05·L06·L12·L13 행에서 URL, 시각, HTTP 상태, 콘텐츠 유형과 바이트 수를 함께 담는다. 기존 22행 구조 안에서 L14·L20·L21 접근 증거를 기록할 수 있다.
