# do-dag

작업 국면 하나를 오케스트레이터 1기와 단명 에이전트들로 완주시킨다.

- **오케**는 파견만 한다 — 【오케 · 쏜다 · 잔다 · 확인한다 · 기입한다】.
- **전개** — 【전개 · 일하지 않고, 일할 행을 저작하고 죽는다】.
- **파견표**는 무엇을 언제 쏘는지의 유일한 운전 정본이다 — 【파견표쓰기 · 오케는 상태 열만 쓴다 · 행을 늘리는 것은 에이전트와, 실행 중 결정을 전파하는 메인이다 · 도구는 Edit뿐이다】. 예외 처분의 상태 쓰기는 `파견문_예외.md`가 진다.

이 문서는 **메인(사용자 세션)의 절차**다. 오케의 절차는 `대응표.md`가, 전개의 절차는 각 행 파일이 담는다.

## 발동 전제

생성이 딛을 정본(사양·기안·확정 결정 기록)이 있어야 한다. 없으면 기안 절차(`brainstorming`·`decision-briefing`)로 반려한다.

그 정본이 에이전트 저작물이면 확정 전 적대 검토(`grilling` 또는 `verify-rounds`)를 거쳤는지 확인한다. 검토가 없으면 발동 전에 검토를 돌린다. 검토 질문 둘 — 품질 목표가 산출물의 완료 기준으로 번역되어 있는가 · 읽기 금지 조항의 대상이 산출물인가 원자료(【원자료 · 작업 대상에 대한 사실·근거의 원본 · 상시 열람 자산이다 · 봉쇄·백지 조항은 산출물에만 걸린다】)인가.

같은 대상을 다시 만들게 하는 국면이면 앞선 시도의 결함 목록·반려 사유를 「대상」에 싣는다. 앞선 산출물의 봉쇄는 이 목록을 차단하지 않는다.

착수 시 `기억/색인.md`의 layer-3을 확인하고 관련 현행 노드를 적재한다.

## 메인의 임무 넷

### 1. 오케 파견

국면 착수·재개 시 do-dag 문서 전건(`전거/` 제외)을 읽는다.

국면명을 정한다. 대상을 나타내는 짧은 식별자이고, 런 디렉토리 `.sdd/dag/<국면>/`의 이름이자 격리 좌표(【격리좌표 · 경로는 <dag-wt 루트>/<국면>+<행> · 브랜치는 dag/<국면>/<행>】)의 어미가 된다. **문법이 있다** — 【이름문법 · 글자·숫자·`_`·`-`만 쓴다(64자 이하). 경로 구분자·공백·`.`·`..`·제어 문자와 Git ref 금지 문자(`~^:?*[\`)는 경로와 브랜치 이름을 함께 깨뜨린다】. 강제는 `dag_marker.validate_phase`가 한다.

그다음 셋을 이 순서로 한다 — 【마커개설순서 · 마커를 열고, 런 디렉토리를 만들고, 그다음 오케를 쏜다】.

1. **국면을 연다** — `python {scripts 경로}/dag_marker.py open --phase <국면명>`. pre-commit 훅이 없으면 `install-hook`을 먼저 돌린다.
2. **런 디렉토리 `.sdd/dag/<국면>/`를 만든다.**
3. **오케를 파견한다** — `references/배정.md` 「배정표」의 `모델_프리셋` 열을 따른다.

2기째부터는 뒤에 ` #<차수>`를 붙인다(`do-dag 오케 veridict-개정 #2`). 이 문자열은
국면 안에서 유일해야 한다(아래 4항).

### 2. 게이트·상신 중계

**게이트**: 오케가 게이트 행에 닿으면 진행 중 파견을 수확한 뒤 멈추고 결정 파일 경로를 보고한다(대응표 「수확 후 정지」). 메인은 그다음 여덟 단계를 이 순서로 한다.

1. 그 파일의 브리핑 절과 신규 제약 절을 사용자에게 올린다. 신규 제약은 항목별로 결정을 받는다.
2. 결정 절에 사용자 응답과 확정 문면을 기입한다.
3. 직접 규범을 담은 자유 입력은 두 자리에 축자로 적는다.
4. 선택 응답은 선택된 라벨과 선택지 좌표를 사용자 응답에 적는다. 이름 있는 선택지를 가리키는 자유 입력도 선택 응답으로 처리한다.
5. 선택지의 「결정 효과」 전문은 확정 문면에 옮긴다.
6. 선택지 설명문을 사용자 발화로 기록하지 않는다.
7. 2~6항과 **같은 편집에서** frontmatter `상태`를 `결정됨`으로 바꾼다.
8. 오케를 재개시킨다.

사용자가 산출물 내용을 반려하면, 결정 기입과 같은 편집에서 재생성 행의 배정 재도출 여부와 근거를 「메인 결정」 절에 적는다(`references/서식.md` 배정표의 반려 환류).

브리핑을 액면가로 받지 않는다 — 재도출 표기가 없는 주장을 우선으로 재측정하고, 방침을 중계할 때는 그것이 처방인지 불변식인지를 가른다.

```전거 전파
| 불변식 문면 | 해당 서브트리에 `불변식-<순번>.md`를 발행한다. 미착수 행 파일의 `불변식:`·`읽기 목록:`·예산 `--files`에 그 좌표를 더한다 |
| 미착수 행 파일 | 읽기 목록·`정본:`·완료 기준·예산 블록을 고친다. 결정이 연 편집을 검증런·싱크가 귀속 대조에서 미귀속 편집으로 세게 되면, 그 파일 목록과 귀속처(결정 좌표)를 싱크·검증런 행 파일에 선지정한다 |
| 파견표 행 집합·선행 | 행 파일을 쓰고 파견표에 등재한다. 싱크 선행 목록을 닫고 검산 exit 0을 확인한다. 파견은 오케가 한다. 미착수 행의 제거·이관은 이렇게 한다 — 파견표에서 그 행을 지우고, 행 파일은 지우지 않고 머리에 폐기·승계 표기를 달아 보존하며, 그 층 싱크의 선행에서 빼고, 승계 노드가 있으면 그 파견문 `정본:`에 구 행 파일 좌표를 싣는다. 완결 행(`완`·`비준`)과 `진행` 행은 제거 대상이 아니다 |
| 파견표 모델 열 | 비완결 행의 모델 열을 고친다. 오케 운전에 닿는 조항은 오케 파견 프롬프트에 적는다 |
| 이음새 원장 | 명세·소비자 열을 고친다. 상태 전이는 건드리지 않는다 |
| 기준선 미결 · 재량 위임 조항 | 해당 항에 해소·개방 사실과 결정 좌표를 한 줄 추기한다. 그 밖의 기준선 절은 고치지 않는다 |

메인이 고치는 것은 런 디렉토리 서류다. 행 파일·파견표는 `Edit`로만 고친다.
파견표를 고친 뒤 `dag_check.py`를 돌려 exit 0을 확인한다. 완결 행(`완`·`비준`)의
파일과 `불변식:` 슬롯은 바꾸지 않는다.

**진행 중 행의 중단·재파견.** 결정이 상태 `진행`·`상신중`인 행의 전제(겨냥·완료
기준·불변식)를 바꾸면 메인이 그 행을 중단하고 다시 쏘게 한다. 전제를 바꾸지 않으면
완주시키고 결과는 하류(재검·이월)로 받는다. 중단은 이 순서로 한다.

1. 오케에 SendMessage로 「행 <번호> 중단 후 교대」를 지시한다. 오케는 대응표
   「중단」대로 한다 — Codex 행이면 자기가 띄운 백그라운드 실행을 `TaskStop`으로
   멈추고, Claude 행이면 그 행의 agentId를 메인에 SendMessage로 보낸다. 그 행의 파견표
   상태를 `미착수`로 바꾼다. 그다음 「교대」대로 수확 후 정지·검산을 거친다.
   첫 줄 `DONE`, 둘째 줄 `종류: 교대준비`, 셋째 줄 `파견표: <절대 경로>`로 반환한다.
2. 메인은 agentId를 받는 즉시 `TaskStop`한다. 오케가 agentId를 보내지 않으면
   `agent_usage.py`가 가리키는 오케 트랜스크립트에서 `agentId:`를 찾아 멈춘다. 오케가
   프로브에도 응답하지 않으면(`고아처분` 사망 판정) 메인이 오케를 `TaskStop`으로
   멈추고, 함께 죽은 다른 진행 행은 `고아진행` 예외로 간다.
3. 정리한다. 런 디렉토리에서 그 행 번호 자리의 파일 전건(`행/<번호>.d/`·
   `<번호>-보고.md`·`<번호>-결산.md` 등)을 지운다. worktree는 격리 노드마다 하나다 —
   중단 행이 그 노드의 전개 행이면 worktree를 `dag_marker.py`로 닫아 지우고 재파견된
   전개가 다시 연다. 중단 행이 그 노드의 자식 행이면 worktree를 보존하고, 그 행의
   보고 「편집 귀속」 표가 지목한 파일만 worktree에서 되돌린다. 보고가 없으면 되돌리지
   않고 다음 싱크의 귀속 대조로 넘긴다. 이 삭제·되돌림은 `격리생명주기` 보존 처분의
   예외다. 중단 행이 싱크이면 `dag_marker.py lease`로 소유자를 확인한다 — 그 행이
   소유자이면 메인 체크아웃을 `git reset --merge`로 되돌리고 `clear-token`으로 grant를
   지우고 lease를 반납한다. 다른 행이 소유자이면 메인 체크아웃에 손대지 않는다.
   중단·삭제 사실은 결정 파일 「전파」 절의 그 행 줄에 적는다.
4. 행 파일을 고치고 검산 exit 0을 확인한 뒤 오케를 다시 쏜다(차수 +1).

메인은 재개·교대·게이트·상신 처리에 앞서 `결정/` 전건의 「전파」 절을 읽고,
`영향있음` 줄의 편집이 실물에 있는지 대조한다.
```

### 3. 종결 보고

오케의 종결 보고를 받아 사용자에게 일괄로 올린다: 파견표 경로 + `비준` 행 목록 + `파킹` 행 목록. 국면 싱크가 가동되지 못한 **조기 종결**도 같은 자리로 온다.

외부 실행기가 둔 비용·시간·토큰 상한은 행·검증런·게이트·싱크를 생략할 권한이 아니다. 남은 상한으로 완주할 수 없으면 국면을 활성 상태로 두고 중단 사유와 미완 행을 보고한다. 메인은 파견표의 미완 행이 있는데 제품 산출만 직접 만들거나 마커를 닫지 않는다.

종결 보고의 바이트 수와 계수는 실물에서 다시 측정한다. 명세의 설명, 문자열 눈대중, 에이전트 반환문을 수치 근거로 쓰지 않는다.

그다음 **런 디렉토리를 저장소로 이관한다.** `.sdd/`는 추적 밖이라 이관하지 않으면 그 국면의 산출이 저장소에 남지 않는다 — 특히 sweep이 파킹된 노드에서 채록한 `행/<번호>.d/`는 그 노드가 남긴 유일한 실물이다.

**활성 국면이 0일 때만 한다**(`<마커 명령> status`). 남은 국면이 있으면 미루고, 마지막 국면이 닫힐 때 `.sdd/dag/` 아래 남은 국면 디렉토리를 전부 이관한다. 조건인 이유는 아래 「런 디렉토리」가 진다. **활성 국면 0인데 `.sdd/dag/` 아래 국면 디렉토리가 남아 있으면 미이관**이다.

국면마다 이렇게 한다. `<국면>`이 이미 `dag/` 아래 있으면 멈춘다 — `mv`가 그 안으로 중첩시키고 종료코드는 0이라 조용하다.

```
test ! -e dag/<국면>
git ls-files -- .sdd/dag/<국면> | sed 's|^\.sdd/dag/|dag/|'   # 이관 전 추적 목록
mkdir -p dag && mv .sdd/dag/<국면> dag/<국면>
git rm -r --cached --ignore-unmatch -q -- .sdd/dag/<국면>
git add -A -- dag/<국면>
git ls-files -- dag/<국면>                                     # 이관 후 추적 목록
```

**두 목록을 대조한다.** 앞에 있고 뒤에 없는 것은 루트 `.gitignore`가 새 자리에서 막은 것이고, 그대로 커밋하면 **이미 이력에 있던 파일이 삭제만 된다.** 그 경로를 `git add -f`로 되살리고 다시 대조한다.

추적된 적 없는 무시분은 `git check-ignore -v $(find dag/<국면> -type f)`로 열거해 M 노드에 적는다. 강제 편입하지 않는다 — 저장소 정책이 「추적되는 원본 바이너리는 없다」다. 빠진 것을 지우는 대신 무엇이 빠졌는지를 남긴다.

커밋·push하기 전에 `.claude/skills/commit-harness/SKILL.md` 전문을 읽는다. 작업 커밋이므로 그 절차대로 M 노드를 동반하고, 그 노드가 국면 종결의 요지와 결산의 「경미 처분」 이월분·「잔여·처분」을 진다.

**이관은 실물을 보존하지 좌표를 보존하지 않는다**(아래 「런 디렉토리」). 아카이브를 읽는 자는 이관된 좌표를 런 시점의 기록으로 읽는다.

**PII 규율의 대가가 여기서 바뀐다.** `dag/`에는 자동 PII 게이트가 없다. 저작 시점 규율(아래 「런 디렉토리」)이 유일한 방어이고, 이관 뒤 위반은 영구 이력이 된다.

### 4. 하트비트와 교대

완만한 주기로:

```
python {scripts 경로}/agent_usage.py --description "do-dag 오케 {국면명}" --phase {국면명}
python {scripts 경로}/agent_usage.py --description "do-dag 오케 {국면명} #2" --phase {국면명}   # 교대 뒤
```

열쇠는 파견 때 네가 써 넣은 description이다. 하네스 내부 값(tool_use id)은 볼 수 없다.

**`--phase`를 빠뜨리지 않는다.** 좁히지 않으면 예전에 같은 국면명을 쓴 런의 오케가 함께 걸려 측정이 실패한다. `--phase`는 마커의 그 국면 `opened_at` 이후만 본다. 국면이 이미 닫혔으면 `--since <ISO8601>`로 하한을 직접 준다.

좁히고도 둘 이상이 걸리면 스크립트는 고르지 않고 걸린 것들을 열거해 오류로 돌려준다 — 차수를 빠뜨린 것이니 붙여 다시 돌린다.

적재가 **120k**에 닿으면 교대한다 — 【교대 · 수확 후 정지로 닫는다 · 검산 exit 0을 확인한다 · DONE에 교대준비와 파견표 경로를 확장해 반환하고 종료한다】.

1. 기존 오케에 SendMessage로 교대를 지시한다. 「수확 후 정지」로 닫고 검산 통과를 확인한다. 첫 줄 `DONE`, 둘째 줄 `종류: 교대준비`, 셋째 줄 `파견표: <절대 경로>`로 반환하고 종료한다.
2. 그 반환을 받고 종료를 확인한다. 공통 첫 줄과 교대 확장이 어긋나면 그 문면대로 처분한다. 게이트·상신은 평시와 같이 중계한다. 처분이 끝나면 교대를 다시 지시한다.
3. 같은 오케 프롬프트로 새 오케를 쏜다. description의 차수만 올린다. 새 오케는 파견표를 읽어 다음 ready 행부터 잇는다.

교대 중에 국면을 닫거나 마커를 건드리지 않는다.

오케의 사망 —

```전거 고아처분
요지: 사망을 셋으로 판정하고 다시 쏜다 · 주인 잃은 행을 예외로 기입한다

**사망 판정은 셋을 순서로 한다.**

1. 오케 파견의 Agent 호출이 이미 반환했는가. 반환했으면 죽은 것이 아니라 종료한
   것이다 — 그 문면대로 처분한다.
2. 반환이 없으면 SendMessage로 프로브를 1회 보낸다(`상태 보고` 한 줄).
3. 프로브 뒤 100분간 파견표 mtime 변화도 프로브 응답도 없으면 죽은 것이다.

죽었으면 곧바로 같은 프롬프트로 다시 쏜다. description의 차수는 오른다. 재파견 뒤 옛
오케가 살아 돌아오면 그 반환은 처분하지 않고 종료시킨다.

**새 오케는 첫 사이클의 재개 점검에서 주인 잃은 행을 `예외`로 기입한다.** 대상은 상태가
`진행` 또는 `상신중`인데 자기가 쏜 적이 없는 행이다. 예외 입력의 첫 줄은 `예외`다.
둘째 줄 `코드:`에는 `진행`이었던 행이면 `고아진행`, `상신중`이었던 행이면
`고아상신중`을 쓴다.

| 한 낱말 | 예외의 처분 |
|---|---|
| `고아진행` | 실물만 보고 처분한다. worktree는 【격리생명주기 · 다시 쓸 가능성이 있으면 보존하고, 쓰지 않기로 처분한 뒤에만 채록하고 삭제한다】를 따른다 |
| `고아상신중` | `결정/상신-<행번호>-*.md`가 실재하면 그 좌표를 행 파일 `정본:` 슬롯에 실어 `미착수`로 되돌린다. 없으면 상신 사유를 실물로 재확인하고 공통 첫 줄 `상신` 뒤에 사유와 좌표를 추가한다 |
```

## 구조 계약

| 층 | 모델 | 여는 것 |
|---|---|---|
| 메인 | 세션 모델 | do-dag 문서 전건(`전거/` 제외) — 국면 착수·재개 시 읽는다 · `결정/` 전건 · 상신 실물 · `.claude/skills/commit-harness/SKILL.md`(이관 커밋 직전) |
| 오케 (1기, 국면 상주) | 모델 프리셋의 오케 배정 | `계약/공통.md` · 대응표 · 파견표(상태를 기입할 행 줄만 — 운전 정보는 검산 `--ready` 출력이 준다) · 결정 파일 frontmatter · `references/배정.md` · Codex 행의 반환 파일과 로그 파일 |
| 행 에이전트 (단명) | 파견표 모델 열 (Claude Agent 또는 Codex: `references/배정.md`) | 자기 행 파일과 그것이 가리키는 것 |
| 검증런 서브에이전트 (단명) | 검증런 모델 프리셋의 verify-rounds 배정 | 검증런 행이 verify-rounds 계약에 따라 지급한 것 |

일반 행 에이전트는 다른 에이전트를 파견하지 않는다. 검증런 행은 예외다. 검증런 행은 verify-rounds 세션으로서 수리자·병합자·심사자를 파견한다. 각 파견 단위는 모델 예산(【예산 · sonnet 200k · opus 250k · fable 250k · gpt-5.6-sol 250k · gpt-5.6-terra 250k · gpt-5.6-luna 250k】) 안에서 완주하도록 설계한다. 검증런 내부 파견의 모델과 분할은 verify-rounds가 정한다.

**크레딧·차단으로 계열이 막히면 하위 티어로 대체하지 않고 그 행을 멈춘다.** 네가 배정을 다시 놓을 때도 같다 — 배정표와 그 이탈 규율은 `references/서식.md`다.

## 런 디렉토리

```
.sdd/dag/<국면>/
├─ 파견표.md    행 인덱스와 상태. 유일한 운전 정본
├─ 기준선.md    전역 사실 — 정본·차분·무효화 계통·규율 포인터·비범위·위임 조항·미결
├─ 이음새.md    노드 간 계약 원장
├─ 결정/       게이트 승인 축자와 메인 결정. 상신 결정(`상신-<행번호>-<순번>.md`)도 여기 산다
│              노드 싱크가 `add -f`로 자기 커밋에 함께 싣는다 — 나머지는 종결 뒤 이관이 싣는다
└─ 행/         그 행 자신의 산출은 행 번호 자리에 중첩한다
               <번호>.md 파견문 · <번호>.d/ 자식 산출
               <번호>-보고.md · <번호>-판정.md · <번호>-결산.md
               바깥에서 그 행을 향해 쓰는 산출은 점 번호로 평면에 둔다
               <번호>.예외.md
```

```전거 런디렉토리
요지: .sdd/dag/<국면>/에 산다 · .sdd/.gitignore가 `*`라 추적되지 않는다

담는 것은 `파견표.md` · `기준선.md` · `이음새.md` · `결정/` · `행/`이다.

추적되지 않으므로 노드 worktree에는 런 디렉토리가 존재하지 않고, 운전 중 상태가
저장소 이력에 섞이지 않는다. **국면이 닫힌 뒤 메인이 이 트리를 통째로
`dag/<국면>/`으로 이관해 커밋한다.** 이관하지 않으면 그 국면의 산출이 저장소에 남지
않는다.

**이관은 활성 국면이 0일 때만 한다.** 조건인 이유 둘 — 활성 국면이 있으면 메인
체크아웃의 이관 커밋이 【관문 · 활성 국면이 있으면 막고, 유효한 grant나 활성 국면의 노드 브랜치만 통과시킨다】에 걸려 grant를 받아야 서고, 활성 국면이 없어야 메인
체크아웃의 인덱스를 쥔 싱크가 없다.
그래서 활성 국면이 0인데 `.sdd/dag/` 아래 국면 디렉토리가 남아 있으면 미이관이다.

**이관은 실물을 보존하지 좌표를 보존하지 않는다.** 런 디렉토리 좌표는 절대 경로가
계약이므로, 이관된 파견문·보고가 싣는 좌표는 사라진 `.sdd/` 경로를 가리킨 채 남는다.
```

이관의 절차는 위 「3. 종결 보고」다. 결산까지 함께 간다 — 이관 시점에는 국면 종결 싱크가 이미 종결했으므로 뒤이을 편집이 없다.

산출물에는 【PII · PII를 인용하지 않는다 · 추상 지칭으로 쓴다】가 걸린다.

## 노드 격리

실행 노드는 각자 worktree에서 돈다. 전개가 `dag_marker.py worktree-open`으로 열고 싱크가 병합한 뒤 처분표(`계약/싱크.md`)대로 닫는다. 이름은 국면과 행 번호에서 파생한다 — 【격리좌표 · 경로는 <dag-wt 루트>/<국면>+<행> · 브랜치는 dag/<국면>/<행>】.

```
메인 체크아웃 (저장소)                worktree (저장소 밖)
├─ .sdd/dag/<국면>/   행 파일·보고    ├─ 저장소 전체 사본   노드의 실작업
│                     이음새 원장     └─ (.sdd 없음)
└─ master             싱크만 커밋한다
```

파견문의 좌표는 둘로 갈린다: 저장소 안은 작업 디렉토리 기준 상대 경로, 런 디렉토리는 절대 경로. 독트린은 `references/분해_원리.md` 1절, 절차는 `references/서식.md`가 담는다.

# 파견문: 예외 에이전트

오케가 이 파일의 경로 한 줄로 파견한다. 모델은 `모델_프리셋`과 배정표의 예외 에이전트 값을 따른다. `claude-full`·`mixed`에서 fable 한도 소진으로 난 예외만 `opus high`다. 함께 오는 것은 행 번호와 반환 텍스트 전문, 또는 검산 출력 전문이고, 어느 쪽이든 **검산 명령·마커 명령·스킬 루트가 축자로 함께 온다**. 첫 행동 전에 `<스킬 루트>/계약/공통.md` 전문을 읽는다. 아래에서 그 두 명령을 그대로 돌린다 — scripts 경로도 파견표 경로도 재도출하지 않는다.

---

너는 do-dag 예외 에이전트다. 한 행이 예상 밖으로 끝났거나 파견표가 검산에 걸렸다. **상황을 실측하고 처분하고 죽는다.**

## 대상이 표일 때

함께 온 것이 행 번호가 아니라 검산 출력이면 대상은 파견표 자체다. 발견마다 그 행을
저작한 자리를 실측해 표를 고친다. 함께 받은 검산 명령이 exit 0이 될 때까지 돌린다.
산출은 `행/표.예외.md`다. 완료 반환의 첫 줄은 `DONE`, 둘째 줄은
`닫은 발견: <수>`다. 아래 절은 대상이 행일 때의 절차다.

## 첫 행동

1. `파견표.md`에서 그 행과 선행·후행을 본다.
2. 그 행의 파견문 파일과, 있어야 할 완료 신호 좌표의 실물을 확인한다.
3. 반환 텍스트의 주장을 액면 수용하지 않는다 — 파일 실물이 정본이다.
4. 첫 줄이 공통 반환어휘 밖이면 `반환형식위반`으로 기록한다.
5. 둘째 줄이 `코드: 고아진행`이면 오케 사망으로 주인이 사라진 행이다. 실물만 보고
   처분한다. 부분 산출이 있으면 worktree를 지우지 않는다.
6. 둘째 줄이 `코드: 고아상신중`이면 상신을 올려 두고 주인이 사라진 행이다.
   `결정/상신-<행번호>-*.md`가 실재하면 그 좌표를 행 파일 `정본:` 슬롯에 싣는다.
   상태를 `미착수`로 되돌린다. 결정 파일이 없으면 상신 사유를 실물로 재확인한다.
   공통 첫 줄 `상신` 뒤에 사유와 실측 좌표를 추가해 반환한다.
7. 대상이 싱크이면 반환 첫 줄이 아니라 결산 frontmatter `상태:`로 상세 결과를 판정한다.

## 처분

```전거 예외처분
요지: 미착수 · 완 · 파킹 · 상신 반환

처분은 그 행의 상태를 바꾸거나 상신하는 것으로 끝난다.

| 처분 | 언제 | 함께 하는 것 |
|---|---|---|
| `미착수` | 다시 쏘면 되는 것 — 컨텍스트 부족, 리밋·장애로 인한 소멸, 지시 결함, 결산 상태 `대기`, 주인이 사라진 행 중 결정 파일이 실재하는 `고아상신중` | 행 파일을 보강한다. 부족했던 좌표·값·정본을 채운다. `대기`는 보강할 것이 없다 |
| `완` | 실물이 완료 기준을 이미 충족하는데 반환 문면만 어긋난 것 | 근거를 예외 기록에 남긴다 |
| `파킹` | 진행 불가 — 보수 기본형조차 서지 않는 것 | 사유와 재개 조건을 예외 기록에 남긴다 |
| `상신` 반환 | 처분이 `상신사유`에 닿는 것 | 파견표 상태는 예외가 바꾸지 않는다. 오케가 `반환어휘`대로 기입한다. 사유와 실측을 예외 기록에 적고 공통 첫 줄 `상신` 뒤에 사유와 좌표를 추가한다 |

수리가 필요하면 수리 행을 그 행의 형제로 추가하고 그 층의 싱크 선행에 더한 뒤,
원래 행을 `미착수`로 되돌린다. 수리 행은 작업자로 세운다.

**예외 파견의 입력은 대상이 무엇이냐로 갈린다.**

| 대상 | 함께 오는 것 |
|---|---|
| 행 | 행 번호 · 반환 텍스트 전문 · 검산 명령 축자 · 마커 명령 축자 · 스킬 루트 |
| 파견표 | 검산 출력 전문 · 검산 명령 축자 · 마커 명령 축자 · 스킬 루트 |
```

상신 사유 넷은 【상신사유 · 불가침을 열어야 목표가 닫힌다 · 사용자가 확정한 문면의 내용·적용 범위를 바꿔야 한다 · 비가역 행위가 필요하다 · 코퍼스에 근거 없는 것을 발명해야 한다】다.

새 행의 선행은 자기 범위 안만 지목한다. 예외 처분은 파견표 상태 변경과 예외 기록으로 끝난다. 수리 자체는 완료 기준을 갖는 수리 행이 한다. 그 파견문은 `references/서식.md` 「파견 행」의 필수 슬롯 전건을 갖춘다.

**모델 배정을 바꾸면 파견표 모델 열과 그 행 파일의 `모델 배정 근거:` 슬롯을 같은 편집에서 함께 고친다.** 둘이 갈리면 파견표가 이긴다.

**진행 불가를 파킹으로 처분할 때 질문을 올리지 않는다.** 종결 보고가 사용자에게 일괄로 간다.

## 경계

- 사용자가 확정한 목표·완료 기준에 손대야 하면 고치지 말고, **보수 기본형으로 진행하는 행**을 세운다. 그 행의 상태는 `미착수`다. 파견문의 `반환:` 슬롯에 완료 첫 줄 `DONE-비준`을 축자로 싣는다. `비준`은 그 행이 실제로 돌고 반환했을 때 오케가 기입한다. 보수 기본형조차 서지 않으면 상신이다(사유: 사용자 확정 변경).
- 행 번호의 **마디가 여섯이면** 의미를 따지지 말고 `파킹`한다. 폭주 방어이고 판단이 아니다.
- 예외가 싱크 행이면 메인 체크아웃이 병합 중간 상태로 남았을 수 있다. `git diff --cached --name-only`·`git ls-files --unmerged`에 무언가 보이면 먼저 **병합 lease의 소유자를 확인한다**(`<마커 명령> lease --status`). 그 행이 소유자이거나 lease가 비어 있을 때만 `git reset --merge`로 되돌리고, 남이 쥐고 있으면 손대지 않는다. 되돌린 뒤 lease를 반납한다. 충돌 자체는 해소하지 않고 분해로 돌아간다. 노드 worktree의 산출은 지우지 않는다.
- 그 행의 결산 파일이 있으면 `단계:`를 읽는다. 재개는 처음부터가 아니라 그 다음부터다 — `커밋완료 <SHA>`면 병합·커밋은 이미 선 것이고 회수부터 남았다. 값을 액면으로 받지 않고 그 값이 가리키는 다음 행위가 이미 섰는지 실물로 잰다(`계약/싱크.md` 재개 규약의 실측 표). `종결`이면 grant·lease까지 놓인 뒤이므로 남은 처분은 없다.

## 산출

- 파견표를 고쳤으면 함께 받은 **검산 명령**을 돌려 exit 0을 확인한다.

# 계약: 공통 규율

전 파견 에이전트가 적재한다.

- 슬롯은 채우거나 **"없음"을 명시**한다. 침묵은 미완성이다.
- **불변식 적재**: 첫 행동으로 `불변식:` 슬롯의 파일 전건을 읽는다. 파견문 임무와
  불변식이 어긋나면 착수하지 않는다. 첫 줄 `예외`, 둘째 줄 `코드: 불변식충돌`로
  반환한다. 불변식 항목이 자기 목적과 충돌하면 기계적으로 집행하지 않고 상신한다.
  기존 산출을 읽지 말라는 지시는 불변식 파일을 차단하지 않는다.
- **파손 검출**: 받은 파견문·지급물에 인코딩 파손이 있으면 임무를 역추정하지 않는다.
  파손은 `?` 연속 치환·깨진 경로·판독 불능 문자다. 첫 줄 `예외`, 둘째 줄
  `코드: 파손`으로 반환한다.
- **작업 디렉토리 확인**: 착수 전에 `작업 디렉토리:` 슬롯 값에서
  `git rev-parse --show-toplevel`을 돌린다. 결과가 슬롯 값과 다르면 착수하지 않는다.
  첫 줄 `예외`, 둘째 줄 `코드: 작업디렉토리불일치`로 반환한다. 일치 결과는 보고에 적는다.
- 산출은 반드시 **파일이 정본**이다. 반환 텍스트는 신호일 뿐이다.
- **완료 신호는 그 행의 실행이 낳는다.** 저작 주체가 미리 만들지 않는다.
- **상신 사유 넷** — 【상신사유 · 불가침을 열어야 목표가 닫힌다 · 사용자가 확정한 문면의 내용·적용 범위를 바꿔야 한다 · 비가역 행위가 필요하다 · 코퍼스에 근거 없는 것을 발명해야 한다】. 어떤 완료 기준도 그 권한을 만들지 못하는 경우가 상신이고, 그 밖은 집행하고 귀속한다.
- **발명의 정의**: 발명은 근거 없는 사실·수치·전거를 지어내는 것이다. 확보한 원자료에 근거한 내용의 생성·재구성·판단은 발명이 아니라 작업의 본체다. 그 내용이 딛는 원자료 좌표를 산출에 남긴다.
- **원자료** — 【원자료 · 작업 대상에 대한 사실·근거의 원본 · 상시 열람 자산이다 · 봉쇄·백지 조항은 산출물에만 걸린다】. 필요한 원자료가 지급물에 없으면 저장소에서 직접 연다. 저장소에도 없으면 확보(웹 검색·수급 도구·저장소 등록)를 먼저 시도하고, 확보가 실패한 경우에만 미확인 표지를 남긴다. 시도와 결과를 보고에 적는다.
- **불가침** — 【불가침 · 결정/ 아래 결정 파일 「결정」 절의 사용자 응답과 확정 문면】. 어떤 완료 기준으로도 열리지 않는다.
- **반증 의무** — 【반증의무 · 파견문·입력과 어긋난 지점을 발견하면 산출에 기재한다 · 없으면 「없음」을 명시한다】.
- **하위 파견 동기 실행** — 【동기파견 · 완료 통지를 기다리며 턴을 마치지 않는다 · 대기가 필요하면 포그라운드 대기 호출을 반복한다 · 병행은 호출 여럿을 한 메시지에 담는다】. 파견을 여는 행(검증런)에 걸린다.
- **산출 이름** — 【산출이름 · <번호>는 행 번호의 마지막 마디이고, 파일은 그 행이 속한 .d/ 아래에 놓인다】. 그 행에 실린 좌표는 파견문 `산출:` 슬롯이 정본이다.
- 【PII · PII를 인용하지 않는다 · 추상 지칭으로 쓴다】.
- 계약이 `계약/…`·`references/…`로 가리키는 상대 경로는 **스킬 루트 기준**이다.
- **문체**: 볼드는 판정 결과와 불변식 머리에만 쓴다. 기록은 한 자리에 살고 가리킴은 한 방향만 간다. 사실·근거·영향으로 쓰고 서사·평가어를 얹지 않는다.
- **작문**: 네 산출은 다음 행이 읽는 입력이다. `.claude/skills/write-for-reader/references/에이전트_채널.md`의 넷을 적용한다 — 범위·좌표를 닫힌 형태로, 지시와 배경을 갈라서, 반환 서식을 지정해서, 부재를 명시해서 쓴다. 위 「없음」 명시와 반환 어휘 규율이 그중 둘의 이 스킬 판이다. 같은 대상을 앞 행이 부른 말과 같은 말로 부른다 — 말이 바뀌면 다음 행이 다른 대상으로 읽는다.

# 수신자를 위한 평문

읽는 사람이 문장을 해석하지 않고 사실과 관계를 바로 파악하게 쓴다.

이 규칙은 한국어와 영어에 함께 적용한다. 수치가 언어마다 다른 자리는 그 자리에 따로 적었다.

서브에이전트에 파견문을 쓰거나 그 반환을 받을 때도 이 규칙이 걸린다. 사람과 달리 에이전트는 모호한 문장을 만나도 되묻지 않고 한 가지 읽기를 골라 진행하므로, 열어 둔 읽기가 곧 갈라진 작업이 된다. 그 채널에만 걸리는 규칙 넷은 이 스킬의 `references/에이전트_채널.md`에 있다. 절차문 — 단계로 수행을 지시하는 문서 — 에 더 걸리는 규칙 일곱은 이 스킬의 `references/절차문.md`에 있다.

규칙의 출처는 ASD-STE100 Simplified Technical English Issue 9의 작문 규칙 53항이다. 한국어에 그대로 옮길 수 없는 항(관사, 철자, 승인 어휘 목록)은 뺐고, 한국어에서 같은 모호함을 만드는 자리('의' 연쇄, 이중 피동, 명사 나열)를 더했다.

## 0. 원리

모호함은 선택지에서 나온다. 한 대상을 부르는 말이 여럿이면 읽는 사람이 그것들이 같은 것인지 판단해야 한다. 한 낱말에 뜻이 여럿이면 어느 뜻인지 골라야 한다. 문장을 엮는 방법이 여럿이면 어느 관계인지 복원해야 한다.

**그래서 이 규칙은 선택지를 줄인다.** 표현을 다양하게 하지 않고, 같은 것을 늘 같은 말로 부르고, 문장 구조를 몇 가지로 고정한다. 글이 단조로워 보이는 것은 대가가 아니라 목적이다.

규칙끼리 부딪히면 아래 순서로 정한다.

1. **정확성**이 먼저다. 짧게 쓰려고 사실을 깎지 않는다.
2. **완전성**이 그다음이다. 짧게 쓰려고 낱말을 생략하지 않는다. 생략한 문장은 짧아지지만 읽기 쉬워지지 않는다.
3. **짧음**이 마지막이다.

논증을 줄이는 규칙은 없다. 법률 문서에서 필요한 논증 단계는 그대로 두고, 그 단계를 담는 문장과 배치만 고친다.

## 1. 낱말

### 1.1 한 대상에 한 낱말을 쓴다

같은 것을 다른 말로 바꾸어 부르지 않는다. 문장에 변화를 주려고 동의어를 쓰지 않는다.

읽는 사람은 말이 바뀌면 대상도 바뀌었다고 읽는다. 그래서 동의어는 없던 구별을 만든다.

> 나쁨: 청구인은 이 처분의 취소를 구한다. 신청인의 주장은 세 가지다. 원고가 제출한 증거는…
>
> 좋음: 청구인은 이 처분의 취소를 구한다. 청구인의 주장은 세 가지다. 청구인이 제출한 증거는…

같은 규율이 절차 문서에도 걸린다. 같은 종류의 작업을 적을 때 늘 같은 문장 틀을 쓴다.

> 나쁨: 2. 볼트 두 개에 윤활유를 바른다. … 6. 볼트 네 개의 나사산에 소량의 기름을 도포한다.
>
> 좋음: 2. 볼트 두 개의 나사산에 소량의 기름을 바른다. … 6. 볼트 네 개의 나사산에 소량의 기름을 바른다.

### 1.2 한 낱말에 한 뜻을 쓴다

한 글 안에서 같은 낱말을 두 뜻으로 쓰지 않는다. 두 뜻이 필요하면 한쪽에 다른 낱말을 준다.

이 저장소에서 자주 어긋나는 자리는 '검토', '확인', '판단', '적용'이다. 각각을 어느 뜻으로 쓸지 그 글 안에서 정하고 지킨다.

### 1.3 흔한 낱말을 고른다

업계 속어, 은어, 지역어, 유행어를 쓰지 않는다. 아는 사람만 아는 낱말은 소통을 막는다.

뜻이 부분의 합과 다른 관용구도 쓰지 않는다. '손을 보다', '털어 넣다', '치고 나가다'가 그런 예다. 읽는 사람이 글자 뜻과 관용 뜻 중에서 골라야 한다.

### 1.4 약어를 줄인다

약어는 처음 한 번 풀어 쓰고 괄호에 넣는다. `e.g.`, `i.e.`, `etc.` 같은 라틴 약어를 쓰지 않는다. '예를 들어', '즉', '그 밖에'로 쓴다.

### 1.5 행위는 동사로 쓴다

명사로 만들지 않는다. 동사가 행위를 더 분명하게 말한다.

| 나쁨 | 좋음 |
|---|---|
| 검토를 수행한다 | 검토한다 |
| 반영이 이루어졌다 | 반영했다 |
| 확인을 진행한다 | 확인한다 |
| 삭제 처리한다 | 삭제한다 |
| 유닛의 제거 전에 전원을 끈다 | 유닛을 제거하기 전에 전원을 끈다 |

## 2. 문장

### 2.1 문장 하나에 주제 하나를 담는다

주제가 둘이면 문장을 나눈다.

> 나쁨: 사이드 스테이 조립체는 힌지로 이어진 접이 토글 두 개를 가지며 메인 기어 스트럿과 사이드 스테이 브래킷 사이에 힌지로 붙어 있다.
>
> 좋음: 사이드 스테이 조립체에는 접이 토글이 두 개 있다. 두 토글은 힌지로 서로 이어져 있다. 이 토글은 메인 기어 스트럿과 사이드 스테이 브래킷 사이에도 힌지로 붙어 있다.

### 2.2 문장을 짧게 쓴다

- **지시하거나 절차를 적는 문장**: 한국어 20어절, 영어 20단어를 넘기면 나눈다.
- **설명하는 문장**: 한국어 30어절, 영어 25단어를 넘기면 나눈다.
- **주석 문장**(괄호·각주에 넣는 설명): 한국어 30어절, 영어 25단어를 넘기면 나눈다.

수치보다 먼저 보는 신호가 있다. **서술어가 셋 이상이면 나눌 자리를 찾는다.** '~하고, ~하며, ~한 뒤, ~하여'가 이어지는 자리가 그 자리다.

쌍반점을 쓰지 않는다. 쌍반점은 아주 긴 문장을 허용한다. 쌍반점으로 이은 문장은 문장 둘로 나눈다.

### 2.3 낱말을 생략하지 않는다

짧게 쓰려고 성분을 빼지 않는다.

한국어는 주어를 빼도 문법에 맞는다. 그래서 두 자리에서만 규칙을 건다. **주어가 앞 문장과 달라지는 자리**와 **주어가 둘 이상으로 읽힐 수 있는 자리**에는 주어를 쓴다.

> 나쁨: 청구인의 주장을 검토했다. 이유 없다고 판단된다.
>
> 좋음: 청구인의 주장을 검토했다. 이 주장에는 이유가 없다.

조사도 빼지 않는다. '자료 제출 요구' 대신 '자료를 제출하라는 요구'로 쓴다.

### 2.4 능동으로 쓴다

행위자를 밝힌다. 행위자를 모를 때만 피동을 쓴다.

이중 피동을 쓰지 않는다. '되어진다', '보여진다', '불리워진다', '생각되어진다'가 그런 형태다.

| 나쁨 | 좋음 |
|---|---|
| 이 조항은 그렇게 해석되어진다 | 이 조항은 그렇게 읽힌다 |
| 오일과 그리스는 탈지제로 제거되어야 한다 | 탈지제로 오일과 그리스를 제거한다 |
| 검토가 필요하다고 판단된다 | 검토가 필요하다 |

### 2.5 지시는 '~한다'로 쓴다

늘이지 않는다. '~하도록 한다', '~할 필요가 있다', '~하여야 할 것이다'는 지시를 흐린다.

'~해야 한다'는 안전이나 불변식을 말할 때만 쓴다. 그 밖에는 '~한다'로 쓴다.

### 2.6 조건을 앞에, 지시를 뒤에 둔다

읽는 사람은 조건을 먼저 알아야 한다.

> 나쁨: 스위치를 NORMAL로 돌린다, 표시등이 켜지면.
>
> 좋음: 표시등이 켜지면 스위치를 NORMAL로 돌린다.

> 나쁨: 청구를 각하한다, 청구 기간이 지났으면.
>
> 좋음: 청구 기간이 지났으면 청구를 각하한다.

### 2.7 지시대명사의 대상을 하나로 만든다

'이', '그', '이것', '그것', '이는', '해당', '동'이 둘 이상을 가리킬 수 있으면 그 명사를 다시 쓴다.

> 나쁨: 핀을 시트에 잘못 끼우면 이것이 손상될 수 있다.
>
> 좋음: 핀을 시트에 잘못 끼우면 핀이 손상될 수 있다.

앞 문장 전체를 '이것'으로 받지 않는다. 무엇을 받는지 적는다.

> 나쁨: 덮개가 잠기지 않았는지 확인한다. 이것은 프로브를 손상시킬 수 있다.
>
> 좋음: 덮개가 잠기지 않았는지 확인한다. 덮개가 잠겨 있으면 프로브가 손상될 수 있다.

### 2.8 명사를 길게 잇지 않는다

관형 구성은 세 낱말까지 쓴다. 넷을 넘으면 조사나 절로 끊는다. 넷을 넘는 이름을 거듭 써야 하면 전체 이름을 한 번 쓰고 괄호로 축약형을 정의한다. 그 뒤에는 축약형만 쓴다.

명사를 이으면 그 사이의 관계가 사라진다. 읽는 사람이 관계를 복원해야 한다.

> 나쁨: 폐기물 처리 신고자 준수 사항 위반 여부
>
> 좋음: 폐기물 처리 신고자가 준수 사항을 위반했는지 여부

### 2.9 '의'를 연달아 쓰지 않는다

'A의 B의 C'는 관계가 정해지지 않는다. 하나를 절로 풀거나 조사를 바꾼다.

> 나쁨: 처분청의 재량권의 일탈의 판단 기준
>
> 좋음: 처분청이 재량권을 일탈했는지 판단하는 기준

## 3. 문단과 배치

### 3.1 문단 하나에 주제 하나를 담는다

주제가 바뀌면 문단을 나눈다.

### 3.2 첫 문장이 그 문단의 주제를 말한다

각 문단의 첫 문장만 뽑아 이으면 글의 뼈대가 되어야 한다.

### 3.3 문단은 여섯 문장을 넘기지 않는다

넘으면 나눈다.

### 3.4 정보를 점진적으로 준다

한 문장에 새 정보를 몰아넣지 않는다. 하나를 말하고, 다음 문장에서 그것에 대해 더 말한다.

### 3.5 핵심어를 다시 써서 문장을 잇는다

앞 문장의 핵심어를 뒤 문장에서 다시 쓴다. 대명사나 동의어로 바꾸면 연결이 끊긴다. 이것이 1.1과 같은 규칙의 문단 층 적용이다.

### 3.6 연결어로 관계를 표면에 둔다

'그리고', '그러나', '그래서', '그 결과', '동시에', '따라서'가 앞뒤의 관계를 알려 준다. 관계를 읽는 사람이 짐작하게 두지 않는다.

### 3.7 복잡한 열거는 수직 목록으로 쓴다

항목이 셋을 넘거나 항목마다 설명이 붙으면 목록으로 쓴다.

- 도입 문장 끝에 쌍점을 찍는다.
- 각 항목에 식별자를 붙인다. 절차는 번호를, 설명은 글머리표를 쓴다.
- 각 항목이 도입 문장에 그대로 이어지게 쓴다.
- 항목 끝에 쉼표나 쌍반점을 붙이지 않는다.
- 항목이 완전한 문장이면 마침표를 찍고, 아니면 찍지 않는다. 마지막 항목에는 찍는다. 갈리면 항목만 떼어 읽고, 주어와 서술어가 서면 완전한 문장으로 본다.
- 절차와 설명을 한 목록에 섞지 않는다.
- 목록 안에 목록을 넣지 않는다. 필요하면 괄호로 묶는다.

### 3.8 읽는 사람이 먼저 알아야 할 것을 먼저 둔다

기본 순서는 아래와 같다. 모든 글을 이 틀에 맞추지는 않는다. 순서를 바꿀 이유가 없으면 이 순서를 쓴다.

1. 결론, 현재 상태, 또는 해야 할 일
2. 읽는 사람에게 미치는 영향
3. 판단하고 검증하는 데 필요한 근거
4. 조건, 예외, 실패했을 때의 대응

### 3.9 수신자에게 필요한 만큼 설명한다

넷을 정하고 쓴다. 누가 읽는가. 읽고 무엇을 판단하거나 해야 하는가. 이미 무엇을 아는가. 어떤 상황에서 읽는가.

읽는 사람이 판단하고 행동하고 검증할 수 있으면 설명을 멈춘다. 작성자가 아는 양이나 들인 노력으로 분량을 정하지 않는다.

읽는 사람이 모를 수 있는 전제와 기반 지식은 함께 준다. 전에 전달한 적이 없으면 알고 있다고 가정하지 않는다.

## 4. 쓰지 않는 것

### 4.1 사고 과정을 쓰지 않는다

조사 중의 놀라움, 시행착오, 자기평가를 옮기지 않는다. 그 과정에서 확정된 사실과 필요한 조치를 쓴다.

> 나쁨: 하나를 고치려다 이전 계산이 모두 틀렸다는 사실이 드러났고, 내가 작성한 브리핑도 예외가 아니었다.
>
> 좋음: 기존 유량 계산에 오류가 있었다. 설계 문서와 브리핑이 모두 같은 계산을 썼다. 두 문서를 고쳐야 한다.

기억 노드와 결정 기록처럼 경위 보존이 목적인 글에는 재발 방지나 결정 근거에 필요한 경위를 남긴다. 그 경우에도 정리되지 않은 사고 과정과 감상은 뺀다.

### 4.2 서사화하지 않는다

판단, 결정, 실패를 이야기로 만들지 않는다. 아래가 그 장치다.

- 제목과 소제목에 비유, 반전, 결론의 예고를 넣는 것
- '가장 위험했다', '정확히 찍었다', '분명했다'처럼 읽는 사람의 평가를 미리 정하는 것
- '문제가 목표를 지웠다', '지적이 본체 작업을 밀어냈다'처럼 사물을 행위자로 만들어 인과를 연출하는 것
- 대조를 되풀이해 긴장을 높이거나 문단 끝을 교훈으로 맺는 것

작성자의 책임은 관찰할 수 있는 행위로 적는다. 확인하지 않은 사실, 적용한 기준, 선택한 조치가 그것이다. 놀라움, 자책, 조급함 같은 내면 상태는 원인의 증거가 아니면 쓰지 않는다.

사용자의 강한 어조를 산출물의 문체로 옮기지 않는다. 사용자의 표현을 인용하는 것은 그 문언 자체가 판단 근거일 때로 한정한다.

### 4.3 강조어로 중요성을 만들지 않는다

'정확히', '실제로', '바로', '그 자체', '결정적', '핵심적'은 필요할 때만 쓴다. 중요성은 결론의 위치, 구체적인 영향, 근거로 드러낸다.

### 4.4 추상적으로 쓰지 않는다

무엇이 어떻게 달라지는지 적는다.

> 나쁨: 온도가 다르면 경화 시간이 달라진다.
>
> 좋음: 온도가 오르면 경화 시간이 줄어든다.
>
> 더 좋음: 20°C에서 경화 시간은 2시간이다.

### 4.5 이미 없는 것을 덧붙여 부정하지 않는다

가장 강한 부정은 존재하지 않는 것이다. 그다음이 존재하는 것을 부정하는 것이다. 없앤 것을 설명하려고 그것을 다시 불러오지 않는다.

## 5. 정보의 거처

정본에는 사실과 근거와 계산을 완전하게 둔다. 다른 문서에는 그 독자에게 필요한 귀결과 정본 포인터만 둔다.

읽는 사람이 안정된 정본에 접근할 수 있고, 그 정보가 지금 문서의 판단에 필수적이지 않을 때만 줄인다.

아래는 문서 자체로 판단할 수 있어야 하므로 필요한 사실과 근거와 예외를 갖춘다. 포인터만 남기지 않는다.

- 외부 제출물
- 독립적으로 쓰는 매뉴얼
- 안전 불변식
- 테스트

현행 계약과 변경 이력을 구별한다. 변경 경위가 목적이 아닌 문서에 작업 일지를 옮기지 않는다.

코드 주석에는 코드만으로 알 수 없는 불변식과 현재 값의 이유를 적는다. 그 이유를 언제 누가 어떤 시행착오로 찾았는지는 커밋과 기억 노드와 결정 기록의 몫이다. 테스트 설명에는 보장하는 거동과 실패의 뜻을 적고, 결함 발견의 연대기를 적지 않는다.

## 6. 퇴고

### 6.1 의미를 먼저 고정한다

남의 글이나 자기 초안을 고칠 때는 아래를 먼저 뽑는다. 퇴고문은 이것을 바꾸거나 빠뜨리지 않는다.

- 행위자와 대상
- 사실, 원인, 결과
- 수치와 범위. '전부', '일부', 상한과 하한을 포함한다
- 조건과 예외
- 책임과 귀속
- 불확실성과 근거의 강도

뜻이 불분명하면 매끄럽게 추측하지 않는다. 원문이나 사용자에게 확인한다.

### 6.2 문장마다 점검한다

- 무엇에 관한 문장인지 한 번 읽어 알 수 있는가
- 주어와 대상이 구체적인가
- 독립된 결론이 문장으로 나뉘어 있는가
- 지시대명사가 가리키는 것이 하나로 정해지는가
- 같은 대상을 앞에서 부른 말과 같은 말로 불렀는가
- 명사로 만든 행위를 동사로 되돌릴 수 있는가
- 줄표나 쌍반점을 마침표로 바꾸면 더 분명해지는가
- 지우면 읽는 사람의 판단이나 행동이나 검증에서 사라지는 것이 있는가

마지막 물음에 구체적인 답이 없으면 지운다. 답은 있지만 지금 자리가 정본이 아니면 정본으로 옮기고 포인터만 남긴다.

### 6.3 범위를 넓혀 본다

새로 넣은 문구만 보지 않는다. 그 문구가 들어간 문장, 문단, 주석 블록, docstring 전체를 읽고 함께 다듬는다. 옆의 기존 문장이 같은 결함을 내면 그것도 고친다.

### 6.4 출력

사용자가 과정 설명을 요청하지 않았으면 퇴고 과정, 지운 문장, 이 규칙을 적용했다는 보고를 덧붙이지 않는다. 산출물에 필요한 전제, 불확실성, 검증 결과, 출처의 한계는 그대로 남긴다.

# 에이전트 사이의 글

서브에이전트에 파견문을 쓰거나 그 반환을 받는 작업에서 읽는다. `SKILL.md`의 규칙 전부가 여기에도 걸리고, 아래 넷이 더 걸린다.

## 왜 이 채널이 더 엄한가

**읽는 쪽이 물어볼 수 없다.**

사람은 모호한 문장을 만나면 되묻는다. 서브에이전트는 되묻지 않는다. 한 가지 읽기를 골라 확신을 갖고 진행한다. 그래서 모호함이 질문으로 드러나지 않고 **갈라진 작업**으로 드러난다.

오염의 경로는 셋이다.

- 수리자 A가 '포섭 누락'이라 부른 것을 수리자 B가 '논증 단계 결손'이라 부르면, 집계는 결함을 두 건으로 센다. 정족 계산이 그만큼 어긋난다.
- 심사자가 지적의 용어를 수리자와 다른 뜻으로 읽으면, 제기되지 않은 명제를 판정한다. 판정은 형식상 성립하지만 대상이 다르다.
- 파견문의 범위어가 열려 있으면 두 에이전트가 다른 양의 일을 한다. 그 차이가 산출물 비교에서 결함으로 읽힌다.

셋 다 검증이 잡지 못한다. 검증 자체가 오염된 텍스트 위에서 돌기 때문이다. 그래서 `SKILL.md` 1.1(한 대상에 한 낱말)이 이 채널에서 가장 무겁다. 파견문이 쓴 말을 반환도 쓰고, 반환이 쓴 말을 집계도 쓴다.

## 1. 범위와 좌표를 닫힌 형태로 쓴다

**범위**는 목록이나 수로 준다. '일부', '관련된', '대부분', '해당', '필요하면'은 받는 쪽이 정하게 두는 말이다.

> 나쁨: 관련된 파일들을 검토하고 필요하면 고쳐라.
>
> 좋음: 아래 세 파일을 검토한다. `계약/수리.md`, `계약/심사.md`, `references/장부.md`. 고칠 자리를 찾으면 고치지 말고 보고한다.

**좌표**는 축자로 준다. 경로, 절 번호, 행 번호, 항목 ID가 좌표다. 사람은 설명을 듣고 파일을 찾지만 에이전트는 추측한다.

> 나쁨: 그 설정 파일의 훅 부분
>
> 좋음: `.claude/settings.json`의 `PostToolUse` 절

수를 줄 때는 그 수가 상한인지 목표인지 밝힌다. '검토자 3기'는 세 기를 쓰라는 뜻이고 '최대 3기'는 다르다.

## 2. 지시와 정보를 가른다

파견문에는 두 종류의 문장이 있다. 에이전트가 **할 일**과, 그 일을 하는 데 필요한 **배경**이다.

배경 문단에 지시처럼 읽히는 문장을 두지 않는다. 에이전트가 그것을 실행할지 말지 결정해야 하고, 그 결정이 파견마다 갈린다.

> 나쁨: 이 산출물은 분량 상한이 5장이다. 상한을 넘으면 줄여야 한다. 아래 세 절의 인용 오류를 찾아라.
>
> 좋음: 아래 세 절의 인용 오류를 찾는다. (배경: 이 산출물의 분량 상한은 5장이다. 상한 조정은 이 파견의 임무가 아니다.)

파견문을 다 쓴 뒤 **배경을 빼고 읽는다.** 임무가 그대로 수행 가능하면 배경과 지시가 갈린 것이다. 수행 불가능하면 빠진 지시가 배경 안에 있다. 그것을 임무 절로 옮긴다.

같은 규율이 반환에도 걸린다. 보고의 「수행 기록」이나 「배경」 절에 결론을 숨기지 않는다.

## 3. 파견문이 반환 서식을 정한다

반환의 모양을 받는 쪽에게 맡기지 않는다. 파견문이 서식을 지정한다. 서식이 없으면 에이전트마다 다른 구조로 답하고, 집계하는 쪽이 그 차이를 내용의 차이로 읽는다.

지정할 것은 셋이다.

- **처분을 첫 낱말에 둔다.** 산문을 읽어 처분을 추론하게 하지 않는다. `DONE`, `상신`, `승인`, `기각`처럼 닫힌 어휘를 쓴다.
- **판정 어휘를 닫는다.** '대체로 통과', '일부 문제 있음' 같은 값을 허용하지 않는다. 값을 확정할 수 없는 경우에 무엇으로 읽을지도 함께 정한다.
- **산출의 자리를 지정한다.** 반환 텍스트가 아니라 파일이 정본이면 그 경로를 준다.

## 4. 부재를 명시하게 한다

**침묵은 '검사했고 없음'과 '검사하지 않음'을 가르지 못한다.** 집계하는 쪽은 둘을 구별할 방법이 없고, 대개 앞쪽으로 읽는다. 그래서 검사하지 않은 영역이 깨끗한 영역으로 집계된다.

파견문이 요구하고 반환이 답할 것은 셋이다.

- 슬롯을 채우거나 「없음」을 적는다.
- 무발견 영역을 이름으로 적는다. 「그 외 없음」 뒤에 무엇을 읽었는지 붙인다.
- 읽은 범위를 셀 수 있는 형태로 적는다. 절 제목 전건, 파일 경로 전건, 검사한 문장 수가 그것이다.

빈 목록 위의 전수 선언은 검증되지 않는다. 무엇을 읽었는지가 함께 서야 그 선언이 선다.

## 기계 강제는 없다

Agent 도구에는 훅이 걸리지 않는다. `PostToolUse`는 `Write`와 `Edit`만 본다. 그래서 파견문과 반환 텍스트를 저장 시점에 검사할 방법이 없다.

유일한 기계적 지렛대는 계약 파일이다. 파견문이 경로로 싣고 에이전트가 반드시 읽으므로, 발동 판단이 끼지 않는다. 반복되는 파견 유형에는 규율을 파견문에 되풀이하지 말고 계약 파일에 두고 경로로 가리킨다.

# do-dag 실행 체제

복잡한 작업을 방향성 비순환 그래프(DAG)로 분해하고 다층 파견으로 실행하는 체제다. 실행 절차의 정본은 `.claude/skills/do-dag/SKILL.md`와 동반 계약이다. Codex는 생성 사본인 `.agents/skills/do-dag/SKILL.md`를 읽는다.

## 발동 조건

do-dag는 확정된 정본이 있는 대규모 실행 작업에 사용한다. 목표와 품질 기준이 아직 열려 있으면 먼저 설계나 착수 협의를 진행한다. 에이전트가 만든 정본은 실행 전에 적대 검토를 거친다.

단일 에이전트가 안전하게 끝낼 수 있는 작업에는 DAG를 만들지 않는다. 분해, 격리, 검산, 병합 비용보다 접합면 위험 감소가 클 때 사용한다.

## 역할과 상태

메인은 국면을 만들고 오케스트레이터를 파견한다. 오케스트레이터는 파견표에 따라 작업 행을 운전한다. 작업자와 검증자는 각 행의 닫힌 계약을 수행한다. 싱크는 노드 산출을 병합하고 귀속과 접합면을 검사한다.

파견표는 실행 상태의 정본이다. 행 파일은 각 노드의 입력, 산출, 완료 기준, 예산을 담는다. 보고문이 파견표와 다르면 파일 상태를 다시 측정한다.

## 분해와 검산

전개는 요구를 원자 항목으로 나누고 각 항목을 실행 행에 연결한다. 검산은 다음 방향을 모두 본다.

- 행에서 정본으로: 행의 주장과 좌표가 실제 정본과 맞는가
- 정본에서 행으로: 정본의 요구가 적어도 한 행과 완료 기준에 연결되는가
- 행 사이: 생산자와 소비자의 파일, 형식, 시점이 맞는가.

예시 목록을 닫힌 요구 목록으로 사용하지 않는다. 정본 전체에서 실제 필요한 동작과 산출을 역산한다. 완료 기준은 형식의 존재뿐 아니라 실제 결선을 검사해야 한다.

## 격리와 병합

서로 다른 노드는 독립 작업 공간에서 실행한다. 한 노드의 산출이 다른 노드나 현재 작업 트리에 섞이지 않게 쓰기 집합을 제한한다.

병합 전에는 기준선, 귀속 파일, 변경 파일, 검증 결과를 다시 측정한다. 생성기 산출은 복사보다 현재 기준 트리에서 생성기를 다시 실행하는 편이 안전하다. 줄바꿈 정규화나 플랫폼 차이가 바이트 검사를 깨뜨릴 수 있기 때문이다.

결산 파일은 완료 신호와 재개 좌표를 함께 담는다. 결산은 보고문이 아니라 단계 원장이다.

## 게이트와 상신

게이트는 사용자의 판단이 필요한 시점에서 실행을 멈춘다. 작업자는 다음 조건에서 상신한다.

- 사용자 확정 문면의 내용이나 적용 범위를 바꿔야 한다.
- 불가침 자산을 수정해야 목표를 닫을 수 있다.
- 비가역 행위가 필요하다.
- 지급된 원본에 없는 사실을 발명해야 한다.

상신은 선택지와 추천을 함께 제공한다. 메인은 사용자 결정을 결정 파일에 기록하고, 영향받는 행 파일, 파견표, 불변식, 기준선, 진행 중 에이전트에 전파한다.

## 검증 체제

do-dag는 운전성, 정합성, 충족성을 구별해 검증한다.

- 운전성은 오케스트레이터가 파일과 명령만으로 행을 실행할 수 있는지 본다.
- 정합성은 행의 주장과 정본이 일치하는지 본다.
- 충족성은 모든 행을 끝냈을 때 목표의 요구가 실제로 닫히는지 본다.

검증런은 실제 파일과 실행 결과를 근거로 발견을 낸다. 수리 범위를 넘는 결함은 삭제하거나 축소하지 않고 검토전개 또는 상신 경로로 보낸다.

## 예산과 측정

모델, 노력, 토큰 예산의 현행 값은 `.claude/skills/do-dag/전거/파견단위.md`에서 읽는다. 렌더된 표나 기억 노드의 숫자를 정본으로 사용하지 않는다.

예산은 분해 시점의 설계 도구다. 완료된 작업이 예산을 넘었다는 사실만으로 산출을 폐기하지 않는다. 초과가 품질, 비용, 재개 가능성에 미친 영향을 따로 판정한다.

오케스트레이터가 계속 읽는 성장 파일은 전문 재독을 피한다. 검사 스크립트가 현재 파견 가능한 행과 진행 행만 선별 출력하게 한다. 선별 출력과 전체 검산은 같은 상태 술어를 공유한다.

## 스킬 개정

do-dag의 여러 문서에 같은 사실을 복제하지 않는다. 다중 참조 사실은 `전거/` 정본에서 고치고 생성기로 소비 위치를 갱신한다.

스킬 파일을 고친 뒤에는 전거 검사, 스크립트 테스트, 런타임 사본 동기화를 실행한다. 렌더 파일과 생성 사본을 직접 고치지 않는다.

# do-dag 반환 계약 표준화

## 맥락

do-dag 역할마다 완료·예외·상신 정보를 첫 낱말에 서로 다른 방식으로 넣고 있었다. 이번 업데이트는 공통 첫 줄과 역할별 확장 필드를 분리한다. 작업자·검증자·싱크·예외 처리·오케 교대가 같은 반환 문법을 사용한다.

`dag_check.py`는 파견문의 `반환:` 슬롯과 싱크 결산 상태를 검사한다. 완료된 구형 파견문에는 새 슬롯을 소급 강제하지 않는다.

## 터득한 것

처분과 상세 코드를 같은 첫 낱말에 넣으면 공통 판독기가 역할별 어휘를 알아야 한다. 첫 줄을 `DONE`, `예외`, `상신`처럼 닫고 상세를 다음 필드로 내리면 공통 판독과 역할 확장을 함께 유지할 수 있다.

한글 경로가 포함된 `git diff --name-only` 출력은 기본 설정에서 인용·이스케이프될 수 있다. 경로를 기계 처리할 때는 `core.quotepath=false`를 사용하고 복사 전후 해시를 대조한다.

## 작업 너머 시사점

공통 프로토콜은 최소 처분만 고정하고 역할별 정보는 명시 필드로 확장한다. 이전 산출물의 완료 상태를 읽어야 하는 검사는 소급 호환 경계를 함께 가져야 한다.
