`gpt-5.6-sol xhigh` 값은 사용자 확정 결정을 집행한 행별 이탈이다. 따라서 파견표와
재판독 작업자 행 파일은 고치지 않았다.

## 처분

- `전거/파견단위.md`의 노력 어휘에 `xhigh`를 추가했다.
- 같은 전거의 배정표에 `xhigh`의 자리를 추가했다. 표 밖 조합에는 행별 근거가 필요하다는 문면도 명확히 했다.
- `dag_facts.py --render`로 `references/배정.md`와 `scripts/dag_check.py`를 갱신했다.
- `test_dag_check.py`에 파견 직전 Codex `xhigh` 행의 회귀시험을 추가했다. 수정 전 시험은 같은 운전 발견으로 실패했고, 수정 뒤 통과했다.
- 런타임 사본 4파일을 생성기로 갱신했다. 사본 검사는 157파일에서 드리프트를 찾지 않았다.
- 파견표, 재판독 작업자 행 파일, 기존 `행/표.예외.md`는 바꾸지 않았다.

수정 뒤 제공된 검산 명령은 exit 0으로 끝났다.

```text
[dag_check] 무발견 (drive: 서식·어휘·칸 계약·폐쇄·수렴·순환·좌표 실재·게이트 결정·운전)
```

`do-dag` 스크립트 시험 8파일은 각 파일 직접 실행으로 모두 exit 0이었다.
`dag_facts.py --check`는 전거 85항목에서 무발견이었다. `quick_validate.py`는 스킬을
유효하다고 판정했다.

마커 명령은 하위 명령이 없어서 exit 1로 끝났다. 사용법 출력 외의 상태 변경은 없었다.

## 반증 의무

입력 검산 출력은 현재 검사기가 `xhigh`를 거부한다는 사실을 정확히 재현했다. 그러나
`gpt-5.6-sol xhigh`가 계약 위반이라는 결론은 사용자 확정 결정과 행별 배정 근거에
어긋났다. `references/배정.md`의 `xhigh` 변환 문장은 맞았고, 노력 어휘 표와 검사기의
누락이 결함이었다. 파견표의 `xhigh` 기입 자체에는 지적할 결함이 없다.
