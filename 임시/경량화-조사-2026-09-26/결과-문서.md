# 결과-문서: 경량화 2라운드 문서 단계

이 문서는 do-math 경량화 2라운드의 문서 단계 기록이다. 결과 파일 9개(K제품, K시험, A~F, 병합A)의 "필요한 문서 변경"과 사용자 결정 5를 스킬 문서에 반영했다. 결정 3·4·6이 바꾼 설명은 모든 스킬 문서에서 전수로 찾아 고쳤다.

- worktree `C:/math-worktrees/r2-int`, 브랜치 `r2-int`, 커밋 `5531d63`(부모 `5169fa0`)
- 고친 범위는 `.claude/skills/do-math/`의 Markdown 문서와 재생성한 `.agents/skills/do-math/` 미러뿐이다. Python 파일과 이음새 계약 문서는 고치지 않았다.
- 원문 파일은 모두 CRLF이며, 고친 18개 문서 전부에서 CRLF 줄 수가 전체 줄 수와 같음을 확인했다.
- 시험(run_tests.py, unittest)과 writing_flow.py는 실행하지 않았다(사용자 결정).
- 코드와 대조한 기준은 커밋 시점 worktree의 제품 코드다(`engine.DEFAULT_CONFIG`, `model_policy`, `record_schemas.config_schema()`, `observations.OPERATORS`, `session_slots`, `context_store`, `submission` 등).

### GLOSSARY.md
- 「작업 예산」을 인스턴스의 유일한 모델 동시성 예산으로 정의했다. 해당 역할들을 "작업 역할"로 명명했다.
- 「운영 예산」 항목을 「운영 역할」로 바꿔 다시 정의했다.
  - 범위: 후보 준비, 연구 계획, 의도 해석, 운영 점검, 유지보수와 실패 시 설치 복구.
  - 이 역할들은 슬롯을 예약하지 않고 역할 하한과 대상 요구로 고른 모델에 배정된다.
  - "운영 AI"를 같은 대상의 이름으로 정의했다. 문서들이 이미 "운영 AI"를 쓰고 있어 기존 용어를 정의로 흡수했다.
  - 호스트·공급자 한도는 면제되지 않는다고 적었다.
- 「모델 등급과 동시 세션 슬롯」: "작업과 운영의 슬롯은 분리"를 "작업 역할만 슬롯을 점유"로 고쳤다.
- 「관찰 규칙」: "사건·활성 시간"을 "카운터·반복 수·체크포인트 수·벽시계 시각"으로 고쳤다(결정 3).
- 「운영 점검」: "운영 예산의 AI 활동"을 "운영 역할의 AI 활동"으로 바꿨다.

   - 대신 "형태의 정본은 제출 검사이고, 문서와 다르면 검사가 정한다"를 명시해 불일치의 우선순위를 닫았다.
   - 필드 나열을 실제로 줄일지는 통합자·사용자의 판단으로 남긴다.
2. **운영-점검.md의 완료 판정 절(REV-09·REV-10, 결과-C)**: 반영할 곳이 없었다.
   - 운영 점검의 출력 스키마(`contracts.disposition_schema`)에는 `task_assessments`나 완료 증거 필드가 없다.
   - 문서에도 완료 판정 절이 없다.
   - 운영 점검 입력의 `supplied_record_ids`와 `blocked_actions`는 「공통 실행」에 적었다.
3. **`--describe`의 `response_fields`와 `reported_evidence`·`provider`(결과-E)**: 스킬 문서 어디에도 `--describe` 결과나 `describe()` 결과 필드를 서술한 곳이 없어 고칠 대상이 없었다. `grep describe`로는 학술자료의 `describe_source`와 초기화-운전의 어댑터 `describe()` 호출 언급만 나왔다.
4. **결과-A 0절의 운영 역할 상한 부재**: 문서에는 코드에 실제로 있는 제한만 적었다. 후보 준비·연구 계획은 역할마다 하나, live 운영 점검은 대상마다 하나다(모델과-실행예산 「우선순위와 실제 배정」). `intent_interpretation`·`maintenance`·비live `operational_review`의 상한 부재는 설계 판단 대상이라 문서에 규칙으로 적지 않았다.
5. **이음새 계약 문서 변경(K제품·K시험·B·C·D·E·F 결과의 `docs/do-math/검사-경량화-이음새-계약.md` 항목)**: 파견 지시에 따라 통합자 몫으로 두었다.
6. **운영-점검.md 27행의 "비활동"**: 점검 발동 사건 목록의 "비활동"은 결정 3의 제거 대상(활성 시간 출처)과 직접 연결되는지 코드로 확인하지 못해 두었다. `observations.py`에 활성 시간 신호는 없지만, 주기 관찰의 무응답을 가리키는 표현일 수 있다.
