## 목적 진술

사용자 요청에 따라 do-math 전체의 문서·역할 계약·실행 코드·시험을 검증하고 실제 결함을 수리한다. 수학 연구를 별도 인스턴스에서 자율 수행하고, attempt·explore·formalizer의 보존 작업을 peer와 독립 review를 거쳐 게시하며 organizer가 공유 지식을 정리하는 현재 목적을 유지한다. 정확한 노드 진술과 독립 Lean 증거에 따른 형식적 해결을 보존한다. 문서와 코드의 불일치, 데이터 보존·복구·동시 실행의 실제 실패, 시험이 놓친 동작을 검토한다. 기각과 무처분은 사용자 위임에 따라 세션이 근거를 재검토하여 처리를 결정한다.

## 불변식 목록

- 결론: 없음.
- 필수 논거: 없음.
- 필수 전거: 없음.
- 분량 상한: 없음.
- 수학 명제의 정확한 의미, 독립 심사, 보존된 연구 근거, 형식 증거의 검증 수준을 낮추지 않는다. 근거는 SKILL.md의 현재 연구 목적과 reference/evidence.md·reference/lean.md다.
- 새 인스턴스를 위한 현재 여섯 역할과 운영 인터페이스를 유지하고, 결함 수리에 필요한 연결된 코드·문서·시험을 함께 고친다. 실제 실행 중인 연구 인스턴스는 이 검증의 편집 대상이 아니다.
- graphify는 조회가 필요할 때만 사용하며 그래프 구축·갱신은 실행하지 않는다(AGENTS.md).
- 각 라운드 적용과 기각·무처분 재검토 뒤 `python -B -m unittest discover -s .claude/skills/do-math/runtime/tests -p test_*.py`를 실행하고 발견된 실패를 고친다. 시험 수리는 사용자 지시에 따른 라운드 사이 통상 편집으로 기록한다.
- 각 라운드 커밋 전에 do-math 생성 사본을 동기화하고 드리프트를 검사한다. 검증·기각 재검토·시험 수리의 계수는 구별하여 기록한다.
- 발견의 호출자 후속: 세션이 실제 원문·코드로 재검토하고 사용자 위임 범위의 문제는 처리한다. 산출물 밖의 확정되지 않은 정책은 창작하지 않는다.

## 모델 배정

사용자가 시작 전에 지정한 일정이다. 라운드 1은 mixed: 수리 claude-opus-5-5 high, 병합 claude-opus-5-5 low, 심사 gpt-6.1-sol medium. 라운드 2는 Astra 전용: 수리 gpt-6-astra high, 병합 gpt-6-astra low, 심사 gpt-6-astra medium. 표준 체급을 유지하며 정확히 두 라운드를 수행한다.

Claude Agent 도구가 없는 환경이므로 설치된 Claude CLI를 사용한다. 각 파견은 새 문맥으로 실행하고 지정 산출을 직접 저장한다. Codex는 CLI를 사용한다. 모델·노력과 실제 완료·오류를 기록한다. 모델을 임의 대체하지 않는다.
