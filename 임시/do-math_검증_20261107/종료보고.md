## 8. `_` 보조 스크립트 승격 후보

- `_prepare.py` — 파견문 템플릿 슬롯 채우기와 「읽지 않는 것」 추가 좌표. 공식 스크립트가 파견문 조립을 덮지 않는다. 승격하면 읽지 않는 것의 런 고유 좌표(런 기억 노드, 지시문 파일)를 정식 슬롯으로 둘 수 있다.
- `_wait_stable.py` — 비동기 Agent 산출의 완료 대기(전건 존재 + 60초 크기 불변). 공식 `wait_outputs.py`는 크기 0 초과만 보아 쓰는 도중의 파일을 완료로 읽을 수 있고, 이 하네스의 Claude Agent는 `run_in_background: false`에도 비동기로 떠 §5.6의 「Agent 호출의 반환이 완료 신호」가 성립하지 않았다.

## 9. 운영 기록 요지

- 사용자 기준 도출: 과거 대화·기억·커밋·설계에서 기준 40개(축 A~I)와 거부 방향 36건을 도출해 사용자 승인 뒤 기준 원문(`사용자기준.md`)으로 썼다. H3은 제외.
- 생성 사본 `.agents/skills/do-math`는 사용자 결정 (가)로 런 동안 재생성하지 않았다. 라운드 커밋은 미러 게이트를 예외로 두었다.
- 비동기 Agent의 완료 통지가 다음 사용자 메시지에만 붙어 세션이 멈췄다. 대기를 보조 스크립트로, 뒤에 사용자 지시로 background shell로 바꿨다.
- 안전 장치(`[reasoning_extraction]`) 중단이 수리·심사 파견에서 반복됐다. 세 경로를 차례로 막았다: gp-matrix 정의의 `omitClaudeMd: true`(재시작 뒤 효력), 파견문의 지시문 파일 열람 금지, `.claude/CLAUDE.md`를 루트 `CLAUDE.md`로 이동(`.claude/` 하위 파일을 읽을 때의 하위 디렉토리 적재 차단, 커밋 c31ea242). 이동 뒤 라운드 4~6에는 중단이 없었다. 라운드 3 심사는 기마다 2~3회 파견이 필요했다.
- 앞 라운드 기록의 누출 경로(런 기억 노드, 색인 줄, 라운드 커밋 diff)를 열람 금지에 더했다.
- 라운드 4와 5 사이 전체 시험은 시스템 메모리 부족으로 셸이 정리되어 끝나지 않았다. 사용자 선택으로 라운드 5 적용 뒤 재실측이 함께 덮었다.
- 라운드 5·6은 사용자 지시로 모든 역할을 Fable 5.1로 돌렸다.
- 런 뒤 처리(사용자 결정): 사본 재생성과 실행 중 인스턴스의 실행기 재기동, 브로커 교체는 실행 중 CLI 턴과 컴파일이 없는 때로 미룬다.
