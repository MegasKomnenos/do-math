사용자는 do-math 전체를 먼저 이해하고, 기존 형식·절차 재검토와 관련 자료를 대조한 뒤 필요한 수리를 코드·계약·도구·검증 전반에 직접 반영하도록 요청했다. 단순성은 필요한 범위와 깊이를 확보한 뒤의 선택 기준이다. 기존 연구 인스턴스의 재개나 목표·예산 변경은 이번 수리의 대상이 아니다.

독해 대상은 최종 스킬 문서 19개의 원문을 합친 묶음이다. 파일 경계 표시는 독해 좌표를 위한 것이며 실제 배포 문서 본문을 바꾸지 않는다. 각 역할의 공통 필수 문서와 전용 계약, 사용자 운영 안내와 독립 운영 계약을 모두 포함한다. 현행 규칙은 스킬 내부에서 닫혀야 하며 외부 감사 보고서를 필수 입력으로 요구하지 않는다.

독자는 실행별 입력의 submission_contract에서 실제 작업 공간, 검사 명령, 주 스키마와 확장 스키마, 검사 입력, 적용되는 파일 한도를 회수할 수 있어야 한다. 제출 전에 주 응답을 파일에 만들고 공통 검사기를 실행하며, 구조·참조 오류를 자기 권한으로 고치고 다시 검사한다. 의미를 바꾸는 수리는 저자의 판단으로, 공유 도구 결함은 실행 구성의 소유자에게 정확한 오류와 재현 자료로 돌린다. 검사 출력은 실제 도구 실행 기록으로 보존된다. 통과 영수증의 존재를 따로 강제하는 절차를 만들지 않는다.

검사 범위는 주 JSON, 허용 확장 가족과 필드, 정확한 참조·등록 종류, 계획 모집단과 완료 기준, 검토 단계의 공개된 할당, 체크포인트·관찰 파일, 실제 수집 범위와 한도다. 생산자 검사는 제공된 고정 입력에 관한 검사다. 적용 직전 현재성·권한·생성 계보, Lean·수학 의미·목표 판정은 별도로 유지한다. 정상적으로 회수되는 원자적 응답을 부분 적용하는 새 체계는 도입하지 않는다. 이전 본문·파일·체크포인트를 재사용해 오류를 수리할 수 있다는 점을 설명한다.

파일 보존에서 disposable .scratch 영역과 필수 근거를 구별한다. 근거로 사용할 파일은 수집되는 경로에 둔다. 수집 실패나 원자료 읽기 실패를 성공·자료 부재로 바꾸지 않는다. 독립 운영은 연구 인스턴스 workspace와 자기 검사 명령의 workspace가 다르므로 정확한 실행 위치를 제공해야 한다.

과제·요청·이전 실행의 큰 이력은 원문 참조로 전달하고 현재 계약·배정 신원은 보존한다. 원문 참조를 빈 값이나 의미 요약으로 읽지 않으며 판단에 필요한 원문을 먼저 회수한다. 입력 초과가 보류된 동일 계약 검토는 같은 조건에서 즉시 반복하지 않는다.

현재성은 사전 선언에 더해 실제 반환에서 드러난 지식과 원자료의 의존을 원래 입력 판본과 대조한다. 현재 지식의 ID·제공 파일 경로와, 제공된 불변 과거 산출 참조를 구별한다. 과거 이력의 참조가 현재 의존으로 자동 승격되지 않는다. 무관한 원자료 교체는 검토를 무효화하지 않는다.

실패한 실행 요청은 오류·산출·인계와 함께 보류하며, 독립 작업을 계속한다. 진단 후 재실패, 운영 진단 실패와 국소 실행 기한을 사용자 정지·전체 실행 기한·공유 상태 문제와 구별한다. 일반 resume은 이미 소진한 실패 요청을 그대로 되살리지 않는다. 고정 질문 조사를 더 재시도하지 않는 처분은 실행 미완료를 원 검토 자리에 전달해야 한다.

부수 통찰은 등록된 종류와 실제 근거를 갖춘 후보다. 파일 원자료의 출처와 지식 의존성을 구별하며, 후보의 수신을 K 인증으로 확대하지 않는다. 현재 검토 단계의 비공개 통찰과 결과는 독립 입력 경계를 지킨다.
