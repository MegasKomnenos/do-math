사용자는 do-math 전체 이해, 기존 형식·절차 감사의 비판적 재검토, 필요한 수리의 전 영역 직접 반영을 요청했다. 이 원고는 수리 결과와 작업 기억의 두 문서 원문을 묶는다. 결과 문서는 기존 재검토의 우선순위와 수리된 실행 경로, 실제 증거의 위치, 의도적으로 유지한 원자적 적용과 검증 한계를 설명한다. 기억 노드는 사용자의 범위·경중 교정, 순서 있는 전수 읽기, 규칙 재사용과 원 입력 판본에 대한 실제 의존 결박, 실패의 자동 재생성 방지, 대역과 실호출 증거 구별을 후속 세션에 전달한다.

원래 스킬은 비캐시 파일 102개, 20,830줄을 먼저 읽고 나서 기준 문서와 재검토를 읽었다. 기존 baseline 전체 회귀는 351개 중 350통과·1건 Windows 심볼릭 링크 권한 건너뜀이다. 신규 결함은 수리 전 실패로 재현했다. 최신 집중 검증 27개는 통과했고, 전체 회귀는 고정 사본에서 진행 중이다. 원고에 아직 얻지 않은 전체 통과 수를 쓰지 않는다. 최종 집계와 판본·로그는 수리-검증.json을 정본으로 둔다. 실제 Codex 작업자는 검사 실패 1회와 성공 2회를 수행했고, 마지막 JSON과 파일 해시가 수신된 값과 일치했다. 실제 호출은 한정한 유지보수 경로 하나이며 전 역할의 공급자 성공률이나 장기 수학 연구의 품질을 측정하지 않았다.

수리 범위는 주 JSON·확장 스키마와 읽기 전용 제출 검사, 파일 한도와 scratch, 정확한 참조와 등록 종류, 실제 KN·과제·source 의존의 원 snapshot 결박, 과거 참조와 현재 의존 구별, 큰 task/action/복구 입력의 exact catalog 전달, 실패 요청 보류와 명시적 재진단, 고정 질문 미완료의 원 검토 자리 인계, 종료 대상과 권한 철회 뒤 늦은 응답의 보존이다. 모든 의미·권한 검사를 생산자 안에 복제하거나 정상 본문·부수 산출의 부분 적용 체계를 도입하지 않는다. 별도 수학 승인·Lean·현재성·계보의 수신 경계를 유지한다.

원자료는 .claude/skills/do-math의 현행 코드·계약, docs/형식과-절차.md, 임시/do-math-format-procedure-audit-20260916/재검토.md, repair의 읽기 manifest·RED 및 GREEN 로그·실호출 JSON과 문서 독해 기록이다. 결과와 기억은 구현을 정본으로 대조하며 과거 감사의 판단을 자동 정답으로 삼지 않는다. 기존 사용자 수정, 병행 세션의 모델별 운영 슬롯 3개 변경과 실제 연구 인스턴스는 이번 커밋에 새 조치로 귀속하지 않는다.
