# do-math 검증 종료 보고

## 종료와 계수

mixed 표준 6라운드를 마쳤다. 수리·병합은 Claude Opus 5.5, 독립 심사는 GPT-6 Astra를 사용했다. 공식 종료 사유는 **판정 순서 3항: 라운드 수 6이 상한 6에 도달**한 것이다. 마지막 라운드에도 적용이 있었으므로 결함이 모두 사라졌다는 종료는 아니다.

공식 제기는 63개 원항목, 병합 후 심사 대상은 53개다. 공식 수리는 22개 심사 대상이며, 묶음 구성 항목을 각각 세는 장부의 적용은 **28행**이다. 기각·무처분 31개 심사 대상 전부를 메인이 다시 읽어 27개를 전부 또는 일부 반영하고 4개는 유지했다. 직접 회수는 원항목 31행에 해당하며 공식 적용 계수에 섞지 않았다. 별도 전체 독해에서 고친 문장과 시험 대기 수정도 공식 적용 계수 밖이다.

## 잔여와 기각 보관

대기 중인 상신·미적용 수리 확정·전달·결번은 없다. 원 처분을 유지한 네 대상은 다음과 같다.

- R2-12: Lean 실행 주체와 cwd가 잘못됐다는 주장은 원문과 맞지 않았다.
- R3-09: 운영 문서의 전면 재배치는 고유 계약을 이동시키는 비용에 비해 실익이 작았다. 반복 예시와 설정 정의는 별도로 줄였다.
- R5-09: 문서 전달 규칙과 실제 파일 접근 감시는 다른 보장이므로 한정을 유지했다.
- R6-01: 현행 구현으로 만든 증거 인스턴스의 조회를 지원하는 두 줄은 유지했다. 폐기된 이전 구현과의 호환 금지를 이 상태까지 확대할 근거가 없으며, 실제 두 증거 인스턴스의 status가 정상임을 확인했다.

R5-06에서는 common.md의 반복만 덜고 계획·연구의 행동 지점에 있는 검토 필요성·비승계 조건은 유지했다. 세션 도중 입력의 실시간 감지, 완료 상태의 자동 재개, 검토 기록의 부분 대체는 이번 정비에서 새 기능으로 만들지 않았다.

기각·무처분 원문과 각 심사 근거는 [1라운드](기각보관/do-math-라운드1.md), [2라운드](기각보관/do-math-라운드2.md), [3라운드](기각보관/do-math-라운드3.md), [4라운드](기각보관/do-math-라운드4.md), [5라운드](기각보관/do-math-라운드5.md), [6라운드](기각보관/do-math-라운드6.md)에 보존한다. 직접 판단은 [장부의 운영 기록](장부.md)에 있다.

## 자체 처리와 승계

0단계 신호 4를 자체 처리했다. Claude Agent 도구가 없어 같은 Opus 5.5를 CLI 독립 세션으로 실행했다. 모델·노력·입력·정족은 유지했고 프로세스 종료와 공식 완료 대기, 산출 검산으로 확인했다. 되돌릴 수 있는 운송 선택이며 사용자 확정이나 제품 계약은 바꾸지 않았다.

심사 자리의 승계는 R1-06(M-0597·M-0601), R1-11(M-0598), R1-13·R1-M2(M-0600), R2-M3(M-0599·M-0601), R6-02(M-0599), R6-05(M-0599·M-0600)다. 기록 좌표와 의미는 장부 신호 처리 절에 있다. R4-04의 한 심사자가 남긴 승계 기록은 최종 무처분을 수리로 바꾼 것이 아니며 공식 적용으로 세지 않았다. 세션의 승계 전환은 없다.

신호 2·3의 연속 조건은 성립하지 않았다. 사용자에게 답을 받아야 하는 상신은 없었다. 런 도중 사용자가 “계속”이라고 지시해 기존 배정을 유지했다.

## 마지막 라운드 결산

6라운드는 제기 5행 중 적용 2·기각 3이다. 수리확정·무처분·상신·전달·결번·병합·제기 잔여는 모두 0이다. 공식 적용 이력은 9·7·5·2·3·2이며 적용 0 연속은 0회다. 하한 2·상한 6·연속영 1을 변경하지 않았다. 기각 셋 중 중복 정리 둘은 심사 근거를 반영해 직접 회수했다.

## 앵커와 비교한 변경

동결한 정본 15파일 중 13파일을 수정했다. 2867행에서 2810행으로 **57행 감소**했고 Git diff는 112행 추가·169행 삭제다. 새 제품 파일이나 계층은 만들지 않았다. research.md와 tests/test_state_write.py는 변경하지 않았다.

- runner.py: 미설정 CLI 공급자를 기존 기동 실패 경로로 처리하고, 지운 입력 파일의 오류가 상태에 남지 않도록 현재 순회의 오류만 기록한다.
- check.py: 깊은 JSON의 재귀 오류를 공식 진단으로 반환하고 중복 오류 경로를 없앴다. NUL 경로를 파일 처리 전에 거부한다.
- cli_adapter.py: 시계가 뒤로 간 세션의 날짜 추측을 기존 미확인 경로로 넘긴다.
- test_runner.py·test_check.py·test_cli_adapter.py: 실제로 재현한 오류의 회귀 확인을 더했다. Windows 실제 프로세스·Git 시험의 대기 상한을 12초에서 60초로 조정하고 미사용 import를 지웠다. 제품의 세션 시간 정책은 바꾸지 않았다.
- SKILL.md·RUNTIME.md·CLI.md·protocol.md: 설정 정본을 모으고 낡은 기동 예시, 중복 명령·표·구현 전 설명을 줄였다. 현재 상태·정지·설정 읽기 시점·실패 사건·검사 범위를 코드와 맞췄다.
- common.md·plan.md·review.md: 사용자 허가·보증 수준, 작성 중 계획 ID, 검토의 상충·대체·인정, 결함 근거의 후속 탐색, 실패 뒤 재시도를 서로 맞췄다. 실행기에 새 수학 판정 장치는 넣지 않았다.

.agents/skills/do-math는 공식 생성기로 동기화했다. graphify는 갱신하지 않았다. 앵커 제거 뒤에도 최초 라운드 커밋 9315768d의 부모와 최종 커밋을 비교하면 전체 변경을 복원할 수 있다.

## 용어 주의 승격 후보

GLOSSARY에 승격할 확정 후보는 없다. 빈 대체 울타리의 삭제 여부를 심사자들이 다르게 읽은 사례는 조각 계약의 예시 후보이며, 이 작업에서 검증 도구나 공통 계약을 바꾸지는 않았다. 공식 적용 행과 병합 후 심사 대상은 이 보고에서 명시적으로 구별했다.

## 보조 스크립트 승격 후보

확정 후보는 없다. _prepare.py는 이번 런의 동결·배정·파견문 슬롯을 작성하고, _dispatch.py는 Windows CLI의 병행 실행·UTF-8 입력·완료 반환을 처리했다. _direct2.py는 공식 적용 후 사용자 지시에 따른 직접 편집을 실행했다. 공식 파서·집계·적용을 대체하지 않았다. 운송 코드의 재사용 여부는 별도 도구 정비에서 판단할 수 있으며 제품에 넣지 않았다.

## 운영과 검증

매 라운드 원본 15파일을 동결 사본에서 읽고, 수리 4기·독립 심사 3기·정족 3을 유지했다. Claude는 수리 high·병합 low, Astra는 심사 medium을 명시했다. 런 이전의 맥락과 사용자 확정은 기준 원문으로 제공했다. 일부 수리자는 접근 가능한 기억 노드에서 앞 라운드 판단을 읽었다고 기록했다. 이전 라운드 장부·심사 산출은 파견 지급물로 주지 않았다.

1라운드 수리 한 기의 필수 작문 참조 누락은 같은 모델로 1회 보완했다. 4라운드 첫 네 호출은 공급자 한도 429로 산출을 못 냈다. 이를 0항목으로 세지 않고 해제 뒤 같은 네 파견을 실행했다. 완료 대기 스크립트의 만료 코드가 문서의 3과 달리 1인 경우에는 대기를 다시 실행해 완료를 확인했다. 원고 전체 독해도 별도로 수행해 원문·코드로 확인한 문제만 문서에 반영했다.

최종 코드의 **22개 시험이 32.582초에 통과**했다. 이후 변경은 문서뿐이다. 미러 검사 185파일, 로컬 Markdown 링크 69개, diff 공백 검사를 통과했다. 일곱째 전체 독해는 최종 문서 8개를 읽었고 메인이 원문과 대조해 수용했다. 근거 전파 문맥 연결, 라이브러리 부재로 형식화할 수 없는 경우의 판단 범위, goal.md 표현에 이후 조건을 포함하는 규칙은 기존 문맥으로 해석돼 추가 반복을 넣지 않았다. 공급자 누락·깊은 JSON·시각 후퇴·삭제된 입력 오류·NUL 경로는 원본 재현이나 수정 후 실제 진단으로 확인했다. 이번 런에서 새로운 수학 목표를 실제 모델과 Lean으로 처음부터 완주시키지는 않았다.

동결문·장부·이 보고·기각 보관·각 라운드 기억 노드는 Git에 보존한다. 마지막 라운드 커밋 뒤 스킬 규정에 따라 앵커·라운드 작업 디렉토리 제거를 시도했으나 자동 승인 검토가 `blocked by policy`로 차단했다. 원본 15파일과 보존 문서 및 삭제 대상의 절대 경로를 별도로 확인하고 일곱 고정 경로만 지정한 명령도 같은 사유로 거부됐다. 다른 수단으로 우회하지 않았으며 **앵커와 라운드1~6은 로컬에 남아 있다**. 제품 수정·검증·종료 판정에는 영향이 없다. 이 임시 자료, 런 루트의 _ 파일과 .codex/writing-flow의 독해 원자료는 Git 제외 로컬 자료이며 장기 보존 근거로 삼지 않는다.
