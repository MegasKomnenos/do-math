```

```

### 영향
JSON 문자열 `"\u0000"`은 유효한 JSON이고, `json.loads`는 이를 NUL 문자로 읽는다. 연구 세션이 `output/output.json`의 `results[0].exposition`에 `"a\u0000b.md"`를 쓰면 `local_file`이 이 문자열을 받는다. 문자열은 59~61행의 상대 경로 조건을 모두 통과하고, 62행 `root.joinpath(*parts.parts).resolve()`에 도달한다. 이 호출은 `ValueError`를 던진다. Python 3.12.10(Windows)에서 실측한 결과는 `ValueError stat: embedded null character in path`다. `references[].file`에 NUL을 담아도 86행에서 같은 경로를 탄다.

`check_session`(267~270행)은 `Invalid`, `OSError`, `UnicodeError`만 진단으로 바꾼다. 그래서 이 `ValueError`는 진단이 되지 못하고 함수 밖으로 나간다. 그 결과 두 곳이 깨진다.

첫째, 세션이 실행하는 공식 검사 명령은 JSON 진단 대신 traceback을 낸다. 세션은 무엇을 고칠지 알 수 없다.

둘째, 실행기는 `finish`에서 `check_session(session)`을 예외 처리 없이 호출한다(runner.py 379행). 그래서 예외가 `collect` → `tick` → `run`으로 올라가 실행기 프로세스가 끝난다. 이때 그 세션의 상태는 반영도 실패도 아닌 채로 남는다. 사람이 실행기를 다시 띄우면 `collect`(runner.py 456~480행)가 같은 세션에 `finish`를 다시 부르고, 같은 예외로 또 멈춘다. 재검사 실패를 `session_failed`로 계획에 넘기라는 불변식 7과, 재기동 뒤 남은 산출을 처리하라는 160행이 둘 다 지켜지지 않는다. 인스턴스는 사람이 세션 폴더를 직접 손볼 때까지 진행하지 못한다.

`check_session`에서 `ValueError`를 넓게 잡으면 프로그래밍 오류까지 삼키게 된다. 그러면 protocol.md 277행의 "프로그래밍 오류까지 삼키지는 않는다"가 깨진다. 그래서 모든 호출자가 지나는 `local_file`의 경로 조건에서 NUL을 거절하는 것이 원인 자리의 수정이다. 시험 한 줄은 이 실패를 고정한다. 수정 전에는 그 시험이 `ValueError`로 오류가 나고, 수정 후에는 진단 문구가 맞아 통과한다.
