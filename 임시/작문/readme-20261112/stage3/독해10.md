# 독해 10: 처음 읽는 영어 모어 화자 수학자의 독해

읽은 문서(이 순서로): `C:\math\README.md`, `C:\math\docs\do-math\first-run-parking-unimodality.md`(아래 "first-run"), `C:\math\docs\do-math\running.md`(아래 "running"), `C:\math\임시\작문\readme-20261112\stage3\zenodo-description.md`의 "## Description" 절(아래 "Zenodo"). 문서는 수정하지 않았다.

## 1. 이해한 것

1. **do-math는 서로 접촉하지 않는 AI 대화 여럿이 파일만 주고받으며 명제 하나를 증명하거나 반증하는 체계다.** 각 세션은 새 대화이고, 앞 세션을 기억하지 못하므로 출판된 기록이 연구의 기억 구실을 한다.
   - README: "The sessions have no contact with one another. Each is a new Claude Code or Codex conversation that knows nothing of the others; what a session produces is handed on as files"
   - README: "the records are the research's memory from one session to the next"

2. **기록 하나는 세 세션을 거쳐 만들어진다.** 생산 세션이 일하고, peer가 그 작업 파일로 기록 후보를 쓰고, review가 후보를 생산 세션의 파일과 대조해 주장마다 지위를 매긴다. 출판된 기록은 고치지 않고, 나중 판단은 "finding"으로 덧붙인다.
   - README: "Every record is produced in three stages, each by a different session."
   - README: "If the review judges the work worth keeping, the record is published with that assessment attached, and it is never edited afterwards."
   - Zenodo: "Published records are never changed; later judgments attach to them."

3. **사람은 명제와 설정, 그리고 "standing input"(이후 세션 모두에게 전달되는 지시)만 준다.** 세션을 직접 띄우지는 않는다. "operator"라는 AI 대화가 실행을 꾸리고, "runner"라는 프로그램이 세션을 띄운다.
   - README: "An AI conversation called the operator sets up the run from the user's statement and settings and operates it on the user's behalf. A program called the runner then launches sessions as the work requires"

4. **연구 대상은 명제의 그래프다.** root(증명할 원래 명제)가 첫 node이고, 다른 node는 review를 거친 함의 관계(relation)로만 들어온다. runner는 승인된 관계를 명제논리가 허용하는 모든 방향으로 전파한다. 어떤 node의 증명이 root 해결에 기여하는 사슬을 "route"라 부르고, 반증만 기여하는 node는 root의 필요조건이다.
   - README: "Every node other than the root enters through a **relation**, a reviewed implication between nodes."
   - README: "a proof of Q together with "Q implies P" proves P, and a refutation of K together with "P implies K" refutes P"
   - README: "a node is a necessary condition of the root when only its refutation can contribute."

5. **역할은 여섯이다.** 생산 역할 셋(attempt, explorer, formalizer), 처리 역할 둘(peer, review), 정리 역할(organizer). attempt는 일을 배정받지 않고 frontier·index·board를 읽고 스스로 node와 그 "section"을 고른다. 예외는 formalizer로, runner가 요청한다.
   - README: "An attempt is handed no node and no task."
   - README: "the one exception is formalization, which the runner requests for an accepted informal proof or refutation that can reach the root."

6. **"informally proved"는 사람의 심사도 증명 검사기의 검사도 받지 않았다는 뜻이다.** AI review 세션이 사람이 읽는 증명을 승인했거나, 승인된 증명에서 관계로 유도됐다는 뜻일 뿐이다. 실행이 끝나려면 review 세션이 Lean 증명을 다시 컴파일하고, 공리를 감사하고, 명제와 대조해야 한다.
   - README: "it was checked by an AI review session reading the candidate against the producer's retained work, not by a person and not by a proof checker."
   - README: "A node is **formally proved** only after a Lean proof has passed three checks that the review session carries out itself."

7. **계산 보조 단계는 두 종류로 나뉜다.** 엄밀한 계산(정확한 정수 연산, 구간 연산, 방향 반올림)과, 미리 가정한 오차 모형 아래의 binary64 계산이다. 둘째 종류에 기대는 결과는, 그 모형을 받아들이지 않는 독자에게 미증명이다.
   - README: "a reader who does not accept an assumed error model should treat the results that depend on it as unproved."

8. **첫 실행의 문제.** 길이 n인 주차함수를 최대 변위 ℓ로 센 수 b(n, ℓ)의 수열 b(n,0), …, b(n,n−1)이 모든 n에서 단봉이라는 Celano 외의 추측 6.5다. 양 끝값은 n!과 nⁿ⁻²이다. 이 두 값은 내가 직접 확인했다.
   - first-run: "the endpoints are b(n, 0) = n! and b(n, n−1) = nⁿ⁻²."

9. **root는 2026년 11월 11일 16:14(한국 시각)에 informally proved가 되었다.** route는 둘이다. 첫째는 "하강 뒤 상승"을 가운데 첨자 m = ⌈n/2⌉ 기준으로 네 경우로 나누어 각각 배제한다. 둘째는 하강하는 자리에서만 요구하는 조건부 로그 오목성으로 단봉성을 얻는다. 두 route 모두 "가운데 아래에서는 하강이 없다"는 명제를 지나므로 서로 독립인 확인이 아니다. 그 명제의 마지막 전제(node pair-beats-capped-threshold)를 기록 r5909c9e7이 증명했다.
   - first-run: "Both routes therefore pass through that statement, and it was the last part to close."
   - README: "The two routes are not independent confirmations; both pass through one statement"

10. **한계.** 심사자는 모두 AI다. 일부 단계가 가정된 오차 모형의 binary64 계산에 기대고, n ≤ 20000까지의 유한 검증도 입력으로 쓴다. root에는 Lean 증명이 없다(11월 9일부터 형식화 일시 정지). Lean 증명이 있는 것은 필요조건 node 하나(r0af7f414)뿐이고, 그것은 root를 열어 둔다.
    - README: "No person has refereed the records."
    - first-run: "the certification that the root holds for all n ≤ 20000 (record r15df76b5, 8 November)"
    - README: "The node is a necessary condition of the root: it states a limit that unimodality for every n implies, so its refutation would have refuted the root, while its proof leaves the root open."

11. **실행 중 개입이 있었다.** 사용자와 operator가 standing input, 설정 변경, 소프트웨어 변경, 세션 종료, 질문 직접 배치로 개입했고, first-run이 그 표를 준다. 그중 하나는 외부 AI 세션이 보고한 분해를 전달한 것이다.
    - first-run: "reported by an AI session outside the instance at the user's request"

12. **출판 증거와 확인 경로.** knowledge/ 디렉터리가 Zenodo에 있다(concept DOI 10.5281/zenodo.24110810, v2는 300기록, v3는 340기록). 확인하려면 index.md → frontier.md → r5909c9e7과 그 review/feedback.md → 그 증명이 쓰는 기록 순으로 따라간다. 세션의 대화와 작업 파일은 공개본에 없다.
    - README: "To check the result, open `index.md`, go to `frontier.md` for the root's two routes and the records they cite, open record r5909c9e7 with its `review/feedback.md`, and continue into the records its proof uses."
    - README: "The producing sessions' conversations and working files are not in `knowledge/`"

13. **직접 돌리는 법.** Python 3.12+, Git, Codex CLI나 Claude Code CLI, Lean 4(필수)가 필요하고, Windows에서만 실전 검증됐다. root.md와 settings.json을 쓰고 `runner.py init`, `start`, `status`를 실행한다. 세션은 권한 확인 없이 내 계정으로 파일과 명령에 접근하며, 운영체제 샌드박스가 없다. 실행을 끝내려면 `stop` → 세션마다 `kill-session` → runner 프로세스 종료 순으로 한다.
    - running: "Sessions run unattended with file and command access under your account"
    - running: "To end a run before the root is formally settled, take three steps in order."

14. **검증되지 않은 것.** 메커니즘이 연구의 질을 바꾸었는지, 비용, review가 주장을 기각·수정한 빈도는 측정되지 않았다.
    - first-run: "the run shows only that they were exercised at this scale."

## 2. 읽기 어려웠던 자리

### README

1. **README, 첫 표 "State of the root" 행**: "Several steps, which the root depends on, rest on binary64 computations with error models assumed in advance."
   쉼표로 감싼 비제한 관계절이라 "root가 기대는 단계들이 (모두) binary64에 기댄다"처럼 읽힌다. 영어로는 "Several steps on which the root depends rest on …"이 자연스럽다.

2. **README, 첫 표**: "| State of the root |" / "every record and every implication on the two routes to the root"
   "root"와 "route"가 정의되기 전(정의는 "Instances, roots and nodes" 절)에 표 머리에 나온다. 처음 읽을 때 "root"가 무엇인지 몰라 멈췄다.

3. **README, 첫 표 "Formal proof" 행**: "One necessary condition of the root has a Lean proof, which leaves the root open."
   "which"가 Lean 증명이 root를 열어 두는 원인인 것처럼 읽힌다. 뜻은 "그 증명이 있어도 root는 열려 있다"일 것이다.

4. **README, 첫 표 머리**: "| At a glance | |"
   둘째 열 머리가 비어 있다. 사소한 일이다.

5. **README, 첫 표와 첫 운전 절의 자리 표시자**: "`[placeholder: version 3 DOI]`" 외 여러 곳
   공개 README에 미완성 표지가 그대로 보인다. 같은 v3에 대해 Zenodo 설명문은 이미 "taken on 12 November 2026 at 23:25 Korean time … it holds 340 records"라고 확정해 두었으므로, 문서 사이에 단계 차이가 있다.

6. **README, "How the research is organized" 앞 개요**: "No session assigns work to another. A session in the first stage reads the knowledge base and decides for itself what to work on; the one exception is formalization, which the runner requests"
   "No session assigns work"의 예외처럼 놓였지만, runner는 세션이 아니므로 예외가 되지 않는다. 실제로는 "스스로 고른다"의 예외다. 또 "a proof … that can reach the root"에서 증명이 root에 "도달한다"는 표현이 어색하다.

7. **README, 개요**: "it records a finding against the record"
   "against"는 불리한 판정을 떠올리게 하는데, 같은 문장에서 finding은 결과를 확인(confirm)하는 데도 쓰인다.

8. **README, 개요**: "Two concerns shaped this design."
   "concern"은 뒤의 "Concerns and findings" 절에서 기술 용어(주장 근거에 대한 이의)로 정의된다. 같은 낱말이 일상어와 기술 용어로 두 번 쓰여, 나중에 되돌아가 확인했다.

9. **README, "Instances, roots and nodes"**: "It holds the statement to be settled in `root.md`, the models and scheduling in `settings.json`"
   "settled"는 다음 문단에서야 정의된다. 수학자에게 "models"는 모형 이론의 모형으로도 읽힌다. AI 모델이라는 점은 문맥으로만 알 수 있다.

10. **README, "Instances, roots and nodes"**: "In the same way, a record that settles part of what a node asserts can propose the parts as nodes, with the relation that the parts together cover the whole."
    일부를 "settles"한 기록이 왜 부분들을 새 node로 제안하는지 연결이 안 된다. "the parts"가 무엇을 가리키는지(해결한 부분과 남은 부분인지)도 불분명하다. 또 relation이 바로 앞에서 "Q implies P" 꼴의 두 node 사이 함의로 소개됐는데, 여기서는 전제가 여럿인 관계가 설명 없이 나온다.

11. **README, "Six roles and the pipeline"**: "Two roles process what the producing roles leave behind: a **peer** develops it into a record, and a **review** assesses that record."
    peer가 만드는 것은 "record candidate"이고 "record"는 출판된 것을 가리키는데, 여기서는 두 용어가 섞였다. Zenodo의 "a third checked that record against the first session's files"도 마찬가지다.

12. **README, 역할 표 explorer 행**: "| explorer | The knowledge base; it works to understand one question about the problem |"
    "What it receives" 열에 받는 것이 아니라 하는 일이 들어 있다. attempt 행의 "it chooses a node to settle"도 같다.

13. **README, 역할 표 review·organizer 행**: "a publication decision and any concerns" / "Modules of records, the choice of shared context, glossary decisions, merges of nodes or questions found to be the same"
    "concerns", "modules", "shared context"가 정의되기 전에 나온다. organizer 칸은 명사구만 이어져 무엇을 하는지 동사로 읽히지 않는다.

14. **README, 도식 설명**: "The arrows are files passed from one session to the next; no two sessions ever converse."
    도식에는 KB → P, REC → KB처럼 세션 사이가 아닌 화살표도 있어 설명과 맞지 않는다. 도식 첫 상자의 "frontier, index, board"도 아직 정의 전이다.

15. **README, retained work 문단**: "They hold the definitions and assumptions it relied on, its arguments and partial results, its computations together with their code and output, the literature it drew on and the conditions under which each source applies, the approaches that failed and what each failure actually rules out, and the steps that still have to be proved, together with the conversation itself, which the runner saves."
    한 문장에 항목이 여섯이고 "together with"가 두 번 나와 지나치게 길다. retained work를 앞 문장에서 "the files it keeps in its own directory"로 정의해 놓고, 끝에 디렉터리 파일이 아닌 대화를 덧붙여 정의가 흔들린다. 그리고 이것이 실제로 담긴 내용인지 담겨야 할 내용인지 불분명하다.

16. **README, frontier 문단과 "The top-level files" 사이 불일치**: "The **index** lists the published records, each with its own description and the review's short assessment beside it." / "Its entry point is `index.md`, which lists the records that the organizer selected as shared context for new sessions, a list of modules with their descriptions, and the recent records not yet organized."
    앞 문장은 index가 출판된 기록을 모두 나열한다고 읽히고, 뒤 문장은 고른 기록, 모듈 목록, 미정리 최근 기록만 나열한다고 읽힌다. Zenodo의 "open `index.md`, which lists the records with each record's own description"은 앞쪽 읽기를 따른다. 모듈 안 기록이 index에 개별로 나오는지 알 수 없다.

17. **README, 낱말 "section"의 두 뜻**: "two levels of assurance that the section "What counts as established" defines" / "the attempt picks a node and a **section** of it, an exact part of what the node asserts" / "each described the way a section of a survey would be"
    문서의 절, node의 부분(기술 용어), 서베이의 절로 세 번 다른 뜻으로 쓰인다. "as the first-run section explains"를 읽을 때 기술 용어인지 잠시 헷갈렸다.

18. **README, lease 문단**: "The reason is that until then the work exists only in the attempt's own files"
    무엇의 이유인지(점유가 출판 때까지 이어지는 이유) 바로 잡히지 않아 앞 문장으로 되돌아갔다. 또 "until the record is published"의 "record"는 아직 존재하지 않는 대상이다.

19. **README, lease와 coordination 문단의 "hold"**: "it holds the node's **lease**" / "registering a whole node while another session holds part of it" / (running) "open and held by no session"
    "hold"가 lease 보유, section 점유, question 점유에 두루 쓰인다. 특히 둘째 용례는 lease인지 등록된 section인지 판단해야 했다.

20. **README, coordination 문단**: "The coordination tools refuse only what a program can decide on its own"
    "coordination tools"가 처음 나오는데 정의가 없다. 세션이 부르는 명령인지 runner 기능인지 모르겠다.

21. **README, "The end of a session"**: "Its session is a conversation that may run over several CLI turns, so the runner does not close it the moment one CLI process exits."
    "CLI turn"과 "CLI process" 사이의 관계(한 turn이 한 프로세스인지)가 설명되지 않아, CLI를 모르는 독자는 따라가기 어렵다.

22. **README, 같은 문단**: "Instead, a separate process called the **session host**, which starts with the session and lives as long as it does, resumes the conversation and asks the session to reconsider, under its role guide, whether to end; by default it does so up to three times."
    주어 "a separate process"와 동사 "resumes" 사이가 멀다. "lives as long as it does"의 "it"이 session인지 process인지 바로 잡히지 않는다. 언제 재고를 요청하는지(프로세스가 끝날 때마다인지)도 문장에서 빠졌다.

23. **README, 같은 문단**: "once the limit is reached, the runner itself authorizes the end. The same reconsideration applies to explorers that have begun research, to formalizers and to peers."
    앞에서는 session host가 하던 일을 여기서 갑자기 runner가 한다. attempt에는 "have begun research" 조건이 없고 explorer에만 있어 비대칭인데, 다음 문단은 attempt도 "only checked for available work"로 끝날 수 있다고 한다. review와 organizer가 왜 빠지는지도 설명이 없다.

24. **README, peer 문단**: "to look for the counterexample or the identity that the producer passed over"
    정관사 "the"가 어떤 특정 반례나 항등식이 있다고 전제한다. 영어로는 "a counterexample or an identity"가 자연스럽다.

25. **README, review 문단**: "A claim is *supported* when the offered evidence establishes it, *unsupported* when the review has found that it does not, and *undetermined* when the review could not complete the assessment."
    시제가 establishes / has found / could not으로 섞여 있다. 첫 항은 증거가 객관적으로 확립한다는 진술처럼 읽혀서 review의 판단이라는 점이 흐려진다. 뒤의 "*Supported* means that the review found the offered evidence to establish the claim as stated"와 정의가 미묘하게 다르다.

26. **README, review 문단**: "if accepting a claim would require an essential proof that the candidate does not contain"
    "essential proof"는 영어에서 드문 낱말 짝이다. "a proof of an essential step"이나 "a missing essential argument" 정도를 뜻하는 듯하다.

27. **README, 모델 문단**: "By default the peer and review roles prefer a different model from the one the producing roles prefer."
    "prefer"가 한 문장에 두 번 나온다.

28. **README, published record 문단과 "A record's directory" 사이 모순**: "The record never changes afterwards. If a later review session … finds a defect in it or confirms a result, it appends a **finding** to the record" / "Concerns and findings are not written into the record they concern; they are in the assessment of the review that raised them"
    "never changes"와 "appends … to the record"가 이웃 문장에서 부딪힌다. 뒤 절은 finding이 기록에 쓰이지 않는다고 명시한다. finding이 실제로 어디 저장되는지 처음 읽을 때 틀리게 이해했다.

29. **README, finding을 내는 주체의 불일치**: "If a later review session, whether reviewing another candidate or examining published evidence, finds a defect in it or confirms a result, it appends a **finding**" / "until a **comprehensive review** issues a finding that withdraws or reaffirms the claim"
    앞 문장은 다른 후보를 review하는 일반 review도 finding을 낸다고 읽히고, 뒤 절은 일반 review는 concern을 보고하고 finding은 comprehensive review가 낸다고 읽힌다.

30. **README, propagation 문단**: "A relation says that its premises cannot all hold while its conclusion fails."
    "cannot all hold"를 먼저 "전제가 다 성립할 수는 없다"로 읽었다가 다시 읽었다. 논리적으로는 맞지만 구문이 두 가지로 읽힌다. "it is impossible for all its premises to hold while its conclusion fails"가 덜 모호하다. 바로 앞의 "in every direction that propositional logic allows"도 모호하다.

31. **README, route 문단**: "A node is on a **route** to the root when a chain of relations lets a proof of the node contribute to settling the root, and such a chain is itself called a route"
    "route"를 node의 성질과 사슬로 두 번 정의한다. "contribute"는 수학적으로 막연하다. 첫 route는 네 경우를 합치는 다전제 관계라서 "chain"보다 나무에 가깝다.

32. **README, questions 문단**: "such as why several methods stall at the same scale, or what an object looks like at the point where every estimate loses its margin"
    예시가 막연해서("several methods", "an object", "the same scale") 질문이 무엇인지 그려지지 않는다.

33. **README, progress 문단**: "The role guides measure progress by the change a piece of work makes to what is known."
    안내문이 진보를 "measure"한다는 표현이 어색하다. "Extending the range over which a statement has been checked … does not count as progress"는, 첫 실행의 증명이 n ≤ 20000 유한 검증에 기대는 사실과 나란히 놓이면 독자가 둘의 관계를 묻게 된다.

34. **README, "Two documents on research and writing"**: "Besides their role guides, attempt, explorer, peer, review and organizer sessions receive two documents"
    "Besides their role guides, attempt, explorer, …"가 앞 목록의 연속처럼 읽히는 garden path다. formalizer가 빠진 이유도 설명이 없다. "the skill's reference folder"의 "skill"은 Quick start에서야 정의된다.

35. **README와 first-run 사이, 소론의 출처**: README "This repository's author and an operator session wrote it after reading the records of an earlier instance that had worked on the first run's problem" / first-run "5 November | Standing input | No records or code from the earlier instance are to be used" 및 "8 November | Standing input | The essay on research … written during this run"
    이전 인스턴스의 기록을 읽고 쓴 글이 "이전 인스턴스 기록 사용 금지" 입력이 걸린 실행 중간(8일)에 standing input으로 들어갔다. 오염 여부를 평가하려는 독자는 여기서 멈춘다. README의 "draws its examples from the history of mathematics rather than from that instance"가 이 물음에 충분히 답하는지 판단할 수 없다.

36. **README, formalizer 문단**: "there is no cap on the number of rounds"
    "rounds"가 무엇의 회차인지(formalizer → peer → review 한 바퀴인지) 정의가 없다.

37. **README, runner 문단**: "Sessions inherit none of the user's personal instructions, hooks or memories"
    "hooks", "memories"는 CLI 용어여서 수학자에게는 정의 없는 낱말이다.

38. **README, "Computer-assisted steps"**: "In the second kind, binary64 floating point with an error model assumed in advance, margins added to the results are trusted to cover the rounding error rather than tracked by the arithmetic."
    "rather than tracked"의 주어가 문법상 "margins"가 되어, "여백이 산술로 추적되지 않는다"는 뜻이 된다. 뜻은 "반올림 오차가 추적되지 않는다"일 것이다. Zenodo의 "in which the rounding error is covered by assumed margins rather than tracked by the arithmetic"이 바르다. 문서 사이에 같은 내용의 품질이 다르다.

39. **README, 전반**: "error models assumed in advance"
    신뢰 평가의 핵심 낱말인데 어느 문서도 정의하지 않는다. 연산마다 상대오차 한계를 가정한 것인지, 여백의 크기를 어떻게 정했는지, 무엇이 "가정"인지 알 수 없다. 이것을 모르면 "treat … as unproved"의 무게를 판단할 수 없다.

40. **README, 낱말 "range"의 두 뜻**: "every result is either exact or comes with a guaranteed range" / "the record states its inputs, range, arithmetic, code and output" / "within the range the review supported"
    값의 포함 구간과 매개변수의 범위가 같은 낱말로 쓰인다. 특히 표의 "range"는 어느 쪽인지 모호하다.

41. **README, "Concerns and findings"**: "the claim and everything derived from it keep their standing, but are marked as resting on a questioned claim"
    문제 제기된 주장 자신이 "resting on a questioned claim"으로 표시된다는 말은 자기 자신 위에 선다는 꼴이라 어색하다. "outcome"(withdrawal 문장)도 정의 없이 쓰인다.

42. **README, 첫 운전 절 첫 문단**: "The **maximum displacement** of a parking function is the largest distance any of its cars had to drive past its preferred spot."
    "its"가 두 번 나오는데, 둘째 "its"는 주차함수가 아니라 차를 가리킨다. 그래서 잠시 걸렸다. 또 "non-decreasing up to some index and non-increasing after it, with a flat peak allowed"에서 "with a flat peak allowed"는 앞 정의에 이미 포함되어 군더더기다.

43. **README, routes 문단**: "The second route shows that a conditional form of log-concavity suffices: log-concavity required only at a step at which the sequence decreases, which implies that once the sequence has decreased at a step it cannot rise again."
    콜론 뒤가 "log-concavity required …"라는 명사구 조각이다. "which"의 선행사가 무엇인지 잡기 어렵다. "at a step"에서 부등식이 어느 세 항에 걸리는지는 first-run을 읽고서야 알았다.

44. **README, 같은 문단**: "and each case has a reviewed informal proof" / "That property was settled on each side of the middle."
    경우에 "증명"이 있다는 말은 그 경우가 일어날 수 없다는 증명을 뜻할 텐데 축약됐다. "settled"는 이 체계에서 증명 또는 반증이므로, 여기서는 "proved"가 맞다.

45. **README, 기록 인용 규칙**: "Records are cited here by the first eight characters of their identifiers"
    실제 인용 "r5909c9e7", "r0af7f414"는 아홉 글자다(Zenodo의 전체 ID "r5909c9e73b34492cbe5e197cf65c02e8"로 보면 "r" 뒤 여덟 자). 사실과 어긋난다. first-run 머리에도 같은 문장이 있다.

46. **README, 한계 문단과 first-run 개입 표 사이**: README 첫 표 "every record and every implication on the two routes to the root was accepted by an AI review session" / first-run "Give priority over all other work to proving two monotonicity properties that a table used by record r030ffaeb relies on and that its review had accepted on numerical evidence" / first-run Limits "Several records on the routes rest on binary64 computations …, r030ffaeb among them"
    route 위의 기록 r030ffaeb에서 review가 단조성 둘을 "numerical evidence"로 승인했다는 사실이 first-run 개입 표 한 칸에만 나온다. README와 Zenodo의 한계 목록(인간 심사 없음, binary64, Lean 없음)에는 이것이 없다. 수치 증거로 승인했다는 것은 오차 모형 가정과는 다른 종류의 빈틈이다. 이 빈틈은 root가 informally proved가 된 11일 뒤인 12일에야 세 기록이 메웠다. 그 세 기록이 지금 frontier의 route에 반영됐는지는 어디에도 없다.

47. **README, 한계 문단**: "ten pipelines were still working on nodes and questions other than the root" / first-run "10 pipelines were active, working on unresolved nodes and unresolved questions beside the root"
    "beside the root"는 "besides/other than"을 뜻하는 듯한데, "beside"는 "옆에"라서 어색하다. 숫자 표기(ten / 10)도 문서마다 다르다.

48. **README, "Requirements"와 running의 외부 통신**: README "do-math itself sends nothing outside your machine; … the only outbound traffic is the CLIs' own." / README "services/scholarly-mcp … some others go through one university library's login. When configured for an instance, it gives do-math's sessions literature search."
    설정하면 do-math 세션이 쓰는 로컬 MCP 서버가 학술 원천과 대학 도서관 로그인으로 통신한다. 이것이 "the only outbound traffic is the CLIs' own"에 포함되는지 걸린다.

49. **README, Quick start**: "ask the do-math skill, a folder of instructions that these CLIs load, to start research on a statement."
    폴더에게 "ask"한다는 꼴이 어색하다. 또 첫 표의 "[Quick start](#running-do-math)" 링크는 "Quick start" 소절이 아니라 상위 절 "Running do-math"로 간다.

50. **README, "Repository layout"**: "the checks performed when it was installed, including live launches of both CLIs, a complete small instance whose root was formally proved with a Lean proof that a review session recompiled and checked, and recovery after a runner restart, are in [docs/do-math/rebuild-verification.md]"
    주어 "the checks"와 동사 "are" 사이에 삽입구가 세 겹이라 따라가기 힘들다.

51. **README, 지원 스킬 표**: "Defines the structure and rules of the working-memory graph in `기억/`"
    영어 README에 한글 디렉터리명이 설명 없이 나와, 영어 독자는 읽을 수도 검색할 수도 없다.

52. **README, 반복 표현**: "so that the sessions could finish the informal mathematics before formalization resumed"
    거의 같은 구절이 README 두 번, first-run 두 번, Zenodo 한 번 나온다. 일시 정지가 아직 유지되는데 "before formalization resumed"(과거)라서 재개된 것처럼 읽힐 여지가 있다.

### first-run

53. **first-run, 머리**: "as of the evening of 12 November 2026 … The size table below is a snapshot from 17:45 Korean time that day." / Limits "at 23:15 Korean time on 12 November the run had launched 1,237 sessions and published 340 records"
    한 문서에 기준 시각이 둘(17:45와 23:15)이다. 규모 표의 337과 한계 절의 340이 다른 이유를 이해하려고 되돌아갔다. 첫 문장의 "evening"이 어느 시각인지도 알 수 없다.

54. **first-run, 문제 절**: "This is Conjecture 6.5 of Celano et al., who write |IPFₙ(ℓ)^max| for the same numbers"
    "IPF"가 무엇의 약자인지 설명이 없다. 나는 "interval parking functions"를 떠올렸고, 같은 수인지 잠시 의심했다.

55. **first-run, 네 경우 문단**: "in the third the descent is below m−1 and the ascent at or beyond m; in the fourth both are below m."
    "below m−1"과 "below m"이 걸음의 시작 첨자 기준인지 걸음 쌍 기준인지 밝히지 않아, 네 경우가 실제로 빠짐없이 덮는지 직접 따져야 했다(시작 첨자 기준이면 덮는다). 넷째 경우에서 하강이 m−1 아래라는 조건은 첫 경우를 빼서 생기는 함의인데, 그것이 적혀 있지 않다.

56. **first-run, 둘째 route 문단 (수학적 의문)**: "a reviewed relation in record rdc276812 derives the second part from the fourth case of the first route."
    넷째 경우("m 아래에서 하강 뒤 상승이 없다")만으로는 m 아래에서의 조건부 로그 오목성 b(ℓ+1)² ≥ b(ℓ)b(ℓ+2)가 나오지 않는다. 예컨대 10, 5, 4는 넷째 경우를 어기지 않지만 25 < 40이다. node의 실제 진술이 더 강하거나 관계에 다른 전제가 있어야 할 텐데, 문서만으로는 이 유도가 성립하는지 알 수 없다. 다음 문단의 "no descent at all below the middle"이 참이면 조건이 공허하게 성립하지만, 그렇다면 관계의 전제는 넷째 경우가 아니라 그 명제여야 자연스럽다.

57. **first-run, 같은 문단과 다음 문단의 "below the middle"**: "The third and fourth cases of the first route were in turn proved by showing that the sequence has no descent at all below the middle" / Zenodo "the sequence never decreases below its middle index"
    "below the middle"이 ℓ+1 ≤ m−1인 걸음인지 ℓ < m인 걸음인지 정확한 범위가 없다. route 전체가 지나는 명제인데 진술이 정밀하지 않다.

58. **first-run, 점근 문단**: "the records found that the neighboring counts b(n, ℓ−1) and b(n, ℓ) agree to leading order as ℓ grows, and that their difference …, whose sign decides the inequality, is only of order ℓ^(−1/3) times either count."
    "found"가 증명인지 수치 관찰인지 모호하다. n이 ℓ에 따라 넓은 범위(2ℓ에서 약 2ℓ^(3/2))를 움직이는데 ℓ^(−1/3)이 그 범위에서 균일한지, 어느 n에서의 크기인지 밝히지 않았다. 그리고 앞에서는 걸음을 ℓ → ℓ+1로 쓰다가 여기서 ℓ−1 → ℓ로 첨자를 바꿨다.

59. **first-run, 마지막 전제 문단**: "The last open premise on the routes was a single node, pair-beats-capped-threshold. Its exact statement is in the frontier; in outline, it is an inequality between two counts of configurations for n between 2ℓ and about 2ℓ^(3/2)."
    낱말을 붙인 node 이름이 설명 없이 나오고, "configurations"가 무엇의 배치인지 없다. 증명의 마지막 열쇠인데 "about 2ℓ^(3/2)"처럼 근사 표현으로만 진술되어, 수학자로서는 무엇이 증명됐는지 알 수 없다.

60. **first-run, 같은 문단**: "the certification that the root holds for all n ≤ 20000"
    무한 명제의 증명이 왜 n ≤ 20000까지의 유한 검증을 입력으로 쓰는지(점근 논증이 큰 n만 덮는지) 설명이 없다. 증명 구조를 짐작으로 메워야 했다.

61. **first-run, 같은 문단**: "That certification checked the steps at or beyond the middle in interval arithmetic with integer endpoints"
    "integer endpoints"의 구간 산술이 무엇인지 걸린다. 정수 끝점이면 정확한 정수 연산과 무엇이 다른지, 왜 구간이 필요한지 설명이 없다.

62. **first-run, Lean 절 (수학적 의문)**: "The node is a necessary condition of the root: record r801ec220 proves that unimodality for every n implies this limit"
    단봉성은 정성적 성질인데, 그것이 상수 e/√(2π)까지 정해진 극한을 함의한다는 말이 수학적으로 이상하게 들린다. 정리 이름이 "critical_increment_unconditional"이므로 극한이 무조건 증명된 것으로 보인다. 그렇다면 "unimodality implies this limit"는 사소하게 참이 되고, "necessary condition"이라는 분류가 무엇을 뜻하는지 의문이 남는다. 함의의 실제 내용(어떤 가정 아래 무엇이 나오는지)이 필요하다.

63. **first-run, 같은 절**: "let F_ℓ(z) = Σ_j A(j, ℓ) zʲ / j!"
    합의 범위(j = 0부터인지)가 없고, z = 1/e에서 수렴하는지는 독자가 확인해야 한다(총수 (j+1)^(j−1)로 보면 수렴한다).

64. **first-run, 개입 표 머리 문단**: "the one action the operator took on its own initiative is marked as such."
    표에서 "Operator action" 행을 찾았지만, 그 행에 "own initiative"라는 표지는 없다. 무엇이 "marked as such"인지 확신하지 못했다.

65. **first-run, 개입 표 7 November 행**: "An attempt may take a node that is equivalent, through an accepted relation, to a node another session occupies"
    relation은 한 방향 함의인데 "equivalent through an accepted relation"은 동치를 말한다. 수학적으로 엉성하다.

66. **first-run, 개입 표 7 November, evening 행**: "Register a section before beginning research on it; withdrawn on 9 November after 89 sessions had received it"
    README는 section 등록을 attempt의 기본 절차로 설명한다. 그런데 여기서는 그것이 standing input으로 들어갔다가 철회됐다. 그렇다면 README가 말하는 lease·section 체계가 이 실행의 어느 기간에 적용됐는지 알 수 없다.

67. **first-run, 개입 표 9 November 행**: "a control file stops the runner from starting formalizers"
    running에는 형식화를 멈추는 제어 파일이나 명령이 없다. 같은 조작을 재현하려는 독자는 방법을 찾을 수 없다.

68. **first-run, 개입 표 12 November, 04:54 행**: "A decomposition of the size-growth probability into a uniform-attachment part and a leaf surplus, reported by an AI session outside the instance at the user's request, with the operator's exact-arithmetic checks and comparison against published records; passed on for the sessions to judge for themselves"
    "size-growth probability", "uniform-attachment", "leaf surplus"가 정의 없이 나오고 문장이 지나치게 길다. 외부 AI의 수학 내용이 주입됐다는 점은 "autonomous"를 평가할 때 중요하다. 그런데 root 증명(11일)보다 뒤라 영향이 없다는 결론은 독자가 직접 끌어내야 한다.

69. **first-run, 설정 문단**: "they were then moved to Claude Opus 5.5 as their first choice" / "Producing roles moved to Claude Fable 5.1 as first choice"
    7일 이후에는 생산과 평가가 모두 같은 공급자(Claude)의 모델이었다. README의 "independent judgment"나 Zenodo의 "(the independent assessment)"가 세션 분리만 뜻하는지, 모델 분리까지 뜻하는지 독자가 따져야 한다. 첫 이틀은 같은 모델이었고, 대체(fallback)로 같은 모델이 된 빈도는 측정되지 않았다("on how often a fallback gave a peer or a review the same model as the producers").

### running

70. **running, Requirements (문서 간 모순)**: "The runtime needs Lean 4 in every case, even for a problem whose proofs will not use it, because the settings name a Lean installation and the broker starts with the runner"
    README는 Lean 증명이 있어야만 실행이 끝난다고 한다("do-math considers a run complete only when a Lean proof … has been recompiled"). 그렇다면 "proofs will not use [Lean]"인 문제는 있을 수 없다. 이유 절("because the settings name a Lean installation")도 설정이 그렇게 되어 있어서 필요하다는 순환 설명처럼 들린다.

71. **running, Requirements**: "The process helpers also support Linux, where they read `/proc`"
    "process helpers"가 정의 없이 나온다. README에도 정의가 없다.

72. **running, 기본값 목록**: "`explore_every`: the runner raises an exploration request each time an attempt is launched; the request is granted when a question is free, that is, open and held by no session, and the launch interval has passed."

### Zenodo

77. **Zenodo, 첫 문단**: "what survives review is published as a record in the instance's knowledge base, of which this archive is a copy, for every later session to read."
    "of which this archive is a copy"가 끼어들어 "for every later session to read"가 "published"에서 멀어졌다.

    README는 "The producing sessions' conversations and working files are not in `knowledge/`"라고 한다. 빠진 것은 둘이 아니라 셋이고, 작업 파일(retained work)이 빠졌다는 사실이 Zenodo에는 없다. review는 후보를 이 작업 파일과 대조했으므로, 독자가 review의 대조를 재현할 수 없다는 점이 Zenodo 독자에게 전달되지 않는다.

    "for each … and for the conjecture …"가 한 문장에 이어져 지나치게 길다. "statement"가 같은 문장에 세 번 나온다.

## 3. 확정하지 못한 것

1. **"error model assumed in advance"의 실체.** 나는 연산마다 상대오차 ≤ k·2⁻⁵³ 같은 한계를 가정하고 거기서 여백을 잡았지만, 코드가 그 가정을 지키는지는 검증하지 않았다는 뜻으로 추측했다. 문서에는 정의가 없다.
2. **|IPFₙ(ℓ)^max|의 뜻.** 원 논문의 ℓ-interval parking function(각 차의 변위가 ℓ 이하인 주차함수) 표기에서, 최대 변위가 정확히 ℓ인 것을 센다고 외부 지식으로 짐작했다. 문서는 "the same numbers"라고만 한다.
3. **rdc276812의 관계가 어떻게 성립하는가.** 넷째 경우 node의 실제 진술이 "가운데 아래 하강 없음"처럼 더 강하리라고 추측했다. 확인하지 못했다.
4. **"below the middle"의 정확한 첨자 범위**와 **pair-beats-capped-threshold의 진술**. frontier.md를 열어야 알 수 있다.
5. **n ≤ 20000 검증의 역할.** 점근 논증이 충분히 큰 n(또는 ℓ)만 덮고 유한 검증이 나머지를 메운다고 추측했다.
6. **"the records found … ℓ^(−1/3)"가 증명인지 수치 관찰인지.**
7. **r801ec220의 함의 "unimodality … implies this limit"의 실제 내용**, 그리고 극한이 무조건 증명됐다면 "necessary condition" 분류에 남는 의미. 정리 이름의 "_unconditional"로 보아, 처음에는 조건부로 증명됐다가 나중에 무조건 증명으로 바뀌었다고 짐작했다.
8. **r030ffaeb의 단조성 빈틈이 지금 frontier에서 어떻게 처리됐는가.** 12일의 세 기록이 route에 연결됐는지, v2(빈틈 메우기 전)와 v3 사이에 root의 근거 구성이 달라졌는지 알 수 없다.
