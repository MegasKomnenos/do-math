# 독해 11: 처음 읽는 독자의 독해

읽은 문서(이 순서로): `README.md`, `docs/do-math/first-run-parking-unimodality.md`(아래 "첫 운전 문서"), `docs/do-math/running.md`(아래 "운전 안내"), `zenodo-description.md`의 "## Description" 절(아래 "Zenodo"). Zenodo는 저장소를 보지 않은 독자로서 따로 읽었다. 문서는 고치지 않았다. 줄 번호는 읽은 시점의 파일 기준이다.

기준 약호: [A] 정의보다 먼저 쓰인 용어, [B] 문서 안과 문서 사이의 순서, [C] 같은 대상에 다른 낱말 또는 다른 대상에 같은 낱말, [D] 영어 문장으로서의 어색함, [E] 문장 사이와 문단 사이의 연결, [F] 수학적으로 틀리거나 모호한 진술.

---

## 1. 이해한 것

1. **무엇인가.** do-math는 한 수학 명제를 증명하거나 반증하려고 서로 대화하지 않는 AI 세션 여럿을 차례로 띄우는 시스템이다. 세션 사이에서는 파일만 오가고, 검토를 통과한 결과는 공유 지식 기반에 기록으로 쌓여 뒤 세션의 기억 노릇을 한다. 사람은 명제와 상시 지시를 주고, 운영자라는 AI 대화가 운전을 차리며, 러너라는 프로그램이 세션을 띄운다.
   - README L14: "Each is a new Claude Code or Codex conversation that knows nothing of the others; what a session produces is handed on as files, and what survives review is published as a record in a shared knowledge base for every later session to read."
   - README L14: "An AI conversation called the operator sets up the run from the user's statement and settings and operates it on the user's behalf. A program called the runner then launches sessions as the work requires"

2. **기록 하나는 세 세션의 일이다.** 생산 세션(attempt, explorer, formalizer)이 작업 파일을 남기면, peer가 그것으로 기록 후보를 쓰고, review가 후보를 생산 세션의 파일과 대조해 주장마다 판정한다. 만든 세션이 제 일을 인증하지 않게 하려는 설계다.
   - README L16: "Finally, a third session, the review, checks the peer's draft against the first session's files and assesses whether each claim in it is supported."
   - README L20: "Each piece of work is assessed by a session that took no part in producing it, so that no session certifies its own work."

3. **기록은 바뀌지 않고, 뒤의 판단은 곁에 붙는다.** 게시된 기록은 고치지 않으며, 뒤의 review가 결함을 찾거나 결과를 확인하면 finding으로 남는다. 이의(concern)는 그 자체로는 지위를 바꾸지 않고, 종합 검토(comprehensive review)의 finding이 철회하면 그 위에서 유도된 결과가 모두 사라진다.
   - README L95: "The record never changes afterwards."
   - README L145: "A withdrawal removes every outcome derived through the claim, and a node that depended on it becomes unresolved again."

4. **인스턴스, 뿌리, 노드, 관계.** 운전 하나가 인스턴스이고 그 명제가 뿌리(root)다. 노드는 확정하려는 정확한 명제이며, 뿌리 밖의 노드는 검토를 거친 함의(관계)를 통해서만 들어온다. 추측에 그친 함의는 노드를 만들지 않는다.
   - README L32: "The statement in `root.md` is called the **root** of the instance. It never changes while the instance runs"
   - README L36: "Every node other than the root enters through a **relation**, a reviewed implication between nodes."

5. **일감은 스스로 고른다.** attempt는 프론티어, 색인, 게시판을 읽고 노드와 그 일부(section)를 고른다. 고르는 동안만 노드의 임대(lease)를 잡고, section을 등록하면 그 부분이 점유된다. 겹침 판단은 수학적 판단이라 등록하는 세션에 맡기고, 프로그램은 기계적으로 판정할 수 있는 것만 거부한다.
   - README L75: "Having read these, the attempt picks a node and a **section** of it, an exact part of what the node asserts, which may be the whole node."
   - README L79: "Sessions coordinate through information rather than enforcement."

6. **세션의 끝.** 생산 세션과 peer는 프로세스가 끝나도 바로 닫히지 않고, 세션 호스트가 대화를 재개해 끝낼지 다시 묻는다(기본 세 번). 연구를 시작한 세션의 작업은 중단되었더라도 peer와 review로 넘어간다.
   - README L85: "In either case, if the session had begun research, its retained work goes on to a peer and a review"

7. **판정과 수용.** review는 주장마다 supported, unsupported, undetermined 가운데 하나를 매기고, 제안(노드, 관계, 증명)은 기대는 주장이 supported일 때만 받아들인다. review가 빠진 핵심 단계를 스스로 증명해 인증하는 것은 금지된다.
   - README L91: "a proposed node, relation or proof is accepted only when the claim it rests on is supported, and only accepted proposals change the frontier."

8. **전파와 경로.** 러너는 받아들인 관계를 명제논리가 허용하는 모든 방향으로 적용한다(전건 긍정, 후건 부정). 양쪽이 다 지지되면 contested다. 뿌리에 대한 증명 기여가 가능한 노드는 경로(route) 위에 있고, 반증만 기여하는 노드는 필요조건이다. 형식화는 그 둘에 해당하는 결과에만 요청된다.
   - README L99: "So a proof of Q together with \"Q implies P\" proves P, and a refutation of K together with \"P implies K\" refutes P"
   - README L101: "Formalization is requested only for the proof of a node on a route or for the refutation of a necessary condition."

9. **보증의 세 수준.** 비형식 증명은 AI review가 받아들였다는 뜻일 뿐 사람이나 증명 검사기가 확인했다는 뜻이 아니다. 컴퓨터 보조 단계는 산술 종류로 나뉘는데, 엄밀한 범위가 보장되는 산술과, 미리 가정한 오차 모형 아래의 binary64가 있다. 형식 증명은 review가 직접 재컴파일, 공리 확인, 진술 대조를 거친 Lean 증명이다. 관계로 유도된 결과는 전제가 모두 형식이어도 비형식이다.
   - README L133: "A proof that the frontier derives through relations is always informal, even when every premise has a Lean proof, because the relation itself has not been formalized."
   - README L137: "a reader who does not accept an assumed error model should treat the results that depend on it as unproved."

10. **첫 운전의 문제.** 길이 n의 주차함수 가운데 최대 변위가 ℓ인 것의 개수 b(n, ℓ)가 ℓ = 0, …, n−1에서 단봉이라는 Celano 외의 추측 6.5다. 양 끝값은 n!과 nⁿ⁻²이다.
    - 첫 운전 문서 L9: "The root states that, for every n ≥ 1, the sequence b(n, 0), b(n, 1), …, b(n, n−1) is unimodal: that there is an index c such that b(n, ℓ) ≤ b(n, ℓ+1) for every ℓ < c and b(n, ℓ) ≥ b(n, ℓ+1) for every ℓ with c ≤ ℓ < n−1."

11. **두 경로.** 첫째 경로는 "하강 뒤의 상승"을 가운데 첨자 m = ⌈n/2⌉에 대한 위치로 네 경우로 나눠 각각 불가능함을 보인다. 둘째 경로는 하강하는 자리에서만 요구하는 로그 오목성이 단봉성을 함의함을 보인다. 두 경로 모두 "가운데 아래에서는 하강이 없다"는 명제를 지나며, 그 마지막 전제 노드를 증명한 기록이 r5909c9e7(11월 11일 16:14)이다. 그 증명은 이전 기록의 binary64 계산들과 n ≤ 20000 유한 검증을 물려받는다.
    - 첫 운전 문서 L36: "Both routes therefore pass through that statement, and it was the last part to be proved."
    - 첫 운전 문서 L38: "The review also stated that the proof inherits computer-assisted inputs from earlier records: several in binary64 floating point, and the certification that the root holds for all n ≤ 20000"

12. **Lean의 현황.** 뿌리의 Lean 증명은 없다. 형식 증명이 있는 노드는 하나뿐인데, 뿌리의 필요조건(지수 생성함수 차의 극한)이라 뿌리를 열어 둔다. 형식화는 11월 9일 사용자가 멈췄고, 진행 중이던 다섯 형식화는 게시 없이 끝났다.
    - 첫 운전 문서 L42: "The theorem states that ℓ^(3/2) (F_ℓ(1/e) − F_{ℓ−1}(1/e)) tends to e/√(2π) as ℓ → ∞."
    - 첫 운전 문서 L44: "The pause is still in force, and no Lean work on the routes to the root has been published."

13. **개입.** 사용자와 운영자가 상시 지시, 설정, 소프트웨어 변경으로 여러 번 개입했다. 외부 AI 세션의 수학 자료를 넘긴 일(12일 04:54)과, 경로 위 기록 r030ffaeb의 표가 수치 증거로 받아들여진 단조성 두 개에 기댄다는 것을 보고 그 증명에 우선권을 준 일(12일 14:15)이 들어 있다.
    - 첫 운전 문서 L67: "Give priority over all other work to proving two monotonicity properties that a table used by record r030ffaeb relies on and that its review had accepted on numerical evidence"

14. **한계.** 모든 검토가 AI이고 사람의 심사는 없다. 가정된 오차 모형을 받아들이지 않는 독자에게 뿌리는 미증명이다. 메커니즘의 효과, 비용, 반려 빈도는 측정하지 않았다.
    - README L159: "Whether do-math's mechanisms changed the quality of the research has not been measured, and no figures were collected on cost or on how often reviews rejected or corrected claims."

15. **돌려 보기.** Python 3.12, Git, Codex나 Claude Code CLI, Lean 4가 필요하다. 세션은 권한 확인 없이 내 계정으로 돌며, 시간, 세션 수, 사용량에 상한이 없다. `root.md`와 `settings.json`으로 `init`, `start`, `status`를 하고, 끝낼 때는 `stop`, `kill-session`, 러너 프로세스 종료의 세 단계를 거친다.
    - 운전 안내 L15: "A run has no cap on time, on the number of sessions, or on usage, and do-math collects no usage figures"
    - 운전 안내 L105: "To end a run before the root is formally settled, take three steps in order."

16. **Zenodo 아카이브.** 한 인스턴스의 지식 기반 사본이다. `index.md`부터 열고, `frontier.md`에서 두 경로를 보고, 기록 디렉터리마다 진술, 증거, 검토 판정을 본다. 상시 지시, 작업 파일, 대화는 들어 있지 않다.
    - Zenodo: "To read the archive, extract it and open `index.md`"
    - Zenodo: "Three things are not part of `knowledge/`: the standing inputs, that is, the instructions the user gave to the sessions during the run; the sessions' working files, against which the reviews checked the drafts; and the sessions' conversations."

## 2. 읽기 어려웠던 자리

### [A] 정의보다 먼저 쓰인 용어

A1. README, 한눈 보기 표 "State of the root" 행. "*Informally proved* on 11 November 2026: every record and every implication in the two chains of reasoning that lead to the root was accepted by an AI review session."
독자가 맨 처음 읽는 칸에 root, record, two chains of reasoning이 한꺼번에 나온다. root는 L32, record는 L95에 가서야 정의되고, "two chains"가 무엇인지는 L151에 가서야 나온다. 같은 문서 뒤에서 정의되는 경우다. 행 제목 "State of the root"부터 root를 안다고 전제한다.

A2. README, 한눈 보기 표 "Formal proof" 행. "No Lean proof of the root exists; the user paused formalization on 9 November 2026."
Lean은 L16에서 "a proof assistant"로 처음 풀이되므로 표에서는 정의 전이다. "the user"가 누구인지(운전을 시작한 사람)는 리드 L14에서야 짐작된다. "formalization"은 어느 문서에서도 용어로 정의되지 않고 문맥으로만 뜻이 잡힌다. 같은 문서 뒤 정의, 일부는 정의 없음.

A3. README, 한눈 보기 표 "Formal proof" 행. "One necessary condition of the root has a Lean proof, a proof that leaves the root open."
"necessary condition of the root"가 시스템 안에서 특정한 지위라는 것(L101 "a node is a necessary condition of the root when only its refutation can contribute")은 뒤에 가야 안다. 수학 용어로 읽을 수는 있으나, 이 문장이 왜 따로 언급되는지는 L155까지 가야 이해된다. 같은 문서 뒤.

A4. README, 한눈 보기 표 "Evidence" 행. "The knowledge base on Zenodo, concept DOI"
knowledge base는 리드 L14에서 처음 풀이된다. 표 안에서는 무엇의 지식 기반인지 알 수 없다. 같은 문서 뒤.

A5. README 리드 L16. "or to turn an accepted proof into a formal proof in Lean 4, a proof assistant"
"accepted"가 누가 무엇을 받아들인다는 뜻인지가 그 자리에서는 아직 서지 않았다. review가 같은 문단 끝에서 처음 나오고, "accept"의 체계상 뜻(L91)은 훨씬 뒤에 온다. 같은 문서 뒤.

A6. README 리드 L18. "The one exception to that free choice is formalization: the runner requests it for an accepted informal proof or refutation whose outcome bears on the root."
리드에서 root가 처음 나오는 자리인데 정의는 L32에 있다. "informal proof"는 L133에서 정의된다. "outcome"은 이후 L145, L155에서도 쓰이지만 어디서도 정의되지 않는다(증명이나 반증의 결과를 가리키는 듯하다). 같은 문서 뒤 정의, 일부는 정의 없음.

A7. README 리드 L22. "The first research run of this implementation began on 5 November 2026."
"this implementation"은 이전 구현이 있었다는 뜻을 품는데, 이전 구현과 이전 인스턴스는 L113과 첫 운전 문서 L13에 가서야 나온다. 같은 문서 뒤, 그리고 다른 문서.

A8. README 역할 표 L44-L49. "Its retained work on that node", "A record candidate: exposition, claims and proposals", "Its assessment and feedback: claim statuses, a publication decision and any concerns", "Modules of records, the choice of shared context, glossary decisions, merges of nodes or questions found to be the same"
표 한 장에 retained work(L71 정의), record candidate(L89), concerns(L145), modules와 shared context(L75, L117), glossary(L95), questions(L105)가 정의 전에 몰려 있다. 같은 문서 뒤.

A9. README 도식 L55. `KB["knowledge base: frontier, index, board, records"]`
frontier, index, board는 L75에서야 정의된다. 도식이 정의보다 앞선다. 같은 문서 뒤.

A10. README L75. "The **frontier** lists the current nodes with their statements, their states and the relations between them."
노드의 "states"가 무엇인지(unresolved, informally proved 등)는 L175에 가서야 나열된다. 같은 문서 뒤.

A11. README L89. "It also decides what the record proposes for the frontier and the glossary: new nodes, relations, proofs of nodes, questions and terms."
questions는 L105에서 정의된다. 표 L45의 "a question to understand"도 마찬가지다. 같은 문서 뒤.

A12. README L113. "both are files in the skill's reference folder that a user can edit."
"skill"은 L193 "the do-math skill, a folder of instructions that these CLIs load"에서야 풀이된다. 같은 문서 뒤.

A13. README L83. "The same reconsideration applies to explorers that have begun research"
"begun research"가 체계상 구분임은 L85에서 부정형("a session that only checked for available work and found none")으로만 드러난다. 무엇이 연구의 시작인지는 끝내 정의되지 않는다. 같은 문서 뒤, 불완전.

A14. README L83. "Its session is a conversation that may continue over several CLI processes in turn"
CLI라는 줄임말은 풀이되지 않고, 대화 하나가 왜 여러 프로세스에 걸치는지(비대화형 실행이 한 차례 응답 뒤 끝나는 방식)도 설명되지 않는다. 이 문단 전체가 그 전제를 알아야 읽힌다. 정의 없음(외부 지식).

A15. README L119. "Sessions inherit none of the user's personal instructions, hooks or memories"
hooks와 memories는 CLI 고유 기능 이름인데 풀이가 없다. 정의 없음(외부 지식).

A16. README L141. "It recompiles the final sources through the broker, forcing the target to be compiled fresh. It prints the theorem's transitive axioms and compares them with the allowed list"
"target", "transitive axioms", `sorryAx`는 Lean/Lake 사용자가 아니면 모른다. AI 연구자 독자에게 형식 증명의 세 검사 가운데 둘이 풀이 없이 지나간다. 정의 없음(외부 지식).

A17. README 한눈 보기 표 L7과 L137. "binary64 computations with error models assumed in advance", "floating point with directed rounding used to compute bounds"
binary64(IEEE 754 배정밀도), directed rounding, interval arithmetic이 풀이 없이 쓰인다. 특히 "error model"이 구체적으로 무엇을 가정하는지가 나오지 않아 신뢰 판단의 핵심 근거를 독자가 평가할 수 없다. 정의 없음.

A18. 첫 운전 문서 L3. "The terms it uses, such as node, relation, route, record, review, informally proved and computer-assisted, are defined in the repository [README](../../README.md)"
목록에 없는 시스템 용어가 본문에 더 나온다. "standing input"(L13), "pipelines"(L28), "organizer outputs, comprehensive reviews and question publications"(L28), "frontier"(L32), "operator"(L48), "section"(L57 표), "occupies"(L55 표). 다른 문서를 읽어야만 뜻을 아는 경우이며, 목록이 그 범위를 다 알려 주지 않는다.

A19. 첫 운전 문서 L38. "The last open premise on the routes was a single node, pair-beats-capped-threshold. Its exact statement is in the frontier; in outline, it is an inequality between two counts of configurations for n between 2ℓ and about 2ℓ^(3/2)."
노드가 이런 낱말 잇기 이름을 가진다는 것이 어디서도 소개되지 않는다. "configurations"가 무엇의 배치인지도 정의되지 않아, 마지막 전제의 내용을 문서만으로는 전혀 알 수 없다. 정의 없음.

A20. 첫 운전 문서 L48. "the installed copy that the instance executes was regenerated and the runner restarted"

### [C] 같은 대상에 다른 낱말, 다른 대상에 같은 낱말

C1. 뿌리에 이르는 추론의 이름. README L7 "the two chains of reasoning", L22 "the two chains of implications", L26 "the two chains of reasoning that led to the result", L101 "such a chain is itself called a route", L149 "both routes to the root"; 첫 운전 문서 L30 "## Two routes to the root"; Zenodo "two chains of implications ... which the frontier calls routes"
한 대상에 chain of reasoning, chain of implications, route 세 이름이 쓰인다. Zenodo만 둘을 잇는다. README에서는 독자가 스스로 같다고 판단해야 한다.

C2. peer가 만드는 산출물의 이름. README L16 "the peer's draft", L40 "a peer develops it into a draft record", L47 "A record candidate", L89 "**record candidate**", L91 "the candidate"; Zenodo "a draft record", "the drafts"
draft, draft record, record candidate, candidate가 섞인다. 굵게 정의된 이름은 record candidate인데, 앞선 리드와 역할 소개는 draft를 쓴다.

C3. "section"의 세 뜻. README L34 "the section \"What counts as established\" defines", L22 "as the first-run section explains", L75 "a **section** of it, an exact part of what the node asserts", L117 "each described the way a section of a survey would be"
문서의 절, 노드의 일부, 개관 논문의 절이 같은 낱말이다. 특히 L34는 노드 section이 정의되기 바로 앞 절에서 문서 절의 뜻으로 쓰고, L117은 노드 section이 정의된 뒤 다른 뜻으로 쓴다.

C4. "range"의 세 뜻. README L133 "later work may use the result within the range the review supported", L128 "Validity beyond the range the computation covers", L137 "every result is either exact or comes with a guaranteed range"
L128의 range는 매개변수(n의 범위), L137의 range는 수치 결과를 감싸는 구간, L133의 range는 주장이 지지된 적용 범위로 보인다. 한 절 안에서 같은 낱말이 다른 대상을 가리킨다.

C5. 확정 여부의 이름. README L34 "settled", L145 "becomes unresolved again", L107 "A question is resolved", L175 "unresolved, informally proved or refuted"; 운전 안내 L46 "a question is free, that is, open"; Zenodo "while the conjecture was still open"
settled와 resolved/unresolved가 같은 대비인지 확실하지 않다. 질문에는 resolved와 open이 쓰인다.

C6. 지위의 이름. README L91 "It gives each claim one of three statuses", L97 "### Relations, propagation and the standing of nodes", L145 "A pending concern does not change any claim's standing", L175 "its state, which is unresolved, informally proved or refuted"
주장에는 status와 standing이, 노드에는 state와 standing이 쓰인다. standing은 정의되지 않으며, status와 state 가운데 어느 것을 가리키는지가 자리마다 다르다.

C7. "hold"와 "occupied"의 여러 대상. README L77 "it holds the node's **lease**", L79 "registering a whole node while another session holds part of it", L77 "The section counts as occupied"; 운전 안내 L46 "held by no session"(질문), L94 "every unresolved node is occupied"; 첫 운전 문서 L55 "a node another session occupies"
hold는 임대, section 점유, 질문 점유에 두루 쓰이고, occupied는 section과 노드에 쓰인다. 노드 점유와 section 점유의 관계가 정의되지 않았다.

C8. retained work의 정의 충돌. README L71 "What a producing session leaves behind is its **retained work**: the files it keeps in its own directory while it works." / L71 "The runner saves the session's conversation alongside these files, and the peer receives that as well." / L89 "receives the producing session's complete retained work, including the full conversation"
정의로는 retained work가 파일이고 대화는 그 곁에 따로 저장된다. 그런데 L89는 대화가 retained work에 포함된다고 한다. review가 대조하는 대상(L48 "the producing session's retained work")에 대화가 들어가는지도 이 때문에 모호하다.

C9. "record"의 여러 대상. README L222 "The design and decision record of the current implementation is"; Zenodo "The software, its design record and a description of these files"; README L18 "it records a finding on the record"
지식 기반의 기록 단위인 record와 설계 문서인 design record가 같은 낱말이다. Zenodo에서는 둘이 한 문단 안에 있다. 동사 record도 같은 문장에서 겹친다.

C10. 관계와 함의. README L36 "a **relation**, a reviewed implication between nodes", L7 "every record and every implication", L22 "two chains of implications"; Zenodo "the accepted implications to other nodes"
정의된 용어는 relation인데, 독자가 가장 먼저 읽는 자리(표, 리드, Zenodo)에서는 implication이 쓰인다. L99에서 relation은 여러 전제를 가질 수 있다고 하므로 "implication between nodes"(두 노드 사이의 함의)와도 결이 다르다.

operator, operator session, operator conversation이 섞인다. 특히 operator session은 러너가 띄우는 세션과 같은 종류로 읽힐 수 있는데, L14에 따르면 운영자는 러너가 띄우지 않는다.

account와 exposition이 섞인다. 같은 문서에서 account는 "full account of the first run"(L10, L26)이라는 문서 이름으로도 쓰인다.

review가 행위와 그 행위를 하는 세션(역할)을 함께 가리킨다. "the review decides"와 "survives review"가 같은 문서에 있다. attempt도 행위와 세션을 함께 가리킨다(L40 "an **attempt** tries to settle a node").

C23. 생산 세션의 이름. README L16 "the first session", L40 "A producing session", L91 "the producer's retained work", L71 "a producing session"; Zenodo "the first session's files", "the third session's assessment"
first session, producing session, producer가 섞이고, Zenodo는 세 세션을 순서수로만 부른다. Zenodo에서 "AI review session"(둘째 문단)과 "the third session"(넷째 문단)이 같은 것임을 독자가 맞춰야 한다.

### [D] 영어 문장으로서의 어색함

D1. README 한눈 보기 표. "One necessary condition of the root has a Lean proof, a proof that leaves the root open."
"a proof that ..." 동격 덧붙임이 앞 명사와 같은 낱말을 되풀이해 걸린다. "whose proof leaves the root open"이 더 자연스럽다.

D2. README 한눈 보기 표. "that is, with rounding error covered by assumed margins rather than tracked."
"rather than tracked"가 무엇에 의해 추적되는지 없이 끊긴다. L137은 "rather than tracked by the arithmetic"로 완결된다.

D3. README L18. "it records a finding on the record"
records/record가 붙어 되풀이된다.

D4. README L24, 첫 운전 문서 L44, L62, Zenodo 셋째 문단. "so that the sessions could finish the informal mathematics before formalization resumes"
같은 목적절이 네 문서에 걸쳐 거의 글자 그대로 반복된다. 과거 시제 "could finish"와 현재 시제 "resumes"가 한 절에 섞여 있고, "재개 전에 끝내도록 멈췄다"는 목적이 동어반복처럼 읽힌다.

D5. README L24. "No person has refereed the records. Several steps depend on computer-assisted inputs. And there is no Lean proof of the conjecture yet."
짧은 문장 셋이 끊겨 나열되고 셋째는 "And"로 시작한다. 셋이 한 묶음의 한정이라는 것을 문장 구조가 보여 주지 않는다.

D6. README L93. "By default the peer and review roles list a different model first than the producing roles do."
"a different model first than"은 영어에서 잘 쓰지 않는 짝이다. "list first a model different from the one the producing roles list first"의 뜻을 독자가 풀어야 한다.

D7. README L83. "Instead, a separate process called the **session host**, which starts with the session and lives as long as the session does, resumes the conversation each time a process exits and asks the session to reconsider, under its role guide, whether to end; by default it does so up to three times."
주어 "a separate process"와 동사 "resumes" 사이에 관계절이 끼고, 이어 "asks ... to reconsider, under its role guide, whether to end"에서 또 삽입구가 끼어 따라가기 힘들다. "session"이 한 문장에 세 번 나온다.

D8. README L101. "A node is on a **route** to the root when a chain of relations lets a proof of the node contribute to settling the root, and such a chain is itself called a route"
"on a route"를 먼저 쓰고 route를 문장 뒤에서 정의해 순환처럼 읽힌다. "lets a proof ... contribute to settling"은 명사구가 동사를 대신해 무엇을 하는지 흐리다.

D9. README L113. "two documents in their starting context, in every instance started with the current do-math."
"in every instance started with the current do-math"가 문장 끝에 매달려 무엇을 한정하는지 흐리다. "started with"가 앞의 "starting context"와 겹친다.

D10. README L137. "In the second kind, binary64 floating point with an error model assumed in advance, the rounding error is covered by margins added to the results rather than tracked by the arithmetic."
동격구가 주절 앞에 끼어 "the second kind"와 "the rounding error" 사이가 멀다.

D11. README L155. "It was formalized before the rule that limits formalization to outcomes that can reach the root was added, as the full account explains."
주어 "the rule"과 동사 "was added" 사이에 관계절이 두 겹이다. formalized/formalization이 되풀이된다.

D12. README L157. "Version 2, [10.5281/zenodo.24142218](https://doi.org/10.5281/zenodo.24142218), was taken on 12 November at 01:52 Korean time, after the root had been informally proved, and holds 300 records; version 1, [10.5281/zenodo.24110811](https://doi.org/10.5281/zenodo.24110811), was taken on 11 November at 00:19 Korean time, while the root was still unresolved."
DOI 링크 두 개와 시각 두 개가 한 문장에 들어가 지나치게 길다.

D13. README L14. "what a session produces is handed on as files, and what survives review is published as a record"
수동태가 행위자(러너)를 숨긴다. 누가 넘기고 누가 게시하는지는 L95에 가서야 나온다.

D14. 첫 운전 문서 L44. "so nothing of them was published"
"nothing of them"은 영어에서 잘 쓰지 않는다. "none of their work was published"가 자연스럽다.

D15. 첫 운전 문서 L42. "the limit was in the end proved outright, which is what the theorem's name records."
"in the end"가 동사구 가운데 끼어 어색하고, "which is what the theorem's name records"는 이름의 어느 부분(unconditional)을 말하는지 적지 않는다.

D16. 첫 운전 문서 L62. "a control file, recognised by a temporary change to the runner"
네 문서는 미국식 철자(organized, authorizes)를 쓰는데 여기만 영국식 "recognised"다.

D17. 첫 운전 문서 L66. "Mathematical material from an AI session outside the instance, reported at the user's request and checked by the operator in exact arithmetic and against published records; passed on for the sessions to judge for themselves"
"reported"의 행위자(그 외부 세션인가, 운영자인가)가 수동태에 숨는다. "passed on"도 주어가 없다.

D18. README L157, 첫 운전 문서 L72, Zenodo 둘째 문단. "Version 2 ... was taken on 12 November", "This version of the archive was taken on 12 November 2026 at 23:25"
"taken"만으로 "스냅숏을 떴다"는 뜻을 맡긴다. "snapshot taken"이나 "archived"처럼 대상을 밝히지 않으면 처음 읽을 때 걸린다. "taken"과 "deposited"의 차이도 첫 운전 문서 L72에서야 분명해진다.

D19. 운전 안내 L111. "their peers and reviews, and any formalizations and organizations, still launch as their inputs become ready"
"formalizations and organizations ... launch"는 일의 이름을 발사 대상으로 쓴 명사화다(C16과 겹친다).

D20. README L99. "The runner applies each accepted relation in every direction that propositional logic allows"
관계를 "방향"으로 적용한다는 비유가 흐리다. 뒤의 예가 전건 긍정과 후건 부정을 뜻함을 밝혀 주지만, 여러 전제 관계에서 "every direction"이 무엇인지는 끝내 말하지 않는다.

D21. README 한눈 보기 표 "What it is" 행. "The session that produces a piece of mathematics, the session that writes it up for others and the session that assesses it are three different conversations"
같은 꼴의 긴 명사구 셋이 주어여서 동사 "are"가 멀다. "the session"이 세 번 되풀이된다.

D22. Zenodo 첫 문단. "One works on the problem, trying to prove or refute a statement, to understand some feature of the problem, or to turn an accepted proof into a formal proof in Lean 4; a second reads everything the first left behind and develops it into a draft record; a third checks that draft against the first session's files and assesses every claim in it."
쌍반점 셋으로 이은 한 문장이 지나치게 길다. "the problem"이 한 절에 두 번 나온다.

D23. README L145. "A pending concern does not change any claim's standing: the claim and everything derived from it keep their standing, and the derived outcomes are marked as resting on a questioned claim, until a review session, usually a **comprehensive review**, issues a finding that withdraws or reaffirms the claim."
"until"절이 어느 동사(keep인가, are marked인가)에 걸리는지 흐리고, 문장 가운데서 새 용어를 정의한다. "standing"이 연이어 두 번 나온다.

D24. 첫 운전 문서 L48. "the installed copy that the instance executes was regenerated and the runner restarted"
수동태로 누가 재생성하고 재시작했는지 숨긴다(앞 문장으로 저자임을 짐작할 뿐이다).

D25. Zenodo 넷째 문단. "the records selected as shared context for new sessions, the modules into which the records were grouped"
수동태 둘이 행위자(organizer)를 숨긴다. Zenodo 독자는 그 행위자를 알 길이 없다.

D26. README L16. "Next, a second session, the peer, takes over from those files."
"take over from"은 보통 사람이나 앞 담당자를 목적어로 받는다. 파일에서 넘겨받는다는 짝이 어색하다.

D27. README L109. "Work may settle something, let the research see something it could not see before, or change how the problem is approached"
"let the research see"는 연구를 주체로 의인화해 뜻이 흐리다. "something"이 두 번 되풀이되고 끝은 수동태다.

### [E] 문장 사이와 문단 사이의 연결

E1. README L18. "No session assigns work to another, and a session in the first stage reads the knowledge base and decides for itself what to work on. The one exception to that free choice is formalization: the runner requests it"
finding 이야기 다음에 일감 선택 이야기가 연결어 없이 붙는다. 또 "No session assigns work"의 예외로 러너(세션이 아님)를 들어 논리가 어긋난다. peer, review, comprehensive review도 할당되는 일인데 예외로 언급되지 않는다.

E2. README L20. "Useful work that is not yet perfect is still published, together with its assessment, so that a later session can tell an established result from a claim that still needs more work."
"독립적 판단" 문단의 마지막 문장인데, 내용은 "불완전한 것도 게시한다"는 연속성 쪽의 결정이다. 앞 문장이 이 문장을 부르지 않는다.

E3. README L109. "The role guides describe progress as the change a piece of work makes to what is known."
질문(question)의 정의와 해결을 다룬 두 문단 뒤에, 진전의 정의가 앞 문단과 잇는 말 없이 놓인다. 이것이 질문의 해결 판정과 어떤 관계인지, 시스템의 어느 결정(발사, 판정)에 쓰이는지 나오지 않는다.

E4. README L24. "The knowledge base is public on Zenodo."
한계와 완료 조건을 말하는 문단 끝에 공개 사실이 연결 없이 붙는다.

E5. 운전 안내 L80. "Changing the root's statement requires a new instance."
상시 지시의 제출과 철회를 다룬 문단의 끝에, 주제가 다른 문장이 붙는다. 상시 지시로 뿌리를 바꿀 수 없다는 뜻이라면 그렇게 이어야 연결된다.

E6. Zenodo 둘째 문단 끝에서 셋째 문단 첫머리. "Version 2 was taken on 12 November at 01:52 Korean time with 300 records, and version 1 on 11 November at 00:19, while the conjecture was still open." → "That state has qualifications that a reader should know before relying on it."
"That state"의 선행어(informally proved)가 판본 이야기 세 문장 앞에 있다. 바로 앞 문장의 "still open"을 가리키는 것처럼 읽힌다.

E7. 첫 운전 문서 L42. "so its refutation would have refuted the root, while its proof leaves the root open; the limit was in the end proved outright, which is what the theorem's name records."
"its proof leaves the root open" 다음에 "the limit was in the end proved outright"가 오는데, 증명된 것이 이 노드와 같은지, "outright"가 무엇과 대비되는지(조건부 증명이 먼저 있었는지) 앞 문장이 준비하지 않는다.

E8. 운전 안내 L9. "The runtime needs Lean 4 in every case, because the settings name a Lean installation and the broker starts with the runner"
"설정이 Lean을 지명하므로 Lean이 필요하다"는 이유는 순환이다. 실제 이유(broker가 러너와 함께 시작한다)만으로 충분하다.

E9. README L83. "so the runner does not close the session when one of those processes exits. Instead, a separate process called the **session host** ... resumes the conversation ... once the limit is reached, the runner authorizes the end."
행위자가 러너에서 세션 호스트로, 다시 러너로 바뀐다. 세션이 "explicit decision"을 제출하면 그 자리에서 끝나는지, 세 번이 다 찬 뒤에만 끝나는지가 연결로 드러나지 않는다.

### [F] 수학적으로 틀리거나 모호한 진술

F1. README L153, 첫 운전 문서 L36, Zenodo 둘째 문단. "that the sequence never decreases below the middle" / "the sequence has no descent at all below the middle, that is, that it never decreases there" / "that the sequence never decreases below its middle index"
두 경로가 모두 지나는 핵심 명제인데 범위의 경계가 정해지지 않는다. 첫 운전 문서 L32의 관례("locate each step at the index ℓ where it begins")로 "below the middle"을 ℓ < m인 하강으로 읽으면 m−1에서 m으로의 하강도 배제되어 첫째 경우까지 따라 나온다. 그런데 문서는 이 명제가 셋째와 넷째 경우만 증명한다고 하므로(L36), 실제 범위는 ℓ ≤ m−2인 듯하다. L36의 "n lies between 2ℓ and about 2ℓ^(3/2)"를 b(n, ℓ−1) ≤ b(n, ℓ)에 대입하면 n이 짝수일 때 ℓ = m이 포함되어 다시 m−1에서 m으로의 걸음이 들어간다. README는 위치 관례 자체를 주지 않는다.

F2. 첫 운전 문서 L36. "the records established that the neighboring counts b(n, ℓ−1) and b(n, ℓ) agree to leading order as ℓ grows, and that their difference b(n, ℓ) − b(n, ℓ−1), whose sign decides the inequality, is only of order ℓ^(−1/3) times either count."
n이 2ℓ에서 약 2ℓ^(3/2)까지 움직이는데 상대 차이가 ℓ^(−1/3) 차수라는 것이 그 범위에서 균일한지, 최악의 경우인지, 특정 n에서인지 나오지 않는다. "about 2ℓ^(3/2)"의 "about"도 경계를 흐린다. 여기서는 걸음을 ℓ−1에서 ℓ로 적어, L32의 ℓ에서 ℓ+1 관례와 첨자가 어긋난다.

F3. README L151, 첫 운전 문서 L34. "whenever the sequence decreases from one term to the next, the square of the next term is at least the product of the terms on either side of it. From this it follows that once the sequence has decreased it cannot rise again."
이 추론(b_{ℓ+2} ≤ b_{ℓ+1}²/b_ℓ < b_{ℓ+1})은 항이 모두 양수일 때만 성립한다. b(n, ℓ) > 0이 모든 0 ≤ ℓ ≤ n−1에서 성립한다는 말이 어디에도 없다(참일 것으로 보이지만 명시되지 않았다). 첫 운전 문서 L34의 범위 "for all n ≥ 3"에서 n = 1, 2가 자명하게 성립한다는 말도 없다.

F4. README L34와 L99. "A node is **settled** once either it or its negation has been proved" / "If accepted arguments currently support both a node's statement and its negation, the node is marked *contested*; it then counts neither as work available to attempts nor as settled"
L34의 정의대로라면 양쪽이 다 증명된 contested 노드도 settled다. L99는 그것이 settled가 아니라고 한다. 정의가 예외를 포함하지 않는다.

F5. README L101. "A node is on a **route** to the root when a chain of relations lets a proof of the node contribute to settling the root, and such a chain is itself called a route; a node is a necessary condition of the root when only its refutation can contribute."
L99에 따르면 관계는 여러 전제를 가질 수 있고, 첫 운전의 첫째 경로는 네 경우가 함께 뿌리를 함의한다. 그러면 경로는 사슬이 아니라 나무(또는 DAG)다. "contribute"가 "다른 전제와 함께 충분조건의 일부가 된다"는 뜻인지 정의되지 않는다. 뿌리와 동치인 노드는 증명과 반증이 모두 기여하는데, 그것이 route 위에 있으면서 필요조건이기도 한지 "only"의 쓰임으로는 판단할 수 없다.

F6. README L36. "In the same way, a record that settles part of what a node asserts can propose the parts as nodes, with the relation that the parts together cover the whole."
"part of what a node asserts"를 확정한 기록이 왜 "the parts"(복수, 나머지 부분까지)를 노드로 제안하는지, "cover the whole"이 논리적으로 무슨 관계(부분들의 연언이 전체를 함의함)인지 분명하지 않다.

F7. README L75. "a **section** of it, an exact part of what the node asserts, which may be the whole node."
명제의 "part"가 무엇인지(매개변수 범위의 제한인지, 연언 성분인지, 경우 분할인지) 정의되지 않는다. 겹침 판단(L79)이 이 정의에 기대므로, 독자는 예 없이 개념을 잡기 어렵다.

F8. 첫 운전 문서 L34. "record rdc276812 proves that, for these particular sequences, the second part is equivalent to the fourth case of the first route, so the frontier derives it from that case."
"the second part"의 선행어가 "at steps below m"인 부분임을 앞 문장에서 짐작해야 한다. 또 "넷째 경우가 일어날 수 없다"는 명제와 동치라고 해야 할 것을 "the fourth case"와 동치라고 적어, 경우(일어나는 사건) 자체와 동치인 것처럼 읽힌다.

F9. 첫 운전 문서 L38, README L153. "That certification checked the steps at or beyond the middle in interval arithmetic with integer endpoints"
b(n, ℓ)는 정수이므로 정확한 정수 산술로 셀 수 있을 텐데, 왜 정수 끝점의 구간 산술을 썼는지(정확한 값을 계산하지 않고 상하계를 계산했는지) 나오지 않는다. 검증의 성격을 판단하는 데 필요한 정보다.

F10. 첫 운전 문서 L67과 README L159, 한눈 보기 표. "two monotonicity properties that a table used by record r030ffaeb relies on and that its review had accepted on numerical evidence" / "Several records on the routes rest on binary64 computations with error models assumed in advance, and the root's informal proof depends on them"
첫 운전 문서 L78에 따르면 r030ffaeb는 경로 위의 기록이다. 그 표가 기대는 두 단조성이 11월 11일 뿌리가 비형식 증명되었을 때 "numerical evidence"로만 받아들여져 있었고, 증명은 12일 16:12 이후에 나왔다. README의 한눈 보기 표와 Limits는 의존을 "binary64 computations with error models assumed in advance"로만 적는다. 이 수치 증거가 그 범주에 드는지, 아니면 다른 종류의 미증명 단계인지, 뒤의 세 기록이 프론티어에서 무엇을 바꾸었는지 어느 문서도 말하지 않는다. 신뢰를 평가하려는 독자에게 가장 걸리는 자리다.

F11. 첫 운전 문서 L42. "let F_ℓ(z) = Σ_j A(j, ℓ) zʲ / j! be the exponential generating function of these numbers" / "the limit was in the end proved outright"
합의 범위(j = 0부터인지 1부터인지)가 없다. 차에서 상수항이 지워지면 결과에는 영향이 없겠으나 정의로서는 빠져 있다. "proved outright"가 무엇과 대비되는지(조건부 증명이 따로 있었는지) 나오지 않아, 형식 증명된 정리와 노드가 정확히 같은 명제인지 판단할 수 없다. 단봉성이 이 극한을 함의한다는 r801ec220의 내용도 한 줄의 실마리 없이 주장만 된다.

F12. README L133. "and later work may use the result within the range the review supported."
review가 "range"를 지지한다는 것이 무엇인지(주장의 적용 범위, n의 범위) 모호하다. 지지된 결과가 노드 진술 전체보다 좁을 수 있다는 뜻이라면 노드가 informally proved라는 판정과 어떻게 맞물리는지 설명이 필요하다.

F13. README L137. "binary64 floating point with an error model assumed in advance, the rounding error is covered by margins added to the results rather than tracked by the arithmetic."
가정된 오차 모형이 연산당 상대오차 한계인지, 누적오차 추정인지, 여유폭이 어떻게 정해졌는지 나오지 않는다. 독자에게 "그 모형을 받아들이지 않으면 미증명으로 보라"고 하면서 판단할 재료를 주지 않는다.

F14. 첫 운전 문서 L36. "In the part of that statement's range that resisted longest, where n lies between 2ℓ and about 2ℓ^(3/2)"
"below the middle"이 ℓ < n/2 쪽이면 n > 2ℓ이므로, n의 범위가 위로 2ℓ^(3/2)까지라는 것은 ℓ이 √n 차수보다 큰 쪽(대략 (n/2)^(2/3) < ℓ < n/2)을 뜻한다. 문서가 변수 하나(ℓ)를 고정하고 n을 움직이는 방식으로 적어, "가운데 아래" 영역 가운데 어느 띠인지 n 기준으로 읽기 어렵다. 해석은 맞게 했다고 보지만 문서가 확인해 주지 않는다.

## 3. 확정하지 못한 것

1. **binary64, directed rounding, interval arithmetic**: IEEE 754 배정밀도, 방향 반올림, 구간 산술로 외부 지식에 기대어 읽었다. "error model assumed in advance"가 구체적으로 무엇인지는 추측도 하지 못했다.
