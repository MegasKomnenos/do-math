## 5. 확인한 사실

### 5.1 do-math(현행, `.claude/skills/do-math/`)

- 역할 여섯: attempt, explore, formalizer(생산), peer, review(처리), organizer. 파이프라인 = 생산 세션 + peer + review. (`SKILL.md`, `reference/common.md`)
- attempt는 배정 없이 스스로 노드와 섹션을 고른다. 섹션은 노드 명제의 정확한 일부. 조정은 live board와 노드 lease. 도구는 같은 문장, 전체 노드 충돌, 비중복 이유 누락만 거부. (`roles/attempt.md`, `reference/tools.md`, `reference/common.md` board 절)
- peer는 생산 세션의 보존물 전체(대화 포함)를 읽고 기록 후보를 만들며 수학을 더할 수 있다. review는 후보와 원본을 양방향 대조해 claim마다 supported/unsupported/undetermined를 판정하고, 본질적 새 증명을 스스로 만들어 인증하지 않는다. (`roles/peer.md`, `roles/review.md`, `reference/review-output.md`)
- 기본 모델: 생산·organizer는 codex/gpt-6.1-sol xhigh 다음 claude/opus xhigh; peer·review는 그 반대 순서. 기본 동시성 8, 출시 간격 180초, explore_every 1(attempt 출시마다 탐구 요청), organizer_every_records 4, max_end_resumptions 3. (`reference/operations.md`)
- 기록은 불변. review 평가와 finding이 덧붙는다. frontier·index·board·glossary는 도출 보기. 인스턴스는 Git 저장소, 게시마다 커밋. (`reference/common.md`, 설계 기록 10.1·11.1)
- 노드는 정확한 명제. 새 노드는 검토된 관계로만. 관계는 절로 읽혀 명제 논리의 모든 방향으로 전파. contested 격리. 질문(이해의 대상)은 explorer가 점유, q0 = root. 운영자도 `questions` 명령으로 질문을 올릴 수 있다. (`reference/common.md` frontier·questions, `reference/operations.md`)
- 완료: root는 독립 검토가 Lean 증명을 재컴파일·공리 감사·정확 대응 비교해 확인할 때 해결. 허용 공리 propext, Classical.choice, Quot.sound. sorryAx 불허. 형식화는 root 경로 위 결과에만. (`SKILL.md`, `reference/lean.md`)
- 세션 시간 상한 없음. 세션 호스트가 같은 대화를 재개해 종료 재판단(기본 3회). 중단된 보존물도 peer로. (`reference/retained-work.md`, `reference/operations.md`)
- 실행기는 CLI 위에서 분리 프로세스. API 직접 호출 없음. 작업자는 개인 지시·훅·기억을 받지 않음. 1M 컨텍스트 요청. Lean 브로커 인스턴스당 하나, 메모리·스레드 예산. 상시 입력은 이후 세션에만, 누적. (`SKILL.md`, `reference/operations.md`, `reference/lean.md`)
- 연구 목적 에세이와 사용자 작문 선호 문서가 연구 역할의 시작 컨텍스트에 실린다. "무엇이 연구를 전진시키는가": 닫기, 보게 하기, 접근 바꾸기. 범위 확장 자체는 아님. (`reference/common.md`, `reference/what-research-is-for.md`, `reference/user-writing-preferences.md`)
- 명령: start, run, status, stop, resume, reconsider-attempts, input --file, review --record/--node, organize, questions --file, kill-session, render, restart-broker. (`reference/operations.md`)
- 시험: `python -B -m unittest discover -s .claude/skills/do-math/runtime/tests -v`. 2026-11-10 런 뒤 316건 통과(M-0697). 오늘 실행 결과는 로그로 확인. 실제 CLI·Lean 검사는 `docs/do-math/rebuild-verification.md`.
- 플랫폼: Windows에서 개발·검증. 프로세스 식별은 Windows API와 Linux /proc만 구현. Linux 실행은 검증되지 않음(L-0020). macOS 미구현.
- 설계 기록 `docs/do-math/rebuild-design.md`(2026-11-04). 검증 보고 `docs/do-math/rebuild-verification.md`.
- 효과 측정: 섹션·질문·종료 재판단 등의 장치가 성과를 바꾸었는지 측정된 적 없음(L-0020 「잔여」).

## 8. 압축 진술

do-math는 하나의 수학 명제를 두고 여러 개의 새 AI 세션이 사람의 개입 없이 연구를 이어 가게 하는 시스템이다. 세션들은 대화를 공유하지 않고, 두 개의 독립 세션이 발전시키고 평가한 불변의 기록만 공유하며, 각 세션은 무엇을 할지 스스로 고른다. 첫 전면 운전에서 이 시스템은 2025년 논문의 열린 추측을 엿새 만에 독립 검토가 승인한 비형식 증명으로 이끌었고, 그 기록 전체를 공개했다. 형식 검증은 아직 남아 있다.

## 9. 경중 선언

- **무거운 것:** (1) 세션들이 협력하는 방식: 계획자 없음, 두 독립 세션의 처리, 불변 기록과 도출 보기, 관계의 전파, 질문. (2) 무엇이 확립된 것으로 세어지는가: 보증의 층과 게시가 증명하는 것·하지 않는 것. (3) 첫 운전의 결과와 그 보증 수준, 근거의 자리, 한계.
- **가벼운 것:** 탐구·종료 재판단·운영 기반, 지식 베이스 읽는 법, 요구 사항과 시작·운영 명령, 저장소 배치·시험·검증, 부속 도구·스킬, 언어·로드맵·인용·라이선스, 자리 표시자 다섯.
- **뺄 것:** 실행기 내부 구현(비상 메모리, 보관 압축, 파일 교체 재시도), 과거 세대의 구현 역사, 다른 시스템과의 비교, 효과에 대한 추정, 측정되지 않은 장점 주장, 작성 경위.

## 10. 작문 계약

- 목적이 내용보다 먼저. 첫 문단들이 존재 이유와 세 독자의 경로를 말한다.
- 담백하게, 충분히 풀어서. 과장 형용사·비유·경구·연출 없음. 장치는 무엇을 어떻게 하는지 완전한 문장으로.
- 경중은 구조로. 무거운 것은 앞에, 길게, 산문으로. 가벼운 것은 뒤에, 표로. 중심 논증을 글머리표로 바꾸지 않는다.
- 한 걸음씩, 정의가 먼저. 용어는 처음 쓰는 문장 안에서 무엇인지 말한다. 절 제목은 내용을 말한다. 앞 문장이 다음 문장을 부른다.
- 디테일은 검증을 위해. 수치·날짜·좌표는 확인 가능한 자리에만. 모든 성과 진술은 링크나 상태를 적은 자리 표시자로 이어진다. 보증 어휘는 시스템 어휘 그대로.
- 닫힌 열거로 읽히지 않게. "such as", "for example".
- 판단의 바탕만. 독자 내적 상태 진술, 비교 최상급, 권유 없음.
- 사족 없음. "does not cover", 작성 경위, "note that", 양해 문장 없음.
- 한 낱말 한 뜻. do-math 어휘 그대로. 빈 명사 뒤 지시어로 채우기 없음.
- 지적은 모아서 원인부터 고친다.
