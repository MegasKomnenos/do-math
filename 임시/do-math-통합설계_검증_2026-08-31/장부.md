## 라운드 2 — 사유 절

- **R2-01** (승인 2/3)
  - 2기: 관문 5와 관문 3이 성립하지 않는다. 대체 문면은 기록 즉시 발견 후보를 F 객체로 만들면서 공용 편입 전에는 새 핵심 기록 ID를 주지 않는다고 한다. 그러나 현행 용어에서 F 객체는 핵심 기록 객체이고 핵심 기록 객체는 안정된 핵심 기록 ID를 가져야 한다. 따라서 대체 문면은 F 객체의 저장·식별 경계를 모순되게 만들며, 기록된 후보가 F 객체인지와 어떤 식별자로 관리되는지를 구현자가 다시 정하게 한다. 영향 칸이 든 F·작업 씨앗·관계 입력의 처분 불명확성도 해소하지 못한다.
- **R2-03** (승인 2/3)
  - 2기: 관문 3이 성립하지 않는다. 대체 문면은 계약이 무엇을 닫아야 하는지와 감사 결과가 가져야 할 내용을 서술하지만, 계약 자체의 ID·판본·필드와 닫힌 판정 어휘의 실제 값을 정하지 않는다. 레지스트리에는 `do-math/goal-audit/1` 한 줄만 추가되어 계약과 결과를 구별한 스키마와 필드를 소유하지 않는다. 그러므로 구현자는 계약과 결과의 기계 문서 경계, 판정 값, 상태 효과를 다시 결정해야 하며 영향 칸의 구현 가능한 인터페이스 결손이 남는다.
- **R2-06** (승인 1/3)
  - 1기: 관문 3 해결에 실패한다. 대체문은 요청 입력만 역할 일반으로 바꾸고 결과 기록의 run 전제를 남긴다. 따라서 비작업 역할 요청의 결과를 어느 예상 OID에 조건부 연결하는지 여전히 정해지지 않아, 영향 칸의 역할 일반 감독기 프로토콜 공백을 없애지 못한다.
  - 2기: 관문 3이 성립하지 않는다. 대체 문면은 요청 본문과 검사 문장만 target ref와 역할별 전이로 바꾸지만, 바로 뒤 결과 기록과 감독기 소실 복구는 여전히 예상 run OID와 run ref만 대상으로 한다. 따라서 작업자가 아닌 역할의 요청은 결과를 어느 상태 OID에 조건부 연결하고 소실 뒤 무엇과 대조할지를 구현자가 별도로 정해야 한다. 영향 칸의 역할 일반 감독기 프로토콜이 완성되지 않는다.
