### 2.1 (10.2) `vertical_exact_constant.py`가 import하는 `exact_first_constant.py`가 묶음에 없다

**사실 여부.** 참. `원고_자료/rce3dc75/vertical_exact_constant.py` 4행 `from exact_first_constant import add,scale,trig_integral`; 묶음에 `exact_first_constant.py` 없음. 기록에는 `records/rce3dc75…/evidence/producer/work/exact_first_constant.py`가 있고(`add`·`scale`·`trig_integral`을 정의하고 자기도 같은 상수 $46\sqrt2-12$를 다른 다항식 묶음으로 계산해 `exact-first-constant.json`을 씀), `vertical_exact_constant.py`의 출력 `evidence/producer/output/vertical-exact-constant.json`도 「자료」 줄에 없어 묶음에 없다. 부록 D D.central-gap-rational-audit 「알고리즘」(ㅁ)이 이 코드를 들고 「자료」 줄이 `exact-first-constant.json`(다른 스크립트의 출력)만 들고 있었다.

**같은 종류의 누락 전수.** 피드백은 하나를 들었지만, 묶음의 `.py` 전부를 훑으니(`…_ZV3_imports.py`) 기록 코드 사본 가운데 **같은 폴더에도 묶음 어디에도 없는 모듈을 읽는 것이 15개 기록 항목에 걸쳐 31건**이었다(`…_ZV3_locate.py`가 기록 안 위치를 모두 찾음; 둘은 기록에도 없음). 아울러 부록 D가 「독립 재계산」 줄에서 인용한 출력 파일 가운데 「자료」 줄에 없거나 생성기가 읽지 못하는 꼴(`…/out/x.out`, `.out`)로 적혀 묶음에 빠진 것이 11건이었다(`…_ZV3_files.py`).

**분류.** 재현을 막는 누락(진짜 결함). 항등식이나 결과의 옳고 그름과 무관하고, 묶음만으로 해당 코드를 돌릴 수 없는 문제다.

**결정.** 바꾼다 — 부록 D 「자료」 줄에 빠진 파일을 더한다(묶음 폴더에 직접 넣지 않음; `scripts/자료묶음_v2.py`가 「자료」 줄에서 복사하므로 세션이 재실행). `python -I scripts/자료묶음_v2.py --dry`로 새 토큰 36개가 모두 기록의 실제 파일로 풀림(문제 0)을 확인했다. 자리와 전→후는 3절.

**함께 드러난 것 — `python -I`.** README 「실행 환경」은 「모든 스크립트는 `python -I`로 돌린다 … 같은 폴더의 모듈을 읽는 스크립트는 스스로 `__file__`의 폴더를 `sys.path`에 넣는다」고 적는데, 이것은 이 글의 재계산(`세션_재계산/`)에만 맞고 **기록 코드 사본은 바이트 사본이라 그 처리가 없다**. Python 3.11부터 `-I`가 `-P`를 함의해 스크립트 폴더를 `sys.path`에 넣지 않으므로(이 기계 3.12.10에서 실측: 형제 모듈 import가 `ModuleNotFoundError`), 빠진 모듈을 더해도 `python -I rce3dc75/vertical_exact_constant.py`는 여전히 실패한다. 같은 폴더의 모듈을 읽는 기록 코드 사본은 묶음 전체에서 약 120건(`…_ZV3_imports.py`의 「sys.path 손보지 않음」 줄). `python -E -s`(`-I`에서 `-P`만 뺀 것; 환경 변수·사용자 site-packages는 여전히 읽지 않음)로 돌리면 된다(실측 성공). README 「실행 방식」 문단과 재실행표 생성기의 머리말·명령 접두를 그에 맞게 고쳤다(3절).

**바꾸지 않고 적어 두는 것(묶음의 평면 배치로는 「자료」 줄 보충만으로 안 되는 것).**
- `r89eb039/cert_ia.py`·`cert_ia2.py`(함수 안 `from bounds3 import sigma_bracket3`): `bounds3.py`는 기록 어디에도 없다. 그 함수가 호출되지 않는 경로에서는 영향 없음.

### 2.2 (10.3) 「근사 없이 재귀식 그대로를 정확 산술로 계산한 것」

**사실 여부.** 참. `장v2/부록D_장8.md` 15행(D.window-mass-env)·39행(D.bprime-boxes)·79행(D.band-boxes)의 「독립 재계산」 줄이 [r030ffae] 검토의 `rv_exact.py`를 「독립 정확 재귀(근사 없이 재귀식 그대로를 정확 산술로 계산한 것)」라 적었고, 11.2절 표 52–54행은 그 줄을 옮긴 생성물이라 같은 문구다. `원고_자료/r030ffae/rv_exact.py`의 머리말은 「reviewer's independent binary64 evaluation of Pr_n(M <= l)」이고 본문은 `numpy` 배열·`np.dot`·`math.lgamma`·`log`·`exp`로 지수 공식의 합성곱 재귀 $n\,a_n=\sum_s\min(s,\ell+1)a_{s-1}a_{n-s}$를 binary64로 평가한다. `rv_checks.py` 머리말도 「binary64; NOT a proof」. 「정확」은 재귀식이 점근 근사가 아니라 정확한 항등식이라는 뜻이었고 산술은 binary64다. 39행이 함께 드는 `evidence/peer/check/check_BV.out`의 코드 `check_BV.py`(기록)도 「binary64 via the exponential-formula recursion」이다. 세 줄의 꺾쇠 괄호 「산술 배정밀도 평가·방향 반올림 구간」은 이미 맞다. 수치 자체(`rv_checks.out`: 여섯 $k$에서 `W_min_ratio` $1.0418$–$1.0419$, $q=1$; `BVT_band_min`$\ge2.174$; `check_BV.out`의 세 $k$ 모두 $\ge2.17$)도 줄의 서술과 맞다.

**분류.** 설명을 흐리는 편집 오류이면서 1.5절 산술 등급 구별에 어긋나는 서술(「정확 산술」은 등급 이름 「정확 정수·유리수」를 떠올리게 한다). 증명의 보증에는 닿지 않는다(세 항목 모두 증명이 기대는 계산은 이 글의 방향 반올림 구간 재계산이고 이 대조는 「증명이 아니라 대조」로 갈라 적혀 있다).

**결정.** 바꾼다 — 세 줄 모두 「정확한 재귀식(지수 공식의 합성곱 재귀)을 독립적인 binary64 구현으로 평가한 수치 대조(`rv_exact.py`)」로. 39행은 `check_BV.py`(둘째 작성자)도 함께 든다. 11.2절 52–54행은 생성이라 세션 몫(4절). 같은 문구는 저장소의 다른 곳에 없다(`grep "근사 없이 재귀식 그대로"`: 부록D_장8 세 줄과 장11 세 행뿐).
