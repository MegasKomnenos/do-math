## 3. 세션 — 선택지(코드·자료 묶음·README; 내 범위 밖)

(가) `원고_자료/세션_재계산/r89eb039_polar_iv/consts_check.py` 73행은 기록의 $\Gamma(5/3)$ 괄호 `I(0.9027452929509336, 0.9027452929509338)`만 검사해 `bracket valid=False`·`SOME BRACKET INVALID`로 끝난다. 이 글이 실제로 쓰는 괄호(`achain_iv.py` 27행 `I(math.nextafter(0.9027452929509336, 0.0), 0.9027452929509338)`)도 함께 검사해 그것이 포위를 담음을 찍고 `ALL OK`로 끝나게 하면(코드 동작 변경 + 재실행 + README SHA 표 325행 갱신) 배포 자료에서 `INVALID`가 사라진다(원칙 8의 「문제 자체가 없어지는 길」). 그렇게 하면 D 216행의 「(검사 출력의 `bracket valid=False`)」 괄호만 빼면 되고 나머지 문장은 그대로 맞다. 하지 않아도 현행 D는 자료와 맞는다.

(나) `원고_자료/README.md` 738행 「… 상수 확인 `out/consts_check.txt`, …」에 출력의 뜻 한 절(예: 「기록 코드의 상수 괄호 검사; $\Gamma(5/3)$ 행의 `valid=False`는 기록 괄호의 아래 끝이 참값 위에 있다는 뜻이고 이 글의 `achain_iv.py`는 한 ulp 내린 괄호를 쓴다」)을 더할지. 원천은 `scripts/_patch_README_세션파일.py`의 PARAS일 것이다(N13 5절 셋째 항목).

(다) D.central-gap-integer 「$k\le40$ … 상대 폭 최대 $3.5\cdot10^{-33}$」의 출력 보존. `python -I validate_small.py out_small.txt`(같은 폴더의 `v_exact_small.py`가 필요)의 표준 출력 한 줄 「checked k up to 40 bad 0 worst relative gap 3.479229219116553e-33」을 `원고_자료/세션_재계산/` 아래 새 파일로 저장하면 D 「자료」 줄 끝에 그 경로를 더할 수 있다(D 본문의 수는 바뀌지 않음). 기록 폴더에는 이 출력이 없으므로 복사할 기록 파일은 없다.
