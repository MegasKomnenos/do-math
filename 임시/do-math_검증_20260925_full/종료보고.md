# do-math 전면 검증 종료 보고

## 종료 판정과 계수

사용자 지정 상한에 따라 1라운드로 종료한다. `종료집계`의 판정 순서 3항, 즉 라운드 수가 상한 1에 도달한 조건으로 종료한다. 이는 수렴이나 무결함 선언이 아니다.

| 단위 | 결과 |
|---|---:|
| 수리자 제기 항목 | 37 |
| 병합 묶음 / 구성 원 항목 | 9 / 20 |
| 단독 항목 / 최종 심사 대상 | 17 / 26 |
| 심사 확정 승인 / 기각 | 23 / 3 |
| 승인 중 수리 / 무처분 | 22 / 1 |
| 공식 적용 대상 / 조각 | 24 / 82 |
| 공식 적용된 원 항목 행 | 34 / 37 |
| 직접 보완한 나머지 원 항목 행 | 3 (심사 대상 2건) |

공식 적용 24건은 수리 승인 22건과 사용자 위임으로 추가한 R1-M1·R1-M3이다. 직접 보완한 R1-M5는 원 항목 R1-10·R1-30을, R1-27은 원 항목 한 행을 닫는다. 원 심사와 장부의 기각 상태는 보존하며 후속 처분은 `직접처리.json`에 분리했다. 중복 발견과 병합이 있으므로 37을 서로 다른 결함 수로 해석하지 않는다.

## 라운드별 제기·적용

라운드 1: 제기 37행, 공식 적용 34행. 수리자 8명 중 4명이 영역을, 4명이 관점을 맡았다. 심사자 3명 전원의 동의가 필요한 정족 3을 사용했고, 수리·심사 모델은 gpt-6-astra였다. 병합은 codex-full 기본 gpt-5.6-terra를 사용했다. 수리·병합·심사 결번은 없다.

## 주요 변경과 잔여

- 소비되지 않는 정지 유예 설정, 인라인 운영 점검 래퍼, 옛 입력 복원 실행·검사 경로를 제거했다. 현행 설치 수리 인계와 retry의 Git 저장·재처리 검사는 유지했다.
- 자기 점검 요청과 실제 native 호출·중앙 영수증을 결합하고, preview·안전 경계·자기 점검 호출을 구분했다. 관찰 규칙 파일·중복 JSON 키·자동 규칙 ID, 활동 종류·질문 차단·사용량 저장의 계약을 맞췄다.
- 지연 게시 후 활동 정산, 완료 복구의 정리 조건, 미검증 지식의 형식 검사, 확장 검토 자리·정기 탐색 사건·참조화된 과제의 소비를 고쳤다. 복합 조건의 반복 인덱싱과 상태 조회의 개별 Git 읽기를 줄였다.
- 예약 실패 후 저장 결과와 실행 가능한 재조정 명령을 보존하고, 현행 실행·입력·신뢰 검사에 맞게 문서를 정렬했다.

제기 항목 중 미처리 잔여, 상신, 무처분 잔여는 없다. 기각·무처분 원문과 심사 근거는 `기각보관/do-math-full-20260925-라운드1.md`에 보존한다. 전체 통합 스위트와 실제 장시간 모델 연구는 실행하지 않았다.

## 직접 처리와 승계

사용자의 명시적 위임에 따라 기각·무처분 4건 전부를 직접 검토했다.

| 대상 | 최종 처리와 근거 |
|---|---|
| R1-M1 | 삽입 조각 서식으로 기각됐다. 실제 오류 포착·저장 영수증·재조정 명령은 타당했다. 삽입한 시험 메서드가 최종 문면에서도 기존 OperatorTests 클래스 내부에 놓이는 것을 확인해 공식 추가 적용했다. |
| R1-M3 | 실행 결과가 같아 무처분됐다. 현행 호출자가 없는 래퍼·상수 플래그 정리는 사용자 목적에 직접 해당하여 공식 추가 적용했다. |
| R1-M5 | 설치 인계 함수를 삭제하고 retry fixture를 깨뜨리는 원 수리안은 유지하지 않았다. 현행 인계·권한·CAS 경계를 보존한 별도 구현으로 옛 복원 계약을 제거했다. |
| R1-27 | 넓은 호출 면제를 제거하되 안전 경계 제출이 자기 자신을 미신고 연구 호출로 보지 않게 별도로 식별했다. Codex·Claude와 중앙 접수 경계를 검사했다. |

사용자 확정 기록의 승계 전환은 없다. 추가 적용을 위해 최초 적용 파일 37개를 라운드 사본으로 복원한 뒤 공식 `적용 --강제 --추가`로 전건 재적용했다. 이후 직접 수리는 통상 편집으로 처리했다. 사용량 필드는 서로 겹치지 않는 두 제안의 중복 정의를 정리해 엄격한 domain 스키마 한 곳에 두었다.

## 최종 검증과 마지막 결산

고유 테스트 ID별 최신 결과는 **389개 전부 통과**다. 최종 단위 368개와 변경 경계의 통합·자원 21개를 합친 수치다. 서로 다른 실행 묶음의 최신 결과이며 전체 스위트 단일 실행을 뜻하지 않는다. 원 보고서별 수치·최신 결과 대응·소스 해시는 `검증결과.json`에 보존한다.

최초 단위 2오류는 시험 import 삭제를 수정해 해소했다. 병렬 회귀의 실패 한 건은 변경 전 사본에서도 재현됐다. 이 병렬 회귀에서는 시험 대역과 제출 도우미가 참조화된 입력을 실제 파일에서 읽지 않아 실패했다. 두 소비자가 정확한 파일 참조를 읽도록 수정했다. 정지 시험은 고정 15초 대신 실제 세 호출의 시작을 기다리게 했다. 실패 관측·기준선·후속 결과를 각각 보존했으며 제품 검사를 약화하지 않았다.

정본·생성 사본의 설치 구조 검사, Python 220파일 구문 검사, 스킬 미러 `--check`, diff 공백 검사를 통과했다. 테스트는 모델 응답 대역과 임시 Git·실제 로컬 프로세스를 사용한다. 실제 수학 연구·외부 모델의 연구 성능·전체 Lean 검증을 보증하지 않는다.

장부 마지막 결산은 공식 적용 34행, 기각 3행, 적용 0 연속 0회, 1라운드 상한 도달이다. 기각 3행은 위 직접 수리로 별도 처리됐으며 공식 승인으로 소급 기록하지 않았다.

## 보조 스크립트 승격 후보

`_prepare.py`는 동결·배분 작성, `_dispatch.py`는 파견문·CLI 병행 수송, `_pipeline.py`는 공식 명령 연결, `_coverage.py`는 수행 기록 대조, `_test_selection.py`는 변경 시험 선택, `_direct_repairs.py`는 사용자 위임 수리, `_debug_live.py`는 실패 실행 상태 보존, `_finish.py`는 종료 기록·검증 요약을 담당했다. 공식 판독·병합·심사 집계·조각 적용은 vr.py를 사용했다. 일반 승격 검토 후보는 파견 수송·독해 기록 대조이며, 판단이 섞인 일회 수리·종료 작성은 승격하지 않는다.

## 운영 기록 요지와 graphify

249파일 78,196행을 4영역으로 비중첩 분담했고, 4관점은 지정 필수 범위에서 연결을 추적했다. 수행 기록 대조에서 수리자 8명 모두 담당 파일·행 누락은 없었다. 이 기록은 이해의 완전성이나 결함 부재의 증명이 아니다. 수리자 전부 graphify와 현재 원문을 함께 사용했다.

graphify 최종 갱신: 파일 249개, 노드 6515개, 관계 23049개. Markdown 24개의 의미 추출은 성공했다. 인용 좌표 오류가 난 두 문서는 재추출했고, 검증 중 원본 변경을 감지한 시도는 기존 그래프를 보존했다. 고정된 최종 판본으로 다시 갱신했다. 그래프는 Git 제외 로컬 생성물이다.

정본·생성 사본·동결·장부·이 보고서·직접 처리와 검증 증거·커밋 기억을 같은 커밋에 포함했다. 커밋 성공 후 `앵커/`와 `라운드1/`의 재귀 정리를 요청했으나, 실행 전 자동 승인 검토가 `blocked by policy`로 거절했다. 삭제는 수행되지 않았고 두 폴더를 보존한다. 구체적인 추가 거절 사유는 제공되지 않았다. 다른 로컬 `_` 작업 파일도 정리 대상에서 제외했다. 정리 미완료는 위 검증 완료와 구별하며 이 운영 결과를 같은 작업 커밋에 반영한다.
