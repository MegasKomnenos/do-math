# do-math codex-full 검증 장부

## 신호 처리 절

- 신호 6, 라운드 1 불변식 재실측: 280개 중 source 변경 뒤 종료 산출 처리 시험 1개 실패, 1개 미실행. 단독 재현에서도 기존 상세 source 변경 사유가 일반 정지 메시지로 바뀜을 확인했다. R1-04를 이번 반영에서 제외하여 무처분으로 두고 나머지 승인 조각을 재적용한 뒤 전체 시험을 다시 실행한다. 오판 비용은 이번 수리 하나의 미적용이고 다음 독립 라운드에서 회수 가능하다. 되돌리기는 고정 사본 복원과 공식 적용으로 가능하다. 판단 근거는 실패 출력과 R1-04의 변경 구간이며 사용자 의도 변경이 필요하지 않다. 이 자체 처리는 사용자 확정 기록이 아니다.

- 영역·관점 선정: 문서, 실행 기반, 연구 판단, 시험의 자연 파일 경계 네 영역과 기능 목적·정보 전달 두 관점. 현행 산출물 85개를 대조했다.
- _파견준비.py: 파견문 슬롯 채우기와 공식 명령 호출. 공식 스크립트가 파견문 저작을 덮지 않아 사용한다.
- _파견실행.py: Windows 프로세스 병행 실행. 공식 스크립트가 파견 실행을 덮지 않아 사용한다. Bash 부재 환경에서 같은 codex 인자와 공식 완료 판정을 유지한다.
- 기존 런과 구별한 새 런이며 이전 항목과 판정은 지급하지 않는다.

- 라운드 1 수리: 6기 모두 완료 신호 뒤 공식 판독 통과. 네 영역은 각 담당 파일 전건, 두 관점은 각각 85파일 17,428행을 읽었다고 수행 기록에 명시했다. 형식과 절차 358행과 구현자 변명 817행의 전문 독해를 6기 모두 기록했다. 통합 설계와 CONTEXT는 관련 좌표 대조이며 전문 독해로 세지 않는다.

## 라운드 1 — 사유 절

- **R1-01** (승인 2/3)
  - 2기: 관문 4·5 미달이다. 대체 첫 문단의 “최초 규칙과 후속 규칙을 activity-extensions.json의 observation_rules에 넣을 때도”는 최초 규칙을 최상위 가족에 넣는 안내로 읽히며, 실제 과제별 task_conditions 경로와 일치하지 않는다. 새 과제를 준비하는 대상 없는 action이 그 안내를 따르면 규칙 배열 자체가 유효해도 적용이 거부된다. 뒤에 유지되는 54행은 다른 경로를 안내한다. 필수 형식을 보강하는 목적은 타당하지만, 제출 위치를 혼동시키는 새 안내까지 포함한 이 조각은 통과하지 못한다.
- **R1-06** (승인 1/3)
  - 2기: 관문 5 미달이다. 조각은 GET·DELETE의 비어 있지 않은 body를 실제 전송하도록 바꾸지만, 역할에 제공되는 “POST와 PUT에서만 전송된다”는 현행 안내를 그대로 남긴다. 기록과 전송의 차이를 해소하는 방향은 타당해도, 외부 요청 작성자가 의존하는 전송 계약과 코드가 서로 달라지는 수리안은 승인할 수 없다.
  - 3기: 관문 5 정합을 통과하지 못한다. 대체를 적용하면 GET·DELETE의 비어 있지 않은 본문도 전송되지만 역할 문서는 계속 두 메서드의 본문을 전송하지 않는다고 안내한다. 통합 설계 0절 17행의 채택 동작을 문서·코드·검사에 일치시키라는 규정과 충돌한다. 외부에 보내는 실제 요청 바이트의 계약이 달라지는 문제이며 코드 한 행의 조각만으로 이 불일치를 해소하지 못한다.
- **R1-08** (승인 1/3)
