## 목적 진술

사용자 요청에 따라 .claude/skills/do-math 구현을 docs/do-math/통합-설계.md의 비전과 각 기능 목적에 비추어 검토하고, verify-rounds의 독립 수리·병합·심사·적용으로 승인된 수리를 반영한다. 문서, 실행 코드, 실제 입력·산출·저장·후속과 검증을 함께 대조한다. 현재 구현을 정답이나 새 완료 기준으로 삼지 않는다.

docs/형식과-절차.md를 전문 읽고 검토에 적용한다. 이 안내는 특정 시스템의 설계 정본을 대신하지 않으며, 통합 설계 0절이 위임한 실익 판단과 함께 해석한다. 필드·파일·명령·강제 경계가 설계와 다르다는 사실만으로 결함을 확정하지 않는다. 그 수단이 맡던 목적과 소비자의 전제, 대체 방법의 실제 효과와 손실을 판단한다. 반대로 문면으로 설명하거나 한계라고 공개한 것만으로 기능 목적의 미달을 면제하지 않는다.

docs/do-math/구현자-결정과-변명.md를 전문 읽어 참고한다. 변명은 판정 기준을 바꾸거나 결론을 구속하는 사용자 확정 문면이 아니다. 각 수리자·병합자·심사자는 자신의 판단으로 그 주장의 사실, 당시 근거, 사후 설명, 대안의 실익을 평가한다. 기록되지 않은 사항을 구현자가 고려했다고 추정하여 변명 범위를 넓히지 않는다. 기존 완료 보고와 검증 통과 선언도 그 자체로 기능 완료의 증거가 아니다.

본 런은 현재 구현의 검토와 승인된 수리다. 새 수학 문제의 실제 풀이, 공개·결제·계정 변경과 같은 외부 효과는 이 요청으로 승인되지 않는다. 기준 원문과 구현자 변명은 읽기 자료이며 수정 대상이 아니다.

## 불변식 목록

- 결론: 없음. 구현의 통과·결함·미검증을 증거에 따라 판정한다.
- 필수 논거: 통합 설계 0절의 구현 재량과 기능 목적 완료 기준을 함께 적용한다. 의미·권한·의무·효력·입력·후속의 보존 여부로 차이를 평가한다.
- 필수 전거: 기준 원문의 실제 좌표와 문언, 산출물 사본의 실제 코드·문장·소비 경로를 확인한다. 구현자의 해설만으로 사실을 확정하지 않는다.
- 분량 상한: 없음.
- 보편 개념의 저작 원천과 정의 위치는 CONTEXT.md 및 통합 설계 0.3·16.5절을 따른다. 정의한 용어를 반복 사용하고 현재 구현의 이름으로 보편 개념을 축소하지 않는다.
- 강한 읽기 격리·제약·선행 관문은 개별 실익 판단 대상이다. 무조건 강제하거나 무조건 생략하는 공통 결론을 두지 않는다. 기능 목적에 필수인 동작은 부수적인 형식으로 분류해 없애지 않는다.
- 지적에는 실제 영향과 근거를, 수리에는 그 영향을 해소하는 완성된 조각을 갖춘다. 없는 장치의 재사용, 검사를 수행하지 않은 성공, 한 실패의 무관한 전역 확대를 허용하지 않는다.
- 과제·활동·실행의 상태, 일반 연구 기록과 인증된 지식, 형식 타당성과 의미 동일성과 목표 충족, 사용자 권한과 AI 판단을 해당 정본의 뜻으로 구별한다.
- 기존 연구 기록의 의미와 사용자 권한을 수리 편의로 덮거나 외부 행동을 새로 실행하지 않는다. 실제 시험은 그 범위·환경·미실행과 판본을 구별한다.
- 적용 뒤 변경된 Python 파일의 문법을 검사하고 do-math의 scripts/tests를 현재 저장소에서 실행한다. 실행 명령은 python -m unittest discover -s .claude/skills/do-math/scripts/tests -p test_*.py 이며 필요한 import 경로는 scripts다. 기존 환경상 미실행은 통과로 세지 않는다. 실패는 원문·출력으로 원인을 확인하고 스킬의 신호 처리에 따른다.
- 수리 정본은 .claude/skills/do-math다. 적용 뒤 저장소의 commit-harness에 따라 생성 미러와 작업 기억을 동기화하고 검증한다. 생성 미러는 별도 수리자가 저작하는 산출물이 아니다.

### 수리 5: 관점 — 기능 목적과 수단의 실익

산출물 목록의 파일 전건을 처음부터 끝까지 읽고, 통합 설계의 기능 목적에서부터 대조한다. 관점은 분석할 주제를 정하며 읽을 파일을 일부로 줄이는 근거가 아니다. 구현의 다른 형식과 실제 목적 미달을 구별하고, 각 규칙이 필요한 소비자의 전제와 실행 효과를 살핀다. 직접 읽기와 보조 조사 범위를 구별하고, 읽지 못한 파일·행을 수행 기록에 명시한다.

### 수리 6: 관점 — 정보 전달과 시간선의 정합성

산출물 목록의 파일 전건을 처음부터 끝까지 읽고, 생산·수신·실패·재실행·개정·정지·복구의 연결로 대조한다. 관점은 분석할 주제를 정하며 읽을 파일을 일부로 줄이는 근거가 아니다. 각 주체가 실제로 받은 정보와 권한, 현재성과 과거 이력, 다음 소유자와 후속이 해당 기준을 만족하는지 살핀다. 직접 읽기와 보조 조사 범위를 구별하고, 읽지 못한 파일·행을 수행 기록에 명시한다.

## 모델 배정

사용자 지정: 수리자와 심사자는 gpt-6-astra low. 병합자는 codex-full 기본 배정인 gpt-5.6-terra low. 라운드 1 전에 확정한다. 전 역할은 codex exec의 독립 컨텍스트로 실행한다. PowerShell/Python으로 프로세스를 실행하고 공식 wait_outputs.py로 완료를 판정한다. 모델·노력·never·danger-full-access·MCP 차단·WindowsApps 제외를 유지한다.
