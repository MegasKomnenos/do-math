# do-math 구현 검증 종료 보고

통합 설계에 비추어 구현을 검토하고 승인된 수리를 반영했다. 사용자가 진행 중인 2라운드를 이어서 마무리하도록 지정했으므로 3라운드는 시작하지 않는다. 이번 종료를 전체 기능 충족이나 무결함 판정으로 해석하지 않는다. 2라운드의 기능 목적 관점은 결번이고, 아래 잔여도 남는다.

## 1. 종료 수치와 종료 항

공식 종료집계: 라운드 2 적용 7건, 적용 이력은 라운드 1의 13건과 라운드 2의 7건이다. 적용 0 연속은 0회다. **종료 항은 판정 순서 3항**이며, 라운드 수 2가 사용자 지정 상한 2에 도달했다. 적용 0 수렴에 따른 종료는 아니다.

초기 설정은 codex-full 전면, 수리 6기·관점 2기, 심사 3기·정족 3, 하한 3·상한 8·종료 연속영 2였다. 사용자 후속 지시에 따라 하한·상한을 모두 2로 변경했다. 수리자와 심사자는 전부 gpt-6-astra low, 1라운드 병합자는 gpt-5.6-terra low를 사용했다. 2라운드는 병합 묶음이 없었다.

## 2. 라운드별 제기와 적용

| 라운드 | 제기 | 심사 대상 | 최종 적용 | 기각 | 무처분 | 수리 결번 |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 18 | 15 | 13 | 4 | 1 | 0 |
| 2 | 7 | 7 | 7 | 0 | 0 | 1 |
| 합계 | 25 | 22 | 20 | 4 | 1 | 1 |

적용은 장부 본표의 구성 항목 행을 센다. 1라운드의 최종 적용은 병합 항목을 하나로 세면 10건·20조각·12파일이고, 2라운드는 7건·14조각·7파일이다. 같은 파일이 두 라운드에서 바뀔 수 있으므로 파일 수를 더해 고유 변경 파일 수로 쓰지 않는다.

## 3. 상신·무처분·기각과 남은 문제

상신 잔여와 별도 기각 보관 파일은 없다. 기각의 판정과 근거는 [장부](장부.md)의 라운드별 사유 절에 보존한다.

- **R1-04, 무처분:** 허가 철회로 이미 정지를 시작한 실행의 늦은 산출을 다른 유효 허가로 수락하는 문제. 심사 승인을 받았으나 구체적인 source 변경 진단을 일반 정지 메시지로 바꾸는 회귀가 발생해 적용에서 제외했다. 알려진 문제를 해결했다고 보고하지 않는다.
- **R1-06, 기각:** GET·DELETE 요청에 기록한 본문과 실제 전송 본문의 차이. 코드만 바꾸면 역할 문서의 기존 전송 계약과 어긋나는 수리여서 기각되었으며, 이번 런에서 후속 수리는 적용되지 않았다.
- **R1-01·R1-08·R1-15, 기각 뒤 후속 수리:** 각각 관찰 규칙 형식 전달, 학술 시작 상태, 재실행 자료 전달의 수리안이 기각됐다. 같은 주제의 별도 수리 R2-01·R2-04·R2-06이 2라운드에서 승인되었다. 앞선 기각 판정 자체를 승인으로 바꾸지는 않았다.

수리 5의 미완료 산출에 적힌 후보는 승인된 발견이나 제기 항목으로 세지 않는다. 두 차례 모두 담당 범위의 전문 독해를 끝내지 못했으므로 산출 전건을 판독에서 제외했다. 큰 기능의 미지원 공개, 실제 연구 효능과 강한 격리의 미검증을 이번 국소 수리와 회귀 통과로 해소했다고 주장하지 않는다.

## 4. 자체 처리와 승계

승계는 없다. 자체 처리는 1라운드 R1-04의 회귀 실패 처리다. 원래 전체 적용을 고정 사본으로 복원하고, 공식 적용에 `--제외 R1-04 --강제`를 주어 나머지 승인 조각만 반영했다. 세션이 대체 문면을 고쳐 쓰지 않았다. 실패 시험의 단독 재실행과 전체 재시험을 통과했다.

오판의 비용은 수리 하나의 미적용이고, 복원은 고정 사본과 공식 적용으로 가능하며, 판단 근거는 실제 실패 출력과 해당 변경 구간이다. 이 자체 처리는 사용자 확정 기록이 아니다. 2라운드에서 끝낸 결정은 자체 종료가 아니라 사용자의 후속 지시다.

## 5. 마지막 라운드 결산과 검증

마지막 라운드는 제기 7·적용 7·기각 0·무처분 0·상신 0·전달 0이다. 수리 관점 1기는 결번이다. 최종 전체 회귀는 `python -m unittest discover -s .claude/skills/do-math/scripts/tests -p test_*.py -v`로 실행했으며, **281개 중 280개 통과·1개 미실행**, 1324.324초, exit 0이다. PYTHONPATH는 do-math/scripts이고 PYTHONDONTWRITEBYTECODE=1을 지정했다.

수정 전 기준선은 278개 시험 중 277개 통과·1개 미실행, 1152.107초, exit 0이었다. 1라운드 첫 적용은 280개 중 실패 1개·미실행 1개였고, R1-04 제외 뒤 전체 재시험은 279개 통과·1개 미실행, 576.730초, exit 0이었다. 미실행은 Windows 심볼릭 링크 생성 권한 부족(WinError 1314)이다.

2라운드의 변경 Python 5파일은 문법 검사를 통과했다. 미러 재생성과 247파일의 드리프트 검사를 통과했다. 다른 작업의 write-for-reader 미추적 정본과 생성 미러는 이번 커밋에 포함하지 않는다.

## 8. 보조 스크립트 승격 후보

- `_파견준비.py`: 파견문 슬롯 채우기와 공식 명령 호출. 공식 vr.py가 파견문 저작을 덮지 않아서 사용했다.
- `_파견실행.py`: Windows에서 지정 Codex 모델·노력으로 병행 프로세스를 실행하고 반환·로그·실행 기록을 보존한다. 공식 스크립트가 프로세스 파견을 덮지 않아서 사용했다.

승격을 확정한 것은 아니다. 이번 런에서 사용한 보조 스크립트 전건을 후보로 기록한다.

## 9. 운영 기록 요지와 검토 한계

1라운드는 수리 6기 모두 완주했다. 2라운드는 네 영역과 정보 전달·시간선 관점이 완주했고 기능 목적 관점은 재차 미완료로 결번이다. 2라운드의 영역 합집합은 85파일·17,576행이며 시간선 관점도 같은 전건을 직접 읽었다. 기계 영역 검산은 파일 배분의 검산이며 실제 독해의 증거는 수행 기록과 구별한다.

완결 산출을 낸 수리자는 `docs/형식과-절차.md`와 `docs/do-math/구현자-결정과-변명.md`의 전문 독해를 기록했다. 통합 설계와 CONTEXT는 관련 원문 좌표를 대조했고 전문 독해로 세지 않았다. 구현자의 과거 설명·완료 선언은 현재 구현의 증거로 대신 쓰지 않았다. 실제 모델·Lean·HTTP·장기 연구의 전 기능 운전을 이 런에서 새로 완료한 것은 아니다.

사용자 메시지 뒤 이전 도구 실행 세션이 소실되어 실제 프로세스·파일을 확인했다. 수리 5의 두 번째 산출은 미완료이며 stdout 파이프 오류도 남았다. 수리 6의 첫 실행은 산출 없이 중단됐고, 같은 파견문으로 한 번 재파견하여 완결 산출을 회수했다. 완료된 다른 기의 산출은 유지했다. 원문 좌표·조각 판독, 묶음, 심사 집계와 적용은 공식 스크립트로 수행했다.

종료 뒤 정리는 완료하지 못했다. 검증 커밋 뒤 앵커·라운드1·라운드2 삭제 명령이 실행 전에 `blocked by policy`로 거부됐다. 사용자가 삭제를 명시적으로 허락한 뒤 동일 범위를 재시도했으나 같은 사유로 다시 거부됐다. 상세 거부 이유는 제공되지 않았다. 세 디렉터리는 모두 보존되어 있고 다른 삭제 수단으로 우회하지 않았다.
