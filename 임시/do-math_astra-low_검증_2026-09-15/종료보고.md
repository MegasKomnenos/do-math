# do-math 구현 전면 검증 종료 보고

요청한 1라운드를 마쳤다. 독립 심사를 통과한 수리안 가운데 최종 정합성 조정 뒤 **7개 수리안·12조각을 정본 5파일에 반영**했다. 최종 전체 회귀는 **276건 중 275건 통과, 1건 미실행**이다. 원자료 별칭 처리에 관한 지적 1건은 기준 인용 오류로 정족을 채우지 못해 미적용 상태로 남았다.

검토 대상·기준·배정은 [동결문](동결.md), 항목별 판정과 자체 처리의 정본은 [장부](장부.md)에 있다. 이 보고는 이번 검토와 시험의 결과이며, 통합 설계의 모든 기능이 완료됐다는 선언은 아니다.

## 1. 종료 수치와 종료 항

공식 `종료집계`는 판정 순서 **3항**, 즉 라운드 수 1이 상한 1에 도달하여 종료했다고 판정했다. 반드시 실행할 하한 1을 충족했고, 적용이 없는 라운드가 2회 연속되면 종료하는 조건은 성립하지 않았다. 적용 0 연속 횟수는 0이다. 라운드 하한·상한은 모두 1이며 추가 라운드는 실행하지 않았다.

| 단계 또는 상태 | 수 |
|---|---:|
| 수리자가 제기한 원항목 | 10 |
| 병합 묶음 | 1 |
| 심사 대상 | 9 |
| 만장일치 승인 수리안 | 8 |
| 자체 처리로 반영하지 않은 승인 수리안 | 1 |
| 최종 적용 수리안 | 7 |
| 본표의 적용 원항목 행 | 8 |
| 무처분 원항목 | 1 |
| 기각 원항목 | 1 |

README를 고치는 원항목 R1-01과 R1-10은 병합 항목 R1-M1 하나로 적용됐다. `종료집계`는 원항목 두 행을 각각 세므로 적용 8건을 보고한다. 실제 적용 명령이 반영한 수리안은 7개다. 무처분은 승인했지만 반영하지 않은 상태를 뜻한다.

### R1-08: 원자료 별칭 수리안은 기각되어 미적용

지적 대상은 `scripts/do_math/review_engine.py`의 `_research_source_spec`다. 입력으로 제공하는 원자료 ID와 `source:<이름>` 별칭을 이 함수가 이름·경로와 같은 원자료로 해석하지 못한다. 검토자가 제공된 ID로 보충 조사에 사용할 원자료를 지정해도 자료를 찾지 못해 보충 조사가 열리지 않고 출력 수리를 요구받을 수 있다. 심사에서도 이 불일치는 확인됐다.

심사자 둘은 승인했지만, 셋째는 CONTEXT.md의 실제 문구인 `쓸 수`를 제출 항목이 `사용할 수`로 인용한 점을 이유로 기각했다. 기준의 축자 대조를 통과하지 못해 승인 2/3으로 정족에 미달했다. 이번 라운드에서는 조각을 적용하지 않았고, 이 항목의 재심사를 위한 추가 라운드도 실행하지 않았다. 별칭 처리의 불일치가 미수리 상태로 남았다는 점을 후속 검토에서 유지해야 한다.

별도 기각 보관 파일은 없음. 기각 사유는 장부의 사유 절에 보존했다.

## 4. 자체 처리와 승계

자체 처리 1건: **신호 6, R1-06**. 신호 6은 동결된 불변식과의 충돌을 다룬다. 여기서는 두 승인 수리의 결합이 정확성·정합성과 충돌했다. 이 런은 `상신_자체판단`이 켬이므로, 운전 세션이 아래 세 기준으로 사용자에게 새 결정을 요구할지 스스로 처리할지를 판단한다.

- **오판 비용:** discovery가 네 파일의 시험을 수집하므로 필요한 검증 기능이 보존된다. 기존에 없던 직접 실행 기능을 새로 추가하지 않는 결정이다.
- **복구 비용:** 사본과 승인 조각이 보존되어 있어 제외 결정을 되돌려 변경 집합을 다시 만들 수 있다.
- **판단 근거:** 실제 시험 파일 37개의 진입점 유무, README 문면, 동결된 discovery 명령으로 판단할 수 있었다. 사용자만 가진 정보나 새 권한은 필요하지 않았다.

진행 중 회귀 시험을 중단하고 처음 적용했던 파일 9개를 라운드 사본으로 복원했다. 이 9개는 최종 변경 5파일과 R1-06의 시험 파일 4개다. 이후 공식 `적용 --제외 R1-06 --강제`로 최종 변경을 다시 반영하고 새 판본의 전체 회귀를 실행했다. 중단한 시험은 성공 수에 포함하지 않았다. 동결문·파라미터·모델 배정은 유지했다. 자체 처리는 사용자 확정 기록이나 후속 승계의 근거가 아니다.

승계는 이미 확정된 사용자 결정을 새 선택 없이 남은 자리에 적용해 수리 처분의 근거로 삼는 절차다. 이번 런의 승계는 없음.

## 9. 운영 기록 요지와 검토 범위

수리의 네 영역은 문서·역할 계약 3,082행, 실행 기반 6,610행, 지식·연구 판단 2,642행, 시험 5,265행을 나누어 맡았다. 영역 합집합과 비중첩 검산은 86파일·17,599행으로 통과했다. 기능 목적·실익 관점과 정보 전달·시간선 관점의 두 담당도 각각 86파일 전건을 직접 읽었다고 수행 기록에 명시했다.

수리자 6기는 형식과 절차 및 구현자 변명을 전문으로 읽었다. 통합 설계·CONTEXT는 담당 주제의 관련 절을 대조했다. 과거 변명에 적힌 공백을 현재 코드에서 이미 해결한 경우에는 같은 결함으로 다시 제기하지 않았다. 이 범위는 통합 설계 전문의 전건 독해, 모든 시간선 벡터 실행 또는 새 수학 연구의 수행을 뜻하지 않는다.

시험 영역 담당의 첫 실행은 전송 오류를 반복했다. 약 40분 경과 후 완료 5기의 영수증과 남은 단일 프로세스를 대조해 그 로컬 프로세스 트리만 종료했다. 공식 완료 신호 뒤 산출 부재를 확인하고 같은 파견문·모델·노력으로 1회 재파견해 정상 산출을 받았다. 최종 결번은 없다.

운영 기록을 잘못된 장부 절 끝에 덧붙인 기재 오류는 원래 실행 출력·영수증으로 복원해 운영 기록 절로 옮겼다. 추가 재현의 최초 인자 순서 오류도 함수 정의와 대조해 고쳤으며 제품 결함으로 세지 않았다. 공식 적용을 다시 실행할 때에는 사본 복원 뒤에만 `--강제`를 사용했다.

이전 런과 작업 시작 전에 존재하던 지침 파일 변경은 이번 스테이징 범위에 넣지 않는다. 커밋에는 정본·생성 사본의 변경, 동결문·장부·이 보고와 작업 기억을 함께 담는다. `임시파일_제거`는 켬이며, 스킬 절차에 따라 커밋 성공 후 이 런의 앵커와 라운드 디렉터리를 정리한다. 동결문·장부·이 보고와 런 직속의 보조·시험 자료는 유지한다.
