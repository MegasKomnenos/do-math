# do-math 구현 검증 종료 보고

사용자 지시에 따라 검증을 2라운드에서 마무리했다. 승인된 수리는 반영했지만, 검토가 수렴했다거나 통합 설계의 모든 기능이 완성됐다는 판정은 아니다. 미완주, 공급자 거절·사용 한도, 병합 결번으로 남은 범위를 아래에 구분한다.

검토 기준은 [통합 설계](../../docs/do-math/통합-설계.md)와 정의 원천인 [CONTEXT](../../CONTEXT.md)다. [형식과 절차](../../docs/형식과-절차.md)를 함께 적용했고, [구현자의 결정과 변명](../../docs/do-math/구현자-결정과-변명.md)은 각 검토자가 독립적으로 평가하는 맥락 자료로 제공했다. 그 문서의 설명이나 과거 완료 선언을 합격 근거로 삼지 않았다.

## 1. 종료 근거

최종 파라미터는 라운드_하한 2, 라운드_상한 2, 종료_연속영 2다. 원래 전면 체급의 하한 3·상한 8은 사용자의 「그냥 2라운드는 마무리」 지시로 변경했다. 진행 중인 라운드를 다시 시작하거나 3라운드를 수행하지 않았다.

종료 항은 공식 종료집계의 **3항, 라운드 상한 도달**이다. 적용 0의 연속으로 수렴하여 끝난 것이 아니다. 모델 배정은 mixed를 유지하고, 심사는 사용자 지정인 gpt-6-astra low를 사용했다. 정족은 3기 전원 승인이다.

## 2. 라운드별 제기·판정·적용

| 라운드 | 유효 제기 | 심사 대상 | 수리 확정 | 심사 기각 | 적용 본표 행 | 병합 결번으로 제외된 본표 행 |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 69 | 56 | 30 | 26 | 34 | 0 |
| 2 | 11 | 9 | 7 | 2 | 7 | 2 |

수리 확정은 심사 대상 단위이고, 적용 본표 행은 병합 항목의 구성 항목에 전파한 계수다. 따라서 **심사 대상 37항목의 수리를 적용했고, 본표에서는 41행이 적용**됐다. 두 수를 같은 낱개로 읽지 않는다. 수리 결번 기의 미완주 산출은 유효 제기에 합치지 않았다.

1라운드는 30항목·51조각을 24파일에 적용했다. 2라운드는 7항목·14조각을 11파일에 적용했다. 같은 파일에 두 라운드가 작용할 수 있으므로 파일 수를 더해 고유 파일 수로 쓰지 않는다.

## 3. 잔여·기각·미검토

확정 상신, 무처분, 발견 전달은 모두 없음이다. 별도의 기각 보관 디렉터리는 지정되지 않았으므로 기각 보관 파일은 없다. 항목별 기각 사유와 묶음 구성은 [장부](장부.md)의 각 라운드 본표·묶음 구성표·사유 절에 보존한다. 기각은 이번 지적과 수리가 승인되지 않았다는 뜻이며, 해당 기능 전체의 무결함 판정이 아니다.

다음 두 항목은 겹치는 조각 때문에 R2-M1로 묶였으나 지정된 Opus 병합자를 실행할 수 없어 **심사·적용하지 못했다**.

- **R2-01:** 공통 실행 문서가 관찰 규칙 객체의 필수 필드 이름을 전달하지 않는다는 지적. 위치는 정본의 `references/공통-실행.md` 52행이다.
- **R2-11:** 거부된 실행 중 관찰 규칙의 사유가 작업자에게 전달되지 않고 시험이 무보고를 정상으로 기대한다는 지적. 위치는 `scripts/do_math/observations.py` 92~93행과 해당 시험·전달 경로다.

이 두 지적은 병합과 독립 심사를 끝내지 못했으므로 확정 결함이나 수리 완료로 표시하지 않는다.

담당별 검토 제한은 다음과 같다.

| 라운드 | 담당 | 결과와 제한 |
|---|---|---|
| 1 | 6기, 정보 전달·시간선 관점 | 첫 파견과 재파견 모두 전건·필수 자료 읽기의 미완주를 기록하여 결번 처리 |
| 2 | 2기, 실행·통치 영역 | Claude 공급자 보호장치의 요청 거절로 산출 없음 |
| 2 | 3기, 지식·연구 판단 영역 | 첫 산출의 필수 자료 미독, 재파견의 세션 한도로 결번 |
| 2 | 5기, 기능 목적·수단 실익 관점 | 첫 산출의 전건 읽기 미완주, 재파견의 세션 한도로 결번 |
| 2 | 6기, 정보 전달·시간선 관점 | 산출은 있었으나 필수 자료·사본 미독이 남았고 세션 한도로 종료; 유효 산출에서 제외 |

다른 담당이 같은 파일 일부를 확인한 것과 위 담당이 자기 검토를 마친 것은 구별한다. 불완전한 담당의 산출을 일부 발췌하여 승인 절차에 끼워 넣지 않았다.

## 4. 자체 처리·승계·사용자 확정

- **라운드 1 전, 신호 4 자체 처리:** 현재 세션에 Claude Agent 도구가 없어 같은 역할 정의·모델·노력을 명시한 설치 Claude CLI의 독립 세션으로 수리·병합을 실행했다. Codex 심사도 Windows 프로세스로 같은 인자·표준 입력을 전달했다. 파견문, 산출 서식, 독립 판정과 정족은 유지하고 실제 응답·모델·종료를 확인했다.
- **라운드 1 심사의 승계:** R1-34에 대해 심사 3기가 통합 설계 0절, 6.1절, 12.3절을 인용했다. 공식 집계에서 수리 확정됐으며, 세션이 새 수리 방향을 선택해 추가한 것이 아니다.
- **라운드 1과 2 사이, 신호 6 자체 처리:** 실재하지 않는 루트 `AGENTS.md` 좌표를 동결문의 기준 목록에서 제거하고, 관점 담당의 기존 전건 읽기 의무를 명료화했다. 이전 동결문과 판정은 1라운드 커밋에 보존했다. 산출물·모델·기수·정족은 바꾸지 않았다.
- **현재 사용자 확정:** 2라운드에서 끝내라는 지시를 라운드 하한·상한에 반영했다. 현재 유효 산출을 마무리하는 지시로 적용했으며, 새로운 수리 재파견이나 다음 라운드를 시작하지 않았다.

세션의 자체 처리는 새로운 사용자 확정이나 향후 승계의 근거가 아니다. 각 판단의 오판 비용·되돌리기 비용·근거는 장부 신호 처리 절에 있다. 신호 2·3으로 자체 종료한 사항은 없다.

## 5. 마지막 라운드 결산

공식 결산의 본표는 제기 11행 중 적용 7행·기각 2행·결번 2행이다. 적용 이력은 1라운드 34행, 2라운드 7행이며 적용 0의 연속은 0회다. 최종 하한 2·상한 2·종료_연속영 2를 적용해 3항으로 종료했다.

2라운드의 심사자 3기는 각각 9항목 전부를 판정했고 모두 승인 7·기각 2에 일치했다. 수리 확정 7항목은 전부 적용했다. 기각 2항목과 병합 결번 2항목은 적용하지 않았다.

2라운드 수리는 다음을 다뤘다.

- 지식 메타데이터와 기존 지식 개정의 전달 형식
- 외부 요청 객체의 형식과 허가 대조 기준
- 부수 연구 통찰의 필수 필드
- 수학 관계 제출의 두 단계 경로
- 외부 거부 해소에서 사용할 기록 ID
- 지식 변경 뒤 완료·종결 과제의 이력 보존과 이에 맞는 시험
- 학술 외부 효과의 비성공·미확정 영수증을 실제 판정 경로에서 검사하는 시험

최종 시험은 553.751초에 끝났고 실패·오류가 없었다. 미실행 1개는 이 호스트의 심볼릭 링크 생성에 의존하는 기존 검사다. 미실행을 통과로 세지 않았다.

전체 시험 명령은 `PYTHONPATH=C:\math\.claude\skills\do-math\scripts`, `PYTHONUTF8=1` 환경에서 `python -m unittest discover -s .claude/skills/do-math/scripts/tests -p test_*.py`였다. 1라운드의 변경 Python 19파일, 2라운드의 변경 Python 6파일은 문법 검사를 통과했다. 각 적용 뒤 미러를 생성했고 `build_skill_mirrors.py --check`가 전체 245파일에서 드리프트 없음을 확인했다.

시험 통과는 현재 시험이 검사한 범위의 근거다. 실제 장기 수학 연구, 모든 전문 분야의 검토 성능, 통합 설계의 모든 기능 목적을 입증하지 않는다. 이번 런의 검토자 CLI 실행과 do-math 자체의 실제 연구 실행도 구별한다.

### 실행 제한과 처리

2라운드 수리 2의 Claude CLI는 공급자 보호장치의 `reasoning_extraction` 사유로 요청을 거절했다. 원 요청을 안전 차단이 해제되도록 재표현하거나 다른 모델·계정으로 보내지 않았다. 이 이유로 해당 기는 검토되지 않은 것으로 남겼다.

이후 Claude CLI는 “You've hit your session limit · resets 6:20am (Asia/Seoul)”을 반환했다. 사용자가 현재 라운드의 마무리를 지시해 재개 시각까지 기다리거나 새로운 수리·병합 요청을 추가하지 않았다. 기존 Astra 심사 배정은 유지했으며 Opus의 수리·병합을 대신 수행시키지 않았다.

일부 수리자는 읽기 전용 보조 조사를 사용했다. 직접 읽기와 위임 조사 범위를 구별했으며 보조 조사를 별도 정족으로 세지 않았다. 그 중 비동기 Agent 호출은 스킬의 동기 파견 방식과 다른 운영 사실로 기록했다.

1라운드 커밋 전 동결문 끝의 빈 줄은 의미를 바꾸지 않는 형식 차이였다. 실행 중 동결문을 바꾸지 않고 그 파일만 일시적인 공백 검사 옵션으로 확인했다. 나머지 파일의 검사는 유지했고, 다음 라운드 전 동결문을 정정할 때 빈 줄을 제거했다. 저장소 설정을 바꾸거나 제품 검사를 완화하지 않았다.

### 보존과 정리

지속 기록은 [동결문](동결.md), [장부](장부.md), 이 종료 보고다. 1라운드는 `b4ede4c`으로 커밋했다. 종료 커밋에는 마지막 적용분·미러·지속 기록·작업 기억을 함께 담는다.

`임시파일_제거=켬`에 따른 정리를 종료 커밋 뒤 요청했으나, 재귀 삭제를 포함한 명령이 자동 승인 검토에서 `blocked by policy`로 거절됐다. 프로세스가 시작되지 않아 해당 명령의 삭제와 푸시는 실행되지 않았다. 세부 차단 사유는 제공되지 않았다.

따라서 앵커와 라운드1·라운드2 디렉터리는 그대로 보존한다. 다른 명령·도구·이동으로 삭제를 우회하지 않았다. 동결문·장부·종료 보고도 보존하며, 푸시는 삭제와 분리해 수행한다. 다른 작업의 임시 문서와 저장소 지침 변경은 정리하거나 커밋하지 않는다. 검증 런은 사용자 지시에 따라 종료했지만 임시 디렉터리 정리는 정책 차단으로 미완료다.

## 발견

없음. 두 라운드 모두 「호출자에게 전달」로 확정된 발견 항목은 0건이다. 위의 미처리·미검토 범위를 발견 전달이나 결함 없음으로 바꾸어 세지 않는다.
