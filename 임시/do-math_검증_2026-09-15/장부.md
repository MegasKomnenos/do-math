# do-math 구현 검증 장부

## 신호 처리 절

### 라운드 2: 사용자 종료 지시

사용자 확정 문면: 「그냥 2라운드는 마무리」. 라운드_하한·라운드_상한을 각각 2로 변경한다. 사용자는 진행 중인 2라운드의 마무리를 요구했으므로, 현재 유효 산출을 심사·적용·검증·결산하고 종료한다. 파라미터 변경을 이유로 수리부터 다시 시작하지 않는다. 3라운드와 추가 수리 재파견은 하지 않는다. 이는 세션의 자체 종료 판단이 아니라 현재 사용자 지시의 적용이다.

### 라운드 1 커밋 뒤·라운드 2 시작 전: 신호 6 자체 처리

상황: 동결문 기준 목록의 AGENTS.md 경로가 실재하지 않았고, 전건 관점의 담당 범위를 일부 파일 탐색으로 읽은 미완주가 있었다. 라운드 1은 b4ede4c으로 결산·커밋됐으며 라운드 2의 사본과 파견은 아직 없다.

판단: 잘못된 AGENTS.md 좌표를 기준 목록에서 제거하고, 관점의 전건 읽기를 수리 계약 작업 순서 2항의 뜻으로 명료화한다. 사용자 지정 세 문서와 정의 원천 CONTEXT.md, 산출물 85파일, 목적·불변식의 내용, 파라미터와 모델은 유지한다. 파견문의 기준 목록도 동결문에서 읽어 중복 목록을 제거한다. 동결문 끝의 불필요한 빈 줄도 이 정정 시점에 제거한다. 라운드 2는 정정한 동결문으로 수리 단계부터 시작한다. 이미 종료한 라운드 1의 판정·사본·커밋을 다시 쓰지 않는다.

오판 비용: 새 규범이나 결함 기대를 추가하지 않고 실재 경로와 기존 읽기 의무를 분명히 하는 변경이다. 잘못된 인용과 미검토를 완료로 세는 위험을 줄이며, 다음 파견의 수행 기록과 공식 검산으로 확인한다.

되돌리기 비용: 다음 라운드는 아직 시작하지 않아 다시 파견하거나 적용을 되돌릴 비용이 없다. 이전 동결문은 라운드 1 커밋에서 회수할 수 있다.

판단 가능성: 실제 파일 부재, 수리 계약의 담당 범위 전건 읽기, 사용자 지정 검토 대상과 자료에 근거한다. 사용자의 새 목적·선호·외부 사정을 정할 필요가 없다. 이 명료화는 새로운 사용자 확정 기록이나 승계 근거로 취급하지 않는다.

### 라운드 1 전: 신호 4 자체 처리

상황: mixed의 Claude Agent 도구가 현재 세션에 없고, 실제 정의 파일은 .claude/agents/gp-matrix/에 있다. 설치 Claude CLI의 opus[1m] high와 Codex CLI의 gpt-6-astra low가 각각 READY를 반환한 실제 실행을 확인했다.

판단: Claude 역할은 같은 정의·모델·노력을 명시한 독립 CLI 세션으로 실행한다. Codex도 PowerShell/Python 프로세스로 동일 argv와 stdin을 전달한다. 파견문, 지급 범위, 산출 파일, 독립성, 정족과 계수는 유지한다. 공식 대기 스크립트를 사용하되 운전 도구는 짧게 반환해 진행 보고를 계속할 수 있게 한다.

오판 비용: 다른 모델이나 불완전 산출을 완료로 세면 검토가 손상된다. 명시 argv, 실제 모델 응답, 프로세스 종료, 공식 산출 검산으로 해당 실패를 확인한다.

되돌리기 비용: 아직 라운드를 시작하지 않았으며, 한정된 파견을 다시 실행하면 된다. 제품 변경과 외부 효과는 없다.

판단 가능성: 설치 도구의 도움말과 실제 READY 반환, 모델 정의 파일, 스킬 5.6의 수단과 역할 계약 분리에 근거한다. 사용자만 가진 추가 의도는 필요하지 않다. 사용자 지정 모델과 mixed 계열을 바꾸지 않는다.

### 라운드 1 전: 사용자 심사 모델 지정

이번 사용자는 심사자를 gpt-6-astra low로 지정했다. 스킬 5.1의 사용자 배정 우선 조항을 적용하며, 동결문과 각 라운드 머리에 기록한다. 자체 처리로 사용자 모델을 변경한 것이 아니다.
