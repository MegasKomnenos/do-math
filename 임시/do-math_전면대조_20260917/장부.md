# do-math 전면 대조 검증 장부

## 신호 처리 절

- 0단계 실행 수단 자체 판단: Claude Agent가 제공되지 않으므로 동일 opus high·low의 로컬 CLI를 사용한다. 모델·정족·파일 지급은 유지한다. 오판 비용은 로컬 파견 실패와 산출 검산으로 포착 가능하며, 되돌리기는 파견 재실행이다. CLI 최소 호출에서 실제 claude-opus-5의 READY와 성공 종료를 확인했다.

## 운영 기록

- 종료 보고 독해: 첫 응답은 행·인용 대조에서 실패해 보존했다. gpt-6-astra medium으로 실제 독해를 다시 수행하고 계수·용어·보존 시점을 다듬었다. 마지막 독해는 합의·공식 수치와 일치했으며 _종료대조최종.json에서 모든 관찰을 처분했다. 최종 보고의 검토는 제품 코드 심사 라운드를 추가한 것이 아니다.

- 최종 불변식 재실측: python -u -m unittest discover -v -s .claude/skills/do-math/scripts/tests -p test_*.py. 412개 중 411통과·1미실행, 실패 0, 1880.803초. 미실행은 Windows symlink 생성 권한(WinError 1314) 검사다. 검증 전후 정본 106파일 SHA-256이 일치했다.

- 예산 전환 집중 검사 추가 1개: 앵커 판본에서 실패(9.827초), 현재 판본에서 통과(12.100초). 실행 중 모드 전환 거부와 실행 종료 후 process_controls에서의 정상 전환을 함께 확인했다. 보조 검사에서 거부 사유를 questions에서 찾던 오류는 실제 rejected_user_control 이력을 읽도록 수정했다. 제품 문면은 바꾸지 않았다.
- 문서 독해는 필수 참조 누락을 보완한 10문서 묶음으로 완료했고, _문서대조.json에서 승인된 변경 취지와 실제 이해를 대조했다. 기존 문단의 길이와 참조를 다시 읽은 관찰을 새 의미 결함으로 확대하지 않았다.

- 승인 수리 10항목·12조각·6파일을 공식 적용기로 반영했다. 본표 적용 행은 병합 구성 2행을 포함해 11행이다. 심사 3기 모두 15항목 덮개를 충족했고 상신·전달·무처분 확정은 없다.
- _focused_checks.py: 승인 수리의 현재성 참조·진단·대기 모델 재배정·복구 저장 경계를 검사한다. 공식 스크립트가 제품 동작 검사를 덮지 않아 별도 작성했다. 최초 실행은 수입한 시험 클래스까지 수집하는 오류로 중단했고, AcceptedRepairs 5검사만 수집하도록 고쳤다. 수정 전 5검사 실패, 수정 후 5검사 통과(9.225초). 실제 모델 호출 검사는 아니다.
- 수정 전 전체 회귀는 장시간 실행 후 중단했다. 완료·통과로 계수하지 않는다. 승인 적용 후에는 unittest discover -v로 최종 전건 검사를 다시 실행했다.
- 설치 검사 probe_codex.py --skill-only: 설치 문서·10역할 스키마 통과. 실행·문서 의미·Lean·연구 효능의 검증으로 확대하지 않는다. 미러 생성 뒤 --check는 269파일 드리프트 없음이다.

- _coverage.py: 수리자의 수행 기록과 담당 파일·전체 행 수 및 실제 도구 호출을 대조한다. 공식 스크립트는 실제 통독 기록의 대조를 덮지 않는다. 표·목록·묶음 목록·분할 행 범위·한 행 파일은 모두 계약이 허용하므로 보조 판독기를 그 실제 서식에 맞췄다. 파일별 범위 미달 0. 문서 담당의 총행 수 자기 합계 4392는 오산이며 사본 실측 4137을 정본으로 사용한다.
- 수리 6기 완료: 영역별 26/15/20/45파일, 관점 2기 각 106파일. 전체 기준선 22950행. 검증/독해기록_1.md부터 독해기록_6.md와 독해범위 JSON에 파일별 범위·도구 호출을 보존했다. 표와 호출은 이해 완전성의 증명이 아니다.
- 대화 발췌 173메시지를 원 JSONL 행과 축자 대조했고 불일치 0이다. 근거대조.json에 18개 기준 파일의 해시와 대조 결과를 보존했다.

- 영역·관점 재량: 문서·사용 진입점, 실행기·자원·운영, 지식·검토·제출, 회귀 검사라는 파일 경계로 4영역을 배분하고 전건 관점 2기를 둔다.
- 사용자 지시인 반드시 모든 담당 영역 통독을 동결문과 각 수리 파견문 담당 슬롯에 직접 적었다. 파일별 통독 범위 기록을 받는다.
- _prepare.py는 원문 회수와 동결문 재료 작성, _dispatch.py는 파견문 슬롯 채우기와 외부 프로세스 파견을 맡는다. 공식 스크립트는 이 작업을 덮지 않는다. 공식 기계 작업은 vr.py로만 실행한다.
- 기준선: Git 색인 비어 있음, do-math 정본·생성 사본 변경 없음. 기존 지침 파일과 임시 자료는 작업 범위 밖이다.
- CLI 파견의 완료는 프로세스 종료를 확인한 뒤 산출을 읽는다. 60초 이하 도구 대기로 진행을 알린다.

## 라운드 1 — 사유 절

- **R1-01** (승인 2/3)
  - 2기: 관문 적용 전 항목 종류 대조에서 기각한다. 사용자에게 새로 받아야 하는 의도·선호·외부 사정이나 사용자 확정 문면의 변경이 입증되지 않았다. 선택지 2·3은 스스로 기존 결정과 어긋나거나 결함을 남긴다고 설명하므로, 현행 정본에 맞는 비동등한 결과가 여럿 남는 근거가 되지 않는다. 선택지 1의 핵심은 이미 확정된 평가 저작·독립 검토의 연결을 산출물 안에서 보완하는 것이다. 재반려 횟수를 두 번으로 정한 추가 제안 자체가 기존 결함 수리에 사용자 결정이 필요하다는 증거는 아니다. 산출물 파일의 수리로 닫을 수 있는 결함에 적용할 조각 없이 상신만 제시했다.
- **R1-05** (승인 1/3)
  - 1기: 관문 1에서 영향 주장의 전제가 성립하지 않는다. 주제별 요약에 빠진 항목이 있다는 것과 허용 가족 목록이 닫혀 그 항목을 배제한다는 것은 다르다. 이 문맥에는 명시적 허용, 역할 표, 스키마 확인 지시가 함께 있어 요약을 배타적인 목록으로 읽을 근거가 없다. 같은 문단에서 평가 확장을 직접 허용하므로 이를 허용 가족으로 인식하지 못하게 하는 불일치라는 설명은 문맥을 보존하지 않는다.
  - 3기: 관문 1에서 주장된 불일치가 성립하지 않는다. 적용 단위인 같은 절 전체에서 빠진 가족의 허용 여부가 명확하며, 요약 문장이 뒤의 명시적 허용을 배제한다는 규정은 없다. 특히 공통 실행의 “이 공통 문서·역할 계약·입력 문맥이 허용하지 않은”이라는 금지는 요약 한 문장만을 허용 목록으로 지정하지 않는다. 요약 두 문장만 읽은 사람의 혼동 가능성을, 문서가 요구하는 스키마·표·역할 계약까지 읽은 생산자의 실제 권한 충돌로 확대할 수 없다. 보완 문면의 가독성과 별개로 지급된 결함 주장은 입증되지 않았다.
- **R1-13** (승인 1/3)
  - 1기: 관문 1에서 영향 설명이 실제 전달 경로와 일치하지 않는다. 항목은 평가 결함이 누구에게도 전달되지 않고 질문 없이 반복된다고 주장하지만, 검토 findings의 과제 내 보존과 후보 준비 입력 전달, 질문 반환 경로가 이미 존재한다. 확인되는 결함은 전달 자체의 부재가 아니라 전달받은 평가 결함을 수정할 실행 경로의 부재다.

  - 2기: 관문 적용 전 종류 대조에서 기각한다. 평가를 기존 후보 준비에 다시 맡기고 사용자 요구를 변경하지 않는 수리 방향은 이미 결정돼 있다. 사용자만 정할 미결정을 제시하지 않은 채, 적용할 조각 대신 구현 대안과 임의의 두 번째 반려 문턱을 상신했다. 제안 B의 평가 재보충은 산출물 내부의 수리로 수행할 수 있다. A·C가 기존 역할 분담의 결함을 남긴다는 사실은 새로운 사용자 선택의 필요성을 만들지 않는다.
- **R1-16** (승인 2/3)
  - 2기: 관문 4에서 기각한다. 대체는 실제 입력과 저장 판본의 동일성을 확보하지 않은 채 구 모드에도 저장 판본 검사를 확대한다. 그 결과 앞서 설명한 첫 원자료 수입 경로에서 기존에 수용할 수 있던 정상 계획을 거부하는 새 결함을 들인다. 계획 입력 이후의 변경을 분리하려는 방향만으로 이 조각을 승인할 수 없다. 실제 제공 모집단과 동일한 기준을 확보하는 보완이 필요하며, 지급된 조각에는 그 보완이 없다.
