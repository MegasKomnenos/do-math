# do-math 경량화 안정화 검증 종료 보고

이 런은 네 경량화 커밋(8d2ffd0, 379a171, 9b434f4, 85a540c)을 막 거친 `.claude/skills/do-math/` 253개 파일을 한 라운드 검증했다. 수리자 8기(Claude Opus 5.5 high)가 항목 58건을 냈다. 그 가운데 겹치는 항목을 묶음 3건으로 합쳐 심사 대상은 53건이었다. 심사자 3기(Codex `gpt-6-astra` medium)가 정족 3으로 판정했다. 승인된 수리 36건을 공식 적용했다. 이어서 사용자 위임에 따라 무처분 15건과 기각 2건을 세션이 직접 다시 판정해 모두 반영했다. 반영 뒤 통합 확인은 시험 1,841개 가운데 1,840개 통과, 1개 건너뜀(심볼릭 링크 권한), 실패 0이었다.

## 1. 종료집계와 종료 항

`종료집계` 결과는 「판정: 종료 — 판정 순서 3항 (라운드 수 1 ≥ 상한 1)」이다. 라운드 1의 적용은 본표 행 기준 40건이다. 라운드 하한과 상한이 모두 1이었으므로, 적용 건수와 관계없이 이 라운드로 끝났다.

## 2. 라운드별 제기와 적용

라운드는 1뿐이다. 계수 단위가 서로 다르므로 나누어 적는다.

| 단위 | 수 |

## 3. 상신·무처분 잔여와 기각 보관

상신은 0건이다. 본표의 상태 칸은 원 심사 판정을 보존하므로, 무처분 15건과 기각 2건은 본표에 그 상태로 남는다. 실제 변경은 세션이 사용자 위임에 따라 후속 처분으로 17건 모두 반영했다. 그래서 반영되지 않은 무처분이나 기각은 남아 있지 않다. 원문과 판정, 근거는 `임시/do-math_검증_20260927/기각보관/do-math-20260927-라운드1.md`에 보존했다.

- **무처분 15건 반영:** R1-09, R1-13, R1-14, R1-15, R1-18, R1-19, R1-25, R1-26, R1-27, R1-33, R1-34, R1-39, R1-42, R1-48, R1-M2. 심사자 셋이 모두 결함과 수리를 승인했지만, 동작이 같다는 이유로 고치지 않음을 골랐다. 이번 런의 목적 진술은 쓰이지 않는 잔재와 죽은 인자의 정리, 코드 행 축소를 명시 초점으로 두었으므로 반영했다.
- **기각 R1-28 반영:** 형식 검사 직전에 판본 식별이 달라진 것을 찾으면, 결과가 `formal_environment` 대기 대신 `research_plan` 재평가로 갔다. 기각 사유는 문서 조각이 두 거부 경로 모두에 `identity_errors` 보존을 약속한 데 있었다. 실행 명령이나 실행 파일 경로가 달라진 경우의 반환은 그 필드를 내지 않는다. 코드 조각과 시험 단언은 그대로 반영했다. 문서 문장은 실제 반환에 맞게 좁혀 고쳤다.
- **기각 R1-36 반영:** 이음새 정본의 `sealed_bytes` 밖 직접 호출 목록에서 `_remember_published`가 빠져 있었다. 기각 사유는 조각 좌표의 형식뿐이었으므로, 목록 개수와 항목을 직접 고쳤다.

수리자가 결함으로 확인했지만 항목으로 쓰지 않은 후보가 남아 있다. 모두 수리자가 수행 기록에 이유를 적었다. 이 런의 잔여로 둔다.

- 모듈 사이에서 밑줄 이름을 쓰는 곳들. 이음새 정본의 공개 이름 원칙에 어긋나지만, 담당 밖 모듈이 많이 걸린다(수리 3).
- `datetime.now(...).isoformat()`이 여러 모듈에 흩어진 것. `trust_inventory.now`의 중복만 R1-31로 고쳤다(수리 3·5).
- 종결·비종결 상태 리터럴이 여러 모듈에 흩어진 것(수리 4).
- `runtime/artifacts/` 리터럴 약 50곳. 정본 상수의 사용처를 세 곳으로만 정한 문서와 모순은 아니다(수리 7).

## 5. 마지막 라운드 결산

라운드 1 결산은 본표 행 단위로 센다(단위의 대응은 2절 표). 적용 40, 수리확정 0, 무처분 16, 상신 0, 전달 0, 기각 2, 결번 0, 병합 0, 제기 0, 합 58(본표 행 수). 무처분 16행은 무처분 15건 가운데 묶음 R1-M2가 구성 항목 두 행을 갖기 때문이다. 결산은 원 심사 판정의 상태다. 이 18행에 대한 후속 반영은 3절과 장부 운영 기록에 적었다.

## 6. 앵커 대조 변경 자리

앵커와 현재 산출물을 비교하면 71개 파일이 다르다(추가 321행, 삭제 347행). 주요 변경 자리는 다음과 같다.

- **이중 프로필 수리의 검증 공백.** 시험 재편 때 `if __name__ == "__main__":` 블록 뒤에 코드가 붙었다. 그 결과 회귀 시험 `test_host_configuration_builds_profiles_once_per_step`이 한 번도 돌지 않았다. 같은 모양의 시험 파일 넷에서 이 블록을 파일 끝으로 옮겼다(R1-01·R1-21·R1-22). 되살아난 시험은 이번 통합 확인에서 통과했다.
- **configure 접수의 효과 없는 프로필 생성 삭제.** configure 접수가 `build_profiles`를 불러 모든 역할의 프로필을 만들고 버리던 호출을 지웠다(R1-02). `validate_config`가 그 거부를 모두 이미 한다.
- **전면 정리가 만든 회귀 수리.**
  - 지식 개정의 생산자 검사가 약해져 있었다. 허용 목록 하나를 검사와 적용이 함께 쓰게 했다(R1-49).
  - status 투영이 HIS-19 수리를 잃어 증거 경로가 없으면 `status` 전체가 실패했다. `academic.stored_evidence` 하나로 모았다(R1-50).
  - `status`의 착수 판정이 평가 문맥 없이 계산되고 있었다(R1-43).
  - 초기 원자료 행에 `bytes`가 없어 길이 관문이 잘림을 보지 못했다(R1-29).
  - 판본 식별 불일치가 잘못 분류되었다(R1-28).
- **정본 단일화.** 역할 집합 리터럴 28행을 정본 상수로 바꿨다(R1-55). 미종료 실행의 행동 ID 규칙을 `session_slots.live_action_ids`로 옮겼다(R1-56). 체크포인트 형식 판정을 `observations.checkpoint_value` 하나로 모았다(R1-51). 참조 필드 목록 사본(R1-24)과 식별 모듈 목록 복제(R1-47)도 정리했다.
- **죽은 인자와 잔재 제거.** 대상은 `build_profiles`의 `roles`, `capability_requirements`의 `required`, `_controls`의 `pump`, 정지 단계 `checkpointing`, `semantic_sha256`, `operation_trace`의 복사 필드 넷, `installation_repair_resolved`, 이중 진입점과 중계 함수, 닿지 않는 분기와 시험 패치, 겹치는 import다.
- **문서 정합.** CLI 실행 계약의 역할 입력 설명(R1-46), `setup_lean.py`의 표준 출력 계약(R1-06·R1-32), 시험 지침의 격리 실행 기록 위치(R1-41), 이음새 정본의 직접 호출 목록(R1-36)을 현행에 맞췄다.

## 9. 운영 기록 요지

- **관점 배치.** 관점을 맡은 수리자 넷(수리 5~8)의 범위를 이음새 묶음이 아니라 경량화 커밋 diff 이력으로 나눴다. 이음새 묶음은 기능 영역과 거의 겹쳐 관점이 영역을 반복하게 되었기 때문이다. 그 가운데 수리 5는 두 커밋을 합쳐 diff가 21,296행이었다. 이 분량은 한 컨텍스트에 넘쳤고, 수리자는 400행만 직접 읽고 나머지는 독해자 아홉에게 나눠 맡겼다. 위임 독해로 담당 diff의 모든 행이 읽혔다고 기록되었으므로, 담당 범위 미독을 이유로 한 결손 재파견은 하지 않았다. 이 관점을 수리자 본인이 통독한 관점과 같다고 보고하지 않는다. 다음 런에서 관점 하나에 줄 diff의 양은 한 컨텍스트 안으로 줄여야 한다.
- **산출 계약 위반.** 수리 5~8의 일부가 저장소 밖 `/tmp`에 임시 diff 파일을 만들었다가 지웠다. 수리 6은 사본 모듈을 import해 사본에 `.pyc` 캐시를 남겼다. 세션이 사본과 앵커가 같음을 확인하고 캐시를 지웠다. 좌표 기준이 훼손되지 않았으므로 결손으로 처리하지 않았다.
- **배치 수 변경.** 사용자 지시로 `배치_항목상한`을 48에서 0(무제한)으로 바꿔 심사를 한 배치로 했다. 이 값은 심사 분할에만 작용하므로 수리를 다시 돌리지 않았다.
- **통합 시험.** 첫 통합 확인은 사용자 지적에 따라 결과 없이 멈췄다. 직접 처리로 코드가 다시 바뀌면 전체를 다시 돌려야 하기 때문이다. 17건을 반영한 뒤 시험 조각 여섯을 세 묶음(research·host, review·foundation, lifecycle·academic)으로 나눠 동시에 한 번 돌렸고, 이 실행이 적용 뒤 불변식 재실측을 겸했다. 결과는 발견 1,841, 통과 1,840, 건너뜀 1, 실패·오류 0, 실행 중 소스 변경 없음이다. `probe_cli.py --skill-only`는 verified였다.
- **graphify update.** 첫 실행은 `scripts/이음새-정본.md`의 의미 추출이 인용 끝에 원문에 없는 마침표를 붙여 검사에서 실패했다. 그래서 기존 그래프가 보존됐다. 다시 실행해 성공했다(노드 7,456, 관계 27,123, 상태 current).
- **런타임 사본.** `build_skill_mirrors.py`로 `.agents/` 사본 71개를 갱신했고, 드리프트는 없다(423파일).
