# do-math 전면 검증 장부

## 신호 처리 절

- 신호 6 자체 처리: 공식 적용 뒤 단위 시험 301개 중 복구 시험 1개가 실패했다. R1-03은 봉인 검사가 실행·응답·확장·스키마를 결속하는지 확인한다. 기존 test_repair_plan.py의 모형 check는 이 결속 정보를 갖추지 않아 publication 대기 전에 failure로 분류됐다. 제품 검사는 유지하고 시험의 receiver mode·execution_id·schema_ref·output/extensions 해시를 현행 계약으로 구성한다. 오판 비용은 잘못된 모형을 성공으로 인증하는 것이므로 최초 실패 기록을 보존하고 단위 전건과 제출 변조 거부 회귀를 재실행한다. 변경은 시험 한 곳이며 쉽게 되돌릴 수 있고 현행 생산자 코드로 근거가 서므로 자체 처리한다.

- 신호 4 자체 처리: 수리 7에서도 실제 입력의 test_redesign_REVIEWS.py 끝부분 20행 누락을 확인해 수리 1과 같은 근거·위험·복구 판단으로 동일 컨텍스트 보완을 1회 실행한다. 기존 수행 기록의 전행 주장은 보완 전에는 그대로 신뢰하지 않는다.

- 신호 4 자체 처리: 수리 1의 수행 기록은 40파일 전행을 주장했으나 실제 도구 출력에서 test_planning.py 137~145행 9개가 누락됐다. 전체 새 파견 대신 같은 모델·노력·컨텍스트에 원 파견문과 검산 좌표를 지급해 해당 파일 전행 독해 및 기존 판단 재대조를 1회 요구한다. 파라미터·산출 서식·정족·담당 범위는 바꾸지 않는다. 오판 비용은 미독 잔존이며 보완 출력·공식 수리판독으로 확인한다. 되돌리기는 재파견 또는 해당 기 결번 처리이고, 실제 입력 기록으로 원인이 특정돼 사용자만 가진 결정은 없다.

- 신호 4 자체 처리: Windows에서 Bash 리디렉션 대신 Python subprocess로 같은 codex CLI 인자·표준 입력·반환·로그 파일을 연결한다. 오판 비용은 파견 실행 오류이며 완료 대기·산출 검산에서 탐지한다. 되돌리기는 실패 실행 보존 뒤 재실행이다. 현행 도구가 PowerShell이므로 실행 경로만 조정하며 모델·독립성·정족·파일 배치는 유지한다.
- 신호 4 자체 처리: 커밋 범위에 commit-harness가 요구하는 생성 미러·메모리 노드·색인을 포함한다. 사용자 요청의 절차에 맞는 커밋과 저장소 결합 불변식에 근거한다. 파생 파일만 추가하며 Git 경로 검산으로 제한한다. 잘못된 스테이징은 되돌릴 수 있다.

- 영역·관점 선정 재량: 기존 자연 경계 분담을 현재 파일 목록·행수와 다시 대조해 사용한다. 이전 지적·심사·결과는 지급하지 않는다. 4개 영역의 비중첩 합집합과 관점별 필수 범위·경계 추적을 분리한다.
