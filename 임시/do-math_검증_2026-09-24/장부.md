# do-math 전면 검증 장부

## 신호 처리 절

1라운드 신호 6 자체 처리: R1-06을 적용 집합에서 제외하고 무처분으로 둔다. `_추가검증_R1.py evidence`는 적용 전 exit 0, 적용 뒤 `failed parent was overwritten as skipped`로 exit 1이었다. 실패한 subTest 뒤 건너뛴 subTest가 이어지면 부모 실패가 skipped로 덮였다. 오판 비용은 검증 보고의 실제 실패 소실이며 추가 재현 검사에서 잡혔다. 되돌리기는 이번 공식 적용의 6파일을 라운드 사본으로 복원하고 R1-06을 제외한 공식 적용을 다시 실행하면 된다. 판단 근거는 동일 입력의 적용 전후 실행 결과로 충분하며 사용자 의도 변경은 필요 없다. 승인 조각을 세션이 고쳐 쓰지 않고 다음 라운드 수리에 회수를 맡긴다. 동결문·파라미터는 변경하지 않는다.

0단계 신호 4 자체 처리: commit-harness가 요구한 생성 사본·메모리 노드·색인을 라운드 커밋 범위에 포함한다. 오판 비용은 생성 검사와 색인 검사로 잡히고, 되돌리기는 한 커밋으로 가능하며, 근거는 두 스킬의 명시적 커밋 결합 계약이다. 산출물의 수리 범위는 바꾸지 않는다.

## 운영 기록

- 0단계: Git 색인과 산출물 변경 없음. 229파일을 원본 목록으로 확정했다. 영역은 문서·계약·도구, 구현 모듈, 테스트 전·후반의 자연 파일 경계로 나눴다. 관점 둘은 사용자 목적을 각각 횡단한다.
- _초기화.py에 해당하는 초기 인라인 코드: 동결·영역 배분·장부 재료 작성. 공식 스크립트는 이 문서들의 내용 선정을 하지 않는다.
- 파견문은 공식 템플릿 슬롯만 채운다. _운전.py는 슬롯 채우기와 Bash 파견 명령 생성만 맡는다. 공식 스크립트가 덮지 않는 §5.7의 작업이다.
- Windows에서 Git Bash를 사용한다. 대기 도구 호출은 실행 세션으로 유지하고 60초 이내 간격으로 운전 세션에 제어를 돌려 진행을 보고한다. 완료 판정은 공식 wait_outputs.py의 exit 0만 사용한다.
- 사용자 추가 지시: 적용이 있었으면 라운드 커밋 뒤 다음 사본 전에 graphify update를 실행한다.
