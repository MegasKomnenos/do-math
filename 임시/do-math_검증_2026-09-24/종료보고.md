2라운드에서 종료했다. 공식 `종료집계`는 사용자 지시에 따라 하한·상한을 각각 2로 확정한 뒤 **판정 순서 3항**(2라운드 ≥ 상한 2)을 냈다. 적용 항목은 1라운드 5건, 2라운드 12건으로 총 17건이다. 이 종료는 결함이 모두 없어졌다는 판정이 아니다.

첫 라운드의 관점 수리자 2명은 전건 독해를 마치지 못해 결번이었다. 2라운드에서는 사용자 지시로 전건 관점 담당 수리자 5기와 6기를 강화 파견했다. 호환 요소·비효율 관점을 맡은 5기는 같은 Codex 세션을 네 번 재개해 사본 전건을 읽었다. 문서·계약·도구, 실행 코드, 시험 전반부와 후반부의 네 영역을 합치면 229개 파일·74,399행이다. 두 관점 수리자는 각각 이 전체를 별도로 읽었고, 파일별 독해 기록을 남겼다. 비어 있지 않은 원문 행 66,999건도 각 열람 로그에서 확인했다. 로그의 행 출현은 내용 이해의 완전성을 인증하지 않는다.

## 상신·무처분·기각 잔여

상신 잔여는 없다. R1-01은 구 실행횟수 모드의 한도 대기를 CLI 상태로 잘못 안내하는 문제였으나, 제안된 대체 문면도 실제 대기 사유 위치 `dispatch_waits[].wait.kind`를 틀려 심사자 세 기가 모두 기각했다. R1-06은 건너뛴 하위 시험의 결과 기록을 고치려는 항목이었지만, 승인 문면이 기존 부모 시험의 실패를 뒤따른 건너뜀으로 덮는 회귀가 적용 뒤 재현되어 제외했다. 원래 기록 문제는 남아 있다.

기각 보관의 로컬 좌표는 `임시/do-math_검증_2026-09-24/기각보관/do-math-라운드1.md`(1건)와 `임시/do-math_검증_2026-09-24/기각보관/do-math-라운드2.md`(0건)다. 보관 파일은 Git 추적 밖의 로컬 자료이며, 판단 요지는 추적되는 장부에 있다.

## 자체 처리와 승계

R1-06 적용 뒤 부모 시험의 실패가 건너뜀으로 바뀌었다. 기존 실패 기록을 보존해야 한다는 동결문 기준과 충돌해 검증 절차의 신호 6으로 처리했다. 세션은 라운드 사본으로 자체 적용 파일을 복원하고 R1-06을 제외해 공식 적용을 다시 실행했다. 사용자가 이미 확정한 수리 방향을 새 선택 없이 적용한다는 근거로 처분을 바꾼 항목은 없다. 2라운드 종료 지시는 사용자가 직접 내렸으며, 종료 집계 직전에 동결문의 하한 3→2와 상한 8→2로 반영했다. 변경은 종료 산술에만 걸렸고 심사의 정족과 적용 조각은 유지됐다.

## 앵커 대조

동결문의 산출물 229개 파일을 첫 라운드 전 앵커와 바이트로 대조해 **20개 파일**의 변경을 확인했다. 앵커는 기준 커밋 `fa49372`의 깨끗한 워킹트리에서 만들었다. 변경 경로의 공통 접두어는 `.claude/skills/do-math/`다.

- `계약/`: `연구-계획.md`. `references/`: `CLI-실행-계약.md`, `공통-실행.md`.
- `scripts/do_math/`: `academic_engine.py`, `context_store.py`, `engine.py`, `formal.py`, `lifecycle_engine.py`, `model_runner.py`, `planning.py`, `repository.py`, `state_checks.py`.
- `scripts/`: `operator_bootstrap.py`, `probe_cli.py`.
- `scripts/tests/`: `test_external.py`, `test_formal.py`, `test_formal_runtime.py`, `test_session_scheduler.py`, `test_submission_boundaries.py`, `v5_fixtures.py`.

주요 변경은 다음 동작을 고친다.

- 입력·완료 판정: 문맥 축소에서 선택 자료를 다시 필수 입력으로 세어 실행을 멈추던 경로를 고쳤다. 학술 요구의 완료는 현재의 해결 근거와 요구 판본에 맞는지 확인하도록 연결했다. 외부 작업의 성공 상태도 과제 착수 판단에 반영한다.
- 반복 비용: 출력 파일이 늘 때 용량을 거듭 합산하던 계산과, 빈 검색어로 조회할 때 페이지마다 본문 전건을 다시 읽던 흐름을 줄였다. Claude 최종 응답 검증이 쓰지 않던 이벤트 목록도 제거했다. 실행 시간의 절감량은 별도로 측정하지 않았다.
- 실행·호환성: 동결 감독의 manifest가 없으면 검증 없이 코드를 가져오던 경로를 막았다. 실제로 계산을 중단하지 않던 formal Job의 timeout 인자를 제거하고, 현행 제출 요청으로 옛 호환 분기를 대신했다.
- 문서·검사: 판본 5 과제 범위 처분과 학술 거부 해소의 필수 근거 참조를 설명하고, Codex 학술자료 probe가 실제 MCP 호출을 검사하게 했다. 시험의 환경 변수 복원과 모델 등급 누락 입력, fixture 설명도 바로잡았다.

## 보조 스크립트 승격 후보

런 직속 `_운전.py`, `_독해대조.py`, `_본문흔적대조.py`, `_추가검증_R1.py` 네 개를 기록한다. 앞의 세 파일은 파견 준비와 파일별 독해 기록·실제 원문 흔적의 대조를 맡았고, 마지막 파일은 적용 뒤 독립 재현을 맡았다. 공식 `vr.py`는 파견 준비·실제 독해 로그 대조·제품 실행 재현을 제공하지 않으므로 세션이 이 보조 스크립트로 수행했다.

## 운영 기록 요지

수리자와 심사자는 모두 `gpt-6-sol`로 운용했다. 스킬 정본의 Codex 사본은 공식 생성기로 재생성하고 `--check`로 일치를 확인했다. 최종 적용본의 단위 시험 293건, Lean 시험 8건, 자원 시험 1건은 모두 통과했다. 관련 통합 시험 125건은 124건 통과·Windows 심볼릭 링크 생성 권한 부족으로 1건 건너뜀이다. 광범위 통합 실행에서는 처음 네 학술 요구 사례가 통과했지만, 과거 소요 시간 기록과 사용자 종료 범위를 고려해 그 뒤의 실행을 중단했다. 따라서 통합 전건 통과나 실제 연구 인스턴스에서의 효과를 주장하지 않는다. 두 변경 계약 문서는 독립 독해와 합의 대조를 마쳤다.

1라운드 수리 뒤 2라운드 전에 graphify를 갱신했다. 마지막 변경 뒤에도 갱신을 완료했다. 현재 상태는 `current`, 파일 229개·노드 6,179개·관계 21,806개이며 변경 문서 2개 의미 추출이 성공했고 미처리 문서는 없다.
