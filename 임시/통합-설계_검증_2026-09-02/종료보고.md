## R1-04
제목: 루트 `CONTEXT.md`가 「작업 씨앗 생성 근거」의 넷째 항을 옛 명칭으로 정의한 채 남아 있다

### 위치
산출물 안의 문제는 `docs/do-math/통합-설계.md` §7.7(사본 995행·997행)과 §7.1 `generation_basis` 행(사본 877행)이다. 이 절들이 넷째 생성 근거를 「생성 회차 규칙」·`seed_generation`으로 닫는 반면, 같은 문서 §0 문서 계약(사본 5행)이 그 용어의 정의 정본으로 지정한 파일은 옛 명칭을 유지한다. 산출물 밖 근본 원인의 좌표는 루트 `CONTEXT.md` 123~124행이다.

### 기준
개편본 §0은 루트 `CONTEXT.md`를 자기가 쓰는 보편 도메인 용어의 정의 정본으로 지정한다(사본 5행).

```
이 문서는 보편 수학 연구 스킬 `do-math`의 구현 정본이다. 루트 `CONTEXT.md`는 이 문서가 사용하는 보편 도메인 용어의 정의 정본이고, 이 문서는 그 용어의 기계 상태·전이·권한·저장·검증을 소유한다.
```

개편본 §7.7은 그 용어의 넷째 값을 새 명칭으로 닫는다(사본 995행·997행).

```
초기화·작업 종결·승인된 외부 변화는 자기 변경 묶음 안에서 작업 씨앗을 제안할 수 있다. 생성 회차 규칙은 이 세 사건과 별도로 씨앗 생성 세션을 연다.
```

```
초기화와 공용 지식 기록 생성에 사용하는 허용 근거 종류 문자열은 `initialization`, `task_terminal_integration`, `approved_external_change`, `seed_generation`으로 닫는다.
```

상시 생성 수정안 3.1은 두 문서에 걸친 명칭 개정을 함께 요구했다(`docs/do-math/상시생성-목차열람-수정안.md` 99행).

```
- 생성 근거 값과 공용 변경 종류의 명칭을 개정한다: 넷째 생성 근거의 이름 "빈 실행 껍질의 생존 규칙" → **"생성 회차 규칙"**, §7.7이 닫는 허용 근거 종류 문자열 `survival_generation` → **`seed_generation`**(§7.1 `generation_basis`와 지식 기록 `cause.kind`가 이 어휘 하나를 함께 쓴다), §18.0 공용 변경 종류 `survival_generation` → **`seed_generation`**. 다섯째 값을 신설하지 않는다. 루트 CONTEXT.md 「작업 씨앗 생성 근거」의 넷째 항을 같은 뜻으로 개정한다(6절 3단계).
```

루트 `CONTEXT.md` 123~124행은 옛 정의를 그대로 두고 있다.

```
**작업 씨앗 생성 근거**:
작업 씨앗의 생성을 정당화하는 연구 인스턴스 초기화, 작업 종결 공용 편입, 핵심 기록에 반영한 승인된 외부 변화 또는 빈 실행 껍질의 생존 규칙. 모든 작업 씨앗은 이 중 하나의 실제 좌표를 가져야 한다.
```

### 영향
`generation_basis` 값을 판정하려는 구현자가 §7.1의 「네 허용 생성 근거 중 하나」에서 출발해 §0이 지정한 정의 정본으로 내려가면, 넷째 근거가 「빈 실행 껍질의 생존 규칙」이라는 옛 트리거를 만난다. 그 정의는 주기 갈래를 배제하므로, 실행 껍질이 비지 않은 상태에서 열린 생성 회차가 만든 씨앗과 지식 기록은 정의 정본 기준으로 허용 생성 근거가 없는 기록이 된다. 개편본 §7.7의 주기 갈래(사본 1001행)와 §26 벡터 S12·S17(사본 2470행·2475행)이 요구하는 동작이 상위 용어 정본과 충돌한 채로 남는다.

### 발견
층위 — 통합-설계와 루트 `CONTEXT.md` 사이의 용어 정본 경계다. 개편은 한 어휘를 두 문서가 나눠 소유하도록 설계됐고(§0 사본 5행: 정의는 `CONTEXT.md`, 기계 상태·전이는 통합-설계), 상시 생성 수정안은 그 어휘의 개정을 두 문서에 동시에 요구했다. 반영은 통합-설계 쪽에만 적용됐다.

근거 — 산출물 안의 문제는 사본 995행·997행·877행이 「생성 회차 규칙」과 `seed_generation`을 닫힌 어휘로 쓰면서, 사본 5행으로 그 정의를 옛 명칭이 남은 파일에 위임한다는 것이다. 산출물 밖의 근본 원인은 루트 `CONTEXT.md` 123~124행의 「빈 실행 껍질의 생존 규칙」이다. 통합-설계 파일만 고쳐서는 이 어긋남을 닫을 수 없다. 통합-설계 안에서 명칭을 되돌리는 것은 동결문 「불변식 목록」 1항(`임시/통합-설계_검증_2026-09-02/동결.md` 23행)이 금지하고, §0이 위임한 정의 자체는 통합-설계 문면에 없기 때문이다. 동결문 「목적 진술」 마지막 문단(같은 파일 14행)도 세 수정안 문서와 다른 기준 원문을 읽기 전용으로 둔다.

실마리 — 상시 생성 수정안 6절 3단계(`docs/do-math/상시생성-목차열람-수정안.md` 230행)와 완료 기준 6(같은 파일 246행)이 이 동기화를 절차와 완료 조건으로 지정한다. 같은 3단계는 루트 `CONTEXT.md`의 「메인 포트폴리오 heartbeat」(397~398행)와 「포트폴리오 선택 세션」(393~394행)도 반드시 대조하라고 지시하는데, 전자는 개편본 §9.3 7단계(사본 1147행)가 heartbeat에 더한 생성 회차 개설을 담고 있지 않고 후자는 「후보 전건」을 받는다고 서술한다. 세 항목이 같은 파일의 같은 미동기화에서 나온다.

## R1-09


### 영향
산출물과 그 정의 정본이 같은 용어에 다른 뜻을 준다. §0.1의 정본 우선순위를 적용하는 독자는 3순위인 `do-math` 계약(§7.7)과 그 위의 보편 용어 정의가 충돌하는 상태에서 넷째 생성 근거가 「빈 실행 껍질의 생존 규칙」인지 「생성 회차 규칙」인지 판정할 수 없고, 주기 갈래로 열린 회차의 씨앗이 정의 정본상 근거 없는 씨앗으로 읽힌다. 선택 세션 정의를 따르는 독자는 §10.2가 없앤 후보 전문 동봉을 여전히 계약으로 읽는다.

## R1-16
제목: §7.7의 넷째 생성 근거가 상위 용어 정본의 정의와 어긋난다

### 위치
산출물 안의 문제는 docs/do-math/통합-설계.md §7.7 사본 997행의 넷째 허용 근거 종류 `seed_generation`과 사본 877행 `generation_basis`의 「네 허용 생성 근거」다. 산출물 밖 근본 원인은 루트 CONTEXT.md 123~124행 「작업 씨앗 생성 근거」 항이다.

### 기준
통합-설계 자신이 §0 문서 계약(사본 5행)에서 용어 정의의 소유자를 CONTEXT.md에 준다.

```
이 문서는 보편 수학 연구 스킬 `do-math`의 구현 정본이다. 루트 `CONTEXT.md`는 이 문서가 사용하는 보편 도메인 용어의 정의 정본이고, 이 문서는 그 용어의 기계 상태·전이·권한·저장·검증을 소유한다. 구현자는 두 문서와 이 문서가 지정한 스키마·도구 계약을 함께 적용한다. 새로운 연구 방법, 상태, 권한이나 예외를 구현 중에 만들지 않는다.
```

docs/do-math/상시생성-목차열람-수정안.md 3.1절 99행이 명칭 개정을 두 문서에 함께 걸었다.

```
- 생성 근거 값과 공용 변경 종류의 명칭을 개정한다: 넷째 생성 근거의 이름 "빈 실행 껍질의 생존 규칙" → **"생성 회차 규칙"**, §7.7이 닫는 허용 근거 종류 문자열 `survival_generation` → **`seed_generation`**(§7.1 `generation_basis`와 지식 기록 `cause.kind`가 이 어휘 하나를 함께 쓴다), §18.0 공용 변경 종류 `survival_generation` → **`seed_generation`**. 다섯째 값을 신설하지 않는다. 루트 CONTEXT.md 「작업 씨앗 생성 근거」의 넷째 항을 같은 뜻으로 개정한다(6절 3단계).
```

같은 문서 7절 완료 기준 6항(246행)이 그 개정을 완료 조건으로 세운다.

```
6. 루트 `CONTEXT.md` 「작업 씨앗 생성 근거」 넷째 항의 개정이 반영됐고, 6절 3단계가 지시한 다른 용어 대조가 「메인 포트폴리오 heartbeat」·「포트폴리오 선택 세션」을 포함해 끝나 어긋남 없음 또는 최소 개정 내용이 보고에 기록됐으며, `docs/wayfinder/pvsnp-재설계/컨텍스트.md`는 일괄 갱신이 커밋됐거나 해결 댓글에 `정본 갱신: 영향없음`이 명시됐다.
```

산출물은 개정된 쪽이다. 사본 997행이다.

```
초기화와 공용 지식 기록 생성에 사용하는 허용 근거 종류 문자열은 `initialization`, `task_terminal_integration`, `approved_external_change`, `seed_generation`으로 닫는다. 지식 기록의 `cause.kind`와 작업 기록의 `generation_basis`는 해당 사건에 맞는 이 어휘를 사용하고 `cause.id` 또는 생성 근거 좌표로 실제 사건을 가리킨다. 생성 회차에서 나온 기록과 씨앗에는 넷째 값 `seed_generation`을 사용한다.
```

루트 CONTEXT.md 124행은 개정 전 문면 그대로다.

```
작업 씨앗의 생성을 정당화하는 연구 인스턴스 초기화, 작업 종결 공용 편입, 핵심 기록에 반영한 승인된 외부 변화 또는 빈 실행 껍질의 생존 규칙. 모든 작업 씨앗은 이 중 하나의 실제 좌표를 가져야 한다.
```

### 영향
통합-설계 §0이 「두 문서를 함께 적용한다」고 지시한 구현자가 넷째 생성 근거에서 서로 다른 두 정의를 받는다. CONTEXT.md는 빈 실행 껍질을 조건으로 하는 생존 규칙만 정당한 근거로 인정하고, §7.7은 실행 껍질과 무관한 주기 갈래에서 만든 씨앗도 같은 넷째 값으로 편입시킨다. 두 문서를 함께 읽는 구현자는 주기 갈래 씨앗의 `generation_basis`가 정당한 근거를 가졌는지 판정할 수 없다. 정의 정본 쪽 문면을 우선하면 상시 생성 개편 자체가 근거 없는 씨앗을 만드는 것으로 읽힌다.

### 발견
층위 — 하류 정본 동기화의 경계다. 통합-설계는 §0에서 용어 정의의 소유권을 루트 CONTEXT.md에 넘겨 두고 기계 상태·전이·저장만 소유한다. 상시생성 개편은 넷째 생성 근거의 이름과 조건을 함께 바꾸었으므로 두 문서를 같은 값으로 옮겨야 했는데, 옮겨진 것은 산출물 한쪽뿐이다.

근거 — 산출물 안의 문제는 사본 997행이 넷째 허용 근거 종류를 `seed_generation`으로 닫고 사본 877행 `generation_basis` 행이 그 값을 네 허용 생성 근거의 하나로 받는데, 사본 5행이 정의 정본으로 지정한 문서의 넷째 정의는 그 값을 뒷받침하지 않는다는 것이다. 산출물 밖의 근본 원인은 루트 CONTEXT.md 123~124행이 개정 전 문면을 유지하고 있다는 것이다. 산출물 파일만 고쳐서는 기준을 충족할 수 없다. 통합-설계 안에서 이 어긋남을 없애는 유일한 길은 §7.7·§7.1·§18.0의 넷째 값을 CONTEXT.md의 옛 정의로 되돌리는 것인데, 그것은 상시생성 수정안 3.1절 99행이 지시한 개정을 되돌리는 일이고 동결문 21~23행 불변식 1이 그런 수리를 금지한다. 반대로 CONTEXT.md는 동결문 3~5행 「산출물」 절에 없어 조각을 세울 수 없다. 실측으로 커밋 fe5a47f의 변경 파일은 통합-설계와 기억 노드·색인 셋뿐이고 CONTEXT.md가 없다.

실마리 — 루트 CONTEXT.md 123~125행 「작업 씨앗 생성 근거」, 같은 파일 393~399행 「포트폴리오 선택 세션」·「메인 포트폴리오 heartbeat」(상시생성 수정안 6절 230행이 「반드시 대조한다」고 지목한 두 용어이며, 후자의 정의 문면은 사본 1139~1151행의 11단계 heartbeat 절차에 생성 회차 개설 단계가 든 것을 아직 반영하지 않는다). 기준 원문 쪽은 docs/do-math/상시생성-목차열람-수정안.md 3.1절 99행, 6절 219행·230행, 7절 246행. 산출물 쪽 접점은 사본 5행, 877행, 997행과 §18.0(사본 1731~1747행)의 `seed_generation` 공용 변경 종류.
