## 2. 영역 판정

DOC 영역은 세 경량화의 방향을 수치 수준에서는 대체로 따른다. 결정 3·4·6이 지운 이름은 영역 문서에 남아 있지 않다. 설정 수치는 CLI 설정 목록으로, 모델 표는 「모델과 실행예산」으로 모였다. 문서가 가리키는 함수·필드·명령은 표본 대조에서 모두 실제 코드에 있었다.

그러나 "이음새마다 정의는 하나"라는 원칙은 문서 사이에서 지켜지지 않는다. 같은 절차를 두세 개의 공통 문서가 따로 적는다. 그중 편입 묶음의 생략 조건은 문서끼리 다르고 코드와도 어긋난다(DOC-01). 설치 복구 AI의 경계는 코드 프롬프트와 `계약/독립-운영.md`에 따로 있다(DOC-06).

가장 큰 개선 여지는 역할 입력 비용이다. 모든 AI 실행이 역할과 무관하게 같은 공통 문서 240KB를 받는다. 이는 기본 입력 한도 500KB의 약 48%다. 세 경량화는 이 묶음을 오히려 7KB 늘렸다(DOC-02, DOC-09).

do-math 전체를 한 구조로 정리한다는 관점에서 이 영역의 답은 다음과 같다. 문서마다 소유 범위를 하나로 정한다. 공통 문서는 모든 역할이 쓰는 정의와 절차만 담는다. 역할 한정 절차는 해당 역할 문서로 보낸다. 운영자 정보는 README와 CLI 계약으로 보낸다. 이렇게 경계를 정하면 중복과 비용을 함께 줄일 수 있다.

검토했고 없음: 이음새(코드 규칙의 이중 구현), 불일관, 미사용, 파생상태, 결함, 임시방편
