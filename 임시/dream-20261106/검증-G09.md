### D1. "이 검수가 없었으면 얻지 못했을 결과"의 둘째 사례를 검수에 잘못 귀속했다 (유형 1)

- 처분 제안: 수정 문안. "이 검수·배정이 없었으면 얻지 못했을 결과는 둘이다"로 바꾼다. 첫째는 배정이 실제 역할 schema를 그대로 쓰게 한 결과로 적는다[[M-0552]] [[M-0553]]. 셋째(M-0563)는 유지한다. M-0571은 "task가 낸 partial을 공식 green보다 우선해 유지했다"는 재실증으로 옮긴다.

### D2. 검산기 실패의 "처리는 모든 사례에서 같았다"는 노드보다 넓다 (유형 1, 7절 패킷 포함)

- 근거: 일곱 노드의 처리 서술은 서로 다르다.
  - 원 실패를 남겼다고 명시한 것은 두 노드다. M-0555("원 실패를 남겼다")와 M-0573("원스크립트를남기고")이다.
  - 검산기를 고쳤다고 명시한 것은 네 노드다. M-0568("관리 검산을 고쳤다"), M-0576("검산기를 고쳤으며"), M-0561("순서만 교정한 재검산"), M-0573("교정")이다.
  - M-0560은 검산기를 고쳤다고 쓰지 않았다. "원 보고는 바꾸지 않고 공용 판단을 그 범위로 한정"했다.

  - "제품과 task 자료는 고치지 않았다"는 일곱 노드 모두와 정합한다.
- 처분 제안: 수정 문안. "일곱 노드 모두 제품과 task 자료는 고치지 않았다. 원 실패의 보존을 명시한 노드는 M-0555·M-0573이고, 검산기의 교정을 명시한 노드는 M-0561·M-0568·M-0573·M-0576이다." 패킷 문장은 규범("원 실패를 남기고 … 고친다")으로 쓰되 근거 id를 실제로 그 처리를 적은 노드로 바꾼다. 현재 그 문장의 근거는 관찰자 사례인 M-0564·M-0575다. D8도 함께 본다.

### D5. partial 계수와 "쓰기 범위 공백" 분류가 노드와 어긋난다 (유형 3·1, 7절 패킷 포함)

- 좌표: 2절 「partial 반환의 상당수는 배정한 쓰기 범위의 공백에서 생겼다」의 제목, "나머지 partial은 … [[M-0560]] … [[M-0565]] …", L-0016 「파견 계약」의 신설 첫 문단.
- 근거: 노드가 partial로 명시한 반환은 여섯이다. M-0553(003), M-0554(004), M-0556(006), M-0558(008), M-0567(017), M-0571(021)이다(`grep -l partial`, M-0555·M-0559는 앞선 partial을 가리킬 뿐이다). 초안에는 세 가지 어긋남이 있다.
  - M-0560과 M-0565는 partial이라는 말을 쓰지 않는다. M-0565는 측정이 "complete"였다고 쓴다. 초안은 둘을 partial로 셌다.
  - M-0556의 partial에는 원인이 둘이다. 범위 밖 fixture에서 생긴 11실패와 "통과한 검사 안의 성공 표본 공백"이다. 뒤의 것은 범위 공백이 아니다.
  - M-0558은 쓰기 범위의 공백이 아니다. "008의 쓰기 목록에는 CLI 문서가 있었지만 objective는 P01 문장만 바꾸도록 한정했다"이므로 임무 범위의 한정이다. 초안 본문은 이 차이를 정확히 적었지만, 제목과 패킷 문장("닫힌 쓰기 범위는 …")은 이 사례를 쓰기 범위 공백으로 묶는다.

  결과적으로 범위 공백에서 생긴 partial은 명시 partial 6건 가운데 3건이다(M-0556은 일부만). "상당수"라는 표현은 유지할 수 있다.
- 처분 제안: 수정 문안.
  - 제목은 "partial 반환의 절반은 배정한 쓰기 범위나 임무 범위가 의무의 수행 위치를 빠뜨려서 생겼다"로 바꾼다.
  - "나머지 partial" 목록에서는 M-0560·M-0565를 빼거나, "partial로 표시되지 않은 미충족"으로 따로 적는다.
  - 패킷 첫 문장은 "닫힌 쓰기 범위와 임무는 의무가 실제로 수행되는 위치를 포함해야 한다"로 바꾼다.

### D6. "좁게 쓴 요약의 대조"를 새 정보로 판정했지만 L-0005에 같은 원리가 있다 (유형 2·5)

### D7. 「회수 검증」 패킷이 초안 스스로 재실증으로 판정한 내용과 판정하지 않은 내용을 L에 넣는다 (유형 2·5)

- **"manager가 회차마다 원자료를 다시 세어 검수를 닫았다."** 대체로 지지된다. 34개 회차 노드 모두에 선택·row·exit·소스 해시·원보고 대조 가운데 하나 이상의 재계수가 있다. 예외는 재사용을 명시한 회차다. M-0584는 "의미 검수·실행은 기존 수용 근거를 재사용"했지만 Git blob 대조는 새로 했다. ## 4. 검증자가 추가로 본 것

아래는 초안에 없던 관찰이며 결함으로 세지 않는다.

- **시험 전제 실패의 반복.** D3에서 센 fixture·대역 전제 실패 6개 노드(M-0556, M-0558, M-0560, M-0565, M-0567, M-0568)는 L-0001 「검증 계약」의 "시험은 제품 생산자의 계약을 따라가야 한다"의 재실증이다. 이 루프는 대부분의 회차에서 이 유형을 새로 만났다. 다만 이 사실은 L에 새로 쓸 내용이 아니라 원장 (가)의 보조 증거다. 같은 계열의 교훈이 L 통합 뒤에도 되풀이됐다는 뜻이다.
- **원장 (가)의 친족 사례.** M-0571의 "반복 회귀·미러·관리 비용은 파일 소유 충돌을 피하는 것만으로 줄지 않는다"는 D-0010 「병렬 구현에서 파일 소유 경계는 의미 충돌을 막지 못했다」와 같은 원리(파일 소유 경계만으로는 부족하다)다. 다만 의미 충돌이 아니라 비용으로 나타났다. 초안의 (가) 답("의미 충돌이나 구조 이동 순서의 실패는 재발하지 않았다")은 좁은 의미로 옳다. 같은 원리의 다른 발현이 있었다는 사실을 덧붙이면 원장 입력이 더 정확해진다.
- **관찰 도구와 측정 도구.** M-0566의 관찰 부작용은 L-0005의 "측정 도구의 출력도 대상과 다를 수 있다"(cProfile 사례)와 인접한다. 앞의 것은 도구가 대상의 상태를 바꾼 경우이고, 뒤의 것은 출력을 왜곡한 경우다. 두 항목 사이에 교차 참조를 두면 독자가 같은 계열로 찾을 수 있다.
