# dream 2026-11-06 L 노드 통합 계약

이 문서는 layer-3 노드 하나를 맡는 통합 에이전트의 계약이다. 먼저 `임시/dream-20261106/파견-공통.md`의 3.4절(현행층에는 현 상태만)과 3.6절(작문 관례), `기억/세칙_dream.md`의 "layer-3(현행 통합층) 유지 관례"와 "병합: 현행층으로 통합"을 읽는다.

## 1. 목적

여러 주제군의 확정 패킷(`확정-G##.md` 5절)이 같은 L 노드에 개정·신설·삭제를 낸다. 통합 에이전트는 그 패킷 전부와 현재 L 노드를 하나의 현행 판본으로 합친다. L 노드는 모든 작업 세션이 착수 때 읽는 현행 지식이다. 로그가 아니다.

## 2. 입력

1. 현재 L 노드 `기억/layer3/L-####.md` 전문.
2. 파견 메시지가 지정한 확정 패킷마다 5절의 `### L-####` 소절 전문. 소절 경계는 다음 `### L-` 또는 `## 6.` 줄이다. 줄 번호를 grep으로 찾아 그 범위를 읽는다. 1~4절은 판정의 맥락이 필요할 때만 읽는다.
3. 패킷 문장의 근거가 의심스러우면 해당 `기억/layer1/M-####.md`를 직접 읽는다. 현행 do-math 사실은 `.claude/skills/do-math/` 아래 파일로 확인한다.

## 3. 통합 규칙

- **통합이 기본이다.** 같은 기존 항목에 여러 주제군이 개정을 냈으면 하나의 항목으로 다시 쓴다. 기존 문단 끝에 덧붙이지 않는다.
- **중복을 지운다.** 서로 다른 주제군이 같은 원리를 다른 사례로 냈으면 원리 한 번과 대표 근거로 쓰고, 인라인 근거 id는 합친다.
- **재실증은 본문을 늘리지 않는다.** 패킷이 재실증이라고 표시한 문장은 본문에 새 문장으로 넣지 않는다. 필요하면 기존 문장 끝의 근거 id에만 더한다.
- **기존 근거 id를 보존한다.** 기존 문장을 다시 쓸 때 그 문장의 `[[id]]`를 지우지 않는다. 문장을 삭제하면 그 근거가 다른 문장으로 옮겨졌는지 본다.
- **정정 대기 줄**(`> 정정 대기: ...`)은 그 항목을 통합 개정하면서 지운다.
- **사라진 경로.** 현행 트리에 없는 파일을 정본으로 가리키는 문장은 회수 좌표(`git show <커밋>:<경로>`)로 바꾸거나 지운다. 경로 실재는 직접 확인한다.
- **분량.** 새 지식이 현행 판단을 바꾸는 만큼만 늘린다. 통합 뒤 분량이 현재의 1.5배를 넘으면, 같은 영역 안에서 겹침을 다시 줄이거나 분할(fork)이 필요한지 판단하고 그 판단을 보고 파일에 적는다. 분할은 메인이 정한다.
- **패킷 사이 충돌.** 두 패킷이 같은 사실을 다르게 적으면 근거 노드를 직접 읽어 정한다. 정하지 못하면 둘 다 쓰지 않고 보고 파일에 적는다.
- frontmatter의 `convention_version`은 바꾸지 않는다(생성 시점 값).

## 4. 산출

두 파일을 쓴다. `기억/` 아래 파일은 수정하지 않는다. 메인이 검토 뒤 적용한다.

1. `임시/dream-20261106/통합-L-####.md`: 통합된 L 노드 전문(frontmatter 포함). 파일을 먼저 frontmatter와 도입부로 만들고, 항목 하나를 마칠 때마다 덧붙인다.
2. `임시/dream-20261106/통합-L-####-보고.md`: 항목별 처분 표(| 항목 | 유지 / 개정 / 신설 / 삭제 | 반영한 주제군 | 한 줄 이유 |), 패킷 사이 충돌과 처분, 쓰지 않은 패킷 문장과 이유, 분량(통합 전·후 바이트), 분할 판단.

## 5. 반환

결과는 파일에 쓰고 응답 본문은 짧게 유지한다. 마지막 메시지는 다음만 담는다.

```
<DONE | PARTIAL | BLOCKED> L-####
산출: 임시/dream-20261106/통합-L-####.md, 통합-L-####-보고.md
분량: 전 <n> B, 후 <n> B
항목: 유지 n, 개정 n, 신설 n, 삭제 n
충돌·미결: <요지 또는 없음>
```
