# do-math 결정 대조 검증 결과

연구 피드백 이후의 대화 원문과 기억을 정본 105파일·22,456행에 대조했다. 네 수리자의 전문 독해를 보충한 뒤 수리·병합·독립 심사를 1라운드 수행했다. 공식 수리 7건을 적용했고, 사용자와 추가로 확정한 평가 필수화·평가 보충 경로 및 후속 회귀에서 재현한 제어 순서 수리를 반영했다. 기존 연구 인스턴스와 예약 작업은 변경하거나 재개하지 않았다.

최종 전체 회귀는 **412건 중 411건 통과·1건 미실행**, 종료 코드 0이다. 미실행은 Windows 심볼릭 링크 생성 권한 부족이다. 다만 대기 순회의 불필요한 상태 커밋 문제 R1-05는 수리안이 기각되어 남았다. 이 보고는 검토한 모든 코드에 결함이 없다는 보증이 아니다.

## 종료 판정과 마지막 결산

`종료집계` 판정은 **종료, 판정 순서 3항**이다. 이는 verify-rounds의 종료 규칙 중 라운드 수가 상한에 도달하면 종료한다는 조건이다. 라운드 수 1이 상한 1에 도달했다. 하한과 상한은 모두 1이다. 적용 0인 라운드가 몇 회 연속되면 멈추는지를 뜻하는 종료 연속영은 1이며, 이번 적용 0의 연속 횟수는 0이다. 라운드 2는 실행하지 않았다.

| 단위 | 제기 또는 심사 | 적용 또는 수리 확정 | 기각 | 상신 | 결번 |
|---|---:|---:|---:|---:|---:|
| 라운드 1 본표의 원 항목 | 13 | 적용 7 | 5 | 1 | 0 |
| 병합 뒤 심사 항목 | 12 | 수리 확정 7 | 4 | 1 | 0 |

공식 적용 수는 `vr.py`가 조각으로 적용한 항목만 센다. 사용자 회신에 따라 별도로 작성·반영한 변경은 이 수에 합산하지 않는다.

본표의 다른 상태는 모두 0이다. 원 항목 두 개가 병합 항목 R1-M1로 심사돼 기각됐으므로 두 단위의 기각 수가 다르다.

상신 1건은 R1-04의 심사 당시 처분이다. 이 항목에는 적용할 조각이 없었다. 사용자가 방향을 확정한 뒤 아래 변경 경로로 구현했으며, 현재 회신을 기다리는 항목은 없다.

## 사용자 확정과 후속 검증에 따른 변경

R1-04는 미평가 과제의 계약 검토를 중·상 등급 중 어느 것으로 시작할지에 관한 문서·구현 불일치였다. 사용자는 기본값 선택에 앞서 평가가 빠지는 경로를 확인하도록 했다. 이어 일반 후보의 평가 완전성을 생산자와 수신자가 확인하고, 자동 학술 과제는 기존 후보 준비가 평가를 보충한 뒤 계약 검토로 보내는 방안을 승인했다. [확정 원문](근거/평가보충-사용자확정.md)을 보존했다.

- 세션 예산의 신규·개정 후보와 연구 계획의 선택 과제는 평가와 정확히 일대일로 대응해야 한다. 공통 검사로 누락·중복·대상 밖 평가를 구별한다.
- 평가 없는 기존 과제에는 판본이 고정된 `action.assessment_targets`를 제공한다. 후보 준비는 계약을 바꾸지 않고 평가만 작성하며, 입력 부족은 명시적 보류로 반환한다.
- 평가 보충에서는 후보 생성·개정·철회와 다른 확장 변경을 허용하지 않는다. 평가와 보류를 합쳐 지정 과제 전건을 한 번씩 처리한다.
- 같은 입력의 보류 요청은 자동 재생성하지 않는다. 입력·대상 판본 변경이나 명시적 재개 뒤 다시 평가한다. 일반 후보 생성과 평가 보충의 요청 병합·실패 해소도 구별한다.
- 사용자 학술 요구와 완료 기준은 유지한다. 새 평가는 과제에 결합한 뒤 난이도·중요도·검토 역할의 최소 등급 중 가장 높은 등급의 모델로 독립 계약 검토를 받으며, 평가 보충 자체는 후보 생성 회차로 세지 않는다. 기존 실행횟수 방식의 인스턴스는 작업·운영 호출 한도와 역할별 모델 설정을 유지한다. 새 평가 필수 검사와 평가 보충은 세션 예산 방식에 적용한다.

후속 회귀에서는 접수 벽시각이 완전히 같은 대화 연결·해제 요청이 임의 ID 순서로 뒤집히는 경우를 재현했다. 높은 분해능의 단조 성능 카운터 값을 고정 폭 문자열로 저장해 같은 시각의 접수 순서를 보존했다. 이 수리는 사용자 정지 보호의 기존 요구를 지키기 위한 후속 변경이며 공식 조각의 적용 계수에 넣지 않았다. [재현](검증/control-tie-red.log), [수리 후 검사](검증/control-tie-final-green.log), [시계 환경](검증/control-clock-environment.json)에 근거가 있다.

## 상신·무처분 잔여와 기각 보관

회신 대기 상신과 무처분 잔여는 없다. R1-04는 사용자 확정 방향의 구현으로 해소했다.

기각된 심사 항목은 R1-03·R1-05·R1-08·R1-M1이다. [기각 보관](기각보관/do-math-라운드1.md)에 항목 원문과 각 심사자의 판정을 보존했다.

R1-05의 반복 저장 현상은 확인됐다. 그러나 제안된 수리는 head와 status만 비교해, 같은 대기 순회에서 새로 생긴 사건과 큐 변경까지 저장하지 않을 수 있었다. 개선 관문에서 기각해 적용하지 않았다. `--watch` 대기의 불필요한 상태 커밋은 남아 있으며 실제 저장 비용은 계측하지 않았다.

나머지 기각에서는 역할·예산 주체의 나열을 닫힌 목록으로 읽은 영향 주장과, 기존 시험을 통과한다는 잘못된 변이 예시 등이 문제였다. 편집상의 보강 가능성을 현재 결함의 입증으로 대체하지 않았다.

## 자체 처리와 승계

승계는 사용자가 이미 확정한 수리 방향을 새 선택 없이 남은 자리에 적용하는 것이다. 아래는 이번 런의 처리 기록이다.

- 초기 동결문에 잘못 적힌 검사 명령은 현행 README의 unittest discovery와 `probe_codex.py --skill-only`로 정정했다. 진행 중 수리를 종료하고 같은 라운드를 처음부터 다시 수행했다. 사용자 목적·모델·라운드 수는 바꾸지 않았다.
- Claude Agent 부재는 사용자 승인에 따라 로컬 Claude CLI로 처리했다. 수리 opus high·병합 opus low를 유지했다.
- 심사 Codex CLI 3기는 사용량 한도로 판정 파일 없이 종료했다. 동일한 `gpt-6-astra medium`의 독립 에이전트 3기로 실행 수단을 바꿨고, 파견문·3인 정족·산출 계약을 유지했다. [실행 기록](검증/심사-실행수단.json)에 근거가 있다.
- 최종 수리 처분에서 승계된 항목은 R1-02, R1-10, R1-12다. R1-02·R1-10은 `근거/계약-학술자료-독립운영.md`의 기본 운영 주기 확정, R1-12는 같은 파일의 사용자 정지·대화 소실 정책과 진행 승인을 인용한다. R1-12에는 심사자 1·2의 승계 기록이 있다.
- R1-03에도 한 심사자의 승계 인용이 있었지만 최종 기각됐으므로 실행된 승계로 세지 않는다. R1-04는 조각 없는 상신 제안이어서 승계 전환 대상이 아니며 사용자 회신으로 방향을 정했다.
- 후속 회귀의 실패는 시험 대역·검증 환경·실제 제어 순서 문제로 구별했다. 대역과 환경을 맞춘 뒤 실제 결함은 재현·수리하고 최종 판본 전건을 다시 검사했다. 실패를 검사 면제나 통과로 바꾸지 않았다.

첫 전체 회귀의 오류 27건은 수명 관리 시험의 대역이 새 스케줄러 메서드를 제공하지 않은 데서 발생했다. 실패 3건은 고정 사본의 Lean 탐색 환경, 평가를 생략한 대역 응답, 같은 접수 시각의 제어 순서였다. 모두 원인을 구별해 처리한 뒤 정본에서 최종 전체 회귀를 실행했다. 최종 검사 시작과 종료 사이에 106개 정본 파일의 해시가 바뀌지 않았음을 확인했다.

미실행 1건은 작업 공간 밖을 가리키는 심볼릭 링크가 산출 수집에서 제외되는지 검사하는 사례다. 링크 생성 권한이 없어 검출 단계까지 실행하지 못했으므로 이 경로를 통과로 세지 않았다.

모델 응답을 사용하는 흐름 시험은 대역 응답이다. 실제 제공된 제출 검사 명령, 임시 Git·SQLite·Windows 프로세스와 일부 Lean 검사는 실행했지만, 실제 모델의 난이도 평가 품질·장기 연구 성능·원래 수학 문제의 해결을 입증한 것은 아니다. 전문 독해 표와 도구 호출 기록도 이해의 완전성을 자동 증명하지 않는다.

## 앵커 대조 변경 자리

기준선의 정본 105파일 중 기존 21파일을 변경하고 시험 1파일을 추가해, 최종 검사 대상은 106파일이 됐다. 생성 사본은 공식 미러 생성기로 함께 갱신했다.

- 문서 9파일: SKILL.md, README.md, references의 CLI-실행-계약·공통-실행·모델과-실행예산, 계약의 독립-운영·연구-계획·작업-계약-검토·후보-준비.
- 실행 코드 6파일: engine.py, lifecycle_engine.py, model_policy.py, scheduled_operator.py, scheduler.py, submission.py.
- 시험 7파일: test_engine.py, test_lifecycle_engine.py, test_operator.py, test_research_recovery.py, test_session_scheduler.py, test_submission_boundaries.py, 새 test_model_assessment_flow.py.

정확한 변경은 커밋의 diff와 최종 파일 해시로 회수할 수 있다. 공식 조각 적용 이후의 사용자 확정과 후속 검증 수리도 이 목록에 포함된다.

## 용어와 보조 스크립트 승격 후보

GLOSSARY 주의 승격 후보는 없음. 읽기 미완료와 부분 나열의 해석 문제는 운영 기록과 기각 근거로 보존했다.

`_` 보조 스크립트는 아래 여섯이다. 모두 이번 런에 사용한 보조물이며 공식 도구로 승격하지 않았다.

| 스크립트 | 맡은 작업과 승격 검토 범위 |
|---|---|
| `_prepare.py` | 대화 원문 좌표를 보존한 자료 회수와 동결 재료 작성. 사건별 입력에 의존한다. |
| `_dispatch.py` | 기존 템플릿 슬롯 채우기와 CLI 파견. 실행 수단 연결을 일반화할지 검토할 수 있다. |
| `_resume_repairs.py` | 사용자가 승인한 전문 독해 보충과 같은 컨텍스트 재개. 일반 기본 절차로 만들지는 않았다. |
| `_coverage.py` | 독해 표의 파일·행 범위 대조와 읽기 도구 기록 보존. 실제 이해의 검증과 구별해야 한다. |
| `_validate.py` | 프로젝트 회귀 명령 실행·종료·로그 보존. verify-rounds의 항목 검산을 대신하지 않는다. |
| `_draft_docs.py` | 사용자 확정에 따른 문서 초안과 독해 입력 구성. 사건별 작성 보조다. |

이 작업들은 공식 스크립트의 조각 판독·병합·심사 집계·적용을 대체하지 않았다. 공식 범위의 기계 작업은 `vr.py`로 수행했다.

## 운영 기록 요지

수리자들은 처음 두 시도에서 부분 독해를 명시했다. 사용자의 후속 지시에 따라 담당 파일 전건·행 수·직접 독해 의무·출력 잘림 회수·파일별 기록·미독해 0의 완료 조건을 명확히 주고 같은 컨텍스트에서 보충했다. 최종 파일별 대조에서 수리자 1의 문서·스키마·진입점 26파일, 수리자 2의 실행기 35파일, 수리자 3의 회귀·검증 44파일, 수리자 4의 전체 관점 105파일이 모두 일치했다. `검증/독해범위_1.json`부터 `독해범위_4.json`까지 대조 결과와 도구 호출을 보존했다.

대화 원문의 후속 결정을 우선했다. 운영 세션 기본값은 모델별 1개에서 3개로 변경된 최종 결정을 적용했고, 제출 검사를 이전 세션 예산 작업에서 제외했다는 기록은 이후 별도 구현 지시를 금지하는 것으로 읽지 않았다. 이번 R1-04의 사용자 확정도 기존 미평가 기본값 논의를 대체하는 현행 결정으로 보존했다.

아래의 발견은 verify-rounds에서 산출물 밖의 근본 원인을 호출자에게 전달하는 별도 항목 유형이다. 이번에 남은 R1-05는 산출물 안의 문제에 대한 수리안 기각이며 이 유형에 포함되지 않는다.
