# do-math question 체계 검증 장부

## 신호 처리 절

- 자체 처리 — 신호 1, R1-07(조각 없는 상신 제안: organizer가 점유된 두 question을 병합하면 병합된 question 하나를 두 explorer가 점유하게 되어 결정 6과 결정 23이 부딪친다. 수리자 추천은 node 병합처럼 예외를 문서화하는 (가), 다른 선택지는 점유 중 병합 거부 (나)와 점유가 끝날 때까지 별칭 적용 지연 (다)). 동결문 불변식 「사용자 결정」이 처분을 「사용자에게 올린다」로 지정했으므로 승계 검사 밖이다. 판단: 「승인하되 고치지 않는다」(조각 없는 상신 제안의 자체 처리가 정할 수 있는 유일한 값). 물음 셋 — 오판 비용: 작다. 두 explorer가 같은 question을 함께 맡는 상태는 병합 직후 그 두 파이프라인이 끝날 때까지만 이어지고 연구를 깨뜨리지 않는다. 되돌리기: 무처분은 비용이 없다. 판단 가능성: 결정 6(한 question 한 explore)과 결정 23(node처럼 병합)이 이 경우에 서로 다른 방향을 가리켜, 어느 쪽을 앞세울지는 사용자 정보가 필요하다. 사용자 지시(파견_검증.md 3절)에 따라 상신하지 않고 종료 보고 「사용자 결정에 닿는 제기」에 모은다. 사용자 확정 기록을 뒤집지 않았다.

- 자체 처리 — 신호 1, R2-13(조각 없는 상신 제안: 이행 스크립트가 `kind: "questions"` 사건을 쓴 뒤 사본을 재생성할 때까지, 살아 있는 세션의 조정 명령과 전송 점검이 생성 사본의 옛 `replay()`에서 `'questions'` 오류로 실패한다. 선택지는 A 사본 재생성을 이행 앞으로 옮김(수리자 추천), B 순서를 두고 docstring에 구간을 적음, C 이행을 `--questions` 없이 한 번, 재생성 뒤 `--questions`로 한 번). 승계 검사: 순서를 바꾸는 사용자 확정 기록이 없다. 순서의 원문은 `임시/do-math-question/파견_개발.md` 5절(134행) 「실행 순서(멈춤 → 이행 → 사본 재생성 → 시작)」이고, 이 런의 금지 「사용자 결정의 변경」에 닿는다. 판단: 「승인하되 고치지 않는다」(조각 없는 상신 제안의 자체 처리가 정할 수 있는 유일한 값). 물음 셋 — 오판 비용: 순서를 그대로 두면 배포 때 짧은 구간 동안 세션 명령이 실패해 attempt가 원인 모를 오류로 판단을 바꿀 수 있다. 런 밖 배포 단계의 손상이라 크다. 다만 그 손상은 배포를 맡는 쪽이 순서를 고르면 피할 수 있다. 되돌리기: 이 런 안의 무처분은 비용이 없다. 판단 가능성: 결함과 대안의 안전성은 수리자의 실측으로 근거가 서지만, 사용자가 정한 배포 순서를 바꿀지는 사용자 정보가 필요하다. 사용자 지시(파견_검증.md 3절)에 따라 상신하지 않고, 종료 보고 「사용자 결정에 닿는 제기」와 운영 보고의 배포 주의에 모은다. 사용자 확정 기록을 뒤집지 않았다.

- `_` 보조 스크립트: `_wait_stable.py` — 파견 산출 파일이 존재하고 일정 시간 크기가 변하지 않을 때까지 포그라운드로 기다린다. 공식 스크립트의 `wait_outputs.py`는 크기 안정을 보지 않아 쓰는 도중의 파일을 완료로 읽을 수 있고, Agent 파견의 완료 통지 대기는 공식 스크립트가 덮지 않는 「파견 수단의 병행 실행」이다. 완료 신호는 Agent 호출의 반환을 쓰고, 이 스크립트는 반환이 비동기일 때만 쓴다.
