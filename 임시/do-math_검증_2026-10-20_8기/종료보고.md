# do-math 제품 코드 검증 종료 보고

정확히 두 라운드의 검토·심사·반영을 마쳤다. 원안 34건 중 정규 승인 적용은 17건이며, 사용자 지시에 따른 미통과 안건의 세션 직접 보완은 14건이다. 사용자 보류 2건과 직접 검토 뒤 미반영한 재심사 정산 문제 1건이 남았다. 원안 수에는 같은 결함으로 병합한 항목도 각각 들어가므로 고유 결함 31개를 고쳤다는 뜻은 아니다.

전수 검사는 4,597건을 완료했고, 실패했던 9건은 보완 후 해당 9건만 재검사해 모두 통과했다. Windows 권한 부족으로 skip한 1건은 미검증으로 남긴다. 전수 뒤 catalog 지급 결박을 추가 수리했으므로, 전수 결과와 최종 판본의 제한된 재검사를 별도 증거로 읽어야 한다.

## 1. 종료 판정

공식 `종료집계`: 라운드 2, 판정 순서 3항인 `라운드 수 2 ≥ 상한 2`로 종료한다. 하한과 상한은 모두 2다. 공식 적용 이력은 1라운드 11건, 2라운드 6건이며 적용 0 연속은 0회다. 무결함이나 수렴으로 종료한 것이 아니다. 신호 2는 정규 심사가 수리한다고 확정한 항목 수에 비해 실제 적용이 절반에도 못 미치는 라운드가 두 번 연속되는 경우다. 두 라운드 모두 수리 확정 전건을 공식 적용해 해당하지 않는다. 신호 3은 심사 대상 수가 줄지 않은 라운드가 두 번 연속되는 경우다. 대상은 19건에서 13건으로 줄어 해당하지 않는다.

## 2. 라운드별 제기와 반영

| 라운드 | 원안 | 병합 뒤 심사 단위 | 정규 승인 적용 | 직접 보완 원안 | 잔여 |
|---|---:|---:|---:|---:|---:|

| 2 | 14 | 13 | 6 | 7 | 직접 미반영 1 |

공식 장부의 기각·무처분 판정은 그대로 보존했다. 직접 보완은 정족 승인으로 바꾸어 세지 않았다. 1라운드는 미통과 6심사 단위에 해당하는 원안 7건을 모두 직접 보완했다. 2라운드는 기각 7심사 단위에 해당하는 원안 8건을 직접 검토해 6단위/7원안을 보완했다.

1라운드의 정규 적용은 사용자 정지 보존, 재시작 사건 중복, 착수 참조, 잘못된 파일명, 목표 감사·학술 증거, 허가 철회 뒤 선택 정산, 초기화 채택, 역할 입력, 빈 Claude 모델 이름을 다뤘다. 직접 보완은 일반·전환 검토의 자원 정산 구별, 복구 관문 대기의 기록과 중복 방지, 시계 정본 포인터, 배정 파생 결박, 지급 입력 파일 참조를 다뤘다. 지식 개정에서는 옛 검토를 끝내고 그 조사를 취소하는 규칙을 공통 함수로 모았으며, 새 검토를 이전 검토 주기에 연결했다.

2라운드 정규 적용은 엔진 요청 계획의 정산 대기, 과거 snapshot의 미관측 공급자 상태, 생산자 OS 잠금, 목표 미해결 뒤 학술 과제, 미시작 의도 해석의 재저작 계수, 운영 점검 스키마의 정본 통합을 다뤘다.

## 4. 자체 처리와 직접 검토

세션의 직접 판단은 사용자 지시에 따른 보완이며 심사자에게 재승인받았다고 서술하지 않는다. 항목별 원안·기각 사유·판단과 검사 좌표는 장부 운영 기록에 보존했다.

| 2라운드 미통과 단위 | 세션 판단과 반영 |
|---|---|
| R2-03 | 철회·대체된 지식에서 컴파일 전 관문을 기다리거나 중단 뒤 재개를 기다리는 형식 검사 요청을 거둔다. 정책 복귀를 기다리던 동일성 검토 초기화 요청도 거둔다. 원 수리가 놓친 실행 전 소유 활동까지 공통 정산하며, 실행 후 실패와 살아 있는 다른 의무를 보존한다. |
| R2-04 | 원자료 변화에 대한 실제 손상은 인정하지만 제안 수리의 범위 위반과 새 상태 불일치 때문에 미반영했다. 잔여 설명은 3절과 같다. |
| R2-07 | Git 응답을 LF로만 나누고 실제 마지막 빈 원소만 버린다. Unicode 경로를 보존하면서 후행 비정상 bytes를 버리지 않고 기존 개수 검사를 유지한다. |
| R2-11 | 정리 범위의 사용자 출처 검사를 `control_contracts.require_cleanup_origin`으로 공유해 접수와 실제 정리에서 같은 규칙을 쓴다. |
| R2-12 | 잠금 시 Claude 전체 모델 ID를 요구하는 `worker_request.check_claude_model_lock`을 설정과 worker가 함께 쓴다. 설정은 운송 접두어만 제거한다. |
| R2-13 | `academic.resolve_evidence_reference`가 지식·형식 결과·해설·외부 작업·실행 기록 중 정확히 한 기록으로 풀리는 참조를 받는다. 여러 기록으로 풀리면 거부하며, 기록이 없을 때만 지급 artifact의 bytes를 찾는다. 역할 응답을 제출하기 전 검사는 지급된 입력의 레코드 색인을 사용한다. 중앙 편입은 실제 저장 레코드를 사용한다. 두 경로가 같은 함수로 학술 증거의 허용 가족과 유일 해석을 검사한다. |
| R2-M1(R2-02·09) | 요청 취소·철회·퇴역 뒤 풀리지 않는 활동 대기를 정산한다. 실패가 미해결로 남아 유지보수 정리에서 제외되는 것은 보존한다. 원안 영향 칸이 주장한 정리 제외의 전면 해소까지 구현했다고 보지 않는다. |

1라운드의 절차 자체 처리에는 Claude Agent 부재에 따른 같은 모델·노력의 CLI 운송, 원안 밖 관련 시험의 세션 보완, 전체 검사의 최종 통합 뒤 1회 배치가 있다. 1라운드 수리자 번호 7 한 명이 자기 산출을 교체하면서 `.new` 파일을 만들었다. 사용자는 공식 검산을 통과한 지정 최종 파일 `수리_7.md`를 사용하도록 이번 사례의 예외를 승인했고, 세션은 재파견하지 않았다. 이것을 일반 산출 계약의 완화로 삼지 않았다. 두 보류 처분은 사용자 최종 답을 그대로 따른 것이다. 공식 승계는 이미 확정된 사용자 결정을 새 선택 없이 수리에 적용하는 절차다. 이 승계로 처분을 바꾼 항목은 두 라운드 모두 없음이다.

2라운드 전에는 최신 보류 결정을 동결문과 별도 사용자 확정에 반영했다. 수치·영역·관점·모델·노력 배정은 그대로 유지했다. `--safe-mode`는 1라운드 커밋 기억과 훅의 자동 주입을 막기 위한 Claude CLI 운송 조정이다. 지정 계약과 현재 기준은 명시적으로 지급했고 실제 모델·Read·Bash 대표 확인을 마쳤다.

## 5. 마지막 라운드 결산과 검증

공식 결산은 원안 14행 중 적용 6, 기각 8, 나머지 상태 0이다. 병합 R2-M1의 기각이 구성 원안 두 행에 전파되어 기각 심사 단위 7건과 장부 행 8건이 구별된다. 직접 보완은 위 표와 같이 별도 7원안이다.

1라운드 관련 회귀는 205/205 통과했고, 구조 검사와 미러 검사도 통과했다. 직접 보완의 최초 7개 재현은 수정 전 실패와 수정 후 통과를 확인했다. 중간 전수 실행 두 개는 세션이 의도적으로 중단했으며 전수 통과 근거로 세지 않는다.

2라운드 관련 회귀는 `임시/vr-r2-related/report.json`에서 108/108 통과, fixture 오류 없음, `complete=true`, `successful=true`, `changed_during_run=[]`로 확인했다. 직접 재현의 초안 오류와 수정·재실행은 장부에 구별했고 결과를 합산해 별도 전수 통과 수로 만들지 않았다.

최종 통합 검사는 다음 명령으로 완료했다. 병렬 4,583건과 별도 격리 14건을 합친 실제 선택은 4,597건이다.

```powershell
python -u -B .claude/skills/do-math/scripts/run_tests.py structure unit contracts sim flows boundary.test_git_process_storage boundary.test_file_io_lock boundary.test_submission_installed_tool --jobs 3 --output C:/math/임시/vr-final2
```

`임시/vr-final2/report.json`은 4,597개 고유 ID 전건을 보고했다. 결과는 통과 4,587·실패 9·skip 1, fixture 오류 없음, `complete=true`, `successful=false`, `changed_during_run=[]`, 종료 코드 1이다. 실측 7,611초(약 127분)로 소프트 예산을 초과했으며 검증 범위를 유지했다. skip은 `unit.test_context_catalog.ContextStoreTests.test_outside_symlink_is_reported_when_supported`의 Windows 심볼릭 링크 생성 권한 부족(WinError 1314)이다.

초기 기준 `9e6a2e08`의 별도 worktree에서 실패 9건만 대조했다. `임시/vr-baseline-check/report.json`은 통과 8·실패 1이었다. 실패는 기존 시험 냄새 3건을 보고한 감사였다. Lean 탐색 시험은 기준 worktree에 portable Mathlib가 없는 환경 차이도 확인했으며, 제품 탐색 코드는 이번 작업에서 바꾸지 않았다.

전수에서 발견한 항목을 보완한 뒤 사용자 지시대로 원래 실패 9건만 재실행했다. `임시/vr-failed-final/report.json`은 9/9 통과, fixture 오류 없음, `complete=true`, `successful=true`, `changed_during_run=[]`, 종료 코드 0, 실측 23.3초다. 그 전에 8건이 통과하고 catalog 참조 시험 한 건에 구성 오류가 있었다. 그 구성을 바로잡은 뒤 같은 시험의 실제 실행기 경로에서 catalog 지급 누락을 재현해 보완했다. 재실행 결과를 전수 결과와 합산해 최종 판본의 새 전수 통과라고 쓰지 않는다.

전수 뒤 제품 코드 추가 변경은 `context_store.py`의 catalog 지급 결박이다. 역할에 허용된 키의 catalog 경로를 검사 전용 `input_catalog`에 결박하고, 실제 파일 생성도 같은 경로 함수를 쓴다. 역할 프롬프트에는 이 검사 전용 필드를 넣지 않는다. 마지막 catalog 시험은 실제 실행기의 문맥·스키마·포장·설치 도구 경로로 지급된 catalog는 통과하고, 파일만 있는 미지급 catalog는 거부하는 것을 확인했다. 미완성 재설치와 정적 스키마를 쓴 시험 초안은 오류로 구별해 기록했다.

그 밖의 보완은 파생 profile 결박의 구 단언, 가짜 사용자 ID 대신 실제 제어 요청, 복구 대기 이유 갱신과 반복의 무변경, 대기 생성 위치 선언, 조건부 스키마 조각과 완전 객체의 구별, 실제 Lean 탐색 정본의 호출 관측이다. 감사 규칙은 유지했다. 기존 냄새 3건도 고쳤다. 변이 시험 대역은 제품 namespace 대신 도구 자신의 프로세스 생성 함수 `_child_job`을 교체하도록 바꿨다. 다른 두 시험은 정확한 예외 객체를 확인하고, 실제 future의 완료 조건을 기다리도록 바꿨다. 사용자 재검사 제한에 따라 통과했던 시험이나 이 세 시험의 개별 기능 실행을 추가로 반복하지 않았으며, 실패한 감사가 수정된 원문을 다시 검사했다.

외부 모델·Lean 실호출이나 T3 전수 도달 측정을 수행한 것으로 확대하지 않는다. 모든 실행 보고는 Git에 넣지 않는 로컬 증거다.

## 6. 앵커 대조

초기 제품 코드 129파일의 bytes를 최종 코드와 대조했다. 변경 30파일, 추가 326행·삭제 97행이다. 이 수치는 제품 코드만이며 관련 시험, 이음새 정본 문서, 생성 미러와 런 기록은 별도다. 원문 앵커는 종료 커밋 뒤 정리되므로 아래 파일 목록과 Git diff를 보존 근거로 삼는다.

## 7. 용어 주의 승격 후보

활동은 실행이 배정되기 전에도 존재한다. 선행 실행을 가리키는 `continuation_of`가 있을 때만 활동을 정산하면 실행 전 활동이 누락된다. 활동의 정산은 배정 이력 유무를 모두 다뤄야 한다는 주의 후보가 있다. R2-03의 기각과 재현이 근거다. 공식 용어집을 이번 런에서 바꾸지는 않았다.

R1-06·08·16은 현행 계약 안에서 구현 수리로 닫을 수 있는 문제를 상신 제안으로 분류했다. 구현 방법의 차이와 사용자가 정해야 하는 결과의 차이를 구별하는 주의 후보로 남긴다.

## 9. 운영 기록과 graphify

기는 독립 컨텍스트로 파견한 작업자 한 명을 세는 단위다. 영역 담당 4명은 제품 코드 129파일을 중복 없이 나누고 관점 담당 4명은 지정한 필수 파일과 연결 원문을 추적했다. 각 관점이 129파일을 전부 통독했다고 주장하지 않는다. 시험·fixture·시험 기반은 독립 검토와 필수 통독에서 제외하고 실제 코드 문제와 관련된 시험만 확인했다. 두 라운드 모두 기별 필수 통독 기록은 배정과 일치했다. 제품 코드 출력이 잘린 경우에는 후속 Read·분할 읽기로 회수했다.

2라운드 최초 수리 파견은 8기 모두 Claude 5시간 한도 429로 산출 없이 종료했다. 이를 결함 0이나 완료 라운드로 세지 않았다. 실패 기록 24개는 런 직속 `_실패보존_R2_한도1/`에 로컬 보존했다. 사용자의 재개 지시 뒤 20:50 KST 초기화 시각이 지난 20:52에 같은 파견문·모델·노력으로 다시 실행했다. 정상 수리와 병합의 native 결과는 모두 `claude-opus-5-5`, 심사 3기의 native 설정은 모두 `gpt-6-astra / medium`이었다.

1라운드 graphify update는 1,218파일·17,526노드·65,948관계로 완료했다. 의미 추출은 26문서 캐시 재사용과 변경 문서 1건 갱신이었고 미완료 문서는 없었다. 2라운드 최종 갱신은 1,218파일·17,546노드·66,044관계로 완료했다. 현재 원문과 일치하고 semantic_pending은 빈 목록이다. 첫 의미 추출은 인용 행 번호 한 곳이 어긋나 기존 그래프를 보존하며 반려됐고, 같은 공식 명령의 재추출이 검사를 통과했다. 최종 catalog 수리와 시험 보완 뒤 의미 26문서 캐시·변경 문서 1건(57노드), 코드 구조 951파일을 추출했다. tree.html과 graph.html(634커뮤니티·5,120커뮤니티 간 관계)도 생성했다.

graphify 산출은 `.claude/graphify/do-math/graphify-out/`에 있는 Git 제외 로컬 생성물이다. 파일·노드·관계 수는 연결 지도의 규모이며 검증된 동작이나 결함 수가 아니다. 원문을 확인해 판단했다. 종료 커밋 뒤에는 이 런의 앵커와 라운드 디렉터리만 정리하고 동결·장부·이 보고·사용자 확정·기각보관과 나머지 파일은 보존한다.

## 발견

발견의 전달은 이 런 밖 근본 원인을 별도 후속 검토로 다뤄 달라고 운전 세션에 요청하는 처분이다. 이 처분으로 확정된 항목은 없음이다. R1-09의 시계 정본 포인터 문제는 무처분 확정 뒤 세션 직접 검토에서 보완했으며 새 전개 작업으로 넘기지 않았다.
