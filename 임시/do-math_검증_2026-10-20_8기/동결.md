## 목적 진술

사용자가 지정한 do-math 실제 제품 코드에서 현행 계약과 구현의 실제 결함을 찾아 수리한다. 시험 파일·fixture·corpus·시험 실행 기반은 독립 검토 대상과 필수 통독 목록에서 제외한다. 실제 제품 코드에서 문제를 발견한 경우에만 그 문제와 직접 관련된 시험을 열어 재현 근거와 기존 검사 범위를 확인한다. 문서·계약은 코드 판정의 기준 원문이며 독립적인 문서 정비를 목적으로 검토하지 않는다. 연구 책임자의 목표·정책·허용 범위를 유지하고, 연구 계획·수행·검토·운영의 현재 계약을 구현·스키마·시험·예제·문서가 함께 따르게 한다. 단순한 표현 선호와 추측을 결함으로 확정하지 않는다.

사용자 지시: mixed 전면, 수리자 Opus 5.5 8기(영역 4기·관점 4기), 심사자 모두 gpt-6-astra, 총 2라운드. 각 관점의 필수 통독 범위는 아래처럼 나누고 연결된 정의·생산·소비를 따라 관점의 목적을 보존한다. 관점 전원이 산출물 전건을 통독했다고 보고하지 않는다. 각 라운드 뒤 세션이 정족 미달·무처분을 포함한 미통과 안건 전건을 직접 심층 검토하고 반영 여부를 판단한다. 이 직접 수리는 사용자 지시에 따른 라운드 사이 통상 편집이며 원 심사 판정과 별도로 기록한다. 각 라운드 끝에 graphify update를 수행한다.

## 불변식 목록

- 결론: 없음
- 필수 논거: 없음
- 필수 전거: 없음
- 분량 상한: 없음
- 개발 원칙: 프리알파 현행 계약 하나만 지원한다. 구판 호환용 분기·별칭·자동 변환을 남기지 않고 현재 구조·참조·권한·증거·현재성 검사를 유지한다. 같은 규칙은 이음새 정본 하나를 생산자와 수신자가 함께 소비한다.
- 검토 기준은 위 사용자 지시와 기준 원문의 현행 목적·계약이다. 산출물 문서의 존재만으로 사용자 확정 문면이라고 단정하지 않는다.
- 시험은 scripts/tests/시험-지침.md를 따른다. 코드 결함에 따른 수리 후 관련 성질의 공식 시험과 구조 검사 `python .claude/skills/do-math/scripts/probe_cli.py --skill-only`를 실행한다. 통합 뒤 공식 실행기에서 T2와 flows를 확인하며, 외부 경계 변경에는 해당 boundary 시험을 확인한다. 성공·skip·미실행·부분 측정을 구별한다.
- 관련 시험의 수리가 필요한 경우 세션은 원 코드 결함에 결박하여 라운드 사이 통상 편집으로 반영하고 별도 기록한다. 수리자는 산출물 목록 밖 시험을 조각으로 저작하지 않는다. 생성 사본 .agents/skills/do-math는 수기 편집하지 않는다. 라운드별 정본 수리 뒤 공식 미러 생성 및 --check를 실행한다. 원녹화 corpus 바이트를 보존한다.
- 발견의 호출자 후속: 전달된 발견은 세션이 실제 근거와 손상을 직접 검토하여 후속 작업 범위와 필요성을 판단한다. 별도 검증런·작업자·산출 검증·싱크가 필요하면 전체 비용과 잔여를 보고하며 자동 승인·자동 전개로 간주하지 않는다.
