# do-math 전면 검증 1회 종료 보고

Opus 5.5 수리자 8기와 GPT-6-Astra 심사자 3기로 1회를 수행했다. 111개 제기를 93개 심사 대상으로 정리했고, 공식 조각 적용으로 본표 102행을 처리했다. 공식 적용에 들지 않은 나머지 9행은 같은 원인을 묶어 6개 문제로 직접 수리했다. 이는 사용자가 요청한 기각·무처분 재검토에 따른 후속 변경이다.

최신 재검사 결과를 합친 선택 검증은 1,526건 통과, 1건 건너뜀이다. 장시간 통합 143건은 미실행이다. 세부 목록과 초기 실패·교정 후 결과는 [시험요약.json](시험요약.json)에 있다.

## 1. 종료집계와 종료 항

공식 `종료집계`는 판정 순서 3항, `라운드 수 1 ≥ 라운드_상한 1`로 종료했다. 적용 0의 연속 횟수는 0이다. 하한과 상한은 모두 1이며 추가 라운드는 실행하지 않았다.

## 3. 상신·무처분 잔여와 기각 보관

기각·무처분 34건의 원 항목, 심사 판정과 근거는 [기각 보관](기각보관/do-math-opus55-라운드1.md)에 보존했다. 직접 처리로 원 판정을 덮어쓰지 않았다.

공식 본표에는 적용 102행, 기각 8행, 무처분 1행이 남는다. 아래 표는 그 기각·무처분 9행에 대응하는 직접 수리 결과다. 이 9행의 문제를 미처리 잔여로 두지는 않았다.

## 4. 자체 처리와 승계

승계는 없음이다. 사용자에게 이번 작업을 직접 재검토하도록 위임받은 사실과 스킬의 승계 절차는 구별했다.

- 무처분의 수리 전환: R1-05·21·23·25·28·37·38·61·62·69·71·82·83·93·94·106·110, R1-M1·M2·M4·M5·M9·M12·M13·M15. 죽은 필드·호출·분기, 현행 계약과 다른 이름, 중복 설명을 실제 정의·생산자·소비자와 대조했다. 항목별 판단은 [장부](장부.md)에 있다.
- 기각 R1-42의 추가 적용: 문서가 전제하는 명령 수리 R1-40을 같은 공식 적용에서 반영하여 기각 사유의 전제 결손을 없앴다.
- 신호 1 자체 처리: R1-96에 현재 완료 의미를 유지하는 명시적 중단·보존·정산을 택했다. 보류 요청을 이력과 사용자 소유 후속으로 넘기며, 완료 상태에서 새 배정 경로를 만들지 않았다.
- 신호 4 자체 처리: 사용자 요청에 따라 관점별 필수 통독 범위를 분담하고 경계 밖 영향 추적을 유지했다. Claude Agent 도구가 없는 환경에서는 같은 모델·노력·역할 정의의 Claude CLI를 사용했다. 수리 1·4·7의 독해 누락은 같은 컨텍스트의 1회 보완으로 회수했고, 수리 3·4의 영향 조회도 보완했다. 기수·정족·라운드 수는 바꾸지 않았다.
- 신호 6 자체 처리: 적용 후 시험 실패를 원문과 원본 앵커에 대조했다. 시험용 실행기 조합, 행동 ID, 필수 입력, 프로필, 봉인 증거, 제거된 무동작 메서드 호출을 교정했다. 원본 앵커에서도 재현된 영향 묶음 시험 오류 2건은 중앙 검사 증거를 교정한 뒤 모두 재검사를 통과했다. 이 두 건도 아래 초기 실패·오류의 해소 결과에 포함한다. 제품의 권한·봉인·현재성 검사는 유지했다.

이 판단들의 오판 비용은 코드 회귀나 검토 누락이다. 공식 축자 대조, 보완 독해, 재현·회귀 검사로 확인했고 Git 변경과 사본으로 되돌릴 수 있다. 사용자만 가진 새 선호를 만들어야 하는 선택은 채택하지 않았다.

## 5. 마지막 라운드 결산

공식 결산은 적용 102, 기각 8, 무처분 1, 그 밖의 상태 0으로 합계 111행이다. 수리·병합 결번과 심사 덮개 미달은 없다. 심사자 3기 모두 93개 항목을 판정했다.

검증 결과는 초기 실행과 교정 후 관련 재검사의 최신 결과를 항목별로 합친 것이다.

건너뛴 것은 외부 심볼릭 링크 검사 1건이다. Windows의 링크 생성 권한 부족(WinError 1314)이 원인이다. 통합 143건은 과거 장시간 시나리오로 선택 회귀에서 제외했다. 과거 시간은 이번 판본의 성능 측정값으로 사용하지 않았다. 실제 연구 인스턴스의 장기 연구 성과나 외부 공급자 운전까지 이 시험 결과로 주장하지 않는다.

초기 통합 결과의 14개 실패·오류와 11개 미실행은 교정·재검사로 해소했다. 교정한 봉인 fixture의 추가 참조 누락도 중앙 검사기가 발견해, 고정 입력에 실제 지식 카탈로그를 제공한 뒤 해당 7건을 다시 통과시켰다. 최초 실패 보고는 성공 결과로 덮어쓰지 않았다.

## 6. 앵커 대조 변경 자리

기준 HEAD는 `85f3c151586abbcbea1bb7cab173046a7ab89251`이다. 정본 228개 파일의 앵커와 대조했으며 새 완료 정산 시험 파일 1개를 추가했다.

- `budget.py`, `execution_profiles.py`, `session_slots.py`, 실행기·스케줄러: 생산자가 없는 사용량 예산 경로, 문자열 프로필 별칭, 죽은 상태·슬롯 관리자·무동작 정리를 제거했다.
- `contracts.py`, `submission.py`, `integration.py`, `context_store.py`, 저장 스키마: 실제 입력·출력 필드와 필수 입력, 검사 대상 식별, 독립 확인, 지식 정보 상태를 맞췄다. 죽은 인자·별칭·중복 등록·불필요한 깊은 복사를 줄였다.
- `knowledge.py`, `repository.py`, `git_store.py`: 영향 계산의 반복 참조 구축, 같은 스냅숏의 중복 적재, 트리 재조회 비용을 줄였다. CAS·불변 바이트·물리 경계 검사는 유지했다.
- `academic_engine.py`, `governance_engine.py`, `engine.py`, `retention.py`: 목표 완료의 미완료 의무 정산과 경로별 정리 실패 회복을 추가했다.
- `cli.py`, 공급자·작업자·예약 운영 코드와 역할 문서: 없는 인자·권한 프로필·죽은 함수, 재조정 명령, 오류 분류·기한·운영 발동 근거를 정리했다.
- 시험·예시·문서는 같은 현행 계약에 맞췄고 `.agents/skills/do-math/`는 정본에서 재생성했다. 외부 추적 정본 `docs/do-math/implementation-v5/traceability.json`의 현행 좌표를 고쳤다. 과거 실행과 관찰 기록은 보존했다.

## 9. 운영 기록 요지

기준선과 Git 색인은 깨끗했다. 수리자는 4개 영역의 합집합 228파일·74,652행을 담당했고, 4개 관점의 필수 통독 범위를 따로 정했다. 모든 관점이 전건을 통독한 것으로 보고하지 않았다. 독해 누락 보완 뒤 수리 1에서 4건, 수리 7에서 3건이 추가됐다.

파견은 수리 `claude-opus-5-5 high`, 병합 `claude-opus-5-5 low`, 심사 `gpt-6-astra medium`이었다. 심사 고정 지급은 69,174바이트였고, 두 배치의 고정 지급 포함 크기는 254,088·333,264바이트로 상한 이하였다.

기준선 전체 시험은 장시간 통합 도중 중단했으며 `complete=false`를 유지했다. 단위 301건만 기준선 완료 결과다. 최종 검증과 혼동하지 않는다. 상세 시험 로그와 graphify 산출은 로컬 생성물이며, 지속 보존할 판단·계수·미실행 목록을 이 보고와 시험요약에 담았다.
