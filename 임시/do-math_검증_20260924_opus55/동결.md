## 목적 진술

do-math가 수학적 질문을 지속적으로 탐구하고, 확보한 근거와 지식을 다음 연구로 연결하는 목적을 유지하면서 스킬 전반의 결함과 비효율을 수리한다. 사용자의 이번 요청을 기준으로 다음을 검토한다.

1. 더 이상 활용되지 않는 호환성 요소, 죽은 패러미터, 무시되는 설정과 유사한 잔재를 제거한다. 현재 입력의 유효성·권한·근거·현재성 검사는 유지한다.
2. 생산자와 소비자 사이의 계약 미스매치를 수리한다. 구현·호출부·스키마·시험·예시·문서가 같은 현재 계약을 사용하게 한다.
3. 요소 전체나 일부가 존재 목적에 위배되는 경우 수리한다. 연구 수행·검토·계획·보존·운영의 의미와 책임을 연결해 판단한다.
4. 같은 목적과 기능을 더 합리적인 로직으로 달성할 수 있는 과도한 비효율을 개선한다.
5. 절차와 스크립트 안팎에서 발견한 다른 문제도 실제 근거에 따라 해결한다.

수리자는 담당 범위에서 소수 사례를 찾은 뒤 멈추지 않는다. 담당 범위를 통독하고 보이는 독립된 문제를 가능한 한 많이 찾아 각각의 항목과 완성된 수리를 작성한다. 건수 목표나 상한은 없다. 추측이나 스타일 취향을 결함으로 만들지 않는다.

수리자는 .claude/skills/graphify/SKILL.md를 읽어 적극 적용한다. 탐색 시작 시 status와 query/explain으로 구조와 경계를 찾고, 각 수리 후보에 affected 및 필요한 path/query를 사용해 영향 영역을 추적한다. 관계가 없으면 rg와 원문으로 보완한다. 정의·호출자·소비자·상태·스키마·계약·시험을 실제 원문으로 확인하며, 영향과 수행 기록에 확인한 경로와 남은 불확실성을 기록한다. 그래프는 근거를 찾는 지도이며 현재 원문과 사본이 판단의 근거다. 수리자는 그래프를 갱신하지 않는다. 그래프 갱신은 라운드 종료 뒤 세션이 수행한다.

관련 중요 스킬을 실제 작업에 적용한다. 수리·문서·파견에는 write-for-reader, 코드의 재현과 검증에는 test-driven-development의 해당 원칙, 단순화에는 simplify의 해당 원칙을 사용한다. 역할의 산출 계약이 파일 쓰기와 검사 권한을 우선 정하므로 수리자는 변경본이나 시험 파일을 별도로 실행·저장하지 않고 조각에 완성된 수리를 담는다.

사용자는 기각·무처분 항목 전건을 세션이 직접 다시 살펴 수리·개선·적용·무처분 등을 재량껏 처리하도록 지시했다. 원 심사 판정과 이 직접 재검토 처분은 따로 보존한다. 마지막에 graphify update와 저장소 커밋 절차를 수행한다.

## 영역 배분

영역 담당 1~4는 아래 파일의 합집합 전건을 나누어 통독한다. 관점 담당 5~8은 사용자의 영역 분할 요청에 따라 각 관점의 아래 필수 파일을 통독하고 그 관점과 관련된 연결 경로를 영역 밖까지 추적한다. 관점 담당의 책임은 단순한 영역 재검토가 아니라 서로 다른 구성 요소 사이의 관계를 해당 관점으로 검증하는 것이다. 네 관점 각각이 산출물 전건을 통독했다고 보고하지 않는다. 모든 기는 사본 전건을 읽고 산출물 전건에 조각을 제안할 수 있다.

통독 시 긴 출력이 잘리면 다음 범위로 나누어 실제 본문을 다시 읽는다. 행 수 집계·검색·요약은 통독을 대신하지 않는다. 수행 기록에 필수 파일별 읽은 행 범위와 전체 행 수를 남긴다.
