사용자는 온톨로지와 시맨틱 레이어를 중심으로 지식·메타데이터를 축적하고, 효과적인 탐색에서 추가 연구를 만들어 목표에 접근하는 방식을 원했다. 먼저 현행 통합 설계의 용어로 가능성을 평가하게 했고, 기존 구조로 가능한 순환과 실제 효과의 미검증을 구별한 평가를 승인했다. 이어 의미 연결의 보존, 후속 선택에 대한 재사용 근거, 실제 효과 검증을 추가하되 문서 전체의 구조·흐름을 이해해 필요한 변화를 모두 적용하라고 지시했다. 몇 절의 문구 추가만으로 범위를 닫는 요청이 아니었다.

착수 시 통합 설계에는 미커밋 수정 7곳이 있었다. 반복 실패 규칙의 중복 제거, 정규형의 결정론 표현, 준비 회차의 무산출 의미 구체화와 기간 정밀도 표현의 수정이었다. 이를 작업 기준선으로 보존하고 새 변경과 함께 커밋했다. 다른 연구·구현 작업의 워킹트리는 이번 변경에 포함하지 않았다.

통합 설계 0~20절 전부를 읽고 생산자·입력·소비자·실패·재개·검증의 연결을 검토했다. 1.5절에 전체 연구 방식을 두고, 7.3.1절에 가족별 지식·메타데이터 공동 저작, 8.4절에 종류·관계 방향·원자료·현재 효력의 회수와 실제 적용 판단을 모았다. 준비·작업 계약·선택·수행·수학 검토·공용 편입에 그 책임을 연결했으며 수입·부수 산출·미완료·취소·재개·옛 기록 변환·사람 보고도 함께 다뤘다. 역할 입력, 명령과 직렬화 인계, 워크스루·품질 대응까지 연결했다. 독립 검토·공통 상태·예산·정지·신뢰의 기존 계약은 해당 경계에서 재사용한다.

온톨로지·시맨틱 레이어는 기존 종류 정의·연구 맥락·형식 정의와 조회·해설·판정이 수행하는 역할로 정의했다. 새 지식 정본·활동 종류·상태·범용 메타데이터 필드·별도 전건 지식 목차는 추가하지 않았다. 현행 목차와 상세 탐색 재량, 원자료 판독과 수학 사용의 검증을 함께 유지한다. 확인된 연결은 종류에 맞는 근거·판정으로 보존하고, 아직 확인하지 못한 연결은 F·근거의 추측과 미결 질문으로 탐색할 수 있다. 기존 관계가 없다는 이유로 새 통찰이나 정확한 부분 K를 배제하지 않는다.

자체 검토에서는 같은 질문을 다루는 F·형식 결과·해설의 정체성을 합치지 않도록 저작 문구를 고쳤고, 기존 기록의 참조를 일괄 exact로 강제하지 않고 7.2절의 용도별 참조형을 유지했다. 일반 연구 연결에 수학 함의의 보증·증명 의무를 잘못 확대하지 않도록 종류별 요구를 명시했다. V250의 사용 정지는 정지된 판정을 실제 전제로 하는 사용으로 한정했다. V254는 실제 효능 실험을 상태 벡터의 선행조건으로 요구하지 않고, 합성 검사·관계 수만으로 성능을 주장할 수 없다는 경계 검사로 정리했다. 실효성의 평가는 17.5절과 D09에 남겼다. 문서의 혼입 문자와 중복된 인계 설명도 교정했다.

보편 정의의 정본인 CONTEXT.md에는 두 개념과 지식 저작·준비·계획·수행의 의미를 동기화했다. docs/wayfinder/pvsnp-재설계/컨텍스트.md에는 그 보편 설계의 요지와 효능 비교만 연결했다. P vs NP의 목표·문헌 정책·모델 배정은 바꾸지 않았다. 이전부터 남아 있던 D08 전체를 완료했다고 주장하지 않으며, 이번 저작·조회·후속 규칙과 V243~V254·Q23~Q25를 후행 동기화 범위에 추가했다.

검증 범위는 문서의 구조·참조·보존과 규칙의 자체 대조다. 최종 본문은 2,564행이며 SHA-256은 082630ce738b8f8dd7e34adbc22aa87d73a17654640d61e3ba71d2ed8809725d다. 임시 검사기로 65개 검사를 통과했다. 기존 절의 순서와 21개 본절, 원래 V01~V242·Q01~Q22 행 전건, 생성 스키마 가족 표, 주요 상태·권한·예산·수학 검토 등 35개 계약 구간의 원문을 대조했다. 새 V01~V254·Q01~Q25의 누락·중복과 참조, 세 문서의 링크·표·코드 펜스, 기존 미커밋 7개 수정의 보존도 확인했다. 새 시나리오 12개와 품질 항목 3개는 검증 명세이며 실제 런타임·모델·Lean 실행 결과가 아니다. git diff --check도 통과했다.

후속 구현은 D08에서 실제 스키마·생성기·관계 검사·role-contracts·입력·검증 자료를 같은 본문 해시에 맞춰 대조하고 재검증해야 한다. D09는 회수 실패와 오적용, 실제 재사용할 결과의 부재를 구별하며 후속 선택의 변화와 비용을 실제로 평가한다. 이번 문서 검사 통과를 그 성능 증거로 사용하지 않는다.

dream에서 묶을 후보: 지식 재사용 요구를 더할 때 새 저장소·단계를 먼저 만드는 대신 기존 생산자와 각 내용의 소유 위치, 후속 소비자·현재성·부분 결과 경로를 대조하는 관례. 전건 검토는 모든 절에 문장을 추가하는 일이 아니며, 공통 정의의 각 단계별 실제 소비와 그대로 유지할 경계까지 확인하는 일이다. 실제 사용자 요청은 평가의 반려가 아니라 승인한 방향의 적용 범위를 문서 전체로 명시한 것이므로, 이를 이전 평가가 잘못됐다는 교정으로 기록하지 않는다.
