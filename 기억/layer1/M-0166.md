title: 학술자료 MCP의 ScienceDirect 인용문·AIP PDF·공개 웹 후보 API를 연결함
convention_version: 24
---

남은 학술자료 MCP 구현을 계속했다. ScienceDirect의 기관 원 인용문과 초록, AIP PDF 파일 호스트, 일반 웹 후보용 Mwmbl 공개 API를 연결했다. IOP 서지·PDF의 양성 관측과 추가 인용문 코드, 이후 접근 제한도 보존한다. 전체 작업은 부분 완료이며 출판사 검색·추가 자료 형식의 남은 항목을 완료로 세지 않는다.

ScienceDirect의 본문·abs 경로가 접근 오류여도 KUDOS 기관 context의 /sdfe/arp/cite는 유효했다. Natural Proofs의 PII S002200009791494X와 DOI 10.1006/jcss.1997.1494를 원 RIS의 UR·DO에서 대조했다. 제목은 TI가 아니라 T1이고 초록 AB는 994자였다. API MIME은 RIS의 application/x-research-info-systems, BibTeX의 text/x-bibtex, plain의 text/plain이다. Crossref의 application/x-bibtex·text/x-bibliography를 재사용한 요청은 provider_error였으므로 형식 이름을 자료원 사이에 자동 이식하지 않는다. 세 원 형식과 서지·초록이 실제 MCP에서 통과했다.

ScienceDirect pdfft는 준비 HTML이었다. Firefox와 Chrome에서 정상 브라우저 준비 절차를 실행했으나 30초 안에 PDF 응답·download 이벤트가 없었다. 기본 검색은 URL만 search?qs로 바뀌고 45초 후에도 홈페이지 본문이었다. 결과 목록 0건과 검색 실패를 구별하며 검색·PDF·첨부를 성공으로 세지 않는다. 인용문 회수 성공이 문헌 HTML 접근 실패에 묻히지 않도록 component를 분리했다.

AIP의 처음 선택한 AAPT 문헌은 PDF URL에서 HTML을 반환했다. 다른 OA 문헌 10.1063/5.0281142를 시험하자 watermark02.silverchair.com이 파일 허용 목록에 빠진 오류가 드러났다. 파일 다운로드에 한해 이 호스트를 추가했고 16쪽 PDF가 정상 회수됐다. 실제 MCP에서 기존 검색·초록·인용문·페이지 경계와 새 OA PDF 첫 쪽의 DOI 대조를 통과했다. 표본을 바꾸면 원인을 구별할 수 있으며 첫 문헌 실패를 자료원 전체의 제약으로 단정하지 않는다.

IOP의 명시적 /meta 문헌 주소에서는 기존 어댑터가 서지·16쪽 PDF를 받았다. 원 초록 영역은 wd-jnl-art-abstract이고 내보내기는 wd-btn-cit-abs-bib·ris 제어였다. 원 제어의 type·doi·exportFormat·exportType을 읽는 코드를 연결했으나, 이후 두 MCP 검증과 정상 KUDOS 깊은 링크·native export 확인은 validate.perfdrive.com으로 이동해 완료하지 못했다. 이 호스트를 문헌 호스트에 추가하지 않았다. gateway 오류에 URL 전체 대신 observed_host를 넣고 알려진 접근 확인 호스트를 restricted로 구별한다. 추가 인용문 응답을 검증했다고 주장하지 않는다.

일반 웹 검색을 위해 여러 공개 경로를 확인했다. Bing은 query를 유지하면서도 무관한 결과를 반환했고 Google·DuckDuckGo·Brave·여러 SearXNG 공개 인스턴스는 결과 부재·접근 확인·429 등으로 정상 흐름을 검증하지 못했다. Mwmbl의 /search/?s= API는 별도 키·계정·이메일 없이 natural proofs의 관련 결과와 무작위 문자열의 빈 결과를 반환했다. 이 경로를 general-web으로 고정했으며 실행 중 다른 엔진으로 전환하지 않는다. 다른 무작위 문자열의 한 번의 20초 HTTP timeout과 정상 빈 배열을 구별한다.

Mwmbl 결과의 title·extract는 value와 is_bold 조각 배열이다. 원 조각을 native에 보존하면서 읽을 제목·snippet 문자열을 만든다. 원 결과 25건 중 요청한 2건의 CSV·추출과 0건 응답이 실제 MCP에서 통과했다. returned_set_size를 웹 전체의 일치 건수로 쓰지 않고 total=null을 반환한다. 문헌 원문은 후보의 실제 자료원을 호출 AI가 선택해 회수한다.

MCP의 구조화 반환 자체에도 공통 정제를 적용했다. 합성 서명 URL과 CSRF 필드가 중첩 component에서 그대로 반환되는 실패를 재현한 뒤 기존 Sanitizer를 반환 경계에 연결했다. 공개 PGP·SSH 서명과 cursor 보존 규칙을 새로 발명하지 않았다. 공통 검사 101개가 통과했다. 실제 성공·실패 보고의 정확한 경로는 services/scholarly-mcp/VALIDATION.md가 소유한다.

남은 작업은 SUPPORT.md와 코드의 미구현 분기를 대조해 이어간다. AMS의 새·옛 문헌 주소와 SIAM citation GET·POST는 접근 제한이었다. JSTOR의 기관 PDF 주소는 HTML이었다. 개별 구독의 구체 서비스는 정해지지 않았으며 별도 웹 계정·연락 이메일이 필요한 경로를 다시 요청하지 않는다. 원 연구 산출물과 사용자의 .codex/config.toml 변경은 보존했고 전체 완료 전이므로 푸시하지 않는다.
