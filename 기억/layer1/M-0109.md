## 맥락

M-0108로 종결한 런의 종료 보고가 올린 상신 5사안(A~E)과 발견 2사안(F·G)에 사용자가 회신했다. A(`CONTEXT.md`의 기계 상태값 리터럴)는 「그냥 둬도 괜찮다」로 유지 결정이다. 근거는 `CONTEXT.md`가 `do-math` 스킬 구현 뒤 그 `GLOSSARY.md`로 넘어가 거기서 섞일 지식이라는 것이다. B~E는 「더 자세히, 읽기 쉽게 설명」을 요청해 설명을 제공했고 결정은 열려 있다. F·G는 「알아서 직접 적용」 지시라 GitHub 이슈 본문을 고쳤다.

F는 이슈 #6 본문의 범위 선언을 컨텍스트 정본 1절에 맞췄다. Destination의 「실제 문헌 수집 … 범위 밖」을 「실제 P vs NP 문헌의 후속 재판독 … 범위 밖. 기준선 문헌 조사와 `do-math` 구현 검증은 … 범위 안」으로, Out of scope의 「문헌 수집」을 「승인·동결한 문헌 기준선 이후의 문헌 재판독」으로 바꾸고 기준선 구축이 범위 안임을 덧붙였다. G는 이슈 #18 본문의 범위 20을 「대표 수학 연구에 적용한 전체 워크스루와 복원을 포함한 초기화 워크스루」로, Question의 P vs NP 정적 입력 문단을 프로젝트 중립 문구(입력 구성은 프로젝트 컨텍스트 정본이 소유)으로 바꿨다. 통합-설계 28절 `R18-20` 행은 그대로 정확해졌다. 이슈 #18 불변 입력의 「P vs NP 프로젝트는 … ZFC …」 항목은 컨텍스트 정본 4절 소유 사실의 재기재라 손대지 않았다.

종료 보고에 11절 「사용자 회신과 적용」을 더해 이 처리를 적었다. 이슈 편집 전후 본문은 `임시/이슈갱신_2026-09-02/`에 남겼다.

## 터득한 것

- 이슈 본문 편집은 `gh issue view --json body -q .body`로 받은 원문에 python으로 축자 치환한 뒤 `gh issue edit --body-file`로 올리고 다시 받아 대조하는 것으로 충분했다. Windows에서 gh 출력이 CR·LF 혼합이라 `diff --strip-trailing-cr -B`로 대조해야 한다.
- 사용자의 A 유지 결정은 「`CONTEXT.md`의 구현 세부 반입 금지」(동결문 불변식 1)가 영구 규범이 아니라 스킬 구현 전까지의 과도기 경계라는 뜻을 담는다. 다음 정합성 검토에서 같은 자리를 다시 올리지 않도록 이 결정을 기준 원문에 실어야 한다.
- Bash 도구의 `cd`가 호출 사이에 지속되어 다음 호출의 상대 경로가 깨졌다. CLAUDE.md의 「cd가 필요한 명령은 같은 호출 안에서 끝낸다」 규칙의 실측이다.
