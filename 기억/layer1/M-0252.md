Oxford의 원본 새 SDK 검증에서 검색 표시 범위 1-1 of1과 실제 문헌 행 0이 다른 377,593바이트 응답을 받아 search_parse_failed/cause range_mismatch가 발생했다. 처음에는 후보의 잘못된 www.oxfordacademic.com host 제거와 현재 title-list 안내만 통합하려 했지만, 이 실제 실패를 별개로 조사하고 수리했다. 원래의 SDK·HTML·오류 artifact는 보존했다.

같은 요청을 실제 HTTP 실행 도구와 원 브라우저에서 재현하자 HTTP 응답은 646,365바이트·정상 1행이었고 원 화면도 1건이었다. 실패가 매번 반복된다고 단정하지 않는다. 주 세션은 HTTP 입력 전·결과 후·안정 화면과 원 페이지 탐색 전·초기 렌더·안정 화면을 직접 읽었다. 초기 원 페이지에는 헤더만 보였고 안정 상태에는 요청 제목과 문헌 행이 보였다. 처음 받은 불완전 HTML도 같은 parser에 로컬 재생해 range_mismatch를 재현하고 전후·안정 이미지 세 개를 직접 읽었다. 준비된 697,462바이트 HTML은 같은 parser에서 1건으로 통과했다. 저장 응답 재생을 새 원격 요청으로 부르지 않는다.

silverchair.rendered_search_page는 원 브라우저 탐색 뒤 표시 범위와 실제 .sr-list 행 및 제목 링크가 맞을 때 HTML을 읽는다. AIP의 기존 렌더 방식도 같은 helper로 모았다. Oxford의 빈 결과 재확인 역시 초기 HTTP body를 직접 파싱하지 않고 원 렌더를 다시 확인한다. query/page 정체성, 실제 범위·total 검증과 parser의 불완전 입력 거부는 유지했다. 준비되기 전의 데이터를 정상 0건으로 바꾸는 수리가 아니다.

수리 후 새 원본 SDK는 검색 1건, 원 BibTeX 1개 available, 추출 DOI10.23943/princeton/9780691175782.003.0005를 확인했다. Publisher20·supplements12 검사와 Figshare 변경을 포함한 전체 562개 검사가 55.257초에 통과했다. 주요 원 근거는 root-user-criteria-20260913T0715Z/oxford 아래 criteria-live-sdk.json(최초 실패), render-20260913T102350Z(재현), parser-replay.json과 대응 이미지, rendered-sdk-20260913T102843Z.json(수리 후 성공)이다. 정제 요약은 data/access-research/user-criteria-oxford/root-review.json이다.

잘못된 대체 host의 N23 입력·직후·안정 이미지를 직접 읽었다. www.oxfordacademic.com은 DNS_PROBE_FINISHED_NXDOMAIN이고 같은 공식 academic.oup.com 경로는 정상이라 프로필을 현행 공식 host로 정리했다. 다른 문헌 URL로 몰래 바꾸지 않는다.

Export title list는 문헌별 CSV/인용문과 다른 책·저널 집계 기능이다. 현재 proxy의 정상 제어를 누른 전후·안정 이미지에서 사이트 키 도메인 오류와 CAPTCHA 완료 요구를 읽었고 정상 checkbox는 없었다. 같은 검색의 직접 host에는 제어가 없었다. 이 현재 접근 상태를 일반 문헌 검색·citation 전체 제한으로 확대하지 않는다. KUDOS 제공리스트 252저널 XLSX도 검색별 집계 CSV의 대체 성공이 아니다. 빈 CAPTCHA 대조의 선언 길이 140·관찰 body0은 회수된 유효 CSV가 없다는 기록으로만 사용하며, 정상 CAPTCHA 요청의 서버 응답을 입증한다고 하지 않는다.

Taylor B15의 정확 DOI·Citation & abstract 양식·동일 파일·초록 필드 부재와 SWH의 준비 성공 toast·new 작업·동일 SWHID raw404는 원본 변경 없이 지원·감사 문서에 연결했다. 두 source에 대한 root 직접 판독과 파일 검산은 M-0250 및 user-criteria-taylor/user-criteria-swh의 정제 근거에 보존돼 있다. 일반 description을 초록으로 만들거나 다른 디렉터리의 tar 성공을 pending 작업의 성공으로 세지 않는다.
