# do-math 전수 독해 확인과 2라운드 종료 범위

## 맥락

사용자는 do-math 스킬 전체의 불필요한 호환 요소·죽은 인자, 생산자와 소비자의 불일치, 목적 위반과 비효율을 verify-rounds 전면 체급으로 고치라고 했다. 수리자와 심사자는 모두 gpt-6-sol이다. 첫 라운드가 끝나 수리 5건을 커밋한 뒤 graphify를 갱신했다. 두 번째 라운드 도중 사용자는 전건을 실제로 읽는 점을 강조해 관점 수리자 둘을 재파견하게 했고, 두 번째 라운드를 끝으로 종료하라고 지시했다. 추적되는 결정과 수치는 `임시/do-math_검증_2026-09-24/동결.md`, `장부.md`, `종료보고.md`에 남긴다.

## 터득한 것

첫 라운드의 네 영역은 산출물 229개 파일을 분담했지만 두 전건 관점은 미독으로 결번이었다. 두 번째 라운드에서는 영역 3기의 수행 기록이 77파일·18,247행 전체를 주장했어도 `test_context_store.py` 앞부분이 실제 실행 로그에 없었다. 같은 수리자 세션에서 그 파일의 모든 행을 다시 읽고 검산했다. 관점 5기는 강화 파견 뒤에도 일부만 읽었지만 같은 Codex 세션을 네 차례 재개해 총 229파일·74,399행을 끝냈다. 관점 6기도 강화 파견에서 전건을 읽었다. 파일별 독해표 대조와 함께 CLI 로그에 각 파일의 비어 있지 않은 원문 행 66,999개 전부가 나타났는지를 검사했다. 네 영역의 합집합과 두 전건 관점이 각각 이 대조를 통과했다. 로그 일치는 읽은 범위의 근거이며 이해의 완전성 인증은 아니다.

두 번째 라운드에서 수리 12건·조각 25건은 겹침 묶음 없이 심사자 세 기가 모두 승인했고, 16개 파일에 적용됐다. 앵커와 비교한 최종 변경 파일은 20개다. 1라운드의 적용 5건을 더하면 적용 항목 17건이다. 첫 라운드의 R1-01은 잘못된 대기 사유 경로를 다시 쓴 수리안이어서 기각됐고, R1-06은 실패한 하위 시험 결과를 건너뜀으로 덮는 회귀 때문에 승인 뒤 제외했다. 두 결함은 해결됐다고 기록하지 않았다. 사용자의 2라운드 종료 지시는 적용과 검사를 마친 뒤 종료 산술의 하한·상한을 2로 바꾸어 반영했으며, 정족이나 승인 조각은 바꾸지 않았다. 종료는 수렴이 아니라 사용자 지정 상한 도달이다.

최종 적용본의 단위 293건, Lean 8건, 자원 1건은 통과했다. 관련 통합 125건은 124건 통과하고 Windows 심볼릭 링크 권한 부족으로 1건 건너뛰었다. 광범위 통합 묶음에서는 학술 요구 사례 네 건이 통과했지만, 과거 실행 시간이 기록된 131건의 합계만 약 95분이고 나머지 16건은 미측정이어서 전건 실행을 중단했다. 전체 통합 통과와 실제 연구 인스턴스에서의 효과는 검증하지 않았다. graphify는 마지막 변경 뒤 다시 갱신되어 229파일·6,179노드·21,806관계의 `current` 상태다. 그래프 자체와 상세 시험·CLI 로그는 Git 추적 밖의 로컬 자료이며, 추적 보고·장부가 근거와 한계를 복원하는 진입점이다.

## 작업 너머 시사점

독해 기록의 파일 수와 행 수가 정확해도 그 행들이 모델에 전달됐는지는 별도 문제다. 실제 로그에 원문 행이 있는지 확인하면 미독인데도 표만 완전한 경우를 가릴 수 있다. 하나의 긴 컨텍스트로 전건을 끝내지 못할 때에는 같은 에이전트의 세션을 이어서 이미 읽은 범위와 남은 범위를 좌표로 보존하면 중복 없이 검토를 끝낼 수 있다. 시험도 역사 실행 시간과 미측정을 나눠 예산을 잡고, 돌린 일부 사례의 통과를 실행하지 않은 전체 사례의 통과로 넓히지 않는다.
