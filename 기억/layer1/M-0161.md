title: 학술자료 MCP의 Taylor·De Gruyter·JSTOR 회수를 확장하고 진단 노출을 기록함
convention_version: 24

학술자료 MCP의 남은 구현을 계속했다. Taylor & Francis와 De Gruyter Brill의 검색·native 인용문·문헌 회수, JSTOR의 공개 RIS를 연결했다. 전체 구현은 부분 완료이며 남은 기능을 완료로 세지 않는다. 현재 정본은 services/scholarly-mcp/README.md·SUPPORT.md·VALIDATION.md·registry.py다. 기존 연구 코드·산출물과 사용자의 .codex/config.toml 변경은 유지했다.

Taylor & Francis는 KUDOS 목록 조회 문자열을 Taylor로 사용하면 정상 기관 프록시에 도착했다. field1·text1과 연도·정렬의 원 검색 조건, 0부터 세는 startPage와 20건 페이지를 확인했다. Citation POST에 두 DOI를 보내 실제 두 BibTeX를 받았으며 DOI 집합을 대조한다. 같은 공개 endpoint에 기관 context 없이 직접 요청한 HTTP 403과 구별한다. 해당 파일의 MIME은 Application/X-Bibtex였고 요청 형식에 맞는 canonical MIME으로 보존한다. 공개 API 문서나 endpoint가 보인다는 이유로 별도 API 자격을 요구하지 않는다.

문헌 PDF는 View PDF의 epdf 뷰어와 Download PDF의 실제 파일 링크를 구별했다. 현재 DOI에 결합된 show-pdf 다운로드만 선택해 관련 문헌 PDF를 섞지 않는다. 실제 MCP에서 40,675건의 페이지 경계 두 문헌·BibTeX, 10.1080/09557571.2011.558053의 서지·초록·23쪽 PDF·인용문을 통과했다. 첫 쪽 제목·저자와 DOI는 별도로 읽었다. abstract가 native BibTeX에 없는 문헌은 확보했다고 표시하지 않는다.

POST 내보내기를 공통 browser_download에 추가했다. 303·301·302에는 GET으로 전환하고 본문을 재전송하지 않으며, 307처럼 본문 유지가 필요한 경우에도 다음 요청 전에 자료원 호스트를 확인한다. 실제 citation POST와 별도 경계 검사를 모두 수행했다. KUDOS 오류에는 실패 단계의 안전한 이름을 추가하여 로그인 실패와 자료원 redirect 실패를 구별할 수 있게 했다.

De Gruyter Brill의 검색은 title:(complexity)와 familyName:(Goldreich)를 AND로 결합한 원 식을 확인했다. visibility=available과 all은 다르며 all에는 저널·서지 항목 등도 포함된다. 원 페이지의 startItem은 0·10·20 순서다. 공개 HTTP 요청의 202 빈 응답과 실제 브라우저의 정상 검색·문헌 응답을 구별했다. 현재 어댑터는 기관 브라우저 검색과 문헌에 실제 제공된 RIS 링크를 사용한다.

De Gruyter의 citation 링크는 숨은 영역에도 있으므로 접근성 role의 표시 대상만 찾는 방식은 맞지 않았다. Download in RIS format의 실제 앵커를 읽고 반환 DOI를 대조한다. 실제 MCP에서 available 범위 654건의 RIS·서지·초록·9쪽 PDF와 페이지 경계를 통과했다. 정확한 보고 경로는 VALIDATION.md가 소유한다. 네트워크나 표시 방식의 한 차이를 확인하기 전에 자료원 전체의 기능 부재로 판단하지 않는다.

JSTOR 검색에는 CAPTCHA가 있었지만 공개 citation/ris endpoint는 원 RIS를 반환했다. stable 번호·URL·10.2307 DOI의 metadata·abstract·export를 API로 연결했고 실제 MCP를 통과했다. 앞의 Provider·Database·Content 안내문 때문에 기존 RIS 파서가 실패했다. 알려진 제공자 서문을 source_preamble로 보존하고 원 파일도 유지하도록 수리했다. 웹 검색·전문은 연결하지 않은 상태로 명시한다.

추가 관측에서 IOP 바로가기는 validate.perfdrive.com의 CAPTCHA로 이동했고, Project Euclid 검색은 Incapsula 차단을 반환했다. SIAM은 일반 브라우저에서 Cloudflare 확인 화면을 표시했으며 검색 결과 준비를 확인하지 못했다. AMS는 AdvancedSearch와 browse의 화면 틀을 열었지만 결과 준비를 확인하지 못했고 browse.js 요청의 HTTP 403을 보았다. ScienceDirect는 고급검색 필드까지 정상인데 제출 뒤 CPE00001이었다. APS 기관 검색은 field_G_0·term_G_0를 제출해 search/results로 이동했으나 Cloudflare 확인 화면이었다. 이들을 영구 부재로 표현하지 않는다.

Numdam 공개 웹 검색은 q0와 qt0를 사용하는 폼을 확인했고 complexity를 제출해 4,804건을 받았다. 리디렉션 URL은 compact query 형태이고 페이지 링크도 그 문법을 사용한다. 결과의 articles/DOI URL에서 문헌 페이지로 가면 export_citation/원NumdamID/bib·ris·enw 링크가 있었다. 예시 DOI 10.1051/ita/2011126의 native ID는 ITA_2012__46_1_67_0이다. 이 추가 검색·DOI 해석·native export는 아직 서비스 코드에 연결하지 않았다. 원 Numdam HTML은 .credentials/scholarly-mcp/probes/numdam-search.html·numdam-article.html에 보존한다.

진단에서 비밀값 비노출 규칙을 두 번 더 어겼다. 압축된 APS HTML에 Get-Content -TotalCount를 사용해 첫 줄 안의 Cloudflare 접근 확인 토큰이 도구 출력에 포함됐다. 이후 Numdam 검색 폼의 입력값을 나열하면서 숨은 CSRF 입력도 출력했다. 사용자에게 각각 즉시 알렸고 값을 재기재하지 않았다. 브라우저는 종료됐지만 기존 출력의 삭제나 토큰 폐기는 이루어졌다고 주장하지 않는다. 이는 앞선 ProQuest 사고와 별개의 재발이다.

URL의 Cloudflare 필드는 이미 정제 대상이었으므로 첫 사고는 원자료 직접 출력이 정제 경계를 건너뛴 경우다. 이번에는 구조화된 _cf_chl_opt·관련 토큰 필드와 csrfmiddlewaretoken도 정제하도록 검사·수리했다. Numdam 원 HTML을 일반 data 관측 경로에서 보호된 probes로 옮겼다. 정제기 수리만으로 직접 출력의 절차 위반이 사라지는 것은 아니다. 후속 진단은 허용한 호스트·상태·문헌 ID·제어 이름만 출력하고, 원 HTML·JS·폼 전체와 숨은 입력값은 도구 출력에 보내지 않는다. 압축 파일의 첫 줄이나 앞부분도 안전한 출력 단위가 아니다.

공통·자료원 검사 76개가 통과했다. 원문 확보와 요청 조건의 검증은 문헌의 학술적 타당성 판정이 아니다. Scopus 별도 웹 계정과 Unpaywall 연락 이메일은 사용자 결정에 따라 계속 보류한다. 전체 남은 구현을 마무리하지 못했으며, 원자료 진단의 노출 재발 때문에 추가 원격 진단을 중단하고 현재 코드·검증·재개 좌표를 보존했다. 후속 작업은 남은 구현을 계속해야 한다.
