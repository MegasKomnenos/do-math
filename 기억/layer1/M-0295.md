사용자는 주차 함수 연구의 진행 문제 분석을 근거로 do-math 전체를 이해하고 필요한 절차를 개선하자며 grill-me를 호출했다. 인터뷰에서 기존 연구의 복구·재개는 제외했다. 사용자가 나중에 처음부터 연구를 시작하므로 이번에는 스킬 자체를 개선한다는 결정이다. 기존 연구 인스턴스·HOLD·예약 작업은 변경하지 않았다. [[M-0292]]·[[M-0293]]·[[M-0294]]의 상태와 이번 개선을 같은 사건으로 합치지 않는다.

## 확정한 권한과 기본값

독립 운영은 설정 가능하며 기본 활성·2시간 주기로 정했다. 작업·운영 실행 횟수 예산은 모두 기본 null이고 사용량은 계속 기록한다. AI가 만든 개별 과제의 조사 범위 변경·축소·철회는 자율로 맡기되, 사용자의 최종 목표·필수조건은 유지한다. 주기 담당과 메인 대화가 충돌할 수 있다는 사용자 질문을 받아, 메인 대화는 사용자 입력·조회 창구, 실행기는 상태와 내부 관찰·점검, 독립 담당은 전체 운전·복구를 맡도록 연결했다.

원래 완료 기준 합집합은 미완료 의무를 지키려는 구현이었지만 승인 전 계약을 고쳐도 옛 문장을 되살렸다. 현행 기준을 교체하고 과거 문면을 이력으로 보존하도록 바꿨다. AI 과제 철회에는 입력 snapshot·계약 해시·생성 계보·현재 실행 부재를 검사하고 부분 결과를 보존한다. 독립 검토 중 사용자의 학술 요구 과제까지 일반 후보 개정으로 덮을 수 있는 경로를 발견해 재현 후 차단했다. 자율 과제 변경과 사용자 요구의 면제를 구별한 수리다.

## 실패를 수정 가능한 단계로 돌린 변경

연구 계획의 현재 ready 모집단을 입력과 수신 검사에서 공유하며 누락·과잉·중복 ID를 구별한다. 출력 수리를 소진한 행동은 별도로 보존하고 진단한다. 일반 resume은 그 실패 출력을 그대로 복원하지 않는다. 진단된 계획 재시도는 새 action과 현재 입력에서 판단하며, 성공 뒤 원 실패를 삭제하지 않고 해결 이력을 남긴다. 실패한 한 행동의 대기와 진단된 재시도 소진이 독립 작업까지 멈추던 경로도 재현해 고쳤다.

scholarly는 설정을 찾아 명시적으로 하위 Codex 실행에 전달한다. 서버 command/args만 회수하고 원문·manifest를 실행별 scholarly-data에 저장한다. 실제 프로젝트 설정에는 timeout 키도 있었는데, command와 args 두 키만 허용하는 검사에 테이블 전체를 넘겨 설정을 거부하던 새 구현 오류를 고쳤다. 신규 operator 모듈은 Python 표준 operator와 충돌해 실제 child가 실패했으므로 scheduled_operator로 이름을 바꿨다. 경로 우회는 제거했다.

독립 운영은 특정 연구 폴더의 supervisor에 의존하지 않고 스킬 안의 계약·CLI·예약 스크립트로 제공한다. 실제 예약 probe에서 raw bytes가 있는 모델 영수증의 JSON 직렬화 실패를 관찰해 공통 json_safe로 수리했다. 원 영수증은 실행별 result에 남기고 최신 보고와 CLI 반환에는 요약·경로를 제공한다. 자동 pause는 복구 점검을 허용하고, user_pause와 HOLD는 자동 재개로 풀 수 없게 했다. 운영 담당은 원자료 보충·계획 요청·로컬 복구를 할 수 있지만 사용자 목표·정책·학술 요구·외부 행동·신뢰 판정을 새로 만들지 못한다.

HOLD를 접수 직후 해제하면 아직 정지가 원장에 적용되지 않았을 수 있다. 해제 요청은 정확한 HOLD ID가 담긴 예상 정지 사유를 함께 제출하고, 실행기가 적용할 때 최신 user_pause와 대조하도록 보강했다. 접수 시점만 확인하면 다른 사용자 정지를 풀거나, 이미 해제한 HOLD의 정지가 나중에 남을 수 있기 때문이다. 두 경우의 회귀를 재현·수리했다.

빠른 제어 시험에서는 같은 밀리초의 ULID가 무작위 접미부 때문에 접수 순서와 다르게 정렬되는 기존 경로도 드러났다. inbox를 기록된 접수 시각 순으로 처리하도록 바꾸고 순서를 고정한 재현으로 확인했다. 대화 소실 시 정지한다는 사용자 정책은 자동 운영의 resume에서 별도로 보호했다.

## 검증의 범위

전체 회귀의 고정 사본은 326건 중 325건 통과·Windows symlink 권한 1건 미실행이었다. 최초 사본은 수정 중 파일이 섞이고 시험용 runner가 새 인자를 받지 못해 실패했으며, 그 기록을 남긴 뒤 일치하는 사본으로 재검사했다. 전체 회귀 이후 운영 보고·HOLD 해제·제어 경계 변경과 문서 정리는 별도 집중 검사·독해로 확인했다. 후속 운영 시험 11건·복구와 제어 경계 시험 16건과 사본의 문서 전달 6건·설치 7건·단독 설치 3건이 통과했다. 스킬 18문서 전체를 세 판본에 걸쳐 독해하고 합의와 대조했다. 검증 진입점은 `docs/do-math/개선-검증-2026-09-16/README.md`다.

새 문헌 연구 인스턴스는 실제 Codex 6회로 준비부터 목표 감사까지 이어졌다. scholarly fetch와 PDF render·이미지 extract를 수행하고 PDF·PNG·manifest의 산출 보존 및 후속 입력 해시 일치를 확인했다. 한 저자 공개 PDF와 첫 쪽 판독의 시험이며 목표 감사자 1명 설정이었다. 이를 전체 자료원 가용성·기본 2인 감사의 실호출·일반 수학 연구 효능으로 확대하지 않는다.

별도 Windows 예약 probe는 실제 Codex와 scholarly 목록 호출을 마치고 연구 snapshot을 그대로 유지했다. 제어 시험은 실행 중 HOLD 접수, 적용 후 종료, 같은 HOLD 해제와 새 실행, 시험 종결을 확인했다. 두 시험의 예약 작업은 제거됐다. 제어 시험은 완전한 작업자 체크포인트가 생기기 전에 중단됐으므로 실행 미완료·부분 관찰을 보존한 범위만 입증한다. 2시간 주기 설정과 수동 호출은 확인했지만 자연 시각 도래의 장기 운영 관찰은 수행하지 않았다.

도구 로그의 별도 파일 경로가 없다는 이유로 소실을 의심한 검토 지적은 철회했다. 정상 result.json 안의 base64에서 JSONL 원바이트를 복원해 live 로그와 일치함을 확인했다. 파일 배치와 근거 소실을 구별해야 한다. 원문 분수 오독의 정정도 원 PDF 바이트 변경이 아니라 지식 판독의 개정이며, 기존 knowledge_changes가 실제 의존 결과를 재검토하도록 함을 회귀로 확인했다.

후속 기억 종합 절차인 dream에서 함께 검토할 후보는 [[M-0274]]·[[M-0287]]·[[M-0293]]·[[M-0294]]다. 문서의 규범이 실제 입력·도구·저장·후속 경로에 전달되는지와, 원자료가 다른 저장 형식으로 이미 보존됐는지를 함께 대조해야 한다. 특정 내부 제약을 계속 누적하는 대신 그 제약이 지키려던 사용자 요구와 AI의 자율 설계 범위를 분리한 사례다.
