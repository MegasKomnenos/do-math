title: EuDML의 응답 대기를 수리하고 현재 유지보수 응답을 직접 판독함
convention_version: 24
---

EuDML의 짧은 응답 대기를 원본에서 수리했으나, 현재 서비스 복원으로 계산하지 않았다. 사본에서는 같은 검색과 NLM 요청이 성공했고 45초를 넘긴 성공도 있었다. 원본 재검증에서는 검색이 91.535초 뒤 timeout, 문헌 196516의 NLM이 63.019초 뒤 HTTP 504였다. 두 회귀로 기존 45초를 재현한 뒤 CQL 90초·NLM 120초를 적용했다. 연결 20초와 다른 자료원의 공통 45초는 유지한다. 원본 전체 531개 검사가 62.332초에 통과했다.

주 세션은 검색식의 공백 직렬화 실수 가능성을 별도로 시험했다. 같은 all="P versus NP", startIndex 0, count 2, RSS 요청을 %20과 +로 각각 전송했다. 진단용 응답 대기는 180초였으며 두 호출은 63.844초와 64.281초에 같은 122,858바이트 HTTP 504 HTML을 받았다. httpcore 기록에서는 연결·TLS 완료 뒤 응답 헤더 대기가 길었다. 대기 시간을 더 늘리거나 인코딩만 바꾸면 현재 문제가 해결된다는 근거는 얻지 못했다.

각 요청의 직전·직후·안정 상태 진단 화면 여섯 개를 직접 읽었다. 이 도구는 실제 HTTP 호출을 표시하는 로컬 실행 화면이며 EuDML 웹 UI라고 부르지 않는다. 상태 코드만 보고 판단하지 않고 받은 HTML 원 바이트도 별도 브라우저에서 렌더링했다. 두 렌더 이미지에서 사이트 유지보수 안내가 보였다. 네트워크 요청과 JavaScript를 끈 오프라인 판독이므로 새 페이지 방문이나 새로운 실패 재현으로 계산하지 않는다. 원 HTML은 utf-8 메타 선언과 달리 엄격한 Python utf-8 디코딩에 실패했다. 이 관찰 도구 오류는 문자열 변환을 강제하지 않고 브라우저에 원 바이트를 전달해 해결했다. 유지보수 메시지가 아닌 다른 숨은 본문을 보이는 안내라고 오독하지 않았다.

정제 결과는 services/scholarly-mcp/data/access-research/user-criteria-eudml/root-review.json, 원본 요청·응답·SDK·이미지는 .credentials/scholarly-mcp/probes/root-user-criteria-20260913T0715Z/eudml에 보존한다. diagnostic-20260913T093129Z가 두 인코딩의 비교 근거다. 사본의 이전 성공과 최신 원본 실패를 지원표·검증 문서에 함께 적었다. 별도 book 레이아웃의 실제 검증이 없다는 기존 범위는 그대로 남는다.

사용자는 CLI도 실제 파견 중인지와 주 세션의 직접 작업을 물었다. state와 살아 있는 프로세스를 대조해 당시 실행 3개·재개 대기 2개·제출 19개를 보고했다. 제출 수는 해결 수가 아니다. 주 세션은 원본 통합, 직접 화면·응답 판독, 회귀와 새 SDK 검증을 수행하고 있으며 다른 세션의 완료 보고를 그대로 승인하지 않는다. DBLP KG RDF 항의 값 비교와 정확한 항 비교 문제, Crossmark 수정 의미, SIAM 저자 exact facet의 의미 보존에는 별도 읽기 전용 검토를 연결했다. CLI 동시 실행 상한은 8개이며 신규 API 자격·제외 자료원·거부된 IdP 재시도 경계를 유지한다.
