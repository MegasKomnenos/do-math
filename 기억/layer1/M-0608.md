사용자는 현재 연구 인스턴스의 전체 동시 세션 상한과 do-math의 기본값을 3에서 8로 올리도록 요청했다. `protocol.md`의 설정 예시와 새 인스턴스 준비 규칙에 기본값 8을 명시하고, `SKILL.md`가 그 기본값을 따르도록 연결했다. 실행기에서 `max_sessions`는 계속 필수 필드이며, 필드 누락 시의 새 대체 동작을 추가한 것은 아니다. 계획·연구·검토와 모든 모델을 합친 상한이 8이고, 계획은 동시에 하나만 실행한다.

실행기는 설정을 기동 때 읽으므로 현재 인스턴스의 파일 수정만으로는 상한이 반영되지 않는다. 새 파견을 일시 정지하고 PID와 OS 생성 식별값을 대조해 실행기만 종료했다. 설정·목표를 8로 바꾸고 변경 요청을 사용자 입력으로 전달한 뒤 새 실행기를 기동하고 파견을 재개했다. 기존 연구 CLI 둘은 같은 PID로 살아 있었고 새 실행기가 이어 관리했다. 반영 직후 실제 실행은 연구 둘과 계획 하나였으며, 상한 8을 반드시 채워야 한다는 지시는 하지 않았다.

Claude 정본과 Codex 사본의 생성·드리프트 검사는 185파일에서 통과했다. 양쪽 예시 JSON의 8, 현재 설정의 8, 목표 문구, 새 기동 토큰과 실행기 생존, 기존 연구 프로세스 생존 및 사용자 입력 소비를 확인했다. 실행기 코드는 바꾸지 않았으며 8개 세션의 동시 실가동을 별도로 시험했다고 주장하지 않는다.

운영 대상은 `.skill-workspace/do-math/parking-unimodality-fresh-20261022-071132`다. 재기동 전 상태·설정·목표와 연구 프로세스 확인은 `.skill-workspace/do-math-inputs/parking-unimodality-fresh-20261022-071132/concurrency-8-20261022-100606/`, 새 기동 정보는 같은 준비 폴더의 `launch-concurrency-8.json`에 보관했다. 이 경로들은 상위 저장소의 Git 제외 로컬 자료이며 이번 커밋에 포함되지 않는다. 영속적인 기본값의 정본은 `.claude/skills/do-math/protocol.md`다.
