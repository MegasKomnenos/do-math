## 맥락

사용자는 통합 설계에 대한 do-math 구현 검증을 새로 요청했다. 구현자의 결정과 변명은 독립적으로 평가할 참고 자료이며 그대로 따르는 기준이 아니고, 형식과 절차 문서도 검토에 적용하라고 지정했다. 프리셋은 codex-full 전면이며 수리자와 심사자 모두 gpt-6-astra low다. 이전 런의 사용자 지정 2라운드 종료를 이번 런의 상한으로 승계하지 않았다. 새 런은 `임시/do-math_codex-full_검증_2026-09-15/`이고 하한 3·상한 8·연속 적용 0 종료 조건 2회를 동결했다.

수리자 6기와 심사자 3기는 지정 모델·노력을 명시한 독립 Codex CLI로 실행했다. 병합자는 프리셋 기본인 gpt-5.6-terra low를 사용했다. PowerShell 환경에서 Python 보조 스크립트로 프로세스를 병행 실행하고 공식 wait_outputs.py로 완료를 판정했다. 파견문 슬롯 채우기와 프로세스 실행 이외의 항목 판독·묶음·심사 집계·적용은 공식 vr.py를 사용했다.

## 검토와 판정의 범위

수리자 6기 모두 유효 산출을 냈다. 네 영역은 문서와 역할 계약, 실행과 통치 기반, 지식과 연구 판단, 시험과 검증이다. 두 관점은 기능 목적과 수단의 실익, 정보 전달과 시간선의 정합성이다. 영역 합집합은 85파일 17,428행이며 비중첩을 확인했다. 두 관점 담당은 각각 같은 산출물 전건을 직접 읽었다고 수행 기록에 명시했다. 여섯 기 모두 형식과 절차 358행과 구현자 변명 817행의 전문 독해를 기록했다. 통합 설계와 CONTEXT는 관련 좌표 대조이며 전문 독해로 확대하지 않았다.

18개 제기 항목에서 교차한 5개 항목을 2개 묶음으로 병합했다. 단독 13개와 병합 2개를 심사자 셋이 각각 전부 판정했다. 만장일치 승인 11개를 처음 적용했다. 이후 회귀 실패를 일으킨 R1-04를 제외하여 최종 적용은 심사 항목 10개, 장부의 구성 항목 13개, 20조각·12파일이다. R1-04는 무처분으로 기록했다. 상신·발견 전달·결번은 없었다.

수리는 관찰된 손상에 한정했다. 입력 catalog 바이트의 불변 보존, 과제 철회의 실제 종료 대기, 관계의 현재 판정 효력 확인, 학술 판정 정지 뒤 후속 생성, 실제 사용한 추가 source의 의존 보존, 예산별 배정과 신뢰 전환 명령 인자 보존 등이 포함된다. 구현자의 과거 설명과 달리 이미 수리된 경로는 다시 결함으로 세지 않았다.

기각 4개는 결함 부재 판정과 구별한다. 관찰 규칙 안내는 제출 위치를 혼동시킬 수 있었고, HTTP 본문 수리는 문서의 기존 전송 계약을 함께 고치지 않았다. 학술 시작 집계 수리는 시작 기준을 실제 프로세스 실행으로 늦춰 다른 정상 상태를 잘못 표시했다. 복구 자료 전달 수리는 재시도 뒤 출력 수리가 이어지는 경우 오래된 recovery 실행을 우선하여 최신 부분 파일을 놓쳤다. 이 사유는 장부에 보존하며 다음 수리자에게 직접 지급하지 않는다.

## 검증과 다음 단계

수정 전 전체 회귀는 278개 중 277개 통과·1개 미실행, 1152.107초, exit 0이었다. 변경 Python 10파일의 문법 검사를 통과하고 생성 미러를 갱신했으며 245파일 드리프트 검사를 통과했다. 첫 적용 후 전체 회귀는 280개 중 실패 1개·미실행 1개, 588.293초였다.

실패한 검사는 원자료 변경 뒤의 종료 산출을 보존하되 수락하지 않는 시간선이다. R1-04가 모든 정지에 일반 오류 문구를 부여하면서 기존의 구체적인 source 변경 사유를 지웠다. 단독 실행에서도 같은 실패를 확인했다. 승인 조각을 세션이 고쳐 쓰는 대신 신호 6의 자체 처리로 R1-04를 이번 적용에서 제외했다. 첫 적용 파일을 라운드 사본으로 복원하고 공식 적용의 `--제외 R1-04 --강제`로 나머지를 재적용했다. 해당 시험의 단독 재실행은 통과했다. 재적용 후 전체 회귀는 280개 중 279개 통과·1개 미실행, 576.730초, exit 0이었다. 미실행은 Windows symlink 생성 권한 부족(WinError 1314)이다. 최종 장부는 적용 13·기각 4·무처분 1로 결산했고 하한 3 미만이므로 다음 라운드를 판정했다.

이 라운드는 전체 구현의 기능 완료나 수학 연구 효능의 인증이 아니다. 독립 검토의 완료 범위, 정적 대조·메모리 재현·실제 회귀의 차이, 기각과 미실행을 구분한다. dream에서 함께 종합할 후보는 [[M-0278]]·[[M-0279]]·[[M-0280]]이다. 문서에 공개된 미구현과 실제 현재 동작은 판본을 대조해야 하며, 실제 결함을 확인했어도 수리의 하류 모순이나 불완전성이 있으면 독립 심사에서 기각될 수 있다.
