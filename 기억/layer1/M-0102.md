## 맥락

M-0101의 커밋 뒤 `gp-fable-high` 검토자가 세 문서, `941eba4` 대비 diff, 사용자·어시스턴트 발화만 옮긴 대화 로그를 읽고 `DEFECT`를 냈다. 대조 항목 45 가운데 반영 43, 누락 1, 초과 1이고 발견은 모순 8, 누락 1, 초과 1, 모호 12다. 보고서는 `임시/수입-경로_설계반영_2026-09-02/검토보고.md`에 있다. 사용자 지시대로 검토 결과를 그대로 적용하지 않고 발견마다 타당성을 다시 읽은 뒤 Edit 도구로 직접 고쳤다.

수용해 적용한 것은 F-01~F-09, F-11~F-14, F-16, F-18~F-22다. 재개가 initializing에서 실행 껍질 재생성과 신뢰 시대 검사를 건너뛰게 했고, 전례 유래 결정 기록에는 답변·되비춤 참조가 부재한다는 뜻을 6.10절과 C10에 적었으며, 작업 씨앗 생성자의 정련안 질문 작성, 4.2.1절의 수입자 초안 승격, 17.1·17.2절과 루트 「전례」의 작업 결정 질문 포함, 검토 항목 「원문이 이미 정한 것을 미결정으로 올리지 않았는지」, 승인 단계의 2~6단계 반복과 수입 기록 승인 참조의 채움 시점, 작업 기록의 `decision_question_ref`와 `task/3`·`status/2` 판본, 5.1절과 I28의 도구 범위, 결정 대기 씨앗의 외부 대기 가드 포함, 5.2.2절의 원문 보존 경로와 「수입 묶음」 통일, 12.1절·E16의 역할 목록, 생성 회차 최초 앵커를 활성화 시각으로, 활성화 관문의 `degraded` 허용과 18.0절 권한 근거의 기반 수용 기록을 반영했다.

다르게 판정한 것은 셋이다. F-10의 초기화 포기 규칙은 로그 밖 결정이 맞지만 4.4절이 ref 삭제를 막으므로 보관이 유일한 길이라는 것은 도출 귀결이라 보고, 「유일한 길」 문구만 걷어내고 4.4절 근거를 적었다. F-17의 「연구 책임자/사용자」 혼용은 검토자가 새 문장을 「연구 책임자」로 통일하자고 했으나, 설계 문서의 고정 어휘와 기존 산문이 「사용자」이므로 설계 문서 쪽을 「사용자」로 통일하고 루트 용어집과 컨텍스트 문서는 「연구 책임자」를 유지했다. F-05는 두 제안 가운데 운영 처분 경로의 설정 변경에 17.1절의 사용자 결정·전례가 승인 결정 기록을 대신한다는 첫 안을 택했고, 전례 유래 결정 기록의 범위를 넓히는 둘째 안은 사용자 결정 없이 17.1절의 적용 방식을 바꾸므로 피했다. F-15는 작업 종결 편입이 맥락 기록의 새 판본을 만들지 못하고 5.2.2절로 올리는 쪽을 택했으며 18.4절 재검사 항목으로도 닫았다.

검토와 별개로 내 자체 점검에서 찾은 셋도 함께 적용했다. 수입 편입 전 연구 설정이 없는 동안의 heartbeat·poll 기본값과 역할별 동시 세션 상한 1, 골격 생성 뒤 메인 세션의 감독기 시작, 결정 질문 파일의 위치와 참조 필드다. 마지막 것은 F-12와 겹쳤다.

## 터득한 것

- 대화 로그를 검토 입력에 넣은 것이 문서 정합성만 보는 검토로는 잡을 수 없는 누락 하나(F-09)를 잡았다. 로그의 발화 한 줄이 문서의 검토 항목 목록과 대조돼 빠진 항목이 드러났다. 확정 결정이 대화에만 있는 반영 작업에서는 로그 기반 충실성 대조가 정합성 검사와 별개의 검사다.
- 새 국면(`initializing`)을 넣으면 「창세 커밋이 곧 활성」을 전제하던 자리들이 문서 곳곳에서 어긋난다. 이번에 걸린 자리는 재개 단계, 생성 회차 앵커, 역할 목록 둘, 지식 초안 저작 관례, 설정 부재 시의 용량이다. 국면을 추가하는 편집은 그 전제를 grep으로 먼저 목록화하는 것이 검토 뒤 되돌아오는 발견을 줄인다.
- 검토자의 「초과」 판정은 위임 세부와 도출 귀결을 구별하지 않고 로그 부재만으로 냈다. 적용 전에 그 규칙이 기존 절에서 도출되는지 확인하면 로그 밖이라도 유지할 수 있고, 이번 F-10이 그 예다.

## 작업 너머 시사점

- 남은 사용자 결정은 M-0100의 복원 인스턴스 초기 입력 원천과, 이번에 가정으로 둔 「승인된 외부 변화에서도 네 종류 기록의 사용자 승인」이다. 둘 다 5.2절·5.2.2절의 문구를 바꾼다.
- 지적한 쪽에 보낼 회신은 만들지 않았다. 필요하면 검토보고의 5절 「지적 해소 표」가 그대로 회신의 골자다.
- dream에서 묶을 후보: 대화 로그를 검토 입력으로 넣는 파견이 정합성 검토와 다른 종류의 발견을 낸다는 관찰. M-0101의 「기존 장치 재사용이 늦게 떠오르는 패턴」과 함께 설계 대화 작업의 검증 설계로 묶을 수 있다.
