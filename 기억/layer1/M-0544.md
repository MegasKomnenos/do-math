B129는 HEAD 9ff37dac994876348b37b489ace1eac35837da04의 기본 다섯 폴더를 jobs 3으로 실행했다. 선택한 3990개가 모두 최종 보고의 실제 행에 대응한다. 결과는 3988통과·1실패·1건너뜀이며 complete는 true, successful은 false, 종료 코드는 1이다. 세 병렬 작업자와 격리 시험 한 개가 모두 종료했다. 최종 보고의 10724초는 소프트 기준 초과이며 강제 종료나 범위 축소의 이유로 삼지 않았다. 시작 전후 정본의 추적·미추적 969개 파일 바이트 해시와 HEAD가 같고 changed_during_run도 비어 있다. 이전 B123의 미실행 및 B127의 최종 보고 없는 중단과 달리 이번에는 완결 원보고를 확보했다.

유일한 실패는 structure.test_test_smells의 unpinned_rejection이었다. B128에서 추가한 영구 게시 거부 시험이 PermissionError 발생만 확인하고 실제 예외를 검사하지 않았다. Windows 읽기 전용 참조를 교체하는 기존 경로는 ctypes.WinError를 전파하며 경로 속성을 별도로 붙이지 않는다. 따라서 예외를 받아 winerror가 5인지 단언하는 한 줄을 추가했다. 기존 참조값 보존, 소유 잠금 정리, 읽기 전용 해제 후 다음 갱신 성공 단언은 그대로 둔다. 제품과 구조 검사 규칙을 바꾸지 않았다. 정확한 게시 시험과 실패했던 구조 검사 두 개가 9.7초에 모두 통과했고 실행 중 소스 변경도 없다.

건너뛴 항목은 외부 심볼릭 링크 감지 시험이다. 실제 기록은 WinError 1314의 링크 생성 권한 부족이다. 이 항목을 통과로 세지 않는다. 검증/2026-10-06-일반통합-B129에 전체·부분 수리 보고와 시작/종료 소스 지문, 실제 실행 메타데이터를 원본 바이트로 보존했다. 전체 실패 보고를 수리 결과로 덮거나 부분 통과를 합산해 전체 성공을 만들지 않는다.

INTEGRATION-CURRENT의 종료조건은 전건 결과와 소스 변경 여부를 판정하고 실패를 한정 수리로 배정하는 것이어서 이번에 이 작업은 닫았다. 최종 판본의 전체 성공을 요구하는 FINAL-ORDINARY는 별도 미완료다. 원문 요구, 보존 성질, P2, fresh T3, 극단 변이와 정상 기준, T4/T5의 남김 역시 유지한다. 한정 단언 수정 뒤 즉시 전체 실행을 반복하는 대신 원래 요구 작업을 이어가고 다음 통합 또는 최종 관문에서 판본을 명시한다.

대기 중에는 새 독립 문맥에서 DOC-RETURN-CLI의 조회 부분만 검토했다. 초기화 문서의 query --files 결과를 레코드 query_records와 _record_evidence의 AST 모양으로 검사하여 같은 snapshot/path 이름으로 통과할 수 있었다. 기존 CLI 파일 조회 반환과 _query_record 단위 시험을 재사용하는 수정안을 별도 복사본에 준비했고, 여섯 원본 해시·수정본 해시·문법 및 git apply --check를 확인했다. 아직 정본 적용이나 실행 검증은 하지 않았다. .skill-workspace/test-restructure-2026-09-29/finish/query-result-candidate-20261006의 패치와 manifest는 Git에서 제외된 로컬 보관 자료다. 다음 작업은 이 조회 slice의 재현·적용·관련 검증이며, init/select-profile이나 13-C 전체를 완료로 주장하지 않는다.
