전용 Chrome에서 실제 KUDOS·학술 DB·AMS 프록시 경로의 고급검색이 열린 뒤 원 XLSX 내보내기와 기본 검색의 페이지·0건 계약을 구현했다. 검색에서 요청한 논리 상품의 순서·전체 건수·다음 위치를 유지하고 각 ProductCode의 원 export를 별도로 회수한다. 기존 native는 원 JSON 페이지라는 의미를 보존하며 XLSX를 새 형식으로 추가했다.

SURV/168 한 논리 상품의 원 XLSX에는 서로 다른 ISBN의 물리 상품 3행이 있었고 ProductCode 열은 모두 비어 있었다. 한 상품을 한 엑셀 행으로 강제하지 않고 정확한 ProductCode의 단일 검색과 원 initExportResults 동작을 결속한다. 실제 POST /product/exportproducts의 advancedSearch.ProductCode를 검사하고 응답 바이트를 직접 읽는다. 이 XLSX는 CDP 파일 이벤트가 없었으므로 PDF용 native_download를 무조건 재사용하지 않았다. 제목·부제·저자·날짜·제공 ISBN과 비어 있지 않은 ProductCode를 대조하고, OOXML 내부의 정제 대상 값도 확인한다.

0건 응답은 TotalRows=0일 때 Products=null이었으며 기존 파서가 이를 오류로 처리했다. 이 경우만 빈 결과로 읽고 원 JSON은 그대로 보존한다. 양수 TotalRows에 Products=null이거나 원 product 응답이 객체가 아닌 경우는 오류로 유지한다. source export 오류가 발생해도 이미 얻은 검색 레코드와 원래 요청 창은 보존한다.

20260912T120447Z-ams-export-mcp.json은 algebra6,589건 중 1건·next1·원 XLSX와 Products 시트 4행(제목 행 포함) 추출, 선택 상품 metadata·책 소개를 실제 SDK에서 통과했다. 125646Z-ams-search-mcp.json은13건·start11/limit2 페이지 경계·앞 결과와 동일성·0건을 completed=true로 통과했다. 131217Z-ams-pdf-mcp.json은 명시 PDF 51쪽·내장 metadata·추출을 재검증했다. AMS 전용 15개 검사가 통과했다.

동적 AND/OR 식은 다른 상태다. 수동 UI의 단일 Title contains algebra 제출도 같은 세션에서 내부 message 문자열을 반환했고, 동일 scalar·sortBy의 기본 Title 검색은 6,589건을 반환했다. dynamicAdvancedSearch만 한 단계 덜 인코딩한 대조도 실패했다. 따라서 복원 함수나 sort 또는 인코딩 깊이 하나의 결함으로 좁히지 않고 현재 제공자의 동적 실행 오류로 기록한다. 다항·중첩 UI는 입력 대기가 끝나지 않아 그 범위까지 직접 제출했다고 주장하지 않는다. 근거는 services/scholarly-mcp/data/access-research/ams-expression-summary.json과 ams-expression-report.md다.

이 커밋은 AMS 어댑터·회귀·실제 SDK 재현 스크립트 단위다. 공통 서버의 전용 Chrome 등록과 전체 지원 설명은 후속 통합 단위에 포함한다. 동적 오류를 사용자 자격 부족으로 바꾸거나 추가 API·계정·이메일을 요구하지 않는다. 전체 작업은 계속 중이고 푸시하지 않는다.
