## 관찰과 사용자 결정

현재 주차 함수 연구의 formalizer 다섯 개는 모두 정상 종료했지만 배정된 임계 EGF 증분 D의 Lean 증명을 완성하지 못했다. 각 세션은 필요한 기초를 실제로 더했고, 남은 확률·측도 의무를 적은 뒤 전달 준비로 옮겼다. 종료 기록에 공급자 거부나 컨텍스트 한도 종료는 없었다. 등록 연구를 수행한 attempt 43개의 공개 메시지와 종료를 선별 검토하고 여섯 사례의 선언·보고·출시 지침을 더 대조했다. 유한 인증 범위, 충분히 큰 크기의 정리, 강화의 반례를 얻은 뒤 원 질문의 의무를 남기고 마무리하는 사례가 있었다. 반면 D 자체를 비형식으로 해결한 attempt는 자기 질문을 끝냈으므로 짧은 실행이라는 이유로 조기 종료로 판정할 수 없다. 모든 미완료 종료가 부당하다고 입증한 감사는 아니다.

사용자는 부분 목표의 완성을 전체 목표의 완성과 혼동하지 않고 같은 세션에서 계속 일하기를 원했다. 목표 달성에 필요한 새 수학은 기존 작업을 대체하는 별도 임무가 아니라 그 목표에 속하므로 또한 현재 세션의 일이다. 방법의 변경은 새 발견이 생겼다는 이유로 요구하지 않고, 목표에 도움이 된다고 판단할 때 선택할 수 있게 한다. attempt의 수학적 목표는 노드의 해결이고 섹션은 현재 책임과 협력을 조정한다. 더 맡을 수 있다는 사용자 설명을 해당 문단에 등록 절차로 다시 넣은 것은 중복이어서 제거했다.

초기 수정은 공통 도입에 계속 수행·종료 판단의 문단을 삽입하고 같은 메시지를 역할마다 반복했다. 사용자는 배치와 흐름이 목적을 전달하지 못한다고 지적했다. grill-me로 의도를 확인한 뒤 공통 서문을 원복하고, 역할의 책임·논증 구성·난점 조사에 설명을 통합했다. 특정 방법의 한계와 질문 전체의 막힘, 남은 의무의 식별과 그 의무를 수행할 수 없다는 판단을 구별했다. 교정 위치는 문장 치환만이 아니라 기존 문서에서 그 판단을 설명하는 절이다. 사용자 교정을 매번 새 지시로 덧붙이는 방식은 문서 구조와 중복을 다시 점검해야 한다는 dream 후보를 남긴다.

## 독립 독해와 그 한계

write-for-reader로 작성 대화와 합의를 보지 않는 역할별 독해를 수행했다. formalizer와 peer의 최종 판본 독해는 어려움 없이 끝났고, 합의와 대조한 판정을 보존했다. attempt의 앞선 독해에서 노드 목표와 섹션 책임의 연결을 명료화했다. 최종 attempt 독해 두 번은 원문의 can을 may로 인용해 정확 인용 검사에 실패했다. 다른 모델의 재독을 시작했으나 사용자가 독립 독해를 끝내라고 지시해 취소하고 프로세스도 종료했다. 이를 최종 attempt 독해 통과로 기록하지 않는다.

독해가 찾아낸 formalizer 원천을 잇는 peer의 범위, 가용성 확인과 연구 착수, 섹션 점유 종료와 lease 해제, 보정 메모리와 단독 초과 작업의 설명도 현재 코드와 대조해 명료화했다. 기록은 `.skill-workspace/do-math-writing-review-20261106-132754/`와 `.codex/writing-flow/`에 있는 Git 제외 로컬 보관이다. 이번 종료 재판단 구현 뒤의 새 운영·출력 설명에는 추가 독립 독해를 실행하지 않았다. 문서 독해는 실제 연구자의 지속성 개선을 입증하지 않는다.

## 실행 설정과 종료 프로토콜

작업자의 475,000 토큰 보고는 사용자 설정의 1M 값이 아니라, 사용자 설정을 무시하는 격리 실행과 당시 모델 메타데이터의 500,000 및 95% 값에 대응했다. 사용자는 모든 모델에 1M 설정을 명시하도록 했다. Codex override, Claude의 [1m] 선택과 900,000 compaction 설정을 작업자 실행에 둔다. 공급자·계정이 실제로 제공하는 용량을 설정값만으로 보증하지 않는다.

이후 사용자는 정상 종료한 attempt·formalizer를 같은 대화로 재개해, 받은 지침에 따라 지금 끝내도 되는지 판단하고 아니면 계속 수행하게 하도록 요청했다. 종료 판단은 현재 요청 ID를 담은 `output/end-decision.json`으로 제출한다. 처음 제안한 한도 도달 시 운영자 대기는 사용자가 기각했다. 한도의 목적은 무한 재개 방지이므로, 한도에서도 실행기 자체가 종료 허가를 기록하고 기존 peer 경로로 넘기는 것으로 확정했다.

기존 분리 세션 호스트가 여러 CLI 턴을 감독하도록 구현했다. 같은 논리 세션·원 지침·작업 폴더·점유·슬롯을 유지하며 추가 턴은 기본 3개, `max_end_resumptions=0`이면 첫 종료에서 실행기가 허가한다. 작업자 판단과 한도 종료는 같은 허가 구조에 서로 다른 발행자와 사유를 기록한다. 이 허가는 수학적 해결의 승인이 아니다. 정상 가용성 전용 종료는 기존 경로를 쓰고, 거부·실패·취소·대화 ID 부재는 운영상 사유를 남긴다. 턴별 로그·요청·실행 영수증을 보존하고 논리 세션 종료 전에 peer나 압축을 시작하지 않는다. STOP은 다음 재개도 막고, kill-session은 CLI 사이의 대기도 취소한다.

## 검증과 적용 상태

전체 런타임 시험 206개가 276.684초에 통과했다. 마지막 재판단 메시지의 JSON 예시를 유효한 단일 basis 값으로 고친 뒤 관련 14개를 다시 실행해 20.709초에 통과했다. 추적된 재현 진입점은 `runtime/tests/test_ending.py`와 `ending_cli.py`이며, 정확 대화 ID·계속 수행·오래된 판단 거부·한도 허가·원 지침 보존·STOP·공급자 대기·취소·호스트 상실·실행기 재시작 후 단일 인계를 확인한다. Codex와 Claude의 실제 설치 CLI로 생성한 resume 인자의 구문 수용을 확인했다. 실제 공급자 대화를 재개하는 실호출이나 연구 성과의 효과는 검증하지 않았다.

시험 로그 두 개는 `.skill-workspace/do-math-end-resumption-tests.log`와 `.skill-workspace/do-math-end-resumption-final-tests.log`의 Git 제외 로컬 자료다. 정본과 `.agents` 사본을 생성기로 동기화했다. 사용자가 요청한 연구 dispatch 정지는 유지했고 연구 실행기를 재시작하거나 재개하지 않았다. 이미 실행 중인 실행기는 적재한 코드를 유지하므로 새 프로토콜 적용에는 실행기 재시작이 필요하며 기존 세션의 출시 계약은 소급 변경하지 않는다.
