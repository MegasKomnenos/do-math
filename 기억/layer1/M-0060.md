## 맥락

전면 검증 다섯 번째 라운드의 수리 후보는 3건으로 줄었고 세 건 모두 심사자 세 명의 만장일치 승인을 받아 통합 설계에 적용됐다.

## 터득한 것

최초 프로젝트 입력 수입에서 “결과를 바꾸는 미결정을 닫는다”는 문면은 AI가 사용자 결정을 대신할 수 있게 읽혔다. 수입기는 미결정을 판별하고 사용자만 정할 항목의 원문 좌표·질문·차단된 수입 단위를 기록한 뒤 초기화를 중단한다. 이미 현행 사용자 결정으로 닫힌 항목만 결정 좌표를 수입 대응표에 넣는다.

실행 상태도는 일시 정지 뒤 같은 `execution_id`를 다시 허가하는 경로를 제거했다. 작업자가 체크포인트와 자기 점검을 공개하면 권한을 `revoked`로 바꾸고 Job 종료 장벽을 거친다. 같은 작업 계약을 이어야 하면 새 `execution_id`의 `preparing` 상태로 재개한다. 종결 재검증 실패도 같은 원칙을 따른다.

정상 감시는 실행 허가보다 먼저 준비돼야 한다. `preparing` run ref가 생기면 `do-math watch`가 그 OID에 결박한 부모 없는 `monitor_started` 사건을 조건부 생성한다. 감독기는 monitor ref와 run OID를 대조한 뒤에만 `authorized`를 공개하고 루트를 재개한다. 원장 생성·대조가 실패하면 정지된 루트를 종료하고 시작 실패를 기록한다.
