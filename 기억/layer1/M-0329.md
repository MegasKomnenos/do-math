# do-math 구현 판본의 보존 경계

이 커밋은 여러 선행 세션이 작업 트리에 남긴 do-math 기능 판본 5의 구현·계약·회귀 검사와 2026-09-23 정적 검토 수리를 함께 보존한다. 정리 착수 때 이미 `.claude/skills/do-math`와 생성 사본 `.agents/skills/do-math` 양쪽에 대량의 미커밋 변경이 있었다. 이번 세션이 그 기능 전체를 새로 설계하거나 전건 구현 완료를 확인한 것은 아니다. 구현 경과와 기능 목적의 대응은 `docs/do-math/구현-진행.md`·`기능-완료-대응.md`, 수리의 범위와 선후는 같은 폴더의 2026-09-23 수리안·결과 문서가 설명한다.

수기 정본과 Codex 사본은 생성기로 다시 맞추고 드리프트 검사를 통과시켰다. 통합 설계 본문과 v9 명세 묶음의 원문 해시가 처음에는 달라 `verify_spec.py`의 85개 검사 중 하나가 실패했다. 정본 생성기 `build_spec.py`로 묶음을 재생성한 뒤 85개가 통과했다. `implementation-v5/traceability.json`의 source-vector-map 해시도 새 바이트에 맞춰 갱신했다. `check_coverage.py`는 역사적 실행 근거를 실제로 읽어 구조 유효성을 확인했지만, 그 메시지가 밝히듯 기능의 실행 통과를 뜻하지 않는다.

검증 증거의 위치를 두 가지로 나눴다. 현행 수리안이 직접 참조하는 정적 검토 보고서, 소스 해시와 그 보고서가 가리키는 17개 고정 소스 파일은 `docs/do-math/review-evidence/2026-09-23-static/`에 추적했다. 고정 소스는 Git 개행 변환을 끄고 17개 모두 원문 해시 및 스테이징된 Git blob과 대조했다. 반면 `traceability.json`의 `observed_runs`가 결박하는 과거 실행 15개의 `run.json`, 로그와 저장소 사본은 Git 제외 `임시/do-math-implementation-20260920/`·`임시/do-math-resume-20260920/`에 남는다. 검사기는 각 실행의 기록·로그 해시와 사본 속 테스트·소스 해시를 읽으므로, 이 로컬 폴더들은 단순한 재생성 캐시가 아니다. 다른 반복 실행 출력은 이 결박과 구별한다.

단위 검사 277개, v9 명세 검사 85개, 스킬 미러 검사와 추적 구조 검사는 통과했다. 변경 부위의 통합 검사 82개 첫 실행에서는 79개가 통과했고 3개가 테스트 구성 오류로 끝났다. 계획 테스트 둘은 입력 생성기가 고정한 과제별 파일 대신 다른 바이트를 반환했고, 다른 하나는 질문 기록 대역이 새 `source_ref` 인자를 받지 못했다. 제품의 검증 조건은 유지하고 테스트가 실제 고정 파일과 호출 형식을 사용하게 고친 뒤 그 3개가 통과했다. 전체 통합 1,330개 순차 실행은 초반 사례의 높은 비용 때문에 중단했으며 완료 결과로 사용하지 않는다. 실제 모델 연구, Lean 검사와 연구 성과도 이번 정리에서 검증하지 않았다.
