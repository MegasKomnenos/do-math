JSTOR·IOP·Software Heritage 구현 뒤 이전에 접근하지 못한 자료원을 현재 시점에서 다시 확인했다. 이미 발생한 실패를 영구적인 기능 부재로 취급하지 않았다. 새 코드가 필요한 결함과 외부 응답 때문에 검증하지 못하는 상태를 구별했다. 전체 학술자료 구현은 부분 완료다.

20260912-jstor-guide-workflow.json은 실제 describe_source가 제공한 첫 예제 입력을 그대로 search에 전달하여 2건·ok, completed=true였다. 호출 설명과 실제 기능의 대응을 확인했다. 정식 JSTOR 검색은 기관 세션의 원 API이며 /new-search의404를 재사용하지 않는다. 현재 검증 범위와 추가 파일·복수 결과군·BCE 등 남은 범위는 M-0208과 SUPPORT.md·VALIDATION.md가 소유한다.

AMS는 UI 초기화와 분리해 이전 실제 /product/browseproducts 요청을 보냈다. 20260912T042311Z-ams-api-recheck.json은 기관·공개 주소 모두 403의 HTML이었다. APS는 /search?q=algebra&page=2도 확인 화면이었고 042406Z-aps-firefox-recovery.json에 남겼다. 앞선 APS 컨텍스트 분리·Chrome 관측, SIAM 확인 화면, ScienceDirect CPE00001과 함께 실패 범위를 유지한다. 재시작이나 다른 자료원 자동 전환을 해결책으로 넣지 않았다.

CORE는 이번에 접근 가능했다. 20260912T043004Z-core-public-mcp.json은 이름 후보와 works340524929의 서지·초록, fullText에 들어 있는 접근 제한 안내문의 restricted 구별을 completed=true로 통과했다. 원 본문을 회수했다는 뜻은 아니다. 이전의 호출 제한 표지를 최신 검증 범위로 갱신했다. 같은 시각 Semantic Scholar는 검색에서 rate_limited였고 completed=false다.

일반 DBLP의 043051828874Z-dblp-workflow.json은 restricted/access_challenge였다. 043051Z-dblp-alternate-hosts.json의 dblp.uni-trier.de와 www.dblp.org도 HTTP200의 확인 HTML이었다. HTTP200을 정상 JSON으로 판정하지 않는다. 별도 dblp-kg의 이전 성공을 일반 DBLP의 이번 성공으로 옮기지 않는다.

공통 248개 검사와 새 실제 검증 기록을 유지하고 기억 색인 검사를 수행했다. 최신 후속 인계 경로는 C:\Users\wogud\AppData\Local\Temp\학술자료-MCP-후속구현-인계-20260910.md이며 현재 구현·실패 근거·남은 작업으로 다시 작성했다. 서지 이외의 원 파일·검색 조건이 남아 있으므로 전체 완료를 선언하거나 푸시하지 않는다. 사용자 연구 자료·공유 do-math 커밋과 설정은 보존한다. 현재 시험·진단은 종료했으며 백그라운드로 이어가는 작업을 약속하지 않았다.

M-0203의 URL 자격값 정제 결함은 수정됐지만 이미 표시된 출력 삭제·원 URL 무효화·전체 과거 기록 감사는 계속 미확인이다. 다음 작업도 보호된 원 자료와 정제된 요약을 구별하고 비밀값을 재출력하지 않는다. 사용자에게 이미 확정된 계정·이메일 보류나 재시작 금지를 다시 확인받지 않는다.
