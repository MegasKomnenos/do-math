title: Project Euclid 보충 탭의 PDF·ZIP과 내부 텍스트 회수를 연결함
convention_version: 24

Project Euclid의 보충자료는 기본 문헌 페이지의 저장 HTML에 들어 있지 않았다. #sup 제어를 누르면 divARTICLECONTENTCITEDTop에 다운로드 행이 생겼다. 이 탭을 연 뒤 문헌에 묶인 파일만 회수하고, 파일 경로의 부모 DOI와 화면의 보충자료 DOI를 서로 다른 필드로 유지하도록 연결했다. 설명 속 GitHub 링크는 파일 후보로 확장하지 않는다.

첫 양성 후보 10.1214/25-AOAS2099에는 PDF·R 코드 ZIP 두 링크가 있지만 원 GET은 모두 152076바이트의 문헌 HTML이었다. 실제 UI 클릭도 다운로드를 발생시키지 않았다. data/validation/20260910T123332Z-project-euclid-supplements-mcp.json은 unexpected_content·partial·completed=false로 보존했다. 링크에 확장자가 있어도 성공으로 표시하지 않았으며 자료원 전체의 부재로 확대하지 않았다.

다른 문헌 10.1214/14-AOS1230의 원 UI에서는 suppdf_1.pdf 333524바이트가 실제 다운로드됐다. 이어 10.1214/24-AOAS1990은 ZIP과 PDF 둘 다 성공했다. 새 SDK stdio의 data/validation/20260910T124043Z-project-euclid-supplements-mcp.json이 completed=true다. aoas1990suppa.zip은 18431바이트·8항목, aoas1990suppb.pdf는 2174641바이트·26쪽이다. 이로써 첫 문헌의 실패와 자료원에 존재하는 정상 파일 경로를 구별했다.

등록된 실제 MCP의 extract에서도 같은 ZIP의 확장자 없는 Analysis 파일을 꺼내 449줄 중 앞 3줄을 읽었다. 별도 보고는 data/validation/20260910T124410Z-euclid-archive-mcp.json이다. R 코드를 실행하거나 GitHub에서 파일을 대신 받지 않았다. 이 단위의 원 fixture 파싱 검사와 변경 시점 공통 174개 검사가 통과했다.

동시에 재확인한 JSTOR는 정상 홈페이지의 Shadow DOM 안에 input[name=Query]가 있었다. 기본 HTML에 input이 없다는 관측만으로 검색 제어 부재를 판단할 수 없었다. 실제 algebra 검색 뒤 Client Challenge와 capInput이 나타났다. SIAM algebra와 APS 기관 quantum computation은 Just a moment, ScienceDirect random graphs는 CPE 안내였다. 각 보호된 원 관측은 VALIDATION의 좌표를 따른다. 이 제한을 해소했다고 주장하지 않으며 남은 검색 구현은 계속 유지한다.

후속 IEEE 문헌 8626436에서는 multimedia=true와 실제 Media 탭의 MP4 링크를 확인해 별도 단위로 구현 중이다. 해당 파일·검사는 이 커밋에 섞지 않았다. 전체 구현은 부분 완료라 푸시하지 않는다.
