## 맥락

do-math 전면 검증 런([[M-0658]], [[M-0659]])에서 서브에이전트가 Opus 5.5 안전 장치에 거듭 막혔다. 막힌 파견의 API 오류 세부는 `[reasoning_extraction]`이었다. 막힌 시점은 두 가지였다. 하나는 산출 전문을 쓰는 도중이고, 다른 하나는 독해 도중이다. 사용자는 서브에이전트가 저장소 지시문을 받기 때문에 생기는 오탐으로 보고, 파견에 지시문이 실리지 않게 하라고 지시했다. 저장소 지시문에는 응답 본문에 긴 학술 복창과 판단 근거를 먼저 쓰라는 의무가 들어 있다.

지시문은 서브에이전트에 세 경로로 실렸고, 이를 차례로 막았다.

1. **시작 적재**: `.claude/agents/gp-matrix/` 12개 정의에 `omitClaudeMd: true`를 더했다(Claude Code 2.1.319). 에이전트 정의는 세션 시작 때 읽히므로, 재시작 전 탐침은 CLAUDE.md가 실려 있다고 답했고 재시작 뒤 탐침은 없다고 답했다.
2. **직접 열람**: 재시작 뒤에도 수리 1·4가 막혔다. 사용자 관찰로는 그중 하나가 `.claude/CLAUDE.md`를 파일로 직접 열었다. 런 파견문의 「읽지 않는 것」에 지시문 파일 좌표를 더했다.
3. **하위 디렉토리 적재**: 그 뒤에도 라운드 3의 수리 1기와 심사 3기가 막혔다. 사용자가 보인 실제 로그에 「Loaded .claude\CLAUDE.md」가 있었다. 서브에이전트가 `.claude/` 아래 파일(verify-rounds 계약, do-math 원문)을 읽는 순간 Claude Code가 그 디렉토리의 CLAUDE.md를 하위 디렉토리 지시문으로 적재한 것이다. `omitClaudeMd`는 이 적재를 막지 않는다. 사용자는 세 선택지 가운데 지시문을 루트로 옮기는 안을 골랐다. 나머지 둘은 지급물을 `.claude/` 밖으로 복사하는 안과 재파견을 되풀이하는 안이었다.

## 변경

- `.claude/CLAUDE.md`를 루트 `CLAUDE.md`로 옮겼다(`git mv`). 메인 세션은 루트 CLAUDE.md를 시작할 때 적재하므로 받는 지시는 같다. 서브에이전트는 시작 적재를 `omitClaudeMd`로 건너뛰고, `.claude/` 아래에는 CLAUDE.md가 없으므로 하위 적재도 일어나지 않는다. 이동은 다음 재시작부터 효력을 낸다.
- gp-matrix 정의 12개에 `omitClaudeMd: true`를 더했다.
- `commit-harness`와 `memory-harness`의 정본 SKILL.md가 가리키던 경로를 루트 `CLAUDE.md`로 고쳤다. `skill-creator`와 `writing-skills`의 `references/원본_대조.md`는 과거 대조 때의 적재 목록을 적은 기록이라 고치지 않았다.
- layer-3 노드 다섯(L-0005, L-0009, L-0012, L-0016, L-0021)에는 옛 경로를 적은 첫 자리 앞에 정정 대기 줄을 남겼다. `기억/세칙.md`와 layer-1 노드의 옛 경로도 그대로 두었다. 세칙은 dream이 고치고, layer-1은 당시의 기록이기 때문이다.

## 남은 것과 주의

- **미러 게이트 예외**: skill 정본을 고쳤지만 `.agents` 사본은 재생성하지 않았다. 생성기 `build_skill_mirrors.py`는 skill 단위 재생성을 지원하지 않는다. 그래서 재생성하면 do-math 사본까지 다시 만들어, 실행 중인 연구 인스턴스에 검증 중인 변경을 배포한다. 이는 [[M-0658]]의 사용자 결정 (가)와 충돌한다. do-math 런 종료 뒤 사본을 한꺼번에 재생성할 때 이 두 skill도 맞춘다. 그때까지 commit-harness와 memory-harness의 `.agents` 사본은 옛 경로를 적는다.
- **효과 미확인**: 이 이동이 분류기 중단을 실제로 없애는지는 아직 확인하지 않았다. 다음 재시작 뒤 파견의 중단 여부로 확인한다.
- **gp-matrix의 행동 변화**: gp-matrix 에이전트는 이제 저장소 규범(작업 기억 참조, 작문 품질 계약 등)을 받지 않는다. 파견문이 필요한 규범을 직접 실어야 한다.
- **dream 제안 후보**: verify-rounds 파견문 템플릿과 `references/근거.md`에 이 세 경로를 기록한다. 서브에이전트 파견 일반의 주의로 L-0016에 승격한다.
