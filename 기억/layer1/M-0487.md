[[M-0486]] 뒤의 B72는 원래 3-C의 B-32 입력 분류, B-33 관찰 규칙 선택/결속, B-49 실행 파일 정규화에 기존 검사를 연결한다. 실제 현재 함수와 소비자 원문을 먼저 읽고, 이미 정본인 규칙을 별도 사본으로 다시 만들지 않았다. 제품 동작은 바꾸지 않고 기존 단위 검사를 보강하며 구조 순회의 현재 직접 소비 목록을 추가했다.

B-32의 정본은 task_contracts.unsupplied_task_inputs다. 제공된 기록·과제·도구·이름 있는 원자료와 알 수 없는 참조의 여섯 표본에 대해 제공 집합과 요청 집합의 모든 부분집합, 4,096조합을 확인한다. 실제 설정·원자료·과제에서 available_input_refs를 만들어 넘기는 기존 준비성/제출 경로는 그대로 유지한다. 이 작은 검사 공간은 참조 어휘 표본의 집합 조합이지 가능한 모든 문자열·별칭이나 실제 외부 자료 도착을 실행했다고 주장하지 않는다.

기대값은 요청에서 제공되지 않은 원소다. 계약을 저작할 때 source:future처럼 아직 도착하지 않은 원자료를 선행조건으로 적을 수 있지만, 준비성 판정은 같은 이름을 이미 제공된 것으로 세지 않는다. 두 분류의 차이를 잘못 없애지 않고 authoring 미제공 집합이 strict 집합의 부분집합임을 확인한다. 반복된 입력 참조는 같은 미제공 집합으로 계산되고, strict가 비어 있으면 authoring도 비어 있어야 한다. 새 검사에는 모델이나 저장 대역이 없다.

B-33은 실제 build_profiles가 만든 현재 모든 role/tier 프로필을 세 관찰 설정 모드마다 검사한다. 연구 수행은 설정한 모드를, 다른 작업 역할은 periodic을, 비작업/기계 역할은 deadline_only를 사용한다. 역할이 쓰는 설정 목록, 설정 검사와 tracker_config의 실제 프로필 결속, research_self_checks·checkpoint_expected와 실제 규칙을 확인한다. 연구 수행의 execution placeholder 규칙은 bind_task_rules로 실제 실행 ID에 결속하고 task_rules_from_execution으로 원 템플릿에 돌아오는지 확인한다. 다른 역할에게 수행의 자기 점검 규칙을 붙이지 않는다. 처음 존재하지 않는 counter_rule 도우미를 잘못 import해 kkl5yjsf에서 한 오류가 났고, 현재 정본 observation_rule 생산자로 교체했다. 제품이나 도우미 이름 별칭을 만들지 않았다. divf4_lw에서 수정한 사례가 통과했다.

B-49는 기존 요청 검사·능력 정체성·관찰 키의 PATH lookup 검사를 현재 ADAPTERS 전건으로 확장했다. Codex와 Claude 각각 실제 worker_options·worker_request_fields가 만든 입력에서 같은 실행 파일의 PATH 이름, 절대 경로와 dot 경로가 같은 정체성으로 계산된다. 다른 파일은 정확한 사유로 거부하고, 없는 선택적 파일은 정규화된 경로만 유지하며 strict는 FileNotFoundError를 낸다. 실제로 만들어진 로컬 파일을 사용하지만 그 파일을 실행하거나 원격 모델 능력을 검증했다고 주장하지 않는다. 기존 seed 불변 단언도 유지한다. 54d99xi8에서 두 공급자 순회가 통과했다.

구조의 직접 호출 목록은 executable_identity의 요청·어댑터·형식 검사 소비, unsupplied_task_inputs의 준비성·저작/제출·중앙 소비, observation_settings_errors와 tracker_config의 활성화·제출·실행 준비 소비를 포함한다. B-33의 설정과 결속은 같은 원래 한 쌍 안의 두 정본 행으로 기록한다. 일반 순회가 다루는 원래 쌍은 이제 여덟이며, 자연어 의미상 복제 전건의 부재를 AST만으로 증명하지 않는다. 7i0g_p_z에서 같은 정본 순회가 2.5초에 통과했다.
