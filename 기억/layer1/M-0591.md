새 연구를 막았던 사건의 조사와 사용자 요구 정정은 [[M-0590]]에 남겼다. 이번 제품 변경은 서비스가 수용한 정본 `.claude/skills/do-math/`, 공식 Codex 미러 `.agents/skills/do-math/`, 두 트리의 시험과 `docs/do-math/flow-repair-20261021/` 설계 문서를 한 단위로 보존한다. 역할·개정·질문, 의도 검사와 공통 제출 검사가 같은 상태와 스키마를 소비하므로 공유 파일의 최종 내용을 임의로 나눠 중간 계약을 커밋하지 않는다.

계약 검토의 실제 수정 필요와 근거 부족을 구분하고, AI 요청에는 근거 있는 예외 종결을 허용하면서 사용자 권위와 필요한 독립 승인은 보존했다. 운영 질문마다 어떤 요청(action)과 실행(execution)이 처리를 맡았는지, 어떤 근거로 해결하거나 기다리기로 했는지, 이후 어떤 판단이 필요한지를 연결해 기록한다. 전체 질문의 상태만으로 다시 실행하지 않고 해당 실행에 고정된 대상 범위와 새 해소 근거를 사용한다. 의도 검사도 근거 부족을 같은 원문 묶음의 대기와 후속 독립 검사로 연결하며, 실제 수정 필요의 재저작과 구별한다.

검사 문맥의 과제 의미 해시를 유지하고 사전·접수·적용에서 공통 선언 검사를 소비하도록 고쳤다. 제출에 빠진 해시와 실제 입력·사용 효력·권한의 변경은 같은 실패로 분류하지 않는다. 통합 과정에서는 검사 목록에서만 써야 하는 해시가 저장할 과제 내용에 섞이는 문제도 수정했다. 또한 필수 상위 요청을 보조하는 선택 작업을 변경 없음으로 끝냈을 때, 그 상위 요청의 필수 의무까지 해소되는 문제를 고쳤다. 공통 함수를 둔 사실만으로 공통 입력·결과·후속의 의미까지 일치하는 것은 아니라는 구체적 경계가 드러났다.

Windows 명령·패치 안내는 기존 공통 문서의 실제 지급 경로에 넣었다. Codex 목록 갱신 timeout은 원 stderr의 바이트 위치와 진단 종류를 보존하되 정상 완료와 실제 실패를 구별한다. 네트워크·공급자 내부 원인의 해결은 확인하지 않았다. 저장 복원은 payload 읽기를 묶어 같은 snapshot 비교에서 Git 호출 260→23회, 31.261→3.677초를 기록했고 복원된 내용도 일치했다. 이는 한 쌍의 측정이며 일반 성능 보장은 아니다.

최종 독립 검토가 학술 과제의 실제 지급 문서에 남아 있던 옛 재준비 지시를 발견해 네 정본 문서와 미러를 추가로 고쳤다. 후속 독립 검토는 현 코드 분기·실제 지급 전문·이전 실행 근거의 판본을 대조해 수용을 권고했고 manager가 완료로 게시했다. 개발의 여러 판본 최신 관측 4618 passed/1 skipped는 최종 판본의 한 번의 전체 회귀가 아니다. 새 실제 모델 연구·Lean·설치 복구 효능은 확인하지 않았다.

커밋 준비에서는 수용된 소스의 판본과 보관 기록을 대조하고 공식 미러 1394파일의 일치 및 probe_cli 구조 검사를 확인했다. `.claude/skills/do-math/scripts/이음새-정본.md` 끝의 중복 빈 줄만 정리하고 대응 미러를 다시 생성했다. 제품 시험의 같은 성공 확인과 실제 연구 운전을 반복하지 않았으며 원 연구는 계속 정지 상태다. 상세 결과와 검증 범위의 추적 진입점은 `docs/do-math/flow-repair-20261021/` 및 `.async/dm-flow-repair-20261021/plan.md`이고, 상세 원자료는 그 문서에 적힌 로컬 evidence에 있다.
