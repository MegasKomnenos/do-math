## 맥락

사용자가 종료된 전면 검증의 계약을 그대로 유지하고 `라운드_상한`만 8에서 12로 높여 이어가도록 지시했다. 기존 8라운드 장부·커밋을 보존하고 라운드 9의 현재 사본부터 재개했다. 라운드 9의 수리 후보 5건 가운데 세 심사자가 모두 승인한 4건을 세 산출물에 적용했다.

## 터득한 것

지도 컨텍스트에서 열린 티켓과 완료 전 계획을 현행 계약처럼 소유하던 문면을 제거했다. 구체 P vs NP 정의·문헌 명세는 각 자기 문서가 주제를 소유하고, 지도 컨텍스트는 현행 공유 계약만 남긴다.

비작업 하위 AI의 권위 있는 시작 원문을 닫기 위해 controller 상태에 `controller_role_requests`를 추가했다. 역할별 전용 portfolio·certification·operations 요청 ref가 없는 실행은 controller 요청의 request ID, 역할, `execution_id`, 논리 세션, output ref와 상태를 사용한다. 감독기는 역할별 요청 ref나 이 controller 요청에서 역할·실행·세션·output ref 전건이 일치할 때만 Job Object를 만든다.

관찰 응답 한계는 호출한 도구 manifest의 필수 ISO 8601 기간 `max_observation_response`가 정한다. 작업 실행 전에 필요한 도구 전건의 이 필드와 허용 여부를 검사하며, 값이 없거나 잘못되면 작업을 파견하지 않는다. 검토자 용어도 한 검토자의 `no_objection`과 검토 계획 전체가 끝난 뒤의 제안 동일성 승인을 구별하도록 고쳤다.

적용 조각이 지도 컨텍스트 파일 끝에 빈 줄을 하나 추가해 `git diff --check`가 실패했다. 의미 문면을 바꾸지 않고 빈 줄만 제거해 같은 검사를 통과했으며 신호 6의 자체 처리 근거를 장부에 기록했다.
