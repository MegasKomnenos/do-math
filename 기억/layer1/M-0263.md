## 맥락

사용자는 `docs/do-math/통합-설계.md`의 구현을 요청한 뒤 실행 경로를 `codex exec` CLI로 확정했다. 최초 작업자가 직접 Responses API를 선택해 키 설정을 요청했지만, 설계는 그 API를 필수로 지정하지 않았다. 사용자 교정 뒤 직접 API 경로를 폐기하고 기존 Codex 로그인으로 실행했다. 선택 가능한 구현 방법을 사용자에게 필수 전제로 전달한 판단을 교정한 사건이다.

작업 착수 시 설계에는 사용자 미커밋 보강이 있었고 v9 묶음은 그보다 오래된 본문 해시를 고정했다. 이번 구현은 제공된 설계를 보존하고 CLI 선택만 추가로 명시했다. 스키마·관계 검사 일부와 V01~V254·Q01~Q25 대응을 갱신했지만 D08 전체 동기화는 완료하지 않았다. 이전 검사 보고는 v9의 review 아래에 보존했다.

## 구현과 검증의 범위

CLI 어댑터는 실행별 request·prompt·출력 스키마 사본, 고정 CLI 인자, 환경 변수 허용 목록, JSONL·최종 응답과 worker 영수증을 사용한다. Windows Job이 루트를 생성 시점부터 소유하고 명시적 재개와 자식 포함 종료를 담당한다. Git 저장 원시는 단일 ref의 CAS와 불변 산출 묶음을, 예산 원시는 work·operations 분리와 고정 예약 집합의 합산·정산을 구현한다. 이 원시들이 아직 연구 인스턴스 운전과 역할 실행기로 연결되지는 않았다.

구현 회귀 50건, 오프라인 명세 79건과 실제 CLI의 일반 응답·구조화 응답·도구 실행·중도 취소를 검증했다. 종료 영수증을 추가한 판본은 실제 취소 사례로 다시 확인했다. 실제 보고와 원자료는 `docs/do-math/구현-검증-2026-09-14/`에 있다. 미러 생성 때 기존 verify-rounds 정본의 목록 파싱 수정 두 파일도 Codex 사본에 반영됐으며 해당 검사 34건을 통과했다.

## 검토에서 확인한 경계

원본 입력의 해시를 시작과 종료에만 비교하면 중간에 내용을 바꾸었다 복원하는 실행을 놓친다. private 사본과 worker가 실제 stdin으로 보낸 바이트의 해시를 함께 대조했다. 출력 스키마도 별도로 고정하고 영수증과 비교한다. 이 조치는 OS 접근 통제를 대신하지 않는다.

JSONL의 `turn.completed` 하나와 exit 0은 완전한 실행 증거가 아니다. thread·turn 시작과 사건 순서·유일성을 확인하고, 최종 응답·worker 영수증·로컬 종료 장벽을 별도로 대조했다. `codex_argv`의 자유로운 꼬리는 provider 설정을 삽입할 수 있어 단일 실행파일 경로와 고정 옵션으로 바꿨다.

Job handle 자체의 비상속과 주변 handle 전건의 비상속은 다른 조건이다. CreateProcess의 전체 handle 상속을 끄고 별도의 부모 Event를 자식이 신호할 수 없는지 검사했다. 검토자가 처음 사용한 `GetHandleInformation`의 숫자 비교는 자식에서 같은 숫자가 다른 handle로 재사용될 수 있어 정체성 증거에서 제외했다. 부모 객체의 실제 신호 상태가 더 직접적인 증거였다.

## 남은 작업과 환경 조건

현재 Windows 설정은 `unelevated`이고 작업 프로세스는 관리자 권한이 아니다. 명시한 입력만 읽는 native sandbox 프로필을 시험하자 `Restricted read-only access requires the elevated Windows sandbox backend`가 반환됐다. 검사 프로그램은 실행되지 않았으므로 그 결과를 접근 차단의 성공으로 세지 않는다. 로컬 계정·방화벽·전역 정책은 변경하지 않았다.

설계 17.1은 첫 어댑터 관문 실패를 해소하기 전에 연구 역할 전체를 만들지 않도록 정한다. 지원하는 Windows backend에서 접근 경계를 검증하고, CLI의 실제 내부 입력·압축·공급자 호출별 식별자와 원격 상태의 관찰 범위를 더 확인해야 한다. 현재 CLI의 turn 사용량과 로컬 종료를 공급자별 사용량·원격 종료로 대체하지 않는다.

시간창 예약 모집단의 완전성·효력, paused maintenance·recovery, 생성기 결속, 지식·관계의 전체 후속 연결, 연구 역할·Lean·전체 시간선과 워크스루도 남아 있다. 재개 좌표와 전건 완료 기준은 `docs/do-math/구현-진행.md`가 소유한다. 전체 구현 완료나 연구 활성화를 선언하지 않았다.
