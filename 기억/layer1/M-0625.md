## 맥락

사용자가 이번 공개 준비에서 작성한 문서를 수신자 관점에서 검토하라고 했다. 작성 맥락이 없는 판독자 둘을 두었다. 하나는 한국어를 읽지 못하는 GitHub 방문자이자 프로그램 심사자, 다른 하나는 이후 이 저장소에서 일할 세션이다. 그 관찰을 원자료와 대조해 결함을 판정했고, 이 커밋은 판정된 결함을 고친다.

- `README.md`
  - 에이전트로 저장소를 열기 전 알아야 할 설정을 실행 절 앞에 적었다. `.claude/settings.json`의 `bypassPermissions`, `.codex/config.toml`의 `danger-full-access`와 `approval_policy = "never"`, `.mcp.json`과 `.codex/config.toml`의 `C:/math` 고정 경로다. 이전 판본은 "이 저장소에서 Claude Code나 Codex를 열라"고 안내하면서 이 설정을 알리지 않았다. 설정 자체는 바꾸지 않았다.
  - 링크 문서 대부분이 한국어라는 안내를 첫머리로 옮기고 한국어 문서 링크에 (Korean)을 붙였다. 이전 판본은 실행 절차가 한국어 문서로 넘긴 뒤에야 언어를 알렸다.
  - research instance 정의, 동료가 받는 단위(세션 하나의 게시 산출)와 동료·검토가 받지 않는 것(작성자의 세션 폴더·로그), async-development가 개발에만 쓰였다는 점, jev-cli가 do-math와 무관하다는 점, 저장소 구조도의 `.mcp.json`·`AGENTS.md`, goal.md의 조건·허용 범위를 보탰다.
  - 별도 독해를 세 번 거쳤고 세 번째 판본은 지적 0건이다.
- 기억 노드(`기억/세칙_dream.md`의 메모리 본문 수정 원칙 중 사실 정정·명확화 범위)
  - M-0622: "계약 단계"를 "사용자와 정리 계획을 합의할 때"로 바꾸고, `임시/` 무시 범위를 실제 규칙(`/임시/*/*`는 하위 디렉토리의 내용만 무시)대로 고쳤다.
  - M-0623: 정의 없이 쓴 "ponytail 상시 모드", "재검토 트리거", "형제 스킬 참조 표기의 정본"에 원문 정의를 붙이고 백업 경로가 Git 밖의 로컬 보관임을 적었다.
  - M-0624: 색인 줄에만 있던 "관례 후보" 표지를 본문에도 적었다.

## 터득한 것

작성자가 자기 문서를 다시 읽으면 같은 지식이 빈틈을 메워 결함이 보이지 않는다. 이번에 독립 판독이 찾은 결함 가운데 권한 설정 미고지는 README를 쓸 때 설정 파일을 대조하지 않아 생겼고, 노드의 미정의 개념은 지운 스킬의 개념을 그 스킬이 사라진 뒤의 독자가 찾아볼 수 없다는 점을 놓쳐 생겼다. 지운 대상의 개념을 기록에 남길 때는 정의를 함께 남긴다(dream에서 묶을 후보).
