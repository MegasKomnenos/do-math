## Git 효과의 소유자와 서로 다른 판정 계약

[[M-0453]]의 Lean 등록/보존은 49eb1584로 확정했다. B38은 formal의 직접 Git subprocess와 CLI의 저장소 준비를 GitBackend 의미 포트로 옮긴다. mhf6uf93의 세 오류는 새 initialize_repository/repository_exists가 아직 없던 설계 기준선이며 기존 동작의 runtime 결함이라고 주장하지 않는다. 기존 코드를 읽어 원 환경·출력·예외 의미를 분리한 뒤 같은 계약을 실제 Git과 대역에 구현했다.

CLI의 생성/존재 확인은 live 환경을 상속하며 종료 코드만 읽는다. empty/비UTF 출력은 성공 판단을 바꾸지 않고 OS/subprocess 예외는 원형대로 전달한다. describe의 저장소 출력·object format·오류 계약으로 대신하지 않는다. missing/empty 자격 검사와 mkdir, initialize 뒤 existence 확인 순서는 CLI가 가진다. Git 대역도 최소 저장소 구조와 명시된 외부 기본 object format을 실제 파일에 보존하여 같은 세계에서 CLI init·읽기·저장·복원이 이어진다.

프로젝트 관찰은 project_repository_root/project_snapshot의 의미를 가진다. 불변 ProjectSnapshot은 repository_root, tree_oid, raw_diff, tracked_paths를 전달한다. root 출력이 비면 None이고 tree 실패는 None, diff는 원 bytes를 보존하며 index 실패는 RuntimeError다. UTF-8 해석과 각 읽기 전후의 중단 검사는 공유 정본을 사용한다. 프로젝트 외부 root와 포트 생략은 자동 fallback으로 살리지 않는다. root memo는 backend identity와 경로를 키로 사용하고 backend를 보유하여 unhashable/equal한 서로 다른 포트 세계를 합치지 않는다.

verify/inspect/identity/Host/engine/preview/setup의 호출부는 같은 필수 backend를 전달한다. formal._git을 제거하고 여러 모듈의 밑줄 stop 함수를 public check_stop 하나로 바꿨다. 프로세스 시작 정적 선언도 새 Git adapter 소유 함수로 옮겼다. 다른 봉인 수리나 Sim.restart의 별도 변경은 복사하지 않았다.

## 통합에서 발견한 배선과 준비 오류

_muo2zq5는 CLI/프로젝트 관련 47개 통과와 공통 Git 계약 여덟 오류였다. 새 configure_project/declare_project_diff/remove_project 준비를 실제·대역 구현체와 sha256 상속까지 연결한 g2vuyxj8의 34개가 통과했다. epmjsj7i의 실제 Git/CLI 경계 선택은 58개 통과와 활성화 두 실패였다. 하나는 Sim.process_state의 deepcopy import 누락이고, 하나는 adapter host metadata의 첫 platform.version이 cmd/ver를 실행하여 Git 감사에 섞인 것이었다. host 준비를 setUpModule로 분리하고 실제 생성/활성화 감사의 no-process 단언은 유지했다. repo/defaultformat 복원과 얕은 실제 설치의 자식 프로세스를 고친 y4q61ztl의 세 시험이 통과했다.
