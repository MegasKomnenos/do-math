[[M-0487]]의 B-32 분류는 정정한다. 그때 확인한 unsupplied_task_inputs는 참조 제공/저작 허용의 유효한 추가 규칙이지만 원래 B-32가 아니다. 원문 `조사/결함-B.md` 690행과 `조사/결함-범주.md` 3범주 검산표는 B-32를 prepare_role_input과 fit_context의 필수 입력 분류 차이라고 특정한다. 구조 행을 extra:task-input-supply로 보존하고 원래 B-32에는 role_direct_keys와 두 실제 소비자를 연결했다. 이전 원보고·역사 노드는 삭제하지 않고 작업판의 B72 연결 오류와 이번 B73의 교정을 명시한다.

실제 열 개 역할의 생산·포장 전건에서 카탈로그 원문을 다시 읽고 같은 입력을 fit_context에 caller mandatory 목록 없이 극단 예산으로 넘긴다. 역할 정본의 direct 키가 그대로 유지되고, 기록된 필수 목록과 정확히 같으며, 원래 prepare_role_input의 필수 목록에 포함돼야 한다. goal·policies·implementation_documents는 표시 사본이므로 direct 키에 없어야 한다. 단순히 정본에서 계산한 목록의 부분집합인지 확인하는 것만으로는 과도한 필수 분류를 놓칠 수 있어 정확한 집합과 독립 제외값을 추가했다.

원문 B-32의 정상 예산 반례도 보강했다. 현재 생산자의 governance와 action을 고정 입력으로 두고 세 큰 표시 사본을 넣는다. 모든 현재 역할에서 필수 데이터 크기보다 여유가 있는 예산을 주면 overflow가 없어야 하고, 세 표시 항목이 모두 참조로 축소돼야 한다. fit_context를 검사하는 순수 포장 입력이며 새 연구 목표를 승인·적용했다고 주장하지 않는다. h7gqsa2l의 실제 역할 전건과 34e7zukr의 정상 예산 반례가 통과했다.

C-13은 검토 실행 횟수 문제가 아니라 입력 바이트의 기록과 비교 값의 어긋남이다. `조사/결함-C.md` 369행은 전체 상한으로 덮어써 문맥 예산이 사라진 것을 설명한다. 기존 회귀 검사를 세 문맥 예산과 UTF-8 한글 payload로 확장하고, 실제 fit_context 호출 인자의 max_bytes가 기록된 context_budget_bytes와 같음을 관찰했다. 전체 profile limit, 고정 문서/스키마/프레이밍을 뺀 예산, 필수 바이트, 실제 렌더된 packed bytes의 관계를 각각 확인한다. 서로 다른 수치를 같은 한도로 읽지 않는다.

A-47은 생산자가 계산한 검토 제안 초과 처분을 소비자가 사용하지 않던 경로다. input_recovery.input_overflow_disposition을 정본으로 추가해 측정 기록의 suggested_disposition 계산과 call_engine의 적용 분기가 같은 정의를 사용하도록 교체했다. 현재 네 cause와 큰 허용 프로필 유무의 여덟 조합은 독립 기대값으로 검사한다. 기존 실제 큰 검토 제안 흐름은 actual prepare_role_input 반환의 overflow와 자원 처분 기록을 대조하며, 계획 후속 하나와 모델 미호출을 확인한다. 원문을 읽고 제안/필수 원자료의 초과를 공통 문서나 복원된 대화 과다와 구별하는 기존 단언은 유지한다. 공유 정본 문서에도 추가했다. 4023crse의 관련 네 사례가 통과했다.

C-15는 실제로 변경한 소유 Temp 실행 파일의 정체성을 사용한다. 원 파일이 정상임을 실제 identity checker로 확인하고, 변경 후 verify_lean이 rejected/trust_environment로 반환하며 compiler Job을 시작하지 않는지 확인한다. 같은 실제 오류 사실을 host 외부 이음매로 넘긴 게시 관문은 EnvironmentUnavailable을 내야 한다. 실제 중앙 형식 경로를 실행하면 formal_environment 대기로 가고 같은 결과를 연구 재평가 계획으로 보내지 않아야 한다. 공개 활성화·실제 후보 생산자·실제 저장/형식 소유자·worker 흐름을 사용한다. 전역 Python이나 공유 템플릿의 실행 파일을 바꾸지 않는다. zruw4u6b에서 통과했고 기존 명령/프로젝트 식별 거부에도 error_kind 단언을 유지했다.

구조 순회는 현재 원래 정본 열 쌍, 별도 참조 허용 추가 규칙을 유지하고 C-15의 알려진 두 생산 거부 표지와 실제 소유자의 분류 소비를 대조한다. 알려진 정의/직접 호출 목록과 특정 차분 경로의 증거이지, 모든 자연어 의미상 사본이 없다는 증거는 아니다. 처음 method source를 inspect.cleandoc으로 파싱해 hlb90v1e에서 들여쓰기 오류가 났고 textwrap.dedent로 교정했다. B-49는 Windows의 대문자·PATHEXT 생략형도 현재 공급자 전건에서 확인해, 이전 PATH/절대/dot 경로 검사만으로 그 원문 조건을 대신하지 않았다. lny90s5a에서 통과했다.

처음 관련 전건 140개가 5j_bz_vn에서 통과한 뒤, 원문 B-32의 정상 예산 반례와 정확한 필수 집합 단언을 보강했다. 마지막 같은 판본 n75t8all은 structure 46개·unit 24개·sim 63개·flows 8개, 합계 141개가 113.6초에 완결 통과했고 실행 중 변경은 없었다. 개별 초과 16개를 기록한다. 원보고는 추적된 `검증/2026-10-04-원문-규칙-정정/report.json`에 보존한다. 중간 Temp 보고는 로컬 보관이다. 이를 최종 전체 T2/flows·T3·변이·실환경·예산 완료로 바꾸지 않는다.

원래 열한 쌍은 이제 각 보고의 명시한 현재 공간에서 연결돼 있다. 이전 식별자 오배정 때문에 연결 건수만 보고 완료로 판단할 수 없다는 사실도 보존한다. 모든 입력 모집단·이후 사본의 최종 종료는 미확정으로 남기고 다음은 원문 5-A의 판정 근거 필드와 민감도 축으로 이동한다. 원래 19의무·61보존 지식·P2 12항목·여섯 부류·2단계 11의무와 모든 최종 전역 관문을 줄이지 않으며, 사용자 진행 문서·기존 미추적 교차 시험은 커밋에 포함하지 않는다.
