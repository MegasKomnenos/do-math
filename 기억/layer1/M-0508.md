[[M-0507]] 다음으로 11-B의 저장된 next_review 경로를 검증했다. 실제 ObservationTracker의 잘못된 실행 ID 반려가 최초 live operational_review를 열고, 실제 모델/worker/수신자가 continue와 next_review를 수락해 operational_continuation을 저장한다. 그 실제 disposition ID를 기한이 된 후속 호출의 observation_refs까지 비교한다. 대상 실행은 실제 수명 생산자와 Repository 검증으로 구성하며 처분 결과를 시험이 직접 조립하지 않는다.

예약 없음, 기한1초 전, 기한과 같은 시각, 기한1초 뒤, 대상 stopping, 대상 ended의6국면을 검사한다. 기한 일치/경과의 running 대상만 새 operational_review 모델과 worker 호출1회, 나머지는0회다. 후속 검토는 next_review=None으로 실제 수락돼 이후 유휴 owner 순회에서 시각·호출 수가 늘지 않고 저장본과 런타임이 같다. 호출 없는 경우 원래 continuation이 보존된다. 제품 코드는 변경하지 않았다.

첫 fixture는 sim.step의 새 run 진입을 반복하여 running 대상을 이전 owner의 잔여 실행으로 복구하고 stopping으로 바꿨다. 따라서 at/after에서 호출0이었으며 제품 버그가 아니다. 진단 메시지에서 선택적인 waiting_actions를 필수로 읽는 오류도 있었다. 현재 검사는 동일 owner의 실제 _run_parallel을 writer lock과 reload 아래에서 호출해 _controls/_upkeep/배정/ModelRunner/worker/수신을 실행한다. 복구 경로를 검증한다고 주장하지 않는다. 저장된 예약 원천과 tracker가 소유한 예약의 역할은 별도다.

수정 중 모델 응답기를 두 개의 같은 조건 규칙으로 등록한 것도 오류였다. ModelDouble은 첫 일치 규칙의 마지막 응답을 반복하므로 과거 next_review가 계속 재설정되어 끝나지 않는 검토 연쇄가 생겼다. PID2208의 명령이 해당 시험임을 확인해 그 실행만 명시 종료했고, 한 규칙의 첫 응답에 예약을, 다음 응답에 예약 없음을 순서대로 등록했다. 시간 상한으로 종료한 것이 아니며 timeout을 추가하지 않았다. 이 중단의 로컬 출력 f52gcv06은 완결 보고가 없는 Git 제외 자료이고 interrupted-fixture.json으로 사실과 원인을 추적한다. 다른 최초 실패3개 원보고도 검증/2026-10-05-예약-발동/에 보존한다.

교정 후 직접1개가32.3초에 통과했다. 관찰 발동 행렬, 실제 live review 처분의 sidecar 반려/수락, 구조 냄새 검사를 함께 실행한7개가115.4초에 통과했고 실행 중 소스 변경은 없다. 최종 report.json SHA256은 578bdbb92a36461faaf3d62d78139f6638c4dec52df93e781e7c6bdb56ea16c4다. 단언·입력 범위를 시간에 맞추려고 줄이지 않았다. 이번에는 새 제품 결함 원장 항목을 만들지 않았다.

11-B 전체는 계속 미완료다. B90 관찰 원천과 B91 저장 예약의 닫힌 범위만 작업판에 반영했다. 자기점검 수신 후속·반복 판정 충돌·실패 진단·계획 발동의 남김은 유지한다. 이미 검증한 예약을 다시 전수 감사하기보다 다음 원천의 실제 생산·대상·호출 연결을 처리한다. 전체 정상 기준선과 최종 fresh T3·전 함수 변이·외부/문서 검증도 남아 있다.
