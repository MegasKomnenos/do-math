[[M-0523]] 뒤 planning.schedule_reconsideration의 잔여 조건을 실제 저장·호출에 연결했다. KD-1918의 원인은 exhaustion_state.next_owner를 곧바로 호출 역할로 사용하던 분기다. next_owner가 research_plan인 미완료 평가의 missing input 대기는 자료가 없는데 실제 계획1회를 만들었고, operational_review인 경우에는 대상 실행이 없는 점검을 만들어 operational disposition has no execution target 예외로 owner가 중단됐다. 정상 저장한 깨진 JSON artifact를 착수 조건으로 가진 승인 과제도 운영 점검과 계획을 동시에 만들었다. _1n1w1zv에 세 실패 양상을 보존했다.

자료 대기의 다음 담당은 그 조건이 풀린 뒤의 담당이며, 그 문자열만으로 판단 대상이 생기지 않는다. 재고의 계획 발동을 선택 사건·반환 결과·재생성 조건 누락으로 명시했다. 주기/실제 재생성의 연구 준비는 그대로다. 준비성 평가 오류는 이미 task_condition_evaluation_error 사건을 기록해 일반 계획 배정으로 보내므로 이 함수에서 대상 없는 운영 점검을 추가하지 않는다. exhaustion_state의 오류 담당도 연구 계획으로 정정했다. 기존 Sim 검사의 평가 오류/비고갈 단언은 유지하고 next_owner 기대만 새 계약으로 바꿨다. 과제 착수조건과 연구 계획 계약에 역할/발동 구별을 반영했다.

실제 missing-input 평가는 연구 계획·운영 점검·연구 준비·사용자 네 next_owner 모두에서 두 owner pass의 호출0을 유지한다. 공개 source로 해당 자료가 도착하면 평가가 무효화되어 실제 계획1회가 수락되고 과제를 완료한다. artifact 조건 오류는 과제 오류가 계획 입력에 들어가고 계획1회가 수락되며 같은 owner의 추가 두 pass에서는 호출이 늘지 않는다. 반환 결과는 큐에 요청이 없어도 재고가 실제 평가 계획1회를 만들고 평가를 보존한다.

기한 없는 empty 영수증은 실제 수신 도메인 훅으로 기록한 저장 상태에서 검사했다. 동일 근거의 계획1회 수락, 추가 관찰/owner 재시작에서 추가0, 실제 새 source로 근거가 바뀌었을 때 다른 exhaustion_event_ref의 계획1회 수락을 확인한다. 이 장면은 새 빈 준비 wire 산출이 기한 없이 수락된다는 증거가 아니다. 새 산출은 submission의 regenerate_after 검증을 유지한다. 기존 도메인 방어 경로의 실제 소비 검증임을 시험 docstring과 작업판에 명시했다.

시험 작성 중 두 도구 계약을 잘못 기억했다. Sim.restart는 owner와 calls 포트를 다시 만들지만 ModelDouble.calls와 Jobs 관측 이력은 유지한다. 따라서 재시작 직후 누적 호출을0으로 기대하면 안 되며, 이전1에서 증가하지 않는지를 봐야 한다. 또 기본 ModelDouble.calls에는 execution_id가 없으므로 action.id로 실행을 찾는다. SubmissionModel의 호출 기록과 혼동하지 않는다. 이 두 fixture 실패는 별도 원보고로 보존했고 제품 결함으로 세지 않았다.

최종 구조48·단위34·Sim20·flow9의111개가67.8초에 통과했다. 주기 재고·실제 자료 변경/불변·초기 배정·정상 점유·빈 준비·수락 보류의 기존 흐름도 포함한다. 실행 중 소스 변경은 없다. 검증/2026-10-05-재고-대기조건/report.json과 작업판 B107이 원증거이며 SHA256도 기록했다. 부분 검사를 합산해 전체 일반 성공으로 쓰지 않는다.
