## 맥락

[[M-0714]]가 둘째 판을 처음 조립한 뒤, 사용자는 「검토 → 수리」 루프를 「지금까지 해온 방식대로 그냥 계속 쭈욱 반복」하라고 했고 상한을 20차로 두었다. 한 차례는 열다섯 독립 검토자(장별 열셋, 7장은 앞뒤 둘, 장부·구조표·의존지도 하나)가 이력을 모른 채 현행 장 파일을 읽어 수학·사실·정합·문면의 네 종류로 지적을 적고, 수리자가 지적마다 원문을 읽고 스스로 판정해 고치거나 두되 근거를 보고에 남기는 구조다. 5차 수리 뒤 사용자가 「네가 판정을 하기보다는 각 수리자들이 직접 살펴보고 판단을 하게 해」라고 정한 뒤로 세션은 판정 문서를 쓰지 않고 공통 안내의 4절에 「임자와 주의」 메모만 적는다. 이 커밋은 6차부터 20차까지의 루프와 그 사이에 끼어든 외부 피드백 묶음 넷(의존성 지도 세션의 「원고의 일」 52건 포함), theorem-W 상수를 두기로 한 사용자 결정 128, 계산 세션이 돌린 재계산 셋(임계 창 44상자 전수 재실행, 정수 인증의 Python 9000열 비트 대조, 모멘트 판정 1500열)의 반영을 담는다. 결정록은 `대조v2/장부_설계_세션결정.md`의 105–131, 번역 쪽 전달은 `대조v2/수학검사2/번역측_전달_1115.md`의 1–24절, 세션 상태는 `임시/주차함수_증명/작업_장부.md`가 정본이다. 커밋 직후 사용자는 외부 검토 일곱 묶음(증명 중복 제거와 컴퓨터 보조 계산 최소화)을 심사·수리하라는 큰 지시를 내렸고, 그 작업은 이 커밋 뒤에 시작한다.

## 터득한 것

- **차례가 거듭될수록 수학 지적은 오독으로 수렴한다.** 13차 29, 14차 19, 15차 22, 16차 16, 17차 11, 18차 19, 19차 19, 20차 14의 지적 가운데 마지막 세 차례의 「수학」 지적은 모두 검토자의 오독이었다(18차 Petersson Theorem 2.1은 PDF 추출본의 프라임 글리프 탈락, 20차 5B 330행은 $\theta=zY^{-1/3}$의 눈금 혼동). 남는 것은 서술·글자·등재·규약의 일이며, 그 가운데도 「진술이 아니라 증명 안 문장에만 있는 사실을 인용」하는 꼴(20차 N7b의 $\kappa_N\ge0.307$)이 여러 차례 나왔다. 재사용되는 사실은 진술로 올려야 인용이 안정된다.
- **검토 스크립트가 표의 셀을 쪼개면 다른 행의 값을 읽는다.** 19차 M11은 부록 A 기호 셀을 쉼표에서 쪼개 「핵」을 뽑는 스크립트로 세 기호의 정의 절이 틀렸다고 적었으나 장부는 현행대로 맞았다. 20차 파견문에 「표 셀을 기계로 쪼갠 값은 원문 행으로 확인」 한 문장을 더했다. 같은 뿌리의 교훈이 18차의 글리프 탈락(PDF 추출본은 다른 추출이나 쪽 그림으로 교차 확인)이다.
- **되풀이 사안은 앞 차례 판단 기록을 읽혀 새 사실이 있을 때만 바꾸게 한다.** 의존 목록의 셈법(머리에 연쇄로만 닿는 입력을 적을지)은 5·11·19·20차에 네 번 올라왔고 매번 둔다는 결론이었으나, 20차 Y8은 「머리에 더하면 둘째 증명이 특정 계산 위에 선다는 거짓 선언이 된다」는 새 근거를 찾았다. 11.4절 GKP 행의 「8.2절」은 다섯 번째 올라와 둔 사안이다. 반대로 5A의 $\mathcal Q_{<k}$는 네 차례 「계산 글자」로만 보다가 19차에 4.3·7.4절의 $\mathcal E_{<k}$와 같은 급수임이 드러나 바뀌었다. 되풀이 자체는 둠의 근거도 바꿈의 근거도 아니다.
- **글자 충돌은 여유 글자 목록으로 풀리지 않는다.** Green 응답 $\mathcal G_{z,i,n}$(2.7절 정의, 5A가 14회 씀)은 전역 조건에 들지만 10장 전역 $\mathcal G_y(q)$와 (바탕 글자, 글자체)가 겹쳐 결정 55가 국소로 두었다. 19차 XG는 10장 쪽을 $\mathfrak M_y(q)$로 바꾸고 Green 응답을 전역으로 올렸는데, 10장 여유 필기체 스물 가운데 1.2 전체와 겹치지 않는 것은 셋뿐이고 셋 다 다른 충돌을 낳았다. 장부 5절의 「여유 글자」는 국소용 목록이라 새 전역 글자 선택에는 모자라며, 앞으로 새 전역은 로마체 이름이 현실적이다.
- **계산 세션의 「독립 재계산」 문장은 기록 본문을 그대로 옮기면 틀릴 수 있다.** D.central-gap-integer의 「$k=4$~$40$ … 비트 단위로 같다」는 기록 본문(560·729행)의 문장인데, 같은 기록의 `evidence/peer/README.md`는 그것이 두 C 빌드 사이의 동일이고 Python 대조는 일곱 $k$뿐임을 밝혔다. 기록 본문도 혼동할 수 있으므로 자료 파일(`pyref_compare.json`)이 정본이다.
- **「상자별 소요 시간의 합」 같은 집계는 어느 실행을 센 것인지 밝혀야 한다.** D.critical-window-rig의 16.9시간은 본 실행 44개만 센 값이었고 요약 파일의 합계는 첫 셀 재인증 다섯을 더한 17.5시간이었다. 사용자의 「계산 상태 확인 후 반영」에서 바로잡았다.
- **자료 묶음의 SHA 표는 처음부터 선택적이었다.** 세션 재계산 폴더 전체를 재귀로 보면 표에 없는 파일이 716개(열별 결과 JSON 501, 상자 캐시 44개 88MB, 로그·바이너리)이고, 표는 항목이 이름을 드는 코드·요약·인증서만 담는 정책이었다. 등록 스크립트의 「진행 중 폴더 건너뜀」은 계산이 끝나 없앴고, 대량 등록은 사용자 결정 자리로 남겼다.
- **배경 검산을 띄운 검토자는 그 검산이 끝나도 스스로 돌아오지 않을 수 있다.** 20차 N7a는 보고 여섯 절을 다 쓰고 배경 스크립트를 기다리며 멈췄고, 사용자가 두 번 재개시킨 뒤에야 돌아왔다. 산출 파일이 완결이면 파일로 판독하고 기다리지 않는 것이 맞다(CLAUDE.md의 재개 회수 규칙과 같은 뿌리).
- **PDF 렌더는 열다섯 에이전트와 함께 돌리면 Chromium이 `Page.pdf: Protocol error (IO.read)`로 끊길 수 있다.** 작업자 하나로 다시 돌려 성공했다. 수식 오류 0은 두 번 모두 같았다.
- **Bash 도구의 heredoc은 역슬래시 한 겹을 벗긴다.** `\\mathcal`을 적으면 Python 소스에는 `\mathcal`이 남아 SyntaxWarning과 함께 그대로 문자열이 되어 결과는 맞지만, `\n`·`\t` 같은 것은 실제 제어 문자가 된다. 패치 스크립트는 Write 도구로 쓴다([[M-0715]]와 같은 교훈이 두 번 더 실측됨).
- **Git Bash의 `grep -c $'\r'`는 LF 파일에서도 줄 수를 낸다.** 세 작업자가 「CRLF」라고 보고했으나 파이썬 바이트 셈으로 모두 CR 0이었다. 줄 끝은 파이썬으로 센다.

## 작업 너머 시사점

- dream에서 묶을 후보: 「판정 없는 수리」는 세션이 지적을 판정하는 대신 작업자에게 원문·선례·선호를 모두 주고 사안별 판단을 맡기는 방식이다. 20차례 동안 세션의 몫은 배정 메모, 여러 작업자에 걸친 결정의 전달, 생성물 재생성, 그리고 작업자가 손댈 수 없는 생성기·묶음 위생이었다. [[L-0016]]의 위임 파이프라인(공유 파생물의 단일 소유, 뒤 단계 작업자)과 이어진다.
- dream 제안 후보: 검토자 오독의 반복 유형(추출본 글리프 탈락, 표 셀 쪼개기, 진술과 증명 안 사실의 혼동, 눈금 혼동, 「비슷한 꼴」을 「같은 것」으로 읽기)을 [[L-0001]]의 검증 사각 목록이나 [[L-0005]]의 판단 편향 항목에 올릴 만하다.
- 경고 후보: 열 개 넘는 에이전트와 동시에 Chromium 인쇄를 돌리지 않는다([[L-0004]] 렌더링 절).
