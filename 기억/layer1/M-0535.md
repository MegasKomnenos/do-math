[[M-0534]]에서 확인한 R17의 조건 반례를 새 문맥 한정 작업으로 수리했다. 이전 작업자는 모델 지원 오류로 시작 전에 종료했고, 실제 HEAD/diff/실행 프로세스를 확인한 뒤 새 작업자를 배정했다. 실패한 작업자의 의도를 구현 완료로 취급하지 않았다.

console_python은 pythonw.exe의 같은 폴더에 python.exe가 없으면 원래 GUI 실행기를 반환했다. 이 값은 PowerShell에서 기다림과 출력을 요구하는 작업자/사람 명령으로 쓰이므로 정본 설명과 충돌했다. 이제 FileNotFoundError(errno.ENOENT, filename=형제 경로)로 거부한다. 임의 PATH의 다른 Python을 찾아 설치 판본을 바꾸지 않는다. 정상 콘솔 실행기와 형제가 있는 pythonw는 기존 선택을 유지한다.

install_tools는 실행기 확인을 진입 첫 단계로 옮겼다. 실패 때 context 변경이나 설치 파일이 일부 남지 않으며 세 지급 명령은 한 번 확인한 interpreter를 공유한다. 예약 등록이 이미 실패한 CLI에서는 두 번째 실행기 오류가 초기화/설정 성공 영수증과 원예약 오류를 덮으면 안 된다. _schedule_failure는 저장된 결과에 status=failed/error/reconcile=null을 먼저 넣고, 실행기 조회 오류는 reconcile_error에 별도 보존한다. 정상 조건의 재조정 명령은 기존대로 생성한다. 실제 initialize와 configure의 생산/저장 결과를 관찰해 보존 여부를 단언했다.

수정 전4yviykas는7개 중3통과/4실패로 설치 미거부와 CLI 직접 보고/init/config의 GUI명령 지급을 재현했다. 수정 후8yaqu8pz에서 설치 거부는 통과했고 나머지3개는 reconcile=null과결과보존을 확인한 뒤 Windows OSError의 filename repr을 str 경로와 비교해 실패했다. 이는 시험 문자열 표현 오류라 별도로 보존하고 교정했다. 해당3개6xbk7d_v 통과 후 관련20개4qa2_4rr가26.2초에 모두 통과했다. 각 실행의 changed_during_run은 비어 있다. 원보고 네 개를 검증/2026-10-05-콘솔-실행기-부재에 바이트 그대로 보존했다. KD-1921은 이 반례와 회귀 시험으로 폐쇄했으며 스킬 구조 탐침도 verified로 보고됐다.

수정은 제품3파일·기존시험3파일·원장·공유정본·CLI계약·README에 한정했다. 정상 실제 pythonw→PowerShell 경계는B117 원증거를 재사용하며 다시 구축하지 않았다. B85 창억제검사, 지급4생산자 검토, B117 실제 경계, 이번 형제부재/결과보존으로9-A를 구현 검토 완료·최종 실행 대기로 옮겼다. 이는전체최종판본통과가아니다. 원래 전체 일반/fresh T3/극단변이·정상기준/T4·T5 및 다른 요구는 유지한다. 다음은 이미 배정한 record_map의 AST 결속 하나를 실제 반환으로 교체하는 독립 변경이다.
