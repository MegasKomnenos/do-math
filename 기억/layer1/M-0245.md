사용자 세 기준의 CLI 재검토에서 DBLP Trier500의 실행 가능한 해법이 확인됐다. 주 세션은 그 수리를 검토하고 원본에 통합했으며, 검토 중 추가로 발견한 로컬 100건 제한과 짧은 원 응답의 조기 종료도 수리했다. 최종 원본 전체 523개 검사, 검색·7형식 내보내기와 추출 13호출,1,000개 고유 문헌 회수·추출이 통과했다. 원본에 통합된 파견 수리는 현재 Springer와 DBLP 두 과제이며 다른 과제의 반환 검토와 통합은 계속 남는다.

CLI의 N14 원 요청 두 개는 같은 GET, 같은 host/path, 같은 해석된 q/f/h/format, 같은 헤더였다. 공백을 +로 표현한 요청은 500 HTML 30,529바이트, %20 요청은 200 JSON 1,706바이트와 2건을 반환했다. 추가 3초 대기만 하고 +를 유지한 별도 실행도 같은 500이었다. 주 세션은 실제 요청·응답 파일과 API 실행 화면을 대조했다. 원본은 urlencode의 quote_via=quote를 사용해 공백을%20, 실제 plus를%2B로 보존한다. 이는 두 표현 중 하나가 일반 URI 규격상 언제나 잘못됐다는 판정이 아니라 관측한 서비스 동작에 맞춘 직렬화 수리다. 공식 Dagstuhl 문헌 링크도 source 경계 안의 입력으로 받되 실제 조회는 canonical DBLP에서 수행한다.

작업자는 격리 사본에 없는 research catalog parser 때문에 BibTeX/RIS 추출이 실패하자 별도의 61줄 native parser와 scholarly.py 분기를 제안했다. 주 세션의 원본에서 동일 구조화 추출·문헌 정체성 회귀가 기존 parser로 통과했고 새 SDK도 7형식을 모두 추출했다. 따라서 이 두 parser 변경은 통합하지 않았다. 사본의 의존성 경로 문제와 원본 기능 결함을 구별해 최소한의 수정만 남겼다.

원본 통합 검토 중 공식 DBLP API 설명은 h 최대 1,000을 명시하지만 DBLP가 APIAdapter.max_limit=100을 물려받고 있음을 확인했다. 실제 새 SDK에서 algebra·limit101이 원격 호출 전에 invalid_range/1..100으로 끝났고, 주 세션이 실제 MCP 실행 도구의 직전·직후·안정 화면을 읽었다. root-user-criteria-20260913T0715Z/dblp/limit-20260913T074314Z가 이 재현이다. 상한 1,000만 수정한 뒤에는 h101과 h1000 모두 원 서버의 computed100·sent100이 반환됐다. 이를 1,000건 성공으로 계산하지 않았다.

DBLP search는 원 @first·@sent·total·문헌 key를 검사하면서 실제 수신 수만큼 f를 진행해 요청 범위를 채운다. 합계 변경·중복 key·범위 불일치·빈 중간 응답을 구별하고, 뒤 페이지 실패 때 기회수 prefix와 오류·next를 partial로 보존한다. native_pages와 기록 artifact의 evidence_refs가 모든 원 응답을 연결하며, 다중 native export는 원 JSON 파일을 각각 반환한다. 검색 중 429가 나면 추가 원격 citation export를 보내지 않고 받은 레코드와 해당 오류를 보존한다.

실제 101건은 2개 응답·101개 고유 key·추출 101건으로 성공했다.1,000건의 3초 대조는 600건 뒤 429였다. limit-20260913T075640Z의 입력 전·partial 직후·안정 화면을 직접 읽어 요청 1000, 수신 600, 다음 600, rate_limited와 Retry-After 부재를 확인했다.6.1초 간격의 진단 대조는 1,000건에 성공했고 원 HTTP 추적 12개에 실패가 없었다. 원본 기본 간격을 6.1초로 적용한 limit-20260913T080745Z도 1,000건·고유 key1,000·추출 1,000이었다. 이 간격은 클라이언트의 실측 기반 선택이며 고정 서버 한도나 429가 없다는 보장이 아니다. 이후 같은 최종 원본의 sdk-runs/20260913T081151903039Z는 검색 창 0·1·3과 7형식 각각의 추출을 포함한 13호출을 모두 통과했다.

사본 파견 폴더와 구별한 주 세션의 전용 실행 루트는 .credentials/scholarly-mcp/probes/root-user-criteria-20260913T0715Z/dblp다. 원본 server.py와 빈 전용 credential-root를 사용했고, 진단 도구 화면은 DBLP 웹 화면으로 표시하지 않았다. 정제 결과는 data/access-research/user-criteria-dblp/root-sdk.json과 root-limits.json에 있다. 실제 source500과 local range 오류, source의 짧은 페이지, rate 제한, 사본 의존성 오류를 각각 구별했다.

앞선 Springer 커밋의 좁은 자격값 검사는 일반 공개 검색어가 저장된 localStorage:last_publications_query까지 비밀값으로 수집해 VALIDATION.md와 registry.py를 일치로 표시했다. Python 검사 뒤의 git diff 명령이 종료코드를 덮어써 커밋 전에 실패 코드가 전달되지 않는 운영 실수도 있었다. 확인 결과 일치는 부모 커밋에 같은 횟수로 존재한 일반 검색어였고 추가된 줄에는 없었다. 해당 공개 필드를 제외하고 커밋 10개 파일을 126개 현재 자격·브라우저 값과 다시 대조해 일치 0을 확인했다. 원 기록은 user-criteria-springer/commit-check.json이다. 이후 검사는 다음 명령으로 종료코드를 덮지 않고 결과를 확인한 뒤 커밋한다. 이 검사는 전체 역사 증거의 비밀값 스캔 통과를 주장하지 않는다.
