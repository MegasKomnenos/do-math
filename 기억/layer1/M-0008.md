# 검증런 2.7.10.59.1 완료: 두 라운드, 결정 반영 결손 5건 수리, 라운드 커밋 절차의 메모리 노드 결합 누락

## 맥락

M-0007이 기록한 0단계 기준선 확립 뒤, verify-rounds SKILL.md 절차를 그대로 따라 검증런 `2.7.10.59.1`(파견문: `.sdd/dag/pvsnp-탐사-1/행/2.d/7.d/10.d/59.d/1.md`)을 완료했다. 검증 대상은 공유 불변식·판정표·파견표와 행 4~13(L02~L06 재판독 작업자·직후 검증런)이다. 잣대는 결정 `2.7.10-첫재판독.md`의 확정 문구 두 항(L01 내용 기준의 적용, 분량·밀도 비례 규범)이다.

파라미터는 파견문이 직접 지정했다: 수리_기수 4(전원 관점 담당: 운전성·충족성·정합성·승인 대조), 심사_기수 3, 심사_정족 3, 라운드_하한 1, 라운드_상한 2, 모델_프리셋 `codex-full`(수리 gpt-5.6-terra high · 병합 gpt-5.6-terra low · 심사 gpt-5.6-terra medium, codex CLI로 파견). 두 라운드 모두 §8 상신 신호를 감지하지 않았다.

라운드 1: 항목 3건 제기, 승인 2건(작업자 완료 기준이 결정 확정 문구를 공통 요건으로 명시하지 않은 결손, `59.d/불변식.md`의 L17 작업자 수가 파견표와 어긋난 결손) 적용, 1건 기각(심사자가 관문 1 미달로 판정: 기준 인용이 지정 기준 원문 밖의 파일을 가리켰다). 라운드 2: 항목 4건 제기(교차 간선으로 3건이 묶음 R2-M1으로 병합), 전건 승인·적용(작업 행의 상태 완료 조건 결손 셋과 검산 명령 결손 하나). 두 라운드 모두 적용 뒤 `dag_check.py --table 파견표.md`가 exit 0 무발견을 냈다.

## 터득한 것

- codex CLI 병행 파견 절차(§5.6 codex 일반 실행 절차)는 `wait_outputs.py`로 반환 파일 크기를 폴링하는 방식이 안정적으로 작동했다. PATH에서 `WindowsApps`를 빼는 사전 조치를 두 라운드, 수리·병합·심사 전 단계에서 반복했고 문제가 없었다.
- `심사집계`의 `--보관출처` 인자는 어휘 제약(글자·숫자·점·밑줄·하이픈)이 있어 한글을 포함한 값(`검증런-2.7.10.59.1`)이 exit 2로 거부됐다. ASCII만 쓰는 값(`verify-rounds-2.7.10.59.1`)으로 바꿔 통과시켰다. 이 제약은 SKILL.md 본문에 명시되어 있었으나(§7 심사 5항) 처음에는 놓쳤다.
- Bash 도구에서 `cd`로 디렉토리를 이동한 뒤 그 상태가 다음 호출까지 지속되지 않는다는 세션 규칙(각 호출이 독립 셸)을 실측으로 재확인했다. `cd` 뒤 상대 경로로 `vr.py`를 호출했다가 스크립트 경로 자체가 깨져 실패했다. 이후 모든 호출을 저장소 루트 절대 참조 또는 매 호출 `cd /c/math` 명시로 통일했다.
- 파견문 슬롯을 라운드마다 새로 채울 때 `sed`의 백슬래시 포함 Windows 경로 치환이 구분자 충돌로 실패했다. Python 문자열 치환(`str.replace`)으로 바꾸니 안정적이었다. 첫 시도에서 이스케이프 처리를 잘못해 깨진 파일을 만들었고, 발견 즉시(파일 grep 확인) 재생성해 바로잡았다.

## 작업 너머 시사점

이 런은 verify-rounds SKILL.md의 라운드 커밋 절차(§7 「라운드 커밋」)를 그대로 따라 커밋 셋(라운드 1 결산, 라운드 2 결산+종료보고, 기각 보관 산출)을 냈다. 그런데 이 저장소의 commit-harness 정본은 "모든 작업 커밋은 정확히 하나의 layer-1 메모리 노드를 같은 커밋에 포함한다"는 결합 불변식을 세운다. verify-rounds의 라운드 커밋 절차는 이 결합을 언급하지 않으며, 스테이징 범위를 산출물·동결.md·장부.md(·종료 라운드는 종료보고.md)로 닫힌 형태로 정해 메모리 노드 파일을 포함할 여지를 주지 않는다. 이 세션은 그 절차를 원문 그대로 따랐고 그 결과 세 커밋 모두 메모리 노드 없이 나갔다. 이 노드(M-0008)가 사후에 그 세 커밋을 소급 결합한다.

dream에서 검토할 후보: verify-rounds SKILL.md의 라운드 커밋 스테이징 범위(§7)와 commit-harness의 결합 불변식이 절차 차원에서 충돌한다. 둘 중 하나를 정본으로 삼거나(예: verify-rounds 라운드 커밋을 결합 불변식의 명시적 예외로 GLOSSARY/근거 문서에 등재하거나, 라운드 커밋 스테이징 범위에 메모리 노드 슬롯을 추가하거나) 두 스킬 사이의 우선순위를 명시해야 한다. L-0016(위임 파이프라인 운영)·L-0006(기억 하네스 운영)이 이 연결의 후보 노드다.
