## 맥락

[[M-0602]]에 이은 같은 verify-rounds 런이다. Opus 5.5 수리 4기가 정본 15파일을 다시 읽어 17건을 냈고, 병합 뒤 14건을 Astra 심사 3기가 판정했다. 수리 5·무처분 6·기각 3으로 확정됐다. 공식 반영은 5항목이며 장부의 구성 행 기준은 7건이다. 사용자가 위임한 직접 재검토에서 기각·무처분 9건 중 8건을 보완하거나 정리하고 1건은 유지했다.

## 터득한 것

- 연구 현황이 작성 중인 계획 자신의 기록 ID를 요구했지만 실행기는 산출 재검사 뒤 ID를 발급한다. 수리는 문서 표기만으로 닫았다. 작성 중에는 ‘이번 계획’과 요청 배열·위치를 적고, 다음 계획이 previous_plan으로 실제 ID·키를 복원해 갱신한다. 조각의 의존 구간 미달로 기각된 제안을 직접 편집으로 회수했으며 ID 선발급 장치는 더하지 않았다.
- 추가 검토를 붙이는 것만으로 상충은 없어지지 않는다. 앞선 사용자 결정에 맞춰 틀린 검토의 전체 대체를 요청하는 경로와, 형식 증명을 면제받은 경우 목표 검토를 막지 않는 조건을 같은 요청 문단에 연결했다.
- 설정 표 삭제안은 계획의 단일 실행 한정을 잃어 기각됐다. 메인은 그 한정을 준비 단계에 직접 보존한 뒤 표를 지웠다. 원문이 이미 Lean 컴파일 주체를 세션으로 적는데 공식 검사기가 실행한다고 주장한 cwd 지적은 기각을 유지했다.
- 내부 검사 메서드 색인, 허용 공리와 대체 읽기의 반복, 실패 사건에 다시 붙인 검토 입력 규칙을 줄였다. 운영 안내는 전면 재배치하지 않고 명령 예시 네 블록과 목표 예시의 반복을 지웠다. 고유한 초기화·입력 소비·기동·프로세스 종료 계약과 기존 절 참조는 보존했다.
- 항목별 심사와 별도로 8개 Markdown의 전체 독해를 Astra로 두 번 수행했다. 첫 독해의 네 지적은 자동 검토 요청 생성과 파견 우선순위, 입력 동률 순서, 이력 참조와 수학 의존의 구분, 잘못된 결함 지적 뒤 의존 결과의 인정 회복이었다. 둘째 독해는 halted 중 기존 실행기 종료를 기다릴 순서, Claude 한도 필드의 생략·null, reason에 붙는 기동 오류, 다른 부정 검토가 남은 경우, 초기 Lean 정의 의무의 목표 범위를 짚었다. 코드·기존 사용자 조건으로 결정되는 문면만 고쳤다. 후속 라운드가 반영된 뒤 최종 판본을 다시 독해한다.

전체 시험 20개가 25.163초에 통과했고 미러 185파일과 diff 공백 검사도 통과했다. 제품 코드 변경은 없고, 정본은 시작 대비 85행 줄었다. 완료 뒤 새 산출 때문에 완료 상태를 자동으로 다시 열지 않는 정책, 전체 검토 대체, 이미 실행 중인 요청의 옛 지시 수행은 기존 확정 구조로 유지했다. 독해자의 불확실성을 모두 새 기능 요구로 바꾸지 않았다.
