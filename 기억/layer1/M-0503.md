[[M-0502]] 뒤 B86에서 실제 외부 자료가 없는 9-B 공백을 처리했다. Codex CLI 0.160.0과 Claude Code 2.1.289를 실제 ModelRunner, Windows Job, worker로 호출했다. 로컬 기록용 호출자는 probe_cli.run_case에 timeout=None을 주었으며 원요청의 max_runtime_seconds도 null이다. CLI의 강제 시간 상한을 녹화를 위해 늘리거나 재도입하지 않았다. 이 호출자는 .skill-workspace/test-restructure-2026-09-29/finish/capture-cli-corpus-b86.py에 있는 Git 제외 로컬 자료다. 지속 근거는 추적한 말뭉치와 아래 원보고다.

Codex 최초 files 탐침은 실행되자마자 HTTP400 invalid_json_schema로 거부됐다. 탐침의 status/nonce에는 const만, phase에는 enum만 있어 명시적인 type이 없었다. 문자열 타입을 명시한 뒤 같은 공개 탐침을 다시 호출하니 구조화 응답, nonce 파일, checkpoint, 실제 로컬 종료 장벽이 모두 통과했다. Claude files 탐침도 네 조건을 모두 통과했다. 실제 Claude 응답의 modelUsage는 claude-opus-5-5였다. 공급자별 요청은 Codex 두 번과 Claude 두 번으로 제한했고, 실제 연구 인스턴스나 배포 설정은 변경하지 않았다.

최초 Codex 거부 출력을 재생하자 별도 제품 결함 KD-1910이 드러났다. parse_jsonl은 error를 알려진 사건으로 받으면서 turn.started와 terminal 사이에는 item 사건만 허용했다. 실제 error 다음 turn.failed의 완결된 거부 프로토콜을 잘못된 순서로 분류했다. 실제 원자료의 실패 재현 fzcpndvs를 보존하고, failed이며 completed가 아닌 호출에서 error를 허용했다. 성공으로 승격하지 않으며 종료 누락·성공 terminal로 바꾼 음성 사례는 계속 불완전으로 판정한다. 원장에는 닫힌 재현으로 연결했다.

네 실제 스트림을 추가하여 말뭉치는 일곱 항목, Codex/Claude/Lean 세 종류가 됐다. 각 새 스트림은 원본 바이트·SHA256·CLI 판본·실제 판정과 출처를 보존한다. 현재 두 공급자 모두에 판본이 맞는 원자료가 있어야 하는 구조 검사를 넣고 Claude 구조화 산출·모델·결과 구간·한도 통지·백그라운드 사건 재생을 연결했다. 기존 판본 미기록 Codex 자료를 현재 판본으로 소급 표시하지 않았다.

Claude 두 번째 background 탐침은 실제 시작, 완료 알림, nonce 파일과 최종 구조화 응답을 확인했지만 actual_wait_tool 조건은 실패했다. init에 TaskOutput이 없고 실제 ToolSearch(select:TaskOutput)는 No matching deferred tools found를 반환했다. 모델은 Bash로 파일을 확인하고 끝냈다. 이 원보고를 성공으로 다시 쓰지 않았다. 백그라운드 스트림 자체의 재생은 성공이며, TaskOutput 이름을 강제하는 탐침의 현행 계약 교정과 최소 실환경 완료 판단은 다음 작업이다. 실제 녹화 성공과 모든 T5 조건 충족은 다르다.

관련 95개가 25.8초에 통과했다. 이후 백그라운드 원자료를 추가하고 재생/말뭉치/대역 계약 12개가 0.1초에 통과했으며, 마지막 원장 연결 뒤 원장·재생·Codex 음성 검증 7개가 3.1초에 통과했다. 세 보고에 실행 중 소스 변경은 없다. 서로 다른 선택과 판본을 합산해 전체 일반 통과로 세지 않는다. 추적 원보고는 docs/do-math/시험-재편-2026-09-29/검증/2026-10-04-공급자-실출력/에 있으며 Codex 최초 거부와 Claude background 실패도 보존한다.

9-B 전체는 아직 닫지 않았다. 여러 결과 구간·종료 정리·실제 한도 거부, 예약 조회·설정 파일·능력 탐침·역할 스키마·Lean 경계 및 현재 대역과의 대응이 남아 있다. 11-B와 13-C의 별도 요구도 유지한다. 정상 자료를 합성해 실제 녹화로 표시하거나 provider 파일 탐침만으로 전체 T4/T5를 통과시키지 않는다.
