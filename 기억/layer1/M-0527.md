[[M-0526]] 뒤 13-C 원문을 다시 확인했다. 요구는 운전/역할 문서의 명령·인자·필드·정책이 코드에 존재하고, 한 번에 읽게 하는 필수 문서의 바이트 합이 실제 운전 도구 한도 안에 드는 것이다. 기존 doc-field-census-b84.json은 무공간 underscore 후보1766곳의 어휘 목록이지 필드 전건이 아니며, 실제 도구 바이트 한도도 null이다. 후보 목록은 재사용하고 미확인 한도를 숫자로 만들지 않았다.

기존 scoped_field_issues는 config/action/task/execution/profile/lifecycle 여섯 공간만 처리했다. field_schemas를24개 공간으로 확장했다. runtime은 RUNTIME_FIELDS만으로 조립하지 않는다. inputs 같은 기록 가족은 그 맵 밖에서 StateContract에 등록되므로 default_state_contract().families의 실제 map/list/metadata/singleton 모양을 따라 root를 구성한다. 첫 초안은 runtime.inputs를 잘못 거부했고 이 실제 등록 구조로 바로잡았다.

저장 실행과 역할 입력의 execution_window는 서로 다른 객체다. stored execution_window에는 마감/공지 시각이 있고, 역할 입력 객체에는 .control 파일 경로와 self_check_directory가 있다. 두 공간을 같은 스키마로 묶으면 올바른 문서를 거부하거나 다른 공간의 필드를 잘못 승인한다. 실제 CoreEngineMixin._context의 고정 객체 대입에서 execution_window/scholarly/formal_verifier의 이름을 추출하고, submission.install_tools가 붙이는 preview/read_tool/submission_contract와 context_store.record_map의 실제 반환 객체를 결합했다. 이름 문자열이 다른 코드에 있다는 이유로 승인하지 않는다.

produced_object_schema는 대상 객체의 literal key를 해당 함수의 실행 공간에서 읽는다. 함수 안의 다른 함수·클래스·lambda 본문은 소유자에서 제외한다. 초기 AST.walk 초안이 중첩 함수만 만드는 foreign 필드를 외부 생산자의 필드로 인증하는 것을 7i_h4_8r에서 재현했고 교정했다. unknown spread나 동적 key, 유일한 literal 객체로 확인할 수 없는 생산자가 되면 검수 오류를 낸다. 선택기의 ast context(Store/Load) 차이는 정규화한 문법 표기로 비교한다. 대상 생산자를 실행하거나 제품 객체를 패치하지 않는다.

현재24개 공간에서 문서 참조93곳/고유49필드를 검사한다. 입력 창 필드를 stored execution에 넣거나 그 반대로 쓰는 경우, 다른 가족의 필드, 없는 중첩 read_tool 필드를 거부하는 대조를 추가했다. 최종 구조50개가 통과했고 원보고는 검증/2026-10-05-문서-필드공간/report.json이다. 실행 시간·SHA256·실행 중 변경 여부는 작업판 B110에 남겼다. 제품 코드는 변경하지 않았다.

남은 점 표기113곳/고유78개에는 .py/.json/.exe 파일명, Python 함수, contract_check 오류 코드, CLI 결과, record/payload 같은 문맥별 변수도 섞여 있다. 따라서 미검증 필드113개라고 부르지 않는다. 정확한 위치/표기를 기존 작업판에 남겨 다음 작업이 같은 원문 후보 검색을 반복하지 않게 했다. bare 이름에는 예컨대 API가 반환하지 않는다고 명시한 needs_revision, 외부 scholarly 어휘, Lean norm_num, 배열 항목을 부르는 import_unit/question_detail도 있어 어휘 부재를 제품 결함으로 단정할 수 없다. invalid_basis_refs는 운영 처분 오류 메시지의 실제 문구이고 checkpoint_schema는 context.update의 실제 키였다.

13-C는 partial_implementation이며 완료가 아니다. 다음은 미결 점 표기의 소유자 구분, 역할별 산출과 무공간 이름의 전건 대응, 실제 읽기 경계의 확인이다. 외부 도구의 바이트 한도가 확인되지 않았다는 한계와 구간별 완독 지침을 유지한다. 원래19+11·보존61·P2 원12와 최종 전체 일반/fresh T3/극단 변이/T4/T5 목표도 그대로다.
