JSTOR 검색 후속 기능을 기존 기관 API에 연결했다. 현재 접근 상태가 다시 Client Challenge로 바뀌었으며 HTTP200의 HTML을 JSON 성공으로 처리하지 않았다. 두 입력 실패 뒤 현재 표시된 다른 문자 과제를 판독·입력해 검색 25건으로 복귀했다. 보호된 원 관측 20260912T051530Z-jstor-after-challenge.html과 엔진별 상태를 보존했다. 서버에 인식기를 넣지 않았고 Codex나 등록 MCP를 재시작하지 않았다.

원 snippets 요청은 선택 문헌의 UUID·native type과 query를 받지만 응답은 검색 결과와 다른 순서의 stable DOI를 사용했다.10.2307 접두사를 정규화하면 기존 표본 25건이 모두 대응했다. snippets=true를 지정하면 해당 문헌의 query·HTML·text·상태와 원 증거를 보존한다. 발췌문을 초록으로 바꾸지 않고, 외래·중복 식별자를 거부하며 발췌문 실패가 검색 결과를 버리지 않게 했다.

20260912T052118Z-jstor-bce-mixed.json은 원 UI의 BCE0500~0100이 -500~-100으로 제출되는 것을 확인했다. 음수 연도를 지원하고 BCE/CE의 연도 0과 역전 범위를 거부한다. 표본의 발행 표시에는 B.C와 BCE가 함께 있었으므로 한 철자만 단언한 053213Z 실제 시험은 실패했다. 원 날짜를 새로 만들지 않고 시험의 잘못된 전제를 교정했다. BCE의 월·일 입력은 이번 지원 범위가 아니다.

혼합 검색은 이미지 carousel5건과 문헌 25건을 별도 결과군으로 반환했다. 미리보기 다음 표식을 요청하면 페이지 범위가 6~30이지만 앞선 미리보기와 실제 중복 2건이 있었다. 미리보기는 전체 이미지 관련도 순위의 첫 구간이 아니었다. 원 이미지 결과군을 처음부터 펼친 뒤 그 표식으로 다음 쪽을 요청한 053615Z-jstor-group-order.json은 25건씩의 중복 0건이었다. 이 경로를 사용해 결과군별 창을 회수한다. 원 미리보기는 evidence로 유지한다. 원 group_efq는 base64 JSON 유형 배열이고 순서가 바뀔 수 있으므로 비교만 집합으로 하며 제출 표식은 그대로 둔다.

혼합 결과군의 start/limit는 각각의 결과군에 적용한다. total은 반환된 결과군 전체 건수의 합이고 source_total은 최초 원 응답의 전체 건수다. result_groups와 각 레코드의 result_group이 범위·귀속을 표시한다. 결과군 사이의 통합 관련도 순위를 만들지 않는다. 후속 페이지가 실패해도 다른 결과군을 처리하고 받은 범위와 재시도 입력을 유지한다. 순회 중에는 첫 요청의 facet 필드도 보존해야 한다. 이를 빼고 group 표식만 보내면 문헌 유형 제한이 풀려 178720건이 197779건으로 바뀌었다.
