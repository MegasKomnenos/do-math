사용자는 남은 전체 작업을 계속 수행하고 실제로 할 수 있는 작업이 없어질 때만 멈추도록 지시했다. 이전 부분 완료를 전체 종료로 취급하지 않고 JSTOR 후속 검색 기능과 Software Heritage 원 Git 형식을 조사했다. 이 커밋은 Software Heritage 단위이며 JSTOR의 독립 변경은 작업 중 상태로 남긴다. 공개 API만 사용하고 추가 계정·이메일 보류와 재시작 금지를 유지한다.

Vault git-bare는 이메일 없이 준비를 요청하고 dir·rev·rel·snp를 받았다. history 항목을 추가하고 snapshot의 fulltext/supplementary도 같은 원 압축을 회수한다. 기존 dir·rev·rel의 flat 회수는 유지한다. dir의 Git 압축은 과거 이력이 아니라 해당 트리의 합성 커밋이다. snapshot은 API의 브랜치 페이지를 전부 읽어 원 snapshot 해시를 검산하고 압축본의 HEAD·refs·대상 타입을 대조한다. 객체 pack의 해시와 Git 객체 연결 관계를 검사하며 config·hooks·외부 object 참조를 실행하거나 적재하지 않는다.

20260912T053018Z-swh-git-mcp.json은 revision2db189928c94d62a3b4757b3eec68f0a4d4113f0의 337920바이트·349개 객체·55커밋과 snapshot2611ba3c6ee63b2078ac02e597ee0e40df930a66의 870400바이트·1084개 객체·296커밋을 실제 MCP로 통과했다. snapshot의 175개 브랜치는 HEAD와 174개 refs다. 최초 확인한 1a8893e6a86f444e8be8e7bda6cb34fb1735a00e는 빈 snapshot이므로 그것만으로 내용 있는 snapshot을 검증했다고 하지 않았다.

SDK 호출 중 Git init의 하위 프로세스가 파이프 종료를 기다려 반환하지 않았다. 별도의 새 SDK 진단 서버에 faulthandler를 넣어 subprocess readerthread·communicate와 swh_git.py의 호출 위치를 보호 파일로 확인했다. Git의 표준입력을 DEVNULL로 분리하고 Windows CREATE_NO_WINDOW를 적용하자 새 호출이 성공했다. 실패한 자체 시험과 그 자식 프로세스만 소유 관계를 확인해 종료했다. Codex·등록 MCP·다른 작업 프로세스를 재시작하지 않았다.

원 releasefc8e44c5bb3fabe81e5ebe46ac013a2510271616의 Git 압축에는 이메일 없는 tag가 있었다. 053213Z 보고의 fsck 실패는 missingEmail이며 원 파일을 source_archive로 보존했다. 원 바이트를 고치지 않고 그 형식 진단만 warning으로 남기되 해시·연결 검사는 유지했다. 053701Z-swh-git-mcp.json은 그 release 회수와 압축 추출을 completed=true로 통과했다. 이 release의 기존 flat 작업은 계속 pending일 수 있으므로 Git 형식 성공을 flat 성공으로 옮기지 않는다.

경로 이탈 시험을 만들 때 원 tar의 PAX path 헤더가 수정한 member.name보다 우선해 변형 입력이 실제로 바뀌지 않았다. PAX 헤더까지 바꿔 실제 이탈 입력을 만들었고 경로 검사가 이를 거부했다. 원 pack 손상·빈 snapshot과 metadata 부재·원 형식 경고를 함께 검사했다. 공통 257개 검사가 통과했다. fixture는 원 바이트를 유지하며 stage의 알려진 비밀값 검사는 전체 과거 기록 감사와 구별한다. 전체 학술자료 작업은 남아 있으므로 푸시하지 않는다.
