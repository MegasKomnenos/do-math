## 맥락

이 커밋은 do-math 정본 `.claude/skills/do-math/` 전체를 다시 검토하는 verify-rounds 런 `임시/do-math_검증_20261110/`의 라운드 1 결과다. 앞선 전면 검증(2026-11-07, [[M-0658]]~[[M-0664]]) 뒤에 question 체계, Job Object 수습([[M-0676]]), 성과·분해의 원리와 영어 참조 문서 둘([[M-0677]])이 들어왔다.

사용자 지시(2026-11-10)의 조건은 다음과 같다.

- 프리셋 claude-full, 체급 전면(수리 6기 중 관점 2, 심사 3기·정족 3, 라운드 하한 3·상한 8, 연속영 2). 수리자 Opus 5.5(`gp-opus-high`), 심사자 Fable 5.1(`gp-fable-medium`), 병합자는 claude-full 그대로 Opus 5.5(`gp-opus-low`). 두 에이전트에게 자기 모델 ID를 보고하게 해 실측했다.
- 검토 기준은 두 갈래다. 코드는 정상 작동과 버그 없음, 산문 문서는 각자의 역할에 맞게 중복 없이, 의도한 기능에 정확하게, 흐름이 자연스럽게 쓰였는지다. 문서의 역할은 이전 대화와 문서에서 복구한다.
- 시험은 모든 라운드가 끝난 뒤 한 번에 돌린다.
- 라운드마다 결산 전에 기각·무처분 등을 운전 세션이 직접 검토해 처리를 정한다.

작업 트리의 `.claude/skills/do-math/runtime/runner.py`에 미커밋으로 있던 임시 형식화 보류 코드([[M-0676]] 경고)는 0단계 기준선 조건과 부딪쳤다. 사용자가 「.claude 쪽은 치워둬. .agents 쪽은 남겨두고」라고 정해, `git stash push -- <그 경로>`로 치웠다. 실행 중 인스턴스가 `.agents/skills/do-math/runtime/runner.py`로 돈다는 사실은 프로세스 명령줄로 확인했다. stash는 런 뒤 작업 트리에 되돌린다. 이 커밋의 `runner.py`에는 그 코드가 없다.

동결문은 write-for-reader 절차(합의·독자 파일, 독립 독해 두 번, 한 번 revise)로 썼다. 동결문의 목적 진술에 문서 사이의 중복을 손상 목록에 더했고, 서브에이전트가 `CLAUDE.md`를 열어 분류기 중단이 났던 앞 런([[M-0659]])을 보고 기준 원문에서 `CLAUDE.md`를 빼고 열지 말라고 적었다.

## 고친 결함

수리자 여섯이 31항목(조각 60)을 냈고 병합 6묶음을 거쳐 심사 25건 가운데 23건이 만장 승인, 2건이 기각되었다. 재검토로 기각 2건을 모두 반영해 적용 31행(본표)이다.

- **Lean 브로커.** `collect`가 exit.json 확인과 호스트 생존 확인 사이에 호스트가 exit.json을 쓰고 끝나면 Lean의 종료 코드를 잃고 잡을 실패로 닫았다(R1-10). 충돌 코드(-9, 0xC0000005)로 끝난 보정을 import 집합에 대한 Lean의 거부로 영구 기록했다(R1-11). 대기 중인 컴파일이 제출 때의 `lean.threads`로 시작했다(R1-12). 잡 호스트 유실 시험이 트리 종료가 Lean에 닿지 않아도 통과했다(R1-13).
- **실행기·지식.** 옛 상태용 `attempt_launches` 기본값과 그것을 굳힌 시험을 지웠다(R1-M6). 배포 대상인 실행 중 인스턴스의 상태에 그 키가 이미 있음(값 17)을 읽기 전용으로 확인한 뒤 적용했다. 받은 값을 쓰지 않는 인자 `exclude_job`을 `launching`으로 바꾸었다(R1-15). root 해결 판정의 두 벌(`root_solved`, `root_settlement`)을 하나로 모았다(R1-19). 실패할 수 없는 시험 단언 둘을 고치거나 지웠다(R1-17, R1-18).
- **운영 문서.** `start`는 살아 있는 runner를 재시작하지 못한다(R1-20). 실행 중 runner의 settings 재적용과 거부 편집의 상태(R1-21). broker가 breakaway 거부 때 세션 job 안에서 뜨는 경로(R1-22). 링크 없는 작업자 문서 참조(R1-30).
- **문서 간 중복과 흐름.** review-output·record-format·organizer-output·organizer·explore·attempt가 다른 문서의 판단 기준을 되풀이하던 자리, writing.md의 module 설명 두 서술, operations.md와 common.md의 여러 주제가 섞인 문단, peer 지침의 참조 순서, lean.md의 session ID 출처와 링크 대상.
- **낱말 충돌.** node가 묻는 내용을 「question」으로 부르던 13곳을 「what the node asserts」·「problem」 등으로 바꾸어 frontier question 개체와 가렸다(R1-M1).

## 재검토의 처리

- **R1-21**(기각 1/3, 사유: 대체 문면이 `lean.md` 199행을 되풀이해 중복을 새로 들인다): 그 사실의 독자는 settings를 고치는 운영자이므로 정본을 `operations.md`에 두고 `적용 --추가`로 반영한 뒤, `lean.md` 199행의 같은 문장을 운영 문서 링크로 바꾸었다. 기각 사유와 원 결함이 함께 닫힌다.
- **R1-M1**(기각 1/3, 사유: 같은 절의 `common.md` 131·133행이 남는 반쪽 수리): `적용 --추가`로 반영하고 두 행을 같은 어휘로 통상 편집했다.
- 수리 1기가 항목으로 쓰지 않은 후보(`writing.md` 7행이 formalizer에게 선호 문서를 가리킴)는 결함이 아니라고 판정했다. `context.py`가 reference 전건을 세션 스냅샷에 복사하므로 링크가 열린다.

## 이 커밋의 절차 예외

- **스킬 미러 게이트를 적용하지 않았다.** 실행 중 인스턴스가 `.agents/skills/do-math` 사본으로 돌기 때문이다(동결 불변식, 앞 런의 사용자 결정 (가)). 사본은 런 동안 수정·재생성하지 않는다.
- **시험을 돌리지 않았다.** 사용자 지시에 따라 마지막 라운드 뒤 전체 스위트를 한 번 돌린다. 이 커밋의 판본은 시험으로 확인되지 않았다.

## 터득한 것

- **서브에이전트 전사로는 실제 입력을 대조할 수 없었다.** 이 하네스에서 Agent 파견의 `tasks/*.output` 파일이 모두 0바이트였다. 그래서 SKILL.md 1단계 5항이 요구하는 실제 도구 반환 대조를 하지 못했고, 독해는 「읽은 범위」 신고와 담당 범위의 일치까지만 확인했다고 장부에 적었다.
- **Agent 파견은 `run_in_background: false`를 주어도 비동기로 뜬다**([[M-0669]]와 같다). 완료 대기는 크기 안정 대기 스크립트를 백그라운드 Bash로 걸어 그 종료 통지로 세션이 깨어나게 했다. 서브에이전트 완료 통지도 같은 턴에 도착했다.
- **기각 사유가 수리안의 형식(중복 재도입, 반쪽 범위)에 있을 때는, 기각 사유를 함께 없애는 작은 보완으로 원 결함을 회수할 수 있었다.** 두 건 모두 그랬다.
