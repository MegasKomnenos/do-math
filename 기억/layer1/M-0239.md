사용자의 후속 상태 확인에서 24개 파견 중 19개가 awaiting_review, CORE files01이 실행 중,4개가 반복 재개 대기임을 확인했다.19개 반환은 사본의 조사 결과이며 원본 통합이나 주 세션의 최종 검토 완료가 아니다. 일부 completed 주장은 기능 복원보다 오류 분류·제약 확정이므로 반환명만으로 성공 건수를 세지 않는다. 원본 생산 코드는 62211db 시점에서 바뀌지 않았으며 514개 검사는 이번 사본 수리의 통합 검사 결과가 아니다.

반복 중단의 일부 원인은 주 세션이 작성한 운영기였다. 최초 exec에는 --sandbox danger-full-access가 있었지만 resume에는 대응 옵션이 없어 재개 환경이 read-only가 됐고 CreateProcess·파일 쓰기가 정책 단계에서 차단됐다. CORE work, DBLP KG, Crossmark 등이 이 문제를 자료로 기록하면서 반복 incomplete를 반환했다. SWH는 이후 ActiveTurnOutputSchemaMismatch 때문에 모델 turn을 시작하지 못한 재개가 누적됐다. 이는 자료원 오류나 사용자 자격 부족이 아니다.

run.py의 resume에도 기존 허용 범위의 실행·쓰기 권한을 명시했다. 현재 CLI가 resume에 제공하는 --dangerously-bypass-approvals-and-sandbox 옵션을 사용하며, 원 작업의 수정 범위·개별 자격 경로·자료원 경계·외부 요청 제한은 그대로 유지한다. 모든 접근을 새로 허가한 것이 아니라 최초 파견의 로컬 실행 권한을 재개에 전달한 것이다. 원본 사용자 설정이나 등록 MCP를 수정하지 않았다. 재개 프롬프트는 자신의 output_dir에서 먼저 가벼운 파일 읽기·쓰기·삭제를 확인하게 했다.

정확한 ActiveTurnOutputSchemaMismatch를 stderr에서 확인한 thread만 resume_without_schema로 표시해 다음 재개에서 출력 스키마 옵션을 빼도록 했다. 프롬프트의 최종 JSON 계약과 필수 파일·이미지·미시도 방법 검사는 유지한다. SWH의 같은 thread에서 변경 후 로컬 명령 exit0 두 건, Crossmark의 같은 thread에서 명령 exit0을 확인했다. DBLP KG의 같은 오류는 감지 후 다음 재개를 대기하며 CORE work는 같은 자료원 files01과의 동시 실행을 피하려고 대기한다. 프로세스 재생성보다 각 thread와 사본을 보존하는 방식을 택했다.

운영기를 교체할 때 실행 중이던 CORE files01 PID38208은 그대로 인계했다. 새 운영기의 실제 PID38652, wrapper19160을 확인했으며 고정 PID보다 실행폴더 state.json을 정본으로 읽는다. 실행폴더는 C:/math/services/scholarly-mcp/data/dispatch/20260913T021511Z다. 각 과제의 result.json/report.md/experiments.json/visual-review.md와 전용 사본에 반환을 보존한다. 수정한 재개 argv를 포함한 운영기 4개 검사는 통과했다. 현재 상태 확인은 새 조사 결과의 전체 통합·전체 회귀를 대신하지 않는다.

반환 중에는 원 기능을 복원한 후보도 있다. DBLP 13호출·7export, Semantic Scholar batch/bulk/title-match/관계, EuDML NLM의 긴 TTFB, ScienceDirect의 늦게 준비되는 export 제어, DOI 없는 DeGruyter 서지, Numdam 날짜 전용 976건, IEEE Media MP4 parser, Figshare 과거 판본 2/3 구성원 등이 보고됐다. AMS 표현식 조기 거부·JSTOR video 비활성·특정 Springer HTML 부재처럼 기능을 복원한 결과와는 다른 경우를 구별해 검토한다. SIAM 기관 인증·Oxford title-list·DeGruyter의 깨진 ZIP은 exhausted로 반환됐지만 그 소진 범위도 주 세션이 검증해야 한다. 불완전한 반환이 반복되는 것을 없애기 위해 완료 조건을 낮추지 않았다.
