[[M-0499]] 뒤 6-A의 대화 임대 판단을 연결했다. lifecycle_engine의 재개 허용, heartbeat 처리, 임대 상실 점검은 연결 상태와 UTC 만료 시각을 각각 비교하고 있었다. conversation_lease_live가 연결 상태이며 만료 시각이 실제 처리 시각보다 엄격히 뒤라는 판정을 소유한다. 세 소비자는 이 함수를 사용한다. 재개에는 마지막 상실 세대보다 새로운 연결 세대라는 별도 조건도 그대로 필요하다. 대화 상실 정책 continue_authorized는 임대 상실을 기록하지만 연구를 자동 pause하지 않는다.

기존 원문 검사 test_heartbeat_is_judged_at_delivery_and_cannot_revive_an_expired_generation은 접수 당시 살아 있던 heartbeat라도 실제 처리할 때 만료되면 거절하며, 행을 바꾸지 않고 이후 readiness가 상실을 기록해야 한다고 선언한다. _lifecycle_now는 주입 시계의 wall을 읽는다. 사건 접수 시각을 임대 갱신 시각으로 대신하지 않았다. 새 검사는 공개 attach가 생산한 실제 행에서 두 정책과 만료 직전 1마이크로초·동일·직후를 순회한다. 재개 판단, 갱신 또는 변경 없는 거절, 상실 이유, 중복 상실 없는 처리를 비교한다. 별도 검사는 공개 detach 뒤 같은 세대 재연결 거절, 다음 세대 연결, 명시적 resume를 확인한다.

처음 검사의 continue_authorized 초기 상태를 idle로 가정해 두 하위 장면이 실패했다. 실제 활성화 생산자와 기존 lifecycle 상태 설정은 ready였다. 특정 상태명을 다시 하드코딩하지 않고 상실 전 실제 상태가 보존되는지 비교하도록 고쳤다. 이 첫 실패는 제품 결함으로 세지 않는다. 교정된 두 검사는 제품 변경 전에 11.0초에 통과했다. 정본 추출 후 구조 47개·단위 3개·Sim 50개, 합계 100개가 127.1초에 완결 통과했고 changed_during_run은 비어 있다. 기존 지연 heartbeat, 실제 lease 정지, 입력 준비 중 pause, 모델 resume 전 pause, 실행 중 즉시 정지도 포함된다. 개별 예산 초과 38개는 소프트 비교 정보이며 실패나 종료 조건이 아니다.
