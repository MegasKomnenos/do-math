용어 정리는 이름과 식을 일관되게 바꾸는 데서 끝나지 않는다. 기존에 사용할 수 있던 결과를 새 정의에서도 사용할 근거가 확보되어야 한다. 미확인 범위를 솔직하게 표시하는 일은 필요하지만, 이번 편집이 만든 검증 의무를 수행하는 일을 대신하지 않는다.

이번 후속 수리의 출발점은 관계 칸에 남은 검토 상태 문장, 순열 모멘트와 숲 표현을 섞은 급수 정의, 원 유한합에 간접적으로 연결된 사슬 기저였다. 주 에이전트는 급수를 숲 다항식으로 통일하면서 옛 계산용 목록과의 Lean 연결을 미완료로 적으려 했다. 사용자는 미검증 표시만으로 넘어갈 문제가 아니라 필요한 검증이 되어 있어야 한다고 교정했다. 원래 연구에 남아 있던 문제와 편집으로 새로 생긴 확인 의무를 구별하지 않은 것이 당시 처리의 결함이었다.

옛 기록을 대조하니 직접 순열 합과 재귀 목록의 일반 Lean 동일성은 원래도 없었다. 반면 원 주차 개수에 대한 하계는 형식 증명되어 있었다. 따라서 모든 과거 구현을 다시 연결하는 작업 대신, 현재의 숲 다항식에서 같은 하계의 역할을 하는 명제와 조건부 증가를 직접 증명했다. 급수의 정의·계수식·원 주차 개수의 부등식을 각각 Lean으로 연결하고, 새 작업 폴더에서 의존 원문까지 재컴파일했다. 수식의 의미 대조와 컴파일, 독립 검토 판정을 구별했으며 작성자 확인을 독립 판정으로 등록하지 않았다.

계약에서는 common.md의 관계 칸에 현재 구현·과거 판정 이력이 쌓이지 않게 역할을 분명히 했다. plan.md의 기존 표현 변경 문단을 고쳐, 현재 사용 가능한 결과의 근거가 새 정의에서도 확보되어야 이전이 끝난다고 정했다. 별도 이전 역할이나 과거 이름의 호환 규칙을 추가하지 않았다.

압축 이후 사용자가 대화 원문 재적재를 요청했을 때 처음에는 넓은 경위를 읽었다. 사용자는 필요한 것이 압축 직전의 꼬리라고 범위를 좁혔다. 마지막 도구 반환을 대조해 당시 새 Lean 파일은 컴파일 성공, 문서 반영·공개·커밋은 미완료였음을 확인하고 그 지점에서 이어갔다. 이후의 작업에서도 과거 시도와 현재 완료 상태를 구별하려면 마지막 실행 결과와 반영 영수증을 먼저 확인해야 한다.

독해는 중간 판본의 두 번 읽기에서 내용 보완을 얻었지만, 이후 반환의 인용 문자·행 번호 검사 실패가 반복됐다. 사용자가 최종 독해를 생략하라고 명시하여 작문 작업을 취소하고 진행 중인 독해 프로세스를 중단했다. 최종 독해를 통과했다고 기록하지 않았으며 Lean 검증과 직접 내용 대조는 이미 수행한 그대로 보존했다.

추적 근거는 `research/reports/do-math-glossary-followup-20261024/`의 검증 설명, 수정 전후 기록, Lean 원문·실행 로그·공개 영수증이다. 연구 인스턴스와 작문 도구의 작업 자료는 `.skill-workspace/`와 `.codex/` 아래 로컬 보관이며 상위 Git에서 제외된다. 인스턴스 공개 기록은 자체 Git으로 보존한다. 사용자의 재개 금지는 유지한다.
