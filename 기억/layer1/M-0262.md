사용자가 CONTINUATION의 partial 잔여 항목에 대해 실제 이유를 파악하고 적절한 해결을 시도하도록 요청했다. 지원표의 48개 partial은 registry가 부여한 자료원별 부분 지원 표지였고 요청 실패 개수에서 계산한 값은 아니었다. 인계의 개별 잔여 항목 19개를 현재 원 호출·화면·응답·코드와 대조했다. 세부 판정과 재개 계약은 services/scholarly-mcp/PARTIAL-REVIEW.md 및 갱신한 CONTINUATION에 보존했다.

ScienceDirect의 기존 성공은 Title+ISSN 검색을 선행한 세션이었다. 새 세션에서 Preface를 직접 조회하면 원 citation_issn이 있는데도 제목만 검색했고, 실제 63,148건 중 첫 100건에 요청 PII가 없었다. 그 실패 뒤 상세 PDF 경로가 같은 문헌 HTML을 반환하면서 앞선 검색 실패가 사라졌다. 원 메타데이터의 형식 적합 ISSN·ISBN으로 후보를 좁히고 두 경로의 실패를 함께 보존하도록 수리했다. 수정 후 실제 45건 중 대상 행을 찾았고, 그 선택 다운로드가 표시한 비구독을 restricted로 반환했다. PDF 권한을 복원한 것은 아니다. ISBN 경계는 회귀 대역으로 검증했다.

APIAdapter는 HTTP 오류를 분류하면서 원 응답 본문을 버렸다. JSON의 민감 필드와 HTML 실행 코드·입력 제어를 정제한 오류 응답을 provider_error_response로 보존하고, 저장 실패도 원래 HTTP 오류를 덮어쓰지 않도록 했다. CORE의 실제 429에서 빈 본문·요청 방식·재시도 헤더를 보존했다. 안내 시각 15:36:45 UTC 이후 15:37:31에 재조회해 200을 받았고 Output 213561553의 fullText가 공개 API 안내문임을 직접 확인했다.

Semantic Scholar는 15:06 UTC에 같은 batch 대상의 429를 반환했지만 15:31:22의 별도 새 SDK에서는 서지·초록·BibTeX·참고문헌 30개를 반환했다. reported referenceCount 30과 일치했다. 그 full-parts 요청의 partial은 Graph API가 원문 파일을 제공하지 않는 범위 때문이었다. 접근 자격이나 endpoint를 바꾸지 않았으며 미래 가용성을 보증하지 않았다. 원본 기준선 633개 검사, 새 실패 검사, 수정 후 638개 검사 46.166초 통과를 기록했다.

Software Heritage의 task 419779186은 15:31:24에도 new였으며 내부 대기 이유는 공개 응답에 없었다. 새 서버 옵션 대신 기존 files 객체의 별도 압축 복원을 선택했다. 기회수 92개 파일·20개 디렉터리의 원 URI와 SHA-256·Git 객체 해시를 재검증하고 899,228바이트 tar.gz를 만들었다. 압축물에서 계산한 Git tree가 7057a716afab8ca80728aa7c6c2cc4bd03b0f45b와 일치했다. 새 원격 요청은 0회였다. 원 Vault 작업 완료나 원 압축 바이트와의 동일성으로 세지 않았다.

작업 중 사용자는 AMS의 건수 반례만으로 끝낸 진단을 교정했다. 최초 보고는 algebra 6,589건보다 algebra AND topology 30,485건·algebra NOT topology 10,343건이 커서 논리 의미를 보존하지 않는다는 결론이었다. 사용자는 실제 검색 과정의 화면을 이미지로 확인하고 왜 그렇게 수행됐는지 보도록 요구했다. 숫자 비교는 처리 기전의 설명을 대신하지 못한다는 교정이었다.

원 실행의 입력 직전·결과 직후 이미지를 실제로 열었다. AND·NOT 문자열은 기본 Title 칸 하나에 들어갔고 결과 chip도 같은 Product Title 문자열이었다. 새 실행에서는 정상 Search 클릭 전·후·안정 이미지, 빈 다른 필드, 원 POST의 빈 filterString/simpleSearch/dynamicAdvancedSearch를 대조했다. 렌더된 performSearch 함수는 기본 필드와 동적 JSON 분기를 구별한다. 단독 AND 25,566건·NOT 3,398건과 각각 0건인 두 음성어 사이 AND·NOT가 각각 같은 건수인 것을 확인했고, 실제 결과 제목에 Andrei·Andrews·Notions 등이 있었다. 대소문자 대조도 같았다. 기본 Title에서 이 두 단어가 검색어로 처리되어 범위가 넓어진다는 근거를 확보했다.

OR는 같은 취급이라고 일반화할 수 없었다. 단독 OR는 4,810건이지만 두 음성어 사이 OR는 0건이고 algebra OR topology는 공백 결합과 같은 7,094건이었다. 이는 원 인터페이스에서 관측한 동작이며 비공개 검색 엔진의 SQL·토큰화 코드를 확보한 것은 아니다. 동적 Custom Search에서 Title/contains/algebra 한 조건은 실제 JSON 구조를 보존했지만 97바이트 Result is null 응답을 받았다. 상품 POST와 앞선 browse POST에서 각각 JSON의 한 단계 URL 인코딩만 제거한 대조도 같았다. 인코딩을 원인으로 단정하거나 그 오류를 0건으로 해석하지 않았다. AMS의 검증된 지원 부분집합은 유지했다.

Figshare v6의 17대16 불일치는 새 호출로 재현했으나 정확한 누락 ID는 확정하지 못했다. 별도로 읽은 DataCite v6 등록에는 구성원 관계가 없었다. JSTOR의 과거 권한 JSON은 disabled였지만 새 호출은 Client Challenge에 막혀 현재 권한 응답까지 받지 못했다. 나머지 문헌별 접근 제한·초록 및 HTML 본문 부재·EuDML의 목차와 전문 구별은 새 호출과 원 자료를 대조했다. 기관 권한의 내부 성립 조건, AMS 동적 null, Vault 대기, Figshare 누락의 내부 원인은 미확정으로 남겼다.

사용자는 이어 “그냥 네가 진짜 사람인 것처럼 페이지 하나하나를 보면서 어떤 내용들이 있는지 읽으면서 해당 웹사이트가 사람 사용자에 제공하는 자연스러운 흐름, 자원, 지시, 정보, 가이드 등이 뭐가 있는지” 살피고 “각 웹사이트에 대 별도 codex exec 들을 파견”하라고 두 번 교정했다. 코드·프로브부터 만들던 접근을 내려놓고 13개 사이트별 Codex CLI를 파견했다. 부모보다 경량인 gpt-5.6-sol high를 사용했다. 실제 첫 화면·메뉴·도움말·본문·다운로드 UI를 이미지로 읽은 뒤 다음 행동을 선택하게 했고, root는 반환된 실제 핵심 이미지를 다시 열었다. 최소 브라우저 조작 코드는 도구 수단으로만 사용했다. 별도 실행 설정의 invalid transport 오류는 작업자 시작 실패로 분리했고 사이트 실패로 세지 않았다.

이 방식에서 이전의 결론을 더 수정했다. AMS 전체 제목은1건인데 짧은 두 단어는915건이며, 명시 OR로 두 단어를 검색한915건이 같은 제목의 나머지 단어를 OR로 추가하면1건으로 줄었다. 빠진 실제 문헌과 빈 다른 필드까지 이미지로 확인했다. 기존 Title OR 문자열 변환의 일반 합집합 보장을 철회하고 여러 Title term의 OR를 브라우저 이동 전에 거부하도록 수리했다. 기존 Author OR는 별도의 Boykan/Jech 검증이므로 Title의 새 반례를 그 필드로 확대하지 않았다. 전체 제목 찾기와 Title+Author는 정상이고 YEAR의 Use Single Year도2025·2024년을 정확히 제한했다. 이 네이티브 YEAR를 내부 PublicationYear 식과 임의로 동일시하지 않았다. MathSciNet의 Boolean 성공도 다른 서비스의 성공으로 분리했다. 새 회귀의 RED2실패 뒤 AMS33검사와 최종 전체639검사46.447초가 통과했다.

기관 목록에서 검색 약칭과 자원 종류를 놓친 부재 판정을 바로잡았다. Oxford는 OUP/OUP-Near Archive, Taylor & Francis는 Taylor로 실제 KUDOS 항목이 나왔다. ScienceDirect에서는 일반 키워드의 PII 오류를 검색 전체 장애로 확대하지 않았다. 이용매뉴얼과 실제 자동완성에 따라 Preface·Advances in Cancer Research·Volume171을 선택하면 정확한 한 건이 나왔다. Semantic Scholar의 빈 openAccessPdf와 isOpenAccess=false는 실제 웹 Reader·arXiv 접근과 달랐다. 원 arXiv v2 PDF698,413바이트·28쪽을 확보하고 첫 페이지의 판본을 읽었다.
