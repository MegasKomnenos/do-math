## 맥락

phase 008은 운영·복구 문서의 동명 source를 실제 반환 객체와 파일에 연결했고, 설치 경로 설명의 낡은 전역 이름을 교정했다. 지정 성과 A1~A4는 검수했지만 최종 관련 검사는 정본110건 중4건, 미러89건 중4건이 실패해 partial이다. 제품 변경은009의 수리·검증 뒤 함께 커밋하고 이번에는 원근거와 관리 인계를 보존한다.

## 판단의 근거

실패는 CLI 문서의 실제 함수 provider_final.output_contract가 bare dotted 표기라 상태 필드로 분류된 데서 발생했다. 현재와 HEAD의 정규화 문서·당시 helper에서 같은 분류를 재현했다. raw 개행 해시는 따로 기록돼 있어 정규화 원문 일치를 원바이트 동등성으로 바꾸지 않는다. 기존 함수 검사기는 명시 호출 표기를 실제 callable로 확인하므로 새 예외나 추론 확장 없이 문서 표기를 교정할 수 있다.

008의 쓰기 목록에는 CLI 문서가 있었지만 objective는 P01 문장만 바꾸도록 한정했다. 작업자가 다른 공급자 절의 표기를 고치지 않고 partial로 반환한 것은 그 경계를 지킨 판단이다.009에는 확인된 원인과 수정할 표기, 재사용할 실패 근거, 정확한4실패 ID와 최종 관련 선택을 함께 준다. 같은 실패를 확인하려고 수리 전 전체 묶음을 다시 실행할 필요는 없다.

운영/복구 실제 입력 검사는 정상·오류·null·부재를 구별한다. template 저장소가 같은 경로를 재사용해 checkpoint fixture의 불변 artifact 정체성이 충돌했던 중간 실패는 새 UUID 묶음으로 해결했으며 제품 cache나 반려 조건은 바뀌지 않았다. runtime124·smoke입력3·corpus102경로도 불변이다. 기존 공급자 호출의 승인된 성질은 유지하지만 새 문서·시험 판본의 최종 전체 관문은 계속 남는다.

## 근거의 보존 범위

추적 진입점은 실행 기록의 phases/008/manager.json, manager-evidence/review.md·verification.json·preservation.json과 phases/009 배정이다. task report·원검사 출력·실행 전후 해시 및 검수된 제품 변경30파일의 raw archive를 같은 관리 커밋에 보존한다. archive는 당시 판본의 증거이며 사용자 변경을 자동 복원할 지시가 아니다. 서비스 세션 로그와 Git stage/commit 수신 기록은 로컬 자료라 정리로 사라질 수 있다. 이전 공급자 재사용의 한계와007 마감은 [[M-0557]]을 따른다.
