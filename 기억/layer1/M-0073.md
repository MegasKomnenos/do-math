# do-math 설계 복잡성·이슈 18 충실성 3단 검토 파이프라인 완료

## 맥락

사용자가 두 검토를 동시에 지시했다. (1) `docs/do-math/통합-설계.md`·`docs/wayfinder/pvsnp-재설계/컨텍스트.md`·`CONTEXT.md`의 복잡성이 타당한지, 동일 목적·기능을 유지하며 더 간단히 구현할 수 있는지 opus 다수로 검토. (2) 이슈 18 본문·댓글이 그것을 생산한 codex 대화의 원 목적을 충실히 반영하는지 fable 다수로 검토하되, handoff·완료로 끝난 세션만 쓰고 사용자가 점유 해제·revert로 끝낸 세션은 배제. 각 결과마다 gpt-5.6-sol high 검증 세션을 붙이고, 파견당 컨텍스트 400k 이하 유지.

산출은 `docs/do-math/검토-20260831/`에 있다: 자료(세션 추출 14건·세션-분류·이슈-18 덤프), 보고 12건(복잡성-O1~O4, 충실성-F1~F7, 충실성-종합), 검증 12건(보고당 sol high 1건). 파견 계약·파견문·반환·로그는 사용자 지시로 커밋 전 삭제했다.

## 파이프라인 구성

- 세션 식별: `~/.codex/sessions/`의 jsonl에서 session_meta의 cwd(`C:\math`)·thread_source(`user`)·source(`cli`)로 대화형 세션 45건을 거른 뒤 이슈 18 관련 20건을 식별, 종결 문구로 13건 포함·7건 배제. 경계 2건(단순화 목적 진술 grill 세션 G, 리셋 실행 세션 H)은 포함하고 근거를 `자료/세션-분류.md`에 남겼다.
- 추출: response_item(message)만 취해 user·assistant 채팅을 뽑고 tool-use·reasoning 제외. AGENTS.md·스킬 본문·environment_context 주입은 한 줄 마커로 치환했다. 이 치환이 세션당 9~20k자를 줄여(B 세션 23k→1.6k) 슬라이스 설계를 바꿨다. 총 73만 자, 대형 세션 M(158k자)은 메시지 경계에서 2분할.
- 파견: 공유 계약 파일(복잡성·충실성·종합·검증 4종)을 쓰고 각 에이전트에는 담당 번호와 산출 경로만 주는 짧은 파견문을 보냈다. opus-high 4(문서 절 범위 4분할, 세 문서는 전원 전문 통독), fable-high 7(시간순 구간), fable-xhigh 1(종합), sol high 12(codex exec).
- 검증 파견은 verify-rounds의 codex 일반 실행 절차를 차용했다(`codex -a never exec -C <루트> -s danger-full-access -m gpt-5.6-sol -c model_reasoning_effort=high -c mcp_servers={}`).

## 결과 요지 (세부는 보고·검증 파일)

- 충실성 종합: 209개 항목에서 왜곡 0. 결함 판정 누락 1건: 세션 C에서 확정된 「P vs NP 최종 결론의 ZFC(또는 더 약한 기초)로의 검증된 이동 요구」가 재론·대체 결정 없이 모든 현행 정본에서 부재. 세션 G의 「정말정말 간단하게」는 정수·재량·구조 단순화 축은 현행 반영, 명세 규모 축은 사용자의 단계별 승인이 대체(정당)하되 긴장이 문서상 닫히지 않았다고 기록. 단, sol 검증은 이 종합의 최종 집계를 「교정 없이 채택하지 말 것」으로 한정했다(대안 기초 프로필·terra 금지 범위 등을 근거보다 강하게 닫음).
- 복잡성: 과잉 지적 48건·타당 판정 42건·기능 절충 4건. sol 검증이 그중 9건을 기각(예: 검토 계획 세션 제거, 프로젝트별 감사 어휘 추상화는 기능을 깎음)하고 다수를 「대안 교정 후 채택」으로 한정. 고영향 축: 역할 요청 레코드의 4중 이형(O1-01·O3-03 독립 수렴), 크리덴셜 가용성의 착수 판정 혼입(O4-01), 필수 도구 표 불완전(O4-07), 무제한 이의 루프의 관찰 사각(O4-08), 범위 차분 감사 어휘의 수입 원천 부재(O4-12).

## 터득한 것

- 백그라운드 Bash 안에서 `codex exec ... &` 뒤 echo로 끝내면 래퍼 셸이 먼저 종료해 완료 통지가 조기 발화하고 codex는 고아로 계속 돈다(O1 검증에서 실측). 통지가 필요하면 파견 명령 하나를 포그라운드로 담은 백그라운드 Bash 하나로 보내고, 고아가 된 실행은 산출 파일 실재·완결(머리와 꼬리 절 확인)로 완료를 판정한다. L-0016의 「완료 신호 파일을 상태 정본으로」의 재확인이자 codex exec 변형.
- codex 세션 jsonl의 채팅만 추출하면 원본 대비 1~5% 분량으로 준다(27MB 세션이 158k자). 로그 분석 파견은 원본을 주지 말고 추출을 만들어 주는 것이 슬라이스 수를 줄인다.
- Git Bash에서 jsonl 안의 `C:\\math` 매칭은 셸 이스케이프 층이 셋(따옴표·패턴·JSON)이라 반복 실패했다. 이런 스캔은 처음부터 Python으로 하는 것이 빠르다.

## 작업 너머 시사점

- 사용자 교정 신호: ⓐ 파이프라인 완료 후 별도 종합 보고서를 작성하려 수합을 시작했다. ⓑ 사용자는 「따로 보고 작성은 불필요. 임시 파일 정리하고 산출물만 커밋, 추출 대화록은 보존」으로 끊었다. ⓒ 추정(대행 예외 아님, 대화 있음): 보고 12건·검증 12건이 이미 파일로 있으니 그 위의 재서술 층은 중복이라는 판단으로 읽힌다. 다층 파이프라인의 최종 단계에서 「종합 산출물이 이미 있으면 메인 세션의 요약은 소비자가 요청할 때만」이 offset 후보. ⓓ dream에서 묶을 후보: L-0016 회수 검증 절에 「메인 요약 재서술의 기본값 억제」를 추가할지 검토.
- 검증 계약에 「보고의 타당 판정도 재검증하라」를 명시한 것이 실효했다. sol 검증들이 타당 판정 쪽에서도 제한·기각을 냈다(O1의 runtime ref 계열 수 등). 검증을 지적 재확인으로만 계약하면 이 절반이 빠진다.
