Figshare의 과거 컬렉션 구성원을 not_implemented로 두던 원본을 공개 웹의 판본별 GraphQL로 복원했다. collection ID와 version을 묶은 필터, 응답 count와 cursor, 고유 ID를 대조한다. metadata와 검색 건수가 다르더라도 확보한 subset은 버리지 않는다. 요청 판본이 current임을 조회 전후에 확인하고 같은 DOI·건수·포함관계가 유지될 때만 그 판본의 REST 관계로 보완한다. 다른 current 판본은 과거 목록의 대체물이 아니다.

독립 검토는 후보 19개 검사와 실제 판본·누락 article·실패 전후 이미지를 대조해 이 의미를 확인했다. 다만 GraphQL data:null 또는 searchAdvanced:null에서 AttributeError가 나 메타데이터까지 반환하지 못하는 결함을 발견했다. 원본에서 두 실패를 재현한 뒤 중첩 object 타입을 확인해 기존 invalid_response와 partial 경로로 넘겼다. 원 메타데이터, 빈 member artifact, 오류의 GraphQL evidence를 보존하는 회귀와 함께 20개 검사가 통과했다.

원본 server.py의 새 SDK는 collection5323961의 v1에서 2건, v2에서 3건을 회수했다. collection4046897의 v8은 metadata21건·GraphQL20건이었고, 같은 current 판본의 REST21건이 검색 subset을 포함했다. REST에만 있던 ID는 17061347이었다. 전후 version·DOI·count를 확인해 21건 available로 반환하면서 원 20건 subset과 차집합도 보존했다. v6은 metadata17건·검색 16건이었으며 current가 v8이므로 16건 partial로 남겼다. 모르는 한 항목을 추정하거나 다른 판본에서 채우지 않았다.

근거는 .credentials/scholarly-mcp/probes/root-user-criteria-20260913T0715Z/figshare/root-sdk.json, 정제 요약은 services/scholarly-mcp/data/access-research/user-criteria-figshare/root-sdk.json이다. 최종 원본 작업 트리의 전체 562개 검사가 55.257초에 통과했다. 이 트리에는 별도로 작업 중인 Oxford host/렌더 수리도 있었으므로 이 커밋은 Figshare 코드·회귀·해당 안내만 분리한다. registry의 Figshare 블록만 index에 올리고 Oxford 블록은 다음 단위에 남긴다.

동일 count지만 다른 ID 집합이라는 가상 상황은 추가 source 결함으로 확정하지 않았다. 현재 계약은 GraphQL의 판본 필터를 기본 근거로 쓰며 count가 다를 때만 current REST 보완을 검토한다. 실제 같은-count 불일치가 없는데 모든 요청에 REST 대조를 추가하면 비용과 원격 실패 지점만 늘어난다. 반대로 null 응답의 예외 유출은 코드로 재현되므로 바로 고쳤다. 변경 여부를 실제 결함과 현재 계약의 범위로 구별한 검토다.
