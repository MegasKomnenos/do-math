## 생산자와 수신자의 계약

[[M-0445]]의 제출 반려 수리는 675398f3로 확정했다. 이번 변경은 원 KD-0601의 Lean 선언 증거 형 검사다. lean_evidence의 constantEvidence는 exprEvidence 문자열 또는 Json.null을 내보낸다. 의존 본문 수신에는 같은 형 검사가 있지만 선언 행에는 빠져 있었다. main의 실제 parse_evidence에 정상 생산 출력의 evidence.value만 배열·객체·boolean·integer로 바꿔 넣으면 모두 verified가 반환됐다. atecn4jj 보고는 1개 시험의 네 하위 반례 실패를 기록한다. 문자열과 null 대조는 통과했다.

선언 행에 의존 본문과 같은 value 형 검사를 추가했다. 입력은 현재 LeanDouble에 정확한 소스와 선언을 등록하고 제품 check_file과 spawn 포트로 만든 합성 출력이다. 실제 Lean 녹화라고 주장하지 않는다. 정상 문자열과 null은 declaration_evidence의 정확한 값을 유지하며 잘못된 형은 failed / malformed dependency evidence로 거부한다. 후보의 check_stop 이름 교체나 엄격한 LeanDouble 기반 전체를 이 변경에 섞지 않았다.

## 검증과 후보의 차이

rrmvxkqd의 기존 evidence/runtime/doubles/corpus 관련 14개가 통과했다. runtime 수신 시험 두 개는 각각 5.328초와 19.516초로 0.2초 개별 예산을 넘었으며 성능 개선을 주장하지 않는다. main 원장 구조 ckvlh277도 통과했다.

원 회귀는 후보의 knowledge_close_evidence에서 같은 성질의 기존 knowledge_formal_evidence_rules로 옮기고 이전 메서드는 제거했다. 처음 main 입력을 그대로 옮긴 후보 n0ywyvn5는 declaration_evidence와 axioms 필수 인자 누락으로 error였다. 이는 후보의 명시 등록 계약이 더 엄격하기 때문이다. 후보 입력에 정확한 선언 증거와 빈 공리 목록을 명시한 gelhqo1u가 통과했다. 제품 fallback이나 옛 API 별칭은 만들지 않았다. 양쪽 원장의 현재 reproduction을 이동 위치로 바꾸고 원 ID는 역사에 남겼다.

현재 main 원장은 30개이며 후보 56개 중 26개가 미기록이다. 이는 전체 완료율이 아니다. 보고 원문·SHA256·소스 지문은 단계-전환표의 current_work.lean_value_integration에 연결한다. 같은 최종 판본의 전체 관문과 원문 19/61/12/여섯 부류/11 의무는 남는다. 다음은 실제 Git에서 고정 조사 원천이 없어졌을 때 원천·슬롯 좌표를 보존하는 복원 진단 통합이다.
