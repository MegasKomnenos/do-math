## 구현 판단과 현재 계약

사용자는 [[M-0266]]의 구현 판단 위임에 이어 끝까지 자율적으로 구현하도록 지시했다. 강한 OS 격리나 공급자 내부 제어를 일괄 선행조건으로 두는 대신, 기존 codex exec 어댑터와 Windows Job·Git 저장을 실제 연구 흐름에 연결했다. 실행 가능한 계약은 `do-math-cli/1`이며 통합 설계 0절과 `.agents/skills/do-math/references/CLI-실행-계약.md`에 선택한 동작을 명시했다. 원래 draft/9 wire·상태 벡터 전건을 구현했다는 뜻으로 사용하지 않는다.

현재는 순차 배정, 작업·운영의 실행 시도 횟수 예산, 새 세션의 선별 입력, 고정 슬롯의 전면 동일성 검토와 별도 목표 감사를 사용한다. 실패·중단도 시도 횟수에 포함하며 실제 CLI 토큰 사용량은 별도로 보존한다. 공급자 내부 호출별 계량·원격 종료·대화 압축의 완전한 관찰과 모든 호스트 경로의 읽기 차단은 보증하지 않는다. 별도 OpenAI API 키는 요구하지 않는다.

## 연결한 실행 흐름

역할별 SKILL·GLOSSARY·계약과 닫힌 모델 출력 schema를 입력으로 제공한다. 후보 준비·계약 검토·작업 선택·수행·형식 검사·동일성 검토·목표 감사·후속 계획이 한 인스턴스 상태를 통해 이어진다. query/read/export는 정확한 snapshot·내용 해시·관계 방향을 유지하며, input/configure/request와 pause/resume/close는 inbox에 요청하고 단일 writer만 Git 상태에 반영한다. 보충 조사·운영 점검·유지보수는 공개 요청 경로를 가지며 실행 실패는 운영 점검으로 연결한다.

과제 완료·활동 종료·실행 종료·K 편입·목표 해결을 구별했다. 형식 검사는 실제 Lean 컴파일과 공리 의존을 확인하고, K 편입은 같은 소스의 필수 독립 검토가 모두 match일 때만 적용한다. 이전 입력·원 출력·검사·판정은 불변 artifact로 저장한다. 실행기 소실은 미완료와 활동 unresolved로 남기며 재개 전에 상태를 정리한다.

## 실제 실행에서 확인한 수리

첫 CLI 계획 출력이 작업 ID 배열에 설명문을 섞고, 수행 전 과제까지 완료 판정에 넣었다. 필드가 소비하는 대상 상태와 정확한 ID 복사 방법을 입력에 명시하고, 오류와 이전 출력을 돌려주는 한정 수리를 추가했다. schema에 문자열 배열이 있다는 사실만으로 소비자가 기대는 의미가 전달되지는 않았다.

목표 감사에서는 완료된 동일성 검토를 숨겨, 과거 수행 보고의 검사 예정 문장이 최신 사실처럼 사용됐다. 이번 동료 판정의 비노출과 이전 단계의 완료 근거 제공을 구별하여 수리했다. 오래된 예정 문장과 후속 검사 결과의 시점을 함께 해석하도록 역할 계약에도 반영했다.

제어 요청은 접수 뒤 전제가 바뀔 수 있다. 낡은 보충 조사 요청이 inbox를 영구히 막는 경로와 완료 상태를 pause/resume으로 다시 여는 경로를 수리했다. 거부된 요청도 이유와 함께 소비하고 후속 요청을 처리하며, CLI는 접수와 적용·거부를 구별해 반환한다.

## 검증 근거와 재개 위치

새 인스턴스를 init/run 명령으로 실행해 `n + 0 = n`을 사용자 개입 없이 완료했다. CLI AI 실행 9회는 작업 6회·운영 3회였고 별도 기계 형식 검사 1회, 동일성 검토 2회, 목표 감사 2회를 거쳐 K 1개와 mathematically_solved를 기록했다. 실제 Lean 4.32.0에서 정상 증명, sorryAx, 추가 공리, 없는 선언과 잘못된 증명을 대조했다. 별도 의미 반례에서는 ∀n∃m을 ∃m∀n으로 바꾼 해설을 두 실제 CLI 검토자가 모두 mismatch로 판정했다. 작은 사례의 통과를 일반 연구 성능이나 수학 판정의 무오류성으로 확대하지 않는다.

정본 증거는 `docs/do-math/구현-검증-2026-09-14/cli-workflow/`다. 실제 입력·출력·판정·Lean 소스·Git bundle과, 마지막 제어 수리 전 실제 전체 흐름에 사용한 정확한 engine/CLI 소스를 해시 대조해 보존했다. 전체 회귀와 최종 코드 해시는 같은 디렉터리의 회귀 보고가 기록한다. portable Lean 배포는 `.skill-workspace/do-math-toolchains/`에 두며 큰 실행파일은 Git 산출물에 넣지 않는다. 사용법과 지원 범위는 do-math README와 `docs/do-math/구현-진행.md`에서 확인한다.

긴 Git 통합 검사는 여러 git subprocess 때문에 수 분이 걸렸다. 완료 출력을 회수하지 못한 것을 실패나 교착으로 추측하지 않고, 숨긴 프로세스의 로그와 최종 result.json을 파일로 보존하여 통과·실패·실제 검사 수를 회수했다. 메모리와 코드 커밋은 같은 작업 단위로 결합한다.
