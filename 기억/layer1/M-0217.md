id: M-0217
layer: 1
title: 자료원별 접근 조건을 조사하고 전용 Chrome 창 실행부를 연결함
convention_version: 24
---

사용자는 남은 자료원마다 서브에이전트를 파견해 접근 조건을 연구하고 headless가 아닌 옵션도 비교하도록 지시했다. 세 경량 작업자를 자료원별로 배정하고 완료한 작업자를 후속 독립 조사에 재사용했다. 실제 실행환경은 완료 스레드도 한도에 포함해 새 스레드 생성이 거부됐으므로 같은 작업자에게 새 source 소유 범위를 지정했다. root는 공통 조건 연구와 원 근거 검토를 병행했다. 초기 보고만 회수하고 멈추지 않고 양성 근거를 구현과 실제 MCP 검증에 연결하는 작업이 계속 중이다.

같은 초기 상태의 Playwright headed/headless 대조는 SIAM에서 모두 확인 화면이었다. root가 일반 Chrome을 전용 빈 프로필로 실행하고 로컬 CDP로 관찰하자 실제 algebra 검색 28,378건 중 첫 20건이 열렸다. 같은 일반 실행 방식의 headless는 계속 확인 화면이었다. 실행 방식·상태·화면 크기·DPI·시각이 함께 달라 창 표시 하나의 인과 효과로 확정하지 않았다. 과거 headed probe가 legacy kudos.json을 썼다는 교란도 분리했다. 근거와 각 자료원 결과는 services/scholarly-mcp/ACCESS-RESEARCH.md가 소유한다.

일반 Chrome의 KUDOS 클릭은 보이는 로그인 제어를 찾고도 안정성 검사에서 멈췄다. 실제 hit-test는 정상이었고 bring_to_front 뒤 focused=true, visibility=hidden이었다. 창 가림 시 실행 억제를 끄는 --disable-backgrounding-occluded-windows를 추가하자 rAF 두 프레임과 로그인·검색 메뉴·학술 DB가 통과했다. 단순한 이름 불일치나 대기시간 부족으로 결론을 내리지 않았다. native-gateway-101851Z/102246Z와 native-class-smoke.json이 근거다.

NativeChromeGateway는 이 조건을 사용하며 자신의 별도 프로필·Chrome PID·로컬 listener만 소유한다. Windows TCP owner를 대조하기 전에는 CDP 연결하지 않는다. 다운로드는 GUID 이름의 전용 파일과 완료 이벤트를 검산한다. 저장 상태는 kudos-native-chromium.json으로 분리하고 실패한 초기화로 기존 상태를 덮어쓰지 않는다. 드라이버 disconnect 실패 뒤에도 자체 Chrome을 회수한다. 종료 뒤 일시 파일 잠금은 새로 만든 자체 실행 폴더에만 제한된 재시도로 처리한다. 전용 6개 검사와 실제 SIAM20행·visible·자체프로필정리 시험을 통과했다.

AMS도 새 실행부의 실제 KUDOS→학술 DB→AMS→프록시에서 검색 6,589건과 SURV/168 단일 상품 원 XLSX7023바이트가 열렸다. 한 논리 상품이 ISBN 변형 3행으로 확장됐고 ProductCode 열은 비어 있었다. SIAM 원서지 RefWorks는 계정으로 넘기는 HTML 안에 RIS가 있으므로 파일이 없다는 이유로 데이터 부재라고 단정하지 않았다. 외부 import를 제출하지 않고 원 payload만 읽었다. 각 어댑터의 별도 구현 커밋에서 실제 검증 범위를 기록한다.

KUDOS의 개별 구독 범주는 실제 제공목록 2개·95행으로 구체화됐다. P+O 원 workbook의 제목 4셀에 별도 ID/PW가 포함돼 있었고 조사자의 한 도구 출력에 노출됐다. 값을 재기재하거나 사용하지 않았으며 원 XLSX를 artifact/fixture로 내보내지 않는 정제로 수정했다. 이미 출력된 내용의 삭제·자격 폐기·교체는 확인하지 않았다. 기존 [[M-0203]] 사고의 역사 감사도 완료로 바꾸지 않는다.

다른 운용 이탈도 보존한다. Chrome --version 호출은 Windows에서 기존 세션으로 전달됐다는 메시지를 반환했으며 정확한 UTC는 남지 않았다. 이후 실행 파일 속성만 읽고 기존 세션을 추가 조작하지 않았다. 초기 owned-rwfpkp09 폴더 수동 삭제는 자동 승인 검토가 거부해 보존했다. 다른 도구로 재시도하거나 새 cleanup 코드에 해당 폴더를 연결하지 않는다. 뒤 시험의 run_removed=false는 실패경로 변수 미대입이었고 실제 새 잔존이 아니어서 정정했다.

전체 작업은 진행 중이며 푸시하지 않는다. 저장 상태를 격리한 새 SDK를 사용하고 Codex·등록 MCP·CLI·취소된 재시작 자동화는 조작하지 않는다. 별도 API키·계정·연락 이메일은 사용하지 않으며 Scopus 추가 계정과 Unpaywall 보류를 유지한다.
