[[M-0501]] 이후 사용자가 반복된 계획 검토와 수행 방식의 정체를 지적했다. 대화 원문과 당시 명령을 대조한 기록은 docs/do-math/시험-재편-2026-09-29/작업-방식-재검토-2026-10-03.md의 10월 4일 절에 보존했다. 중간 통합 검사와 최종 완료 검사를 혼동해 검사 필요성을 번복했고, 현재 작업판의 상태 대신 새 감사 파일을 계속 추가한 것이 확인됐다. simplify 요청 뒤 사용자가 재량 수행을 지시했으므로 기존에 확인한 공백의 교정부터 실행했다. 새 관리 체계나 전수 감사를 선행하지 않는다.

B85는 제품 동작을 바꾸지 않는다. 프로세스 생성의 creationflags 키 존재만 검사하던 곳을 표준 CREATE_NO_WINDOW 식의 실제 사용 검사로 강화했다. setup 전용 중복 검사는 일반 호출 전건 검사로 흡수하고, 네이티브 CreateProcessW의 실제 여섯째 인자가 검사한 flags이며 창 억제와 suspended 비트를 OR로 전달하는지 확인한다. 두 Win32 상수의 실제 정수 값도 고정한다. closed 결함 KD-0003의 재현 연결과 현재 의무 연결은 흡수한 검사로 옮겼다. 과거 실행 결과와 선택 색인은 수동 갱신하지 않았다.

저장 필드 검사의 UNPRODUCED는 반복 한도 다섯 설정이 무시된다고 설명했으나 실제 revisions.record_repetition은 lineage + '_limit'로 읽는다. 해당 실제 소비식의 존재를 확인한 뒤 task_contracts.REPEAT_LINEAGES에서 계산한 이름을 반영하고 거짓 미사용 예외를 제거했다. 이는 이름 사용 검사이며 모든 저장 분기의 의미 검증은 아니다. 기존 실제 반복 검사가 다섯 lineage 각각의 한도 도달·중복 미계수·정확한 사용자 계속 결정을 확인하므로 기능을 새로 구현하거나 같은 검사를 복제하지 않았다.

직접 검사 10개가 10.4초에 통과했다. 구조 전체와 반복 보류 검사 48개가 40.6초에 통과했고, 결함 원장의 옛 검사 ID를 교정한 뒤 최종 관련 11개가 12.4초에 통과했다. 세 보고 모두 실행 중 소스 변경이 없다. 원보고는 검증/2026-10-04-경계-설정-정적검사/에 바이트 그대로 보존한다. 최종 report.json SHA256은 0b30d0ff6cfeb2ba6d04945e62cbd703480de34c35d6b60beaab37e829d0d86b다. 서로 다른 판본의 결과를 합쳐 전체 일반 통과로 표시하지 않는다.

기존 B84 원문 검수의 1-D 저장 왕복과 11-A 역할 호출 수 증거는 대상 시험·지원 파일 해시가 일치함을 확인하고 작업판에 직접 반영했다. 이 두 항목은 같은 의미 검토를 다시 요구하는 상태에서 구현 검토 완료·최종 실행 대기로 구별했다. 출처와 구체적인 단언 근거를 기존 JSON 안에 보존했다. 9-A의 지급 명령 인터프리터 모집단과 1-A/1-B의 실제 쓰기 분기 연결 등은 남김으로 유지한다.

B84의 3924개 전체 실행은 재개 시 세션과 소유 프로세스가 없고 최종 보고서도 없었다. 중간 작업자는 72·32개이며 complete=false다. 종료 원인을 추정하지 않고 미완결로 기록했으며 running/동결을 현재 명령으로 이어받지 않았다. 새 전체 목표를 등록했고 다음 작업은 9-B의 실제 녹화 자료와 지원 판본 연결이다. 원래 요구·fresh T3·전 대상 변이·T4/T5·최종 통합 관문은 유지한다. 시험 timeout을 재도입하지 않는다.
