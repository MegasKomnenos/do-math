학술자료 MCP 구현을 계속했다. 사용자가 정한 공개 API 기준은 별도 API 자격 없이 호출할 수 있는 API이며, API 실패를 브라우저 전환 조건으로 삼지 않는다. Scopus·IEEE·PQDT는 KUDOS 로그인 뒤 학술 DB 바로가기를 거친 Firefox 경로로 연결했다. Scopus 검색·원자료 보존과 웹 계정이 필요한 native export를 구별한다. native export 제어가 별도 Scopus 계정 로그인을 요구한 사실을 확인했고 보호 파일 경로를 질문했다. API 키를 다시 요청한 것이 아니다. Unpaywall의 키 없는 API는 연락용 이메일을 요구하는 HTTP 422를 반환해 사용할 실제 이메일을 별도로 질문했으며 아직 입력되지 않았다.

실제 MCP 클라이언트에서 Scopus의 페이지 경계 조회·CSV·추출·EID 서지와 초록, IEEE의 Command Search·초록 포함 BibTeX·PDF, PQDT의 제목 검색·RIS·서지·초록·40쪽 PDF를 확인했다. DROPS의 검색과 공개 Schema.org 메타데이터·PDF, Crossmark가 사용하는 Crossref API의 검색·추출도 연결했다. 전체 선정 자료원의 구현 완료를 선언하지 않는다. 정확한 검사 범위와 로컬 증거 경로는 services/scholarly-mcp/VALIDATION.md에 있다. 공통·자료원 검사 51개가 통과했다.

Scopus는 같은 검색 endpoint에 preprint의 별도 건수 조회와 primary 문서 요청을 보냈다. primary 분류와 원 query를 대조하지 않으면 빈 preprint 응답을 문헌 검색 결과로 오인할 수 있다. itemCount는 수신 건수가 아니라 페이지 수용량이었다. 단일 문헌 응답에서도 값은 10이고 실제 문헌은 1개였다. 이 실측을 회귀 fixture로 보존하고 전체 건수·offset·수용량과 실제 배열 길이를 대조한다.

PQDT의 publication number와 docview 번호는 다르다. 회수한 논문은 publication number 28843251, docview 2618193239이며 native RIS의 AN은 후자다. 같은 문헌의 PDF 첫 쪽에서 제목과 저자 Chinmay Mukhopadhyay를 대조했다. 지연 표시되는 OneTrust 창은 준비와 거부 완료를 확인해야 했다. RIS는 별도 export 창에서 내려와 원 검색 탭의 download 이벤트만 기다리는 방법은 실패했다. 같은 ProQuest의 실제 RIS 응답을 받아 선택 문서 AN과 대조하도록 바꿨다. PDF 화면의 전체 load 대기와 접근성 이름 선택자도 실패하여 문헌 번호에 결합된 다운로드 제어를 확인한다. 연속 검색·추가 페이지 범위와 다른 내보내기 형식의 검증은 남아 있다.

진단 중 ProQuest 상대 링크의 CSRF 값이 도구 출력에 포함됐고, 뒤이어 PDF 전송 URL의 `_a`·`_s`가 기존 정제기를 통과했다. 각 사고를 사용자에게 즉시 알렸으며 값을 재기재하지 않았다. 해당 브라우저는 종료했지만 앞선 출력 자체를 삭제한 것은 아니다. 상대 URL, 서명 매개변수와 중첩 URL 정제를 수리했다. 기존 KUDOS 세션을 재사용하는 경우에도 보호 파일의 ID/PW를 정제기에 등록하도록 보완했다. 확인한 9개 값을 값 출력 없이 코드·문서·fixture·20MB 이하 로컬 산출의 원 표현과 URL 디코딩 표현에서 검사하여 일치 파일이 없음을 확인했다. PDF 내부 압축·이미지까지 검사한 것으로 확장하지 않는다. 원 진단 파일은 `.credentials/scholarly-mcp/probes`에 있으며 Git에 넣지 않는다. 인증된 링크를 진단할 때 전체 href나 쿼리를 출력하지 않고 필요한 호스트·상태·문헌 식별자만 선별해야 한다.

AFP 공식 다운로드 안내가 가리키는 Heptapod의 공개 API는 프로젝트·Mercurial 커밋·파일을 자격 없이 반환했다. 기본 afp-devel의 branch/default를 커밋으로 고정하고 그 커밋의 항목 TOML과 증명 소스를 회수하도록 구현했다. Cook_Levin의 검색·서지·초록·증명 소스와 archive 내부 22개 항목 목록을 실제 MCP에서 확인했다. 저장소가 반환한 application/octet-stream을 그대로 추출기에 넘긴 첫 검증은 실패했다. tar.gz임을 실제 파싱으로 확인한 archive에는 그 MIME을 붙이고 원 응답 참조도 유지하여 재검증을 통과했다. 개발판·릴리스·커밋을 구별하며 소스 회수를 Isabelle 검증 성공으로 표현하지 않는다.

출판사 후보 어댑터는 메타데이터의 문헌 식별자와 문헌에 결합된 PDF 제어를 사용한다. Springer 서지·초록·PDF는 직접 어댑터 호출로 확인했고 MCP에 연결했다. Project Euclid는 메타데이터·PDF, AIP는 메타데이터·초록, Oxford는 메타데이터를 회수했다. Oxford PDF는 watermark02.silverchair.com으로 이동해 현재 호스트 경계에서 중단됐다. AMS의 새 pubs.ams.org 호스트를 확인했고 목록에 반영했다. Cambridge·JSTOR·SIAM의 대기 실패와 ScienceDirect 프록시의 CPE 오류는 관측으로 남아 있다. 후보 전체를 완료로 세거나 모두 MCP에 연결한 것은 아니다.

문헌 화면의 이동 전후에 자료원 호스트를 확인하고, 다운로드는 허용하지 않은 redirect에 다음 요청을 보내기 전에 중단한다. 이 동작과 URL을 포함할 수 있는 브라우저 예외의 안전한 시간 초과 변환을 검사했다. 이를 모든 하위 리소스의 네트워크 격리로 확대하지 않는다. stdio 다섯 도구와 실제 자료 참조·기계적 추출 계약은 유지한다. 이 커밋은 진행 중 구현의 보존 단위이며, 출판사·보완 자료원, native 기능과 큰 범위·연속 호출 검증을 계속해야 한다.
