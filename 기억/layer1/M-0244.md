사용자 세 기준에 따른 23개 CLI 재검토와 병행해 주 세션이 Springer 과제를 직접 검토하고 첫 사본 수리를 원본에 통합했다. DOI10.1007/s00037-008-0249-x의 형식 분류 대상이며, 다른 파견 사본의 구현은 아직 원본에 통합하지 않았다. 원본 전체 516개 검사와 새 SDK의 15개 판정이 통과했다.

주 세션은 과거 실패 직전·직후·안정 화면을 먼저 직접 읽고, 별도 소유 KUDOS 상태와 브라우저로 같은 문헌을 새로 열었다. .credentials/scholarly-mcp/probes/root-user-criteria-20260913T0715Z/springer/run-20260913T071554Z가 수정 전 실행이다. 07:16:30.933240Z부터 07:16:31.104105Z까지 원 parser는 not_implemented/html_fulltext_not_identified를 반환했다. 새 전체 화면 3장도 직접 읽었다. 동일 제목·기관 접근·초록·Article PDF·저자·서지 정보가 유지됐고, sidebar는 첫 캡처 이후 렌더됐다. 실제 .main-content는 텍스트 0자·자식요소 0개였다. 같은 실행의 양성 문헌은 7개 본문 절과 29,102자를 제공했다.

작업자 사본은 초록·PDF preview·PDF 제어가 있으면 형식 부재로 분류하는 변경을 제안했다. 원본에는 더 좁은 조건으로 통합했다. 실제 .main-content 컨테이너가 존재하고 텍스트와 자식 요소가 모두 없는 관측 레이아웃만 not_found/html_fulltext_not_available로 분류한다. 인식하지 못한 텍스트나 이미지가 본문에 남으면 not_implemented를 유지한다. 이 두 상태를 구별하는 회귀를 먼저 추가했고, 원 코드의 not_implemented가 예상 not_found와 달라 실패하는 것을 확인했다. 수리 후 publisher HTML 10개 검사, 원본 전체 516개 검사가 71.651초에 통과했다.

수정 후 새 브라우저 실행은 같은 전용 경로의 run-20260913T072009Z다. 새 원본 server.py를 사용한 SDK는 sdk-integrated/report.json에 있으며 07:23:31.103974Z부터 07:24:37.758298Z까지 실행됐다. metadata·abstract·28쪽 PDF가 available이고 native HTML만 not_found인 partial을 확인했다. PDF 372,391바이트·제목·DOI·이미지 운반이 통과했고 주 세션이 실제 첫 쪽 이미지를 직접 읽었다. 양성 문헌의 native HTML 7개 절 추출도 성공했다. 정제 근거는 data/access-research/user-criteria-springer/root-ui.json과 root-sdk.json, 사건별 기준 판정은 캠페인의 springer-html-negative/criteria-review.json이다.

전체 페이지 캡처의 하단에 기관 접속 IP와 내부 기관 식별번호가 보인 뒤 주 세션이 별도 마스킹 절차를 추가하려 했다. 사용자는 그런 표시 때문에 캡처를 복잡하게 만들지 말라고 교정했다. USER-CRITERIA.md와 23개 재개 프롬프트 파일에 이를 반영하고 전용 재현 스크립트의 footer 마스킹을 제거했다. 실제 암호·인증 토큰의 비공개 경계는 유지한다. 사용자 교정 이전에 생성된 마스킹 화면 때문에 다시 촬영하는 작업은 하지 않았다.

이 수리는 해당 PDF-only 문헌에 HTML 버전을 새로 만든 것이 아니다. 확인된 자료 형식과 아직 식별하지 못한 레이아웃의 오류 분류를 구별하고, 정상 PDF·초록·다른 문헌 HTML 기능을 보존했다. 지원표와 감사 문서의 최초 514개 검사 기준선을 현행 재검토 완료로 오인하지 않도록 현재 상태를 함께 적었다. 사용자 세 기준의 나머지 23개 과제는 같은 thread·사본·최대 8개 실행으로 계속 진행 중이다.
