[[M-0515]] 뒤 기존 목적 수준 지식 현재성 흐름을 확장했다. 공개 knowledge invalidate와 revise는 서로 다른 요청 ID를 갖고, 해당 지식 ID와 각 source_ref를 가진 계획 요청이 하나씩 만들어진다. 기존 연구 해결 흐름 안에서 두 요청 모두 실제 모델/worker를 통해1회 수락되고, 실행 action의 지식/원요청 좌표가 보존됨을 검사한다. 실제 해결 후 두 owner 순회에서 전체 호출 수가 늘지 않는다. 이전 평가·완료된 후속 과제 결과 보존과 수정된 지식의 새 독립 검토·목표 감사라는 기존 단언을 유지했다.

위임 반환은 기존 test_closed_delegate_returns_obligation_and_queues_one_replan의 모든24개 문장을 AST로 대조하여 그대로 유지했다. 실제 과제/준비 수신자가 만든 delegation과 실제 철회 생산자로 원래 개정 의무가 반환되는 장면이다. 원래 검사에는 정확한 전체 queue 병합, delegated_targets 제거, delegation_history, 동일 reconcile 재적용 불변, 저장 후 재시작의 대기 보존이 있었다. 여기에 revision_followup의 record_id/task_id를 가진 계획의 실제1회 수락과 추가 두 순회의 중복 없음을 덧붙였다. 반환하지 않은 원래 의무를 임의로 없애지 않는다.

실제 호출까지 포함하게 되어 위임 검사를 sim.test_planning_revision_obligations에서 flows.test_scheduling_research_recovery.DelegatedRevisionPlanningTests로 옮겼다. 메서드 이름과 기존 단언을 보존하고 known_defects의 현재 재현 ID와 현재 의무 연결을 갱신했다. 과거 원보고와 역사 ID는 소급 수정하지 않았다. 파일 직접 실행에서도 새 클래스가 정의된 뒤 unittest.main이 호출되게 했다.

제품 코드는 변경하지 않았다. 지식 직접1개가114.8초, 위임 직접1개가52.8초에 통과했다. 최종 구조48·기존 개정Sim9·확장flows2, 총59개가170.1초에 통과했고 실행 중 소스 변경은 없다. 목적 흐름은 해결까지 두 차례 진행하므로 단독114.75초/병렬167.547초의 본문 비용이 있으며 기존60초 기준 초과 사유를 유지한다. 추적 원보고는 검증/2026-10-05-지식-개정-발동/이며 report.json SHA256은 73453273ee95c814f28e00f9e929af6fad2d58d2345433ac6b314bb2c0797ad6다.

B99는 공개 지식 제어 두 원천과 닫힌 위임 과제 반환의 실제 호출 범위다. 목표 근거 상실·개정 순환·평가 변화·선택 무효화·학술 후속/반려·일반 입력초과·수락 결과의 다른 원천은 남김이다. B96 이후 source_ref 등 판단 데이터의 충돌 시 요청을 나누는 규칙이 이 흐름에서도 실제로 소비된다. 최종 전체 일반/T3/변이/실환경/문서 관문은 계속 유지한다.
