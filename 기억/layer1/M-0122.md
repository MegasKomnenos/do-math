## 맥락

사용자는 기존 통합 설계의 과도한 복잡성과 새 초안의 내용 성숙도·유효 요소 누락을 우려했다. 두 문서의 본문·표·워크스루·벡터를 전부 읽어 비교한 뒤, 적용 방향의 실익과 구체 작업 절차를 물었고 마지막에 진행을 지시했다. 합의한 방법은 기존안 전체를 보존 검토의 기준으로 삼되 실행 구조는 타당한 쪽을 선택해 초안을 재작성하는 것이다. 앞선 지적 몇 곳만 보강하거나 원문 문장을 기계적으로 합치는 방식은 범위가 아니다.

기존안 3068행·3차 초안 1258행과 CONTEXT·지도 컨텍스트의 바이트 사본/해시를 docs/do-math/재구성-2026-09-06에 보존했다. 개정안은 기존안 192개 절 구간·초안 100개 절 구간, 기존 테스트 목적 246개를 각각 대응했다. 표제 구간과 내용 구간은 구별하며 행수의 전건성을 의미 보존의 자동 증명으로 쓰지 않았다. 문서 검증기는 실제 원문 행·목표 절·벡터·로컬 링크·Markdown 표·패치를 대조한다. 런타임·Lean·독립 외부 AI 검증은 수행하지 않았다.

## 선택과 검증

단일 실행기/상태 머리, 공통 실행, 과제 대기와 원격 자원 정산의 분리는 유지했다. 지속적 탐색의 예정 사건, 작업별 기대 변화·진전 증거, 충분한 착수 입력, 수학 해설의 주 산출물 지위, 양화·중요 증명 단계, 프로젝트 추가 감사와 현재 해답 판본별 학술 검증을 새 구조에 연결했다. OKF의 기본 필드·항해는 보존하면서 새 type/subkind와 native YAML 자료형을 사용한다. 세 기본 검토 관점과 필요한 전문 분야를 하한으로 유지하고, 전건 match·무쟁점이면 중복 최종 AI 없이 기계 관문으로 가며 쟁점 경로는 셋의 독립 최종 판정과 unresolved를 사용한다.

수리 대조에서는 착수 승인을 실제 시작에 연결하는 조건, 과제 revision과 수학 객체의 새 정체성 경계, queued가 남은 대기, 호출 뒤에 생기는 외부 ID, YAML의 NFC·개행, 초기 검토 미완료의 분기, 학술 거부의 기계 입력, 일반 완료 판정의 활동 소유자, 초기 프로필의 사전 능력 검사, 판정 사용 효력의 최초 값·근거를 보강했다. 기존 L11의 해시 변경→새 제안은 기존 19.11절과도 어긋나므로 예기치 않은 훼손과 의도적 수정을 나누어 대응했다.

문서 검사 첫 실행에서 Python write_text의 Windows 개행 변환이 확인됐다. 생성기 출력에 newline을 명시해 해결했다. 원문 대응·벡터·정의의 JSON 자료와 사람이 읽는 표를 함께 보존하고 실제 검증 결과를 별도 JSON으로 남겼다. 동기화 패치는 git apply --check를 통과했다. 현행 통합-설계.md·CONTEXT.md·지도 컨텍스트는 변경하지 않고 채택 때 적용할 수정안으로 준비했다.

## 남은 선택과 재개

Q1: 개별 사용자 결정을 전례로 삼아 유사 사례에 재사용할지, 명시한 재사용 범위 안에서만 자동 적용할지 질문했고 이 커밋 시점에는 회신이 없다. 회신 전 13.2절은 3차의 후보 문면을 유지하며 새 사용자 승인으로 기록하지 않았다. 결정.json, 검토기록, 대응표의 전례 항목이 대기 상태를 표시한다. 답이 오면 13.2절·전례 벡터·정의 수정안·결정/검토 기록을 함께 확정해야 한다. 정본 채택과 실제 어댑터·공급자·수학 검토 효능·규범 스키마 검증은 이 문서 작성의 완료와 별개다.

집필용 스크립트는 임시/do-math-rebuild에 남는다. rebuild.py는 보존한 3차에서 재생성하므로 실행 전에 현재 초안 해시가 자기 직전 출력과 같은지 검사한다. 사용자가 그 뒤 문서를 고쳤으면 그대로 재실행하지 말고 원문을 다시 대조한다. 검토 산출물과 현재 초안만 이번 작업 단위이며 다른 세션의 문헌조사·설정·실험 디렉터리는 포함하지 않는다.

커밋 준비 중 다른 세션의 가상 키보드 작업이 같은 Git 색인에 올라왔고, 그 세션은 자기 범위를 M-0123과 함께 먼저 커밋했다. 우리 M-0122와 색인 줄은 워킹트리에 유지됐으므로 재번호나 다른 커밋의 되돌림 없이 경로를 지정해 따로 편입한다. 또 core.autocrlf가 사본 해시를 바꿀 수 있어 관련 문서 넷의 LF와 감사 디렉터리의 바이트 보존을 gitattributes로 고정했다. unified diff의 빈 문맥 행은 공백이 데이터이므로 해당 패치만 whitespace 예외로 두고 apply 검사를 사용한다.

Git 색인에서 관련 자료 22개를 임시 경로로 checkout-index해 워킹트리의 검사한 바이트와 비교했고 차이가 없었다. 원문 사본의 해시가 현재 머신의 LF에만 기대지 않는지 확인한 것이며 수학·실행기 검증을 대신하지 않는다.

## 작업 너머 시사점

연구 판단의 구체성을 보존하는 것과 기존의 실행 기구를 보존하는 것은 별개의 검토다. 원문 전체를 감사 기준으로 남기고 새 구조에서 소비자·시점·후속을 다시 연결하면, 과거 문면 유지와 의미 누락 사이의 이분법을 피할 수 있다. 새 기능의 내용이 산문에 있어도 기계 파생 상태가 읽을 필드와 최초 생성 주체가 없으면 연결이 완성되지 않는다. 이 검토는 문서 이식 단계에서도 같은 문제가 재발할 수 있음을 보여준다.
