# Jev 호출 도구의 목적과 경계

사용자는 처음에 AI 에이전트의 도구 호출을 위한 MCP 방식으로 TypeSafe Jev를 쉽게 쓰게 하자고 제안했다. 목표와 설계를 구체화하는 인터뷰 스킬인 `grill-me`도 요청했다. 인터뷰에서 목적을 API 통신 세부사항의 은닉으로 구체화했다. 호출자는 판단 대상·맥락·질문·선택지·평가 기준처럼 상황마다 달라지는 정보를 직접 지정하고, AI 에이전트와 셸 스크립트가 같은 도구를 재사용하기를 원했다. 특정 운영체제나 저장소에 종속되지 않는 도구와 사용 설명서를 요구했다. 필요한 실행 환경 설치는 허용하되 불필요한 의존성은 추가하지 않는다는 조건도 확정했다.

사용자는 Python 표준 라이브러리 CLI와 파일·표준입력·JSON 출력 계약을 승인했다. 구현은 `services/jev-cli/jev.py`, 사용 안내는 같은 폴더의 `README.md`, 실행 예제는 `examples/request.json`에 있다. 스크립트를 다른 위치로 복사해 실행할 수 있다. 질문의 의미를 내부 프리셋으로 제한하지 않고 Choice(후보 선택), Score(단계 점수), Noul(참일 확률)을 제공했다. 질문 지시인 instructions와 판단 기준인 criteria에는 구조화된 값도 그대로 전달한다. 공식 HTTP API 설명보다 구조 문서가 null을 허용하는 위치를 더 넓게 명시하므로 `https://docs.typesafe.ai/primitives/advanced`의 허용 형태도 반영했다.

재시도는 일시적 HTTP 오류에만 횟수를 제한해 적용한다. 연결 중단이나 시간 초과는 서버가 이미 요청을 처리했을 수 있어 자동 반복하지 않는다. 이 선택과 모델 선택 우선순위, 확률·신뢰도 해석을 사용 안내에 적었다. 별도 SDK 없이 표준 라이브러리로 이 범위를 구현했다.

## 확인한 범위

Windows Python 3.12.10에서 `services/jev-cli/test_jev.py`의 18개 검사가 통과했다. 실제 로컬 HTTP 서버로 정상 요청·리다이렉트 차단·인증 오류와 키 가림을 확인했다. 재시도와 손상된 응답 처리는 실제 서비스 대신 준비된 응답·오류를 돌려주는 테스트 구성으로 검사했다. 비정상적으로 큰 수치와 읽다 끊긴 HTTP 오류 본문이 일반 예외로 새어 나오는 경로는 먼저 재현한 뒤 구조화된 오류로 수정했다.

설정된 API 키로 공개 예제에 대한 실제 Jev 요청을 두 번 수행했다. 파일 입력과 다른 작업 디렉터리에서의 표준입력이 각각 성공했고, 두 응답 모두 모델은 `jev-1.13.0`, 사용량은 입력 547·출력 70토큰이었다. 키 값은 출력하거나 기록하지 않았다. 이 호출은 연결과 응답 계약을 확인한 표본이며 도메인별 판단 정확도의 근거가 아니다.

Linux는 설치된 WSL 배포판을 실행하려 했으나 호스트가 `HCS_E_HYPERV_NOT_INSTALLED`를 반환했다. 호스트 설정은 바꾸지 않았다. macOS와 다른 Python 버전도 실행하지 않았으므로 호환 설계와 실행 검증을 구별한다. 후속 사용 시 해당 환경의 `test_jev.py` 실행과 실제 서비스 연결을 확인해야 한다.

작업 당시 do-math 등 다른 작업의 변경이 많이 남아 있었다. 이번 커밋 범위는 Jev 도구, 루트 README의 진입 링크, 이 노드와 색인 줄이다. 작문 독해 원문은 `.codex/writing-flow/`의 로컬 보관 자료로 Git 제외 대상이며, 후속 사용의 정본은 추적된 사용 안내와 코드·검사다.
