## 연구 인스턴스와 원자료

인스턴스는 `RI-01M2JP80JC7RHQAJ7QGRPYZQEG`다. Git 정본 저장소는 `C:\math\.skill-workspace\parking-unimodality-20260915\repo`, 실행 작업 공간은 같은 상위 폴더의 `work`다. 정본은 저장소의 `refs/heads/do-math/RI-01M2JP80JC7RHQAJ7QGRPYZQEG`에 있으며, 루트 작업 트리의 파일 목록으로 실행 상태를 추측하지 않는다. `.agents/skills/do-math/scripts/do_math.py status`에 이 repository와 instance를 지정해 현재 상태를 읽는다.

선정 근거 문서를 목표 원문으로, 후속 연구 준비를 정책으로 보존하고 선행연구·원문 PDF·추출물·독해 기록을 입력했다. 학술 완료 기준인 기존 정리와의 실제 대조, 핵심 구조의 설명, 일반적인 적용 범위와 한계의 명시는 academic_requirements로도 등록했다. 정확한 세 질문의 원문은 선정 근거 문서 §5와 인스턴스의 해당 필드에서 읽는다. 기존 자료 재현 검사는 34개 모두 통과했다. scholarly-mcp의 arXiv 검색과 메타데이터 확보는 시간 초과, zbMATH 검색은 HTTP 404로 끝났다. 이를 문헌 부재로 처리하지 않았다. scholarly-mcp의 author-repository로 저자 공개 PDF를 확보했고 기존 보존본과 SHA-256이 일치했다. 추측 6.5와 표가 있는 23–24쪽을 다시 읽었다. 공식 arXiv 페이지의 판본은 v1이었다.

후보 준비는 정확 계산, 점화식 차분, 인접 제한 사이의 자리 보존 대응, 순열별 곱 차분을 제안했다. 독립 계약 검토는 자리 보존 대응과 순열별 곱 차분 과제에서 조사 범위와 완료 갈래의 불명확성을 지적했고 후보 준비가 계약을 개정했다. 개정 계약과 검토 근거는 인스턴스의 task 기록에 보존돼 있다. 문헌 현재성 과제도 추가됐다. 연구 계획은 먼저 n≤50의 정확 계산, 이어 점화식 차분 과제를 선택했다. 예산 변경 뒤 실제 research_work 실행이 시작된 것을 확인했으며, 이 기록 시점에 원 문제의 증명이나 반증은 확보하지 않았다.

## 무제한 예산의 구현과 적용

기존 구현은 work_calls와 operations_calls에 양의 정수만 허용했다. 큰 정수를 무한대로 표시하지 않고 두 필드의 null을 실행 횟수 상한 없음으로 지원했다. 기본값 40·30과 양의 정수의 유한 상한 의미는 유지했다. 일반 배정, 개별 실행 착수, 실행 중 운영 점검, 동일성 검토자의 보충 조사에서 같은 예산 판정을 사용한다. JSON 상태와 역할 입력은 limit=null을 보존하고 사람용 상태는 unlimited로 표시한다. 사용 횟수는 계속 누적한다. 실행 시간·검토 횟수·행동 허가는 별도 설정과 계약이다.

연구를 일시 정지해 진행 중 기록을 회수한 뒤 정본 코드와 안내 문서를 수정하고 Codex 사본을 재생성했다. configure로 두 null을 적용했으며, 당시 작업 5회·운영 8회의 사용량이 유지됐다. 저장 상태 검사 뒤 resume과 run을 실행했다. 새 실행이 시작되고 작업 사용량이 늘어도 두 limit가 null인 상태를 확인했다.

## 검증 범위

전체 회귀는 281개를 실행해 280개 통과·1개 미실행이었다. 미실행은 Windows의 심볼릭 링크 생성 권한 부족(WinError 1314)으로 건너뛴 외부 링크 수집 검사이며, 해당 파일을 별도로 실행해 같은 사유를 확인했다. 이 회귀의 수집 이후 추가한 두 예산의 혼합 유한·무제한 검사 1개는 별도로 통과했다. 생성된 Codex 사본에서도 무제한 관련 동작 검사 5개가 통과했다. 검사에는 유한 예산 소진 뒤 무제한 전환과 실행 이력 보존, 한쪽만 무제한인 경우, CLI 상태, 실행 중 운영 점검과 검토 보충 조사가 포함된다. 설치 문서·역할 스키마 검사와 스킬 사본 드리프트 검사도 통과했다.

CLI 계약과 공통 실행 문서의 전체 독해 결과를 확정된 변경 의미와 대조했다. 독해자는 null이 실행 횟수 상한만 없앤다고 정확히 이해했다. 코드 회귀와 저장 관계 검사는 수학적 해결이나 연구 성능의 인증이 아니다. 이후 연구는 위 인스턴스의 현재 상태와 보존 결과에서 이어간다.
