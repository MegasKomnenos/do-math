g08 작업자가 검증된 코드·시험·로그·종료된 실행 manifest를 명시 목록으로 인계하여 중간 보존한다. 루트는 checkpoint-ready.json의 SHA와 목록 56개 파일의 개별 SHA가 현재 디스크와 모두 일치함을 확인했고, 100개 unittest 시험이 32.555초에 통과한 로그와 실제 실패·수리 기록을 읽었다. 명시 경로의 Git 공백 검사를 통과했고 자격 파일의 ID·PW 리터럴도 없었다. 원문과 결과·진행 파일은 이 코드 단위에 포함하지 않는다. 시험은 현재 작업 공간의 보존 원자료와 일부 g05 UI 증거를 사용하므로 원자료가 없는 새 체크아웃만으로 실행 가능하다는 뜻은 아니다. 이 검사 범위는 g08-checkpoint-verification.json에 남겼다.

g08의 현행 실행은 저장된 MR·Summon 증거를 재사용하고 필요한 출처·PDF·직접 검토를 연결한다. PDF 후보의 앞 세 개 상한을 없앴고, Article의 같은 탭·새 탭 이동을 구별한다. 실제 저자 페이지의 전체호에서 Vakil 논문을 추출할 때 앞 글이 함께 들어가는 첫 면의 경계를 따로 검토했다. 저자·제목·발행정보의 부제나 원어 차이도 대상 판본과 근거를 비교한다. 같은 책의 다른 연도 판본이나 다른 논문을 입력에 붙이지 않는다. 공개 검색은 입력 URL 없음·MR Article 비활성·Summon 무결과로 닫혔던 27건에 보완하여 54회를 수행했고, 발견한 링크의 실제 회수는 계속한다.

루트의 최신 부분검사에서는 새 abstract 검토가 mathscinet-review 파일을 참조하면서 같은 결과의 evidence 목록에는 그 파일을 넣지 않은 두 실물 사례를 발견했다. 공통 pending_work는 이를 완료로 인정하지 않았다. g08은 실제 review·description artifact를 결과 증거에 결박하는 함수와 중복·해시 검사를 추가하고 해당 결과들을 다시 검사했다. 파일이 존재한다는 사실과 소비자가 그 파일에 도달할 수 있는 근거 결박이 별개의 조건임을 보여 준 사례다.

ScienceDirect의 정상 기관 상세에서 View PDF는 최초에 href가 없고 aria-disabled=true였다가, 초기화 후 목표 PII의 다운로드 주소를 갖는 제어로 바뀌었다. g08은 늦은 초기화·목표 PII 대응·참고문헌 PDF 배제·중복 주소 제거를 시험했다. 같은 주소의 request.get과 page.goto가 CPE00001을 반환했을 때 루트는 실제 활성 제어의 locator.click도 구별하여 수행하도록 했다. 클릭은 정상 새 PDF 탭을 만들었으나 다운로드와 PDF 응답은 없었고 새 탭 본문 역시 CPE였다. 따라서 제어 처리 수리는 검증됐지만 이 경로의 원문 확보 성공은 없다는 범위를 보존한다. 한편 g05에서는 다른 자료의 관측 다운로드 주소가 Preparing your download HTML을 반환해, 브라우저의 후속 동작을 조사하고 있다. 이 단계의 성공은 아직 본 커밋의 근거가 아니다.

루트의 Scopus 준비 조사에서는 Firefox 기본 설정과 KUDOS 정상 바로가기에서 문헌 검색 폼이 열렸다. 앞선 Chrome Cloudflare 화면과 다르다. 처음에는 외곽만 표시되고 입력이 없었으며, 준비 뒤 기본 입력은 동적 autosuggest ID를 가졌다. Search within의 실제 select는 data-testid=select-search-within이고 DOI를 선택하면 입력이 data-testid=search-field-input으로 바뀌었다. 선택 전 입력의 ID를 계속 쓰면 실패했다. 실제 g07 첫 DOI10.1163/19606028-90000199 검색은 대응 문헌 한 건을 반환했고, 제목·Paris·2014·Cahiers de Linguistique d'Asie Orientale2(1)이 화면에 표시됐다. 제출 직후의 빈 외곽은 무결과가 아니었다. 고급검색에서는 표제·설명·도움말이 보였지만 편집 입력을 확보하지 못했으므로 기본 DOI 검색의 정상 경로를 우선 사용했다.

EBSCO의 전체 전자책 다운로드 메뉴는 로딩 뒤 별도 MyEBSCO 개인계정을 요구했다. 루트는 실제 Sign in 뒤 개인계정 폼까지 확인하고 값을 제출하지 않았다. 이를 기관 인증 실패와 구별한다. 정확한 Connes1994판이 EBSCO에도 있다는 후속 보고가 있었지만, 루트와 g08이 같은 저자 공식 출판 목록에서 정상 공개 PDF 링크를 발견하여 그 회수를 우선했다. g08은 654쪽 전자본을 확보했고 다른 기관 미러가 같은 SHA임을 보고했다. 저자 배포 전자본의 쪽 체계와 인쇄 xiv+661을 구별하는 판독·결과 반영은 계속된다.

g02는 resolver의 전자자료 없음 문구를 접근 제한으로 분류한 오류를 고쳤다. 루트가 확인한 Methods of summation 사례의 실제 CiNii URI도 출처 작업으로 복구했고, 완료 후보를 포함한 저장 888건을 재판정했다. no_resource 관측 259개가 정정됐다. 이후 새 수집과 저장 900건의 재판정까지 진행했다. 원 MR이 완결되게 선택한 Gradient flows·CRC handbook의 인용도 실제로 읽고 적용했으며 훼손 Summon 문구 철회와 새 정상 출처를 구별했다.

g02의 실제 921초 실행은 새 결과 18건을 처리했다. 루트는 범위를 줄이지 않고 고정 입력 위치로 두 흐름을 나누는 실물 시험을 허용했다. 입력 5138개의 중복·누락 없는 분할과 소유권·원자저장·진행 분리를 시험하고, 작은 실물 범위에서 요청 오류와 처리시간을 비교하도록 restart-contract에 명문화했다. 두 흐름은 서로 다른 신규 2건씩을 각각 56.8초와 111.9초에 처리했고 인증 상태·부분검사를 통과했다. 429는 없었고 한 흐름의 전체 리소스에서 5xx3건이 집계됐으나 최초 계측에는 호스트·종류가 없어 원인을 추정하지 않았다. 서로 다른 자료·출처 수이므로 속도 개선의 인과 증거는 아니다. 이후 113회귀 통과와 요청 오류 상세 계측을 결합해 두 고정 흐름의 생산 실행을 재개했다. 요청 제한이 늘면 한 흐름으로 되돌리며, 이 코드 판본은 본 g08 중간 커밋에 섞지 않는다.

루트는 Ciarlet2005의 215쪽 파일도 원입력·MR·표제 이미지·목차·Preface·마지막 색인과 대조했다. 입력은 article/paper이고 DOI10.1007/s10659-005-4738-8이다. 출판사도 그 article을 1–215로 명시하므로 해당 DOI 단위의 전체 원문으로 채택할 수 있다. MR의 iv+215와 Fosdick foreword는 보존하되 별도 앞부분까지 확보했다고 쓰지 않는다. 이는 일반적인 책 앞부분 누락을 허용한 것이 아니라 실제 입력이 지정한 출판사 단위의 완전성을 확인한 판단이다. 별도 재판 단행본 DOI의 VI+209 쪽 체계와 혼합하지 않는다.

세 신규 작업자는 수집·수리·검토를 계속하고 있으며 전체 작업은 완료되지 않았다. 다른 작업의 스테이징과 파일을 건드리지 않고 명시 경로만 커밋한다. 최종 푸시는 전체 요청 완료 후에 수행한다.
