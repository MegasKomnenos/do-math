[[M-0517]] 뒤 작업판의 선택 무효화와 개정 순환 발동을 확인했다. 선택 무효화는 승인된 TK-1을 제품 _apply_task_plan으로 선택한 다음 공개 source 제어로 실제 자료를 변경한다. 변경 전에는 계획 요청이 없고 변경 후 _selected_action_current는 오래된 연구 실행을 제거한다. 해당 계획 ID의 실제 모델·worker 호출이 한 번이고 산출이 output_accepted임을 확인한다. 오래된 research_work는 실행하지 않으며 obsolete_selection 이력은 한 번이다. 추가 owner 두 번의 전체 호출 수와 저장 상태도 유지한다.

처음에는 기존 Sim 검사를 flows로 옮겨 그대로 확장했지만, 해시만 b 64개로 바꾸는 기존 국소 fixture 때문에 실제 호출의 봉인 검증에서 실패했다. 기존 Sim 검사는 입력 현재성을 직접 검사하는 용도로 그대로 남기고, 별도 flow는 공개 source의 바이트·해시·판본을 함께 변경하게 했다. 다음 초안의 빈 계획은 실제 후속 상태의 과제 모집단을 반영하지 못해 수락되지 않았다. 최종 응답은 기본 응답기가 현재 ready_task_ids로 만든 처분을 사용하고 선택을 미래 재검토로 보류한다. 목표 감사는 요청하지 않는다. 준비된 결과를 강제로 완료시키지 않고 실제 수신 계약을 따른다. 두 초안 실패는 제품 결함으로 분류하지 않았고 원보고를 보존했다.

개정 순환의 양성 발동은 현행 제품 규칙상 불가능했다. pending_revisions는 write 대상이 있는 요청만 모으고 live 실행을 running으로 덮어쓴다. revision_waits는 자기 자신을 제외하며 미시작 writer가 큰 ID의 미시작 writer를 기다리지 않게 한다. 따라서 미시작 요청 사이 간선은 ID가 엄격히 작아지는 방향이다. running 요청은 그래프 출발점에서 제외되어 그쪽 간선은 종점이며, 기존 reader 대기는 execution_id로 표현되어 action_id 순환에 들어가지 않는다. 이 조건에서 revision_cycles는 항상 빈 목록이다.

항상 빈 필드의 생산·저장 스키마·입력 배포·문서 약속과 불가능한 재계획 분기를 함께 제거했다. pending_revisions와 실제 revision_waits의 차단 규칙은 유지한다. 기존 상호 읽기·실행 중 writer·유지보수·위임 반환의 무순환 단언 네 곳은 제품 순환 함수 대신 기존 support.cross_contracts.assert_wait_graphs의 graphlib 검사를 사용한다. 입력 필드 기대 목록도 현행 계약으로 교체했다. 역사 raw 보고와 측정 자료는 수정하지 않는다.

최종 관련 구조48·단위33·Sim9·flow1의91개가96.2초에 통과했다. 입력 필드 제거의 실제 소비를 추가 확인한 포장 단위20개와 열 역할 생산자/포장 전건 Sim1개는24.3초에 통과했다. 두 실행 모두 소스 변경이 없다. 검증/2026-10-05-선택-무효화/report.json 및 role-inputs.json이 원보고이며 해시는 작업판 B101에 기록했다. 부분 묶음을 전체 일반 통과로 합산하지 않는다. 미러 생성과 check, 기억 색인 검증을 커밋 관문으로 적용한다.

B101은 선택 무효화 연결과 불가능한 개정 순환 경로의 제거까지만 닫는다. 목표 근거 상실·학술 후속/반려·일반 입력초과·연구 수락/부수 통찰·형식 계속 실행의 입력 변경 등 다른 계획 원천은 남는다. 전체 일반·fresh T3·함수 변이·T4/T5·문서 모집단의 원목표를 유지하며 이 변경으로 완료를 선언하지 않는다.
