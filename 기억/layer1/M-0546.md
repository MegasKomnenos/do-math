B130 뒤 DOC-RETURN-CLI의 남은 init_result·scheduling_result·selection_result 결속이 같은 CLI 코드와 기존 경계 시험에 모여 있음을 원문에서 확인했다. 하나씩 별도 관리 단위로 늘리는 대신 세 결속을 한 새 독립 문맥에 배정했다. 다른 역할·검토·신뢰 반환으로 범위를 넓히지 않았다. 기존 구조 시험의 공개 API에 실제 결과 필수 단언을 먼저 넣었고, 원래 검사기는 여섯 정규/별칭 subtest에서 ValueError를 내지 않아 시험 한 개가 실패했다. 이는 import나 새 인자 오류가 아니며 red 0.6초, 실행 중 소스 변경 없음으로 보존했다.

initialize_instance의 반환 AST, cli.execute init 분기의 쓰기 AST, select-profile 분기의 반환 AST와 selected의 수동 RECORDS 결속을 제거했다. 세 CLI 소유자는 실제 결과가 없으면 기본 거부하며, defer_cli_results에 지정한 소유자만 보류한다. 보류 이름의 오기도 거부한다. 기존 상태·진행·조회 시험이 제공하지 않는 CLI 결과만 명시적으로 보류하도록 직접 호출부를 함께 바꿨다.

초기 검토에서는 기존 init 시험이 operator_enabled=False라 operator_schedule 키를 반환하지 않는 한계가 있었다. configure의 예약 결과나 예약 어댑터의 반환으로 init 문서의 근거를 대신하지 않았다. 직접 지원 코드에서 기존 FakeScheduler 포트를 찾고, 두 번째 init 한 번의 설정을 True로 바꾸어 실제 cli.main·execute·Git·저장소·엔진의 최종 응답을 얻었다. 외부 scheduler만 dataclasses.replace로 교체하므로 실제 Windows 예약 등록은 없다. 기존 원문 파일 보존, 수학 목표와의 분리, 원문 SHA-256 단언을 유지했고 실행 횟수도 늘리지 않았다.

변경 전 self.cli는 support.cli_inputs.run_cli를 거쳐 같은 프로세스의 main을 호출했다. 변경 후에도 같은 프로세스 main이며 scheduler 포트를 명시한 차이다. subprocess.CompletedProcess는 기존 helper와 마찬가지로 응답 봉투를 담는 객체일 뿐 실제 subprocess를 실행했다는 증거가 아니다. cwd 전환과 프로세스 시작·스트림 인코딩을 새로 검증했다고 주장하지 않는다. 여기서 필요한 것은 절대 경로 입력을 받은 실제 CLI 최종 JSON의 문서 필드다.

README의 result.instance_id와 README/CLI-실행-계약의 result.operator_schedule는 같은 실제 init 응답에 연결했다. 초기화-운전의 result.selection.profile_ref는 기존 select-profile 응답에 연결했다. 실제 최상위 키와 selection/profile_ref의 고정 중첩만 읽으며, 필드 삭제·다른 생산자 키 차용·배열 표기 오류·별칭 줄 누출을 거부한다. status는 기존 과거 snapshot과 현재 CLI 응답 각각으로 문서 전건을 확인하고 config_sha256 삭제를 거부한다.

관련 검증은 구조 18개·단위 3개·CLI 경계 4개, 총 25개가 54.9초에 모두 통과했다. changed_during_run은 비어 있고 검증 뒤 소스도 바꾸지 않았다. init 34.094초를 포함한 다섯 시험이 소프트 기준을 넘었지만 정확성과 범위를 줄이지 않았다. 검증/2026-10-06-CLI-실제반환에 red.json과 green.json을 원본 바이트로 보존한다.

DOC-RETURN-CLI는 앞선 B130 조회 slice와 이번 결과를 연결하여 종료했다. 예약 실패·reconcile_error의 전체 의미나 실제 OS 예약 성공까지 입증한 것은 아니다. 13-C 전체와 최종 일반/T3/극단 변이/T4/T5는 미완료이며, 다음은 DOC-RETURN-ROLE의 같은 생성 경계에 있는 input_manifest와 prompt다. 다른 역할 결과와 복원 파일은 그 작업으로 확대하지 않는다.
