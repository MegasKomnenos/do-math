사용자는 새 주차 함수 연구의 진행이 준비·검토에 머문 원인을 조사하게 한 뒤 연구 실행기를 정지했다. scholarly의 실제 호출 성공과 모델의 도구 부재 보고는 별개였으며, 당시 공급자가 제시한 목록 원본이 없어 최초 미노출 인식과 후속 자기모순의 내부 원인은 확정하지 못했다. 저장된 입력으로는 해시를 잃은 검사 문맥, 누락을 현재성 변경으로 분류한 경로, 운영 질문 기록과 실제 배정 사이의 공백을 재현했다. 수리 전 보고서는 `research/parking-unimodality-audit-2026-10-21/원인-분석.md`이며 원 코드는 당시 주 저장소 판본에서 읽어야 한다.

개발 인계에서 사용자는 예외 상황의 재량을 모든 요청의 상시 의심으로 확대하지 말라고 정정했다. 역할 계약 검토도 특정 장애 문구 탐색으로 한정하지 않고 목적·책임·판단·재량·연결 전체의 적합성을 보도록 했다. 검사 구조의 최초 상속 요구는 마지막에 사전·적용 검사의 공통 내용을 한곳에 두고 양쪽이 호출하며 각 위치의 추가 검사는 각자 수행하는 요구로 바뀌었다. 현행 지시에는 이 최신 요구만 적고 이전 설계를 금지문으로 남기지 않도록 했다. 다음 인계에서도 이 교정의 의미를 유지해야 한다.

`.async/dm-flow-repair-20261021/`에 원문·현행 맥락·계획·인터페이스를 작성하고 services/async-development를 별도 예약 작업으로 시작했다. 시작이 확인되면 계속 따라가지 말라는 사용자 요청에 따라 인계했고, 이후 명시적인 상태 조회에만 응답했다. 서비스는 최종 독립 검토와 11개 task의 수용을 마치고 종료됐다. 일부 task의 partial 이력은 덮어쓰지 않고 후속 수리·수용과 연결한다.

정리 시 최종 검토의 시작판 3,420파일과 현재 파일이 일치했고 11개 archive의 기록 해시도 일치했다. task workspace/base는 이미 정리돼 있었다. 사용자 요청에 따라 남은 캐시와 종료된 잠금 파일은 삭제 대기 임시 폴더로 옮겼다. 캐시 일괄 삭제 명령은 자동 승인 정책에서 차단되어 실행되지 않았으며, 이후 사용자가 이동을 명시했다. 원 연구·HOLD와 복원용 objects·원 evidence는 그대로 보존했다.

Git에는 공용 문서·배정·보고·통합·manager 판단·최종 assessment를 남긴다. 상세 실행과 objects, archive, 계측, 작문 보조 자료는 `.async/.../runtime`, task evidence 및 `.skill-workspace/parking-unimodality-20261021/`의 로컬 보관이다. Git clone만으로 원 실행 전체를 복원할 수 없으며 별도 백업이 필요하다. `.async/dm-flow-repair-20261021/README.md`가 추적 자료와 로컬 자료의 경계를 설명한다. 수리 전 감사와 수리 후 최종 검토를 같은 판본의 검증으로 읽지 않는다.
