## 맥락과 원인

주차 함수 연구의 상태 조회에서 Lean 브로커는 살아 있고 버전 확인도 성공했지만, calibration과 컴파일은 모두 Lean을 시작하기 전에 WinError 2로 실패했다. Lake를 거치는 버전 확인과 직접 Lean을 시작하는 컴파일은 실행 경로가 달랐다.

브로커는 Lake의 환경을 캡처한 뒤 `lake env lean`을 bare `lean` 실행으로 바꿨다. Windows의 Python subprocess 실행에서는 전달한 자식 환경의 PATH로 bare 실행 파일을 찾지 못했다. 실패한 작업의 환경과 작업 디렉터리를 그대로 사용한 재현에서 `lean --version`은 실패했고, 같은 환경의 LEAN 값이 가리키는 절대 경로로는 성공했다.

## 수정과 검증

Lake 환경을 캡처하는 프로세스 안에서 실행 파일을 탐색하고 절대 경로로 변환하여 브로커에 돌려주도록 고쳤다. 탐색할 수 없으면 직접 실행 최적화를 끄고 설정된 Lake 명령을 유지한다. 정본 진입점은 `.claude/skills/do-math/runtime/lean_broker.py`의 `capture_environment`와 같은 runtime의 `tests/test_lean_broker.py`다. bare 이름의 절대 경로 해결·실제 작업 실행, 탐색 실패의 fallback을 회귀 시험에 추가했다. 브로커 시험 51개가 151.459초에 통과했다.

적용 대상은 `C:/math/.skill-workspace/do-math/parking-unimodality-fresh-20261105-150803`이다. 새 dispatch를 멈추고 세 peer의 종료를 기다린 뒤 지원 명령 `restart-broker`로 PID 2648의 브로커를 시작했다. Mathlib 네 모듈을 사용하는 calibration과 `ring` 증명을 브로커에 제출해 모두 exit 0을 확인했다. 증명의 출력 공리는 propext뿐이었다. 검증 뒤 resume했으며 runner와 broker 생존, stopped=false를 확인했다. 이 시험은 실행 경로 복구의 근거이며 연구 명제의 형식적 해결을 뜻하지 않는다.

실제 컴파일 작업은 `j86bfb0efa640496cb385742c34f993fb`, 성공한 calibration은 `cf818966c6a0a4e49b3278d3add53583d`다. 인스턴스의 `runner/lean/jobs/<id>/result.json`과 `.skill-workspace/do-math-inputs/broker-launch-smoke-20261106.lean`은 Git 제외 로컬 자료라 정리로 사라질 수 있다. 장기 재현의 진입점은 추적되는 구현과 회귀 시험이다.
