## 맥락

사용자는 [[M-0597]]이 커밋한 do-math 작업맥락 보충을 평가해 달라고 했다. 메인의 평가 결론은 다음과 같았다.

- 보충은 실행기·검사기를 바꾸지 않고 올바른 층, 곧 작업맥락 문서에서 손실을 메웠다.
- 보충이 근거로 든 사실은 runner.py와 Lean 출력으로 모두 확인했다. 확인한 것은 `#print axioms` 출력 형식, 세션 상태 필드, `tick` 순서다.
- 보충 전 커밋본([[M-0594]])에서 `lean: accepted`는 종료 코드 0이면 성립했다. 그런데 `sorry`도 종료 코드 0으로 컴파일되므로 이는 결함이었다. 보충이 이 결함을 공리 기준으로 막았다.

평가에는 제안 셋과 위험 하나를 붙였다. 사용자는 "제안한 것들 반영해서 커밋해줘"라고 지시했다. 이 커밋이 반영한 것은 다음과 같다.

- **허용 공리의 사용자 예외**(common.md 공리 문단, review.md `lean` 행, research.md 공리 확인 문단): 기본 셋 `propext`·`Classical.choice`·`Quot.sound`에, `goal.md`가 명시적으로 허용한 공리나 `native_decide`를 더한다. `sorryAx`는 어느 경우에도 허용하지 않는다. review.md와 research.md는 공리 이름을 직접 나열하지 않고 common.md의 허용 공리를 가리키게 했다. 사용자 예외가 생긴 뒤 세 곳의 목록이 서로 어긋나지 않게 하려는 것이다.
- **`output.json`의 원자적 교체**(research.md): 자기 세션 폴더의 `work/`에 새 내용을 다 쓴 뒤 `os.replace` 등으로 `output/output.json`을 교체한다. 실행기는 세션이 어떻게 끝나든 그때의 `output/`을 재검사한다. 그래서 쓰는 도중에 세션이 끝나 반쯤 쓴 파일이 남으면, 그때까지 쌓은 산출이 재검사에서 통째로 실패한다.
- **"## 오래 걸리는 명령" 절**(common.md): 위험 항목을 측정한 결과를 그대로 적었다(아래 '터득한 것').

형식화 기준 "두 개 이상의 과제가 기대는 비형식 결과는 형식화를 우선한다"(plan.md)는 문서를 바꾸지 않았다. 이 기준이 적절한지는 아직 실제 목표에서 확인되지 않았다. 첫 실사용 목표에서 형식화 과제가 언제, 몇 개 게시되는지를 보고 판단한다.

## 터득한 것

- **도구 시간 제한 측정**(2026-10-21, Claude CLI 2.1.306, Codex CLI 0.163.0). 실행기가 세션을 띄우는 것과 같은 인자로 쟀다. 기록은 `.skill-workspace/timeout-probe/{c1,c2,x1,x2,x3}`에 있다. 이 위치는 Git에서 제외된 로컬 보관이므로 정리하면 사라질 수 있다. 같은 내용은 추적되는 common.md 절에 남아 있다.
  - Claude: Bash 도구는 `timeout`을 지정하지 않으면 120초에 "moved to the background"로 돌아오고, 명령은 계속 돌아 완료된다. 출력 파일 경로가 주어지고 완료 알림이 온다. `timeout: 900000`을 요청해도 600초로 줄어 적용된 뒤 백그라운드로 넘어간다. 도구 안내 문구는 백그라운드에서 10분이 더 지나면 중단한다고 말한다. 620초 명령이 끝까지 완료됐고, `--print` 세션은 완료 알림을 받을 때까지 살아 있었다.
  - Codex: 셸 도구는 약 10초에 그때까지의 출력과 `session_id`를 돌려주고, 명령은 그 세션에서 계속 돈다. 같은 세션을 폴링하면 480초 명령의 종료 코드 0과 전체 출력을 회수했다(총 493초). 폴링하지 않고 응답을 끝낸 실험에서는 Codex 프로세스가 26초에 종료되어 결과를 받지 못했다.
  - Mathlib을 import한 파일의 냉간 컴파일은 이 호스트에서 7분 22초였다. 두 CLI 모두 기본 동작만으로는 결과를 놓칠 수 있는 길이다.
- **독해에서 고친 것**: 첫 독해에서 공리 문단의 예시 문장이 `native_decide` 보조 공리를 무조건 "허용 밖"의 예로 들고 있었다. 그래서 사용자 예외와 충돌하는 것처럼 읽혔다. 이 문장을 "`sorryAx`는 언제나 해당하고, `native_decide` 보조 공리와 선언된 공리는 `goal.md`가 허용하지 않았을 때 해당한다"로 고쳤다. 커밋 판본을 다시 독해했을 때 이 충돌은 나오지 않았다. 남은 지적 둘(상충의 정의, 대체 가지 규칙)은 이번 변경 밖의 기존 문장이며, 둘 다 protocol.md 3절이 세부 정본이라 유지했다.
  - 독해 자료: `.skill-workspace/writing/do-math-common2/`
  - 독해 상태: `.codex/writing-flow/claude-2d19cb20-dmr-common3/`
  - 둘 다 Git 제외 로컬 보관이다.
- **병행 세션과 같은 파일을 나눠 커밋한 방법**: 커밋 직전에 다른 세션이 같은 do-math 문서를 고치고 있었다. 그 세션은 SKILL.md, plan.md, common.md의 사용자 조건·형식 증명·근거 전파 문단, review.md의 결함 기록·목표 판정 문단을 고쳤고, 독해 파일이 계속 생기고 있었다. 두 세션의 변경 덩어리는 겹치지 않았지만, common.md에서는 한 diff 덩어리 안에 붙어 있었다. 그래서 다음 방법으로 이 세션의 변경만 커밋했다.
  1. HEAD 판본에 이 세션의 변경만 적용한 파일을 만들었다.
  2. `git hash-object -w --path=`와 `git update-index --cacheinfo`로 그 파일을 인덱스에 직접 올렸다.
  3. 미러 생성기는 디스크의 정본을 읽고 저장소 루트를 자기 위치에서 정한다. 그래서 `git checkout-index --prefix`로 `.claude/skills`와 `.agents`의 인덱스 내용을 임시 루트(`.skill-workspace/mirror-index-export/`)에 내보내고, 그 안의 생성기 사본을 돌렸다. 갱신된 do-math 사본 셋만 인덱스에 올렸다.
  4. 시험 19개도 같은 임시 루트에서 돌려 통과했다.

  독해도 같은 이유로 커밋 판본 파일을 대상으로 했다. 작업 트리 파일을 독해했을 때는 독해 도중 그 세션이 23·67행을 고쳐, `decide`가 입력 불일치로 거부됐다. 다른 세션의 변경은 작업 트리에 그대로 두었다.
- **다른 세션 커밋 시 주의**: 그 세션이 나중에 common.md·review.md를 커밋하면, 작업 트리에는 이 커밋의 내용과 그 세션의 내용이 함께 있다. 따라서 그 세션이 생성기를 다시 돌리면 미러가 양쪽을 모두 담게 된다. 이 커밋의 미러는 이 세션의 변경만 반영한다.

## 작업 너머 시사점

- dream에서 묶을 후보: 세칙 v18 "커밋 직전 병행 세션 재확인"은 변경의 귀속을 판별하는 데서 그친다. 이번 사례는 귀속이 다른 변경이 같은 파일에 섞여 있을 때 쓸 수 있는 분리 방법을 더한다. 방법은 두 가지다. HEAD에 자기 변경만 적용한 판본을 인덱스에 직접 올린다. 디스크를 읽는 생성기·시험은 인덱스 내용을 내보낸 임시 루트에서 돌린다. 쓰는 중인 파일을 독해 대상으로 삼으면 해시 결속이 깨진다는 점도 같은 관례의 한 항목이 될 수 있다.
- 첫 실사용 목표에서 확인할 것: 연구 세션이 긴 컴파일에 common.md의 회수 방법을 실제로 쓰는지, 회수하지 못한 결과를 `verification`에 적는지. 그리고 위의 형식화 기준 "두 개 이상"이 적절한 양의 형식화 과제를 만드는지.
