전체 학술자료 MCP 구현을 계속했다. 이 커밋은 DROPS의 원 내보내기·전문 HTML, OpenCitations의 CSV·OCI·건수 조회, 두 증명 라이브러리의 실제 검증과 공통 응답 보존 경계 수리를 담는다. 전체 작업은 아직 부분 완료다. Numdam 확장은 M-0163에 보존되어 있고 후속 정본은 services/scholarly-mcp/SUPPORT.md·VALIDATION.md·registry.py다.

DROPS에서 검색 export=bibtex가 invalid_options인 것을 재현했다. 원 사이트에는 논문의 XML·ACM-XML·DOAJ-XML·Schema.org·BibTeX가 있었고, /metadata/bibtex는 HTML 미리보기였다. 미리보기의 실제 /download 링크가 공개 원 파일을 반환함을 확인해 최종 구현을 API로 고정했다. CodeMeta도 /metadata/codemeta-json/download를 사용한다. HTML 미리보기를 브라우저로 읽는 중간 구현은 실제 다운로드 API 확인 후 제거했다. API 실패를 계기로 브라우저에 전환하는 구조는 넣지 않았다.

DROPS의 소프트웨어 artifact는 논문과 다른 제공 형식을 갖는다. artifact의 XML 헤더를 article로 읽던 실패를 재현해 유형별 헤더를 대조하게 했다. CodeMeta identifier는 SWHID이며 요청 DOI와 같다고 주장하지 않는다. 이름·코드 저장소를 같은 DROPS Schema.org와 대조한다. 10.4230/artifacts.27685의 네 형식이 실제 MCP에서 통과했다. 코드 저장소 URL은 남기되 다른 자료원으로 자동 방문하지 않는다.

현재 문헌의 Files 영역에서만 파일을 선택해 관련 논문 PDF를 섞지 않는다. HTML 파일 URL을 지정하면 그 문헌의 공개 파일 목록과 대조해 HTML만 회수한다. 실제 MCP에서 P versus NP 44건 중 두 문헌 BibTeX, CSL.2020.5의 다섯 내보내기와 2쪽 PDF, DNA.31.9의 전문 HTML·article 추출·부가자료 설명을 확인했다. 부가자료 설명의 외부 파일을 확보했다고 보고하지 않는다. 최종 성공 보고는 VALIDATION.md에 기록했다.

이번 조사에서 임시 DROPS HTML 응답 세 건에 폼 토큰이 저장된 사실을 확인했다. APIAdapter.request의 accept=binary가 HTML을 그대로 artifact에 보존하던 결함이다. 값은 도구 출력에 표시하지 않았으며 사용자에게 저장 사실과 조치를 알렸다. 해당 blob·manifest를 경로 검증 후 .credentials/scholarly-mcp/probes/quarantine-drops-20260910으로 이동했다. 일반 저장소에서 격리했지만 토큰 폐기를 수행한 것은 아니다. 바이너리·JSON·XML 요청의 HTML은 보존 전에 거부하고 명시적인 HTML 응답에는 clean_html을 적용한다. 합성 토큰의 저장 실패 재현과 회귀 검사를 남겼다. 보존 경계를 고쳤다는 사실을 과거 전체 자료의 보안 감사로 확대하지 않는다.

OpenCitations는 DOI의 나가는·들어오는 관계와 건수, ISSN의 저널 인용 건수, OCI 단건 경로를 연결했다. CSV 원 파일 전체와 요청 창의 재직렬화 파일을 구별한다. 실제 MCP의 첫 CSV 요청은 Accept: text/csv에도 JSON을 받았고, 제공자 문서의 format=csv를 명시하여 재검증을 통과했다. JSON에도 format=json을 명시한다. 원인을 캐시라고 추정해 확정하지 않는다. 실제 72개 참고문헌, 그중 두 레코드의 CSV·OCI, reference-count의 72개를 대조했다.

Mathlib와 Mathematical Components는 별도 자격 없이 저장소의 현재 머리를 커밋으로 고정한 뒤 소스 줄을 검색하고 같은 커밋의 파일·줄을 실제 MCP에서 회수했다. Mathlib/Computability/의 theorem 1,014개, Mathematical Components algebra/의 Lemma 5,284개 중 각 두 줄을 검색했다. 첫 Mathematical Components 0건은 검증자가 오래된 mathcomp/ssreflect/ 경로를 입력했기 때문이었다. 실제 archive를 열어 현재 경로를 확인하고 검증 입력을 교정했다. 어댑터 결함이나 정리 부재로 판정하지 않았으며 형식 증명기 실행 성공을 주장하지 않는다.

추가 공개 API 관측에서 OpenAlex와 CORE는 응답했고 CORE는 별도 검색식과 무작위 문자열의 0건을 대조했다. DBLP는 두 공식 호스트의 검색과 단건 XML·BibTeX에서 접근 확인 화면을 반환했다. Semantic Scholar는 호출 제한을 반환했다. 추가 계정·키·연락 이메일을 요구하지 않았고 해당 제한을 문헌 부재로 표현하지 않는다.

공통 검사 89개가 통과했다. 실제 MCP 검증과 모의 응답의 범위는 분리해 문서화한다. 남은 출판사 검색·자료 형식·첨부, 일부 링크·이름 입력과 범주 자료원의 구현을 계속해야 한다. 원 인계 계약과 별도 자격 기능의 보류 결정을 유지한다.
