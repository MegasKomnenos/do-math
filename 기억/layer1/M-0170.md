SIAM 공개 PDF 경로와 IEEE 문헌의 원 참고문헌 배열을 연결했다. 두 자료원의 실제 MCP 회수·추출과 공통 검사 115개가 통과했다. SIAM 검색·원 인용문과 IEEE 개별 첨부를 완료로 세지 않고 남겨 두었다. 전체 작업은 계속 진행 중이다.

SIAM 홈페이지는 정상이었지만 convex optimization 검색은 접근 확인 화면이었다. 다른 공개 자료인 First-Order Methods in Optimization의 Front Matter PDF는 계정 없이 10쪽 파일을 반환했다. /doi/pdf/DOI가 .pdf로 끝나지 않기 때문에 SIAM에 이 명시적 파일 형태를 연결했다. 실제 MCP는 PDF 내장 메타데이터와 첫 쪽 제목, 10쪽 파일을 대조했다. 책의 앞부분을 전체 책으로 확대하지 않는다. SIAM News June 2025의 12쪽 PDF도 직접 어댑터로 회수했으나 같은 수준의 MCP 검증으로 표시하지 않는다. PDF 뒤에 원 /doi/abs 문헌 페이지를 조회한 시도는 document_not_ready였다.

IEEE 참고문헌 화면 진입의 기존 h1 대기는 여러 요소를 만나 strict-mode 오류였다. 실제 문헌에는 문헌 제목·Alerts·References의 h1이 있었으므로 h1.document-title을 기다리도록 했다. References 탭도 가시 제어를 선택한다. 문헌 10488889의 화면은 참고문헌을 제공하지 않는다고 표시했지만, 원 references 응답에는 같은 articleNumber와 22건의 배열이 있었다. 첫 항목은 PRIMES is in P이며 원 인용문에 DOI 10.4007/annals.2004.160.781이 있었다.

처음에는 화면 안내를 원 응답 부재로 확대해 진행 보고했다. 이후 references의 실제 자료형·22건·문헌 번호를 확인하고 즉시 정정했다. 다음 시도에서는 다른 문헌도 확인했지만, 핵심 오류는 한 표본의 화면 안내를 데이터 확인 없이 확정한 데 있었다. 원 응답의 문헌 식별자와 배열을 먼저 대조하고 UI의 부재 안내와 구별해야 한다.

IEEE 참고문헌 배열은 원 id·order·title·text·context·links 등을 보존한다. 원 응답의 userInfo·사용자 설정 상태는 문헌 근거에서 제외한다. 참고문헌의 외부 링크는 회수한 정보이며 자동으로 따라가지 않는다. 문헌 번호가 다른 응답과 정상 빈 배열을 별도 검사했고 실제 MCP에서 22건 전체 추출을 통과했다. supplementary.references는 available이지만 개별 첨부 회수는 미구현이므로 supplementary와 fetch 전체는 partial이다. 이 상태를 회귀 흐름에서도 유지한다.

정확한 실측 보고 경로는 services/scholarly-mcp/VALIDATION.md가 소유한다. 지원표와 describe_source도 구현 범위에 맞췄다. AMS 원 검색·export의 추가 접근 검증, SIAM 검색·인용문, 다른 출판사의 남은 기능과 개별 첨부 회수를 계속 처리한다. 사용자 설정과 기존 연구 산출물을 보존하고, 전체 작업 완료 전이므로 푸시하지 않는다.
