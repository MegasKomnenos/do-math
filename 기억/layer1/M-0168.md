title: 학술자료 MCP의 Project Euclid 고급검색과 네 가지 원 인용문을 연결함

---

Project Euclid의 원 고급검색·정렬·페이지 조회와 문헌별 RIS·BibTeX·EndNote·인용문 PDF를 연결했다. 실제 MCP의 연속 흐름과 공통 검사 109개가 통과했다. 이전 접근 제한 관측을 영구 부재로 취급하지 않고 다시 양성 경로를 확인한 작업이다. 전체 구현은 부분 완료이며 남은 자료원 검색·추가 첨부를 계속 처리한다.

검색의 초기 Loading 화면과 늦게 도착한 정상 결과를 구별했다. All Fields complexity는 7,662건, TITLE complexity는 2,806건이었다. 첫 화면은 25건인데 추가 Ajax 응답의 Query.Page는 2였고 Items도 다음 25건이었다. 미리 받기 응답을 현재 페이지로 사용하지 않도록 화면의 페이지 번호·건수·행을 대조한다. 같은 Ajax 주소를 별도 HTTP 클라이언트로 부르면 200 HTML이었으므로 공개 API 성공으로 세지 않았고 브라우저 원 검색을 구현 경로로 유지한다.

Advanced Search는 href 없는 a 제어였으며 첫 가시 제어는 다른 요소와 겹칠 수 있었다. 홈페이지 마지막 가시 제어에서 실제 모달이 열렸다. 필드 TITLE·AUTHORNAME과 AND·NOT, 2010년, The Annals of Statistics 발행물을 결합해 DOI 10.1214/10-AOS798의 한 문헌을 회수했다. 네 번째 조건은 Add another field로 추가했다. 발행물 선택은 선택 방식 라디오 뒤 titleButton을 열어야 실제 제목 체크 제어가 나타난다. 사용자가 화면을 디버깅하지 않도록 가능한 발행물 이름을 facets.ref에 제공한다. 원 정렬 값과 pageSize=100을 UI에서 확인하고 99·100번째 위치 경계를 실제 MCP에서 회수했다. 원 50쪽 제한은 페이지 크기와 함께 표시한다.

연속 검색 검증에서 이전 저자·발행물 선택이 복원되는 결함을 찾았다. 다음 TITLE complexity에 Fan·Song·NOT 조건과 PubTitle이 섞여 0건이 됐다. 화면 입력과 체크박스를 해제해도 PubTitle이 요청에 남는 사례를 대조했다. 요청하지 않은 조건을 query_mismatch로 구별한 뒤, 공개 검색마다 빈 브라우저 컨텍스트에서 시작하는 방식으로 바꿨다. 개별 UI 초기화 코드를 계속 늘리지 않았다. 최종 검증은 조건이 많은 첫 검색 뒤 넓은 제목 검색과 0건 검색을 같은 MCP 세션에서 수행해 상태 혼입이 제거됐음을 확인한다.

EndNote 원 내보내기는 %DOI 태그를 썼다. 기존 단문자 태그 파서의 실제 실패를 재현하고 원 태그 이름을 보존하는 지원을 추가했다. 네 번째 인용문 형식은 1쪽 PDF이며 서지·초록을 담는다. 논문 전문 38쪽 PDF와 역할을 구별하고 각 파일의 DOI를 대조한다. 텍스트 원 형식의 바이트와 초록·필드를 fixture에 보존했다. 구체적인 성공·실패 보고 경로는 services/scholarly-mcp/VALIDATION.md가 소유한다.

새 컨텍스트 적용 후 한 전체 흐름에서 검색은 통과했으나 문헌 metadata_not_identified가 발생했다. 이후 직접 문헌 진입과 홈 경유는 모두 정상이라 경로 차이를 원인으로 단정하지 않았다. 정적 코드에는 일반 h1·og:title만으로 준비 대기를 끝내면서 실제 파서는 citation/DC title을 요구하는 불일치가 있었다. 대기 기준을 실제 필요한 메타데이터에 맞췄고 최종 전체 흐름이 통과했다. 이 성공으로 앞선 실패 보고를 덮어쓰지 않는다.

지원표·사용법·실측 기록을 갱신했다. 새 euclid.py를 공통 Publisher에 연결하고 기존 연구 파일·사용자 설정은 보존한다. AMS·SIAM 등의 남은 검색과 추가 형식, 기존 접근 확인 조건은 계속 남아 있다. 전체 완료 전이므로 푸시하지 않는다.

원 fixture의 개행과 RIS 종료 태그 공백을 유지하도록 fixture 디렉터리에 별도 .gitattributes를 뒀다. 사용자가 변경한 루트 .gitattributes는 수정하지 않았다. 기본 git diff --check가 정제한 HTML fixture의 CRLF 행을 대량 출력했으므로 이후 검사는 원문을 도구 출력으로 보내지 않는 방식으로 실행한다. 이번 stage의 알려진 보호 값 122개 대조에서는 일치 파일이 없었다. 이 대조를 모든 비밀값이나 과거 자료 전체에 대한 감사로 표현하지 않는다.
