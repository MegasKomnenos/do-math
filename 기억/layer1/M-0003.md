# 결함 상신과 승인 범위의 분리

## 맥락

do-dag와 verify-rounds는 결함의 정확성·완전성 영향만으로 사용자 상신을 만들 수 있었다.
verify-rounds는 산출물 밖 결함도 사용자 상신 제안으로 분류했다. 두 문면이 함께
작동하면 기존 정본에서 판정 가능한 결함도 전체 런을 멈췄다.

선택지 설명문을 사용자 발화와 함께 축자로 기록한 규칙도 승인 범위를 넓혔다. 구현
세부가 든 스냅샷과 설명문이 사용자 확정 문면으로 읽힐 수 있었다. 추천은 현재
수행자의 편집 권한에 정박해 알려진 결함을 남기는 우회안을 선호할 수 있었다.

## 터득한 것

사용자 결정 필요 여부를 결함 위치보다 먼저 판정한다. 사용자의 의도·선호·외부 사정이
필요하거나 비동등한 적합 결과가 둘 이상 남을 때만 상신 제안으로 쓴다. 사용자 결정이
필요하지 않으면 산출물 안 결함은 조각으로 쓴다. 산출물 밖 결함은 발견으로 쓴다.

발견은 수리 방향을 담지 않는다. 심사자는 발견의 타당성을 확인한 뒤 검토전개 비용 대비
실익을 판정한다. `호출자에게 전달`로 확정된 발견만 검토전개를 만든다. 무처분·기각
발견은 검토전개를 만들지 않는다.

선택 응답은 선택지의 설명문 전체를 확정하지 않는다. 선택된 라벨과 좌표는 사용자
응답이다. 질문 전에 닫은 `결정 효과`가 확정 문면이다. 승인 대상 스냅샷과 설명문은
결정 효과에 포함되지 않으면 증거로만 남는다.

추천은 사용자 승인 뒤의 최종 상태를 비교한다. 현재 수행자의 권한 부족은 품질상
이점이 아니다. 알려진 결함을 남기는 대체 구조에는 독립 소비자·호환 계약·이행 제약이
필요하다. 그 근거가 없으면 대체 구조 선택지를 추천하지 않는다.

## 작업 너머 시사점

편집 책임 경계와 사용자 권한 경계는 다른 경계다. 절차는 사용자 결정 필요 여부를 먼저
판정해야 두 경계를 섞지 않는다. 호출자에게 전달하는 항목이 후속 전개를 자동 생성하면,
심사자는 그 고정 비용을 처분 근거에 포함해야 한다.

이번 개정은 검증런 배치, 잔여 재심, 상신 시 전체 정지를 바꾸지 않았다. 사용자는 잔여
재심과 전체 정지를 의도된 장치로 유지했다. 경정 처분과 검증 비용 조정도 도입하지 않았다.
