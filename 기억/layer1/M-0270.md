사용자는 services/scholarly-mcp의 중간산출물·임시파일 정리와 디렉토리 정비, 외부자가 서비스를 파악할 공식 진입점을 요청했다. 루트 README를 설치·MCP 등록·첫 호출·지원 범위의 진입점으로 작성하고, 기존 상세 설명은 docs/USAGE.md, 지원표는 docs/SUPPORT.md, 과거 조사·검증·인계와 dispatch는 docs/history로 옮겼다. 구현 모듈의 패키지화는 import와 실행 경로 변경에 비해 이번 목적의 실익이 작아 시행하지 않았다.

실서비스 스크립트 75개를 tests/live로 이동하며 서비스 루트 계산만 수정했다. 별도 파견 도구 검사에서 tasks.json의 옛 tests/live_ 경로가 남은 사실을 발견했고 목록도 교정했다. 서비스 회귀 639개가 39.775초에 통과했고 파견 도구 5개, 실서비스 스크립트 75개의 구문·변경 범위 대조, 문서 37개의 로컬 링크 106개 검사를 통과했다. 이번 작업에서는 외부 자료원을 재호출하지 않았다. 회귀 로그는 로컬 data/validation/structure-cleanup-tests-20260914.txt에 있다.

data 루트의 일회성 파일 295개는 data/research로 옮겼다. 기존 artifact 참조를 유지하려고 blobs와 manifests, DjVu runtime과 조사 원자료 디렉토리는 보존했다. 삭제 명령은 자동 승인 검토에서 blocked by policy로 거부됐으며 구체적인 이유는 제공되지 않았다. 삭제를 우회하지 않고 사용하지 않는 JSTOR 조사 환경·Python 캐시·GPU 로그 폴더를 data/research/retired로 이동했다. 디스크 공간을 회수한 작업이 아니며 보관 파일은 Git 제외 대상이다. 조사 환경의 패키지 버전은 data/research/jstor-audio-requirements.txt에 보존했다.

사용자가 보관 영역의 위치를 다시 물었으므로 data/research/retired와 일반 조사 파일이 있는 data/research를 구별해 안내했다. 뒤이은 커밋 요청은 이 정리 작업에 적용했다. 병행 작업의 M-0269가 이미 커밋되어 있음을 확인하고 새 번호를 사용했다. 과거 기억의 서비스 루트 문서 경로는 같은 이름의 docs/history 문서에서 찾을 수 있으며, README와 SUPPORT의 이동 위치는 위와 같다.
