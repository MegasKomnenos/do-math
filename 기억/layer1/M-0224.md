ScienceDirect의 기본·고급 필드 검색, 원 facet·정확한 저널 자동완성, 선택 창의 RIS·BibTeX·plain, 서지·초록·PDF·보충 파일을 연결했다. 이 커밋은 앞선 SIAM·KNU 보유 목록·AMS·APS와 두 인용 색인 변경의 공통 서버 등록·설명도 함께 통합한다. 실제 호출 설명이 구현보다 뒤처진 상태를 교정하고 원 자료원별 접근 방식·보류·부분 결과를 유지했다. Codex나 실행 중인 등록 MCP는 재시작하지 않았고 새 SDK stdio에서 검증했다.

검색은 PII checkbox·문헌 링크·같은 행의 제목을 결속하며 DOI가 없는 원 검색 행에 DOI를 발명하지 않는다. 원 페이지 25행의 offset·페이지 번호·전체 건수·요청하지 않은 필터의 부재를 검사한다. 제목 후보 100건을 살핀 뒤 문헌을 내보낼 때는 그 PII가 있는 25행 페이지로 다시 돌아가 local index를 대조한다. 서로 다른 facet 그룹은 교집합, 같은 그룹의 복수 값은 원 쉼표 값의 합집합을 보존한다. Show more는 실제 후보를 동적으로 늘리므로 초기 4개를 전체로 표시하지 않고 각 원 그룹을 펼친 뒤 반환한다.

정확한 저널 자동완성은 검색어와 pub를 빠르게 함께 입력하면 React 갱신 과정에서 값이 초기화됐다. pub 단독 입력·현재 후보 선택으로 cid를 확정한 뒤 본 검색 조건을 결합해 해결했다. 검색어 변경이나 발명으로 결과를 맞추지 않는다. Journal of Algebra의 원 cid272332·21,628건이 실제 MCP로 확인됐다. Article type Research/Review·Mathematics·구독 저널·2020–2025년 조합은 33,229건 중 2건의 JSON·CSV가 일치했다.

긴 제목 한 건의 원 표시가 1 result found여서 파서가 거절하는 문제와 Export 버튼 자체·클릭 후 형식 메뉴의 두 단계 지연 표시를 구별해 수리했다. 첫 root 실패는 버튼 자체가 없다는 분기였는데 작업자의 초기 수정은 메뉴 대기만 고쳤다. 실제 오류 문구와 해당 코드 분기를 대조해 버튼 대기도 추가했다. 다른 층의 비슷한 실패를 고친 것만으로 원 실패가 해결됐다고 판단하지 않는다.

추가 두 페이지 RIS 검증은 수식의 text node 경계가 만든 공백 때문에 실패했다. 같은 PII의 원 제목 Weak generators of W- algebras for type A와 실제 DOM의 W-algebras 차이를 직접 확인했다. 비교에서만 공백을 제외하고 문자·기호·대소문자와 원 파일 바이트는 유지한다. PII·문헌 경로·제공 DOI 검사는 그대로다. 단위 반례와 실제 페이지 경계 재검증이 통과했다. 비문자 field가 unhashable TypeError로 끝나는 반례도 invalid_options로 교정했다.

실제 SDK 141311Z-science-direct-extended-mcp.json은 세 원 인용 형식·추출과 동일 PII S156042922600065X의 metadata·abstract·세 인용문·PDF 1,031,171바이트·31쪽을 통과했다.141127Z는 위 facet·자동완성 범위,141704Z는 다른 문헌 S0167278924001155의 원 Video S1·mmc1.mp4 1,315,119바이트와 resources/read·ftyp 검증이다.142839Z-science-direct-search-mcp.json은 Natural Proofs 제목 2건·CSV, algebra start24/limit2의 두 페이지 RIS·PII 대조,0건을 통과했다. 앞선 135804Z·140813Z·141842Z 실패도 VALIDATION.md에 남겼다. 새 파일 호스트 ars.els-cdn.com은 실제 동일 PII의 원 제어에서 확인하고 파일 전송에만 허용했다.

일반 GitHub도 별도 source의 실제 MCP 증거를 닫았다.134822Z-github-mcp.json은 검색·원 JSON export, 고정 commit7fd1a60b01f91b314f59955a4e4d4e80d8edf11d의 ZIP387바이트와 README13바이트를 회수하고 압축 내부·개별 파일의 내용 일치를 검증했다. 처음 검증 스크립트가 지원하지 않는 CSV와 잘못된 압축 name 필드를 요청한 것은 스크립트 결함이었다. 원 JSON·path·items의 실제 계약으로 고치고 describe_source에 원 export 형식을 명시했다. 소스 코드는 실행하지 않았다.

전체 378개 검사가 통과했다. 첫 전체 실행에서는 기존 explicit PDF 시험의 범용 MagicMock이 실제 KudosGateway에 없는 native_download 메서드까지 만들어 다른 분기로 들어갔다. 실제 인터페이스를 spec으로 제한하고 원 교차 자료원 다운로드 거부 검증을 유지한 뒤 전체를 다시 통과했다. ScienceDirect 전용 21개 검사와 모든 실제 SDK 결과를 구별한다.

전체 구현은 아직 끝나지 않았다. 현재 describe_source를 실행해 남은 개발 문구를 확인한 자료원은 WOS·ACM·IEEE·PQDT 네 곳이다. WOS 고급검색과 ACM·IEEE는 개별 작업자가 계속 연구·구현하고 PQDT도 후속으로 닫아야 한다. Semantic Scholar의 새 SDK는 첫 요청 429, Software Heritage의 특정 직접 directory release flat은 pending, AMS 동적식은 원 UI 제공자 오류다. SIAM 기관 목록과 실제 비공개 문헌 권한 실패, 별도 계정·연락 이메일 보류, 과거 비밀값 노출·삭제 거부의 미해결 경계는 ACCESS-RESEARCH.md에 보존한다. 전체 작업이 남아 푸시하지 않는다.
