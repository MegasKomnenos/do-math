## 맥락

[[M-0364]]로 1b를 닫은 뒤 1c(층 분리)를 시작했다. 진행 기록은 `docs/do-math/시험-재편-2026-09-29/진행.md`의 1c 절에 있다. 사용자가 작업 도중 멈추고, 커밋 `25bff5d`의 설계·조사 문서와 합의가 이루어진 원 대화를 다시 읽어 목적을 세밀하게 복구한 뒤 작업을 검토하고 진행 방식을 재량으로 정하라고 지시했다.

## 터득한 것

**요약만으로 재개하면 목적이 대리 지표로 좁아진다.** 요약에서 재개한 뒤 1c를 "`PENDING`에 걸린 모듈 수를 줄이는" 순서로 몰고 있었다. 원 대화([8]의 동기, [456]의 "틀을 위한 틀이 아니라", [483]의 "과하게 늦추지 않게")를 다시 읽으니 1c의 실익은 의무의 제품 전제였다. `Sim`의 가상 시간 일관성(6-A·4-B·7-A)을 위한 시계·ID 이전, 주입 지점을 만드는 `_call_steps` 절단, 9-B 말뭉치와 T3 관문을 위한 해석 함수 이동이다. 층 표의 수는 `# layer:` 예외로 채울 수 있는 대리 지표라서, 예외는 판별 질문이 정당화할 때만 달고 수를 보고하기로 했다. 같은 재검토에서 1b의 A12·A13이 사용자 결정 절을 묻지 않고 바꾼 것임을 찾아 확인을 요청했다. 사용자는 실질과 원칙에 더 부합하면 재량으로 판단해도 된다고 답했다(설계 U9).

**새 부류를 만들려다 판별 질문으로 되돌아갔다.** 파일 시스템 도우미 `file_io`가 "경계 어댑터"로 선언되어 2층이 import할 수 없었다. 처음에는 새 층 값(`filesystem`)을 두려 했다. 그러나 설계는 파일 시스템을 포트로 두지 않았고, 판별 질문도 이미 2층으로 답한다. 그래서 `file_io`를 2층으로 선언하고 Windows 파일 API 행에만 사유를 달았다(A14).

**이름 이동의 속성 사용 검색은 제품 모집단 전체에서 한다.** `values` 분리 뒤 `operator_bootstrap.py`가 동결 스냅숏의 `file_io` 모듈 객체에서 `json_digest`를 속성으로 부르다 깨졌다. 검색이 `do_math/`와 `tests/`만 보고 `scripts/` 바로 아래를 보지 않았다. 1b의 "패치 형식 셋을 모두 찾는다"와 같은 부류의 누락이다. 작업자가 Job 안에서 적재하는 모듈은 구현 식별(`identity_modules`)에 들어가야 한다는 규칙은 시험 기대값을 먼저 고쳐 지켰다.

**worktree에서 옛 모음을 돌리면 추적되지 않는 도구 사슬이 없다.** 검증을 스냅숏 worktree에서 돌려 작업 트리 편집을 계속할 수 있었다. 그런데 Lean 시험 20개가 `.skill-workspace/do-math-toolchains` 부재로 실패·건너뛰었다. 연결(junction)을 만든 뒤 같은 스냅숏에서 다시 돌려 통과를 확인했다. 백그라운드 명령에서 `cd X && (a) & (b) &`는 `cd`가 첫 괄호에만 걸려 둘째·셋째 묶음이 엉뚱한 폴더에서 떴다. 묶음마다 `(cd X && ...) &`로 둔다.

**커밋은 검증한 스냅숏 트리로 만든다.** 작업 트리에 다음 단위(시계·ID 이전)의 편집이 이미 있어서, 스냅숏 worktree에서 미러를 재생성하고 `git write-tree`로 트리를 얻은 뒤 주 작업 트리의 색인을 그 트리로 맞췄다(`git restore --staged --source=<tree>`).

## 작업 너머 시사점

- 압축 요약에서 긴 작업을 재개할 때는 원 발화와 설계 원문으로 목적을 다시 확인한 뒤 진행한다. 요약은 결정을 남기고 이유를 잃는다.
