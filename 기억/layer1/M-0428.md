## 독립 통합

[[M-0427]]은 c37929b0으로 확정했다. 다음 단위는 main에 열린 KD-0001 하나다. 수리 후보의 file_io에는 실행 파일 정규화도 섞여 있으므로 파일을 통째로 복사하지 않았다. os_lock의 빈 파일 바이트 쓰기만 잠금 획득 뒤와 해제 guard 안으로 옮겼다. 잠금 파일 경로·형식과 차단/비차단 동작은 유지한다.

기존 boundary.test_file_io_lock의 결함 표시를 제거하고 실제 Windows msvcrt 잠금으로 red를 확인했다. 선행 보유자는 byte0을 잠갔지만 아직 쓰지 않은 빈 파일을 보유한다. 두 번째 os_lock은 기존 코드에서 잠금 획득 전에 os.write를 실행해 m9qz0qdv의 PermissionError를 낸다. 보유자의 해제를 기다리며 잠금을 얻어야 하는 원래 기대값은 바꾸지 않았다.

수리 후 원 시험에 초기화된 실제 바이트 b'\0'과 해제 뒤 비차단 재획득을 추가했다. 경계 시험과 원장 대응2개가 blhabm61에서 통과했다. 실제 Git writer lock/CAS와 운영 복구의 잠금·저장·재시작 관련33개도 r1_j8850에서 통과했다. 기존 Sim1개의 개별 예산 초과는 남는다. boundary1개 통과는 전체 T4 완료가 아니다.

## 판본과 근거

main 원장의 KD-0001만 닫아 열린 결함13개다. KD-0002 실행 파일 정규화와 KD-0003 setup 호출 창 억제는 별도 독립 통합으로 남는다. 수리 후보에는 os_lock 제품 변경이 이미 있었고 같은 강화 단언을 맞췄다. M-0427의 후보 교정19파일 아카이브는 그때의 판본이다. 새 경계 단언을 넣은 현재 후보 전체 통과로 읽지 않는다.

추적 진입점은 단계-전환표 current_work.lock_integration의 원 보고 SHA256·main 파일 지문이다. 사용자 Temp의 원 보고 전문은 Git 제외 로컬 자료이며 정리될 수 있다. 전체 기준선 report.json과 당시19파일 후보 patch는 직전 커밋에 원문으로 보존됐다. 이번 커밋은 제품1파일, 기존 경계 시험, 원장과 생성 미러, 작업판·기억만 포함한다. 기존 교차 지원과 시험, 진행 문서는 보존하고 포함하지 않는다.

새 목표는 active이며 전체 관문·실행 예산·함수 전건 변이·말뭉치·나머지 main 통합이 남는다. 독립 수리의 실제 red→green을 반복할 필요는 있으나 이미 닫힌 동일 영역을 다시 광범위하게 실행하지 않는다. 푸시, graphify 갱신, 기존 연구 재개나 삭제는 하지 않는다.
