# pvsnp-탐사-1 L02 수식 표기 수리 산출물 커밋: 검증런 2.7.10.55.7 0단계 기준선 확립

## 맥락

행 `2.7.10.55.6`이 정본 `행/2.d/7.d/기각보관/2.7.10.5-라운드1.md`(R1-02)가
지목한 L02.md의 C12·C16·Q9·Q10·Q11·E5·E7 7개 행에서, 일반 괄호 안의 수학
기호와 복잡도 계급을 인라인 LaTeX(`\(...\)`)로 교체했다. 결과는
`research/pvsnp/literature/readings/L02.md`(노드 worktree
`C:\Users\wogud\AppData\Local\dag-wt\pvsnp-탐사-1+2.7`, 브랜치
`dag/pvsnp-탐사-1/2.7`)와 `55.d/6-보고.md`(메인 저장소 `C:\math`, `main`
브랜치)다. 이 세션은 그 결과를 검사하는 검증런 `2.7.10.55.7`(파견문
`행/2.d/7.d/10.d/55.d/7.md`)을 verify-rounds로 완료하도록 위임받았다.

0단계 착수 전 확인에서 두 산출물이 모두 미커밋이었다. `L02.md`는 워크트리
워킹트리 변경(`M`), `6-보고.md`는 메인 저장소 미추적(`??`)이었다.
M-0006~M-0012·M-0015~M-0021이 기록한 같은 패턴(do-dag 산출 미커밋 인계)이
같은 국면에서 이번까지 열다섯 번째로 재현했다. 각 파일을 이름으로 지정해
해당 저장소에서 단독 커밋했다. 워크트리 커밋 `521508f`(L02.md), 메인
저장소 커밋 `625e00f`(6-보고.md). 메인 저장소 커밋은 M-0021과 같은 dag
pre-commit 게이트(국면 `pvsnp-탐사-1` 활성)에 다시 걸려 `dag_marker.py
allow --minutes 10`으로 `grant-24`를 발급받은 뒤 통과했다.

워크트리의 `git status`는 이 검증런과 무관한 다른 미커밋 변경(L04·L11·
L17·L21.md, `_parts/` 4건, `records/L16.md`, 다수 미추적 파일)을 함께
보였다. 이들은 이번 대행 커밋에 포함하지 않고 `L02.md` 하나만 이름으로
지정해 스테이징했다. M-0019가 세운 verify-rounds 산출물/정본 분할(산출물 =
워크트리 파일만, 작업자 보고류는 기준 원문/정본으로 재분류)을 이번 동결문
작성에도 그대로 적용한다. 「산출물」 절은 `L02.md` 하나로 좁히고,
`6-보고.md`는 「기준 원문」 절로 옮겨 서브에이전트에 읽기 전용으로 지급할
예정이다.

## 터득한 것

- do-dag 완료-커밋 미결합 패턴의 재현이 이번까지 열다섯 번째다.
- 메인 저장소 dag pre-commit 게이트의 대행 커밋 차단이 M-0021 이후에도
  재현했다. grant 발급 절차(`dag_marker.py allow --minutes 10 --reason
  "<사유>"`)가 일회성 사례가 아니라 이 국면의 반복 관문임을 확인한다.
- Bash 도구에서 Windows 절대경로를 백슬래시로 넘기면 POSIX 셸이 백슬래시를
  이스케이프 문자로 소거해 경로 마디가 붙어버린다(`C:\math\.claude\...` →
  `math.claudeskills...`). `python`류 명령의 Windows 경로 인자는 슬래시로
  써야 한다. 이 세션에서 `dag_marker.py` 첫 호출이 이 오류로 실패했다.

## 작업 너머 시사점

M-0019가 세운 verify-rounds 산출물/정본 분할선이 세 번째 사례(M-0021, 이번)
로 재사용됐다. do-dag×verify-rounds 접속에서 반복 재현하는 구조적 간극에
대한 재사용 가능한 절차임을 추가로 뒷받침한다. dream 제안 후보: 이 국면의
do-dag 완료-커밋 미결합이 열다섯 번째로 재현했으므로, 작업자 행 반환 계약에
"자기 산출을 커밋까지 완결한다" 또는 "커밋 대행이 필요함을 명시 반환한다"
조항을 편입할 실익을 검토할 것. L-0016(위임 파이프라인 운영)·L-0019(do-dag
실행 체제)가 연결 후보다.
