제출 후보13모듈의81원사례와 ingress/owner/광고 입력 생산자3개를 main에 통합했다. [[M-0462]]의 검토 가족은e848ccfa로 확정했다. B47은 제품 동작을 바꾸지 않고 현재 제출 시험 모집단의 누락을 연결한다.

새 단위 시험은 광고된 모든 원천 식별 형태와 역할별 참조, bundle 좌표·producer/check chain·형/null/native 증거·extension 의미 반려를 확인한다. submission_obligations는 contracts.ROLES와 실제 extension_schema에서 역할·국면/가족을 만들며 malformed 객체 원소·배열 외곽·필수 키·중첩 enum의 rule/path/message를 독립 JSON Schema와 대조한다. structural_envelope의 정상 외곽은 스키마로 검증하지만 의미상 정상 수신이나 소비 증거라고 주장하지 않는다.

실제 소비는 submission_owner_obligations가 실제 모델 호출의 정상 답과 control binding을 받아 수행한다. 같은 실행에 손상 제출을 넣어 rejected 영수증1개와 submission_checked event1개, 정확 check/output/extensions 봉인 바이트, 도메인 불변, 실행 running 유지, 같은 locator의 바이트를 바꿔도 같은 요청 영수증 재전달 불변을 확인한다. 같은 request_id의 다른 payload는 정확 거부해야 한다. 이후 정상 응답은 실제 중앙 봉인·적용까지 output_accepted여야 한다. worker/ControlTransport/owner/Repository 수신을 대체하지 않는다.

새 flows는 initial/active 해석·검토·계획·작업·정비·goal audit·고정 조사·designated impact/live operational·평가/규칙/결합 준비의 실제 참조 목록과 확장 가족을 순회한다. 질문/기준/원천의 id·name·source:alias·published path가 실제 plan을 해소하고 재개하도록 검사한다. 부분 metadata 재시도와 게시 대기의 같은 bundle 비중복·역할별 정산·pending followup 보존도 기존 가족 선택에 포함한다.

record_builders.execution_state는 현재 전체 config를 지정해 프로필과 상태를 같은 설정으로 생산할 수 있게 했다. 이전 기본 config 생략의 의미는 유지하며 구판 호환 변환을 넣지 않는다. 후보와의 차이를 정확히 적용하고 다른 Sim.restart/engine_lifecycle 차이는 복사하지 않았다.

run-family.py는 실제 파일 test_submission*.py38개에서 폴더 한정 모듈 ID를 얻어 canonical run_tests.py에 명시했다. requested.json의259개와38모듈을 확인했고 다른 모듈은 없었다. jgj6vaki의 unit158/sim57/flows44 모두573.9초에 완결 통과했다. 실행 중 source 변경은 없다.14개 개별 예산 초과 중 실제 owner 가족 순회130.297초를 남긴다. 구조 j198il7p의6개도 통과했고 smell5.906초는5초를 넘었다. 원보고·SHA256·파일 지문은 current_work.submission_population_integration에 연결한다.

작업판의 현재 단계 삽입이 착수 이력 표의 header와 separator 사이에 들어간 렌더 오류를 확인했다. 현재 단계는 착수 이력 제목 앞에 넣고 running_test를 실제 값에서 표시하도록 고쳤다. 원 B01/B02 이력과 실패 보고를 지우지 않는다. 실행 중에는 session46856/report_directory와 고정 상태를 기록했고 실제 terminal 이후 이를 해제한다.

다음 공급자 가족은11모듈과두 정상 입력/수치 CLI 생산자가 남는다. 먼저 Calls 포트의 종료 계약을 actual/fake 양쪽과 현재 source로 검증한다. 현재 대역은 미시작 계산을 버리고 이미 반환된 turn에 다시 handoff하여 Future 완료와 thread 정리에서 실제 구현과 다를 수 있다. 후보의 별도 abandon_owner와 Sim.restart 차이는 이 의존성이 검증된 뒤 함께 연결한다. 기존 source에서 끝난 turn에 대한 close가 기다릴 수 있음을 확인했으므로 수리 전 동적 재현은 안전한 미시작 경로로 먼저 선택한다.
