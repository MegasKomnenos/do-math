## 맥락

사용자가 README 첫 문단을 독자의 눈으로 읽어 보라고 한 뒤, 같은 방향으로 공개 문서를 다시 쓰라고 지시했다. 이 작업에는 조건이 두 개 붙었다. 이전 관점, 곧 기억 그래프와 M-0625의 수신자 검토 결정을 보지 않을 것, 그리고 `write-for-reader`를 쓰지 않을 것이다. 그래서 착수할 때 `기억/색인.md`를 읽지 않았다. 내용의 근거는 `.claude/skills/do-math/`의 원문 전부(SKILL·protocol·common·RUNTIME·CLI·plan·research·explore·peer·review)와 `runner.py`·`knowledge_index.py`를 서브에이전트 없이 직접 읽어 얻었다.

원문과 코드를 대조해 이전 README에 없거나 틀렸던 사실은 다음과 같다. 모두 새 README에 반영했다.

- runner가 띄우는 모든 세션은 승인 없이 실행된다(`--dangerously-skip-permissions --permission-prompts none`, `--sandbox danger-full-access`). 세션 폴더 격리는 지시일 뿐 OS가 강제하지 않는다. 이전 README는 저장소 설정만 경고했다.
- 세션 실행 시간에도 세션 총수에도 상한이 없다. 실행이 멈추는 경로는 다섯이다. 목표 검토의 `achieved`, `stop`, 계획의 `wait`, 공급자 한도, 그리고 한도 탐지 없이 계획이 3번 연속 실패했을 때의 `halted`다. 멈춰도 알림 장치는 없다.
- 계획은 전달할 사건이 있고, 다른 계획이 돌지 않으며, 빈 슬롯이 있을 때 파견된다(`Runner.tick`). 연구 공개 자체는 사건이 아니고, 그 뒤의 자동 동료와 자동 묶음 검토를 거쳐 `review_finished`가 사건이 된다.
- 프로세스 식별이 `/proc`에 의존하므로 macOS에서는 모든 프로세스를 끝난 것으로 판정한다. README에 미지원으로 적었다.
- runner가 만드는 `knowledge/index.md`의 표지는 한국어다.
- 계획은 실패한 세션의 `cli.stdout.jsonl`을 읽는다(plan.md). 그래서 "세션은 서로의 대화를 보지 않는다"는 문장은 거짓이었다.

범위는 루트의 README.md와 ROADMAP.md다. `services/`의 한국어 README는 손대지 않았다.

## 사용자 교정의 연쇄

사용자는 결과를 직접 고치기보다 질문과 비유로 결함을 지적했다. 같은 문단을 여러 번 고치면서, 교정할 때마다 반대 극단으로 넘어가는 패턴이 반복되었다.

| 차례 | ⓐ 내가 낸 것 | ⓑ 사용자가 지적하거나 고친 방향 |
|---|---|---|
| 1 | 첫 재작성. "a runner for long, unattended math research", 정의하지 않은 session·published | 차분히 다시 보라. 원 문단에서 진단한 결함을 낱말만 바꿔 되풀이했다 |
| 2 | "work on one mathematical problem for as long as it takes" | 관용구가 해결을 약속하는 것으로 읽힌다 |
| 3 | "Claude Code, Codex, or both", "Nothing guarantees that this happens" 같은 단서를 첫 문단에 쌓음 | 사람이 쓰듯 자연스럽게 쓰라. 구어체 흉내도 하지 말라 |
| 4 | "do-math is a Python program" | 식칼은 철인가. 재료로 정의했다 |
| 5 | "do-math takes a goal and keeps working on it" | 금왕관은 왕이 대관식에 쓰는 것인가. 용도만으로 정의했다 |
| 6 | "a skill … that carries out research" | 물건을 자를 수 있는 철인가. 배포 형태를 유로 둔 채 종차만 붙였다 |
| 7 | "a tool that lets …" | 물건을 자를 수 있는 무언가인가. 유가 비었다 |
| 8 | "a multi-agent system … Its agents are Claude Code and Codex sessions" | 사용자가 직접 "a multi-agent management system that provides governance for autonomous mathematical research"로 고쳤다 |

8에서 사용자가 첫 섹션을 직접 고친 판에서 끌어내 문서 나머지에 적용한 원리는 다섯이다.

- A. do-math는 에이전트를 다스리는 쪽이다. 세션은 do-math의 일부가 아니다.
- B. 구성 요소는 하는 일로 설명하고("instruction documents that direct agent behavior"), 스킬이라는 배포 형태는 소개에서 뺀다.
- C. runner의 동작은 "dispatch"다. 코드의 `Runner.dispatch`·`dispatch_blocks`와도 맞는다.
- D. "check"는 `check.py`의 형식 검사에만 쓰고, 수학적 확인은 "verify"로 쓴다.
- E. 소개에서 시연용 예시(n + 0 = n)와 그것이 사소하다는 해명을 뺀다.

"You can give it a goal"의 `can`은 그 자리의 판단으로 보고 일반화하지 않았다. 사용자가 쓴 문장의 문법 오류("is consisted of")와 대명사 중의성("dispatches them")은 지적만 했다가, 사용자의 지시를 받은 뒤 고쳤다.

ⓒ 반복 가능한 편향(추정 아님, 대화로 확인):
- 지적을 받으면 그 문장만 고치고, 고칠 때마다 반대쪽으로 지나치게 넘어간다. 재료를 빼자 유까지 빠졌고, 유를 넣자 형태를 유로 썼고, 그것을 빼자 빈 유가 되었다.
- 문장이 매끄러운지는 보았지만, 독자가 그 문장을 문자 그대로 믿었을 때 원문에서 참인지는 시험하지 않았다.
- 정확성을 지키려는 단서를 그 정보가 필요한 절이 아니라 첫 문단에 쌓았다.

ⓓ 교정 위치: 사물을 정의하는 문장을 쓸 때는 세 가지를 따로 둔다. 바로 위 부류를 기능으로 고른 유, 구성이나 배포 형태, 전형적 쓰임이다. 그리고 문장마다 "독자가 믿게 되는 것이 원문에서 참인가"를 확인한다. 이번에는 생성이나 검증 시스템의 파일을 바꾸지 않았다. 사용자가 금지했으므로 `write-for-reader`에 이 점검이 이미 있는지도 확인하지 않았다.

## 터득한 것

정의 문장의 결함은 낱말 하나를 바꿔서는 사라지지 않았다. 매번 결함이 다른 꼴로 옮겨 갔다. 사용자의 비유는 차례대로 재료, 용도, 잘못된 유에 붙인 종차, 빈 유를 짚었다. 이것은 아리스토텔레스의 정의 규칙(최근류와 종차, 재료가 아닌 기능, 피정의항과 범위가 같을 것)을 하나씩 점검한 것과 같다. 처음부터 그 규칙을 문장에 대 보았으면 한 번에 끝났을 일이다.

do-math를 "multi-agent system"이라 부르면 에이전트가 do-math에 포함된다. 원문 대부분이 역할, 분리, 수용 기준, 판정 전파, 완료 권한을 정하는 규정이라는 점에서 "governance"는 실제 구성과 맞는 말이다.

## 작업 너머 시사점

- dream 제안 후보: 공개 문서와 스킬 description에서 대상을 정의하는 문장을 점검할 기준을 작문 관례에 넣는다. 유가 재료나 형태가 아닌지, 용도만으로 정의하지 않았는지, 유가 비지 않았는지, 실행 주체(에이전트)를 시스템에 넣지 않았는지를 본다. 같은 오류가 README의 보조 스킬 표("A knowledge graph of …", "Rounds in which …")에도 있었다.
- 경고: `.agents/config.toml`과 `.agents/hooks.json`(둘 다 Git 추적)은 저장소에 없는 `.agents/skills/do-dag/`와 `.agents/skills/ponytail/`의 스크립트를 가리킨다. M-0623의 스킬 삭제 뒤 남은 낡은 참조로 보이며, 이번 커밋에서는 고치지 않았다.
