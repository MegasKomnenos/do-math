실제 ModelCalls와 대역이 종료 후 Future·결과·예외·thread에서 일치하도록 대역을 교정했다. [[M-0463]]의 제출 가족은c1936857로 확정했다. B48은 공급자 통합의 선행 의존성이며 제품 ModelCalls 실행 코드는 바꾸지 않는다.

abkqqlrl의 같은 close-before-owner-progress 계약에서 실제 ThreadCalls는 통과하고 대역과 대역의 미시작 전체 stop 확인은 실패했다. entered가 비어 있고 Future.done이 false였다. 원 대역 close는 thread가 아직 없는 계산을 건너뛰고 turn 목록을 지워 실제 계산의 결과/예외를 생산하지 않았다. 이미 done을 전달한 turn에 다시 give하면 응답할 thread가 없어 기다릴 수 있는 별도 경로도 원문에서 확인했다. 수리 전 동적 재현은 안전한 미시작 경로 세 개만 선택했고 나머지는 수리 뒤 검증했다.

_Turn._body는 실제 ModelCalls가 만든 원 run closure를 수행한다. wait는 완료한 thread를 join하고, close는 모든 stop/미적용 callback 차단 후 미시작 계산까지 실제 결과/예외를 만든다. _finish_turns는 owner_call에 정확 RuntimeError 응답, yield에 STOP, 이미 done에는 추가 give 없이 join한다. Future와 generator는 owner abort에 남기고 결과 수집이나 on_returned를 적용하지 않는다. 실제/대역 공통 계약은 미시작·pending callback·반환 후 미수집·중복 close와 원 결과/예외 identity 및 thread 생존 여부를 검사한다.

모의 process loss는 normal close와 다르므로 Sim 전용 abandon_owner를 별도로 제공한다. 시작한 계산은 원 closure의 cleanup 결과/예외를 보존하고 아직 시작하지 않은 Future만 cancel한다. old owner의 callback/관찰/결과 적용·pending 작업 실행 없이 turns/futures를 정리하며 Sim.restart가 이 동작을 사용한다. 이를 제품 포트 API의 구판 alias나 새 production 동작으로 넣지 않는다. 포트 docstring에 close의 실제 의미를 명시하고 무응답 외부 계산에 새 시간 상한을 발명하지 않는다. close만으로 Job 종료/예약 정산을 인증하지 않는다.

9srned_3의 actual/fake 계약과 turn 종료25개가0.6초에 모두 통과했다. r7vf4mgu의 기존 병렬 운전13개·template key3개·port/layer/smell/ledger 구조7개는110.4초에 통과했고 실행 중 변경은 없다. 추가 실제 Sim.restart8xkym091의3개도8초에 통과했다. 이 검사는 실제 worker 응답 이력과 예약을 유지하고 알려진 owner만 종료하며 같은 세계의 recovery를 재결합한다. artifact 바이트·file hash/default contract의 낡은 cache 폐기도 확인한다. smell7.094초와 재시작2.781초의 개별 예산 초과는 남긴다.

기존 Calls 일반 계약은 wait/pump로 계산을 진행한 뒤 close하는 경로를 주로 확인하여 미시작·pending start callback·done turn을 놓쳤다. 같은 계약을 actual/fake 양쪽에서 수행하고 실제 반환/예외를 관찰하도록 검사 범위를 확장했다. 원보고·SHA256·파일 지문은 current_work.calls_close_integration에 연결한다. 이 부분 실제 thread 경계 검증은 전체T4나 최소 공급자 실호출을 대신하지 않는다.

남은 공급자11모듈과 native 입력/수치 CLI 두 도우미를 이 기반 위에서 이어서 통합한다. 원1e19/1f61/P2원래12/여섯 부류·2단계11와 같은 최종 판본 전체T2/flows·freshT3·분기/전함수극단변이·예산·T4/T5·말뭉치는 계속 미완료다.
