저장 가족의 남은 후보 시험13모듈과 정상 규모 입력/외부 포트 관찰 도우미2개를 main에 통합했다. [[M-0459]]의 계획 가족은 536d14b2로 확정했다. B44는 제품 동작 변경 없이 저장 의무와 기존 개선의 모집단을 연결한다.

단위 시험은 코덱·큰 값·JSON 형/null·Unicode 경계 생성 왕복, 게시마다 새로운 계약으로 읽기와 큰 값 재등장, context/payload/contract/Git/snapshot 손상과 정확 반려, 실제 검사·보고 투영·값 분기·보존/정리 재검사를 포함한다. 정상 Repository/GitStateStore를 만든 뒤 다른 reader와 손상 입력으로 검사하며 기존 저장 도우미는 후보와 원문 일치하여 덮어쓰지 않았다. 두 새 도우미는 JSON 생성 전략/유한 규모 표와 실제 owner용 관찰 시계·Git 포트다.

코덱 생성 시험은 큰 값 둘과7~9회 게시 및 sha1/sha256 object format을 유지한다. 비용 표는 원문 B-27/D-10/A-18/B-03/D-08을 연결한다. export는 N=3/64/65/1043에서 ceil(N/64)+2 Git 연산과 모든 파일의 정확 바이트·실제 쓰기를 함께 검사한다.8MiB 배치 경계와 단일 초과 파일도 검사한다. query는3/16/17/200 항목에서 일치 항목 해시와 batch 호출을 센다. idle owner는 공개 pause 전 commit0을 검사하고 readiness는6/100 과제에서 상태 전체 deepcopy0·평가 결과의 분리 복사를 검사한다.

flows 설치 비용은6/56230 실제 파일을 생성하여 record_installation·공개 trust 등록/transition·actual worker 검증·상태/저장 읽기까지 거친다. 판단 파일은각1회 내용 읽기, 구조 identity/environment 검사는 open/hash/resolve0이어야 한다.56,230은 원 파일 수이고8.55GB 전체 내용 재생은 아니며 이 한계를 docstring 그대로 남긴다. 도구 출력 대역은 외부 Lean 위치에만 두고 제품 판정은 대체하지 않는다. 원 결함-B610~612행의64파일·8MiB export 개선과1023행의실제규모 누락 기록을 다시 확인했다.

ehg6ftt9의 선택136개는125.5초에 모두 완결 통과했고 changed_during_run은 비어 있다. wildcard는 ID전체에 적용되어 다른 모듈의 storage 이름 메서드도 포함하며 보고 ID를 선택 정본으로 삼는다.17개 개별 예산 초과 중 실제 설치 파일 검사93.14초, export15.25초, 생성 게시 왕복13.406초, readiness6.844초를 보존한다. 구조 g07b9h_5의6개도 통과했고 smell6.125초는5초를 넘었다. 속도 향상을 주장하거나 규모·예제를 줄이지 않는다.

보고 경로·SHA256와 파일 지문은 단계-전환표 current_work.storage_population_integration에 연결한다. 같은 판본의 이 부분 통과는 전체 T2/flows/T3·분기/모든 함수 극단변이·시간예산·원문 전건·최소T4/T5를 대신하지 않는다. 다음은 다른 기능 가족의 시험/정상 생산자와 남은 여섯 부류·2단계11의무를 기존 작업판에 연결하는 작업이다.
