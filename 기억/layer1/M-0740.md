## 맥락

넷째 세대 do-math의 완료 조건 가운데 「작은 명제가 Lean 루트에서 논문 PDF까지」는 원고까지만 충족된 채 남아 있었다. 기계에 TeX가 없었고 설치는 사용자 승인이 필요했다(M-0735, M-0738). 사용자가 「tex 설치 승인」으로 승인했다. 설치 방법은 정하지 않았으므로, 받아 둔 Tectonic 0.15.0(실행 파일 하나)을 풀어 쓰는 쪽을 택했다. 시스템 PATH를 바꾸지 않고 기계에 남기는 것이 가장 적은 방법이다.

## 터득한 것

**Tectonic의 출처와 자리.** 압축 파일은 프로젝트의 GitHub 릴리스(`tectonic@0.15.0`, `x86_64-pc-windows-msvc`)에서 받은 것이고 크기가 릴리스 자산의 값(19,268,177바이트)과 일치한다. GitHub가 이 자산의 해시를 공개하지 않아 독립된 해시 대조는 하지 못했다. 압축 안에는 `tectonic.exe` 하나만 있다. `.skill-workspace/do-math-toolchains/tectonic-0.15.0/bin/`에 풀었고(미추적 로컬 보관) PATH에는 넣지 않았다. 논문 명령에는 `--tex <경로>`로 준다. Tectonic은 처음 쓰는 패키지와 글꼴을 외부 서버에서 받아 사용자 캐시에 둔다. 앞서 자동 모드 분류기가 거부했던 압축 해제와 실행은 사용자 승인 뒤에는 거부되지 않았다.

**첫 조판이 드러낸 것.** 앞 실행의 원고를 사본으로 떠서 Tectonic으로 직접 조판했다. 스크립트가 쓰는 LaTeX(머리말, Lean 진술을 찍는 명령)가 TeX를 지난 첫 경우다. 오류는 없었고, 찍힌 쪽을 눈으로 보아야만 보이는 결함이 셋 있었다.

- 짝수 쪽 머리글에서 제목의 변수 n이 대문자 N으로 찍혔다. 원고에 저자가 없으면 `amsart`가 짝수 쪽 머리글에 제목을 쓰면서 한 번 더 대문자로 바꾸고, 이때 수식 안의 글자도 바뀐다. 스크립트가 머리글을 직접 정하게 했다(`\RunningHead`를 `\uppercasenonmath`로 만들고 `\maketitle` 뒤에 `\markboth`). 스크립트를 고치기 전에 사본에서 이 처방이 듣는지 조판으로 확인했다.
- Lean 진술의 `^`가 악센트 글리프로 찍혔다. 스크립트가 `\^{}`로 적었기 때문이다. `\textasciicircum{}`과 `\textasciitilde{}`로 바꾸었고, 방법 문서에 작성 세션도 그렇게 쓰라는 문장을 넣었다.
- 수식 한 줄이 본문 폭을 69pt 넘었다. TeX는 이것을 경고로만 남기고 조판을 마치는데, 스크립트는 오류만 보았다. 조판이 성공한 뒤 TeX의 로그에서 넓은 줄을 읽어(`wide_lines`, 문턱 5pt) 수리 세션에 보내게 했다. 수리 뒤에도 남으면 논문은 그대로 조판되고 명령이 열린 지적으로 보고하며, 독해와 비교는 그대로 진행된다. 조판 오류와 달리 PDF가 있는 상태이기 때문이다.

**`--typeset-only`가 옛 출력 폴더에서 멈춘 일.** 앞 실행의 대응표(`correspondence.json`)는 검증 라운드 1이 비교 결과에 `record_disagreement` 칸을 더하기 전에 쓰인 것이어서 지금 스크립트가 `KeyError`로 멈췄다. 옮김 코드를 넣거나 옛 파일을 손으로 맞추지 않고, 명령을 새 출력 폴더에 처음부터 다시 돌렸다. 세션 여덟(계획 1, 작성 2, 독해 2, 수리 2, 비교 1), 합 780초였다. 원고는 세 번 조립되었고 세 번 모두 조판 오류와 넓은 줄이 없었다. 종료 코드 0, PDF 3쪽이다. 작성 세션은 방금 넣은 방법 문서의 문장대로 `\textasciicircum{}`을 썼다. 출력은 `.skill-workspace/do-math-e2e-20261122/out/paper-tex`다(미추적 로컬 보관). 옛 폴더 `out/paper`는 멈춘 시도 때문에 `log.json`에 끝 사건 없는 줄 하나가 더해지고 `paper.tex`가 새 머리말로 다시 조립된 상태다.

**병행 세션과 겹친 파일의 시험.** 내 시험이 도는 도중에 다른 세션이 `runtime/paper.py`와 `tests/test_paper.py`를 고쳤다(비교되지 않은 진술을 열린 지적으로 보고하는 변경). 시험 한 건이 오류로 끝났는데, 이 시험 모듈은 시험 파일 자신을 대역 세션과 대역 TeX로 하위 프로세스에서 다시 실행하므로 파일이 도중에 바뀌면 영향을 받는다. 다시 돌리면 통과했다. 커밋할 내용을 따로 확인하려고, 내 변경만 HEAD 판본에 적용해 색인에 넣은 뒤 `git checkout-index --prefix`로 색인의 스킬을 다른 폴더에 내보내 거기서 `test_paper`를 돌렸다(25건 통과). 작업 트리를 건드리지 않고 스테이징한 내용을 시험하는 방법이다.

**검증 기록.** 완료 조건 셋이 모두 충족된 것으로 고쳤다. 시험 조건에는 단서가 붙는다. 전체를 통으로 돌린 마지막 실행 뒤에 실행기가 여러 번 바뀌었고, `test_ending`, `test_retention`, `test_views`는 그 뒤로 돌리지 않았다. 첫 독해가 「변경 네 번, 다시 돌리지 않은 모듈 넷」이라는 내 서술이 사실과 다름을 드러냈다(`init` 수리도 전체 실행 뒤의 변경이고 `test_context`는 그 뒤에 다시 돌렸다).

## 작업 너머 시사점

- **경고: 정본과 사본의 어긋남은 그대로다.** `.agents/skills/do-math`는 재생성하지 않았다(M-0735).
- 사용자에게 남은 결정: 논문 방법 문서 `reference/paper-method.md`의 확인, 논문이 가리킬 Lean 원천의 공개 위치(이번 실행의 독해 세션도 같은 점을 짚었다), 사본 재생성 시점, push 여부.
- 이 커밋 직후의 사용자 지시: 표준적인 실제 수학 논문의 사본을 충분히 확보해 논문 작성 세션이 실제로 참고하게 하고, 그와 같이 쓰였는지를 반복적인 독립 독해로 검증한다. 이 커밋에는 들어 있지 않다.
- dream에서 묶을 후보: 찍힌 결과를 눈으로 보아야 드러난 결함 셋은 「통과가 증언하는 범위」(L-0001)와 이어진다. 조판 오류가 없다는 것은 쪽의 모양에 대해 아무것도 말하지 않았다.

## 검증 기록

- `test_paper` 25건(새 시험 4건 포함)이 스테이징한 내용의 사본에서 통과했다. 다른 모듈은 이 변경 뒤에 돌리지 않았다. 바뀐 실행 코드는 `runtime/paper.py`뿐이다.
- 실제 실행: 위의 논문 명령 한 번(종료 코드 0, PDF 3쪽). PDF를 읽어 머리글과 Lean 진술의 글리프를 확인했다.
- 검증 기록은 합의를 새로 등록해 독립 독해 두 번을 거쳤다(세션 `claude-lean-canon-verification-20261122-tex`).
