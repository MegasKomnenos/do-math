[[M-0516]] 뒤 기존 자료 도착 재평가 검사의15문장을 그대로 보존해 flows로 옮기고 실제 계획/worker/수신까지 연결했다. 공개 source로 new.txt가 도착하면 현재였던 미완료 평가가 무효화되고 기존 계획과 합쳐지며, 반환 결과는 그대로다. 같은 refresh를 반복해도 계획은 하나라는 기존 단언을 유지한다. migration/dispositions/planning.2.json의 현재 new_ids만 갱신하고 legacy_id와 이력은 유지했다.

실제 산출 수락까지 가자 이전에 수락된 OB-scope 이전을 유지하는 평가가 transfer cannot overwrite an existing recipient obligation으로 반려됐다. task_scope.apply_task_assessments는 같은 이전을 재확인하는 경우도 새로운 수신 의무를 추가하려 했다. 최초 unit 재현 v22l7vgk와 실제 flow의 integration.application 진단 ea605uoi를 보존하고 KD-1916으로 연결했다. 원래는 계획 큐 생성만 검증했기 때문에 후속 수락이 불가능한 사실을 놓쳤다.

기존 수신 의무가 있으면 원 과제·판본·의무·수신 의무 ID·권위가 일치하는 이전 기록이 정확히1개인지 확인한다. 의무 내용은 새 ID를 대입한 원 의무와 정확한 JSON 해시로 비교하고, 기록된 생산 실행은 종료된 research_plan 또는 operational_review여야 한다. 일치하면 기존 이전을 유지하며 수신 과제의 판본/검토/의무/이력을 다시 쓰지 않는다. 현재 권위·입력 결속·별도 미종결 수신자·실행 중 수신자 거부는 앞의 기존 관문으로 유지한다. 불일치/중복/기원 생산 실행 부재는 기존 덮어쓰기 오류로 원자 거부한다. 반복 보존과8개 출처/내용 교란의 무변경 거부를 단위 검사했다. 연구-계획 계약에도 같은 이전 보존의 의미와 조건을 명시했다.

첫 응답 초안의 빈 missing_inputs는 저장·산출 스키마 위반이었다. 이를 open 의무로 고친 뒤 실제 이전 오류가 드러났다. 최종 시나리오는 new.txt는 도착했지만 proof-report.txt는 아직 없는 미완료 상태로 응답한다. 기존 이전을 유지하면서 다음 구체적 자료를 기다리므로 평가가 다시 현재가 되고, 같은 입력으로 추가 계획이 반복되지 않는다. 기본 응답기의 완료 가정을 사용하지 않고 실제 남은 의무의 미완료 응답을 쓴다. 초기 schema 실패와 실제 이전 오류를 구별해 원보고를 보존했다.

교정 후 단위15개0.2초와 실제 flow1개42.1초가 통과했다. 최종 구조48·단위54·Sim12·flow1, 총115개가66.1초에 통과했고 실행 중 소스 변경은 없다. 원보고는 검증/2026-10-05-평가-발동/이며 report.json SHA256은 c0067e1a218e5130ef56fd3b107a1f75298e65ec6e10623e2ad093967cc333fd다. 같은 시간대에 이동 검사 장부를 수정했지만 최종 검증은 모든 코드/장부/계약 변경 후 고정해서 수행했다. 부분 보고들을 전체 일반 통과로 합산하지 않는다.

B100은 평가 무효화에서 실제 재평가 수락까지의 범위다. 개정 순환·선택 무효화·목표 근거 상실·학술 후속/반려·입력초과·수락 결과의 다른 발동 원천은 계속 남는다. 전체 일반 정상 기준선과 fresh T3·전 함수 변이·외부/문서 관문도 유지한다.
