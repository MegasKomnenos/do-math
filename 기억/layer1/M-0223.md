title: MathSciNet과 Web of Science의 전후방 인용 회수를 연결함

원 계약 대조에서 선정 자료원의 명시적 역할과 구현 사이에 인용 관계 회수의 누락을 확인했다. MathSciNet의 supplementary는 Review PDF였고 Web of Science의 원 Full Record에 있는 CR은 나가는 참고문헌이었다. 두 결과를 들어오는 피인용 문헌 목록으로 확대할 수 없었다. 두 작업자를 각각 배정해 현재 원 제어를 조사하고 기존 search·export 흐름을 재사용했다. 다른 자료원의 인용 그래프로 자동 전환하지 않는다.

MathSciNet MR2733384의 From References 제어는 3건이며 원 검색식은 cp:2733384였다. Search References는 원 참고문헌 48개 중 MR occurrence44개를 쉼표 목록으로 연결했다. 고유 MR은 42개이고 중복 occurrence는 2개다. 처음 추정한 반복 |mr 문법 대신 실제 @|mr: 뒤 쉼표 목록으로 교정했다. MR 없는 참고문헌과 중복도 정제 원 페이지에 남기고 구조화된 42건을 참고문헌 전체로 표시하지 않는다. kind=citations 또는 references와 MR·DOI 대상을 기존 search에 연결했다. DOI는 검색 후보와 원 BibTeX가 유일하게 같은 DOI를 식별해야 MR로 해석한다.

첫 표본의 From Reviews가 0이라는 이유로 조사 범위를 닫지 않고 다른 문헌을 확인했다. 원 서지로 MR0463157이 Algebraic geometry임을 대조했고 해당 문헌의 From References 제어 7,912와 From Reviews 제어 76을 발견했다. 리뷰 인용은 r:(MR0463157 OR "refcno 463157")라는 별도 원 검색식이었다. citation_basis=references 또는 reviews를 추가하고 제어의 76과 실제 검색 결과 72를 각각 보존한다. 차이의 원인을 추정하거나 두 건수를 덮어쓰지 않는다.0건 리뷰 제어는 query를 새로 만들지 않고 not_found로 반환한다. 이 확인은 같은 문헌의 인용 수가 0이면 기능이 없다고 해석하는 성급한 결론을 피한 구체 사례다.

MathSciNet 실제 SDK는 incoming3건의 start1/limit2와 BibTeX, outgoing42건의 start4/limit2 두 원 페이지와 EndNote, DOI 기반 관계 조회, reviews72건 중 1건과 원 BibTeX·추출을 통과했다. 검색·관계 제어·MR 식별자·페이지 범위 회귀를 포함해 test_mathscinet_citations와 test_browser39개가 통과했다. 근거는 services/scholarly-mcp/data/access-research/mathscinet-citations/의 구현보고.md, implementation.json, live-sdk.json, from-reviews-probe.json이다.

Web of Science는 Full Record의 실제 Citations 제어에서 mode=citing_article과 부모 UT의 colluid를 대조한다. search의 kind=citations는 UT·DOI·Full Record URL을 받고 기존 범위·원 export를 유지한다. fetch supplementary는 원 CR과 incoming 문헌을 구별해 제공한다. 문헌 화면의 136회 인용과 기관에서 반환된 125건은 서로 다른 원 집계로 보존했다. 원 제어를 너무 일찍 읽는 대기 실패는 제한된 제어 대기로 교정했다.

WOS의 20260912T141742Z-wos-citations-mcp.json은 첫 2건의 plain·JSON 추출, DOI 기반 start124/limit2의 마지막 1건, fetch의 양방향 관계를 completed=true로 통과했다. WOS·browser26검사와 compile 검사가 통과했다. 원 근거는 data/access-research/wos-citations/의 citations.json과 구현보고.md다. WOS 정렬·facet·개별 edition은 원 요청 전 locator timeout이었으므로 접근 제한으로 바꾸지 않고 추가 구현을 계속한다.

이 커밋은 같은 browser_adapters.py의 두 인용 기능과 전용 시험을 함께 보존한다. 후속 WOS 고급검색과 ACM 변경은 이 인용 상태를 스테이징한 뒤에 진행하도록 소유 범위를 나눴다. 공통 사용 설명은 후속 통합에서 갱신한다. 원 계약의 고급검색·export 누락을 실제 연구 요청이 생길 때만 하자는 범위 축소는 채택하지 않았다. 모든 조건 조합의 전수 실측과 알려진 기능의 미구현을 구별하며 전체 작업을 계속한다. 푸시하지 않는다.
