## 확정한 독립 변경

[[M-0423]]의 작은 변경 단위 원칙과 [[M-0424]]의 저장 타입 수리 다음으로 KD-1200을 main에 독립 통합했다. 사용자 요구는 새 목표로 재편 전체를 끝까지 이어가는 것이다. 이번 변경은 전체 수리판을 덮어쓰지 않고 수학 목표의 기초 하나를 공유하는 범위로 좁혔다. governance.mathematical_goal_basis는 학술 요건을 제외한 헌장 내용과 문서를 정확히 해시한다. 헌장 결정, 목표 판정 생산, 판정 현재성, 대기 감사의 기초, 학술 해답 기초가 이 함수를 사용한다. 학술 요건은 기존의 별도 판본 결합을 유지한다.

main의 기존 시험에서 KD-1200 표시만 제거해 실제 실패를 확인했다. `do-math-tests-htvtby_s`의 공개 요건 변경 뒤 목표가 unsolved가 되는 red를 보존한다. 제품 수정 뒤 `do-math-tests-yhaq4qsd`의 관련 42개가 모두 통과했다. 공개 제어와 직접 거버넌스 경로 둘 다 owner readiness를 새로 확인한다. 해결된 판정 전문과 해답 기초를 학술 요건 변경·저장·재시작 동안 그대로 비교한다. 같은 기존 모듈에 반대 사례를 더해 실제 수학 목표 변경은 판정을 폐기하고 미해결로 돌아가며 재시작 뒤에도 유지하는지 확인했다. 제품 내부 패치는 없다.

새 판정 기초 필드를 저장 스키마에 넣고, 이관 기록 네 곳의 열린 결함 연결을 제거했다. 각 기록의 과거 red 설명은 남기고 수리 뒤 의미를 덧붙였다. 다른 결함 원장은 보존한다. 수리판의 템플릿 warm-up 변경은 이 독립 단위와 관계없어 복사하지 않았다. 원문 이음새 표와 생성 미러를 함께 갱신했다. 현재 main의 열린 결함은 14개다. 후보의 0개와 혼동하지 않는다.

## 기준선에서 발견한 후속 문제

수리판의 일반 기준선 `knvwwf8d`는 여전히 실행 중이며 원 트리를 편집하지 않았다. 종료한 작업자의 슬롯을 써 별도 후보에서 수정했다. B04는 고정 trace 행번호를 실제 AST 좌표로 바꾸고, 영향 변경/반려의 출구를 존재하지 않는 과제 평가 대신 실제 task_dispositions 철회로 구성했다. 원문 과제의 광고 해시, 수학 기록 보존, 대기 전문, 실제 접수 영수증, 저장 재시작을 단언한다. focused7과 related73이 통과했다.

B05는 KD-1200/KD-1900의 의도적 수리와 충돌하던 옛 기대값 두 개를 교정했다. 학술 요건은 진행 중 수학 감사를 유지하고, 실제 수학 목표 변경은 폐기한다. 판단 대상 없는 빈 준비는 접수만 하고 계획을 만들지 않는다. 준비된 과제의 정상 계획 개방도 유지한다. scheduling.1의 역사 legacy_id는 남기고 현행 시험 이름으로 연결했다. focused5와 이관/관련30개가 통과했다. 서로 다른 범위의 수를 합해 전체 성공으로 세지 않는다.

B06의 실제 red `b18_r9ug`는 단계 신뢰 활성화 실패 history에 `staged identity review publication premises changed`를 남겼다. 생산자는 헌장을 제외한 거버넌스를 봉인했는데 수신자는 헌장까지 비교하는 복제 규칙 불일치였다. 후보에서 knowledge_records.review_publication_premises를 생산자와 수신자 정본으로 공유했다. 다섯 전제 각각의 변조 반려를 기존 시험에 보강했다. focused3과 관련13개가 통과했고 KD-0805를 새 폐쇄 이력으로 기록했다. B07은 wait_rules 계층 선언 누락을 순수 규칙 layer1과 scheduling 영역에 등록하여 구조6개를 통과했다. B04~B07 제품 변경은 아직 main에 통합하지 않았다.

## 근거와 남은 범위

추적 진입점은 단계-전환표-2026-10-03.md/json의 current_work다. 원 보고 전문은 사용자 Temp, 패치와 갱신 스크립트는 .skill-workspace 아래의 Git 제외 로컬 자료다. 경로와 보고 SHA256, 시험 실행 중 소스 변경 없음, 개별 시간 예산 초과를 작업판에 보존했다. 이번 main의 42개는 87.8초이며 개별 예산 초과 4개가 있다. 성능 충족이나 최종 전체 관문 통과로 표현하지 않는다.

원 기준선은 적어도 일곱 실패를 발견했으며 후보의 부분 통과로 원 실패를 덮지 않는다. 현행 전체 T2/flows, fresh 전체 T3, 모든 대상 함수 극단 변이, 합의 예산, T4/T5와 말뭉치, 나머지 검수된 main 통합이 남아 있다. 다음 작업은 원 실행의 실제 종료 결과와 비용을 확정하고 후보의 검증된 변경을 의존관계에 맞춰 통합하는 것이다. 푸시, graphify 갱신, 기존 연구 재개나 삭제는 수행하지 않는다.
