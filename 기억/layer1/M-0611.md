## 맥락

사용자가 실행 중인 주차 함수 인스턴스의 `knowledge/index.md` 검토를 요청했다. 검토의 결론은 정확성 통과, 진입점 쓰임새 결함이었다.

**정확성 대조 결과(이상 없음)**
- 공개 커밋 순서로 157기록에서 재생성한 색인이 문자 단위로 같았다.
- 계획 소개문 53개의 요청 수와 Astra·Sol 배정이 실제 산출과 모두 일치했다.
- 소개문 안의 세 자리 이상 수치가 원문에 없는 경우는 0이었다.
- 소급 커밋 `e9874b3`은 공개 `output.json` 148개에 `overview`와 `overview_assessment` 두 키만 추가했고, 기존 키의 변경은 0이었다.

**쓰임새 결함**
- 판정 근거 줄이 전체의 19%였다. 같은 소급 면책 문장이 49회 반복됐고, 판정 값은 52개 모두 `supported`였다.
- 현재 상태(최신 `research-status.md`)로 가는 연결이 없었다.
- `&lt;`, `\(`, `\_`, `\+` 같은 과잉 이스케이프가 세션이 읽는 원문 수식을 흐렸다.

사용자가 반영을 지시했고, 이어 실행 중 인스턴스 적용과 커밋을 지시했다. 두 보고서의 원고와 독해 기록은 `.skill-workspace/writing/index-review/`와 `.skill-workspace/writing/do-math-value-eval/`에 있다. 상위 Git 제외 로컬 자료다.

**변경**
- `knowledge_index.render_index(records, status=None)`
  - 머리말에 마지막 계획의 `research-status.md` 링크를 둔다.
  - 연구 항목의 판정 근거 줄을 없앤다.
  - "요약 판정은 각 검토 기록의 `overview_assessment` 값이며 근거와 작성 경위는 그 기록에서 읽는다"는 문장을 둔다.
- `plain()`: `\`, 백틱, `<`, `[`, `]`만 백슬래시로 이스케이프한다.
- `runner.refresh_index`: 마지막 계획 기록에 `research-status.md`가 실제로 있을 때만 status를 넘긴다. 마지막 계획에 파일이 없으면 더 오래된 계획의 낡은 현황을 가리키지 않는다.
- `protocol.md`와 `SKILL.md`의 색인 설명 한 문장씩을 맞췄다.

## 터득한 것

**검토 때의 "소급" 표지 제안은 반영 단계에서 버렸다.** 생성기가 소급 판정을 구별하려면 특정 문구 탐지나 Git 이력 대조가 필요하다. 이는 일회성 변환을 위한 호환 논리를 제품에 넣는 일이고, M-0610에서 사용자가 거부한 종류다. 대신 색인이 판정 값만 보이고 작성 경위는 원 기록에 맡기는 일반 문장으로 바꿨다. 판정 근거를 색인에서 빼면 출처 오인이 오히려 커질 수 있었는데, 이 문장이 그 위험도 막는다.

**이스케이프를 "렌더링이냐 원문 독해냐"의 선택으로 남긴 검토 판단은 다시 열어 해소했다.**
- CommonMark에서 렌더링 때 글자를 숨기는 경로는 원시 HTML뿐이다. 예를 들어 `0<L and n>3`의 `<L and n>`은 여는 태그로 해석된다.
- 글자를 바꾸는 경로는 링크와 코드 스팬이다.
- 이 경로와 백슬래시 자체만 이스케이프하면 두 소비 경로를 함께 만족한다.
- 나머지 기호(강조, 행 첫머리 블록 기호)는 렌더링에서 모양만 바꾸고 글자를 숨기지 않는다. 옛 코드도 행 첫머리 `-`는 막지 않았으므로 이 변경으로 잃는 안전성은 없다.

**같은 모델 검토의 부정 0이 결과 167개로 늘어서도 유지된다.** 실행 중 인스턴스의 현재 판정은 Lean 수용 79, Lean 없는 `supported` 88, 부정·상충 0이다. 직전 가치 평가에서 지적한 "부정 0이 정확성과 너그러운 검토를 구별하지 못함"은 표본이 늘어도 그대로다. 해소하려면 결함을 심은 산출로 같은 모델 검토와 다른 공급자 검토의 검출력을 재는 측정이 필요하다.
