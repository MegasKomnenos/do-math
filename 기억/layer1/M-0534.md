[[M-0533]]의 R07/R17 next_packet을 대화 이력 없는 새 작업자에게 배정했다. 스키마 편집과 경계 검토를 병행하되 실제 편집은 차례로 진행했다. 두 편집이 끝난 뒤 공유 트리를 고정하고 통합자가 관련 세 모듈을 한 runner 호출로 검증했다. 새 문서 반환 교체의 입력 확인은 별도 readonly 작업으로 끝냈다.

R07은 기존 named12/67변형·composition13/25변형을 유지했다. 기존 발견은 공개 모듈 함수만 보았지만 이제 클래스 schema 메서드4개도 찾아 선언 누락/낡은 선언을 검사한다. _response_schema/_review_schema/_review_research_schema는 검토한 실제 복사 경계·delegate·불변 scalar 후처리에 근거를 연결하고, _governance_schema는 borrowed transformer로 구별했다. 이 명시 근거를 실제 메서드 전체를 동적으로 실행한 증거라고 부르지 않는다.

상수 빌더6개는 실제 직접 호출로 검사한다. lifecycle_values와 knowledge_io._definition의3형태, StateContract.manifest의 초기 계산/캐시 재사용, 두 observation 목록 생성자, _blocked의 정확 scope·fallback·미등록 scope가 대상이다. dict/list/set 결과를 보존하여 두 반환·전역과 가변 노드가 겹치지 않는지 검사하고 frozenset/문자열 leaf는 불변 공유로 구별한다. borrowed outcome getter는 편집 가능한 사본 API로 바꾸지 않는다. schema 모듈11개가 통과했다. 지정 후보의 등록/검사는 끝났으므로 새 근거 없이 다시 감사하지 않으며, 원문 전체 모집단과 최종 관문의 연결은 별도로 남긴다.

R17은 기존 SnapshotReadToolTests의 성공/거부 장면에 실제 pythonw 부모를 넣었다. 이 프로세스가 install_tools를 호출하고, 같은 부모가 시작한 PowerShell이 보존 context의 record_map.read_tool.command를 그대로 소비한다. 부모 실행기 경로와 console handle0, JSON stdout, reads.jsonl, 성공0과 권한 거부1을 확인한다. support.cli_inputs.role_reach도 수동 sys.executable 명령 재구성 대신 실제 지급 명령을 소비하도록 바꿨다. 원래 두 경로에 남아 있던60/120초 subprocess timeout을 제거했고 실제 프로세스는 격리 Job/CREATE_NO_WINDOW를 사용한다. 모델·Lean·연구 전체를 기동하지 않았다.

첫 관련 실행은 구조11 및 기존 경계8 통과, 새 windowless2 오류로 종료했다(190.1초). 오류는 read-request에 arguments tuple을 넣어 canonical JSON이 거부한 것으로 pythonw 기동 전 시험 준비 오류였다. 이 한 줄을 list(arguments)로 고친 뒤 실패한 두 시험만 재실행하여2통과·skip0·7.0초를 얻었다. 첫 실패 보고는 그대로 보존하고 전체 성공으로 바꾸지 않았다. 두 실행 모두 changed_during_run은 비어 있다. 원보고는 검증/2026-10-05-빌더-모집단-pythonw-읽기에 있다. 오래 걸린 기존 경계 두 시험의61.266/40.640초는30초 소프트 기준 초과로만 기록하며 실패로 간주하지 않는다.

지급 정본의 남은 제품 반례도 구체화했다. file_io.console_python은 문서상 pythonw일 때 같은 폴더 python.exe를 지급하지만, 형제 파일이 없으면 코드가 원래 pythonw를 반환한다. GUI 실행기를 일반 PowerShell 호출로 쓰면 기다림/출력을 보장할 수 없다는 함수 설명과 충돌한다. 네 지급자가 이를 따로 거부하지 않는다. 이번에는 제품 동작을 바꾸지 않았고, 다음은 정본의 명시 거부와 직접 호출자의 오류 경로를 한정 수리하는 작업이다.

문서 AST 제거 검토는 최초 묶음 이름 PURE가 정확하지 않음을 확인했다. record_map은 (index, scope, snapshot)을 받는 순수 반환이므로 기본 반환 키의 AST 결속 하나를 실제 함수 결과로 바꾸면 된다. read_tool 생산자와 다른 네 함수는 그 첫 수정에서 제외한다. trace_report.progress의 파일 읽기와 status_report의 callback/검사 의존은 별도 경계로 두며, 이름 때문에 억지로 순수 함수처럼 호출하지 않는다. 이 검토 원문은 작업판 builder_population_and_windowless_boundary.pure_document_review에 통합했다.

현재 목표의 전체 일반/fresh T3/극단 변이·정상 기준/T4·T5·말뭉치·배포 일치는 아직 미완료다. 부분 실행 수를 합산하지 않으며, 이전에 확인한 후보와 발동 규칙을 반복 탐색하지 않는다.
