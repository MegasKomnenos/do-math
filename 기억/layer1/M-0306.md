## 맥락

[[D-0006]]의 제안 2를 사용자가 승인해 집행했다. 검증·수리 작업이 끝나면 보존분만 커밋되고 나머지 중간물이 미추적으로 쌓여 이틀 사이 1,898개가 됐고([[M-0303]]), Codex 세션의 재귀 삭제는 다섯 번 자동 승인 검토에 거부됐다. 제안은 `.gitignore`에 `임시/*/`를 넣고 보존할 증거만 `git add -f`로 추적하는 방식이었다.

## 제안 문구와 달라진 구현 형태

집행 전에 `임시/`에 파일을 만들고 커밋하는 절차를 찾았다. verify-rounds는 런 디렉터리 기본값이 `임시/<산출물 이름>_검증_<날짜>/`이고, 라운드 커밋에서 `<런>/동결.md`·`<런>/장부.md`·`<런>/종료보고.md`를 `-f` 없이 `git add -- <범위>`로 올린다. 제안 문구대로 디렉터리를 통째로 무시하면 이 커밋이 거부된다. 또 Git은 무시된 디렉터리 안으로 내려가지 않으므로 하위 파일의 부정 규칙이 작동하지 않는다.

그래서 디렉터리가 아니라 그 내용을 무시하는 `/임시/*/*`를 쓰고, verify-rounds가 커밋하는 세 파일 이름을 `!/임시/*/동결.md` 등 부정 규칙으로 허용했다. verify-rounds 절차는 바꾸지 않았다. `임시/` 바로 아래의 파일(예: do-dag 테스트가 인용하는 기안 문서 경로)은 규칙에 해당하지 않는다. write-for-reader 독해 흐름의 `임시/작문/` 같은 작업 파일은 무시 대상이 되며 원래 커밋 대상이 아니다. 새 증거를 커밋하는 절차의 진입점인 commit-harness 5항에 `git add -f`와 스테이징 확인 한 문장을 더했다. 로컬 디스크의 누적은 이 변경으로 줄지 않으며, 삭제가 허용되는 세션에서 필요할 때 정리한다.

## 검증

`git check-ignore`로 시험 경로를 확인했다. 런 디렉터리의 `a.json`과 `라운드1/수리_1.md`는 무시되고, 같은 디렉터리의 `동결.md`·`장부.md`·`종료보고.md`와 `임시/` 직속 파일은 보였다. 이미 추적된 `임시/` 파일 170개는 그대로 추적되며 `git status`에 변화가 없었다. `-f` 없이 무시 경로를 `git add`하자 Git이 무시 안내와 `-f` 힌트를 출력했다. 시험 파일은 확인 뒤 삭제했다. commit-harness 정본 변경 뒤 미러를 재생성했고 `--check`는 드리프트 없음이었다. 산출물 자체가 `임시/` 작업 디렉터리 안에 있는 verify-rounds 런은 산출물 커밋에 `-f`가 필요하지만, 그 경우 Git이 추가를 거부하고 라운드 커밋 절차의 스테이징 확인이 결손으로 드러내므로 조용히 누락되지 않는다.
