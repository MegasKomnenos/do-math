[[M-0488]] 뒤의 B74는 원문 `조사/결함-범주.md` 5-A의 근거 필드 선언과 민감도를 시작한다. 모집단은 인용 근거, 과제 완료 근거, 검토 개설, trust manifest/inventory, 편입 허용 목록을 포함하는 판정 함수 전건이다. 이번 변경은 검토의 비제안 근거와 과제 인용 projection을 다루며 이 전체 모집단을 작은 부분으로 바꾸지 않는다.

capture_review_input_basis의 필드 tuple을 공개 REVIEW_INPUT_BASIS_FIELDS 정본으로 옮겼다. review_policy·scope_assessment·owner_activity_id·activity_execution_limit·identity_basis·policy_ref·publication_premises의 일곱 항목이다. 제안 내용은 별도의 immutable proposal digest와 원문 검증이 소유하며, 진행·이력·결과·수락 표지는 이 비제안 근거를 대신하지 않는다. 현재 캡처와 비교가 같은 선언을 사용하고 일반 검사가 선언 항목 전건을 순회한다. 공유 정본 문서에도 추가했다.

첫 재현 f1m50rq7은 저장 근거의 activity_execution_limit=True와 현재 값 1의 형식 변화에서 변경 배열이 비어 실패했다. 비교가 Python ==로 bool과 int를 같다고 본다. 형식 검사를 이 내부 함수에 새로 중복하지 않고, 현재 JSON 값 동등성 정본 same_json_value로 정확하게 비교했다. 저장 가능한 review premises는 현재 상태 계약의 JSON 값이며 구판 호환을 위해 숫자나 boolean을 변환하지 않는다.

두 번째 재현 m2ptq8ou는 캡처가 선언한 identity_basis=null 항목을 아예 제거해도 변경 없음으로 판정했다. basis.values.get(field)가 부재를 null로 보충했다. 선언 항목 존재를 먼저 확인하여 누락이면 해당 field·missing_basis_field·refresh_review를 반환하고, 존재할 때만 값 비교를 한다. 새 기본값·이름 별칭·구판 snapshot 변환을 만들지 않는다. 값이 명시된 null과 근거 선언의 부재는 다르다.

기존 governance basis 계약 모듈에 실제 start_review 생산자의 결과를 사용해 일곱 필드 변경과 각각의 누락을 순회하는 검사를 넣었다. progress/history/phase/round/receipt 등 선언 밖 관리 정보는 근거를 바꾸지 않아야 한다. scope selected_profile_ref의 구체적인 기존 진단과 캡처 사본 불변 단언도 유지했다. u_2orynm의 여덟 관련 사례가 통과했다.

과제 인용 근거는 이미 planning.CONTRACT_FIELDS라는 선언을 쓴다. 기존 decision basis 모듈에서 선언된 계약 필드 전건의 JSON projection 변화가 contract_sha256 변화로 드러나는지 확인하고, status·reviews·selection·history·review_cycle_id·receipt 관리 정보는 인용 근거를 바꾸지 않는지 확인했다. 이는 더 높은 저장/형식/착수 검사의 앞 단계인 projection 민감도 검사이며 변조한 임의 JSON shape를 정상 계약으로 게시했다고 주장하지 않는다. 읽었던 결과 prefix의 추가는 안정적이고, 원래 결과의 교체·삭제는 results_sha256 변화여야 한다. 이 내용/모집단 축의 기존 독립 소비 검사는 유지하며 v15wr8qa의 여섯 사례가 통과했다.
