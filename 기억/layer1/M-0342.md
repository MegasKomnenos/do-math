## 맥락

사용자는 `RI-01M3AB8E1KYF02E3T0G7BFEVAC`의 전체 실행을 실제 기록에 근거해 분석하고, 단계별 시간·병목·비효율·결함을 파악한 뒤 자율적으로 가장 건전한 개선안을 구현하도록 요청했다. 대상은 자연수 오른쪽 덧셈 항등원 연구이며 앞선 초기화 실험들과 구분했다. 기존 연구를 정지·보존하고 큰 payload와 환경 관측을 개선한 선행 작업은 [[M-0341]]이다. 이번에는 당시 bootstrap과 현행 코드를 대조하여 이미 개선된 부분과 남은 결함을 구별했다.

역사 snapshot `6abb6ed150a65f8c6de41326e991894206372fb4`의 실행 17건과 상태 30건을 추출 요약과 대조했고, native final 13건의 바이트 및 사용량 보고도 확인했다. 연구 수행의 worker 종료 기록은 05:11:19였지만 중앙 접수는 05:31:55, 정산은 05:35:02였다. 동일성 scope의 worker 종료 기록은 06:07:39, 미수락 정산은 07:06:37이었다. 파일 수정 시각은 전체 Job 종료 장벽의 관측 시각이 아니므로 이 차이를 전부 순수 큐 대기나 모델 추론 시간으로 분류하지 않았다. 기존 연구의 수학 목표 완료를 선언하거나 연구를 재개하지 않았다.

## 확인한 원인과 설계 판단

당시 비 artifact 레코드는 신뢰 환경 등록 뒤 약 118.8MB, 동일성 검토 시작 뒤 약 158.9MB였다. 로그 한 행마다 중앙 callback 완료를 기다리고 상태를 복사·검증·공개하는 경로에서, 이미 생성된 응답과 중앙 처리 사이의 지연이 커질 수 있었다. 정확한 함수별 시간 분배는 당시 trace 부재로 확정하지 않았다. 현행의 불변 payload 공유와 비동기 환경 관측은 유지하고, native stream을 순서 보존 배치로 적용하며 완료 결과 회수를 우선하도록 바꿨다. 단일 writer, 권한 확인, 저장 CAS와 실제 종료 장벽은 유지했다.

실제 기록에는 05:11:39에 열린 자기 점검 의무에 대해 과거 첫 명령의 시작 사건을 05:15:55에 처리하면서 응답 전 연구 행동으로 판정한 사례가 있었다. 수신·처리 시각과 native 행의 위치를 분리했다. 독립 검토는 전달 시점을 가로지르는 부분 JSONL 행의 끝 위치만 비교하면 같은 오판이 남음을 찾아냈다. 행 시작·끝 위치를 함께 보존하도록 수정했다. 더 나아가 전달 뒤 출력됐다는 사실만으로 작업자의 인지를 인정하지 않고, 해당 의무의 정확한 요청을 반환한 성공적인 poll 완료가 있어야 이후 명령을 응답 전 행동으로 분류한다. 인지 미확인과 기한 뒤 응답 미수신 진단은 구분한다. 요청 ID가 필요한 poll을 작업 공간에서 발견할 수 있도록 `.control/self-checks/` 전달 사본도 제공했다.

운영 점검 입력 snapshot에 이미 `ready_to_submit` 체크포인트가 있었으나 live 점검에는 지급되지 않았다. 체크포인트 본문과 그때 포착한 증거 파일을 정확한 참조로 전달하고, 누락·크기 초과·읽기 실패를 명시했다. 큰 본문은 prompt에 중복 삽입하지 않는다. 별개의 두 운영 반려는 읽을 수 있는 출처와 처분에 허용된 canonical 참조가 달랐기 때문에 발생했다. 같은 resolver로 입력의 `admissible_basis_refs`와 제출·적용 검사를 구성했으며 임의 경로를 허용하는 방식은 택하지 않았다.

제출 의무의 완료 판정은 같은 형식 원문·선언·해설에 후속 검증 결과와 review ID가 추가됐다는 이유만으로 stale이 되지 않게 했다. 독립 검토는 새 의존 순회에서 관계 양끝을 빠뜨린 반례도 찾아냈다. 관계·조건·프로필 참조를 복원하고, 직접 사용한 전문 판정과 전이 의존의 효력은 엄격하게 유지했다. 실제 근거가 바뀐 terminal 과제는 다시 열지 않고 원 판정·현재성·사유와 후속 계획 책임을 보존한다. 초기화 사건은 최초 역할이 소유하고 수락 뒤 소비하며, 정상 실행 점유만으로 새 빈 계획을 열지 않는다. 점유 중 실제 허가 상실은 계속 계획으로 전달한다.

## 작업 너머 시사점
