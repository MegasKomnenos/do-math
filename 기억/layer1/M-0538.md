[[M-0537]]에서 남긴 status_report의 최종 전달을 별도 새 문맥 작업으로 처리했다. 두 순수 생산자의 키가 있다는 사실만으로 status 최종 응답에 존재한다고 추론하지 않도록, produced_object_schema(status_report)와 supervision_facts/operating_summary/observed의 수동 source-expression binding을 제거했다.

structure 검사 안에 저장소나 엔진을 기동하지 않는다. status 한 공간을 기존 실제 저장소 반환 경계에 맡기는 표식으로 두고, 명시적 defer_status에서만 구조 순회를 넘긴다. 기본 호출은 실제 report가 없으면 오류로 거부한다. unknown owner와 result=status 별칭은 여전히 검사하며, status의 기존 양성/음성 단언은 삭제하지 않고 실제 응답을 얻는 unit.test_storage_report_projections로 옮겼다.

그 unit의 기존 record_store 초기화/적재 뒤 status_report 반환에서 최상위 키와 이미 문서가 참조하던 고정 중첩 객체만 얻는다. 생산자 키들을 합쳐 결과를 재구성하지 않는다. 동일 문서 모집단을 실제 응답에 대조하며, 실제 응답 사본에서 summary/facts/OBSERVED_FIELDS/config_sha256를 하나씩 제거한 경우 해당 필드 참조가 실패한다. 실제 문서의 status와 result 별칭, summary.supervision/configured_enabled 중첩 누락도 확인한다. 관측 없음/있음의 값과 unknown observation 거부, inspection/human projection/저장 무변경 단언은 유지했다. 별도 읽기 제약 모듈은 수정하지 않았다.

지원 코드·구조 시험·기존 unit 세 파일만 변경했다. 제품 코드·새 스키마 사본·범용 추론기는 추가하지 않았다. 관련 structure17+unit5가10.0초에22개 통과했고 실행 중 변경은 없다. 원보고는 검증/2026-10-05-status-실제반환/report.json에 바이트 그대로 보존했다. human-report는 기존 실제 저장소 결과에 문서 owner 준비/반환 누락 검사를 더해0.891초로 개별0.2초 기준을 넘었으나 정확성을 낮추지 않았다.

이 성과는 현재 문서 경로와 최종 반환의 전달 확인이며 모든 상태값 의미나 선택적 블록 전체의 증명이 아니다. DOC-RETURN-PURE로 묶었던 record_map·운영요약·감독사실·status는 교체했고, 파일 I/O를 하는 trace_report.progress만 별도 한정 작업으로 남겼다. 이 마지막 경계를 처리한 뒤 같은 묶음을 계속 확장하지 않고 원래 남은 요구/통합 관문으로 이동한다. 13-C 전체 및 재편 전체는 미완료다.
