[[M-0288]]에서 웹 이용 방식과 학번을 반영한 수행계획서를 다시 첨삭했다. 멘토는 시맨틱 레이어가 무엇을 담은 결과물이며 어떤 구조로 구현되는지 직관적으로 보이지 않는다고 지적했다. 이후 사용자는 문서 전체의 설명과 흐름을 여러 차례 검토하고 첫 페이지 등의 문장을 직접 수정했다. 마지막에는 현재 작문 방식을 승인하고, ‘개념 그래프’를 ‘지식 그래프’로 통일하면서 학술 문헌 DB와 독립된 OKF 파일·Git 관리 구조로 바꾸라고 요청했다. 최종본은 [수행계획서 HWP](../../임시/작성작업/수행계획서.hwp)와 [PDF](../../임시/작성작업/수행계획서.pdf)다.

사용자는 압축으로 사라진 대화를 도구 호출·결과 등을 제외하고 복원해 읽은 뒤 수정하라고 지시했다. 복원 요청 시점까지의 원 세션 로그 `rollout-2026-09-15T05-14-36-01a0a18e-a88a-7422-89d3-9e478c8706ea.jsonl`에서 user·assistant 발화 44개를 순서대로 추출했다. 압축 전 발화 43개와 마지막 멘토 피드백 검토 1개를 합친 수치이며, user로 기록된 환경 지침도 포함한다. 도구 호출·결과, 내부 추론, 압축 대체 이력은 제외했다. 이전 작성 세션의 grill-me 공통이해 확정까지의 68개 발화도 원 로그와 대조해 읽었다. 이후 사용자가 이미 읽은 내용을 다시 읽지 말라고 지시하자, 첨삭을 맡은 에이전트는 확정된 맥락을 바탕으로 작업을 이어갔다. 새로 저장된 사용자 첨삭본을 확인할 때에는 직전 판본과 대조했다.

초기 퇴고에는 목적과 비교 대상을 흐리는 문장이 남았다. ‘학술 문서를 이해하려면’은 용어·개념을 기존 학술 개념과 비교하려는 목적을 문서 이해 일반으로 바꾸었다. ‘관련 연구와 비교하려면’은 무엇을 비교하는지 밝히지 않았다. ‘여러 문헌에서 같은 개념을 어떻게 설명하는지 찾아볼 수 있는 자료’라는 설명만으로는 의미에 따른 통합과 관계 구성, 에이전트의 활용이 드러나지 않았다. 추진배경에 활용 가능성이나 처리 절차를 먼저 쓰면 왜 이 과제를 추진하는지 설명되지 않는다는 지적도 받았다. 사용자는 이런 문장을 특정 단어나 표현의 문제로 좁히지 말고, 무엇을 전달할지 이해한 뒤 독자가 따라갈 순서로 글을 구성하라고 요구했다.

최종 설명은 논문 초안의 명칭만으로 학술 개념과의 대응을 판단하기 어려운 이유와 문헌 탐색·대조의 부담에서 시작한다. 이어 학술 문헌의 개념을 통합·정리하는 구축 기능과 그 지식으로 입력 문서를 비교하는 분석 기능을 설명한다. 구축에서는 문헌에 쓰인 개념의 의미를 대조해 같은 개념을 모으고 다른 뜻은 구분하며 관계를 연결한다. 분석에서는 입력 표현이 실제 학술 용어인지와 관계없이 그 문서에서 쓰인 뜻을 보존한 뒤 비교할 실제 학술 용어·개념을 찾는다. 산출물은 입력 문서의 용어·개념 목록, 학술 용어·개념 목록, 비교 근거와 수정 제안을 담은 분석 문서다. 일반적인 시스템은 한 학술 분야를 대상으로 하며, 이번 과제의 실제 구축 자료는 인공지능 분야다. 입력 문서도 구축된 시맨틱 레이어와 같은 분야에 속한다.

사용자가 직접 고친 여섯 문단에서는 표현의 성립 범위와 문장 내부의 묶음이 함께 달라졌다. ‘문헌마다’ 차이가 난다는 서술은 ‘서로 다른 문헌에서는’ 그런 차이가 생길 수 있다는 표현으로 바뀌었다. 배경의 보호 대상은 ‘작성자가 사용한 뜻’에서 ‘작성자의 의도’로 바뀌었고, 개념마다 조사를 반복해야 한다는 고정 단위는 문헌 탐색·비교의 부담으로 정리되었다. 구축 대상은 ‘기존 문헌’의 ‘학술적으로 사용되는 개념과 그 의미’로 명시되었다. 사용자는 ‘정리한 뒤,’와 ‘올리면,’의 쉼표를 덜고 ‘같은 분야에 속하는,’에는 쉼표를 두어 긴 수식 관계를 구분했다. 후속 퇴고에서는 쉼표를 일괄 제거하지 않고, 긴밀한 구문을 끊는 곳과 대조·나열·수식 범위를 구분하는 곳을 가려 적용했다.

멘토 피드백을 처음 반영할 때에는 상하위·부분전체 등의 관계 유형을 반복해서 제시했다. 사용자가 세부사항의 실익을 평가하라고 요청한 뒤, 현재 비교 기능을 이해시키는 데 기여가 작은 유형 열거를 덜었다. 학술 개념을 노드로 두고 관계의 뜻과 판단 근거를 기록한다는 설명은 유지했다. 문헌별 의미·적용 조건·근거는 실제 비교에 필요하므로 추출과 분석 절에 남겼다. 구체적인 노드 종류와 관계 유형은 이번 계획서에서 새로 확정하지 않았다. [Graft](https://github.com/trailhq/Graft)는 개념의 설명·관계·출처를 연결하고 에이전트가 탐색하게 하는 구성의 참고 사례로 사용했다.

저장 구조의 초기안은 SQLite에 문헌·개념·관계·작업 상태를 저장하고 그 기록으로 OKF 문서를 생성하는 방식이었다. 사용자의 마지막 지시로 이 연결을 없앴다. 최종안의 문헌 DB는 서지 정보, 원문 확보 경로, 선정·수집 상태를 관리한다. 지식 그래프는 설명과 문헌별 근거·출처·개념 간 링크를 담은 Markdown 파일로 직접 구성하고 Git으로 버전을 관리한다. 에이전트는 이 파일과 목차·검색 색인을 읽어 DB 조회 없이 탐색한다. [Google OKF v0.2](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md)는 파일의 메타데이터와 링크를 표현하는 형식으로 사용한다. 문헌 원문과 그래프의 연결은 유지하며, 문헌 DB와 그래프를 동기화하는 구조는 두지 않는다.

이 변경은 구현 기술 문단에만 적용하지 않았다. 작업·검토 에이전트가 개념을 확인하는 자료는 기존 지식 그래프로 바꿨다. 구축 프로그램은 검토를 통과한 변경안을 최신 지식 그래프와 대조한 뒤 순서대로 반영하도록 했다. 중단 후 재개에 필요한 진행 단계와 반영 결과도 해당 그래프 버전과 함께 기록하도록 했다. 개념 파일과 목차·색인을 갱신하고 변경을 Git 커밋으로 기록한다. 평가와 배포에서는 문헌 자료의 범위와 지식 그래프의 Git 버전을 각각 보존한다. 이전의 ‘DB 버전’, ‘DB에서 그래프 생성’, ‘DB와 시맨틱 레이어 갱신’ 설명은 관련 표와 일정·완료 기준까지 수정했다. 사용자가 고친 여섯 문단 가운데 다섯 문단은 그대로 유지했고, 나머지 한 문단에는 ‘지식 그래프’ 명칭만 적용했다. 웹 이용 방식, 평가 수량·방법, 일정·예산 수치와 인력 정보, 팀원 학번 ***REMOVED***는 유지했다.

독립 독해는 원고가 무엇을 전달했는지 확인하는 자료로 사용했다. 앞선 판본에서도 독해자가 기능을 요약했지만, 사용자는 그 뒤에 목적의 변질과 어색한 연결을 찾아냈다. 따라서 요약이 가능하다는 사실만으로 사용자의 의도나 작문 품질을 충족했다고 판단할 수 없었다. 최종 독해에서는 문헌 DB와 파일 기반 그래프의 역할, Git 기준의 변경 처리, 입력 의미 보존과 세 산출물이 원고 근거로 전달되었다. 독해자가 제기한 쟁점은 분야의 범위, 문헌 수, 관계 규칙, 장비 배치, 평가 영역, 일정이었다. 지적마다 원고의 해당 설명을 확인하고 확정된 사용자 의도와 대조했다. 일반 구조와 인공지능 적용의 구분을 유지하고, 아직 선정하지 않은 수량이나 세부 설계를 임의로 추가하지 않은 이유를 독해 대조 기록에 남겼다.

최종 HWP를 한글에서 저장한 뒤 다시 열어 추출한 본문이 원고와 일치함을 확인했다. 최상위 본문·표 블록은 110개이며, 텍스트가 있는 365개 문단을 PDF와 대조해 누락이 없음을 확인했다. PDF 11쪽의 이미지 전체를 읽어 표·일정표·인력표와 참고문헌의 배치를 확인했고, 페이지 밖으로 밀린 글자도 없었다. 사용자 기준본의 글자·문단 서식 정의를 유지했다. 표의 셀 안 줄바꿈을 텍스트로 펼칠 때 생긴 해석 문제는 실제 HWP·PDF와 대조했으며, 이 경험은 [[L-0004]]의 추출·렌더링 결과 판독 원칙과 함께 참고할 수 있다. 완료한 작업은 계획서의 첨삭과 검증이다. 계획에 적힌 시스템 구현과 성능 실험은 이번 작업에서 실행하지 않았다.

대화 추출물, 각 단계의 기준본과 수정본, 편집 스크립트, 독해·검증 자료는 `임시/보관/수행계획서_2026-09-15/작성작업/` 아래에 단계별로 보존했다. 원 대화 복원은 `멘토피드백_20260915/`, 사용자 직접 첨삭의 차이와 후속 퇴고는 `사용자첨삭_20260915/`, 마지막 구조 변경과 최종 검증은 `지식그래프분리_20260915/`에서 확인할 수 있다. 앞선 grill-me 추출물은 `전문첨삭_20260915/`에 있다. 보관 폴더에는 기존 Git 제외 규칙이 적용되며, `임시/작성작업/`에는 최종 HWP와 PDF만 남겼다. 초기 메모리 초안도 보관하고 이 노드를 최종 작업 내용으로 다시 작성했다.
