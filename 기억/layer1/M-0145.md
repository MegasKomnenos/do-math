g02가 전수 수집을 두 고정 흐름으로 재개한 뒤, 그 실행 코드와 실물 수리의 시험·판정 데이터를 중간 보존한다. 루트는 명시 73개 파일의 SHA와 두 실행이 시작 때 기록한 52개 파일의 SHA를 현재 디스크에서 다시 계산해 불일치 0을 확인했다. 실행 중 계속 바뀌는 진행 manifest는 이 커밋의 고정 입력으로 삼지 않고 operator-checks에 시점이 붙은 별도 사본을 만들었다. 수집기 113개 회귀와 별도 운영 집계기 3개 회귀의 로그, 전수 5138건의 분할 시험, 두 실제 pilot의 기록을 포함한다. 각 후보의 최종 결과와 원문 전건은 이 코드 단위에 포함하지 않는다.

분할은 원래 입력 위치의 나머지로 정하며 실행 도중 결과 수나 완료 여부에 따라 소유자가 바뀌지 않는다. 두 프로세스는 서로 다른 문헌 ID만 쓰고 독립 브라우저 context·진행 파일·PID·시작 manifest를 갖는다. 공용 증거는 내용 주소와 고유 임시파일을 사용한다. 나중에 추가한 snapshot_progress.py는 두 진행 파일의 전체 수를 더하지 않고 실제 고유 결과 ID를 한 번 집계하는 별도 운영 도구다. 이 파일은 기존 두 프로세스가 수입하지 않으며 이 구분을 체크포인트 기록에도 남겼다.

두 pilot은 서로 다른 신규 2건씩을 처리했고, 두 결과의 부분검사와 실제 인증 표시를 확인했다. 429는 관측되지 않았다. 처음 한 흐름에서 집계한 5xx3건은 리소스 종류가 없어 원인을 추정하지 않았고, 생산 판본에는 호스트·경로·종류 계측을 추가했다. 이후 두 생산 흐름의 5xx는 hdl.handle.net의 개별 문서 요청으로 확인됐다. 작업자가 읽은 본문은 특정 handle을 찾을 수 없다는 안내였고 수집기는 그 링크만 link_not_found로 기록했다. 현재 관측을 Summon 요청 제한이나 해당 문헌 전체의 부재로 확대하지 않는다. 처리 자료와 출처 수가 다른 pilot의 시간만으로 병행의 인과적 속도 개선을 주장하지 않는다.

전자자료 제공 경로 없음과 접근 제한의 구별은 실제 Ross1987 사례로 수리했다. 두 resolver의 제공 경로 없음 안내는 no_resource로 재분류하고 unavailable 판정식에서 제외했다. 보존된 대응 Summon 문서의 CiNii URI를 복구해 정상 UI에서 제목·저자·출판사·연도와 종이책 소장관 정보를 확인했다. 저장 888건의 완료 결과까지 다시 검사하여 259개 관측의 분류를 정정했다. 이후 작업자가 MR 서평·대응 응답의 빈 초록·CiNii와 공개 보완검색을 직접 읽고 두 구성요소의 한정범위 not_found 결정을 별도 파일로 준비했다. 이 추가 음성 결정과 이후 혼합 출처 판정 helper는 아직 본 생산 코드에 연결되지 않아 이 코드 단위에 포함하지 않는다.

selected_summary.py는 DB가 선택한 인용의 실제 경계를 찾고, 작업자가 직접 판독한 문헌 ID·원자료 SHA·인용 SHA가 모두 맞는 결정만 적용한다. 코드가 사용하는 selected-summary-decisions.json도 실행 판본의 일부로 해시를 기록한다. Gradient flows의 훼손 Summon 문구를 복원한 것이 아니라, 실제 MathSciNet의 정상 TeX와 완결된 두 문단 인용을 새 출처로 채택했다. CRC handbook의 인용 뒤 Contents와 검토 안내는 인용 바깥으로 구별한다. 일반 서평자의 평가나 임의로 자른 원문 서론을 새 초록으로 만들지 않는다. 루트가 직접 확인한 Ciarlet의 215쪽 DOI article도 출판사 범위·원문 구조와 결박해 채택됐다.

g05의 초록 267건이 264건으로 바뀐 것을 루트가 확인하고 이유를 대조했다. 세 건은 각각 경쟁비·매개변수 공간, 지수와 그래프 곱, 복잡도 부류 첨자가 평문에서 모호하여 실제 형식 출처의 대조를 다시 연 경우였다. 실제 결과의 abstract_source_history, abstract.candidate_artifacts, candidate_review 사유와 열린 작업을 확인했다. 정상 값을 단순 접근 실패로 덮은 상황은 아니며 원시 자료를 보존한 품질 재판정이었다.

g05는 정상 ScienceDirect 상세의 본문이 충분히 로드된 경우 전문 HTML을 MathML·그림과 함께 보존하는 경로를 시험 중이다. g08의 Tolksdorf 상세는 실제로 View PDF 다음에 References만 있고 본문 절이 없었으므로 같은 표시만으로 전문 HTML로 세지 않았다. 정상 PDF 링크의 request.get·직접 이동·실제 클릭과 브라우저 후속 다운로드는 서로 다른 관측으로 기록한다. 이 시점에 g05의 전문 HTML 수집 성공을 확정한 것은 아니다.

루트는 g08의 이미 관측한 MathSciNet6건에 한정해 기존 Chrome 순회와 별도 DOM 읽기 흐름을 허용했다. 별도 PID·코드·대상 목록을 남기고 원자료와 인덱스만 쓰며 결과 작성자는 겹치지 않게 분리한다. 이 작은 읽기가 끝나면 해당 브라우저를 닫는다. 일반 전수 병행의 추가 허용이나 모델 증설로 확대하지 않는다. 전체 6,101건의 작업은 계속 진행 중이며 나머지 네 디렉토리의 전담 작업자는 슬롯이 열리면 파견한다.
