[[M-0511]] 뒤 task_new_input의 실제 생산과 소비를 연결했다. 공개 source 등록으로 파일을 보존하고 실제 준비 후보가 source:plan-input.txt를 입력으로 선언한다. 계약 검토와 계획을 실제 모델/worker로 수락한 뒤, 계획은 미래 재방문을 가진 not_selected 처분을 남겨 현재 작업을 선택하지 않는다. 전체 초기 역할 호출은 준비1·계약검토1·계획1이다.

같은 source 바이트를 다시 공개 등록하고 owner를 진행해도 사건 수와 실제 모델/worker 호출 전건은 불변이다. 실제 파일을 다른 바이트로 바꾸고 source 요청을 수신하면 과제의 newinput은 정확한 요청 ID를 가리킨다. 실제 재계약 검토가 실행되고 정착 기한을 지난 뒤 계획이1회 추가된다. 추가 호출은 계약검토1·계획1뿐이다. task_new_input 사건은 정확한 과제 ID/요청 ID를 가지며, 이를 포함한 계획 execution의 action.event_refs와 output_accepted를 확인한다. 수락 뒤 pending_events와 과제 newinput에서 소비되고 같은 두 번째 바이트를 다시 등록한 뒤3순회에도 호출이 늘지 않는다. 실제 Repository 저장본과 런타임은 일치한다.

초기 준비/계약/계획을 실제 생산 경로로 만들었고, newinput이나 사건을 시험이 직접 삽입하지 않았다. 제품 코드는 변경하지 않았다. 기존 초기화·정상 점유·빈 준비·기한 재방문·주기 재고의 호출 검사도 유지한다. 직접1개가25.3초에 통과했고, 구조4·관련flows7 총11개가100.3초에 통과했다. 실행 중 소스 변경은 없다. 새 검사 본문은 단독17.078초, 관련 병렬21.5초였다. 원보고는 검증/2026-10-05-새-입력-발동/에 추적하며 report.json SHA256은 d9d46a7ad9a077905e0d052a0815b9ab03ff03a05b2df86fdb413f6b08816f75다.

B94/B95는 collect_due_events의 재방문·주기·새입력 원천을 실제 owner 호출에 연결했다. 이것을 모든 직접 계획 발동 완료로 표시하지 않는다. 형식 결과, 검토 결과, 지식 변경, 개정 의존성, 평가 변경, 외부 반려, 입력 초과, 수락 산출에서 여는 계획은 기존 실제 시나리오와 연결할 남김이다. 그 밖의 최종 전체 일반/T3/변이/실환경/문서 관문도 유지한다.
