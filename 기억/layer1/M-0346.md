## 맥락

사용자는 새 do-math 인스턴스에서 모든 자연수에 대한 오른쪽 영항등원을 증명하되 모델 상한을 gpt-6-sol로 정했다. 이어 초기화 전 과정을 실제 하위 계층까지 검토하도록 했고, 발견한 문제를 수리하는 동안 원 인스턴스는 대기시키라고 지시했다. 수리의 영향 영역 전체를 다루고, 구체화했을 때 이익이 없는 구현은 버리며, 기존 전제가 틀리면 방향을 수정하라는 기준을 함께 줬다.

초기 운전은 입력 보존·환경 채택·독립 의도 검사와 인계까지 갔지만, 인계 뒤 작업 프로필 불일치와 과거 시도에 대한 운영 retry 충돌로 설치 수리 대기에 들어갔다. 초기화 검토는 14개 항목을 분리했다. 모델 호출을 더 하며 증명을 밀어붙이는 대신 사용자 지시에 따라 HOLD·pause·quiescence를 공개 제어로 적용했다. 원 기록의 구형 manifest를 현재 설치에 맞춰 변환하지 않았다. [[M-0341]]의 초기화 관측·정비 경계와 [[M-0345]]의 현행 소비 계약 정렬을 실제 사례에서 다시 대조한 작업이다.

## 수리 과정에서 수정한 판단

신뢰 manifest에 여섯 파일 역할이 있고 `verified`라는 문자열이 있다는 사실은 전체 설치와 실제 검증 증거의 결박이 아니었다. 채택한 root의 파일 전건을 준비·활성화·형식 사용에서 같은 규칙으로 관측하고, 전후 toolchain과 실제 소스·명령·출력·종료 코드·inventory 해시를 가진 검증 record를 사용하도록 바꿨다. 완전성은 역할 라벨 수가 아니라 선언한 모집단과 실제 파일의 대응으로 판정해야 했다. 해시 기록이 같은 사용자 권한의 악의적 조작까지 막는 외부 인증이라는 뜻은 아니다.

작업의 준비 상태와 실제 배정은 같은 모델 요구를 사용해야 한다. 후보 수신과 평가 보충 단계, 준비 상태 갱신, 최종 배정 사이에서 선택 규칙이 달라지면 독립 계약 검토를 통과해도 착수하지 못한다. 공통 선택 규칙을 연결하고 정확한 프로필을 조회하는 공개 명령을 제공했다. 초기화에서는 전체 사용자 요청과 짧은 수학 목표를 나눠 보존하고, 활성화 직후 반환하는 경계를 추가했다.

과거 시도에 이미 후속이 있다는 이유로 retry·resume·repair를 모두 소급 해소하려던 수리안은 철회했다. 같은 활동의 명시적 continuation은 중복 재시도를 막는 근거다. 설치 결함은 별도의 수리 의무이므로 후속 연구가 성공했더라도 자동으로 해결됐다고 할 수 없다. 수리 완료 뒤에는 기존 후속을 유지하고 새 시도를 또 만들지 않는다. 활동의 실행 계보와 설치 결함의 효력은 서로 다른 소유 범위였다.

계측 오류를 더 기록하는 데서 끝내려던 범위도 실제 실패를 보고 넓혔다. 검사 자체는 통과했지만 Windows에서 최종 JSON 보고서를 교체하다 WinError 5가 발생했다. 삭제 공유를 허용한 reader만으로는 기존 이름 교체가 성공하지 않았다. 실제 파일 핸들로 재현하고 `FileRenameInfoEx`의 POSIX 교체 의미를 공통 경로에 적용했다. 가변 파일명 버퍼의 끝 문자 공간을 빠뜨린 첫 구현도 실제 교체 검사에서 고쳤고, 긴 경로·유니코드 이름·반복 교체까지 검사했다. 제어·감독·관찰·계측·시험 보고 파일까지 적용했다. Git과 입력의 물리 경계 검사는 허용 root 안의 경로, 열린 파일의 실제 대상, reparse 경로 치환을 확인하는 기존 검사이며 이를 유지했다. 재시도는 같은 파일명 교체에만 제한하고 연구나 제어 효과를 반복하지 않는다.

실제 환경 등록 시험의 실패 중 하나는 제품 결함이 아니었다. 드라이버가 운영 실행 횟수를 모델 호출 횟수로 가정했다. 저장된 단 하나의 실행이 `actor_kind=machine`인 `trust_activate`였으므로 전체 파일 관측과 활성화는 성공했고 모델 호출은 없었다. 원 assert 실패를 삭제하지 않고 전건 실행 기록으로 해석을 정정했다. 테스트 성공·명령 종료·모델 호출·수학적 성공을 서로 다른 근거로 세야 한다.

## 실익과 검증의 경계

공통 역할 문서를 광범위하게 줄이는 안과 이해를 보증한다는 읽기 영수증 체계는 채택하지 않았다. 실제로 반복되는 37개 프로필의 직접 입력만 60,381바이트에서 12,529바이트로 줄이고 전문 판본을 보존했다. 1,043파일 export도 바이트 동일성을 확인하면서 17개 blob 묶음, 총 19번의 Git 호출로 처리했다. 이 수치는 전체 모델 요금이나 전후 시간 배율이 아니다.

실제 설치 관측은 137,271파일·10,463,602,438바이트의 활성화 영수증을 남겼다. 그 증거는 관측 당시 판본에만 대응하며 이후 검사기 파일 변경까지 덮지 않는다. 별도의 실제 Lean 검사에서는 정확한 선언 이름과 `True.intro` 의존성, 실행기의 형식 결과 수락을 확인했다. 컴파일 뒤 시험용 검사기 사본을 바꾸거나 승인 환경 출처를 바꾸면 그 형식 결과를 수락하지 않는 것도 확인했다. 통합 검사에는 실제 Git 저장소와 합성 모델 응답을 쓴 경우가 있고, 실제 컴파일러 검사에도 승인·저장을 대역으로 치환한 경우가 있으므로 각 시험의 실제 경계를 구분했다. 넓은 고정 사본 회귀와 뒤의 변경 영역 재검사는 테스트 ID별 판본 근거로 합치며, 반복 실행 횟수를 서로 다른 검사 수로 세지 않는다.

문서 수정에는 `write-for-reader`의 새 독해 세션을 사용했다. 독해 모델은 gpt-6-sol 또는 gpt-5.6-sol로 제한했다. 잘못된 행 인용으로 거부된 독해 응답은 고쳐 적거나 성공으로 취급하지 않았다. 원 입력·출력과 실패를 남기고 새 독해를 수행했다. 소스의 전문을 얻지 못한 잘린 도구 출력도 읽기 완료 근거가 아니다.

사용자가 background terminal이 많은 이유를 물었다. 긴 통합 검사를 분할한 뒤 문서 독해와 실패 재현을 추가하고 종료된 세션을 늦게 회수한 것이 원인이었다. 완료된 14개 세션의 종료 결과를 회수하고 중복 검사와 멈춘 진단을 종료했다. 이후 이 세션의 장기 작업을 동시에 네 개 이내로 제한했다. 묶음 전체가 끝날 때까지 실패 상세를 얻을 수 없어 진단용 재실행을 추가했던 문제도 확인했다. 시험 실행기는 이제 실패가 발생하면 `failures/`에 해당 검사 ID·오류·완료되지 않은 진단이라는 표지를 즉시 게시한다. 다음 검사가 진행 중일 때 앞선 실패를 읽을 수 있는지 별도로 검사했으며, 이 기록을 전체 묶음의 완료 보고서로 취급하지 않는다.

## 보존 좌표

사용자는 실행 지연이 자원 소비와 throttling 때문일 수 있음을 지적하고 정적 성능 검토로 방향을 바꾼 뒤, 추가 작업을 끝내고 커밋하도록 요청했다. 진행 중인 검사와 진단을 다시 시작하지 않고 미완료 상태를 보존한다. 순차 재현은 11단계에서 시험용 K를 만들었지만 동시 배정 재현은 결론에 도달하기 전에 중단됐다. 이를 무한 대기나 동시 실행 결함으로 확정하지 않는다. 입력 초과 시험의 전역 호출 수 가정은 해당 검토와 영수증만 검사하도록 수정했으나 최종 재검사는 끝나지 않았다. 전체 통합 검증과 성능 원인 확정은 이번 커밋의 미완료 항목이다. 정적 검토에서 확인한 반복 상태 복사·누적 증거 재검사·일괄 읽기·설치 해시 관측·물리 경계 검사 후보는 동명 결과 JSON에 남겼으며 성능 수리는 구현하지 않았다.

추적되는 진입점은 `docs/do-math/initialization-repairs-20260925.md`와 같은 이름의 JSON이다. 최종 검사 결과·판본·원 보고서 해시, 정본 코드·테스트·절차 문서, 생성 미러와 이 기억을 같은 커밋에 보존한다. 대용량 상세 증거는 Git 제외 경로 `.skill-workspace/initialization-fixes`와 `.codex/writing-flow`에 남는다. 최초 상세 검토는 `.skill-workspace/initialization-review-20260925/review.md`에 있다. graphify의 자동 갱신은 수행하지 않았다.

원 연구 `RI-01M3BXA1GTK78NEXX9DAW13H67`의 머리는 `e55d890e580c5a9c0a75814be84e3c31972b5150`이다. HOLD `64ff6a79123b455893bd852bf2d65529`, 사용자 pause와 정비 fence를 유지한다. 현재 설치에서 임의 재개하거나 구형 기록을 자동 변환할 근거로 이 수리의 통과를 사용하지 않는다. 원 수학 목표의 해결은 아직 남아 있다.

후속 기억 종합 절차인 dream에서 묶을 후보는 성공 표지와 책임 범위의 분리다. 파일 역할 목록, 후속 실행 성공, 운영 실행 카운터, 명령 종료 코드가 각각 더 넓은 완전성·결함 해소·모델 호출·수학 성공을 대신하지 못했다. 관측한 값이 무엇의 증거인지를 소비자마다 같은 의미로 유지하는 일이 공통 과제였다.
