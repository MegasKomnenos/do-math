## 맥락

사용자가 `/do-math`로 요청한 것은 `Parking.root_unimodal`에 대해 다음을 한 폴더에 모으는 일이었다. 컴파일에 필요한 최소 Lean 라이브러리의 추출과 단순화, `paper.py`로 쓴 영어 논문, 의존성 지도, 이 인스턴스와 그 앞 인스턴스의 지식 폴더 압축, 그리고 README에 해결한 문제로 한 줄. 작업 중에 연구의 역사를 원자료에서 쓰라는 것, Lean·Mathlib 4.36으로 올리라는 것, 버전 고정과 빌드 명령과 기대 공리 출력을 넣으라는 것이 더해졌다.

이 커밋은 사용자가 "지금 있는 것을 커밋하고 푸시"하라고 한 시점의 상태다. 논문은 사용자가 띄운 운전이 계획 단계에 있어 폴더에 없고, 다섯 문서의 퇴고를 맡은 오케스트레이터는 아직 문서를 고치지 않았다. 폴더 README의 「The paper」 절은 그래서 예고문으로 남아 있다.

## 폴더에 든 것과 그 검증

- **`lean/`.** 모듈 61개, 약 21,400줄, 공개 선언 399개, 커널 평가 38개. 출발점은 뒤 인스턴스가 낸 114개 모듈, 28,051줄, 공개 선언 약 1,500개, 커널 평가 61개였다. `Parking/Defs.lean`은 원본과 바이트가 같다(SHA-256 앞자리 `7a5ebd0e6a69a06bf510`). 확인한 것: 빈 폴더에서의 전체 컴파일(오류와 자체 경고 없음), `lake build`와 `lake env lean Check.lean`(공리 `propext`, `Classical.choice`, `Quot.sound`), 넷째 세대 `init`의 외부 판정(`leanexport`와 `lake comparator`) 수락. Windows에서는 비교기의 샌드박스가 꺼진다. Mathlib을 네트워크에서 받는 경로는 돌려 보지 않았고 `lean/README.md`가 그렇게 적는다.
- **`records/`.** 기록 400개(공개 선언 399개와 제기된 정리)와 기록이 인용하는 12편의 서지. 여덟 작성자가 Lean 증명을 따라 썼다. 독립 대조는 counting, series-tilt, top-level, crossing 묶음에 있었고 나머지 묶음은 작성자 자신의 확인뿐이다.
- **`dependency-map/`.** 포장한 인스턴스에서 `depmap.py`로 그렸다. 단위 173개, 선 916개, 묶음 12개.
- **`history/`.** `timeline.md`(약 41,700단어), `SOURCES.md`, 인용한 원자료 131개. 앞 인스턴스에 관한 53개 대목은 대조자가 안전장치로 두 번 멈춰 대조되지 않았고 9절이 그렇게 적는다.
- **`knowledge/`.** 뒤 인스턴스의 `knowledge/`를 커밋에서 뽑은 보관 파일(68 MB)과 `MANIFEST.md`. 보관 파일은 일반 Git 파일이다(`.gitattributes`에서 이진 파일로 지정). 앞 인스턴스의 보관 파일(349 MB)은 만들어 두었지만 저장소에 싣지 않는다. 처음에는 사용자 지시로 둘을 Git LFS에 두었는데, 푸시를 GitHub가 저장소의 LFS 예산 초과로 거부했다. 사용자가 큰 쪽을 `.gitignore`에 넣으라고 했고, 68 MB 쪽도 LFS로는 같은 거부를 받아 일반 Git 파일로 두라고 했다. 이 파일은 저장소 이력에 68 MB로 남는다. 그 파일은 이 기계의 같은 폴더에 남아 있고 `MANIFEST.md`가 설명과 체크섬을 싣는다. 그래서 역사에서 앞 인스턴스의 보관 파일로 이어지는 좌표는 그 파일을 가진 독자만 열 수 있으며, `SOURCES.md`와 `timeline.md`가 그렇게 적는다.

포장한 인스턴스는 `.skill-workspace/parking-unimodality-solved`이고 root 상태는 `formal_proved`다. 끝난 root를 첫 커밋과 대조하는 판정(`judge.py`)은 돌리지 않았다(`root_judge: null`).

## 단순화의 경로와 결정

일곱 작업자가 묶음별로 단순화했고(각자 사본에서, 다른 묶음이 기대는 이름과 진술은 고정), 구조 검토자가 묶음을 가로지르는 11건을 냈으며, 병합 뒤 한 작업자가 라이브러리 전체를 읽고 주제별 배치로 다시 짰다. 내가 정한 것은 다음이다. 사용자에게 알렸고 반대가 없었다.

- 다음 열 진술(Mono)은 k ≥ 9로 좁혔다. 사슬 열 진술(C)은 표 검사기가 2~8열을 추가 비용 없이 훑으므로 k ≥ 2로 남았다. 16행 이하는 표 하나로 본다.
- 표의 "줄인" 검사를 완전한 검사로 바꿨다. 같은 빌드에서 잰 짝 비교로 커널 시간이 늘지 않음을 확인했다.
- 첫 층 부등식은 k ≥ 7에서 핵 경로 하나로 낸다. 쓰는 쪽이 k ≥ 7에서만 쓰므로 나무 정규화 경로와 접합부 크기 두 개를 지웠다.
- 공개 선언을 399개까지 줄인 것은 논문 명령의 자료 크기 때문이기도 하다. 요소 1,505개와 자리표시 기록만으로 자료가 1.07 MB였다.
- 대소문자만 다른 이름 일곱 묶음은 `init`이 거부하므로 서로 다른 이름을 주었다.

## 도중에 틀렸던 것과 고친 것

- 처음의 기계적 가지치기가 root 증명이 쓰지 않는 정의 `IsParkingFunction`을 `Defs.lean`에서 지웠다. 병합본을 확인하다 체크섬 차이로 찾아 원본으로 되돌렸다. `simp`가 쓰지만 증명항에 나타나지 않는 `rfl` 보조정리(`dn_tail`)와 `local notation`도 같은 도구가 지웠었다.
- import 정리에서 "같은 파일의 다른 import가 이미 가져온다"는 이유로 72줄을 지웠다가 빈 폴더 빌드가 다섯 모듈에서 실패했다. Mathlib 4.36의 파일은 거의 모두 모듈 체계를 쓰고, 그 안의 일반 `import`는 가져가는 쪽에 전달되지 않으며 `public import`만 전달된다. 전달되는 것만 따라 다시 했고(22개 모듈 51줄), `Defs.lean`은 대상에서 뺐다.
- 병합에서 같은 이름의 보조정리가 두 파일에 있던 것이 둘(`A_eq_pow`, `dq_nonneg_iff`) 있었다. 두 작업자에게 같은 것을 허락한 내 지시에서 나왔다.
- Claude Code의 저메모리 보호가 내 배경 명령을 네 번 멈췄다(`lake build`와 `init`을 함께 돌렸을 때, `init` 단독의 판정 단계, `paper.py`). 판정 단계에서 멈춘 운전은 "Lean default kernel rejected the solution"을 남겼는데 선언 이름도 이유도 없었고, 메모리가 충분한 재운전에서 수락됐다. 재운전은 `init`을 그대로 부르되 멈춘 운전의 컴파일 캐시를 먼저 복사하는 스크립트(`scripts/init_reuse.py`)로 했다. 캐시 키가 인스턴스 경로를 담지 않아 같은 입력에만 맞는다.
- 메모리를 쓰던 것은 돌고 있는 해바라기 인스턴스였다. 그 인스턴스의 새 파견을 `stop`으로 멈췄다가 사용자가 되돌리라고 해 `resume`했다. 다른 연구를 멈추는 것은 선택지가 아니다.
- 폴더 README 초안에 정의 파일이 "연구 전에 사용자와 고정"됐고 사용자가 읽기를 "확인"했다고 썼다. 근거가 없었다. 뒤 인스턴스는 root를 말로 고정했고 Lean 정의는 연구의 형식화에서 나왔다. 지금 문장은 정의 파일이 발표된 형식 증명의 것과 바이트가 같다는 것과, 추측과의 대응은 검토 세션이 판단했다는 것만 말한다.

## 두 인스턴스의 관계

내가 처음에 "뒤 인스턴스가 앞 인스턴스에 기반한다"고 말한 것은 원자료와 달랐다. 앞 인스턴스(11월 5~13일, 11일에 비형식 증명)에서 원고가 나왔고, 원고에서 구조 문서와 보고서 다섯, 그리고 논문 하나가 나왔으며, 뒤 인스턴스(19일 시작, 23일 형식 증명)의 씨앗은 그 논문을 자른 것이다. 뒤 인스턴스의 입력과 기록은 앞 인스턴스를 이름으로 가리키지 않는다. 두 운전 모두 결과를 검토된 기록과 노드로 두던 이전 세대 실행기로 돌았다. 그래서 저장소 README의 「Solved problems」 줄은 그 사실을 한 문장으로 적는다. 같은 README의 도입부가 "지금까지 작은 진술 하나를 실제 세션으로 형식 증명까지 가져갔다"고 말하기 때문이다.

## 커밋 전 확인

- `solved/`와 README에서 Windows 계정 이름, 전자우편 주소 꼴, 자격 증명 꼴의 문자열을 찾았고 없었다. 역사의 원자료 사본 열 개에서는 계정 이름이 `<account>`로 바뀌어 있다(작업자의 결정, `SOURCES.md`에 적힘).
- `Defs.lean`이 체크아웃에서도 같은 바이트이도록 `.gitattributes`에 LF 고정 한 줄을 넣었다. 이 저장소는 `core.autocrlf=true`다.

## 남은 일

논문 운전이 끝나면 `paper/`를 채우고 폴더 README의 논문 절과 저장소 README 줄을 고친다. 문서 퇴고와 지도 사용 시험의 결과를 받아 반영한다([[M-0766]]). 작업 폴더 `.skill-workspace/parking-root-paper/`(분석 문서, 작업자 보고, 역사 작업 파일, 스크립트)는 버전 관리에서 제외되어 있어 정리로 사라질 수 있다. 추적되는 진입점은 이 폴더의 두 README, `history/timeline.md` 9절, `knowledge/MANIFEST.md`다.

## 사용자 교정(dream 후보)

작업자에게 같은 전체 빌드를 각자 시킨 것과 그것을 막는 장치를 넣으려던 것은 [[M-0764]]에 적었다. 이 커밋의 범위에서 더할 것은 하나다. ⓐ `init`이 판정 단계에서 죽은 뒤 나는 한 시간짜리 `init`을 처음부터 다시 돌리는 선택지들을 냈다. ⓑ 사용자는 이미 한 것을 건너뛸 수 없느냐고 물었다. ⓒ 컴파일 결과가 내용 주소 캐시로 디스크에 남아 있다는 것을 알면서 재사용을 선택지에 넣지 않았다. ⓓ 긴 단계를 다시 돌리기 전에 앞 운전이 남긴 산출물 가운데 다시 쓸 수 있는 것을 먼저 센다.
