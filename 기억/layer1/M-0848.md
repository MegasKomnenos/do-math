## 맥락

돌고 있는 연구에 지금 전달되는 사용자 입력은 넷이다(1, 2, 6, 7. 3·4·5는 가이드에 담긴 뒤 사용자가 2026-11-27 15:24에 거두게 했다). 사용자가 지시했다: 「dispatch an agent that will check all current user inputs and figure out a way to apply it(if at all) to current directives in a way that is seamless, robust, style coherent, does not cause conflicts or contradictions, does not create duplicates or bloat, written such that actual effect when read by the worker sessions with different context would be as intended without unwanted deviance or lack of effect」. 에이전트 하나(`gp-fable-high`)가 입력마다 판정하고 가이드의 사본에 글을 썼고, 운전 세션이 차이와 보고를 읽고 설치했다.

## 결과

- **입력 1(폴링 같은 일에 처리기 시간과 메모리를 낭비하지 말라): 담겨 있다.** `reference/tools.md` 31행의 「You should not waste processor time or memory on things like polling.」이 라운드 6부터 서 있고 여섯 역할이 모두 받는다. 운영자의 측정값과 인스턴스의 설정 변경은 담지 않는다.
- **입력 2(`wait` 명령을 고쳤다는 보고): 담지 않는다.** 세션에게 요구하는 것이 없는 도구 변경의 보고다.
- **입력 6: 담는다.** `roles/peer.md` 19행 문단 끝에 두 문장. 생산 세션의 `input.json`의 `task.continues`가 폴더를 들면 그 과제는 그 세션들을 먼저 거쳤다는 것(review 가이드 53행과 같은 문면), 그리고 그 폴더마다 보고서와 `output/`의 나머지도 읽는다는 것. `continues`가 없으면 두 문장은 아무것도 요구하지 않는다. 앞 세션들의 대화는 사용자의 말에 없어 건드리지 않았다.
- **입력 7: 담는다.** `reference/common.md` 257행의 「If you are about to revisit an approach, …」를 시도마다의 읽기로 넓혔다(「as far as you have not read it yet」으로 되읽기를 빼고, 사용자가 준 목적 「what to avoid … a way through」를 지닌다). 같은 문서 73행의 「One reading of the canon is asked of you more definitely」를 둘로 고쳐 두 자리가 어긋나지 않게 했다. 문헌은 넣지 않았다(사용자의 말에 없다).
- 계기가 된 탐구는 가이드의 세 문장(다시 가려 할 때, 진술을 맡을 때, 질문의 대상 전부)을 모두 받고도 먼저 시도했다. 세 문장 어느 것도 「길 하나를 시도하려는 때」에 걸리지 않았다는 것이 에이전트의 읽기다.

## 확인된 것과 확인되지 않은 것

- 가이드는 세션이 뜰 때 디스크에서 읽히므로 설치 뒤에 뜨는 세션부터 읽는다. 프로그램과 시험은 바뀌지 않았다. 고친 문장을 단언하는 시험은 없다(찾아서 확인).
- 새 글을 읽은 세션은 아직 없다. 효과는 확인되지 않았다. 입력 6을 입력으로 받은 peer 둘은 앞 보고서를 마지막 보고서와 견주어 읽어 값을 스스로 줄였다(에이전트의 관찰).
- 입력 파일은 건드리지 않았다. 거둘지는 사용자가 정한다. 입력 7을 남겨 두면 그 운영자 글의 한 문장이 가이드보다 좁게 적은 말이 된다. 입력 2는 입력 1의 낡은 대목을 정정하는 구실뿐이어서 입력 1과 함께 거두는 것이 맞다.
- 심사자는 읽지 않았다. 독립 독해도 하지 않았다.
- 사용자의 말이 닿지 않아 그대로 둔 자리 둘: 이어진 과제의 앞 세션들의 대화를 peer가 어디까지 읽는가, 시도 전의 읽기가 수학 문헌에도 미치는가.

## 작업 너머 시사점

- 입력을 가이드에 담을 때 먼저 볼 것은 「가이드에 그 말이 있는가」가 아니라 「그 말이 걸리는 때가 사용자가 가리킨 때와 같은가」다. 같은 읽기를 요구하는 문장이 셋 있어도 저마다 다른 때에 걸리면 사용자가 가리킨 때는 비어 있을 수 있다.
- 읽으라는 문장은 지나친 적용의 값이 문맥이다. 「아직 읽지 않은 만큼」과 읽기의 목적을 문장에 함께 두면 세션이 어디서 그칠지를 스스로 정할 수 있다.
