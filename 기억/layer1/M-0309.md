사용자는 `research/problem-selection-2026-09-15`의 주차 함수 최대 변위 분포 단봉성 연구를 기존 인스턴스 정리 후 처음부터 다시 시작하되, 난이도와 역할에 관계없이 Claude Opus 5만 소비하도록 요구했다. 이 정책은 이번 연구에만 적용한다. 기존 목표·정책·학술 요구와 원자료 38개는 유지하고 이전 과제·판정·실행 상태는 새 연구에 수입하지 않았다. [[M-0307]]의 인스턴스 `RI-01M2PZY54SEB1B0P140FTCPQQT`는 closed로 종결하고 예약 두 개를 제거했다. 더 오래된 `RI-01M2JP80JC7RHQAJ7QGRPYZQEG`의 저장소는 이미 없었으며 남아 있던 비활성 예약 두 개도 제거했다. 다른 연구의 예약은 변경하지 않았다.

첫 시작 인스턴스 `RI-01M2S6Y5GCYTM0RZNQ996ZFQEW`에서는 Claude CLI가 역할 스키마의 `$schema`에 지정된 Draft 2020-12를 인식하지 못해 모델 응답 전에 실패했다. 해당 표기를 제외하자 다음에는 사용자 정의 주석 `x-contract-id`를 거부했다. 연구에 HOLD를 걸어 후속 실행을 막고, Claude에 전달하는 사본에서 두 주석만 제외하도록 수리했다. 역할 스키마의 제약과 중앙 제출 검증에 사용하는 원본 파일은 유지한다. 현재 역할 스키마 전건에서 두 주석 외의 내용이 유지되는지 검사했다. Claude CLI의 실제 수용 여부는 별도의 실호출로 확인했다. 미래에 추가할 판본 전용 키워드의 호환성까지 보장하지 않는다.

이후 Opus 5의 실제 응답은 성공했지만 `modelUsage`에 Haiku 보조 호출도 있었다. 주 모델 지정과 작업 배정만으로 CLI 내부 모델 소비까지 제한되지는 않았다. 이를 사용자에게 알리고 연구 정지를 유지한 채 인스턴스 옵션 `claude_only_assigned_model`을 추가했다. 기본값은 false이며 이번 인스턴스에서만 true다. true이면 전체 Claude 모델 ID를 요구하고, CLI의 `availableModels`를 배정 모델 하나로 제한하며, fallback 목록을 비우고 자동 모델 전환을 끈다. `ANTHROPIC_DEFAULT_HAIKU_MODEL`과 `CLAUDE_CODE_SUBAGENT_MODEL`에 배정 모델 ID를 넣고, 강제 적용 스위치인 `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`는 `1`로 켠다. 연구 실행기와 독립 운영 담당은 각각 Claude CLI를 호출할 때 이 설정을 전달한다. 독립 운영 담당은 이 제한을 변경할 수 없다. 설정 뒤 동일한 실제 응답 검사에서 `modelUsage`에는 `claude-opus-5`만 나타났다. 공급자가 보고하지 않는 내부 연산까지 관측했다는 뜻은 아니다. 공식 설정 근거는 [Claude Code 모델 설정](https://code.claude.com/docs/en/model-config)이다.

시작 오류가 남은 `RI-01M2S6Y5GCYTM0RZNQ996ZFQEW`도 종결하고 예약을 제거했다. 현재 연구는 `RI-01M2S7DEH95FK8DEC0H0R4QMM8`이며 저장소는 `.skill-workspace/parking-unimodality-opus5-20260918/repo`, 작업 공간은 같은 폴더의 `work-v2`다. 상·중·하 등급 모두 `claude-opus-5`, 작업·운영 세션은 각각 3개다. 독립 운영 주기는 2시간이다. 연구 예약 `DoMath-Engine-21614d08d967`을 시작했고 최초 후보 준비의 init·assistant 사건에서 Opus 5 사용과 학술자료 MCP 서버 scholarly의 연결을 확인했다. 연구의 수학적 성과나 완료를 확인한 것은 아니다.

`test_claude_adapter`, `test_model_runner`, `test_operator`, `test_contracts`, `test_controls`의 회귀 40건을 통과했다. 그중 `test_claude_adapter`와 `test_operator`의 전달 경로 검사를 보강한 뒤 두 파일의 23건을 다시 통과했다. 두 수치는 중복을 포함한다. 이후 공식 문서 대조에서 `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`가 모델명이 아니라 `1`을 받는 스위치임을 확인했다. 값을 고치기 전에 HOLD로 후보 준비를 멈추고 체크포인트를 보존했다. 수정 뒤 `test_claude_adapter` 11건을 다시 통과하고 HOLD를 해제해 실행기를 재시작했다. 재시작 뒤 연구 계획 실행 `EX-01M2S7PM8VCXXMCY6FEPNCCC9P`의 산출이 수락됐으며 그 사용량에는 Opus 5만 있었다. 후보 준비는 계속 진행 중이었다. 보강 중 시험 코드가 실제 클래스명 ResearchEngine 대신 Engine을 import하여 한 번 실패했으며 이름을 고친 뒤 재검사했다. 전체 회귀를 새로 수행했다고 보고하지 않는다. 설정·최초 실패·수정 전후 실호출·연구 로그는 위 `.skill-workspace` 아래 로컬 보관이며 주 저장소 Git 제외 대상이므로 정리로 사라질 수 있다. [[M-0308]]의 작은 실호출 스키마 검증은 실제 역할 스키마의 CLI 수용성과 보조 모델 소비를 확인하지 않았던 범위다.
