title: do-math에 Claude CLI를 모델별 세션 예산과 연결함
convention_version: 26
---

사용자는 do-math에 Claude CLI 호출을 추가하되 기존 Codex처럼 예산을 부여하고 활용하기를 원했다. 단발 호출과 전체 연구 실행의 교체 중 무엇인지 묻자 기존 모델 자원과 같은 활용으로 범위를 정했다. 이어 스킬 수정에 서브에이전트를 사용하지 말라고 명시했다. 구현·문서 대조·검증 판단은 메인이 직접 수행했고 별도 작성자나 독해자를 호출하지 않았다. 실제 CLI 검사는 고정 입력의 계산·파일·MCP·종료 동작을 확인하는 용도였으며 스킬 수정을 위임하지 않았다.

기존 예산은 공급자와 무관하게 모델 이름별 작업·운영 슬롯을 관리했다. Claude 이름을 넣은 배정·점유·대기·반환 검사는 실행기 추가 전에 이미 통과했다. 따라서 새 예산 저장소나 스케줄링 정책을 만들지 않고 모델 라우터를 연구 실행기와 독립 운영 담당에 연결했다. `claude:` 접두어는 Claude CLI용 모델 이름·별칭을 표시하고 `claude-`로 시작하는 전체 ID도 Claude로 보낸다. 다른 모델은 기존 Codex 경로를 사용한다. 슬롯 식별자는 원래 설정 문자열이므로 같은 실제 모델을 별칭과 전체 ID로 중복 등록하면 별도 예산으로 계산된다. 등급당 모델 하나, 슬롯 부족 시 원 모델 대기, 작업·운영 용량 분리는 유지한다. 기본 모델·용량과 중단된 연구 인스턴스는 바꾸지 않았다.

두 CLI는 입력 사본·해시·worker 영수증과 Windows Job 수명 관리를 공유하고 사건 해석은 구분한다. Claude는 구독 로그인을 쓰는 `--print`·`stream-json`·`--json-schema` 경로다. `--bare`는 OAuth 로그인을 읽지 않으므로 채택하지 않았다. 고정한 scholarly 설정을 별도로 전달하고 도구·메시지 사건을 진행 관찰에 연결한다. 예산을 실제로 사용하더라도 CLI 내부 호출별 제한이나 강한 파일 격리를 새로 보증하지 않는다.

Claude 2.1.274의 scholarly 실호출에서 `rate_limit_event`가 `system/init`보다 먼저 도착했다. 최초 해석기는 시작 사건이 첫 줄이어야 한다고 요구해 정상 결과를 거부했다. 원본 출력과 실패 재현을 보존하고 시작 전 제한 알림만 허용했으며, 시작 전 실제 작업·세션 혼합·중복 최종 결과는 계속 거부하게 했다. 수정 후 scholarly 자료원 49개 조회와 Python의 2+3 계산 결과가 정상 수신됐다. JSON 결과 대조에서도 Python의 `True == 1`과 기본 JSON 디코더의 중복 키 덮어쓰기가 잘못된 일치를 만들 수 있음을 재현했다. 중복 키를 거부하고 JSON을 정규 직렬화한 바이트로 대조하도록 고쳤다.

실제 파일 읽기·쓰기와 구조화 출력, 시작 전·실행 중 정지, 실행 파일 부재 뒤 실패, Job 종료 후 슬롯 반환, Codex 실호출을 각각 확인했다. 전체 회귀와 최종 검증 판정은 `docs/do-math/claude-cli-validation-2026-09-18.json`에 보존한다. 편집 중 정본의 최초 회귀와 중간 고정본의 직렬 회귀는 최종 완료 근거로 쓰지 않고 중단했으며, 최종 고정본의 파일별 프로세스로 전체 검사를 수행했다. 원본 CLI 출력·최초 실패·검증 사본과 상세 로그는 Git 제외 대상인 `.skill-workspace/do-math-claude/`의 로컬 보관이므로 정리로 사라질 수 있다. 문서 대조는 직접 검토이며 독립 독해의 보증으로 보고하지 않는다.

49개 파일의 452개 회귀에서 창 방지 정적 검사 1건과 동시 실행 검사 2건이 처음 실패했다. 창 방지 플래그는 이미 공통 인자에 있었지만 기존 AST 검사는 호출문에 직접 적힌 키워드만 인식했다. 호출문에 플래그를 명시한 뒤 실제 창·콘솔 검사를 포함한 해당 3건과 Claude 검사 9건을 다시 통과했다. 동시 실행 두 검사는 세 실행 대신 둘을 관찰했다. 대역의 동료 시작 대기는 8초, 정지 제어의 시작 대기는 15초로 제한돼 있다. 나머지 회귀를 끝낸 뒤 코드·기준을 바꾸지 않은 단독 재검에서는 두 사례 모두 통과했다. 원인을 병렬 부하로 확정하지 않으며 최초 실패를 보존한다. 최종 확인은 451건 통과와 Windows 심볼릭 링크 권한 부족에 따른 1건 미실행이다. 중간에 다음 검사명으로 넘어간 것을 이전 검사의 통과로 잘못 읽어 안내했고, 최종 로그에서 실패를 확인한 뒤 바로 정정했다. 진행 보고에서도 현재 검사명과 완료 판정을 구별해야 한다.
