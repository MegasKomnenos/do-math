[[M-0493]]의 시험 timeout 제거와 [[M-0494]]의 학술 제출 시험 문맥 교정 이후 사용자는 원문 재확인, 수행 계획 제시와 반복 검토를 요청했고 마지막으로 수행을 지시했다. 목표는 원문 재편 전체를 유지하되 실제 변경 하나를 검수·검증·확정하는 방식이다. 시간 예산은 정확성 우선의 소프트 기준선이며 별도 시간 강제 종료를 재도입하지 않는다. 이번 범위는 B78의 활동 대기 종류 계약, 복구 좌표 보존, 최근 결과 다섯 개 밖의 대기 표시다. 과제 표시 수리나 모든 대기 공간의 의미 검증을 이 변경에 계속 붙이지 않는다.

활동 대기의 종류는 행동 대기 22종과 활동 전용 11종을 공유 정본 ACTIVITY_WAIT_RULES에 선언한다. 종류·이유·조건·다음 담당자·시각을 만드는 activity_wait_record를 생산자와 저장 스키마가 사용한다. 조건부 continuation도 명시적 종류를 요구하고 잘못된 종류를 상태 변경 전에 거부한다. 모든 호출부와 현행 시험을 함께 교체하고 구형 기록 자동 변환은 넣지 않는다.

이전 검토 착수 관문은 설명문 reason을 종류처럼 비교했다. kind로 판정하도록 고치고 실제 검토 입력 복구 시험에서 reason만 설명문으로 변경했다. 추가로 드러난 결함은 held 활동의 재등록 거부가 원래 복구 condition을 짧은 admission 표지로 덮는 것이었다. 원래 waiting 전문을 보존하도록 held 때 wait_for를 다시 호출하지 않게 했다. 시험은 admission 호출 없음, 새 실행 없음, 회계 불변, waiting 전문 불변과 실제 입력 복원 후 실행을 함께 확인한다. 과거 y4sfuzqq의 실제 복구 실패와 t_xwk6h1의 교정 후 통과는 서로 다른 판본의 근거다.

상태 보고는 모든 waiting activity를 깊은 복사하여 종류·이유·조건·담당자와 활동/소유자/실행 좌표를 포함한다. 저장한 33종 대기를 JSON과 사람용 출력에서 확인하고 보고 사본 변경이 저장 상태를 바꾸지 않음을 검사한다. 33종 공통 API의 조건 일치 검증과 해소자 callable 존재는 각 종류의 실제 의미별 owner 해소를 증명하지 않는다. user_resume와 required_input은 API 전용 종류로 구별한다. 4-A/4-B/4-C/13-B 전체 의무는 남는다.

재개한 관련 검증 ju5aelfn은 구조47·단위86·Sim55·flows11, 합계199개가143.4초에 완결 통과했으며 실행 중 변경은 없다. 개별 예산 초과16개는 보고 정보다. 그 원보고와 과거 red를 추적 검증/2026-10-04-활동-대기에 보존한다. 전체 일반 검증은 동일 후보를 고정하고 timeout 없는 공식 실행기로 시작했다. 이전 300초 중단 사례 review_alphabet의 LONG6×20은287.265초에 정상 통과했다. 사건 수나 단언을 줄이지 않았다. 이는 해당 사례의 결과이며 성능 절감률의 근거가 아니다. 전체는3915개 중3909통과·5실패·1건너뜀으로3879.6초에 완결했고 소스 변경은 없다. 다섯 실패는 B78 없는f56a2772에서도 같은 이유로 재현되어 기존 학술 평가 문맥 누락으로 분류했다. dc75da99의 독립 교정은 일곱 기존 시험 메서드의 AST를 유지하고 실제 근거 생산자를 사용한 뒤54개를 통과했다. B78 제품·호출부·스키마·시험32파일은 전체 실행 이후 바뀌지 않았다. 원 전건 보고의successful=false를 수정하지 않고 전건 성공으로 합산하지 않는다. 건너뜀은 symlink 생성 권한의 WinError1314이며 제품 동작을 확인한 통과가 아니다. 미완결 cc31zngi의 중간 보고를 새 성공으로 재구성하지 않는다.
