# do-math 테스트 비용 전수검토의 범위와 근거

## 맥락

do-math 테스트 절감 작업은 처음에 실행시간이 긴 소수의 통합 테스트를 상세히 읽고 고쳤다. 이후 전체 테스트를 검토했다고 표현했으나 실제로는 모든 메서드의 검증 의미를 확인하지 않았고, 사용자가 이 차이를 여러 차례 바로잡았다. 이번 작업의 교정 기준은 비용 순위만으로 전체 검토를 대신하지 않는 것이다. 현재 `test_*.py` 121개에서 정적으로 선언된 테스트 메서드 1,648개를 모두 열거하고 각 본문의 위치·해시·직접 단언 대상·실행/반복/대기 형태를 추적 가능한 원장에 기록했다. 검토 판단은 `docs/do-math/테스트-비용-전수검토-2026-09-24.md`와 개별 CSV에 남겼다.

## 터득한 것

- 이전 완료 통합 배치의 1,242개 개별 시간 합계는 41,844초였다. 30초 이상 134개가 94.8%를 차지한다. 그러나 배치에 없는 테스트를 0초로 출력한 초기 집계는 오류였다. 다른 보존 보고서를 합쳐 현재 1,648개 중 1,604개의 역사 시간이 있고 44개는 숫자 시간이 없다. CSV의 빈칸은 미측정으로 유지했다. 과거 보고서는 로컬 임시 폴더에만 있었으므로 추적 CSV에 시간과 출처 실행 폴더 이름을 옮겼다.
- 단언 호출이 없는 메서드 32개는 무효 테스트가 아니었다. 시나리오 헬퍼에 단언을 위임하거나, 유효한 입력을 예외 없이 통과시키는 계약이었다. 이름이나 단언 수만으로 삭제하면 보증이 사라진다.
- 두 리뷰 비공개 테스트를 한 엔진 흐름에 병합하면 하나는 일반 제출에서 보충 조사 요청으로 바뀌어 같은 경계를 검사하지 않게 된다. 병합 시도는 적용하지 않았다. 외부 HTTP 실패 테스트를 합성 활성 fixture로 바꾸는 시도 역시 외부 정책이 달라져 적용하지 않았다. 비용을 줄일 때는 시작 상태가 같은 계약인지까지 대조해야 한다.
- graphify 조회는 `stale`였고 원문 검증 대신 쓰지 않았다. 사용자에게 그래프 갱신 권한이 없으므로 상태는 그대로 두었다. commit-harness의 미러 검사에서는 `.agents/skills` 61개 파일의 생성·갱신 필요가 드러나 정본에서 재생성했고, `--check`가 드리프트 없음으로 끝났다.

## 작업 너머 시사점

전수라는 말은 대상 집합뿐 아니라 **검토 깊이**를 함께 밝혀야 한다. 테스트 이름·시간의 전수 집계, 각 본문 구조와 단언의 전수 정적 검사, 후보 경로의 원문 독해, 변경 후 실행 검증은 서로 다른 증거다. 특히 0초와 미측정을 분리하고, 테스트가 싸거나 느리다는 사실에서 바로 보존 가치의 결론으로 건너뛰지 않는다. 사용자 교정이 드러낸 빈틈은 검토 시작에 분모와 증거 수준을 고정하지 않고 비용 상위 표본의 판단을 전체 결론처럼 보고한 데 있었다. 다음에는 원장으로 분모를 고정한 뒤 각 결론에 실제 읽은 범위를 붙인다. 정적 검토만 허용된 이번 변경의 통과 여부와 절감량은 아직 확인되지 않았다.
