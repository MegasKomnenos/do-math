사용자는 [[M-0311]] 뒤에 나눈 거부 35건의 의미·복구·의존성 파견·예방 가능성에 관한 대화를 붙여 넣고 검토를 요청했다. 연구 정지를 유지한 채 코드와 원 응답을 대조했고, 보완 제안은 `docs/do-math/review-2026-09-18/dialogue-review.md`, 수치·두 사례·최소 파견 함수 검사는 `dialogue-evidence.json`에 보존했다. 실행기 구현은 수정하지 않았다.

35건은 계약 검토 5, 계획 17, 준비 5, 내부 운영 점검 8이며 연구 수행 역할은 없다. 출력 수리 횟수 표지 repair_attempt가 0인 실행은 25건, 1인 실행은 10건이다. 35개 독립 실패나 재수행 과제로 계산하면 안 된다. 원 실패에서 파생된 수리·진단·재시도의 연결을 따져야 예방 효과를 평가할 수 있다. 당시 전체 과제 19개의 dependencies는 비어 있고 그중 13개에 reuse가 있었다. 후보 준비는 activity-extensions.json의 task_conditions로 선행관계를 작성할 수 있으므로 기능 부재라고 진단하지 않는다. 실제로 필요한 관계가 전달됐는지와 진행 중 변경과의 충돌 검사는 별개다.

파견 함수는 역할·요청·일부 대상 중복과 모델 슬롯 등을 검사하지만 일반적인 읽기·변경 범위의 교차 비교는 하지 않는다. 최소 함수 검사에서 A 계약 개정용 후보 준비와 A 또는 A를 재사용하는 B의 계약 검토는 허용됐고 준비 두 개는 차단됐다. 모델 선택을 대역으로 둔 함수 검사이며 전체 파견 경로 재현이나 실제 연구 시작을 의미하지 않는다. 의존관계만으로 무조건 직렬화할 필요도 없다. B가 최신 A나 개정 결과를 요구하면 순서를 조정하고, 허용된 A의 고정 판본을 쓰는 조건부 결과라면 병렬 가능성을 남긴다. 판본 고정은 근거 철회·정책·권한 변경을 무시할 허가가 아니다.

실제 승인 사례 EX-01M2S84J1J4VR5KZ9SWWBC61VE는 판정 대상 기록과 목표·정책·원자료가 유지된 채 다른 과제의 정상 진행 때문에 거부됐다. 계획 EX-01M2SDQ2GH174XGW32PVCT2633는 기록이 유지된 세 과제의 완료 2·미완료 1 판정과, 제출 전 종결된 다른 과제의 보류를 함께 반환했다. 전면 재수행과 제한된 재검토를 구별할 근거지만 두 사례의 수학 판단 전체나 35건 전수의 의미적 유효성을 인증한 것은 아니다.

기존 수신은 한 결과 묶음의 적용 중 오류가 나면 연구 상태를 되돌리고 계획 입력의 전체 후보 처분을 검사한다. 따라서 낡은 JSON 항목을 삭제해 나머지만 곧바로 적용하는 수리는 위험하다. 첫 구현은 변경된 전제와 이전 판단·근거를 제공해 필요한 부분만 재검토하고, 최종 묶음은 전체 검증 후 함께 적용하는 방식으로 제안했다. 부분 적용은 별도의 필요가 남을 때 항목 간 결합·중복 방지·실패 후 재개를 정해 검토한다. 입력 후보 집합이나 부재 조건도 전제이므로 ID 교집합만으로 충돌을 완전히 판정한다고 약속하지 않는다.

새로 큰 동시성 체계를 만들기보다 기존 선행관계 작성 경로를 점검하고, 대상이 알려진 계약 개정·검토 충돌부터 막으며, 현재성 검사와 제한된 재검토를 연결하는 순서다. 원 응답 로그와 분석 보조 스크립트는 `.skill-workspace/`의 Git 제외 로컬 자료이므로 정리하면 사라질 수 있다. 추적 문서에는 판단에 필요한 발췌와 판본·해시를 보존했다.

수치·두 사례·참조·코드 불변의 검산 8개를 통과했다. 독립 독해 3회는 작업 전용 연결 코드로 Claude Opus 5만 호출했고 최종 독해와 합의 대조를 완료했다. 독해자가 지적한 연결·용어를 보완했으며 마지막 지적은 본문과 원 대화를 읽은 독자 조건에 비춰 유지 이유를 기록했다. 독해 기록은 dialogue-reading 계열 파일에 있고 원 CLI 로그는 `.codex/writing-flow/`의 로컬 보관이다.
