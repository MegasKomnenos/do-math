## 맥락

사용자는 do-math 구현 산출의 GLOSSARY, SKILL과 역할 계약이 개념을 충분히 정의하지 않고, 구조가 불분명하며, 뜻을 전달하기보다 급히 축약한 문장으로 작성됐다고 지적했다. 이후 관련 스킬의 지식을 참고하되 그대로 따를 필요는 없다고 했고, 용어를 한 번 정의한 뒤 같은 뜻으로 사용하며 정의의 위치는 통합 설계에서 확인하라고 요구했다. 마지막으로 통합 설계 전문을 다시 읽으라고 지시했다.

기존 완료 판단 [[M-0269]]는 코드 경로와 실제 CLI·Lean의 작은 실행 사례를 중심으로 했다. 이번 개정 전 문서만 제공한 독해 실행은 U·온톨로지·시맨틱 레이어를 정의에서 찾지 못했고, K와 목표 상대적 연구 진전을 설계보다 좁거나 강하게 설명했다. 코드 검사의 통과와 연구 역할이 문서를 읽고 올바른 판단을 재구성하는지는 별도 검증이 필요했다.

통합 설계 0~20절의 2,634행을 검증 벡터·판본 이력까지 순서대로 다시 읽었다. 정의의 저작 원천은 루트 CONTEXT이고, 0.3절은 용어와 소유 절을 연결한다. 16.5절의 소유 배치에 따라 SKILL은 목적·전체 흐름·읽기 대응표, GLOSSARY는 공통 정의·판정, 역할 계약은 해당 입력·판단·산출·실패, references는 공통 긴 절차를 맡도록 다시 작성했다. 구현의 필드 이름을 보편 개념의 정의로 가져오지 않았다.

## 확인한 것과 교정 위치

문서가 늘어나는 것 자체를 개선 근거로 삼지 않았다. 같은 세 질문에 개정 전후 문서를 제공한 실제 Codex CLI 독해와 별도 독립 검토를 사용했다. 개정 중 독해는 새 개념과 부분 결과·목표·진전의 구별을 설명했지만, 기록 기반 대체 실행의 허가 조건을 빠뜨렸다. 독립 검토는 그 정의의 권한 조건 누락과 일반 결함 제보를 판정 사용 정지로 곧바로 연결하는 정의를 지적했다. 원문과 대조해 두 조건을 복원한 뒤 재검토를 통과했다. 일반 연구 기록에 형식·동일성 관문을 일괄 요구하는 문장, 관찰 조건이 자기 점검을 여는 것처럼 설명한 문장, 계속 처분에 현재 진전 확인을 일괄 요구하는 문장도 고쳤다.

교정 후 별도 독해는 일반 연구 기록과 K 편입, 관찰·체크포인트·운영 처분, 대체 실행의 허가와 판정 사용 효력의 발동 조건을 구별했다. 이 결과는 지정한 질문에 한정한다. 모든 독자의 이해나 넓은 수학 문제군의 연구 성능으로 일반화하지 않는다. 비교용 전체 문서 입력은 개정 전 30,642토큰에서 개정 중 97,824토큰으로 늘었다. 충분한 설명을 위해 실제 비용이 늘어난 사실도 보존했으며, 이것을 역할별 평시 입력 비용으로 사용하지 않았다.

문서를 실제 수신 경로와 대조하자 코드에서 공통 참조 문서가 전달되지 않는 문제가 확인됐다. `contracts.py`의 별도 파일 목록을 제거하고 SKILL의 읽기표에서 문서를 선택하게 했다. 정확한 원문을 한 번 읽어 공유하고 작업 공간 사본·입력 산출 묶음·manifest·설치 판본 검사에 연결했다. 코드 안의 별도 영어 역할 지시도 해당 공통 절차와 역할 계약으로 옮겼다.

원자료 전달과 후속에서 실제로 재현한 결함만 함께 고쳤다. 준비·계획에는 설정 전체와 과거 준비·선택의 원문·수신 상태를 제공했다. 최초 관찰 규칙은 과제의 계약 해시·검토·실행에 연결했고, 계약 개정 때 이전 실행 중 규칙이 새 최초 규칙을 덮지 않게 했다. 원자료 변경 때 완료 과제의 처분을 다시 열던 처리는 완료 이력을 보존하고 판정의 현재성을 따로 정지하도록 고쳤다. 운영 점검에는 실제 결과·체크포인트·부분 파일을 복원했으며, 최종 결과 미생성·읽기 실패·별도 활동 결과의 경로를 구별했다.

감사 중에는 설계의 별도 필드가 없다는 사실을 곧바로 기능 미완료로 판정한 지적도 있었다. 사용자가 위임한 실익 판단에 맞춰 다시 검토했다. 같은 의미가 기존 문면에 충분히 보존되고 실제 지정 역할이 소비하면 표현 수단의 차이일 수 있다. 반대로 문장이 있어도 다음 역할에 필요한 원자료가 전달되지 않으면 목적을 충족하지 못한다. 모든 차이를 수기 필드나 새 승인 단계의 추가로 해결하지 않았다.

## 검증과 작업 범위

최초 전체 고정 사본 회귀는 272건 중 255건 통과, 2건 실패, 14건 오류와 1건 미실행이었다. 고정 사본의 디렉터리 깊이에 맞는 명세 지원 자료와 Lean 경로를 주지 않은 15건은 같은 소스에 그 입력을 제공하자 통과했다. HTTP 시험 서버의 요청 본문 소비와 응답 길이를 보강한 뒤 관련 11건과 재시도 반복 5회도 통과했다. 최종 문서의 관련 회귀 53건과 마지막 입력 복원 교정의 회귀 20건을 추가 확인했다. 최초 실패를 지우거나 이를 단일 최종 전체 실행의 통과라고 기록하지 않았다. Windows symlink 권한이 필요한 1건은 미실행으로 남는다.

문서와 검증의 진입점은 `docs/do-math/문서-검증-2026-09-15/README.md`다. 최초 입력·모델 응답·독립 지적·교정·고정 소스·실패와 보완 검증을 보존했다. 이전 2026-09-14 연구 실행 증거는 수정하지 않고 그 판본의 역사 근거로 유지했다. 정본과 `.agents` 생성 사본의 형식·드리프트 검사를 통과했다.

검증 소스를 그대로 복사하면 그 안의 원래 `.gitattributes`도 함께 들어온다. 이 파일의 텍스트 정규화가 바깥 증거 디렉터리의 바이트 보존 설정보다 우선하는 것을 확인해, 해당 하위 경로에 보존 속성을 추가했다. 캡처 자료 자체를 정규화해 경고를 없애지 않았으며 스테이징된 증거 파일 305개의 Git blob과 실제 파일 바이트를 대조해 불일치가 없음을 확인했다.

동시에 진행된 저장소 정리 [[M-0273]]는 별도 작업이었다. 그 커밋 뒤의 HEAD와 메모리 번호를 다시 확인했고, 삭제된 연구나 이동된 과거 작업 공간을 이번 문서 작업의 일부로 복원하지 않았다. 작업 중 만든 검증 자료와 do-math 변경만 이 커밋에 묶는다.

## 후속 작업에서 재사용할 판단

용어의 통일은 같은 단어를 찾는 검사만으로 끝나지 않는다. 정의에서 조건과 판정 주체를 빼면 같은 단어를 사용해도 행동의 범위가 달라진다. 독자가 실제 사례에서 무엇을 허용하고 보류하는지 설명하게 하면 이런 누락을 확인할 수 있다.

문서 품질 검증은 원천의 뜻, 문서의 설명, 실제 역할 입력과 후속 소비를 연결해야 한다. 기계 검사는 바이트와 전달 범위를 확인하고 독립 독해는 의미를 대조한다. 어느 한쪽을 다른 쪽의 통과 근거로 사용하지 않는 것이 이번 교정의 재사용 지점이다.
