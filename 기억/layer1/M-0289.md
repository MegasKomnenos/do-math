## 검토 기준과 범위

사용자는 통합 설계를 기준으로 do-math 구현을 검토하고 `형식과-절차.md`를 적용하라고 요청했다. 구현자의 결정·변명은 독립적으로 평가하는 참고 자료로 지정했다. 실행 조건은 codex-full 전면, 수리자 6기와 심사자 3기 모두 gpt-6-astra low, 1라운드였다. 병합은 기본 배정인 gpt-5.6-terra low를 사용했다. [[M-0287]]의 스킬 폴더 자기완결성 요구도 유지했다. 외부 설계를 검토 기준으로 읽는 것과 설치본이 실행 때 외부 문서를 요구하는 것을 구별했다.

수리 영역 4개가 정본 86파일·17,599행을 분담했고, 두 관점 담당은 각각 같은 파일 전건을 직접 읽었다고 수행 기록에 명시했다. 수리자 6기 모두 형식과 절차 및 구현자 변명을 전문으로 읽었고 통합 설계·CONTEXT는 담당 주제의 관련 절을 대조했다. 통합 설계 전문 독해나 모든 기능의 실행 검증으로 확대하지 않았다. 같은 날짜의 이전 런과 분리해 `임시/do-math_astra-low_검증_2026-09-15/`에 기록했다.

## 독립 승인 뒤의 결합 모순

수리 10항목은 겹치는 README 항목 둘의 병합을 거쳐 심사 대상 9개가 됐다. 그중 8개 수리안은 세 심사자가 모두 승인했다. 그러나 두 승인 수리안을 함께 적용하자 새로운 문서 모순이 생겼다. README 수리는 일부 시험에 직접 실행 진입점이 없으므로 discovery를 쓰도록 안내했다. 별도 수리는 바로 그 네 시험 파일에 진입점을 추가했다. 적용 후에는 시험 파일 37개 모두 진입점이 있었으므로 README의 이유 설명이 사실과 달라졌다.

편집 구간은 겹치지 않았고 두 수리자는 서로의 항목을 볼 수 없었다. 조각 교차 검사로는 이 충돌을 묶을 수 없었다. 심사도 각각의 수리가 원래 상태의 손상을 해소하는지를 확인했지만 두 수리의 결합 결과까지 보증하지 않았다. 이 사례는 항목별 만장일치와 최종 산출물의 정합성이 다른 확인 대상임을 보여 준다.

메인은 최종 문면과 시험 파일의 AST를 대조해 모순을 확인했다. discovery 안내만으로 누락된 시험 12건을 실행할 수 있으므로, 진입점을 추가하는 R1-06을 승인하되 반영하지 않는 무처분으로 바꿨다. 동결된 불변식과의 충돌을 다루는 신호 6으로 기록하고, 오판·복구 비용이 작으며 실제 파일로 판단할 수 있어 사용자에게 새 결정을 요구하지 않고 처리했다. 진행 중 회귀 시험을 중단하고 자체 적용 파일을 라운드 사본으로 복원한 뒤, 공식 적용 명령의 `--제외 R1-06 --강제` 경로로 변경 집합을 다시 만들었다. 최종 적용은 7수리안·12조각·정본 5파일이며 본표의 적용 행은 병합 구성 두 행을 각각 세어 8행이다. 사용자만 가진 정보가 필요한 선택은 없었고 동결문과 라운드 수는 바꾸지 않았다. 자체 판단을 사용자 확정이나 승계 근거로 기록하지 않았다.

## 남긴 지적과 실행 복구

R1-08은 보충 조사에서 제공된 원자료 ID와 source 별칭을 거부하는 문제였다. 심사자 둘은 승인했고, 셋째는 기준 인용의 `사용할 수`가 실제 원문의 `쓸 수`와 다르다는 이유로 기각했다. 세 번째 심사자도 코드의 별칭 불일치는 확인했다. 정족을 채우지 못했으므로 수리안을 적용하지 않았으며, 결함 주장이 반박되었다고 보고하지 않았다. 사용자가 지정한 1라운드를 넘겨 인용을 고쳐 재심사하지 않았다.

시험 영역 수리자의 최초 실행은 WebSocket 재연결과 HTTPS 전환 뒤에도 전송 오류를 반복했다. 약 40분 경과 후 완료된 다른 5기의 영수증과 남은 프로세스를 대조해 그 실행의 로컬 프로세스 트리만 종료했다. 공식 완료 대기와 산출 부재 확인 뒤 같은 파견문·모델·노력으로 1회 재파견했고, 재파견은 정상 완료했다. 최초 실행의 오류와 제품 검토 결과를 구별했으며 최종 결번은 없었다.

## 검증 증거의 범위

수정 전 전체 회귀는 275건 중 274건 통과, 1건 미실행이었다. 미실행은 심볼릭 링크 생성 권한 부족인 WinError 1314였다. 추가 재현 네 시험은 `engine.py`의 실행별 정지 수리 R1-02를 검사 전과 검사 중 두 시점에서 확인하고, `knowledge.py`의 R1-04를 개정 후 원자료 변경으로 확인하며, `engine.py`의 R1-03을 개별 Git 읽기 실패 뒤의 검사 지속으로 확인했다. 앵커에서는 네 시험이 모두 실패 또는 예외를 냈고 수정 후에는 모두 통과했다. 저장·Lean·권한 응답 일부를 대역으로 둔 검사이며 실제 원격 종료나 일반 수학 연구 효능의 검증으로 확대하지 않았다.

추가 재현의 첫 실행에서는 메인이 `sources_current`의 인자 순서를 잘못 사용했다. 함수 정의와 오류 출력을 대조해 호출을 바로잡고 앵커·수정본에 같은 시험을 실행했다. 보조 시험의 호출 오류를 제품 결함으로 세지 않았다. 원문과 실행 파일은 런의 `_추가회귀.py` 및 대응 로그에 남겼다.

최종 전체 회귀는 276건 중 275건 통과, 기준선과 같은 Windows symlink 권한 제한으로 1건 미실행이었다. 변경된 Python 4파일의 문법 검사, 스킬 미러 249파일의 드리프트 검사와 README 독립 독해·합의 대조도 통과했다. 종료집계는 라운드 상한 1에 따라 종료를 판정했다. 본표는 제기 10항목 가운데 적용 8·무처분 1·기각 1이며, 중복 병합을 제외한 실제 수리는 7개다. 이 검토는 수정된 기능과 검사한 사례의 증거이며 일반 수학 연구 효능이나 통합 설계의 모든 기능 완료 선언이 아니다.

항목별 위치·처분과 자체 처리 근거의 정본은 [장부](../../임시/do-math_astra-low_검증_2026-09-15/장부.md)다. 이 노드는 그 표를 복제하지 않고, 개별 승인 뒤의 결합 모순과 미적용 지적을 해석하는 데 필요한 맥락을 보존한다.
