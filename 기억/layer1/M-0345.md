## 맥락

사용자는 do-math 전체를 1라운드로 검증하면서 수리자 8명, 관점 4개, 수리·심사 gpt-6-astra를 지정했다. 미사용 호환 요소와 죽은 설정, 생산자·소비자 불일치, 목적 위반·비효율, 최근 실사용 수리의 불충분함과 파급 누락을 함께 조사하도록 했다. 기각·무처분은 운전 세션이 직접 판단해 처리하고, graphify 갱신과 커밋까지 마무리하도록 위임했다.

249파일 78,196행을 네 영역으로 비중첩 분담하고, 네 관점에는 별도의 필수 통독 범위와 담당 밖 영향 추적 책임을 줬다. 최근 실행 사례와 수정의 진입점은 [[M-0341]]·[[M-0342]]·[[M-0343]]·[[M-0344]]다. 수리자들은 graphify를 위치 지도로 쓰고 현재 원문에서 생산·검사·저장·소비·복구·시험을 대조했다. 파일·행 기록의 일치와 의미 이해의 완전성은 구별했다.

## 심사와 직접 수리의 구분

37개 원 항목이 9개 병합 묶음과 17개 단독 항목, 총 26개 심사 대상으로 정리됐다. 심사 결과는 수리 22건, 무처분 1건, 기각 3건이다. 공식 적용 대상은 수리 승인 22건에 사용자 위임으로 두 묶음을 더한 24건이다. 이 대상들이 가진 편집 조각은 82개이며, 병합 전 원 항목으로 환산하면 장부 34행에 대응한다. 나머지 원 항목 3행은 두 심사 대상의 직접 보완으로 처리했다. 중복 발견이 포함되므로 원 항목 수를 서로 다른 결함 수로 읽지 않는다.

기각 사유의 성격은 달랐다. 예약 실행 도구의 시작 실패 때 저장 결과를 잃는 수리는 코드 내용이 타당했다. 다만 시험 메서드를 클래스 안에 삽입하면서 이웃 행을 조각 구간에 포함하지 않아 서식 위반으로 기각됐다. 미사용 인라인 점검 래퍼는 실행 결과가 같아 무처분됐지만 사용자 정리 목적에 해당했다. 두 항목은 이웃 문면과 호출부를 대조해 추가 적용했다.

옛 입력 복원 제거안은 현행 설치 수리 인계 함수까지 삭제하고, retry 시험이 공유하던 Git fixture를 잃었다. 직접 수리에서는 현재 기록·설치 대상·권한·저장 경계를 유지한 인계 함수를 남기고, fixture를 현행 retry 계약으로 바꿨다. 불필요한 복원 실행기와 검사를 제거하면서 유효한 복구 검증을 함께 잃지 않는 것이 핵심이었다.

다른 기각안은 모든 제어 호출을 자기 점검으로 면제하던 코드를 제거했지만, 정상 안전 경계 제출 자체를 미신고 연구 호출로 만들었다. 자기 점검·안전 경계·일반 preview를 실제 도구 인자와 요청 관계로 구별해 보완했다. 세 심사자 중 한 명이 이 회귀를 지적했고, 두 명의 승인만으로는 적용되지 않았다. 원 심사와 직접 후속 처분은 별도 기록에 남겼다.

## 검증에서 확인한 추가 영향

최초 단위 검사에서 직접 편집 중 시험의 필요한 import를 지운 오류가 드러나 복원했다. 병렬 통합 시험은 이전 사본에서도 같은 실패를 냈다. 입력을 참조화한 최근 구현에 맞춰 시험 대역의 입력 읽기를 바꿨지만, 제출 도우미가 다시 원 prompt의 참조 객체를 목록으로 순회해 실패했다. 종료 실행의 실제 오류는 `AttributeError: 'str' object has no attribute 'get'`였다. 도우미도 정확한 로컬 참조를 읽도록 바꾼 뒤 live 운영 점검 회귀가 통과했다. 입력 생산의 최적화는 직접 수행자뿐 아니라 제출 봉인·시험 도우미에도 영향을 준다는 사례다.

정지 시험은 모든 호출이 시작되기 전에 고정 15초가 지나면 정지를 요청했다. 실제 세 호출의 시작을 동기화하고 시간 제한을 실패 감시로만 사용하도록 바꿨다. 제품의 입력 검사나 정지 계약을 완화하지 않았다.

고유 테스트 ID별 최신 결과는 389개 통과다. 최종 단위 368개와 변경 경계의 통합·자원 21개를 합친 값이며 여러 고정 판본 실행 묶음의 최신 결과다. 전체 스위트나 실제 장시간 모델 연구의 완주 증거는 아니다. 설치 구조·미러·구문·기억 색인 검사도 커밋 게이트로 수행했다.

## 보존과 재개 좌표

추적되는 진입점은 `임시/do-math_검증_20260925_full/종료보고.md`, 같은 폴더의 `동결.md`·`장부.md`·`직접처리.json`·`검증결과.json`과 `기각보관/do-math-full-20260925-라운드1.md`다. 이 증거 파일들은 커밋에 포함한다. 상세 CLI 로그·전체 테스트 원 보고서·작업 보조 파일은 Git 제외 로컬 자료다. 이 노드를 포함한 커밋은 성공했다. 이후 기준선 사본 `앵커/`와 중간물 폴더 `라운드1/`의 재귀 삭제가 실행 전 자동 승인 검토에서 `blocked by policy`로 거절되어 두 폴더를 보존했다. 우회하지 않고 정리 미완료를 운영 기록에 남겼다.

graphify는 인용 좌표 오류를 낸 두 문서를 재추출했고, 실행 중 원본 변경을 감지한 시도는 기존 그래프를 보존했다. 최종 고정 판본의 갱신은 성공했으며 파일 249개·노드 6,515개·관계 23,049개와 Markdown 24개의 의미 추출을 확인했다. 그래프와 추출 캐시는 Git 제외 로컬 생성물이다.

dream에서 묶을 후보는 정리 작업의 경계다. 폐기 기능과 현행 기능이 하나의 함수나 fixture를 공유하면, 호출되지 않는 경로만 지우는 판단과 살아 있는 계약을 보존하는 검증을 분리해야 한다. 원 수리안의 기각은 결함의 부재와 구별된다.
