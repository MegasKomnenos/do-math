B131에서 CLI 반환 묶음을 닫은 뒤, 새 독립 문맥에 DOC-RETURN-ROLE의 input_manifest와 prompt를 배정했다. 문서 원문은 CLI-실행-계약의 prompt.artifact_ref와 input_manifest.prompt.sha256이었다. 기존 RoleInputTests의 prepare_role_input 최종 반환을 재사용하므로 큰 _context 전체나 새로운 엔진 실행이 필요하지 않았다. 실제 결과가 없으면 거부해야 한다는 기존 공개 API 단언을 먼저 넣었고 ValueError not raised로 정확한 구조 시험 한 개가 실패했다. 네 AST 추출과 조립을 교체한 첫 관련 검증은 26개가 34.8초에 모두 통과했다.

마감 검토에서 같은 prepare_role_input의 documents 항목을 만드는 두 AST 추출도 확인했다. CLI-실행-계약의 documents[].artifact_ref는 같은 생성 결과를 설명하므로 동일 manifest와 artifacts로 검증할 수 있었다. 별도 관리 단위로 넘기지 않고 이번 생성 메타데이터 묶음에 포함했다. documents의 실제 결과 없는 거짓 통과도 기존 API의 ValueError not raised로 재현했다. 이 두 번째 red는 1.5초에 시험 한 개가 실패했다. 기존 첫 red/green 원보고는 덮지 않았다.

최종 변경은 input_manifest·prompt·documents 세 소유자의 AST 추출 여섯 곳과 조립을 제거한 것이다. prompt와 input_manifest.prompt는 같은 실제 manifest의 prompt 한 단계 키를 사용한다. documents와 input_manifest.documents도 같은 실제 배열을 사용하고 모든 항목에 공통인 최상위 키만 인정한다. 빈 배열은 항목 필드의 증거가 아니다. 범용 재귀 추론이나 다른 생산자 키의 합집합은 만들지 않았다. 실제 결과가 없으면 기본 거부하며, 다른 경계 시험은 자신이 제공하지 않는 역할 입력 소유자만 명시적으로 보류한다.

실제 sha256·artifact_ref 삭제, prompt 전체 삭제, 문서 항목 하나의 artifact_ref 삭제와 빈 목록이 해당 원문 경로를 실패시키는지 확인했다. 정상 별칭은 통과하고 키 차용과 배열 표기 오류는 거부한다. prompt artifact_ref가 실제 prompt 바이트를 가리킴을 직접 확인했고 문서의 실제 바이트·해시는 기존 verify_manifest_artifacts 단언을 재사용한다. 기존 생성 호출 한 번, catalog 파일 한 번 생성 및 읽기 없음, private resume 바이트, 필수 direct 키, output contract, 변조 거부 단언은 유지했다. 제품 코드는 바꾸지 않았다.

최종 green-documents는 구조 18개·단위 4개·CLI 경계 4개, 같은 26개 모집단이 모두 통과했다. 298.5초였고 complete/successful은 true, changed_during_run은 비어 있다. 소프트 예산 초과 9개를 시간 제한·재실행·단언 축소로 처리하지 않았다. 첫 green과 실행 조건의 차이가 있으므로 속도 개선 또는 회귀의 증거로 단정하지 않는다. 검증/2026-10-06-역할입력-실제반환에 두 red와 두 green 원보고를 바이트 그대로 보존하고, 26개와 26개를 합산해 52개 통과로 표현하지 않는다.

여기서 입증한 것은 실제 반환 manifest와 artifacts 매핑이다. 별도 manifest 파일 출판을 검증한 것으로 확대하지 않는다. 같은 prepare_role_input 안에도 profile_selection이라는 역할별 본문 소유자의 AST 결속은 남아 있으며, 이를 메타데이터 마감과 혼동하지 않는다. DOC-RETURN-ROLE은 partial_complete로 두었다. 다음은 restore_continuation의 결과·반려·이전 출력 파일 결속이며, _context와 profile_selection은 별도로 유지한다. 13-C 전체와 최종 일반/T3/극단 변이/T4/T5는 계속 미완료다.
