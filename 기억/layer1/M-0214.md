원 API 접근이 복구된 뒤 DBLP 문헌 페이지의 내보내기 링크를 확인했다. BibTeX 메뉴는 HTML 보기로 연결되지만 .bib endpoint도 실제 원 파일을 제공했다. RIS·N-Triples·Turtle·RDF/XML·XML·plain은 각각 원 파일 endpoint가 있었다. DOI를 검색 문자열이나 doi:/ee: 조건으로 넣은 진단에서는500 또는0건이 있었으며, 알려진 Natural Proofs 문헌 자체의 부재로 해석하지 않았다. fetch의 입력은 native key·문헌 URL·이름이며 다른 자료원으로 자동 전환하지 않는다.

문헌 조회는 원 XML에 정확한 key가 하나 있는지 대조한다. 이름은 검색 후보를 반환하고 자동 선택하지 않는다. 검색의 @first·@sent와 실제 행 수를 검산한다. fetch export는7개 원 형식을, search export는 선택된 레코드의 요청 형식을 회수한다. XML·BibTeX·RIS·RDF의 문헌 식별자와 plain의 제목을 대조하고 실패한 원 파일은 source_export에 남긴다. 한 형식의 실패가 다른 파일이나 metadata를 없애지 않는다.

conf/stoc/Cook71의 원 파일 크기는 XML472·BibTeX778·RIS532·N-Triples6162·Turtle3287·RDF/XML4551·plain81바이트였다.072659Z-dblp-documents-mcp.json은 그7개 형식의 실제 extract, 이름 후보4건, P versus NP의start1/limit2와 원 RIS2개를 completed=true로 통과했다. N-Triples는 원 텍스트 줄로 추출한다. RDF/XML은 XML 요소이며 별도의 그래프 질의 인터페이스를 추가하지 않았다.

원 XML의 다른 key와 BibTeX의 다른 key를 거부하는 재현, 이름 후보, 다른 export 보존 검사를 추가했고 공통267검사가 통과했다. 이 커밋으로 앞서 함께 검증하던 JSTOR 단위와 DBLP 단위가 모두 커밋됐다. 남은 출판사 접근·원 내보내기와 JSTOR의 추가 이미지 검색 조건은 계속 진행한다. 전체 작업 종료 전이므로 푸시하지 않는다.
