사용자는 [[M-0312]]의 대화 검토가 중요하지 않은 예외를 확대해 핵심 진단을 평가절하했다고 지적했고, 이어 반대 방향으로 과잉 교정해 제안을 무조건 받아들이지도 말라고 요구했다. 실제 do-math 절차 전체와 상호작용을 검토한 뒤 simplify를 적용해, 변경이 예정된 필수 전제를 사용하는 작업은 기다리고 무관한 변화로 유효한 결과를 거부하지 않는 두 규칙을 채택할 방향으로 정리했다. 같은 고정 판본의 독립 검토 병렬 수행은 유지한다. 이번 요청은 이 최소 수정들과 나머지 개선이 충분한지 근거로 판단하되 이미 읽은 내용을 반복해서 읽지 말라는 것이었다.

검토의 초점을 제안의 찬반이나 지적 수에서 의도한 효과·삽입 위치·소비자·해소 조건으로 바꿨다. 이미 읽은 계약과 코드는 맥락에서 재사용하고 미확인 경로만 새로 확인했다. 산출물은 `docs/do-math/review-2026-09-18/sufficiency-review.md`와 `sufficiency-evidence.json`이다. 제안 방향은 유지하되 기존 승인 재사용, 대기 해소, 질문에 따른 진행 제어, 종료 전 예고, 새 요청 정보의 병합에 연동이 필요하다고 판정했다. 일반 잠금 관리 체계, 결과의 부분 적용, 검토 인원 축소를 선행조건으로 요구할 근거는 없었다.

모델별 세션 예산 모드의 실행기를 메모리 저장소와 명시한 역할 출력으로 초기화해 실제 `_apply`의 준비·계약 검토 경로와 `_refresh_readiness`를 호출했다. A를 입력·재사용 대상으로 가진 B를 승인하고 A의 질문·범위를 개정하자 A의 판본은 1에서 2로 바뀌었지만 B의 기존 승인과 ready 상태는 유지됐다. 승인 실행에 보존한 A의 전제와 현재 A는 달라졌다. 모델 호출은 0회다. 이는 실제 연구에서 B가 오승인됐다는 입증이나 전체 파견 경로 검증이 아니다. A 변경이 B 승인 전제에 영향을 주는 경우, A 종료 후 B를 파견하는 것만으로 승인 재사용의 현재성까지 보장되지 않는다는 연결 근거다. 기존 승인과 그 필수 근거의 판본을 연결하고 실제 사용 시 확인해야 한다.

실패 해소 함수의 제한된 검사에서는 서로 다른 준비 이유를 가진 같은 역할·대상 요청도 한 후속 성공으로 해소됐다. 실제 의미상 대체나 미소비 사건의 후속이 있을 수 있으므로 의무 유실을 확정하지 않았다. 다만 질문 ID나 표시만 고쳐서는 요청 해소의 정확성이 생기지 않으므로 재시도 계보·해소 근거를 함께 다룰 대상으로 남겼다. 가상의 새 provider_limit 종류는 기존 해소 함수에서 남았고 기존 execution_failure는 해소됐다. 이것은 현행 생산 오류가 아니라 새 분류의 소비자 연동을 확인한 시험이다. 기존 대기 종류에 원인을 붙여 재사용하는 선택도 가능하다.

기한 예고는 실제 사용자 정지와 구별해야 한다. 현재 수신은 정지 요청·일시 정지 뒤 돌아온 완료 응답을 보존만 하고 수락하지 않는 경로가 있으므로, 종료 전에 정상 제출을 돕는 예고를 같은 정지 효력으로 처리하면 의도한 수락을 막을 수 있다. 기존 체크포인트 요청을 재사용하되 예고 후 제출과 실제 정지 후 반환을 따로 검증해야 한다. 슬롯 반환의 실제 프로세스 종료 확인도 유지한다.

Lean 미리보기와 중앙 검사는 같은 verify_lean과 선언 이름 검사를 사용함을 새로 확인했다. 이 수정 때문에 별도 검증 절차를 만들 필요는 없다. 출처 안내·문헌 인계·모델 잠금·운영 집계·수리 판본·상태 표시는 기존 경로 안에서 다룰 수 있다. 입력 절감·계약 품질·오인 점검의 개선 효과는 측정 전 미확정이며, Claude 수집기는 최종 결과 선택 규칙과 사용량 의미를 확인해야 완료 판정할 수 있다. 공통 함수의 다른 소비자를 회귀 검증할 필요와 그 소비자의 절차 자체를 바꿔야 한다는 주장은 구별한다.

시험용 초기화 도구를 세션 예산 모드로 바꾸는 과정에서 구 실행횟수 모드의 model 인자를 함께 전달해 한 번 거부됐다. tier_models로만 배정하게 고친 뒤 같은 관측을 확인했으며 이 설정 실수를 제품 결함으로 집계하지 않았다. 원고 독해는 연구와 분리한 Opus 5만 사용했다. 원 실험 보조 스크립트는 `.skill-workspace/do-math-sufficiency-20260918/`, 원 독해 CLI 증거는 `.codex/writing-flow/`의 Git 제외 로컬 보관이다. 연구 정지와 기존 미커밋 수리는 그대로 두었고 실행기 구현은 변경하지 않았다.

실험 입력의 판본 일치, 실제 A 계약 변경과 B 계약 불변, 관측 결과, 코드 불변·참조를 포함한 검산 14개를 통과했다. 독해 4회는 보고된 사용 모델이 모두 claude-opus-5였고 최종 판본의 독해·합의 대조를 마쳤다. 최종 독해의 중심 이해와 남은 지적은 본문·독자 조건·평가 범위에 대조해 처분했다. 근거는 sufficiency-verification.json과 sufficiency-reading 계열 파일에 있다.
