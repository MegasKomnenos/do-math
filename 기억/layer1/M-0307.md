사용자는 주차 함수의 단봉성을 다루는 연구를 새 인스턴스로 시작시킨 뒤 반복되는 창과 호출·입력 수를 문제 삼았고, 이후 실행을 멈추고 재개하지 말라고 확정했다. 새 인스턴스는 `RI-01M2PZY54SEB1B0P140FTCPQQT`이고 `.skill-workspace/parking-unimodality-20260917/`의 별도 연구 저장소와 작업 공간에 있다. 그 폴더는 Git 제외 대상인 로컬 보관이다. 주 저장소의 스킬 수리는 연구 재개와 구별한다. 연구는 snapshot `fc178e3ed7f2ab3a84835ee8b516620d04f4effd`, HOLD `ddb615629ad343849c21133969d7f08a`, 사용자 pause를 유지하며 현행 예약 작업 두 개도 비활성이다. [[M-0295]]의 구 인스턴스·예약 이름과 혼동하지 않는다.

초기 효율 검토는 큰 입력과 비슷한 준비 결과를 관찰한 뒤 절차가 지키는 의무를 충분히 확인하지 않고 축소를 권했다. 사용자는 발생 이유와 주변 절차, 대안이 전체 실행에 주는 효과를 더 깊게 이해하라고 교정했다. 재검토 결과 빈 계획도 독립적인 전략 판단일 수 있고, 후속 준비가 새 계약을 만들지 않아도 기존 계약이 요청을 충족하는지 대조한 가치가 있을 수 있었다. 기존 입력 토큰을 전부 제거 가능한 낭비로 읽지 않는다. 현행 수리 판단과 검증 근거의 추적 진입점은 `docs/do-math/efficiency-repair-2026-09-18.md`와 같은 이름의 JSON이다. 상세 최초·재검토 보고서 및 작업 로그는 `.skill-workspace/do-math-efficiency-review/`, `.skill-workspace/do-math-repair/`의 미추적 로컬 자료다.

실제 초기 왕복은 시작 전 학술 요구 등록이 계획 요청을 만들고, 최초 준비와 병렬로 시작한 계획에 그 준비의 업무 정보가 없으며, 계획이 새로 요청한 준비 의무를 실행기가 보수적으로 보존한 경로에서 생겼다. 준비·계획 전체를 직렬화하거나 후보 0개인 계획을 금지하면 정상 진행을 막는다. 수리는 초기 등록으로 생긴 계획만 첫 판단 자료를 기다리게 하고, 첫 ready·반환 결과·준비 실패·빈 결과·반려·새 사용자 판단에서 풀리게 했다. 요청·사건은 보존한다. 공개 준비 정보는 미공개 결론과 구별하고, 미시작 요청의 이유·사건·사용자 출처를 합치되 시작·정지 중 실행의 입력에는 합치지 않는다.

Git 호출은 같은 자료와 저장 보증을 유지하며 묶었다. 실제 원자료 38개 읽기는 38회에서 1회로, 별도 저장소에서 그 원자료와 상태 두 파일을 저장하는 Git 프로세스는 50회에서 11회로 줄었다. 무변경 저장에서는 `runtime/state.json` 최상위의 `updated_at`만 비교 대상에서 제외하며 실제 상태나 artifact 변경을 저장한다. 준비 평가 내용이 같으면 평가 시각도 유지해야 대기 커밋이 계속 생기지 않는다. 설치 해시는 반복 순회의 주기를 제한하되 입력·실행·수신 경계에서는 다시 검사한다. 입력 준비 중 정지에는 미공개 폴더만 정리하고 실행을 시작하지 않으며, 다른 진행 중 실행의 시작 알림·진행 관찰도 처리 과정에서 상태 저장을 만들 수 있다. 그 알림 때문에 새 입력을 반복 폐기하지 않도록 입력 준비 중에는 사용자 제어만 따로 확인한다. 모델을 시작하기 전 최초 정지 확인에서 체크포인트 유예가 적용되던 경계도 재현해, 시작 전에는 즉시 중단하고 수행 중에는 유예를 유지하게 했다.

첫 창 수정은 Python 대역의 콘솔 핸들과 실제 Git 바이트 보존만 확인한 상태였다. 이번에는 실제 Git 응답·자손 계보·콘솔 연결·가시 창 검사와 숨긴 콘솔의 양성 대조를 추가했다. 연구 재개를 통한 전체 사용자 경험 재검증은 수행하지 않았다. Lean 실행기는 공식 4.32.0 배포본을 로컬에 준비했고, 같은 지급 검증 코드·구성 명령의 사전 검사로 오류를 고칠 경로를 추가했다. 사전 검사 결과는 권위가 없으며 중앙이 정확한 제출 소스를 다시 검사한다. 공유 라이브러리·Lake 캐시까지 동일하게 격리했다고 주장하지 않는다.

최초 전체 회귀는 시험용 Popen을 함수로 바꿔 표준 라이브러리의 상속을 깨뜨렸고, 다음 실행은 시험용 메모리 저장소에 새 배치 읽기 인터페이스가 없어 오류를 냈다. 이 실패들은 원 결과에 보존하고 검증 실행기·대역을 고친 뒤 다시 검사했다. 검증 보조 코드의 실패와 실제 제품 결함을 분리하되 둘 다 통과 전에 해결한다. 공통 문서 축약·검토 단계 통합·동일성 범위와 인원 축소·상태 불변을 근거로 독립 점검 생략은 동등성 근거가 없어 채택하지 않았다. 비용 관찰에서 보증 축소로 넘어가기 전에 절차의 목적과 대안의 전체 영향을 대조하는 위치가 이번 사용자 교정의 재발 방지 지점이다.
