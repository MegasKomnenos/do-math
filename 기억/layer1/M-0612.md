## 맥락

사용자가 `/grill-me`로 do-math에 두 기능을 요청했다. 하나는 연구 인스턴스마다 `glossary.md` 용어 정본을 두어 세션들이 하나의 용어에 하나의 의미만 쓰게 하는 것이다. 다른 하나는 해결에 묶이지 않은 느슨한 탐구 작업과 scholarly-mcp 기반 문헌 조사 작업을 파견하는 것이다. 구체 방법은 AI가 제안하라고 했다. 스킬 폴더의 문서 8개, 코드 4개, 시험 5개를 직접 읽은 뒤 결정을 하나씩 확정했다.

**사용자가 확정한 결정**
1. 용어 정본의 작성자는 계획 세션 하나다. 매 계획이 `glossary.md`를 공개하고, 연구·탐구 세션은 `glossary-proposals.md`로 제안만 한다. 계획은 한 번에 하나만 돌므로 정본 갱신이 충돌하지 않는다. 세션이 공유 파일을 직접 고치는 안은 "세션은 자기 폴더에만 쓴다"는 불변식을 깨고 갱신 분실을 낳으므로 배제했다.
2. 정본의 범위는 수학적 대상과 기호뿐이다. AI는 명제 라벨(T, P, R, I3 같은 것)까지 넣는 안을 추천했지만 사용자는 대상·기호만 골랐다. 명제 라벨은 연구 현황이 계속 관리한다.
3. 항목 칸은 이름·기호, 종류, 정의, 잘 정의됨, Lean 대응, 출처, 기록별 이명이다. 이름은 재사용하지 않고, 정의 의존 순서로 배열하며, 동의어를 두지 않는다.
4. 검토는 결과마다 `terminology: conforms | deviates`를 판정한다. AI는 의미 위반만 판정에 반영하는 안을 추천했다. 사용자는 이름 위반까지 판정에 반영하되, 판정 때문에 이전 결과를 다 버리고 다시 하는 극단적 대응은 하지 말라고 정했다. 그래서 `terminology`를 별도 판정 축으로 두고, 상충 판단과 근거 사슬 전파에서 제외했다. `assessment`에는 논증을 깨는 의미 위반만 반영한다.
5. 별칭은 그 별칭이 쓰인 옛 기록을 읽기 위한 기재일 뿐이다. 이후 작업에서 쓰면 이름 위반이다. 이 점을 정본 머리말과 `common.md`에 명시하라는 것도 사용자 지시다.
6. 탐구는 문제의 요소 해결에 묶이지 않고 문제와 천천히 친숙해지며 이해의 지평을 넓히는 작업이다. 연구 초기, 그리고 물러서서 큰 시야가 필요할 때 낸다. 검토는 붙이지 않고 진술마다 인식 지위를 표시한다. 새 범주 `explore`와 작업맥락 `explore.md`로 두었다. 종료 기준은 포화다.
7. 근거로 쓸 문헌 조사는 `research`로 내어 자동 검토를 받는다. 영감을 얻으려는 읽기는 탐구 안에서 한다. scholarly를 모든 범주의 기본 도구로 바꾸었다. 외부 문헌에서 가져온 내용은 원문을 다시 읽지 않고도 이해하고 이어서 쓸 수 있게 옮겨 적으라는 규칙도 사용자가 더했다.
8. 기존 주차 함수 인스턴스는 재개하지 않는다. 같은 연구를 새 인스턴스로 다시 시작할 예정이다. 그래서 옛 기록 호환 장치(`terminology` 없는 검토의 "용어 미확인" 처리)를 두지 않았다.

**변경**
- `check.py`: `explore` 범주, 계획의 필수 `explorations` 배열, `exploration_finished` 사건(대상이 탐구 기록인지), 검토 결과의 필수 `terminology`를 검사한다.
- `runner.py`: 탐구 요청을 `<계획>:explorations:<i>`로 게시하고, 탐구가 반영되면 자동 검토 대신 `exploration_finished` 사건을 만든다. `defaults.explore`를 필수로 읽는다. 최신 계획의 `glossary.md`를 색인에 연결한다.
- `knowledge_index.py`: 용어 정본 링크, "탐구" 표시와 검토 없음 문장, 용어 판정 개수(상충 계산 제외)를 낸다.
- 문서: `common.md`(용어 정본·문헌 절 분리, 탐구 기록 읽기), `plan.md`(용어 정본 갱신하기, 탐구와 문헌 조사를 내기), `research.md`(문헌을 조사하기), `review.md`(정본 용어의 준수 판정하기), `explore.md` 신규, `protocol.md`·`RUNTIME.md`·`SKILL.md`의 계약 갱신. `.agents/` 사본은 생성기로 재생성했다.
- 시험: 신규 6개를 먼저 실패시킨 뒤 구현했다. 전체 38개 통과.

## 터득한 것

**scholarly 미사용의 원인을 잘못 추정한 교정.** 실행 중 인스턴스의 Codex 세션 166개 로그에 MCP 호출이 0건이고 `web_search`가 114건인 것을 보고, AI는 인스턴스 자체 `.git` 때문에 저장소의 MCP 설정이 세션에 닿지 않는다고 추정해 사용자에게 제시했다(ⓐ 거부된 기본값). 사용자는 쓸 수 없어서가 아니라 사용하라는 지시가 없어서라고 정정했다(ⓑ). 실제로 옛 `common.md`는 scholarly를 "제공되면 쓰고 없으면 웹 검색"이라는 조건부 선택지로만 적고 있었다. 사용 흔적이 없다는 사실에서 도구가 없다는 결론으로 건너뛰면서, 그 도구를 쓰게 한 지시의 문면과 직접 가용성 확인을 둘 다 거치지 않았다(ⓒ). 다음에는 도구 미사용의 원인을 판단하기 전에 지시가 그 도구를 요구했는지부터 읽고, 가용성은 직접 호출로 확인한다(ⓓ 교정 위치: 원인 추정을 사용자에게 제시하는 단계).

**검토 없는 범주는 활성 성질을 따로 확보해야 한다.** do-math의 계획은 사건이 있을 때만 뜬다. 연구 반영은 자동 검토를 만들고, 그 검토의 반영이 사건이 된다. 탐구에서 검토를 빼면 탐구 반영이 아무 사건도 만들지 않는다. 그러면 계획이 탐구만 게시한 경우 실행기가 영원히 쉰다. 실패하도록 먼저 쓴 실행기 시험이 바로 이 정체를 보였고, `exploration_finished` 사건을 더해 해결했다.

**정본 판본의 시점 문제.** 정본은 계획마다 갱신되므로, 검토가 현재 최신본과 대조하면 작성 뒤에 개명된 이름을 작성자의 위반으로 오판한다. 검토는 대상보다 앞서 공개된 마지막 계획의 정본과 대조하고, 더 앞선 판본에서 정본이었던 이름은 위반이 아니라고 정했다. 제안 처리도 "직전 계획 이후 공개된 기록"이 아니라 정본 안의 '처리한 제안 기록' 목록으로 추적한다. 계획 실행 중에 공개된 기록을 기간 기준은 놓치기 때문이다.

**계약 문면 사이의 숨은 모순 하나.** `common.md`는 정본 이름을 다른 뜻으로 쓰는 것 자체를 금지하는데, 처음 쓴 검토 기준은 "차이를 밝히지 않은 경우"만 의미 위반으로 잡았다. 차이를 밝히고 정본 이름을 다른 대상에 쓴 경우를 이름 위반으로 분류해 맞추었다.

**`explore.md`의 독립 독해.** 1차 독해가 지위를 붙일 진술의 단위, 짧은 논증과 증명 시도의 경계, 포화 판정 시점을 어려운 대목으로 짚었고, 고친 뒤 2차 독해에서 어려운 대목이 0이 되어 `accept`했다. 독해 자료는 `.codex/writing-flow/claude-domath-explore-20261023/`와 `임시/do-math_탐구문서_20261023/`에 있다. 둘 다 Git 제외 로컬 자료다.

**도구 함정.** Bash heredoc 안의 Python 문자열에 `\n`과 `'''`가 섞이자 셸이 따옴표 짝을 잘못 읽어 편집 스크립트 전체가 실행되지 않았고, 다른 경우에는 `\n`이 실제 줄바꿈으로 들어가 시험 파일이 문법 오류가 났다. 긴 치환 편집은 임시 디렉터리의 `.py` 파일로 써서 `python -I`로 실행하는 편이 안전했다.
