# 검증런 2.7.20 완주 — 원장 E^NP 코드 스팬 잔존 1건 수리, 절차 전체 자체 운전

## 맥락

행 `2.7.20`(파견문 `.sdd/dag/pvsnp-탐사-1/행/2.d/7.d/20.md`)은 행 `2.7.19`가
`source-ledger.md`·`records/L01.md`~`L11.md`에 적용한 82건 후보(원장 30건·
기록 51건·URL 1건)의 LaTeX 변환·URL 보존·좌표 동문성을 독립 검증하는
{경량} 검증런이다. 파견문 추가 지시에 따라 이 세션이 verify-rounds 절차
전체(0단계 동결부터 종료 보고까지)를 자기 컨텍스트 안에서 직접 운전했다 —
절차를 단일 서브에이전트에 위임하지 않고, 개별 수리자·심사자 파견만
codex exec(`gpt-5.6-terra`)로 내보냈다.

0단계 전 확인에서 산출물 대상 12건(원장 1 + `L01`~`L11`) 중 8건이 워크트리에
미커밋으로 인계돼 있었다(대행 커밋, `M-0032`). `19-보고.md`의 편집 귀속
표를 실측해 실제 편집 파일이 8건(원장 + `L01`·`L03`·`L04`·`L05`·`L06`·
`L09`·`L10`)뿐임을 확인하고, 동결문 「산출물」 절을 그 8건으로 좁혔다.
`L02`·`L07`·`L08`·`L11`은 후보가 0건이라 대상에서 뺐다. 메인 저장소
파일인 `19-보고.md` 자신은 `기준 원문` 절로 옮겼다(M-0019·M-0021 산출물/
정본 분할의 네 번째 재사용).

「수리 관점:」 슬롯이 파견문에 없어 영역·관점 배분은 재량으로 정했다.
대상 8파일 합계가 419행으로 작아 수리자 3기 전원을 관점 담당으로
배정했다(수리_관점기수 3, 영역 없음) — 관점은 LaTeX 변환 완전성 / URL
예외와 축자 인용 보존 / 좌표·내용 동문성 셋이다.

라운드 1(라운드_하한=라운드_상한=1)을 실행했다. 관점 1(LaTeX 변환
완전성) 담당 수리자가 항목 1건(`R1-01`)을 냈다 — `source-ledger.md` 27·
28행(L09·L10 행)의 `E^NP`가 코드 스팬으로 남아, 같은 값이 이미
`\(E^{NP}\)`로 전환된 `records/L09.md`·`L10.md` 본문과 표기가 갈리는
결함이다. 다른 두 관점 담당은 결함 0건을 보고했다. 항목 1건은 교차·결합이
없어 병합을 거치지 않고 바로 심사로 갔다. 심사자 2기(codex
`gpt-5.6-terra medium`)가 독립으로 모두 승인해 정족 2/2로 확정, 적용
1건. 적용 뒤 `git diff --check`와 `E^NP` 잔존 재검색으로 불변식을
재실측해 위반 0건을 확인했다. 라운드 판정은 순서 3항(라운드 수 1 ≥
상한 1)으로 종료했다. 기각 보관 0건
(`기각보관/2.7.20-라운드1.md`, 파일 실재·본문 「없음」). 발견 항목
0건이므로 검토전개 행을 등재하지 않았다.

라운드 커밋은 워크트리 `f1071aa`(산출물 1건), 메인 저장소는 이 노드가
담당한다(동결·장부·종료보고·파견표 상태 갱신·기각 보관 신규 1건 + 이
메모리 노드·색인).

## 터득한 것

- 82건 후보 중 81건 전건이 이미 LaTeX으로 전환됐다는 앞선 보고(`19-보고.md`)
  의 자기 판정은 산출물 파일들 사이의 상호 참조 불일치(원장 요약 행과
  기록 본문이 같은 수식을 다르게 표기)를 놓쳤다. 검증런의 관점별 독립
  수리자 배분(같은 파일 집합을 다른 렌즈로 훑는 것)이 이런 파일 간
  불일치를 잡는 데 파일별 영역 분할보다 유리했다 — 영역 분할이었다면
  한 수리자가 `source-ledger.md`만, 다른 수리자가 `records/L09.md`만
  봐서 둘을 대조할 기회가 아예 없었을 것이다.
- 작은 산출물(773행/12파일, 실편집 419행/8파일)에서는 수리_관점기수를
  수리_기수와 같게 잡아 전원 관점 배분하는 것이 영역 분할보다 재량으로
  더 나은 선택일 수 있다 — 영역 분할은 산출물이 커서 한 수리자가 전체를
  통독하기 비쌀 때의 절충이지, 통독 비용이 낮으면 전원 관점이 교차
  검증 범위를 넓힌다.
