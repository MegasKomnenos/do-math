사용자는 학술자료-MCP-구현-인계.md에 따라 검색·확보 MCP를 구현하도록 지시했다. 작업 중 KUDOS 로그인 뒤 학술DB 바로가기로 기관 프록시에 접속하도록 교정했고, 공개 API는 별도 API 이용 자격 없이 호출할 수 있는 API라는 의미를 확정했다. 앞서 API 문서가 공개된 경우까지 포함해 Scopus·Web of Science의 추가 키를 질문했던 해석은 폐기했다. 키·승인·계약을 따로 요구하는 API는 선택에서 제외하고 해당 자료원에는 Playwright 경로를 구현한다. API의 실행 오류를 브라우저 전환 조건으로 삼지 않는 계약은 유지한다. 이 기준은 새 서버 README·registry와 별도 API 자격 입력이 없음을 검사하는 테스트에 반영했다.

구현은 services/scholarly-mcp에 있다. 다섯 stdio 도구, 내용주소 자료 보존·재열람, 기계적 추출, 상태 구별, 자료원별 사용 설명을 제공한다. Python 3.12 전용 환경과 MCP SDK 1.30.0을 사용했고 .mcp.json과 .codex/config.toml에 scholarly를 등록했다. 기존 연구 수집 코드와 산출물은 수정·중단하지 않았다. BibTeX·RIS 파서는 기존 보존형 파서를 호출하며 그 catalog 작성기는 실행하지 않는다. 전역 Python 환경은 바꾸지 않았다.

실제 MCP 흐름으로 MathSciNet의 KUDOS 프록시 검색·BibTeX·리뷰 PDF·추출, Web of Science의 Core Collection 검색·전체 서지와 인용문헌 export, ECCC의 revision별 초록·PDF, ACM의 제목 검색·서지 export·1971년 원 논문 PDF를 확인했다. Crossref·arXiv·zbMATH의 MCP 검색·추출과 GitHub·Numdam·Software Heritage의 어댑터 호출도 별도로 확인했다. 공통 검사 36개가 통과했다. 정확한 범위와 증거 위치는 services/scholarly-mcp/VALIDATION.md가 소유한다. 나머지 어댑터와 추가 기능은 개발·검증 중이며 전체 완료나 모든 옵션의 검증으로 보고하지 않는다.

MathSciNet은 빈 저장 상태가 아니라 만료된 기존 세션이었다. 정상 로그인과 새 context 재사용을 확인했고, 서버 전용 상태는 .credentials/scholarly-mcp에 둔다. Web of Science 기본 바로가기의 옛 진입점 대신 같은 Core Collection을 여는 실제 CPCI 바로가기를 확인했다. Chromium에서 접근 확인 화면이 나온 Scopus·ACM·IEEE는 기본 Firefox에서 정상 화면에 도착했고 PQDT도 같은 경로가 열렸다. 정상 화면 도착과 실제 검색·export의 통과는 별개다.

ACM의 새 세션에서는 서버의 citation 응답이 정상인데 페이지의 UX.CSL 초기화와 관련 script chunk가 실패하여 미리보기가 Loading에 머물렀다. 응답·페이지 오류를 확인하기 전에 기다림이나 선택자를 바꾸는 수리는 원인을 해결하지 못했다. 실제 UI가 수신한 원 서지·CSL 스타일·locale과 자료원의 처리기를 보존하고, 외부 통신을 막은 렌더 페이지에서 기계적으로 export하여 새 MCP 세션의 흐름을 통과시켰다. 검색 결과의 1971년 원 논문과 2023년 재수록본은 별도 DOI·연도로 유지한다.

표현의 존재를 데이터 보존으로 오해할 수 있는 사례도 확인했다. Web of Science는 실제 18건의 응답 중 화면에 한 카드만 렌더링되어 있었으므로 카드 수로 결과를 세지 않는다. HTML form 전체를 지우면 ACM의 검색 결과도 함께 사라져 form은 해체하고 본문을 보존하도록 바꿨다. URL 정제가 BibTeX의 닫는 중괄호를 먹는 실패와, JSON 원 파일의 수치·공개 예제 필드가 정규화·정제로 달라지는 실패도 검사했다. 코드·압축 내부 파일의 원 바이트 보존을 인터페이스 응답 정제와 구별한다. 공개 commit 서명과 페이지 cursor를 인증 비밀로 오분류하지 않는다.

Software Heritage는 숫자 offset을 조용히 무시해 첫 페이지를 반복했다. 서로 다른 offset의 실제 반환을 대조한 뒤 서비스의 page_token을 MCP cursor로 연결하고 서로 다른 두 페이지가 회수되는지 확인했다. 0건·제한·실행 실패·개발 중 상태를 구별하는 것과 함께, 성공 응답의 범위가 요청과 맞는지도 실제로 대조해야 한다.

이 커밋은 진행 중인 구현의 보존 단위다. API 호출 제한·접근 확인 화면과 아직 구현·시험하지 않은 기능을 구별하여 후속 작업을 계속한다. 로컬 data와 전용 가상환경은 Git에서 제외하며, 실서비스 자료를 이관할 때는 data 전체와 해시 참조를 함께 보존한다.
