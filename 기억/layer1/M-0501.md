[[M-0500]] 뒤 원문 A-19와 현행 실행 경로를 대조했다. 조사/결함-A.md의 A-19는 과거 입력 준비 중 또는 모델 시작 전에 실행 중 체크포인트 유예를 적용하던 문제였다. 현재 call_engine._call_stop_requested는 체크포인트를 immediate=true와 현재 UTC deadline으로 요청하고 정지를 즉시 반환한다. model_runner는 resume 전에 should_stop을 검사해 실제 provider resume 없이 종료시키고, 실행 중에도 should_stop 또는 유한 호출 기한으로 중지한다. 현재 README는 전체 run 기한을 두지 않는다. 과거 유예와 run 상한은 검사를 채우려고 다시 구현할 기능이 아니다.

기존 sim.test_engine_queue의 세 정지 검사를 강화했다. 입력 준비 중 공개 pause는 모델과 Job 시작 0회, started_at 없음, 새 run 디렉터리 없음에 더해 주입 단조 시각이 전혀 진행하지 않음을 검사한다. Job이 보고됐지만 모델 resume 전인 경계는 정지 콜백 반환 중 단조 시각 불변, 실제 execution.stop_observed_at과 stop-request.json의 deadline이 현재 UTC에 일치하고 immediate=true임을 확인한다. 실행 중 정지는 같은 즉시성에 더해 1밀리초 뒤 반복 정지에도 최초 stop_observed_at과 stop-request 바이트가 보존됨을 확인한다. 정지 경과를 검사하려고 실제 대기나 hard timeout을 추가하지 않았다.

기존 세 검사 강화 후 focused 3개가 8.2초에 통과했다. 같은 소스의 구조 47개·단위 54개·Sim 34개, 합계 135개가 49.5초에 완결 통과했고 changed_during_run은 없다. 실제 provider pre-start stop, 무기한 작업의 정상 완료와 정지, 유한 운영 호출 기한도 포함됐다. 관찰 국면·자기 점검·호출 창의 기존 검사도 유지했다. 예산 초과 8개는 소프트 정보다. 추적 근거는 검증/2026-10-04-정지-시간-국면/focused.json과 report.json이며 최종 원보고 SHA256은 6e75c7d83a7c0e1e678fe3a9a9b7d05ec4b20bb1e584597ab506da622ae142db다.

이번에는 제품 함수를 더 나누거나 비슷한 시나리오를 별도 모듈에 늘리지 않고, 이미 실제 정지 경계를 통과하던 검사에 누락된 관찰과 결과 단언을 넣었다. 6-A 전 시간 규칙·모든 원문 의무가 닫혔다고 선언하지 않는다. 같은 판본의 전체 일반 회귀는 마지막 전건 실패 이후 아직 확정하지 못했으므로 이 검수 커밋 직후 새 출력에서 실행한다. 실행 동안 소스를 고정하고 다른 시험을 동시에 시작하지 않는다. 전체 성공 여부는 실제 원보고만 판단하며 이전 부분 통과들의 합으로 만들지 않는다. 최종 목표와 fresh T3, 전 함수 변이, 실제 T4/T5 관문은 계속 미완료다.
