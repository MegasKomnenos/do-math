Semantic Scholar의 bulk 원1000건 응답을 호출자 limit 초과라고 버리던 오류를 수리했다. 공식 API에는 limit 파라미터가 없으며 최대1000건과 다음 token을 보낸다. 구현은 원 batch를 artifact로 보존하고 호출자가 요청한 구간만 반환한다. 같은 batch의 잔여 위치와 다음 native token은 query/options/export에 결속된 불투명 cursor로 연결한다. raw native token을 직접 입력하면 결속 검사를 우회할 수 있었으므로 이를 거부하고 cursor version을2로 올렸다.

독립 검토는40자리 paperId의 잘못된 형식, 페이지 안의 중복과 앞 페이지의 중복을 찾았다. 대소문자를 통일해 ID를 대조하되 원 레코드는 바꾸지 않는다. ID 목록을 매 cursor마다 복제하면 작은 창 순회에서 저장량이 불필요하게 커지므로 native page마다 immutable history node를 하나만 둔다. 순차 호출은 adapter-local cache로 이미 읽은 이력을 재사용하고, 새 adapter나 오래된 cursor 분기는 artifact lineage를 읽는다. 검증 실패가 cache를 오염시키지 않으며 terminal 결과에서는 해당 cache를 해제한다. 원본에서3실패·17오류를 먼저 확인했고24검사가 통과했다.

식별자 fetch는 공식 batch에 ID 하나만 보내고, 이름은 title-match의 최대 한 후보로 돌려준다. 후자는 relevance 후보 집합과 같다고 주장하지 않으며 selection_required로 남긴다. 필요한 parts에 맞춰 fields를 구성한다. 원 BibTeX가 DOI를 생략하면 원 metadata 제목과 파싱된 제목을 정규화해 대조하며 불일치 원 파일도 보존한다. fulltext의 not_offered는 Graph API가 파일 bytes를 제공하지 않는 범위의 의미다. 외부 openAccessPdf를 자동 방문하지 않고 모든 S2 문헌의 PDF 부재로 확대하지 않는다.

새 원본 SDK는 bulk HTTP200 두 번, 각1000개 원 레코드,1/998/1 창의 고유·정렬된1000ID와 같은 evidence, 다음 token의 새 evidence 및 다음ID를 확인했다. 남은 한 행에서 limit2를 주면 received1과 has_more=true다. 따라서 limit은 현재 native batch 안의 상한이며 다음 batch까지 채우지 않는다고 guide를 고쳤다. 원 total38,345는 추정값이다. 이 실행의 natural AND proofs는 페이지 동작만 검증한다. root가 검색식 문법을 다시 검토했고 공식 문서가 +/|/-를 AND/OR/NOT로 정의함을 독립 확인했다. word AND를 문서화된 연산자로 해석하지 않는다. guide 예제는 natural + proofs이며 caller query 자체는 변환하지 않는다.

ID 하나를 담은 요청을 대조했고 Retry-After·rate 헤더는 없었다. 독립 세션은 local SDK console이라고 표시한 전후·안정12이미지와 실제 JSON 오류를 직접 읽었다. 오류는 기다리거나 더 높은 한도의 키를 신청하라는 안내이며 키 필수·문헌 부재를 입증하지 않는다. 새 키나 fallback은 사용하지 않았다. 사본의 앞선 batch·281바이트 BibTeX·30references 양성 이력과 최신 원본 제한을 별도로 보존한다.
