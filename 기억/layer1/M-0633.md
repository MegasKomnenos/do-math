## 맥락

두 번째 전면 라운드에서 12항목을 제기했고, 병합 뒤 10항목 중 9항목이 세 심사자의 승인을 받았다. 장부는 구성 항목 기준 11행을 적용으로 센다. 역할별 문서·전체 용어집 전달과 build ID 형식 증거, 탐구 주기의 시험을 보강하고, 재시도 우선순위·보존 실패의 재개·게시판의 생산 세션 식별·Lean 모듈 헤더 탐색을 고쳤다.

## 검증과 실제 도구의 차이

전체 108시험과 미러 검사가 통과했다. 그러나 실제 Lean 4.32로 실행한 별도 검사에서는 새 결함을 확인했다. 모듈 헤더 수정 뒤 최초 두 모듈 빌드는 성공했지만, 의존 모듈을 캐시에서 가져와 대상을 새로 컴파일하면 Basis.olean.server가 없어서 실패했다. 실제 컴파일러는 .ir, .olean, .olean.private, .olean.server를 만들었다. 기존 제어된 컴파일러는 이 산출 묶음을 표현하지 않았다. 시험 초록이 실제 도구 계약을 보증하지 못한 구체적인 사례다.

## 계속할 작업

다음 라운드는 이 관찰과 재현 코드를 원자료에 추가해 검토한다. 원자료 추가는 기대 결함을 추정해 지정하는 것이 아니라 실제 관찰을 독립 판단에 제공하는 변경이며 장부에 입력 변경의 판단을 남긴다. 취소 경합 수리는 전 모듈 캐시 적중 경로를 해결하지 못해 기각됐다. 첫 라운드의 빌드 실패 상태 문제도 미해결이다. 실제 실행 결과는 Git 제외 로컬 파일 `임시/do-math_검증_20261105/sources/lean-4.32-observation.json`에 보존되고 핵심 사실은 이 노드와 추적 장부에 남는다.
