[[M-0482]] 뒤의 B68은 역할 요구 표를 live·종료 운영 근거, 추가 목표 감사, 검토 개정·같은 자리 복구로 확장한다. 같은 흐름을 새로 복제하지 않고 기존 검사에서 실제 입력 포장 반환을 관찰한다. 요구 좌표를 고정 객체 필드뿐 아니라 목록의 각 항목까지 순회하도록 `[]` 표기를 지원한다. 현재 소비자는 새 context 필수 인자를 사용하며 구형 호출 래퍼나 기본값 보충을 남기지 않는다.

운영 점검의 `operational_evidence`는 checkpoint_status·checkpoint_source·checkpoint_files·미수집 범위·실행 상태·source_snapshot을 제공해야 한다. preserved이면 정확한 파일 참조의 local_path·sha256·bytes를 요구한다. 종료 진단의 대상 실행이 artifact_bundle을 갖는 경우에는 recovery_materials의 실행 ID·snapshot·체크포인트·결과·종류·실제 최종 결과 상태·산출 파일을 요구한다. live에 종료 진단 자료를 임의로 넣거나, 체크포인트가 없다는 사실을 진전 없음으로 바꾸지 않는다.

목표 감사의 additional_audit_input 전 항목에서 감사 계약·원자료·입력 해시를 확인한다. eligible_knowledge 전 항목에서는 형식 검사와 동일성 판정, 선언·타입·공리·소스 해시를 확인한다. 모든 역할은 snapshot·실행 프로필·기록 지도와 색인을 제공한다. 이 선언은 입력 내용의 수학적 진위를 승인하는 것이 아니라, 계약이 요구한 근거가 실제 제공되고 보존된 원문으로 도달할 수 있다는 요구다.

공통 검사자는 필요한 루트가 참조로 축소돼도 카탈로그의 정확한 행을 확인하고 바이트를 회수한 뒤 좌표를 읽는다. 단일 파일과 파일 목록을 모두 읽으며, 복구 실패 진단이 있는 행에는 local_path가 없어야 하고 오류 종류·이유·관찰 해시·관찰 크기가 있어야 한다. 읽지 못한 원문을 성공한 참조로 위장하지 않는다. 기존 손상 제출 진단 흐름에 이 검사를 연결했고 `wfg474xa`의 한 사례가 11.1초에 통과했다.

관련 13개 검사는 `wxotp7y7`에서 26.2초에 통과했다. live 체크포인트의 원문과 종료 후 산출은 서로 다른 시점의 바이트일 수 있다. 기존 checkpoint persistence 검사는 첫 캡처의 proof.txt가 original evidence이고, 종료 산출은 changed after checkpoint임을 계속 확인한다. 새 검사도 이 차이를 보존한다. 추가 감사 입력의 원래 독립 소비·거부 검사를 유지하면서 실제 전체 context와 포장 결과의 요구 좌표를 대조했다. 제한 복구가 사용자 pause를 유지한 채 필요한 입력만 받는 기존 흐름에도 연결했다.

검토 자리 복구의 첫 보강은 `2fohdg0p`에서 실패했다. 실제 복구 생산자를 직접 호출한 뒤 해소 상태를 게시하지 않아 다음 소유자 회차가 저장된 옛 상태를 다시 읽었다. 제품이나 대기 판정을 바꾸지 않고 바깥 제어 소유자가 하는 save를 시험에 반영했다. 같은 review_cycle·stage·slot의 실제 입력 재지급까지 조건과 상한을 두어 진행한다. 복구와 개정의 두 사례가 `3moqppf5`에서 51.9초에 통과했다. 새 판본의 보충 조사 흐름은 이전 조사 답을 다시 읽고 previous_revision이 포함된다는 기존 단언을 유지한다. 단순히 새 검토가 발생했다는 사실로 이전 근거 재사용 검증을 대신하지 않는다.

편집한 두 시험의 CRLF를 LF로 정리하며 AST 동일성을 확인한 뒤, 현재 같은 판본의 관련 모듈 전건과 전체 구조를 한 번 실행했다. `e327rt5w`는 structure 44개·unit 20개·sim 55개·flows 49개, 합계 168개가 268.7초에 완결 통과했고 실행 중 변경은 없었다. 개별 예산 초과 12개에는 새 판본 currentness 흐름 84.922초와 기존 이의·답변 흐름 73.016초 등이 포함된다. 이 시간은 일반 관련 범위 실행이며 전체 T2나 fresh T3 예산 충족으로 해석하지 않는다.

원보고는 추적된 `검증/2026-10-04-운영-감사-입력/report.json`에 보존하고 B68에 현재 파일 지문·명령·모집단·제약을 연결한다. 중간 Temp 보고는 로컬 보관이며 영구 보존을 가정하지 않는다. 사용자 진행 문서, 기존 미추적 교차 시험, 보존·후보 작업 트리는 이번 변경에 섞지 않는다.

역할 입력 요구의 일반 진입 및 주요 단계·복구 변형은 이제 실제 생산·포장·기존 흐름에 연결됐다. 다음은 3-B 전체 모집단의 선언과 소비·누락 검사를 원문 계약별로 확인하여 종료 가능한 범위와 남은 범위를 구분하는 것이다. 부분 실행이나 원장 0open으로 전체 목표를 닫지 않는다. 원래 19의무·61보존 지식·P2 12항목·여섯 부류·2단계 11의무, 최종 같은 판본의 전체 T2/flows와 실행 예산, fresh T3·전 대상 함수 변이, T4/T5 최소 실호출·말뭉치·최종 지침·미러·main은 계속 목표에 포함된다.
