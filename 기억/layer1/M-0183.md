CORE의 fullText에 담긴 공개 API 접근 안내문을 본문으로 표시하던 처리를 수리했다. 실제 원 검색 기록으로 결함을 재현했고, 실제 텍스트·빈 초록·잘못된 문헌 ID와 이름 후보 입력을 구별하는 검사가 통과했다. 공통 검사 154개가 통과했지만 신규 CORE 실서비스 흐름은 호출 제한으로 미완료다.

공개 API를 다시 확인했을 때 Semantic Scholar·OpenAlex·CORE의 natural proofs 검색과 두 항목 추출은 실제 MCP에서 성공했다. 이후 Semantic Scholar·CORE의 개별 fetch와 CORE의 이름 후보 조회는 다시 rate_limited였다. Retry-After 값은 제공되지 않았다. 이 상태에서 다른 전송 경로로 우회하거나 별도 API 자격을 요청하지 않았다. DBLP도 여전히 access_challenge였다. 성공한 검색과 제한된 후속 호출은 각각의 보고로 보존했다.

CORE의 원 검색 레코드 340524929, Deriving Safety Cases from Automatically Constructed Proofs에는 fullText가 Not available for public API users.라는 35자 안내문이었다. 기존 fetch는 이 레코드를 받으면 문자열이 비어 있지 않다는 이유로 fulltext available을 반환했다. 같은 원 레코드를 응답으로 사용하는 회귀 검사로 입증해 restricted/public_fulltext_restricted로 바꿨다. 실제 본문이면 별도 텍스트 artifact로 보존하고, 빈 필드·빈 초록은 해당 기록의 not_found로 처리한다. 원 metadata 필드는 그대로 남긴다.

CORE work URL·번호의 응답 ID를 대조하고, 이름 입력은 원 검색 후보와 selection_required로 반환하도록 연결했다. 그러나 이 신규 경로의 실제 MCP 재검증은 이름 조회 단계부터 rate_limited여서 완료로 세지 않았다. 공통 검사 통과와 실서비스 통과를 구별한다. 정확한 보고 파일은 services/scholarly-mcp/VALIDATION.md가 소유한다.

다음 단위의 OpenAlex 조사도 보존한다. 기존 docs.openalex.org 문서는 help.openalex.org로 이동했다. 현행 도움말은 기본 API의 별도 계정·키 없는 사용을 명시하며 실제 무인증 요청도 성공했다. 원 그룹 응답은 results가 아니라 group_by 배열이고 meta.groups_count는 전체 그룹 수가 아니라 현재 페이지 수다. 커서 페이지를 사용한다. 일반 개요의 최대 100건 설명과 달리 실제 per_page=200 요청은 200건을 반환했으므로 구현 상한을 문서 한 줄만 보고 줄이지 않았다. W2741809807의 abstract_inverted_index는 167개 단어 키를 가진 양성 표본으로 확보했다. API 입력·그룹·초록의 남은 구현은 이 실제 응답을 바탕으로 이어간다. 전체 완료 전이므로 푸시하지 않는다.
