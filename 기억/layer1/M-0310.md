사용자는 [[M-0309]]의 새 연구에 대해 전체 진행을 상세하고 직관적으로 정리하고 타임스탬프도 보여 달라고 요청했다. 현재 인스턴스의 고정 판본 c2021a0f9490cb6d16cc08778ef27e5703f54423에서 실행 169건(모델 167, 형식 검사 2), 과제 19개, 수락된 연구 수행 보고 14개를 추출했다. 추적 산출물의 진입점은 `research/problem-selection-2026-09-15/progress-2026-09-18/analysis.md`다. 같은 폴더에 역할·실패·검색 필터가 있는 시간축 HTML, CSV, 판정·시각·원 보고 경로를 연결한 evidence.json과 원 보고 사본을 보존했다. 보고서의 상태 기준은 2026-09-18 17:18 KST이며 이후 실행을 설명하지 않는다.

연구는 n≤500 단봉성 계산, n=80 로그오목성 반례, 앞 구간 √n 규모와 오른쪽 꼬리 log n 규모의 자연어 증명까지 진전했지만 일반 단봉성은 미해결이었다. 형식 정본은 정의·n≤5 결과와 누적 점화식 두 건이다. 완료 과제 12개를 증명 12개로 읽지 않으며, 부분·실패 보고를 완료로 허용한 계약과 필수 증명 의무를 남겨 미완료 판정·분할한 과제를 구별했다. 마지막 B4′ 수행의 결과는 수락됐지만 과제 완료 판정은 남았다.

분석 과정에서 14:02의 독립 운영 담당이 결과 수락 결함을 직접 수리한 사실을 확인했다. 운영 담당은 거부 35건을 인용 과제의 정상 생애 전이 32건과 지식 reviewing→verified 전이 3건으로 보고했고, 인용 과제 대조만 좁혔다. **정정([[M-0311]]): 입력·거부 판본의 직접 대조 결과는 과제의 계약·기존 결과·종결 여부가 유지된 변화 26건, 인용 계약 변경 6건, 지식 검증 승인 변화 3건이다. 마지막 3건 중 2건에는 과제 종결도 겹쳤다. 원 운영 보고의 32건 분류는 부정확했다.** 전체 실패를 불필요한 낭비로 일반화하지 않는다. 기존 코드의 실패 재현과 수정 후 회귀 로그를 직접 읽었다. 로그의 457건은 1건 건너뜀을 포함하므로 실제 통과는 456건이다. 수리 정본·사본 8개 파일은 분석 착수 때 이미 미커밋이었으며 이번 보고 커밋에 섞지 않았다. 상세 운영 수리·호출 원 로그는 `.skill-workspace/parking-unimodality-opus5-20260918/work-v2/operator/`의 Git 제외 로컬 보관이므로 정리로 사라질 수 있다.

15:34~15:37의 내부 실행 16건과 16:02의 별도 운영 점검은 Claude 세션 한도 응답으로 실패했다. 연구 슬롯은 비어 있었고 사용자가 정지한 상태도 아니었다. 한도 초기화 안내는 18:20이며 다음 운영 예약은 18:02였으므로 초기화 직후 재개를 보장하지 않았다. 분석용 독립 독해도 Opus 5만 호출했으나 같은 한도로 실패해 writing-flow를 blocked로 남겼다. 원장·시각·집계·파일 해시 대조는 통과했고 독립 독해는 미완료임을 본문·검산 기록에 표시했다. 실패한 독해를 성공으로 보완 기록하거나 다른 모델을 사용하지 않았다.
