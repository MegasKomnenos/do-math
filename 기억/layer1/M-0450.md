## 실제 소유 루프의 두 반례

[[M-0449]]의 제출·복구 결과 정본은 eb49d5b5으로 확정했다. B34는 원 KD-1000/1001을 main의 실제 runner·ResearchEngine·저장소·예약·완료 수집으로 다시 확인했다. ogb8unjj는 첫 계산 전에 외부 Calls 포트가 소유자에게 차례를 돌려 공개 pause를 전달한 경우 cancelled 대신 execution_incomplete를 기록했다. 다른 회귀는 실제 named Job이 이미 done일 때 외부 종료 관찰만 unknown으로 만들어 raw bytes가 canonical_json에서 ValueError를 일으켰다. 둘 다 정상 ready_work_sim(1) 생산 상태에서 시작하며 제품 함수는 바꾸지 않고 관찰했다.

call_engine의 종료 미확인 결과 저장에도 기존 json_safe를 사용했다. bytes·보고된 소수·큰 정수 등을 저장용 명시 표현으로 투영하는 기존 계약이며 데이터를 버리는 기본값은 없다. 저장 JSON 전체가 관찰한 실제 _receive_call result 인자의 json_safe 값과 같은 것을 추가 단언했다. 해당 Job 이름, 동일 소유 활동, 종료 unknown, non-ended 실행, held 예약과 returned=0, 저장 execution 일치를 보존한다. 종료가 확인되지 않았는데 예약을 반환하지 않는다.

session_slots.started는 일치하는 실제 Job/process 식별과 started_at을 기록하되 이미 stopping인 실행을 running으로 되돌리지 않는다. 첫 계산 전 pause의 늦은 시작 callback이 illegal stopping/running 전이를 만들던 원인이다. 실제 owner/collect/pump를 sys.monitoring으로 관찰하고 모든 새 실행의 ended, confirmed 종료, settled 예약, 반환 전 바이트 증거와 남은 future 없음, executor 종료를 검사한다. 해당 결과는 cancelled여야 한다.
