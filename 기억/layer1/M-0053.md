# AI 작문 스킬 체계를 의도 발굴과 실행 계약 중심으로 재구축함

## 맥락

사용자는 AI가 읽는 SKILL.md, SendMessage, handoff, 연구 문서 전체의 프롬프트 품질을 높이고자 했다. 핵심 요구는 사용자가 완전한 프롬프트를 직접 쓰지 못해도 AI가 필요한 사용자 결정을 스스로 찾고 모두 회수하는 것이었다.

현행 `write-for-reader`를 기존 규칙에 덧붙이지 않고 단일 스킬·조건부 참조 체계로 전면 재작성했다. 스킬 식별자와 기존 `절차문.md`·`에이전트_채널.md` 경로는 활성 계약의 호환성을 위해 유지했다. `명료한_산문.md`, `의도_발굴.md`, `AI_프롬프트.md`를 추가했다. AGENTS.md와 CLAUDE.md에는 정확성·충실성·정합성 통과 조건과 발동 계약만 남겼다.

평가 기준은 직접 검사, 기준점 비교, 명시된 판단 절차 중 하나로 판정 가능해야 한다. 최종 기준을 아직 모르면 탐색 단계를 두고 현재 단계의 기준을 판정 가능하게 했다. 컨텍스트는 프롬프트 본문, 시스템 주입, 선행 절차, 필수 원자료 열람으로 구분했다. 수신 AI가 실제로 얻는 컨텍스트를 기준으로 중복과 결손을 판정한다.

## 사용자 교정과 반영 위치

첫 시험의 수정본은 의도 발굴에서 질문 하나만 바로 제시했다. 사용자는 전체 질문 구조와 현재 답의 위치를 파악하기 어렵다고 판정했다. `의도_발굴.md`는 첫 질문 전에 전체 결정 지도를 보이고, 각 질문이 실행 계약의 어느 항목을 바꾸는지 설명하도록 바꾸었다. 질문은 여전히 하나만 제시한다.

첫 시험의 파견문 수정본은 사용자 요청을 압축했지만 판정 기준을 실행 계약으로 충분히 펼치지 않았다. `AI_프롬프트.md`는 사용자 의도 창작과 원천·논리의 필연 귀결 도출을 구분하도록 바꾸었다. 작성자는 입력 상태별 처분, 전수 여부, 부재·읽기 실패, 좌표와 반환 값을 실행 기준으로 드러낸다.

첫 시험의 탐색 프롬프트 수정본은 세부 기준은 충분했지만 장식적 역할 부여로 시작했고 원리에서 세부 조건으로 내려가는 순서가 약했다. `AI_프롬프트.md`는 역할이 실제 권한과 판정 관점을 바꾸는 경우에만 적게 했다. 긴 프롬프트는 작업 지도와 원리를 먼저 설명하고 판정 기준·실행·출력으로 내려가게 했다.

실행 컨텍스트에 루트 저장소의 기억과 기타 스킬이 포함되면 작문 스킬 차이를 독립적으로 판정하기 어렵다. 최종 A/B 검증은 `.skill-workspace`에 두 미니 Git 저장소를 만들었다. 각 저장소에는 해당 버전의 작문 절, `write-for-reader`, `grilling`, 동일한 시험 입력과 fixture만 두었다. 사례 세 건의 독립 `codex exec`에서 사용자는 모두 새 체계의 산출을 선택했다. 사례 2의 이전 판정은 제공 컨텍스트가 이미 담은 판정 기준을 확인한 뒤 철회됐다.

## 터득한 것

질문을 하나씩 묻는 규칙과 전체 발굴 지도를 보이는 규칙은 충돌하지 않는다. 지도는 사용자가 현재 질문의 의미와 다음 분기를 예측하게 하고, 한 질문은 지금 확정할 결정만 닫는다.

프롬프트의 충분성은 반복 분량과 도출 분량을 구분해야 한다. 이미 주어진 문장을 다른 말로 늘리는 것은 수신 AI의 판정을 줄이지 않는다. 확정된 원리를 입력 상태별 처분과 완료 조건으로 펼치는 것이 프롬프트의 실질적인 충분성을 높인다.

## 작업 너머 시사점

dream에서 묶을 후보는 A/B 검증의 격리 단위다. 같은 루트 저장소에서 작업 디렉터리만 바꾸면 상위 AGENTS.md, 기억, 기타 스킬이 두 실행에 함께 들어갈 수 있다. 서로 다른 미니 저장소 루트에 평가 대상 지시만 두어야 개입 차이를 격리할 수 있다.
