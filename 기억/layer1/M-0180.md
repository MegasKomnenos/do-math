title: Taylor의 보충 ZIP·원 표 CSV와 문헌 DOI 인식을 연결함

Taylor & Francis 문헌의 보충 ZIP·본문 표 CSV를 회수하고 중첩 압축 안의 R 소스를 실제 MCP에서 읽었다. URL로 지정한 문헌의 DOI도 실제 Dublin Core·publication_doi에서 회수하도록 보완했다. 공통 검사 148개가 통과했으며 전체 자료원 구현은 계속 진행한다.

대상은 Goodness of Fit of Logistic Regression Models for Random Graphs, DOI 10.1080/10618600.2017.1349663이다. 첫 진단이 citation_title 태그만 기다려 시간 초과였지만 정상 문헌 화면에는 dc.Title이 있었다. 접근 제한으로 단정하지 않고 보존 응답을 확인해 대기 조건을 수정했다. dc.Identifier에는 숫자 native ID와 DOI가 함께 있었고 publication_doi도 있었다. 공통 문헌 파서에서 이 값들을 구별해 DOI를 얻는다. URL 입력의 관측 DOI를 사용자가 입력한 DOI로 바꾸지 않도록 원 요청값과 관측값도 분리했다.

보충 ZIP은 원 downloadSupplement 제어의 doi·file에서, 두 표의 CSV는 downloadTable의 doi·id·downloadType에서 회수한다. 파일 경로의 문헌 DOI를 대조하며 보충 파일과 본문 표를 서로 다른 역할로 반환한다. CSV는 원 바이트와 헤더를 유지하고 파일명만 table_id로 지정한다. 두 번째 표의 첫 헤더가 빈 문자열인 점도 그대로 보존했다. 이미 검증된 공유 보충 다운로드 처리에 제어 파서만 추가했으며 별도 전송 체계를 만들지 않았다.

실제 MCP에서 ZIP 1,111,477바이트·구성 항목 5개, CSV 두 개의 데이터 행 3개·열 4개, 원 BibTeX·초록을 확인했다. ZIP 안의 code.tar.gz를 다시 추출해 14개 항목과 code/gof.R 90줄 중 앞 3줄을 읽었다. R·C++ 코드를 실행하지 않았고 install_first에 포함된 패키지도 설치하지 않았다. 원 연구 파일은 커밋에 넣지 않고 메타데이터와 보충/표 제어 영역만 fixture로 보존했다. 정확한 보고 경로는 VALIDATION.md가 소유한다.

병행 조사한 De Gruyter 문헌 DOI 10.2202/1558-3708.1089는 첫 기관 이동 실패 뒤 재조회에서 정상 문헌과 ga_download_supplementary 제어를 확인했다. Data and code (zip file) 링크의 파일명은 snde1089_supplementary_2.zip이다. 이 보충 파일의 연결은 다음 단위로 진행한다. 개별 실패의 원인을 서비스 전체 제한으로 확대하지 않는다. 전체 완료 전이므로 푸시하지 않는다.
