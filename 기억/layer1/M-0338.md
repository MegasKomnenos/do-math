# do-math 단일 라운드의 실제 입력 독해 대조와 봉인 시험 계약 보완

## 맥락

사용자는 do-math의 불필요한 호환 요소·죽은 매개변수, 생산자와 소비자 계약 불일치, 목적을 어기는 구현, 지나친 비효율을 대상으로 한 라운드의 전면 검증을 요청했다. 수리자는 8명, 그중 관점 담당은 4명이며 수리자와 심사자 모두 gpt-6-astra로 지정했다. 심사 중에는 기각·무처분 지적 전건을 운전자가 다시 검토해 재량으로 처리하라는 지시를 더했다. 동결·공식 판정·직접 후속 조치의 지속 기록은 `임시/do-math_검증_2026-09-24_astra8_3차/동결.md`, `장부.md`, `종료보고.md`다.

네 영역은 228파일·74,182행을 나눴고 관점 담당자는 각각 한 영역을 필수 통독하면서 연결된 정의·생산·소비·검사·문서로 추적 범위를 열었다. 수리 항목 25개·82조각 중 겹치는 항목 6개를 세 묶음으로 병합했다. 단독 19개와 병합 3개를 합쳐 심사 항목 22개를 세웠다. 심사자 세 명이 각각 전건 판정한 결과 공식 수리는 20개, 무처분 1개, 기각 1개다. 공식 적용은 20개 심사 항목·59조각·39파일이다. 장부는 병합 구성 지적도 각각 세므로 적용 22행으로 기록한다. 사용자 후속 지시로 남은 두 심사 항목을 직접 수리해 정본은 최종 42파일이 바뀌었다.

## 터득한 것

수행 기록과 실제 입력은 서로 다른 검증 대상이었다. 여덟 수리자 모두 파일별 전행 독해를 기록했고 공식 서식·좌표·축자 검산을 통과했다. CLI 표시 로그와 원문 행을 대조하자 수리자 1에서 391행이 보이지 않았다. 실제 세션의 도구 반환 기록을 읽으니 대부분은 입력에 있었고 시험 파일 끝의 9행만 빠져 있었다. 반대로 수리자 7은 CLI 표시 로그에서 원문 행을 모두 찾았지만 실제 모델 입력에서는 다른 시험 파일 끝의 20행이 절단돼 있었다. 표시 로그의 원문 출현을 실제 모델 입력의 출현과 같게 취급하면 두 방향으로 오판할 수 있다.

운전자는 공식 독해 결손의 새 컨텍스트 재파견 대신 같은 모델·노력·컨텍스트에서 대상 파일 전체를 다시 읽고 기존 판단과 수행 기록을 보완하게 했다. 이 절차 조정은 신호 4 자체 처리로 장부에 남겼다. 원 파견문에 구체적인 검산 좌표를 더한 보완이며, 새 라운드나 추가 수리 기로 세지 않았다. 보완 뒤 실제 세션 도구 반환에서 여덟 명의 필수 비공백 원문 행 미출현은 0이었다. 이는 원문이 입력에 나타난 근거이며 이해의 완전성 증명은 아니다. [[M-0333]]·[[M-0334]]·[[M-0336]]의 독해 결손·범위 분담 기록과 함께 종합할 후보이며, 이번의 차이는 표시 로그와 모델 입력의 불일치를 직접 확인한 점이다.

R1-11의 지적은 CLI 성공 응답을 `result` 봉투 없이 설명한다는 것이었다. 심사자들은 결함은 인정했지만 README 대체 조각에 JSON 코드 블록의 닫는 울타리가 없어 기각했다. 운전자는 현행 `_emit`의 실제 반환을 확인하고 울타리를 유지하면서 `result.instance_id`·`result.operator_schedule`과 성공·오류 봉투의 안내를 고쳤다. R1-M2는 `_identity_assessment`가 읽지 않는 필수 `effective` 인자를 제거하는 수리였다. 함수 정의 1곳에서 인자 선언을, 호출 6곳에서 그 인자 전달을 지우며 함수 호출 자체는 유지했다. 심사자들은 제거의 정합성을 인정하면서도 실행 결과가 달라지지 않는다는 중대성 기준으로 무처분했다. 사용자가 죽은 인자 정리를 명시했고 후속 재량 처리도 허용했으므로 운전자는 제거했다. 생성된 판정 기록의 내용과 별도 사용 효력 계산은 유지했다. 기각과 무처분을 그대로 최종 잔여로 삼지 않고 각각 수리안의 구조 결함과 이번 작업 목적에 비춘 실익으로 다시 판단한 사례다. [[M-0337]]과 함께 종합할 후보지만, 모든 무처분을 자동 적용한다는 규칙은 아니다.

공식 적용 뒤 단위 시험은 301개 중 하나가 실패했다. R1-03은 저장된 봉인 검사와 실제 실행·응답·확장·스키마의 결속을 검증한다. 기존 복구 시험 `test_repair_plan.py`는 `passed`와 검사 ID만 갖춘 모형 기록을 만들었으므로 현행 검사에서 거부돼 예상한 publication 대기 대신 failure 대기에 들어갔다. 운전자는 제품의 봉인 검사를 완화하지 않고 시험 모형에 receiver mode·execution_id·schema_ref·내용 해시를 넣었다. 처음의 300성공·1실패 기록을 남기고 단위 전건을 다시 실행해 301개 성공을 확인했다. 반환·봉인 변조 거부를 검사하는 변경부 통합 시험도 통과했다. 이 수정은 승인 조각을 몰래 바꾼 것이 아니라 적용 뒤 불변식 실패에 대한 신호 6 자체 처리로 기록했다.

## 검증 범위와 보존 경계

최종 단위 301개와 변경부 통합 31개, 설치 문서·스키마 구조 검사, Python 200파일 AST 파싱, README JSON 3블록과 실제 초기화 응답 대조, 미러·공백 검사를 통과했다. AST로 새 시험·본문 변경 시험을 찾았지만, 보조 fixture 변경의 영향은 별도로 확인해 지식·저장 소비 시험을 추가했다. 자동으로 찾은 변경 시험 목록만으로 영향 범위가 닫히지는 않는다. 전체 통합·Lean·자원 스위트와 실제 모델 연구 운전은 수행하지 않았다. 한 라운드 상한으로 종료했으며 수렴이나 무결함을 뜻하지 않는다.

graphify는 최종 원본 228파일·6,183노드·21,784관계로 갱신됐으며 status는 `current`, 의미 추출 대기는 0이다. 변경 문서 10개의 의미 추출과 구조 추출, graph.html·tree.html 생성이 완료됐다. 첫 호출은 README의 의미 추출 결과가 존재하지 않는 파일 경로를 대상으로 제시해 검증에서 거절됐다. 기존 그래프는 보존됐다. 문서마다 의미 추출 캐시 하나를 사용한다. 첫 호출에서 성공한 변경 문서 9개와 변경 없는 문서 13개의 캐시를 합쳐, 두 번째 호출은 문서 22개의 캐시를 재사용했다. 같은 README 원문에서 의미 추출을 다시 실행해 경로 검사를 통과했다. 그래프 산출물은 Git 제외 로컬 자료다.

정본에서 `.agents/skills/do-math/`의 생성 미러 42파일을 갱신했고 398개 미러 파일의 드리프트 검사를 통과했다. 상세 CLI 로그·세션 입력 대조·기각 원문·시험 보고와 graphify 그래프는 Git 제외 로컬 자료다. 작업 커밋 성공 뒤 앵커와 라운드 디렉터리를 삭제하려 했으나 자동 승인 검토가 명령을 `blocked by policy`로 차단했다. 삭제를 우회하지 않아 이번 앵커·라운드 자료는 보존돼 있다. 런 직속의 기각 보관·시험 보고는 남지만 Git 제외 로컬 자료라 다른 환경에서의 존재를 보장하지 않는다. 위 지속 기록은 판정 요지·계수·검증 범위를 복원하는 진입점이며 상세 실행 로그 전체를 대신하지 않는다.
