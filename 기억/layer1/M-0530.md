[[M-0529]]에서 남긴22곳을 처리했다. check.passed는 submission.check_submission의 결과이고 check.sha256는 governance.check_import가 봉인하는 독립 수입 검사다. 같은 check 이름에 두 결과를 합치지 않고 행별 별칭을 붙였다. 각각에 상대 객체의 필드를 적으면 실패한다. payload.kind도 validate_import_units의 입력이며 payload.deadline_offset_ms는 worker_feedback의 전달 계약이다. 서로 바꿔 붙이면 검사에 걸린다.

change.value는 닫힌 공개 입력 스키마에 선언된 키가 아니라 evaluate_condition의 decision_value_is 분기가 선택적으로 읽는 키다. 고정 키 읽기를 특정 함수·객체 표현에 한정해 추출하는 도우미를 추가했다. 대입 대상·다른 객체·중첩 함수의 읽기를 포함하지 않으며 동적 키로 임의 이름을 승인하지 않는다. 이 모양은 소비자가 읽는 필드의 근거이지 객체 전체를 닫는 schema가 아니다. 열린 payload.kind도 같은 방식으로 실제 validator에 연결했다.

source_ref는 지식 기록의 문자열 source_ref가 아니라 write_source_catalog가 생산한 참조 객체다. source_range는 interpretation_schema의 실제 import_units 항목에서 읽는다. review_research는 전용 입력 생산자의 반환, role_review는 review_cycle.context_for의 실제 합성 반환에 결속했다. project와 toolchain은 formal의 최초 객체 및 후속 search_paths 대입을 합치고 environment_check는 trust_validation의 정상·오류 반환 대안에서 읽는다. CLI 문장의 dispatch_wait는 일반 배정 대기 전체가 아니라 plan_settle를 설명하므로 해당 생산자에 행별로 연결했다.

이전에는 모르는 공간을 별도 미결 목록에만 남겼다. 이제 현재 문서의 소문자 단순 점 표기는 전건 소유자가 정해졌으므로, 미소유 이름을 발견하면 실패시키는 검사도 추가했다. recrod.id 같은 오타나 새 공간의 미등록을 조용히 통과시키지 않는다. 함수·진단 코드는 각자의 기존 검사로 확인하고 파일명은 별도로 분류한다. 파일 존재를 인증하는 검사는 아니다.

65개 공간에 필드161곳을 연결했으며 이 표기의 미결은0이다. 함수5·진단7·파일명33의 분류를 유지했다. 구조57개가51.0초에 통과했고 실행 중 변경은 없었다. 원본 보고는 검증/2026-10-05-문서-점표기-전건/report.json, 전건 위치는 기존 단계-전환표의 document_dotted_reference_population에 보존했다. smell 검사9.032초가 개별5초 기준을 넘었지만 검사 강도를 유지했다.

원문 13-C는 운전·역할 문서가 이름으로 드는 명령·인자·필드·정책 모두와 필수 문서 읽기 한도를 요구한다. 단순 점 표기 완료를 13-C 전체 완료로 바꾸지 않는다. 단독 필드 이름, 배열 인덱스, 대문자 상수 표기, 역할별 산출 전건 및 실제 출력 한도의 남김을 유지했다. 제품 코드의 실행 동작은 바꾸지 않았다. 전체 목표의 일반/fresh T3/극단 변이·정상 기준/T4·T5도 계속 남는다.
