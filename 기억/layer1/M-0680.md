## 고친 결함

- **브로커 기동 중 사망(R3-06).** `Broker.adopt`가 `self.state["jobs"].items()`를 사본 없이 돌고, 같은 순회의 `finish()`가 `prune()`으로 끝난 작업을 지웠다. 끝난 작업이 `KEEP_FINISHED`(200)만큼 쌓인 상태에서 `GO`를 받지 못한 호스트가 `CANCEL` 뒤 2초 안에 끝나지 않으면 `RuntimeError`로 브로커가 기동 중에 끝나고, 상태 저장 전이라 다시 띄워도 같은 자리에서 죽는다. 실행 중 인스턴스의 브로커 상태가 정확히 작업 200건이었다.
- **실행기 호스트 핸들 누수(R3).** `runner.py`의 `collect()`도 라운드 2의 브로커 쪽([[M-0679]] R2-10)과 같은 꼴로, 호스트 `poll()`이 생존 확인보다 먼저 와서 그 사이에 끝난 호스트의 `Popen`이 회수되지 않았다.
- **보정 작업의 제출 순서와 추월 계수(R3).** 순회 중 `queued.insert(0, ...)`로 보정 작업을 맨 앞에 넣어 제출 순서와 추월 한도가 어긋났다.
- **실제 호스트를 밟지 않던 수습 시험(R3-M2).** `test_containment.py`가 대역 호스트를 돌렸고 대역이 `contain_session_processes()`를 스스로 불러, 실제 `session_host`가 CLI보다 먼저 자신을 묶는지 아무 시험도 보지 않았다. 대역을 외부 CLI 경계로 옮기고 `runner.py _session`으로 실제 호스트를 띄운다. 같은 묶음이 `ensure_broker`의 breakaway 요청과 `PermissionError` 대체 분기를 검증하는 시험을 더한다.
- **시험의 공백과 중복.** 고아 컴파일 취소의 네 상태, restart-broker의 세 관문, `archive_work`의 링크 거부, 병합 question의 빈 칸 계수 단언, 같은 경로의 중복 시험.
- **문서.** review의 철회가 지우는 범위의 과장(코드는 증명 경로로 도출된 결과만 다시 계산한다), node `wait`의 거부, 정의보다 앞선 공유 용어, 절 사이에 끼어 있던 종료 재고 문단과 node lease 설명보다 앞선 explorer 점유 문단, 2,814자 문단, 실행기 자신으로 읽히던 「its files」, organizer 지침의 되풀이, 「as before」 같은 개발 경위 지시어. `what-research-is-for.md`에서 세션이 맡은 문제를 question이라 부르던 일곱 자리를 problem으로 바꿨다. 37행이 closing을 「settling the whole question a session has taken on」으로 정의해 explorer가 점유한 question 개체로 읽을 수 있었기 때문이다. 동결 불변식은 그 글의 중심 내용·장면·비중을 바꾸는 수리를 상신으로 보내는데, 심사 셋 모두 낱말 수준의 정확성 수리로 승인했다.
