title: AMS 원 검색 메타데이터를 연결하고 명시적 PDF 링크 회수를 수리함

AMS 원 검색의 양성 응답을 확보해 새 어댑터를 연결하고, Publisher의 명시적 PDF 링크 회수를 수리했다. AMS 부속 PDF의 실제 MCP fetch·extract와 공통 검사 113개가 통과했다. 신규 검색 어댑터와 native 파일 export는 이후 접근 확인 때문에 전체 실서비스 검증이 남았다. 부분 구현과 접근 제한을 구별하며 전체 작업을 완료로 선언하지 않는다.

이전 AMS 관측은 browse 화면 틀과 browse.js 403이었다. 다른 검색어 algebra로 재확인하자 원 브라우저에서 6,587건 중 12건이 나타났고 browse.js·/product/browseproducts가 200으로 응답했다. Products·TotalRows·PageNumber·RowsPerPage의 원 JSON을 회수했다. 12건에는 책·논문·학회 초록이 섞였고, 책의 Title와 Subtitle이 별도였다. ProductCode SURV/168은 책이고 JAMS는 여러 논문의 공통 출판 코드이므로 모두 고유 문헌 ID로 취급하지 않는다. 논문 DOI 10.1090/jams/1045·PII S0894-0347-2024-01045-3와 DOI 없는 학회 초록도 보존한다.

원 기본 고급검색의 ProductCode 제어 ID는 advancedSearchFreeformInput이고 Book Text는 advancedSearchAnywhereInput이다. 이름만 보고 자유 검색식이나 전체 자료의 본문 필드로 해석하면 안 된다. 실제 data-advanced-search-term 속성에서 ProductTitle·Author·ProductCode·Anywhere·ISBN·MSC의 요청 이름을 확인했다. 내용 유형의 원 값은 책 B, 논문 A, 학회 초록 ABS다. 검색 어댑터는 원 요청·페이지·행 수를 대조하고 문헌 링크와 원 레코드를 연결한다. 동적 조건 그룹 편집은 추가 구현이 남아 있다.

책 코드에는 MPRIZE처럼 슬래시가 없는 값도 있다. /view?ProductCode=MPRIZE를 입력했는데 코드에 슬래시가 없다는 이유로 문헌 화면 경로로 보내던 분기를 대역 재현하고 고쳤다. 이 검사는 입력 해석을 확인한 것이며 MPRIZE 서지의 별도 실서비스 회수 성공으로 세지 않는다.

같은 출처의 다음 어댑터 호출들은 /browse에서 Just a moment 접근 확인을 반환했다. 이 실패를 0건으로 바꾸지 않고 restricted로 구별했다. 실제 MCP 검색 흐름도 여기서 미완료다. 원 exportproducts는 기관 context의 요청과 사이트 원 exportResults 함수의 브라우저 요청 모두 403이었다. 책과 논문의 문헌 페이지 표본도 접근 확인이었다. 양성 브라우저 응답이 있었다는 사실과 신규 어댑터의 완전한 실측 통과를 구분해야 한다. 보고 파일 경로는 VALIDATION.md가 소유한다.

AMS의 공개 gsm128-endmatter.pdf는 KUDOS 기관 경로에서 607,667바이트·51쪽으로 내려왔다. 페이지 이동은 Download is starting 예외로 끝났지만 실제 download 이벤트와 파일은 존재했다. 기존 MCP의 execution_error를 재현한 뒤 파일 이벤트를 회수하는 명시적 PDF 경로를 공통 Publisher에 추가했다. 파일 내장 메타데이터는 문헌 페이지의 서지와 구별한다. 이 부속 파일을 전체 책으로 해석하지 않는다. proxy URL을 조합해 context.request로 직접 받는 시험은 403이었으므로 실제 브라우저 파일 회수 경로를 유지했다.

명시적 PDF 회수는 요청 경로·쿼리에 해당하는 native download의 자료원 URL을 확인한 뒤 파일을 읽는다. 외부 자료원의 URL은 파일 읽기와 보존 전에 거부하는 대역 검사를 추가했다. 이 경로의 브라우저 이동은 사후 호스트 검사이며 browser_download의 HTTP redirect 사전 검사와 동일한 네트워크 보장으로 표현하지 않는다. listener는 일반 Python 함수로 등록하고 작업 후 해제한다. 탐색 프로브에서 list.append를 직접 넘기면 Playwright가 handler 속성을 붙이는 단계에서 AttributeError가 났고, 일반 함수로 감싸 해결했다.

최종 실제 MCP PDF 보고는 completed=true다. tests/live_ams_pdf.py로 독립 재실행할 수 있다. 원 검색 JSON과 범위 불일치·외부 download 거부 검사를 추가했으며 공통 113개가 통과했다. AMS 검색의 안정된 양성·페이지 이동·ProductCode 독립 회수·0건과 native 내보내기는 계속 검증해야 한다. SIAM 등 남은 자료원과 부가 첨부 구현도 남아 있다. 사용자 설정·기존 연구 산출물을 보존하고 전체 완료 전이므로 푸시하지 않는다.
