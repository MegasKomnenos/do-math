신규 g02·g05·g08 작업자가 재개 계약을 구현하면서 루트는 실제 결과와 실행을 다시 대조했다. 이 커밋은 진행 중 계약과 공통 관측을 보존한다. 담당 전체와 네 대기 묶음의 회수는 아직 완료되지 않았다.

`reviews`를 실제 판독 뒤에만 기록한다는 표현이 모든 후보의 AI 전수 재판독 의무로 읽히지 않도록 경계를 명확히 했다. 실물 TDD로 검증한 결정론 규칙이 문헌 대응·초록 경계·원문 충분성을 실제로 검사한 경우에는 규칙·코드 판본·시험·증거에 결박한 자동 판정을 허용한다. 스키마·해시 통과는 의미 검토를 대신하지 않으며, 적용 범위 밖·모순·OCR·구획·판본 불확실성은 직접 판독한다. 이 구별은 자동화 자체를 금지하여 작업량을 불필요하게 늘리지 않으면서 자동 판별의 적용 범위를 검증하려는 것이다.

루트의 초록 표본 판독에서 g02 Gradient flows의 DB 문구에 단어 내부 물음표, 수식 손상, `separable Hilbert` 뒤 절단이 있었다. 작업자는 실제 입력을 회귀로 추가하고 자동 초록 확정을 철회했다. 이후 Duke 대학의 정상 공개 PDF 경로에서 342쪽 파일을 회수했다. 루트도 파일 SHA와 제목·세 저자·2005 판권·ISBN9783764324285·마지막 Index333을 직접 대조했다. 파일 10쪽 서론은 DB 문구의 나머지를 포함했다. 원문 확보는 인정하고 서론 발췌를 새 초록으로 바꾸어 보고하지는 않았다. Chrome PDF viewer의 짧은 응답과 실제 관측 URL의 PDF 수신이 다른 사례도 작업자의 실물 TDD 수리로 연결됐다.

g05의 새 DB 초록에는 본문과 bullet 하이라이트가 한 문자열에 합쳐진 값이 있었다. 작업자는 원시값을 보존하고 두 종류를 분리했다. 다른 문헌의 abstracts 배열 두 값은 수식 자체가 달라 자동 결합을 철회하고 원출판사 대조로 보냈다. g08도 목차만 있는 값과 수식이 소실된 값을 기존 초록에서 철회했다. DB 필드 이름과 문장 끝의 마침표만으로 완전한 초록을 보장할 수 없다는 실물 반례다.

g08이 입력 URL 없음·MR Article 비활성·필수 Summon 검색 0건·명시적 MR 초록 없음의 좁은 규칙으로 27건을 부재 처리한 뒤, 루트는 그중 두 건을 표본 대조했다. Vakil2013은 Stanford 공식 저자 목록과 EMS Newsletter89 전체호 PDF에 있었고, Burgos Gil2001은 영어 입력 제목 대신 Catalan 원제로 바르셀로나대 저장소에 있었다. 둘 다 원자료의 저자·연도·권호쪽과 대응했다. 기존 판정은 인터넷 전체의 부재를 주장하지 않았지만, 실제로 회수할 수 있는 자료를 찾는 목적에는 이 종료 분기의 검색 범위가 부족했다.

이에 `restart-contract.md`에서 그 종료 분기만 보완했다. 제목·저자 검색과 확인한 발행정보 검색을 각각 한 번 수행하고 첫 결과 화면에서 대응 가능한 공식 출판사·저자·기관·저장소를 확인한다. 검색 도구로 단서를 발견할 수 있고 회수는 Playwright와 TDD 수집기로 수행한다. 같은 검색의 중복과 목표 내용을 이미 확보한 뒤의 불필요한 탐색은 피한다. 도구 실패는 무결과가 아니며 인터넷 전체를 무한 탐색하는 의무도 없다. g08은 기존 27건을 재개하고 54개 공개 검색 작업으로 보존했다고 보고했다.

Burgos의 UB 항목은 검색 도구의 직접 열기에서는 타임아웃이었으나 실제 Chrome에서 열렸다. 작업자가 처음 파일 링크를 찾지 못했을 때 루트는 `510783.pdf` 표시를 기다려 `https://diposit.ub.edu/bitstreams/7c137138-70ed-4751-82c0-b7f5ab08e7cb/download`를 실제 anchor에서 읽어 전달했다. 원래 파일명만으로 endpoint를 추측하지 않았다. 준비 조사에서는 KUDOS Web of Science도 최초 짧은 대기에 입력이 없었으나 충분히 기다리면 `#composeQuerySmartSearch`가 나타났다. 반면 Scopus 준비 탐색 한 번은 검색 전에 Cloudflare 화면을 보였으며 전건 접근 불가로 확대하지 않았다.

실행 검증에서는 g08 PID37012의 시작 시 기록한 다섯 코드 SHA가 현재 파일과 같은 것을 루트가 확인했다. 작업자는 후보 12건 저장 뒤 그 프로세스를 종료하고 새 수리·시험·manifest로 재개했다. g02의 다운로드 수 중복 증가와 시작 시 전건 결과를 메모리에 읽는 실행의 외부 교정 덮어쓰기 가능성도 코드 좌표로 전달했다. 후자는 실제 덮어쓰기를 관측한 주장과 구분했고, 작업자는 코드 수리 시 체크포인트 종료를 유지했다.

루트 부분 검사에서 g05의 0바이트 마지막쪽 추출 파일 한 개가 발견됐다. 원문이 없는 것이 아니라 스캔된 마지막면에서 텍스트가 추출되지 않은 경우였다. 작업자는 빈 원시파일을 그대로 보존하고 원본 PDF·쪽수·0문자·실제 PNG 판독을 담은 진단 JSON으로 증거 참조를 바꿨다. 빈 파일에 원문처럼 안내문을 채우거나 유효 PDF 전체를 폐기하지 않았다.

다음 회수 검증의 초점은 각 수집기의 새 진입점이 실제 남은 작업을 소비하는지, 자동 검토의 반례가 전체 해당 결과에 재적용되는지, 공개 검색의 새 단서가 이미 닫은 작업을 다시 여는지다. 부분 검사나 완료 후보 수는 전체 완료를 대신하지 않는다. 현재 실행 정본은 dispatch·operator-state와 작업자별 runs·results·work-queue·feedback-response다.
