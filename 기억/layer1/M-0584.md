title: do-math 수용판을 main에 인도하고 남은 외부 조건을 구분한다
convention_version: 27

manager 0108은 제품 수정 없는 g8-review를 변경 0으로 통합했다. 원30의무와 보존·역사 검토 연결, G6 수리와 기존 실행 근거는 수용 범위에서 유효하지만, 최종 review 배정 완료와 프로젝트 전체 충족은 다르다. G8이 확인한 실제 로컬 남김은 수용판이 main 작업트리에만 있고 HEAD/index에는 없다는 점이었다. 새 제품 결함은 확인되지 않았다.

기존 HEAD와 다른 do-math 파일 654개와 신규 108개를 수용 manifest와 대조해 커밋 대상으로 삼았다. Git 제품 2168개 파일의 현재 SHA가 G8 baseline과 같았다. stage 뒤 실제 blob과 비교하면 1838개는 원바이트가 같고, 330개는 기존 Git 정책의 CRLF/LF 차이만 있다. 원녹화 corpus는 바이트가 같다. G8 manifest 2436개에는 Git 제외 캐시·선택/시간/T3 생성 자료 268개도 포함돼 있었다. 이 자료들은 로컬 보존하며 제품 인도 모집단과 구별했다. 파일 수가 다른 것만으로 제품 누락으로 판단하지 않았다.

공식 미러 생성/check와 의미 검수·실행은 기존 수용 근거를 재사용했다. 내용 변화 없는 Git 전달 때문에 전체 시험이나 review를 다시 만들지 않았다. 관리 변경에는 기억 색인 검사와 실제 Git blob 대조를 적용했다. 기존 M-0579 초안과 색인 한 줄, 다른 작업의 변경은 보존하고 이번 커밋에서 제외했다.

로컬 인도 마감 뒤에도 G4 최종판 한 전체보고와 최신 정확 회귀 범위 제한의 처리 권위, G5 실제 symlink/POSIX 환경, G7 현재 지원판 native 원자료, L01 실제 운전 프로필·원UTF-8 출력byte 조건은 남는다. 확인되지 않은 기능 결함을 가정해 task를 만들거나 이미 수용된 시험을 반복하지 않는다. 큐의 blocked는 필요한 외부 조건의 대기이며 complete가 아니다. 같은 질문과 probe를 반복하지 않고 입력이 생겼을 때 필요한 경계만 잇는다.

추적 근거는 `.async/dm/managers/0108/review.md`·`delivery-manifest.json`과 이번에 보존한 `tasks/g8-review`의 report 및 세 결론 파일이다. 귀속 커밋은 이 노드의 생성 이력으로 찾는다. 전체 과거 raw·objects·workspace와 커밋 후 `delivery-state.json`·`handoff-delta.json`을 포함한 나머지 실행 기록은 RECORDS에 로컬 보관되며 이번 커밋에 모두 포함되지 않는다. 수용 workspace 정리 뒤 과거 소스는 workspaces.py restore를 사용한다.
