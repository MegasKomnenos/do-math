[[M-0483]]까지 역할 입력 요구의 실제 도달을 보강했지만, 요구 목록을 순회하는 검사 자체가 항목 누락이나 읽을 수 없는 원문에서 실패하는지도 확인해야 했다. B69는 새 흐름이나 도메인 대역을 만들지 않고 기존 열 개 역할의 실제 생산·포장 전건 검사에 부정 입력을 넣는다. 원래 범위는 `조사/결함-범주.md`의 3-B이며, 설계 3.1~3.2의 부류 기준은 모든 구성원 일반 순회와 불완전 선언의 탐지다.

실제 준비 입력에서 선언된 필수 루트를 하나씩 전달값과 검사기 값 양쪽에서 제거한다. 두 사본을 서로 같다고만 확인하여 누락을 놓치는 경우를 막는다. 원본의 하위 값은 그대로 두고 최상위 dictionary만 복사하므로 상태·자료를 새로 채우거나 역할 입력을 손으로 대신 만들지 않는다. 검사의 결과는 unittest TestResult로 수집하며 assertRaises로 대체하지 않는다. 기존 검사자의 subTest는 실패를 기록한 뒤 예외를 삼키므로 assertRaises만으로는 탐지 성공을 잘못 판정할 수 있다. 각 제거는 실패해야 하고 실패 사유가 그 항목을 지목해야 한다.

각 역할에는 실제 카탈로그 참조로 읽는 필수 항목이 있다. 그 첫 항목의 파일을 작업 공간 내부인지 확인한 뒤 삭제해 실제 읽기 실패를 만들고, 같은 크기의 바이트 변조로 해시 실패도 만든다. 검사자가 둘을 모두 거부하는지 확인하고 finally에서 원문을 그대로 복원한다. 가짜 read_source나 보충 기본값을 사용하지 않는다. 파일 크기만 같다는 이유로 성공시키지 않는다. 이 검사는 기존 역할 전건의 Temp 작업 공간에서만 수행하며 저장소 소스나 연구 인스턴스를 지우지 않는다.

역할 목록은 현재 contracts.ROLES 및 설치 읽기 대응표와 대조한다. 검토 단계 요구는 실제 stage_schema가 선택하는 stage 문자열 분기를 AST로 추출해 요구 선언 전건과 일치시킨다. 새로운 stage가 실제 스키마에 생기거나 요구 선언에서 빠지면 실패한다. 현재 스키마가 stage를 선택하는 방식의 정적 검사이며, 자연어 역할 계약의 모든 의미를 자동 추출했다고 주장하지 않는다. 선언 단계마다 실제 출력 스키마와 필수 좌표도 함께 확인한다.

`laypl63_`는 누락 검사, `lzs1wpwf`는 원문 삭제·같은 크기 손상까지 포함한 실제 열 개 역할 순회가 각각 통과했다. 단계 선언 검사는 `01n5moa3`에서 통과했다. 마지막 같은 판본의 전체 구조와 관련 두 모듈 실행 `vmx2jf_l`는 structure 44개·unit 21개·sim 32개, 합계 97개가 42.4초에 완결 통과했고 실행 중 변경은 없었다. 개별 예산 초과는 9개이며 새 전건 검사 11.515초 등이 포함된다. 이 결과는 역할 입력 요구 검사자의 강도와 현재 선언 누락 탐지의 증거다. 최종 전체 T2·flows, T3·극단 변이·실환경 또는 시간 예산의 완료로 사용하지 않는다.

원보고는 추적된 `검증/2026-10-04-입력-누락-관문/report.json`에 보존하고 B69에 현재 파일 지문과 실행 범위를 연결한다. 중간 Temp 보고는 로컬 보관이다. 기존 입력 부류의 일반 검사와 실제 단계·복구 흐름을 재사용한 것이며 역할마다 새로운 모델 호출 흐름을 복제하지 않았다. 사용자 진행 문서와 미추적 교차 시험은 커밋에 포함하지 않는다.

3-B는 이제 요구 선언·일반 진입/주요 변형의 실제 도달·루트 누락·필수 원문 부재/손상 거부가 연결됐다. 계약별 의미 항목과 모든 변형 모집단의 최종 종료는 미확정으로 남긴다. 이를 이유로 같은 영역에 작은 감사를 계속 증식시키지 않고, 다음 작업은 원문 3-C의 원래 열한 평가자 쌍과 이후 사본의 정본·차분 검증으로 옮긴다. 원래 19의무·61보존 지식·P2 12항목·여섯 부류·2단계 11의무와 모든 최종 전역 관문을 유지하며, 현재 통과한 부분으로 목표를 줄이거나 완료 표시하지 않는다.
