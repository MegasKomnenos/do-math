# do-math 단일 라운드의 기각 수리 보완과 시험 전제 교정

## 맥락

사용자는 do-math에 대해 수리자 총 8기(영역 담당 4기·관점 담당 4기), 수리자와 심사자 모두 gpt-6-astra, 정확히 한 라운드의 전면 검증을 다시 요청했다. 불필요한 호환 요소와 죽은 인자, 생산자·소비자 계약 불일치, 목적을 어기는 구현, 지나친 비효율을 중점으로 삼았다. 수리 도중에는 심사의 기각·무처분 전건을 운전자가 재량으로 다시 검토하고 처리하라고 지시했다. 공식 판정과 직접 조치를 함께 복원하는 진입점은 `임시/do-math_검증_2026-09-24_astra8_신규/동결.md`, `장부.md`, `종료보고.md`다.

영역 담당 네 명이 228파일·73,567행을 나누고 관점 담당 네 명이 각각 한 영역을 통독하면서 경계를 넘는 생산·소비 경로를 추적했다. 여덟 명 모두 독해 기록과 실제 출력의 비공백 원문 행 대조를 통과했다. 이는 모델 입력에 원문이 나타났다는 근거이며 이해의 완전성이나 결함 부재의 증명은 아니다. 26개 지적을 두 묶음으로 병합하여 심사 항목 24개를 만들었다. 세 심사자의 전건 판정에서 22개가 수리로 확정되고 2개가 기각됐다. 승인된 심사 항목 22개에는 원 지적 24개가 들어 있어, 지적별로 한 행을 두는 장부 본표에서는 적용 24행으로 센다. 이 수리안의 편집 구간은 75개이며 42파일에 반영됐다. 기각 2개에 대한 직접 수리는 이 공식 적용 수와 구별한다.

## 터득한 것

R1-15는 조회 모드가 사용하지 않는 인자를 받아 성공 응답을 반환하는 결함이었다. 심사자 세 명은 코드 수리 자체가 아니라 문서 조각이 기존 반환 필드인 path·size·SHA-256 설명을 지운 점을 기각했다. CLI와 JSON 각각의 잘못된 필터 조합 다섯을 재현하니 모두 거부되지 않았다. 조합 검사를 양쪽 인터페이스에 연결하고 기존 출력 설명을 보존했으며, 정상 기본값과 명시 필터가 소비자에게 도달하는 시험도 추가했다.

R1-18의 사건 번호 API는 실제 저장소가 이전 사건 원문을 제공하는데도 번호만으로 이력을 인정하는 별도 인자를 유지했다. 그 호출자는 시험 둘뿐이었고 다른 보조 인자에는 소비자가 없었다. 두 심사자는 구형 경로를 제거하는 조각이 현행 경로의 정수형 검사까지 지운다고 지적했다. 운전자가 재현한 현행 코드에서도 과거 사건의 앞 번호가 True 또는 1.0이고 마지막 번호가 정수 2이면 통과했다. 현재 사건에 같은 값을 주어도 거부하지 않았다. 구형 인자 둘과 약한 분기를 없애고 과거·현재 사건 번호를 모두 정확한 양의 정수로 검사했다. 이력의 삭제·내용 변조·번호 변경을 거부하는 조건도 보존했다. 최초 재현 3개 시험의 실패 16경우는 수정 뒤 통과했다.

공식 적용 뒤 단위 시험 297개는 통과했지만 선택 통합 20개 중 학술 요구 과제 시험 하나가 실패했다. 요구를 전부 제거할 때 완료를 처리하는 R1-05와 학술 요구의 문자열 ID를 검사하는 R1-20이 같은 시험에서 만났다. 그 시험은 해결된 수학 결과를 모사하면서 목표 상태는 미해결로 두었다. 제품의 `_solution_basis`는 목표가 해결됐을 때만 값을 반환하므로 두 시험 전제가 모순이었다. 새 완료 분기는 이 모순에서 학술 요구를 적용할 수 없다고 판정하여 준비 대기를 지웠다. 기준선 통과와 수정 후 단독 실패, 실제 상태 출력을 확인한 뒤 해당 시험에서 goal_status를 mathematically_solved로 설정했다. 이로써 시험의 목표 상태와 모사한 해결 근거가 일치하게 했다. 제품 코드를 시험 예외로 바꾸지 않았다.

최종 변경부 시험 43개와 실제 스레드·프로세스 시험 3개, 구조·구문·미러 검사를 통과했다. 앞의 단위 297개와 변경부 43개에는 겹치는 시험이 있으므로 합을 고유 시험 수로 쓰지 않는다. 전체 통합·Lean·자원 스위트와 실제 모델 연구 운전은 수행하지 않았다. 상세 CLI 로그·기각 원문·시험 보고는 Git 제외 로컬 자료이며 정리로 사라질 수 있다. 지속 기록에는 판정과 실패 원인, 직접 조치와 검증 범위를 남겼다.

## 작업 너머 시사점

이번 기각은 결함이 없다는 판정이 아니라 수리안이 유효한 정보나 입력 검사를 잃는다는 판정이었다. 지적과 조각을 구별한 뒤 삭제하려던 호환 요소와 유지해야 할 현행 검사 각각의 소비 경로를 확인해야 했다. 독립 심사의 승인은 결합된 시험 전제까지 보증하지 않으므로 적용 후 실행 결과를 별도로 확인한다. [[M-0336]]의 기각 수리 재검토와 함께 향후 기억 종합(dream)에서 묶을 후보이며, 실제 차이는 이번에는 문서 정보 보존과 Python의 bool·int 값 비교가 수리의 경계를 정했다는 점이다.
