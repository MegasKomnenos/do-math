AMS는 기본 Title·Author 등만 구현되어 원 고급검색의 AND/OR 그룹과 PublicationYear 조건을 사용하지 못했다. options.expression의 condition/terms와 field/operator/value를 원 조건 트리로 옮기고 현재 화면의 showDynamic·loadDynamicSearch를 호출한다. 화면에서 다시 읽은 조건과 각 browseproducts 요청이 원 입력과 같은지 대조한다. 기본 query·추가 필터와 expression을 혼합하면 사전에 거부하며 검색 의미를 임의로 결합하지 않는다.

원 스크립트는 Title·Author·ProductCode·Anywhere에 equals/contains, PublicationYear·ISBN·MSC·BookSeries·Subject에는 equals를 제공한다. 범위 비교나 NOT을 발명하지 않았다. 공개 인터페이스의 BookText는 Anywhere에 대응하지만 기본의 책 본문 검색 의미를 유지한다. Series·Subject의 현재 선택값 목록은 미검증이며 제어에 값이 남지 않으면 query_not_supported를 반환한다.

보존된 실제 AdvancedSearch HTML과 advancedSearch.js를 외부 통신을 막은 Chromium에서 실행했다. 페이지에 링크된 AMS jQuery는 공개 요청에서 403이어서 이 오프라인 시험에만 공식 jQuery 3.7.1을 사용했다. 이를 실제 서비스의 동일 환경이나 실제 검색 성공으로 확대하지 않는다. 원 loadDynamicSearch와 getQueryElements, performSearch가 만든 요청을 직접 비교했다.

재현에서 조건 항목의 condition 빈 문자열·queryElements null, 하위 그룹의 빈 field/operator/value를 확인했다. 모델에서 생략하면 원 요청과 달라지므로 보존했다. 실제 제출은 dynamicAdvancedSearch의 이중 URL 인코딩 POST이며 이전 코드 문자열의 advancedSearchJson은 현재 browse.js에서 쓰이지 않았다. 20260910T235329Z-ams-dynamic-offline.json은 이 키 차이를 발견한 실패다. 20260910T235356Z와 20260910T235527Z 보고는 입력 복원·원 POST 대조를 통과했다. fixtures/ams-dynamic-query.json은 원 제어가 출력한 트리다.

Search와 Delete 버튼들이 advancedSearchGo라는 ID를 공유했다. 동적 화면에서는 Delete가 먼저 보이므로 기존의 첫 visible ID 선택은 조건을 삭제한다. 정확한 Search 텍스트로 한정했다. 페이지 전환도 동적 조건을 잃을 수 있는 URL 재구성 대신 원 clickPageBtn으로 연결하고 다음 요청을 대조한다. 이 페이지 순회의 실서비스 완료는 아직 확인하지 않았다.

실제 SDK 20260910T234814714383Z-ams-workflow.json과 20260910T235700Z-ams-expression-mcp.json은 접근 확인 restricted/publisher_access_challenge였다. 별도 www.ams.org/AdvancedSearch 프로브는 AMS 404였으므로 이를 pubs.ams.org 검색의 장애나 0건으로 해석하지 않는다. ScienceDirect의 홈페이지 폼은 제출 후 결과 요청이 관측되지 않았고, 정확한 /search 심층 링크는 CPE00001이었다. 각 실패는 원 보호 폴더에 보존했으며 접근 실패를 기능 부재로 바꾸지 않았다.

공통 검사 214개가 통과했다. 전체 구현은 진행 중이며 AMS 원 파일 export와 실제 조건 검색 검증은 남았다. 다음 작업은 접근 가능한 IEEE의 문헌 조회 export 형식과 HTML 경로 등이다. 재시작 실험은 재개하지 않고 새 SDK stdio로 검증하며 전체 완료 전에는 푸시하지 않는다.
