학술자료 MCP의 남은 출판사 구현을 계속했다. 이 커밋은 Oxford·AIP·Cambridge의 검색·내보내기와 회귀 수리를 보존하는 단위이며 전체 작업을 종료하지 않는다. 실제 구현과 사용법은 services/scholarly-mcp, 정확한 실측 범위는 VALIDATION.md가 소유한다. 별도 웹 계정과 연락 이메일이 필요한 기능을 보류한 사용자 결정은 유지한다. 기존 연구 수집 코드·산출물과 사용자의 .codex/config.toml 변경은 수정하지 않았다.

Wiley 0건을 언급한 진행 보고에 대해 사용자는 결과가 나올 만한 다른 검색으로 대조하면 된다고 물었다. 실제로 random graphs의 684건을 양성 대조로 이미 확인했고, 수정 대상은 0건 자체의 타당성이 아니라 그 화면을 인식하지 못해 시간 초과를 내던 코드였음을 설명했다. 데이터의 부재 판정과 자동화 동작의 실패를 진행 보고에서도 구별해야 한다.

Oxford는 기본 q 검색과 Query Builder cqb·qb를 구별하고 제목·저자·초록 등의 필드, 구문 설정과 정렬을 전달한다. All과 Full Text를 같은 검색 범위로 취급하지 않는다. KUDOS 기관 진입 후 검색 HTML을 같은 Playwright context의 HTTP 요청으로 회수한다. 실제 제목 구문 검색, The Prehistory of P versus NP의 서지·초록·BibTeX, complexity 제목 검색의 페이지 경계 조회가 MCP에서 통과했다. 성공 기록과 이후 범위 대조 실패 기록은 별도로 보존한다. 최신 검증에서도 모든 호출이 안정적으로 같은 전체 건수를 준다고 보장하지 않는다.

초기에 Oxford의 일부 실패를 응답 자체의 문제로 해석했으나, 큰 검색 결과에 저널·그림이 섞이면 제목 링크의 클래스가 달라 파서가 실제 행을 놓치는 결함도 확인했다. Source HTML과 헤더·행·제목 링크를 직접 대조하고 이 유형들을 파싱하도록 고쳤다. 미인식 레이아웃을 공급자의 기능 부재로 바꾸지 않는다. 파싱에 실패하면 이미 보존한 응답과 회수 레코드를 반환하며, 전체 건수와 실제 시작 위치를 대조한다. 같은 자료원의 서로 다른 요청·응답을 섞어 진단하지 않도록 실패 근거와 코드 판본을 함께 확인해야 한다.

Oxford의 Cite 창은 정상적으로 열려도 형식 선택 뒤 다운로드 버튼에 CSS disabled가 남을 수 있었다. HTML disabled 속성이 false인 것만으로 준비가 끝났다고 볼 수 없었다. 실제 형식 재선택으로 파일이 내려오는 것을 확인했고, 최종 구현은 현재 문헌의 실제 citationModal GET form에서 resourceId·resourceType을 읽고 제공 형식 값으로 동일한 Citation/Download endpoint를 호출한다. 반환 DOI를 문헌 metadata와 대조한다. Export title list는 개별 문헌 CSV가 아니라 책·저널 목록이며 CAPTCHA를 요구하므로 사용하지 않는다. 현재 csv는 검색 레코드의 기계적 CSV다.

AIP는 Query Builder의 Title·Author·Abstract·DOI 등 필드, Exact Match 설정과 추가 terms의 condition=AND·OR·NOT을 확인했다. 화면에 보이는 대문자 SEARCH와 접근성 이름 Search가 다르고, 숨은 템플릿 컨트롤도 있으므로 실제 표시된 제어를 식별해야 했다. Cite는 Tools 메뉴 안의 stats-get-citation 링크이며, 열린 창의 BibTex·Ris (Zotero)·EndNote 링크가 실제 Citation/Download로 연결된다. Oxford의 selectFormat 폼을 AIP에 그대로 적용하지 않는다.

AIP의 10.1119/5.0328433에서 초기 메타데이터 페이지에는 초록이 없고 뒤에 830자 초록과 별도의 영상 영역이 나타났다. native BibTeX에는 같은 문헌 DOI와 abstract 필드가 들어 있었다. abstract는 이 원 필드를 기계적으로 보존하며 같은 fetch의 export와 파일을 재사용한다. 실제 MCP에서 제목 검색·서지·초록·BibTeX·페이지 경계를 통과했다. PDF나 첨부 영상을 확보한 것으로 확대하지 않는다.

Cambridge는 공개 aop-easybib/export의 RIS를 키·계정·이메일 없이 회수했다. 단일 product ID와 쉼표로 결합한 두 ID를 실제로 시험했고, 각 RIS UR의 Cambridge product ID를 요청 ID와 대조한다. 기존 Zotero 번역기는 endpoint를 찾는 참고였으며 그 구현 코드는 복제하지 않았다. 다른 exportType의 빈 응답과 오류를 그 형식의 지원으로 세지 않는다. citation API와 기관 검색·문헌 브라우저 경로는 구현 시 고정된 역할 분담이며, API 실패를 브라우저 전환 조건으로 삼지 않는다.

Cambridge의 검색 결과에는 장 제목 내부 링크와 책 제목을 바깥에서 감싼 링크가 함께 있었다. 두 구조와 product ID를 대조하여 6건을 보존했고, 온라인 발행일과 인쇄 발행일을 함께 유지했다. 주제·저널·출판사·학회 facet ID는 원 페이지에서 회수해 별도 자료 참조로 제공한다. 실제 MCP에서 이용 가능 Articles로 제한한 2건, RIS·추출, 10.1017/S1062798713000598의 서지·초록·16쪽 PDF·RIS와 67,908건 검색의 페이지 경계를 통과했다.

공통·자료원 검사 70개가 통과했다. AIP와 Cambridge의 새 서버 재검증도 통과했다. Oxford는 검색·인용문·서지·초록·혼합 결과의 페이지 경계가 통과한 기록을 보존하되, 별도 재검증의 범위 대조 실패도 남긴다. 문서의 성공 범위를 그 자료원의 모든 질의·형식·미래 호출로 확장하지 않는다. 대량 원문 확보나 연구 내용의 타당성 판정을 수행한 것이 아니다.

진단에서는 오래 실행되는 브라우저 프로브의 상태와 이후 코드 변경을 혼동하지 않도록 해야 한다. 실패한 호출의 단계, 해당 입력, 실제 HTML과 코드 판본을 먼저 고정한다. 출처 출력에는 호스트·제어 이름·문헌 식별자만 필요한 범위로 보존하며 인증 URL이나 비밀값을 출력하지 않는다. 원 브라우저 관측은 .credentials/scholarly-mcp/probes, 공개 관측과 실행 보고는 무시된 services/scholarly-mcp/data에 있다.

다음 출판사 연결을 위한 현재 관측도 남긴다. Taylor & Francis의 KUDOS 조회는 전체 문자열에서 실패했으나 Taylor로 조회하면 www-tandfonline-com.libproxy.knu.ac.kr의 정상 홈페이지에 도착했다. 후속 구현에서 이 확인된 목록 조회를 사용한다. De Gruyter Brill은 btnSearch, Project Euclid는 headerSearchTerm·고급검색 링크, SIAM은 AllFieldheaderQuickSearch0·고급검색 링크, AMS는 simpleSearchInput·AdvancedSearchLink가 있었다. JSTOR·IOP는 초기 DOM에 검색 컨트롤이 아직 없었고 이를 서비스 부재로 판정하지 않았다. ScienceDirect의 이번 홈페이지 진입은 정상으로, 이전 CPE 관측만으로 영구 차단을 주장하지 않는다. 이들 검색·내보내기와 남은 API·첨부 형식은 이어서 구현한다.
