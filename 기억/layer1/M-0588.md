# 맥락

사용자는 do-math를 mixed 전면 체급으로 총 2라운드 검증하되 수리자는 Opus 5.5 8기, 심사자는 모두 gpt-6-astra로 지정했다. 영역 4기와 관점 4기를 선택했고, 시험을 독립 검토 범위에서 빼고 실제 코드 문제와 관련된 시험만 확인하도록 교정했다. 산출물은 제품 코드 129파일이었다. 각 라운드의 기각·무처분 안건은 세션이 직접 심층 검토해 재량으로 반영하고 graphify를 갱신하라는 지시다. 런의 진입점은 `임시/do-math_검증_2026-10-20_8기/동결.md`와 `임시/do-math_검증_2026-10-20_8기/장부.md`다.

1라운드는 원항목 20건을 제기해 결합된 두 건을 병합한 19건을 심사했다. 공식 승인 조각으로 원항목 11건을 적용했고, 세션이 기각·무처분 심사 안건 6건의 수리를 보완해 원항목 7건을 직접 반영했다. 남은 두 상신안은 사용자 결정으로 보류했다. 신뢰 전환과 진행 중 검토의 조정은 전환이 드문 사건이라는 실익 판단으로, 감사 출력 위조 대응은 AI의 악의를 가정할 필요가 없다는 판단으로 보류했다. 앞서 선택한 A는 진행 중 검토가 끝날 때까지 신뢰 전환을 기다리게 하는 안이었으며, 최신의 두 건 보류 지시로 철회됐다. 이는 이 런의 결정이며 일반적인 형식 검사 보증을 새로 정의한 것은 아니다.

# 터득한 것

**기각 이유와 코드 결함의 실재를 나누어 보아야 했다.** 자원 처분·복구 대기·배정 관문의 항목은 현행 계약으로 수리할 수 있는데 상신안으로 작성되어 기각됐다. 다른 두 수리안은 실제 결함을 지적했지만 기존 검사나 공유 규칙을 손상했다. 직접 보완한 대응은 다음과 같다. 아래 구현 경로는 `.claude/skills/do-math/scripts/do_math/` 기준이다.

- R1-06: `review_engine._settle_review_resource_dispositions`가 일반 검토의 주기 포인터를 전환·재심사에도 비교했다. 그 비교를 일반 검토에만 적용해, 자원 소진 뒤 실제 제안의 개정·철회까지 기다리는 기존 `defer` 정책을 지켰다.
- R1-08: `scheduled_operator.recovery`가 착수 관문에서 반환한 이유는 활동 대기에 저장되지 않았다. 같은 실패를 처리하는 복구 활동에 대기 이유와 후속 처리를 맡을 담당자를 보존하고, 복구 실행이 실제로 입장한 뒤에만 활동을 재개하여 같은 대기의 반복 게시를 막았다.
- R1-16: 배정 관문이 임시로 선택한 `grant_id`·`profile_ref`가 미입장 요청에 남아 병합과 다음 권한 판정을 막았다. 입장하지 못한 판정에서는 두 필드를 원래 저작된 값으로 복원하고 모델 선택·대기 진단은 보존했다.
- R1-18: 입력 참조 수리안이 기존 파일 존재 검사를 잃었다. `submission._validate_reference`에서 해당 `input/` 파일을 이번 입력이 지급했는지와 실제 파일이 있는지를 함께 검사하도록 고쳤다.
- R1-M1(R1-04·R1-05): 공용 지식 개정이 이전 검토를 닫지 않았고 새 검토는 이전 판본의 계보를 잃었다. 중복된 종결·조사 취소 규칙은 `review_cycle.close_knowledge_review`로 모아 사용자 제어와 공용 개정이 함께 쓰게 했으며, 새 검토는 선행 주기의 검토 기록과 초기 검토자 자리 ID(`retained_reviewer_slots`)를 계승하게 했다.
- R1-09: 무처분된 시계 포트 안내는 실제 소유 모듈과 이음새 표를 함께 바로잡는 작은 편집으로 닫았다.

원 심사 판정과 이 직접 반영의 계수는 장부에서 구별한다.

**운전자의 일반 역할과 사용자 지정 예외를 먼저 구분해야 했다.** 세션은 별도 TDD 단계로 재현·시험 작성·수리를 하겠다고 제안했다가, 수리자가 조각을 쓰고 세션은 절차를 운전한다는 사용자 교정을 받았다. 이어 직접 재검토를 긴 회귀 검사 뒤로 미뤘다가, 기각·무처분도 직접 판단하라는 지시를 다시 받았다. 직접 재검토를 정규 승인 적용 뒤에 수행해 최종 보완 판본을 검사하도록 순서를 정리했다. 이는 미통과 안건에 대한 명시적 예외이며 일반 파견 절차에 세션의 독자 수리 단계를 추가한 것이 아니다.

**정상 최종 산출과 파일 처리 위반의 처분도 구분해야 했다.** 수리자 7번은 자기 산출을 교체할 때 `.new`를 만들었으나 최종 지정 파일과 공식 검산은 정상이었다. 산출 계약의 임시 파일 금지에 따라 재파견하려 했고, 사용자는 최종 산출을 사용하고 진행하도록 예외를 확정했다. 실제 재파견은 하지 않았다. 이 사례를 일반 산출 계약의 폐지로 확대하지 않는다.

검증은 단계별로 보존했다. 직접 수리의 재현 7건은 수정 전 모두 실패하고 수정 후 같은 7건이 통과했다. 재현은 R1-06·R1-16·R1-18에 각 1건, R1-08과 R1-M1에 각 2건이며 원항목 계수와 구별한다. 그중 복구 prompt의 입력 한도 초과를 확인하는 시험에는, 같은 요청을 반복해도 새 상태 commit을 만들지 않아야 한다는 단언을 더했다. 이 단언이 실패한 뒤 수리 후 통과하는 것도 확인했다. 관련 회귀 105건 중 104건은 통과했고, 나머지는 독립 peer를 선행 판본의 개정으로 만든 시험 전제였다. 실제 독립 후보 생산자로 고친 뒤 해당 검사 하나를 다시 실행해 통과했다. 별도 변경 영역 회귀 205건은 모두 통과했고 실행 중 소스 변경이 없었다. 미러와 구조 검사도 통과했다. graphify 갱신도 완료했으며 규모와 추출 결과는 장부에 기록했다. 전수 회귀의 두 중간 실행은 중단했으므로 전수 통과 근거가 아니다. 시험 지침이 요구하는 전수 회귀 1회는 두 라운드의 반영이 끝난 최종 코드 판본에서 완결할 예정이다. 이 커밋은 런 종료가 아니다.

원 회귀 자료는 `임시/vr-r1-direct-red/`, `임시/vr-r1-direct-green/`, `임시/vr-r1-direct-regression/`, `임시/vr-r1-peer-fixture/`, `임시/vr-r1-changed-regression/` 등에 있다. 모두 로컬 Git 제외 자료이며 정리로 사라질 수 있다. 추적되는 장부와 `임시/do-math_검증_2026-10-20_8기/기각보관/do-math-20261020-라운드1.md`가 판단 복원의 진입점이다.

# 작업 너머 시사점

라운드의 기각을 결함 부재로 읽거나, 정상 산출을 형식 위반 하나와 동일하게 취급하면 호출자가 요청한 미통과 안건의 재검토와 정상 산출의 활용이 누락된다. 이번에는 역할 경계, 최종 산출의 검산, 사용자 예외와 실제 코드 손상을 각각 확인해야 했다. 후속 dream에서 [[L-0016]]의 미통과 재검토와 운송·결손 처리, [[L-0001]]의 시험 전제와 제품 회귀 구별을 함께 검토할 후보로 남긴다. 이 사례를 검산이나 정족을 임의로 우회하는 일반 권한으로 승격하지 않는다.
