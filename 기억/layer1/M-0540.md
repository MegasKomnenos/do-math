B123 전체 일반 실행은 세션2987과 실제 프로세스·작업자 보고로 관찰했고 종료코드1로 끝났다. 선택은3984개다. 최초 배너의3983개는 병렬 대상이며 별도 격리1개가 더 있었다. 최종은3424통과·1실패·558미실행·1건너뜀,6457.3초이고 complete=false/successful=false다. 시간 초과가 아니라 실제 실패와 작업자 미완결로 판정했다. 공식 Python 지문의 changed_during_run은 비어 있고, 별도로 기록한 canonical tracked/untracked969파일의 실행 전후 SHA와 HEAD도 동일했다. 사용자 변경과 미추적 시험은 제외하지 않았다.

단언 실패는 flows.test_git_init_activation의 템플릿 복원 시험이었다. HEAD를 지워 로컬 .git를 불완전하게 한 뒤 저장소가 없다고 기대했지만, 현재 실제·대역 Git 계약은 정상 부모 checkout 탐색을 계속한다. B124 수정은 기존 isolated_nonrepository_parent(first.root)를 HEAD 삭제 전에 적용하는 두 줄(import 포함)이다. 제품·대역·공통 builder는 바꾸지 않았다. 깨진 로컬 저장소의 False, 복원 후 True·sha256형식·describe·head 동일성과 subprocess 미기동 단언을 유지했다. 같은 checkout 내부 조건에서 Git init flow2개와 불완전 내부 .git의 정상 부모 탐색 계약1개를 실행해3개 통과·14.4초·실행 중 변경 없음을 확인했다. 이 부분 통과로 B123 원보고를 성공으로 바꾸지 않는다.

558개 미실행은 별도 문제다. parallel-0 worker가 exit1로 끝났고 결과 게시가 완결되지 않았다. 마지막 report 행은 Git backend read_objects 시험의 running이었지만 stderr에는 ok가 있고, 잔존 result.json.tcjee01f.tmp에는 passed/1.188초가 있다. 마지막 제품 검사를 실패로 추정할 근거가 없으며 stopTest → preserve → 결과 게시에서 중단된 정황이다. 그 뒤557개와 보고 미완료인 마지막1개를 합쳐558개 미실행으로 보존했다. 다른 worker 둘과 별도 격리는 종료0·완료였다.
