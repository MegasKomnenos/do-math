## 맥락

[[D-0006]]의 제안 3을 사용자가 승인해 집행했다. [[M-0284]]에서 `hwp5html`이 없던 HWP 추출은 stderr에 오류를 냈지만 종료 코드가 0이었고 본문 없는 TXT가 남았다. 코드를 읽어 보니 두 경로가 있었다. `main`은 파일 없음·추출 오류를 stderr에만 출력하고 항상 정상 종료했다. `extract_hwp`는 변환기가 실행됐지만 xhtml 산출이 없으면 오류 없이 빈 문자열을 반환해 "[완료] 0자"로 처리됐다.

## 변경과 판단

실패는 세 조건으로 정했다. 입력 파일이 없을 때, 추출 중 예외가 나서 결과에 error가 기록될 때, 추출 텍스트가 공백뿐일 때다. vision 플레이스홀더는 텍스트 안에 들어가므로 이미지 페이지만 있는 PDF는 빈 추출로 잡히지 않는다. 여러 파일 중 일부가 실패해도 나머지 파일의 처리와 stdout 출력은 계속하고, 마지막에 종료 코드만 1로 둔다. 가용한 결과를 버리지 않으면서 호출 측이 실패를 알게 하려는 선택이다. 무음 음성처럼 정당하게 빈 결과도 실패로 표시되지만, 그 경우에도 사람이 확인해야 하므로 허용했다. `extract_hwp`는 산출이 없으면 변환기의 종료 코드와 stderr 앞부분을 담은 RuntimeError를 내고, 이는 기존 `process_file`의 예외 처리로 error에 기록된다.

SKILL.md 사용법에는 종료 코드 1의 조건과, 0이 완전성을 보증하지 않는다는 한 문장을 더했다. 숫자만 빠지는 텍스트 레이어처럼 스크립트가 감지하지 못하는 손실은 기존 4항 설명이 그대로 다룬다.

## 검증

`scripts/test_extract_all.py`를 새로 두었다. 먼저 실행하자 파일 없음, 빈 텍스트, 여러 파일 중 일부 실패, HWP 산출 없음의 4건이 실패했고, 비어 있지 않은 텍스트의 성공을 보는 양성 대조 1건은 통과했다. 구현 뒤 5건이 모두 통과했다. 미러 생성기로 `.agents` 사본을 갱신했고 270파일 드리프트 없음이었으며 사본의 테스트도 통과했다. 실제 `hwp5html`이 없는 환경에서 HWP 파일로 end-to-end 실행하지는 않았고, HWP 경로는 `subprocess.run`을 대역으로 둔 단위 검사로 확인했다.

L-0004 "완전성 검증" 항목의 종료 코드 서술이 과거 동작이 되었으므로 정정 대기 한 줄을 남겼다.
