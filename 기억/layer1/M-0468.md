운영자 후보4모듈의52원사례를 기존 정상 생산자 위에 통합했다. [[M-0467]]의 학술 가족은e63bcbab로 확정했다. B52는 제품 동작이나 기존 운영자 fixture를 바꾸지 않고 evidence/supervision/bootstrap/recovery 계약의 모집단을 연결한다.

증거 시험은 실제 scheduled_operator._json/_load_json으로 path와 원 바이트의sha256/text/base64를 왕복하며 마지막 개행과 원자적 파일 하나를 검사한다. 지원하지 않는 값·비유한 수의 반려는 이전 파일과 directory 전건을 보존해야 한다. 예약 인자와 공급자 제한의 시간/표시는 실제 scheduler 포트를 지나며 감독은 기존 저장 상태와 진단/기동 증거를 다시 읽는다.

bootstrap 시험은 실제 설치의 frozen manifest와 파일을 읽어 한 좌표씩 손상시킨다. bytes 변경·파일 대신directory·누락 entry·future mtime·비정규/탈출 path·invalid mark를 거부하고 검증되지 않은 cache를 게시하지 않는다. 동일 동결의 경쟁 게시자는 검증한 winner를 재사용하며 copy 중 설치 변경은 자기 staging만 정리한다. CLI는 정확 검증 receipt를 출력한다. 제품 기동/파일 검증을 대역으로 바꾸지 않는다.

복구 시험은 실제 Scene/Repository/lock/ModelRunner와 외부 Job/Scheduler 포트를 사용한다. 미확인 live execution은 capacity/model 생성 전 복구를 막고 상태를 보존한다. 실패한 검증은 diagnosis를 보존해 restart/repeat를 막는다. receipt 수신 전 HOLD와 후 HOLD의 계수, provider limit/모델정책/unknown local termination, 예약·수집·unlock 뒤 재기동의 순서가 기존 가족 선택에 포함됐다.

정확17모듈의 unit4/sim78/flows35, 총117개가93mxh4xo에서114초에 완결 통과했다.15개 개별 예산 초과를 보존한다. 실행 중 source 변경은 없다. 원보고·SHA256·현재4파일 지문과 구조 보고는 current_work.operator_population_integration에 연결한다. 이 부분 설치/Job 계약은 전체T4나 최소 실공급자T5의 성공 증거가 아니다.

다음은 지식7모듈과 명시 합성 Lean 생산자1개 및 남은 engine/CLI/교차 모집단이다. 녹화 원문과 합성 stdout를 구별하고 현재 스키마/생산자/원문1e19·1f61·P2원래12·여섯 부류/2단계11의 검증과 최종같은판본 전체관문·예산을 이어서 완료한다.
