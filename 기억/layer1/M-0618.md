사용자는 연구 실행기가 언제, 왜 종료됐는지 확인한 뒤 파일 교체 재시도를 1초에서 1분으로 늘리도록 지시했다. 2026-10-24 한국 시간 04:58:39의 실행기 stderr에는 knowledge/index.md 임시 파일을 본 파일로 교체하는 os.replace가 WinError 5로 실패했다고 기록돼 있었다. 임시 파일 수정 시각은 04:58:38이며, 기존 write_text는 50밀리초 간격으로 약 1초 재시도한 뒤 예외를 최상위로 전달해 실행기 전체를 종료했다. 파일 교체를 막은 프로세스나 보안 프로그램은 확인하지 못했다. 파일 점유는 가능한 설명이며 확정 원인으로 기록하지 않는다.

종료한 것은 실행기였고 이미 파견된 세션은 별도 프로세스로 계속 작업했다. 실제 연구는 05:13:58, 탐구는 05:39:18에 종료됐지만 후속 반영·파견은 멈췄다. 07:50:39 재기동 뒤 미반영 산출을 회수했다. 이 운영 사실의 원자료는 `.skill-workspace/do-math/parking-unimodality-fresh-20261023-014524/runner/start-bd8217dfa07345fab434f7d0750af241.stderr.log`와 해당 세션의 exit.json이다. 이 경로들은 상위 Git에서 제외된 로컬 자료로, 이번 커밋에 로그 사본을 보존하지 않는다.

사용자가 선택한 수정 범위에 따라 정본 runner.py의 교체 재시도 기한만 60초로 늘렸다. 같은 함수가 색인과 JSON 상태 파일을 쓰므로 양쪽에 적용된다. 재시도 대상인 Windows 오류 5·32·33, 50밀리초 간격, 완전한 임시 파일을 교체하는 방식과 기한 초과 시 오류 반환은 유지했다. 무기한 대기나 자동 재기동 감시는 추가하지 않았다. 따라서 60초를 넘는 접근 거부에 대한 전체 종료 가능성까지 해결한 변경은 아니다.

기존 Windows 시험은 파일을 1.15초 동안 실제로 연 채 두었다가 해제하는 경우의 성공을 확인하도록 바꿨다. 지속 거부 시험은 시계를 0·2·59.95·60초로 모의해 60초 이전 재시도와 기한 도달 시 오류, 이전 파일의 보존을 확인했다. 두 시험은 통과했고 정본과 배포 사본 192파일의 미러 검사도 통과했다. 수정 적용 시 프로세스 생성 식별값을 확인해 실행기 하나만 종료·재기동했으며, 그때 실행 중이던 세션 다섯 개의 프로세스 생존과 새 실행기의 정상 상태를 확인했다. 이후 사용자가 working tree 전체의 커밋을 요청했고, 변경 네 파일과 이 기록·색인을 한 작업 단위로 묶었다.
