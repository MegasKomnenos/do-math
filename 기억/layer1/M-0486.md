[[M-0485]] 뒤의 B71은 원래 3-C의 C-19와 B-36을 현재 소비 흐름에 연결한다. 현재 공통 grant 판정은 governance.authorize이고, 제한 복구의 공통 허가 판정은 lifecycle_engine._limited_recovery_allowed다. 이미 한 정의를 쓰는 실제 코드와 소비자를 확인하면서 기존 시뮬레이션을 보강했으며 제품 동작은 바꾸지 않았다.

C-19에서는 실제 실행을 준비·시작한 소유자 위에서 같은 action의 authorize와 _action_lifecycle_gate를 확인한다. 공개 제어로 원 grant를 철회한 뒤 권한 거부·배정 거부와 계산자가 보는 실제 stop flag가 연결되는지 확인한다. 만료는 wall clock만 유효기간 뒤로 옮겨 호출의 monotonic deadline과 구별한다. 기본 허가가 유지되는 동안에는 배정 관문이 통과하며, 같은 grant가 만료되면 권한과 배정이 거부되고 실제 실행이 한 번 stopping으로 간다.

대체 grant가 남아 있는 기존 실행 중 철회 흐름도 보강했다. 원 grant가 바인딩된 action은 계속 거부되고, grant_id를 벗긴 별도 질의는 대체 grant가 허용한다는 기존 단언을 유지한다. 원 실행에 다른 허가를 소급 적용하지 않으며, 늦은 산출은 원 실행의 실패·종결·보존 원문과 연결된다. 이 사례는 실제 worker/ModelRunner 흐름을 Job·외부 CLI 대역 경계 위에서 실행하며 원격 모델 품질을 주장하지 않는다.

B-36은 공개 pause와 공개 limited_recovery 결정으로 만든 실제 입력을 사용한다. 유효 입력, 결박 없음, pause ID, pause basis, action hash, 대상, 목적, 프로필 판본, 승인 원문, grant 철회, 영구 종결, 새 정지의 열두 조건을 각각 대조하고, 마지막에는 실제 승인 만료까지 확인한다. _limited_recovery_allowed·_execution_stop_requested·_action_lifecycle_gate가 같은 허가를 소비해야 한다. 유효한 제한 복구만 paused 상태에서 정지 veto를 통과하고, 범위나 현재 전제가 달라지면 배정이 거부된다. 일반 연구를 다시 허용하거나 pause를 해제하는 동작을 만들지 않는다.

6iybd26y의 세 사례와 bs4afdpv의 승인 만료·대체 grant 사례가 통과했다. 첫 관련 전체 _dw8abzh는 99개 통과·한 개 구조 실패였다. 새 assertRaises가 거부 사유를 고정하지 않아 unpinned_rejection을 탐지했다. 실제 연구 권한 거부, lifecycle/conversation 배정 금지, 영구 종결, stale profile의 사유를 확인해 고정했다. 처음 프로필 오류 사유를 잘못 추측한 6fg0ls0m의 한 실패는 `profile reference is absent or stale`로 교정했고 jn2hociz에서 통과했다. 이는 새 시험의 사유 기재 오류이며 제품 결함을 수정한 것으로 세지 않는다.

구조의 공유 규칙 순회에는 C-19의 현재 authorize 소비자와 B-36의 상속된 소유자 허가 소비자를 추가했다. 현재 선언은 원래 규칙 다섯 쌍에 대한 직접 소비를 다룬다. 하나의 정의와 현재 직접 호출자의 모집단을 확인하며, 이름이 다른 의미상 복제 전건의 부재를 AST만으로 증명했다고 주장하지 않는다. 호출 목록에 승인·현재성·제출·형식 실행·복구·준비성 소비도 유지하고 실제 두 소유 관문을 독립적으로 검증했다.

다섯 규칙으로 늘린 첫 구조 검사 tu5nnhx4는 7.2초로 5초 예산을 넘었다. 제품 AST를 규칙마다 다시 순회하지 않고 노드·함수·호출 지점을 한 번 수집해 같은 목록을 재사용하도록 바꿨다. 후속 h72hs655는 같은 다섯 규칙의 소비 집합을 2.2초에 확인했다. 두 실행은 같은 기계에서 다른 무거운 실행 없이 순서대로 수행했으며 선언·단언을 줄이지 않았다. 이 작은 구조 검사의 비용 감소를 전체 T2/T3 속도 달성으로 바꾸지 않는다.

교정을 모두 포함한 마지막 같은 판본의 전체 구조·변경 영역·실제 제한 복구 호출 실행 y8r6bywy는 structure 45개·sim 54개·flows 1개, 합계 100개가 56.8초에 완결 통과했고 실행 중 변경은 없었다. 개별 예산 초과는 11개다. 원보고는 추적된 `검증/2026-10-04-허가-정지-차분/report.json`에 보존하며 B71에 현재 파일 지문과 정확한 명령·범위·제약을 연결한다. 중간 Temp 보고는 로컬 보관이므로 정리 후 존속을 가정하지 않는다.

원래 열한 쌍 중 현재 소비와 검증을 연결한 쌍은 B-16·C-12·D-02·C-19·B-36 다섯이다. 각 보고의 명시한 입력 공간 밖까지 완료라고 주장하지 않는다. 남은 원래 C-15·B-49·B-32·B-33·C-13·A-47과 이후 사본, 원래 19의무·61보존 지식·P2 12항목·여섯 부류·2단계 11의무, 최종 같은 판본 전역 T2/flows·fresh T3·전 대상 변이·예산·T4/T5 최소 실호출·말뭉치·최종 지침·미러·main 목표는 유지한다. 사용자 진행 문서와 미추적 교차 시험은 이번 확정에 포함하지 않는다.
