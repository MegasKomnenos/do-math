## 실제 플래그와 실제 프로세스

[[M-0429]]의 실행 파일 정규화는af3b7193으로 확정했다. 그때 남은 예상 실패 KD-0003을 별도 변경으로 닫는다. setup_lean.run의 짧은 subprocess가 CREATE_NO_WINDOW를 전달하도록 고쳤다. 기존 cwd/env/check/stdout 동작은 유지하며, Git 포트 전달 등 후보 setup의 다른 변경은 가져오지 않았다.

main의 fjtl48u4는 정본 소스에 콘솔 억제 플래그가 없는 실제 구조 red다. 기존 WINDOWED 예외와 결함 표시를 제거했다. 호출이 실제 하나 존재하고 creationflags 값이 정확한 Windows 억제 플래그인지 검사한다. 단지 인자가 있다는 검사나 호출이 없어서 통과하는 검사를 남기지 않는다.

기존 boundary.test_setup_lean_compile에 Windows resource 격리 시험을 추가했다. 실제 setup_lean.run이 실제 자식 Python을 실행하고, 자식이 kernel32.GetConsoleWindow로 자신의 콘솔 핸들을 기록한다. 결과는0이며 작업 디렉터리와 명시한 probe 환경값도 그대로다. 새 모듈과 내부 제품 패치는 없다. 수정 전 실제 창을 띄우는 프로브를 실행할 필요는 없었고 소스 red로 원인을 확인한 뒤 숨김 플래그가 있는 현재 경로만 실제 호출했다.

main의 afxt_xhn은10개가 전부 통과했고 예산 초과가 없다. 기존 대표 compile2개는 실제 Windows Job과 작은 Python compiler로 명령·원문·stdout/stderr·실패 판정을 검사한다. 실제 Lean 증명이나 설치를 실행한 것은 아니다. 후보도 같은 새 실제 콘솔 검사1개 ypf5rpgp를 통과했다. 후보의 별도 Git 포트 계약은 보존하여 전체 파일을 덮어쓰지 않았다.

## 근거와 다음 범위

후보 동기화 첫 shell 명령의 quoting SyntaxError로 복사가 실행되지 않았고 뒤 선택은 missing ID로 거부됐다. 이를 제품 시험 실패로 세지 않았다. 동기화 코드를 로컬 파일 스크립트로 옮겨 성공을 확인한 뒤 실제 시험을 실행했다. 이 운영 오류를 감추려고 시험 선택이나 단언을 바꾸지 않았다.

main의 열린 결함은11개다. 전체 T4 폐쇄를 부분 경계3개로 대신하지 않는다. 원 보고 전문은 사용자 Temp, 복사 스크립트는 .skill-workspace의 Git 제외 로컬 자료이고, 추적 진입점은 단계-전환표 current_work.console_integration의 보고/소스 SHA256이다. 전체 실패 기준선 원보고와 당시 교정 원문은 M-0427의 추적 아카이브에 있다.

미러873파일 drift0과 기억 색인을 확인해 setup2행, 정본 구조 검사와 기존 경계 시험, 원장/미러/작업판/기억을 함께 확정한다. 기존 Lean 설치·연구 인스턴스는 변경하지 않았다. 다음은 입력 소비와 신뢰 전환의 남은 수리이며, 최종 전체 관문·성능 예산·함수 변이·말뭉치도 남아 있다. 새 목표는 active로 유지하고 푸시/graphify 갱신은 하지 않는다.
