title: JSTOR의 원 BibTeX와 현재 도서 식별자를 연결하고 구현 작업으로 복귀함
convention_version: 24

사용자는 재시작 관련 조작을 중단하고 본래 구현을 계속하라고 지시했다. 앞선 작업은 현재 연결의 갱신에 매달려 CLI 콘솔 제어와 자동 종료·재개를 시도했고 두 차례 종료 대기가 실패했다. 사용자가 원한 것은 구현의 지속이었다. 현재 연결의 갱신을 코드 작업의 선행 조건으로 둔 것이 작업을 지연시켰다. 후속 구현은 기존 SDK stdio 검증으로 진행하며 CLI·콘솔 재시작 실험을 반복하지 않는다. 임시 자동 제어 helper는 CANCELLED_BY_USER 표지로 비활성화했고 인계문에서 실행 지시를 제거했다.

JSTOR의 공식 내보내기 안내에는 Text file이 있었다. 실제 공개 citation/text/345683 응답은 text/plain이지만 파싱 가능한 BibTeX 한 건이었다. citation/bibtex 경로의 404와 구별해 실제 작동하는 text 경로를 연결했다. 인용문에는 doi 필드가 없었으나 url은 요청 문헌의 stable 링크였다. RIS의 UR과 BibTeX의 url을 원 식별자로 대조하고, DOI 필드를 임의로 추가하거나 BibTeX를 재생성하지 않는다.

현재 JSTOR 도서에는 jj.8306294 같은 식별자가 있다. 기존 검증은 숫자와 j. 접두사만 허용해 유효한 도서 URL을 거부했다. 실제 원 RIS가 BOOK 기록을 반환함을 확인한 뒤 jj. 식별자와 DOI·stable URL 형태를 허용했다. 도서 서지의 유형·저자·발행연도·ISBN과 제공자 안내문을 그대로 보존한다.

export는 원 RIS와 BibTeX를 함께 반환한다. 기본 artifact는 기존 RIS로 유지한다. 추가 형식의 요청 실패나 다른 문헌 반환이 발생해도 이미 받은 서지·RIS를 남긴다. 다른 문헌의 BibTeX는 identity_mismatch로 거부하고 받은 원 파일은 source_export로 보존한다. 원 응답과 대역 실패 검사로 이 경계를 확인했다.

새 SDK stdio의 services/scholarly-mcp/data/validation/20260910T223621032180Z-jstor-workflow.json은 completed=true다. 기존 문헌의 서지·초록·RIS·BibTeX와 jj.8306294 도서의 서지·두 원 인용문을 실제 MCP로 회수·추출했다. 추가 회귀 검사 4개가 통과했다. 실제 원 검색·전문 회수는 이 완료 범위에 포함하지 않는다.

전체 작업은 진행 중이며 푸시하지 않는다. 다음 조사는 JSTOR의 원 검색 화면이 사용하는 요청 경로와 남은 출판사 기능이다. API 키·별도 계정·연락 이메일을 요청하거나 자료원 경계를 자동으로 바꾸지 않는다.
