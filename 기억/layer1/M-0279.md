## 맥락

사용자는 verify-rounds로 do-math 구현이 통합 설계의 목적을 달성하는지 검토하라고 요청했다. mixed·전면 체급을 지정하고 심사 모델은 gpt-6-astra low로 바꿨다. [[M-0278]]의 구현자 변명은 각 검토자가 독립적으로 평가할 참고 자료이며, 그대로 승인하거나 따르는 기준이 아니라고 명시했다. 형식과 절차 문서도 함께 검토하도록 했다.

정본 85개 파일을 대상으로, 문서·역할 계약, 실행·통치 기반, 지식·연구 판단, 시험·검증의 네 영역과 기능 목적·수단 실익, 정보 전달·시간선의 두 관점을 배정했다. 강한 제약의 형식 차이를 곧바로 결함으로 만들지 않고, 해당 수단이 맡던 목적과 소비자의 전제가 실제로 보존되는지 대조하게 했다. 현재 구현과 과거 완료 보고를 새 완료 기준으로 삼지 않았다.

## 실행과 판정 범위

운전 세션에 Claude Agent 도구가 없어 같은 역할 정의와 Opus 모델·노력을 명시한 설치 CLI 세션을 사용했다. 실제 시작·응답과 모델을 확인한 뒤 수리·병합을 실행했다. 심사는 Codex CLI의 기·배치별 새 세션을 사용했고, 6개 실행 모두 실제 로그의 gpt-6-astra·low 설정과 서로 다른 세션 ID를 확인했다. 운송 수단의 차이는 런 장부에 기록했으며 새로운 사용자 확정으로 취급하지 않았다.

수리 산출은 서식 검산뿐 아니라 수행 기록도 확인했다. 시험 담당의 첫 실행은 필수 참고 자료를 부분적으로만 읽어 같은 파견문으로 한 번 재파견했고, 재파견은 담당 시험 전건과 지정 원문의 읽기를 마쳤다. 시간선 관점 담당은 재파견에서도 명시한 미검토 범위가 남아 이번 라운드에서 결번 처리했다. 이 관점을 전건 검토했다고 보고하지 않는다. 기능 목적 관점 담당은 같은 Opus high의 보조 조사를 사용했으며 직접 읽은 범위와 위임 조사 범위를 구별했다. 보조 조사 호출의 비동기 실행은 스킬의 동기 Agent 파견과 다른 운영 사실로 보존했다.

동결문의 기준 목록에 루트 AGENTS.md를 실제 파일처럼 적은 좌표 오류도 확인했다. 운전 세션이 대화로 받은 지침의 이름과 실재 경로를 혼동한 것이다. 그 파일을 읽었다거나 인용 검산을 통과했다고 처리하지 않았다. 사용자 지정 세 문서와 CONTEXT.md의 실제 원문을 기준으로 검토했고, 해당 경로의 부재를 장부에 공개했다.

유효한 5기 산출의 69항목을 공식 판독했다. 교차·결합으로 10개 묶음을 만들고, 46개 단독 항목과 함께 56개 심사 대상을 구성했다. 28항목씩 두 배치로 나누어 지급 크기와 항목 수를 검산했다. 심사 3기 모두 56항목 전건을 판정했으며, 정족에 따라 30항목을 수리 확정하고 26항목을 기각했다. 확정 상신·전달은 없었고, 심사에서 기록한 승계 1건을 장부에 보존했다. 세션이 별도로 조각을 저작하거나 기각을 승인으로 바꾸지 않았다.

## 적용과 검증

공식 적용은 30항목·51조각을 정본 24개 파일에 반영했다. 변경 Python 19개 파일의 문법 검사와 생성 미러 24개 갱신·드리프트 검사를 통과했다. 수정 전 전체 시험은 272개 중 271개 통과, 심볼릭 링크 관련 1개 미실행이었다. 시험의 통과와 통합 설계의 목적 전건 충족은 별도 판단으로 유지한다.

적용 후 전체 시험은 277개 중 276개 통과, 같은 심볼릭 링크 관련 1개 미실행이며 실패·오류가 없었다. 589.082초, exit 0을 원문으로 확인했다. 공식 결산은 본표 69행 중 적용 34행을 기록했다. 병합 항목의 구성 행까지 전파한 계수이며, 적용 대상 30항목과 구별한다. 첫 라운드이므로 연속 두 라운드를 요구하는 신호는 없었고 하한 3 미달로 다음 라운드를 판정했다.

본 런의 지속 기록은 임시/do-math_검증_2026-09-15/동결.md와 장부.md다. 라운드별 산출·원문·모델 로그는 같은 런의 라운드1에 있으며, 종료 후 정리는 사용자가 호출한 스킬의 설정을 따른다.
