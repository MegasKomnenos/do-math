[[M-0503]]의 실제 Claude 2.1.289 원자료에는 같은 작업의 시작과 완료 알림, 정상 최종 응답이 있었지만 TaskOutput은 없었다. 실제 ToolSearch도 도구가 없다고 반환했다. 공통-실행.md는 TaskOutput이 제공될 때 쓸 수 있다고 이미 조건부로 적었으므로 제품 탐침의 무조건적인 도구 이름 강제가 현행 계약과 어긋났다.

기존 sim.test_operator_probe_contract의 성공 시나리오를 실제 task_started/task_notification 모양으로 바꾸니 4r57pk4v에서 actual_wait_tool=False로 실패했다. B87은 TaskOutput 호출 여부 대신 네이티브 작업이 최종 응답 전에 완료했는지 판정한다. 시작·완료 알림이 각각 하나이고, 비어 있지 않은 task_id와 tool_use_id가 일치하며, local_bash background 시작과 completed 상태이고, 시작 행 < 완료 행 < 선택된 result 행이어야 한다. 파싱과 실제 turn 완료도 필요하다. 기존 nonce 파일과 로컬 종료 장벽 검사는 유지한다.

실제 B86 녹화 스트림으로 새 판정의 성공을 확인하고 작업 ID·도구 호출 ID 교체, stopped/failed 상태, 완료 누락과 시작 전/최종 응답과 같은 행/응답 이후 완료를 반례로 검사했다. 실제 ModelRunner·worker·collector를 통과하는 기존 시뮬레이션 성공/실패 검사도 유지한다. 원래 B86 background 실패 보고는 변경하지 않았다. 새 실호출을 추가하거나 그 원보고를 현재 코드의 성공 보고로 바꾸지 않았다.

같은 실환경 탐침 CLI에는 아직 기본 180초와 필수 양수 --timeout-seconds가 남아 있었다. 사용자의 소프트 예산 지시에 따라 이 옵션과 run_case의 timeout 인자를 제거하고 ModelRunner에는 None을 전달한다. 기존 탐침 검사마다 실제 직렬화 요청의 max_runtime_seconds=null을 확인한다. 옛 CLI 옵션은 조용히 무시하지 않고 알 수 없는 인자로 거부한다. 제품의 유한 역할 호출 창·임대 등 의미상 기한은 변경하지 않았다. stop 시나리오는 도구 착수 사건을 받은 명시적 중지 요청으로 계속 검사한다.

현재 탐침 스키마의 status·nonce·phase 문자열 타입도 기존 파일 탐침 검사에 연결했다. 직접 탐침 23개가 통과한 뒤 구조48·단위13·Sim39, 합계100개가 49.7초에 통과했고 실행 중 소스 변경이 없었다. 원보고는 docs/do-math/시험-재편-2026-09-29/검증/2026-10-04-백그라운드-탐침/red.json, focused.json, report.json으로 추적한다. 마지막 report.json SHA256은 510d23e8edb878d3b650a8d4f4e7b6462dec3d745ca53ceaca10d1a314850ad5다. KD-1911은 이 재현과 수리로 닫았다.

다음 실행은 B85~B87을 포함한 현재 후보의 일반 통합 확인이다. 최종 요구 전체나 T4/T5 마감으로 부르지 않는다. 기본 선택의 contracts 포함을 실행 전에 확인하고, 실행 소스는 고정한다. 남은 녹화 자료 확보는 제품/시험 편집 없이 별도 로컬 원자료로 진행할 수 있지만 새 전수 감사로 확장하지 않는다. 다른 원문 의무와 최종 T3·변이·배포 관문은 계속 남아 있다.
