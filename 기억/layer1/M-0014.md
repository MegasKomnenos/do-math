# 검증런 2.7.10.59.3 완료: 두 라운드, L12~L16 결정 반영 결손 4건 수리, 병합 묶음의 독립 수렴 관측

## 맥락

M-0012가 기록한 0단계 기준선 확립(커밋 `adf41fc`) 뒤, verify-rounds SKILL.md 절차를 그대로 따라 검증런 `2.7.10.59.3`(파견문: `.sdd/dag/pvsnp-탐사-1/행/2.d/7.d/10.d/59.d/3.md`)을 완료했다. 검증 대상은 공유 불변식·판정표·파견표와 행 24~33(L12~L16 재판독 작업자·직후 검증런)이다. 잣대는 결정 `2.7.10-첫재판독.md`의 확정 문구 두 항(L01 내용 기준의 적용, 분량·밀도 비례 규범)이다.

파라미터는 파견문이 직접 지정했다: 수리_기수 4(전원 관점 담당: 운전성·충족성·정합성·승인 대조), 심사_기수 3, 심사_정족 3, 라운드_하한 1, 라운드_상한 2, 모델_프리셋 `codex-full`(수리 gpt-5.6-terra high · 병합 gpt-5.6-terra low · 심사 gpt-5.6-terra medium, codex CLI로 파견). 두 라운드 모두 §8 상신 신호를 감지하지 않았다.

라운드 1: 항목 4건 제기(4기 수리자 각자 1건씩). 셋(R1-01·R1-03·R1-04)이 같은 좌표(`59-보고.md` 64행)를 지목해 묶음 R1-M1으로 병합됐고 3/3 만장일치로 승인·적용됐다. 판정표가 L12 작업자의 원문 분량·구조·항목 수·읽기 구간 기록 의무를 작업자 행(24)이 아니라 직후 검증런 행(25)에 잘못 귀속한 결손이다. 나머지 하나(R1-02, 작업자 행 5개의 완료 기준이 일곱 내용 기준을 빠뜨렸다는 지적)는 심사 2/3으로 정족(3) 미달로 기각됐다. 심사 1기가 위치 칸의 인용("임무 8항")이 실제 조각이 고치는 9~10행과 대응하지 않는다고 판정했다. 라운드 2: 항목 1건 제기(R2-01, 직후 검증런 5행의 결정 적용 완료 기준이 일곱 내용 기준을 이름으로 요구하지 않는 결손), 3/3 만장일치 승인·적용. 두 라운드 모두 적용 뒤 `dag_check.py --table 파견표.md`가 exit 0 무발견을 냈다.

## 터득한 것

- 라운드 1의 R1-01·R1-03·R1-04는 4기의 수리자 중 3기가 서로 다른 관점(운전성·정합성·승인 대조)에서 독립으로 같은 결함(같은 파일, 같은 64행)을 발견하고 각자 다른 각도로 서술한 뒤 같은 조각으로 수렴했다. `묶음` 하위명령이 조각 교차 간선으로 이 셋을 정확히 하나의 병합 항목으로 묶었다. 관점 분산이 같은 결함을 여러 각도에서 잡아내는 사례를 실측했다.
- R1-02(기각)와 R2-01(승인)은 같은 근본 문제(일곱 내용 기준의 명시 누락)를 서로 다른 필드에서 겨냥했다. R1-02는 작업자 행의 「완료 기준」, R2-01은 직후 검증런 행의 「결정 적용 완료 기준」. R1-02가 위치 인용 오류로 기각된 뒤, 다음 라운드의 독립 수리가 같은 종류의 결손을 정확한 위치·정확한 조각으로 다시 잡았다. SKILL.md §3이 명시하는 "한 라운드가 놓친 것을 다음 라운드가 같은 절차로 회수한다"는 설계 지향의 실제 작동을 확인했다.
- 이 국면(`pvsnp-탐사-1`)에서 형제 검증런(`59.1`·`59.2`·`59.4`·`59.5`)이 병행 실행 중이었으나, 이 런의 라운드 진행(사본·수리·병합·심사·적용·커밋)은 자기 전용 산출물(행 24~33, `59-보고.md`)만 건드려 형제 런과 충돌하지 않았다. 유일한 병행 마찰은 0단계 전 메모리 노드 번호 배정(M-0012 참조)이었다.

## 작업 너머 시사점

M-0006·M-0007·M-0009·M-0010·M-0011·M-0012가 이미 지목한 dream 후보(do-dag 파견 반환 계약에 "검산 통과 직후 그 파견의 쓰기 집합만 커밋한다" 단계를 넣는 안)는 이 런에서는 재현하지 않았다. 0단계 대행 커밋 이후 라운드 진행 자체는 병행 마찰이 없었다. 반면 메모리 노드 번호 배정의 다자간 경합(M-0012)은 이 국면이 끝나기 전에 검토할 실익이 있는 별개 후보로 남는다. L-0016(위임 파이프라인 운영)이 verify-rounds 라운드 커밋과 commit-harness 결합 불변식의 관계(M-0008이 이미 지목)를 다룰 때, 이 런처럼 병합 묶음이 관점 분산의 효과를 실증한 사례를 참조 근거로 쓸 수 있다.
