AMS의 숨은 dynamic builder 오류를 전체 expression 불가로 남기지 않고, 현재 가시 기본 필드로 의미를 보존할 수 있는 부분집합을 구현했다. Title/Author contains의 단일 영숫자 토큰, 같은 필드 OR와 중첩 OR, Title식과 Author식의 AND다. 원 폼의 Unicode 정규화를 실제 요청과 대조한다. 같은 필드 AND/NOT·필드 간 OR·equals·안전하게 매핑하지 못한 다단어/문장부호는 원 UI·최소 입력·집합 대조에서도 정상 경로를 찾지 못했다. 복원한 범위로 이 잔여 제한을 덮지 않는다. 원 제어 미제공과 로컬 의미 매핑 미확정의 오류 코드도 구별한다.

세 차례 후보 검토에서 cursor 무시, 빈 세션의 첫 expression XLSX 실패, 용량 12와 실제 11행의 차이를 일괄 오류로 만드는 결함을 확인했다. cursor를 navigation 전에 거부한다. XLSX는 기관 페이지 cache를 먼저 요구하지 않고, 선택 ProductCode 검색을 실행한 뒤 그 페이지에서 내보낸다. 새 공개 expression 페이지를 호출마다 따로 준비해 이전 navigation 대기에 묶이지 않게 했고, 실제 가시 제어의 animation/actionability 대기는 같은 제어의 DOM click으로 해결했다. 실패 후 다른 자료원으로 전환하지 않았다.

문제 식은 Title OR algebra topology analysis다. 이를 geometry가 포함된 다른 양성 식으로 바꿔 검증을 닫지 않았다. 같은 입력에서 페이지 1·2·3·724가 total8,685, capacity12와 실제 11·12·12·9행을 반환했다. 새 원 화면에도 1–11·13–24·25–36·8,677–8,685가 보였다.12번째 순번은 실제 공백이며 다음 페이지로 밀려 있지 않다. start0/limit20은11행 prefix와 partial/source_range_gap, missing[11,12), next.start12다. start12/limit20은20행과 next32다. 부분 결과를 완전하다고 표시하지 않는다.

44개 관측 원 행은 전체 표현 기준으로 고유했지만 ProductId는 37개였다. 같은 ProductId가 서로 다른 제목의 abstract 행을 가리키므로 ID만으로 제거하면 정상 결과를 잃는다. 완전히 같은 원 행의 반복은 별도로 source_duplicate_record로 검출한다. BOOKREV에 상위 Title이 없고 유일한 BookReviews 자식에 원 표시 제목이 있으면 그 위치를 TitleSource로 명시한다. 중간 빈 페이지·초과행·page/total 변화는 계속 거부하고, 후속 오류에서는 이미 확인한 prefix·evidence·재개 위치를 보존한다.

Root의 변경 전 32개 검사는 3실패·12오류였고 통합 뒤 32개 검사가 통과했다. 독립 검토는 native/html export가 부분 결과에도 정확한 전체 창이라고 주장하던 문구를 찾았다. root는 이 설명이 순번 공백뿐 아니라 후속 네트워크 실패에도 쓰임을 확인해, 원인을 단정하지 않는 불완전 요청 범위의 확인된 prefix로 정리했다. 이 작은 설명 변경 뒤에도 32개 검사가 통과했다. 전체 624개 검사 49.487초는 그 최종 설명 변경 직전의 구현 통과 기록이다.

새 원본 stdio SDK는 13개 판정을 통과했다. 첫 브라우저 사용 호출이 expression+xlsx였고 SURV/168의7,023바이트 workbook, 논리 1상품·물리 3행을 받았다. 문제 11행 prefix와 20행 이어받기, Gödel total5, 동등한 중첩 OR total8,685, Title OR와 Author smith AND total38을 확인했다. cursor-only 새 서버는 invalid_options로 끝나 소유 브라우저를 만들지 않았다. 실제 전후·안정 이미지와 원 요청/응답 hash를 직접 대조했다. source/server/native_browser hash는 이 live 실행 전후 동일했고 소유 Chrome 프로세스는 남지 않았다. 기존 51쪽 PDF는 변경 경로가 아니어서 재실행하지 않았다.

처음 검증 도구가 nested OR 기대 total을 geometry 표본에서 가져온 오류와, 확장자 없는 XLSX artifact를 경로로 열어 openpyxl이 거부한 오류를 각각 수리했다. 전자는 같은 입력의 실제 total을 대조하고 새 서버로 재실행했으며 후자는 BytesIO로 원 bytes를 다시 열었다. 공급자 실패로 분류하지 않았다. 정제 결과는 services/scholarly-mcp/data/access-research/user-criteria-ams/root-sdk.json, 원 근거는 private ams-merge/live-original-20260913T120718Z의 report/result/sdk-report/provider-sparse-summary다.
