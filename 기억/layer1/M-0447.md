## 실제 Git 원인과 보존할 좌표

[[M-0446]]의 Lean 선언 형 검증은 29a986e8로 확정했다. 이번에는 후보 KD-0700을 main의 실제 GitProcess 경계로 옮겼다. 정상 ReviewScene의 실제 등록·종료 생산자로 author를 완성하고 같은 상태를 실제 Git 저장소에 초기화했다. 고정 원천의 저장, 스냅샷 읽기, 리뷰 문맥 생산, 원천 기록 생산, 정상 복원 바이트를 확인한 뒤 artifact_ref만 존재하지 않는 경로로 바꿨다. 4c49ogb_에서 제품 GitStateStoreError가 그대로 유출되어 ReviewRestorationError 기대가 실패했다. 제품 내부나 저장 실패를 대역으로 만들지 않았다.

review_engine._materialize_research_sources에서 GitStateStoreError를 기존 OSError와 함께 복원 오류로 연결한다. Git 오류에는 errno와 filename이 없으므로 null로 기록하고 retryable은 false로 둔다. 원인 예외와 메시지, 슬롯/원천 인덱스/참조/스냅샷/기대 SHA256, 빈 검증 범위, continuity_broken=false를 정확히 단언한다. 실패 후 입력·runtime·HEAD는 그대로이고 출력 디렉터리는 비어 있다. 기존 OSError의 일시 오류 재시도와 정확 바이트·해시 검사는 유지한다.

## 관련 검증과 남은 범위

main q_xy_quu는 원천 복원 경계 및 기존 연구 슬롯·리뷰 단계·복원 전사 관련 39개가 통과했다. 기존 unit 두 개의 0.2초 예산 초과를 남긴다. 후보 2srlihhs에서는 이동한 동일 실제 Git 회귀와 원장 구조 2개가 통과했다. 후보의 별도 ReviewOwnerCase 상속을 단일 경계 시험의 setUp으로 옮겨 해당 시험에 필요한 정상 생산 경로를 자체 구성한다. 다른 소유자 시험이나 전체 후보 도우미는 삭제하지 않았다.

양쪽 원장의 reproduction은 FixedSourceRestorationTests의 현재 ID를 가리키며 원 ID는 missed_kind에 남겼다. main 원장 31개와 후보 56개는 다른 모집단이다. 아직 미기록인 후보 25개는 제품 미구현 수나 전체 완료율이 아니다. 보고 원문과 SHA256 및 소스 지문은 단계-전환표 current_work.review_restoration_integration으로 연결한다. 전체 T4/T5, 최종 T2/T3와 예산 및 원문 전건 의무는 남는다.
