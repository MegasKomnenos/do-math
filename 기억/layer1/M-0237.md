직접 판독은 잘못된 원인 설명을 여러 번 교정했다. AMS의 0건은 서버 null 오류 응답 뒤 표시였다. PQDT21필터는 정상 검색 뒤 검증기 실패였다. Springer의 기관 표시와 PDF 제어를 paywall로 읽었던 설명을 철회했다. Scopus의 no-observable-export 설명은 원 CSV/Blob이 이미 있었다는 기록으로 교정했다.

마지막 CORE 조사에서도 기존 경계를 다시 열었다.60초 대기하던 확인 화면의 체크박스를 root가 직접 읽고 누르자 정상 work/output으로 진입했다. 기존 표본 1511018은 저자 요청으로 전문이 제거됐다는 고지가 있어 원문 양성 대조에 부적절했다. 다른 표본 213561553의 원 UI Download PDF는 329,196바이트·8쪽이었고 root가 첫 쪽 제목·세 저자를 대조했다. 다른 관측된 fileserver-az URL287883844는 원 302가 지정한 pdf.core.ac.uk 파일을 공개 HTTP로 받아663,749바이트·26쪽·제목/DOI를 확인했다. files01 표본의 522와 API의404/429는 이 양성과 구별했다.

CORE의 works 전용 입력이 이 공개 파일 URL을 거부하므로 실제 관측한 세 명시 파일 URL 형식을 추가했다. APIAdapter.request의 선택적 url_guard는 모든 단계에서 같은 output ID와 원 CORE 파일 연쇄를 대조하며, PDF 호스트 이후의 redirect·다른 ID·API 경로·외부 호스트는 요청 전에 거부한다. 원 PDF와 내장 metadata를 보존하고 HTML·손상·암호 PDF를 전문으로 표시하지 않는다. pdf.core.ac.uk의 SAS sig 정제도 추가했다. 새 7개 검사의 RED→GREEN, 관련 33개 검사, 독립 검토와 22:21:51Z~22:22:01Z의 새 실제 SDK가 통과했다. 원 26쪽 파일·제목/DOI·끝쪽·ImageContent를 확인했으며 결과/manifest5개에서 sig query는 0이었다. 숫자는 계속 works ID이며 API 실패 후 브라우저나 추정 파일 URL을 자동 사용하지 않는다. core-public-reader/의 보고들을 따른다.
