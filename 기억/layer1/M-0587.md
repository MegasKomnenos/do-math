사용자는 현재 unstaged 변경을 처리해 비우고 삭제할 파일은 실제로 삭제하라고 요청했다. 시작 index는 비어 있었고 서비스는 blocked였으며 다른 프로젝트의 실행은 이 작업의 대상이 아니었다. 미추적 파일 대부분은 async objects·task evidence와 과거 phase 중간 자료로, 약10만파일·8GB 이상이었다. 이를 모두 커밋하거나 원증거를 삭제하는 대신 재개에 필요한 로컬 보관과 추적할 결론을 구분했다.

작은 task objective/task/report/integration과 manager review, 현재 context/plan/seams/queue/settings/start 및 사용자 지시는 추적한다. 과거 continuous phase의 배정·report·게시된manager 결론과 기존에 추적된 선별증거도 유지한다. objects·baseline/result/archive·상세evidence·로그는 로컬 보관이며 새clone만으로 완전복원이 가능하다고 주장하지 않는다. 해당 경계와 별도백업 책임은 .async/dm/README.md와 sources/working-tree-cleanup-2026-10-20.json에 명시했다. 역사 조사·시험지도 원문을 보존하고 옛 진행 문서의 현재 진입점은 최종 인도기록으로 연결했다.

이전에 접근거부로 남은 수용사본27개는 archive 기록과 원objects SHA를 확인했다. 삭제경로가 해당 tasks의 base/workspace에 한정되는지와 남은 추적바이트를 검사하고, 그 안의 read-only 플래그만 해제해 잔여 .git와 사본37,989파일·약183MiB를 실제 삭제했다. 미수용/취소 사본은 남겼다. 삭제목록은 로컬 runtime/working-tree-cleanup-2026-10-20-deletions.json이고 최초 tracked변경과 M-0579 초안은 로컬 임시/working-tree-cleanup-2026-10-20에 백업했다. 이 로컬 경로들은 Git증거가 아니며 이관시 별도백업이 필요하다.

M-0579는 중단초안의 지위를 명시해 별도 보존했고 독해 모델설정·두 서비스소스도 별도 커밋했다. 기존 기본모델29시험, async9시험, continuous30통과/1skip, 미러1388파일 일치와 실제 blocked queue 검사를 확인했다. 새 시험·전체 제품관문·모델실호출·서비스재시작은 수행하지 않았다. tracked로 보이던 do-math 네 파일은 내용diff가 없는 상태정보로, Git clean 변환 해시가 같음을 확인하고 index를 갱신한다.
