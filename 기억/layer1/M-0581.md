r02 조사에서 기존 pair의 요청 표본은 수신 형식 검사를 통과하지만 실제 runner의 AI 배정을 거치지 않는다는 공백이 확인됐다. r02-fix는 research_work 프로필·ticket·seal·host start 게시로 실제 저장·adapter·두 worker·collector를 연결했다. manager 0005는 코드 diff와 최종6passed의 Python875개 판본을 대조하고 정본 시험2·미러2·비용 캐시2를 통합했다. 새 제품 시험을 반복하지 않았고 통합판 미러 검사는1336파일 드리프트 없이 끝났다.

lock을 바꾸면 프로필 참조도 달라진다. 시험은 각 참조를 자기 배정과 먼저 대조하고 서로 다름을 확인한 뒤, CLI 전송효과 비교에서만 그 참조와 실행별 경로를 제외했다. workspace·control·tools binding을 함께 지워 두 실행을 같게 만드는 방식은 사용하지 않았다. 실제 내부 경로가 실행됐다는 사실과 외부 모델·Job이 실제로 실행됐다는 사실도 구별한다. 이 시험은 기존 외부 경계 대역을 사용하며 전체 G4~G8의 성공을 뜻하지 않는다.

진행 중인 r07-fix와 r18-fix의 배정을 유지하면서 기존 R04의 조건 enum·다섯 반복 한도 소비·결과 영수증 JSON 연결을 후속 task로 준비했다. 같은 pairs와 관련 검사를 읽고, 확인된 시험 공백은 조사만 끝낸 뒤 다시 파견하지 않고 같은 task에서 수리하도록 쓰기 범위를 열었다. 실제 runtime 결함은 아직 확인되지 않아 임의 runtime 변경 권한은 주지 않았다. 이 배정은 r02-fix만 선행으로 두며 다른 두 수리와 의미 있는 쓰기가 겹치지 않는다.

검수와 원자료의 추적 진입점은 .async/dm/managers/0005/review.md·source-review.json·preservation.json 및 r02-fix-result.zip이다. archive는 task 원보고·공식 red/green/final·여섯 파일의 base/제출 바이트·manager 판단을 보존한다. 전체 workspace와 세션 로그, 다른 manager의 미추적 기록은 로컬 보관이며 정리로 사라질 수 있다. 공용 문서와 최종 queue 게시를 현재 진행의 정본으로 사용한다. 기존 M-0579 초안 색인 변경과 다른 작업의 dirty 파일은 이 커밋에 넣지 않는다. L01·symlink 실제 반려 미검사·최종 전체 관문은 남는다.
