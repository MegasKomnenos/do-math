사용자는 막힌 기능을 설명받은 뒤 일곱 자료원을 모두 직접 계속 확인하며 해결하라고 지시했다. 과거 접근 실패를 영구적인 상태로 다루지 않고 현재의 기관 진입·문헌·검색·다운로드를 재관측했다. CLI·콘솔·MCP 재시작 조작은 하지 않았다. 단순 재시도에서 멈추지 않고 성공 경로와 실제 코드 결함을 구별했다.

IEEE는 20260911T011529Z 기관 진입에 성공했다. 첫 연속 내보내기 프로브 20260911T011646Z는 BibTeX 뒤 RIS에서 시간 초과였다. 원 페이지에 열린 ngb-modal-window가 남았다. 다운로드 뒤 Cancel로 닫도록 고쳤고, CSV는 스스로 닫히므로 남아 있을 때만 닫는다. 두 번째 프로브 20260911T012006Z는 CSV 요청에서 282바이트 Plain Text를 받았다. 이전 Citations 선택이 남았기 때문이며 CSV에서 Results 탭을 명시적으로 선택하도록 고쳤다.

20260911T013009Z-ieee-native-export-probe.json은 네 형식을 같은 화면에서 내려받고 추출했다. BibTeX 666바이트, RIS 683바이트, Plain Text 643바이트, CSV 1139바이트다. BibTeX·RIS·CSV의 형식·선택 건수 검사를 추가했고 잘못된 파일은 source_export로 남긴다. export 실패가 이미 확보한 검색 레코드를 버리지 않도록 부분 결과를 보존한다.

새 SDK stdio 20260911T015517Z-ieee-exports-mcp.json은 completed=true다. 네 형식의 DOI 대조, complexity 검색에서 첫 1건 및 두 번째부터 2건의 CSV와 원 레코드 DOI 배열 일치를 확인했다. 앞선 P versus NP 제목 검색은 총 1건이어서 start=1의 빈 결과가 올바른 응답이었다. 범위 검증의 양성 표본을 complexity로 교체했다. 20260911T013544Z의 시간 초과와 014608Z의 프록시 진입 실패는 보존한다. 직접 어댑터 014306Z의 다섯 연속 검색도 통과했다. 실패한 프록시 페이지를 보호 폴더에 남기는 임시 SDK 실행기는 data/record_gateway_server.py이며 등록 서버나 CLI를 조작하지 않는다.

AMS는 한국어로 번역된 확인 화면을 기존 영어 제목 검사로 탐지하지 못했다. 원 title과 challenge-error-text 요소를 fixture로 보존해 실패를 재현했다. 공통 is_access_challenge로 화면 구조를 검사하고 AMS 검색 및 Publisher 문헌 조회에 연결했다. 실제 AMS와 SIAM은 각각 같은 브라우저에서 0·5·20·45·90초 관찰해도 결과로 바뀌지 않았다. 확인 화면의 성공 안내 문구만으로 원 검색에 도달했다고 판단하지 않는다.

IOP는 20260911T011850Z의 기관 문헌 페이지가 정상이며, 다른 시도의 첫 기관 진입은 validate.perfdrive.com의 Radware/hCaptcha 화면이었다. Chrome도 같은 확인 화면이었다. 홈페이지 확인에서 막힌 뒤 동일 기관 경로의 심층 문헌으로 이동하는 추가 시험은 시간 초과였다. 접근 실패의 원인을 로그인 만료 등으로 단정하지 않았다. SIAM은 공개 홈페이지가 정상이지만 홈페이지에서 검색한 경우와 Chrome 직접 검색 모두 확인 화면이었다. KUDOS DB 목록에서 SIAM과 Industrial 검색은 0행이었다. 이를 모든 형태의 기관 이용권 부재로 확대하지 않는다.

JSTOR의 원 문자 확인 화면을 직접 판독해 입력했으나 통과하지 못했고 다시 확인 화면이 나타났다. 보존 화면에 Incorrect CAPTCHA가 있다. 입력 실패의 원인을 프록시나 문자 판독 중 하나로 확정하지 않았다. 이 세션의 진단 도구는 서버에 CAPTCHA 인식 기능을 넣은 것이 아니다. 첫 진단은 스크립트가 준비되기 전에 입력란 부재를 판단했으므로 성공 근거가 아니며 후속 진단은 입력란 또는 결과가 준비될 때까지 기다리도록 고쳤다.

ScienceDirect는 Chrome 기관 검색에서도 CPE00001이었다. APS는 정상 문헌과 인용문 제어를 확보했으나 모달 뒤 중복 쿠키 조작이 진단 도구를 막았다. 이를 제거한 원 파일 요청과 실제 Download Citation 클릭은 모두 HTTP403이었다. 반면 20260911T014507Z의 APS 기관 algebra 검색은 37987건 중 20건의 실제 결과를 반환했다. 다음 구현은 이 접근 가능한 검색이다. 원 검색 HTML은 보호 폴더에 있고 query clauses와 필터 제어의 후속 관측을 계속한다.

공통 검사 218개가 통과했다. 전체 구현은 진행 중이고 APS 검색의 신규 생산 코드는 이 커밋에 포함하지 않는다. 보호된 원 자료와 정제된 보고의 경계를 유지하며, 전체 완료 전에는 푸시하지 않는다.
