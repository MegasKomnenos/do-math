# do-math graphify 수동 갱신과 로컬 산출물 경계

## 맥락

사용자가 graphify 갱신과 커밋을 명시적으로 요청했다. 작업 시작 시 Git 작업 트리는 깨끗했고 `main`은 원격보다 한 커밋 앞서 있었다. 기존 graphify 상태는 `stale`이었다. 지난 그래프 이후 추가 5개, 변경 다수, 삭제 6개가 있었고 의미 추출 대기 문서는 15개였다.

## 실행과 확인

정본 명령 `python .claude/skills/graphify/scripts/graph.py update`를 실행했다. 기존 캐시 8개를 재사용하고 새 문서 15개의 `codex exec`·`gpt-6-sol` 의미 추출이 모두 성공했다. Python·Markdown 구조 추출과 내부 경로·인용·끝점 검사를 거쳐 228개 파일, 6,119개 노드, 21,520개 관계의 그래프를 만들었다. `graph.html`과 `tree.html`도 생성됐다. 후속 `status`는 `current`이며 추가·변경·삭제·의미 추출 대기가 모두 비어 있다. graphify 자체 테스트 10개가 통과했다. 테스트 출력의 `intentional failure`는 실패 경로 시험의 예상 메시지다.

그래프의 문서별 사용량은 실제 Codex 이벤트에서 읽혔다. `graph.scope.usage`에는 재사용 캐시를 포함한 문서 23개의 기록이 모두 있으며, 합계는 입력 447,537토큰, 그중 캐시 입력 52,096토큰, 출력 170,578토큰이다. 이 값은 이번 호출만의 사용량으로 해석하지 않는다.

## 보존 경계

그래프 JSON·HTML·의미 캐시·실행 기록은 `.claude/graphify/do-math/`의 Git 제외 로컬 산출물이다. 이번 커밋의 추적 기록은 이 노드와 색인이고, 그래프 데이터 자체는 커밋에 들어가지 않는다. 다른 머신이나 로컬 정리 뒤에는 추적된 graphify 스킬의 명시적 업데이트 절차로 다시 구축해야 한다. 이 기록은 갱신 결과와 확인 범위를 남기지만 그래프 내용을 복원하지는 않는다.
