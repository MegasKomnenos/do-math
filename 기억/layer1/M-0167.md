title: 학술자료 MCP의 Scopus 인용 관계와 XLS·XLSX 추출을 연결함

남은 구현을 계속하면서 Scopus 문헌의 참고문헌·피인용 목록과 WOS Excel 내보내기의 추출 경로를 연결했다. 실제 MCP 검증과 공통 검사 106개가 통과했다. 지원표·검증 기록을 갱신했으며 전체 출판사 검색과 추가 형식의 미완료 항목은 계속 남아 있다.

Scopus의 현재 문헌 주소는 /pages/publications/숫자이고 References·Cited by 탭이 별도 응답을 제공한다. 2-s2.0-77957268169의 참고문헌은 10건씩 다섯 페이지, 합계 47건이었다. 검색 요약은 48건이므로 문헌 목록 건수와 같은 값으로 만들지 않는다. 참고문헌 응답의 totalCount·offset·itemCount와 탭 표시를 대조하고 EID가 없는 레코드도 보존한다. 피인용 응답은 documents 배열 3건으로 탭의 3건과 일치했다. 더 큰 배열의 별도 페이지 조회를 관측 없이 발명하지 않았으며 불일치면 회수한 자료와 부분 상태를 반환한다. 원 계정 요구 RIS·BibTeX 내보내기는 계속 보류한다. 정확한 보고 경로는 VALIDATION.md가 소유한다.

실제 KUDOS 공개 ACM Open TitleList(2026).xlsx에서 저장 단계가 invalid_xml로 실패했다. MIME의 openxml 문자열을 XML로 오인한 것이 원인이었다. XML MIME을 application/xml·text/xml·+xml로 구별하고 XLSX는 ZIP인 채 보존한다. 공개 원본의 세 시트와 Journal 178행을 검사했다. 시트가 여럿이면 선택을 요구하며 열은 A·B·AA 좌표로 지정한다. 반환 행 번호는 원 시트의 1부터, 요청 start는 공통 계약의 0부터다. XLSX 수식은 문자열로 반환하고 날짜와 표시 형식을 구분한다.

WOS의 Excel 제어는 실제로 savedrecs.xls OLE 파일을 내려주었다. 고정 XLSX MIME의 오류를 파일 서명 판정으로 수정하고 xlrd 추출을 연결했다. UT=(WOS:000269418800023)의 2행·72열 중 I·BE·BS에서 제목·DOI 10.1145/1562164.1562186·accession을 실제 MCP로 대조했다. XLS는 저장된 값과 표시 형식을 읽으며 수식 정의·링크·삽입 개체는 원 파일에 남는다. openpyxl 3.1.5, et-xmlfile 2.0.0, xlrd 2.0.2를 전용 환경에 설치하고 요구 파일에 고정했다.

로컬 추출 성공 뒤 실제 stdio 검사가 정지하는 결함도 있었다. 진단 스택은 MCP 호출 중 openpyxl의 첫 import가 NumPy의 Windows native module 초기화에 멈춘 위치를 보여 주었다. stdio 읽기 스레드가 시작되기 전에 openpyxl을 import하자 실제 MCP 추출과 회귀 검사가 종료됐다. 앞선 WOS 검색 성공만으로 추출까지 통과했다고 세지 않았고 미완료 보고는 그대로 남겼다. 정지한 이 작업의 Python 프로세스만 확인 후 중단했다. 환경 전체 프로세스나 다른 세션을 정리하지 않았다.

Scopus의 새 문헌 URL을 EID로 해석하지 못하던 기존 입력 결함도 실제 URL 형태로 재현해 수정했다. 문헌 ID와 형식은 원 응답을 근거로 연결하며 소프트웨어 내부 성공을 실제 MCP 성공과 혼동하지 않는다. 원 연구 산출물과 사용자 설정 변경은 보존한다. 남은 기관 검색·첨부·추가 형식 구현을 계속해야 하므로 푸시하지 않는다.
