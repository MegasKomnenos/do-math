## 맥락

사용자는 추가 Opus 검증 뒤 Astra 두 라운드를 요청했다가 마지막 지시에서 Astra 한 라운드로 줄이고, 기각·무처분 항목도 주 세션이 직접 판단해 고치도록 명시했다. 이에 9라운드에서 공식 검증을 끝냈다. 이는 적용 0으로 수렴한 종료가 아니라 사용자가 지정한 상한에 따른 종료다. 121건은 중복 제안과 문서·시험 결함을 포함한 원제안 수이며, 독립적인 런타임 버그 수가 아니다. 판정·처분의 정본은 `임시/do-math_검증_20261105/장부.md`, 최종 근거 요약은 같은 폴더의 `종료보고.md`다.

## 판단과 교정

공식 9라운드의 6개 항목은 전원 승인으로 적용했다. 이후 8개 기각·무처분 항목은 원래 판정을 덮어쓰지 않고 별도로 판단했다. 이미 후속 수리로 해결된 두 항목은 원래의 불완전하거나 퇴행적인 조각을 버렸다. 나머지는 작업별 재시도 지연, 성공 시 가용성 대기 이력 초기화, peer 세션 기반 제안 ID, 제출 전후 오류 구별, 관련 출판물의 provenance로 특정되는 원본에 대한 종합 검토 접근, 시험 도우미 명칭으로 구체화했다. 특히 종합 검토 접근은 ordinary attempt에 대한 사용자 제한을 전체 역할로 잘못 확대하지 않으면서 관련 없는 미출판 작업은 열지 않는 주 세션의 위임 판단이다.

사용자는 마무리 중 v1/v2 잔재도 제거하고 최신 구현만 남기라고 추가 지시했다. 앞선 보존 판단은 당시 미추적 v2와 기존 범위를 존중한 것이었으며, 새 지시 이후 삭제 대상이 되었다. 정본의 구형 파일 26개와 파생 미러, 미추적 v2 문서 19개를 삭제하고 역사적 출처 설명의 깨진 링크를 고쳤다. 기존 연구 인스턴스·복원 근거를 설치 코드로 오인하여 삭제하지 않았다. 재귀 삭제와 더 좁은 캐시/빈 디렉터리 삭제 명령은 자동 승인 심사에서 구체 사유 없이 policy 차단되었다. 파일별 패치 삭제와 공식 미러 생성은 성공했지만 캐시·빈 폴더·라운드 임시 디렉터리는 남으며 보고서에 명시했다.

## 검증과 한계

개인 수리 전 새 회귀 시험 중 세 개가 의도한 결함으로 실패했고 두 대조군은 통과했다. 수리 후 142개 전체 시험과 실제 Lean의 주석·의존성·독립 컴파일·형식 증거 검사, Claude 원본과 다섯 부속 파일의 바이트 보존, 실제 결과 소비자의 0/1/-9 반환 보존을 확인했다. v1/v2 삭제 뒤 전체 시험을 다시 수행하여 숨은 의존 여부를 검사했다. 다섯 변이 주입도 각각 시험에 검출되었다. WSL은 HCS_E_HYPERV_NOT_INSTALLED로 시작할 수 없어 Linux 실행을 주장하지 않는다. 어려운 수학 연구나 Mathlib를 새로 실행한 것도 아니다.

원문 채팅 추출·개별 파견·프로브 원출력은 Git 제외 로컬 자료다. 저장소에서 복원 가능한 진입점은 추적된 동결·장부·종료보고 세 파일이며, 로컬 경로만을 영구 증거로 간주하지 않는다.

정리 후 최종 전체 시험은 142개가 209.460초에 통과했다. 현행 Markdown 21개에서 로컬 링크 누락이 없고, 두 설치 트리의 구형 소스·시험 파일 및 v2 파일이 남지 않음을 확인했다.
