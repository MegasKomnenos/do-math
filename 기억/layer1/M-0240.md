사용자는 각 세션이 실제 실패 직전·직후 화면을 직접 읽었는지 물으며 그렇게 했다면 스스로 해결할 수 있는 문제가 남아 보인다고 지적했다. 주 세션은 기존 보고를 근거로 한 설명과 직접 이미지 열람 증거 검증을 구별하지 못한 범위를 인정하고 원 세션 기록으로 대조했다. 현재 문제는 사진이 존재하는지뿐 아니라 본 내용을 후속 실험과 종료 판단에 충분히 연결했는지다.

24개 Codex CLI의 간략 events.jsonl에는 view_image 항목이 따로 없었다. 이를 미열람으로 판정하지 않고 C:/Users/wogud/.codex/sessions의 정확한 24 thread rollout을 찾았다. response_item/custom_tool_call의 tools.view_image와 동일 call_id 출력의 input_image를 결합하니 24세션 모두 실제 이미지 입력이 있었다. 검사 시점 225호출·658이미지 블록이며 반복 열람과 일부 과거 이미지를 포함한다. 식별 경로의 누락 파일은 0이었다. 658개의 새 고유 화면이나 모든 실패의 정확한 전후 쌍을 입증한 수치가 아니다.

정제 원장은 services/scholarly-mcp/data/dispatch/20260913T021511Z/visual-call-audit.json, 검사 코드는 같은 폴더 audit_visual_calls.py다. 원 도구 입력·이미지 바이트·추론 원문은 비공개 세션 파일에 두며 보고는 호출 ID·시각·이미지 반환 수·파일 실재만 사용한다. before/after 파일명은 후보 선별에만 사용했다. 주 세션은 Oxford 프록시 모달·직접 검색·기관 입력 결과와 SIAM 연맹 화면도 다시 직접 열었다.

이미지를 실제로 봤다는 것과 방법을 소진했다는 것은 별개여서 3개 종료 판단을 다시 열었다. Oxford는 정식 기관명 한 건의 빈 화면만으로 직접 기관 로그인 경로를 닫기 전에 양성 후보 응답·입력 이벤트·다른 공식 표시명·제어 렌더 조건을 대조해야 한다. SIAM은 노출된 discovery 목록에 없다는 관측에서 관리자 수정만 필요하다는 결론으로 넘어가기 전에 공식 IdP metadata·문서화된 정상 기관 인증 경로·실제 proxy 유지를 확인해야 한다. AMS는 잔존 동적 경로 오류를 근거로 조기 거부하는 변경을 기능 복원으로 수용할 수 없으며 현재 공식 다른 검색 문법·초기화와 OR 직렬화 문제를 추가 대조한다. 이들은 해법이 반드시 있다는 판정이 아니라 현재 소진 근거의 충분성 재검토다.

공통 계약의 새 자격·타기관·토큰 위조·외부 지원 문의·공유 상태 변경 제한은 유지했다. 공식 metadata로 확인한 자기 기관 식별자를 문서화된 정상 입력에 쓰는 것까지 '목록에 없다'며 배제하지 않도록 구별했다. 현재 화면에 제시된 후속 제어를 실행했는지 기록하고 사진 재열람만 추가한 반환으로 종료하지 않도록 세 파견문을 썼다. services/scholarly-mcp/dispatch/remaining-20260913/reviews/에 정본을 보존하고 실행 폴더의 작업별 review-01.md로 전달했다.

운영기에 review-requests.json 소비를 추가했다. 검토 대기 작업만 고유 요청 ID로 재개하고 이전 반환을 보존하며 같은 thread와 사본을 사용한다. 신규 지시는 실제 resume 입력에 함께 넣는다. 운영기 5개 검사는 통과했다. 기존 실행 중인 CORE work·DBLP KG·Crossmark는 유지했고 AMS·SIAM 기관·Oxford의 원 thread가 다시 running임을 확인했다. 당시 최대 8 중 6실행·18검토 대기였다. 새 운영기 실제 PID37548·wrapper22832였으나 이후 재개는 state.json을 정본으로 읽는다.

주 세션은 이미지 열람·실패 국소화·대안 소진·기능 복원을 구분해 후속 반환을 검증해야 한다. 보고의 완료 표시나 자동 검사의 파일 실재 통과는 원본 통합 승인이 아니다. 이번 커밋은 조사 감사와 재검토 파견이며 생산 기능 수리 결과 통합은 아직 남는다.
