사용자는 실패가 확인됐지만 정확한 전후 화면을 읽지 않은 사례의 목록을 받은 뒤 세 기준을 제시했다. 같은 실패를 재현하면서 직전과 직후 화면을 실제로 읽고 그 단서로 해결을 시도해야 한다. 서버 문제보다 로컬 입력·문법·선택자 실수가 개연성 있으면 접근 방식을 다시 검토해야 한다. 시간초과·경로·대기·도구 등 수정 가능한 기술 문제는 고쳐 재실행해야 한다. 불가 판단은 이 작업들이 끝난 뒤의 근거 범위로 한정된다.

직전 목록은 services/scholarly-mcp/data/dispatch/20260913T021511Z/failure-visual-gaps-20260913T0655Z.md다. 24개 과제의 보고·실험·판독표와 실제 CLI 이미지 반환을 대조해 API·파일 요청 27유형과 불완전한 전후 근거 15사례를 구별했다. 이는 미해결 기능 42개라는 뜻이 아니다. 정상 논문 UI와 과거 오류 한 장을 본 Semantic Scholar가 최신 API429의 전후를 판독한 것은 아니었다. CORE files01의 522와 문헌 UI403, EuDML CQL504와 홈페이지 504, IEEE 참고문헌 timeout과 Media 성공도 각각 다른 사건이었다. 코드·시험의 로컬 실패와 보조 자원 오류는 별도 부록에 보존했다.

현행 계약은 dispatch/remaining-20260913/USER-CRITERIA.md에, 개별 범위는 criteria-tasks.json에 기록했다. N01부터 N27, B01부터 B15를 전부 담당 과제에 연결한 것을 코드로 검산했다. 23개 CLI 과제를 기존 같은 thread와 사본에서 재개하고, 전후 근거가 갖춰진 Springer 과제는 주 세션이 직접 이미지·원응답·parser·diff를 검토한다. API의 공식 실행 화면이나 실제 진단 도구에서 원 요청·응답을 관측하되 진단 도구를 원 사이트 UI로 제시하지 않는다. 과거 실패가 재현되지 않으면 같은 조건의 현재 성공과 미재현을 기록하고 불가능 주장을 철회한다.

앞선 24개는 모두 awaiting_review로 반환해 전용 운영기가 정상 종료한 상태였다. 그 PID의 부재를 확인한 뒤 추가 과제만 수행할 운영기를 실행했다. 현재 새 운영기에서 8개가 실행 중이고 15개가 재개 대기, Springer1개는 주 세션 검토 대기임을 확인했다. 기존 Codex·등록 MCP·사용자 브라우저는 재시작하지 않았다. 쓰기 범위는 전용 사본·private·output으로 유지하며 추가 API 키·계정·연락 이메일은 제외한다. SIAM 세션이 이미 거부당한 KNU IdP 자격은 다시 제출하지 않도록 명시했다.

재개 요청 소비기는 과제의 마지막 review_request_id만 저장한다. 같은 과제의 과거 요청과 새 요청을 활성 목록에 동시에 남기면 최종 반환 뒤 과거 요청부터 다시 소비될 수 있다. 운영기 코드를 확장하는 대신 기존 목록을 review-requests-before-user-criteria-01.json에 보존하고 활성 review-requests.json에는 과제별 최신 요청 하나만 두었다. 정확한 추가 지시는 각 과제 review-user-criteria-01.md에 저장했다. 별도 criteria-review.json은 사건별 재현, 실제 이미지, 로컬 가설, 기술 수리와 재검증, 처분, 남은 작업을 연결하는 검토 입력이며 파일 존재만으로 의미 검증을 통과한 것으로 세지 않는다.

원본 서비스에 파견 사본의 코드 변경은 아직 통합되지 않았다. 이번 커밋은 현행 실행·종료 계약과 작업 연결의 결정화이며,23개 과제의 실험 완료나 원본 통합 검증 통과를 뜻하지 않는다. 주 세션이 회수 결과의 실물과 원 코드를 검토하고 가능한 기능을 통합하는 작업이 남아 있다.
