사용자는 최근 GPT-6 Astra 모델의 작문 세션을 검토한 뒤 증상의 나열과 원인 설명을 구별하도록 요구했고, 반복 실패를 줄이는 작업 흐름의 구현을 승인했다. 기록에서는 원칙을 설명한 뒤에도 초안에서 관계와 목적이 빠지고, 사용자의 반응에 따라 검토 판단이 바뀌는 사례가 확인됐다. 모델의 학습 원인이나 특정 지시의 인과 효과는 세션 기록만으로 확정하지 않았다. 학술 복창을 제거하면 글이 좋아진다는 주장을 구현의 전제로 삼지도 않았다.

## 실행에 연결한 위치

기존 AGENTS에는 write-for-reader를 읽으라는 진입점이 이미 있었다. 작문 스킬의 자기 점검 뒤에 실제 독해와 합의 대조를 연결했다. 정본은 .claude/skills/write-for-reader이고 .agents 사본은 생성기로 반영했다. 새 writing_flow.py는 합의·독자 정보·원고를 세션에 등록하고, 원고와 독자 정보만 별도 codex exec에 제공한다. 원래 응답과 입력·실행 자료를 보존하며 원고·합의·독자 정보가 바뀌면 기존 판정을 현재 판본에 적용하지 않는다.

독해자는 이해한 내용과 본문 근거, 읽기 어려운 부분과 불확실성을 반환한다. 메인이 그 내용을 확정된 합의에 대조하고 지적마다 유지하거나 수정할 이유를 기록한다. 인용 존재, 파일 해시, 실행 성공은 의미의 타당성이나 문체의 우수성을 인증하지 않는다. [[L-0001]] [[L-0005]]

현재 Codex 0.154.0은 활성 .codex/hooks.json의 Stop을 사용한다. .agents/hooks.json 생성물의 존재만으로 실제 발동을 판단할 수 없었다. 새 훅 한 항목의 정의와 해시를 대조하고, 공식 app-server에서 이 버전의 /hooks TUI와 같은 hooks/list·config/batchWrite 경로로 신뢰를 등록했다. 같은 해시에 trusted가 반환되는 것을 확인했다. 신뢰 우회 플래그나 DB 직접 편집은 사용하지 않았다. 후속 환경에서는 [[L-0012]]의 규범 전달 원리에 따라 실제 발견·신뢰·발화를 확인해야 한다.

## 검증과 수리

동작 검사 29건을 통과했다. 독립 코드 검토는 새 독해 실패 뒤 과거 독해를 재사용하는 경로와 매번 달라지는 실행 ID가 반복 재개 검사를 초기화하는 경로를 재현했다. 제한 시간에 무한대나 숫자가 아닌 값(NaN)을 입력한 경우와 잘못된 CLI 이벤트를 받은 경우에도 실행 중 상태가 남는 문제가 있었다. 선행 회귀 실패를 확인한 뒤 수리했다. 일반 셸의 루트 세션 ID와 하위 thread ID도 구별하도록 고쳤다.

실제 작성자는 원자료와 사용자 첨삭 예문을 읽고 수행계획서의 필요성 절을 새로 작성했다. 이전 실패 문단은 보지 않았다. sol high의 독해 3회에서 첫 지적 1건은 원고에 반영했고, 최종 지적 2건은 원문의 기능 설명과 필요성 절의 범위를 근거로 기각했다. 마지막 독해·판정은 최종 코드로 다시 실행했으며 입력과 원고의 해시가 유지됐다. 메인 에이전트도 원고 전문과 합의를 대조했다. HWP 편집·렌더링이나 연구 시스템의 실제 효과를 검증한 것은 아니다.

과거 실패 문단의 별도 독해는 difficulties가 비었지만 지원 목적을 주로 오해 방지로 재구성했다. 사용자 첨삭문의 독해는 기능과 활용 목적을 설명하면서 표현 지적 4건을 냈다. 지적 수만으로 원고를 채택하거나 순위를 정하지 않았다. 두 문서는 범위가 다르므로 통제된 모델 성능 비교가 아니다. 독해자의 무발견과 합의에 맞는 전달을 구별해야 한다는 후속 검증 근거다.

실제 Codex 세션에서 미검토 원고 등록 후 종료를 시도하자 Stop의 후속 지시로 작업이 재개됐다. 검증용 작업을 취소한 뒤에는 정상 종료했다. Windows 명령은 Codex의 실제 COMSPEC /C와 raw 인자 전달 방식으로 확인했다. 처음의 Python argv 배열 모사는 다른 인용 규칙 때문에 실패했으므로 훅 설정 결함으로 귀속하지 않았다.

## 보존 범위와 한계

검증 진입점은 docs/writing-flow/validation-2026-09-15/README.md다. 원자료, 원고 판본, 독해 원문, 대조, CLI·훅 실행과 신뢰 등록 자료를 선별 보존하고 manifest에 바이트 수와 해시를 기록했다. 일상 실행 상태는 .codex/writing-flow에 보존하며 Git에서는 제외한다. 스킬 형식 검사와 정본·사본 드리프트 검사를 통과했다.

이 흐름은 등록된 작업의 누락과 낡은 판정을 찾는 절차다. 등록 자체의 누락, 모든 독자의 이해, 모든 작문 유형의 성능, 악의적인 상태 파일 조작을 완전히 막는 장치로 확대하지 않는다. Stop은 이미 전달된 메시지를 회수하지 않고 후속 지시를 만든다. 외부 실행 실패와 사용자 대기는 미완료로 남기며 같은 문제가 반복되면 자동 재개를 멈춘다. 사용자 중단은 종료를 방해하지 않는다.

후속 기억 종합(dream)에서는 독해 원문과 각 지적을 수정하거나 기각한 이유를 함께 읽어, 독해 결과를 실제 판단의 근거로 사용했는지 검토할 수 있다. 관련된 현행 규범은 기억/layer3의 [[L-0001]], [[L-0005]], [[L-0012]], [[L-0016]]에 있다. 이번 실전 한 건을 전반적인 작문 품질 향상이나 재발률 감소의 증거로 일반화하지 않는 것이 이 기록의 적용 경계다.
