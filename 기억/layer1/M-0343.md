## 맥락

사용자는 직전 두 커밋의 수정 이유를 유형과 원인으로 이해하고, 같은 문제가 다른 생산자·저장·전달·소비 경로에 남는지 사실에 근거해 조사하도록 요청했다. 이후 발견한 문제의 수리를 승인하면서 영향 영역 전체를 파악하고, 구체적 구현의 실익을 판단하며, 기존 전제가 틀렸으면 방향을 바꾸도록 했다. 선행 작업은 [[M-0341]]과 [[M-0342]]다.

감사는 정본 242개 파일과 두 커밋의 변경 파일 합집합 81개를 고정하고 정상·복구, 직접·간접 참조, 현재 참조·재등장, 검증·게시 경계를 비교했다. graphify는 조회에만 사용했고 판단은 현재 원문과 실행 재현으로 확인했다. 확정한 일곱 항목과 기각 근거는 `docs/do-math/similar-defects-2026-09-25/`에, 수리 판단과 검증 결과는 `docs/do-math/boundary-repairs-2026-09-25/`에 이 커밋으로 보존한다.

## 수리 과정에서 달라진 판단

자료가 Git에 남아 있어도 다음 판단자가 읽는 참조가 끊기면 보존 목적을 달성하지 못했다. 종료·복구 시 체크포인트의 본문 참조만 이어 붙이는 안은 봉인 제출물에 포함되지 않은 본문이나 input 근거를 놓쳤다. 마지막 유효 기록과 근거 버전을 유지하고 새로운 최종 원문을 별도로 포착하는 공통 절차로 바꿨다.

관계 의존 누락은 단순 변조 실험에서 완료 현재성 오류처럼 보였지만, 정상 개정에는 별도의 영향 전파가 있었다. 그 주장은 철회하고 실제로 재현한 개정 전 독자 차단 누락으로 영향을 한정했다. 수리에서도 의존 순회를 통째로 합치지 않았다. 독자 대기·완료 근거·영향 분석·인용 수집의 정책은 다르며 직계 관계 해석만 공유한다. 독립 재검토는 파일 locator를 레코드 의존으로 바꿔 불필요한 검토를 요구하는 회귀를 찾아냈고 기존 필터를 복원했다.

제어 입력은 AttributeError를 넓게 잡는 대신 접수와 수신에 같은 구조 검사를 두었다. checked import의 승인 값까지 조사하면서 같은 오류를 추가로 회수했다. 이때 새 검사가 기존 유효 입력을 좁히는 문제도 확인했다. 부분 설정을 기본 설정에 합쳐 미리 판단하는 안은 버렸고, 대상 없는 action과 알림 객체 등은 실제 저장·소비 계약의 형식을 재사용했다. 입력의 구조와 현재 권한·상태 판단을 분리하는 것이 수리 경계였다.

## 검증과 정리

수리 전 반례를 실패 검사로 전환한 뒤 수정했다. 고유 테스트 ID별 최신 결과는 단위 358개와 관련 통합 229개, 합계 587개 통과다. 여러 고정 판본 실행 묶음의 집계이며 전체 스위트 단일 실행이나 실제 모델 연구의 검증을 뜻하지 않는다. 통합 215개 중 하나의 예전 접수 후 거절 기대는 새 접수 전 input_error 계약에 맞춰 갱신하고 영향 검사를 재실행했다. 모델 응답은 대역이고 Git·CLI·로컬 실행 수명은 실제 임시 환경을 사용했다.

검증 도중 정본을 수정한 실행은 설치 판본 변경 감시가 의도대로 정지시켰다. 그 결과와 독립 점검 반영을 위해 중단한 실행은 최종 통과 수에 포함하지 않았다. 이후 고정 판본 실행과 마지막 영향 검사의 원 보고서·소스 해시·최신 결과 대응을 보존했다. 정본과 `.agents` 생성본을 함께 갱신했으며 graphify는 재생성하지 않았다.

사용자의 정리 요청에 따라 이번 작업의 `임시/do-math-audit-20260925/`와 `임시/do-math-repair-20260925/` 및 do-math의 Python 생성 캐시를 제거했다. 필요한 감사·재현·검증 증거는 위 docs 경로로 승격했으므로 삭제한 임시 경로를 후속 판단의 진입점으로 쓰지 않는다. 다른 작업의 임시 자료와 기존 연구 기록은 정리 대상에 넣지 않았다.

커밋 준비에서는 증거 폴더의 개행 변환을 막아 보고서 해시를 유지했다. 기존 스킬의 LF 규칙으로 테스트 파일 두 개의 CRLF만 정규화됨을 별도로 대조했고, 측정 당시 원본 해시는 바꾸지 않았다. 커밋될 소스 바이트의 대응은 수리 폴더의 `commit-byte-check.json`에 보존한다.

dream에서 묶을 후보는 공통화의 범위다. 같은 참조 표기를 읽는 부분은 공유할 수 있지만, 그 참조를 가지고 내리는 판단까지 같다고 가정하면 새 오류가 생긴다. 재현 가능한 경계 위반과 다른 소유자가 이미 막는 영향을 구분해야 수리 범위를 넓히면서도 과장하지 않을 수 있었다.
