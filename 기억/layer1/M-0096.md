## 맥락

최근 네 수정안을 반영한 `docs/do-math/통합-설계.md`를 원천으로 루트 `CONTEXT.md`와 `docs/wayfinder/pvsnp-재설계/컨텍스트.md`를 갱신하고, 열린 GitHub 이슈 18에 최종 변경 전건을 정리했다. 루트 용어집에서는 발견 후보의 ID 부여와 공용 편입 시점, 저장 형식 중립의 핵심 기록 공통 기능, 항해 색인과 작업 없는 관리 공용 편입을 현행 설계에 맞췄다. wayfinder 컨텍스트에는 OKF 지식층, 생성 회차와 목차 checkout, P vs NP 프로젝트 분리, 스킬 문서 구조와 역할별 모델 배정을 구현 세부의 제2 정본이 되지 않는 수준으로 반영했다.

후속 교정에서 `GLOSSARY.md`와 루트 `CONTEXT.md` 사이에는 별도 양방향 경로·동반 수정·지속 동기화 의존성을 두지 않기로 확정했다. `GLOSSARY.md`가 `CONTEXT.md`의 보편 정의를 저작 원천으로 삼아 포함하는 계약은 유지한다. `GLOSSARY.md`와 다른 `do-math` 구현 정본·스키마 사이, 통합 설계와 스킬 문서 사이의 양방향 경로와 동반 수정 계약도 유지한다. 통합 설계, 스킬 구조 수정안과 기존 이슈 코멘트를 이 경계로 맞췄다.

## 터득한 것

- 관계 제거 지시의 대상은 두 문서 사이의 간선이었다. 이를 “외부 정본 전반과 GLOSSARY 사이의 관계”로 일반화하면 스키마·통합 설계 등 다른 구현 정본이 소유한 사실의 드리프트 방어까지 함께 사라진다.
- 현행 계약은 `CONTEXT.md`를 GLOSSARY 저작의 보편 개념 원천으로만 사용한다. 루트 문서에는 GLOSSARY 역참조가 없고, 완료 조건도 두 문서 사이의 링크를 검사하지 않는다.
- `docs/do-math/스킬-실물-구조-수정안.md`의 30절 삽입 전문과 통합 설계의 현행 30절을 원문 그대로 대조해 일치시켰다. 금지한 CONTEXT 의존 문구는 0건이고, 다른 `do-math` 구현 정본을 대상으로 한 양방향 링크 문구는 양쪽에 존재한다.
- 사용자 교정 신호: 처음에는 특정 관계 제거를 상위 범주의 모든 양방향 관계 제거로 넓혔다. 사용자가 선호한 교정은 끝점이 `GLOSSARY.md`와 `CONTEXT.md`인 관계만 제거하고 형제 관계는 보존하는 것이었다. 이후 관계 변경에서는 삭제할 끝점 쌍과 보존할 인접 간선을 먼저 열거하고, 적용 뒤 두 집합을 각각 검사해야 한다.

## 작업 너머 시사점

문서 의존성은 문장 집합보다 간선 집합으로 판정하는 편이 안전하다. “A와 B의 관계를 제거”하는 변경은 A의 모든 외향 관계나 B와 같은 종류의 모든 관계를 제거한다는 뜻이 아니다. 생성 단계에서 대상 간선을 닫고, 검증 단계에서 대상 간선 부재와 보존 간선 존재를 함께 확인하면 과잉 적출을 막을 수 있다.
