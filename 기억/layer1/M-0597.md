## 맥락

사용자는 [[M-0594]]로 완성한 새 do-math가 형식을 간결하게 만드는 과정에서, 세션이 참고할 지시·방향·기준까지 잃지 않았는지 물었다. 메인은 `.async/do-math-rebuild-20261021/`의 기록, `docs/do-math/통합-설계.md` 전문, 옛 do-math의 역할 계약(연구 수행·연구 계획·후보 준비·동일성 검토·목표 감사)과 참조 문서(지식 저작과 재사용·학술자료 활용·모델과 실행예산)를 직접 읽고 새 common·plan·research·review.md와 대조했다. 옛 구현은 `4e793d17`에서 읽었다. 기계 쪽 문서(CLI 실행 계약, 이음새 정본, 공통 실행, GLOSSARY 등)는 읽지 않았다.

판정은 다섯 가지 손실이었다.

1. Lean 결과를 증명으로 인정하는 기준(허용 공리, `sorry` 배제)
2. 계획의 연구 전략과, 기대한 결과를 실제 결과와 비교하는 고리
3. 기록이 쌓였을 때 연구 전체를 조망하는 수단
4. 진전이 없을 때의 처리
5. 형식화 시점의 판단

사용자가 반영 범위를 재량에 맡겼다. 이 커밋은 실행기·검사기·프로토콜 구조를 바꾸지 않고 네 작업맥락 문서에 판단 기준을 더한다. 바뀐 내용은 다음과 같다.

- common.md: 공리 기준과 `#print axioms` 절차, 기존 결과 적용 전 네 가지 대조, 검토 "상충"의 정의, 자료 속 명령문의 취급, 용어 일관성, 문헌 조사 기준
- plan.md: 연구 현황 문서 `research-status.md`, 집중과 탐색·관점 전환·정보 가치, 기대 기록과 비교, 형식화 계획, 지시의 논리 함정 넷과 병렬 범위 경계, 진전 없음의 처리
- research.md: 같은 세션 형식화, 공리 확인, 종료 판단과 `output/` 중간 갱신
- review.md: 적극적 반박, 결함 뒤 계속 검토, `lean` 판정의 공리 기준, 목표 해석

protocol.md는 `lean` 판정 설명과 예시 두 곳만 맞췄다.

## 터득한 것

- **손실이 생긴 경로**: context.md의 단절 규칙 "이전 코드와 문서에서 구조나 장치를 가져오지 않는다"가 `session-contexts` 지시에서 "설계를 가져오지 않는다"로 옮겨졌다. 그 결과 옛 역할 계약 전체가 읽을 자료에서 빠졌다. 사용자가 과설계의 예로 든 것은 신뢰 환경 고정과 파일 해시 대조, 곧 장치였다. 그런데 이 규칙은 판단 기준까지 함께 걸렀다.
- **손실이 드러나지 않은 이유**: manager 수용과 최종 검토는 사용자 원문과 다섯 목적만 대조했다. 완주 목표 `n + 0 = n`은 `rfl` 한 줄이라 탐색·정체·형식화 판단을 쓰지 않았다.
- **사용자 교정 신호**: ⓐ 시스템의 기본값은 장치를 걷어내면서 판단 기준도 함께 버린 세션 문서였다. ⓑ 사용자는 손실 검토와 반영을 요구했고, 반영 문서를 수신 세션의 관점에서 쓰라고 지정했다. ⓒ 드러난 공백은 둘이다. 단절·간소화 지시를 하위 지시로 옮길 때 "무엇을 버리는가"의 범위가 넓어진다. 그리고 수용 검토가 이전 판본 대비 기능 손실을 대조 대상으로 두지 않는다. ⓓ 교정 위치도 둘이다. 재구축 계약에는 버릴 장치와 보존할 판단 기준을 나눠 적고, 판단 기준의 원천을 읽을 자료로 지정한다. 최종 검토에는 이전 판본의 세션 지침과의 기능 대조를 넣는다.
- **Lean 4.32.0 실측**(`.skill-workspace/lean-axiom-probe/`, Git 제외 로컬):
  - `sorry` 정리는 경고와 함께 종료 코드 0으로 끝났다.
  - `#print axioms`는 보조정리를 거친 `sorryAx`도 보여 줬다.
  - `native_decide`는 `Lean.ofReduceBool`이나 `Lean.trustCompiler`가 아니라 정리별 보조 공리 `<이름>._native.native_decide.ax_1_1`에 의존했다. 그래서 문서는 금지 이름 목록이 아니라 허용 셋(`propext`, `Classical.choice`, `Quot.sound`) 밖은 모두 거부하는 방식으로 썼다.
  - `add_zero_example`(`rfl`)은 "does not depend on any axioms"를 출력했다.
- **연구 현황 문서의 배치**: 계획 기록끼리 `supersedes`로 잇지 않았다. `supersedes`가 "전체 대체"로 정의돼 있어, 앞 계획의 요청이 취소되는 것처럼 읽힐 수 있어서다. 대신 `runner/state.json`의 `sessions`에서 `category=plan`, `status=integrated`이고 `started_at`이 최대인 세션의 `record`로 직전 문서를 찾게 했다. 필드 이름은 runner.py에서 확인했다.
- **wait 뒤 파견 순서**: 사용자 입력으로 대기가 풀리면 `Runner.tick`이 계획을 먼저 띄우고 남은 슬롯에 게시된 요청을 파견한다. 그래서 답에 따라 달라질 요청은 `wait`와 함께 게시하지 말라고 plan.md에 적었다.
- **수신자 독해**: 실제 세션이 받는 묶음(common + protocol + 범주 문서) 셋을 별도 독해에 2~4회씩 돌려 지적을 고쳤다. 마지막 판본에서 남은 지적 셋은 모두 이번에 고치지 않은 기존 문장이라 유지했다. protocol의 예시 문장, 검토 예시의 빈 `references`, RUNTIME.md 참조다. RUNTIME.md는 실제 계획 기동 프롬프트에 경로가 들어간다.
  - 독해 자료: `.skill-workspace/writing/do-math-guidance/`, `.skill-workspace/writing/do-math-loss/`
  - 상태: `.codex/writing-flow/`
  - 모두 Git 제외 로컬 보관이라 정리하면 사라질 수 있다.
- **검증**: do-math 시험 19개 통과(29.2초). 미러 생성기는 do-math 다섯 파일만 갱신했고 `--check` 드리프트 없음.

## 작업 너머 시사점

- 효과의 확인은 첫 실사용 목표(예: 주차 함수 단봉성)에서 한다. 볼 것은 계획 `reason`과 연구 현황에 기대와 그 비교가 적히는지, 검토가 공리 목록을 기록하는지다. 연구 품질 향상 자체는 같은 목표의 비교 없이 확인되지 않는다.
- dream에서 묶을 후보: [[M-0593]]의 "장치 누적이 정지를 만든다"는 진단과 이번의 "장치를 걷을 때 판단 기준도 함께 빠진다"는 진단은 같은 간소화의 양면이다. L-0020의 재작성과 L-0012의 지시 분해 항목(위임된 재량이 기능 목적의 생략을 허가하지 않음)에 함께 반영할 후보다.
