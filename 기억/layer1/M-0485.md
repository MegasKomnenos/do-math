[[M-0484]] 뒤에 입력 요구 영역의 국소 검사를 계속 증식시키지 않고 3-C로 이동했다. 원문 `조사/결함-범주.md`의 (c)는 B-16·C-19·B-36·C-15·C-12·B-49·B-32·D-02·B-33·C-13·A-47 열한 쌍을 명시한다. 이번 B70의 확정 범위는 B-16 준비성/프로필 선택, C-12 종결 판정, D-02 철회 허용 범위다. 원래 열한 항목과 이후 의미상 사본 전체를 이 세 항목으로 줄이지 않는다.

현재 B-16은 model_policy.work_profile_selection 정본을 계획 준비성·준비성 갱신·평가 보충·중앙 적용이 사용한다. 기존 task contract 단위 모듈에서 실제 프로필 생산자와 검토 봉인 생산자로 모든 입력을 구성했다. 두 작업 역할, 난이도 세 값, 중요도 세 값, 역할 하한 세 값, 허용 프로필의 여덟 부분집합, 명시 프로필 없음/세 tier의 1,728조합을 전수 확인한다. tier 모델들은 이 시험의 명시적 fixture-model 설정이다. 모델 이름의 모든 동등/상이 분할이나 전체 과제 상태까지 전수했다고 주장하지 않는다.

기대값은 난이도·중요도·역할 하한의 순서와 실제 허용 집합으로 독립 계산한다. 자동 선택은 필요한 정확한 tier가 있어야 하고, 명시 프로필은 하한 이상이며 허용 집합에 포함돼야 한다. 실제 work_profile_selection의 허가/거부와 task_ready의 ready/not_ready, 선택된 정확한 프로필 참조를 확인한다. 처음 연구 수행 프로필의 role만 보충 조사로 바꾸자 kr33sxny에서 observation mode differs from role responsibility로 실패했다. 역할의 관찰 책임을 시험에 맞춰 완화하지 않고 build_profiles를 사용하여 현행 두 역할의 실제 프로필을 생산했다. 수정 후 52wepw39에서 전수 사례가 8.7초에 통과했다. 이는 시험 입력 구성의 오류이며 제품 결함의 재현 성공으로 세지 않는다.

C-12는 실제 Sim 소유자의 _instance_closed와 planning.instance_ended를 같은 유한 공간에서 확인한다. 저장 스키마의 생명주기 세 값과 실행 상태 여덟 값, 영구 종결 표지 두 값의 48조합이다. 단순 조회이며 저장소는 바뀌지 않는다는 단언도 둔다. 실행 상태 closed/completed 또는 영구 종결일 때만 끝난 것으로 계산하며 생명주기 상태 이름만으로 종결을 창작하지 않는다.

D-02는 현재 과제 상태 다섯 값, 사용자 필수·학술 요구·이전받은 의무의 세 보호 축, 제안 평가 없음/incomplete/completed/closed의 160조합을 실제 계약 생산자의 산출 위에서 검사한다. 종결 과제 거부, 종결 평가 거부, 보호 의무 거부의 정확한 우선순위와 메시지, 성공하는 미수행 비보호 범위를 확인하며 입력이 변경되지 않는지도 확인한다. 이미 수행한 결과의 모든 근거·시점 축은 이 작은 공간의 범위가 아니며 기존 별도 검사를 유지한다. 두 규칙의 부정·긍정 조합은 brtody5n에서 통과했다.

새 구조 검사 rule_consistency는 이 세 공유 규칙의 정의가 각 소유 모듈에 하나인지, 선언된 현재 직접 호출자가 정본을 사용하는지 전건 순회한다. B-16의 소비는 core_engine._apply, lifecycle_engine._refresh_readiness, planning.task_ready, planning_engine._finish_assessment_preparation이다. C-12의 소비는 제어 접수·실제 소유자 wrapper·모델 정책 위반·설치 복구 보류·status 과제 행이다. D-02는 제출 검사와 중앙 적용 검증이 같은 validate_withdrawal_scope를 부른다. 제출의 내부 disposition closure와 바깥 _payload_issues는 같은 호출을 포함하는 두 함수 범위로 기록한다. 실제 소스의 직접 호출 모집단이 바뀌면 선언 검수가 필요해진다. 다른 함수 이름으로 만든 의미상 복제 전건의 부재를 이 AST 검사로 증명했다고 주장하지 않는다.

dtq1eehb에서 구조 일반 검사가 통과했다. 마지막 같은 판본의 전체 구조와 변경한 세 단위 모듈 및 계획 소유 연결 모듈 실행 oke10p5s는 structure 45개·unit 63개·sim 11개, 합계 119개가 34.9초에 완결 통과했고 실행 중 변경은 없었다. 개별 초과는 세 개이며 유한 프로필 공간 10.329초, 실제 소유자 종결 조회 준비 3.875초 등이 포함된다. 단위 예산을 맞추려고 조합이나 단언을 줄이지 않는다. 전체 T2나 fresh T3의 시간 달성으로 해석하지 않는다.

원보고는 추적된 `검증/2026-10-04-판정-규칙-세쌍/report.json`에 보존하고 B70에 현재 파일 지문·명령·범위·제약을 연결한다. 중간 Temp 보고는 로컬 보관이다. 제품 동작이나 사용자 변경을 이번 범위에 섞지 않는다. 다음은 남은 원래 여덟 쌍과 이후 같은 판단의 사본을 실제 현재 생산자·소비자 및 정본으로 확인하는 것이다. 원래 19의무·61보존 지식·P2 12항목·여섯 부류·2단계 11의무와 최종 전역 T2/flows·T3·전 대상 변이·실행 예산·T4/T5 최소 실호출·말뭉치·최종 지침·미러·main 목표를 유지한다.
