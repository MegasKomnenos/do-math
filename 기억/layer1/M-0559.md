phase 008의 운영·복구 문서 결속은 의미 검사를 통과했지만 기존 함수 표기로 관련 검사4건이 실패해 제품 커밋을 보류했다.009는 해당 함수명 뒤 (...)만 추가했고 정본110·미러89의 원선택 전건이 통과했다. 이번 커밋은008~009의 검수된 문서·시험28파일과 관리 인계를 함께 마감한다. 이전 partial 보고와 실패 원자료는 보존한다.

## 판단의 근거

함수와 상태 필드의 구별은 기존 검사기에 이미 있었다. bare dotted 이름의 오분류를 해결하려고 unknown/defer나 schema를 넓힐 필요가 없었다. manager는 기존 callable 검사·없는 함수/호출 불가능한 값의 반려, 현재2640소스, 각865개 Python 판본, 원실패4건의 정확한 passed ID를 대조했다.008 지정 단언은 불변이며 runtime124·smoke입력3·corpus102경로도 그대로다. 문서 회귀의 종료로 전체 일반/T3/변이나 다른 실제 연쇄를 완료로 올리지 않는다.

후속은 제품을 쓰는 host-smoke와 고정 자료만 읽는 reading-limits를 병렬화했다. 둘이 파일을 다르게 쓴다는 것 외에, 읽기 조사에서 변경 중 시험·지침·캐시·미러와 host 결과를 소비하지 않도록 경계를 정했다. 공식 시험은 host만 jobs1로 실행하고 읽기 조사는 새 모델 세션을 기동하지 않는다. 공통 cache/설치 판본을 사용하는 여러 실경계 구현을 무리하게 나누는 대신, 현재 코드와 외부 도구 계약만으로 진행 가능한 남김을 함께 배정했다.

L01은 역할 stdin과 운전 도구 출력을 구별해야 한다. 실제 도구의 token 제한을 byte 요구로 임의 환산하거나 현재 개발 세션의 host를 제품 운영자의 host와 같다고 가정하지 않는다. 조사 완료는 권위 있는 한도와 정확한 미정 질문을 확보한 상태일 수 있으며13-C 충족 여부는 별도 판단이다. Job/pythonw도 예약 cmdlet 대역의 결과로 실제 등록·발화·해제를 대신하지 않는다.
