사용자는 형식·절차 검토가 최초 사례에만 좁혀지거나 경중을 잘못 배분하지 않았는지 재검토하도록 했고, 이어 전체 스킬을 먼저 깊게 이해한 뒤 필요한 영역을 직접 수리하도록 요청했다. 기존 감사는 여러 수신 반례를 찾았지만 실제 사용 지식의 현재성 누락을 놓쳤고, 응답 전체를 되돌리는 동작의 비용을 원문 재사용·원자성의 이점과 충분히 비교하지 않았다. 이 작업에서는 당시 비캐시 파일 102개·20,830줄을 먼저 읽고 기준 문서와 재검토를 뒤에 대조했다. 읽기·실패 재현·수리의 근거는 `임시/do-math-format-procedure-audit-20260916/수리결과.md`와 같은 폴더의 검증 집계로 연결된다.

생산자에게 스키마 준수 의무를 적는 것과 실제로 준수할 수 있는 입력·도구·수리 경로를 제공하는 것은 별개다. 실행별 `submission_contract`가 검사 명령, 공개된 고정 입력, 주·확장 스키마와 한도를 제공하도록 했다. 작업자는 제출 초안을 파일로 만들고 실제 명령을 실행해 오류를 고친 뒤 다시 검사한다. 검사 함수는 수신자와 공유하지만, 중앙 상태 적용기 전체를 작업자 안에 복제하지 않았다. 정상 본문을 재사용할 수 있는 원자적 수리를 유지하고, `.scratch/`를 명시적인 임시 영역으로 제공했다. 읽기 전용 검사에 수기 통과 영수증이나 추가 승인 절차를 붙이지 않았다.

현재성의 비교 범위는 너무 넓어도, 좁아도 문제가 된다. 사용하지 않은 원자료를 모두 결박하면 무관한 변경이 검토를 멈춘다. 반대로 사전 선언만 검사하면 작업 중 새로 사용했다고 밝힌 지식의 변경을 놓친다. 반환 참조를 원 입력 snapshot의 지식·과제·원자료 판본에 결박하고 수신 시점의 새 판본으로 대체하지 않게 했다. 원 자료의 ID·이름·제공 경로를 원 입력 대응표에서 해석하는 것도 같은 경계다. 과거 artifact 참조는 당시 바이트를 읽기 위한 좌표이므로 최신 지식 의존과 구별한다. 지식의 현재 의존을 수집할 때 이력 제외 목록이 중복 할당으로 덮인 결함도 이 구별을 시험하는 과정에서 드러났다.

실패를 보류하는 수리에는 보류 이후의 생성 경로까지 포함해야 한다. 전체 정지만 없애면 착수 조건 갱신과 동료 검토의 완료가 같은 계약·검토 자리의 요청을 새 ID로 다시 만들 수 있었다. 이 재생성을 막고, 일반 resume과 실제 수리 뒤 명시적으로 요청한 운영 진단을 구별했다. 고정 질문 조사의 재시도를 끝낼 때는 원 검토 자리로 실행 미완료를 반환한다. 원 허가가 철회됐는데 다른 허가가 남아 있으면 늦은 응답을 받아들이던 경로도 재현해, 이미 내려진 정지 요청을 수신 시점에 존중하도록 했다.

누적 입력에서는 현행 계약의 전문과 과거 기록의 전문을 모두 큰 인라인 객체로 유지할 필요가 없었다. task·action·이전 실행·복구 자료를 원문 참조로 외부화하면서 현재 계약과 배정의 식별 정보를 남겼다. 600,000자 보고에서 계약 개정·검토·연구 재개로 이어지는 시험은 다음 단계가 정확한 원문을 다시 읽는지 확인한다. 검토 이력이 커졌다는 사실을 수학 제안에 분해가 필요하다는 판단으로 바꾸지 않는다.

검증의 종류를 섞지 않았다. 대역 응답은 실제 스케줄러·Git·SQLite의 상태 전이와 인계 경계를 확인하고, 실제 Codex 한 호출은 제공된 검사 명령의 실행·실패·수리·재검사와 최종 JSON·파일 해시의 일치를 확인했다. 이 실호출은 유지보수 경로 하나이며 전체 역할이나 장기 수학 연구의 품질 검증이 아니다. 문서 독해는 전 문서의 설명과 합의를 대조하는 용도로 사용했고, 코드 검증의 독립성을 대신한다고 보고하지 않았다. 실행 중 다른 세션에서 운영 세션 기본값이 모델별 3개로 바뀐 [[M-0297]]의 변경은 존중하되 이 수리의 성과로 귀속하지 않는다. 기존 연구 인스턴스의 재개·목표·예산·예약 작업도 이 작업의 대상이 아니었다.

저장소 작업 기억을 종합하는 dream 절차에서 함께 검토할 후보는 생산자 지원, 현재성의 실제 의존, 대기의 재생성 경계를 하나의 인계 문제로 읽는 관점이다. 규칙의 문면을 늘리는 것만으로는 충분하지 않으며, 다음 주체가 필요한 원문과 정확한 오류를 받고 자기 권한으로 다시 판단할 수 있는 경로가 있어야 한다. 다만 이 관점이 모든 실패의 부분 적용이나 모든 수신 검사의 복제를 정당화하지는 않는다. 원문 재사용, 원자성, 실제 실패 영향과 구현 비용을 함께 비교하는 것이 이번 사용자 교정의 핵심이었다.
