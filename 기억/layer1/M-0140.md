사용자는 기존 세 수집기의 실제 실행 절차와 효율 평가를 제공하고, 작업자를 중단한 뒤 개선하여 신규 작업자로 이어 가도록 지시했다. 기존 실행은 일부 단계가 끝났다는 표시로 미해결 후보를 제외하거나, 별도 수집·후처리·의미 검토 사이의 인계를 작업자 판단에 맡겼다. 사용자가 요구한 교정은 남은 작업에 따른 재개, 저장 증거의 우선 재판정, 건별 장애 격리, 탐색 제한과 완료의 연결, 실제 비용 측정이다.

기존 g02·g05·g08 작업자를 interrupt했다. 직후 Win32_Process에서 KUDOS 수집용 Python·Node 프로세스는 없었고 관련 없는 dag_measure_mcp.py만 남아 있었다. 결과 870·382·304개와 자기 코드의 SHA256을 restart-snapshot.json에 보존했다. 이는 실행 중 코드와 나중에 수정된 디스크 코드가 같다고 가정하지 않기 위한 교체 기준선이다. 새 작업자는 같은 디렉토리의 결과를 이어받으며 원자료를 다시 처음부터 수집하지 않는다.

루트가 실제 결과를 다시 집계했을 때 g02에는 미방문 검색 페이지 기록 90건, g08에는 unvisited_link 30건과 collection_error 13건이 있었다. g08의 VER-100ededc2c64ac34d061ddb4는 초록·원문이 모두 not_found인데 required_sources_complete=false, unvisited_link=true였다. 마지막 AMS 기관 링크의 본문은 비어 있었고 Summon OpenURL 중계 화면은 출판사 제목 불일치로 끝났다. 이 사례는 새 g08 작업자에게 실제 연결 경로와 부재 판정의 회귀 입력으로 전달했다.

공통 work_queue.py와 restart-contract.md를 만들고 check_recovery.py의 완료 판정에 연결했다. 입력 전건의 결과 상태, 남은 작업, 문헌 식별과 각 구성요소의 현재 검토가 완료 판단에 들어간다. 이전 단계 표시는 완료 근거로 사용하지 않는다. 구성요소 검토의 해시는 그 구성요소와 식별 전제에만 기댄다. 다른 자료의 진전·진행 시각 때문에 검토를 무효화하지 않는다. 새 work_state는 기존 증거의 폐기가 아니라 필요한 검토·방문의 인계다. 저장된 파일의 무결성과 실제 내용·범위의 타당성은 별도 검사다.

기존 완료 검사가 미방문 링크·미방문 검색 페이지·수집 오류·현행 증거 검토 부재를 통과시키는 네 사례를 실패 시험으로 관찰하고 고쳤다. 해당 네 검사, 기존 검사 20개, 재개 경계 검사 12개가 통과했다. 이전 진행 중 미커밋이었던 바이너리 초록 구획 지원과 그 시험·실물 fixture 경로도 함께 보존한다. 새 부분 검사로 기존 1,556개 결과의 파일·해시를 검사한 결과는 세 묶음 모두 passed=true, complete=false였다. 이 통과는 음성 판정의 의미를 승인한 것이 아니다.

신규 kudos_g02_replacement·kudos_g05_replacement·kudos_g08_replacement를 사용자가 지정한 gpt-6-astra / medium으로 파견했다. 각 작업자는 공유 재개 계약과 실제 검사기를 먼저 받고, 자기 수집기의 피드백을 실물 TDD로 수리한 뒤 resume.py로 저장 증거·브라우저 잔여 단계·내용 검토·검사를 연결한다. 코드 수리와 실제 의미 검토를 수행하는 반복의 소유자는 작업자이며, 일반 수집기가 스스로 코드 수정을 발명한다고 가정하지 않는다. 세 작업자는 초기 확인에서 주요 피드백의 현행 결함을 각각 재확인했다. 전수 수집 완료와 네 대기 묶음의 파견은 아직 남아 있다.

g05의 root-pdf-review.json에 있던 10건의 루트 검토 예약도 신규 g05 작업자에게 넘겼다. 루트는 그 10건의 검토를 끝내지 않았으므로 인계문에서 완료된 검토로 취급하지 않게 했다. 공용 인증은 새 Chrome context에서 저장 상태를 재사용하여 visible 로그아웃 링크로 확인했다. 비밀값과 원자료는 기존 비추적 경로에 유지한다.

재발을 막을 위치는 공통 완료 검사와 각 수집기의 실제 재개 분기다. 문서에 끝까지 수행하라고 적는 것만으로 단계 사이의 인계가 생기지는 않는다. 이번 신규 작업자의 수리도 소규모 실물 실행과 실제 큐 소비 여부를 회수 검증해야 하며, 공통 검사기의 통과만으로 자동 실행과 의미 판독의 연결이 검증됐다고 주장해서는 안 된다.
