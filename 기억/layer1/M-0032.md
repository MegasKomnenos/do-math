# pvsnp-탐사-1 원장·L01~L11 수식 표기 수리분 커밋 — 검증런 2.7.20 0단계 기준선 확립

## 맥락

행 `2.7.20`(파견문 `.sdd/dag/pvsnp-탐사-1/행/2.d/7.d/20.md`)은 행
`2.7.19`가 `source-ledger.md`·`records/L01.md`~`L11.md`에 적용한 수학
표현 LaTeX 변환과 URL 보존 처분을 verify-rounds로 독립 검증하는 런이다.
추가 지시에 따라 이 세션이 verify-rounds 절차 전체를 자기 컨텍스트
안에서 직접 운전한다 — 절차 전체를 단일 서브에이전트에 위임하지 않는다.

0단계 착수 전 `작업 디렉토리:` 슬롯(`C:\Users\wogud\AppData\Local\dag-wt\pvsnp-탐사-1+2.7`)에서
`git rev-parse --show-toplevel`을 실행해 일치를 확인했다. 이어 그
워크트리의 `git status`를 열자 산출물 대상 12건 중 8건
(`source-ledger.md`, `records/L01.md`·`L03.md`·`L04.md`·`L05.md`·
`L06.md`·`L09.md`·`L10.md`)이 미커밋 상태(`M`)로 인계돼 있었다.
`L02.md`·`L07.md`·`L08.md`·`L11.md`는 diff 0으로 이미 HEAD와 같았다.
verify-rounds §0단계 8항(산출물 절 경로마다 git 변경 없음 확인)을
충족하지 못하므로 라운드 1 시작 전에 이 8건을 대행 커밋했다
(워크트리 커밋 `94b29bc`).

같은 워크트리에 `.agents/`·`.claude/` 스킬 스크립트 미러 6건과
`records/L12.md`~`L22.md`·`readings/*.md` 다수가 함께 dirty했으나,
이번 검증런의 동결문 「산출물」 절이 될 12건(원장 1 + L01~L11)에
속하지 않아 대행 커밋 범위에서 제외했다 — 다른 행·병행 세션의 미완
작업으로 추정되고, 이 행이 손댈 근거도 필요도 없다. 메인 저장소
(`C:\math`)도 별도 행 수십 건의 미커밋 산출이 누적돼 있었으나, 이
행의 산출물은 워크트리 파일뿐이고 메인 저장소 쪽 확인 대상은 이
행 자신이 아직 쓰지 않은 `20.d/종료보고.md`뿐이므로 손대지 않았다.

## 터득한 것

- do-dag 완료-커밋 미결합 패턴이 이 국면에서 재차 재현됐다(M-0006 이후
  누계 20회 이상). 이번엔 다만 이 행의 산출물 범위(12건 중 8건)만
  대행 커밋하고, 같은 워크트리의 범위 밖 dirty 파일(스킬 스크립트
  미러·L12~L22·readings)은 손대지 않는 경계를 실측으로 확정했다 —
  0단계 8항의 검사 단위는 동결문 「산출물」 절의 경로 각각이지 워크트리
  전체의 청결이 아니다.
- L02·L07·L08·L11이 diff 0으로 이미 HEAD와 일치했다 — 행 `2.7.19`의
  수리 대상 82건 중 이 네 파일에 해당하는 후보가 없었거나 앞선 커밋에서
  이미 반영됐을 가능성이 있다. 검증런 라운드에서 이 네 파일도 산출물
  절에 포함해 심사 대상으로 열어야 한다(이미 클린이라는 사실이 검증
  생략 근거는 아니다).
