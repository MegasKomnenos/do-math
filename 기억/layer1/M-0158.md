title: 학술자료 MCP의 공개 원문·형식 보존과 연속 호출을 검증함

별도 API 자격을 요구하지 않는 경로만 사용한다는 사용자 교정을 유지하며 학술자료 MCP를 확장했다. 전용 구현과 최신 지원 범위는 services/scholarly-mcp/README.md·SUPPORT.md·VALIDATION.md가 소유한다. 전체 선정 범위의 구현은 부분 완료다. 미연결 출판사와 추가 검색·내보내기 기능, 구체 서비스가 정해지지 않은 범주를 완료로 세지 않는다. 현재 등록 자료원은 APS 접근 범위를 나눈 47개 식별자이며 공통·자료원 검사 63개가 통과했다.

실제 MCP에서 Theory of Computing의 주제 색인·native BibTeX, gs010의 초록·166쪽 PDF·PostScript·LaTeX 소스 ZIP·HTML 참고문헌과 저자 안내를 확보했다. 본문 검색과 다음 페이지 조회도 확인했다. 저널의 기존 검색 페이지는 옛 HTTP Google loader를 사용해 HTTPS에서 입력이 초기화되지 않았다. 저널이 공개한 같은 검색 엔진 ID를 현재 공개 위젯으로 렌더링하여 수리했으며 별도 Google API 키를 사용하지 않았다. 본문 검색은 웹페이지 단위이므로 같은 문헌의 여러 페이지와 주제 색인이 별도 결과가 된다. Google 추정 건수와 실제 문헌 건수를 구별한다.

PQDT에서는 원문 조회 후의 재검색과 다음 페이지 조회를 실제 MCP로 이어서 시험했다. 검색 시작 화면과 이전 선택 목록을 정리하고 실제 Next Page 제어를 사용하여, 기존 문헌 RIS·PDF 뒤 다른 질의의 7,575건 결과 중 다음 페이지 한 문헌을 회수했다. 앞선 성공 기록을 연속 호출 성공으로 간주하지 않고 이 흐름을 별도로 검증했다.

EuDML은 공개 CQL/OpenSearch 검색·RSS 추출·NLM 문헌 ID 대조를 실제 MCP에서 통과했다. RSS의 pubDate와 dc:date는 다를 수 있다. 실측 표본은 pubDate가 2016년이고 실제 발행연도인 dc:date가 2001년이어서 두 값을 분리했다. 현재 문헌의 식별자는 front의 article/book metadata header에서만 대조하며 참고문헌의 같은 ID로 대체하지 않는다. NLM의 외부 PDF 링크는 다른 자료원을 자동 방문하는 근거로 사용하지 않는다.

EuDML 조회 실패 중에는 XML 요청에 JSON Accept 헤더를 보내 발생한 HTTP 406이 있었다. 같은 대상에 JSON Accept를 보낼 때 406, XML Accept를 보낼 때 200임을 대조하고 요청 형식별 헤더를 지정했다. API 오류에 따른 브라우저 전환을 넣은 것이 아니다. 이후 arXiv의 MCP 검색·추출과 Numdam의 MCP 메타데이터·PDF 회수·추출도 재검증했다.

Zenodo는 공개 레코드와 특정 파일 URL을 해석하고, 파일 크기·checksum을 제공자 메타데이터와 대조하도록 구현했다. 실제 MCP에서 검색·파일 회수·PDF 추출을 통과했다. concept 식별자와 개별 record 식별자를 구별해 응답에 남긴다. 검증은 자료 전송과 파일 대조이며 테스트 대상으로 쓰인 문헌 주장의 타당성을 판정하지 않는다. HTTP 504 같은 일시 오류의 실패 기록과 나중의 성공 기록은 구별해 보존했다.

APS Harvest는 공개 접근 문헌의 JSON·PDF와 openaccess 피드를 키 없이 제공했다. 다른 DOI는 JSON·PDF 모두 HTTP 401을 반환했다. aps는 공개 API 범위, aps-institutional은 KUDOS 기관 경로로 별도 등록했고 호출 안에서 자동 전환하지 않는다. 공개 API의 피드·서지·초록·PDF는 실제 MCP로 검증했다. 기관 접근의 직접 시험에서는 메타데이터를 회수했지만 PDF는 제한됐다. Cambridge·Oxford·AIP·Project Euclid도 문헌 조회 어댑터로 연결했으며 고급검색·추가 native export는 남아 있다.

형식 보존에서 세 가지 회귀를 수리했다. XML 안의 URL을 일반 문자열처럼 정제하면 ampersand 이스케이프가 깨져 원 RSS를 다시 파싱할 수 없었다. lxml 6.1.3을 전용 환경에 추가하고 네임스페이스·QName 값의 선언을 유지하며 정제·직렬화한다. 엔터티 확장과 외부 파일 읽기는 거부한다. 인증 정제가 필요 없는 URL은 원 표현을 유지해 공개 서명 payload의 URL이 바뀌지 않게 했다. API XML의 정규화와 저장소 원 파일·archive 내부 파일의 원 바이트 보존을 구별한다.

Windows MIME 추정은 archive 안의 .bib를 text/plain으로 분류했다. 확장자에 따라 BibTeX·RIS 파서로 연결했다. 이어서 ToC 소스의 BibTeX 엔트리 밖 #OK 표기 때문에 기존 엄격 파서가 멈추는 것을 확인했다. 기존 수집 코드를 바꾸지 않고 MCP의 스캐너 운용에서 엔트리 밖 주석을 넘기며 원 파일은 보존하도록 확장했다. 해당 gs010.bib의 84개 레코드를 추출했다. BibTeX·RIS·WOS·CSV에는 selection=raw로 원 줄을 읽는 경로도 제공한다.

Unpaywall은 공개 문서에 따라 제목 검색·DOI 조회를 구현했고, 연락 이메일을 도구 인자가 아닌 보호된 설정에서 읽게 했다. 이메일 없이 HTTP 422가 나오는 사실과 메일이 없을 때 네트워크 호출 전에 설정 오류를 반환하는 경로를 확인했다. 실제 연락 이메일은 아직 입력되지 않았고 정상 API 흐름 검증은 남아 있다. Scopus native export용 웹 계정 파일 경로도 아직 답변이 없다. 별도 API 키를 다시 요구하지 않는다.

이 커밋은 진행 중 구현의 검증·보존 단위다. 구체적인 남은 자료원과 기능은 지원표와 각 describe_source에 남긴다. 실서비스 자료와 실패 진단은 전용 data 및 보호된 .credentials에 있으며 Git에 넣지 않는다. 새 커밋과 이어지는 작업에서도 기존 연구 수집 코드·산출물과 사용자의 다른 변경을 보존해야 한다.
