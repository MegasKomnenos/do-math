[[M-0505]]의 통합 후속 교정을 확정한 뒤 B89에서 준비한 외부 원자료를 편입했다. 녹화 당시 이름 b88-corpus-draft의 기존 세 소스 SHA가 여전히 일치하는지 확인한 뒤 적용했다. 제품 코드는 변경하지 않았다. 말뭉치는 기존7항목에서12항목으로 늘고 Codex/Claude 스트림·Lean 출력·scholarly 설정·예약 조회·CLI 명령 표면 여섯 종류가 됐다. 항목 수를 9-B 전체 완료율로 해석하지 않는다.

실제 프로젝트 .codex/config.toml에서 scholarly 테이블의 원문 바이트 구간만 보존했다. 원파일 해시와 원문 행 범위도 남기고 다른 설정은 포함하지 않았다. startup_timeout_sec=30과 tool_timeout_sec=1800을 포함하지만 실제 scholarly_config._from_config는 command/args만 반환한다. 비밀값을 대입한 합성 설정이나 다른 환경의 경로를 현재 설정으로 표시하지 않았다.

실제 Lean4.32.0은 작은따옴표가 있는 corpus_apostrophe' 선언을 컴파일했고, 서명과 빈 공리 목록을 출력했다. 원래 source, 제품 check_file이 만든 실제 컴파일 입력, 실제 출력 세 파일을 보존한다. 재생은 현재 check_file의 입력 생성 바이트까지 비교하고 실제 parse_evidence로 서명·공리를 판정한다. 대형 Lean 증거와 Mathlib 실행 전건을 이 작은 경계 사례로 대신하지 않는다.

예약 자료는 operator_schedule.ps1의 status를 실제로 호출한 결과다. UUID로 만든 존재하지 않는 세 작업 이름에 operator/engine/wake=null이 반환됐다. PowerShell5.1.22621.6133, Windows10.0.22631도 관측해 기록했다. 재생은 PowerShellScheduler의 공개 runner 이음매에서 외부 프로세스 결과만 녹화로 공급하고 실제 JSON 해석·거부 코드를 실행한다. 기존 연구 인스턴스나 예약 작업을 등록·시작·삭제하지 않았다. 등록돼 있으나 trigger가 없는 작업은 아직 별도 남김이다.

현재 Codex0.160.0과 Claude2.1.289의 adapter.help_commands에 적힌 실제 version/help를 모두 녹화했다. surface_report가 현재 필수 플래그, supported/unknown 구분, version/help 해시를 같은 값으로 판정한다. 이 자료의 범위는 cli_command_surface_only다. 도움말만으로 원격 종료·읽기 격리·연구 실행 능력을 증명하지 않는다.

구조 검사는 새 컴파일 입력과 명령별 녹화 파일을 선언·해시 검사하고, Lean/설정/예약/CLI 표면 종류가 말뭉치에서 사라지면 실패한다. 현재 provider 등록부에 있는 양 공급자의 판본별 스트림 요구도 유지한다. 최초 관련22개가 통과했고 구조를 포함한 관련68개가27.1초에 통과했다. 정확한 PowerShell 판본과 필수 종류 검사를 반영한 최종 구조·재생3개는0.2초에 통과했다. 모든 보고에 실행 중 소스 변경은 없다. 원자료 출처·판정·판본과 보고는 검증/2026-10-04-외부-말뭉치/에 추적하고 실제 stdout/TOML/Lean 입력은 tests/corpus에 추적한다. 최종 report.json SHA256은 b959d3b46f40ecace4433c83d163c99e3ec2092ae52ff922ec7e9e6d05f2eddc다.

복수 결과 구간·종료 정리·실제 quota 거부·실제 역할 스키마 수용·모든 해석 함수와 판본의 전건 연결은 남아 있다. 이 목록을 숨기지 않고 작업판에 유지했다. 다음은 기존에 조사한 11-B의 사건×판단 대상 있음/없음에서 실제 호출0/1을 연결하는 작업이다. 원문 전체를 다시 감사하거나 현재 데이터를 더 모으기만 하는 반복으로 돌아가지 않는다. 교정 후 새 전체 일반 성공과 최종 T3·변이·T4/T5도 계속 필요한 관문이다.

커밋 전 원바이트 비교에서 상위 스킬의 JSON LF 규칙이 예약 조회의 CRLF를 바꾸는 것을 확인했다. tests/corpus/.gitattributes에서 녹화 파일의 text 변환을 끄고 manifest와 속성 파일은 LF로 유지한다. 구조 검사는 이 Git 제어 파일을 자료 파일에서 구별한다. 추가 구조·재생3개가 통과했으며 attributes-and-replay.json의 SHA256은 7e80924aa98c80107147c2c3d2ffe9936b245c435a9683a222599f955a23af5a다. 원바이트를 고쳐 통과시키지 않고 index blob과 실제 checkout filter 결과를 원자료와 비교한다.

checkout filter 검사에서 원보고 네 파일도 core.autocrlf 때문에 바뀌는 것이 확인돼 검증 디렉터리의 JSON/JSONL에도 원바이트 보존 속성을 적용했다. 실제 Codex help의 공백뿐인 줄은 외부 원문이므로 corpus 자료에 한해 whitespace 정규화 검사를 제외하고 manifest와 Git 제어 파일의 검사는 유지한다. 기록을 고쳐 해시를 맞추지 않는다.
