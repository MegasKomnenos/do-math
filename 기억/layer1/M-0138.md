사용자는 초록 미확보 7개 디렉토리의 6,101건에 대해 디렉토리별 gpt-6-astra / medium 작업자를 파견하고, 실제 Playwright UI 탐색 뒤 TDD 수집 스크립트로 초록·원문·필요 정보를 끝까지 회수하도록 요청했다. 루트에는 `docs/형식과-절차.md`에 근거한 사전 계약을 지정하여 알리도록 했다. 이 커밋은 파견·회수의 진행 중 계약을 보존하며 전체 수집 완료를 뜻하지 않는다.

`research/pvsnp/literature-baseline/kudos-recovery/contract.md`에 입력과 쓰기 범위, 문헌·판본 동일성, 초록과 원문별 상태, 실제 근거·해시, 재개·수리·종료·반환을 정했다. 같은 디렉토리의 `check_recovery.py`와 13개 테스트를 TDD로 제공했다. 부분 검사 통과와 전체 완료를 구별하고, 미해결 동일성이 남은 부분 검사에서 complete가 참이 되던 결함도 재현 후 수정했다. 결과는 후보별 JSON이고 원자료는 기존 Git 제외 경로인 intake 아래에 보존한다.

KUDOS 실제 로그인과 새 browser context에서의 인증 재사용을 루트가 확인했다. 비밀값과 storage_state는 `.credentials/`에만 두었다. 루트를 포함한 동시 슬롯 4개에 맞춰 g02 5,138건, g05 382건, g08 304건을 먼저 파견했고 g07·g09·g10·g12는 대기 배정으로 보존했다. 각 작업자는 자기 브라우저 context와 파일 영역을 사용하고 공용 인증 갱신·계약·검사기·Git은 루트가 맡는다.

실제 UI 판독에서 필수 조사의 종료 범위를 구체화했다. KUDOS 학술DB, 비구독 포함 Summon 검색, 입력·상세에서 실제 제시된 정상 원문 연결 경로까지 확인한다. 그 범위에서 제공 경로가 없는 경우와 명시적 접근 제한은 근거를 붙여 닫되, UI 오류나 미방문 링크는 미해결로 남겨 수리한다. 인터넷 전체의 모든 가능한 검색을 소진해야만 종료하는 의무는 두지 않았다.

공통 실측은 `shared-findings.md`에 보존했다. Summon의 ho=t에서 0건인 책이 정상 UI의 ho=f 확장에서 검색됐다. DOI가 같으나 제목·저자·연도가 다른 문헌으로 결합된 검색 상세를 루트도 새 context에서 재현했다. Connes의 1994년 책에 붙은 다른 논문 PDF도 루트가 첫 면의 제목·저자·DOI·발행 정보를 직접 대조하여 철회를 확인했다. PDF 원본이 맞더라도 텍스트 레이어의 초록에 OCR 오류가 있는 Lee 사례는 실제 이미지로 확인해 교정과 원시 OCR 보존으로 연결했다.

동적 화면을 같은 파일명으로 덮어쓰면 기존 evidence 해시가 깨지는 사례는 원자료를 내용 해시별로 보존하도록 수리했다. 수집 속도는 같은 서지를 여러 자료원에서 반복 조회하는 방식을 줄이고, 실제 UI 검색이 발생시킨 응답의 상세 필드를 화면과 대조한 뒤 활용하는 방법으로 개선 중이다. 이 방법은 미관찰 API 추측 호출과 구별된다. 활성 작업자와 재개 좌표의 정본은 `dispatch.json`, 각 작업자의 `progress.json`, 결과 파일 및 실제 실행 상태다.
