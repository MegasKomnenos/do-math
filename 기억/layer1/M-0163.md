title: 학술자료 MCP의 Numdam 검색·인용문·DOI 회수와 EndNote 추출을 연결함
convention_version: 24
---

사용자는 지원표·인계문·최신 기억으로 맥락을 복구하고 남은 구현을 끝까지 계속하도록 지시했다. SUPPORT.md와 OS 임시 디렉터리의 학술자료-MCP-후속구현-인계-20260910.md, M-0159~0161 및 정본 구현 계약을 확인했다. 이번 커밋은 Numdam 확장을 보존하며 전체 구현의 완료를 뜻하지 않는다. 별도 Scopus 웹 계정과 Unpaywall 연락 이메일을 요구하는 기능의 보류 결정은 유지한다.

Numdam의 키워드 검색은 기존 서비스에서 not_implemented, DOI 조회는 invalid_target이었다. 실제 공개 웹 폼에서 complexity의 4,804건과 문헌별 PDF·DJVU 링크를 다시 확인했다. 검색은 Playwright의 실제 폼, 메타데이터는 공개 OAI, 인용문은 공개 export_citation endpoint로 역할을 고정했다. API 실패를 브라우저 전환 조건으로 사용하지 않는다. DOI 페이지의 citation_doi와 native export 링크의 내부 ID를 대조한 뒤 OAI에 같은 ID를 요청한다.

웹 검색은 제목·저자 등 필드와 추가 조건을 원 UI로 전달한다. 추가 날짜 조건은 발행연도이고 OAI의 from·until은 메타데이터 갱신일이다. 원 검색의 페이지 링크는 compact query 문법이며 두 번째 페이지 링크의 페이지 번호 부분을 바꿔 요청한다. 표시된 현재 페이지·전체 건수·실제 행 수를 대조한다. 검색의 원 응답은 활성 요소를 제거해 보존하며 미인식 레이아웃을 0건으로 바꾸지 않는다.

실제 MCP에서 19·20번째 위치의 두 문헌과 RIS 두 건, DOI 10.1051/ita/2011126의 JATS·초록·10쪽 PDF·DJVU·BibTeX·RIS·EndNote를 회수했다. 제목 구문과 2012년 조건의 1건, 무작위 문자열의 0건, 이후 AIF_1956__6__1_0의 43쪽 PDF 조회까지 통과했다. 첫 전체 시도는 마지막 기존 표본의 OAI 연결 오류로 끝났으나 독립 재호출과 두 번째 전체 흐름은 성공했다. 이 한 번의 연결 오류에서 원인을 추정해 공통 재시도 정책을 추가하지 않았다. 실패 기록은 completed=false로 보존한다. 정확한 보고 경로는 services/scholarly-mcp/VALIDATION.md에 있다.

확보한 실제 EndNote 파일을 공통 extract에 넣어 format_not_supported를 재현했다. 원 태그 대소문자·반복 필드·연속 줄과 원 레코드 텍스트를 보존하도록 추출기를 확장했다. Numdam의 두 저자·제목·DOI·내부 ID를 실제 파일과 대조했다. 공개 검색 응답과 EndNote 파일을 회귀 fixture로 남겼으며 공통 검사 81개가 통과했다. DJVU는 확보한 대체 전문 바이너리이고 현재 기계적 문서 판독 대상은 PDF다.

ScienceDirect는 공개 citation endpoint가 HTTP 403 HTML, KUDOS 기관 경로의 Natural Proofs PII 문헌이 publisher_access_restricted를 반환했다. AMS의 10.1090/jams/1019 기관 조회도 같은 접근 제한이었다. 이 관측을 자료 부재나 전체 구현 완료로 표현하지 않는다. 나머지 출판사 검색·추가 원문 형식·첨부와 아직 특정 서비스가 없는 범주는 계속 구현해야 한다.

이번 진단은 원 HTML·JS·숨은 입력값을 출력하지 않고 상태·제어 이름·공개 문헌 식별자·건수만 선택해 출력했다. 원 관측은 보호된 .credentials/scholarly-mcp/probes에 보존하고 회귀 fixture에는 검색 결과 영역만 정제해 넣었다. 앞선 도구 출력 삭제나 토큰 폐기를 수행한 것으로 주장하지 않는다. 기존 연구 변경과 사용자의 .codex/config.toml 변경은 커밋 대상에서 제외했다. 병행 do-math 커밋이 M-0162를 사용했으므로 최신 번호를 확인한 뒤 M-0163으로 결정화했다.
