# do-math 영역·관점 분할 검증과 기각 수리의 직접 재검토

## 맥락

사용자는 do-math 전면 검증의 수리자를 여덟 기, 관점을 네 기로 늘리고 수리자·심사자를 gpt-6-astra로 지정했다. 불필요한 호환 요소·죽은 인자, 생산자와 소비자 사이의 계약 불일치, 존재 목적을 어기는 구현과 지나친 비효율을 중점으로 삼았다. 처음에는 두 라운드였으나 1라운드의 공식 적용 뒤 기각·무처분 항목을 운전자가 직접 다시 보고 graphify를 갱신한 다음 현재 라운드에서 끝내라고 바꿨다. 확정 수치와 각 항목의 처분은 임시/do-math_검증_2026-09-24_astra8/동결.md·장부.md·종료보고.md가 복원 진입점이다.

## 터득한 것

영역 담당 1~4기가 228파일·73,025행을 자연 경계의 네 영역으로 나눠 읽었다. 관점 담당 5~8기는 각각 영역 4·2·1·3 담당자의 파일 전건을 필수로 읽고 다른 물음으로 검토했다. 각 담당 범위는 약 1.5만~2만 행이었다. 영역은 전건의 비중첩 합집합으로 검산했고, 여덟 수리자의 수행 기록과 CLI 로그에서 담당 사본의 비공백 원문 행 131,310회를 대조했다. 기록과 출력의 일치는 그 글이 모델 컨텍스트에 나타난 근거이며 이해의 완전성 인증은 아니다. 이전 do-math 검증에서 전건 관점의 미독이 문제였다는 [[M-0333]]·[[M-0334]]에서 확인한 독해 결손이 더 작은 관점 필수 범위에서는 나타나지 않았다.

수리 항목 하나는 결함 보고와 파일의 행 구간을 바꿀 완성된 조각 하나 이상을 담는다. 수리 항목 41건에 조각 108개가 있었고, 조각이 겹치는 항목을 일곱 묶음으로 병합해 최종 심사 항목 34개를 세웠다. 세 심사자의 전건 판정으로 29개 심사 항목이 수리, 둘은 무처분, 셋은 기각됐다. verify-rounds 공식 스크립트 .agents/skills/verify-rounds/scripts/vr.py의 적용 하위명령이 승인 조각의 원래 문면을 사본·원본과 대조한 뒤 29개 심사 항목·86개 조각을 42파일에 반영했다. 병합된 항목의 구성원까지 포함해 장부.md 본표의 항목 행 36개가 「적용」 상태가 됐다. 사용자 후속 지시로 다섯 미적용 항목을 원문과 심사 사유에 다시 대조했다. R1-12는 지적한 역할 필드가 실제 소비자에서 쓰이지 않고 기존 시험이 통과해 기각을 유지했다. R1-01에서는 연구 수행에 쓰는 과제 자기 점검 규칙을 보충 조사에도 전달했지만, 보충 조사 프로필은 실행 중 주기 관찰을 쓴다. 이 프로필의 rule_bindings는 자기 점검 규칙을 허용할 항목 목록인데 비어 있다. 엔진이 연구 수행용 규칙을 보충 조사에 넘기자 ObservationTracker가 빈 목록과 전달된 규칙을 대조해 모델 호출 전에 거절했다. R1-40에서는 스트림의 줄 하나를 처리할 때마다 남은 전체 바이트를 다시 분할했다. 두 결함은 실재했지만, 처음 낸 R1-01 시험 조각은 생성자를 건너뛴 엔진 모사체에 저장소 스냅샷 포인터인 head 속성을 채우지 않아 실행 기록 생성 전에 실패했다. R1-40의 시험 조각은 바이트 문자열 안에 이스케이프되지 않은 실제 줄바꿈을 넣어 Python 구문이 성립하지 않았다. 이 둘은 시험을 다시 쓰고 제품 코드와 함께 직접 적용했다. R1-31·R1-41의 미사용 인자는 사용자가 특별히 제거를 요청한 종류여서 정의와 호출부를 함께 정리했다. 심사 원판정과 사용자 지시의 처분 변경을 장부에 따로 남겼다.

적용 뒤 단위 시험 292건, 바뀐 통합 사례 15건, Lean 그룹으로 옮긴 실제 형식 검사 1건, R1-01의 연구 수행·보충 조사 규칙 구별 시험 1건과 R1-12의 기존 기각 확인 시험 1건, 구조·구문·미러 검사에 성공했다. R1-40의 스트림 시험은 단위 시험 292건에 포함된다. 전체 통합·Lean·자원 스위트와 실제 연구 인스턴스는 실행하지 않았다. 앵커는 첫 라운드 전에 정본 228파일을 바이트 그대로 복사한 기준 사본이다. 이 사본의 기준 커밋 0fe3906add3f93a687c7672567bc5b23411c7fea과 최종 원본의 바이트를 대조하면 정본 .claude/skills/do-math/의 45파일이 달라졌다. 공식 적용의 42파일 밖에 사용자의 재검토 지시를 받은 운전자가 test_redesign_ENGINE.py·test_model_runner.py와 provider_engine.py를 더 고쳤다. Codex용 생성 사본 .agents/skills/do-math/는 정본에서 재생성했다. graphify의 첫 갱신은 긴 계약 문서의 인용 한 글자가 원문과 달라 기존 그래프를 보존하고 실패했다. 성공한 여섯 문서 추출을 캐시에서 회수하고 해당 문서만 재추출한 두 번째 호출은 성공했다. 최종 그래프는 current, 228파일·6,157노드·21,647관계다. 그래프 자체와 상세 CLI 로그는 Git에서 제외되는 로컬 산출물이며 종료 정리 뒤 라운드 로그는 없어질 수 있다.

## 작업 너머 시사점

심사에서 기각된 조각 항목은 결함 부재와 다르다. 제품의 문제는 타당하지만 함께 제출한 시험 코드가 실패할 수 있다. 반대로 명료한 지적처럼 보여도 소비자가 실제로 읽는 필드를 따라가면 근거가 사라질 수 있다. 사용자가 운전자에게 기각·무처분 항목의 직접 재판정을 지시하면 두 경우를 분리해 검토해야 한다. 이번 종료는 사용자가 라운드 상한을 1로 바꾼 결과다. 적용 건수와 종료 판정은 실행하지 않은 전체 통합이나 실제 연구 운전의 효과를 증명하지 않는다.

graphify의 축자 인용 검사는 의미가 같은 표현도 원문과 다르면 거절했다. 이 실패가 기존 그래프를 보존한 덕분에 잘못된 근거를 그래프에 넣지 않았고, 한 문서만 새 모델 실행으로 회복할 수 있었다. 후속 작업에서 그래프의 current는 추출 완료의 상태로 쓰되, 결함의 판단 근거는 현재 원문과 코드에서 다시 확인해야 한다.
