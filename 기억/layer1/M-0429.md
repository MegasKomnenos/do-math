## 독립 변경과 실제 red

[[M-0428]]의 잠금 수리는 d701b82c로 확정했다. 다음 KD-0002는 후보의 formal 전체를 복사하지 않고 실행 파일 정규화 호출만 가져왔다. 후보의 formal에는 Git 포트 전달과 중단 검사 공개화도 섞여 있어 다른 단위로 남겼다. file_io.executable_identity가 PATH/cwd/링크 경로를 해소하고 strict일 때 존재를 요구한다. 어댑터 능력 식별과 관찰 키, 요청 수신 비교, Lean 관찰/검증, Lake 관찰 키의 여섯 소비함수가 공유한다.

main의 c0zd9v1o는 정본 외 다섯 함수의 중복 정규화가 남는 구조 실패와 실제 PATH 이름 요청을 절대경로의 동일 실행 파일로 받아들이지 못하는 ValueError를 재현했다. 새 규칙의 미존재 import에서 실패하지 않도록 실제 checked_start_paths 수신 검사부터 실행했다. 입력은 adapter.worker_options와 worker_request_fields 생산자로 만들었다.

구조 검사만으로는 기존 cli_execution의 Path 비교를 발견하지 못한다. 구조 수집기는 Path(shutil.which(x) or x) 모양만 찾는다. 실제 요청 수신의 정상/다른 파일 반려 시험을 함께 요구한 이유다. 입력 전문 보존, 엄격 누락 FileNotFoundError, 비엄격 누락 관찰, 어댑터의 두 식별 결과도 확인한다.
