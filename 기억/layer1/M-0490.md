[[M-0489]]의 다음 B75는 원문 5-A 중 task_scope.assessment_basis와 _refresh_readiness 개설 조건을 다룬다. 기존 함수의 제출 형식 projection 일곱 필드와 KN 검토 주기 제외 두 필드를 공개 상수로 옮겼다. 정책을 새로 좁히지 않고 기존 의미를 선언으로 드러낸 변경이다. KN을 통한 제출 내용 인용과 FR 직접 인용은 서로 다른 계약이며, 직접 인용의 판단 현재성을 제출 내용으로 축소하지 않는다.

실제 completed_with_knowledge 생산자의 봉인 완료 과제에서 선언된 일곱 필드 변화는 완료 현재성을 잃고, KN 검토 주기 ID와 이후 FR verification/publication_state/formal_use 변화는 제출 완료 근거를 유지한다. FR 구성원 제거는 무효화한다. 같은 봉인에서 FR 직접 인용을 추가한 경우는 verification 변화에 민감하다. 임의 JSON projection 변화는 더 높은 형식·게시 관문을 통과한 정상 계약이라는 주장이 아니다. 기존 관계 끝점·직접 전문가 근거의 현재성 시험을 보존한다.

실행 중 검토 시험은 실제 활성 Sim에서 실제 과제 생산자, _refresh_readiness, _register_execution과 execution_lifecycle 전이를 쓴다. 등록된 실행의 action은 admission에서 profile_ref 등으로 결속되므로 개설 직후 action과 비교하면 틀린 기대다. 첫 준비 실패는 필수 role 부재(3ja8gv7u), 두 번째 실패는 등록 전 action을 봉인 비교 기준으로 삼은 오류(u_qk4y91)였다. 둘 다 시험 구성 오류이며 제품 결함 발견으로 세지 않는다. 등록 후 action 사본을 기준으로 하고 running→stopping→ended, outcome=execution_incomplete의 현행 전이를 사용했다.

외부 work profile의 effort 변화는 review_basis_key를 바꾸지만 같은 contract_basis의 검토가 실행 중이면 두 번 준비 갱신에도 추가 검토는 없다. 다른 대상은 검토 한 개를 유지하고 실행 중 action도 변하지 않는다. 종료 뒤에는 변경된 근거 키의 검토 한 개를 개설하며 추가 갱신에도 중복되지 않는다. 이는 개설 판정 성질을 보는 최소 실제 엔진 상태이며 모델 응답 수락·현재성의 전체 연쇄를 새로 검증했다고 주장하지 않는다. 국소 8개(bk4v6rn9)와 동시 검토 한 개(kc9pb9rp)는 각각 다른 시점의 보조 결과다.
