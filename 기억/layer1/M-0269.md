## 완료 기준의 교정

사용자는 각 기능의 목적 달성에 필수인 효과는 모두 구현하고, 강한 읽기 격리 같은 부수 수단은 구현자가 실익에 따라 선택하라고 명확히 했다. [[M-0266]]의 구현 재량은 기능 자체를 생략할 허가가 아니다. [[M-0268]]의 작은 CLI/1 흐름과 그 범위를 전체 설계의 완료 기준으로 삼는 해석을 교정했다. 통합 설계 0절과 `docs/do-math/기능-완료-대응.md`가 이 구분을 구현·소비자·검증 근거에 연결한다.

기존 코드에는 없던 이의 심사 왕복, 원 검토 자리의 대화와 보충 조사 복원, 사건·복합 착수 조건, 사용자 결정과 현재성 전파, 실행 중 관찰·부분 산출 회수, 외부 효과 원장, 신뢰 환경 전환, 학술 후속을 실행기에 연결했다. 영속 계약 이름은 `do-math-cli/1`, 기능 판본은 2다. 특정 v9 wire를 복제하는 일과 각 기능의 목적을 구현하는 일을 구별한다. 알 수 없는 미래 판본은 거부하며, 알려진 초기 CLI/1의 승인 결과는 이력을 보존한 채 현재 형식·동일성 검사를 다시 받는다.

## 실행에서 확인한 경계

CLI가 JSON 결과를 반환했다는 사실만으로 작업자의 도구가 작동했다고 판단할 수 없었다. 실제 연구에서 elevated 모드는 `ShellExecuteExW` 설정 도우미 오류 1223을 내고 파일 변경을 끝내지 못했다. Unelevated workspace-write도 상대 경로와 명시적 절대 작업경로에서 쓰기가 거부됐다. 같은 호스트의 기존 사용자 권한을 사용하는 `danger-full-access`에서는 실제 파일 쓰기·다시 읽기가 통과했다.

현재 기본 CLI 실행은 승인 정책 never와 로컬 권한 모드를 사용하고 Windows Job의 자손 수명 관리는 유지한다. 모델에 절대 작업경로를 전달하고 shell workdir·절대 파일경로를 명시하게 했다. 이는 현재 환경에서 확인한 실익 판단이며 강한 호스트 파일·네트워크·크리덴셜 격리를 보증하지 않는다. 별도 OpenAI API 키는 요구하지 않는다. 향후 다른 환경에서 더 유용한 경계가 확인되면 이 선택을 다시 평가할 수 있다.

실제 관찰 시험은 checkpoint와 부분 파일이 생성되고 긴 명령이 실행 중인 상태에서 별도 운영 CLI가 동작하는 것을 확인했다. 이 과정에서 적용된 pause를 후속 운영 처분이 ready로 덮는 결함을 찾았다. 코드가 명시적 pause와 운영 stop을 유지하도록 고치고, 최신 동결본의 실제 실행에서 최종 paused·종료 장벽·원문 바이트 보존을 확인했다. 구버전의 부분 성공과 pause 실패는 별도 보고서에 그대로 남겼다.

## 소비자 연결에서 수리한 사항

과제 의무를 이전한다는 기록만 추가하면 받는 과제의 완료 판정에는 영향이 없었다. 이전 기준을 실제 completion criteria에 합치고 새 revision의 독립 검토를 요구하도록 연결했다. 같은 과제의 개정도 미완료 의무를 조용히 지우지 않는다.

초기 검토의 질문과 일반 연구 이력이 다른 독립 검토 입력으로 새는 경로를 제거했다. 봉인된 이전 단계와 자기 자리의 대화는 정확한 출처로 복원하며, 같은 단계의 동료 판단은 전건 반환 전 공개하지 않는다. 보충 조사 결과는 원래 요청한 자리로 돌아간다. 철회 답변을 세 심사자가 확인한 뒤에도 같은 답변을 반복하던 경로도 닫았다.

신뢰 환경 재검사 성공은 의미 승인의 자동 승계가 아니다. 선언 시그니처·프로젝트·의존 근거가 달라지거나 불명확하면 전체 동일성 검토를 다시 열고, 그 검토가 해소한 전환 원인만 제거한다. 무관한 의미·의존 정지 원인은 남는다. 수학 관계도 무관한 K와 판정 ID를 붙여 승인할 수 없게 정확한 관계·끝점·범위를 입증하는 결과와 현재 끝점 근거에 결박했다.

학술 요구는 수학적 해결 뒤 별도 과제로 생성한다. 사전에 보여 준 학술 요건이 증명 작업의 미래 선행조건으로 섞이지 않도록 역할 지시를 교정했다. `tool:lean`은 제출 후 실행기가 검사하는 방식임을 명시하고, 아직 관찰하지 않은 판본을 추측하지 않게 했다. 학술 외부 효과는 실제 성공 원장과 현재 요구·해결 근거를 대조해야 완료할 수 있다. Unknown은 성공으로 간주하지 않으며, 명시적 대조와 허용된 재시도는 같은 논리 요청의 정체성을 보존한다.

## 검증 근거와 보존

영구 증거는 `docs/do-math/구현-검증-2026-09-14/feature2/`에 있다. 실제 전체 흐름은 새 인스턴스에서 CLI 18회와 Lean 1회를 사용해 자연수 오른쪽 영 덧셈의 K와 목표 감사를 완료하고, 이어 재현 설명의 학술 요구까지 completed로 끝냈다. 입력·출력·사용량·원문 산출·Git bundle과 실행 당시 소스 ZIP을 보존했다.

별도 심사 왕복은 합성 초기 판단 2건으로 경로를 열고 실제 CLI 8회로 정리·3인 심사·원 자리 답변·재심을 통과했다. 이를 실제 초기 검토로 계산하지 않는다. 별도 부정 사례에서는 실제 Lean과 실제 초기 검토자 2명을 사용해 양화 순서를 바꾼 해설을 두 명 모두 mismatch로 탐지했고 K를 만들지 않았다. 이 사례는 정리 단계 전에 멈췄으므로 최종 심사 불일치까지 확정했다고 표현하지 않는다.

실제 Lean 환경 전환은 정상 재검증과 허용 밖 공리의 거부를 대조했다. 선행 의미 판정만 합성 fixture였음을 표시한다. 전체 동결 회귀는 261건 중 260건 통과·1건 환경상 skip이었다. 마지막 planning 변경과 관련 소비자의 45건도 통과했다. 중간 loopback 시험 한 건의 unknown은 원 예외가 보존되지 않아 원인을 확정하지 않았다. 시험 서버의 요청·응답 처리를 완결하고 예외를 관찰하게 보강한 뒤 반복 및 관련 전건 검사를 통과시켰다. Unknown을 성공으로 바꾸어 검사를 통과시키지 않았다.

검증 중 정본 편집 때문에 실행 판본 검사가 의도적으로 pause하는 사례도 있었다. 이후 검사는 고정 소스 사본에서 실행하고 원본 해시·결과를 함께 보존했다. 실제 모델 검사, 모델 대역의 상태 검사, 실제 프로세스·HTTP·Lean 검사는 각각 입증하는 범위를 구별한다. 작은 수학 사례의 성공을 일반 연구 성능이나 수학 판단의 무오류성으로 확대하지 않는다.

Dream에서 함께 종합할 후보는 [[M-0268]]의 이전 단계 근거 제공 문제와 이번 의무·영수증·관계 결박 문제다. 이름이나 기록의 존재만 검사하면 하류가 실제로 소비하는 전제가 빠질 수 있다. 완료 판정은 선언한 기능 이름보다 입력부터 후속 효과까지 연결된 경로와 반례에 근거해야 한다.
