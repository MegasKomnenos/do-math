WOS·ACM의 고급검색과 자료 회수를 구현하고 IEEE·PQDT·공통 추출의 설명·지원표를 함께 통합했다. ACM Boolean 교정 전 전체 서비스422검사와 기존 문헌 catalog16검사, 의존성 검사가 통과했으며 공유 KUDOS Chromium·Firefox 상태 파일의 SHA-256도 조사 시작 값과 같았다. 사용 설명의 개발 중 문구가 없어지는 것을 기능 완료의 근거로 삼을 수 없다. 사용자가 지적한 ACM 예외를 확인해 구현을 다시 열었고, 같은 종류의 제한 판단을49개 자료원 전체에서 감사하기로 했다.

WOS 정렬 대기는 접근 제한이 아니라 두 관측 오류였다. 실제 후보는 option이 아닌 menuitem이었고 정렬 변경은 최초 runQuerySearch가 아닌 runQueryGetRecordsStream 응답이었다.21개 현재 메뉴와 여섯 edition을 연결했고 원 값·표시·route·결과 건수를 대조한다. CPCI-S 단독은 WOS.ISTP와 원 WE 필드로 확인했다. 모든 edition 선택의 원 null 표현은 기관 전체 선택과 함께 해석한다.

초기 analyze 후보만 연결해서는 실제 가능한 추가 필터를 쓰지 못했다. 처음 가시5개 밖의2013년을 See all에서 확인한 뒤, 별도 collapsed section이 원 분석 요청을 보내는 사실도 조사했다.22개 분야를 사용자용 이름과 정확한 표시 label로 연결했다. facet_group/facet_query는 결과 집합을 바꾸지 않는 후보 조회이며 facet_filters는 같은 분야 OR·다른 분야 AND다. Free to Read가 내부 OAJ.BRONZE인 차이처럼 backend 값을 label에서 발명하지 않고 현재 input에 결속한다. 호출자에게 API나 DOM 지식을 요구하지 않는다.

WOS의 독립 검토에서 세 반례를 추가 수리했다. Friendly 필터 뒤 total1인데 과거 DT16 후보를 Current로 반환하던 것을 최종 DT1로 갱신했다. Refine·후보 요청을 현재 QID와 건수에 결속하고 preview의 QID·건수·선택 상태 불변을 확인한다. 원 QID를 출력하지 않고 일치 여부만 기록한다. 요청한 추가 export가 실패해도 records·원 plain·evidence를 partial로 보존한다.170140Z advanced와170340Z citing SDK가 통과했으며 같은 분야 두 label의9건 조합도 검증했다. wos-final-review의 원 세 반례 재실행이 PASS다.

ACM의 일반 field 행은 기본 AND로 결합한다. 이를 AND만 지원한다고 단정했던 조사는 잘못이었다. 사용자가 Search Tips의 Edit Query 예외를 제시했고 실제 View Query Syntax 아래 editableQuery에서 Title:(algebra) OR Abstract:(complexity)가95,534건, AND가320건임을 확인했다. 대문자 연산자를 사용하며 소문자 or는 같은 의미가 아니었다. 별도 범주 한 행은 복수 values와 And/Or/Nor를 제공하며 그 연산은 범주 값 사이에 적용된다. JACM·CACM Match Any의93건은 Title 조건과 별도 AND다. 범주 입력 행 추가는 관측하지 못했지만 이것을 검색식 자체의 결합 한계로 확대하지 않는다. 연속 facet은 패널을 열고 이전 조건을 유지하는 원 링크만 선택해 CACM1,781건에서 Research Article220건으로 좁혔다. 여러 패널이 같은 ConceptID 필드를 사용하는 의미도 후보에 보존한다.

ACM의 새 HTML 전문은 같은 DOI의 원 full 제어·제목·bodymatter·backmatter를 대조한다. 문헌10.1145/3831699의31쪽 PDF와 HTML·TeX30개가 실제 SDK로 검증됐다. 추가로 실제 SIGPLAN 원 export가 선택1개 외 다른 DOI를 포함하는 경계와 JMLR의 DOI 없는10.5555 레코드 경계를 닫았다. 추가 CSL 자료를 버리거나 관계를 추정하지 않고 요청·포함·추가 범위와 원 source_export를 partial로 보존한다. JMLR은 exact CSL key·record URL·제목을 결합해 식별한다. PDF·HTML 오류가 기성공 metadata나 다른 구성요소를 지우지 않게 수리했다. 관련44검사와 live-sdk-boundaries.json이 통과했다.

정상 표본으로 바꾸는 것만으로 실제 실패 표본의 문제가 해결되지는 않는다. 이 작업에서는 후보 밖 값, 같은 label의 다른 분야, 원 export의 추가 문헌, key와 DOI의 구별, 추가 형식 실패의 부분 결과처럼 실측·독립 검토가 드러낸 경계를 다시 열어 교정했다. ACM에서는 행별 연산자 선택기가 없다는 사실과 검색식의 Boolean 지원을 혼동했다. 도움말의 예외·별도 편집 경로까지 확인해야 하며 관측하지 못한 제어를 자료원의 기능 부재로 단정하지 않는다. 검사 수를 늘리기보다 원 의미와 검증 결과가 일치하도록 범위를 조정했다.

ACM 교정은 query를 비우고 options.expression에 원 검색식을 받는다. field/fields와 병용하지 않으며 날짜·범주·facet·sort는 원 제어로 함께 적용한다. Edit Query 입력과 결과 AllField의 일치를 확인한다. acm-boolean-recheck/live-sdk.json은 교차 field OR95,534건과 날짜·두 발행물·자료 유형·정렬을 결합한13건, 원 BibTeX를 completed=true로 검증했다. 관련46검사가 통과했다. Guide collection은 코드에서 보존을 검사하지만 이 추가 실측은 기본 fulltext collection의 관측이다.

근거는 services/scholarly-mcp/VALIDATION.md와 data/access-research/wos-citations/advanced.md, wos-final-review.json, acm-advanced/구현보고.md, acm-boolean-recheck/보고.md 및 관련 SDK 파일이다. Semantic Scholar의 fetch-first429, SWH 특정 flat 작업 대기, AMS 동적식의 원 제공자 오류, SIAM 일부 원문 권한 실패는 당시 조건의 관측으로 보존하며 영구 불가 판정으로 확대하지 않는다. 추가 계정·키·연락 이메일을 쓰지 않는 사용자 결정은 유지한다. IEEE HTML 전문과 Figshare·Wiley의 확인된 기능 축소 수리, 나머지 자료원 감사는 후속 단위에서 계속한다. 전체 원 작업 완료나 푸시는 아직 선언하지 않는다.
