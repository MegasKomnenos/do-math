[[M-0538]] 다음으로 지정 조회 출력 묶음의 마지막 trace_report.progress만 새 문맥 작업자에게 배정했다. produced_object_schema(progress)를 제거하고 기존 unit.test_engine_trace_report_corruption의 실제 임시파일 반환으로 operation_progress의 문서 키를 검사한다. status와 이 한 공간은 각자의 실제 경계에 명시적으로 위임하며, 실제 결과 없는 기본 호출은 거부한다. 구조 검사 내부에 파일/저장소 I/O를 추가하지 않았다.

corrupt error 파일16개 상한·관측시각·빈 rows의 기존 단언을 유지하고, 같은 실제 결과를 문서 전건과 별칭에 연결했다. 최종 키를 하나씩 제거하면 해당 참조가 실패하며 telemetry_errors의 실제 문서 누락도 확인한다. 다른 소유자의 필드나 이번 결과로 증명하지 않는 배열 내부 경로를 통과시키지 않는다. 정상 live/파일부재의 기존 sim 시험과 status 최종반환 시험도 유지한다. 지원/구조/기존unit 두 개의 네 파일만 변경했고 제품 수정·새 스키마 사본·범용 분석기를 추가하지 않았다.

구조17+unit7의24개가9.5초에 통과했고 실행 중 변경은 없다. 원보고는 검증/2026-10-05-progress-실제반환/report.json에 바이트 그대로 보존했다. progress/status의 문서연결 시험0.734/0.766초는 개별0.2초보다 길지만 실제 경계와 단언을 유지했다. 지정 DOC-RETURN-PURE의 record_map·운영요약·감독사실·status·progress 교체는 여기서 완료로 닫았다. 다른 문서 생산자나13-C전체를 완료로 표시하지 않는다.

다음은 같은 문서 검사기를 더 확장하는 대신 B88 이후 누적된 현재 후보의 전체 일반 통합 결과를 얻는 B123이다. 기본 runner 선택은 structure/unit/contracts/sim/flows 다섯 폴더이며 --jobs3으로 한 번 실행한다. 마지막 편집을 확정하고 실행 동안 소스를 고정한다. 이것은 중간 통합 확인이며 최종 요구 검수/fullT3/극단변이/실환경 완료를 대신하지 않는다.
