## 맥락과 변경 경계

사용자는 do-math 스킬이 외부 문서에 대한 의존성을 완전히 없애고 자기완결적으로 존재하기를 요청했다. CONTEXT.md는 예시로 제시됐으므로 다른 외부 문서와 간접 의존도 검사했다. 배포 단위는 스킬 폴더 전체로 정했다. 연구별 목표·정책·허가·원자료와 Python·Git·Codex·Lean 같은 실행 환경은 별도로 제공받는 입력이다.

공통 정의 본문은 대부분 GLOSSARY에 이미 있었지만, 서두가 외부 CONTEXT와 통합 설계를 정본으로 지정했다. 역할과 CLI 문서에도 상위 설계의 이름·필드를 전제로 한 표현과 외부 검증 이력 링크가 남아 있었다. 외부 설계 전체를 복제하면 현재 실행에 필요하지 않은 명세까지 관리해야 하므로, 필요한 정의와 절차의 권위를 스킬 내부에서 닫았다. [[M-0274]]가 기록한 외부 저작 원천 관계를 현행 운영의 필수 읽기 계약으로 승계하지 않는다.

## 확인한 의존성과 교정

보조 검사 `probe_codex.py --spec-only`는 외부 v9 명세 묶음과 설계·검증 보고서를 읽었다. 스킬만 복사한 위치에서 이 검사가 실패하는 것을 관찰한 뒤, 설치본의 역할 문서와 출력 스키마를 검사하도록 바꿨다. 현재 명칭은 `--skill-only`이며 옛 옵션은 같은 검사의 별칭이다. 결과의 범위도 `installed_skill_structure`로 구별한다. 이 구조 검사는 문서 의미나 연구 품질·실제 모델 실행의 검증이 아니다.

독립 감사는 역할 문서가 구별하도록 요구한 연구 생산의 정의가 내부에 없다는 점과 검토 계획자·범위 계획자의 명칭 불일치를 발견했다. 연구 생산은 당시 원천인 통합 설계 9.4절과 대조했다. 해결 전의 원고 정리·외부 수학 조사 준비도 포함할 수 있고, 형식 산출의 유무와 다른 구분이라는 의미를 내부 정의에 보존했다. 검토 계획을 작성하는 실행은 GLOSSARY의 검토 자리 설명과 맞춰 범위 계획자로 통일했다. 독립 독해는 별도 `.agents` 사본 사용을 강제하던 CLI 문장이 단독 설치와 충돌함을 발견했다. 실제 설치 폴더의 문서와 코드를 함께 사용하도록 고쳤다. 계약 검토의 주체가 모호한 문단은 주체·전달·판정·후속 순서로 재구성했다.

GLOSSARY의 보편 K 편입 관문과 현재 CLI의 Lean 재실행 없음은 내부 문서가 구별하므로 외부 의존 결함으로 확대하지 않았다. 상태 압축, 판정 불가 전용 필드의 부재와 유지보수의 서술형 반환도 현재 구현 한계 또는 입력 계약으로 보존했다. 자기완결성을 만들기 위해 기존 보증을 과장하거나 미구현 기능을 새로 구현한 것은 아니다.

얕은 설치 경로에서는 Lean 자동 탐색과 네이티브 격리 보조 명령의 부모 경로 인덱스가 예외를 냈다. 두 경우를 재현하고, Lean 미발견을 반환하거나 현재 작업 위치를 출력 기준으로 사용하도록 고쳤다. 기존 도구의 설치 요구와 명시적 경로 설정은 유지했다.

## 검증 범위

수정 중 고정한 단독 복사본에서 시험 파일 37개를 실행했다. 그중 직접 실행으로 시험이 시작되지 않는 기존 파일 4개는 unittest discovery로 실제 시험을 실행했다. 합계 273건 중 272건이 통과했고, Windows symlink 권한이 필요한 1건은 미실행이었다. 그 뒤의 경로 교정과 문서 수정까지 포함한 최종 복사본에서는 `test_preflight.py`, `test_probe_codex.py`, `test_standalone.py`, `test_native_probe.py`, `test_formal.py`, `test_reading_map.py`의 25건을 모두 통과했다. 이 6파일은 설치본 검사, 보조 명령, 경로 이식, Lean과 역할 문서 적재를 검증한다. 두 실행의 중복 시험을 서로 다른 검증 건수로 합산하지 않는다. Lean 실행에는 설치된 도구체인의 bin 경로를 PATH로 제공했으며 외부 프로젝트 문서는 복사하지 않았다.

Markdown 16개 전체의 독립 감사를 수행했다. 독해·합의 대조는 외부 참조 정리본, 연구 생산·범위 계획자 정의 보완본, 단독 설치 안내 교정본의 세 판본에 각각 수행했다. 최종 문서는 내부 링크 9건이 모두 존재하며 외부 설계·맥락·검증 이력 문서의 참조를 요구하지 않는다. `.claude/skills/do-math/` 정본과 `.agents/skills/do-math/` Codex 생성 사본의 동기화·드리프트 검사, 스킬 형식 검사도 통과했다. 실행 로그와 고정 복사본 좌표는 `.skill-workspace/do-math-standalone/`에, 독해·대조 기록은 해당 세션의 `.codex/writing-flow/`에 보존했다. 이 검증은 일반 수학 연구 효능이나 강한 OS 격리를 입증하지 않는다.

## 후속에 남길 구별

문서에 외부 경로가 없다는 사실만으로 자기완결성을 확정할 수는 없다. 정의되지 않은 구분을 쓰거나 형제 사본의 존재를 강제하는 문장도 실제 읽기·실행의 전제가 된다. 외부 원천의 필요한 의미를 내부에서 설명하는 일과, 역사 문서 전체를 배포물에 복제하는 일은 구별해야 한다. [[M-0274]]와 함께 문서의 정의·권위·실제 입력 전달을 검토하는 사례로 종합할 수 있다.
