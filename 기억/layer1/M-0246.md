주 세션은 반환된 SIAM 기관 접근과 JSTOR 영상 과제의 화면·요청·코드를 검토하고 로컬 제어·관찰·상태 분류 수리를 원본에 통합했다. 두 수리를 포함한 원본 전체529검사가67.613초에 통과했고, 각각 새 원본 SDK의5개 판정도 통과했다. 실제 보호 문헌의 권한이나 다운로드 비활성이 해제된 것으로 계산하지 않는다.

SIAM은 현재 a#downloadPdfUrl[data-doi] 제어를 인식하지 못해 not_implemented를 반환했고, 명시 PDF가 같은 DOI의 접근 화면으로 돌아온 경우에는 download_missing으로 끝났다. 원본 회귀 두 개가 이 잘못된 상태를 재현했다. publishers.py의 제어 인식·동일 문헌 접근 상태 분류를 수리하고, DOI의 대소문자와 인코딩을 정규화하되 다른 DOI·호스트를 제한 상태로 바꾸지 않는 추가 회귀를 통과했다. 주 세션은 criteria-b11-20260913T071345Z의07·08·09 이미지를 직접 읽어 정확한 문헌, 중간 보안 확인, 안정된 Previews are depleted/Get Access를 구별했다.

SIAM 검색 조건 CLI와 원격 호출이 겹치지 않도록 전용 run_when_free.py가 같은 source의 실행·대기를 확인한 뒤 검증했다. root-user-criteria-20260913T0715Z/siam/sdk-root-target-084936, sdk-root-explicit-085003, sdk-root-open-085106이 원본 SDK 근거다. 일반 DOI는 metadata available·fulltext restricted인 partial, 명시 PDF는 access_restricted, 공개19M1299001은705,276바이트·53쪽 PDF available이었다. 첫 쪽 제목·DOI를 텍스트와 직접 이미지로 확인했다. 별도 KNU IdP 로그인은 다시 시도하지 않았다. 현재 세션의 비공개 PDF 거부가 구독 계약 부재나 특정 관리자 설정 오류를 증명하지는 않는다.

JSTOR의 document_uuid는 #cdt만 기다려 빈 화면 뒤에 나타난 client challenge를 보지 못했다. 새 회귀에서 원시 TimeoutError를 확인한 뒤, 준비된 식별자를 우선하고 없으면 접근 확인도 관찰하도록 고쳤다. 준비된 문헌 제목이 challenge처럼 보이는 경우를 잘못 제한하지 않는 회귀도 포함했다. 끝내 식별자가 없으면 문헌 부재나 identity mismatch로 단정하지 않고 document_load_timeout/retryable로 반환한다. 실제 브라우저 관찰 자체가 실패하면 document_load_failed로 구별하며 일반 Python 오류를 무차별적으로 삼키지 않는다.

주 세션이 b08-load의 탐색 전·흰 중간 화면·안정 client challenge·정상 문헌 이미지를 직접 읽었다. 원본 SDK의 community.39197180은 metadata와2,191바이트 전사문을 보존했으며 native download disabled에 따라 fulltext not_offered였다. community.41259097은24,416,379바이트 MPEG 오디오와33,159바이트 VTT가 모두 available인 ok였다. 영상의 broad Download 버튼은 관련 문헌 소유일 수 있으므로 현재 영상의 비활성 제어와 혼동하지 않는다. 공개 MPEG 양성은 영상 파일 회수의 증거가 아니다.

정제 결과는 data/access-research/user-criteria-siam/root-sdk.json과 user-criteria-jstor/root-sdk.json이다. 원 코드·검증 원문·직접 판독 파일은 각 전용 root-user-criteria-20260913T0715Z 경로에 보존했다. 지원표와 검증·감사 문서에 로컬 수리와 남은 source 조건을 함께 기록했다. SIAM의 별도 Author exact facet 수리는 아직 원본 통합 전이다.

통합 전 다른 사본에서도 근거가 부족한 제한을 확인해 재검토를 연결했다. AMS basic_expression의 ASCII 한 토큰 제한, 평탄화 가능한 중첩 Boolean의 조기 거부, 일반 검색의 고정 공개 호스트 이동과 페이지 캐시 결속을 reviews/ams-criteria-code-review.md에 적었다. 과거 요청을 새 요청과 함께 활성화하지 않고 AMS의 review_request_id만 user-criteria-02-ams-code로 교체해 같은 CLI thread를 재개했다. 이는 아직 실제 결함으로 확인하지 못한 경로 오염 가설까지 모두 수정하라는 지시가 아니라 검증·반증 후 필요한 변경을 하라는 계약이다.

CORE files01의 사본이404를 일괄 복구 제외하는 판단도 queued 과제의 legacy-404-resolution 사례로 추가했다. 옛 URL404와 현재 공식 metadata가 같은 output의 활성 공개 파일을 주는 경우를 구별하도록 했다. 실제 제거·비활성·접근 제한을 우회하지 않고,404 자체를 문헌 소실로 일반화하지 않게 검토한다. 이 항목은 아직 구현이나 실측 완료가 아니며 criteria-tasks.json과 해당 재개 프롬프트에 연결했다.
