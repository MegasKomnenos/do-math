ScienceDirect PDF와 Export 후보를 현재 원본에 합쳤다. 행 Export가 없거나 준비되지 않으면 정확 PII 하나의 상단 Export를 사용하고, 제목 검색으로 정확한 행을 복원하지 못하면 같은 문헌 상세의 Cite를 사용한다. PII·제목·제공 DOI 검증을 공유한다. 오래된 PDF 후보 전체를 복사하면 selected_export_choice와 native_search_citation의 상단 Export 수리가 사라지므로 해당 함수는 그대로 보존하고 PDF 관련 변경만 이식했다. doc_id는 ISSN/ISBN 구조이며 PII·DOI나 체크섬 검사로 설명하지 않는다.

Preface S0065230X26000631의 상세 View PDF와 object 열기는 실제 준비 HTML을 거쳐 같은 문헌 HTML로 복귀했다. 과거 loopback handler가 만든 404를 공급자 signed404로 해석했던 결론은 철회했다. 새 원 제어·provider challenge·직접 사람 확인·양성 31쪽 PDF를 대조했지만 그 상세 경로만으로는 fulltext_unresolved였다. ClinicalKey 링크와 전권 다운로드는 개별 Preface PDF의 성공으로 세지 않았다.

최종 검토가 남긴 정확 Title=Preface+ISSN0065-230X 경로를 실제로 실행했다.45건의 첫 행은 정확 PII·제목·연도에 맞았고 View PDF가 없었다. 한 행을 선택한 Download 1 article은 현재 세션이 해당 콘텐츠를 구독하지 않는다는 모달을 보였으며 PDF·download event는 0이었다. root가 입력 전, 정확 행, 선택 직전, 비구독 직후·안정 이미지를 직접 읽었다. 이 결과는 PDF 복원이 아니라 원인 구체화다. restricted/fulltext_access_restricted를 유지하고 상세 fulltext_unresolved도 detail_error_code로 보존한다.

새 후보는 대상 checkbox를 무조건 토글해 이미 선택된 행을 해제하고 다른 행 선택도 남겼다. 독립 사본에서 실제 선택 상태 회귀 1실패·1오류를 재현한 뒤, 정확히 하나의 대상 PII를 확인하고 전체 선택 집합을 저장·임시 변경·복원하도록 고쳤다. 모달이 열린 상태의 복원은 DOM label click과 확인을 사용한다. 복원만 실패하더라도 주 ServiceError는 유지하고 정리 오류 종류를 덧붙인다. root는 이미 검증된 PDF를 받은 뒤 정리만 실패하면 그 파일까지 버리는 추가 반례를 재현해, available artifact와 정리 오류를 함께 보존하도록 수리했다.

새 원본 stdio SDK 4기능이 모두 통과했다. There is no universal separable Banach algebra의 PII S0022123626003204, DOI10.1016/j.jfa.2026.111656과 RIS 1,165바이트를 대조했다. Preface는 실제 exact_detail_cite 경로로 RIS 405·BibTeX 440·plain316바이트를 받았다. S156042922600065X는 1,031,433바이트·31쪽 PDF와 첫 두 쪽 DOI10.1007/s40593-025-00498-2를 확인했다. 정확 Preface 검색 후 fetch는 비구독, artifact 없음, 상세 오류 보존을 확인했다. 별도 소유 브라우저의 네 주 기능 전후·안정 화면도 직접 판독했다. 시각 하네스의 사후 선택 해제 TimeoutError는 원본 SDK 실패로 세지 않았고 주 결과 뒤의 별도 오류로 남겼다.

시각 검증의 검색 단계에서는 원본 대기 오류가 추가로 재현됐다. 동일 Preface+ISSN 요청이 33.589초에 search_interface_not_ready로 끝났지만 직후 화면에는 조건 chip·45건·목표 첫 행이 이미 있었다. root도 그 화면을 읽었으며 단순 하네스 문제로 분류하지 않았다. 원래 30초 대기 뒤 같은 selector를 즉시 다시 확인하고, 아직 없을 때만 5초 더 기다리게 했다. 끝내 준비되지 않으면 retryable typed 오류를 반환하고, 접근 확인·URL·query·PII 검증은 유지한다. 다른 검색 경로나 조건으로 바꾸지 않는다.

두 추가 회귀를 포함한 ScienceDirect36검사가 통과했다. 새 원본의 같은 검색은 28.828초, 새 소유 브라우저는 20.078초에 45건과 정확한 PII를 반환했고 비구독의 전후·안정 화면도 다시 확인했다. 이 두 실행의 성공을 모든 환경의 timeout 제거로 확대하지 않는다. 원본 최종 sciencedirect.py SHA256은 ae625d140f7219078fb0dd72a33b2743ef3cd8b899d90b66c06f48010ee373c1이다.

소유 Chrome 종료가 정상 wait·terminate 뒤에도 timeout이면 그 소유 프로세스만 kill하고 reap하도록 한 공통 수리도 포함한다. 관련 12개 검사가 통과했고 실행 종료 뒤 소유 프로세스는 없었다. 일부 private 임시 profile 정리 PermissionError는 잔존 파일 경고로만 남기며 등록 MCP·Codex·사용자의 브라우저는 건드리지 않았다.
