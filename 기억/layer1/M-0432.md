## 생산 검증과 저장 수신의 일치

[[M-0431]]의 입력 소비 수리는 07604a32로 확정했다. KD-0007/0008은 생산자와 저장 계약의 어긋남이다. main ui4pakqv의 기존 두 재현 시험에서 공백·한글·콜론을 포함한 규칙 이름3개와 잘못된 조건 열거값4곳이 실제 실패했다. 결함 표시만 제거해 원래 기대값을 재현하고 수리했다.

관찰 규칙의ID는 파일이나 레코드 이름이 아니라 비어 있지 않은 로컬 텍스트다. observations.RULE_ID_SCHEMA를 생산 검증과 저장된 규칙·관찰 rule_ids에 공유했다. producer가 이미 허용하는 progress check/규칙/r:1을 파일 식별자의 REFS로 저장 거부하던 오류를 없앴다. 서로 다른 이름과 비어 있지 않음의 기존 검증은 유지한다.

planning.validate_condition은 RECORDS/RESEARCH_FIELDS의 실제 enum을 읽는다. 별도 목록을 복제하지 않는다. execution/outcome, formal-result/formal_use, formal-result/publication_state, identity-assessment/decision에서 임의 잘못된 비교값을 받던 것을 막았다. 기존 lifecycle/형/공간/포인터 검사는 유지한다. 후보의 반복 결과 표·자기 점검 진행 표·관찰 반려·추가 저장 필드처럼 다른 변경은 복사하지 않았다.

## 검증의 범위

tglpoiy0의44개가2.0초에 모두 통과했고 개별 예산 초과가 없다. 현행 PAIRS의 생산/수신 검사, 규칙 결속과 다른 실행의 재결속 거부, 프로필 실제 Git 저장 왕복, 관찰 규칙의 입력 거부, 조건 판정과 현재성이 포함된다. 새 시험 모듈이나 같은 성질의 중복 시험을 만들지 않았다.

특정 규칙 이름3개는 validate_rules의 생산 수용과 실제 저장 계약 rule_ids 속성 검사로 검증한다. 이 쌍 검사가 전체 실제 owner의 관찰 생성·게시까지 통과한 증거는 아니다. 기존 프로필 저장 왕복의 정상 규칙 검사와 구별한다. 최종 동적 모집단/분기/변이 관문을 이44개로 닫지 않는다.

main 원장에서 이 두 항목만 닫아 열린 결함7개다. 공개 이음새 표와 생성 미러를 함께 갱신했고873파일 drift0을 확인했다. 추적 진입점은 단계-전환표 current_work.rule_integration의 보고 SHA256·소스 지문이다. 원 보고 전문은 사용자 Temp의 Git 제외 로컬 자료이며 전체 실패 기준선/당시 교정 원문은 M-0427의 추적 아카이브에 있다.

다음은 신뢰 전환의 재기록·핀 고정 실행·출처·외부 전송과 남은 영향/빈 준비 수리다. 목표는 계속 active이며 최종 전체 관문과 비용, 함수 전건 변이와 말뭉치가 남는다. 푸시, graphify 갱신, 기존 연구 재개/삭제는 하지 않는다.
