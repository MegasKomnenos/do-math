## 맥락

[[M-0263]]에서 남은 Windows elevated 설정을 사용자가 승인했다. Codex 0.154.0이 설치한 backend에서 실제 저권한 계정으로 실행하고 파일·네트워크·프로필 간 권한을 대조했다. 별도 API 인증은 사용하지 않았다. 연구 역할을 만들거나 D01 통과를 선언하지 않았다.

## 확인한 능력과 실패

단일 프로필에서는 허용 입력 읽기와 작업 공간 쓰기가 성공했고, 입력 변경과 비공개 경로 읽기·쓰기는 AccessDenied였다. 원본 Python도 재실행에서 정상 동작했다. 첫 CreateProcessAsUser 오류 5는 현 설정에서 재현되지 않았으므로 실행 파일 복사나 원본 ACL 교정을 추가하지 않았다.

외부 TCP는 같은 IP·포트에 대한 호스트의 전후 양성 대조가 성공한 가운데 sandbox에서 SocketError AccessDenied, native error 10013으로 거부됐다. Loopback TCP는 연결됐다. 이 두 네트워크 범위를 같은 결과로 합치지 않았다.

읽기 권한은 실행별로 독립적이지 않았다. 초기 private ACL을 SYSTEM·Administrators·호출자로 제한한 뒤 A에 inputA를 허용했다. A 종료 뒤 CodexSandboxUsers RX가 남아 B가 이전 A의 canary를 읽었다. 동시 실행에서는 B를 시작하면서 A도 B의 canary를 읽었다. 상대 경로를 명시적으로 deny하면 순차 실행은 통과했지만, B가 공유 principal의 ACL을 교체하여 살아 있는 A가 자기 inputA를 잃고 원래 거부했던 inputB를 읽었다.

최초 대조 중 프로그램 오류와 넓은 상속 ACL을 가진 fixture는 증거에서 제외했다. 폐쇄 초기 ACL을 사전 보존한 v3와 grant·deny ACE를 모두 초기화한 v4-clean에서 같은 문제를 확인했다. 재사용 도구는 fresh fixture, 양성 대조, AccessDenied·부재·프로그램 실패 구별, 동시 실행 전·중·후 표본, Job 종료 장벽을 보존한다. 현재 backend의 결함을 재현하면 exit 1을 반환하며, 그 결과를 검사 도구의 실패로 수리하지 않는다.

## 구현과 검증

CLI worker에 닫힌 filesystem 경로 목록과 고정 TOML 생성, legacy sandbox와의 배타 분기, 알 수 없는 필드의 거부를 추가했다. 쓰기 루트는 모델 작업 공간 안이어야 하고 고정 입력·출력·상태 파일을 포함할 수 없다. 실제 단일 CLI가 허용 input의 새 canary를 읽고 반환하는 것을 확인했다. 이 구성 기능은 프로필 간 격리의 보증이 아니다. describe의 검증 범위도 CLI 명령 표면으로 명시했다.

paused maintenance·recovery의 참조 구조와 관계 검사를 추가했다. 의미 검토를 거쳤어도 동일한 기계 전제를 모두 확인하며, 새 정지는 재개 허용과 다른 처분으로 검사한다. 실제 원장·승인·역할 실행과의 연결은 남아 있다. 구현 회귀 55건과 오프라인 명세 80건은 통과했고, native 읽기 격리 검사는 불통과다. 원문과 반복 실행 결과는 `docs/do-math/구현-검증-2026-09-14/`에 보존했다.

## 다음 구현의 경계

기존 WSL2 Ubuntu-20.04를 대안으로 확인했지만 가상화가 켜지지 않아 HCS_E_HYPERV_NOT_INSTALLED로 시작하지 못했다. Windows 기능·펌웨어·배포판을 변경하지 않았다. 현재 CLI의 외부 exec-server 연결은 실험적 app-server 표면에서만 확인됐고 standard exec의 검증된 대체 실행 경로는 확인하지 못했다.

추가 격리·제어 계층으로 원래 보증을 유지할지, CLI 지원 범위에 맞춰 계약을 재설계할지 사용자에게 방향을 물었다. 이 노드를 작성할 때 답은 아직 없으며 원래 계약을 낮추지 않았다. 호출별 자원 예약·출력 상한, 실제 내부 입력과 자동 압축, 공급자별 식별자·원격 종료의 남은 검증도 코드의 존재로 대신하지 않는다. 재개 좌표는 `docs/do-math/구현-진행.md`다.
