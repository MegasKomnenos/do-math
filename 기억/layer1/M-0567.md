## 맥락

017은 새 제품 코드를 쓰지 않고 015의 측정과 016의 fixture 수리·Git 과거 입력을 연결했다. 두 exact 비교는 정본과 미러에서 통과했고, cleanup 전에 보존한 정본 6개 fixture의 snapshot 30개·coverage DB 16개·실제 child 30개를 검산했다. 이전 T4의 12개 미통과 항목도 최종 양쪽 전체에서 통과했다. 그러나 정본은 294통과·1오류, 미러는 295통과여서 작업을 partial로 유지했다.

## 다음 판단에 필요한 조건

parent TEMP를 저장소 안에 두면 Git 없는 fixture가 상위 저장소를 찾는다. 외부 TEMP로 옮겨도 resource worker는 공식 output 아래 scratch를 쓰므로 긴 경로 문제는 별개로 남는다. 이번 설치 probe는 존재하는 cwd 262자에서 WinError267, 241자에서 정상·반려 경로가 각각 예상 종료했다. 다음 배정의 task 이름과 output을 짧게 정했고, 이를 Windows 보편 상한으로 일반화하지 않았다. 같은 소스의 환경 대조와 근거 없는 반복 실행을 구별해야 한다.

남은 오류는 재resume 반려를 확인한 뒤 임시 디렉터리를 삭제하는 단계의 WinError32/5다. shared fixture는 job.close를 디렉터리 정리보다 먼저 실행하지만, 현 close는 핸들을 닫을 뿐 root와 빈 Job을 기다리지 않는다. 실행 순서와 종료 완료는 다르다. 오류 순간의 프로세스·핸들 상태가 없어 race는 아직 가설이며 앞선 통과로 오류를 해소하지 않았다. 018은 실제 상태 관측과 현 API를 사용하는 fixture 정리 순서 수리, real/fake 회귀와 양쪽 전체 T4를 맡는다. runtime close 계약을 먼저 바꾸는 배정은 하지 않았다.

과거 비교의 정본 raw는 동일한 미러 시험 바이트와 별도 미러 공식 실행에 한정해 재사용한다. 미러 fixture raw를 따로 보존한 것은 아니다. 같은 성공 주장의 적용 범위를 소스·실행·원자료별로 구별했다. 다른 의미/문서·L01과 최종 일반/T3/변이/review는 남는다.
