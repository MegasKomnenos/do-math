IOP의 확인된 세션에서 실제 Search 버튼으로 검색 메뉴를 열어 /nsearch 결과를 확보했다. 기존 label[for=quickSearch]는 메뉴가 닫혀 있어 클릭하지 못했다. 기사 카드10개에 링크20개가 있었고 상위500건 중1-10이 표시되었다. 링크 수를 문헌 수로 세지 않고, 원 검색의 노출 건수는 accessible_total로 분리했다. 전체 일치 건수를500으로 만들지 않는다.

원 RSS 링크 /nsearch/rss도 조사했다. 익명 요청에서 실제 XML200을 받았지만 다른 요청은 validate.perfdrive.com으로302였다. 유효한 기관 세션에서는 RDF/RSS를 확보했다. 요청한 관련도·오래된 순을 무시하고 최신순을 유지하는 반면 terms·pageLength·currentPage·저널 조건은 동작했다. currentPage2에 GoNext를 함께 주면3쪽이므로 API는 currentPage만 사용한다. pageLength20과 페이지2를 대조했고, 페이지51에서도 자료를 받아 원 HTML의500건 상한을 API에 적용하지 않았다.

공개 API 기준에 따라 기본 sort=newest는 별도 API 자격이 없는 RSS API를 기관 프록시에서 일관되게 호출한다. 관련도·오래된 순, 현재 원 UI로 검증한 pub_type/open_access 조건은 원 검색 경로로 고정했다. API 실패 뒤 HTML로 전환하지 않는다. API 요청의 원 XML과 개별 필드·항목 XML을 보존하고, native XML/HTML과 정확한 창의 JSON/CSV를 구별한다. RSS는 전역 일치 건수를 제공하지 않는다.

원 RSS의 rdf:Seq에는 항목 수만큼 빈 rdf:li만 있었다. 처음에는 정상적인 resource 참조로 가정해 실패했고 실제 속성·본문·tail을 대조해 빈 항목임을 확인했다. 전부 비어 있고 수가 일치하는 경우만 원 item 등장 순서를 사용하고 empty_rdf_sequence_used_item_order 경고를 남긴다. 다른 참조 불일치를 조용히 허용하지 않는다. 최신순 HTML과 RSS의 첫 문헌들도 대조했다.

이름 조회에 최신순을 쓰면 오래된 대상보다 그 문헌을 인용한 최근 문헌이 먼저 나왔다. 이름 입력은 관련도 후보 검색으로 연결했다. iop-name-relevance.json은5후보 중 첫 DOI가10.1088/0022-3727/34/10/311임을 확인한다. 이름만으로 자료를 자동 선택하지 않는다.

원0건 화면은 Showing 범위나 정렬 제어를 생략하고 returned0results 제목과 숨은 기간 값을 남겼다. 기존 검사는 이를 invalid_response 또는 filter_mismatch로 읽었다. 원0건과 읽을 수 없는 페이지를 구별하고, 필터의 체크 상태 또는 숨은 원 값을 대조하도록 고쳤다. 이전 실패는 20260911T045825Z-iop-search-mcp.json에 남아 있다.

20260911T050214Z-iop-search-mcp.json은 completed=true다. 최신순 API의 페이지 경계와 start500 뒤2건, 관련도 페이지 경계·CSV, 저널1742-6596·article·공개 접근·oldest 조건, 원 웹 상한 초과 거절과 실제0건을 확인했다. 앞선 044439Z는 익명 API 접근 확인, 044657Z는0건 추가 전의 성공 기록이다. 모든 기간·문헌 유형·페이지 크기 조합을 검증했다는 뜻은 아니다.

브라우저 상태는 로그인 직후의 공용 kudos.json만 저장되고 종료 때 갱신분이 남지 않았다. 엔진별 kudos-chromium.json·kudos-firefox.json을 읽고 종료 시 원자적으로 갱신하도록 했다. 파일이 없으면 기존 kudos.json으로 시작한다. 다른 엔진 파일의 비변경과 갱신 상태의 재열람을 검사했다. 이것만으로 접근 확인의 재발 원인을 확정하지 않는다. IOP의 재확인은 20260911T041819Z-iop-verification-control.json에서 성공했고 새 엔진 파일에 보존했다.

공통234검사가 통과했다. 전체 구현은 계속 진행 중이다. APS는 첫 페이지·CSV·MathML과 부분 결과를 제공하지만 연속 조회가 제한된다. AMS·SIAM·ScienceDirect·JSTOR의 남은 접근 문제를 원 파일과 최신 관측으로 이어간다. CLI·기존 Codex 창을 재시작하거나 조작하지 않고, 전체 완료 전에는 푸시하지 않는다.
