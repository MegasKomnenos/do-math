DBLP의 일반 검색 API와 Trier·Dagstuhl 미러가 모두 HTTP 200의 HTML 접근 확인 응답을 반환했다. 반복 재시도로 끝내지 않고 운영기관의 다른 공개 인터페이스를 확인했다. 공식 문서에 공개된 sparql.dblp.org/sparql은 자격 없이 실제 서지 JSON을 반환했다. 일반 검색의 접두어 문법과 SPARQL은 다르므로 dblp-kg를 별도 자료원으로 명시적으로 선택하게 했다. 실행 중 실패에 따른 자동 전환이나 다른 제공자 호출은 넣지 않았다.

SPARQL SELECT 원문에 도구 start/limit를 최상위 OFFSET/LIMIT로 적용한다. 원 결과의 변수별 RDF term과 자료형·언어·미결합 변수를 유지한다. QLever의 result-size-total은 제한된 질의의 값이라 전역 검색 건수로 확대하지 않고 total=null로 둔다. 원 CSV·TSV와 JSON의 행·값을 대조하고 실패한 원 export도 source_export로 보존한다.

외부 질의의 SERVICE와 데이터셋 선택 FROM은 문법 구조로 검출해 요청 전에 거부한다. 문자열·주석의 같은 단어는 거부하지 않으며 하위 SELECT의 범위는 허용한다. 직접 문자열 파서를 만들지 않고 RDFLib 7.6.0과 pyparsing 3.3.2를 사용했다. 두 버전을 requirements에 고정했다. 로컬 Graph.query나 RDF 원격 로딩은 수행하지 않는다. 현재 지원 질의형은 SELECT이며 다른 질의형의 연결 완료를 주장하지 않는다.

첫 실제 MCP 보고 20260910T132325Z-dblp-kg-mcp.json은 검색·세 내보내기·문헌 key 조회까지 성공한 뒤 소문자 DOI에서 not_found로 끝났다. 실제 key 조회의 32개 statement에는 DOI가 10.1006/JCSS.1997.1494로 들어 있었다. RDF IRI의 대소문자 동일성을 DOI 동일성에 그대로 적용한 오류였다. 질의와 DOI 대조만 대소문자를 구별하지 않도록 수리하고 원 RDF 표기는 보존했다. DOI 끝의 .xml을 DBLP export 확장자로 잘못 제거하는 입력 처리와 빈 문헌을 기본 parts에서 partial로 표시하는 처리도 회귀 사례로 고쳤다.

새 SDK stdio의 services/scholarly-mcp/data/validation/20260910T132715Z-dblp-kg-mcp.json은 completed=true다. 앞 4건과 start=1/limit=2, native JSON·CSV·TSV, 문헌 key·DOI의 32 statements, 이름 후보, SERVICE 거절을 확인했다. provider의 결과와 다른 원 export를 잃지 않는 검사도 통과했다.

추가 직접 어댑터 검증에서 yearOfPublication의 JSON 자료형은 xsd:gYear였지만 원 TSV는 1997을 따옴표·자료형 없이 출력했다. 이는 정수 RDF term이므로 같다고 처리하지 않았다. 20260910T132945Z-dblp-kg-terms.json은 partial/미완료로 보존하고 현재 오류 코드는 export_term_mismatch로 구분했다. 연도 조건은 xsd:integer(STR(?year))로 변환한 실제 질의를 안내한다. 20260910T133158Z-dblp-kg-extra-terms.json은 저자 집계·언어가 있는 개행/따옴표 문자열·미결합 변수·빈 결과의 원 TSV 직접 검증을 통과했다. 이 보고를 MCP 검증으로 세지 않는다.

공통 검사 186개와 pip check가 통과했다. APS 인용문 조사의 최초 직접 요청은 기관 바로가기의 www.aps.org 호스트에 저널 경로를 붙인 잘못된 프로브였다. 이를 성공·실패 근거로 사용하지 않았다. 실제 KUDOS 경로로 journals.aps.org에 진입한 뒤 요청한 BibTeX는 HTTP 403이었다. 보호된 관측 20260910T130807Z-aps-citation-failure.html을 남겼으며 구현 성공으로 세지 않는다.

전체 구현은 부분 완료이고 푸시하지 않는다. 주요 기관 검색은 실제 접근 확인 때문에 남아 있다. 사용자에게 사람이 처리해야 하는 확인 화면을 직접 처리할 수 있는지 비동기로 물었으며 API 키·새 계정·연락 이메일을 요청하지 않았다. 응답이 없으면 수동 확인을 했다고 간주하지 않는다. 최신 인계문은 OS 임시 디렉터리의 학술자료-MCP-후속구현-인계-20260910.md다.
