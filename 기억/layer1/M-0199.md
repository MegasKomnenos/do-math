화면에서 읽은 숨은 초록에는 MathJax의 mjx-lazy만 남아 수식이 사라졌다. 원 HTTP HTML 응답에는 MathML 22개가 있고 빈 자리표시는 없었다. 브라우저 context의 원 응답을 확보하여 렌더링 전 HTML을 파싱한다. Algebra of causality의 원 초록 MathML 두 식을 fixture로 보존하고 늦은 DOM 대신 원 응답이 사용되는지 검사했다. clean_html로 스크립트·숨은 입력·민감 URL 값을 제거한 뒤 자료를 보존한다. 점검한 원 APS 페이지에는 민감 이름의 meta 값이 없었으며 이를 비밀값 노출 사건으로 기록하지 않는다.

실제 SDK 20260911T021223Z·021441Z-aps-search-mcp.json에서 첫 2건과 CSV의 DOI 배열 일치를 확인했다. 다음 범위를 요청하면서 같은 검색을 다시 여는 경우에는 확인 화면이 나타났다. 동일 조건에서 start>0인 후속 요청은 최근에 받은 원 페이지를 재사용하도록 했다. evidence의 원 retrieved_at를 유지하고 start=0은 새 검색을 수행한다. 데이터의 조립 시점과 원 수신 시점을 구별한다.

20260911T021913Z 보고는 start=19, limit=2에서 20번째 1건을 보존한 partial이었다. 원 Next 버튼의 화면 내부 요청은 실제 HTTP403이었다. 023237Z·024034Z 보고도 연속 페이지·추가 조건·선택 문헌 조회를 완료하지 못했다. 후속 페이지의 실행 오류가 이미 받은 요청 범위의 자료를 버리지 않도록 했고, 탐색·페이지 오류를 안전한 코드와 오류 유형으로 반환한다.

반면 별도 KUDOS 심층 진입으로 페이지 2를 열면 20건을 받았다. 보호된 aps-second-page-deep-20260911.html과 20260911T023101Z-aps-exact-next-deep.html의 page=2, start=20, total=37987 및 원 조건을 대조했다. 두 번째는 원 Next href의 쿼리를 그대로 사용했다. 이를 근거로 페이지 이동을 문서 탐색으로 연결했으나 같은 세션에서의 연속 호출은 여전히 제한되었다. 차이를 만드는 원인이 요청 종류·접근 경로·브라우저 상태 중 무엇인지는 확정하지 않았다. 독립 진입의 성공을 연속 MCP 워크플로 통과로 표현하지 않는다.
