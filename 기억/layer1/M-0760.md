## 맥락

[[M-0759]]의 문서 커밋 뒤 푸시가 거부됐다. 원격 `origin/main`에 로컬에 없는 커밋 하나(488d6f46, 2026-11-21 02:53 UTC, GitHub 웹에서 사용자가 만든 "Remove summary table from README")가 있었고, 로컬은 그보다 29커밋 앞서 있었다. 그 커밋은 옛 README 머리의 「At a glance」 표 11줄을 지운 것이다. 로컬 저장소는 이 커밋을 받은 적이 없어서, 이 세션은 표가 있는 판본을 "현재의 문체"로 보고 새 README에도 같은 꼴의 표를 두었다.

## 터득한 것

- **처분.** 강제 푸시나 재배치는 하지 않고 병합했다. 재배치는 로컬 29커밋의 해시를 바꾸어 기억 노드들이 적어 둔 커밋 좌표를 깨뜨리기 때문이다. 충돌은 README 머리 한 곳이었고, 사용자의 삭제를 따라 새 README의 표를 지웠다. 표에만 있던 내용 가운데 본문 앞부분에 없던 것은 "지금까지 검증된 것" 한 줄이어서, 도입부 마지막 문단에 한 문장으로 옮겼다. 나머지 행(완료 조건, 완료가 보이지 않는 것, 해결한 문제, 실행, 설계·검증, 인용)은 도입부와 각 절에 이미 있다.
- **확인하지 못한 것.** 표를 지운 뒤의 README는 독립 독해를 다시 받지 않았다. 세 차례 독해는 모두 표가 있는 판본에 대한 것이고, 독해자들이 표의 "What completion does not show" 행을 가장 쓸모 있는 대목으로 꼽았다는 점은 [[M-0759]]의 독해 보고에 남아 있다. 사용자가 표를 되살리려면 커밋 c4851e6c의 README 머리에서 회수할 수 있다.
- **교정 신호.** ⓐ 나는 작업 착수 때 `git status`의 "ahead 22"만 보고 원격을 가져오지 않았다. ⓑ 사용자의 원격 편집이 공개 판본의 현재 문체였다. ⓒ "현재 문체를 유지하라"는 지시의 기준 판본을 로컬 HEAD로만 잡았다. ⓓ 공개 문서를 고치는 작업은 착수 때 `git fetch`로 원격의 판본부터 확인한다.

## 근거 경로

추적(이 커밋): `README.md`. 병합한 원격 커밋은 488d6f46, 표가 있던 새 README는 커밋 c4851e6c에 있다.
