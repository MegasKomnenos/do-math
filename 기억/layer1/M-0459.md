계획 영역의 후보 시험 열한 모듈과 필요한 정상 생산자를 main에 통합했다. [[M-0458]]의 반복 모집단 통합은 ec6a57a2로 확정했다. 제품 동작을 바꾸지 않고 남은 시험 가족을 이관하는 B43이며 원장 번호나 감사 문서를 추가하지 않는다.

새 단위 모듈은 조건 문법·평가, 처분과 의무, 개정, 범위 검증이다. 새 sim 모듈은 관찰 복구, 준비 전이, 준비 경계, 실제 관계 조건과 위임, 개정 전이, 평가·양도·철회 수신, 독립 전문 판정이다. 조건의 runtime_error·부재·JSON scalar 형·정확 근거 hash, 의무 전건과 권한, 양도의 source/task/edition/recipient 좌표, 봉인·결과·잔여범위 currentness, 활성 위임 비탈취, 개정의 남은 목표·필수성·owner 유지 등을 정상 생산자에서 검사한다. 이전 두 KD 이동 메서드는 후보에서 제거된 상태를 유지하므로 중복 도입하지 않는다.

planning_contract_inputs의 기존 함수들은 AST로 후보와 일치함을 확인했고 warm_prepared만 기존 main 구현을 유지했다. 새 함수만 추가하고 contracts/planning/disposition import를 연결했다. 전문 판정 생산자는 실제 Lean 대역 허용 사실 전건, 실제 연구 출력 수신, identity review match, assessment/ref와 관계 import를 거친다. 제품 판정 함수를 교체하지 않는다.

처음 계획 가족 404개 선택 01uxu689는 complete=true/successful=false, 345passed/59not_run,139.4초였다. 보고의 준비 error 행 세 개는 전체 counts에 포함되지 않지만 setUpModule traceback에 보존돼 있다. warm_transfer/warm_relation/warm_specialist가 main에 아직 없는 support.sim.warm_built를 참조했다. 제품 실패나 실행 제한 초과로 오인하지 않는다. 완료 관찰 대기로 같은 선택을 재시작하지 않았다.

sim.built의 기존 입력 정규화와 sticky failure cache를 warm_built로 분리하고 built는 그 템플릿을 restore하도록 연결했다. warm_built는 소비 상태를 복원하지 않고 정상 생산자의 캐시만 준비한다. 후보의 별도 Sim.restart abandon_owner 변경은 복사하지 않았다. 본 교정은 도우미 동작이며 제품 함수의 대역화가 아니다.

pp5enjc9는 미실행 세 모듈59개, template_inputs3개와 구조6개를 62.7초에 모두 완결 통과했다. 최초139.4초 보고와 현재62.7초 보고는 서로 다른 helper 판본이므로 합산해 같은 최종 판본404개 전체 통과라고 주장하지 않는다. 초기 개별 예산 초과14개와 재검증5개를 남긴다. 원보고·SHA256·파일 지문과 한계는 단계-전환표 current_work.planning_population_integration에 연결한다. 실행 중 코드 변경은 두 보고 모두 없다.

원 조사 보고의 실행 원칙은 원본 Claude JSONL 16d62671의0기준367행 사용자 속도 배분 조건과483행 시험 품질·방어 비용 조건에서 다시 확인했다.377행의 A는375행 assistant가 제시한 동작 보존 리팩터 뒤 수리 선택을 승인한 것이다. 발화 요약만으로 선택의 뜻을 추정하지 않았다. 이번 이관의 실패가 helper 준비 배선으로 구분된 점과 연결되며, 전 로그를 새로 전독했다고 주장하지 않는다.

여전히 다른 기능 가족의 시험 모집단, 여섯 부류와2단계11의무 전건, 원1e19/1f61/P2원래12, 같은 최종 판본의 전체T2/flows/T3·모든 함수 극단변이·시간예산·최소T4/T5·말뭉치가 남아 있다. 부분 통과 수로 전체 완료를 대체하지 않는다.
