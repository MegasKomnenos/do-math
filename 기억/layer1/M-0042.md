# pvsnp-탐사-1 조기 종결과 DAG 기록 이관

## 맥락

사용자는 국면 `pvsnp-탐사-1`을 더 수행하지 말고 `dag/`로 이관해 닫으라고 확정했다. 게이트 2.8.2.15의 표본 승인·반려는 추가로 판단하지 않았다. 게이트 뒤 미착수 행 22건은 실행하지 않은 상태로 기록에 남겼다.

실행 중 오케스트레이터는 없었다. 2.8 worktree에는 미커밋 파일 넷이 남아 있었다. 네 파일을 런 기록 `행/2.d/8.d/2.d/조기종결-2.8-worktree/`에 복사하고 SHA-256으로 대조했다. main에 병합되지 않은 2.8 브랜치 HEAD는 태그 `archive/pvsnp-탐사-1-2.8`로 보존했다.

회수기는 worktree와 국면 브랜치를 제거한 뒤 잔존 0을 보고했다. 마커는 활성 국면 없음으로 전환됐다. 런 디렉터리는 `dag/pvsnp-탐사-1/`으로 옮기고, 컨텍스트 정본의 현행 국면 상태를 종결로 갱신했다.

## 검증

메모리 색인은 파일 51개와 색인 51개가 일치했다. 채록한 네 파일은 원본과 SHA-256이 모두 일치했다. 이관 뒤 `dag_check.py`는 보존된 절대 `.sdd` 좌표를 현재 런 좌표로 읽어 실패했다. do-dag 이관 계약은 실행 좌표를 보존하지 않으므로, 이 실패를 고치려고 기록을 재작성하지 않았다.

## 터득한 것

국면 종결은 미완 작업을 실행 완료로 바꾸는 일이 아니다. 파견표의 미착수 상태, 게이트 결정, 종결 결산을 함께 보존해야 나중에 실행하지 않은 범위와 중단 근거를 구별할 수 있다.

회수기는 미커밋 worktree와 병합되지 않은 브랜치를 자동 삭제하지 않는다. 사용자 지시로 종결할 때도 파일 복사본의 해시 대조와 도달 가능한 Git 참조를 먼저 만들면 산출과 커밋 이력을 분리해 보존할 수 있다.

## 작업 너머 시사점

wayfinder의 국면 처분 결정과 do-dag의 실제 종결은 다른 기록을 남긴다. 전자는 후속 작업의 범위를 정한다. 후자는 worktree·브랜치·런 기록을 보존하고 제어 마커를 닫는다. 직접 사용자 지시가 두 절차를 연결할 때, 두 기록을 모두 갱신해야 다음 세션이 실행 상태를 오독하지 않는다.
