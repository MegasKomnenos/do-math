[[M-0521]]의 직접 큐 생산자 여섯 가족 중 task_scope.apply_task_assessments와 knowledge._apply_impact_effects의 남은 조합을 처리했다. B104 제품 소스 지문이 전부 그대로임을 확인해 원천 검색을 반복하지 않았다. 제품 코드는 바꾸지 않았으며 기존 시험 ID와 원단언을 보존했다.

미완료 평가 수신에서는 현재 계획이 큐에 남아 후속 요청을 가로막을 가능성을 먼저 확인했다. 실제 실행 결과는 누락이 아니었다. 현재 계획의 적용 단계에서는 중복 계획을 만들지 않지만, 수신 뒤 과제가 ready가 되어 task_became_ready 사건이 새 계획을 만든다. 최초 검사는 requested_by가 평가 실행 ID인 요청만 찾았으므로 이 정상 경로를 놓쳤다. 실패 보고의 큐에는 실제 새 계획과 사건 참조가 있었다. 이를 제품 결함으로 등록하거나 불필요한 추가 계획을 만들지 않고, 실제 사건의 과제 ID와 과제 waiting.basis_ref의 평가 실행 ID를 따라가도록 검사했다.

실제 수신은 open·missing·completed 세 경우다. 열린 의무는 후속 계획이 정확히 한 번 수락되고 같은 준비 사건은 추가 owner 두 번에도 한 번만 소비된다. missing은 추가 증거를 기다리고 completed는 끝나므로 해당 후속 계획은0이다. 도메인 검사는 open·missing·closed와 기존 research_plan·research_preparation·없음의 아홉 조합이다. 입력 불변, 기존 요청 보존, 필요한 때만 새 계획1, 반복 적용에서 같은 계획 유지도 확인한다. 후속 계획은 선택을 보류하므로 기본 응답기가 선택용 모델 평가 확장을 남기지 않도록 plan_assessments=False를 명시했다.

지식 영향은 이미 있던 독립 검토의 승인/미해결 두 흐름을 확장했다. 승인 뒤 실제 영향 계획이 B를 포함한 affected_ids 전건을 그대로 받아 한 번 수락하며, 추가 두 owner pass 뒤에도 같은 요청은 한 번만 실행된다. 미해결 검토에서는 생산 산출을 보류하고 실제 계획 호출0이다. 도메인 단위 검사는 영향 없음0/있음1과 동일 영향 요청 반복 시 큐 불변을 확인한다. 기존 영향 적용·증거 보존·원산출 재수신 단언도 유지한다.

영향 흐름의 기본 완료 응답은 실제로 없는 EV-proof를 충족했다고 주장해 거부됐다. 입력초과 복구에서 이미 쓰던 미완료 응답과 같은 조건이므로 support.role_answers.assessment_awaiting_required_evidence로 모아 두 소비자가 사용한다. 이 도우미는 모든 의무에 이름 있는 필수 증거가 있는 fixture만 받아, 해당 증거를 기다리는 unresolved 평가를 만든다. 보고서가 존재한다는 사실을 필수 증거 충족으로 바꾸지 않는다. 이 추가 응답 생성은 시험 지원 코드이며 제품 평가 규칙을 완화하지 않는다.

최종 구조48·단위29·flow5의82개가62.3초에 통과했고 실행 중 소스 변경이 없다. 검증/2026-10-05-평가후속-영향전파/report.json과 작업판 B105가 원증거 진입점이다. 초기 요청 선택기 실패, 후속 계획 응답 실패, 영향 평가 응답의 OB-proof 거부 보고도 별도로 보존했다. 부분 보고를 합산해 전체 일반 통과로 삼지 않는다. 미러와 기억 색인 검증도 적용한다.

B104 remaining_new_judgment_families에서 두 가족을 검증 근거와 함께 verified_additional_families로 옮겼다. 남은 것은 governance._queue의 판단 요청, revisions.record_repetition 진단, planning.schedule_reconsideration의 잔여 조건, 일반 lifecycle 사건 및 공개 직접 요청 네 가족이다. 이 목록은 원래19+11·보존61·P2 원12 및 전체 일반/fresh T3/변이/T4/T5 완료 조건을 대체하지 않는다.
