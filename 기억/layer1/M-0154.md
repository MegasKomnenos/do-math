## 맥락

사용자는 통합 설계 한 문서만 근거로 세부 지시의 합성 결과를 검토하도록 한 뒤, 보고한 수정과 구조 정리를 모두 진행하고 커밋하라고 지시했다. 최초 검토는 원문만 읽었고, 수리 단계에서는 연결된 명세 검사기와 직접 영향받는 정의를 확인했다. 지적 아홉 건의 근거·처분·검증 범위는 `docs/do-math/검토-교정-2026-09-09/발견과-처분.md`에 남겼다.

사용자가 원하는 간결화는 필요한 구분의 삭제가 아니었다. 과제·활동·실행, 종료·정산, 판정 종류의 분리는 보존했다. 초과 처분을 8.3절에 모으고 목차 필드의 중복 정의와 현재 규칙에 필요하지 않은 외부 규격 설명을 덜었다. 기존 절 번호와 V·Q 번호는 유지하고 경계 사례 일곱 개를 추가했다.

## 터득한 것

규칙의 정의와 표의 적용 범위가 달랐다. 안전 제어 경계는 공급자 호출까지 포함했지만 마감 표와 함수는 도구 호출만 구별했다. 입력 초과의 문구는 복원 실패의 사용자 대기와 제안 재구성 종료에 같은 필수 대화를 포함했고, 서로 다른 기대가 V145와 V162에도 남아 있었다. 벡터의 번호·해시 대응만으로는 이런 조건 중첩을 검출하지 못한다.

보충 조사 총한도는 직접 배정 목록의 개수로 구현할 수 없었다. 기존 활동 소유 관계에서 하위 AI 실행까지 합산하고 종료된 하위 활동도 유지하는 계산을 넣었다. 별도 원장은 추가하지 않았다. 검토 회차 상한은 정확한 방침을 해석한 뒤 배정 몫과 대조하며, 스키마에 회차 값을 복제하지 않았다. 단독 자료 구조 검사와 관계 입력을 받은 검사의 보장 범위는 다르다.

새 검사 다섯 개를 먼저 실행해 기존 검사기의 미지원 입력과 한 회차 방침 거부를 확인했다. 수정 후에는 핵심 동작 네 가지를 각각 메모리 안에서 무력화해 새 검사가 실패하는지 확인했다. 이 검증은 오프라인 명세의 의미 분기를 다룬 것이며 실제 Windows 생성·종료나 모델 대화 복원을 실행한 증거가 아니다. 실제 능력의 후행 관문을 유지했다.

작업 트리에 다른 작업의 변경이 많아 이번 변경 경로만 커밋 대상으로 삼았다. 생성 명세의 해시·벡터 행 의존 때문에 문구 정리 뒤 묶음 재생성과 검증 보고를 함께 갱신해야 했다.

## 작업 너머 시사점

dream에서 묶을 후보: 검증 벡터를 검토할 때 번호 전수 대응에 더하여 서로 다른 벡터의 입력 조건이 겹치는지 확인하는 관례. 같은 조건에 종료와 대기를 각각 기대하는 두 벡터는 개별적으로는 잘 구성되어도 합쳐서는 실행 계약을 닫지 못한다.
