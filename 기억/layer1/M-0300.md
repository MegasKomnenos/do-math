사용자는 작은 주차 함수 연구의 피드백 이후 추가한 do-math 기능과 계약을 대화 로그·기억의 결정과 다시 대조하도록 verify-rounds를 요청했다. mixed·전면, 심사 gpt-6-astra medium, 1라운드를 지정했고, 모든 수리자에게 반드시 모든 담당 영역을 통독하라고 명시하도록 요구했다. [[M-0295]]의 계약·학술자료·독립 운영, [[M-0296]]·[[M-0297]]의 모델별 세션 예산, [[M-0298]]의 제출·현재성·복구 수리와 [[M-0299]]에서 확정한 평가 보충 결정을 함께 추적했다. 이번 기록의 진입점은 `임시/do-math_전면대조_20260917/종료보고.md`다. 기존 연구 인스턴스·HOLD·예약 작업은 변경하거나 재개하지 않았다.

## 통독 범위와 독립 심사

기준선은 정본 106파일·22,950행이었다. 수리자 네 명은 문서와 사용 진입점 26파일, 실행기·자원·운영 15파일, 지식·검토·제출 20파일, 회귀 검사 45파일을 맡았다. 관점 담당 두 명은 각각 106파일 전체를 읽었다. 각 파견문에 통독 의무와 검색·diff·요약 대체 금지, 잘린 출력의 재확보, 파일별 읽은 범위 기록을 직접 적었다. 담당 파일의 범위를 사본과 대조한 기록과 실제 도구 호출 좌표는 같은 런의 `검증/독해기록_*.md`와 `독해범위_*.json`에 있다. 기준 대화 발췌 173메시지도 원 JSONL의 지정 행과 대조해 문언 불일치가 없음을 확인했다.

수행 기록은 표, 목록, 한 줄의 여러 파일, 분할된 행 범위 등으로 작성됐다. 보조 판독기가 특정 표 모양만 받거나 한 행짜리 파일을 구간으로만 기대한 오류는 실제 기록을 읽고 판독기를 고쳐 처리했다. 이 오류를 미독해로 판정해 재파견하지 않았다. 문서 담당의 파일별 범위는 맞았지만 총행 수 합계 4,392는 오산이어서 사본 실측 4,137을 사용했다. 범위 기록과 도구 호출은 독해 범위의 근거이며, 이해의 완전성이나 결함 부재를 자동 증명하지 않는다.

Claude Agent 도구가 없어 로컬 Claude CLI의 독립 컨텍스트로 수리 opus high와 병합 opus low를 실행했다. 심사는 Codex CLI의 gpt-6-astra medium 세 컨텍스트가 맡았다. 역할별 파견 10회의 모델·완료 정보는 `검증/파견실측.json`에 있다. 수리·병합 모두 산출을 완성했다. 제기된 16개 중 두 항목을 하나로 병합해 심사 대상은 15개가 됐고, 심사자 세 명이 각각 전 항목을 판정했다. 이 가운데 10개 수리안이 만장일치로 승인되고 5개는 기각됐다. 승인된 10개 수리안을 6파일·12조각으로 적용했다. 그중 병합 수리안 하나가 원래의 두 항목을 함께 해결했으므로 공식 장부의 적용 계수는 11행이다.

## 수리한 실행과 인계 경계

모델 배정은 설정과 계약이 바뀌는 두 경계에서 낡은 값을 재사용하고 있었다. 모델 대응이나 역할 하한을 바꿀 때 큐의 요청만 갱신하고 보류된 행동의 배정은 남겨 두어, 재개 뒤 옛 모델을 쓰거나 존재하지 않는 모델 슬롯을 계속 기다릴 수 있었다. 과제를 개정할 때도 대기 계약 검토의 계약 해시만 바꾸고 이전 평가로 고른 모델은 유지했다. 두 경계에서 미시작 요청의 저장된 배정을 지워 현재 평가·설정으로 다시 고르게 했다. 구 실행횟수 루프가 도는 중 모델 호출 사이에 예산 모드가 전환되면 슬롯 예약 없이 실행할 수 있는 경로도 막았다. 실행기 루프가 끝난 뒤의 정상 설정 전환은 유지했다.

참조 처리에서는 `workspace:` 접두가 있는 제공 파일 인용을 제출 검사가 허용하지만 실제 의존 집계가 같은 지식 ID·원자료 이름으로 해석하지 못했다. 이 별칭 해석을 연결해 반환된 실제 의존의 판본 변경이 수신 검사에 잡히게 했다. 연구 계획의 완료 판정 오류에는 누락·중복 과제와 어긋난 기준을 구체적으로 넣었다. 생산자와 수신자가 함께 사용하는 검사 함수에서 진단을 보완한 것이며, 완료의 판정 조건 자체를 완화하지 않았다.

소실 실행 복구에는 기록과 실제 파일이 갈리는 경로가 있었다. 먼저 종료를 확인한 실행의 파일 참조를 기록한 뒤 종료 미확인 실행을 만나면, 앞서 회수한 바이트 없이 상태만 저장하고 반환했다. 앞의 실행은 이미 종료된 것으로 기록되므로 다음 회차에도 파일을 다시 수집하지 않았다. 종료 미확인 실행과 그 슬롯은 유지하면서 확인된 실행의 부분 산출·실행 증거·체크포인트를 모아 저장하도록 고쳤다. 문서에서는 초기화의 구 모드 선택, 예약 연구와 수동 실행의 사용 조건, 후보 준비가 계약을 저작하고 연구 계획은 개정을 요청하는 역할 분담을 명확히 했다. 기본 모델 대응과 작업·운영의 모델별 세션 수를 합계가 아닌 확정값으로 비교하는 회귀도 보완했다.

## 기각과 남은 두 문제

심사 대상 다섯 항목이 기각됐다. R1-05는 확장 파일의 최상위 배열 항목을 뜻하는 ‘확장 가족’의 요약을 폐쇄된 허용 목록으로 읽은 지적이다. 같은 문단·표·역할 계약·스키마가 해당 확장을 명시적으로 허용하므로 지적이 성립하지 않았다. 이 문면은 검증을 통과했고, 요약을 길게 늘리지 않았다.

R1-01·13·15가 다룬 학술 과제의 평가 반려 문제는 남았다. 계약 검토의 findings와 질문은 전달되지만, 사용자 학술 요구를 유지한 채 AI가 쓴 평가만 다시 수정하고 검토받는 실행 경로가 없다. 수리자들은 이를 새 사용자 선택 문제로 올렸으나, 심사에서는 평가 재작성 권한과 방향이 이미 확정돼 있어 산출물 안의 수리로 처리할 수 있다고 지적했다. 구현 대안이나 재반려 횟수를 제안했다는 사실은 사용자에게 새 의도를 물어야 할 근거가 아니었다. 적용할 조각이 승인되지 않아 이번 라운드에서는 이 경로를 구현하지 않았다. 기각을 문제의 부재나 해결로 보고하지 않는다.

R1-16은 구 실행횟수 모드의 계획 검사를 저장된 입력 판본으로 바꾸려는 수리안이다. 실제 제공 입력과 저장 판본의 동일성을 먼저 확보하지 않아, 첫 원자료 수입 흐름의 정상 계획까지 거부할 수 있다는 반례로 기각됐다. 후속 수리는 계획 AI가 실제 받은 과제 목록·상태와 검사 기준을 일치시켜야 한다. 사용자 지정 1라운드 상한을 유지했고, 주 세션이 기각안을 새 문면으로 바꾸어 적용하지 않았다. 기각 원문과 심사 근거는 같은 런의 `기각보관/do-math-20260917-라운드1.md`에 있다.

## 검증 근거와 한계

최종 전체 회귀는 unittest discovery로 412개를 실행해 411개 통과·1개 미실행·실패 0이었다. 미실행은 Windows 심볼릭 링크 생성 권한 부족(WinError 1314)이다. `_최종회귀.log`에 시험별 결과와 1,880.803초의 실행 시간이 있으며, 검사 전후 정본 106파일의 SHA-256은 같았다. 별도 집중 검사 기본 5개와 예산 전환 경계 1개도 각각 수정 전 실패·수정 후 통과를 확인했다. 설정 변경은 실제 임시 Git을 사용해 검사했다. 복구 검사는 Windows Job 종료 확인 함수의 응답을 대역으로 통제하고, 실제 임시 파일을 읽어 저장 함수에 그 바이트를 전달하는지 확인했다. 참조 해석과 오류 진단은 해당 함수를 직접 호출해 검사했다. 초기 보조 검사의 수집 범위와 거부 이력 조회 오류는 검사 자체를 고쳐 재실행했다. 중단한 수정 전 전체 회귀와 중복 진단은 완료·통과로 세지 않았다.

설치 문서와 10개 역할 스키마, 미러 269파일의 드리프트 검사도 통과했다. 변경 문서는 필수 참조 10문서의 전문을 별도 독해하고 승인 취지와 대조했다. 메인이 변경 문서 독해 AI에게 처음 준 문서 묶음에는 필수 참조 일부가 빠져 있어, 이를 추가한 뒤 다시 독해했다. 종료 보고 독해의 인용·행 번호 오류도 실패로 보존한 뒤 다시 읽었다. 독해가 드러낸 보고의 계수·용어·시점 설명은 명확히 고쳤으며, 추가 수정이 필요하지 않은 관찰은 실제 문맥과 이해를 대조해 유지했다. 문서 독해, 코드 회귀, 실제 모델의 연구 수행 품질은 서로 다른 검증이다. 이번 결과를 장기 수학 연구의 효능이나 모든 학술자료원의 가용성으로 확대하지 않는다.

후속 기억 종합에서 함께 검토할 후보는 [[M-0299]]다. 통독 요구를 파견문에서 분명히 전달하는 것과 그 실제 범위를 확인하는 것은 별도 작업이다. 또한 내부 수리의 구현 선택을 사용자 결정으로 넘기면, 결함을 정확히 발견하고도 수리 단계에서 완성된 수정안을 얻지 못할 수 있다. 기존에 확정된 권한과 사용자만 정할 의도를 구별하는 지점이 후속 검토의 대상이다.
