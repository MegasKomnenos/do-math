title: 실제 MCP 연결의 코드 갱신 상태와 호출 제한을 대조함
convention_version: 24
---

현재 Codex의 scholarly 연결은 이전 코드를 사용하고 있음을 확인했다. 새 기능의 실제 검증은 새 stdio 프로세스에서 이루어졌다. 기존 연결까지 갱신됐다고 주장하지 않으며 클라이언트 재시작이 필요하다. 대용량 작업을 수용하도록 scholarly 호출 제한만 180초에서 1800초로 조정했다.

등록된 mcp__scholarly__describe_source(openalex)를 직접 호출했을 때 이전 public_endpoint_search_observed 안내가 나왔다. 로컬 설치 CLI의 mcp 명령에는 restart가 없었다. app-server JSON Schema를 생성해 config/mcpServer/reload를 확인했지만 현재 Windows의 기본 제어 소켓에 연결할 수 없었고 daemon 관리 명령도 Unix 전용이었다. 관련 없는 MCP 프로세스를 종료하거나 새 원격 제어를 켜지 않았다. Codex의 공식 MCP 문서는 설정 뒤 클라이언트의 Restart 절차를 안내한다.

기존 프로젝트 설정의 180초는 일부 실제 성공한 파일 회수의 실행 시간을 수용하지 못한다. HEAD와 작업 파일에서 모두 180임을 먼저 확인해 사용자 편집 값이 아닌 기존 등록값임을 대조했다. scholarly 절의 값 하나를 바이트 단위로 바꾸고, 역변환한 파일이 원 작업 파일과 같은지 확인했다. stage에는 HEAD에 그 한 줄만 바꾼 패치를 적용했으며 사용자 설정의 다른 미커밋 변경은 포함하지 않았다. TOML 파싱과 stage 내용 대조를 통과했다.

동시에 진행한 기관 재검증에서 AMS는 서비스 불가 응답·별도 주소의 404·후속 기관 이동 실패를 보였다. IOP는 한 번 서지·초록을 실제 MCP로 확보했지만 PDF와 인용문은 validate.perfdrive.com으로 이동했다. 이어 원 인용문 제어를 클릭하려는 조사도 기관 진입에서 같은 접근 확인으로 막혔다. 이 자료원의 기능 부재로 단정하지 않고 구체적인 실패 단계와 상태 처리 수리를 다음 단위로 이어간다. 해당 코드와 검사는 아직 이 커밋에 포함하지 않았다.

전체 구현과 기존 연결의 갱신은 아직 끝나지 않았다. 후속 작업은 새 stdio 검사로 계속 수행하고, 최종 적용 안내에는 현재 연결 재시작이 필요함을 포함한다. 전체 완료 전이므로 푸시하지 않는다.
