## 실제 대역 계약의 두 실패

[[M-0451]]의 공급자 사건 수리는 6328e9ed로 확정했다. 이번에는 모델 대역과 Lean 대역의 계약 변경을 독립 단위로 나눴다. B36은 모델 영수증만 옮기며 Lean 인터페이스와 증거 자료는 다음 변경에 남긴다. 7ixeemgp에서 정상 응답에 control binding이 없는데도 출력과 final을 쓰는 실패를 확인했다. 실제 닫힌 ControlTransport에서는 닫힌 초기 delivery를 처리하지 못하고 owner_turn으로 들어가 thread-local turn AttributeError를 냈다. 직접 검사를 위한 후보 원 시험으로 먼저 확인했으며 import 오류를 제품 반례로 세지 않았다.

Answer는 호출별 mode, expected_receipt, returncode를 갖는다. 정상 bound 응답은 실제 결속과 accepted 최종 영수증을 요구한다. 음성 시험은 정확한 기대 영수증을 명시하며 provider의 실패 종료는 returncode=1로 따로 선언한다. standalone/None만 비제출 응답이고 결속 파일 존재에 따라 자동으로 일반 JSON 응답으로 바꾸지 않는다. native_final, Produced, SubmissionRejected 우회 경로는 제거했다. ModelDouble.output은 출력과 해당 Answer를 함께 반환하여 병렬 호출이 기대값을 공유하지 않는다.

FakeCLI의 송신과 영수증 검사는 공통 구현 하나다. scheduling/submission/live/기록 소비자들이 같은 finish를 사용하며 live 호출은 submission_turn에서 job_turn을, 기록 도우미는 receipt_received hook을 쓴다. 다른 모듈의 송신 사본을 없애면서 원 차례 전달과 제출 기록을 유지했다. 직접 입력을 관찰하는 engine_control도 bound/accepted 계약을 확인한 출력만 사용한다. 정상 기대값을 실제 실패값으로 느슨하게 바꾸지 않았다. 이미 검수한 후보의 음성 입력 기대값을 같은 시험에 명시했다.

## 호출부 이관 실패의 교정

첫 선택 편집은 read_bytes에서 얻은 CRLF와 후보 read_text의 LF를 그대로 비교하여 선택한 hunk가 실행되지 않았다. Windows write_text가 남은 CRLF의 줄끝도 중복했다. native_final import가 남아 실행 전 discovery가 거부됐고 실제 시험은 시작되지 않았다. 이 오류는 제품 실패가 아니다. intake 때 clean이었던 아홉 소비자 경로만 HEAD 원문에서 회복하고 LF로 정규화했다. 선택 전건의 적용 개수를 단언하도록 편집기를 고친 뒤 17개 helper/consumer/test 파일을 이관했다. 기존 cross_machine/cross_contracts와 다른 미커밋 수정은 덮어쓰거나 stage하지 않았다.

## 실제 worker와 소유자 검증

lnfsqrdd는 직접 계약·초기 진단·실제 제출 30개가 통과했다. qwp953sl의 병렬 작업·학술 준비·복구·live 호출·소유자 리뷰·제어 수송 관련 59개도 통과했다. 마지막 live pause 정산까지 같은 실행을 기다려 실제 terminal을 확인했고 다시 시작하지 않았다. 전체 299.3초는 해당 부분 선택의 시간이며 전체 T2 300초 성공으로 읽지 않는다. 최초 집합의 late-output sim 한 개가 2.500초로 개별 2초 예산을 넘었다.

후보 gvgf92eq의 직접 계약 5개와 main lchpv8wg의 층/시험 냄새 5개가 통과했다. 기존 냄새 검사 5.640초의 5초 초과는 남긴다. 관련 선택들의 통과 수는 합산하지 않는다. 보고 원문 경로·SHA256·실행 중 변경 없음과 문서를 포함한 18개 정본 파일 지문은 단계-전환표 current_work.model_contract_integration에 연결한다. 로컬 편집의 전후 지문과 선택 hunk는 finish/model-foundation-source.json과 model-foundation-plan.json에 남긴다.

모델 정상 영수증 기반은 강화했으나 1f의 61개 보존 지식 전건을 이 회귀로 대신하지 않는다. Lean의 표시 서명에서 선언 본문을 추정하는 경로, 실제 defaultfacts 보존과 모든 명시 등록 소비자, 형식 Git 의미 포트와 설치/작업자 소비자 이관이 다음이다. main 43개/후보 56개 및 미기록 13개를 전체 완료율로 세지 않는다. 원문 19/61/12/여섯 부류/11과 최종 동일 판본 T2/flows, 재사용 없는 T3·극단 변이·예산, 최소 T4/T5·말뭉치는 남긴다.
