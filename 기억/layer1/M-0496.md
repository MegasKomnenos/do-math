[[M-0495]]의 활동 대기 확정 뒤13-B의 과제 표시를 독립 변경으로 진행했다. 현재 reporting.task_status는 planning.task_ready가 준 구조화 waits를 버리고 required_input/errors로 다시 만들며 저장 task.waiting도 표시하지 않았다. 함수 이름과 문자열 목록의 존재가 실제 표시 일치를 뜻하지 않으므로 실제 생산자로 두 경로를 재현했다.

첫 재현은 owner_sim의 실제 승인 과제와 하루 기한의 grant에서 시작한다. 최초 준비성 ready를 확인하고 grant·과제·검토 기록을 수정하지 않은 채 시계만 마지막 만료 시각 뒤로 전진했다. snapshot_report의 실제 준비성은 permission, GR-research-sim, governance를 반환하지만 행 waits는 required_input으로 표시하여 실패했다(tmzv_huw). revoke는 검토 전제를 바꾸므로 이 재현의 사건으로 사용하지 않았다. 둘째는 실제 apply_task_assessments 생산자가 만든 reassessment_sim의 assessment_input, missing source new.txt, research_work와 EX-plan 근거다. 저장한 waiting 전문이 report waits의 빈 목록에서 사라져 실패했다(8j9g8s4q). 새 레코드를 손으로 끼워 넣어 정상 생산을 대신하지 않았다.

수리는 status projection에 한정한다. 종결하지 않은 인스턴스의 저장 과제 대기를 포함하고 실제 준비성이 구조화 대기를 제공하면 그 값을 사용한다. 구조화 대기가 없는 판단은 기존 계약 검토/일반 오류 표시를 유지한다. 사용자 대기를 우선하는 기존 정책은 보존하고 나머지는 실제 대기가 준 next_owner를 계약 검토 이름 추정보다 먼저 사용한다. 여러 대기의 전역 해소 우선순위를 새로 설계한 변경이 아니다.

준비성 및 중복 제거한 waits를 깊은 복사하여 조회 사본이 입력 runtime과 저장을 바꾸지 않도록 한다. 사람용 과제 행 뒤에는 실제 wait의 전체 종류·담당자·target_refs·basis_ref 등 좌표를 JSON으로 표시하고 준비성 오류도 보여 준다. 권한 만료 시험은 담당자와 grant 대상이 JSON/사람용에 나타나며 저장 상태가 불변임을 확인한다. 평가 대기 시험은 실제 저장 waiting과 사람용 좌표가 같고 보고 사본의 target_refs와 basis_ref를 바꾸어도 원 입력과 저장이 불변임을 확인한다. 이전 상태로의 복구·이벤트 처리·계수·새 대기 enum은 추가하지 않았다.

두 재현 교정 후2개가33.0초에 통과했다(o_g9eyjs). 마지막 같은 소스의 관련 검증은 구조47·단위10·Sim19·flows11·실제 Git 경계5, 합계92개가220.6초에 완결 통과했고 실행 중 변경은 없다. 공개 CLI 여정과 JSON/사람용 동일 스냅숏, 종결 인스턴스의 준비성 부재, 관찰 거부, 시간대/timeline 등 기존 소비 검사를 보존했다. 개별 예산 초과21개는 비교 정보다. 현재 인프로세스 역할/검토/배정 전체의 새 전건 통과 또는 fresh T3/변이 통과라고 하지 않는다.
