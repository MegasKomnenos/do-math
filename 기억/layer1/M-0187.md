사용자가 Codex를 재시작한 뒤 등록된 scholarly 도구에서 최신 OpenAlex 사용 안내를 확인했다. 이전 연결의 public_endpoint_search_observed 대신 그룹 검색·임의 범위·초록 복원이 포함된 현행 verification이 반환됐다. 새 SDK 프로세스에서만 검증됐던 기능과 실제 등록 연결의 갱신을 구별하던 미결 사항이 해소됐다.

재시작 전에 남긴 AMS·IOP 수정도 같은 단위로 검증했다. AMS는 고급검색 제어의 input_value 대기에서 TimeoutError가 났지만 원 응답은 66바이트 HTML의 The service is unavailable. 안내였다. 해당 실물 fixture를 보존하고 provider_unavailable로 분류한다. 401/403과 접근 확인 제목은 restricted로, 나머지 HTTP 오류는 검색 화면 오류로 구별한다. 검색 제어 전체가 준비됐는지 먼저 확인해 제어 하나의 시간 초과로 실제 원인을 가리지 않는다.

IOP의 이전 실제 MCP 기록 20260910T112043832340Z-iop-workflow.json은 서지·초록을 확보했지만 PDF와 두 인용문 요청이 validate.perfdrive.com으로 이동했다. 기존 코드의 source_boundary를 알려진 접근 확인 목적지에 한해 restricted/publisher_access_challenge로 바꿨다. 이 호스트를 다운로드 허용 목록에 추가하지 않으며 리디렉션 요청을 따라가기 전에 반환한다. 합성 서명 값으로 후속 요청 부재와 진단 비노출을 검사했다.

공통 검사 173개가 통과했다. 재시작 뒤 등록된 연결의 실제 AMS 검색은 publisher_access_challenge였고 IOP는 publisher_redirect 단계의 같은 제한이었다. 따라서 이번 호출이 새로운 서비스 불가·파일 리디렉션 분기까지 실서비스로 통과했다고 주장하지 않는다. 현재 연결의 요약 보고는 services/scholarly-mcp/data/validation/20260910T122338Z-registered-restart.json다. 실패한 워크플로는 completed=false이며 연결 갱신 검사만 통과다.

기존 Codex 설정·루트 gitattributes와 연구 산출물의 사용자 변경은 보존했다. 전체 구현은 아직 진행 중이며 푸시하지 않는다. 다음 작업은 남은 출판사 검색·원 형식·첨부의 접근 가능한 실물 경로를 확인하고 연결하는 것이다. 이미 반복된 접근 제한은 문헌 부재로 해석하지 않는다.
