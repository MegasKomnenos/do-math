[[M-0498]] 뒤6-A의 다음 실제 시간 판단을 연결했다. 현재 실행기는 작업 역할5개에는 호출 기한을 두지 않고, 준비·계획·운영 점검·초기 해석·유지보수·복구에는 선택한 프로필 창을 사용한다. Recovery의 창은 실제 프로필 생산자가 operator_timeout_seconds로 고정한다. 전역 run 상한·Lean의 경과 종료·시험 timeout은 이 계약과 다르므로 새로 넣지 않는다.

execution_window.AI_CALL_TIME_RULES는 모델 정책이 정의한 현재 AI11역할을 순회해 WORK_ROLES는 기한 없음, 나머지는 고정 config의 call_timeout_seconds라는 실제 계산 원천을 선언한다. call_deadline과 deadline_passed는 실제 _prepare_call의 입력 게시 직후 기한 계산과 _call_stop_requested의 만료 판단에서 사용된다. 첫 입력 준비나 실제 시작 anchor를 바꾼 것이 아니라 기존 식을 같은 정본으로 추출했다. publish·finish-request의 형식과 notice 비회수 의미도 유지한다.

일반 시험은 실제 build_profiles 생산자가 만든33개 AI프로필에서 역할·등급과 게시 elapsed0/0.125/전체기간의99장면을 순회한다. 각 장면은 None 또는 정확한 기한, 정수 밀리초의 남은 기간, 저장된 execution-window와 출력 동일성, 만료 직전·동일·직후 세 비교, notice 경계의 첫 게시·중복 없음·revokes_authority=false를 확인한다. 프로필을 만든 뒤 authoring config의 창 설정을1로 바꾸어도 고정 profile의600/5400초를 그대로 사용한다. 연구·Lean 기한 없음 중 이번 AI범위의 작업5역할은 duration 설정 없는 입력에서도 기한 clock을 읽지 않고 deadline None의 비교도 clock을 읽지 않는다. 머신 실행은 이 AI역할 표에 넣지 않고 자기 계약으로 남긴다.

개별 기존 execution-window 시험의 소수 ms와 비회수·무기한 경과 시험은 유지했다. 처음 관련 선택에서 존재하지 않는 unit.test_execution_profiles를 지정해 실행 전 거부됐으며 실제 디스크의 profile_selection/close_profile_guards 모듈로 수정했다. 제품 실패나 timer 검출로 세지 않는다. 마지막 같은 소스의 구조47·단위29·Sim46, 합계122개가126.8초에 완결 통과하고 소스 변경은 없다. 실제 call-stop, engine queued input, 고정 profile runner, 제출/늦은 산출, 권한·lease 정지 경로도 포함된다. 개별 예산 초과40개는 소프트 비교 정보다. 원보고 SHA256은 5322a4686a42309919f240a62e5d4e519c6290e7eeea10364d0c72185a4bd7ce다.

추적 근거는 검증/2026-10-04-AI-호출-시간-규칙/report.json이다. 처음 focused5개 통과0.8초와 Temp 출력은 로컬 보관이며 정리 시 사라질 수 있다. 이 변경은 실제 AI역할 창 계산을 정본과 일반 검사에 연결한 것이며6-A 전체의 checkpoint 유예·임대·시작 전 생산/국면·전 시간 규칙 부류,19/61/11/P2원래12 및 최종 동일 판본 관문은 완료하지 않았다. Product 설정·프로필 window의 기존 역할별 뜻을 바꾸거나 예산을 hard guard로 해석하지 않는다.
