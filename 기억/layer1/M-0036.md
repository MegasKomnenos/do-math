# 검증런 2.7.9.3 0단계 기준선 확립 — 심사집계 기각 보관 순서 수리를 대행 커밋

## 맥락

행 `2.7.9.2`(작업자 파견, `codex-full`)가 `.claude/skills/verify-rounds/scripts/vr.py`의 `cmd_심사집계`를 고쳤다. 고침 전에는 `_심사집계.json`을 기각 보관 파일보다 먼저 썼다. 기각 보관 디렉터리 생성이나 파일 쓰기가 `OSError`로 실패해도 `_심사집계.json`은 이미 존재하는 상태로 남았다 — 실패한 집계를 장부 갱신·적용 단계가 정상 집계로 소비할 수 있는 결함이었다(기각 보관 `2.7.6-라운드1.md` `R1-01`이 이미 지목했으나, 조각 셋 중 시험·문서 조각이 관문 5·4에서 기각되어 라운드 1에서는 반영되지 않았다). 행 `2.7.9.2`는 산출 순서를 「기각 보관 성공 → `_심사집계.json` 쓰기」로 뒤집고, `test_심사집계.py`에 실패 주입 시험 3건(성공 순서, 디렉터리 생성 실패, 파일 쓰기 실패)을 더해 닫힌 시험 수를 17로 갱신했다. 이 작업은 `2-보고.md`(`C:\math\.sdd\dag\pvsnp-탐사-1\행\2.d\7.d\9.d\2-보고.md`)에 RED·GREEN과 시험 전건 통과(17개 파일)로 기록됐다.

행 `2.7.9.2`는 이 변경을 worktree(`C:\Users\wogud\AppData\Local\dag-wt\pvsnp-탐사-1+2.7`)에 남긴 채 커밋하지 않았다 — `계약/검증런.md`의 "제품 수리는 worktree에 남고 그 노드의 싱크가 커밋한다" 조항대로다. 다음 행 `2.7.9.3`은 이 수리를 독립 검증하는 verify-rounds 런이고, `SKILL.md` 0단계 7·8항은 라운드 1 시작 전 git 색인과 동결문 「산출물」 절 경로의 git 상태가 깨끗해야 함을 요구한다. 이 저장소의 do-dag 운영 관례(이 저장소 git 로그에 "검증런 X 0단계 기준선 확립을 위해 ... 대행 커밋한다" 패턴의 선례 다수)에 따라, 검증런 직전에 앞선 작업 행이 남긴 미커밋 변경을 대행 커밋해 0단계 기준선을 세운다. 이 커밋이 그 역할이다 — `verify-rounds` 절차 자체가 아니라 그 절차를 여는 행이 사전에 실행하는 baseline 확립이다.

## 터득한 것

do-dag 프레임워크에서 "작업자 행이 worktree에 미커밋 산출을 남긴다 → 다음 검증런 행이 그 산출을 대행 커밋해 0단계 기준선을 세운다"는 패턴은 문서(SKILL.md·계약)에 명시된 절차가 아니라 git 로그의 반복 선례로만 확인되는 운영 관례다. `계약/검증런.md`의 "커밋하지 않는다" 조항은 verify-rounds *내부* 절차(라운드 커밋 등)에 거는 금지이지, 그 절차를 여는 행이 0단계 전제조건을 갖추기 위해 실행하는 대행 커밋에는 걸리지 않는다 — 이 구분이 문서화되어 있지 않아 실측(git log 검색)으로 확인해야 했다.

## 작업 너머 시사점

`계약/검증런.md`에 이 대행 커밋 관례를 명문화하면(예: "0단계 시작 전 산출물 경로가 dirty하면, 그 행이 대행 커밋 절차로 기준선을 세운다"), 다음 검증런 행이 git 로그 고고학 없이 바로 이 절차를 알 수 있다. dream에서 묶을 후보: 이 저장소의 "관례가 코드·계약이 아니라 로그 선례로만 존재한다"는 패턴이 do-dag 계열 다른 관례(예: 노드 싱크의 병합 순서)에도 있는지.
