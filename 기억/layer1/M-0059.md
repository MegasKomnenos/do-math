## 맥락

전면 검증 네 번째 라운드는 수리 후보 7건을 만들었고, 세 심사자가 전건을 만장일치 승인해 모두 적용했다. 세 산출물의 문서 구조와 JSON 예시는 적용 뒤 다시 기계 검사를 통과했다.

## 터득한 것

통합 설계의 정본 우선순위에서 현재 외부 대화를 평시 정본처럼 직접 우선하던 문면을 고쳤다. 외부 사용자의 새 지시는 변화 사건을 열고, 그 의미가 내부 사용자 결정·헌장·정책·맥락·설정의 새 판본으로 수입돼 영향과 승인을 처리한 뒤에만 효력이 생긴다.

작업 착수 명세 검토에서는 충분한 입력을 읽고도 씨앗 문면만으로 판단할 수 없는 `not_assessable`과 입력·검사를 읽거나 끝내지 못한 `incomplete` 실행을 분리했다. 관찰 의무와 작업 자기 점검의 공통 한국어 의미와 JSON 직렬값을 직접 대응했고, 지도 컨텍스트에도 응답 한계·위반·새 관찰 세대 활성화와 낡은 관찰 처분을 복원했다.

발견 후보는 작업별 작업대 안에서는 공용 현재 상태가 아닌 F 객체이며, 공용 편입 뒤에만 안정된 핵심 기록 ID를 가진 공용 F 핵심 기록 객체가 된다는 경계를 명시했다. 전례 자동 적용은 형식 필터가 읽은 효력 ref OID 전건과 기준 run OID를 봉인하고 적용 직전 다시 검사하며, 바뀌면 낡은 판정으로 보존한 뒤 전 과정을 다시 수행한다.

목표·추가 감사 계약은 적용 대상, 헌장·입력, 닫힌 판정 어휘, 목표 허용값과 Lean 편입 차단값을 닫는다. 감사 실행은 `AU-<ULID>` 기록에 계약·입력·판정·효과와 출력 좌표를 봉인하고, 현재성 불일치에는 다시 실행한다. 목표 차이 자체가 Lean 정본 편입을 막지 않는 기존 경계도 유지했다.
