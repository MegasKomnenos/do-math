title: IEEE 그래픽 초록 동영상을 검증된 바이트 구간으로 회수함

---

IEEE 문헌의 그래픽 초록과 표지 파일을 회수하고, 일반 요청이 시간 초과로 끝난 104,143,825바이트 MP4를 HTTP byte range로 끝까지 받았다. 실제 MCP에서 25개 구간의 파일 조립·표지 이미지·참고문헌과 첨부 없는 표본을 검증했다. 전체 공통 검사 142개가 통과했다. 다른 자료원의 남은 구현은 계속 진행한다.

기존 문헌 10488889와 알려진 문헌 7780459에는 Media 탭이 없었다. 부가자료가 있는 표본을 찾기 위해 IEEE의 공식 동영상 수상 문헌 11259066을 선택했다. 이 문헌도 sections.multimedia=false지만 graphicalAbstract에는 video·file·coverImage·summary·표시 크기가 있었다. 따라서 Media 탭 상태 하나를 전체 부가 파일의 부재로 사용하지 않는다. 문헌 초기 메타데이터의 JSON을 읽고 articleNumber를 대조하며, 사용자·운영 정보는 제외한 원 문헌/미디어 필드만 보존한다.

표지 JPEG는 36,328바이트로 회수됐지만 99.32MB로 표시된 MP4는 일반 다운로드의 45초와 시험한 180초 제한에서 모두 시간 초과였다. 시간만 계속 늘리는 방식을 중단하고 실제 부분 요청을 확인했다. 65,536바이트 요청은 HTTP 206과 전체 크기 104143825를 반환했다. 이 관측을 바탕으로 MP4를 4MiB 구간으로 회수한다. 각 응답의 위치·길이·전체 크기·URL과 validator를 대조하며, 중간에 바뀌면 완성 파일로 보존하지 않는다.

원 응답에 ETag는 없고 Last-Modified가 있었다. RFC 9110의 Date/Last-Modified 강한 검증자 조건을 확인했고, 충분한 시간 차이를 요구하는 보수적인 60초 기준을 적용했다. 강한 ETag가 있으면 우선 사용하고 weak ETag는 사용하지 않는다. 다음 구간 요청의 If-Range와 응답의 validator가 일치해야 한다. 공통 browser_download의 45초 제한은 유지하고 선별된 응답 상태·range·validator 메타데이터 전달만 추가했다. 별도 새 전송 경로나 계정은 도입하지 않았다.

최종 실제 MCP는 문헌 11259066의 참고문헌 30건·표지·동영상과 기존 문헌 10488889의 참고문헌 22건·첨부 not_found를 통과했다. 참고문헌과 첨부 회수는 각각 실패를 보존하므로 한쪽의 실패로 다른 성공 자료를 잃지 않는다. 처음 180초 시험의 partial 보고는 미완료로 남겼다. 정확한 보고 파일은 VALIDATION.md가 소유한다. 동영상 내용을 분석하지 않았고 일반 Media 탭의 다른 첨부는 아직 구현하지 않았다.

작업 중 PQDT 문헌 2485541561의 Supplemental files 탭에서 PNG 한 개와 native 다운로드 제어를 확인했다. 이 제어가 서명된 미디어 URL을 경로 인자로 포함해 진단에 노출된 문제는 독립적인 M-0177/13c8841에서 먼저 수정했다. 새 진단은 임의 다운로드 path를 출력하지 않는다. 다음 작업은 이 PQDT 원 제어를 사용한 파일 회수·이미지 추출이다. 전체 완료 전이므로 푸시하지 않는다.
