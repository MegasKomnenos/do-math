[[M-0540]]의 B123 worker 미완결을 진단 가능하게 하는 한정 수리다. 새 작업자 생성은 thread limit으로 거부돼, 해당 실패를 방금 읽기 전용으로 분석한 작업자에게 같은 문제의 최소 수리만 이어 맡겼다. 전체 작업 이력을 다시 상속하거나 새 조사 범위를 열지 않았다.

run_tests._worker는 stderr 리디렉션 내부에서 _run_suite 전체를 try/except Exception으로 감싼다. 예외의 traceback을 같은 stderr 파일에 출력하고 flush한 뒤 bare raise로 원래 예외를 그대로 전파한다. stopTest의 중간 결과 게시뿐 아니라 _run_suite의 최종 preserve/write도 이 범위다. 보고 실패를 성공으로 바꾸거나 자동 재시도·시간 종료·새 오류 처리 틀을 추가하지 않았다. 제품 file_io는 변경하지 않았다.

기존 runner 회귀 시험에서 synthetic 성공 시험의 stopTest 결과 게시 때만 runner의 _write_json에 OSError를 주입했다. 수정 전에는 보존 stderr에 traceback이 없어 정확히1개가 실패했다. 수정 후에는 같은 예외 객체의 전파, 기존 result의 complete=false/successful=false/running 유지, 다음 progress 부재, stderr의 성공 줄·traceback·경로·stopTest frame이 확인됐다. 정상 시험은 exit0/complete=true, 일반 assertion 실패는 exit1/complete=true인 기존 계약도 별도 단언했다. runner_regressions18개가8.9초에 통과했고 두 실행 모두 소스 변경이 없다. 원보고는 검증/2026-10-05-worker-예외보존에 바이트 그대로 보존했다.

이 실패 주입은 원 B123의 Windows 오류를 재현하거나 특정한 것이 아니다. 당시 정확한 오류는 여전히 미확정이고 B123의558개 미실행도 그대로다. root의 진행 관찰은 앞으로 제품 read_bytes_shared의 삭제 공유 읽기를 쓴다. 실행 결과를 Path.read_text로 열어 원자 교체를 방해할 가능성을 줄이며, 이 가능성을 실제 원인으로 확정하지 않는다. 로컬 관찰 스크립트 .skill-workspace/test-restructure-2026-09-29/finish/observe-test-run.py는 Git 미추적 실행 보조 자료이고 제품 프레임워크가 아니다.

B123 미실행558개는86개 모듈에 있다. 공식 runner에 그 모듈들을 주면 같은 모듈의 앞선13개가 더해져571개를 검증한다. 전체 ID와 모듈 대응을 추출해 누락 없음을 확인했다. B126은 이571개의 고정 소스 실행이며, 기존3424통과와 합쳐 새 전체 일반 통과라고 부르지 않는다. 실행 전후 소스 지문과 선택 ID·완결·성공·미실행을 확인하고, 그 뒤 현재 판본 전체 일반 정상 결과가 필요하다. 원래 나머지 요구·fresh T3·극단 변이·실환경 관문도 유지한다. 이 커밋 시점 B126은 준비 완료·아직 시작 전이다.
