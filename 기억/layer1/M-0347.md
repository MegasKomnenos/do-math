## 맥락

사용자는 do-math 전체를 한 라운드 검증하되 Claude Opus 5.5 수리자 8명과 GPT-6-astra 심사자를 지정했다. 4개 관점이 지나치게 넓은 범위를 읽는 문제를 줄이고, graphify로 영향 범위를 확인하며, 발견한 일부 문제에서 탐색을 멈추지 않도록 요구했다. 불필요한 호환 요소·죽은 인자, 생산자와 소비자의 계약 불일치, 목적 위반, 최근 수리의 미완결과 영향 누락, DRY와 반복 검증·상태 복사·파일·Git 비용이 검토 기준이었다. [[M-0346]]의 실제 초기화 실패와 공통 경계 수리를 현재 코드의 결함이라고 가정하지 않고 탐색 사례로 제공했다.

4개 영역은 253파일·79,475행을 비중첩 분담했고, 4개 관점은 지정된 필수 파일에서 시작해 다른 영역의 생산자·소비자로 연결을 추적했다. 각 관점이 전체 파일을 통독한 것은 아니다. 8명 모두 담당 범위의 독해 기록을 냈고 graphify 명령과 실제 사용 모델을 확인했다. Claude Agent 도구가 없는 실행 환경에서는 같은 모델·노력을 명시한 Claude CLI를 사용했다. 심사는 두 배치마다 독립 컨텍스트 3개와 정족 3을 유지했다.

## 원 판정과 후속 처리의 구별

수리자가 제기한 원 항목은 69개이고, 겹치는 24개를 12개 묶음으로 합쳐 심사 대상은 57개였다. 원 심사는 수리 40개·무처분 9개·기각 8개다. 사용자 위임으로 무처분 9개와 의존 삽입의 좌표 규약으로 기각된 1개를 추가 적용했다. 공식 적용은 심사 대상 50개·조각 192개·원 항목 62행이다. 기각된 5개는 직접 수리·개선하고 2개는 유지했다. 중복 발견과 병합이 있으므로 원 항목 수를 서로 다른 결함 수로 읽지 않는다. 원 판정을 승인으로 고쳐 쓰지 않았다.

동작이 같다는 이유로 무처분된 공통화와 죽은 인자 정리는 이번 사용자의 명시적 목적에 해당했다. 반면 지적 자체의 전제가 틀린 경우에는 삭제하지 않았다. `archive` 시험은 `test_group`을 `category`라는 이름으로 가져온 데코레이터에 실제로 존재했다. 제품 기본 설정과 다른 두 probe에도 서로 다른 취소 시점과 어댑터 진단 범위가 있었다. 기본 실행과 다른 설정이라는 사실만으로 죽은 코드라고 판단할 수 없었다.

기각된 수리안에서는 결함과 수리의 완결성을 나눠 확인했다. 권한 검사 중복을 없애는 안은 허가 후보가 없을 때 잘못된 시각의 검사를 생략했다. 진입에서 시각을 검사한 뒤 공통 내부 검사에 전달하도록 고쳤다. 지식 종류의 `check-kind`·`activate-kind` 연산을 삭제하는 안은 남은 처리기로 흘러가 검토·조사를 변경한 후 거절될 수 있었다. 공개 입력 스키마와 내부 처리의 변경 전 경계에서 지원 연산을 검사했다. 공통 CLI 어댑터의 별칭 제거에는 수리자가 놓친 probe 소비자도 함께 바꿨다.

재심사는 기존 Python 제어 API와 적격 근거 수신자가 있었으나 CLI의 파일 입력이 연결되지 않았다. 정확한 원 판정 해시와 근거를 받는 요청 형식을 기존 수신자에 연결했다. 적격 근거 수신 때 사용 정지와 유한 재심사가 열리고 같은 근거는 기존 순환을 재사용한다. 일반 제보만으로 판정 효력을 바꾸지 않는다. 전 상태를 매번 탐색하는 별도 자동 검색기를 추가한 것은 아니다.

## 공통화와 검증의 범위

부모 스냅샷은 내부 비교에서 재사용하고 공개 조회는 분리된 값을 반환하도록 복사 위치를 정리했다. 이미 검증한 부모의 동일 증거 참조·해시·길이는 재사용하되 새 증거·변경된 해시와 길이·이번 공급 바이트는 다시 검사한다. 입력 목록의 중복 생성, 참조별 전체 색인 재구성, 이미 복사한 검토 순환과 영향 계획의 재계산도 줄였다. 이 변경들은 전체 실행 시간이나 모델 비용의 배율을 측정한 결과가 아니다.

공리 집합의 생산자 둘을 정리한 뒤에도 초기화·기본 설정·형식 검사와 시험에 같은 정의가 남아 있었다. 영향 대조를 넓혀 하나의 정본과 그 파생 표현을 쓰도록 정렬했다. 형식 검증 시험의 수작업 승인 정보는 현행 `verifier_path`가 없어 실행 전 거부를 일으켰고, 변경 전 사본에서도 같은 실패가 재현됐다. 시험도 실제 `inspect_toolchain` 생산자를 사용하도록 고쳐 제품의 신뢰 검사를 유지했다. 별도의 단위 실패는 새 공통 메서드를 제공하지 않은 시험 대역의 문제였으며 실제 메서드를 연결해 수정했다.

긴 학술 통합 묶음은 대표 시나리오의 통과를 관측한 뒤 반복되는 수학 증명 초기화의 비용을 확인하여 검사 범위를 계약 경계 중심으로 조정했다. 중단된 묶음은 미완료로 보존하며, 전체 통합 스위트나 실제 모델 수학 연구의 통과로 보고하지 않는다. 후속 수리는 고정 사본에서 검사한 뒤 원본과 바이트를 대조했다. 최종 고유 시험 계수와 판본 근거는 종료 보고와 검증결과 JSON이 소유한다.

## 보존 좌표

추적되는 진입점은 `임시/do-math_검증_20260925_opus/종료보고.md`, `장부.md`, `직접처리.json`, `검증결과.json`이다. 원 수리·병합·심사 산출과 공식 중간물은 같은 폴더의 `검토근거.zip` 및 SHA-256 목록으로 보존한다. 기각·무처분 원문은 `기각보관/do-math-opus-20260925-라운드1.md`에 남긴다. 상세 CLI 로그·시험 작업 폴더·독해 실행 자료와 graphify 그래프는 Git 제외 로컬 보관이며 정리로 사라질 수 있다. 검증 대상 밖의 원 연구는 재개하지 않았다.

후속 기억 종합 절차인 dream에서 묶을 후보는 공통화의 세 경계다. 이 절차의 정본은 `.agents/skills/dream-harness/SKILL.md`다. 같은 규칙을 합치는 것, 입력 경계가 모든 경로에서 검사를 수행하는 것, 시험이 실제 생산자의 계약을 사용하는 것은 각각 확인해야 한다. 한 함수를 공유한다는 사실만으로 나머지 두 조건까지 성립하지 않는다.
