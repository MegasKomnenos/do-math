사용자는 작은 주차 함수 연구의 피드백 뒤 추가한 do-math 기능과 계약을 대화 로그·기억의 확정 사항에 대조하도록 verify-rounds를 요청했다. mixed, 심사 gpt-6-astra medium, 1라운드가 지정됐다. [[M-0295]]의 계약·학술자료·독립 운영, [[M-0296]]·[[M-0297]]의 모델별 세션 예산과 후속 기본값, [[M-0298]]의 제출 검사·현재성·실패 복구를 함께 추적했다. 원문 발췌와 검증 기록은 `임시/do-math_결정대조_검증_20260916/`에 보존한다. 기존 연구 인스턴스와 예약 작업은 이 작업에서 재개하거나 변경하지 않았다.

## 검토 범위와 실행 경로

수리의 기준선은 정본 105파일·22,456행이었다. 세 영역 담당과 전건 관점 담당이 처음에는 일부 파일만 읽고 종료했다. 같은 파견문으로 한 차례 재파견해도 미독해를 남겼다. 사용자는 네 수리자 모두에게 모든 파일을 반드시 읽도록 아주 명확히 지시하라고 정했다. 같은 컨텍스트에서 담당 파일·행 수·사본 좌표를 전건 지급하고, 검색·diff·부분 발췌 대체 금지, 잘린 출력 회수, 파일별 실제 독해 표와 미독해 0의 완료 조건을 명시했다. 보충 뒤 문서·스키마·진입점 담당은 26파일, 실행기 담당은 35파일, 회귀·검증 담당은 44파일, 전체 관점 담당은 105파일을 읽었다고 기록했다. 파일별 표는 사본과 일치했고, 보충 도구 호출 기록도 보존했다. 일부 보고의 합계 산술은 틀렸으므로 집계 수치는 사본의 실측을 썼다. 표와 호출 기록은 독해 범위의 근거이며 이해의 완전성을 자동 증명하지 않는다.

결함 발견과 수리안 작성에는 Claude opus를 추론 노력 high로 사용하고, 겹치는 수리안의 병합에는 같은 모델을 low로 사용했다. Claude Agent 도구가 없어 사용자가 승인한 로컬 Claude CLI로 실행했다. 이후 심사를 맡긴 Codex CLI 세 기는 사용량 한도로 판정 파일 없이 종료했다. 검증을 운영하는 주 에이전트는 같은 gpt-6-astra medium 모델의 독립 에이전트 세 컨텍스트로 실행 수단을 바꾸고 파견문과 산출 계약, 심사자 3명 전원이 승인해야 수리하는 정족을 유지했다. 최종 심사 12항목의 전건 판정과 서식 검산을 마쳤다.

이 심사에 앞서 별도로 정정한 사항도 있다. 목적·대상·검사 명령을 고정하는 `동결.md`에 주 에이전트가 파일별 직접 실행과 존재하지 않는 설치 검사 명령을 잘못 적었다. 현행 README의 unittest discovery와 probe_codex.py --skill-only로 고친 뒤, 같은 1라운드의 수리를 처음부터 다시 수행했다. 이 초기 정정과 이후 실행 수단 변경은 장부의 별개 기록이다.

13개 제기 항목 중 둘을 병합해 심사 대상은 12개였다. 7개 수리안을 만장일치로 확정해 공식 스크립트로 적용했고, 4개 심사 항목은 정족 미달로 기각됐다. 한 항목은 미평가 과제의 모델 정책 불일치로 사용자에게 올렸다. 역할 계약에 공통 제출 검사를 되풀이하지 않았다는 지적은, 이미 전 역할에 공통 문서가 지급되고 의무가 명시돼 있어 기각됐다. 역할 계약이 공통 절차 일부를 나열한 문장을 닫힌 적용 목록으로 읽어, 이미 전달된 다른 공통 의무가 없다고 판단하지 않아야 한다.

## 사용자가 확정한 평가 경로

미평가 계약 검토를 중·상 등급 중 어느 것으로 시작할지 물었으나, 사용자는 미평가가 발생하는 경우를 먼저 확인했다. 코드에는 일반·개정 후보의 평가 누락을 수신자가 허용하는 경로와, 사용자 학술 요구에서 과제를 만들고 평가 없이 계약 검토를 요청하는 경로가 있었다. 사용자는 후보별 평가가 정확히 하나씩 있는지 생산자와 수신자가 확인하는 일을 우선시했다. 이어 자동 학술 과제도 기존 후보 준비가 평가를 보충한 뒤 독립 계약 검토로 보내는 방안을 승인했다. 현재 코드에 맞춰 문서를 좁히는 제안은 이 결정으로 대체됐다.

세션 예산의 일반 후보 준비와 연구 계획은 대상 전건의 평가를 같은 검사 함수로 대조한다. 누락·중복·대상 밖 평가를 구별하고, 개정 후보도 새 평가를 제출한다. 평가 없는 기존 과제에는 `action.assessment_targets`로 판본을 고정한 후보 준비를 요청한다. 평가 보충 모드의 후보 준비는 `candidates`를 비운다. 작업 공간의 `activity-extensions.json` 파일에는 `model_assessments`의 평가와 `model_assessment_deferrals`의 입력 부족 보류만 허용하며, 두 배열을 합쳐 지정 과제 전건을 정확히 한 번씩 처리한다. 사용자 학술 요구·계약 본문·완료 기준을 바꾸지 않는다. 정상 평가는 해당 과제에 결합한 뒤 새 계약 해시로 독립 검토를 받으며, 보충 실행 자체는 후보 생성 회차로 세지 않는다. 실행횟수 방식의 기존 인스턴스는 작업·운영 호출 한도와 역할별 모델 설정을 유지한다. 새 평가 필수 검사와 평가 보충은 세션 예산 방식에 적용한다.

일반 후보 생성 요청과 평가 보충 요청은 같은 research_preparation 역할을 쓴다. 실행기가 요청을 합치거나 실패의 해소 여부를 판단할 때 두 요청의 대상 판본 집합을 구별하지 않으면, 별개 요청을 잃거나 실패를 잘못 해결 처리할 수 있었다. 요청 비교에 대상 판본 집합을 포함해 두 경로를 분리했다. 입력 부족은 같은 조건에서 재생성하지 않고 보존하며 입력 변경이나 명시적 재개로 이어진다. 원자료가 있는 보류 기록의 저장 형식도 실제 JSON 저장 경계로 검사해 수정했다. 새 필드를 만드는 일과 큐·보류·복구·재개가 그 필드를 정확히 구별하는 일은 별도 검증 대상이었다.

## 검증과 남은 범위

새 흐름은 먼저 실패를 재현한 뒤 수정했다. 집중 검사 18건은 제출된 검사 명령, 대상 완전성, 계약 변경 금지, 판본 변경 뒤 늦은 응답 보존, 보류·재개, 실제 학술 과제 생성과 세션 전환, 실제 임시 Git을 사용하는 인계를 포함한다. 모델 응답은 대역이므로 실제 모델의 평가 품질이나 장기 연구 성능을 검증했다고 주장하지 않는다. 주 에이전트는 문서와 필수 참조를 별도 독해 AI에게 제공했다. 독해 AI는 일반 후보 준비·평가 보충·연구 계획의 세 사용 상황에서 이해한 내용을 반환했고, 주 에이전트는 그 이해를 확정된 요구와 대조했다. 전체 회귀에서 기존 수명 관리 시험의 대역이 새 평가 준비 호출을 제공하지 않아 오류가 났다. 그 대역에 실제 SchedulerMixin을 연결하고 기존 실행횟수 모드를 명시했으며, 이를 사용하는 수명·호환·검토·상태 검사 전건을 다시 실행했다. 큰 보고서 인계 시험의 대역도 필수 후보·선택 평가를 반환하도록 맞추고 기존 보존 단언을 유지했다. 전체 회귀는 검사 판본의 scripts/tests/test_*.py 전건을 unittest discovery로 실행한다. 같은 런의 검증/final2-source-manifest.json에 최종 파일별 해시를, 검증/final2.log에 최종 판정과 미실행 사유를, 종료보고.md에 집계와 한계를 기록한다. 초기 고정 사본에서는 Lean의 저장소 상대 탐색이 성립하지 않아 설치 경로를 명시한 별도 검사도 수행했다.

후속 회귀에서는 접수 벽시각이 완전히 같을 때 요청 ID의 임의 순서로 대화 세션의 연결·해제가 뒤집히는 경우도 재현했다. 제어 요청에 접수 순서 값을 보존해 같은 시각의 순서를 가른다. 이번 Windows 환경에서는 time.monotonic_ns도 15.625ms 분해능으로 같은 값을 반환했으므로, 0.1μs 분해능으로 확인된 time.perf_counter_ns를 사용했다. 접수 순서 값은 JSON 정수 한도를 넘지 않도록 고정 폭 십진 문자열로 저장한다. 날짜·시각의 선후와 같은 시각 안의 순서를 구별한 수리이며, 이전 기록에 없는 순서를 만들어 붙이지 않는다.

R1-05는 실행기가 --watch로 자원이나 후속 입력을 기다릴 때 새 사건 없이 반복하는 대기 순회에서도 상태 커밋을 계속 만드는 문제다. 이 동작은 확인됐지만 수리안이 기각되어 남았으며 실제 저장 비용은 계측하지 않았다. 제안이 head와 status만 비교해 저장을 생략하면, 같은 순회에서 생긴 실제 사건과 큐 변경도 저장되지 않을 수 있기 때문이다. 기각을 결함 부재나 해결로 보고하지 않는다. 1라운드 상한을 유지하며 이 잔여와 기각 근거를 보존한다.

작업 기억을 종합하는 dream 절차에서 함께 검토할 후보는 [[M-0296]]·[[M-0298]]이다. 미평가의 기본값을 고르기 전에 누락의 생성 경로와 필수 여부를 확인하면, 예외의 등급 선택 대신 평가를 보충하는 공통 경로로 문제를 해소할 수 있다. 또한 검토 범위의 목록·실측은 결함 타당성의 근거와 분리해 관리해야 한다.
