[[M-0525]] 뒤 B104의 lifecycle 호출28곳을 현재 원문에서 확인하고 동적 kind를 펼쳤다. 외부 실행 결과는 confirmed/failed/unknown/cancelled뿐 아니라 자격정보 부재의 prepared도 반환한다. prepared는 제어의 준비 사건과 결과 사건 양쪽에서 발생하므로 원천-kind 조합35개와 고유 종류34개를 구별했다. knowledge의 invalidate/revise, conversation의 attach/heartbeat/detach도 펼쳤다. 기존 작업판 B109의15개 증거 그룹에 원천별 발동/비발동 조건과 실제 검사 ID를 연결했고, 모든 이름이 현재 AST의 실제 시험으로 해소됨을 확인했다. 단순 ID 존재를 동작 검증으로 대신하지 않고 아래 실행을 함께 수행했다.

외부 사건 검사는 기존 external_sim과 공개 prepare/reconcile/retry, 실제 기계 실행, HTTP·Git 포트 대역을 사용한다. 처음에는 unknown 효과를 운영 점검 retry로 재진입시키려 했지만 실제 일반 복구는 외부 효과 대조를 먼저 요구한다. 그 실패는 제품 결함이 아니며 소스의 거부 규칙을 확인했다. 전송 중 중단 역시 로컬 종료가 불명확한 기록을 남겨 곧바로 새 실행을 시작할 수 없었다. 최종 복구 장면은 결과와 종료가 실제 저장된 직후 Git update_ref 포트에서 owner 소실을 발생시킨다. 재시작은 HTTP를 재전송하지 않고 reconciliation_required로 진행한다. 이후 공개 효과 부재 대조와 허가된 재시도만 두 번째 전송을 한다. 과거 상태를 직접 되돌리거나 제품 저장 메서드를 패치하지 않았다.

외부 결과 다섯 종류, 준비/대조/재시도, 복구 대조 필요, 최종 권한 검사 거부의 사건이 각각 실제 수락 계획에 한 번 포함됨을 확인했다. 여러 사건이 한 계획에 모일 수 있다. paused에서는 계획0이며 resume 뒤 전달한다. unknown에 증거 없는 retry는 반려되고 사건을 바꾸지 않는다. 동일 작업 prepare 재전달도 새 사건을 만들지 않는다. failed 사례의 effect_absent는 포트가 명시적으로 제공하는 정보이며 일반 non-2xx를 효과 부재로 간주하지 않는다. 자격정보가 없거나 전송 전 취소/권한 만료이면 HTTP 호출0이다.

신뢰 전환의 기존 성공·실패·중지/재개 흐름에 관련 사건 전건의 실제 수락을 연결했다. 메타데이터만 다시 기록한 trust_environment_rebound는 pending/실제 호출 원인으로 쓰지 않음을 확인한다. 신뢰 환경 철회는 계획1과 공개 제어 replay0이다. 형식 계속 실행의 기존 검사에서는 새 환경 등록/전환 시작/활성화 사건 세 개가 실제 계획의 event_refs에 들어감을 확인했다. 기존 지식 변경의 긴 흐름에서는 terminal 평가 무효화 사건도 실제 계획에 한 번 포함되고 수락됨을 확인했다. 미확립 목표 감사 묶음은 judgment_ids를 가진 계획1을 열며, 미완료 묶음과 실제 전체 목표 완료는 추가 계획/역할0이다. 대화 attach/heartbeat/detach/lost와 submission_checked는 실제 관찰에서도 계획/운영 점검을 자동으로 열지 않는다. 한정 복구 승인 기록도 일반 pending에 넣지 않는다.

source_imported의 대상 없음 대조에서 KD-1920을 발견했다. 첫 준비 전에 자료를 제공하면 준비는 그 자료가 든 snapshot으로 실행되지만, 자료 사건은 별도 계획에 남았다. 준비가 후보 없이 수락돼도 빈 계획이 하나 더 실행됐다(w4frrm49). 이제 과제와 지식이 없고 미시작 일반 준비가 있으면 그 준비에 자료 사건을 결속한다. 수락된 빈 준비는 사건을 소비하고 계획0이다. 이미 입력이 고정된 준비에는 사건을 붙이지 않으며, 이후 도착 자료는 나중 계획1로 간다. 기존 과제 또는 지식이 있으면 계획의 판단을 유지한다. 기존 준비성 상실/회복 사건도 실제 계획에 포함시키고, 정상 점유의 상실 기록은 pending/호출 원인이 아님을 검사했다. 연구 계획 계약에 이 담당 구별을 추가했다.

최종 구조48·Sim52·flow28의128개가174.1초에 통과했다. 실행 중 소스 변경은 없다. 긴 지식 복구 흐름은90.9초로 소프트 예산을 넘었지만 목표를 두 번 검증하는 범위와 단언을 줄이지 않았다. 원보고는 검증/2026-10-05-사건-원천-대응/report.json이며 SHA256은 작업판 B109에 있다. 외부 복구 fixture의 잘못된 경로/중단 국면과 실제 빈 계획 재현 보고도 구별해 보존했다. 같은 트리의 부분 실행이며 전체 일반·T3·변이·T4/T5 통과로 합산하지 않는다.

11-B는 B90~B109의 직접 enqueue/직접 큐/관찰/시간/재시작 검증과 이번 lifecycle 대응을 결합해 implementation_reviewed로 옮겼다. 비발동 기록은 판단 사건과 구별하고, 실제 action.target의 부재와 판단할 원인의 부재도 구별했다. 공유 배정 경로의 호출 증거와 원천별 수신/거부 증거를 함께 읽는 구성이다. 최종 전체 판본 관문은 별도로 남는다. 다음은 원래 요구의13-C 문서 명시 공간/필드 대응이다. B84 로컬 검수 자료와 현재 checker/정본을 먼저 사용하며 발동 원천을 다시 전수 감사하지 않는다. 원래19+11·보존61·P2 원12와 최종 전체 일반/fresh T3/극단 변이/T4/T5 목표는 그대로다.
