## 종합

전수 검토는 무엇을 빠짐없이 다뤘는지와 무엇까지 확인했는지를 함께 밝혀야 한다. 파일 목록, 독해 기록, 모델에 전달된 원문, 내용에 대한 판단은 서로 다른 증거다. 수리에서도 결함의 존부, 제안한 편집의 타당성, 편집을 적용한 결과를 각각 판단해야 한다. 이번 기록은 이 구별이 없으면 미독을 놓치거나, 실재하는 결함을 기각 판정 뒤에 남기거나, 시험 전제의 모순을 제품 문제로 잘못 처리할 수 있음을 보여 준다.

이번 dream은 사용자가 명시한 기억 종합·정비 사이클이다. 대상은 M-0331~M-0338 여덟 건이며, 모두 이전 반영 수위 이후의 기록이다. 반영 수위는 하위 기록을 현행 L 노드에 반영할지 판단한 마지막 번호이고, 색인에 적는다. do-math는 AI 역할들이 수학 연구를 나누어 수행하는 실행기이고, verify-rounds는 그 구현과 문서를 여러 수리자·심사자가 검토하는 절차다. D-0007의 대리 표지에 관한 판단과 D-0008의 비용·검증 범위 구별을 이어받되, 이번 종합의 중심은 검토 증거와 처분의 범위를 정확히 연결하는 데 있다.

### 전수의 대상과 확인 깊이를 함께 정한다

테스트 비용 검토에서는 오래 걸린 일부 사례의 상세 검토가 전체 테스트 검토처럼 보고됐고, 사용자가 그 차이를 바로잡았다. 후속 작업은 모든 테스트 메서드를 원장에 열거하고 본문 위치, 단언 대상, 실행 형태, 보존된 역사 시간을 구별했다. 이때 역사 시간이 없는 사례를 0초로 두면 미측정이 빠른 실행처럼 보인다. 단언 호출이 없는 메서드도 공통 헬퍼에 단언을 맡기거나 예외 없는 수락을 검사할 수 있으므로 이름·시간·단언 수만으로 보존 가치를 판단할 수 없다. [[M-0332]]

따라서 전수라는 표현에는 대상 집합과 수행한 검토를 붙인다. 이름·시간의 전수 집계, 각 본문 구조의 정적 검사, 계약 경로의 독해, 변경 뒤 실행 검증은 같은 완료 상태가 아니다. 비용을 줄이려면 시작 상태와 검사하는 경계도 보존해야 한다. 서로 다른 제출 경로를 한 실행으로 합치거나 외부 정책이 다른 시험 준비 상태로 바꾸면, 단언 문장이 남아 있어도 검사 대상이 달라질 수 있다. 이는 D-0007이 말한 대리 표지의 한계를 테스트의 초기 조건과 증거 수준으로 구체화한다. [[M-0332]] [[D-0007]]

사용자 교정의 절차상 의미는 비용 상위 표본의 관찰에서 전건 검토 완료로 넘어간 데 있다. 단순히 사용자가 나중에 더 넓은 검토를 원했다고만 읽지 않는 이유는 M-0332가 앞선 전체 검토 표현과 실제 수행의 차이를 명시하기 때문이다. 교정 위치는 검토 범위를 정하고 완료를 보고하는 단계다. 기존 검증 계약에 이 구별을 통합하며, 별도 상시 보고 양식을 추가하지 않는다.

### 독해표를 실제 입력의 증거로 확대하지 않는다

M-0333에서는 파일을 열어 행 수만 집계한 기록으로 전행 독해표가 작성됐다. M-0334에서는 표가 담당 범위를 모두 덮어도 실행 로그에 특정 파일의 앞부분이 빠져 있었고, 같은 세션을 재개해 보완했다. 행 수가 맞는 독해표는 범위 선언을 검사하는 자료이며, 실제 본문 전달을 별도로 확인해야 한다. [[M-0333]] [[M-0334]]

M-0338은 표시 로그와 실제 세션의 도구 반환도 구별해야 함을 더했다. 한 수리자의 표시 로그에는 다수 행이 없었지만 실제 입력에는 대부분 있었고, 다른 수리자는 표시 로그 대조를 통과했는데 실제 입력에서는 시험 파일 끝이 잘렸다. 따라서 표시 로그의 출현·미출현만으로 실제 입력의 완전성·결손을 확정할 수 없다. 당시 운전자는 실제 도구 반환을 확인하고 대상 파일을 다시 읽게 했다. 보완 뒤의 원문 행 출현 대조는 입력에 해당 글이 나타났다는 근거이며, 순서대로 충분히 이해했다거나 결함을 모두 찾았다는 증명은 아니다. [[M-0338]]

이 관찰은 앞선 M-0334·M-0336·M-0337의 CLI 로그 대조를 소급해 실제 입력 전건 대조로 바꾸지 못하게 한다. 그 런들의 기록과 대조 결과는 당시 증거로 보존하되, 현재의 완료 판단에서는 표시 로그가 실제 입력을 충실히 보존하는지 확인한다. 이번 dream은 앞선 런들의 실제 입력을 다시 전수 감사하지 않았다.

범위 분담도 증거 수준과 함께 읽는다. 전건을 맡긴 관점 담당자가 미독을 남긴 런들 뒤에, 각 관점 담당자에게 한 영역을 필수로 읽게 하고 연결된 생산·소비 경로를 추적하게 한 런들이 나왔다. 이 방식은 담당 범위를 완결할 수 있게 나누는 선택지다. 모든 관점이 전건을 본 것과 같지는 않으며, 분할만으로 누락이 사라진 것도 아니다. M-0338은 같은 분할 구조에서도 입력 절단이 남았음을 보여 준다. [[M-0333]] [[M-0334]] [[M-0336]] [[M-0337]] [[M-0338]]

### 결함, 수리안, 적용 결과를 각각 판단한다

기각된 수리안에는 서로 다른 이유가 있었다. M-0336에서는 실제 소비자에서 쓰지 않는 필드를 문제 삼은 지적의 기각을 재검토에서도 유지했다. 같은 런에서 제품 결함은 타당해도 시험 코드의 구문 오류나 준비 상태 누락 때문에 조각이 기각된 사례도 있었다. M-0337에서는 수리안이 유효한 반환 필드 설명이나 현재 사건 번호의 정수 검사를 함께 지운 것이 기각 이유였다. M-0338에서는 README의 닫는 코드 울타리를 빠뜨린 조각이 기각됐다. 결함을 재현하고 잃으면 안 되는 정보를 보존해 새 편집을 만드는 일이 필요했다. [[M-0336]] [[M-0337]] [[M-0338]]

무처분도 이번 작업의 목적과 대조해야 한다. M-0338의 미사용 인자 제거는 실행 결과를 바꾸지 않는다는 이유로 무처분됐지만, 사용자가 죽은 매개변수 정리를 명시하고 후속 직접 처리도 허용했으므로 적용됐다. 함수 호출을 없앤 것이 아니라 인자 선언과 전달만 제거했다. 앞선 두 런도 사용자가 기각·무처분 전건의 직접 재검토를 지시했다. 이는 검토 목적과 판단 기준을 맞춘 사례이며, 모든 기각·무처분을 자동 적용하라는 규칙이나 운전자의 일반적인 승인 우회 권한이 아니다. 원 심사 판정과 후속 조치를 따로 보존한다. [[M-0336]] [[M-0337]] [[M-0338]]

적용 뒤 실패의 원인은 실제 회귀와 시험 전제의 불일치로 나뉘었다.

| 기록 | 실패 입력과 원인 | 처리 |
|---|---|---|
| M-0333 | 승인된 변경 뒤에 실패한 하위 시험의 결과가 다음 하위 시험의 skip으로 덮였다. 기존 동작을 깨뜨린 제품 회귀다. | 해당 수리 항목을 제외하고 나머지를 공식 재적용했다. |
| M-0337 | 시험은 함수의 반환값만 바꾸어 수학 목표의 해결 근거가 있는 것처럼 만들었다. 그러나 실행기에 저장된 목표 상태는 미해결이었다. 새 코드가 학술 요구를 적용할 수 없는 상태로 판정해 준비 대기를 지우자, 그 대기가 남기를 기대한 시험이 실패했다. | 시험에 저장한 목표 상태를 해결됨으로 바꿔 모사한 해결 근거와 일치시켰다. 제품 검사는 유지했다. |
| M-0338 | 봉인 검사는 저장된 검사 결과가 같은 실행·응답·확장·스키마에 속하는지 확인했다. 시험의 모형 기록에는 그 결속 정보가 없었다. | 시험 모형에 실제 검사 계약이 요구하는 정보를 넣었다. 제품 검사는 유지했다. |

각 사례의 사건 근거는 [[M-0333]]·[[M-0337]]·[[M-0338]]이다. 서로 다른 원인을 한 방향의 처방으로 처리하지 않은 점이 이 비교의 핵심이다.

그러므로 적용 후 실패를 만나면 현재 계약과 실패 입력을 대조해 제품 회귀인지 시험 전제의 불일치인지 판정한다. 다중 심사의 합의가 이 확인을 대신하지 않는다. 자동으로 찾은 변경 시험 목록도 공통 시험 준비 코드의 영향까지 모두 덮지는 못한다. 이번 런들의 선택 검사 통과와 라운드 상한 도달은 전체 통합 통과나 실제 연구 성능의 검증 완료를 뜻하지 않는다. [[M-0334]] [[M-0337]] [[M-0338]] [[D-0008]]

### graphify의 관계와 상태는 원문으로 돌아가는 데 쓴다

graphify는 do-math 내부 파일의 관계를 찾아 현재 원문으로 돌아가기 위한 지도다. 조회는 필요에 따라 수행하고, 갱신은 사용자 명시 요청이 있을 때만 한다. 원문 인용 검사와 추출 완료 상태는 의미 해석이나 구현의 계약 준수를 보증하지 않는다. 실제 갱신에서 원문과 다른 인용이나 존재하지 않는 대상 경로를 거부했고, 기존 그래프를 보존한 채 성공한 문서 추출을 재사용해 회복했다. 재사용된 문서의 과거 추출 토큰까지 합친 사용량을 이번 호출만의 사용량으로 읽지 않는다. [[M-0331]] [[M-0335]] [[M-0336]] [[M-0338]]

그래프와 상세 추출 기록은 Git 제외 로컬 자료다. 기억 노드와 스킬을 커밋한 사실이 그래프 내용을 보존한 것은 아니다. 이 운영 경계는 이미 graphify 정본에 있으므로 현행층에는 정본 포인터와 적용 한계만 둔다. 이번 dream에서는 그래프를 갱신하지 않았다.

## 근거

- [[D-0007]]: 대리 표지에 기댄 축소·검사 제안을 원자료로 대조하는 선행 종합이다.
- [[D-0008]]: 전체 경로의 비용과 검증 범위를 구별하고, 보류된 프로젝트 점검을 임의로 재개하지 않는 경계를 이어받는다.
- [[M-0331]]: graphify의 범위·수동 갱신·읽기 전용 조회·인용 검사와 로컬 보존 경계다.
- [[M-0332]]: 전수 검토 표현의 사용자 교정, 미측정과 0초의 차이, 시험 초기 조건 보존의 근거다.
- [[M-0333]]: 행 수 집계를 독해로 취급한 결손과 만장일치 승인 뒤의 실제 회귀를 기록했다.
- [[M-0334]]: 같은 세션에서 독해를 보완한 경로와 CLI 로그 대조·선택 검증·라운드 상한의 범위다.
- [[M-0335]]: 명시적 graphify 갱신, 재사용 캐시를 포함하는 사용량, Git 제외 산출물을 구별했다.
- [[M-0336]]: 영역·관점 분담과 재검토 뒤 기각 유지·직접 수리의 서로 다른 이유를 기록했다.
- [[M-0337]]: 유효한 문서 정보와 현행 검사를 보존한 재수리, 학술 과제 시험 전제의 교정이다.
- [[M-0338]]: 표시 로그와 실제 모델 입력의 양방향 불일치, 사용자 목적에 따른 무처분 재검토, 봉인 시험 모형과 영향 범위의 보완이다.

소스 대조의 위치와 용도는 다음과 같다.

- 독해·후속 수리 권한: `.claude/skills/verify-rounds/SKILL.md`의 1단계 판독과 「런 도중의 사용자 지시」, 같은 스킬의 `계약/수리.md` 작업 순서 2와 수행 기록을 읽었다. 현재 독해 의무와 제안할 완료 근거의 차이를 확인했다.
- graphify의 보증 경계: `.claude/skills/graphify/SKILL.md`, 같은 스킬의 `scripts/semantic.py:validate`와 `scripts/graph.py:update`에서 인용·경로 검사와 실패 시 그래프 보존을 확인했다.
- 현행 검사와 시험 전제: `.claude/skills/do-math/` 아래 `scripts/do_math/events.py`의 사건 번호 검사, `submission.py:read_sealed_submission`의 봉인 결속 검사, `scripts/tests/test_academic_engine.py`와 `test_repair_plan.py`의 모형 구성을 대조했다.
- 비용 검토와 작업 사건: `docs/do-math/테스트-비용-전수검토-2026-09-24.md`와 각 M 노드가 가리키는 종료 보고·장부를 진입점으로 삼았다.

이번 대조는 소스·기록의 확인이며 제품 시험이나 연구 운전의 재실행은 아니다.

## 제안

> 독해 기록과 담당 범위가 일치해도 실제 본문이 전달됐는지는 별도로 확인한다. 행 수 집계나 파일 열기 기록은 본문 독해의 증거로 쓰지 않는다. 출력 절단이나 기록 불일치를 확인할 때에는 해당 세션의 실제 도구 반환을 원문과 대조한다. CLI 표시 로그는 실제 입력을 충실히 보존하는지 확인된 범위에서만 그 대조를 대신할 수 있다. 실제 입력 기록을 확보하지 못했으면 그 한계를 남기고 전건 전달 확인으로 보고하지 않는다. 원문 행의 출현은 이해의 완전성이나 결함 부재의 증명이 아니다.
