# 스킬 지형과 외래 스킬 각색

스킬을 만들고, 각색하고, 검증할 때 관할을 고르는 지도다. 수기 편집 정본은 `.claude/skills/`다. `.agents/skills/`는 Codex용 생성 사본이다.

## 세 정본의 관할

- `skill-creator`: 새 로컬 스킬을 만들거나 자작 스킬을 개선하고 평가한다.
- `adapt-skill`: 기존 플러그인이나 전역 스킬을 이 프로젝트 규범에 맞게 판정하고 각색한다.
- `writing-skills`: 스킬의 구조, description, 검증 방법론을 설명한다.

실제 생성과 수정 절차는 `skill-creator`가 우선한다. 외부 스킬의 로컬 각색은 `adapt-skill`이 우선한다. 방법론 설명만 필요하면 `writing-skills`를 사용한다.

기준 승계: [[M-0001]]의 일반 작업 템플릿.

## description의 역할

description은 스킬 본문의 요약이 아니라 호출 라우팅 계약이다. description에는 스킬이 하는 일과 호출 조건을 함께 적는다.

비슷한 스킬은 관할 경계를 서로 설명해야 한다. 모든 스킬이 넓은 표현으로 “분석”, “검토”, “검색”을 주장하면 자동 선택이 경합한다. description을 줄일 때는 글자 수보다 구별되는 트리거를 보존한다.

기준 승계: [[M-0001]]의 일반 작업 템플릿.

## 외래 스킬의 처리

외래 스킬은 세 방식 중 하나로 처리한다.

1. 각색 편입: 프로젝트 규범과 충돌하거나 관할 조정이 필요하면 `adapt-skill` 절차로 로컬본을 만든다.
2. 원본 직접 사용: 충돌이 없고 원본 갱신을 그대로 받을 가치가 크면 설치본을 사용한다.
3. 무각색 로컬 편입: 원본을 고정 배치할 필요는 있지만 문면 수정이 필요 없으면 출처와 해시를 기록해 로컬에 둔다.

외래 스킬이라는 이유만으로 수정하지 않는다. 수정은 실제 충돌, 중복 관할, 환경 전제 차이, 검증된 품질 결함이 있을 때만 한다.

기준 승계: [[M-0001]]의 일반 작업 템플릿.

## 각색 절차의 판단 기준

각색은 다음 순서로 판단한다.

1. 프로젝트의 기계 강제, 로컬 스킬, AGENTS.md, 참조 문서를 실제 파일에서 찾는다.
2. 대상 스킬과 동반 리소스를 전문으로 읽는다.
3. 지시 단위마다 로컬 규범과 대조한다.
4. 지시에서 로컬 규범으로, 로컬 규범에서 지시로 양방향 점검한다.
5. 독립 검증자가 원본과 대조표를 직접 읽어 반증한다.
6. 사용자가 처리안을 승인한 뒤에만 로컬본을 만든다.

요약과 대조표는 판정을 돕는 중간물이다. 원문 인용과 최종 생성 시점에는 설치된 원본과 로컬 정본을 다시 읽는다.

## 정본과 사본

스킬 정본은 `.claude/skills/`에 하나만 둔다. `.agents/skills/`는 생성기로 만든다. 생성 사본을 직접 수정하지 않는다.

동기화 구조와 생성기 사용법은 `.agents/skills/writing-skills/references/멀티런타임_동기화.md`가 정본이다. 정본 변경 뒤에는 생성기와 드리프트 검사를 함께 실행한다.

## ponytail 계열

`ponytail`은 코드 산출에서 과잉 구현을 줄이는 상시 규범이다. SessionStart와 SubagentStart 훅이 full 본문을 주입한다. 산문, 기억 노드, 문서 작성에는 적용하지 않는다. 파견 계약과 산출 계약이 ponytail 출력 규칙보다 우선한다.

ponytail 계열은 네 스킬로 나뉜다.

- `ponytail`: 필요한 최소 구현을 선택하고 기존 코드, 표준 라이브러리, 플랫폼 기능을 먼저 찾는다.
- `ponytail-review`: diff에서 과잉 설계와 삭제 가능한 코드를 찾는다.
- `ponytail-audit`: 저장소 전체에서 과잉 설계를 감사한다.
- `ponytail-debt`: `ponytail:` 주석을 모아 의도적 단순화의 한계와 승급 조건을 확인한다.

ponytail은 문제 이해, 보안, 데이터 손실 방지, 접근성, 사용자가 명시한 범위를 줄이지 않는다. 비자명한 코드에는 깨지면 실패하는 최소 검사를 남긴다. 의도적으로 한계를 둔 구현에는 한계와 승급 경로를 `ponytail:` 주석으로 기록한다.
