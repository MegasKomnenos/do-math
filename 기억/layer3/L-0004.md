# 문서 추출과 렌더링 결과 판독

PDF, HWP, DOCX, 이미지, 음성, 영상에서 텍스트를 추출할 때 쓰는 공통 지식이다. 실행 절차와 지원 형식의 정본은 `.claude/skills/extract-documents/SKILL.md`다. Codex는 생성 사본인 `.agents/skills/extract-documents/SKILL.md`를 읽는다.

## 표현과 렌더링의 분리

문서 생성 도구는 구조 파싱, 표현 생성, 파일 렌더링을 분리한다. 표현 규칙을 한 곳에 두면 렌더러를 바꿔도 문서 구조와 스타일의 수정 지점이 늘어나지 않는다.

렌더러별 보정은 공통 표현 규칙과 분리한다. 서로 다른 렌더러의 결과는 비슷할 수 있지만 바이트나 줄바꿈까지 같다고 가정하지 않는다.

## PDF 페이지 판정

PDF는 파일 전체가 아니라 페이지별로 판정한다. 한 PDF 안에 텍스트 레이어가 있는 페이지와 이미지 페이지가 섞일 수 있다.

1. 텍스트 추출량과 구조를 확인한다.
2. 텍스트 레이어가 충분하면 추출 텍스트를 사용한다.
3. 텍스트가 없거나 불완전하면 페이지를 이미지로 렌더링한다.
4. 렌더링한 이미지가 생기면 시각 인식 기능(vision)으로 판독한다.
5. 페이지 순서와 누락 여부를 원본 페이지 수와 대조한다.

벡터 경로로 글자를 그린 PDF는 화면에서 글자가 보여도 텍스트 추출량이 0에 가까울 수 있다. 도형 수만으로 벡터 글자와 표가 많은 정상 PDF를 구별하지 않는다. 텍스트 추출 결과와 렌더링한 이미지를 함께 본다.

## vision 판독

`extract-documents`가 `[[VISION ...]]` 플레이스홀더를 만들면 해당 이미지 파일을 직접 읽는다. 플레이스홀더를 최종 텍스트로 남기지 않는다.

판독은 다음 순서로 교정한다.

- 제목, 표, 각주, 다단 배치처럼 읽기 순서가 갈리는 영역을 먼저 식별한다.
- 숫자, 날짜, 고유명사, 기호를 원본 이미지와 다시 대조한다.
- 잘린 행과 페이지 경계에서 이어지는 문장을 확인한다.
- 불확실한 글자는 추측하지 않고 불확실성을 표시한다.

해상도를 높이는 것만으로 판독 정확도가 보장되지 않는다. 입력 이미지가 선명한지, 페이지가 올바르게 잘렸는지, vision 도구가 실제 원본 크기를 읽는지를 함께 확인한다.

## 완전성 검증

> 정정 대기: [[M-0305]]가 이 항목을 뒤집음. 통합은 다음 dream.

텍스트 추출의 완료 조건은 파일 생성이 아니다. 다음 항목을 확인한다.

- 원본 페이지 수와 처리 페이지 수가 같다.
- 각 페이지가 텍스트 또는 vision 판독 결과를 가진다.
- 표, 각주, 머리말, 꼬리말의 처리 기준이 일관된다.
- 숫자만 빠진 페이지처럼 부분 추출된 페이지를 탐지한다.
- 최종 텍스트에 플레이스홀더와 도구 오류 문구가 남지 않는다.

종료 코드는 추출의 성공을 보증하지 않는다. `extract-documents`의 HWP 경로는 `hwp5html` 실행 파일에 의존하며, 실행 파일이 없을 때 파일별 오류를 결과에 기록하고도 프로세스는 0으로 끝나 본문 없는 TXT를 남겼다. 출력의 오류 표시와 텍스트 분량을 함께 확인한다. [[M-0284]]

텍스트가 이미 Markdown이나 TXT이면 추출 절차를 다시 돌리지 않는다. 원본 형식이 바이너리이거나 사람이 읽을 텍스트가 직접 보이지 않을 때 `extract-documents`를 사용한다.

## HWP 원고의 편집과 저장 검사

HWP 원고를 고칠 때에는 한글 자동화로 원본을 HWPX로 내보내 그 문단과 표를 원문으로 삼고, 수정한 뒤 HWP와 PDF로 저장했다. 저장한 HWP를 다시 열어 내보낸 본문이 개정 원문과 같은지, PDF에 모든 텍스트 블록이 있고 페이지 밖으로 밀린 글자가 없는지, 기존 글자·문단 서식이 유지됐는지를 대조했다. 표의 셀 안 줄바꿈을 텍스트로 펼치면 문장이 끊겨 보일 수 있으므로 실제 HWP·PDF와 대조해 판단한다. [[M-0284]] [[M-0288]] [[M-0291]]

인쇄 설정에 모아찍기가 있으면 PDF의 장수와 문서의 쪽수가 다르다. 확인용 PDF는 문서 한 쪽씩 보이게 따로 만든다. 페이지 이미지에서 본문과 표가 겹쳐 보여도 확대 이미지와 PDF 좌표로 확인한 뒤에만 결함으로 판정한다. 고정된 표 높이 때문에 표 전체가 다음 쪽으로 넘어가는 경우처럼 배치 문제는 실제 출력 화면에서 찾는다. [[M-0284]]

한글 자동화의 경고창 설정을 적용해도 파일 접근 확인창은 따로 나타났다. 작업용으로 생성한 한글 프로세스의 창만 확인해 처리하고, 사용자가 열어 둔 다른 문서는 닫거나 저장하지 않는다. [[M-0284]]

저장·변환·배치 검사는 손실이 없음을 확인할 뿐 문장 의미의 정확성을 입증하지 않는다. 의미 검토는 [[L-0005]]의 독자 관점 퇴고를 따른다. [[M-0284]]
