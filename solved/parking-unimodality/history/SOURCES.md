# Where the sources of the history are

The history, `timeline.md`, cites its sources by coordinates. In its running text a coordinate stands in a numbered note at the end of the document, and a mark after the statement leads to the note; in its tables the coordinates stand in the cells; and a few sentences of its section 9 name a source itself, by its sequence number or by the number of a memory note. Beside the coordinate a note says, where there is need of it, which record states a step of an argument, what name or letter a record itself has for something, and how the history came to the statement. This file says, for each kind of coordinate, where a reader finds the source, and lists the sources that are cited and not published. It lies beside the history, in the folder `solved/parking-unimodality/history/` of the repository.

The sources are in three places.

- **The archives.** `solved/parking-unimodality/knowledge/` holds two archives, described in `MANIFEST.md` in that folder: `parking-unimodality-fresh-20261105-150803-knowledge.tar.xz` for the earlier instance (E) and `parking-unimodality-20261119-knowledge.tar.xz` for the later instance (L). Each contains the folder `knowledge/` of its instance at the last commit that the history considers (E: `12e91f442`, 13 November 2026, 06:12; L: `130a7a3`, 23 November 2026, 08:10; times are Korean Standard Time). Only the archive of the later instance is in the repository. The archive of the earlier instance is 349 MB and is left out of it; at present it can be obtained only on the machine on which it was made. `MANIFEST.md` gives its checksum.
- **The folder `sources/`**, beside this file. It holds copies of the cited files that are not in the archives and are not tracked files of the repository. Its layout shows where each file came from. `sources/earlier-instance/` and `sources/later-instance/` repeat the layout of the two instance directories. `sources/between/` holds the documents written between the two instances. `sources/operator/` holds files kept by the operating sessions outside the instances. `sources/machine/` holds the extract of the system log.
- **Tracked files of the repository**, cited by their path from the repository root.

The history tells of two runs of a research system on one statement, a conjecture about parking functions that the system calls the root. It calls a run an instance; each instance has a directory of its own, with its own Git repository. E stands for the earlier instance and L for the later one. Section 1 of the history says what a coordinate is and where the coordinates stand, the head of its section "Notes" explains their forms, and section 2.2 explains the words of the research system that occur below.

## Paths in the history

How a path in `timeline.md` is to be read depends on how it begins.

- A path that begins with `sources/` is relative to the folder of this file.
- A path that begins with `knowledge/`, `control/`, `runner/` or `sessions/` is relative to the directory of the instance concerned. With `knowledge/` it leads into the archive of that instance. With one of the other three it leads to the same path under `sources/earlier-instance/` or `sources/later-instance/`, if the file is published. What the history cites as L `runner/seeds-inserted.json`, for example, is `sources/later-instance/runner/seeds-inserted.json`.
- A path that begins with `lean/`, `evidence/` or `review/` lies in the folder of a record, and a path that begins with `output/` lies in the folder of a session. A Lean file that a note gives from `Parking/` on, as `Parking/Tilt.lean`, lies under `lean/` in the folder of a record.
- A file that the history names without a folder, such as `settings.json` or `root.md`, is found where its row below says.
- A path that a note gives as a file "of the working files", as `findings/P1-part2.md`, lies in the folder of the working files of the history, which are not published (see "Cited and not published").
- Any other path is relative to the repository root.

## Coordinates and where they lead

In the first column, an entry in quotation marks or in code gives a coordinate in the form in which the history writes it. Often it is one example that stands for all coordinates of its kind. Where the history gives a file by its whole path, the entry may give only the name of the file, as with `합의.md`. An entry in plain words describes what is cited.

A record token, a commit, an input or a path that begins with `knowledge/` can stand without the letter of its instance. If you cannot tell from the history which instance is meant, look in both: for a record token in the two indexes of publications, `sources/earlier-instance/publications.tsv` and `sources/later-instance/publications.tsv`, and for a commit in the two lists of commits, `sources/earlier-instance/git-log.txt` and `sources/later-instance/git-log.txt`.

### Publications, records and commits

A record is a piece of work, done by AI sessions of an instance, that a review session has judged and decided to publish. It consists of a mathematical exposition, a list of claims, and the review's verdict on each claim. A publication of an instance is most often a record. Each publication has a sequence number and an event, a file in `knowledge/events/` that carries the number and the time. The index of an instance, `sources/earlier-instance/publications.tsv` or `sources/later-instance/publications.tsv`, gives for each sequence number the time, the kind, the identifier, the folder under `knowledge/`, and the commit.

### Standing inputs and the pause flag

A standing input is a text that every session started afterwards receives along with its task. Either of two parties can submit one. The user is the person who commissioned the research. The operator is an AI session, outside the instance, that starts and tends the instance on the user's behalf.

The history cites an input by the word "input" with its date and time, by a number, or by both. The name of the input's file begins with the number, as in `1795057444813564600-a61b69ea35b74ebbbd7f7ff2608e2423.txt`. The history writes the number with the letter of the instance or without it, and with `-…` after it or without it. A section or the word "preamble" after the number, as in "`1795329795877819300-…`, §2", names a part of the input's text. It also refers to the inputs of the later instance by their order of submission, as in "the fifth input", and its section 2.2, with the paragraph before the table of its section 7.1, says how they are counted.
