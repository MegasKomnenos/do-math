# 학술자료 MCP 구현 인계

> 2026-09-09 요구사항 확정 당시의 인계 기록이다. 현재 구현·지원 범위는 [서비스 안내](../../README.md)를 따른다.

작성일: 2026-09-09 · 작업 루트: `C:\math`

## 1. 목표와 현재 상태

후속 세션의 작업은 이 문서의 확정 계약에 따라 학술자료 검색·확보용 MCP 서버를 구현하고 검증하는 것이다. 사용자는 `grill-me` 인터뷰에서 아래 공통 이해를 정한 뒤, MCP 구성까지 포함한 최종 요약에 **“확정”**이라고 답했다. 이 문서는 그 결정을 구현 세션에 전달하는 인계문이다.

사용처는 [do-math 통합 설계](../../../../docs/do-math/통합-설계.md)에 따라 구현될 시스템의 P vs NP 연구다. AI 작업자가 닫힌 연구 자료 목록에만 의존하지 않고, 연구 중 필요에 따라 고전 연구의 원문을 다시 확인하거나 최신 연구 지형을 조사할 수 있어야 한다. 대표 흐름은 **자료원 사용법 조회 → 검색·서지 export → 결과를 읽고 대상 선별 → 선택한 자료의 전문 확보**다. 자료의 연구상 필요성과 가치 판단은 호출 AI가 맡는다.

이 세션에서 완료한 것은 요구사항 확정과 원자료·기존 코드·공식 문서의 사전 확인이다. **새 MCP 서버의 코드 작성, 등록, 실행 및 실서비스 검증은 아직 수행하지 않았다.** 기존 KUDOS 수집 코드는 별도 조사 작업의 산출물이며 새 MCP 서버의 구현 완료 근거가 아니다.

## 2. 확정된 계약

| 항목 | 확정 내용 |
|---|---|
| 외부 인터페이스 | MCP 서버로 제공한다. 초기 배치는 단일 Windows 호스트의 로컬 stdio다. |
| 자료원 범위 | [자료원 목록](SOURCE-SELECTION.md)에서 선정한 인증 검색 자료원, 공개 주자료원, 후보별 보완 자료원과 원문 확보 자료원을 포함한다. 인증 검색용 여섯 DB만으로 좁히지 않는다. |
| 어댑터 | 공통 인터페이스를 자료원별 개별 어댑터가 구현한다. **공개 API가 존재하면 API로, 없으면 Playwright로 구현한다.** 이 선택은 어댑터 구현 시 정한다. 실행 중 API 실패를 계기로 Playwright로 자동 전환하는 구조를 넣지 않는다. |
| 한 호출의 범위 | 입력으로 지정한 자료원에서 탐색·확보를 끝낸다. 확보하지 못하면 그 결과를 반환한다. 다른 자료원을 시도할지는 호출 AI가 결정한다. |
| 검색식 작성 | 호출 AI가 자료원별 문법에 맞춰 작성한다. 도구가 연구 목적을 대신 정하거나 검색식을 새로 발명할 책임을 맡지 않는다. |
| 검색 기능 | 자료원이 제공하는 고급검색과 export를 지원한다. 자료원별 검색 조건의 의미를 보존한다. |
| 사용 지식 제공 | 검색식 작성에 필요한 자료원별 문법·검색 필드·연산자·필터·기능·제약·검증된 예제를 제공한다. 호출자가 API 요청 방법, 로그인 과정, 화면 조작이나 어댑터 코드를 알아야 사용할 수 있는 구조는 허용하지 않는다. |
| 자료 확보 | 링크·이름·식별자로 지정한 자료의 서지, 초록, 전문과 그 밖의 유용한 내용을 회수한다. BibTeX와 PDF는 예시이며 지원 자료와 형식을 그 둘로 한정하지 않는다. |
| 기계적 추출 | 파싱·역직렬화 등으로 확보한 결과에서 필요한 문헌·항목·필드·구간을 추출하는 기능을 제공한다. |
| 이미지 판독 | 호출한 AI 세션이 직접 맡는다. 서버에 이미지 인식 AI를 넣지 않는다. 파일의 기계적 처리와 이미지의 의미 판독을 구별한다. |
| 인증 | 필요한 어댑터가 `.credentials`의 인증 정보를 내부에서 사용한다. KUDOS 인증이 필요한 자료원은 그 기관 접근 경로를 처리한다. 비밀값을 호출 AI의 입력·출력이나 로그·산출물에 복제하지 않는다. |
| 효율 | 인터페이스와 응답을 간결하게 만들고 불필요한 토큰 소비와 반복 호출을 줄인다. 필요한 정보나 결과 범위를 조용히 생략하는 방식으로 비용을 줄이지 않는다. |
| 안정성 | 자료원별 시행착오와 구현 결함은 개발·검증 단계에서 해결한다. 연구 작업자가 사용 중 내부 코드를 읽거나 화면을 디버깅해야 정상 기능을 수행할 수 있는 상태를 완료로 보지 않는다. |

확정된 결정을 단순 재확인하기 위해 인터뷰를 다시 열지 않는다. 조사에서 새로 드러난 사실이 계약 충족을 막거나 실제로 새로운 사용자 결정을 요구하면, 해당 사실·영향·남은 선택만 설명한다.

## 3. 공통 MCP 도구와 반환

최종 합의에서 정한 도구 구성은 다음과 같다. 세부 인자·스키마·자료원 식별자는 구현 세션이 아래 역할을 보존하면서 정한다.

| 도구 | 입력의 의미 | 제공할 결과 |
|---|---|---|
| `list_sources` | 지원 자료원의 목록·기능 조회 | 자료원 식별자와 제공 기능 |
| `describe_source` | 자료원 지정 | 그 자료원의 요청을 작성하고 결과를 해석하는 데 필요한 사용 지식 |
| `search` | 자료원, 호출 AI가 작성한 검색식과 고급검색 조건·범위 | 검색 결과와 export |
| `fetch` | 자료원, 대상의 식별자·링크·이름, 필요한 내용 | 해당 자료원에서 확보한 자료와 확보 상태 |
| `extract` | 확보한 자료의 참조, 선택할 항목·필드·구간 | 선택한 정보의 기계적 추출 결과 |

공통 도구 설명에는 사용 흐름과 공통 입력 계약을 둔다. 자료원별 상세 문법은 `describe_source`로 필요할 때 조회한다. 모든 자료원의 상세 설명을 매번 모델 입력에 싣지 않는다. 설명은 실제 구현과 일치해야 하며, 외부 공식 문서의 링크만 나열하고 호출에 필요한 지식을 빠뜨려서는 안 된다.

큰 검색 결과와 원문은 서버가 보존하고, 응답에는 상태·건수·자료 참조와 요청한 정보만 담는다. 호출 AI가 보존 자료를 다시 읽거나 필요한 부분을 추출할 수 있어야 한다. 출처와 실제 자료의 대응을 유지한다. 진단 로그는 도구 결과와 분리한다.

미확보, 접근 제한, 실행 오류와 부분 결과를 구별한다. 해당 자료원에서 확보하지 못했다는 결과를 모든 자료원에서의 부재로 표현하지 않는다. 자료원이 제공하지 않는 기능, 현재 구현하지 않은 기능, 접근 조건 때문에 검증하지 못한 기능도 구별한다. 이 구별은 구현 누락을 자료원의 한계로 포장하기 위한 예외가 아니다.

자료원 목록에는 과거 조사 묶음의 운용 규칙도 들어 있다. 예를 들어 6절의 사용자 직접 인증 검색과 자동 원문 수집에 관한 문구를 이번 MCP의 확정 계약으로 옮겨 사용자 결정을 되돌리지 않는다. 그 문서가 인용한 서비스 접근 조건은 별도의 외부 사실로 확인한다. 이번 합의만으로 기존 문헌조사 작업을 중단하거나 기존 수집물을 삭제하는 범위를 만들지 않는다.

기존 수집에서 발견한 문헌 오결합·판본 차이·인증 만료·HTML 및 수식 보존·잘못된 링크 확장에 관한 조사 경로는 [M-0138](../../../../기억/layer1/M-0138.md), [M-0140](../../../../기억/layer1/M-0140.md), [M-0143](../../../../기억/layer1/M-0143.md), [M-0146](../../../../기억/layer1/M-0146.md)에 있다. 이 기록은 관찰과 회귀 사례를 찾는 색인으로 사용한다. 그 작업의 다중 자료원 탐색이나 운영 절차를 새 MCP 계약에 자동 승계하지 않는다.

외부 공식 문서의 조사 출발점은 다음과 같다. 구현 때 실제 지원 판본과 접근 조건을 다시 확인한다.

- [MCP 도구 명세](https://modelcontextprotocol.io/specification/2025-06-18/server/tools): 입력·출력 스키마, 구조화 결과와 자료 링크. 이 링크의 판본을 새 서버의 고정 판본으로 결정한 것은 아니다.
- [MCP 전송 명세](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports): stdio의 메시지·로그 경계.
- [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/), [필드 선택과 페이지 조회](https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/): 공개 API 기능을 확인한 사례.
- [Elsevier API 인증](https://dev.elsevier.com/tecdoc_api_authentication.html), [Web of Science API Expanded](https://developer.clarivate.com/apis/wos): API의 존재와 실제 이용에 필요한 키·자격을 구별하기 위한 조사 출발점.

## 5. 남은 구현 작업과 재량

다음 순서로 진행한다. 각 단계의 결과가 다음 단계의 입력이다.

1. **현행 환경과 자료원별 기능을 조사한다.** 설치된 런타임·MCP 클라이언트·라이브러리와 기존 코드의 상태를 직접 확인한다. 자료원 목록의 선정 대상을 지원표에 대응시키고, 자료원별 공개 API의 존재·제공 기능·접근 조건과 API가 없는 자료원의 실제 UI를 조사한다. 아직 특정 서비스로 구체화되지 않은 범주는 임의로 누락시키지 말고 그 범위를 명시한다.
2. **구체 인터페이스와 구현 위치를 정한다.** 확정된 다섯 도구에 입력·출력 스키마, 자료 참조·보존 방식, 자료원별 사용 지식과 오류 표현을 연결한다. 구현 언어·SDK·프로토콜 판본·디렉토리·세부 인자는 후속 세션의 기술적 재량이다. 호출자가 내부 작동을 알아야 하는 인자를 넣지 않는다.
3. **MCP 서버와 자료원별 어댑터를 구현한다.** 공개 API의 존재에 따라 정한 어댑터 구현 방식을 지킨다. 인증 정보를 확보하지 못한 상태를 API 부재로 해석하거나 실행 중 브라우저 전환 조건으로 바꾸지 않는다. 기존 코드의 재사용은 새 계약과 실제 동작을 대조한 뒤 결정한다.
4. **설명과 실제 사용 흐름을 검증하고 수리한다.** 아래 완료 기준을 적용한다. 검증에서 발견한 구현 결함을 고치고 영향받은 기능을 다시 확인한다. 문서에만 지원한다고 적힌 어댑터나 내용 없는 구현을 완료로 세지 않는다.

쓰기 범위는 새 MCP 서버 전용 구현·어댑터·사용 설명·시험·검증 자료와 그 서버를 연결하는 데 필요한 설정 항목이다. 전용 디렉토리의 위치는 착수 시 정해 기록한다. 기존 설정은 다른 서버 항목을 보존하며 수정한다. 기존 수집 코드의 공용 부분을 바꾸는 경우에는 그 변경이 영향을 주는 기존 동작도 검증한다. do-math 전체 구현과 기존 조사 체계의 전면 개정은 이 인계의 임무가 아니다.

구현에 필요한 추가 API 키나 이용 자격의 실제 확보 여부는 남은 확인 사항이다. 이 세션은 `.credentials/kudos.md`의 로그인 항목 존재만 값 출력 없이 확인했고, 자료원별 API 인증이나 실제 로그인을 시험하지 않았다. 필요한 정보는 보호된 저장소와 환경에서 직접 확인하고, 없으면 해당 자료원·필요 정보·검증하지 못한 범위를 특정해 사용자에게 전달한다. 이미 확정된 구조를 재승인받는 질문과 새로 필요한 인증 정보를 구별한다.

## 6. 완료 기준과 검증 보고

산출물은 실행 가능한 MCP 서버, 공통 사용 설명, 자료원별 사용 지식, 실제 검증 결과다. 다음을 확인한다.

- 선정 자료원과 구현·지원 기능·시험의 대응을 제시한다. 서비스 자체가 제공하지 않는 기능과 개발이 남은 기능을 구별한다.
- 실제 MCP 클라이언트에서 호출 AI가 제공된 설명만으로 자료원 선택, 검색식 작성, 검색·export, 결과 선별·추출, 선택 자료 확보를 수행할 수 있다. 내부 코드나 브라우저 디버깅을 호출자의 정상 절차로 요구하지 않는다.
- 검색 조건·회수 범위·출처가 실제 결과와 대응하고, 확보한 파일이 요청한 자료의 해당 판본·내용인지 확인한다. 원문 대신 검색 안내나 오류 페이지를 반환한 경우를 성공으로 세지 않는다.
- 기계적 추출이 요청한 항목·필드·구간을 보존하는지 원자료와 대조한다. 이미지의 의미 판독을 서버의 완료 조건으로 추가하지 않는다.
- 지정 자료원 경계, 고정된 어댑터 구현 방식, 인증 정보의 비노출을 확인한다. 결과 없음·접근 제한·실행 오류·부분 결과의 구별을 실제 사례 또는 적합한 시험으로 검증한다.
- 큰 결과를 매번 모델 입력에 싣지 않고도 다음 요청을 수행할 수 있다. 실제 클라이언트에 전달되는 설명·결과와 반복 호출을 살펴 중복과 불필요한 출력을 줄인다.
- 실서비스에서 수행한 검증과 모의·오프라인 검증을 구별한다. 접근 조건 때문에 수행하지 못한 검증은 미완료로 남긴다. 서비스의 향후 변경까지 실패가 없다고 보장하지 않고 검증한 시점·환경·범위를 기록한다.

후속 세션의 반환은 **완료·부분 완료·차단** 중 실제 상태를 먼저 밝히고, 구현 위치와 MCP 연결 방법, 자료원별 지원·검증 범위, 검증 근거의 경로, 남은 작업과 필요한 사용자 입력을 제시한다. 파일이 상세 결과를 소유하면 해당 경로를 참조하고 본문에 다시 복제하지 않는다.
