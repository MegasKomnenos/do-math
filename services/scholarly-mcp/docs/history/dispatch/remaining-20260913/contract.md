# 개별 미해결 기능 조사·구현 파견 계약

현재 재검토는 같은 디렉터리의 USER-CRITERIA.md가 정한 사용자 세 기준을 추가 적용한다. 해당 문서가 오류 전후 판독·로컬 실수 재검토·기술 수리와 종료 판단의 정본이며, 아래 API 대조 화면 안내만으로 실제 실패 요청의 전후 판독을 대신하지 않는다.

이 세션은 학술자료 MCP의 미해결 항목 한 개를 맡는다. 현재 알려진 원인 설명을 원자료에 대조하고, 해결 가능한 구현과 검증을 끝까지 수행한다. 먼저 여러 해법을 탐색하고, 확인된 해법을 구현·실서비스 검증으로 수렴한다. 조사는 보고서 작성만을 목적으로 하지 않는다. 실제 가능한 기능을 구현이 막는다면 독립 작업 사본에서 고치고 검증한다. 최종 통합은 주 세션이 맡는다.

## 입력과 현재 계약

주 세션의 대화는 자동 전달되지 않는다. 이 문서 뒤의 개별 임무와 절대 경로 표를 읽고 시작한다. C:/math/.agents/AGENTS.md, 기억/색인.md의 layer-3 절, L-0001·L-0004·L-0005·L-0016, 최신 M-0237을 읽는다. write-for-reader 스킬과 산문·AI 프롬프트·에이전트 채널·절차문 참조 문서도 적용한다. 단순 진행 보고마다 다시 적재하지 않는다.

확정 계약은 C:/math/학술자료-MCP-구현-인계.md다. 현재 구현·검증의 정본은 C:/math/services/scholarly-mcp/docs/SUPPORT.md, AUDIT-MATRIX.md, LIMITATIONS-AUDIT.md, VALIDATION.md다. 현재 질문은 이 문서들의 한계 판단을 재검토하라는 사용자 지시다. 과거 문서의 '이미 끝났으므로 재조사하지 않는다', '양성 표본을 찾으면 재개한다'는 메모를 이번 조사 거부의 근거로 쓰지 않는다.

개별 임무의 시작 파일을 읽고 정의·호출부·시험으로 이동한다. 기존 실측은 C:/math/services/scholarly-mcp/data/access-research와 data/validation에 있다. evidence에 파일명이 있으면 먼저 그 파일을 찾고, 표본 식별자·문헌 제목·오류 코드로 rg 검색해 원 보고와 비공개 근거까지 추적한다. 과거 세부 파일의 경로가 바뀌었다면 발견 절차로 회수한다. 요약만으로 원인이나 부재를 확정하지 않는다. 현재 웹 기능·정책·문법은 공식 원문과 실제 응답으로 확인한다.

## 범위·권한·격리

사용자는 각 미해결 항목의 독립 codex exec 파견, 실제 화면 이미지의 직접 판독, 해결 또는 시도 가능한 방법의 소진까지의 지속 수행을 명시적으로 지시했다. 되돌릴 수 있는 실험·구현·테스트는 자율 수행한다. Unpaywall, Scopus의 개인 계정 내보내기, GitHub의 인증이 필요한 전역 코드 검색처럼 추가 자격 때문에 사용자 결정으로 보류된 경로는 이 작업에서 제외한다. 새 API 키·개인 계정·연락 이메일·결제·직원 메시지·지원 문의·원문 복사 신청을 사용하거나 제출하지 않는다. 기존 KUDOS 자격은 아래 전용 사본에서 내부적으로 사용할 수 있다.

세션의 작업 디렉터리는 C:/math로 유지한다. 수정 범위는 개별 경로 표의 workspace/services/scholarly-mcp 아래 코드·시험·문서, private_dir 아래 원근거·전용 인증·브라우저 상태, output_dir 아래 정제 보고뿐이다. C:/math/services/scholarly-mcp의 원본 코드, 공유 인증 상태, 공유 기억·색인·설정·Git index는 읽기 전용이다. 다른 작업의 private_dir도 수정하지 않는다. 주 세션만 원본 통합·커밋·푸시한다. 이 사본은 Git 작업트리가 아니므로 원본 Git 명령으로 변경을 되돌리거나 스테이징하지 않는다.

실행은 C:/math/services/scholarly-mcp/.venv/Scripts/python.exe로 한다. 복제한 server.py를 새 stdio 프로세스로 띄울 때 항상 --data-dir와 --credential-root를 아래 전용 경로로 지정한다. 어댑터 직접 생성도 같은 전용 경로를 사용한다. 기존 live 스크립트의 기본값이 공유 경로를 가리킬 수 있으므로 실행 전에 모든 실제 경로를 확인한다. 등록 MCP는 이 CLI에서 비활성화되어 있으며, 검증은 사본의 새 SDK로 수행한다. 기존 Codex·등록 MCP·CLI·다른 브라우저 세션을 재시작하거나 조작하지 않는다.

한 호출은 한 자료원 안에서 끝낸다. 공개 API 자료원에 대한 UI 열람은 실패 진단의 대조 실험으로 허용되지만, 생산 코드가 API 실패 후 브라우저나 다른 자료원으로 자동 전환하게 만들지 않는다. 새로운 고정 경로를 찾으면 공식 제어·응답·문헌 정체성으로 근거를 확립한다. 없는 파일 URL을 추정 조합하거나 이미 제거·비활성으로 확인된 파일의 접근제한을 우회하지 않는다. 동일 자료원의 다른 공개 양성 표본을 찾는 것은 허용된다.

소유 브라우저는 전용 프로필로 연다. Headless와 창 모드, 필요한 경우 다른 설치 엔진을 비교할 재량이 있다. 실제 UI의 프레임·Shadow DOM·input·가시 상태를 조사하고 제어를 정상 조작한다. 현재 소유 화면의 사람 확인 체크박스·이미지 과제는 호출 AI인 이 세션이 직접 판독해 정상 수행할 수 있다. 외부 solver, 토큰 위조, 서버 이미지 인식 AI를 추가하지 않는다. OS 전역 SendKeys·다른 창 포커스를 빼앗는 자동화는 쓰지 말고 해당 브라우저의 CDP/Playwright 제어를 사용한다. 닫을 때는 자신이 생성한 정확한 프로세스·컨텍스트만 종료한다. 기존 삭제 거부 폴더나 다른 세션의 프로필을 정리하지 않는다.

원 HTML·JS·응답 헤더·signed URL·인증값·원 예외·CLI 원 로그는 private_dir에만 저장한다. 자격파일 본문, 대량 원 HTML/JSON, 임의 query/path를 터미널에 출력하지 않는다. 공개 보고는 사전에 허용한 학술 필드·오류 유형·상태·바이트수·공개 문헌 식별자만 기록한다. 도구 출력의 URL도 먼저 정제한다. 공개 저자·기관·저널·논문 제목은 비밀이 아니며 재현에 필요하면 정확히 유지한다. 개인 계정 입력 영역만 캡처 전에 마스킹하거나 영역 밖으로 제외한다.

## 실험과 직접 판독

1. 현재 사본과 원기록에서 실패 표본·입력·기대 결과·실패 단계를 회수한다. 새 시도의 가설과 그것을 구별할 관측을 experiments.json에 기록한다.
2. 실제 실패 동작 직전, 직후, 응답이 안정된 뒤 화면을 각각 고유 파일명으로 캡처한다. 캡처를 만들기만 하지 말고 view_image 또는 런타임의 동등한 이미지 열람 도구로 직접 열어 읽는다. 시각, CSS viewport·DPR, 현재 문헌 식별자·입력·제어 상태, 화면에 읽힌 오류 문구를 기록한다. 처음 화면 판독 뒤에도 상태가 바뀌거나 새 과제가 나타나면 새 이미지를 다시 읽는다. 옛 좌표·옛 과제 답을 재사용하지 않는다.
3. API 중심 과제에서도 공식 문헌 UI나 공식 기능 화면을 열어 직접 판독하고 API 결과와 대조한다. UI에 대응되는 개념이 없으면 공식 문서의 해당 화면을 읽고 이를 '문헌 UI'로 표시하지 않는다. 프로그램이 만든 가짜 오류 화면을 원 사이트의 화면이라고 제시하지 않는다. 이미지 열람 도구가 실패하면 다른 실제 이미지 입력 경로를 시도하고 그 실패를 기록한다.
4. 입력 시작·클릭·request·response·DOM 변화·download event·파일 검증 시각을 UTC ISO 형식으로 기록한다. 원 응답의 status/MIME/bytes, console/page error, 도착한 파일과 원 요청의 식별자를 연결한다. UI0건·HTTP200·비어 있지 않은 파일만으로 성공을 판정하지 않는다. 자동 제어 count와 직접 화면 판독이 다르면 프레임·태그·가시성·렌더 시점을 조사한다.
5. 양성 대조와 실패 대조를 확보한다. 가능하면 변수 하나만 바꾸고, 실패 문헌이 삭제·초록 전용·권한 제한이라면 다른 정상 문헌으로 기능 자체를 대조한다. 실제 UI 사용법·공식 문법·옵션·endpoint·정렬·페이지·응답 내용과 로컬 parser/validator를 서로 구별한다. 근거가 가리키는 새로운 방법을 experiments.json에 추가하고 계속 실행한다.
6. 구현 결함을 확인하면 해당 결함을 재현하는 의미 있는 회귀 검사를 만든 뒤 가장 작은 수리로 해결한다. 사본의 설명·호출부·추출·오류·부분 결과 보존을 함께 검증한다. 실제 새 MCP SDK에서 호출자가 공개 설명만으로 기능을 쓸 수 있는지 확인한다. 기회수 데이터 재생과 새 원격 요청, 모의 검사와 실제 검사를 각각 표시한다.

Rate limit은 공유 IP에도 적용될 수 있다. Retry-After와 공식 한도를 지킨다. 응답에 근거하지 않은 빠른 무한 재시도를 하지 않는다. 대기 중에는 로컬 코드·공식 문서·원자료 분석을 계속한다. 막힌 방법 하나가 전체 과제의 종료 조건이 되지 않는다. 근거가 있는 독립적인 경로와 양성 대조가 남아 있으면 계속한다.

## 지속 수행과 종료 판정

작업이 끝나지 않았는데 '여기까지 했다', '다음에 하겠다', '원하면 계속하겠다'라는 최종 반환으로 종료하지 않는다. 시간 경과·문맥 압축·검사 한 번 통과·첫 차단·방법 하나 실패는 종료 사유가 아니다. 문맥이 부족해지면 progress.json과 보고에 정확한 재개 위치를 저장하고 계속한다. 완료되지 않은 채 CLI가 종료되면 운영기가 같은 thread_id를 재개한다.

최종 종료는 다음 두 처분만 허용한다.

- **completed**: 개별 목표를 해결했고 필요한 구현·설명·회귀·실제 SDK 검증을 마쳤다. 코드 결함 없이 기존 기능이 정상이라는 결론도 현재 실제 입력·결과와 실패 원인 설명을 입증해야 한다. 사본 통합은 주 세션의 후속 작업이므로 commit·merge를 기다리지 않는다.
- **exhausted**: 해결하지 못한 범위를 정확히 남기되, 현재 권한과 환경에서 실행 가능한 모든 발견 경로와 새 근거가 제시한 대안을 실제 조사했다. experiments.json의 각 방법에 입력·실행/미실행 여부·근거·결과·다음 방법이 불가능한 구체 이유가 있으며, 실행 가능한 미시도 항목이 0개다. 단순히 오래 걸린다는 이유나 과거 보고의 불가 선언으로 이 처분을 쓰지 않는다. 계정·정책 변경 등 사용자에게 속한 새 결정이 필요한 경우에도 독립적으로 수행할 수 있는 작업을 모두 마친 뒤 조건과 영향을 남긴다. 이 처분은 세계의 모든 가능한 방법을 증명했다거나 기능이 영구히 불가능하다는 주장이 아니다.

완료 전 환경 장애로 강제 반환해야 한다면 상태는 **incomplete**다. 시도·산출·다음 행동을 저장하며 exhausted로 바꾸지 않는다. 운영기는 이를 같은 세션에서 재개한다. 정상 종료 직전에는 실제 이미지 판독 목록, 실패 최초 단계, 구현 변경, 검사 결과, 남은 범위가 서로 모순되지 않는지 확인하고 자신이 연 브라우저를 정상 종료한다.

## 파일과 반환

매 주요 실험 후 output_dir/progress.json을 갱신한다. task_id, state, updated_at, current_stage, next_action, latest_evidence를 기록한다. 중간 상태는 running 또는 waiting_external이며 최종 처분과 구별한다. 원격 대기 중에도 마지막 정보가 무엇인지 남긴다.

output_dir/report.md에는 현재 결론, 해결 범위, 실패가 처음 나타난 정확한 단계와 시각, 직접 판독한 화면 내용, request/response/file 대조, 시도한 대안, 변경·실서비스/오프라인 검증, 남은 조건을 적는다. 구현이 바뀌면 output_dir/changes.json에 workspace 기준 변경 파일과 이유를 나열한다. production 코드 파일의 실제 사본이 산출물이며 보고에 코드가 있다고만 적지 않는다.

output_dir/experiments.json은 방법별 객체 배열이다. 각 객체는 method, executed, input, observed, evidence_paths, next_or_stop_reason을 가진다. visual-review.md에는 화면별 파일 경로·캡처 시각·직접 열람 여부·보이는 내용·네트워크 대조·불확실성을 적는다. 각 경로는 실제 존재하는 파일이어야 한다.

최종 응답은 출력 스키마의 JSON이다. task_id, disposition, summary, report_path, experiments_path, visual_review_path, changed_files, tests, evidence_paths, remaining_executable_methods, exhaustion_reason을 채운다. 각 tests 객체에는 command, result, kind를 쓰고 kind는 live/offline/mock 중 하나다. completed는 남은 실행 작업이 없고 목표 검증을 통과한 경우, exhausted는 미해결 범위와 소진 근거가 있는 경우다. 해결과 소진을 섞지 않는다. 최종 결과의 수용 여부와 원본 통합은 주 세션이 근거를 직접 읽어 판정한다.
