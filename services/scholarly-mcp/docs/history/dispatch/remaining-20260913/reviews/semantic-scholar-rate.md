# 대체 endpoint 성공과 남은 기능의 구분·검증

주 세션이 report.md와 SDK 검증 흐름을 직접 읽었다. 공식 batch/bulk/title-match/관계의 양성은 유의미하지만, 현재 report의 '이 항목은 해결했다/남은 실행 가능한 방법 없음'을 전체 검색·fetch기능의복원으로수용하지않는다. 기본relevance와single-detail은429였고,새SDK최초batch는실패했으며full-parts batch도02:52:49에429,마지막03:05:39성공은최소export-only batch였다. 다음범위를해결하고기존실측을보존한다.

1. 실제사본의fetch가공개사용설명에서약속하는metadata·abstract·export·supplementary필드와실제요청fields를매핑한다. 원live에서검증된부분과offline/mock만검증된부분을구분한다. 최소export-only의양성을full-parts양성으로확대하지않는다.
2. 현재권한에서공식헤더·정책과작업별호출상태를지키면서미검증full-parts를양성대조한다. 실패하면요청필드를의미있는단위로분리해필드오류/레코드부재/크기/현재rate상태를대조한다. 헤더없는10분관측을보장간격으로발명하지않고,동일429연타없이근거있는실험만수행한다. 이미부분성공한자료는보존한다.
3. relevance검색과bulk검색은순서·문법·범위가다른기능이다. 기존이름후보검색을title-match최대한후보로바꾼것도같은후보집합을보장하지않는다. 현재정상동작하는공식경로가원요청의의미를보존하는지구분한다. 기본검색의남은429를대체기능성공으로숨기지말고currentcontract의성공·제한·미검증범위를명시한다.
4. 기본relevance/단건이반드시동작해야한다는미래가용성보장은요구하지않는다. 다만현재가능한공식사용법·입력·요청형식·불필요한fields·타당한간격의추가대조가남는지현재문서와실험근거로판정한다. 새APIkey·브라우저자동fallback·숨은endpoint자동전환은계속금지다.
5. 새문헌UI또는관련기능화면의전후를실제판독하고API실험과같은paperId를대조한다. UI자료존재가API가용성을증명하지않음을유지한다. 최종보고는완료된기능목록과계속제한되는기능목록을각각제시하고,실제SDK성공을각기능에결속한다.

현재사본수리가필요하면가장작은변경·회귀·새SDK를마친다. 기존성공의재현범위를넘는설명을고치는것과기능을복원하는것을구분한다. 미확정기능이남으면근거있는소진처분으로정확히남기며성공으로포장하지않는다.
