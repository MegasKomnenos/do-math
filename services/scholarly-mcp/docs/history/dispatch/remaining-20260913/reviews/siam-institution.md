# SIAM 기관 접근 종료 판단 재검토

주 세션은 실제 rollout의 이미지 입력과 기관 선택·연맹 화면을 대조했다. UI상 기관 인증 미성립과 비공개 PDF 실패는 관측 사실이지만, 관리자가 고쳐야만 한다는 필요조건까지 입증됐다고 수용하지 않는다. 사용자는 화면을 읽고 실행 가능한 다음 방법을 더 탐색하라고 요구한다. 기존10실험·공개PDF양성·덮어쓰기 사고 이력을 보존하고 다음을 수행한다.

1. SIAM discovery에 KNU/KAFE가 없다는 결과와 KAFE 공식 metadata에 경북대 IdP가 있다는 결과를 같은 문맥에서 대조한다. 현재 SIAM/Silverchair의 공식 기관 인증·연맹 발견 프로토콜이 지원하는 정상 경로와 선택 파라미터를 확인한다. 화면 목록에 없다는 사실만으로 공식 문서·실제 provider 응답이 지원하는 경로까지 닫지 않는다. 공식 metadata에서 확인한 자기 기관 식별자를 문서화된 정상 입력에 쓰는 것과, 임의 entity/토큰을 위조하거나 권한을 꾸미는 것은 구별한다. 새 자격·타기관 선택·토큰 위조·관리 설정 변경은 하지 않는다.
2. 실제 KUDOS의 현재 SIAM 링크와 구독 저널 목록의 원 바로가기, URL rewrite·redirect별 프록시 유지 여부, SIAM 세션 쿠키 적용 범위를 단계별로 대조한다. 공개 SIAM 도착과 기관 인증 성공은 별개다. 프록시가 중간에 풀렸거나 legacy 저널 호스트가 현재 경로와 다르면 원 안내·제공자 응답에 근거한 정상 이동을 검증한다. 호스트를 추정해서 치환하지 않는다.
3. '공개PDF는 된다'는 결과는 파일 처리의 양성 대조다. 등록IP·기관활성화·proxy설정 중 어느 하나가 반드시 잘못됐다는 증거로 확대하지 않는다. 실제 관측으로 좁힐 수 없는 내부 원인은 미확정으로 남긴다.
4. 현재 SDK가 접근 미성립인 대상에 fulltext not_implemented나 download_missing을 반환한 것이 정확한지도 따로 검토한다. 이것은 기관 접근 자체의 해결과 별개인 오류 분류 문제다. 분류를 고쳤다면 원문 접근을 복원했다고 표시하지 않는다.
5. 새로운 원 UI 입력·인증 선택·PDF 동작 전후를 고유경로로 촬영하고 즉시 직접 판독한다. 각 요청/응답/쿠키 적용 여부의 원값은 private에만 저장하며 공개에는 상태·정체성·오류 유형만 기록한다.

이 과제의 모든 신규 쓰기는 자신의 private/output/workspace뿐이다. 과거 helper의 원래 출력 경로는 사용하지 않는다. 종료 전 실제 함수 전역·실행인자·출력path를 확인한다. 원본 통합·공유 근거 복원은 주 세션이 별도 처리한다. 사진 재열람이나 앞결론 반복만으로 종료하지 말고 위 신규 축을 실제 실험하거나 실행할 수 없는 근거를 남긴다.
