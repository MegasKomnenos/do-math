# AMS 기능 제한 제안 재검토

주 세션은 네 rollout에서 view_image10회와실제이미지28블록을확인했다. 단일조건·AND·중첩조건의전후화면,Edit500,기본검색양성은실제근거다. 다만 options.expression을 브라우저 실행 전에 거부하는 변경은 기능 복원이 아니며 아직 채택하지 않았다. 사용자는 불가능 판정으로 기능을 제약한 것에 남은 해법이 없는지 다시 조사하라고 지시했다.

1. 현재 공식 Advanced Search의 자연스러운 조작 흐름에서 시작한다. 잔존 JavaScript의 숨은 builder를 호출하는 경로와, 현재 사용자가 접근할 수 있는 여러 기본 필드·검색어 문법·필터 조합의 표현력을 분리한다. 현재 공식 도움말과 실제 요청에서 AND/OR/NOT·괄호·구문을 지원하는 다른 원 제어/문법이 있는지 대조한다. 다른 문법을 시험할 때는 입력 보존과 의미를 구별할 양성·음성·합집합/교집합 대조를 사용한다.
2. Edit 경로의 NullReferenceException 위치는 서버 오류를 입증하지만 모든 검색 표현 경로가 불가능함을 증명하지 않는다. 오류 직전 실제 post model의 필수 필드·초기화·세션 상태가 현재 화면에서 어떻게 만들어지는지 공식 렌더/JS/응답과 대조한다. 올바른 사용자 조작으로 만들 수 있는 요청이 더 있다면 실행한다. 임의 민감필드 주입이나 토큰 위조는 하지 않는다.
3. 중첩 OR가 AND로 직렬화된 관측을 별도 미해결 항목으로 닫는다. 원하는 연산자가 실제 어느 제어/단계에서 바뀌는지 전후이미지·DOM·요청을대조한다. 이 문제가 legacy builder 자체인지 호출 방식인지 구별한다. 첫 단일조건이 실패했다는 이유로 이 표현 보존 결함의 분류를 생략하지 않는다.
4. 기존 조기거부 guard 때문에 새 경로가 실행되지 않지 않도록 전용 probe나 작업 사본의 실험 경로로 원 UI를 조사한다. 사용자의 검색식을 서버가 임의로 다시 발명하거나 일부조건을 빼지 않는다. 의미동등성을 입증할 수 없는 대체 경로는 같은 기능이라고 주장하지 않는다.
5. 새 동작 전·후·안정 화면을 즉시직접읽고원응답과결속한다. 구현이 가능하면 수리·설명·회귀·새SDK를 마친다. 불가능하면 각 현재공식경로의실측경계와남은외부조건을보고하되 '조사완료/오류분류개선'과 '검색기능복원'을명확히구분한다.

이 추가지시는 해결이나근거있는방법소진전조기종료를금지한다. 이미수행한실험을새실험인것처럼반복나열하지말고위미검증축을해결한다. 기존실험·사본diff·이미지·원서버진단을보존하며원본쓰기·공유state변경은금지다.
