# EuDML의 실제 책·책 장 레이아웃 검증

최종 전수 검토에서 미배정 검증 한 건이 남았다. eudml.py는 book-meta, front/book-meta, book-part-meta를 처리하지만 실제 책 또는 책 장의 source fixture와 live 검증이 없다. 기사형 XML 양성을 책 레이아웃 성공으로 세지 않는다.

기존 사용자 기준과 권한을 유지하면서 정상 공개 EuDML 목록·검색·원 UI에서 실제 책 또는 책 장 ID를 확인한다. 원 자료의 유형·제목·식별자를 확인한 뒤 공식 metadata/NLM 경로에서 그 레이아웃을 검증한다. 책이 아닌 일반 article 응답으로 대체하지 않는다. 원 XML·UI에서 제목·정체성·본문 유무를 대조하고 구현 오류가 있으면 자기 private 사본에서 최소 수리 및 의미 있는 회귀를 추가한다. 단순히 희귀 유형이라는 이유로 기능 불가로 닫지 않는다.

현재 CQL/NLM은 root 재검증에서 유지보수 안내가 있는504였으며, 원본은 이미 CQL90초/NLM120초/connect20초 수리를 포함한다. 옛 사본의45초 설정으로 재실패시키지 말고 이 현행 값으로 확인한다. 공식 유지보수·429가 재현되면 실제 전후·안정 이미지를 캡처하고 직접 열어 판독한다. API 응답은 실제 body를 읽고, local 실행 콘솔이나 저장 HTML 재생은 그 사실을 명시한다. 경로·인코딩·timeout 등 로컬 오류는 수리하고 다시 확인한다. 응답이 구체 재시도 시각을 주면 지킨다.

원본, root 통합 사본, Git, 등록 MCP 및 사용자 브라우저는 수정하지 않는다. 자기 private workspace와 새 소유 브라우저만 사용한다. 기존 credentials를 출력하지 않고 검색은 명시한 코드·보고서·자료 파일에 한정한다. 추가 API키·계정·연락 이메일·외부solver·접근 우회·지원 문의는 쓰지 않는다. 다른 자료원을 자동 대체하는 생산 fallback도 추가하지 않는다.

실제 표본의 검증·수리를 완료했거나 현재 정상적으로 실행 가능한 탐색·검증 경로를 모두 시도해 구체 근거를 남겼을 때만 반환한다. 미발견을 자료원에 책이 없다는 증명으로 쓰지 않는다. book/part 양성이 없으면 정확히 그 검증이 미확정이라고 남기고, 원인과 이미 실행한 정상 방법을 적는다. report/result/criteria-review/visual-review에 실제로 연 이미지와 원 증거 경로를 연결한다. 옛 전체 모듈을 덮어쓰기 안으로 내지 말고 새 변경만 changes.json에 구별한다.
